# B1 — The 2026 agentic tooling landscape, audited against our stack
**Researcher:** mesh subagent, ZABZ-TECH, 2026-09-30

Scope: 2026-01 → 2026-09-30. Every entry carries a source and the date the source was published, last updated, or checked. Vendor-run benchmarks are labelled as such. Anything I could not reach a primary source for is marked **not verified**.

---

## 1. Verdict (max 4 sentences)

We are **current on harness and sandboxing, behind on durability semantics and cost accounting**. DSH's model — a scheduler that starts headless sessions on a Windows box — is the same shape the whole field converged on in 2026, and Claude Code, Codex CLI and Gemini CLI all now ship the headless/background/scheduled primitives we rely on. What we are missing is the layer the field spent 2026 building *underneath* that shape: checkpoint-based durable execution with resumption, hibernation while waiting on a model call, and exactly-once side effects. Cost is where we are most exposed: every major sandbox and durable runtime now bills idle time differently, and an always-on desktop fleet is the worst possible shape under wall-clock billing.

**What durability now means in practice:** (1) *checkpointing* — persist step results, not whole-runtime determinism; (2) *waiting is free* — a run must release compute while blocked on a model call or an approval; (3) *human-in-the-loop is a first-class durable state*, not a timeout (Cloudflare stores pending approvals across hibernation); (4) *exactly-once side effects* — the guarantee is scoped to what sits inside a checkpointed step; (5) *agent-legible control plane* — the system exposes an MCP/skill surface so an agent can list, inspect, replay, resume and unblock runs, not just a human dashboard.

## 3. The entries that actually matter to us

1. **OpenClaw** — MIT, foundation-governed, no paid tier. A local **Gateway** owns sessions, tools, events and channel connections; models and harnesses (Claude, Codex, local) are swappable plugins; skills and plugins are a published ecosystem (ClawHub); release v2026.8.1 shipped durable ingress monitors, external Gateway lifecycle supervision, and verified SQLite backup/restore. This is our architecture, open, with a community. The strategic question is not "is it better" but "why are we maintaining a private copy". Source: [README](https://raw.githubusercontent.com/openclaw/openclaw/main/README.md), [release notes](https://newreleases.io/project/github/openclaw/openclaw/release/v2026.8.1-beta.3) (2026-08).
2. **Claude Code's background-agent model** — pinned background sessions (`Ctrl+T`) that stay alive when idle, auto-restart in place to apply updates, and are shed under memory pressure only after non-pinned sessions (v2.1.147, 2026-05-22); `claude agents --json` for scripting session lists (v2.1.145, 2026-05-20); `--resume` resurrecting unexpired scheduled tasks (v2.1.110, 2026-04-16); dynamic workflows orchestrating tens-to-hundreds of background agents (v2.1.154, 2026-05-28). This is DSH's target model, already shipped.
3. **Codex CLI's headless contract** — `codex exec --json` streaming JSONL turn/item events plus defined exit codes (0,1,2,3,4,130) and `--output-schema`. Our durable record should look like this. Source: [non-interactive mode docs](https://mintlify.wiki/openai/codex/concepts/non-interactive-mode) (checked 2026-09-30).
4. **Checkpoint-based durable execution (Absurd / Kitaru)** — resume from stored step results instead of replaying with deterministic constraints; suspends release compute entirely; both expose an agent-legible surface (a skill for coding agents, an MCP server). For a fleet where each session costs real money per step, "retry from scratch is unacceptable" is the whole argument. Source: [ZenML, 2026-05-11](https://www.zenml.io/blog/where-durable-execution-is-headed).
5. **Cloudflare Agents durable runtime** — Durable Object hibernation with a Code Mode runtime persisting execution history, **pending approvals**, and snippets across hibernation, plus fibers, scheduled tasks, retries and a human-in-the-loop pattern library. The clearest published answer to "how does an unattended agent hold a state while it waits". Source: [durable Code Mode runtime](https://developers.cloudflare.com/agents/tools/codemode/durable-runtime/) (last updated 2026-07-22); [long-running agents](https://developers.cloudflare.com/agents/concepts/agentic-patterns/long-running-agents/).
6. **Fly.io Sprites billing shape** — actual-usage billing, auto-pause ~30s after activity stops, storage-only while asleep, copy-on-write checkpoints; Fly's own worked example puts a 4-hour Claude Code session at $0.44. Even if we stay on the desktop, this is the correct cost model to benchmark against. Source: [AI sandbox pricing](https://fly.io/learn/ai-sandbox-pricing/) (2026-09-09).
7. **GEPA** — the only self-improvement technique in this survey with a peer-reviewed, reproducible result (ICLR 2026) and released code. Applying reflective prompt evolution to our own skill/prompt library is the highest-certainty improvement available. Source: [ICLR 2026](https://proceedings.iclr.cc/paper_files/paper/2026/hash/0e9e708b6f48e14fd0ac29e167413f76-Abstract-Conference.html).
8. **Agent Skills as a portable standard** — adopted by Claude Code, Codex CLI, Cloudflare Agents and OpenClaw. If our skills are in this format, we can move harnesses without rewriting capability. Sources: see §2.1–2.3.

## 4. "Dots" — what it is, and whether it matters

**Identification: OpenAI Dots, launched at OpenAI Dev Day on 2026-09-29.** An always-on personal/business agent. Each Dot runs on its own private cloud computer with its own browser; powered by **GPT-6 Astra**; connects to 4,000+ apps via plugins; learns from feedback over time; can also be granted access to the user's own laptop; an **auto-review** system checks in with the user before sensitive actions such as password changes, and OpenAI can pause a Dot's work. - **Pricing:** bundled with ChatGPT **Pro at $100/month** and Business Premium; the first Dot is included at no extra cost; Dot conversations do not count against usage limits — but the FAQ says only "for the next month".
- **Availability:** rolling out immediately, **not** in the EEA, Switzerland or the UK.
- Sources: [Mashable, 2026-09-29](https://me.mashable.com/tech/76660/openai-introduces-dots-a-new-always-on-ai-agent-at-dev-day-2026) (quotes and links the primary announcement `openai.com/index/introducing-dots/`); [9to5Google, 2026-09-29](https://9to5google.com/2026/09/29/openai-dots-agent/); [The Verge](https://www.theverge.com/ai-artificial-intelligence/1002033/openai-dots-launch-muse-competitor). **I could not fetch `openai.com/index/introducing-dots/` directly — it returned HTTP 403 — so the product details above rest on secondary reporting of that page, not on my own read of it.**

## 5. "Coral" — what it is, and whether it matters

**Identification: Coral by Coral (withcoral.com) — an open-source data-retrieval layer that gives agents one SQL interface across APIs, databases and file systems.** Launched publicly **2026-04-27**. It began as the retrieval infrastructure behind the team's vertical agent "Phoebe" and was unbundled into a standalone product.

- **Why it fits the owner's grouping:** the owner named it alongside **Firecrawl** and **JINA** — i.e. tools that get external data into agents. Coral is exactly that category, applied to *internal/company* data rather than the open web.
- **Licence and price:** Open Source tier **free forever, Apache-2.0**, self-hosted, unlimited sources/agents/queries, bring your own LLM keys. **Team $249/month** including 50,000 queries, then $0.005/query. **Enterprise** custom. ([withcoral.com/pricing](https://withcoral.com/pricing), checked 2026-09-30)
- **Claimed performance (vendor benchmark, NOT independently verified):** on 82 real-world tasks using Claude Code + Opus 4.6, Coral vs direct provider MCPs (Datadog, Sentry, Linear, Slack, GitHub): **+20% fact accuracy, 42% lower latency, 52% lower cost** overall; on the 51 complex multi-hop tasks **+31% accuracy, −70% cost, 3.4x more cost-efficient**. On 31 simple single-source tasks the difference is marginal (+6% accuracy, −2% cost). The stated mechanism is that SQL enables server-side aggregation instead of O(N) MCP pagination, and cross-source JOINs replace agent-side orchestration. ([withcoral.com/blog/benchmarks](https://withcoral.com/blog/benchmarks), 2026-04-28; [introducing Coral](https://withcoral.com/blog/introducing-coral), 2026-04-27)
- **Does it plausibly outperform Firecrawl and JINA for our use?** They are not substitutes. Firecrawl and JINA fetch and parse *the web*; Coral queries *systems we already have credentials for* (ticketing, monitoring, chat, code host, databases, files). For a phone-repair and resale business, the analogous win is joining the POS/repair-ticket system, inventory, supplier pricing and messaging into one queryable surface so an agent answers "which SKU is under-priced, and which supplier is late" in one query instead of a dozen tool calls. The benchmark is vendor-run and Opus-4.6-in-a-sandbox specific; treat the size of the gain as unverified, and the direction as credible.
- **Confusable with:** **Coral Protocol / CoralOS** (docs.coralos.ai), an unrelated open-source multi-agent orchestration platform marketed as "Kubernetes for AI agents" with a server, registry, marketplace and experimental x402 payments ([docs.coralos.ai/about](https://docs.coralos.ai/about), [Marketplace](https://docs.coralos.ai/concepts/marketplace), checked 2026-09-30; also [Coral-Protocol/Coral-FirecrawlMCP-Agent](https://github.com/Coral-Protocol/Coral-FirecrawlMCP-Agent)). Because the owner grouped Coral with Firecrawl and JINA, **withcoral.com is the far more likely referent**; Coral Protocol is the secondary possibility.

## 6. What changed in 6 to 9 months about unattended agents

Three things changed materially, and all three are about the *runtime*, not the model. First, **durability became a named category**: after OpenClaw's rise, "there seems to have been a collective realization that durable execution needs to be part of how people think about agent systems", and 2026 produced a wave of entrants (Kitaru open-sourced 2026-03-21, Absurd in production, plus Restate, DBOS, Inngest, Convex, LittleHorse, Golem Cloud, Orra, Microsoft's durabletask-go and the cloud vendors' own takes) around Temporal as the incumbent ([ZenML, 2026-05-11](https://www.zenml.io/blog/where-durable-execution-is-headed)). The practical consequence is that *replay semantics became a design choice rather than a constraint*: checkpoint-based replay restores completed step results and lets ordinary code re-run, while Temporal's deterministic replay demands the same commands in the same order — so multi-hour runs stopped being an all-or-nothing bet on one heavyweight system. Second, **waiting became free**: Cloudflare persists execution history, **pending approvals** and snippets across Durable Object hibernation ([updated 2026-07-22](https://developers.cloudflare.com/agents/tools/codemode/durable-runtime/)), Absurd/Kitaru suspend by releasing compute, and sandbox vendors moved to active-CPU or actual-usage billing with auto-pause ~30 seconds after activity stops ([Fly.io, 2026-09-09](https://fly.io/learn/ai-sandbox-pricing/)) — an agent that idles 70% of the time went from paying full wall-clock to paying roughly storage. Third, **headless multi-hour orchestration shipped in the mainstream CLI harnesses**: Claude Code 2.1.154 orchestrates tens to hundreds of background agents with a `/workflows` monitor, pinned background sessions survive idle and self-restart in place, and `--resume` resurrects scheduled tasks ([changelog](https://code.claude.com/docs/en/changelog), [2.1.x history](https://raw.githubusercontent.com/alexica00/claude-code-ultimate-guide/refs/heads/main/guide/core/claude-code-releases.md), entries dated 2026-04-16 → 2026-05-28), while Codex CLI documents an exit-code-and-JSONL headless contract and Gemini CLI v0.61.0 (2026-09-23) hardened sandbox and prompt-injection boundaries. Capability and durability both improved sharply; cost per idle agent-hour collapsed on rented infrastructure.

## 7. Table stakes we may be missing

Now-standard things a 2026 fleet is expected to have, with our likely gap in brackets: **checkpointed resumption of a killed session, including mid-tool-call** [if DSH restarts a session from the top, that is now table stakes, not a limitation]; **human-in-the-loop as a durable state that survives process death and costs nothing while pending** [the owner is usually asleep — approvals must be a stored state, not a blocking prompt]; **exactly-once side effects** for anything that spends money, sends messages or writes to the POS [scoped to checkpointed steps, so it requires the checkpoint layer first]; **an agent-legible control plane** — an MCP server or skill so *an agent* can list, inspect, replay, resume and unblock runs [Kitaru ships one out of the box; Absurd ships a coding-agent skill; a human dashboard no longer counts alone]; **portable skills in the `SKILL.md` convention** [Claude Code, Codex CLI, Cloudflare Agents and OpenClaw all read it, so compliance buys harness portability]; **per-run cost and duty-cycle accounting** [without it we cannot tell whether the desktop is cheaper than a Sprite, nor attribute spend to a flag]; **outcome-graded evaluation of a multi-hour run** rather than trace inspection [no commercial product does this yet — the closest work is research benchmarks, §2.6]; and **capability-scoped credentials** so broad API keys never reach the model context, which is Coral's explicit pitch ([withcoral.com/blog/introducing-coral](https://withcoral.com/blog/introducing-coral), 2026-04-27) and also the exact failure class Gemini CLI's 2026-09-23 prompt-injection fix addresses.

## 8. Candidate improvements

**LS-1 — TOPIC:** Checkpoint-based durable execution for DSH sessions. **WHAT:** wrap every side-effecting step in a persisted checkpoint keyed by session id; on restart, reload completed step results from Postgres and re-enter from the top; suspend (release the process) while waiting on a model call or an approval. **WHY:** a 6-hour unattended run that dies at hour 5 currently costs 5 hours; the field moved to checkpoint replay in 2026 precisely because retry-from-scratch is unaffordable. **EFFORT:** L. **EXPECTED GAIN:** eliminates re-execution of completed work; enables multi-day runs. **RISK:** ordinary code between checkpoints may re-run and produce different values — side effects must live *inside* steps. **SOURCE:** [ZenML, 2026-05-11](https://www.zenml.io/blog/where-durable-execution-is-headed). **FIRST CONCRETE STEP:** instrument one existing session type to log how many steps it repeats after an induced restart; that number sizes the win.

**LS-2 — TOPIC:** Durable human-in-the-loop approvals. **WHAT:** store pending approvals as first-class durable state that survives process death; the session parks, the owner approves later from a phone/chat, the run resumes. **WHY:** our owner is not at a keyboard; a blocking prompt is a lost night. **EFFORT:** M. **EXPECTED GAIN:** removes the largest source of stalled runs. **RISK:** an approval queue that nobody watches becomes a silent graveyard — needs an escalation/expiry policy. **SOURCE:** [Cloudflare durable Code Mode runtime, updated 2026-07-22](https://developers.cloudflare.com/agents/tools/codemode/durable-runtime/). **FIRST CONCRETE STEP:** add an `approvals` table plus a `paused_approval` session state, and make the flag server surface it in its daily digest.

**LS-3 — TOPIC:** Adopt Codex-CLI-style headless contract and durable event log. **WHAT:** every headless session emits JSONL events (`turn/started`, `item/*`, `turn/completed`) and returns defined exit codes; the log is the durable record. **WHY:** it makes sessions inspectable, resumable and machine-gradable, and it is the documented convention. **EFFORT:** M. **EXPECTED GAIN:** replay, grading and cost attribution all become possible. **RISK:** event-schema churn — pin a version. **SOURCE:** [Codex non-interactive mode docs](https://mintlify.wiki/openai/codex/concepts/non-interactive-mode) (checked 2026-09-30). **FIRST CONCRETE STEP:** define the minimal event set (start, tool call, tool result, message, end, exit code) and write it for one session type.

**LS-4 — TOPIC:** Agent-legible control plane (MCP server) for the fleet. **WHAT:** expose list-sessions, inspect-run, replay, resume, unblock, kill as MCP tools so an agent on the Linux box can operate the Windows fleet without a human. **WHY:** 2026 convergence is that the protocol exposed to external actors matters as much as the human dashboard. **EFFORT:** M. **EXPECTED GAIN:** the fleet becomes self-healing and self-auditing. **RISK:** an agent with kill/resume rights needs exactly the guardrails of LS-7. **SOURCE:** [ZenML, 2026-05-11](https://www.zenml.io/blog/where-durable-execution-is-headed). **FIRST CONCRETE STEP:** ship read-only tools (list, inspect) first; add mutating tools only after the audit log exists.

**LS-5 — TOPIC:** Port skills to the `SKILL.md` convention. **WHAT:** express DSH capabilities as `SKILL.md` packages with frontmatter, so they load in Claude Code, Codex CLI, Cloudflare Agents and OpenClaw. **WHY:** harness portability without rewriting capability; also the ecosystem is where new capabilities now appear (ClawHub). **EFFORT:** S–M. **EXPECTED GAIN:** removes harness lock-in; instant reuse of community skills. **RISK:** low; mainly a discipline change. **SOURCES:** [Claude Code changelog](https://code.claude.com/docs/en/changelog) (skills, `disallowed-tools`, `effort` frontmatter); [OpenClaw README](https://raw.githubusercontent.com/openclaw/openclaw/main/README.md) (skills + ClawHub). **FIRST CONCRETE STEP:** convert the three highest-traffic internal playbooks into `SKILL.md` and load them from one harness.

**LS-6 — TOPIC:** Duty-cycle and cost instrumentation. **WHAT:** record wall-clock, active CPU, tokens, and dollars per session and per flag; compute daily duty cycle for the Windows desktop. **WHY:** every sandbox vendor now bills idle differently, so "is the desktop cheaper" is answerable only with this number. **EFFORT:** S–M. **EXPECTED GAIN:** a defensible build-vs-rent decision, plus the ability to kill expensive flags. **RISK:** none material. **SOURCE:** [Fly.io AI sandbox pricing, 2026-09-09](https://fly.io/learn/ai-sandbox-pricing/) (its worked example: 4-hour Claude Code session at 30% of 2 CPUs / 1.5 GB ≈ $0.44). **FIRST CONCRETE STEP:** log tokens + wall-clock + exit code per session for two weeks and publish a single page of numbers.

**LS-7 — TOPIC:** Capability-scoped credentials, never broad API keys in context. **WHAT:** mediate every external data access through a proxy that holds the credential and enforces per-agent scopes, so the model never sees a broad key. **WHY:** both a security control and, per Coral, a cost control; prompt-injection into build files and command flags was serious enough that Gemini CLI shipped a fix for it on 2026-09-23. **EFFORT:** M. **EXPECTED GAIN:** blast-radius reduction plus auditability. **RISK:** proxy becomes a single point of failure — needs its own durability. **SOURCES:** [Coral, 2026-04-27](https://withcoral.com/blog/introducing-coral); [Gemini CLI v0.61.0, 2026-09-23](https://geminicli.com/docs/changelogs/latest.md). **FIRST CONCRETE STEP:** inventory every credential DSH currently exposes to a model context and rank by blast radius.

**LS-8 — TOPIC:** Pilot Coral (withcoral.com) as the data-retrieval layer. **WHAT:** stand up the Apache-2.0 open-source self-hosted build against our POS, inventory, supplier and messaging sources; give agents one SQL surface. **WHY:** our agent work is heavily retrieval-bound, and Coral's pitch — fewer, more precise queries, cross-source JOINs, credentials held outside the LLM — maps directly onto it. **EFFORT:** M. **EXPECTED GAIN:** claimed +31% accuracy / −70% cost on complex tasks (vendor benchmark, unverified); realistically, fewer tool calls and fewer timeouts. **RISK:** **the benchmark is Coral's own, run on Opus 4.6 in a sandbox — do not budget against it**; also a young product (launched 2026-04-27, ~5k GitHub stars). **SOURCES:** [benchmarks, 2026-04-28](https://withcoral.com/blog/benchmarks); [pricing](https://withcoral.com/pricing). **FIRST CONCRETE STEP:** reproduce the benchmark on 10 of our own retrieval tasks, MCP vs Coral, and measure tool calls and cost yourself.

**LS-9 — TOPIC:** Adopt GEPA for prompt/skill optimisation. **WHAT:** run GEPA's reflective prompt evolution against our skill and prompt library, using real session trajectories as the training signal. **WHY:** it is the only surveyed self-improvement method with a peer-reviewed, reproducible result (beats GRPO by 6pp average with up to 35x fewer rollouts). **EFFORT:** M. **EXPECTED GAIN:** measurable quality lift on existing prompts without new models. **RISK:** needs a scoring signal — blocks on LS-7/LS-3 producing gradeable trajectories. **SOURCE:** [ICLR 2026](https://proceedings.iclr.cc/paper_files/paper/2026/hash/0e9e708b6f48e14fd0ac29e167413f76-Abstract-Conference.html); code [github.com/gepa-ai/gepa](https://github.com/gepa-ai/gepa). **FIRST CONCRETE STEP:** pick one narrowly-scored task (e.g. triage classification) and run GEPA against a held-out split.

**LS-10 — TOPIC:** Outcome-graded evaluation of multi-hour runs. **WHAT:** build a small harness that grades the *final state of the world* after a 6-hour unattended run (files, tickets, records) rather than the trace. **WHY:** no commercial eval product in this survey evaluates multi-hour autonomous sessions; this is the biggest unserved gap and it is the only way to know if long runs are actually working. **EFFORT:** L. **EXPECTED GAIN:** replaces vibes with a pass rate; makes regressions visible. **RISK:** building an eval nobody runs — keep it to one session type. **SOURCES:** [Long-Horizon-Terminal-Bench, arXiv 2026-07](https://github.com/AkihikoWatanabe/paper_notes/issues/6081); [ScenDroid, ICLR 2026](https://iclr.cc/virtual/2026/10012489). **FIRST CONCRETE STEP:** define the pass condition for one recurring flag and record it against the last 20 runs manually.

**LS-11 — TOPIC:** Evaluate OpenClaw as the substrate, not just a peer. **WHAT:** timebox a comparison of DSH against OpenClaw's Gateway + plugin model for one workload, and check whether our differentiators survive the comparison. **WHY:** it is MIT, foundation-governed, free, multi-channel, plugin-swappable and moving faster than a private harness can; not evaluating it is a strategic risk in both directions. **EFFORT:** M. **EXPECTED GAIN:** either a large maintenance saving or a documented reason our build is genuinely better. **RISK:** porting cost if we half-commit; also OpenClaw runs tools on the host by default unless sandboxing is configured, and its channels pair unknown senders by default — read the security guide first. **SOURCE:** [OpenClaw README](https://raw.githubusercontent.com/openclaw/openclaw/main/README.md) (checked 2026-09-30). **FIRST CONCRETE STEP:** run one low-risk nightly flag on OpenClaw on a spare machine and compare the failure modes.

**LS-12 — TOPIC:** Sleep-when-idle sandbox for burst work, desktop for the always-on core. **WHAT:** split workloads — keep always-on, latency-sensitive flags on the Windows desktop; move bursty, parallelism-hungry work to an actual-usage-billed sandbox that auto-pauses. **WHY:** idle is now nearly free on rented infrastructure but fully priced on owned hardware, and the two workload shapes have opposite cost curves. **EFFORT:** M. **EXPECTED GAIN:** capacity for parallel bursts without buying hardware. **RISK:** state must live outside the sandbox (depends on LS-1); egress and snapshot fees are real ($0.15/GB on Vercel, $0.08/GB-month snapshots). **SOURCE:** [Fly.io AI sandbox pricing, 2026-09-09](https://fly.io/learn/ai-sandbox-pricing/). **FIRST CONCRETE STEP:** pick one burst workload and price it at 25% and 100% CPU utilisation using the published rate table.
