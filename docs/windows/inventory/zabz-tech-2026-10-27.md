## 3. "Phantom files": 141 abandoned agent working copies

This is the real shape of the problem, and it is **mostly an illusion of size**.

`C:\Users\ezabz\Code` holds **105** directories matching the fleet's naming (`_w-*`, `_lpt-*`,
`_wt*`, `_audit-*`, `_fleet`, `_worktrees`, `_scratch`, …) and `C:\Users\ezabz` holds **50** more at
the profile root. Together: **141 directories, 309.5 GiB logical, 14.6 M files.**

Age of those 141, by the directory's own last-write:

| Age | Dirs | Logical GiB |
|---|---|---|
| 30+ days | 7 | 30.2 |
| 14–29 days | 28 | 56.4 |
| 7–13 days | 84 | 141.4 |
| 2–6 days | 18 | 51.4 |
| 0–1 day | 4 | 30.3 |

Most are clones of the same repo — sampled five, all `https://github.com/lakewoodphone/phone-and-tech-full.git`,
one branch each (`lpt/signout-security-20261020`, `lpt/charge-tax-reconcile-20261020`, …). Four of
the sampled trees are clean (`git status --porcelain` → changed=0; untracked files are build output).
Only **9** are registered `git worktree`s of `lpt-hub`; the rest are plain clones sitting on a
branch that already exists in the repo.

**But deleting all 141 does not free 309 GiB.** Measured, two ways:

1. `node_modules/react/package.json` is **one inode — `844424932029948`, 132 links — in three
   different worktrees** (`_w-auth`, `_w-tax`, `_lpt-defects-20261013`). `pnpm` hardlinks every
   package from its store into every checkout, so those bytes exist once on disk and 132 times in
   the directory tree.
2. One worktree measured end to end: `_w-auth` **1.58 GiB total, `node_modules` 1.20 GiB, everything
   else 0.39 GiB**. `_w-tax` identical.

So the honest yields are: **~55 GiB** if all 141 go (141 × ~0.39 GiB of real content), plus a large
reduction in file count — 14.6 M directory entries that every backup, virus scan and search index
has to walk. The 120-odd GiB that disappears from the *logical* total is shared package content that
stays on disk once.

That also closes the books: **1,024.2 GiB of logical files − ~131 GiB of hardlinked duplicates =
893.2 GiB, against 893.55 GiB actually used.** There is no unexplained hole in the disk.
