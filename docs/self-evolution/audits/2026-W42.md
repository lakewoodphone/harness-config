## 5. Instruments that are working but weakly defined

These are not broken — they return a `measured` value — but the value is not the thing its name promises, so a reader can be misled without any cell going dark:

- **`wake.stats`** — unit says count but value = number of matching lines from `wake.py stats` (3). It counts lines, not rows and not work. Evidence: `["wake rows: new=2 claimed=2 done=469 failed=89 unverified=0 cancelled=0 expired=0"]`
- **`spend.spend`** — the metric is named spend_records and its value is the line count of wake-cost.jsonl, not USD. The $/day ceiling lives in the `wake.py stats` text, so this cell cannot test the ceiling. Evidence: `"cost ledger rows"`
- **`sessions.sessions_marker`** — named sessions_agents_run but value = len(~/.dsh) + recursive count of ~/.sms-inbox/wake-instances. It is a composite of directory entries and files, not sessions; it moved +28 in 47 minutes from new instance files alone. Evidence: `{"dsh_dir_entries": 17, "wake_instances": 87}`
- **`journal.open_pain`** — not windowed. by_kind counts pain=2 inside the 7-day window while open_pain counts 50 open entries all-time; a reader can read one as the other. Evidence: `{"decisions": 4, "handoff": 18, "lessons": 25, "pain": 2, "wins": 1}`
- **`home-of-the-tool`** — the tool's declared path scripts/self-audit/weekly-evolution-audit.py did not exist in any repo, and docs/self-evolution/README.md (referenced by run-wake-sources.sh) did not exist. The only runnable copy was /root/bin/sources/weekly-evolution-audit.py. Evidence: `"find / -path '*scripts/self-audit*' -> only self-audit.ps1 files"`
