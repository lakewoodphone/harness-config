## P161 - The public rentals endpoint was a read proxy into the company backup bucket

**Found:** 2026-09-15, by two independent auditors working the same app (PHOTO-1 in `photos-moderation.md`, DATA-1 in `data-api.md`); both proved it live, neither fetched a body.

**What it was.** `apps/rentals/app/uploads/[...file]/route.ts` took the URL path verbatim and used it as an S3 key against `R2_BUCKET=psm-backups` - the nightly restic repository for the whole VPS. Unauthenticated:
- `GET https://rentals.lakewoodphoneandtech.com/uploads/config` -> 200, 155 B (the restic repo config)
- `GET /uploads/data/6e/6e11461b...` -> 200, 2157 B (a restic data blob)
- `HEAD /uploads/lpt-apps/config` -> 200

And `/root/lpt-apps-backup.sh` on lpt-apps-01 writes into that same bucket a `pg_dump -Fc` of **every** Postgres database plus a copy of **every** `/opt/*/.env` - which includes the app's own R2 keys and `LPT_SSO_SHARED_SECRET`. The app also held the same credential pair restic uses, i.e. read *and delete* on the backup repo.

**Fixed at the edge, 2026-09-15 19:34Z (verified):** the rentals vhost in `/opt/caddy/Caddyfile` now refuses every `/uploads/*` request that does not match `^/uploads/listings/[A-Za-z0-9._-]+$` (Caddy `path` + `not path_regexp`; RE2 has no lookahead). Backup at `/opt/caddy/Caddyfile.bak-rentals-uploads-20260915T193403Z`; `caddy validate` -> Valid configuration; reloaded. Re-probed: `/uploads/config` 404, `/uploads/data/6e/...` 404, `/` 200, `/api/health` ok. Same patch set trustworthy proxy headers (`header_up X-Real-IP {remote_host}`, `X-Forwarded-For {remote_host}`) and a 12 MB `request_body` ceiling.

**Still open (app + infra, wave 2):** the app-side key allowlist in both storage drivers, and the real fix - a bucket and credential scoped to `listings/` instead of the shared backup bucket. Rotating the app's R2 credential and the restic credential is required; the age of the exposure cannot be measured because neither R2 nor this vhost kept an access log, so treat the objects as potentially read and rotate rather than audit.

**Why it existed.** The 2026-09-06 deploy notes recorded the bucket reuse as a *convenience* ("reuses the `psm-backups` bucket under `listings/` prefix") and the audit's A4 graded photo exposure as medium ("world-readable-by-URL is acceptable for public listings"). Both readings missed that the same route could address any key in the bucket. The lesson is in L1552.
