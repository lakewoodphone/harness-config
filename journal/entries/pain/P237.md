## P237 — install-client-plugin.sh (POSIX) has the pre-fix bundle-enrolment bug; only the PowerShell installer was repaired

`scripts/install-client-plugin.sh` (POSIX) still carries the defect that `install-client-plugins.ps1`
was repaired to remove, and nothing links the two files.

Measured by reading the file, 2026-09-17:

 scripts/install-client-plugin.sh:77-85
 const bundles = config.dsh.profile.bundles || []
 if (bundles.includes(name)) { console.log('ok: bundle list already contains ' + name); process.exit(0) }
 bundles.push(name)
 config.dsh.profile.bundles = bundles

No `dsh.bundle.patch` test anywhere in the file. `install-client-plugins.ps1:140` and `:204-214` now
gate enrolment on `[bool]($parsed.dsh -and $parsed.dsh.bundle -and $parsed.dsh.bundle.patch)` and
REMOVE a declared name that fails it, after exactly this defect made two Windows machines unbootable
(90-provider-mount.md SS3, measured with `--dump-config` exit 1 on both).

Severity, honestly: it takes a package DIRECTORY as an argument, so it cannot arm a node by itself the
way the PowerShell enumerator could -- something has to name the package. That is why no node is broken
by it today. But it is the installer the macOS and Linux nodes are provisioned with, and the Mac's
bundle list is written by hand-adjacent tooling (its profiles/web/package.json was written by a sync at
08:48:28 today, the same row that stopped it booting). One wrong invocation on the one macOS node arms
the same class of fault, on a machine whose engine is a KeepAlive LaunchDaemon that would crash-loop.

What would fix it: the same two changes install-client-plugins.ps1 received -- require
`dsh.bundle.patch` to enrol, and drop a declared name that fails the test -- with the check's failure
demonstrated on a pre-repair input before it is trusted, as 90 SS3 did.

Recorded rather than fixed: this session owns docs/mesh/97 and the three repairs, and
scripts/install-client-plugin.sh is not one of them.

Evidence: docs/mesh/97-fleet-repairs.md SS5.1; docs/mesh/90-provider-mount.md SS3.
