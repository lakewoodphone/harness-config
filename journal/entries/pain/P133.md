## P133 — log/** and the six flat files are still writable by any stale checkout

Symptom: `log/**` (1.4 MB of shards) and the six flat files are tracked in git, still writable by any machine running the older tool, and were being appended to tonight - which is why the drift count moved under the audit and why one migration had to be re-run against a tree that changed while it read it.

Cost: a read of the record can be stale mid-session; every migration must be re-verified against sources that can move; and the record temporarily exists in two shapes (shards plus `entries/`).

Fix available and not yet run: `journal.py gc-legacy --quiet-hours 24 --apply` moves `log/**` into `archive/legacy-shards-<date>/` once nothing there has changed for a day, leaving `log/README.md` and a re-creatable directory so a stale writer still lands somewhere the importer scans; `check` counts drift with the alias-aware identity rule and `import-legacy` absorbs it.

Residual after that: a stale machine can still create `log/<kind>/<month>.md` and append a flat file, so the record can grow a parallel copy until a session runs `import-legacy`. The durable fix is to retire the v1 writer everywhere, which means every machine pulling this commit.
