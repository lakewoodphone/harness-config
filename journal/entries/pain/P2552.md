## P2552 — P-production-tree-is-not-in-git: the running secretary code is uncommitted and diverged both ways

The code that RUNS in production is not in git, and the checkouts have diverged in both
directions. Measured 2026-09-28 while trying to deploy the owner-text gate:

 * `/home/zabz/personal-secretary-mvp` on `secratary` is `master` @ 7d8dd160 with ~30
 files LOCALLY MODIFIED and many commits (`git log origin/master..HEAD`) that exist
 nowhere else. Its own `origin/master` is 5bf31461.
 * Blob hashes for `app/main.py`, `app/autopilot.py`, `app/tool_factory.py`,
 `app/sms_service.py` differ across all three of: the server, the laptop checkout, and
 `origin/master`. Three different versions of the same four files.
 * It is not simply "the laptop is behind": server `app/autopilot.py` is 8,994 lines
 against the laptop's 8,110, while server `app/personal_assistant_context.py` is 476
 against the laptop's 703. Diverged BOTH ways, so neither is an ancestor of the other.
 * `git rev-list --left-right --count origin/master...master` on the laptop: 37 commits on
 origin the laptop lacks, 7 on the laptop origin lacks.

CONSEQUENCE: copying either tree over the other destroys work that exists in exactly one
place. Every production change has to be an anchored patch on the running tree.

WHAT WOULD FIX IT: reconcile the server tree into git (commit what is there, push, then
merge the laptop's 7 commits), after which a deploy is `git pull` + restart. Until that
happens, treat "the repo" and "production" as two different things and never assume a file
you can read is the file that is running.

SECOND, SEPARATE, URGENT: the authority's root filesystem is at 100% -- 191 MB free of
467 GB (`df -h /`). That is why `cp data/secretary.db /tmp/` failed with "Disk quota
exceeded" during this session, and why a 3 GB database cannot be snapshotted to /tmp. It is
not caused by this work and it was not cleaned up.
