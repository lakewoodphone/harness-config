## P6306 — ZABZ-YOGA cannot pull harness-config: an untracked journal id collision blocks every update

WHAT HURTS: this laptop cannot pull harness-config, so it can receive no configuration, tool or fix from the estate. MEASURED 2026-10-12 on ZABZ-YOGA while pushing a one-bullet skill correction I had already committed (29b08efb, still local and safe): `git pull --rebase` refuses with unstaged changes and `git pull --no-rebase` aborts because incoming commits add journal entries that exist here UNTRACKED (journal/entries/decisions/D3124-D3126, handoff/H3556, lessons/L3708, pain/P3150, docs/mesh/163-*). That is an id collision: origin assigned the same ids to different content.

The failure is silent from outside - the local commit just never lands, and nothing says why.

WHAT WOULD FIX IT: scripts/unblock-journal-sync.sh, which is written for exactly this and is careful - it backs up every affected file to ~/.dsh-journal-collision-backup-<stamp> FIRST, moves the untracked entries out, takes the generated index from the incoming commit, pulls, then re-adds each entry through journal.py append so it gets a FRESH id, and never deletes an entry or force-pushes.

WHY I DID NOT RUN IT: it renumbers other sessions' journal entries, several sessions are writing to this same tree right now (the plugin-remote-fanout libs and journal/index were also dirty), and triggering an id-renumbering pass as a side effect of a label job is the wrong scale. It deserves its own session on a quiet tree. Cost of waiting: this box stays unable to receive harness updates, which is the documented worst consequence of an id collision - worse than the collision itself.
