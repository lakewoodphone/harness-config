## P207 — personal-secretary-mvp repo HEAD is older than the deployed code; a merge from HEAD regresses the security roster

The repo HEAD of personal-secretary-mvp is OLDER than the deployed code on `secratary`. A merge from HEAD can silently regress production.

MEASURED 2026-09-16 while preparing an agent to edit `/webhook/ha/security-alert`.

DEPLOYED `app/main.py` lines 8244-8253 reads the alert roster and passes it explicitly:
 _extra = [n.strip() for n in str(getattr(settings, "security_alert_extra_recipients", "") or "").split(",") if n.strip()]
 result = send_security_alert_mms(body=body, settings=settings, recipients=_extra, media_url=first_pic or None)

REPO HEAD `app/main.py` (~line 8299) does NOT pass `recipients` at all.

DEPLOYED `app/sms_service.py` additionally has:
 send_security_alert_mms(..., bypass_owner_kill_switch: bool = True)
which REPO HEAD lacks — and that bypass is load-bearing, because `data/OWNER_SMS_KILL_SWITCH`
EXISTS on the server (259 bytes, dated 2026-07-20). Security alerts deliberately bypass it.

Consequence: an agent working from a worktree cut at HEAD would ship code that silently drops the
wife and mother from the intrusion roster and re-subjects security alerts to the owner's SMS
kill-switch. Both are invisible in tests written against HEAD.

Rules:
1. Before editing a live-serving path in this repo, read the DEPLOYED file, not just the worktree
 copy: `ssh secratary-ts "sed -n '8240,8260p' ~/personal-secretary-mvp/app/main.py"`.
2. Treat the deployed file as the baseline and say explicitly which parts were taken from deployed.
3. This is the inverse of the ha-config drift problem: there the repo had LOST live config
 (`recorder:` present live, absent in git); here the repo lags live code. Both mean
 "read the running system before trusting the repository".
4. Same session, same class: the repo's `ha-config/config/configuration.yaml` has 312 lines and no
 `recorder:` block, while live `/config/configuration.yaml` has `recorder: purge_keep_days: 30`
 plus two `exclude.entity_globs` at lines 84-89. Deploying the repo would have reduced retention.
