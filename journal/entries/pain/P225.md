## P225 — A task is retired by its session's progress mirror, not by its action (#25106 closed 26 minutes after creation)

**Symptom.** A task is marked `done` because the work SESSION that was working on it ended, not because the thing the task describes happened. Measured 2026-09-14: task **#25106** — *"File PayPal item-not-received dispute for Global Direct Parts order 161898 ($167.96, paid 2026-04-19, never shipped)"* — was closed `done` at **23:30:51Z**, 26 minutes after it was created and 20 minutes after the autopilot delegated it. Nothing had been sent and no dispute existed. It had to be reopened by hand, and `supplier-delivery-watch.py` then raised a duplicate task because its dedupe correctly saw no open work.

**Mechanism, traced end to end.** `app/autopilot.py` mirrors work-session step progress into the task (`update_task_progress(..., progress_pct=pct)`, where `pct = steps_done / steps_planned * 100`). When the last step lands the task reads **100**. `app/services/lifecycle_sweep.py::_close_completed_progress_tasks` then closes *any* task at `progress_pct >= 100` with no active goal plan, with the activity-log line `completed_progress_tasks_closed — Closed 1 active task(s) with progress_pct=100 and no active goal.` The sweep runs on the API's own schedule, so the gap between "session ended" and "task retired" is minutes.

**Cost.** This is the fourth recorded instance of the same failure and it is not a coincidence: the owner's **question #8** is four broken syncs with seven tasks "marked completed while the failures are unchanged"; **task #1777** was closed `done` on 2026-04-26, two days after paying 167.96 USD for an order that never shipped — the loss this session spent the evening documenting; and now #25106. Every one of those made the company's own success metric read *clean*.

**Fix applied.** The mirror is capped at 99 (`min(int(pct), 99)`) — the same way this class already states an unfinished outcome at its failure paths — and the API was restarted to load it. Pre-existing failures in `test_autopilot_event_driven.py` / `test_boa_autopilot.py` are unrelated (both fail identically with the line reverted).

**Still open, and named so "fixed" is not overread.** The sweep will still close any task that *anything* puts at 100 with no active goal; nothing yet requires a task's own action to be EVIDENCED before it closes. The honest end state is a completion artifact check (the shape `_work_output_has_completion_artifact` already uses for work sessions) applied to tasks that represent an external action — sending, filing, paying.
