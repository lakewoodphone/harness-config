## P2931 — Neither backup pusher has a completeness marker, so an interrupted backup becomes the offsite copy

MEASURED 2026-10-09. push-db-offsite.sh picks `ls -1d */ | sort -r | head -1` and
company-offsite-push.sh picks the newest directory too. Neither requires the directory to be
COMPLETE, and neither verifies the artifact is a database. An interrupted backup therefore
sorts first, gets uploaded, OVERWRITES the previous good object, and reports OK — because the
only check is that remote bytes equal the bytes sent, which proves the transport and not the
content.

Nearly cost the company its offsite database backup on 2026-10-10 at 05:10 UTC. Caught by a
fleet workstream; the partial was removed and the good object is intact.

WHAT WOULD FIX IT: (1) backup-data.sh writes a completion marker (e.g. `COMPLETE` containing
the stamp + byte count) as its last act; (2) both pushers skip any directory without the
marker, and refuse rather than push; (3) push_one opens the source with sqlite3 and runs
PRAGMA schema_version (or integrity_check) BEFORE compressing, refusing a non-database;
(4) the freshness monitor checks the payload, not only the tag timestamp.
