## P3817 — The bench's ddrescue slot accounting keeps dead runs and refuses live ones

Measured 2026-10-20 on zabz-tech-linux while starting the Werner image. 'lpt-recovery-manager slot ddrescue' answered: 'ERROR: no free ddrescue slot (in use 2/2). Retry later or use --block.' The two holders were newman-3477680413 (claimed 2026-09-15) and bauman-7322329552 (2026-10-18), and NEITHER case had a ddrescue process running - the manager's 'running recovery processes' block showed only a photorec for bauman and my own ssh. So the slot table is a claim store with no liveness check: a slot is released only if the owning agent releases it, and an agent session that ends without releasing blocks the bench for months.

Consequence: the live case ran its image OUTSIDE the slot accounting, which is exactly the state the slots exist to prevent (nothing then caps how many ddrescue jobs can run at once). The case log says so rather than pretending the slot was held.

Fix that would work: make 'slot' validate holders against live PIDs/mapfile mtime before refusing, and expire a slot whose owner has no process and whose case has not been touched in N hours. Until then: a refusing slot line is an open item to report, not a reason to stop, and the case file must record that the job ran unaccounted.
