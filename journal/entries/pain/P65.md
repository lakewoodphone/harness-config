## P65 — The "authoritative" deploy doc stated a fact that is false about the Netlify webhook

**What hurts.** `phone-and-tech-full/docs/operations/DEPLOY_ARCHITECTURE_REALITY.md` — the document the
repo points at as *the* authority on deployment — says: *"There is **no** Netlify webhook / build hook.
Pushing to `test`/`main` does **NOT** auto-deploy the frontend."* It does. Pushing `test` triggers a
Netlify **API** build, which fails with `Build blocked: Unrecognized Git contributor. This plan allows only
verified account members to push to private repos.`

**Evidence.** Two such deploys in the site's own deploy history: `6aa78cd5f05cd500095e718a` (05:57:41Z) and
`6aa78f87a5e685000867e8e1` (06:09:11Z — titled with the commit message I had just pushed). Both
`deploy_source: "api"`, both `state: "error"`. The site object itself carries
`deploy_hook: https://api.netlify.com/hooks/github`.

**Why it matters.** This is very likely the source of the **197 GitHub "Run failed" emails in 7 days**
another session measured — a failing automation nobody has connected to its cause, generating noise that
trains everyone to ignore build failures. A wrong line in the authoritative doc is worse than a missing
one, because it stops the next agent looking.

**What would fix it.** Correct the doc (done 2026-09-14: it now states the webhook exists and that its
builds fail by design on this plan), then either disable the site's GitHub deploy hook — deploys here are
manual `netlify deploy --no-build` anyway — or stop the pushes from triggering it. The doc fix is mine and
is done; silencing the integration touches a shared integration and is not yet done.
