## P2819 — The mesh transport silently loses children: empty host string, no final message, no cause

## P2819 — The mesh transport silently loses children, and its failure mode is unreadable

**What hurts.** Dispatching a five-child fleet on 2026-09-30: two children died with *"the transport
reported host "", which is not one of the hostnames the placement named ... refusing to report work
from a node the broker did not name"* — a correct refusal, but the fleet is gone and the reason names
a host the string is empty for. Two more exited `4294967295` (that is `-1`) and produced **no final
message at all**, so there was nothing to read: no stack, no stderr, no partial report. The fifth
behaved like the others. Cost: five dispatches, roughly ten minutes of wall clock, and zero work
products, and the only way to learn what happened was to infer it from two other children's stderr
tails.

**Why it is worse than a crash.** A child that fails loudly costs one retry. A child that vanishes
silently makes the fleet's integration step unusable, because a missing report is indistinguishable
from a child still working — and I was notified of all five failures at once, after the fact.

**What would fix it.**
1. Emit `MESH-HOST: <hostname>` as the **first line of the child's first output**, not only in its
 final report, so the transport can match the node before the work starts and fail in the first
 second instead of the tenth minute.
2. Never let the host string be empty: if the placement names a node and the transport cannot
 determine which node answered, say *which side* was unknown.
3. On exit `-1` with no final message, return the child's last N lines of output rather than a bare
 `stderr tail:` — the two children that did this at least had a tail; two had nothing.
4. A brief should carry its own bootstrap so a child landing on an unexpected node can still work:
 clone the repository from the authority into a path that exists *there*, work on its own branch,
 and push that branch back. That removes the whole class of failure (see `L3184`).

**Interim rule until it is fixed.** Dispatch one cheap probe child that reports `MESH-HOST` before
spending a fleet on a guess; if the node is not the one holding the code, either clone-and-push or
fall back to `subagent_local` and mark every result LOCAL.
