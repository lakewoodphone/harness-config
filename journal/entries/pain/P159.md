## P159 — Handy cannot insert text while you speak, so it is not a perfect Windows voice-typing clone

Handy cannot insert text while you speak, so it cannot fully mimic Windows voice typing, and no setting
changes that.

Windows (Win+H) inserts word by word into the focused box through the platform text service: the user watches
the sentence form. Handy records, transcribes at the end, and pastes once (`paste_delay_ms: 60`; measured
562 ms for a one-second sentence). The end state in the text box is the same; the feedback is not, and for a
user copying a Windows habit the "is it even hearing me?" feeling is the thing that reads as broken.

Why not just switch: the two ways to get live insertion are worse for this shop --
 * a streaming model inside Handy (e.g. Parakeet Unified EN 0.6B, the catalog's #1) shows words in Handy's
 own box as you speak, but it is English-only and it SPELLS NUMBERS OUT ("one five five"), which is
 useless for prices, phone numbers and IMEIs; and
 * Apple's own dictation (Control twice) really does type as you speak, on-device, free -- but it has no
 custom vocabulary at all, so it cannot be taught "IMEI" or a customer's name.

WHAT WOULD FIX IT PROPERLY, if it ever matters: a small piece of software that consumes Handy's *streaming*
transcript events and types partial text at the cursor, or an app built on macOS's text-input (TSF
equivalent) path instead of paste. Neither exists in Handy today. Until then the honest position is: same
result, less live feedback, and Apple's dictation is the fallback when live feedback matters more than
accuracy -- a trade to make deliberately, not by drifting.

EVIDENCE: Handy docs (Overlay/Advanced/paste methods), the transcription_coordinator source (transcribe
action pastes once at stop), and 2026-09-15 LAKEWOOECHSMINI: "Using paste method: CtrlV ... Text pasted
successfully in 562ms".
