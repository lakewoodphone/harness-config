## P127 — Tailscale on ZABZ-YOGA is dead since boot, so the authority and the owner queue are unreachable from home

What hurts: from home, the authority is unreachable. Tailscale on ZABZ-YOGA is wedged in
`NoState` -- no tailnet IP, MagicDNS not resolving -- so `secratary`, `secratary-ts`, the
`owner_decision_queue`, the phone layer and the journal's remote are all dark from this machine.
Home and office are separate networks and Tailscale is the ONLY path between them, so there is no
fallback route.

State: tailscaled up since 16:42:06 (boot 16:41:46). Its own record of the cause: "You are logged
out. The last login error was: fetch control key: Get https://controlplane.tailscale.com/key?v=138:
context canceled" -- it tried to reach the control plane before the network was up at boot and
never retried. `tailscale up` and `tailscale login` return with no effect and no error;
`tailscale status --json` stays `BackendState: NoState`, `AuthURL` empty. The network is provably
fine: `netcheck` reports UDP true and DERP New York, and 443 to controlplane.tailscale.com connects
in 206 ms.

What would fix it: an ELEVATED `Restart-Service Tailscale` (then re-auth in a browser if the node
key is gone), or a reboot. This session is not elevated and the DSH sandbox cannot grant Windows
admin, so it is blocked on the owner or a UAC consent click. Second-order damage already observed
from the same window: DNS-Client 1023 "Name resolution policy table has been corrupted" at 17:20:30
(rule {5abe529b-675b-4486-8459-25a634dacc23}, error 0x57) plus 1012/1014, which has since cleared.
The refused ssh to the authority is all over the engine stderr:
`ssh: Could not resolve hostname secratary.tail93e6e6.ts.net: No such host is known.` x15.
