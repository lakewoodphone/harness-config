## P9676 — code_self_edit raises an uncaught JSONDecodeError 60+ times a day on an unguarded state-file read

**Found 2026-10-20 13:27Z while verifying a deploy — unrelated to it, and older than it.**

```
Traceback (most recent call last):
 File "/opt/company/app/code_self_edit.py", line 1112, in dedup_key_record
 record = _ledger(_load_state(repo, state_path), "dedup_keys").get(key)
 File "/opt/company/app/code_self_edit.py", line 975, in _load_state
 parsed = json.loads(state_file.read_text(encoding="utf-8"))
json.decoder.JSONDecodeError
```

**63 occurrences today**, the first at **2026-10-20T00:05:26Z** — five hours before the earliest deploy of
the cost programme (13:08Z), so it is pre-existing and not caused by that work.

`_load_state` reads a self-edit state file and calls `json.loads` with no guard, so a truncated or
partially-written JSON file raises on every call into `dedup_key_record`. A self-edit state file that
cannot be parsed should be treated as empty (with a loud warning and the bad file preserved beside it),
never as an uncaught exception on a heartbeat path.

**Not fixed, because it is outside the cost programme's scope and belongs to whoever owns
`code_self_edit.py`.** The next session should: locate the state file, check whether it is truncated
or contains a partial write, and make `_load_state` fail soft with the corrupt file renamed aside so
the evidence survives. It is a small fix and it is firing dozens of times a day.
