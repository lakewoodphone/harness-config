## P216 — the live harness-config install and the git checkout drift, and nothing detects it

**RANKED: high**, because the drift silently reverts verified fixes.

`/home/zabz/harness-config` (what the services read) and `/home/zabz/code/harness-config` (the git
checkout) are two directories, not one. By 2026-09-16 they disagreed on:
`assets/{mobile,question-card}.css`, `assets/phone-badge.js`, `packages/plugin-mobile/*`,
`packages/plugin-health` (checkout only), `docs/*`, `multi-window/*`,
`presets/{zabz,yocheved,cordis-bg}/*`, `README.md`, and about 25 scripts — some existing only in the
live tree, some only in the checkout.

**Measured cost, one instance.** The phone question-card repair — the sheet layout *and* the plugin
that pins the card to the band the reader can actually see — was live and correct on secratary and
absent from the checkout. The checkout's HEAD held `question-card.css` at 5015 B (the version that
anchors the sheet to the layout viewport) against 7382 B live, and `plugin-mobile/lib/client.js` at
10141 B against 20173 B live. A sync from any other machine would have written the older copy back
onto the phone and re-broken a bug the owner had already reported twice.

**What would fix it.** One authoritative tree with one-way delivery, or a check that fails loudly
when they disagree:

```
diff -rq --exclude=.git --exclude=node_modules --exclude=__pycache__ \
 /home/zabz/harness-config /home/zabz/code/harness-config
```

Until then: any file edited under the live path is uncommitted work, and must be mirrored and
committed before the session ends.

**Partial mitigation applied 2026-09-16, phone surface only** — `assets/mobile.css`,
`assets/question-card.css`, `packages/plugin-mobile/*`,
`scripts/{check-phone-ui.sh,question-card-live-probe.py}` — committed as `eb34bc8` / `84b452e`. The
rest of the drift is untouched and still dangerous.
