## P3993 — The generated-rows gate is self-locking and silent: every persona edit pushes the live layer further behind

**The failure, measured three hours before this was written.** `python scripts/sync.py` printed, with **exit code 0**:

 profiles: SKIPPED -- the committed generated preset rows are STALE: --check: DRIFT --
 profiles\web\presets.generated.patch.yml does not match what the converter would write | ...
 profiles: regenerate and commit them with `node scripts/make-preset-rows.mjs --install`;
 the live profile patch is left untouched
 profiles: already filed (same reason as the last refusal)
 verify: loaded surface matches the repo (compared 15 match=15 drift=0 missing=0)

`sync.py` refused the profile layer — correctly — because `profiles/web/*` no longer matched `presets/`. But it exits 0, and its own verifier then reported a clean 15/15 for a surface that does not include the layer it had just refused.

**The consequence is a one-way ratchet, and it is silent.** Every edit to the persona widens the gap between `presets/` and `profiles/web/`. The gate then refuses. The live layer (`~/.dsh/profiles/web/cordis.patch.yml`, the thing every Web GUI session actually loads) falls further behind, and nothing reports it, because the detector is aimed at `.agent-presets/` — which the 0.1.7 line no longer reads.

**Measured end state:** the live layer's mtime was `2026-10-14 07:47:29` and it did not contain `7b. When he corrects you` — the correction rule written into the canonical preset at 08:58 the same morning. It also lacked the compressed do-not-ask block, the extended measurement rule and the tool-failure rule. The owner's own agent was running a persona a day and a half old, and the instrument said 15/15.

**Fixed 2026-10-14, commit `378e7b49`:** the generator's hand edits were moved into the generator, both web artefacts regenerated from `presets/`, the layer published (live sha == repo sha), and `preset-drift.py` extended to compare `profiles/<n>/cordis.patch.yml`.

**What still hurts:** nothing alarms when a machine's sync *skips* a step. The refusal is only visible to a reader of one line among thirty. **What would fix it:** a refused deploy is a non-zero exit or a journal alarm, never a printed sentence — and `sync.py`'s `verify` step must cover every surface its own steps are allowed to skip.
