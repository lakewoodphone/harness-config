## P3172 — The shop cannot attach a photograph to a work order - every case photo lives only in git

Measured 2026-10-13 on WO26101312747 and store-wide on `operational`.

There is no path in this shop that puts a photograph on a work order.

- `orders` carries an `attachments` field and it is empty or null on every row: `lpt photos` reports `orders_with_attachments 0` store-wide, and `notes_with_attachments 0`.
- `lpt-write` has no attach command. Its documented surface is note add, status set, total set, payment set, customer create, order create (`lpt-ops/docs/writes.md` section 2).
- The one path that DOES work - a row in `repair_intake_case_photos` with the bytes in Cloudflare R2 under `repair-intake/<case uuid>/<position>.<ext>`, written before the row so a row implies an object - is bound to an **intake case**. `repair_intake_case_photos` holds 16 rows on operational, newest 2026-10-08. A retroactively-filed order like Ullman's has no intake case row of its own (its customer's intake case is the June phone job, promoted to order 1856), so there is nowhere to hang the picture.

WHY IT COSTS MONEY. A counter staffer opening the order sees the notes and no picture. For Ullman, the board label (MB LENOVO PN 5B21B85082), the serial, the battery label and the owner's handwritten tag exist only in the lpt-hub repo and in a scratch work dir on secratary-cloud. The shop has lost customer data twice; an unexplained absence of photographs on an order reads as loss, and this session had to spend a production note explaining in prose where the bytes are.

The 2026-10-08 intake batch has the same shape - the push tool writes the order id back only for an order it created itself, so orders created the other way are born with no link and stay that way. Same class: the record is complete only for orders that arrived by the one blessed route.

FIX, in order of preference:
1. Put the photograph rows on the customer's intake case when the order has none - the R2 path already works and `bin/lpt-storage-audit.sh` re-checks it in both directions afterwards.
2. Add an attach operation to `lpt-write` that writes the `repair_intake_case_photos` row and uploads the object in the same call, so the row implies the object and a failure leaves no orphan.

NOT DONE here: this session corrected the record and named where the images are. It did not build an attachment path, and it did not touch the 2026-10-08 batch.
