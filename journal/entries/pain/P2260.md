## P2260 — The mesh probe calls a live node unable to take agent work, and files that reading as an owner message every 1-2h

## What hurts

The fleet broker reports a **live** node as unable to take agent work, and that
reading is then enqueued as an owner message roughly every 1-2 hours. It is
diagnosed but not understood: the cause was not found in this session.

## Symptom, with the reading

`/home/zabz/.personal-secretary/mesh-placement.json` on secratary (rewritten every
~5 min):

 "ok": false, "total": 5, "usable": 4,
 "bad": [{"node": "zabz-yoga-1",
 "reason": "timed out after 4000 ms (hard wall-clock deadline)",
 "lastReadingAgeSec": 21000, "location": "home"}]

`roster_source` is `http://127.0.0.1:3091/nodes?fresh=1`. The node named bad was, at
that moment, running an agent session and had dispatched a subagent itself -- so
"cannot take agent work" is either a true capacity statement with a different
meaning than liveness, or a false reading produced by the probe.

The same string reached the owner-facing queue 18 times, as
`owner_message_queue.reason = 'proactive_update'`, status `held`, from 2026-09-22
03:20 to 2026-09-23 21:35, naming every node at least once (not only zabz-yoga-1).
Those rows are refused by the sender gate by design (`proactive_update` is in
`_OWNER_SMS_REASON_DENY`), so their only effect is noise in the held count.

## What would fix it

1. Decide what the probe is actually asserting. If it answers "does this node have
 a free agent slot right now", a timeout is a normal busy answer and must not be
 reported as a fault; if it answers liveness, 4000 ms is too short for the cold
 path and the reading is an artifact.
2. Whatever it means, stop enqueuing it as an owner message. It is self-healing
 telemetry, not news, and it dilutes the one count that matters.

## How to reproduce (nobody has run this yet)

 ssh secratary-ts 'cat ~/.personal-secretary/mesh-placement.json'
 ssh secratary-ts 'for i in 1 2 3 4 5; do time curl -s "http://127.0.0.1:3091/nodes?fresh=1" >/dev/null; done'
 ssh secratary-ts 'grep -rn "cannot take agent work" ~ --include="*.py" | head'

A background diagnosis was started and killed after 35 minutes without output, so
nothing here is a measurement of the probe itself -- only of the readings it wrote.
