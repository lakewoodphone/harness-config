## P3135 — The GitHub mirror of harness-config has diverged, and every push to origin half-fails

FOUND 2026-10-12 while pushing the mesh audit. `origin` has TWO push URLs - the GitHub mirror
(`https://github.com/lakewoodphone/harness-config.git`) and the estate bare repo
(`secretary-ts:/home/zabz/harness-config.git`) - and the two have DIVERGED:

 offsite/main (GitHub) = f38366fc "journal: generated index churn after the fast-search entries"
 origin/main (estate) = 7bbd341e this session
 git merge-base --is-ancestor 8c00270d offsite/main -> exit 1 (GitHub does NOT contain it)
 GitHub has 2 commits main does not; main has 15+ commits GitHub does not.

CONSEQUENCE: `git push origin main` tries GitHub FIRST and is rejected non-fast-forward, so the
GitHub half of every push has been failing silently for as long as this has been true, while the
estate bare repo still gets the ref (which is why nobody noticed). **The offsite copy of the code and
the journal is therefore STALE, and a mirror that is believed fresh is the exact "two writers /
stale copy" class this estate has already paid for twice.**

WHAT WOULD FIX IT: a merge of `offsite/main` into `main`, resolved for the generated journal index
(the binary `journal/index/journal.db` conflicts), then one push to both URLs. NOT DONE HERE, for two
concrete reasons and neither is difficulty: the shared working tree currently holds another session's
UNCOMMITTED churn in `journal/index/*`, so the merge belongs in its own worktree; and a force push is
forbidden precisely because the lost side would be a sibling session's published commits.

THE ONE-LINE CHECK, so this is never rediscovered:
 git fetch offsite && git merge-base --is-ancestor origin/main offsite/main; echo $? # 0 = in sync
