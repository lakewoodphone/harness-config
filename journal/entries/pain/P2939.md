## P2939 — /opt/company/data (~14 GB, incl. the chroma memory store) has no offsite copy at all

The company's memory store has no off-machine copy. `/opt/company/data` is ~14 GB on secratary-cloud (du -sh, 2026-10-11 06:23Z) and holds `mem0/chroma.sqlite3` (293 MB and growing during the cutover morning), `calendar_tokens`, `browser_sessions`, `agent_identities.json` (39 MB), `autopilot_state.json` and `briefings`. The offsite backup covers /root/authority.db and the accounting ledger. Nothing covers this.

chroma.sqlite3 is the one that cannot be re-derived: the tokens can be re-issued and the state files rebuilt, but the company's memory is only written once.

WHAT WOULD FIX IT: the same page-stream-then-gzip-then-multipart pipeline the authority database now uses, run against the chroma store and the small JSON state files, to a second prefix in the same bucket. The machinery is already deployed and proven; it is a second object, not a second design.
