## P2190 — Outbound SMS audit rows are lost to SQLite lock contention (no outbound spool)

# The send path has no durable audit for outbound SMS, so sent texts can vanish from the record

2026-09-23T20:16:44Z: the API log records `SMS sent: SID=SM6a6835584e8bec8c7ce2331d7af7550a
to=+18483897895 status=queued segments=1` — a real text to the owner. One second later
`ERROR app.sms_service: SMS audit row FAILED ... sqlite3.OperationalError: database is
locked`, and at 20:17:14 `WARNING app.database: sms_log row not written (SQLite busy; audit
row skipped)`. There is NO sms_log row for that message: sms_log 909 (inbound "?") is the
last row of the night.

Inbound has `app/services/sms_spool.py` exactly for this (filesystem first, DB later,
because Twilio does not retry an inbound after a 5xx). Outbound has no equivalent, and the
owner daily cap is counted from sms_log rows, so a lost row also under-counts the cap.

Fix: an outbound spool drained by the same worker, or a retry queue keyed on the Twilio SID
(which is already in hand at the moment of loss).
