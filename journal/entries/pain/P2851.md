## P2851 — The USB kit promises the access disappears on reboot; it registers sshd start=auto instead and the temp admin account is never removed

**P — The USB kit promises the access disappears on reboot. It does the exact opposite: it registers sshd to start automatically at every boot, and the temp admin account is never removed.**

The claim appears in three places:

- `Enable-ShopSsh.ps1:21` — `CLEANUP: Account and SSH are auto-disabled on next reboot.`
- `Enable-ShopSsh.cmd:35` — `echo The account is auto-cleaned on next reboot.`
- `Run-CopilotSshAccess.cmd:34` — `echo The account is auto-cleaned on next reboot.`

**There is no cleanup mechanism of any kind.** Measured 2026-10-05 by searching the whole field kit
for boot-time removal: `Register-ScheduledTask`, `New-Service`, `schtasks`, `RunOnce`, a `Run` key,
`nssm` — none of them appears anywhere for cleanup. The only boot-related registrations in the kit are
the opposite:

- `Enable-ShopSsh.ps1:83` — `sc.exe create sshd binPath=... start=auto`
- `Enable-ShopSsh.ps1:84` — `sc.exe create ssh-agent ... start=auto`
- `Install-CopilotSshAccess.ps1:281` — `sc.exe create sshd ... start=auto`

So the true behaviour is the inverse of the documented behaviour: **the temp admin account
(`repairtech` / a random password) persists forever, and OpenSSH starts on every boot**, on every
machine the shop has ever run the field kit on. The owner believed this for months and said plainly on
2026-10-05 that he did not think it had ever actually disappeared on reboot. He was right, and the
docs were the thing that was wrong.

**Why it matters beyond the doc error.** The claim is what made the kit *feel* safe to run on a
customer's machine, and it is what justified leaving an admin account behind. The residual risk is a
permanently open inbound SSH service and a local administrator account, on machines that leave the
building.

**What would close it** (the rebuild, not a patch):
1. A real boot-time destructor that runs before any access service: remove the account, the sshd and
 firewall rules, the tunnelling service, the keys, and then remove itself.
2. A time-box so the window closes even if the machine never reboots.
3. A **post-reboot verification** that asserts absence from a fresh vantage — because "I installed the
 cleanup" is the same class of claim as the one that was false here. Prove it by rebooting and
 looking.

**The generalisable rule** is in `L3324`: a cleanup promise written in a comment is not a mechanism,
and the only acceptable proof is a post-reboot absence check.
