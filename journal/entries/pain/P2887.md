# Mesh agent dispatch is down: remote subagents die on their own MCP DNS

Measured 2026-10-09 02:00-02:20 UTC on ZABZ-YOGA, during the owner-alert audit.

Three consecutive `subagent` (mesh) dispatches failed. The provider diagnostic, verbatim:

- dispatch 1 (`Inventory owner alert producers`): `remote-ssh: broker-unreachable: the placement
 broker could not be reached at secratary-ts:http://localhost:3091/place — ssh exited 255:
 Connection timed out during banner exchange / Connection to 100.84.72.88 port 22 timed out`
- dispatches 2 and 3 (`Audit owner text gate`, `Audit CFO charge categorization`): the remote one-shot
 exited 1 with no final message, stderr tail:
 `Error: getaddrinfo ENOTFOUND mcp.jina.ai ... at fetchWithMcpHeaders (.../mcp-remote/dist/chunk-CGVEK4Z7.js)`

**The mesh is NOT network-down.** At the same moment, `ssh -o ConnectTimeout=12 secratary-ts hostname`
returned `secratary` in **1.68 s**. So this is not a Tailscale or ssh fault: the placement broker at
`localhost:3091` did not answer, and the two dispatches that did get a remote process started died
before their first step because the remote agent's own MCP client could not resolve `mcp.jina.ai`.

That makes this a **provider/bootstrap fault, not a reachability fault**, and it is the more dangerous
of the two, because it fails fast with what looks like a normal error. Any session that reads only the
exit status would conclude "the fleet is fine, it just did not have any work".

**Consequence for the work it interrupted:** the two read-only investigations (producer inventory, gate
audit) and the finance audit were re-run on `subagent_local` and must be labelled **LOCAL** in any
report — per the standing rule that a fallback nobody can see is a claim about where work ran that is
not true.

**Next action for whoever picks this up:** the DNS failure is inside the remote agent's MCP client
initialisation, so repair it at the MCP client config (why is a Jina MCP server being resolved at all in
a read-only child?), and make the placement broker's absence say so in one line instead of masquerading
as ssh. Related: `P10` (duplicate MCP server spawns) is the same family.
