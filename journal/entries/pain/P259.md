## P259 — The sync-record mirror check in tools/customer/store.py cannot fire: wrong argument type AND an unrecognised verdict shape

## The claim

`python tools/customer/cli.py edit` is supposed to notice when a case file and
its sync-record mirror have drifted apart. It cannot. It is blind in two
independent ways, and both are in `tools/customer/store.py`.

## Blindness 1 - the wrong argument type

`record.diff_record(repo, case_id)` takes a **case id string**
(`tools/customer/record.py:1458`). `store._record_step` calls it as
`fn(repo, case)` with a `Case` object (`store.py:1385`). Measured 2026-09-17 on
this laptop, calling it the way the store does returns:

 {"same": false, ..., "error": "no case file for \"n', warnings=[], digest='17122c7a...')"
 under docs/customer-operations/cases"}

It stringified the Case object into the path. So the check never compares
anything - it always errors.

## Blindness 2 - the verdict shape is not recognised

`_diff_verdict` (`store.py:1348`) recognises `equal`, `in_sync`, `insync`, `ok`,
`valid`, `matches`. Anything else that is a dict returns `"differs"`.
`diff_record` returns `same` - not in that list. So even after fixing the
argument, every comparison reports `differs`.

## Consequence

Every `cli.py edit` without `--regenerate-record` emits a `record-stale`
warning, and any caller that trusts it concludes every mirror is stale. A
verifier that always fires is a verifier nobody reads. This is the same failure
shape as P3/P4 (reading the wrong data, and a loop that does not close).

## Do not "fix" it by making the differ stricter

Even called correctly, `diff_record` reports three classes of difference on the
shop's own best records (measured 2026-09-17):

 Greenwald (Acer charging jack, in_progress) customer.aliases, device.summary, operational.nextAction
 Goldstein (SD card, closed) the same three + pricing.quoted

So repairing the plumbing alone converts a silent no-op into permanent noise.
The job is: (1) pass `case.case_id`; (2) teach `_diff_verdict` about `same`;
(3) then reconcile the three genuine comparison rules - `customer.aliases` is
compared against aliases+phone, `device.summary` against the front-matter
`device` field, and `operational.nextAction` against the header's
`**Next action:**` line, which most rich records do not even have (Greenwald
uses `**Where it stands:**` instead).

## Fix when the corpus is quiet, and run tools/customer/tests/ before and after

`tools/customer/tests/test_store.py` and `test_record.py` exist. This was left
unfixed on 2026-09-17 because the fix is three coordinated changes, not one, and
a half-fix makes the noise worse.
