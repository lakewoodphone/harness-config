## P2850 — No shell works on ZABZ-TECH: ACL temp root is inside the workspace, blocking every pwsh call

Every shell command on ZABZ-TECH dies before executing: "Windows ACL temp root must be outside the workspace: workspace=C:\Users\ezabz; temp=C:\Users\ezabz\AppData\Local\Temp". Hits pwsh with any workdir (including C:\Windows\Temp and run_in_background), and the one-shot danger-full-access escalation is rejected automatically when no approval channel exists.

MEASURED IMPACT 2026-10-05: five mesh research children dispatched to that node all lost their shells; they had to fall back to web_fetch/r.jina.ai and file evidence, and could not run hostname. Playwright MCP on the same host is separately locked ("Browser is already in use for ...mcp-chrome-32dbea4"). Any fleet aimed at ZABZ-TECH must assume no shell and no browser.

WHAT WOULD FIX IT: the temp root resolves inside the workspace, so the policy rejects it. Either the workspace for mesh children launched against that node must be a directory whose temp root is outside it (set TEMP/TMP to a path outside the workspace for the child process), or the ACL/temp-root rule must treat %LOCALAPPDATA%\Temp as outside-workspace by default. Until then, treat shell-less operation as the expected mode on that node and say so in the child brief.
