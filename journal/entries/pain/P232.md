## P232 — The MDM enrolment profile is served to the internet with no authentication, protected only by an unset env var default

Verified 2026-09-17: GET https://mdm.abletelsolutions.com/enrollment.mobileconfig returns HTTP 200, 7782 bytes, a real Apple plist profile, no credentials required. ENROLLMENT_DYNAMIC_IDENTITY is absent from /opt/waze-mdm/.env, so the embedded password is inert only because the code default is true - an unset variable is the entire protection. The same password literal is tracked in git at deploy/waze-mdm/enroll/enrollment.mobileconfig:9. Filing as owner queue row 83 with the recommendation to set the flag explicitly and rotate the literal out of the tracked file, and to consider restricting the URL in Caddy only after a bench test of new-device setup-assistant enrolment. Fixes nothing on its own: the point is that a monitor or attacker on a conventional path sees a hardcoded 200 from Caddy for /health, /healthz and /readyz too, so an outage is invisible.
