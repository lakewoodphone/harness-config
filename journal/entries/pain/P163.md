## P163 — journal.py search could not read entry bodies, so recall returned false negatives

MEASURED 2026-09-15 (ZABZ-TECH). `journal.py search` matched TITLES ONLY. `search "inter-start gap"` -> `no match`, while `entries/wins/W136.md` line 6 contains that phrase. `search "watchdog"` returned hits only because those entries carry the word in their headings.

ROOT CAUSE (located, not guessed): `catalog()` (~line 1045) loads entries from the fresh TSV cache; `_from_tsv()` (~line 1059) constructs every Entry with `body="`"` hard-coded (~line 1071); `cmd_search()` (~line 1545) searches `heading + body` (~line 1566). With an empty body, a body-only term can never match.

WHY IT MATTERS: this is the primary recall path the continuity discipline is built on -- the system prompt instructs `search "<words>" --kind lessons`. A false `no match` reads as " his was never recorded", which is precisely how the same audits get recommissioned and the same files re-litigated. Found by an audit subagent (workstream 08), which reported that search returned no match for `kernel`/`sentinel`/`ceo-kernel`/`autopilot` although `L30`/`L29`/`D11`/`L1464` contain those terms.

FIX: delegated to a subagent on branch `fix/journal-search-bodies` in `~/code/harness-config` -- read the body region via the TSV `file`/`line_start`/`line_end` columns (or the existing `index/journal.db` if it already carries bodies), keep every flag's semantics, keep `check` at 0 errors, add a test with a negative control, and report before/after timings for `search`/`status`/`show`.
