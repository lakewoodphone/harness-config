## The test-type backlog is ~2,400 errors, and `prisma-stub.ts` holds a second stale status vocabulary

Two debts, both created by closing `P2873`.

### 1. `phone-and-tech-full` test files now type-check, and they do not pass

Measured 2026-10-08, ZABZ-YOGA, branch `pbp/w2b-status-tests`:

- **2353 error lines** with production strictness, on a pristine `b3d6bdd57` tree.
 Top codes: `TS2339` 1389 (property does not exist), `TS2345` 542, `TS2322` 97,
 `TS2554` 59, `TS2820` 32 ("did you mean…?").
- **2427 error lines** with RELAXED settings (`strict:false`, `strictNullChecks:false`)
 on the same branch after the fixture fixes — which can only have REMOVED errors.
 So relaxing is not smaller; it is marginally larger. The shipped
 `tsconfig.test.json` therefore keeps production strictness.
- `pnpm typecheck` (production, `tsconfig.json`) is **0 errors**, before and after.

The bulk is `TS2339`/`TS2345` from mocks whose shapes drifted from the real Prisma
model — e.g. `Property 'workOrderTimeEntry' does not exist on type 'PrismaClient'`
— not from anything semantic. That is good news for the burn-down: it is
mechanical.

Consequence: `pnpm typecheck:tests` exists and **records** the debt, but a
~2,400-error `tsc` cannot gate CI without turning the authoritative suite red, so
it is not wired into `typecheck`. What IS wired is
`scripts/validate-order-status-members.ts`, which is O(seconds) and has a
zero-error baseline.

What would fix it: burn the backlog down by directory, highest-value first
(`src/services/payments/**`, `src/services/work-orders/**`, the `ai-workspace-*`
suites). Once the count fits, wire `typecheck:tests` into `typecheck` and delete
the vocabulary validator — the general check then covers what the narrow one does.

### 2. `prisma-stub.ts` still declares the three deleted members

`backend/src/types/prisma-stub.ts` declares its own `OrderStatus` enum containing
`CHECKED_IN`, `IN_REPAIR` and `COMPLETED`, all deleted by `d5f3b4831`. Eight test
files import from that stub — none of them for `OrderStatus` — so it does not
defeat `validate-order-status` today.

But it is a SECOND vocabulary that can drift, and `types/work-orders.ts` already
documents the rule it breaks: "THE STATUS LIST IS NOT DEFINED HERE ANY MORE … it
lives, once, in `services/work-orders/order-status.ts`". The one test that starts
importing `OrderStatus` from the stub would silently accept a deleted member and
re-open the exact ten-month hole `P2873` describes, because the stub's enum would
type-check instead of failing.

What would fix it: delete the three members from the stub, and preferably
re-export the real enum from `services/work-orders/order-status.ts` the way
`types/work-orders.ts` does, so the vocabulary has one home.

**NOT changed in this workstream** — `src/types/**` is outside its enumerated lane
(the lane was the named test files plus the `tsconfig`/`typecheck` wiring), and it
is a vocabulary-source change that deserves the review the rename commits got.

Ranking: (2) is five minutes and closes a real hole; (1) is a programme of work.
