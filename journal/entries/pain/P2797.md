## P2797 — Live traffic is unmeasurable from the authority, so every drive-time estimate is a guess with an honest label

WHAT HURTS: on 2026-09-29 the whole evening turned on one number — how long the drive from Lakewood to St George would take at 16:40 on a weekday. Free-flow is measurable (OSRM over OpenStreetMap: 50.8 mi / 84 min). The rush-hour adder is not, from here. Tried and failed tonight: a maps API key (none exists on the authority), headless Google Maps (returned no rendered content), and both authoritative live sources — PANYNJ's crossing times and 511nj — which are JavaScript apps that serve nothing to a fetcher. So the plan carried a 15-35 minute judgement where it needed a reading, and the owner's own navigation app (18:02 → 18:03) was the only traffic-aware number in the whole session.

WHAT IT COSTS: a wrong adder is the difference between catching a boat and missing it — a 30-minute slot — and it is the one input the owner cannot check while driving.

WHAT WOULD FIX IT: one traffic-aware routing source reachable from the authority — either a maps/OSRM-proxy key stored in the secrets store, or a managed headless-browser job that can read Google Maps directions and return the ETA as text. Until then the rule is: label every drive estimate as free-flow-plus-judgement, and give the plan a decision point that does not depend on the estimate being right (tonight's 'be at Turnpike Exit 13 by 17:30' was that, and it worked).
