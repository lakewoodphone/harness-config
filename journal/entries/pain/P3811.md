## P3811 — LPT deploy leaves the app-list config with one package: the drawer shows only Tech Mode

LPT deploy writes the app-list runtime config, and the phone ends up with `allowed_packages: ["com.android.cts.techmode"]` only.

Reproduced 2026-10-18 on E4810 558800292460, deploy `--model E4810 --tier standard --profile
standard-no-text --serial 558800292460`. The `runtime_config` phase reported success and
"Wrote runtime configs: ... com.android.cts.apps4fliplauncher:lpt_app_list_config.json", but the file
on the phone (mtime 17:02, same minute) held only techmode, so the app drawer offered one entry.

Ruled out: the loader. Calling `load_deployment_config(model="E4810", tier="standard",
profile="standard-no-text")` returns `user_app_slugs` = the 12 user apps, and
`_app_list_visible_packages()` yields 13 packages. Pushing that exact 13-package payload by hand
sticks — unchanged after 12 s, and after `am force-stop` + relaunch the drawer reads 13 entries.

So either `_push_external_files_json` wrote a stale/different payload for this run, or the app list
app rewrote the file after the push. Unproven; the check that would have caught it,
`app_list_runtime_config`, is a verify-phase check and verify runs after the phase that wrote the
bad file.

What to look at next: (1) log the payload byte count in `_phase_runtime_config`, and diff the pushed
file against the intended payload immediately after `push_file`; (2) check whether the app list app
writes `lpt_app_list_config.json` on start (its mtime after a launch without a deploy would settle
this); (3) make `lpt verify` accept `--profile` so `apps_installed` (Message+) and
`lpt_keys_runtime_config` (home_message omitted when texting is off) stop failing on every
`-no-text` handset.
