## P2996 — The operational store has no terminal completed status, so 425 of 636 orders including finished-and-paid ones read READY_FOR_PICKUP

**What hurts.** Closed jobs and open jobs are indistinguishable in the operational store.
`orders.status`, read at runtime 2026-10-08, has exactly seven values — `AWAITING_DIAGNOSIS`,
`AWAITING_APPROVAL`, `AWAITING_PARTS`, `AWAITING_PAYMENT`, `READY_FOR_PICKUP`, `CANCELLED`,
`UNFIXABLE` — and **425 of 636 orders sit at `READY_FOR_PICKUP`**. There is no terminal "completed",
and today no `CHECKED_IN` either, though production note 2790 records a 2026-09-03 change ending at
`COMPLETED`: the vocabulary has moved under older corrections.

**Why it is a real problem, not cosmetics.** Order 2774 is a fitted-and-paid HP back cover — 65
collected, `paymentStatus CAPTURED` — and it reads `READY_FOR_PICKUP`. A staff member opening it, or
any list built off that column, phones a customer about a job that finished a month ago. The case
file has read `closed` / `paid` since 2026-09-14, and the 2026-09-14 note claiming the row was
"corrected to `COMPLETED`" is not what production holds — because **`COMPLETED` cannot be written
there at all.**

**What would fix it.** One of: (a) add a terminal value to the enum and to whatever
`website_db.update_order` validates against, then sweep the genuinely-finished rows; or (b) decide
that `READY_FOR_PICKUP` **is** terminal and rename it, so nobody reads it as "not done yet". Either
way it is the shop's decision, and until it is made the write path will keep refusing `COMPLETED` —
correctly, because inventing a status is worse than a stale one.

**The workaround used, so it is reusable:** when a job is finished but the store cannot say so,
**write a note on the order saying plainly that it is closed and paid and must not be chased.** The
status stays wrong; the next human does not.

**Also open on this case and not yet resolved:** there is **no order row anywhere** for the new-laptop
sale — the 500 Dell lives in the case file, in Newegg order #419077624 and in the texts, and in no
work order in either store. Money on the books with no work order behind it.
