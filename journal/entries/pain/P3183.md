## P3015 — The 2026-10-11 cloud cutover left the office box running a shadow company, and it cannot simply be stopped

**What hurts.** The 2026-10-11 authority cutover was executed without a journal entry, without its own
runbook on any machine (`docs/mesh/126-authority-cutover-runbook.md` does not exist in any checkout;
`scripts/mesh/cutover-authority.sh` is uncommitted), and with stage 4 -- the freeze -- skipped or
undone. The consequence is a half-moved company: the public path serves the cloud, while the office box
runs a full second company writing a forked database that several consumers still read, and the
autonomy/wake loop still lives there. Nothing about that state is self-announcing; every surface
answered healthily throughout (PAIN P3, LESSONS L3508).

**Second half.** The office's Dialpad harvesters cannot simply be stopped, because `lpt-dialpad-apply.sh`
-- office-only, and the only bridge from Dialpad events into the shop's operational Postgres -- reads
the office store. Freezing the office before moving that job would stop customer-visible notes. So the
narrowest correct fix is unavailable and the one-writer end state waits on a migration.

**Third.** On the 0.1.7 line the live `profiles/web/cordis.patch.yml` managed block is a BLOCK sequence
while `make-preset-rows.mjs` writes a FLOW sequence, so `--install-target <live>` refuses to write in
place. The correct values are in that block today only because they were substituted line by line.
A regeneration path that works against the live home is the real repair.

**What would fix it, in order.** (1) Move `lpt-dialpad-apply.sh` to the authority, prove it writes,
then strip the office Dialpad cron lines. (2) Move the wake loop as one switch, with a proven wake
fired from the cloud. (3) Port `lpt-hub`/`audit.py` or repoint the case-work skill honestly.
(4) Fix the managed-block shape so the sanctioned generator can write the live home. (5) Move
`harness-config`'s git origin off the box being frozen -- its origin is still
`secretary-ts:/home/zabz/harness-config.git`, and a frozen rollback should not be the trunk.
