## P — one journal id means two different entries, across machines

Found 2026-09-17 by a mining agent with read access to several hosts; verified by direct reads, not inferred. This is the **third** occurrence (the mac-mini's `harness-config` HEAD, `7708e2d15a`, is itself titled "docs/mesh/87: the third id collision, caught live").

- `mac-mini:/Users/lpt/code/harness-config/journal/entries/lessons/L1852.md` (1,968 B, mtime 2026-09-17 00:13:02Z) carries header `<!-- e:lessons|L1852|2026-09-16|ZABZ-YOGA|open -->` and the **same body text as ZABZ-YOGA's L1836** — the lesson "Apple has no MDM call blocker; allowEnablingRestrictions is the Screen Time gate and allowScreenTime is not a real key".
- On ZABZ-YOGA, `L1852` is a **different** entry entirely (the `_wallpaper_label()` site-rank lesson).
- So one id denotes two entries, which is exactly what `journal.py check` calls an ERROR — but `check` only ever inspects one tree, so no per-machine run can see it.
- The trees are also not subsets of each other. ZABZ-YOGA: handoff 340 / lessons 692 / pain 190 / decisions 198 / wins 164 = 1,584. mac-mini: handoff 341 / lessons 675 / decisions 204 / pain 192 / wins 164 = 1,576. ZABZ-YOGA has 17 more lessons; the mac has 6 more decisions and 2 more pain.

**Cause:** ids are allocated per machine at `append` time, so two machines writing concurrently mint the same id over different content, and a later carry keeps whichever numbering it met first.

**What would fix it:** a cross-machine id-consistency pass before any further `append` — at minimum a read-only comparison of `entries/**` filenames + their `<!-- e:kind|id|... -->` headers across the fleet's `harness-config` checkouts, then `journal.py repair-ids --apply` **on the tree that is wrong** (the mac's L1852 should become L1836 with an alias recorded) and a re-`append` of anything that collided. `dedupe --apply` handles exact duplicates; this is not one. Then add the cross-machine check to the harness so it runs on a schedule rather than being rediscovered — three occurrences is a pattern.

**Not done here:** both tools WRITE, and the session had no budget left to verify the convergence across four machines. Recorded rather than half-done.
