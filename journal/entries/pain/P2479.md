## P2479 — Lab mail is classified but never filed: the Weissman arrival email sat unread two days while the case file and an owner-queue row asserted the drive had never shipped

RANKED: high. It stops the system at the exact moment it matters — a counterparty answers, and nobody turns the answer into work.

**MEASURED, 2026-09-24, Weissman case (300DDR ticket #74048).** The lab's automatic arrival email — *"We just received your device! … rate is 500 … Your device is now in our data recovery queue!"* — arrived **2026-09-22 20:15:24Z** (Gmail id `1a0cac24d997a673`). It was classified (`email_triage_log` 2026-09-22T20:39:11Z, so the poller was working) and then **sat UNREAD in the inbox for two days**. Meanwhile:

- the case file asserted the opposite — *"it has NEVER fired for 74048. That absence is evidence… the drive is almost certainly still in the shop"*;
- owner-queue **row #129 asked the owner to go and physically search the shop** for a drive that was already in California;
- a session had written the conclusion up as a **lesson** (`L2079`: the absence of the arrival email is proof of non-shipment), turning a wrong inference into doctrine.

**WHY IT IS SYSTEMIC, NOT A ONE-OFF.** Three things are true at once: inbound mail from a vendor is *classified* but nothing **files** it into the case that owns it; the case file is the only place a session reads on a case; and a wrong belief in a case file is *load-bearing* — it sent a human to search a shop, and it was written up as a rule. The Goldstein case was the same shape (a case file confident about a conclusion the mailbox had already refuted) and it is why the journal keeps saying provenance is the discipline. **The classification proves only that we saw the mail. Nothing proves it reached the file.**

**WHAT WOULD FIX IT.**
1. **A lab/vendor-email → case binding.** Ticket numbers appear in every one of these subjects (`Update from 300DDR: Ticket #74048`). Match `Ticket #NNNNN` against `labEscalation.ticketNumber` in the sync records, and write the message body into a dated case-file section automatically (append-only), or raise a flag when no case matches.
2. **A daily "unpicked lab mail" check with teeth:** any 300DDR/partner message older than, say, 6 hours with no corresponding case-file append since its arrival. The absence of a *filed* action, not the absence of a message, is the signal — the same INSERT-only trap as coms_freshness (D2325).
3. **Never let a case file carry an unbounded negative claim.** "The email never came" must be written with its horizon ("never came as of 2026-09-18 12:00Z") so a later reader knows to re-check, instead of reading it as a permanent fact about the world.

**COST OF THIS INSTANCE.** Two days of a drive sitting unread, an owner-queue row sending the owner on a false errand, a lesson taught the wrong way, and a customer left past a promise while the system believed there was nothing to say.

**EVIDENCE.** `dialpad`-adjacent: mailbox ids `1a0cac24d997a673` (the arrival email) and `email_triage_log` 2026-09-22T20:39:11Z (its classification); case file `weissman-ssd-not-read-8482993187-2026-08-27.md` (the refuted conclusion, marked 🔴 at the end); owner-queue #129 before/after in `~/bin/owner-queue-backup-20260924/`; lpt-hub `e6d643543`; lesson `L2079` (the rule that must be superseded).
