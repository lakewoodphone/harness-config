## P4253 — TOOL_LOOP_DEADLOCK: 36 of 176 weekly failures are an action retried forever because the FIX line names the wrong remedy, and the right one is in a hint nobody sees

`TOOL_LOOP_DEADLOCK` is the company's second-largest failure class and it is caused, for a measurable third of it, by the estate telling the agent to fix the wrong thing.

MEASURED 2026-10-15, 7 days, `/root/authority.db` read-only:

 sessions carrying the marker : 176
 ... where an action is `temporarily disabled` : 36
 ... where the failure is `file not found` : 28

READ IN FULL, session 78859. The agent calls `repo_map` / `repo_read_file` with a `repo_path` that does not exist ON THE AUTHORITY (a Windows canonical path from the company blueprint). The action is circuit-broken after 10 consecutive failures. The session then spends its whole budget re-announcing intent -- steps 5 through 13 are thirteen consecutive "I'll stop re-probing and take the mutating action now", and none of them is an action. The log also shows the STALL-DIRECTIVE firing with the correct advice, which the agent does not take.

WHY THE ADVICE IS WRONG. `chat_action_resilience.py:305` tells it:

 FIX: Use repo_path alias (e.g. personal-secretary, phone-and-tech)

An alias resolves through `resolve_managed_repo_path` (`chat_action_repos.py:92`) to the blueprint's canonical Windows path, then to `~/repos/<repo>` on Linux -- and neither exists on the authority. So the argument is not the problem and changing it cannot help. The resolver ALREADY computes the right instruction and returns it as `hint`: use `github_*` tools, or `scripts/repo-bootstrap.sh <repo>`. **The agent never sees that hint; it sees the FIX line instead.**

THE FIX, bounded: when `resolve_managed_repo_path` returns `exists=False`, the failure is TERMINAL FOR THE SESSION -- no alias, no retry, no argument change can succeed -- so surface the `hint` on the FIRST failure, mark the action non-retryable, and stop the identical-failure counter from spending three strikes on something that can never work. 36 seven-day failures become 36 sessions that are told what to do instead.

SEPARATE, SMALLER, SAME SHAPE: `ps_circuit_breakers` -- the CEO's own tool for reading breaker state -- errors on call with `no such column: action_name`. The real schema is `circuit_breaker_events(agent_id, event_type, reason, spend_at_event, created_at)`. The tool the estate uses to LOOK at this problem is itself broken.
