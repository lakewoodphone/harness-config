## P9868 — A ledger 'done' with a proof block, for work that exists in no commit anywhere

Found 2026-10-22 while advancing the roadmap register. **Ledger 1006 was marked `done` for work that exists nowhere.**

## What the record said, and what the repository says

The ledger row's own attempt text is convincing: it reports adding `docs/BYPASS-TRIAGE.md` (the fields a
finding must carry, triage rules, closure rules, seed rows B-001 and B-002) and
`scripts/check_bypass_register.py` wired into the gate, and it quotes a negative test -
`BYPASS-TEST: B-001: doesNotExist is not in ...AntiEvasionPolicyManagerTest.kt, rc=1`.

Measured, in this session:

* `git cat-file -e origin/main:docs/BYPASS-TRIAGE.md` - **absent**.
* `git rev-list --all --objects | grep -E "BYPASS-TRIAGE|check_bypass_register"` - **no object at all**.
 Not on a branch, not on a remote, not in history.
* `git fsck --lost-found` - two dangling commits, one of which is the model-licence audit already merged
 by content; neither carries these files.

## The mechanism, which is the transferable part

The attempt ran from `C:/Users/ezabz/code/kosher-filter-ai` - the **shared checkout the wake loop switches
branches in**. That checkout's reflog shows it moving from `fix/play-integrity-1078` to
`feat/approval-report-device-1117` at 01:46. Anything written there without a commit is discarded by the
next `git checkout`, and nothing warns anybody.

> **Lesson: a `done` with a proof block is not evidence that the artefact survives.** The proof ran and
> passed; the file was never committed; a branch switch in a shared tree removed it. When a ledger row's
> DoD does not require a commit on a named ref, "done" records an intention, not an artefact.
>
> **Check before trusting a `done` whose product is a file:** `git cat-file -e origin/main:<path>` for the
> path, and `git rev-list --all --objects | grep <name>` for any object at all. If both are empty, the
> work is gone and the row is wrong - do not carry it forward into a register as if it had landed.

This is the same family as journal `P13` (`git add -A` in a shared tree) and the estate's "a branch is not
a deliverable" rule, but one step worse: the work was never even a branch.

## What I did about it

* `X-P6-09` stays **open**, and its body now records exactly what was claimed, what the repository shows,
 and the mechanism - so the next reader does not re-close it on the strength of the ledger text.
* Filed **ledger 1132** to re-create the register and its checker, with a DoD that requires the artefact on
 a merged ref **before** the row may be closed again.
* `A-P4-11` (Play Integrity) advanced to **partial**, not done: the loop's fix is real and good - an
 unprovisioned build now reports "you did not provision this" with four distinct reasons instead of
 "your device failed" - but neither branch of the item's own DoD is met, and the missing input is a
 Google Cloud project, which is an account decision rather than a code change.
