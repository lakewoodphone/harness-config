## P145 — The sourcing venv had no browser binary, and the harvester writes into a checkout that does not exist here

Two frictions hit the moment I tried to run the shop's laptop sourcing pipeline on the Mac mini (LAKEWOOECHSMINI), 2026-09-15:
1. ~/personal-secretary-mvp/.venv has playwright 1.54.0 installed but NO browser: 'Executable doesn't exist at ~/Library/Caches/ms-playwright/chromium_headless_shell-1181'. The cache held chromium-1234 (a newer build) which 1.54 does not accept, so a previously-working machine looked broken by a version skew, not a missing install. Fixed permanently with: cd ~/personal-secretary-mvp && .venv/bin/playwright install chromium (128 MiB + 82 MiB, ~1 min). Anyone who upgrades playwright without re-running install re-breaks every scraper at once.
2. ebay_laptop_search.py computes SEARCH_DIR as REPO_ROOT/'lpt-hub'/... where REPO_ROOT is the personal-secretary-mvp checkout — but ~/personal-secretary-mvp/lpt-hub DOES NOT EXIST on this machine (the checkout only has it on desktop-ts, at C:\Users\ezabz\Code\personal-secretary-mvp\lpt-hub). So the default output path is into a tree that isn't here. Pass --output /tmp/<name>.json explicitly. The same applies to laptop_sourcing.py record.

WHAT WOULD FIX IT: a requirements/readme note that says 'run .venv/bin/playwright install chromium after any playwright bump', and pointing the scripts' output paths at ~/lpt-hub (the real checkout on this machine) instead of the sibling path that only exists on the Windows desktop.
