## P2833 — The mesh fan-out tool is 100% broken: a child is rejected with 'unknown option --- mesh mailbox', and the broker placed it on the dispatching machine itself

WHAT HURTS: the mesh fan-out tool is 100% broken on this machine, and every rule in my operating
model that depends on fanning work out across nodes silently degrades to local work.

MEASURED 2026-10-05, first dispatch of this session. `subagent` was placed by the broker on node
`ZABZ-TECH` — the SAME machine the parent was on — and the child exited 1 in 3130 ms having produced
no final message. The provider's own diagnostic:

 error: unknown option '--- mesh mailbox (read this before the task) --- MESH_MAILBOX={dir:...} ...'
 exit = 1 in 3130 ms (ssh client terminated after the completion frame)
 invocation = C:/Program Files/nodejs/node.exe <npx-cache>/.../@deepseek-ai/dsh/lib/bin.js
 --profile <profile> <task> [interpreter]

CAUSE, located by reading the launcher: `scripts/mesh/Start-AgentFleet.ps1:156` builds

 $argline = '"' + $bin + '" --profile headless "' + $prompt + '"'

The child's prompt is the mesh mailbox preamble, which BEGINS WITH `---`. The remote `dsh` CLI parses
it as an option and rejects the invocation before the agent starts. So the mesh's own framing text is
what breaks the mesh.

TWO SEPARATE FAULTS, and the second is not obviously the same bug:
 1. argument quoting — a task string beginning with a dash must be passed in a way the CLI's parser
 accepts (a `--` end-of-options separator, a dedicated flag, or stdin), never as a bare positional;
 2. PLACEMENT — the broker chose the dispatching machine itself. Fan-out to the local node is not
 fan-out, and it means a "remote" child competes for the same memory the parent is using.

WHAT WOULD FIX IT: the argument-quoting fix (in flight, brief `fleet/dsh-meshfix`), then a re-dispatch
and a placement check. Until a `subagent` call returns a child that reports a hostname other than
ZABZ-TECH, treat every subagent result as LOCAL and say so, and do not claim the fleet ran on the mesh.

EVIDENCE: the full provider diagnostic is quoted in this session's transcript; the launcher line is
`scripts/mesh/Start-AgentFleet.ps1:156`.
