## P3162 — The transcript archive has been dead since the cutover: 4 days of sessions exist in one place only

VERIFIED 2026-10-13 13:4xZ by me, on the box that holds it. The owner's standing rule
(2026-10-09) is that every DSH session and every VS Code Copilot chat is archived forever and
"A copy must always exist off the machine that wrote it."

THE ARCHIVE HAS BEEN DEAD SINCE THE CUTOVER.

 * The raw archive is `secratary:/home/zabz/lpt-transcripts/` -- 5.5 GB, last written
 **2026-10-11 20:23Z**, on the office box that was FROZEN at 05:43:36Z the same day.
 * `/home/zabz/.transcript-archive/status.json` on that box reads:
 "at": "2026-10-11T20:23:01Z", "pull_rc": 3, "check_rc": 2
 and lists as SILENT `secratary` (last contact 65.5 h) and `zabz-yoga` (64.0 h).
 * Coverage it last measured: `zabz-yoga` **dsh-sessions last arrival 2026-10-09T04:22Z**
 with 109 files; `zabz-yoga` dsh-attachments last 2026-10-09; `secratary` dsh-attachments
 last 2026-10-09.
 * **The authority does not have the archive at all.** `secratary-cloud` has no
 `/root/lpt-transcripts`, no `/root/.transcript-archive`, and no status file.
 * `AGENTS.md` §1 says the raw archive lives on the authority and is driven hourly by cron
 from the always-on host. Both halves are false on the box the file is about.

CONSEQUENCE NOW: **four days of this laptop's DSH sessions -- including the whole of this
evolution program -- exist on exactly one machine and in no archive.** The same is true of
`secratary-cloud`'s own work since 10-11. This is the exact failure the rule was written to
prevent, and it is invisible because the only thing that would report it (the check) is on the
box that stopped running.

SECOND, SMALLER CORRECTION: an audit child reported that `AGENTS.md` names
`scripts/push_vscode_chats.py` and `scripts/vscode_chat_extractor.py` and that "neither exists".

`personal-secretary-mvp/scripts/` (24,934 B and 35,494 B). The section's host and path claims are
what is wrong, not the filenames.

WHAT WOULD FIX IT: run the pull from the authority (where the always-on cron now is), move or
mount the archive store there, and make the staleness check run from a machine that does not
depend on the machine being checked. The scripts already exist
(`scripts/transcript-archive-run.sh`, `transcript-archive-pull.py`, `transcript-archive-server.py`)
and only their host is wrong.
