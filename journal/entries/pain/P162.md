## P162 — A device attached to a household is not visible to a scoped admin until it logs a hello

Spent a debugging cycle in kf2/measures-reader convinced my scoping was broken: a tenant_admin with one device reported no visible devices, and the route correctly (but confusingly) returned an unmeasured report. Root cause was the test seeder, not the code: POST /admin/households/{id}/phones writes only the phone_households mapping, while every device scope in app/admin_scope.py reads the phones table via list_phones - and that row is created by log_hello, i.e. by a device checking in. So a household-attached device with no hello is invisible to every tenant/household-scoped surface (not just mine). Fix in the seeder: call storage.log_hello(phone_id, ...) after the mapping, and assert list_phones(tenant_id=...) is non-empty so a future empty-layout seeder fails loudly instead of turning scope tests into empty-fleet tests. Would be fixed properly by a scope helper that joins phone_households directly, or by /admin/households/{id}/phones inserting the phones row.
