## P170 — curl -fsS health gates in restart.sh and verify-production.sh turn a degraded 503 into did-not-start - and my 90s revert all-clear was too short to prove the loop stopped

MEASURED 2026-09-15 20:41 UTC, secratary.

THE GATE, IDENTIFIED. W1's `/health` 503 branch broke production because these callers use `curl -fsS`, and `-f` makes curl exit non-zero on any 4xx/5xx -- so a dead write path looked identical to "the server did not start":
 - `scripts/server/restart.sh:10` `curl -fsS http://localhost:8002/health`
 - `scripts/server/verify-production.sh:11` `curl -fsS http://localhost:8002/health >/dev/null`
 - `scripts/secretary-startup.sh:43` reads the status code directly
This is a LATENT DEFECT independent of W1: any future change that makes `/health` return non-2xx for a reason other than "down" will trip launch and verification gates. Before the next /health change, these three callers must be taught to distinguish "degraded but serving" from "did not start" -- otherwise the next person to improve health reporting reproduces this exactly. W1's own agent flagged this in its report; credit to it for surfacing it.

HONEST LIMIT ON MY REVERT VERIFICATION. I reverted W1 at ~20:36 and observed 90 seconds with **0 API starts, 0 process exits, 0 probe warnings** -- and I reported the loop as stopped on that basis. Re-reading the same system 5 minutes later: `api starts last 20m` = **14**, and the watchdog counter moved 296 -> 300. That 20-minute window STRADDLES the revert, so it very likely includes the pre-revert storm, and the watchdog rise could be entirely pre-revert too. But I cannot prove that from what I measured, and a 90-second window is too short to establish absence for a fault whose period was ~2 minutes. **Do not treat "the restart loop is resolved" as verified.** The confirming measurement is one hour of clean starts after the revert, and it has not been taken.

RULE: a 90-second all-clear after a revert is an observation, not a resolution. For a fault whose observed period is minutes, the absence claim needs a window at least an order of magnitude longer than the period, and it must be stated with the window length attached.
