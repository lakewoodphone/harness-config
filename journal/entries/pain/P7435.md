tests/test_department_tools.py::TestMultiTurnExecution::test_execute_approval_needed_suspends_step
fails on the authority, and it is NOT mine: it fails identically at 22bf850b5^, the commit
before the SMS policy change.

 tests/test_department_tools.py:1015

The test patches `app.copilot_client.copilot_chat` and `app.services.agent_worker.
_execute_tool_with_autonomy` to return ("Requires approval", False, "APPR123"), then
asserts the step suspends. The captured log shows the worker never used that mocked
return -- it went to the gateway: "step None round 1 recovered via gateway fallback model
deepseek/deepseek-v4-pro". So the approval result is produced by a path the mock does not
cover, and the test has drifted away from the worker rather than from policy.

Not fixed here on purpose: it needs the fallback path in agent_worker understood first,
and the fix is either a mock seam or a behaviour decision -- neither belongs in a session
about who a text came from. It is recorded so it stops being invisible.

Scope check: no phone number, no policy target, gmail_send only. The SMS owner_target
branch is not on its path.
