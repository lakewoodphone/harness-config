## P2994 — Mandatory [string] parameter refuses an array argument, and @stringSplat passes characters

A PowerShell `param([string]$X)` DOES accept an array normally, but the moment the parameter is marked `[Parameter(Mandatory = $true)]` PowerShell 7.6.6 REFUSES array -> string coercion at binding time and throws "Cannot process argument transformation on parameter 'X'. Cannot convert value to type System.String."

Measured 2026-10-08 on ZABZ-YOGA, pwsh 7.6.6, while fixing the `param($Args)` bug in lpt-flip-phone:
 function x1 { param([string]$y) "y='$y'" } ; x1 -y @('a','b') -> y='a b'
 function x3 { param([Parameter(Mandatory=$true)][string]$y) ... } ; x3 -y @('a','b') -> THROWS

Consequence: three helpers in lpt-flip-phone (scripts/utilities/Get-MmsPermissionState.ps1, Invoke-MmsStep.ps1, New-MmsForensicRun.ps1) declare `[Parameter(Mandatory=$true)][string]$AdbArgs` while their call sites pass arrays such as @('shell','dumpsys','telephony.registry'). After the `$Args`->`$AdbArgs` rename those helpers bind the value (no longer silent) but still cannot run the command: array call sites THROW, and scalar-string call sites (e.g. 'shell pm grant X Y') do `@AdbArgs`, which splats the string CHARACTER BY CHARACTER and adb answers "unknown command s".

What would fix it (NOT applied - the delegated brief forbade behaviour changes beyond the rename):
 1. change the declared type [string] -> [string[]] so array call sites bind; and
 2. for the call sites that pass one space-joined string, split it in the helper the way scripts/deployment/Audit-E4810Messaging.ps1 already does: $la = ($AdbArgs -split ' ' | Where-Object { $_ -ne '' }) then splat @($la).
The type change alone fixes the array call sites (13 of them) but leaves the space-joined-string call sites broken.

Evidence of the fix direction, same day: with the body unchanged and only the type widened to [string[]], `Invoke-Adb -Serial 616462586 -AdbArgs @('shell','getprop','ro.product.model')` returns E4610.
