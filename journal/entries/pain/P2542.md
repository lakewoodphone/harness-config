## P2542 — 26 identical outbound SMS to one customer in one day - the send path has no duplicate guard

## P — 26 identical outbound SMS to one customer in a single day; the send path has no duplicate guard

**What is measured.** `dialpad_sms_cache`, phone `8485258603` (ticket 73459 at 300DDR),
`created_at LIKE '2026-09-20%'`:

- **26 rows, 26 distinct `message_id`s, 1 distinct body.**
- First 2026-09-20 03:17:05Z, last 2026-09-20 20:09:15Z — roughly one every 30-40 minutes for 17 hours.
- Body, identical every time: *"Hi, update on your USB drive: the lab's chip-off worked and they read
 the chip, but the first file rebuild was only partial, so they're re-running it with a different
 tool. About another week for the full result. Nothing..."*

This is not one row read 26 times and not a cache artefact — 26 `message_id`s means the carrier
accepted 26 deliveries. The customer received the same message 26 times.

**Why it hurts.** This is a live customer on a $700 chip-off case the shop has already told to
expect a callback. It is also exactly the class of incident the outbound rules exist for, and it ran
for 17 hours without anything stopping it. Worse, the customer's own channel is the one we cannot
re-read: the damage is in her phone, not in our database.

**What would fix it.** A duplicate guard on the send path keyed on
`(phone_normalized, sha256(body))` inside a rolling window, enforced where the send is *accepted*
rather than where it is queued, plus a per-phone hourly send ceiling that trips a circuit breaker and
writes one row. `outbound_buffer.py` already has retry/backoff; the gap is that a retry that
actually succeeded looks identical to one that did not, so nothing dedupes. Measure after the fix
with the same query: `count(DISTINCT message_id)` for one phone-day must be ≤ the number of distinct
bodies.

**Not yet investigated:** whether the other 7 live lab cases show the same pattern, and whether the
loop came from `outbound_buffer_flush` or from the case-update path directly. Do that first — the
size of the blast radius is unknown and the query is one line.
