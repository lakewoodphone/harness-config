## P3013 — The case-to-order link lives in six places and the push tool only writes it back for orders it created itself

The link between a customer case and its production order lives in SIX different places and no two consumers read the same subset: `workflow.orderNumber` (audit.py C11 AND sync-health-audit.py), `references.orderNumber` (audit.py C11 only), `references.productionOrder.orderNumber` (both), `references.websiteOrder.orderId` (the push tool's duplicate guard), `references.workOrderId` + `ticketNumber` (the contract matcher order), and the case file's front-matter `work_order:`.

MEASURED 2026-10-11 on WO26100812739: a case file, a live production order, a schema-valid sync record, three photographs and two notes on the order - and `sync-health-audit.py` still listed it as a recent active prod order with NO lpt-hub case, because the record carried none of the fields that verifier reads. Filling them took the reverse-gap count 16 -> 15.

ROOT CAUSE: the push tool writes the order id back into a sync record only for an order IT created. Every order created by `lpt-write order create` leaves the record born unlinked - which is the whole 2026-10-08 intake batch: nine real cases (Senzer, Pearl, Schreiber, Niasoff, Gestetner, Reifman, Bohrille, Kenchitz, Sayagh), three of them with front-matter `work_order` still empty.

FIX: write every home, not one (documented in CROSS_REPO_CUSTOMER_SYNC_CONTRACT.md and skill section 7). Better: one accessor that all verifiers share, or the write-back moved into the case-creation path so a record is never born unlinked.
