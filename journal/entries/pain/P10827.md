## P10827 — An appointment documented in a dossier was on no calendar and in no reminder - the owner had to ask

## P2888-class again: an appointment can be fully documented and still not scheduled — the owner asked "is today my food stamps appointment?" and nothing in the estate could answer it

WHAT HAPPENED (2026-10-22, 11:44 UTC / 07:44 EDT, secratary-cloud): the owner asked whether today was his
food-stamps appointment. The answer was **tomorrow**: NJ SNAP interview, case **C202417015**,
**Fri 2026-10-23 08:00** America/New_York, Ocean County Board of Social Services, rescheduled from a
missed 09/03/2026 interview (letter dated 10/15/2026).

The record existed — and nothing scheduled it:

- `/root/phone/snap-2026-10-23/` holds `letter.jpg`, three crops and `dossier.md` (written 2026-10-20 02:07 UTC).
 Its §6 *specifies* the calendar entry. It was never created: `calendar_events` on the authority holds
 **1 row in total**, latest `start_time` 2026-03-01.
- Google Calendar — the calendar he actually uses — read live 2026-10-22 11:47 UTC via
 `GET /calendar/events?days=30&all_accounts=true`: 5 accounts authenticated, **0 events in the next 6 days**,
 2 in 30 (a Bar Mitzvah 10/29 and an anniversary 11/15). No SNAP event on any account.
- `reminders`: 65 pending, **none** about this interview. The only SNAP row is 564, the 2026-10-07
 "sign up for gov programs" reminder that P2888 records as silently held.
- The dossier's own plan row "Wed 10/21 — call 732-370-8854, is Friday's 8:00 interview by phone or in
 person?" has no reminder, no task and no record that it happened. A step written in markdown has no actuator.

WHAT I DID: created the event on `eliyahuzabrowsky@gmail.com` — id `tvidphhg3knl5plm69vcb02gtc`,
2026-10-23 08:00-08:30 America/New_York, popups 90 and 15 minutes before, description carrying the case
number, the county line and the documents list. Verified twice: `GET /calendar/events?days=3` returns it
`confirmed`, and a direct `events().get` from Google returns
`start.timeZone=America/New_York` and `reminders.overrides=[{popup,90},{popup,15}]`.

WHAT STILL HURTS: nothing here watches a dossier for the appointments it names. The failure is not
"we forgot" — it is that the only thing that knew the date was a folder nothing polls, and the only
delivery channel that would have told him (reminder SMS) is held by the urgency gate (P2888, still open).
WHAT WOULD FIX IT: when a dossier like this is written, it must create the calendar event and a reminder
as part of the same act, and the handoff must state the event id — not "calendar entry: <spec>".
