## P2893 — Backend ESLint cannot fail CI - the implicit shell has no pipefail, and enforcing it now would block every PR

**What hurts.** `Lint Backend` in `pr-precheck.yml` cannot fail. Its step's implicit GitHub shell (`bash -e {0}`) has no `pipefail`, so `pnpm -w run lint:backend:json 2>&1 | tee /tmp/backend-lint.log || { LINT_EXIT_CODE=$?; exit $LINT_EXIT_CODE; }` never enters the `||` block — the pipeline returns `tee`'s 0. Measured 2026-10-09, PR #342, run 37876302907: job concluded **success** with 568 files, **41 errors, 59 warnings** and `##[error]` annotations in its own log. `pr-precheck.yml`'s frontend lint step is fine because it sets `set -o pipefail` in the script; the backend step is the one that was missed.

**Consequence.** Backend ESLint errors are unenforceable. The `aggregator` reads `needs.lint-backend.result`, so a job that cannot go red means `CI Validation (PR Pre-Check)` — a required check on `test` and `main` — cannot go red for backend lint either.

**Why it was not fixed on 2026-10-09.** Adding `shell: bash` or `set -o pipefail` alone converts the 41 errors into a `Lint Backend` failure, which fails the `aggregator`, which fails the required `CI Validation (PR Pre-Check)` — blocking **every** pull request in the repository. That is the same "gate nobody can open" defect that `docs/development/required-checks-must-always-report.md` was written to prevent, rebuilt deliberately.

**What would fix it, in order.**

1. Clear the backlog: 41 errors (mostly `import/order` and `@typescript-eslint/no-unused-vars` in `backend/src/cli/waze/**`) plus 59 warnings. `pnpm lint:backend` locally reproduces it exactly; `eslint --fix` covers 31 of the 41.
2. Then make the step propagate the exit status — add `shell: bash` to that step (GitHub's explicit `shell: bash` is `bash --noprofile --norc -eo pipefail {0}`), or put `set -euo pipefail` at the top of the `run:` block.
3. Then prove it can go red: break one import order on a throwaway branch and confirm `Lint Backend` fails. A gate that has never been observed failing is not known to be a gate.

**Blast radius if it is left alone:** the repo's stated backend lint policy (`--max-warnings=0`) is decorative; nothing enforces it.

Repo write-up with the same finding: `docs/development/required-checks-must-always-report.md` (added by PR #342).
