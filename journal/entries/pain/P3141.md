## P3141 — Mesh children land on nodes without the repository, so nothing that builds can be delegated

## P3139 — Mesh children land on machines that do not hold the repository, so a fleet on this estate is briefed around ssh

Measured 2026-10-12, from ZABZ-YOGA, four `subagent` dispatches in one message:
placements went to `zabz-tech-linux` (three of them) and `secratary` (one). The
mesh was healthy — every child ran and returned a full report — but **none of those
three machines holds `phone-and-tech-full`**:

| node | repo present |
|---|---|
| `zabz-tech` (desktop-ts) | **yes** — `C:\Users\ezabz\code\phone-and-tech-full` |
| `zabz-tech-linux` | no (`/home/zabz/code` holds harness-config only; 25.8 GiB free) |
| `secratary` | no |
| `zabz-yoga-1` | yes, and it is the machine being routed away from |

The broker ranks by capacity, not by working set, and `prefer-remote` sends work
away from the dispatching host — so the one machine with the checkout is the one
most likely to be skipped. Nothing in the placement rationale mentions the repo.

**The workaround that worked, and should be the default here:** every brief carries

```
Your own host probably does NOT hold the repository. All repository commands run
on ZABZ-TECH: ssh desktop-ts "<powershell command>"
Test first: Test-Path C:\Users\ezabz\code\phone-and-tech-full
```

All four children read the repo, the branches, the live databases and the live
hosts through that one hop and produced usable audits. It costs a few seconds per
command and requires no orchestration change.

**What it rules out:** dispatching anything that must EDIT the repository, or run
its test suite, as a plain mesh child. Those need either a node-restricted roster
(`MESH_TARGET_NODE` exists in the static provider, `lib/placement.js`), or the
worktrees staged on every node, or — what this session did — the manager editing
in the one local clone and running the suite on ZABZ-TECH over ssh.

**What would fix it properly:** make the repository a placement input, so work
that names a path is placed on a node that has it, and say so in the rationale the
way the transport and disk lines already do. Until then, `docs/mesh/*` should say
plainly: *a mesh child can read this estate, but it cannot build in it.*
