## P2900 — 133 git worktrees hold 130.2 GB against 43 GB free - the one-worktree-per-workstream model has no removal step

MEASURED 2026-10-09, ZABZ-YOGA, by walking every worktree.

 133 git worktrees exist for phone-and-tech-full
 130.2 GB held
 C: has 43 GB free

That is ~1 GB per worktree, which is node_modules: each agent worktree that ran `pnpm install`
pays for its own. The count is not incidental - it is the residue of the one-worktree-per-workstream
model, and nothing ever removed one.

WHY IT IS NOT A BULK DELETE
A worktree holds uncommitted changes that exist nowhere else. Deleting one with a dirty tree destroys
work. The fleet tooling keeps branches (`agent-fleet rmall` drops the worktree, keeps the branch), so
the risk is uncommitted work, not committed work. There is precedent that this bites: the repo
already carries `wip(preserve): uncommitted <topic> work rescued by the orchestrator before any
worktree cleanup` commits on `fix/hours-truthful-20260916` and `fix/hours-single-source-20260916`.

THE CORRECT PROCEDURE
1. List every worktree with `git -C <wt> status --porcelain` and its HEAD.
2. Any dirty worktree: rescue the diff onto its own branch first (the `wip(preserve)` pattern), or
 leave it alone.
3. Any worktree whose branch was deleted in the 2026-10-09 prune (312 branches went): those hold no
 unique committed work, so they are safe once (2) is satisfied.
4. Remove in batches, never the five ACTIVE ones: _lpt-idx (the origin/test reading base),
 _lpt-state, _w30-truth, _w31-auth, _w32-gate.
5. `git worktree prune` afterwards.

WHAT WOULD FIX IT SYSTEMATICALLY
A worktree is created by the manager and nobody is assigned to remove it. The fleet scripts have
`rm`/`rmall`; the discipline to run them after integration does not. Either the integration step ends
with the cleanup, or a scheduled job reports worktrees older than N days with their dirty state so
the leak is visible before it is 130 GB.

NOT VERIFIED
The 130.2 GB was measured by summing file lengths under each worktree, which double-counts hard
links if git used them (it does not, for worktrees). It is an upper bound on reclaimable space, not
a promise: some of each worktree is the checked-out source, which is real and cheap.
