## P239 — An installed host-plane row is silently reverted from ~/.dsh every 15 minutes unless it is committed, and nothing says so

WHAT HURTS (measured 2026-09-17, ZABZ-YOGA)
1. `mesh-provider-install.ps1` copies profiles/web/cordis.patch.yml and the zabz preset into ~/.dsh -
 and those copies are only as durable as the commit. `scripts/autosync.ps1:358-380` then runs
 `sync.py` FROM A HEAD SNAPSHOT every 15 minutes (task PersonalSecretary-HarnessSync), so the
 installed rows were reverted to a placement-less layer 15 minutes after they were installed:
 09:32:40 applied -> 09:47:17 reverted, the placement version kept as
 cordis.patch.yml.bak-20260917-134717. Nothing warned. Nothing failed. The layer just went back.
2. Consequence: "I installed it, it is inert until the engine restarts" was a claim with a 15-minute
 expiry, and it was acted on - the idle restart window was briefed on that premise, and its own
 post-restart verification (the composed configuration carries placement/brokerSsh/brokerUrl) would
 have FAILED, because the layer it would compose does not carry them. (The package code would still
 have fallen back to broker mode, so the failure would have been "verification failed" rather than
 "placement did not work" - the more dangerous of the two, because it looks like a false alarm.)
3. It is invisible to every check that reads the live file rather than the composed tree, and it is
 invisible at INSTALL time - it only shows up at the next :02/:17/:32/:47 tick.

WHY IT IS NOT ALREADY "WORKING AS DESIGNED"
The snapshot apply is deliberate and good for committed config: it stops another session's half-written
file being published. What is missing is the other half of that sentence: with no commit, an installed
host-plane row cannot survive. There is no signal that distinguishes "this live file matches HEAD" from
"this live file matches HEAD because I reverted someone's install".

WHAT WOULD FIX IT
a. `mesh-provider-install.ps1` says, at the end of every apply, whether HEAD carries what it just
 installed, and if not, names the exact `git add` that makes it durable. (The idle window already
 does this for the placement rows and warns; the installer is the right place for it.)
b. The window's own record keeps the warning (it does: warnings[] in the marker), so the next reader
 sees that a later restart would boot the old layer.
c. The 07:00 window's step 3 already stages profiles/web/cordis.patch.yml - the once-a-day path
 commits it; only the between-times path is exposed.

NOT FIXED HERE, DELIBERATELY: this session's brief was one window script, one document and one task.
The commit of profiles/web/cordis.patch.yml is a human/parent decision, because the same commit would
carry about twenty other paths another stream is mid-edit on.
