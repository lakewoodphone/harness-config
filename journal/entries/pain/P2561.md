## P2561 — Ranked 2026-09-28: unmergeable journal ids, tmpfs /tmp, silent job failure, an owner queue that is partly mine

**Ranked, with what would fix each. Written 2026-09-28 after a session in which the first three were all live at once.**

1. **The journal cannot be merged across machines, and it is merged every few days by hand.**
 Root cause: ids are allocated locally from overlapping bands (`journal/alloc/bands.tsv`) while
 two hosts write entries independently, so the same id is handed to two different entries.
 Measured 2026-09-28: merging origin into ZABZ-YOGA produced **51 add/add conflicts where the
 same id holds two different entries**, every one materially different. The store's own check
 cannot see it — `journal.py check` reads one file per id — so it is invisible until someone
 merges. `repair-ids` exists and heals it, but only after the merge.
 **Fix:** make allocation race-safe (one allocator, or claim through the authority), and put a
 `journal.py`-aware merge driver or a `pairs`-after-merge gate in `scripts/autosync.sh` so a
 merge that would land duplicate ids stops instead of committing.
 **Cost so far:** a full session on 2026-09-17 (1249 paths deleted by a journal push, reverted),
 a merge with 21 id collisions on 2026-09-22, and 51 on 2026-09-28.
 → this entry, item 1.

2. **`/tmp` is a tmpfs sized 50% of RAM, and one large file there breaks every job that uses it.**
 `/tmp/livecopy.db`, 9.8 GB, filled the 12 G tmpfs at 03:23Z on 2026-09-28 and silently killed
 both comms harvesters for thirteen hours. Rediscovered as "the harvest is broken", never as
 "the disk is full", because a failed heredoc hangs instead of erroring.
 **Fix, in order:** (a) nothing legitimate writes a multi-gigabyte file to tmpfs — find and stop
 the producer; (b) a `tmpfiles.d` lifetime for `/tmp` so orphans are reaped; (c) a kernel check
 on tmpfs usage, since no current check would have caught the full filesystem itself.
 → this entry, item 2.

3. **A failure in a scheduled job can look exactly like an empty result.**
 The harvest logged `FAILED ... output=<empty>` three times per half hour for thirteen hours and
 nothing raised it; the kernel only reported the age of the data. Between "job failed" and
 "channel quiet" the system has no distinction at the point of failure.
 **Fix:** scheduled jobs write a heartbeat AND a last-error line, and a check reads both; the
 harvest scripts now have the first half of this.

4. **The owner queue is 23 rows and still growing, and four of its items are this agent's, not his.**
 `#174/#180/#181` (Moishe Bachrach: SIM failure on device #36, whether Daniel confirms with
 Eliyahu before sending) are answerable from standing policy; `#170/#173` (LabCorp results) are
 answered in their own context; `#177` (a quarantined work order) is an engineering fault.
 **Fix:** audit the queue weekly against the question "could I have solved this?" and resolve
 everything that fails the test. The queue is a decision queue, and a row that is not a decision
 is an admission that was never owed.
