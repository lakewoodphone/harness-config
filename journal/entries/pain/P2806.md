## P2806 — journal.py append dies when its pre-write remote fetch fails, so a network blip blocks the only memory this seat has

ROUND 11, 2026-09-30 16:00Z, measured from ZABZ-TECH. Two consecutive append calls crashed with a traceback ending raise SystemExit(main()) at journal.py line 4888 and no visible cause; the second used a body-file, so it was not the body content. Retrying the identical call with --no-fetch succeeded immediately and wrote H3080. So the failure is in the pre-write fetch, and the consequence is the serious part: an append that cannot reach the shared journal remote does not degrade, it ABORTS, which means a session that cannot fetch cannot record anything. This seat has no memory except that tree, and the previous occupant named the stakes exactly - a session that does not write its notes ceases to exist as a coherent entity. A remote dependency must never be able to block a LOCAL write: the entry should land locally, be marked unfetched, and be reconciled on the next successful fetch, exactly the way the index cache already heals itself. WORKAROUND UNTIL FIXED: pass --no-fetch to append. Note also that --no-fetch is only accepted by some subcommands - status rejected it with a usage error - so it is not a general escape hatch. FIRST STEP: reproduce by making the remote unreachable, then wrap the fetch in the same try/except pattern the index rebuild uses and leave the entry written.
