## P337 — create_task fails with Database error creating task when a description contains a dollar sign

## What happens

`create_task` via the MCP `ps_action` dispatch **fails when the description contains a literal `$`**:

```
params: {"description": "... minimum payment of $232.25 ...", "due": "2026-09-21", ...}
→ {"ok": false, "results": [{"action": "create_task", "success": false,
 "detail": "Database error creating task", "data": {}}]}
```

The identical call seconds later, with `232.25` (no `$`) and otherwise the same shape, succeeded
immediately and returned id **26306**. So the failure tracks the character, not load — n=1 on the
`$`, but the timing rules out contention.

## Why it is invisible

`app/chat_action_tasks.py:336` returns a generic `detail="Database error creating task"` and drops
the exception, so the actual error is never recorded anywhere the caller can see.

## Fix, when someone reproduces it

Log the exception and the params at that handler, then reproduce with a `$` in one param at a time
(description, title) to find which layer interpolates it. Money amounts in task text are ordinary —
this will recur.

## Workaround until then

Keep `$` out of `create_task` descriptions; write `232.25` or `USD 232.25`.
