## P221 — The phone gate keeps being killed, and the only supervisor available is the one-minute watchdog

Measured repeatedly on 2026-09-16: the gate process dies silently (banner printed, no traceback,
no Application-event-log entry, gate-3086.err 0 bytes) while main() is an infinite accept loop, so
it is killed rather than crashing. Deaths observed: pid 19592, 7248, 17312, 28448, 9020 (ZABZ-TECH)
-- the last two under pythonw.exe, so the console-close hypothesis was wrong. The DSH Process
Reaper is excluded: dsh-reap.ps1:70 only matches node|cmd|conhost|pwsh|powershell. Every gate that
was started by a scheduled-task-free path from inside a tool call or an ssh session has eventually
died; a gate started on ZABZ-TECH inside an ssh session died the moment the session closed.
WHAT ACTUALLY KEEPS IT UP: `dshw.ps1 ensure`, which now checks the gate first and runs every
minute as the user. Measured self-heals: 22:56Z (pid 22196 -> 9020) and 22:06Z (pid 28448 -> 11428).
COST: up to 60 seconds of a published 502 after every death, which a phone sees as "site cannot be
reached". Acceptable now, not acceptable as the end state.
WHAT WOULD FIX IT: one elevated action to register the `DSH Phone Gate` scheduled task
(scripts/Install-PhoneGate.ps1 is written and ready; registering a task is DENIED on the laptop
because BUILTIN\Administrators is present but marked "deny only", a UAC-filtered token). A task
owner is outside every agent process tree, which is the property that matters.
STILL UNKNOWN, and it should be chased: WHO kills it. The experiment that would settle it is a
wrapper that records the exit code and the elapsed time, running the gate from a context nothing
else touches.
