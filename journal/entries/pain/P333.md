## P333 — Four mesh defects the false 'Mesh ingress repaired' spam was hiding

Ranked, with the fix for each. All four were found while diagnosing the
watchdog's false "Mesh ingress repaired" spam on 2026-09-19. The spam itself is
fixed (commit 7d4588e8a); these are what it was hiding.

1. mesh_status.py reports the wrong machine's drift. The "desktop" block is
 built from `_local_node()`, which measures WHATEVER node runs the script,
 yet the violation text says "desktop". Run it on the laptop and the
 laptop's own commit drift is reported as the desktop's. A `hostname` field
 was added, but the LABEL is still wrong and the messages still say
 "desktop".
 FIX: name the measured host in the local-node violation strings, or split
 the local-node block out from the desktop contract entirely. Cheap; not
 done because it changes report text other tooling might match.

2. ZABZ-YOGA's API runs autopilot. mesh_status reports "desktop autopilot
 enabled (split-brain: desktop must not run a second CEO; secretary is
 canonical)" — measured on the laptop, the laptop's API has autopilot on.
 If the single-CEO contract means anything, a second node running an
 autonomous loop is the same split-brain the contract forbids.
 FIX: decide whether the laptop may run autopilot; if not, pin it off in the
 laptop's .env and restart, exactly as was done for the desktop.

3. The desktop's API is unreachable off the office LAN. `Test-NetConnection
 100.85.153.96 -Port 8002` is False: the desktop listens on 127.0.0.1 and
 192.168.50.138 only, with no Tailscale binding and no portproxy for its
 Tailscale address. Secretary DOES answer on its Tailscale name, so the mesh
 is asymmetric — the desktop can be reached only from inside the office.
 FIX: add a portproxy for the Tailscale address on the desktop (needs an
 ELEVATED run there; cannot be done from the laptop, and could not be
 verified from here, so it was not done blind).

4. ZABZ-YOGA's public tunnel is dead and the watchdog keeps saying so.
 "cloudflared.exe not found ... Tunnel disabled." every ~2 minutes, plus
 "TUNNEL DOWN. Restart #1" cycles. This is probably CORRECT and merely
 noisy — the contract says secretary is the canonical public origin, so the
 laptop should not be serving the site. The watchdog still tries, and fails,
 on every cycle.
 FIX: on nodes that are not the canonical origin, disable the tunnel
 supervision entirely instead of re-discovering its absence forever. Same
 class of bug as the one just fixed: a check that cannot succeed, retried
 on a loop.

NOT CHANGED, DELIBERATELY
- 150 bogus `activity_log` rows already written by the false violation are

 context.
- 29,773 false lines remain in .runtime/logs/watchdog.log. It rotates at 5 MB
 and keeps 5 .bak, so it will age out on its own. Left as evidence.
