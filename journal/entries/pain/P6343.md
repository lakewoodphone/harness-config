## P6343 — sync.py exits 0 while skipping a step, and the authority could not run the row generator at all

Two mechanisms, one shape: a step that did not happen read as success.

(a) `scripts/sync.py` returns `max(plugin_status, sampler_status)`. The presets/profiles SKIP decisions and the `verify_loaded_surface` verdict never reach the exit code, so a REFUSED profile publish exits 0. This is round 5's finding and it is still open. The mechanism is what let a stale persona sit on ZABZ-TECH and `secratary-cloud` for days while the 15-minute sync task reported LastTaskResult=0 (measured 2026-10-15: `PersonalSecretary-HarnessSync` on ZABZ-TECH, last run 10:02, result 0, next 10:17, persona stale).

(b) `secratary-cloud` could not run `node scripts/make-preset-rows.mjs` at all: `dsh-update/lib/yaml.mjs` threw `cannot resolve a usable "yaml" package` because there is no `node_modules` beside `/root/code/harness-config`. The authority's generated rows were therefore stale with no signal of their own. FIXED 2026-10-15 with `npm install yaml --no-save --no-audit --no-fund` run in `/root/code` - one level ABOVE the checkout, so the checkout is untouched and the resolver's documented search path finds it. Verified: `make-preset-rows.mjs --check` now runs and reports real DRIFT instead of a module error.

Fix for (a) is a change to sync.py's return value; not yet made.
