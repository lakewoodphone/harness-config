## P166 — Chip's 2026-09-15 sends bypassed the production reply path entirely - unknown producer, and it is the same day he sent canned lines to one member at a time

WHAT HURTS
Four pieces of evidence agree that something OTHER than personality._worker produced
Chip's 2026-09-15 messages:

1. chip_last_reply_at in the family chat DB is still 2026-09-04T15:48:01Z. _record_reply
 sets that on every reply, so if _worker had run, it would have moved.
2. chip_monthly_spend is 0.0 for 2026-09; _record_reply also bumps that on every reply.
3. chip_mood is unset, and _maybe_drift (which runs after a successful send) would have
 set it with 30% probability per reply.
4. Twilio shows 19 hub sends on 09-15 between 15:48 and 15:53 whose bodies are NOT in our
 messages table at all, including two test-looking replies ("Loud and clear, ETZ -- one
 pass, no dropped messages, no ties"; "Morning, Eliyahu! All quiet on the server") and a
 group send of a canned line.

So the sends happened, they reached real family phones, and they left no trace in our
database or in Chip's own state. The producers are unidentified: a script, a direct
twilio_client call, an admin/management path, or a developer test that used the live
credentials and the real group number. Nothing on the authority still references the
group number outside the repo (checked scripts, bash history, /tmp), so the evidence is
not on disk any more.

WHY IT MATTERS
The owner's actual question was "why is Chip giving out of place texts". The context-swap
bug answers most of it and is fixed. But a message can be sent to the family by something
we cannot name, on a code path that does not record itself or update Chip's presence
state, and there is no log at INFO for the send. That is the machinery behind "why did
Chip say that" being unanswerable.

WHAT WOULD FIX IT
- One door for sending (in flight: robust/hubrecord) so no path can send without
 recording.
- Record the caller/trigger alongside each row (which function, which trigger reason) so a
 future investigation names the producer from the database.
- Ensure nothing but the hub can reach a live send with production credentials: a guard
 that refuses to send to the real group number unless the process is the API service, or
 a marker on test sends.
- An alert when a message is delivered per Twilio with no matching row within a minute.
