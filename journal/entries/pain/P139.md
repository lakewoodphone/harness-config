## P139 — The test suite cannot be run green (8 pre-existing failures, 153 order-dependent errors), so it is not a gate

PAIN: the test suite cannot be run green, so it has stopped being a gate

MEASURED 2026-09-15 on personal-secretary-mvp: `pytest tests/` gives 21 failures and 153
errors, of which 8 failures are PRE-EXISTING -- present at commit 32a912a6, the commit
whose message reads "audit: full test-suite green (2123 pass) + 5 real prod bug fixes".
That claim was already stale when it was written.

 pre-existing failures: test_ai_gateway (3), test_config_contract (3),
 test_vscode_chat_extractor (1), test_assistant_chat_prompt_profiles (1)
 153 errors: whole-suite interference -- test_work_generation.py passes 94/94 in isolation
 total: 2404 passed, 30 failed, 153 errors

WHY IT MATTERS: a suite nobody can run green is a suite nobody runs, and that is exactly how
nine of my own regressions survived a whole night of "verified" changes. The failure count is
also unstable (21 one run, 30 the next), which makes it impossible to read as a gate even if
someone does run it.

WHAT WOULD FIX IT, in order: (1) quarantine or fix the 8 known-stale failures so the suite
has a stable expected-green baseline; (2) find the shared state that turns 153 tests into
errors when run together -- isolation passing strongly suggests a module-scoped fixture, a
shared SQLite path, or an import-time side effect; (3) only then re-adopt "suite green" as a
claim worth making.

DO NOT add new tests to this suite expecting them to be a gate until (1) and (2) are done --
they will be lost in the noise, which is how P136 and P138's mechanisms went unnoticed.
