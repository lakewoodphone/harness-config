## P2255 — A dead session's uncommitted working-tree edit blocks the next merge; the stash pile is now three deep

A shared repo accumulates uncommitted working-tree edits from sessions that died or moved on,
and the next session that needs to merge or rebase cannot, until it parks them. Every park is
a judgement call about somebody else's unfinished work, made by an agent with no context.

MEASURED, lpt-hub on ZABZ-YOGA, 2026-09-22:
- `git merge` refused outright: "Your local changes to the following files would be overwritten
 by merge: docs/customer-operations/cases/heichal-hatorah-order-2026-08-24.md".
- `git merge --autostash` then parked it as stash@{0}, and the POST-COMMIT restore conflicted
 ("Applying autostash resulted in conflicts... The stash entry is kept"). So the merge landed
 but the tree was left with an unmerged file and a stash that could not be popped.
- That working-tree edit was 117 insertions / 12 deletions of real heichal case work: front
 matter set to closed / paid / $895.65, aliases, phone, WO26082712650, dated sections.
- It was SUPERSEDED, and only inspection proved it: origin's version carries every one of those
 facts plus the later $1,006.65 total, so it is a strict superset. I could not have known that
 without diffing, and guessing wrong either destroys a session's work or reintroduces a stale
 case state as current.
- This is the THIRD such stash. stash@{1} (2026-09-17) and stash@{2} (2026-09-17) are still
 parked, and stash@{1}'s own message says "parked only to allow a merge of origin/main".

COST: a session doing unrelated customer work spent real turns on a file it had no business
touching, and the safe outcome still leaves three stashes that nobody can safely drop.

WHAT WOULD FIX IT:
1. Sessions that hold a repo dirty should not end dirty. If work is unfinished, commit it to a
 scratch branch (wip/<host>-<date>-<slug>) rather than leaving it in the working tree. A
 branch is reviewable and mergeable; a stash is invisible and un-poppable.
2. Ship a guard that refuses to leave a repo dirty across sessions, or at minimum a `doctor`
 command that lists dirty tracked files per repo with their age, so the pile is visible.
3. Treat `git stash list` as a triage surface with the same weight as the owner queue - a
 stash older than a day is either finished-but-uncommitted or abandoned, and both are worth
 one line of attention.

Not fixed here: it is a repo-hygiene build, and this session's job was one customer sale.
Recorded because the third occurrence means it is a pattern, not an accident.
