## P3066 — The journal on ZABZ-TECH carried 179 uncommitted entries and two ids that collided with origin/main; nothing on this node pushes the journal and bands.tsv never reaches origin

**Measured 2026-10-11, ZABZ-TECH, while trying to push four entries from the Fisher SD-card session.**

Pushing four journal entries turned into a reconciliation job. The state found:

- `git status --porcelain -- journal` on ZABZ-TECH listed **187 changed paths**, of which **179 were
 untracked new entries** - other sessions' work that was never committed, let alone pushed.
- Of those 179, **44 already existed on `origin/main`** (stale local view, harmless) and **135 did not**.
- `origin/main` was **10+ commits ahead**, and it had minted its **own** entries at ids this machine had
 also used. Two of them collide outright: local `entries/decisions/D3032.md` (2,643 bytes, ZABZ-YOGA,
 2026-10-08, the ADB `$AdbArgs` contract) and `D3033.md` differ in content from `origin/main`'s entries at
 the same ids (3,482 and 3,426 bytes). **One id, two different entries — the exact condition
 `journal.py check` exists to catch, and it was invisible because neither side had been pushed yet.**
- The first commit attempt made this worse rather than better: `git add journal` swept all 179 untracked
 files into one commit, because they were sitting loose in the tree. That commit was undone
 (`git reset --mixed`) and every affected file was copied to
 `C:\Users\ezabz\Code\_scratch\journal-collision-backup\` before anything else was touched.

**How it was resolved, and how it should be resolved next time.** The four entries this session owned were
re-published from a **separate `git worktree` pinned at `origin/main`** (`git worktree add --detach <path>
origin/main`), which cannot disturb the dirty working tree at all - the 135 unpushed entries and the two
colliding ids were left exactly where they were. My ids (L3510, P3017, P3018, H3500) were checked absent
from `origin/main` before the push, and `journal.py check` in the worktree returned **0 errors**.

**What is still wrong, and whose it is:**
1. **135 entries exist only on this machine.** Nothing on ZABZ-TECH pushes the journal; entries accumulate
 in the working tree until a session happens to `git commit journal`, and no session does. Every session
 that ends here therefore hands its memory to a machine that cannot see it.
2. **`journal/alloc/bands.tsv` - the file whose whole job is to stop two machines minting the same id - is
 not being propagated** between this node and the origin. That is the mechanism behind the D3032/D3033
 collision, and it will keep producing them.
3. The remedy for the two colliding entries is the tool's own: restore both to the tree, let `check` report
 the collision, then `journal.py repair-ids --apply`, which renumbers one and records the alias. Do not
 hand-merge them; do not delete either - both are real entries.

**Do not do what I nearly did:** `git add journal` on this node is never a safe way to publish your own
entries while 100+ foreign entries sit untracked beside them.
