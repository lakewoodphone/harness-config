## P181 — Two of six workstreams landed 0 commits while reporting 'running'; 'running' is an assertion, not evidence - count commits per branch

## P - File-ownership partition produced two agents that landed nothing, and 0/0 branches look like success

**Observed 2026-09-15, `personality-system` fleet (12 agents, 6 workstreams).**

Two workstreams reported "running" for hours and landed **0 commits**. Checking each branch with
`git rev-list --count` showed `0 ahead, 20 behind` - i.e. still sitting on the base commit. One of
them had spent its whole phase building a scratch reproduction harness and had not started coding.
Both had been sent a long, confident brief; neither had been asked for a mid-flight artefact.

**Why it hurts.** While they held "running", I treated their work as in-flight and did not take it
over. The result was that the two highest-value gaps in the whole job - a real compare-and-swap on
the shared library and the "stop asserting findings from an empty profile" work - were unowned for
the entire session. I only discovered it by counting commits per branch, not by asking.

**What to do instead.**
- After dispatching, check `git rev-list --count <branch>` per workstream. A branch that is still
 `0 ahead` after its expected first hour has produced nothing, whatever its status says.
- Ask for a **one-line status with a commit count** on any workstream longer than ~30 minutes. The
 agent that was asked replied honestly and immediately; the problem was never deception, it was
 that nobody asked.
- Treat "running" as an assertion, not evidence. Same rule as an agent's report: reproduce it.
- When a workstream lands nothing and the gap is critical, **take it over yourself** rather than
 re-briefing. I did that for the compare-and-swap and it shipped within the session.

**Corollary that bit me too:** I merged a branch whose report claimed it had delivered a
`secretary-provider.ts` rewrite and a new `gateway-model-source.ts`. The merge reported success and
I moved on. `git cat-file -e HEAD:src/lib/assessment/gateway-model-source.ts` said the file **did
not exist**. Checking file existence after a merge is cheap and I had skipped it because the merge
output looked clean. Include "does the file it claims to have created actually exist on my branch?"
in the post-merge check, alongside the test run.
