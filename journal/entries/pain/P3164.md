## P3164 — harness-config has two main lineages and the file I edited was not the one that runs

MEASURED 2026-10-13, hit while editing this estate's own tooling.

Context: I edited `scripts/transcript-archive-run.sh` on ZABZ-YOGA (main @ my HEAD) to add a
free-space guard, committed it, and then discovered the file I had edited was NOT the one that runs.

 * the runner on the authority is `/usr/local/bin/transcript-archive-pass.sh`, which calls
 `/opt/company/archive/tools/transcript-archive-run.sh` -- 10,795 bytes
 * the file in my checkout was 6,322 bytes and my edit took it to 9,896
 * the authority's `\\root\\code\\harness-config` is on `main` at `04661ae`, carrying two commits my
 branch does not have on that path:
 a0df670 'make the exit-code fix and the honest pull error DURABLE' (run.sh +101, pull.py +37)
 04661ae 'stop failing the unit on a CLEAN pass' (run.sh +30)
 and `25fe0e1 'converge pull.py to the running artifact'` on the pull.
 * my branch's tip for that path was `2d9bbe40`, a DIFFERENT commit after the same ancestor. The
 two lineages share `2af8f8e` and diverge from there.

WHAT IT COST: my commit edited a stale base and could have reverted a fix that is running in
production hourly. I caught it only because the deployed file's size did not match the file I had
just committed, and then asked why. RESOLVED: took the authority's two files as the base and
re-applied only my guard, additively; verified.

WHY IT MATTERS BEYOND THIS FILE: `harness-config` has at least two `main` lineages that are not
supersets of each other, on the machine that RUNS the estate's scheduled work. Every agent that
edits a script here is editing one of two truths. The journal has the same disease at ~120 refs
(K2). The session that reads `git log` sees a coherent history and has no way to know a second one
exists.

WHAT WOULD FIX IT: one canonical `main`, and a push/fetch gate that refuses a non-fast-forward --
which is what the estate already does for the journal via `unblock-journal-sync.sh` and
`repair-ids`. The same shape is needed for code. Until then, the rule an agent can act on:
**before editing a script that RUNS somewhere, compare the file in your checkout against the file
on the host that runs it** (`md5sum` both). A size or hash mismatch means you are on the wrong
lineage, and the host is the one that is right.

Evidence for this entry: `stat -c '%s'` on both, `md5sum` on both, and `git log --oneline` on both
trees, all run 2026-10-13.
