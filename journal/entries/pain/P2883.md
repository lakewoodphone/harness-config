## P2883 — install.ps1's ssh probe reports a working alias as dead, so the installer cannot be re-run

## `install.ps1`'s ssh probe reports a working alias as dead, so the installer cannot be re-run on a machine where it is needed

Run on ZABZ-YOGA 2026-10-09, the installer printed:

```
probe: ssh secratary hostname -> no answer: secratary
probe: ssh secratary-ts hostname -> no answer: secratary-ts
two consecutive failures - stopping the probe class here
install: no ssh alias answered, so lpt cannot reach the operational store.
```

and exited 1 **before writing anything**. The same command, run by hand in the same shell one minute
later:

```
ssh -o BatchMode=yes -o ConnectTimeout=8 secratary-ts hostname -> secratary (exit 0)
```

So the probe is wrong, not the network, and the failure is silent about why: `Invoke-SshCaptured`
(install.ps1:126) runs `Start-Process -RedirectStandardInput $inFile -RedirectStandardOutput
$outFile -RedirectStandardError $errFile -ArgumentList (@($sshOpts) + @($Target, $Command))` and
tests `$probe.ExitCode -eq 0 -and $probe.Output.Trim()`. Either `$sshOpts` is wrong here, or the
exit code/output is not being read back off the redirected files.

The cost is real: **the fix to the launcher (`call %%L`, which is now in the repo) cannot be pushed
to another machine by running the installer**, and neither can the six per-tool shims. They had to be
written by hand on this machine (`write_shims.py`, mirroring the generated content) and the other
nodes still do not have them.

**What would fix it:** run the probe by hand first (`ssh -o BatchMode=yes -o ConnectTimeout=8
secratary-ts hostname`) and, when it answers, make `Invoke-SshCaptured` report *why* it failed —
print the captured stdout, stderr and exit code on failure instead of `no answer`. A probe that
cannot say why it failed costs an hour every time. Then re-run the installer on ZABZ-YOGA and
ZABZ-TECH so both get the launcher fix and the shims.
