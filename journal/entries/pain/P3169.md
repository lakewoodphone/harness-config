## P3169 — secratary-cloud is running an 80 GB disk while its server type is billed for 160 GB

MEASURED 2026-10-14T01:0xZ on secratary-cloud. /dev/sda blockdev --getsize64 = 81923145728 (76.3 GiB); sda1 fills it (79738863 KiB); df -Th / = 75G ext4, 4.0G free, 95% used. No unallocated space exists in the guest. The Hetzner console for this server shows 4 vCPU / 16 GB / 80 GB DISK LOCAL at 102.99/mo, i.e. CCX23 compute priced, and the Rescale tab lists CCX23 as 4 vCPU / 16 GB / 160 GB / 102.99/mo. So the compute half of the type change applied and the DISK HALF DID NOT. Cause, from Hetzner's own API contract (change_type_of_server): 'Server must be powered off for this command to succeed. This copies the content of its disk... If the disk gets upgraded, the Server type can not be downgraded any more. If you plan to downgrade the Server type, set upgrade_disk to false.' A type change made without a stopped server therefore defers the disk. CONSEQUENCE, all measured in the last 24h: the transcript archive REFUSED TO START at 2026-10-14T00:23:15Z because free space was 0 bytes, against a 2.5 GB floor; swap is at 4082/4095 MB; the database is 26.8 GB and growing on this same filesystem. FIX: power the VM off at the hypervisor and on again, then growpart /dev/sda 1 && resize2fs /dev/sda1 -> about 157 GB usable, i.e. ~84 GB free instead of 4. Needs the owner: no hcloud API token exists on the box and this cannot be driven from inside the guest (an in-guest reboot does not power the VM off).
