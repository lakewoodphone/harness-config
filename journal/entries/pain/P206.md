## P206 — No admin on zabz-yoga blocks Defender exclusions and thermal telemetry

## Pain
`zabz-yoga` has **no admin rights** (and this session has approval prompts
disabled), which blocks the two highest-value dev-box mitigations measured on
2026-09-15:

1. **Defender exclusions.** `MsMpEng` was burning ~29.5 % of a core
 continuously while an agent fleet churned files, because it rescans
 `node_modules`, `.venv`, build output and every audit artifact the fleet
 writes. `HKLM:\SOFTWARE\Microsoft\Windows Defender\Exclusions\Paths` is
 unreadable and unwritable without elevation. This is a per-scan tax on every
 fleet run, forever.
2. **Thermal telemetry.** `MSAcpi_ThermalZoneTemperature` → Access denied;
 `\Thermal Zone Information(*)\Temperature` → −273.15 °C sentinels. So
 "is it too hot?" can only ever be answered indirectly (absence of
 Kernel-Processor-Power throttle events), never with a real °C number.
 `powercfg /requests` also needs elevation.

## What would fix it
One elevated bootstrap, run once and recorded in `harness-config`:
- add Defender path exclusions for `C:\Users\ezabz\code` (and `_worktrees`,
 `_scratch`, `_lpt-audit`), plus process exclusions for `node.exe`,
 `python.exe`, `pwsh.exe`;
- optionally `powercfg /requests` and thermal reads via a scheduled task
 running as SYSTEM that dumps a JSON snapshot to a readable path.

Until then: do not claim temperature numbers for this host, and expect
MsMpEng to be a permanent ~15–30 % single-core tax during fan-out work.
