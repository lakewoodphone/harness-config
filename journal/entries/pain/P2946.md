## P2946 — The authority refuses the estate's only SSH key, and the provider token is dead: no way in

WHAT HURTS (ranked 1)
The authority has no working interactive access path, and no out-of-band one either.
- root@178.156.194.1 refused the estate's only SSH key from three networks between 06:44Z and 06:47Z on
 2026-10-11 (evidence in handoff H140). The key file is unchanged on two machines; the host key is
 unchanged; ssh-ed25519 is still offered by the server. So the change is on the box: authorized_keys
 content, its modes/ownership (sshd ignores a group/world-writable authorized_keys silently), or an sshd
 Match/AllowUsers/PermitRootLogin rule.
- 135-PARITY-AND-ROBUSTNESS.md sec 4.6 already said this key was the ONLY path in and recommended adding a
 second one. Nobody did; the predicted single point of failure fired the same day.
- HETZNER_API_TOKEN is 401 invalid, so the provider API cannot reboot/rebuild/snapshot either; the only
 remaining path is the Hetzner web console, which nobody has tested (135 sec 6.1).

WHAT WOULD FIX IT
1. On the box, from any working session: chmod 600 /root/.ssh; chown -R root:root /root/.ssh;
 grep -c 91iMQc2AFg /root/.ssh/authorized_keys; add the key back if missing; check sshd_config for
 AllowUsers/Match/PermitRootLogin; systemctl reload ssh.
2. Add a second authorized key from ZABZ-TECH and keep a sealed copy off the laptop.
3. Re-issue the Hetzner token and store it somewhere reachable when the company is down.
4. NEVER leave the authority with a single credential that lives on one laptop again.
