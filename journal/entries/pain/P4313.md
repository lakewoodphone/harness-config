## P4313 — The mesh broker reports a 403 from phone-gate as 'unreachable' - a refusal and an unreachability are different sentences

Measured 2026-10-15 on the authority's broker: two roster nodes answer a capacity read with a FAST 403 from their own phone-gate (secratary, lakewooechsmini) and the broker publishes them as:

 state=unreachable unreachable=true latencyMs=74 elapsedMs=74 retried=false

'Unreachable' and 'refused' are different facts and this round's own rule says they must never be the same sentence. The cost is small (~70 ms each, not the 4,000 ms P3134 recorded) so this is not urgent -- but it is the number that made round 5 call the mesh '46.3% broken' and it is the number an operator reads when deciding whether a node is down.

The distinction matters operationally too: a node that REFUSES is up and being refused by policy, and the remedy is a security decision; a node that is UNREACHABLE is down, and the remedy is to fix or drop it. Today both read the same.

WHERE: /opt/mesh-broker/lib/capacity.js classifies the failure; /opt/mesh-broker/lib/broker.js publishes the state. Check how a non-2xx status is mapped before adding a state -- a new vocabulary member ripples into every /nodes consumer, so it is a change to make deliberately and not in a hurry.
