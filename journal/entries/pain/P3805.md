## P3805 — The customer-text response deck was built in _scratch and did not survive 24 hours

PAIN: the customer-text response deck was built inside `_scratch` and was gone within 24 hours.

EVIDENCE
- `lpt-hub/docs/customer-operations/sops/CUSTOMER-TEXT-RESPONSE-FLOW.md` §5, written 2026-10-14 (ZABZ-TECH), lists the deck tools and their home: "All under `_scratch/respond/` on ZABZ-TECH" — `build-response-queue.py`, `queue-view.py`, `respond.py draft|show|send|witness`.
- Measured 2026-10-15 on ZABZ-TECH: `Test-Path C:\Users\ezabz\Code\_scratch\respond` = **False**. `_scratch` holds `__pycache__`, `before`, `briefs`, `cases-snapshot-20260914`, `ch137`, `chrome-sign`, `dialpad`, `dialpad-map`, `dialpad-probe`, `edge-*` — no `respond`.
- The file index (`ps_search what=files`) answers from the authority's filesystem, so it cannot confirm or deny a Windows path; the absence above is a local Test-Path, which is the right instrument for a local path.

WHY IT MATTERS
The doc still names three tools that no longer exist, so a later session either rebuilds them from scratch (the duplicate-work failure the estate keeps paying for) or believes the deck is available when it is not. `_scratch` is a cache: it is cleaned, and this estate has cleaned it before.

THE FIX (not yet done)
1. The deck belongs in a repo that owns it — `lpt-ops/` or `lpt-hub/tools/` — not in `_scratch`. `send-lpt-sms.py` is the one mouth and must stay the one mouth; this is about the queue and the review loop, not a second sender.
2. `CUSTOMER-TEXT-RESPONSE-FLOW.md` §5 must name that durable path, and must say plainly that `_scratch/respond/` was transient and is gone — otherwise the next reader follows a dead link and concludes the work was never done.
3. Rule it generalises: anything a session builds for reuse goes in a repo, and a doc that points at `_scratch` is a doc with an expiry date. Distinguish "tool" (repo) from "output" (`_scratch`).
