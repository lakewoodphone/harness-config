## P6281 — lpt-hub case files and sync records have drifted apart in both directions, and nothing reconciles them

## P — `lpt-hub`'s case files and its sync records have drifted apart in both directions, and nothing reconciles them

MEASURED 2026-10-11, `cd ~/Code/lpt-hub && python tools/case-index/lptcase.py check`:

- **224 sync records with no case file** — `case-without-sync-record`'s mirror image.
- **106 case files with no sync record.**
- **282 case files on disk vs 283 tracked by git** — the tool's own words: "a gap like this is
 exactly what a reparse point or a partial copy looks like".

WHAT THE ORPHAN CLASS ACTUALLY IS (three sampled, not assumed): records written BEFORE
`CASE-FILE-STANDARD.md` was adopted 2026-09-14, whose `sourcePath` points at something that is not
a case file. `2026-05-18-weisenfeld-usb.json` → `docs/customer-operations/weisenfeld-usb-recovery-2026-05-18.md`
(does not exist); `2026-06-07-canon-sx740-nahem.json` → a `case-media/` DIRECTORY;
`2026-06-17-iphone16promax-screen-nina-shwartz.json` → another sync record. So these cases exist
ONLY as a mirror, they are invisible to `lptcase find`, and the mirror is the only surviving copy
of the narrative. That is one deleted directory away from being the third customer-data loss.

WHY IT HURTS: §0 of `lpt-hub/AGENTS.md` tells every agent to answer case questions from the case
index and never to tree-grep. A case that lives only in a sync record is a silent miss from that
path — the search returns a clean, empty, wrong answer, which is the exact failure mode §0 exists
to prevent. And `check` prints 330 problems on every run, so the one NEW problem is invisible in
the noise.

WHAT WOULD FIX IT (not done — this is a fan-out, not a single-thread job): partition the 224 by what
`sourcePath` actually points at (missing .md / a directory / another record / nothing), regenerate a
case file per orphan from its own `internalSummary` + the referenced production order, and backfill
the 106 missing mirrors through `tools/customer/cli.py edit --regenerate-record`, which already
validates before writing. Chase the 282-vs-283 git gap separately and first: it may be one file
nobody can see.
