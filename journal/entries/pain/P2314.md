## P2314 — A 'publish the record' commit silently deleted a section from an unrelated health file, and nothing detected it

2026-09-24, found while grounding an unrelated question. Commit 5fca27af (2026-09-23 19:19Z, message: 'publish the record as of 2026-09-23 - sections 14-28 ... plus the three Quest lab draws') deleted 43 lines - the whole of section 9 'Treatment actually started' - from docs/personal/health/groin-skin-condition.md, a file its message never mentions. That section was the only record that a real 14-day miconazole nitrate 2% course ran 2026-09-18 -> 2026-10-02 (Desenex, Walmart order #200015023655635); the record therefore lost the fact that the owner was mid-course for a day. Verified scope the same day with 'git show --numstat' and a per-file section-count comparison against 6c974521: groin-skin-condition.md was the only file that shrank. Restored verbatim in commit 00deabd9 with a provenance comment.

What allowed it: a publish/regenerate step wrote whole files from a stale in-memory copy, and nothing diffs a 'publish' against the previous file content. What would fix it: any automated writer to a record directory should refuse to remove heading-delimited sections from a file it did not edit, or should print a deletion count per file and require it to be zero. A cheap check exists and is worth automating: for each tracked .md under docs/personal/health, compare 'grep -c ^## ' at HEAD against the previous commit and fail if it fell.
