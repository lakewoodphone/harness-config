## P3137 — No agent can create a work order, and none can record a settled payment - an after-hours drop-off stays invisible until a human types it in

Measured 2026-10-12. `lpt-write` exposes doctor, deploy, vocab, note, status, total, payment, audit,
probe — there is **no `order create`**, and `lpt order` is an alias of `lpt ticket`, which takes only
a key. So when a device is left in the drop-off bin with a note on it, the one act that would make it
real in the shop's own system is the one act no agent can perform.

Cost, this case: the Rahimi/Mizrachi OnePlus Nord N30 was dropped off 2026-10-07 with three sticky
notes. On 2026-10-12 production still showed only that customer's two old work orders. A note written
on 2026-10-09 already said *"the device now in the shop needs its own new order"* — it was still true
five days later, and the customer rang in the meantime.

What would fix it: an `order create` path through the same single writer
(`app.services.website_db`), taking customer id, deviceInfo, issue text and no price, with the same
dry-run and ledger guards as `note add`. Until then every after-hours drop-off depends on a human
typing the order in, and an agent can only write a note asking for it.

Same shape, second gap found the same session: **a settled payment cannot be recorded either.**
`payment set` requires a `--stripe-charge ch_...` id, so the $95 taken in person by card for
WO2608200003 on 2026-08-20 cannot be put into the ledger by an agent at all — the money is real, the
note says so, and the order still reads PENDING.
