## P2873 — phone-and-tech-full does not type-check its test files, so an enum rename goes silently stale

## The pain

**No test file in `phone-and-tech-full` is type-checked, so a schema change cannot make a fixture
fail to compile — it makes it silently compare against `undefined`.**

Measured 2026-10-08, ZABZ-YOGA, `0933c9b03`: `backend/tsconfig.json` excludes `src/**/*.test.ts`,
`src/**/__tests__/**/*` and `src/test-utils/**/*`. `pnpm --filter phone-and-tech-backend typecheck`
returns **exit 0** while three test files reference `OrderStatus.CHECKED_IN`, `OrderStatus.IN_REPAIR`
and `OrderStatus.COMPLETED` — enum members deleted from `schema.prisma` by `d5f3b4831`. At runtime each
is `undefined`.

Consequence, in this very workstream: `ChargeLineItemService`'s "a closed job's money is settled" guard
was exercised by fixtures passing `status: undefined` for **ten months** of test history, and the guard
was never proven to fire for the state it was written for. Nothing failed loudly; three tests failed
quietly with `promise resolved "..." instead of rejecting`, which reads like a service bug and is not one.

## What would fix it

A `tsconfig.test.json` that includes test files, wired into the `typecheck` script (or
`vitest --typecheck` in CI), so a deleted enum member becomes a compile error in the fixture that names
it. Cost: one config plus whatever pre-existing errors it surfaces — unknown, and not measurable from
inside one lane.

## Ranking

High leverage, low urgency: nothing is broken *today* (the production paths use live literals —
verified by grepping the whole of `backend/src` for the three deleted members, which found only the two
test files and one comment). But it is the mechanism that lets the next enum rename go dead silently,
and this system has already lost money to a silent fallback once
(the hardcoded-model-name incident, `journal.py show L1606`).
