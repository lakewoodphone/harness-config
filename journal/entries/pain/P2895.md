## P2895 — scripts/** has zero ESLint coverage, and hides delegator-scheduler.mjs which cannot parse

`scripts/**` has no ESLint coverage at all, and it hides a file that cannot run.

Reported 2026-10-09 from worktree `_w26-stamp` (originates in `test`): there is no root
`eslint.config.*`; `scripts/` is not a pnpm workspace package; `pnpm lint` is
`turbo run lint --filter=phone-and-tech-frontend --filter=phone-and-tech-backend`; the frontend
script is `eslint src --ext ts,tsx`; `.eslintignore` names two instruction files. So ~1,200 files
under `scripts/` are linted by nothing.

Found while measuring: `scripts/automation/delegator-scheduler.mjs` is a markdown prompt with an
`.mjs` extension - `node --check` exits 1 with `SyntaxError: Unexpected identifier 'decision'` at
line 69. It has presumably never run. Nothing noticed for the same reason.

What would fix it, in order:
1. Fix the 189 errors a `js.configs.recommended` + `globals.node` config reports over
 `scripts/**/*.{mjs,cjs,js}` (measured: 169 files linted, 73 with errors; `no-unused-vars` 151,
 `no-useless-escape` 14, `no-empty` 8, `no-regex-spaces` 6, `no-case-declarations` 4).
2. Add the root `eslint.config.mjs` plus `eslint`, `@eslint/js`, `globals` as root devDependencies
 (none is resolvable from the workspace root today, because `public-hoist-pattern[]=` is empty).
3. Only then wire it into a job that always reports.

Do NOT do 2 before 1: a lint config that fails immediately on existing code is the trap that was
just removed from `Lint Backend` (see docs/development/required-checks-must-always-report.md). The
cheaper first step that is green today is a `node --check` sweep over `scripts/**/*.mjs`, which
finds exactly 1 real defect and makes "a script that cannot run" impossible to ship unnoticed.
