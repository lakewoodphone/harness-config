## P2834 — The mesh subagent path is dead from zabz-tech, which is the default fan-out route for every larger job

The fleet is the DEFAULT behaviour for any larger job - the standing instruction is to fan work out
across subagents rather than iterate single-threaded. On 2026-10-04 the mesh path was dead from
zabz-tech: three dispatches, three identical failures, the provider reporting "the remote one-shot
exited 1 and produced no final message". So the default path is unavailable and every fleet silently
degrades to local or to me.

What would fix it: reproduce the dispatch and read the remote one-shot's actual stderr rather than the
mailbox tail the tool quotes. The diagnostic points at
C:\Users\ezabz\.dsh-mesh-mailboxes\remote-<uuid>\, and that directory did not exist - so the first
question is whether the mailbox is being created at all, or whether the remote node is simply not
reachable and the error is being reported as an exit code. Second: `agent-fleet doctor` is the
documented pre-flight for a machine's first fleet and I did not run it before dispatching. Run it
first next time.

Cost of leaving it: every "larger job" instruction will keep silently degrading, and the LOCAL marking
is the only thing keeping the reporting honest.
