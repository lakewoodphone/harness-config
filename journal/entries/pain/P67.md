## P67 — 2026-09-14 · The authority cannot receive a fix, so every fix is a hand-port into an already-diverged file

**The host that runs the company cannot receive a fix, so every fix becomes a hand-port into an already-diverged file**

The authority's `personal-secretary-mvp` checkout is **87 commits behind `origin/master` and 16
ahead**, with 52 dirty entries. `scripts/server/deploy.sh` — the documented deploy path — is
`git pull --ff-only` under `set -euo pipefail`, so on a diverged HEAD it cannot run at all and
aborts at step 1 of 6 with its error swallowed by `| tail -2`. The three most recent HEAD moves
before this session were `commit:` made *in place on the server*.

The cost is not the drift itself, it is what the drift forces. Every change must now be
hand-ported into a file that is 87 commits stale, and each hand-port makes the divergence
slightly worse. Fixes verified on a workstation are absent from the host that serves the API —
the same shape as the failure that once produced a fabricated 45-day outage report, applied to
code instead of data (**P3** at a new layer, already recorded as **P49**).

**What is fixed:** the risk of *losing* the divergent state. The working tree's 2666 files now
exist on `origin/live-snapshot-20260914T152412Z` (`380e1133`), and
`scripts/server/backup-data.sh` now snapshots code as well as runtime state. Two live fixes
were delivered by hand-port with per-anchor gates, a compile gate and a proven rollback.

**What is still open, named so it is not rediscovered:** the reconciliation itself. The safe
procedure is known and was verified as far as it can be without cutting over — build the merged
tree in a second worktree (`git worktree add ~/psm-merge origin/master`; merge
`origin/ops-evolution-loop`; carry the 11 unreproducible files across), gate on
`scripts/server/verify-production.sh`, then repoint `secretary-api.service`'s
`WorkingDirectory` and restart, with "revert the unit + restart" as the rollback. It is a
production cutover of the business system and needs a session with room to do it properly, not
the tail of an audit.

**Two traps inside that job, found the hard way and worth not re-learning:**
- `app/main.py` is the only file where taking `origin/master`'s version loses something real:
 48 lines near `api_owner_vscode_chats_ingest_stats` exist only in the working tree, while the
 DSH-auth and `/shabbat/*` blocks are merely relocated. Review those hunks, do not overwrite.
- Two untracked-but-different files (`scripts/server/prune-backups.sh`,
 `tests/test_computer_form_intake.py`) make any broad `git checkout`/`merge` refuse with
 "untracked working tree files would be overwritten". Move them aside; never delete them.

**And one secret to handle before any of it:** `deploy/twilio-studio-flow/.env.vogel` is
**tracked in git** and contains an account SID, auth token and phone number. Removing the file
does not remove it from history, so the real fix is rotation, which needs the owner's account
access.
