## P2927 — model_usage records 0 cached tokens for every DeepSeek flash call, overstating flash cost ~14x

Found 2026-10-08 while answering whether our high DeepSeek cache-hit rate makes it cheaper
than Claude. Our own session logs prove the cache rate is 99.5%, but the company's own
telemetry does not record it.

EVIDENCE (model_usage on the authority, last 30 days, provider = 'deepseek'):
 model deepseek-v4-flash : 165,345,656 prompt tokens, cached_tokens 8,448 -> 0.0%, cost 74.48 USD
 model deepseek-v4-pro : 29,775,940 prompt tokens, cached_tokens 20,535,552 -> 69.0%, cost 4.80 USD
 provider deepinfra DeepSeek-V4-Flash-0731: 1,105,122,133 prompt tokens,
 cached_tokens 254,720 -> 0.0%, cost 90.44 USD
Daily breakdown for provider=deepseek shows cached_tokens = 0 or near-0 for deepseek-v4-flash
on EVERY day from 2026-09-28 to 2026-10-08, while deepseek-v4-pro on the same provider and
same days records 57.7-88.4% every day.

WHY 0.0% IS NOT CREDIBLE: DSH's own session logs from this laptop show 1,769,675,008
cache-read tokens against 8,404,696 miss tokens -- 99.5% -- on agent loops against
api.deepseek.com. DeepSeek's API also returns prompt_cache_hit_tokens on every response.
A 1.27B-token flash population at exactly 0% is a field that is not being populated, not a
workload with no caching.

CONSEQUENCE: estimated_cost_usd for every flash row is computed as though every prompt token
were a cache miss. At 99.5% real hits the true input cost is ~0.0207 per 1M at peak versus
the 0.30 charged in the estimate -- up to ~14x overstated on input. That is why deepinfra
flash shows 90.44 USD for 1.1B prompt tokens. Any budget, per-agent cost or routing decision
built on model_usage cost for the flash routes is wrong by an order of magnitude.

WHAT WOULD FIX IT: find the usage writer that maps DeepSeek's response (prompt_tokens_details
vs prompt_cache_hit_tokens / prompt_cache_miss_tokens are two different shapes, and the AI
SDK normalises only the OpenAI one) and make the flash route populate cached_tokens; then
prove it with one live flash call and a re-read of the row. The secretary repo is NOT on
ZABZ-YOGA (~/code here holds harness-config, lpt-ops, unified-search, home, _fleet_p1seam),
so this needs the authority or ZABZ-TECH.
