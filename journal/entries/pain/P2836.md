## 2026-10-05 · ZABZ-TECH · P-LEAK: I leaked live credentials into a transcript while verifying that credentials were intact

WHAT HURTS. `ssh lpt-apps-01 "docker inspect lakewood-rentals" | Select-String -Pattern '"R2_|"ADMIN_'`
printed the VALUES of `GOOGLE_API_KEY`, `R2_ACCESS_KEY_ID` and `R2_SECRET_ACCESS_KEY` into this
session. Same class as P13b. It is 2026-10-05 and this is the second recorded instance, which means the
first fix did not generalise: P13b was about pasting a key; this was about *printing a whole env block
through a name-shaped filter*, which feels like inspection and is not.

WHAT WOULD FIX IT (ranked)
1. A mechanical guard, not a resolution: a shim/alias for `docker inspect` and `docker compose config`
 that refuses to emit `=`..`=` values unless explicitly asked, or a masker the harness runs on tool
 output. Resolutions have now failed twice on this class, so the fix has to be in the tool path.
2. Cheaper interim: `docs/` note plus the corrected one-liners (see the lesson entry) at the top of the
 rentals ops doc, where the next agent doing an env check will actually be looking.
3. Rotation, which is the owner's: the Google AI key is shared with personal-secretary-mvp, and the R2
 key pair is owner-queue #47 (dismissed 2026-09-15).
