## P2799 — The Shabbat/Yom Tov power automation was deleted by the deploy and both its endpoints were returning HTTP 500

FOUND AND FIXED 2026-09-29, late evening. This is the highest-severity thing found all session and it was found only because a deploy gate was written and run.

WHAT WAS BROKEN: the entire Shabbat / Yom Tov power-down chain was missing from the production tree on secratary.
 app/services/shalom_zmanim.py - computes WHEN (candle lighting, power-down blocks, zmanim)
 app/services/shelly_plug.py - the HANDS; actually switches the Shelly plug
Both had been deleted by the copy-deploy. Their bytecode was still in __pycache__, which is how they were identified.

WHY IT WAS SILENT: the imports live INSIDE the endpoint functions and inside the orchestrator/safety modules:
 app/main.py:22514 from app.services import shabbat_orchestrator, shalom_zmanim
 app/services/shabbat_safety.py:49 from app.services import home_assistant, shalom_zmanim, shelly_plug
 app/services/shabbat_orchestrator.py:38
So `import app.main` succeeded and the service looked healthy, while at REQUEST time both endpoints raised ImportError.

MEASURED BEFORE THE FIX: GET /shabbat/status -> HTTP 500, GET /shabbat/safety -> HTTP 500.
MEASURED AFTER THE FIX: both 200. /shabbat/status reports enabled=true, plug_connected=true,
switch_on=true, next_action {"action":"off","label":"Candle lighting 2026-10-03","when":"2026-10-02T15:37-04:00"}.
/shabbat/safety reports automation_enabled=true, safe=true, power_down_allowed=true, cameras next_off 2026-10-02T15:37.

TIMING: Shmini Atzeres fell on Saturday 2026-10-03 with candle lighting Friday 2026-10-02. So this was found four days before the automation was needed, and an unknown number of days after it had stopped working. We do not know how long it was broken - that is not recoverable from the evidence available.

ALSO DELETED, also restored: vehicle_analytics.py (2,523 lines), vehicle_telemetry.py, company_outcome_monitor.py, dialpad_sms_ws.py. app/accounting_paths.py is in no snapshot and nothing references it, so it is left as leftover bytecode and reported as a warning rather than restored.

LESSON THAT GENERALISES: imports inside a function body are invisible to a startup import check, so "the service started fine" proves nothing about whether a feature works. Only calling the endpoint proves it. When auditing a system for silent failure, exercising the ENDPOINTS matters more than reading the imports.
