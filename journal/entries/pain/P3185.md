## P3019 — The fleet scrapes suppliers from the shop's own public IP - and it has now cost the shop its screen supplier's website

RANKED, with the fix.

1. THE FLEET SCRAPES SUPPLIERS FROM THE SHOP'S OWN PUBLIC IP, AND SPENT ITS
 REPUTATION. Measured 2026-10-11: laptopscreen.com - the shop's screen supplier -
 now serves every page as an empty HTTP 200 to 71.104.140.242 (Verizon FiOS,
 AS701, Lakewood), the single public IP that every agent on the shop LAN and
 every human in the shop shares. Consequence: the OWNER cannot open his own
 supplier's website in his own browser, and a case quote (Pearl, 840 G5) rests on
 a price read from that site three days earlier that can no longer be re-read.
 FIX: supplier scraping and price checks run from the datacenter (secratary-cloud /
 Hetzner), never from the shop LAN; rate-limit per host; keep a named human route
 (phone/email/account) for every supplier so a soft block never stops the shop
 buying. This is the fix that matters: an IP block on the shop is a business
 defect, not a tooling annoyance.
2. NO ONE OWNS PER-SUPPLIER REACHABILITY. There is no record of which suppliers the
 shop can reach, from where, and by which route, so a block is rediscovered by hand
 every time ("I think we faced this problem before" - the owner, 2026-10-11). FIX:
 one reachability row per supplier, machine-checked from the datacenter, with the
 human ordering route and account number beside it.
3. NOTHING FLAGS A SUPPLIER THAT ANSWERS 200 AND NOTHING ELSE. A zero-byte 200 is
 invisible to every health check that looks at status codes. FIX: any supplier
 probe treats "200 with 0 bytes" as a FAILURE, and says which IP it was tested from.
