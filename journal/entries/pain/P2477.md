## P2477 — reply_to_message on our OWN sent message addresses the reply to ourselves - ok:true, right thread, label SENT, and the lab got nothing; the To header is the only witness

**A correction email that reported success went to ourselves. `gmail_service.reply_to_message` pointed at one of our own sent messages addresses the reply to the message's own sender — and the API says `ok`, the thread is right, and the labels say SENT.**

**MEASURED 2026-09-24 (ZABZ-TECH), 300DDR ticket #73890.** The owner approved a three-line apology to a lab partner for an earlier email of mine. To make it land **under** my own message in the thread, I called `reply_to_message(message_id="1a0d53e9f870eb3c")` — that message being the one *we* had just sent. Result:

```
{"ok": true, "id": "1a0d569a455a6e45", "thread_id": "1a0b70e2983f93c4",
 "labels": ["UNREAD", "Label_34127...", "SENT", "INBOX"], "replied_to_message_id": "1a0d53e9f870eb3c"}
```

Every field reads like success. The read-back shows the truth:

```
To: info <info@lakewoodphoneandtech.com>
```

The lab never received it. The message was addressed to us, sat unread in our own inbox, and the labels still said `SENT` — which is literally true and completely misleading. Re-sent as a reply to the **counterparty's** message (`1a0b70e2983f93c4`) it went out correctly: `id 1a0d56a2da5a038b`, `To: Brian - 300DDR <helpdesk3@300dollardatarecovery.com>`, label `SENT`.

**WHY NOTHING CAUGHT IT.** `send_message` has no `thread_id` parameter, so threading a message under a specific earlier one is only possible through `reply_to_message`, whose recipient is derived from the message being replied to. When that message is ours, the derived recipient is ours. No guard exists, no error is raised, and every signal a caller normally checks — `ok`, `id`, `thread_id`, `SENT` — confirms the wrong thing. **The labels describe what we did with the message, not who received it.**

**THE RULES.**
- **After any outbound email, read the `To` header back. Not the labels, not `ok`.** This is the email sibling of the SMS lesson (H2658/L2511: a `STORED` line is not a stored row; `DRAFT` is not a reply). The witness is the recipient field.
- **Never point `reply_to_message` at a message we sent.** Thread under the counterparty's message instead — the thread is keyed by subject and references, so a correction still lands last in the same conversation.
- **A tool that cannot express the recipient cannot be trusted to get it right.** `reply_to_message` should refuse a message whose `From` is one of our own authenticated accounts, or accept an explicit `to` that overrides the derivation. Until it does, the check above is manual.

**EVIDENCE.** `personal-secretary-mvp` `gmail_service.reply_to_message` (L1413) and `send_message` (L1310, no `thread_id`); header read-back of `1a0d569a455a6e45` (To: ourselves) versus `1a0d56a2da5a038b` (To: helpdesk3@); case file `lpt-hub` wilner-sd-card-7329664296-2026-08-31.md.
