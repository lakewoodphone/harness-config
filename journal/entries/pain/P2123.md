## P2123 — P348 - the AI line texted a door code to the wrong person, was told so, and filed the complaint as queue

**Measured 2026-09-20 from the store and Twilio, while rebuilding the AI text line.**

On **2026-09-09 ~02:29Z** the AI line sent, to seven numbers, a message of the form
*"Your door code is NNNNNN. It auto-rotates every two weeks — I'll text you the new one when
it changes."* Two of those sends went to different numbers **carrying the same code**:

```
outbound -> +17326745878 "Your parents door code is 9982. It auto-rotates ..."
outbound -> +17326747491 "Your parents door code is 9982. It auto-rotates ..."
```

`+17326747491` is **the owner's father** (`permissions`: *Totty (father)*, family). Three and a
half hours later he replied:

```
inbound <- +17326747491 "I believe you sent this message to the wrong number"
```

**The old system filed that as `queued/model` and never answered him.** It has been unanswered
for 11 days. The `queued` path raised no owner row either, so nobody was told the assistant had
texted a door code to the wrong person or been corrected about it. It surfaced only because this
audit counted waiting correspondents.

Three separate defects in one event:

1. **A door code went to a number it was not for.** Whatever produced "your parents door code"
 resolved the same code for two different recipients.
2. **He told us it was wrong and we said nothing** - `allow=queue` meant silence, and `queue` on
 an inbound from a *person who is correcting an error we made* is the worst possible branch.
3. **Nothing recorded 9982.** `memories` has 0 rows mentioning it, so the current value is not
 recoverable from what we hold. **A stale door code is worse than silence**, which is why the
 rebuilt system must not "helpfully" re-send one.

**Related, unresolved:** Bachrach `+18453762305` asked *"Is this the door code for the outside
door or it's the door code for the office?"* 11 minutes after receiving *"Your bachrach door code
is 6693"* - the system holds no mapping from door **name** to code, so neither question can be
answered from our records today.

**What would fix it:** a door-code registry keyed by door *and* person, with the send path
refusing a code that is not bound to the recipient, and rotation tracked. Until that exists every
door-code question is `work` that ends in an escalation, never a guess. Fixing this is now the
next piece of work on this line.
