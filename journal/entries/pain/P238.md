# Pain: a measurement brief whose turn budget cannot afford the comparison it asks for

Ranked, with what would fix it.

## P-new-1 · A 30-turn budget for a question that needs 54 turns of sweep

The brief asked for **N = 1, 2, 4, 8, 12 on TWO transports** — that is Σ(N) = 27 child turns for one
transport's sweep alone, so 54 for the comparison, against a stated cap of 30. What was delivered was
one transport at its derived limit plus the other at one small level, and the **matched pair at equal N
— the thing that would actually decide which transport wins — was the thing that got cut.**

WHAT WOULD FIX IT: size a measurement budget as `K × Σ(N) + retries` for K transports and M levels, and
say which single level is the *decision* point (here: N = 8, the derived limit) so the remaining budget
goes to the comparison rather than to points already measured by `84-calibration.md` on the same node.
A brief that asks for a sweep and a cap smaller than the sweep guarantees an incomplete answer.

## P-new-2 · The work consumed the measurement twice before it produced one

Three defects in my own rig each cost a full level's wall clock (and, for one, **12 child turns**):
a `Start-Process`-detached sampler killed by its launching ssh session; a `Get-Counter` key that
returned nothing because `Path` is machine-qualified, writing rows of zeroes; and a missing
`--secret-file` that failed *after* the capture window had opened. Two of the three are silent — the
CSV existed, it was just empty or zeroed — and the third failed after starting the expensive part.

WHAT WOULD FIX IT: a rig must prove **itself** before it spends the resource it is measuring — here, a
`--no-children` dry run that asserts the capture produced ≥ 3 non-zero rows, which costs 30 s and zero
turns (`test/run-level.mjs --no-children` now exists for exactly this). And every argument a driver
needs should be validated at parse time, not at first use.

## P-new-3 · An invisible, probabilistic ceiling on somebody else's node

`sshd_config` on `zabz-tech` has `#MaxStartups 10:30:100` **commented out**, so the compiled default is
in force and begins dropping unauthenticated connections at random from the 11th. Transport v1 holds no
slot, so nothing in the mesh knows this; the observable is a 255 exit with no diagnostic, reported as a
failed child.

WHAT WOULD FIX IT: set and record `MaxStartups` explicitly on every node that accepts fleet ssh work,
so the ceiling is a number in a config rather than a compiled default nobody read — and prefer v2 for
fleets, because v2's ceiling is derived from the node and enforced where the work is.
