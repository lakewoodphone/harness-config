## P227 — The installation cannot tell a break-in from the owner, and the cameras' own detection never reaches Home Assistant

**P — the security system cannot tell a break-in from the owner walking in. Ranked first because every other gap is downstream of it.**

There is no `alarm_control_panel` entity anywhere in the installation (0 entities in that domain). `zone_control_room_active`, `zone_hallway_active` and `zone_outside_active` exist, and automations named `phoenix_extreme_intrusion_trigger` / `phoenix_extreme_intrusion_disarm` exist, but there is no armed/disarmed state that the system and the owner agree on. So an intrusion response cannot distinguish "someone forced the door at 2am" from "Eliyahu came in" — which means the one behaviour a security system exists to provide (alert on the unexpected) is not implemented; only "capture everything" is.

What would fix it: an alarm panel entity (manual or MQTT) with night-armed semantics, and intrusion automations gated on it. Note `POST /webhook/ha/security-alert` already exists on the company API — the escalation path is there and unused.

**P — the cameras' own detection is not wired into Home Assistant at all.**
Every `binary_sensor.cam_deserted_interior_*`, `cam_front_hallway_*`, `cam_larry_s_interior_*` alarm entity (`motion_alarm`, `cross_line_alarm`, `cross_region_detection`, `smart_motion_human`, `smart_motion_vehicle`) reports **0 transitions in 7 days** — and their unsuffixed twins are `unavailable`. So the NVR's motion/IVS/tripwire detection, which is already configured on the device, produces no events, and the only real inputs are three Zigbee door contacts plus the Reolink doorbell AI. Camera-based motion and a tripwire across the shop floor are available for free on the hardware and simply not connected.

**P — 96 of 174 security entities are `unavailable`, with duplicate ghost pairs.**
The Dahua integration exposes each channel several times (`cam_front_hallway_sub`, `_sub_2`, `_sub_2_2`, `_sub_3`, `_sub_4`), some `unavailable` and some `idle`, plus `binary_sensor.active_apartmentdoor_1..10` and `pin_synched_apartmentdoor_1..10` all unavailable. 377 ghost entities estate-wide. It makes the security surface unreadable to a human and risks a future session automating against a dead twin — which is exactly what the two dead still streams were.

**P — every captured clip costs ~1 minute of Pi CPU, and only because of the container format.**
The NVR records H.265; browsers need H.264, so each 20 s clip at 1440p is transcoded at ~10 fps on the Pi 4. Switching the NVR's main-stream codec to H.264 would make clips a near-instant remux at *better* quality (no re-encode) and remove the load from the machine that also runs Home Assistant. The cost is roughly double the NVR's bitrate/storage, which nobody has measured. Check the NVR's disk headroom first; if it is comfortable this is a clean win rather than a trade-off.
