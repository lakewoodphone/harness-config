## P2858 — The mesh subagent provider is a single point of failure: one offline node (secratary) kills the entire fleet while healthy nodes sit idle

WHAT HURT (measured 2026-10-06, ZABZ-TECH)
Three mesh dispatches were attempted for a research job. All three failed identically:
 "remote-ssh: broker-unreachable: the placement broker could not be reached at
 secratary-ts:http://localhost:3091/place - ssh exited 255: ssh: connect to host
 secratary.tail93e6e6.ts.net port 22: Connection timed out"

THE STRUCTURAL DEFECT (this is the finding, not the outage)
- The placement broker runs ON secratary, and the provider is hardwired to reach it at
 secratary-ts:3091. packages/plugin-remote-fanout/lib/placement.js exposes only
 process.env.MESH_TARGET_NODE (a node SELECTOR), not an alternative broker endpoint.
- Measured at the same moment: `ssh zabz-yoga-1 "echo OK"` -> OK, and tailscale showed
 zabz-yoga-1 active with a direct path; secratary offline 14h; zabz-tech-linux and the mac-mini
 offline. So ONE healthy worker node existed and was unreachable as a target because the control
 plane that names nodes lives on the dead node.
- Consequence: the standing instruction is "never fan out locally while the mesh is reachable".
 When the mesh's ONLY control plane is down, the mesh is unreachable BY CONFIGURATION even though a
 node is up, and every dispatch burns a full round-trip to discover it. The rule then forces a
 visible LOCAL fallback (correctly) that the harness could have avoided by talking to any live node.

WHAT WOULD FIX IT
- Failover placement: try the roster's live nodes' own /mesh/capacity when the broker is unreachable,
 or honour a MESH_BROKER_URL override so a broker can be started anywhere (including the node that
 is already up). The roster (packages/mesh-broker/nodes.json) is a configuration, not state, so a
 dispatcher could read it without the broker.
- Cheap partial: make the failure message name the live candidates it refused to consider, so the
 operator sees "yoga was up" in the error instead of having to ssh around to find out.
- Cost when it bites: every mesh fan-out during any authority outage silently degrades to local
 execution, which is the exact thing the standing instruction forbids, and the degradation is only
 visible if the agent chooses to report it.
