## P168 — journal.py drops body, tags and refs from its cache - so --tag never matches and backlinks cannot see prose citations

MEASURED 2026-09-15 (ZABZ-TECH) while fixing P163. Three defects in journal.py, all the SAME root cause,
all verified, none yet fixed.

ROOT CAUSE (shared with P163). `_from_tsv()` builds every Entry from the generated TSV cache and hard-codes
not just `body=""` but `tags=[]` and `refs=[]`. `catalog()` answers from that cache whenever it is fresh,
which is always. So EVERY field the TSV does not carry fails silently: search matched headings only (P163),
`--tag` can never match anything, and `backlinks` cannot see citations made in a body.

1. `--tag` CAN NEVER MATCH. 640 cached entries carry the tag `legacy-import` (17 `dialpad`, 16 `comms`),
 yet `search journal --tag legacy-import` returns 0 hits. Output was byte-identical before and after the
 P163 fix -- preserved, not changed. Any filtered read that depends on tags or refs is therefore unreliable.
 FIX: read tags/refs in the same body-provider tier that fixed search (~2 lines each).

2. `backlinks ID` MISSES BODY CITATIONS. `backlinks W136` lists only W136 itself, yet
 `entries/pain/P163.md` cites W136 twice in its body. So a citation made in prose is invisible to the
 backlink graph, which is exactly how a lesson gets "rediscovered" by a later session.
 FIX: route backlinks through the same provider (~2 lines).

3. `costs` CAN PRINT A SECONDS-LONG `ok NO` ROW THAT IS NOT A REGRESSION. `costs` times `cmd_search`, which
 rebuilds a stale cache inside the measured window when another session appends meanwhile
 (`rebuild_cache()` alone is ~3.4-4.2 s and is untouched). Measured 6046 ms once; the OLD code measured
 3471 ms on the same stale-cache path. So do not read a slow `costs` search row as a search regression --
 check whether the cache was stale first.

ALSO WORTH KNOWING: `index/journal.db` already held every body verbatim in an fts5 table (959 rows, 1.8 MB),
so the P163 fix is one ~6 ms `SELECT` for the whole tree, with a per-file fallback reading only
[line_start, line_end] from the TSV and re-deriving the body through the same parser -- both tiers verified
byte-identical. The lesson generalises: WHEN A CACHE ROW IS NOT THE WHOLE ENTRY, EITHER SAY SO OR READ THE
ENTRY -- a dropped field never errors, it just returns a confident empty answer.
