## P146 — ps_task_update and ps_memory_search MCP tools are dead - they call routes that do not exist (HTTP 404)

**Symptom:** `ps_task_update` and `ps_memory_search` return
`{"ok": false, "error": "HTTP 404: {\"ok\":false,\"error\":\"http_error\",\"message\":\"Not Found\"}"}` every call.

**Cause (read from source, 2026-09-15):** `scripts/ps_mcp_server.py` calls routes that do not exist.
- line 305: `ps_task_update` → `POST /api/v1/tasks/update` — **no such route**. `grep 'api/v1/tasks'` across the
 whole repo returns only that one line, and `@app.post`/`@app.patch` over `main.py` has no `/api/v1/tasks*`.
 The real route is `@app.patch("/ceo/tasks/{task_id}")` (`app/main.py:15671`), body `TaskUpdateInput`
 (`status, priority, title, description, due_date, tags` — **there is no `note` field**, so a "note" has to be
 appended to `description`).
- line 320: `ps_memory_search` → `POST /api/v1/memory/search` — same class of bug, also a missing route.

**Cost:** the two tools an agent reaches for first when it needs to *record* work are the two that fail. This
session lost calls to it and had to route around it (see fix below). A broken write-path is worse than a broken
read-path: it silently converts "logged" into "not logged".

**Immediate workaround (verified working this session):** the route is live and unauthenticated from the server
itself —
```
ssh secratary-ts "curl -s -X PATCH http://localhost:8002/ceo/tasks/<id> -H 'Content-Type: application/json' --data-binary @-"
```
with the JSON body piped on stdin (PowerShell: `Get-Content -Raw payload.json | ssh secratary-ts ...@-`). Do **not**
send an empty `{}` body — `update_task()` returns False when nothing changed and the handler then raises 404, which
looks identical to "task not found". Send at least one changed field.

**Fix that would close it:** point `ps_task_update` at `PATCH /ceo/tasks/{task_id}` (appending any `note` to the
current `description`), and repair or delete `ps_memory_search`. Then deploy `scripts/ps_mcp_server.py` to the
machine running the MCP server — `API_BASE` is `http://localhost:8002` (`ps_mcp_server.py:66`) and `DB_PATH` is
`ROOT/data/secretary.db`, so that server runs **on secratary**, not here.

**Note for next time:** every tool in `ps_mcp_server.py` should be smoke-called once after any deploy; a 404 from a
missing route is indistinguishable from a missing record until you read the source.
