## P146 — ps-shop intake case_id slug is unusable when --model is descriptive

`ps-shop.mjs intake` returns a server-built `case_id` slug made from customer+device+date. If
`--model` contains anything long or punctuated, the slug is unusable:

 --model "ThinkPad X201 / X201i (12.1in WXGA) — model ID'd from bottom-cover label, confirm with customer"
 -> case_id "lenovo-thinkpad-x201-/-x201i-(12.1in-wxga)-—-model-id'd-from-bottom-cover-label,-confirm-with-customer-shlesinger-2026-09-15"

It keeps `/`, `(`, `'`, `—` and commas, so it is not a safe path component and it is horrible to read
back. Evidence: task 25404, contact 639, created 2026-09-15T18:34Z from lakewooechsmini.

Fix: keep `--model` short and factual ("ThinkPad X201") and put the uncertainty in `--issue` or a case
note. Better fix (for the tool): slugify the model the way `ps-case.mjs` already slugifies with
`slugify()` before sending, or have the server do it, so the returned `case_id` is always a valid slug.
