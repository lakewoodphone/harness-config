## P2798 — The deploy deletes imported modules and broad except-blocks hide it - seven were missing, and every one of them looked like a different bug

MEASURED 2026-09-29. The live tree on secratary was missing SEVEN modules that the tree itself imports. A static scan (ast over every .py, checking that each referenced app.* module resolves to a file) found them in seconds:

 app/direct_request.py <- sms_service.py
 app/owner_text.py <- sms_service.py
 app/services/owner_sms_flood_guard.py <- autopilot.py, outbound_buffer.py
 app/services/shabbat_orchestrator.py <- agent_bus.py, main.py
 app/services/shabbat_safety.py <- shabbat_orchestrator.py
 app/services/subsystem_presence.py <- autopilot.py, self_audit.py
 app/services/computer_form_intake.py <- main.py
 app/api/vehicle.py, app/api/vehicle_dashboard.py
 app/services/work_step_ledger.py <- autopilot.py (found in round 1, it took the API down)

WHY NOBODY NOTICED: every one of those imports sits inside a try/except that logs at debug or warning and carries on. So the system ran DEGRADED and SILENT. The visible consequences, all of which looked like unrelated bugs:
 * the direct-request exemption could never fire (app/direct_request missing), which is why a text the owner ASKED FOR was refused by the autonomous daily quota;
 * the one-at-a-time owner_text gate was inert, feeding the owner's "you asked me this already" complaint;
 * there was no SMS flood guard at all.

THE MECHANISM: deployment here is FILE-COPY, not git. All the missing modules sit in about twenty sibling snapshots named pre-copydeploy-* / pre-deploy-* / _verify*, and stale __pycache__ .pyc files for them were still sitting in the live tree - proof they were deleted, not never-created. In the same tree, ~30 files are modified relative to HEAD and uncommitted. So the live tree is a copy target that is periodically overwritten and never verified.

WHAT WOULD FIX IT, in order:
 1. A deploy gate: after any copy, run `python -c "import app.main"` and refuse to call it deployed if it fails. That one command would have caught all seven.
 2. A static missing-module scan as part of the same gate - it is cheap, needs no imports, and catches the case where the app still starts because the import is inside a try/except. A working script is at /tmp/scan2.py on secratary.
 3. Commit the deployed state. A file-copy deploy whose result is not in git has no way to notice or recover a deletion.
 4. Stop swallowing ImportError silently in paths that implement policy. A missing policy module must be loud.

RULE FOR THE NEXT SEAT: when a feature "does not work" in this system, before reading the feature's logic, run the missing-module scan. Three separate reported bugs this session - the quota refusing a requested text, the duplicate questions, the silent inbox - traced to a module that was not on disk.
