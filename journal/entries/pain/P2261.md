## P2261 — dsh-update detector produced a false BREAKS on a healthy candidate; six fixes specified but unapplied

## P — The dsh-update detector produced a false BREAKS on a healthy candidate; six fixes are specified but unapplied

RANKED: high. This is a trust defect, not a cosmetic one: the pipeline's entire purpose is to answer
"will this upgrade break us", and on its first real run it answered **BREAKS** for a candidate that
breaks nothing (verified by hand, 2026-09-23). An untrustworthy detector is worse than none, because
it will be believed.

WHAT HAPPENED: `analyze 0.1.5-rc.3` -> `BREAKS=2`, both on `tool-subagent-remote`, both false. Cause
and evidence: LESSONS L2373. The patch applies (`disabled: true` in both versions); the engine prints
no `patched by` comment for a disable-only patch, and the detector asserted on that comment.

WHAT WOULD FIX IT (full detail in `harness-config/dsh-update/SPEC.md`, section `## C13`):
1. **F1** B3 asserts on an incomplete signal -- replace with an effect comparison against
 `--dump-default-config` (the arm `compose.mjs --default-config` now provides, verified working).
2. **F2** `patchRowTargets` records each target 2-4x (absolute + repo-relative spellings), so one
 cause produced duplicate findings. Deduplicate by `(profile, id)`, keep all locations as
 `consumers`.
3. **F3** targets are not scoped by profile: `remote-fanout` belongs to `profiles/mesh/` and was
 checked against the `web` tree. Add `profile` to each target.
4. **F4** `patchRowTargets` entries carry no `intent {config, disabled}` (keys are only
 `id,file,line,layer`), so B3 *cannot* be effect-based until `consumed.mjs` emits it.
5. **F5** 253 INFO and 422 `unverified` findings on one run -- honest reasoning, unusable volume.
 Aggregate `unverified` settings keys by key.
6. **F6** cosmetic: multi-token argv truncates in B9 subjects (`dsh --dump-config did`).

ALSO NEEDS FIXING, found the same day and NOT yet done:
- **The boot gates cannot run without credentials.** An isolated `DSH_HOME` has no
 `.credentials.yaml`, so G4/G5 fail with `MISSING_CREDENTIAL` (measured). The working fix is
 measured too: pass `DEEPSEEK_API_KEY` in the child environment, never copy the secret into the
 isolated home and never log it. SPEC section `## C14`.
- **`--dump-config` is not read-only** -- a successful run rewrites
 `profiles/<name>/cordis.yml` (mtime moves, content canonical `[]`). Never hash the profile
 directory as evidence. SPEC `## C4`.
- **A session-format version gate is missing.** `dsh-session-format-catalog` declares
 `currentVersion: 3` and the live home holds 1,095 files, all `session.v3.jsonl.zstd`. A candidate
 that writes v4 makes rollback unable to read his history -- a one-way door, and nothing in the
 pipeline sees it. SPEC `## C8`, gate G8.
- **Preset breakage is invisible to a tree diff** -- agent presets contribute **zero** rows to
 `--dump-config` (14 preset-exclusive row ids, none present in the 163-row dump). Needs gate G7.
 SPEC `## C3`.
- **`dsh --profile <name> <anything>` boots the app** (the CLI passes unknown tokens through), so
 engine exit codes are not a usable guard. Bare `dsh status` does error, exit 1. SPEC `## C7`.

EVIDENCE: `harness-config/dsh-update/SPEC.md` sections C1-C14; `state/candidates/0.1.5-rc.3/diff.json`
(the false findings, kept as the record); `state/history/events.tsv`.
