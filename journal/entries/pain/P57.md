## P57 — The journal still has two writers - the sharded log and the flat files a second session keeps appending to

**Symptom.** The journal now has two writers at once: the sharded log (`log/`, written only by `journal.py`)
and the six flat files, which a second session was still appending to during the rebuild — all five were dirty
in git at 01:19-01:23 while the migration ran, and `HANDOFF.md` grew from 273 KB to 288 KB mid-session. An
entry written to a flat file today is invisible to `journal.py newest` until someone runs `import-flat`.

**Evidence.** `git status journal/HANDOFF.md` was modified immediately after the migration; `import-flat`
absorbed a new handoff entry (H67) and a grown pain entry (P55 grew 2,999 -> 7,313 chars, which a body-only
comparison first mistook for a new entry) within the hour.

**Cost.** Two sources of truth for the same fact, which is the exact defect this rebuild removed elsewhere.
A session reading only `log/` can be minutes behind; a session reading only the flat files is unbounded and
getting worse.

**Fix.** `journal.py check` warns when a flat file holds an entry the log lacks, and `import-flat` absorbs it
(and resyncs an entry whose source grew). Retire the flat files once `import-flat` reports nothing new for a
full working day: move them to `archive/flat-<date>/` and leave one-line stubs at the old paths. Tracked here
rather than in prose so it actually gets closed.
