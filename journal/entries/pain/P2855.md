## P2855 — the broker fail-closed startup check can fail transiently, needing a Docker restart to boot

## PAIN — the broker's fail-closed startup check can fail transiently, and it took a Docker restart to boot

`lpt_filter_ai_api_b` failed its first boot after the 2026-10-05 deploy:

 File "/app/app/startup_validation.py", line 594, in validate_startup
 raise RuntimeError(msg)
 RuntimeError: Integrity anchor chain verification failed at startup: access_requests, decisions

Died 16:55:54, Docker restarted it, healthy at 16:56:06. The anchor file is clean immediately
afterwards (ops/anchor-order.py probe: 380 rows, no inversions), the twin is a non-writer, and the
primary has never failed this check.

Two explanations were tested and killed: it is NOT the blocklist ReadTimeout (a separate caught
traceback at 16:57:06), and it is NOT a torn tail (a partial last line becomes an invalid_json
record the verifier skips, not a chain mismatch).

**What the evidence points to: two instances share one SQLite file.** The primary publishes an anchor
for the tables that get written at boot - access_requests and decisions are exactly what startup logs
into - while the twin verifies against the same file, and the prefix comparison sees a prefix that
does not yet include what the anchor was computed over. Deterministic once writers quiesce, which is
why the second boot passed. This is the same root as the 3,322 'database is locked' events in 7 days.

**Why it hurts:** a fail-closed security check whose outcome depends on timing is a boot that depends
on luck. Today Docker's restart policy absorbed it. If both instances had raced the same way, the
broker would have refused to start - which is exactly what happened earlier today via a different
route (one out-of-order anchor pair).

**Fix, in order:**
1. Retry the startup verification a few times with a short backoff before failing closed. A genuine
 tamper fails every attempt; a race resolves. This preserves the fail-closed property exactly and
 costs a few lines in startup_validation.py. **Not yet done.**
2. Then the real question, and it is the owner's: whether HA should mean two processes on one SQLite
 file at all. Every symptoms traced back to this today - the lock storms, the anchor races.
