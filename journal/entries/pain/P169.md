## P169 — The only gate on the fleet location map is a bcrypt hash committed to the repo

Caddyfile:76 and :87 carry `basic_auth ezabz <bcrypt>` on /fleet/* and /api/v1/fleet*.
That is the ONLY authentication in front of the dashboard: deploy/fleet-dashboard/backend/main.py
has no auth middleware, its AUTH_TOKEN env var is read by no code, and the implementation
that did check it survives only as main.py.bak:43,69-72. The gate itself works (verified:
unauthenticated /fleet/ -> 401), so this is not an open door today.

What would fix it: move the hash into ${DASHBOARD_PASSWORD_HASH} in .env (Caddy substitutes
env vars in the Caddyfile) so the repo carries no credential, and either delete the unused
AUTH_TOKEN or honour it. It needs a Caddy force-recreate, so it belongs in a window, not at
the end of a long session. Related non-finding: `allow_origins=["*"]` on a basic-auth
dashboard is not exploitable (a wildcard origin means browsers will not attach credentials)
but it is meaningless.
