## P224 — The journal exists in two lineages that differ byte-for-byte on nearly every shared entry, and nothing reports it

**Symptom.** `harness-config` has two lineages of the same journal and they cannot be merged casually. Measured 2026-09-14 23:20 on `secratary`: `origin/master` is **3 commits ahead**, and of the entries both trees hold, **82 of 83 handoffs, all 241 shared lessons, all 54 shared pains, all 76 shared decisions and all 46 shared wins differ byte-for-byte** — the same logical entries, rewritten by two different migrations of the same six flat files. Origin reaches H203 / L1085 / P131 / D141 / W106; this checkout reached H115 / L1022 / P71 / D85 / W48 before today.

**Cause.** The migration that rebuilt this journal on 2026-09-14 produced *different bytes* for the same entry depending on which machine ran it, so git sees every shared entry as a conflict and no fast-forward is possible. `journal.py`'s own collision guard did not help: `git_max(kind, fetch=True)` returned H115 while `origin/master` already held H203, so three entries written here took ids that already meant something else on origin (H116, D105, P92 — renumbered by hand to H204, D142, P132).

**Cost.** Every write to this journal is now local-only until the reconciliation happens, and the divergence is silent: `autosync.sh` reports `converged: true` while the branch is three commits behind (it never merges, by design). A session that allocates ids from the local tree can collide with the other lineage and not know it. The journal is the organ that makes the agent continuous; two of them is worse than one stale one.

**Fix.** A deliberate reconciliation with the **entry file** as the unit: for each shared id, decide which bytes win (they are the same entry — pick the richer body and record the other as an alias), then let `journal.py index` rebuild the cache and `check` prove it. Not `git merge`. Two mechanical prerequisites first: make `git_max` fetch and consult `origin/*` before allocating (it demonstrably does not today), and make the migration byte-deterministic so a second machine cannot re-migrate the same source differently.

**Related.** H115 named the same shape for four other repos on 2026-09-14 ("fast-forward-only syncs freeze a machine's copy with no alarm"); this is the fifth instance and the first one that is the agent's own memory.
