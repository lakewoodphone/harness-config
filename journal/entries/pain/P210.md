## P210 — A new bundle cannot hot-mount, so every plugin costs an engine restart and the live sessions with it

A new bundle cannot hot-mount, so activating any new plugin package costs one engine restart, and on this deployment that restart ends every live session. Measured 2026-09-16: adding the name to a running engine's `dsh.profile.bundles` plus linking the package left /healthz at 404 before and after, with no side effect.

What it costs today: plugin-health was finished, installed, tested and green at ~15:20 and cannot serve the live engine until someone chooses to restart it. The same wall will apply to every future plugin.

What would fix it (not attempted, needs a design decision): make the loader re-read `dsh.profile.bundles` on the same watch that drives `patchReload: live`, so a bundle ADD is a live operation like a row edit. The blast radius is that a partially-mounted new bundle could fail while the old tree is live — which is presumably why it was not built that way. A cheaper half-step: a supported "restart at the next session boundary" (finish the current turns, then relaunch) would turn a 10-session interruption into a queue.

Recorded rather than fixed: this is a harness design question, not an engineering fault we can patch from a plugin.
