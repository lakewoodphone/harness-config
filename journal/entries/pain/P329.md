## P329 — ZABZ-YOGA cannot reach GitHub at all - gh token invalid, credential manager interactive-only

MEASURED 2026-09-18 from secratary over Tailscale (ssh laptop-ts).

FACTS
- 'gh auth status' on the laptop: 'X Failed to log in to github.com account lakewoodphone ... The token in default is invalid.'
- 'git fetch origin' over a non-interactive ssh session fails: GCM is the credential helper ('manager') and it tries to open a prompt, which fails with 'bash: line 1: /dev/tty: No such device or address' then 'could not read Username for https://github.com'.
- Consequence: ZABZ-YOGA cannot fetch or pull ANY repo from GitHub. Verified by contrast: the same command on ZABZ-TECH (desktop-ts) succeeded and resolved the new docs branch.
- Separately, the laptop's checkout of personal-secretary-mvp is on branch feat/owner-direct-request-sms at bf6f4957, not master - so even with a credential the doc would need an explicit branch checkout there.

WHY IT MATTERS: this is the machine the owner works on at night. Anything written on any other machine does not reach it. It also silently breaks any automation that assumes the laptop can pull.

WHAT WOULD FIX IT: either run 'gh auth login -h github.com' on the laptop (cleanest - a per-machine token), or install the working credential already stored on secratary (~/.git-credentials, two github.com entries). Credentials are the owner's call, so this was put to him as a question rather than done silently. Note AGENTS.md says the GitHub PAT rotates, so any copied credential needs a reminder to re-rotate.
