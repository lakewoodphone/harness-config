## P16b — 8,182 files written for two days, every one of them empty

**Symptom.** `personal-secretary-mvp/docs/drn/generated/` accumulated **8,182 files** (a JSON+CSV pair
every ~30 seconds starting 2026-09-09 20:50). Every one is a 463-byte record whose own content says
`rows_total: 0, rows_with_phone: 0, rows_blank: 0`. It was still running when found.

**Evidence.** File inventory read 2026-09-11; newest `drn-live-phone-source-2026-09-11-125139.json`;
writer is `scripts/drn-export-live-phone-source.py`, whose inputs
(`docs/drn/inputs/drn-owner-sheet-2026-07-08.csv`, `drn-live-phone-source-template.csv`) resolve to
0 rows. **The invoker is not on this host** — no matching process and no matching scheduled task — so it
is driven from elsewhere in the six-node mesh and is not yet identified.

**Cost.** Repo bloat, and a directory that makes `git status` and content search useless, plus ~2,800
wasted file writes a day. Low severity, high noise. More importantly this is a *second* instance of the
same pattern as P15: **a job producing provable nothing, on a schedule, with nobody watching the outcome.**

**Fix.** (1) Identify and stop the invoker. (2) Make the exporter refuse to write when it has 0 rows —
a zero-row export is a failure, not an artefact. (3) Delete the 8,182 files (all provably empty).
(4) Add `docs/drn/generated/` to `.gitignore` so generated output cannot enter the repo either way.
