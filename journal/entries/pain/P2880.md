## P2880 — The deploy target is out of disk, so no deploy can complete

The Hetzner deploy target (lpt-apps-01, 2.28.33.58) cannot build a backend image: `/` is 75G with
0-990MB free, and `docker build` dies with "no space left on device". Measured 2026-10-09:
docker images 45.57GB of which 30.16GB reclaimable (23 images, 13 in use), build cache 11.2GB that
`docker builder prune -af` will NOT reclaim (BuildKit reports it in use), volumes 1.93GB.

WHAT WOULD FIX IT, in order of preference:
1. `ssh lpt-apps 'docker image prune -a --filter "until=336h"'` - frees most of the 30GB and keeps
 the last two weeks of images as rollback targets. Every removed image is rebuildable from its
 commit by the new one-command pipeline, so nothing is truly lost.
2. Grow the 75GB disk (it has been above 95% for a while; this will recur).
3. Delete stale release tags by hand.

NOT DONE because it is a production host and image removal is the owner's call. Until it is done,
NO deploy can succeed on this repo - the CI path is proven up to `docker build` and then the target
refuses. That makes this the single highest-value unblock in the shop's CI right now.
