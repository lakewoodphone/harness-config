## P6316 — harness-config's GitHub mirror is diverged and every push prints a misleading rejection

harness-config has two push URLs on `origin` (the GitHub mirror and the authority on secratary), and the
GitHub one has been rejected as non-fast-forward for days. Measured 2026-10-13:

- `offsite/main` (GitHub) vs local `main`: **2 commits on GitHub that we lack, 187 on our side that
 GitHub lacks.** Merge base 2026-10-08 00:30. So the mirror has been diverged for at least five days,
 and the divergence grows with every journal commit.
- **Consequence that actually costs time:** every `git push` prints
 `! [rejected] main -> main (non-fast-forward)` and `error: failed to push some refs` for GitHub, then
 **succeeds against the authority**. The failure output reads like the push failed. Anyone who stops at
 the error will believe the journal was not pushed when it was. Read the whole output, or use
 `git push origin main` and check `git ls-remote` / the authority, not the exit summary.

**Why it is not a two-minute fix:** attempting `git merge offsite/main` produced six conflicts, and they
are two different kinds of thing:
- **Generated, safe to regenerate:** `journal/index/entries.tsv`, `journal/index/journal.db`,
 `journal/index/stamp.json`, `journal/state/absorb-stamp.json`, `journal/alloc/bands.tsv`. (Careful:
 `alloc/bands.tsv` is an id-allocation ledger, not a pure cache — it must be unioned, not taken from one
 side, or id bands are lost.)
- **A real content conflict:** `presets/zabz/skills/fast-search/SKILL.md`. The GitHub side carries
 "fast-search tested end to end (five silent defects fixed)" and both sides have edited that file. This
 needs a real three-way read, not a strategy flag.

**What makes it worse:** the repo has a live concurrent writer. During this session `index.lock` was
present, `HEAD` moved twice under me (a67750b1, 0aaa4a17), and the journal tool auto-commits generated
index churn — so a merge can be invalidated mid-flight by another session's commit.

**What would fix it:** at a quiet moment, with no other session committing in harness-config:
1. `git fetch offsite`
2. `git merge offsite/main --no-edit`
3. Resolve the four generated index files and `alloc/bands.tsv` by **union** (or by taking either side and
 running `journal.py` so the index rebuilds itself); resolve `alloc/bands.tsv` by union of lines
 specifically.
4. Read `presets/zabz/skills/fast-search/SKILL.md` on both sides and merge the five defect fixes by hand —
 do not take one side blindly, it is a loaded instruction surface on every machine.
5. `journal.py check` must report 0 errors (it did, before and after this session's aborts).
6. Push to both URLs and confirm with `git ls-remote`.

Until then: **the authority (secratary) is the complete record, and the GitHub mirror is stale.** Do not
read the mirror to decide whether a journal entry exists.

Evidence: `git rev-list --left-right --count offsite/main...main` = `2 187` on 2026-10-13; the merge
conflict list above; `git push` output showing the GitHub rejection followed by a successful push to
`secretary-ts:/home/zabz/harness-config.git`.
