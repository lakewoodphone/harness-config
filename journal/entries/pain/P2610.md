## P2610 — The preset plane is invisible to every boot-based gate; only static resolution can catch preset breakage

## The preset plane is invisible to every boot-based gate: presets belong to neither the composed tree nor any headless run

MEASURED 2026-09-28 (ZABZ-TECH), with a canary that removes all doubt.

1. Presets contribute **zero rows** to `dsh --profile web --dump-config`; the 14 preset-exclusive row
 ids in `zabz` appear in the composed tree in no form. On the 0.1.7 line this is no longer merely
 "not listed" -- local presets are not read at all (see LESSONS L2375).
2. A **headless** run does not load a preset either. Three staged `DSH_HOME`s, candidate engine
 `0.1.7-rc.2`, one trivial prompt each:
 ```
 A repo presets, new names exit=0 "OK" stderr empty
 B live presets, old names exit=0 "OK" stderr empty
 C preset row names a package THAT DOES NOT EXIST exit=0 "OK" stderr empty
 ```
 Stage C named `@deepseek-ai/dsh-package-that-does-not-exist-xyz` in a preset row and **nothing
 complained**. The headless profile's own composition has 95 rows and **no preset-service row at
 all**, so presets are never resolved there. (`web` has that row, and 193 rows; `mesh` has it via
 the insert in `profiles/mesh/cordis.patch.yml`.)

WHY THIS MATTERS: verify gate G5 ("a headless agent turn completes") is the pipeline's strongest
end-to-end gate, and it **cannot detect preset breakage**. Neither can G1/G2/G3 (they read the
composed tree, which presets are absent from). So for the agent's own persona and for session
creation, the **only** detector is *static resolution*: check every `name:` in every preset file
against the candidate install. That is gate G7 in `harness-config/dsh-update/SPEC.md` section C3, and
this measurement is why it is not optional.

A related trap: an unresolvable **bundle** fails `--dump-config` loudly (`cannot resolve profile
bundle "dsh-plugin-attention"`, exit 1), but an unresolvable **row package** does not -- a mesh profile
composed 97 rows and exited 0 while its `insert:` row named a package that had been removed upstream.
`--dump-config` validates bundles, not row packages.

METHOD NOTE: a three-way staged test costs three small model calls and is worth it; the first attempt
was invalid because PowerShell's `$home` is read-only, so `DSH_HOME` silently became
`C:\Users\ezabz` and the engine created a stray `profiles/`, `sessions/` and `storages/` there.
Use a variable name that is not a PowerShell automatic. The stray paths were quarantined (moved, not
deleted) to `~\_stray-dsh-home-from-my-mistake-20260928T1453`.
