## P242 — lpt-hub on ZABZ-TECH is a diverged branch, so case work written there is invisible to the fleet

**The pain.** ZABZ-TECH's `lpt-hub` checkout is a diverged branch: 48 commits ahead of `origin/main`,
2775 behind, and `git merge-base --is-ancestor origin/main HEAD` is false — the histories are not
related by ancestry. Nothing written in that checkout reaches the fleet until someone reconciles it, and
nothing the fleet writes reaches it.

**What it already cost.** `docs/customer-operations/cases/14in-laptop-weitman-8483336341-2026-09-14.md`
— 900 lines, the whole laptop sale for a live waiting customer — lived only on that laptop from
2026-09-14 to 2026-09-17. The secretary bot had meanwhile pushed the file's *sync record* to
`origin/main`, so every machine could read a mirror of a case file that did not exist anywhere the
fleet could see. A previous session on the Mac mini saw this, wrote "the case file is not on GitHub …
Say the word and I'll push" into its final message, and stopped — which is exactly the halt-to-ask
pattern that costs this system its work.

**The fix, and what is still missing.** 2026-09-17: the case file and its source session were committed
directly onto `origin/main` (`12368820e`), and the full desktop lineage was preserved on
`origin/rescue/zabz-tech-lpt-hub-20260917` (`624ba0647`). What is still missing is a reconciliation of
the two histories — a 48-commit rebase onto a 2775-commit-ahead main, which will conflict on at least
`non-device/Computer-Sourcing/deals-log.md` and `docs/customer-operations/cases/`. Until that is done,
the desktop checkout keeps drifting and the same near-loss repeats on the next case written there.

**Measured, not assumed:** `git rev-list --count origin/main..HEAD` = 48; the same command reversed =
2775; `git ls-tree origin/main -- docs/customer-operations/cases/` held 183 files and no Weitman laptop
case before the fix.
