## P2935 — The mesh has no way to hand a file to a worker, and its broker is a single point of failure on secratary

## The mesh has no way to hand a file to a worker, and its broker is a single point of failure on `secratary`

Measured 2026-10-11, dispatching 26 workers for the Yanofsky profile.

**What hurt, ranked.**

1. **Every mesh dispatch depends on one broker on one host.** Ten dispatches in one burst, four died:
 `remote-ssh: broker-unreachable: the placement broker could not be reached at
 secratary-ts:http://localhost:3091/place — ssh: connect to host secratary.tail93e6e6.ts.net port 22:
 Connection timed out`. Immediately afterwards `ssh secratary-ts` alternated between answering
 (`hostname` → `secratary`, and a `curl` to port 3091 returned HTTP 404, i.e. the broker was up)
 and timing out. Six of the ten survived on `zabz-tech`. There is no fallback and no queue: a
 dispatch in that window does not wait, it fails.
 **Fix**: make the dispatcher degrade instead of failing — if the broker cannot be reached, place on
 any node already known-good from the local ssh config (here `desktop-ts` answered throughout), and
 say which node it chose. A broker outage must not be indistinguishable from "no capacity".

2. **A worker cannot be given a file that lives on another machine.** The book text existed only on
 this laptop. There is no mesh file transfer, so the fan-out had two options: push the inputs to
 the nodes and hope the child lands where they were pushed, or run the children locally. I pushed
 `_raw` to `zabz-tech` and `secratary` first, then moved the whole book half local when the broker
 failed — meaning 18 of 26 children ran on the laptop the owner was sitting in front of, which is
 exactly what the fleet doctrine says to avoid.
 **Fix**: a first-class "attach this path/dir to the brief and materialise it on the child's node"
 in the dispatch, with the sha256 recorded on both sides. Until that exists, file-local fan-out is
 manual scp in both directions (see `tools/collect.ps1`).

3. **The background-job ceiling is 10, and it is the fleet's real concurrency cap**, not memory. The
 governor granted a 24-slot budget on this host; the job registry refused the 11th subagent. That
 is fine, but it has to be planned for: a 26-worker job is three waves, and the waves only advance
 as earlier workers settle, so the slowest worker sets the pace of the whole fleet.
 **Fix**: nothing to fix — just brief the manager to expect it (this job queued seven workers and
 launched them as slots freed, which worked).

**Not a pain, worth recording**: the 45-minute ceiling per dispatch and the never-redispatch-a-started-
child rule behaved exactly as documented. No worker was silently rerun, and no work was duplicated.
