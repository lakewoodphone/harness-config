## P2540 — The owner health record lives on unmerged branches and the live checkout is not uniformly the newest copy of each file

**P2xxx · The owner's health record — the single source of truth for his body — lives on unmerged per-session branches, and the authority's checkout is not uniformly the newest copy of each file.**

First seen 2026-09-25 (ZABZ-YOGA). Still open.

WHAT HURTS, MEASURED.
- `docs/personal/health/` **is not on `origin/master`**. `git ls-tree origin/master -- docs/personal/health` returns **empty**. The record exists on `docs/owner-health-2026-09-18`, `docs/owner-health-2026-09-20`, and now `docs/owner-health-2026-09-25` (pushed 2026-09-25).
- **The newest copy of the record was not on any branch at all.** On 2026-09-23 the authority's checkout held §1–§33 (147 KB) as an **uncommitted modification on its local master**, while the branch that a fresh session would naturally branch from held §1–§16 (30 KB).
- **Drift is per-file and bidirectional.** Measured the same day: the authority's `groin-skin-condition.md` was 43 lines *behind* the branches (missing §9); its `README.md` and `recurrent-febrile-episodes.md` were far *ahead*. There is no single "newest copy".
- **The authority cannot push** (`git push` needs credentials in BatchMode; branch 126 ahead / 176 behind). **It can fetch**, verified 2026-09-25 — so publishing works, but the authority is a consumer, never the publisher.
- Consequence: a session that trusts the obvious branch would silently publish a record missing 17 sections and a treatment section — and `docs/personal/health/` is what every future session reads to answer anything about the owner's health.

WHAT WOULD FIX IT.
1. **Get `docs/personal/health/` onto `master`** and stop shipping the source of truth on per-session branches. The reason it was kept separate (H601: master's divergence, 48 conflict blocks in 7 core files) is real, but it is a *merge* problem and the record has now been hostage to it for a week across three abandoned branches.
2. **Make the authority's checkout converge** — reconcile its 126-ahead/176-behind local master, or repoint the service at a clean checkout (P49). Today the fix was manual: `git fetch origin <branch> && git checkout origin/<branch> -- docs/personal/health`.
3. **A staleness check with a clock on it.** "Newest health-record commit vs. what is on disk here" as a kernel check, on the same principle as `db_writable` (H2729) — absence of signal is the failure, not presence.
4. Cheaper interim guard, doable today: a header line in the directory stating the branch and commit that the file set corresponds to, so a reader can tell at a glance whether they are holding the head. Partly done — §34 records the commit it was written against.
