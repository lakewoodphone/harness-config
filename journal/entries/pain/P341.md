## P341 — The authority's database has no cheap test fixture, so every test that needs realistic data tempts a full 9.8 GB copy

**P · 2026-09-20 · ZABZ-YOGA — The authority's database has no cheap test fixture, so every test that needs realistic data tempts a full copy**

**What hurts.** `/home/zabz/personal-secretary-mvp/data/secretary.db` is **9.80 GB** (measured 2026-09-20 in
the kernel report's own `database.size_bytes`) on a **dm-crypt** volume, and it is the *live* database: the
shop's inbound calls and texts, the agents' ticks, and the API all write to it. There is no small fixture
of it anywhere, so a task that needs realistic rows — like testing a guard that reads `tasks`,
`reminders` and `owner_message_queue` — has exactly one obvious-looking move: copy it. That move cost
**25 minutes of disk saturation** on 2026-09-20 (load 23.87, tailnet `/health` at 18.5 s, ssh handshakes
timing out) and the copy had to be killed by hand from a channel it was itself breaking. Lesson L2089.

**The specific numbers.** The three tables that guard actually needed hold a few hundred rows; the copy
moved 9.80 GB to obtain them.

**What would fix it.**
1. **A fixture builder**: `scripts/make-test-db.py` that writes a scratch SQLite file with the schema for a
 named list of tables plus N rows per table (deterministic, no customer data), defaulting to
 `tasks`/`reminders`/`owner_message_queue`. A test then runs in milliseconds against a file that is
 kilobytes. This is the fix; everything below is a guard rail.
2. **A guard rail if the builder is not used**: `VACUUM INTO` with a `WHERE`-filtered source table — not a
 file copy — and always with a size cap and a time cap in the instruction.
3. **A rule in every brief that touches the authority**: state the size of the thing being touched
 (`du -sh` first) and forbid any operation proportional to the whole database. A brief that says "copy
 the DB" is an instruction to degrade the company, however harmless it reads.
4. **A printed size in the fixture path**: the maker refuses to run if the target table's `COUNT(*)` is
 above its cap and tells the caller to sample instead, so the default cannot be the expensive thing.
