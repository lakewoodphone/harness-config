## P6337 — The engine-port fallback opens windows with a STALE token, and live-url.txt is never written on a normal boot

**What is still broken in the same failure, and is NOT fixed. Two defects, both mine to do.**

**1. `live-url.txt` does not exist.** `~/.dsh/multi-window/live-url.txt` is the one file that is supposed to answer "open this URL" — the engine's current URL with its current single-use token — written by `Set-LiveEngineUrl`, called ONLY from `Start-EngineDetached` (the `-Detached` path). A normal boot does not write it: measured on ZABZ-TECH 2026-10-14, `Test-Path` -> MISSING while the engine had been up since 08:12:09. So the file that exists to make the current token readable by anyone is absent on the ordinary path.

**2. The fallback opens a window with a STALE token.** Measured in `~/.dsh/multi-window/windows.log`: at 2026-10-14 08:12:50, six seconds after a NEW engine had minted a new token at 08:12:09, the launcher opened five windows with `--app=http://127.0.0.1:3200/?token=zkhRwa6zmpK6nsz9n0yMkN95d5j-MoyNIdyYyTxHqd4` — the token from 2026-10-12 — and `verify=skipped-direct-to-engine`. The engine answers a consumed/unknown token with `401 dsh web authentication required; reopen the URL printed by dsh web.` (68 bytes, no title), which in a browser is a blank tab titled `127.0.0.1`. That is what the owner saw and called "404 unreachable"; the browser history at 2026-10-13 21:53:17 and 2026-10-14 08:12 shows the same title for the same reason.

**Why it matters:** the deliberate degraded path ("proxy is down, open against the engine port so you still get a GUI") does not actually give a GUI — it gives an auth page — and the 5 windows collapse onto ONE origin (3099), so they also lose their per-window session isolation. With the proxy now on a base Windows cannot reserve, this path is rarer, but it is the path that turns a control-plane hiccup into "dsh is broken".

**The shape of the fix:** have the launcher read the live URL immediately before opening a window (state.json's 3099 url is the fallback, and it can be up to a minute stale), write `live-url.txt` on every successful start rather than only the detached path, and make the engine-port fallback use the freshly read token.
