## P8587 — The mesh placed five children on a different branch of the right repo, and every artefact had to be re-verified line by line

## The mesh placed five children on the wrong node, and every one of them edited a different branch

Measured 2026-10-19, `kosher-filter-ai` discipline run, ZABZ-YOGA. Five `subagent` calls, each briefed
with the absolute path, the branch (`agent/kf-counter-install-nonwipe`) and the files they owned.

**Five of five ran on `ZABZ-TECH`, in a checkout on `agent/kf-compliance-contact-20261018`.** The mesh
recorded why in its own header: local pressure was HIGH (85.3 % of physical committed), so the broker
declined the local option and placed each child remotely — and it placed them on the one node that had a
*checkout of the right repository* but on a *different branch*. Every child reported the mismatch at the
top of its answer, which is the only reason this was recoverable.

What that cost, in order:

1. **Nothing they wrote was in this tree.** Six Kotlin files, four test files and four new documents had
 to be scp'd back, file by file.
2. **Four of six Kotlin files were byte-identical between the branches and two were not**, so "the patch
 applies" was not the same question as "the citation is true here". Fifteen `path:line` citations had
 to be re-measured; `BrokerHeartbeatService.kt:2185` was `:2237` here, `PolicyApplier.kt:687` was `:702`.
3. **Two findings were true of the other branch and false of this one** — a notice contact block that
 exists there and not here, and a `docs/README.md` index that exists there and has been deleted here.
 Both were caught only because the claims were checked against this tree before being published, and
 one of them (the contact block) I had already written down wrongly and had to correct in public.
4. **One child could not do its job at all**: it was told to update `docs/TEST-COVERAGE.md` in place, and
 that file has never existed on the other branch. It correctly refused to invent one.
5. A child's local test run and this host's disagreed on the same file, because `ZABZ-TECH` has no
 `server/.venv` and ran on `C:\Python313` with different package versions.

**The rule, and it is not "don't use the mesh":** the broker chooses the node from pressure and fit, and
it does not know what branch a checkout is on. So the brief must ask the child to *report* `git log -1`
and `git rev-parse --abbrev-ref HEAD` before it touches anything, and the manager must treat a reported
mismatch as **a diff to be re-verified against the intended tree**, never as a completed workstream.
Research delegates cleanly across a fleet; a build is only as good as the tree it lands in. When the
result is a patch from a foreign base, re-check every line number, and re-read every claim that could be
branch-specific — a compliance fact, a generated document, an index that has since been deleted.

A second, cheaper fix: check local pressure *before* fanning out. Two of these five children were doing
work that needed no parallelism at all, and the placement cost more than the parallelism bought.
