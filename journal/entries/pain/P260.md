## Why that blocks the push

A merge would need a clean tree for `audit.py` and would land in a real
conflict in `lptcase.py`, which is the case index every lookup runs through.
Resolving either means finishing or discarding another session's in-flight work.
Not something to do unilaterally while a customer case is being written.

## Consequence, and it is the point

Nothing committed on this machine is visible to the digest, the drift verifier,
or any other host. `lptcase.py` says so on every single run. Also: the index
this machine searches is 26 commits stale, so a case created elsewhere is
invisible here - which is how a duplicate case gets created for a customer who
already has one.

**Guard before creating any case on this machine:** `git fetch` first and search
`origin/main` for the phone/device as well as the local index:

 git grep -l "<phone-or-device>" origin/main -- docs/customer-operations hardware-diagnostics

## The safe move that was taken

Commit to local `main`, then push the commit to a TOPIC BRANCH rather than main:
`git push origin HEAD:refs/heads/<topic>`. Non-destructive, no force, no merge,
and the work becomes visible and backed up. `origin/rescue/authority-customer-
sync-20260917` already exists, so topic branches are an established pattern here.

## Next action

Someone who owns both workstreams should merge `origin/main` into `main`
(resolving `lptcase.py`), commit or stash the `audit.py` edit, and push. Until
then every case written on this machine is single-copy.
