## P152 — The suite's residual failures are flaky: ~six members, membership varies per invocation, three visible mechanisms

**P-new — the suite's residual failures are a flaky set, membership varies per invocation.**

Measured 2026-09-15 after the quiet-hours fix: `pytest tests/` gives **4 failed / 2,711 passed / 0
errors**, and the four are not the same four between runs. Across six invocations of just
`tests/test_family_chat.py tests/test_family_chat_personality.py` the failures appeared as
`TestWorker::test_worker_clears_in_flight_after_send` (twice), `TestHardGates::test_dormant_cooldown_blocks`,
and in full-suite runs also `TestMemberCommands::test_muted_member_queued_outbox_dropped`,
`TestSpendAccuracy::test_no_duplicate_message_rows_after_flush`,
`test_api_endpoints::test_twilio_sms_timeout_sends_async_followup_reply`,
`test_family_chat::TestAtomicDedupe::test_duplicate_webhook_deliveries` and
`test_phase3_modules::TestPhase3ConfigFlags::test_mcp_enabled` -- roughly six known members, one to
four per run, with `test_mcp_enabled` the most persistent.

Three mechanisms are visible in the code and each is cheap to test:

1. **time arithmetic with the server-local helper** -- `test_dormant_cooldown_blocks` patches `_now_ts`
 to `_local_ts(14)`, the same server-local helper that just caused four failures; a cooldown window
 computed across zones can land inside or outside by an hour depending on when it runs.
2. **a thread and a marker** -- `test_worker_clears_in_flight_after_send` asserts
 `_in_flight_until() == 0.0` after `_worker()` runs, where the worker starts a thread; if the
 assertion wins the race it fails, which is a race, not a bug in the marker.
3. **shared mutable settings** -- `test_mcp_enabled` asserts `settings.mcp_enabled is True`, which is
 exactly what a *previous* test mutating a global would break; that is state leakage and it is
 order-sensitive by construction.

Fix order: (3) is the cheapest (find the mutator, restore it in a fixture), then (1) via the same
`_family_ts` treatment, then (2) with a bounded wait instead of an immediate assert.
