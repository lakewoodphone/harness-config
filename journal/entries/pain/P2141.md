## P2141 — P2124 - work is queued onto an unreachable mesh node and reported as running: the 30-minute silent black hole

**The owner's words, 2026-09-20: *"if the desktop isn't there than it should go somewhere else on the mesh, not fail
silently, what the heck"*. He is right, and this is the exact defect.**

## What happened, measured

Four mesh children were dispatched. The dispatcher reported them running. **Nothing ran for 30 minutes.**
Root cause found by reading the code, not guessing:

`packages/plugin-remote-fanout/lib/placement.js`, `waitForSlot` (the queue wait):

```
if (freeSlots !== null && freeSlots >= children) { freed = observation; break; }
...
note: freed === undefined
 ? `no free slot appeared within ${wait} ms; dispatching anyway (queue, never amputate)`
```

An **unreachable** node has no capacity reading, so the broker reports `freeSlots: null`. The condition
`freeSlots >= children` can therefore **never** be true — the loop is guaranteed to burn its entire
budget, and then the code **dispatches anyway** under "queue, never amputate". The ssh hop that follows
has no listener to fail against, so it hangs to the turn cap. A dead node's answer is
indistinguishable from a busy node's.

Contributing facts, all measured:

- **The broker appends, it does not exclude.** On 2026-09-20 with `zabz-tech`'s gate dead, the broker
 reported it `unreachable` (`HTTP 502`, last good reading 10,985 s old) **while four other nodes were
 healthy and idle** — `zabz-yoga-1`, `zabz-tech-linux`, `secratary`, `lakewooechsmini` all `ok`.
 Its own docs are explicit: `broker.js:527` — *"unreachable ... reported, never dropped, never faked"*,
 and *"queue, never amputate"*. The rule is deliberate; a caller declining the answer is not.
- **`mesh-health.json` said the machine was fine.** It reported `desktop: {reachable: true}` the whole
 time, because **ssh** answered. The machine was up; the *gate* was what died, and the gate is the only
 thing the broker reads. Liveness by ssh is not liveness for placement.
- **Both keep-alive tasks are `logonType: Interactive`** (`DSH Phone Gate`, `DSH Engine Watchdog (1m)`,
 principal `ezabz`, Windows desktop). They run only while the owner's desktop session is live, so they
 stop firing exactly when he logs off or the box reboots — and nothing alerts.
- **Nothing watched node visibility.** No cron on the authority read the broker.

## What was DONE this session

- **`scripts/mesh-placement-monitor.py`** (new, committed, deployed to `~/bin/` on the authority, cron
 `*/5`). It reads the broker with `?fresh=1`, **confirms a failure with a second forced read** before
 alerting, and reports per node. Exit 1 when any node cannot take work; an EMPTY roster is a failure,
 not a pass. It notifies through the app's owner-notification queue (never SMS — the owner kill switch
 is live). Verified live: it immediately named `zabz-tech ... MISSING ... HTTP 502 (reading 559s old)`.
- **`zabz-tech` recovered** during the session (engine on 3099 restarted, gate on 3086 answering
 `/mesh/capacity` HTTP 200, all five nodes `ok`) — then the desktop went off the tailnet again, which
 the owner explained: *"we were fixing the desktop windows hello so we rebooted it a bunch of times
 today"*.

## THE FIX, NOT YET LANDED (do this first next session)

`waitForSlot` must distinguish **unmeasurable** from **busy** and the caller must failover. The
diagnosis and a working patch were written and reverted unlanded; the shape that is right:

1. In `waitForSlot`, after the loop, take **one** `readNodeStates(broker, logger)` (a module-level
 helper already sketched in `lib/placement.js:200`) and return `nodeUnmeasurable: true` when the
 chosen node is `unreachable` / `absent` / `capacity-unreadable`. **Do not add a read inside the
 loop and do not add one in `acquire`** — measured: either shifts the mocked-read counters and
 changes the wait's own timing (`test/placement.test.mjs:158` expects `waitedMs 15000` from three
 polls, and it becomes 10000/2).
2. The **provider** (`lib/provider.js`), not the placer, owns the failover: on `nodeUnmeasurable`,
 release the lease (`broker.done(lease, false)`) and re-ask with that node in `exclude`, bounded to
 one retry, recording a `reachabilityNote` on the placement. Placement is per child, so a re-ask is
 safe; a second `acquire` in the placer would not be.
3. Never leave "dispatched anyway" as the outcome of an unmeasurable node. If nothing else is
 eligible the child must be **reported as not started**, not as running.

**Definition of done:** a test that names an unreachable node while another answers, and asserts the
child ends up on the answering node with the dead one excluded; plus `npm test` in
`packages/plugin-remote-fanout` green (112 tests today, `waitForSlot`'s timing tests unchanged).
