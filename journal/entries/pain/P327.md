## P327 — memories.category='health' is a write-only dumping ground: 44 rows, 0 health facts

WHAT HURTS: the memories table's 'health' category holds 44 rows (measured 2026-09-18 with SELECT category, count(*) GROUP BY category) and every one of them is a near-duplicate CHEMED portal notice ('test results available on the patient portal'), spread over 2026-09-06 to 2026-09-16, plus duplicates of the same notification under 'health_wellness' and 'health-followup'. Not one row records a symptom, a condition, a medication or a provider.

WHY IT MATTERS: any agent asked 'what do we know about the owner's health' queries that category by its name, gets 44 plausible-looking hits, and concludes there is a health record. That is exactly the P3 failure - reading the wrong data and believing it - applied to the owner's body. It also means a real health fact written into that category would be invisible in the noise.

WHAT WOULD FIX IT: (a) DONE 2026-09-18 - a source-of-truth record now exists at docs/personal/health/ with a README index and a per-condition file, indexed into owner_profile_v2 category=health; (b) NOT DONE - stop agents filing portal notifications as category='health'; they are operational task state, not health records, and should carry a distinct category or live only in the task system; (c) NOT DONE - retire or supersede the 44 legacy rows so the category is not read as a record.
