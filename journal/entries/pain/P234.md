## P234 — P229 — waze-mdm fleet state defects measured 2026-09-17 (alert age, DRN 26 flood, false critical, blind registry, dead metrics)

## P — waze-mdm fleet state defects, measured 2026-09-17

Ranked from a read-only audit of the live fleet (readings 03:55–04:02Z; full report `_scratch/fleet-audit-state-20260917.md`, endpoint detail `_scratch/fleet-api-endpoint-audit-20260917.md`). Each one has a fix; none is fixed yet except where noted.

1. **`/fleet/health` can never report alert age.** `_raise_alert` does `UPDATE fleet_alerts SET message=?, severity=?, created_at=CURRENT_TIMESTAMP WHERE id=?` on every refresh and the table has no `updated_at`, so `created_at` is rewritten. Proven: ids 153/166/161/162/164/171 read 03:30:01 at 03:56Z and 04:00:01 at 04:01Z. `alert_age_days: 0.0` and `alerts_aged: 0` are structurally always zero while the oldest true condition (DRN 39) is 101 days old. The endpoint's own comment says those fields exist to expose a silent alert pipeline — the refresh defeats exactly that. Fix: never rewrite `created_at`; add `updated_at`.
2. **The queue number was 68% bookkeeping** (541/578 reported vs 179 real). *Fixed 2026-09-17* — see the queue lesson.
3. **One dead test device owns the real backlog.** DRN 26 (`G90G2C5WK7`, group `test`) holds 141 of the fleet's 179 undelivered rows — 132 of them `Settings` — and is still being fed (newest created 2026-09-17 04:00:01Z) while its last check-in is 2026-09-11. The enqueue path has no give-up and no bound.
4. **False critical alert.** DRN 40's "has NEVER checked in" is wrong: `fleet_devices.enrollment_id IS NULL` while enrollment `00008110-001175AA34D3601E` (serial GDYHW70QXH) exists and last checked in 2026-07-12. The monitor's LEFT JOIN finds nothing → `stale_never:40` critical, wrong since 2026-09-15.
5. **The registry is metadata-blind while the data is already on disk.** `product`/`version` `device_class` NULL/unknown for all 65, `udid` NULL for 21 — yet 102 `Acknowledged` DeviceInformation results cover 49 devices (DRN 48 and 54 both iOS 26.5.1 / 23F81). A backfill costs no device interaction; I had to hand-query Postgres to learn a device's iOS version.
6. **`device_profiles` is empty (0 rows, never populated)** though fresh ProfileList results are on file. "Is the kiosk profile installed?" is unanswerable.
7. **Duplicate identity + broken joins.** DRN 21 and DRN 41 are two registry rows for ONE enrollment (41's serial is a placeholder `ZZTMP5DRN103`), so both get alerts and a batch hits the device twice. DRN 1006/1007 have lowercase serials that do not join to `devices.serial_number`.
8. **`/fleet/stats` serves a 73-day-dead metric as current**: `avg_queue_depth: 0.0`, `max_queue_depth: 0`, `snapshot_rows: 3572`, all from `fleet_queue_snapshots` whose last row is 2026-07-05 — while `/fleet/health` (same service, same second) says 179 outstanding. The claimed producer `POST /fleet/health/snapshot` is in no crontab.
9. **`fleet_device_health_history` is permanently healthy**: the 30-minute monitor's INSERT literally hardcodes `queue_depth = 0, push_ok = 1`, so DRN 26's history reads `0/true` while its live queue is 138. Also grows ~130 rows/hour, never pruned.
10. **`healthy: 55` means `state = 'deployed'`**, not healthy — DRN 39/5/15/26/2001 are counted healthy and stale in the same response. And 62 of 65 devices have not checked in for >24h, but that band is *our* silence (last fleet-wide push 2026-09-15 13:50), not 49 broken phones. Report it as such.
11. **Two Telnyx endpoints disagree with each other** about the same two SIMs (blocked/2.0 GB/184 MB vs enabled/0.8 GB/214 MB) and the usage snapshots are ~23h stale.
12. **`push-channel` returns a false negative that blames the device** — it reads the retired filekv path while `verify` reads Postgres and shows a live token 6 minutes old.

What would fix the class: the merged fleet-api (plan in `_scratch/fleet-api-merge-plan-20260917.md`), a scheduled `health/snapshot`, an ingest path for DeviceInformation + ProfileList results, and never letting an enqueue acknowledgement stand in for a device result.
