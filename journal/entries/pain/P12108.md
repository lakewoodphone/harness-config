## P12108 — The deployed profile patch is not the repo's and nothing syncs them (web 123,851 B vs 152,995 B)

The DEPLOYED profile patch is not the repo's profile patch and nothing syncs them.

Measured 2026-10-26 on ZABZ-YOGA by `scripts/preset-drift.py`:

 DRIFT profiles/web/cordis.patch.yml repo=7579464d9bea loaded=537069ebd79d [123851B vs 152995B]

Before today's edit the loaded copy was 152,398 B against the repo's 123,843 B — 1,885 inserted and 871
deleted lines between two files that are supposed to be the same lineage. The loaded copy carried the
persona's false rule 8 while the repo carried the corrected one, so a correction could be committed,
verified and reported fixed while every session kept loading the old text.

Consequences found today: (a) fixing rule 8 in the repo did NOT change what runs; (b) editing the loaded
copy in place broke it (a straight double quote inside the double-quoted persona scalar produced
`failed to parse overlay ... cordis.patch.yml`, which would have stopped the web profile booting) — the
backup at `~/.dsh/profiles/web/cordis.patch.yml.bak-rule8-20261026T182240Z` and a `--dump-config` exit-0
check are what caught it; (c) the same trap hides in `profiles/mesh/cordis.patch.yml` (9745B vs 9669B).

What a fix looks like: `profiles/<n>/cordis.patch.yml` must be DEPLOYED by a script, not edited on the
host, and `preset-drift.py` should run on a timer and alarm on drift. Until then, every persona fix needs
two writes and a diff of the two lineages — and `harness-sync`'s own step list (settings, presets, bundles)
does not include the profile patch, which is why nobody noticed.
