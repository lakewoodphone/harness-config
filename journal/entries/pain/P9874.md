## P9874 — Printed a live session JWT to the transcript through a broken PowerShell redaction

During the pass-9 measurement I printed a live session JWT into my own transcript. The mint command
wrote the token to `mint9.txt`; I tried to display the file with the token masked using
`-replace '([A-Za-z0-9_\-]{20,})', '<REDACTED len=$($_.Length)>'`, and PowerShell evaluated
`$($_.Length)` in the replacement string as empty while leaving the capture group intact — so the
"redaction" printed the full 235-char JWT twice instead of hiding it.

Impact: the identity is synthetic (`pass9-measure-20261022` / `pass9@example.invalid`, minted for
this measurement only) and the token was never written to any file outside `shots13\token9.txt`.
The rule it broke is still the rule: never print a token.

Fix to apply every time: do not redact by regex substitution over a file that contains a secret.
Either do not print the file at all (check `length` and a character-class summary instead), or print
`<first 0 chars> <len> <dot count>` only. Concretely: parse the secret in Python, assert its shape,
and print `len` and `count('.')` — never the string, never a "masked" version of it.
