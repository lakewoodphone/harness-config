## P2666 — A fleet worktree has no server/.venv, and pytest --basetemp=./_pt trips the frames write-guard

Measured 2026-09-28 on kosher-filter-ai kf0928 fleet worktrees (ZABZ-YOGA).

1. No venv. server/.venv is gitignored, so a fresh worktree cannot run the suite with its own interpreter; every run must point at C:\Users\ezabz\code\kosher-filter-ai\server\.venv\Scripts\python.exe. That works (tests/conftest.py puts the server root on sys.path), but it means a worktree run uses the main checkout's dependency set, so a requirements change on the branch is not tested. Fix: a setup step that copies or links the venv, or a documented shim.

2. Basetemp under the repo. --basetemp=./_pt is required (pytest's own tmpdir cleanup throws PermissionError on this machine), but ./_pt lands inside the work tree, and scripts/frames_commit_guard.py refuses to let tests/test_pilot_capture.py write frames anywhere inside the repository that no .gitignore rule covers. 20 of that file's 38 tests fail in every worktree, and pass in CI only because pytest's default basetemp is under %TEMP%. Fix: put the basetemp outside the repo (e.g. --basetemp=\C:\Users\ezabz\.dsh\tmp/lpt-pt) or add server/_pt*/ to .gitignore.

3. Log redirection into the basetemp. Redirecting pytest's own output to ./_pt/<name>.txt makes pytest fail at every test setup with PermissionError [WinError 32] when it deletes the basetemp tree, because the shell still holds the file. Cost one 30 s debugging cycle. Logs belong outside the repo.
