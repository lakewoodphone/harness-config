## P256 — The stage/finalize split has no release gate, so a half-hardened phone left the shop

What hurts: the E4610 customer flow is deliberately two-phase — `stage-e4610-standard.ps1` installs the
apps and stops, `finalize-e4610-standard.ps1` applies the lockdown — but nothing at handoff tells the
operator that a phone is unfinished. The staged run writes receipt + `deployments.status = staged` and
prints a STOP banner in a scrollback nobody reads, so a handset can walk out of the shop with our apps
working and: bloatware still enabled (stock browser, Email/Exchange, JPEG WebViewer, FM radio, Verizon
apps), no launcher/app-drawer default, no wallpaper, and no Tech Mode device admin or USB code
protection.

Observed 2026-09-17: serial 615765621 staged 17:45:19Z, handed to the customer before finalize
(deployments.id=244, receipt status `staged`). From the customer's side it "looked ready" — the apps
all work — which is exactly why the gap is invisible at handoff.

What would fix it:
1. Make `stage-*` impossible to miss: write a machine-readable pending marker while the receipt/DB stay
 `staged`, so any later check can list "staged, not finalized" handsets.
2. A one-line shop check before handoff — a `lpt history --pending`-style listing of serials whose newest
 row is `staged` — so "did we finalize this one?" is answered by data, not memory.
3. Prefer one end-to-end command for walk-in customer jobs where the operator will not be at the bench
 for the whole session, with the manual steps scripted through ADB (now that they can be — see the
 tap/uiautomator lesson).
