## P2869 — A mesh node with no working DNS is found by spending a real child on it

## A mesh node that cannot reach the model API is discovered by losing real children

Two dispatches were spent tonight before the node's DNS fault was visible: each returned the same
provider text, "the remote one-shot exited 1 and produced no final message ... dsh: TRANSPORT:
DeepSeek API request to https://api.deepseek.com failed". Nothing in the dispatch path checks
whether the node it is about to use can resolve the model host.

What would fix it: the node probe already reads each node's capacity over
`https://<node>/mesh/capacity`. Have the same probe report the node's own resolver's answer for the
model host (or have the node report `getent hosts api.deepseek.com` / `Resolve-DnsName
api.deepseek.com`), so a node with no working DNS is marked `transport.v1: false` BEFORE a child is
spent on it. The broker's own ranking then does the rest - it already ranks a transport-broken node
below a working one once it knows.
