## P3810 — lpt disable-features --no-text silently disables QR Reader + QuickOffice on a standard-tier E4810 (hardcoded standard-lite)

Measured on E4810 serial 558800255007, 2026-10-18 20:47-20:52Z, staging with `-NoText`.

THE DEFECT: `lpt disable-features --no-text --serial <s> --model E4810` DISABLES TWO APPS THE STANDARD TIER INSTALLS ON PURPOSE. On this handset it disabled com.android.mms (wanted), and also com.android.cts.qr (QR Reader) and com.android.cts.quickjack (QuickOffice). Cause, read not guessed: cli/lpt/cli.py:894 hardcodes `base_tier = "standard-lite"` and then disables `config.forced_disabled_packages`; standard-lite's profile carries forced_disabled_packages = [com.android.cts.sidsefard, com.android.cts.qr, com.android.cts.quickjack] (cli/configs/tiers/standard-lite.yaml:44-48). Those three exist in standard-lite because E4610's customer package excludes them - on an E4810 deployed with tier `standard`, qr-reader and quickoffice are shipped apps, so the command removes working apps from a sellable phone while reporting success. The command has no --tier and no way to know which tier the phone actually carries.

MITIGATION DONE: `adb shell pm enable com.android.cts.qr` and `pm enable com.android.cts.quickjack`; both read back enabled=1, disabled list is now exactly [com.android.mms, com.verizon.pushtotalkplus]. The deployment receipt logs/deployments/deployment-receipt-558800255007-20261018-204817.yaml therefore OVERSTATES what is disabled - it records qr and quickjack as disabled and they are not. Trust the device, not that receipt.

SECOND FACT, quieter: the staged deploy with standard-no-text does NOT disable messaging at all. `disable_texting: true` only clears sms_app_package/sms_fallback_app (loader.py:615-618) and puts the SMS packages into forced_disabled_packages (loader.py:601-609); the `--fast-stage` path never applies them - the disable belongs to finalize. After staging, `pm list packages -d` was empty and stock Messaging was still the default. So "phase 1 with texting off" needs the explicit disable step, or finalize.

VERIFIED END STATE: launching com.android.mms/.ui.ConversationList fails with "Error type 3 ... Activity class does not exist" - texting is actually gone, not merely unset. `settings get secure sms_default_application` still returns com.android.mms, because disabling a package does not clear that setting: the documented trap where "a disabled-but-default SMS app passes verify while the customer has no texting UI" is live on this handset. Message+ (com.verizon.messaging.vzmsgs) is not present at all, confirming the owner: E4810 ships without it and we no longer install it.

FIX NOT APPLIED, deliberately: the correct shape is for disable-features to disable only the packages belonging to the requested FEATURE (sms_app + sms_fallback_app for --no-text) instead of the whole tier's forced list, or to take the tier from the device's own receipt. Both change shared CLI semantics used by the E4610 flow, so it needs its own change with the test at cli/tests/test_cli_commands.py:1115 updated - not a bench-time patch.
