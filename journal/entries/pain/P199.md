## P166 — No byte-safe remote file read in the mesh: ps-mesh file corrupts records on round-trip

The mesh has no byte-safe file read. `ps-mesh file` is the documented way to read a file from another
machine, and on Windows hosts it silently mangles every non-ASCII character, so the natural workflow
"read a record over the mesh, edit it, write it back" quietly degrades customer records. It cost a
full rebuild of a 600-line case file this session, and it would have gone unnoticed if the file had
not contained em dashes that git reported as gratuitous changes.

What would fix it: add `get`/`put` verbs to `ps-mesh.mjs` built on scp (or on `base64 -w0` piped over
`ssh`, decoded on the far side), and make `file` say loudly in its own output that it is display-only
and not safe to round-trip. Until then the rule is: scp for anything you will write back, and verify
the result with a SHA256 on both ends.
