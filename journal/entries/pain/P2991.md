## P2991 — lpt-ops runs on the authority from a copy, not a checkout - commit and push does not deploy it

**What hurts:** `~/lpt-ops` on the authority is **not a git checkout** — it is a plain
directory that the tooling was copied into. So committing and pushing `lpt-ops` from the
laptop changes nothing about what actually runs when `lpt-label` is invoked there. Measured
2026-10-08: `ssh secratary-ts 'cd ~/lpt-ops && git log'` answers
"fatal: not a git repository", while the file present was byte-identical to the committed
HEAD blob (git hash-object ff6390e8) — so it was deployed by copy, by hand.

`lpt-write` solves this for itself: `bin/lpt-write` pushes `lpt_ops/write_helper.py` when its
sha256 differs and **refuses the call if the deployed copy does not re-hash to the local
one**. Nothing equivalent exists for `lpt_ops/label_printer.py`, or for anything else in the
repo. A change can be committed, pushed, tested green, and quietly not be running on the only
machine that can reach the printer.

**Why it matters more than it looks:** this is the same class of failure as the stale
`PRINT_SERVICE_URL` that made the work order page's Print Label button do nothing for months
while its code and 54 tests were correct. A tool that is right in git and absent in
production is indistinguishable from a tool that does not exist, and the person who finds out
is the owner holding a printer that produced nothing.

**What would fix it:** the `lpt-write` pattern generalised — a tiny `lpt-ops deploy` that
pushes every `lpt_ops/*.py` the authority's `~/lpt-ops` should hold, re-hashes each after the
push, refuses on mismatch, and prints the per-file sha256 of what is now deployed. Failing
that, at minimum make `lpt-label` refuse to run when its own module sha does not match the
checkout it was launched from.

**Worked around today** by `scp`-ing the one file and verifying with a sha256 comparison on
both ends (61d1cc1e both sides) plus an end-to-end dry run on the authority. That workaround
is per-file and per-session, which is exactly why it is written down here.
