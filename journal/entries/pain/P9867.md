## P9867 — The 2-minute terminal flash was journal.py refresh spawning git without CREATE_NO_WINDOW - one visible console per journal entry

**What the owner saw, and what it was.** 2026-10-21, zabz-yoga: a console window titled `C:\Program Files\Git\cmd\git.exe` flashing ~3x/second for about two minutes, on two evenings, always while he was working in a DSH session. It is `journal.py refresh`.

**Mechanism.** Every journal append calls `spawn_ceiling_refresh()`, which starts `journal.py refresh --delay 20` with `DETACHED_PROCESS|NEW_PROCESS_GROUP`. A detached child has **no console**. Inside it, `_git()` / `_git_repo()` / `git_max()` ran `subprocess.run(["git", ...])` with **no creationflags**, so Windows allocated a *new* console per git — and a new console on Windows is a visible console window. `refresh` walks the tree and runs git once per kind and per entry, so one ordinary append produced **157 git launches in 120 s**. Multiply by each append from any session on the box and you get a 2-minute flash storm.

**How it was named (and why it took two evenings).** Nothing could name it the first night: `4688` Process Creation auditing was **No Auditing** and `Microsoft-Windows-TaskScheduler/Operational` held zero events. I enabled 4688 with command lines at 18:20 (`auditpol /set /subcategory:"Process Creation" /success:enable` + `ProcessCreationIncludeCmdLine_Enabled=1`, verified with a marker process). At 18:41 the audit record gave creator pid 25468, `python.exe C:\Users\ezabz\code\harness-config\journal\tools\journal.py refresh --delay 20`, spawning 157 git in 120 s — and the owner's own screenshot showed the window title `C:\Program Files\Git\cmd\git.exe`.

**The measurement defect that hid it.** My window enumerator filtered on `IsWindowVisible`, and every one of these console windows is created and destroyed too fast to be caught by 15–25 ms polling in an *unreproduced* state: 0 hits while it was visibly happening. Do not report "0 windows seen" from a poll unless the poll has been validated against a known-positive reproduction.

**Proof, A/B, exact path.** A detached child running 12x `git rev-parse` with no creationflags produced **10 distinct visible console windows** titled `C:\Program Files\Git\cmd\git.exe` in 5.4 s (18:51:07.9–18:51:13.3). The same 12x with `CREATE_NO_WINDOW|STARTF_USESHOWWINDOW/SW_HIDE` (18:51:14–18:51:20) produced **none**.

**Fix.** `journal/tools/journal.py` now installs, once at import, wrappers around `subprocess.run/Popen/call` that OR in `CREATE_NO_WINDOW` and a hidden `STARTUPINFO` on Windows. One place, so a call site added later cannot reintroduce the window; the detached refresh child re-imports the module and gets the same shim. Verified: `py_compile` clean, `journal.py refresh --delay 0` exit 0 spawning 256 children, **0 visible console windows** over 932 samples.

**Residual, not fixed.** `refresh` still runs git once per entry — ~250 processes per append, invisible now but not cheap. Batching it (one `git ls-tree` / `for-each-ref` read) is the real fix and is a separate change.
