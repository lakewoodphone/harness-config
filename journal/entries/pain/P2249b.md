## P2249b — A mesh child that crashes at settlement loses its entire report - nothing is recoverable

**What hurts:** a mesh child that crashes at settlement loses its ENTIRE report, with no partial artifact and no way for the parent to recover it. Measured 2026-09-22: three children died this way in one session.

**Evidence.** Two of them (both long web-research runs) failed identically with `the remote one-shot exited 1; stderr tail: .../dsh-agent-loop/lib/index.js:82:15`, and the stack names the crash site explicitly:

```
at get hasPending (dsh-agent-loop/lib/index.js:82:15)
at ContinuableActivationRegistry.settlementState (dsh-subagent/lib/index.js:1196:24)
at file:///.../dsh-subagent/lib/index.js:1153:91
```

`settlementState` means the crash happens **when the child is settling, i.e. after its work is finished**. The work almost certainly happened; only the report was lost. `job_output` returned `(no new output)` for all of them - there is nothing to salvage, and the parent cannot even see how far the child got.

**Confirmed distinct from the other mesh failure mode:** the third child was rejected by the `MESH-HOST:` rule (H7, lesson L2379) - that one is a protocol refusal, this one is a crash. Both discard the output; they need different fixes.

**What would fix it:**
1. **Require every mesh child to write its report to a FILE on its own node** as well as returning it as the final message, and report that path as the FIRST line of the final message. A settlement crash then costs the message, not the work. This is the cheap, immediate mitigation and it is a briefing change, not a harness change.
2. Ideally the harness should persist the child's last assistant message before `settlementState` runs, so a settlement crash cannot lose a completed report at all.
3. For BUILD children the damage is bounded because a child that commits to its branch leaves the work in git - but a research child that produces only prose leaves nothing.

**Consequence for how I brief:** any child whose value is prose (research, audit, analysis) must write its output to a file on its own node and name that path first. Do not rely on the final message surviving.
