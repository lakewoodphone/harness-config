## P130 — The owner-question mirror silently keeps a stale copy while the authority is reachable by ssh in the same second

**Symptom.** `python tools/journal.py questions` on ZABZ-YOGA answers `state/owner-questions.md: authority unreachable — existing mirror kept (0 day(s) old)` and leaves the file untouched — while `ssh secratary-ts` from the same shell, in the same second, works: I added queue row **#33** over ssh and got `queued #33 [medium]` back.

**Measured.** `~/bin/owner-queue.py` on the authority is present and executable (`10911` bytes, 2026-09-14 16:53). The mirror file `state/owner-questions.md` does **not** contain the new row (`Select-String 'take money'` → `False`) after two attempts. So the mirror is stale and says nothing about it; the only signal is a line of prose in the command's own output.

**Cost, and why it is not cosmetic.** This is the exact shape that produced *two rival question registers* earlier today on another machine: one register the owner had already answered from, one mine, neither aware of the other. A mirror that cannot refresh and does not fail loudly is how the same question gets asked twice and a real answer gets lost. The command exiting 0 while doing nothing is the worst part — a caller that only checks the exit code would conclude the mirror is current.

**What would fix it.** Two small things: (1) make the mirror refresh path report *why* the authority was unreachable (the ssh call succeeded, so the failure is inside the script — wrong host label, a local DB path, or a short timeout), and (2) exit non-zero, or print the age prominently, when a mirror cannot be refreshed — "kept an N-day-old copy" is a different state from "mirrored", and only one of them is safe to read.
