## P336 — Lenovo firmware updates are offered by Windows Update on ZABZ-TECH but never installed, and the machine keeps losing its Hello container

On ZABZ-TECH Windows Update offers three Lenovo firmware updates and never installs them, while the
machine wipes its Windows Hello container on roughly half of all boots:
 Lenovo Ltd. - Firmware - 15.24.18954.0 uefi\res_{2327d974-d5a6-4f5e-909a-94229bd95964} <- TPM (machine reports 15.23.17664.0)
 Lenovo Ltd. - Firmware - 16.1.30.2330 uefi\res_{7fd2a343-8917-48a5-8aa6-b47edd8431cd}
 Lenovo Ltd. Firmware Driver Update (1.0.0.92) uefi\res_{8a15883b-8f20-4aaf-a7d8-ceb35316fb3d}
Measured 2026-09-20 16:20 UTC with Microsoft.Update.Session Search("IsInstalled=0"); the version shape
15.23.17664.0 -> 15.24.18954.0 is what identifies the TPM item, since tpmtool reports the same shape.
The last firmware-class install in the 1680-entry Windows Update history is 2026-09-15 - and that was
a driver, not firmware.

Why it hurts: it is invisible from inside Windows. The WU UI and Get-WindowsUpdateLog do not surface
"staged firmware device driver that never applies", and nothing in error_log, Setup or Kernel-PnP says
the flash was skipped. It took reading `pnputil /enum-devices /class Firmware` (3 UEFI\RES_ devices
"Started", a 4th "Disconnected" storage-firmware device) side by side with the offer list to see it.

What fixes it: install the firmware updates (reboot required, owner's OK required), then on the next
boot confirm `8002 ... State: Okay` and the absence of `3611` in the Hello log.

Related unresolved: `C:\$WINDOWS.~BT` exists and `SoftwareDistribution\Download` holds 743.8 MB -
check whether a feature update is staged and being re-attempted.
