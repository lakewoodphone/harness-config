## P149 — lpt-hub on ZABZ-TECH is 2442 behind / 26 ahead of origin/main - a local commit is not a record anywhere else

**Measured 2026-09-15 on ZABZ-TECH.** `~/code/lpt-hub` on the desktop is **2442 commits behind `origin/main` and
26 commits ahead of it**, with 23 dirty files. Pushing is therefore rejected (`! [rejected] HEAD -> main
(non-fast-forward)`) and nothing done on this checkout reaches the remote.

The 26 stranded commits are real work, not scratch — the tail is laptop-sourcing and Weitman-laptop case work:
`c1ea0d09f` ("a two-option quote was SENT - record it and correct the file that said nothing had been sent"),
`b62ae8c15`, `64aba0270`, `cf8ca76a0`, `5a25d3283`, `535df7590`, `b60bff629`, `503cb2384`, `21b630a54`, …
A local commit for a new file when the base is 2442 commits stale is invisible to anyone reading `main`.

**Mitigation applied immediately (not a fix):** pushed the whole local history to a side branch so it cannot be
lost —
```
git push origin HEAD:refs/heads/rescue/zabz-tech-lpt-hub-20260915
```
→ `* [new branch]`. That preserves the 26 commits and this session's case log on the remote without rewriting
local history and without a 2442-commit merge. It does **not** put the work on `main`.

**This is the same class as P85 (`personal-secretary-mvp` diverged on the desktop) and P140 (`personal-secretary-mvp`
on secratary 41 ahead / 134 behind).** Three repositories are now known to be diverged across the fleet, all for the
same reason: each machine commits locally and nothing reconciles. `harness-config/scripts/lpt-hub-refresh.sh`
already exists and is **fast-forward only — it never forces and never discards a local commit**, which is the right
discipline, but ff-only cannot help a checkout that has local commits.

**What would fix it (one job, not three):**
1. A single reconcile pass per repo: back up the checkout, `git fetch`, rebase the local commits onto `origin/main`
 (they are small and mostly additive files, so conflicts should be rare), run whatever the repo's `check` is, then
 push.
2. Then make it a standing job so it cannot drift again — the existing `PersonalSecretary-RepoSync` task is
 evidently not covering `lpt-hub` on this machine.
3. Until then: **do not assume a commit on a machine means the work is anywhere else.** Check
 `git rev-list --count origin/main..HEAD` before reporting work as recorded.

**Severity:** high — it silently converts "recorded" into "local only", which is the exact failure mode the journal
was rebuilt to prevent.
