## P176 — A task brief's measured claims still need re-measuring before you act on them

Ranked, with the fix.

1. The brief for the personality-system scoring job stated two measured facts that were wrong. (a) 'career-fit.test.ts lines 217-218 assert constrainedZone === 1 on inputs that actually compute to 2' — the inputs compute to 1; the test was correct and needed no change. (b) 'tsc baseline ~34 test-file errors' — the real baseline is 28. Acting on either without re-measuring would have produced a silently weakened test and a bogus regression claim.
 FIX: treat every number in a delegated brief as a hypothesis and reproduce it with execution before it changes a decision. Say plainly in the report which claimed numbers did not hold.

2. Re-measuring costs a harness, and building one for a Next.js repo is fiddly: vitest will not glob outside its config root, '@' aliases must be re-pointed per measurement run, and a mirror of HEAD is needed for before-values.
 FIX: the recipe is now written down as a lesson (absolute include globs, root = repo, alias to repo-src for after / a 'git show HEAD' mirror for before). Reuse it instead of rediscovering it.

3. A lint agent and a scoring agent shared src/components/assessment-scores.tsx: adding two comment lines above line 44 shifted the other agent's four error lines from 215/227/229/236 to 217/229/231/238, which would look like new errors in a later lint diff.
 FIX: recorded in the handoff; when two agents share a file, expect line-number drift and prove your own diff is confined by 'git diff <file>' rather than by error counts.
