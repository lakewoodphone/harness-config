## P7307 — Owner SMS delivery truth lands in a mirror and never reaches sms_log

## P — The owner's SMS delivery truth is written to a mirror and never reaches the store the tools read

MEASURED 2026-10-18 03:43-03:55 UTC on the authority.

`reconcile-sent-status.py:38` opens `~/.sms-inbox/inbox.db` and `:113` reconciles the table **`messages`**.
The owner's texts — the ones `owner_attention`, the `ps_*` MCP tools and every reporting query read —
live in **`/root/authority.db` -> `sms_log`**, which has no `messages` table.

One message, two truths:

```
sms_log 4276 queued 2026-10-17T14:22:32.105770+00:00 (SID SM8dea23086e7e9f203aadb4134ecaf70c)
messages same SID -> delivered
```

Of the **65** outbound rows in `sms_log` that are `queued`, carry a real SID and are older than 48 h
(correct date arithmetic, `julianday`, not a string compare), **50 exist in the mirror with a settled
status**. So 50 deliveries are known and are not being told to the store that asks.

The mirror is one-way by design (`mirror-owner-sms.py` is insert-only, keyed on `twilio_sid`), which is
correct for capture and wrong for status: reconciliation flows into the end that nobody reads.

**Impact, stated honestly.** This is not "he never gets the texts" — the earlier count for 7 days is
`delivered 2, failed 5, queued 35, sent 8, suppressed 23`, and the path does deliver (one row flipped
`queued -> delivered` at 03:30:03 that night). It is that **the system cannot answer whether a message
arrived**, and 50 rows prove the answer existed and was withheld. Any automation that decides on
`sms_log.status` — retry, escalation, "the owner was told" — is deciding on a stale field.

**Fix, not yet applied (needs its own round):** a write-back `messages.status -> sms_log.status` on
`twilio_sid`, idempotent, refusing SIDs absent from the mirror, and a count on both sides before and
after. Do not widen `--hours`: measured, widening to 720 h changed the unsettled count from 1 to 2,
because the window was never the cause.

**Why this is a pain and not a lesson:** it is a live defect in the path the owner's whole request
depends on ("make sure everything still running"), and it will not fix itself.

Refs: docs/mesh/178 §50 (the wrong number), §53 (the correction and the proof), H7337.
