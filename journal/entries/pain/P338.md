## P338 — reminders has no dedupe - four identical rows for one vendor order

## What happens

`create_reminder` has no de-duplication. The `reminders` schema (read on the authority 2026-09-20)
has no dedupe column and no uniqueness constraint on `(message, scheduled_time)`.

Evidence — four rows for one item, all created within 7 minutes:

| id | created (UTC) | scheduled_time | message |
|----|---------------|----------------|---------|
| 447 | 2026-09-20T03:37:10Z | 2026-10-10T09:00:00+00:00 | Global Direct Parts #161898: follow up for tracking … PayPal dispute |
| 448 | 2026-09-20T03:41:38Z | 2026-10-10T09:00:00+00:00 | same |
| 449 | 2026-09-20T03:42:08Z | 2026-10-10T09:00:00+00:00 | same (reworded) |
| 450 | 2026-09-20T03:44:03Z | 2026-10-10T09:00:00+00:00 | same (reworded) |

## Why it matters

When the date arrives the owner gets the same nudge four times, and each one also enqueues its own
`owner_message_queue` row. Repeated nudges are how a reminder surface loses its authority.

## Fix, when someone gets to it

Either add a `dedupe_key` to `reminders` and reuse the pattern `tasks` already has
(`tasks.dedupe_key` exists), or run a similar-open-reminder check before insert — the same check
`chat_action_tasks.py` already performs for tasks (`similar_count` / `similar_tasks`).
