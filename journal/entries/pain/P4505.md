## P4505 — A 403 from web_fetch and a dead chromium hide real public pages: the authority cannot browse, and the text proxy is the only route

**The authority cannot drive a browser, and a scripted fetch dies on any Cloudflare-walled supplier page — so shop research that needs a real page has one working route: the text proxy.**

Measured 2026-10-15 while reading MobileSentrix's Return Policy:

- `browser_goto` / `browser_use_run` — **both fail on secratary-cloud**: *"Navigation failed: Failed to
 launch chromium browser: BrowserType.launch_persistent_context: Unsupported chromium channel
 \"chrome # F4 2026-08-30: use system Chrome (Playwright bundled chromium can't install on Ubuntu
 26.04)\". Ensure Playwright browsers are installed: `python -m playwright install`"*. That is verified
 at call time, not inherited from the 2026-10-02 comment in `app/services/work_orders.py`, which said the
 same thing about a CI host.
- `web_fetch` on `mobilesentrix.com` → **HTTP 403** (Cloudflare interstitial, *"Just a moment..."*), on the
 product page and on the policy pages alike.
- **What worked:** `web_fetch https://r.jina.ai/https://www.mobilesentrix.com/return-policy` → HTTP 200
 with the full policy text. Note the tool also returns the *target's* status, so a wrong URL still reads
 as a 404 rather than as a proxy failure.
- `gmail_accounts` → **requires owner approval (L2)** and queued itself as task 28803; `gmail_search` runs
 without approval but the shop's supplier mail is not on the `primary` account, so `gmail_search
 mobilesentrix` returned 0 and proved nothing about whether the mail exists.

**Cost of not knowing this:** a session concludes a public policy page does not exist, or that a supplier
has no published return route, and tells the owner to phone and ask. Two of the three failures above look
like "the site has no such page" from inside a session.

**What would fix it:** either install a working chromium channel for Playwright on the authority, or make
`r.jina.ai` (or any text-extraction proxy) the documented first move for a 403 from `web_fetch`.
