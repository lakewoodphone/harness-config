## P2826 — The mesh transport loses a child the target node can run by hand (5/5 dispatches, exit 0, no frame, no outbox)

# P — the mesh transport loses a child that the target node can run by hand

**Measured 2026-10-02, ZABZ-YOGA → zabz-tech, five consecutive dispatches.**

Every `subagent` call to the mesh came back as:

 Error: subagent run failed
 Diagnostic: the remote process exited 0 but printed no completion frame —
 the target profile did not run (stderr tail: )
 --- child final message ---
 FANOUT_TRANSPORT_HOST_<id>=ZABZ-TECH
 FANOUT_TRANSPORT_CWD_<id>=C:\Users\ezabz
 FANOUT_BEGIN_<id>

with `MESH-HOST: (not reported)`, `exit = 0 in 2128 ms` (1882-3960 ms across the
five), and `lease … released to the broker with POST /done at settle (ok=true)`.
So the broker placed the child, the transport reached ZABZ-TECH, a shell started,
and then **nothing** — the child's own report never arrived and the lease was
released as if it had.

**The profile is not the problem.** Invoked by hand on the same node, the same
invocation works:

 ssh desktop-ts 'node C:\Users\ezabz\AppData\Local\npm-cache\_npx\1e7f6d9597241db0\
 node_modules\@deepseek-ai\dsh\lib\bin.js --profile headless "reply with: PROBE-OK"'
 → PROBE-OK

It starts MCP proxies (mcp-remote StreamableHTTPClientTransport, tools/list) and
answers in a few seconds. So: **the target profile runs; the mesh wrapper loses its
output.** `~/.dsh/profiles/headless/` exists and is populated
(`cordis.yml`, `cordis.patch.yml` 5,607 B, `package.json`, `pnpm-workspace.yaml`).

**Recovery is not automatic.** `mesh_collect` cannot help: the children's outboxes
do not exist. `$env:USERPROFILE\.dsh\mesh\children\remote-<id>\outbox.jsonl` is absent
for all of them (checked 5 of 5), even though the registry row says
*"answer lands in …\outbox.jsonl"* and gives a path. Two older settled children from
2026-09-27 have no outbox either. So a child that dies between dispatch and its first
checkpoint leaves **no artefact at all** — not on the parent, not on the target.

**Consequence that was actually paid:** the four-agent fleet for the text-line audit
was dispatched to the mesh, all four returned nothing, and the work had to be
re-dispatched with `subagent_local` — i.e. it ran on the laptop. Every result from
that session is therefore LOCAL, and the "fan out across the mesh" default could not
be used at all. One diagnostic dispatch and a hand-run profile probe were spent
establishing the above.

**What would fix it, cheapest first:**
1. Have the mesh wrapper **keep the child's raw stdout on failure** rather than
 discarding it — the raw output would say which step stopped. Today the diagnostic
 says only "no completion frame", and `stderr tail` is empty.
2. Treat "exit 0 with no frame" as a **hard failure with the lease not released as
 success** — the `POST /done (ok=true)` is what makes this invisible to the broker.
3. Write the child's own first checkpoint (even just "started on <host> at <time>")
 to the target outbox *before* the agent turn begins, so `mesh_collect` has
 something to read when the turn dies.
