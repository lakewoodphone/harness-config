## P6475 — vault/main is a divergent work lineage that a branch-checkout published over main; unreconciled, and publication now uses refs/heads/journal instead

`vault/main` on `2.28.33.58:/srv/git/harness-config.git` is `1214720467270b0deed5be4444280aafade561fe`
(2026-10-14 18:50:46 +0000, subject *"dictation: resolved - Whisper Small (English) is ~3s on his iPhone
against ~15s for the 1.6 GB model"*) — a **work** commit, not one of `journal-commit.sh`'s own
`journal: autocommit …` commits. The authority's checkout is on branch `i359-contentless-waiting` and its
`HEAD` has merge-base `83bc260ba5511d6f29ba20bc1d9cf1a5e6a008b7` with it. Neither is an ancestor of the
other.

**Why it exists.** `journal-commit.sh` pushes `HEAD:$BRANCH` with `BRANCH` fixed to `main` while `HEAD` is
whatever branch the checkout has checked out. So a session that switched branches republished its branch
over `main`, and once that happened every later push from a branch that is not its descendant was refused
— permanently, on the machine that is supposed to be the source of truth.

**Immediate mitigation, done 2026-10-16:** the cron payload now carries `JOURNAL_BRANCH=journal`, so the
journal publishes to a dedicated rolling ref that cannot conflict. `refs/heads/journal` = the local HEAD,
read back, rc=0 (`L6403` supersedes; `P4697` resolved). Publication works again. **`main` is untouched and
still holds the divergent lineage.**

**What is left is a decision about meaning, not a bug.** `main` on that remote currently means "whatever
branch some session had checked out on 2026-10-14". Three ways to settle it, none free:

1. **Merge `vault/main` into the checkout's lineage** and push the result to `main`. Correct if the work on
 it matters; it is a merge into a repository that other sessions commit to, so it wants a quiet window.
2. **Repoint `main` at the `journal` ref** — one `git push` that is a fast-forward only if the two are
 unrelated, which they are not, so this is a force and is forbidden without a per-action yes.
3. **Leave `main` as a dated relic** and make `journal` the published name, documenting it. Costs one
 convention change in whatever consumes the remote.

**CHECK** (0 = the remote's `main` is an ancestor of the local checkout, i.e. reconciled):

 cd /root/code/harness-config && git merge-base --is-ancestor \
 "$(git ls-remote vault refs/heads/main | awk '{print $1}')" HEAD && echo RECONCILED || echo DIVERGED
