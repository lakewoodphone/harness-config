## P2854 — A worktree flagged for a pnpm install has no node_modules and no pnpm-lock: it is an npm repo, and npm install rewrites package-lock.json with noise

WHAT HURT
The phase brief said `pnpm install --frozen-lockfile` might still be running and to wait for
node_modules. Neither existed: no pnpm-lock.yaml, no node_modules, and three overhaul worktrees
(_ov_card, _ov_report, _ov_resume) all without dependencies. `npm install` took 5 minutes and added
407 packages, and it also touched package-lock.json (16 insertions / 22 deletions of mostly
`"peer": true` flags and removed optional @emnapi entries) - i.e. an unrelated file would have been
modified by a phase forbidden from touching other files.

WHAT I DID
Ran npm install, then `git checkout -- package-lock.json` to restore it, and left the working tree
with exactly one modified file plus the new directory. node_modules survived the restore.

WHAT WOULD FIX IT
Either prepare each overhaul worktree's dependencies before handing it out, or give the worktrees a
shared node_modules (node_modules is not tracked either way). Discovering a 5-minute install after a
brief that says it has already happened costs the agent its first quarter hour and tempts it into
believing a file it must not touch is its business.
