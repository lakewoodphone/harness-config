## P164 — Nothing watches the LOCAL services the mesh depends on: a stopped Tailscale or IP Helper silently makes a whole machine LAN-only, with no alert

FOUND 2026-09-15 ~19:45Z on ZABZ-TECH, by accident, while pushing the journal.

WHAT HAPPENED
- ssh secratary-ts and the harness-config git remote (secretary-ts:/home/zabz/harness-config.git) both failed with 'Could not resolve hostname ...tail93e6e6.ts.net'. The same symptom had already made ZABZ-YOGA look offline twenty minutes earlier, and I wrote it down as 'yoga is unreachable'.
- Cause, both times: **Get-Service Tailscale = Stopped** (StartType Automatic) on the machine I was working from. Office-LAN names still resolved, so the machine looked networked; only the tailnet was gone. Starting the service restored every MagicDNS name within seconds, and yoga answered immediately.
- A second instance of the same shape the same evening (L1565): LAN ingress to the desktop API is a netsh portproxy implemented by IP Helper. iphlpsvc was Stopped, the LAN address refused connections while loopback was perfectly healthy, and nothing anywhere said so.

WHY IT MATTERS
- The fleet talks over Tailscale because home and office are separate networks. A stopped Tailscale on one machine does not degrade that machine — it silently downgrades the whole fleet's view of it, turns agents' ssh and git into DNS errors, and reads as 'the other machine is down'. I misdiagnosed yoga for exactly that reason.
- Both failures are invisible from the outside: the service is Automatic, so it is expected to be up; nothing polls it; and the failure looks like a remote problem.

WHAT WOULD FIX IT
1. A local prerequisite check that runs every few minutes on every Windows node: Tailscale service running (and, on ZABZ-TECH, iphlpsvc running plus the 192.168.50.138:8002 portproxy entry present), restart what is stopped, and write the result to a status file the same way harness-autosync already does (~/.dsh-sync-status/status.json).
2. Expose it in journal.py status or the kernel's health view next to sync state, so 'tailscale stopped' is one line rather than a 20-minute DNS hunt.
3. Because it is a prerequisite for the sync path itself, it must NOT live inside the thing that needs it: it belongs in a standalone script in harness-config invoked by a scheduled task, same pattern as scripts/autosync.ps1.
Evidence and full record: H275, L1565, L1566.
