## P6295 — Two of the four shop devices reach the harness only if Tailscale is running on the device, and nothing on the server can tell

## P — a device that is not on the tailnet cannot sign in, and the server cannot see why

2026-10-12. phone-gate-allow.txt admits the owner's devices by the address tailscale serve appends
as X-Forwarded-For, and the harness itself is reachable only on the tailnet name
(secratary-cloud.tail93e6e6.ts.net). So two things must be true on EVERY device, for ever:
Tailscale is installed, and it is running.

tailscale status on secratary-cloud showed the two shop iPhone 11s OFFLINE
(iphone-11: 100.118.10.22, last seen 2 DAYS ago; iphone-11-1: 100.119.73.69, last seen 2h ago)
while the iPhone 15 Pro and the iPad were connected. The devices are correctly allow-listed, so if
they come back the path works - but nothing on the server knows whether the Tailscale app was
closed, the battery died, or the app was never installed, and the owner sees only
\"This node does not sign in this device\", which reads like a server fault.

WHAT WOULD FIX IT
- An allow-list entry that is present but whose address has not appeared for N days should be
 reported (not refused) in the same place the owner looks - the attention badge the gate already
 serves from the kernel's latest.json.
- The refusal page itself should say the likely cause in plain words when the source address is a
 loopback redirect from Cloudflare (i.e. not through Serve): \"turn Tailscale on\".

WHY NOT FIXED HERE: it is device-side and needs the owner's hands; a server change cannot make a
phone run Tailscale.
