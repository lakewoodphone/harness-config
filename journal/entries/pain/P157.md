## P157 — pwsh 'spawn EPERM' on long here-string commands

pwsh calls that combine a PowerShell here-string (@'...'@) with Set-Content and then a subsequent command failed at spawn with `Error: spawn EPERM` twice in a row on ZABZ-TECH (2026-09-15), even though a plain `python ... --help` call in the same session succeeded. The command never ran - the failure is before execution, so it is not a sandbox file denial and no escalation applies (and approval prompts are disabled in that session, so escalation was not available anyway).

What worked instead: create the long body text with the `write` tool, then run a single short pwsh command that only PASSES that file path (`--body-file`). Two short commands beat one long here-string command.

TOOL-LEVEL FIX (whoever picks this up): when passing long text into a CLI, write it to a file first with the file tool instead of inlining a here-string in pwsh. If the harness is genuinely mis-spawning on long commands, that is the bug to chase - the current workaround is cheap but it is a workaround.
