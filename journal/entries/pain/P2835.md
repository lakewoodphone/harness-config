## P2835 — Owner-attention sweep: voicemail unreadable, bills.due_date null, no Plaid matcher, noisy gmail urgent bucket

﻿RANKED, worst first, with what would fix each.

P1 -- VOICEMAIL CANNOT BE SEEN. dialpad_ui_voicemail_row last captured
2026-06-14; dialpad_call_full.voicemail_link has 0 rows in the last 7 days. This
is the only channel where a customer SPEAKS and the business does not hear it.
The sweep reports the channel DEGRADED rather than a clean queue, which is
correct but is not a fix. FIX: find why the ui capture stopped in June and either
revive it or pull voicemail from the Dialpad API into dialpad_call_full.

P2 -- bills.due_date IS NULL ON ALL 11 ROWS. The bills table can never raise a
due-date finding, so the sweep's finance channel silently covers only provider
failure email and Plaid. FIX: populate due_date at bill creation, or derive it
from the provider's own email.

P3 -- NO PLAID MATCHER. "unmatched" had to be defined as a heuristic
(amount >= 250, not personal, not Transfer, no bills row naming the provider).
It is explainable but it is a guess at what "unmatched" should mean. FIX: a
real transaction-to-obligation matcher.

P4 -- gmail_live "urgent unread" IS NOT URGENT. It returns 2FA codes and
receipts from Dec 2025 and Mar 2026 (zabzgpt@gmail.com), so the top of the ranked
list is padded with things nobody needs. Upstream in
gmail_service.get_owner_attention_digest, not in the sweep. FIX: age-bound the
urgent bucket and drop one-time-code senders.

P5 -- THE SWEEP'S OWN MEMORY OF WHAT IT ASKED IS THE QUEUE, NOT ITSELF. If a row
is deleted from owner_decision_queue, the fingerprint that makes a question
idempotent goes with it, and the sweep would ask again. FIX: keep the
fingerprint in owner_attention_findings (it is already there) and dedup against
that too.

P6 -- RANKING HAS NO LEARNED WEIGHTS. The score is a fixed formula (severity
weight + capped age bonus + money + channel bias). It has not been tuned against
what the owner actually acts on, so `owner_attention_findings` cannot yet answer
"did the top of the list earn its place". FIX: join findings to queue rows by
fingerprint and measure acceptance.
