## P129 — Local master and origin/master have diverged, so this machine's journal writes never reach the authority

Observed 2026-09-15 on ZABZ-YOGA: harness-config master and origin/master are 6 and 5 commits apart. git push origin HEAD is rejected ('the tip of your current branch is behind its remote counterpart'), so nothing written here is visible from ZABZ-TECH, secratary or the CEO kernel. Both sides are journal/ + scripts/ commits, i.e. two machines appended independently and neither reconciled. This is the third time the remote has diverged under a session (see L210). Two aggravating facts: (1) the tree carried 159 dirty paths at the time, including another live session's edits, so a blind merge or a bare 'git add -A' would sweep someone else's work; (2) a concurrent auto-commit (41d7cb0) swept my staged files into its own commit mid-command, so the thing that needs fixing is not only git but the fact that more than one process commits the same tree. WHAT WOULD FIX IT: a single journal-commit owner (one process, or a lock file beside the index) plus a documented divergence reconciliation that regenerates journal/index/* and journal/NOW.md rather than merging them, and that refuses to run while the tree has foreign dirty paths. UNTIL THEN: treat 'committed' on this machine as 'not yet shared' and never trust origin/master as the state of the journal.
