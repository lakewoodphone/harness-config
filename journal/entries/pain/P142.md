## P142 — Her laptop's Tailscale login cannot complete (IPv6 preferred, and 0xFF broke her engine — do not repeat that)

MEASURED 2026-09-15. Her laptop's Tailscale cannot complete a login, and the diagnosis is now precise
enough that a future session should not restart it from scratch.

SYMPTOM: `tailscale status` = Logged out / NeedsLogin; `tailscale login` hangs with an EMPTY AuthURL
and writes nothing to stdout or stderr; the desktop app's sign-in also does nothing (the owner
confirmed this from the machine). An auth key from the repo's TAILSCALE_AUTH_KEY did not help.

THE ERROR, from tailscale status --json's health field and tailscaled.log2.txt:
 'fetch control key: Get "https://controlplane.tailscale.com/key?v=142": dial tcp
 [2606:b740:49::105]:443: connectex: The requested address is not valid in its context.'
It resolves the control plane to an IPv6 address and the connection fails instantly.

WHAT I TRIED, AND WHAT IT TAUGHT ME:
1. Pinned the control plane's A records in the hosts file. On the network it was on at that moment
 that worked for the IPv6 fault -- but on the network it moved to later, the pinned IP itself became
 unroutable ('dial tcp 192.200.0.102:443 ... not valid in its context'), so the pin started CAUSING
 the failure. Networks are not stable for this machine; it is on a mobile/hotspot connection
 (gateway 192.168.12.1, self 192.168.12.203, IPv4 via 172.59.215.73). The pin was removed and the
 hosts file is back to original.
2. Set DisabledComponents=0x20 (prefer IPv4), then 0xFF (IPv6 off). Neither helped: Tailscale's Go
 resolver still chose AAAA. Setting 0xFF also BROKE HER ENGINE, because the engine needs the network
 too. Both registry changes were reverted and the engine restarted. That was a real mistake: I
 changed a machine-wide network setting for a feature the machine does not need.
3. Auth keys silently did nothing -- worth knowing before trying again.

LESSON: do not fix a machine-wide network setting to bring up an OPTIONAL capability. The laptop loses
nothing from being off the tailnet: it reaches the company API over HTTPS, which is the path that
matters, and ps-shop/ps-system work there. Tailscale would only add a shorter hop to the same API.
