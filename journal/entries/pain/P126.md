## P126 — A wedged engine on 3099 survived 100 minutes because the watchdog could not reclaim the port it held

What hurts: for 100 minutes the machine ran an engine that held port 3099 and answered nothing,
while the 1-minute watchdog logged a failure a minute and produced no fix. The owner saw it as
"disconnected for a few minutes and now everything froze".

Ranked, with the fix:

1. The watchdog had NO WAY to recover it. `Invoke-Ensure` (the 1-minute task) only ever tried to
 START an engine, so on a bound port every attempt died with "port 3099 already in use" -- ~11
 times between 16:45:50 and 18:22:45. The only path that could take the port was `Ensure-Engine`,
 and that was reachable ONLY from `dshw new` / `dshw restore`. Recovery was therefore coupled to
 the owner clicking "new window", which is also why he got a window-open storm at 18:28-18:32
 instead of a repaired engine.
 FIXED: `Invoke-Ensure` now delegates to `Ensure-Engine` (L505, D139).

2. Even when that path ran it could silently do nothing, because `Get-PortOwner` returned null:
 at 17:49:33 `Ensure-Engine` logged "not answering, attempt 1/3" and 5 s later "start FAILED -
 port 3099 already in use" with NO reclaim line. `Get-ListenTable` wraps
 `Get-NetTCPConnection -State Listen`, which on this loaded box came back empty, so the reclaim
 guard read "no holder" while the port was demonstrably held (EADDRINUSE proves it).
 FIXED: an empty table is retried 3x, and EADDRINUSE now forces a cache-bypassed refresh and a
 reclaim before the next attempt.

3. The reclaim that finally worked (18:27:31, pid 19556) was decided by a 1500 ms / 2500 ms probe
 on a machine at 84% CPU. It happened to be right that time; it is also exactly how the same
 script killed a live engine at 15:05 that afternoon (pid 32044, in this file's own comments).
 FIXED: two patient probes (10 s / 30 s), five seconds apart, before anything is taken away.

What still hurts and is NOT fixed: nothing here explains WHY pid 19556 wedged. Its stderr is
clean -- it reported a URL at 16:43:25 and was silent by 16:45:50 with no fatal error. Until that
is known, this fleet can wedge any engine again; the difference is that it will now be replaced
within about a minute instead of after 100.
