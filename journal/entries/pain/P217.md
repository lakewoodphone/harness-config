## P217 — Customer SMS sent by scripts/send-lpt-sms.py write nothing to sms_log, so they are invisible to dedup and to the send audit

WHAT HURTS: personal-secretary-mvp/scripts/send-lpt-sms.py calls app.services.dialpad_service.send_sms directly. It never calls _log_action_sms, so a customer SMS sent that way leaves no row in sms_log. Verified 2026-09-16: sent message id 6148386292539392 to +18482999657 (Hirschfeld case) and sms_log has zero rows for that number.

CONSEQUENCE, two of them:
1. DB-level duplicate suppression (_db_recent_outbound_sms_id in chat_action_phone_tech.py) reads sms_log. A script send is invisible to it, so a script send followed by an action-path send of the same words will not be caught as a duplicate.
2. The send audit trail is incomplete. When asked 'did we text that customer, and exactly what did we say', the answer for script sends lives only in Dialpad, and Dialpad v2 exposes no GET-by-id for SMS (/api/v2/sms/{id} returns 404, confirmed twice 2026-09-16). So there is no reliable programmatic read-back.

WHAT WOULD FIX IT: have the script call the same logging helper the action path uses (or emit the same sms_log row) after a successful send. Until then, any script-sent customer SMS should be recorded in the case file by hand, which is what the Hirschfeld case file does.

SEPARATE, NOT A BUG: agent_sms_signature defaults to 'Daniel' (app/config.py L399) and the script appends it unless --no-signature is passed. Daniel is a real LPT staff member who signs his own customer texts, so the default is intentional - but any non-Daniel system send that omits --no-signature goes out signed as him.
