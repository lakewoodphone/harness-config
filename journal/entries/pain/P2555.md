## P — The kosher-filter-ai product stopped moving on 2026-09-18 while finished work sat unmerged on branches

**Symptom.** The owner asked, on 2026-09-28, how the *"kosher ai filter for android and ios"*
project is coming along. The honest answer is that it has not advanced on `main` for **ten days**.

**Measured 2026-09-28 (ZABZ-YOGA, from `C:\Users\ezabz\code\kosher-filter-ai` after `git fetch --all`):**

**Why this is worse than "slow".** Every one of those three branches contained *finished or
nearly-finished* work that was built, tested to some degree, and then left where nobody would see it:

- `fleet/android` (2026-09-17) is the fix for the audit's headline Android defect — the screenshot
 accountability path was **dead, not partial**: `ScreenshotService.startWithConsent` had zero callers
 repo-wide and `createScreenCaptureIntent()` appeared nowhere. The branch adds
 `ScreenshotConsent.kt` (247 lines) plus two test files (464 lines). **Unmerged for 11 days.**
- `origin/agent/windows-wfp-ale` (5 commits, 2026-09-21 → 2026-09-27) is the *only* part of the repo
 that moved in ten days, and it lived on a branch whose own tip is the newest work in the project.
- `fleet/web-merged` (2026-09-17) makes the onboarding level step actually act.

**The failure mode, named.** This is not "the work was not done". It is **work produced and never
integrated** — the same shape as the 55 unapplied improvements the journal already records, and the
same reason the owner has to ask "are you doing so". A branch is not progress; `main` is progress.

**What would fix it.** A merge is the cheapest step in the whole pipeline and it was the step being
skipped, because the session that built the branch ends and the session that would merge it starts
with no memory that the branch exists. The durable fix is one line in the journal protocol: **an agent
that leaves work on a branch must write a `handoff` entry naming the branch, and the next session's
`status` read must surface unmerged branches for the repos that matter.** Written as a rule: *a branch
is not a deliverable.*

**Fixed this session (partly):** `fleet/android` is merged (`20f5f65`, pushed as
`origin/integrate/kf-20260928`) with the only conflict being a package-path rename. `fleet/web-merged`
and the Windows lane are being resolved and verified under `C:\Users\ezabz\code\_fleet\kf0928\`.

**Evidence.** `git log -1 --date=iso origin/main`; `git branch --no-merged main`;
`git diff --stat main...fleet/android`; `git log --oneline --all --not main` (8 commits, all unmerged).
