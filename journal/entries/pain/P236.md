## P236 — A queued remote child looks like a running one to its parent, because the seam has no start()-time progress channel

The subagent seam has NO live progress channel to the caller during a delegation: `SubagentProvider.start(request)` must fulfil before a run is published (dsh-subagent/lib/types/types.d.ts:292-318) and @deepseek-ai/dsh-tool-subagent has no progress/emit/onUpdate hook at all (read: no such symbol in its lib/index.js). So a remote child that is QUEUED at position N is, for its parent model, indistinguishable from a child that is running: the parent sees a pending tool call and learns the position only when the child settles and its report arrives. What was done instead: the placement is recorded in a live file (<DSH_HOME>/mesh/placements/<id>.json, rewritten at each transition) so a human or another agent can see it, and the child's report carries it. What would fix it properly: a start()-time progress channel on the provider contract, or a tool-layer update hook - a dsh-subagent change, not this package's. Related existing pain: P11 (preset default chosen at session start) is the same "no live channel" family.
