**D8321 · 2026-10-19 · Routing half complete but for a key: the V4.1 lane exists and the direct preference is now enforced.**

## 2026-10-19T23:05Z · ZABZ-YOGA · the routing half is now complete except for a key

### What was missing, and is now there

1. **The lane.** `deepinfra/deepseek-ai/DeepSeek-V4.1-Flash` now exists in `_CAPABILITY_DB`. The price
 book had declared it as a same-weights pipe all along; no candidate lane existed, so
 `_yield_to_cheaper_same_model` could find the equivalence, fail to find the model, and decline —
 silently. Capability metadata mirrors the model (1M context, tools, vision, reasoning). The price is
 a **dated stand-in** from the book, deliberately **not zero**: a zero cost would look free and win
 every comparison while `ROUTING_HOUR_AWARE_COSTS` is off.

2. **The demotion.** This is the half that would have gone wrong quietly. A same-weights pipe that is
 cheaper at *every* hour wins the generic cost-weighted score — and DeepInfra Flex is 0.112 against
 DeepSeek's 0.15 off-peak, so it is cheaper even off-peak. Enabling it without a demotion would have
 replaced DeepSeek direct permanently, which is the precise opposite of "usually we prefer direct".
 So the function now **enforces** the preference: a declared equivalent that is not significantly
 cheaper at this hour is pushed below direct, with the same 0.001 margin the OpenRouter preference
 uses, and idempotently (the `min()` cannot keep shaving the score on repeated passes).

**The rule is now one rule, in one place:**

| hour | delta | outcome |
|---|---|---|
| off-peak | 25.3 % | below threshold → **demote**, DeepSeek direct stays |
| peak | 62.7 % | above threshold → **promote**, DeepInfra wins |
