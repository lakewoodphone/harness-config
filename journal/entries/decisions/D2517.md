## D2409 · 2026-09-24 · Where intake evidence and device credentials live

DECIDED (dev decisions, mine; recorded because both will otherwise be relitigated):

1. **Intake-note photographs are committed to lpt-hub.** `docs/customer-operations/case-media/`
 gets an explicit `!` exception in `.gitignore` for the folder, with the reason written next to
 the other curated exceptions. Rationale: for a walk-in customer the note is the only record of
 the request, and this repo has already lost a photo set (82 files / ~240 MB, April 2026) to the
 blanket `*.jpg` rule. Each case file cites its photo by sha256 so the exact bytes are verifiable.
 Keep these small — three files, 1.9 MB — and keep the camera masters off git.

2. **A device passcode goes in the case file and nowhere else.** Devorah Goldberg's iPad passcode is
 in `cases/ipad-goldberg-7325697189-2026-09-24.md` because the charging port cannot be tested
 without booting the device, and there is precedent (`_credentials-perel-kuritsky-2026-06-24.md`,
 which carries the same "do not show this to the customer" warning). It is deliberately NOT in the
 sync record, NOT in the order description, and NOT in the customer note pushed to production —
 those surfaces are wider and are read by staff who do not need it.

3. **An unreadable annotation is recorded verbatim, never interpreted.** `(20D)` circled on the
 Ribowsky note stays unexplained in the case file and the order carries no total. Guessing a price
 onto a live work order is a money error; leaving a total empty is not.

4. **No total is written unless a price was actually quoted.** All three 2026-09-24 intakes carry
 `price: null` and orders with `total: NULL`.
