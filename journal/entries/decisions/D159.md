**The four engineering rules this becomes** (the last sentence is the load-bearing one):

1. **D39-03 — the vendor is a configuration value, never an architecture.** Exactly one provider seam;
 model id, prompt version and endpoint are data; swapping vendors must require no source edit outside
 the seam, and that is stated as the test. This is *"don't lock things in heavily"* made enforceable.
2. **D39-04 — no model is adopted or kept without being scored on our own labelled frames.** This is what
 makes *"constantly get better"* measurable instead of aspirational. Consequence: a model that cannot be
 scored cannot ship, which makes the never-run labelling pilot the first task rather than a nicety. The
 harness exists and is tested (21 tests); **zero frames have ever been captured.**
3. **D39-05 — continuous asynchronous spot-checking.** The phone's verdict and tier 2's verdict are both
 recorded and their **disagreement is the signal** (D33-06 strata + trigger E5, as a standing job). It
 exposes an existing defect: `update_screenshot_review_classification` overwrites the machine verdict in
 place, so "did we override the model, and was that right?" is currently unanswerable. Designed fix in
 `research/022` §1; this decision makes it required.
4. **D39-06/07 — prompts and models are versioned artefacts**, signed, A/B'd and rollback-able (D20-01
 extended to prompts). An update that cannot be rolled back is not shipped.

**Why DeepSeek's own API is excluded — and it is not cost.** Verified from primary sources 2026-09-15:
contracting entity is Hangzhou DeepSeek Artificial Intelligence Co., Ltd.; data is processed and stored
**in the PRC**; terms governed by **PRC mainland law**; **no DPA**; **no API-level training opt-out**, with
the Chinese-language policy *more* permissive than the English one and stating inputs may be used for
training; **no published API retention period**; and the policy expressly does not cover children's data
from a developer's end users. Model cost is trivial ($0.0001–0.00014 per picture off-peak; 1024x1024 = 652
tokens, 1080x2400 = 947). **The weights are MIT-licensed, so the route is a US host, not the vendor.**

**CORRECTS AN ERROR I MADE EARLIER THE SAME DAY AND HAD NOT WRITTEN DOWN.** I told the owner that DeepSeek
models are on AWS Bedrock and that this would put Amazon's terms around the data. **Bedrock carries only
DeepSeek V3.2 / V3.1 / R1; Azure carries V4-Pro and V4-Flash but not V4.1 Flash.** The escape hatch I
offered does not work for the named model. It is corrected in the decision document because an uncorrected
assumption in a written record is exactly the class P3 exists to prevent.

**Open / owed:** the US host choice (Fireworks and Baseten are candidates; terms verification died once and
was relaunched). And a **physical shop test phone** for the labelling pilot — there is none attached to
ZABZ-TECH, only an offline emulator, and the frame geometry has to be real for the measurement to mean
anything.
