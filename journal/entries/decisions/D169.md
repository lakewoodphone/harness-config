**D169 · 2026-09-15 · The Waze/MDM fleet API is TLS-only: /api/fleet and /api/waze on mdm.abletelsolutions.com, port 8003 loopback-only.**

Decided 2026-09-15, from measurement. Before: fleet-api published 8003 on 0.0.0.0 on
a box with ufw inactive and iptables INPUT ACCEPT, so /docs, /openapi.json, /health and
/healthz were world-readable and the bearer token travelled in cleartext on every call.
No Hetzner Cloud Firewall exists (the metadata endpoint answers), so the token was the
only protection on the API.

Now: compose binds `127.0.0.1:8003:8003`; Caddy exposes
 https://mdm.abletelsolutions.com/api/fleet/* -> /fleet/*
 https://mdm.abletelsolutions.com/api/waze/* -> /waze/* (new; the portal bridge needs it)
Verified: public :8003 connection-refused; /api/fleet/devices 200 with token and 401
without; /api/waze/device/{serial} 200 with token and 401 without; host cron jobs on
localhost:8003 still 200; /version (MDM protocol) still 200.

Caller convention, so nobody double-prefixes: the /fleet family base is
https://mdm.abletelsolutions.com/api/fleet and call sites drop the /fleet segment;
scripts/waze keeps /fleet/... in its own paths and therefore strips a trailing /fleet
from a resolved base. /health, /healthz and /readyz are NOT published through Caddy:
liveness is probed on the server (localhost) or through the token-gated /fleet/health.
