**D2660c · 2026-09-28 · Device-cell backfill: write target, guards, class-only writes, frontend fallback.**

DECISIONS taken 2026-09-28 while backfilling the Work Orders Device cell
(`lpt-more-apps`, `docs/work-orders/device-cell-backfill-20260928.md`). Each one was mine to
make (engineering, not owner's money/customers/legal) and is recorded so it is not relitigated.

D1. Write target is `orders."deviceInfo"` with `||` merge, never a new column, never
`repair_intake_cases.device*`. Reason: `deviceInfo` is the only thing `describeDevice` reads;
the intake columns are already empty for 351 of 355 cases and enriching them fixes no existing
cell. The merge preserves every other key already in the blob.

D2. The write is guarded in SQL on `brand` AND `model` both being blank, in the same statement
as the address. Consequence accepted: rows whose recorded brand is the literal `Unknown`
(26 of them) were NOT overwritten, and are reported as candidates instead. "Never overwrite a
value that is already present, even if you think it is wrong" beats a tidier column.

D3. A class-only inference writes `deviceInfo.type` alone â€” never `brand`, never `model`. "laptop
diagnosis" says laptop, not a make. 21 rows.

D4. `describeDevice` gained a `deviceInfo.type` -> label fallback, placed AFTER the title and
BEFORE the literal. Reason: the column was printing "Device not recorded" for orders where we
had in fact recorded a class, i.e. the label was false. `OTHER` and `UNKNOWN` are deliberately
absent from the label map. Measured blast radius before keeping it: 52 cells change over 595
rows, 0 regress (7 "not recorded" -> "Laptop"; 45 "Unknown" -> a real class).

D5. Provenance keys on every write (`backfilledBy`/`backfilledRule`/`backfilledAt` for the
one-off repair; `inferredBy`/`inferredRule` for the live promotion path). Two vocabularies is a
wart; the alternative was calling a live inference a "backfill", which would have been an
untrue record. Any future session may collapse them â€” the rows stay identifiable either way.

D6. When the live promotion path infers only a class, it writes no `UNKNOWN` placeholders. The
pre-existing structured path keeps its `?? 'UNKNOWN'` defaults because `describeDevice` joins
brand and model, so a placeholder there would reach the screen as a device name.

D7. Rejected feature, on purpose: filling the 375 rows that have a brand but no model. Not the
complaint, and the measurable risk (a wrong model in the cell the owner now trusts) is higher
than the reward. Left as the next tranche, with the method to do it safely.
