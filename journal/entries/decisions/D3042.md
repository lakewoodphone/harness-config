**D3042 · 2026-10-11 · Offsite backup of the cloud authority: zero-extra-disk streaming via sqlite_dbpage, systemd-scheduled.**

v3 of `authority-offsite-backup.sh` (docs/mesh/133-OFFSITE-BACKUP.md). No second full-size file is ever needed:

 read-pages.py (sqlite_dbpage, one read transaction) | gzip -6 | upload-multipart.py (64 MiB parts) -> R2

Chosen over the alternatives on measurement, not taste:
* `.backup` into a FIFO - impossible (measured: SQLITE_CANTOPEN on a FIFO, sqlite3 3.46.1)
* a snapshot file plus a gzip file - the disk holds 27 GB free and the pair needs ~31 GB
* `bounded-db-backup.py` (existing, ~/bin on the office box) - guards at 2x the source size, so it refuses on this host
* boto3 `upload_fileobj` - needs a seekable file object; the input is a pipe, so the multipart upload is hand-rolled

Also decided: started by a Type=oneshot systemd unit (never an ssh foreground), daily 05:20 UTC +600 s jitter with Persistent=true, Nice=10, gzip level 6 (GZIP_LEVEL is the tunable; -1 would cut a ~30 min run to ~8 min for ~15% more bytes), ledger object sent FIRST because it is small and the least replaceable, and the freshness reporter and dead-man switch PORTED from the office box rather than rebuilt.
