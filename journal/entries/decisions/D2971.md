**D2971 · 2026-10-07 · The search exit code is part of the contract.**

**The search exit code is part of the tool's contract, on every surface.**

Decided 2026-10-08 after finding seven defects in the fast-search surface. The specific ruling:

- Every `fa` mode returns the documented codes: 0 hits, 1 no-match, 2 usage, 3 stale index,
 4 **nothing was searched**, 5 index failure. Three modes violated this and are fixed.
- 4 means a *refusal* and must never be reachable from a code path that also produces a clean
 negative. A truncated scan is a refusal.
- The MCP wrapper propagates `exit_code` and `searched`. `ok:true` with `(no hits)` is no longer an
 acceptable rendering of a refusal.
- The wrapper does **not** set a staleness ceiling the caller did not ask for. Omitting `--max-age`
 is what lets each index use its own rule, and what lets the journal answer from coverage.
- `--scope` **replaces** the curated roots (the help said "add").

Why it is written down: these are all the "0.81 GB shape" - a number or a status asserted as settled
when the mechanism underneath does not produce it. The whole point of this tool is that an agent can
trust "no match". Any future mode must land its miss path in the same commit as its hit path.
