**D231 · 2026-09-16 · Where the Shlock project's authoritative records live, by layer (tarp on secratary psmvp master; frame in lpt-hub research).**

**Decision.** The Shlock project's authoritative records are split by layer, and each layer has exactly one
home. Read the right one or you will be reading a stale copy.

| Layer | Authoritative location | Notes |
|---|---|---|
| Tarp / vendor comms, delivery, open items | `personal-secretary-mvp/docs/personal/shlock/` **on `secratary`, branch `master`** | Committed there. Local clones of psmvp are often on a feature branch and do **not** contain the Sep 2026 files. Read from secratary, or `git fetch && git show origin/...` — never from a local working tree by assumption. |
| Project memory (owner-visible to Copilot) | `secratary:~/personal-secretary-mvp/memories/repo/shlock-sukkah-rain-cover.md` | Gitignored — the tracked file carries the durable copy. |
| Frame build, mechanism design, money, field plans | `lpt-hub` `research/miscellaneous/` (+ `archive/shlcok-old-docs-*`, `directives/`, `external-research/`) on `secratary` | Live set is the 2026-06-30 file family + the 07-26/07-28 mechanism docs. Everything older is superseded (the V4–V6 wood-post architecture in particular). |
| Raw site/house photographic evidence | `lpt-hub/artifacts/shlcok-site-photos|shlcok-house-plans` — **gitignored, manifests only in git** | 44 + 38 HEIC, ~240 MB. Not reachable from a fresh clone. |

**Why recorded.** On 2026-09-16 a "get a clear handle on shlock" session found the local ZABZ-YOGA copy of the
tarp records **three weeks stale** (its README still said "awaiting Mark's ship date") while the delivered tarp
record and the Sep 13/14 chase sat only on secratary — the same shape of failure as P3 (reading the wrong data
and believing it). Two independent reads of the same folder name produced two different truths.

**Rule that follows.** For any personal-project record, resolve the *host and branch* before quoting a file:
`ssh secratary-ts "git -C ~/<repo> log --oneline -1 -- <path>"`. An empty local result is not evidence of
absence — it is a wrong-mount.
