**D2094 · 2026-09-20 · D336 - the run_once timing instrument: design, insertion points, and why it is not in yet.**

D335 named the blocker: `run_once` takes 480-600 s, and the system records **no per-subsystem duration**
(`autopilot_state.json` has 37 subsystem entries and every one carries `dur=None`). Without that, "make
the tick fit" cannot be targeted. This records the instrument's design precisely enough to apply it in
one session, and the reason it was not applied in this one.

## What already exists

`AutopilotController._subsystem_health` (autopilot.py:589) is a `dict[str, dict]` with, per subsystem:

 successes, failures, last_status, last_error, last_ran_at,
 consecutive_failures, consecutive_empty_ticks, recent_runs, last_detail

set via `setdefault` at :1191. **`last_ran_at` is already recorded; `duration` is the only missing
field.** So the instrument is an extension of an existing record, not a new mechanism.

## The insertion points (all in `run_once`, ~4605-6093)

Each subsystem is a guarded `if` block with its own `try:` and its own `ThreadPoolExecutor(...).result(
timeout=N)`. The eight that matter, with their start lines:

 world_context 4665 (result timeout 20.0 s)
 company_tick ~4821 (guarded by self._run_count % self._company_tick_every)
 ceo_tick ~5642
 work_mode, healing, self_prog, evolution, llm_checkin - same shape, further down

Every one of them is a self-contained `try/except` with a `logger.warning` on failure, so a wrapper
cannot change their semantics - it can only measure them.

## The change, in three small pieces

1. **A field.** Add `"last_duration_sec": None` to the `setdefault` dict at :1191, and let
 `_record_subsystem_*` overwrite it. One line.
2. **A timer, local to `run_once`.** Next to the existing `_tick_action_counts = {}` (which is already a
 run-local dict at :1882 of the agent worker's twin, and at the analogous place in run_once):

 _stage_secs: dict[str, float] = {}

 and one tiny helper on the class:

 @contextmanager
 def _timed(self, name: str, sink: dict[str, float]):
 _t0 = time.monotonic()
 try:
 yield
 finally:
 sink[name] = round(time.monotonic() - _t0, 3)

3. **Wrap the eight blocks.** `with self._timed("world_context", _stage_secs):` directly inside each
 existing `try:`, so the surrounding `try/except` keeps owning every failure path.

4. **Persist it where it can be read.** At the end of `run_once`, write `_stage_secs` into the returned
 dict and into the state file (the state file already carries `subsystem_health`, so extending it is a
 dict update, not a new file).

## Why it is not in this round

Applying it means editing eight separate code paths in the single most critical file in the system - the
one whose failure mode is "the company stops working" and which I have already had to restart twelve
times today. Doing that at the end of a session, with the attention budget low, is the exact pattern
that produced two of my own near-miss bugs this session (a flush after `close()`, and a name collision
that raised `NameError` inside `run_once`). The instrument is worth one fresh session with the whole
context window, and the design above is complete enough that it should take one.

**Being explicit about the tradeoff:** the objective's remaining work is measurement, and this
instrument is the key that unlocks the biggest unmeasured thing. Deferring it leaves the autopilot
cadence decision (D335) blocked on it. That is a real cost, and it is smaller than the cost of a subtle
break in `run_once`.
