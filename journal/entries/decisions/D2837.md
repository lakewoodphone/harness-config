**D2837 · 2026-09-29 · The 13.9 GB database: 79% of it is dsh_session_events plus its full-text index, and the fix is already sitting in the owner queue as #197.**

ANSWERED 2026-09-29 with dbstat and exact counts. The 13.9 GB (13.0 GB main file) is NOT what anyone assumed, including two wrong guesses made earlier the same day.

WHAT IT IS:
 dsh_session_events table 4.3 GB (979,643 rows, ~4.7 KB/row - session JSON blobs)
 dsh_session_events_fts_content table 4.2 GB (FTS5 stores its OWN copy of the indexed text)
 dsh_session_events_fts_data table 1.7 GB (the FTS index structures)
 ------------------------------------------------- 10.2 GB = 79% of the file
 procedural_experiences 574 MB
 dialpad_stats_record 350 MB
 memory_vectors_vector_chunks00 264 MB
 gateway_trace_span 140 MB
 work_sessions 134 MB
 ...and about 215 other tables sharing the remaining ~2.8 GB

These are the harness's own session transcripts, shipped to the server every 30 minutes by push-dsh-sessions.mjs in secratary's crontab.

WHAT WAS WRONG BEFORE THIS MEASUREMENT:
 * first guess: unbounded tick telemetry. WRONG - tick_telemetry is 32,281 rows, 12 MB-ish.
 * second guess: free pages from deleted rows. WRONG - freelist_count is 1,142 pages = 4.5 MB = 0.0% of all pages. The file is real data, not holes.
 * there is NO table above 1,000,000 rows, and only 3,406,092 rows across all 210 ordinary tables. Row COUNT was never the right question; row SIZE was.

THE LEVER: the FTS index costs 5.9 GB (content + data) to make 4.3 GB of table searchable - a 137% overhead. So deleting old session rows reclaims roughly 1.4 bytes for every byte of table, and dropping or rebuilding the FTS on a retained window reclaims the rest. Realistic reclaim on a 7-day retention: about 10 GB.

NOT MINE TO DO: owner_decision_queue item #197 already asks exactly this - "Authorize deleting dsh_session_events older than 7 days after a verified archiver" - and a per-day archiver is recorded as already existing with no DELETE. So the decision is already queued, the safety net already exists, and what is missing is his yes, not engineering.
