**D3149 · 2026-10-18 · lpt-write authority repointed: frozen anchor secratary -> secratary-cloud.**

## What was wrong

`lpt-write` deployed its helper, and `lpt` read the operational store, through the host named
`secratary` — the **FROZEN rollback anchor** (`harness-config/settings/machines/host-posture.tsv`:
"never create a second writer for the company database"). The anchor was therefore an ACTIVE
writer of the production RDS, not a snapshot.

## Config location and the change (branch `lpt/web-parity-20261014`, NOT committed)

* `lpt-ops/lpt_ops/transport.py` — `AUTHORITY_SSH` default `secratary` → `secratary-cloud`
 (ONE constant, with the posture citation). Added `AUTHORITY_PYTHON` =
 `~/personal-secretary-mvp/.venv/bin/python3`, and `AUTHORITY_NAMES = {AUTHORITY_SSH}`.
* `lpt_ops/writes.py`, `lpt_ops/web_api.py` — deleted the duplicate literal
 `AUTHORITY_NAMES = {"secratary", "secretary"}`; both now import it from `transport`, so the
 frozen box is no longer mistaken for a local write target.
* `lpt_ops/redact.py` — two `os.environ.get("LPT_AUTHORITY_SSH", "secratary")` defaults replaced
 by the imported `AUTHORITY_SSH`; `lpt-redact` no longer carries a third copy of the hostname.
* `C:\Users\ezabz\AppData\Roaming\lpt\env.cmd` — `set LPT_AUTHORITY_SSH=secratary` →
 `secratary-cloud` (backup `env.cmd.bak-20261019`).
* `install.ps1`, `install.sh` — candidate list names `secratary-cloud` FIRST. The installer's
 probe tests reachability, not posture; `secratary` answers `hostname` from the LAN, which is
 exactly how the frozen box got recorded in the first place.

## Which host holds the DSN — the test does NOT discriminate

`PHONE_TECH_FULL_DATABASE_URL` is present in BOTH `~/personal-secretary-mvp/.env` on `secratary`
and `/root/personal-secretary-mvp/.env` on `secratary-cloud` (variable NAME printed only, value
never read), and both have `psql` and reach the RDS. So DSN presence cannot choose. What chooses
is `host-posture.tsv`: `secratary` = frozen; `secratary-cloud` = THE AUTHORITY.

## Evidence the anchor was writing

`secratary:/home/zabz/lpt-ops/audit/writes.jsonl` had **496** rows; the last two were
`2026-10-19T00:59:57Z order create WO26101912755` and `2026-10-19T01:00:13Z note add id 4152`,
operator `ezabz@zabz-tech`. The authority's ledger had **150** rows, last
`2026-10-18T10:46:47Z`.

## The measured defect did NOT reproduce on this host

Measured on **ZABZ-TECH** (Windows), not ZABZ-YOGA as the brief said. Here `lpt doctor` already
exited 0 via `ssh secratary`, and `python bin/lpt-write doctor` exited 0. The reported
`banner exchange: Connection to UNKNOWN port -1: Connection timed out` is host-position specific:
`secratary` is `192.168.50.77`, a LAN address, so a machine off the LAN times out while this
desktop does not. The policy defect (frozen box as writer) was real everywhere; the timeout was not.

## Error text, verbatim

`ModuleNotFoundError: No module named 'psycopg2'` — `lpt doctor` immediately after the repoint.
Cause: `secratary-cloud`'s `python3` is the system interpreter with no psycopg2; the app venv has
2.9.13. Fixed by naming `AUTHORITY_PYTHON` rather than editing the command inline.

## Risk noted, not fixed

(`df -Pk /`). This note write is a few hundred bytes, but the authority holds the company
database on that filesystem.
