**D196 · 2026-09-15 · Search engine: SQLite FTS5 stays, vectors are a later backfill (evidence from web research + measurement).**

**D-2026-09-15 · Search engine choice settled by primary sources and measurement: SQLite FTS5 stays; vectors are a later backfill.**

A deep web-research pass (2026-09-15, sources below) tested the engine question against this fleet's
actual topology, and it was already the right call — but for a better reason than "SQLite is the
existing idiom".

*Windows is the hard filter.* Zoekt has no Windows support in main and the restoration PR
(sourcegraph/zoekt#941, opened 2025-04-13) is still open; its own description says `go test ./...`
remains unavailable on Windows because `zoekt-local-sync` needs Unix file locking. ParadeDB ships
`.deb`/`.rpm`/`.pkg` only. Quickwit is Linux-only and a maintainer closed vector search as "unlikely
to happen". Typesense's Windows issue has been open since 2023 and needs WSL/Docker. Meilisearch
wants Windows Server 2022+ and is a daemon. **Of every candidate only FTS5 and Tantivy run
first-class on all four hosts.** Tantivy measured slower on the same corpus class (~6 ms median,
~79 ms median for phrase queries, vs sub-millisecond for FTS5), so the migration would buy index
size and nothing else.

*The one real cost of staying is index size*, and it is content-dependent rather than the 4.3x a
synthetic benchmark suggests: on 3,000 real `.py`/`.md`/`.ts`/`.ps1` files the ratio was ~0.4x of
raw text. That matters on the 22 GB server, which is why the design shards by source.

*Vectors: defer, but ship the schema.* No embedding model can run at useful throughput on these
hosts today (CPU only, no GPU, no Ollama); the only hardware-stated CPU figures are ~20 sentences/s
for bge-small on a 16-vCPU GCE instance, which is days of CPU for this corpus. sqlite-vec carries an
open corruption bug (#297: vec0 corrupts on first write after a cross-platform file move) and is
pre-v1 by the author's own description. So `chunks_meta.embed_key` now holds the sha256 of each
chunk's text, which makes an embedding a **cache keyed by (embed_key, model_id)** rather than a
property of a row id — a model swap fills a second model_id instead of invalidating the index. The
model-drift failure is solved by construction, and turning semantic search on later is a backfill,
not a reindex.

*Rejected on the evidence:* Zoekt, Livegrep, Meilisearch, Quickwit, Typesense, ParadeDB, Tantivy,
and building the vector path now.
