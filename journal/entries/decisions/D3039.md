**D3039 · 2026-10-12 · LPT NAVIGATION ships at 299 with the case as a 20 add-on; the 285 proposal is dead.**

The owner said on 2026-10-12 that the iPhone stock for the Waze product is arriving and he wants to
start selling it immediately. That makes the price live again, and the record contained two numbers.

**What was on record, read today:**
- **299.00** — settled 2026-09-14 in the supply-pipeline decision **D101**, wired into the code as the
 `WAZE_DEVICE_PRICE_CENTS` default (`29900`), and into the live Stripe objects. Owner-queue row
 **#140** (answered 2026-09-22) records him confirming the plan figures and the seat then setting the
 device placeholder to the settled 299 list price. Row **#255** asked him to approve 299 + the plan a
 second time and was closed 2026-10-08 as a **re-ask**, without troubling him.
- **285** — proposed in `lpt-hub/docs/customer-operations/waze-device-launch/FIRST-RUN-2026-10-05.md`,
 with the case moved to an optional **20** add-on. That document's own §6 says it plainly: *"The 285
 price is not in the code. `WAZE_DEVICE_PRICE_CENTS` still defaults to `29900`."* It was never landed
 in the code, the Stripe objects, the storefront copy or any environment.

**Ruled:** the product sells at **299.00**, with the case as an optional **20.00** add-on. Reasons, in
order: 299 is the number that is approved, published and wired in every system that actually takes
money, so it is the only one that can be live this week; the real landed cost is **151.69** per device
(phone 145.00, cable 6.35, labels 0.34 — the amounts actually paid, from FIRST-RUN §2/§3), so 299
clears the owner's standing **100-dollar gross-profit floor** with **147.31** of margin; and 285 buys
14 dollars less margin for a change that would have to be re-wired through code, Stripe and copy.

**Not a re-litigation, and not a new question for him.** He set the floor and the terms; the numbers
are arithmetic. If he wants 285 he will say so and it is a one-line change, but nothing in the record
shows he ever asked for it.

**What this ruling also fixes:** `PRICING-AUTHORITY-2026-10-12.md` (lpt-hub, same day) is the single
place every price now lives, so this cannot be re-derived wrong from two documents again.
