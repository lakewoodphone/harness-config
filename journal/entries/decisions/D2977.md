**D2977 · 2026-10-08 · origins basePort stays 3200 - restore the shared truth, do not adopt the local aberration.**

Decided 2026-10-08 on ZABZ-YOGA, after finding windows.json at basePort 3200 while a stray proxy
served 3300-3323 and a window had been launched on origin 3300.

The tempting fix was to write 3300 into windows.json, because 3300 was what was RUNNING and what the
owner could see. Rejected, for three reasons:
 - 3200 is the value in every committed revision of windows.json, in the dshw.ps1 comments that
 describe the model, and in windows-registry.json (rows 3200..3215, written against it);
 - windows.json is shared by every machine, so 3300 would have made the OTHER machine's config
 disagree with the proxy running there - the same fault, moved rather than fixed;
 - 3300 was a local override: origins.log has `start pid=31592 base=3300 ...` from 2026-10-02, and a
 harness-config sync rewrote windows.json at 2026-10-07 20:20:32, reverting the local edit and
 leaving the running proxy on a range the config no longer named.

So the value is unchanged and the LOCK was the fault (L3416). With the lock fixed, `ensure` bound
3200-3223 at 20:43:22 with no override, the 3200 proxy (pid 4056) serves the door, and the stray 3300
proxy (pid 21252) was reaped only after proving no process held any connection to 3300-3323.

RULE: when a running service and its config disagree, ask which one is shared and which one is local,
and fix the local one. Adopting the aberration into the shared file spreads the fault to every machine.
