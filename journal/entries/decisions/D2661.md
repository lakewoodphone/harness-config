**D — Android and iOS are both to be fully activated, and customers' own devices are enrolled in the MDM (which resets them).**

**The owner's direction, given 2026-09-28 in conversation.** Verbatim: *"we want android and ios fully
activated, we have a vpp license and full apple mdm, we will enroll our customers devices in the mdm,
which would mean resetting the devices i think"*.

**Two corrections I had to make first, because the question I had queued was built on them.**
1. **`kosher-filter-ai` and "Kosher Waze" are different products.** Kosher Waze is LPT NAVIGATION™ — an
 iPhone 11 (A2111), MDM-locked to Waze, Telnyx cellular, $299. The filter's own
 `docs/HANDOFF_2026-09-11.md:235` says *"This document covers kosher-filter-ai only"*. The only link is
 that the filter's iOS plan **reuses** the Waze Apple/MDM stack (`ios/README.md:51-56`).
2. **Kosher Waze ships on iOS, not Android** — the runbook's enrolment path is Apple Configurator +
 ABM + ADE on iPhone. I had written the opposite.
Together those made owner question **#178** invalid — it asked the owner to buy a Mac (four figures) and
an Apple Developer membership that the Waze programme already provides. **#178 was withdrawn on
2026-09-28.**

**His confirmation is correct, and it is the important consequence.** Full MDM control means a
**wiped** device:
- **iOS.** The enrolment point is Setup Assistant — *"DEPLOY (Phase 1) — run once device enrolls (after
 Setup Assistant / 'Remote Management')"* (`deploy/waze-mdm/archive/2026-06-29-old-runbook.md:224`),
 and the recorded primary path is Apple Configurator 2 **Prepare → Manual Configuration → Add to Apple
 Business Manager** (`waze-mdm/RUNBOOK.md:139-145`), and *Prepare* erases. The alternative — a device
 that arrived already ABM-assigned from a reseller (Option B, `:147-148`) — still enrols at first
 Setup Assistant. There is no supported way to make an in-use iPhone supervised without wiping it.
- **Android.** The equivalent (device owner / fully managed) is provisioned at the setup wizard, which
 likewise requires a factory reset.
- **The no-wipe alternatives are not this product.** An iOS MDM profile installed by hand is
 user-removable, and an Android work profile covers only the work side. A filter that the user can
 remove is not a filter, so neither is a substitute here.

**Operational consequence, recorded so it is never a surprise at the counter:** the customer's phone is
erased, so it must be backed up first, iCloud/Google sign-in happens again at setup, and **the shop
performs the enrolment at the bench** — which is the model already used for the Waze fleet. A customer
who will not have their phone wiped can instead be sold a device (the Waze model), where no customer
data is ever at risk.

**Two gates found while recording this.**
1. **Our own iOS app cannot reach a device over VPP without an Apple Developer Program *organization*
 membership and the app published in App Store Connect as a custom app.** A VPP licence for Waze — a
 public App Store app — is a different thing from being able to distribute *our* app. Whether the
 membership exists is **UNVERIFIED**; the January directive
 `lpt-hub/directives/active/2026-01-30-apple-business-manager-direct-contact-recourse.md:101` asked the
 question and the record has no answer.
2. **There is no Android MDM.** The fleet stack (NanoMDM/NanoDEP, 11 containers, 65 devices enrolled as
 of 2026-09-15) is **Apple-only**. Enrolling a customer's Android device therefore needs the filter's
 own device-owner provisioning path (QR at setup wizard) or a purchased EMM. This is a build item, not
 a decision.
