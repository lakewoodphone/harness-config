**D180 · 2026-09-15 · Kept the committed /api/health healthcheck as measured-200; corrected the box compose build context to ./fleet-dashboard/backend.**

Two decisions made while deploying fleet-dashboard honesty (1b0c91d6) to waze-mdm-01, 2026-09-15.

1. HEALTHCHECK: KEEP THE COMMITTED `/api/health` + `assert r.status == 200`. Not a preference —
 the live config answers HTTP 200 (`status: degraded`), measured, so the committed check is
 correct as written and the "relax it" branch of the brief does not apply. Rationale in the
 lessons entry of the same date: 503 is emitted only when the database is genuinely unqueryable,
 which is a real liveness failure here. No code change, so nothing to commit or push.

2. BOX COMPOSE BUILD CONTEXT: corrected `context: ../fleet-dashboard/backend` →
 `./fleet-dashboard/backend` in `/opt/waze-mdm/docker-compose.yml`, with a 4-line comment saying
 why. `../fleet-dashboard/backend` resolves relative to the compose file's directory, so on this
 box it means `/opt/fleet-dashboard/backend`, which does not exist — `docker compose build
 fleet-dashboard` failed with `unable to prepare context: path "/opt/fleet-dashboard/backend" not
 found`, and had been failing since the tree was laid out (the running image dated 2026-07-05).
 The repo value is CORRECT FOR THE REPO (where deploy/fleet-dashboard is a sibling of
 deploy/waze-mdm); the box puts fleet-dashboard INSIDE /opt/waze-mdm, so the same relative path
 cannot serve both layouts. This is a dev/file-layout call, so it is mine to make and record.

PROVENANCE OF THE COMPOSE, which is why I am confident nothing else moved: with the 4-line comment
block and the new context line reverted, the box compose hashes to
211f8b8431e4d741f20ac6baeb1e62b9adee581e7fc018ce2194bbc0c5a0dcda — byte-identical to
`git cat-file blob 1b0c91d6:deploy/waze-mdm/docker-compose.yml`. So the box compose is the committed
compose plus exactly one deliberate, documented deviation.

FOLLOW-UP THIS CREATES (not done, because the brief permitted no push and the fix is not a
healthcheck fix): the repo has no way to express the box layout. Either the repo should move the
dashboard under `deploy/waze-mdm/fleet-dashboard/`, or the deploy runbook should ship the context
override as a documented step. Until then, the next person who copies the repo compose over the box
re-breaks the build.
