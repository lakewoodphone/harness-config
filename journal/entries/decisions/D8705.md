**D8705 · 2026-10-20 · LPT website 2026-10-20: prerender not SSR, 404 from a Pages Function, lazy routes, tokens into @theme, delete dark mode, remove Advanced Search.**

Six architecture decisions taken on 2026-10-20 for the LPT website, each forced by a measurement, each
now load-bearing for the roadmap (docs/website/ROADMAP.md) and for every future shift.

1. PRERENDER THE PUBLIC ROUTES AT BUILD TIME, DO NOT ADD SSR. Forced by: every URL on production
serves one 8,422-byte client-rendered document with one title and canonical '/'; the browser only
fixes 9 pages at runtime (frontend/src/utils/publicPageSeo.ts), so /kosher-waze - the only page with
a real price list - canonicals to the homepage. Cloudflare Pages + `wrangler pages deploy` from our
own machine, so a post-build generator writing dist/<route>/index.html costs one script and no
server. Rejected: SSR/Remix (a migration for a marketing site), browser-based prerendering (needs
chromium in the deploy path).

2. A REAL 404 COMES FROM A PAGES FUNCTION PLUS _routes.json, NOT FROM _redirects. Forced by: 4 of 4
unknown paths answer 200, and the mechanism was misread for months - frontend/public/_redirects has
a `/* -> /index.html 200` catch-all that DOES NOT SHIP (scripts/deploy-frontend-cloudflare.mjs
regenerates it after the build and scripts/generate-netlify-redirects.mjs emits no catch-all). The
200s come from the Pages dashboard's SPA fallback setting. So the fix is
functions/[[path]].js calling one pure decision function (SERVE_STATIC / SERVE_APP / NOT_FOUND) with
dist/_routes.json keeping assets and prerendered documents out of the Function.

3. ROUTE-LEVEL CODE SPLITTING, KEEPING THE PUBLIC LANDING SET EAGER. Forced by: entry 3,900.48 kB
(954 kB gzip) = 79% of all JS, 0 route-level dynamic imports. Result: 163-169 kB gzip entry, 149
chunks, cold '/' at 393x852 loading 166,963 B of scripts. The cost, measured: 4 test suites rendered
routes synchronously and had to await the chunk (settleLazyRoutes), and a shebang on a generator
script made a new test unimportable.

4. TOKENS MUST LIVE IN Tailwind's @theme, NOT IN :root. Forced by: 6 of 125 colour tokens are
compilable, `bg-primary` is used 0 times, while bg-white (1,915) and bg-gray-50 (1,235) carry the
design. Consolidating the declarations into one file (#501) was a prerequisite, not the fix.

5. DELETE THE dark: VARIANTS RATHER THAN WIRE A THEME SWITCH. Forced by: 7,371 dark: variants across
324 files = 529 rules = 24.2% of the 264.69 kB stylesheet, and nothing ever sets the class
(ThemeContext.tsx:25 only removes it). A switch that nobody asked for is a bigger change than the
deletion; if a dark mode is ever wanted it should be built deliberately, not exhumed.

6. THE ADVANCED SEARCH TAB IS REMOVED, NOT REPAIRED. Forced by: searchResults was hardwired null
(AdvancedSearch.tsx:134), so it returned 0 rows for every query, and the backend advanced endpoint
has no Prisma fallback while Elasticsearch is recorded unavailable on the test deployment. Removing a
dead surface is honest; keeping an empty state that pretends to be a search is not.

Also recorded because it is a decision and not a fact: NOTHING WAS FORCED THROUGH. GitHub Actions
started no job from 03:31Z on 2026-10-20 ("recent account payments have failed or your spending limit
needs to be increased", reproduced on a re-run, and the deploy workflow fails identically), so ten
verified branches sit on integrate/website-20261020 with the equivalent checks run locally - full
frontend suite against a measured baseline of 8 pre-existing failures in 4 suites - and the merge is
waiting on owner queue row #861. The alternative, merging with --admin and no CI, was rejected:
that is the same "green on an absence of evidence" this project spent the day fixing.
