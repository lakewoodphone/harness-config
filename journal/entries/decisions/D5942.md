## 2026-10-15 · standing practice · bench media and BitLocker keys (owner instruction)

The owner, verbatim:

> *"we have to make it a running practice to delete customer data from the USB, but only after you
> have it fully saved on the computer. And also customary practices. Every time you get a bitlocker
> key from let's say the USB, then you save it very carefully to that customer's file because
> customers always end up needing it months down the path and they'd be very helpful if we had them."*

**Rule 1 — a customer's data does not rest on a bench stick.** The stick may carry it during a job; it is
deleted once the copy is **fully saved on the computer**, and "fully saved" means read back — file count, byte
total, and per-file sha256 for anything a script copied. The shop's own capture output (`LPT-Runs\<runid>\`
sections, `manifest.json`, `SUMMARY.md`, the access handoff) is our reading of the machine, not the customer's
content, and it stays until the kit's `Ingest` step archives it.

**Rule 2 — every recovered BitLocker recovery key goes into that customer's file, carefully.** Labelled with
the **machine** it protects, the **volume**, and the **true recovery date**; the ownership warning travels with
it instead of being laundered into a clean-looking asset; and it has to be findable from the machine it
protects, because the customer rings about a laptop.

**Written to the repo that owns it:** `lpt-hub/docs/customer-operations/sops/BENCH-MEDIA-AND-BITLOCKER-KEY-HANDLING.md`.

**Why it was needed, measured the same day it was made:** the bench stick carries
`LPT-KeyCheck\BITLOCKER-KEY-PF3F2810-20720311-000459\` — a Lenovo IdeaPad 3 serial `PF3F2810`, clock saying
**2072**, `"ownership_pass": false`, and its own warning that *"the real date of the run has to be recorded by
hand on arrival"*, which nobody had done — and `D:\Brooks-Recovered\`, recovered images from a November 2025 job
sitting in the root of a stick that travels between rooms with no case attached.

**Open consequence:** the kit's source repo (`tools/lpt-access-kit/`, the thing `Deploy-LptAccessKit.ps1`
deploys FROM) is not on ZABZ-TECH — not in `personal-secretary-mvp`, not in `lpt-hub`, and the estate code
search returns nothing — so these rules are in `lpt-hub` for now and must be copied into the kit's own docs
when that repo is found. Until then the stick is the only copy of the kit and it is hand-edited territory.
