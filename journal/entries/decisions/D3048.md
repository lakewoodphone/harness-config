**D3048 · 2026-10-11 · The phone engine's install-layout invariants are re-asserted at every start.**

## Decision, 2026-10-12

Decided (dev, mine): the phone engine's two install-layout invariants are enforced mechanically
rather than remembered.

1. @deepseek-ai/dsh-scope resolves to ONE file across /opt/dsh-phone and the profile tree.
2. the phone-layer assets exist where phone-gate.py looks for them.

Mechanism: scripts/repair-phone-engine.sh, wired as phone-engine.service ExecStartPre with --check.
--check fails the start instead of repairing silently, so a recurrence is visible in
systemctl status phone-engine rather than on the owner's phone.

WHY A DROP-IN: the unit file is regenerated from harness-config on redeploy; a drop-in is additive
and survives that. Reconciled from settings/phone-engine-repair.conf in the repo.

WHY NOT fix the code instead: the two defects are properties of the INSTALL, not of the code. Both
would return with any reinstall or rebuild. A guard at start is the only place that sees them.
