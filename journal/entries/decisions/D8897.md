**D8897 · 2026-10-20 · The update system after 2026-10-20: assumption check as a three-site gate, an undo per writing phase, measured-version tables, both-ways proof, and the record as part of the pipeline.**

DECIDED 2026-10-20, after the ZABZ-YOGA window (record: docs/POSTMORTEM-2026-10-20-ZABZ-YOGA.md, lessons L11646 and L11711). Each decision names the gate that enforces it, because a decision with no enforcement point is the failure this night was made of.

1. THE ASSUMPTION CHECK IS A GATE, NOT A TOOL. `tools/config-assumptions.mjs` blocks `preflight` (guard "our config assumptions (prompt tokens, ctx injections)"), refuses inside `install-engine` before the staged copy is made, and runs as STEP 2.5 in `switch-yoga.ps1` against the CANDIDATE before the live config is touched. Rationale: it answers the one question no other guard asks (does OUR config name something THIS version does not offer) and it had already been the difference on ZABZ-TECH a day earlier. Three call sites on purpose: preflight reports, install refuses at the last possible moment, the switch refuses before the config mutation that a failed install cannot undo.
 Rule kept: it blocks only when it RAN and found something; a candidate that is not fetched or a tool that cannot start is a GAP, never a pass.

2. A PHASE THAT WRITES MUST REGISTER ITS UNDO BEFORE IT WRITES. `switch-yoga.ps1` now restores `cordis.patch.yml.bak-switch-<stamp>` in its failure path before it restarts the old engine. The failure it fixes was self-inflicted: install-engine refused, the script restarted the OLD engine against a patch it had already rewritten to the NEW version's shape, and the machine crash-looped. Standing rule for every future phase: make the copy, then write; the failure path runs the copy back before any restart.

3. PROMPT-VARIABLE SETS ARE KEYED BY A MEASURED VERSION, AND AN UNMEASURED VERSION REFUSES (exit 3). The set was one hardcoded 0.2.1 constant applied to every engine — the same class the tool exists to catch, one level up. A version with no measured row is not guessed.
 Also: full-line YAML comments are skipped, because a checker that fails on documentation gets turned off (measured on ZABZ-TECH, where three preset files carry the 0.2.1 explanation in comments).

4. A GATE IS TRUSTED ONLY WITH A POSITIVE AND A NEGATIVE CASE IN THE REPO. config-assumptions: PASS on 0.2.1-rc.2, exit 1 naming `cordis.patch.yml:4 row "preset-zabz" {{cwd}}` on a scratch home. audit(): 4/4 `registered` on the trees that previously reported 4/4 `NEEDS-PATCH`. install-engine: the PASS line is exercised in a dry run against the previous tree; its refusal is the same code path with findings present (not separately exercised — stated rather than claimed).

5. THE RECORD IS PART OF THE PIPELINE. `docs/KNOWN-BREAKAGE-CLASSES.md` is the index (class → journal id → gate → search words) and RUNBOOK/README point at it before anything else; `docs/UPDATE-SYSTEM.md` is the phase chain with the gate that owns each phase and the six open items; the postmortem is the account. Chosen over "write a better handoff" because the handoff is written by the session that is inside the work and is read by a session that is looking for an action.

6. TWO BRANCHES ARE A NAMED DEFECT. ZABZ-YOGA (cloud-audit/20261019) and ZABZ-TECH (fleet/search-api-20261019) each needed the same three commits. Both are now applied and committed (yoga 1c0420f07, 712ebaba5, 62c3a3356, b4875cb6a; tech 6e99f847, 922a492b) and pushed (yoga → cloud, tech → mirror), but the divergence will repeat until they converge. Converging them is a session-sized job and belongs on the owner-queue only if it costs him a decision; it does not — it is engineering.

STILL OPEN, with the reason (full table in docs/UPDATE-SYSTEM.md §5): the config mutation should move into `install-engine` and happen with the tree swap (a failed install currently leaves the live config implying a version that is not installed); `dshw ensure` checks the origins proxy before the engine and so refuses to start a machine whose engine is down; profile anchors are verified only for the staged home, not at boot; presets carry machine-specific absolute paths; `artifact provenance` will stay NO-GO until the judging verbs re-stamp their artifacts against this home.
