**D9363 · 2026-10-22 · Authority disk: 20 GB reclaimed with archive-before-remove; reaper and 88%/25GB journal alarm installed.**

Implemented on secratary-cloud, 2026-10-22 17:35-18:10 UTC, on his instruction "figure this out fully and implement it end to end without losing any data we want and make sure this is protected for the future".

RESULT, by `df -h /`: **`225G 194G 23G 90%` before → `225G 174G 43G 81%` after.** Twenty GB reclaimed.

WHAT WAS IN THE WAY. 83 scratch trees (74 under /root/wt*, 8 under /root/repos/_worktrees, 8 pr-wt-*): 71 were git WORKTREES sharing a parent repo's object store, 4 were already-broken clones (their .git pointed at /root/wt777c, gone before this session), 8 were pytest basetemp dirs.

HOW REMOVAL WAS MADE SAFE, in this order:
1. `/root/wt-archive/` holds, per tree, `dirty.patch`, `status.txt`, `staged.patch`/`unstaged.patch` when the HEAD diff was empty, `untracked.txt`, a copy of every untracked file under 200 KB, `stashes.txt`, and `INFO.md` with remote + restore commands. The big captures are real work: pr-wt-247 25 MB over 2,614 paths, pr-wt-355 15 MB over 1,730, pr-wt-446 12 MB over 1,458.
2. Proved with `rev-parse --git-dir` that 71 trees were worktrees - removing a worktree cannot lose a commit, because the objects live in the parent repo.
3. The 4 broken clones were tarred whole first (`orphaned-broken-clones-20261022.tar.gz`, 127 MB, 24,483 entries) and only removed after the tar listed at least as many files as the source.
4. Removed with `git worktree remove --force` + `git worktree prune` in each parent; pytest basetemp dirs removed outright.

PROTECTION INSTALLED
- `/usr/local/bin/worktree-reaper.sh` (sha256 9ae131fc...), cron `17 4 * * *` through cron-wrap.sh. Touches only the three scratch roots; only trees with no file modified in 48 h; archives before removing; skips clones; skips any tree it cannot capture. Dry run after install: reaped=0 freed=0MB skipped=12 (nothing left).
- `/usr/local/bin/disk-alarm.sh`, cron `7 * * * *`. Fires at 88% used OR under 25 GB free - the old disk-guard only spoke at 90/95 into a log nobody reads - and appends a JOURNAL pain entry. Both branches proved: quiet (`used=78% below threshold`) and forced (`journal pain appended`). Self-test entries P11339/P11340 resolved at once.

HONEST RUNWAY. 43 GB free. authority.db freelist was 10.07 GiB at 0.88 GiB/day, so the file grows again ~2026-11-02, after which 43 GB buys ~6 weeks. **This protects against worktrees, not against the database.** The only permanent lever is moving the session-event history out of the live database file (dsh_session_events is ~89% of it) - designed but NOT implemented, because it deletes rows and needs a maintenance window and a verified export.
