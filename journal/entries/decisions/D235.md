**D235 · 2026-09-16 · The broker derives its reserve per node from mem.totalMiB; the gate's budgetSlots is advisory (closes 81-overnight-program section 3 item 2).**

The broker's slot arithmetic now derives its reserve PER NODE from that node's own `mem.totalMiB`,
and the gate's `governor.budgetSlots` is advisory and is not consumed.

DECIDED 2026-09-17 by stream O5 of the overnight program. This closes §3 item 2 of
docs/mesh/81-overnight-program.md ("the gate and the broker use two DIFFERENT reserves — decide
which is right and say why"). **Do not re-litigate it.**

WHICH IS RIGHT: the gate's form. `max(2 GiB, 12% of physical)` is `governor.js:126`, and it is a
per-host rule because the reserve is memory held back ON THAT HOST for everything that is not a tool
process. `3885` is that rule evaluated on one 31.6 GB laptop and was applied to all four nodes.
MEASURED, per node: 11,673 MiB -> 2,048 (floor binds); 23,422 -> 2,811; 32,373 -> 3,885 (exact);
65,173 -> 7,821. The literal under-reserved the 64 GB desktop by 3,936 MiB — ~24 slots.

WHO OWNS THE ARITHMETIC: the broker. 71 §2.1's last rule already says "Residency/budget arithmetic
belongs to the BROKER, not here: the gate reports measurements only". And the gate's number cannot
be consumed even if that were wanted: `governor.js:131-132` floors it at 4 and caps it at 24, which
turns "no measurable headroom" into "4 slots".

WHAT SHIPPED:
 * `lib/scoring.js` gains `reserveMiB(reading)` = `max(2048, round(mem.totalMiB * 1048576 * 0.12))`
 computed on BYTES so it is byte-identical to governor.js:126, returning
 `{reserveMiB, basis: derived|floor|fallback, line}`; `slotArithmetic()` uses it and prints the
 derivation in the rationale.
 * `3885` is KEPT and still exported as `RESERVE_MIB` — it is the FALLBACK for a node reporting no
 `mem.totalMiB`, and the rationale says so when it is used.
 * `lib/broker.js`: `/nodes` rows carry `scoreTerms.reserveMiB` and `.reserveBasis` per node;
 the exported `broker.config.reserveMiB` scalar (read by nothing) became `reserveRule`.
 * docs/mesh/71-mesh-program.md §2.2's frozen formula corrected, §2.1's advisory note added.
 * `test/scoring.test.mjs`: two assertions updated (the fixture's own reserve is 7,819 MiB, so
 `beforeCap` is 269 not 294) and strengthened to assert `reserveMiB`/`reserveBasis` directly.
 The published score the worked example pins is UNCHANGED at 9, because `maxSlots=24` binds.
 Suite: 60/60 on Node v24.12.0 and on the authority's Node v20.20.2.

NOT FIXED, ON PURPOSE: `12% of physical` makes a fixed cost scale with RAM (7,821 MiB held back on
a 64 GB desktop). Capping it needs a measurement from a node under a real fleet (stream O3), not a
guess. The broker now reproduces the governor's number for the node in front of it and publishes it,
so that change is one place and visible.

Full record: docs/mesh/86-authority.md §3.
