**D2976 · 2026-10-08 · phone-and-tech: the order-status vocabulary validator gates typecheck; the test tsc only records.**

## Decided: the vocabulary validator gates `typecheck`; the test `tsc` only records

Decided 2026-10-08, ZABZ-YOGA, `pbp/w2b-status-tests`. A development decision, so
it was made and recorded rather than escalated.

**The decision.** `pnpm typecheck` runs
`npm run validate:order-status && tsc --noEmit`. `pnpm typecheck:tests` runs
`tsc --noEmit -p tsconfig.test.json` and is NOT part of `typecheck`.

**Why not wire the test `tsc` into `typecheck`, as the brief literally asked.**
Because it surfaces 2353-2427 pre-existing errors. Wiring it in does not make the
class recur-proof; it turns `pnpm typecheck` red for every other workstream the
moment this branch lands, and a gate everyone has learned to ignore is worse than
no gate. The brief anticipates exactly this ("if it surfaces a large backlog … report
the count, fix only what is in your lane, and record the rest"), so the backlog is
recorded here and in pain, and the debt is `pnpm typecheck:tests`.

**What delivers the value instead.** `scripts/validate-order-status-members.ts`
reads the enum out of `prisma/schema.prisma` — the single source of truth — and
fails if any `backend/src` file names an `OrderStatus.<MEMBER>` the schema does not
declare. O(seconds), zero-error baseline, and it covers TEST files, which
`tsconfig.json` excludes. The next deleted enum member now fails `pnpm typecheck`
instead of becoming an `undefined` that reads like a service bug. Verified with a
negative control: a probe naming `OrderStatus.COMPLETED` exits 1 and reports
`src/__tests__/__validator_probe.ts:2`; the probe was removed.

**What this decision does NOT cover.** The validator catches enum MEMBER access
only. It cannot catch `'COMPLETED' as OrderStatus` — a string literal that stays
the live string at runtime and fails as a wrong VALUE. Three of the twenty
failures fixed in this workstream were that shape (see lesson L3404). Neither the
validator nor a test `tsconfig` can police a string assertion; only a human
reading the expectation against what production interpolates can.

**Reversal condition.** When the `typecheck:tests` count fits, wire it into
`typecheck` and delete the validator. The general check subsumes the narrow one.
