**D7626 · 2026-10-18 · Owner queue: a work-order item carries a fresh read or is held; age is not news; no numbered menus.**

**Owner queue: a row about a work order now carries a fresh read or it is not shown. Age is not news. No menus.**

Host written from: **ZABZ-TECH** (desktop, Windows). Authority used read/write: `ssh secratary-cloud` (bash, writable authority). The frozen office anchor `secratary` was not touched. No outbound message was sent; no DSN or token value was printed.

## What already existed

- `/root/bin/premise-check.py` and the `owner_premise_check` table (`row_id, probe, checked_at, verdict, detail, expect_max_h`) were real: 189 recorded rows (1 changed, 10 fresh, 178 unprobed).
- `owner-queue.py` already read that table and printed a "premise MOVED" warning; `add` already had a dedupe guard and a P265 text guard.
- `owner-queue.py` already had a working-set hold for unbriefed decisions ("N decision(s) held back while I gather the facts").

## What was missing (the four defects)

1. **No work-order probe.** Nothing read production's current status; every probe looked at the row's own text or a ledger. A task row's text was never challenged.
2. **The presentation gate only warned.** `cmd_queue` printed the moved-premise lines and then showed the row in the same list, so "held back" did not apply to a moved premise at all.
3. **Nothing carried the read into the row at filing.** No producer recorded a fresh read, so there was nothing to hold the row TO.
4. **The aging paths made age look like movement.** `staleness_detector._flag_stale_tasks` appended `[AUTO] Stale: no progress for N days` and wrote `updated_at = now`, resetting the clock it measured; `app/database.py::_infer_task_lifecycle` called an age-only approval artifact "ready" to close.

## Files changed

- `/root/bin/premise-check.py` (+308/-5, 10 hunks): new `work-order` probe (`lpt ticket`, read-only, records the store, status, completed date and `read_at`), `customer-contact` probe (last message direction from `dialpad_sms_cache`), `already-sent` probe (`email_catalog`), and `replay --task|--row`; `check --record` writes the verdict at filing. A failed read is `unknown`, never `fresh`. `DONE_WO_STATUSES` covers COMPLETED/READY_FOR_PICKUP/PICKED_UP/UNFIXABLE/CANCELLED etc.
- `/root/bin/owner-queue.py` (+163/-8, 15 hunks): `_premise_hold` holds any record-shaped queue row whose latest check is absent, not fresh, or older than its budget; `_working_set` hides it by default and `--all` shows it with the reason; `cmd_add` runs `premise-check.py check --record` at filing and prints `premise MOVED — created but HELD`; `_menu_defect` refuses a numbered packet naming 2+ distinct records (exit 5).
- `/opt/company/app/database.py` (+50/-1, 3 hunks): `_task_is_age_only` and a `lifecycle.age_only` field; an age-only approval artifact now returns `review_required` ("being older is not evidence that it was handled"), not `ready`.
- `/opt/company/app/services/staleness_detector.py` (+24/-8, 4 hunks): marker is now `[AUTO] Stale (age only) ... not grounds for a customer message or an approval item`; **`updated_at` is no longer rewritten**; the WHERE clause skips marked rows (also fixes LIMIT 20 always returning the same oldest 20).
- Backups: `*.bak-gate-20261019T014644Z` beside each file. No schema change, no deletion, no live `owner_decision_queue` row written; tests ran against `/tmp/oqtest.db`.
