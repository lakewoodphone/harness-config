### Two things about my own process, both caught by not walking past them

1. **My deploy script aborted before the restart.** A stray `"` before a closing `)` in an `echo` left a
 new file on disk while the running process still held the old inode. Sections 1–7 had all passed, so
 the deploy *looked* complete. What exposed it was section 8 never printing. Completed by hand:
 restart at 22:19:46, and the process start is *after* the file mtime, which is how I know the new
 code is in memory rather than merely on disk.
 **Rule:** a deploy script's last statement must be the one that proves it finished. "No output"
 after a long success list is not success.

2. **The liveness watchdog restarted `company-api` again** (see `DEPLOY.md`): my restart brought it up at
 22:19:46 and `ExecMainStartTimestamp` later read from that same start, so this time it did not
 double-start. But `company-api-liveness.timer` runs every minute, and a deploy verification window
 must always be anchored to the LAST start, not to the deployer's.
