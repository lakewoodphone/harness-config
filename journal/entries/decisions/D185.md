**D185 · 2026-09-15 · The app configures its own logging at INFO with credential redaction; scheduled tasks state their refusals.**

**Decision: the application configures its own logging, at INFO, with credential
redaction.**

`app/logging_setup.py` (new) installs one root `StreamHandler` with
`"%(asctime)s %(levelname)s %(name)s: %(message)s"` and the level from `LOG_LEVEL`
(default INFO), called from `app/main.py` immediately before the first `from app.`
import so import-time records are captured. It is idempotent (a marker on the handler,
so a double import cannot double every line), it replaces a stray root handler in a
real process but deliberately leaves pytest's handlers alone (closing them mid-suite
breaks `caplog` for every later test), and httpx/httpcore/urllib3/asyncio/PIL are
capped at WARNING so the app's own narration stays readable. App loggers are never
capped.

Because INFO is now on app-wide and this codebase logs provider URLs and OAuth flows at
INFO, the handler carries a redaction filter: `Bearer <token>`, key/value pairs whose
key names a credential (with any of `_`, `-`, space or nothing between words, since
`X-Api-Key` had walked straight through the first version), `sk-`/`rk-`/`pk-`/`ghp_`/
`xox*` keys, and credential query parameters. It is deliberately narrow: a line that
merely *mentions* a token ("Gmail token health 4/4 ok") must survive unchanged.

**Decision: the lifecycle and staleness sweeps state a refusal.** A scheduled task that
is disabled, or waiting, or cannot import, says so once per distinct reason, at WARNING.
That line is what produced the answer above; without it a refusal and a dead subsystem
are the same silence.
