## The shop's work-order book is maintained by a tool family, not by a session; the review policy is code

Decided 2026-10-09, on the owner's instruction *"you will constantly be evaluating and fixing work
order fully and more, so make sure you are building and documenting for that not some one off
thing"*, followed by *"separate tools, not just one massive one… we want to run information or
things on one work order. It doesn't mean we have to run them on all billion work orders."*

**The decision, stated so it is not relitigated:**

1. **Six tools, one job each** — `lpt-case` (one work order, on demand), `lpt-review` (decide about
 one order under the standing policy), `lpt-questions` (the owner's questions, one at a time),
 `lpt-sweep` (the bulk pipeline, every stage sliceable with `--only`), plus the existing `lpt`
 (read) and `lpt-write` (change). All six are on PATH via generated shims.
2. **The review policy is a tested function**, `lpt_ops/sweep.default_review_policy`, not a
 reviewer's habit: terminal→terminal and open→open corrections are allowed; **a reopen is held**;
 closing live work is held; a note resting on message ordering is held; a price with no citation
 is rejected. A hand-written override always wins, and every decision prints the rule that made it.
3. **`READY_FOR_PICKUP` is terminal.** The shop has seven statuses and no `COMPLETED`;
 the 2026-10-07 migration maps `COMPLETED` onto `READY_FOR_PICKUP`. Nothing "closes out" those
 orders, because they are already closed.
4. **A price is only ever set from a figure quoted on the row**, and the action carries the citation.
 A total with no basis is rejected before it can be planned.
5. **Card-shaped text is scrubbed at merge and refused at apply**, because the shop's own message log
 holds live card numbers and the sweep must not be a second place they travel to.
6. **An analyst is a claim, not evidence.** Every verdict is validated against the dossier it was
 written from; every proposed change is read by a human against raw production before it is
 applied; and two of the first 33 were wrong for identifyably the same reason.

Why each of these exists rather than being "best practice": every one of them was earned by a
measured failure or a measured cost in this run, and the metrics are in the underlying lessons and
pain entries. The one line that matters if all of this is forgotten: **the record is the product, and
a change nobody can audit is worse than no change.**
