**D — The DataRoaming MDM route is deployed, and git now holds the production fleet_api.py**

Decided 2026-10-14 by me (a dev decision, not the owner's) — recorded because the same question
will come up again.

**Deployed.** `POST /fleet/devices/{drn}/data-roaming` (`{"enabled": true|false}`) and
`make_data_roaming_settings_plist()` are live on `waze-mdm-01` in `waze-mdm-fleet-api-1`, built
from commit `af005bc0` (written 2026-10-14 00:24Z, never deployed until now). Files:
`/opt/waze-mdm/fleet-api/fleet_api.py` sha256 `051f2331aafb8c7d…`,
`nanomdm_client.py` sha256 `2f1138ae9ad7c9a6…`. Backups `*.bak-20261014T225750Z`. Pre-flight was
an in-container import of the patched pair **before** the restart; then the built plist was
printed and checked to be exactly one `DataRoaming` Item. 12 tests pass
(`test_data_roaming.py`), 7 devices enqueued, 5 `Acknowledged`.

**Derived from the host, not from git — deliberately.** The host `fleet_api.py` was 263 lines
ahead of the repo (L3789), carrying the usage-ledger integration and `GET /waze/billing/usage`
that have never existed in git on any branch. Deploying the repo copy would have silently
reverted that route.

**And so the production file was captured into git** on branch
`feat/lpt-cellular-data-roaming-20261014` (commit `95597b086`, pushed). `fleet_api.py` in that
commit IS the production artefact. Rationale: a deploy-from-git that reverts a live route is the
exact hazard L3789 describes, and it only exists because production and git disagree. Capturing
production is the cheap half of fixing that; **it is not merged to master** — merging 263 lines of
never-committed work is a bigger call than this night's job, and it is recorded in P3178.
