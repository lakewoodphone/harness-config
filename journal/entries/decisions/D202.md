**D186 · 2026-09-15 · Her desktop launcher has exactly one chain, and the verb is `new`**

DECIDED and deployed, on DESKTOP-FGV6KMH (Yocheved's laptop).

THE CHAIN, one link each, no alternatives:
 desktop shortcut -> DESKTOP-FGV6KMH.open.cmd
 -> scheduled task "Yocheved DSH Window" (runs as cheve, Interactive only)
 -> DESKTOP-FGV6KMH.launch.cmd new
 -> dshw.ps1 -ConfigPath <her machines/*.windows.json> ensure + new

WHY `launch.cmd` IS THE ONLY PLACE THE MACHINE'S ENVIRONMENT OR CONFIG PATH IS DECIDED. It must set
`NODE_EXTRA_CA_CERTS` (Techloq MITM CA -- machine-scope env is not reliably inherited on this box),
`NODE_OPTIONS=--dns-result-order=ipv4first` (IPv6 is blackholed), `DSH_HOME=C:\Users\cheve\.dsh`, and
`DEEPSEEK_SEARCH_BASE_URL` (the provider's default endpoint is category-blocked and the name is
bootstrap-only, so a .env cannot carry it). Those have to be in place BEFORE PowerShell starts, which is
why the entry point is a .cmd and not a .ps1.

WHY THE SCHEDULED TASK STAYS IN THE MIDDLE. A window created by a process outside her interactive
session is created where nobody can see it. The task's Interactive logon type puts it inside her session
by construction, whatever launched it. The shortcut itself is NOT elevated (verified: no RunAsUser flag
in the .lnk), so the session-0 trap is gone too -- the task is kept for independence from who clicks.

WHY `new` AND NOT `restore`. `restore` reopens every window marked open in the registry -- on this box
that is w1 AND w2, i.e. two windows. `new` opens the first slot with zero live app windows, which is
exactly one window, which is what "open my assistant" means. `new` also refuses to leave her with no
engine: if no slot is free it starts one before reporting.

NOT DONE, deliberately: the older task `Yocheved Open Assistant` was left in place. Its payload
`DESKTOP-FGV6KMH.open.ps1` is now a one-line delegator to `launch.cmd`, so that path is correct instead
of duplicated, and deleting a task on someone else's machine buys nothing once both are correct.

CONSEQUENCE FOR FUTURE ME: any new way to start her harness must set its environment by calling
`DESKTOP-FGV6KMH.launch.cmd`, never by invoking `dshw.ps1` directly.
