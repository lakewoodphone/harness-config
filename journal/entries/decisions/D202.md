**D202 · 2026-09-15 · LPT full build: the plan, and the one question that is the owner's.**

2026-09-16, ZABZ-YOGA. Written after a five-stream audit (frontend, auth, infra, data, shipping) plus the reconciliation of two prior audits (`_lpt-audit/W3-deploy-gap.md`, `W1`).

DECIDED (engineering, mine, no owner gate):
1. **Reproducibility before promotion.** The LPT artifacts have no source: prod API is a hand-patched image with no commit, prod frontend was uploaded from a test-only commit and labelled `main`, and `main` is 102 commits BEHIND `test`. So promoting `main` ships nothing. Fix the artifacts first (recipe + sha label + honest deploy history), then promote.
2. **The `systemLog` guard is ported to source before any backend rebuild.** `origin/test` exposes `systemLog.log*` on the bare unguarded `procedure`; prod is 401 because of a hand patch. Measured: prod 401, test 400 for the same anonymous call. A naive rebuild publishes an anonymous write endpoint.
3. **The customer portal launch is the owner's call, and it is the ONLY thing on this build that is.** Everything else — the Google redirect fix, the questionnaire migration, the catalogue seed, the deploy scripts, the watchers, the promotion PR — is engineering.
4. **Fleet isolation:** seven worktrees cut from `89e5ff81d` (`origin/test`); the manager alone touches the main checkout, because the production frontend is built from that working tree and a sibling operator is active in it.

CORRECTION RECORDED: the master index says *prod DB untouched*. False. `20260909000000_add_google_identity` is applied on the container Postgres since 2026-09-10 18:49:31Z. Two audits disagreed because they read two different stores; F1 settles which store the running container uses. Until then, every data claim is provisional.
