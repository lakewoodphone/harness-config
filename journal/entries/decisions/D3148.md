## What is staged, and inert

`/opt/phoenix-pin-rotation/rotate.py` on `secratary-cloud`, with
`/etc/systemd/system/phoenix-pin-rotation.service` and `.timer`. `systemctl is-enabled` =
**disabled**, `is-active` = **inactive**. Nothing runs it.

It rotates exactly two credentials - owner admin and parent - and sends exactly one SMS with the
parents' new code to +17326745878 **in the same run**. If Twilio does not return ok + SID it
restores both old codes and exits non-zero; a rotation that was not delivered is rolled back, never
left in place. The admin code is not texted; it goes to
`/root/.phoenix-pin-rotation/admin-pin.txt` (0600) and an HA persistent notification. Verified with
`--dry-run` (read both helpers, generated, wrote nothing, sent nothing) and by POSTing an empty
body to `/sms/send` -> 422 (route reachable, no message).

**The one action that activates rotation:**

 systemctl enable --now phoenix-pin-rotation.timer

That single command rotates both codes, sends the one SMS and leaves the 14-day timer enabled (the
timer fires the service 45 s after start; the script refuses to rotate again until 14 days have
passed since the last success).
