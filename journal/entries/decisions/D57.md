**D57 · 2026-09-14 · Owner questions live only in owner_decision_queue; QUESTIONS.md is retired.**

*Decided:* owner questions live in `owner_decision_queue` on the authority and **nowhere else**.
`journal/QUESTIONS.md` is retired; `journal/state/owner-questions.md` is a generated mirror that says so on
its face.

*Why:* the same question lived in two stores with no declared authority. The file accumulated 22 rows in three
tables with a bulleted list spliced through the middle, rows out of date order, and answered rows that were
never removed; the table had 3 pending. A session reading the file believed one thing, a session reading the
database believed another, and neither could tell which was stale.

*What was done:* five live owner-only rows were promoted into the queue (#12 email reply loop, #13 Yocheved's
write access, #14 iPhone location permission, #15 Google Voice, plus #11 the delivery channel); sixteen were
closed as answered, superseded, retracted, or as mine to decide (**L7**), each with its disposition in
`archive/README.md`. #11 was answered within the hour — the owner picked the harness badge — and is marked
answered, because the one thing this file must never do is ask him something he already answered.

*Also decided:* `scripts/owner-queue.py` is tracked in `harness-config` instead of existing only on
`secratary` (**P47**), gained `--json`, and the preset now tells a session how to read the queue from a
machine that does not host the database (`ssh secratary-ts ...`) instead of naming a path that exists on one
machine of four.
