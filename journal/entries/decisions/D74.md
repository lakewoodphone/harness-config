**D74 · 2026-09-14 · Consent is enforced at every door, and I only found the other three by going to look.**

Building the consent gate at the upload path (`D37-15`) made the parent notice's promise — *"nothing is sent while your permission is withdrawn"* — look true, and it was not. Asking the code rather than believing the sentence turned up **three more egress doors**: `POST /classify/gemini`, `POST /classify/clip`, the false-positive challenge at `/self/audit/screenshot_reviews/{id}/declare_clean`, and the nightly batch that re-classifies stored rows per phone. All four send stored frames to a provider, and all four ignored consent. One shared helper now gates them; the classify routes refuse with 403 rather than silently filtering, because a caller handed results for some images and not others would not know why, and the batch skips the phone and names the reason in its summary rather than reporting a bare zero.
*Rule:* a promise about a *class* of behaviour ("we never send without consent") is a claim about every code path that performs it, not about the one that was easiest to guard. Enumerate the paths by grepping for the egress call, not by recalling where they are — four tests then had to be corrected to record consent first, which is itself the evidence that the gate bites.
