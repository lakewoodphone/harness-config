**D · Mesh children stay invisible to the Subagents UI, and the remedy is two core changes — not a plugin patch**

Decided 2026-09-18 (ZABZ-YOGA) after pinning the mechanism to two exact lines. Recorded because this is
the most-repeated complaint in this seat's history and it must stop being re-investigated from scratch.

THE CAUSE, EXACTLY:
- `@deepseek-ai/dsh-subagent/lib/types/index.js:437-441` appends the parent's child-catalogue entry only
 when the provider's run exposes a local session: `const child = run.localAgent?.session; if (child
 !== undefined) establishCatalogChild(...)`.
- `harness-config/packages/plugin-remote-fanout/lib/provider.js:639` returns `localAgent: undefined`.
It must: the child is a turn on another machine. So the catalogue is never written, the projection the
UI reads is legitimately empty, and the UI is not lying. Measured with three live children:
`subagentCatalog: {"inheritedEventCount":0}`, `subagent: {}`.

IT IS DELIBERATE, NOT A BUG: `plugin-remote-fanout/README.md:56-59` states that `prepareContinuable` is
deliberately absent and that remote children are one-shot by design, and two tests pin both facts
(`run.localAgent === undefined`, `provider.prepareContinuable === undefined`).

DECISION 1 — do NOT append a synthetic catalogue entry from the provider. It would light the chip and
leave a switcher pointing at a session that does not exist; a row that lies is worse than truthful
silence.
DECISION 2 — do NOT claim a cheap plugin-side fix for the job label either. It was proposed and then
falsified: `dsh-jobs` has no relabel/update (the label is set at `start()` and only *validated*
afterwards, `dsh-jobs/lib/invariant.js:19`), and the label is chosen BEFORE the broker names a node
(`dsh-tool-subagent/lib/index.js:540` passes the model's own `description`).
DECISION 3 — record the two real remedies, both core changes, cheapest first: (a) let `dsh-jobs` relabel
a job once at placement, so the collapse row reads `Mesh latency matrix → zabz-tech`; (b) add an
optional provider capability that publishes a remote child identity, so `dsh-subagent` writes a
catalogue fact and the UI renders it non-navigable. The UI already models that: `readonly.oneShot.title`
/ `readonly.oneShot.body` in `dsh-client-ui-subagent`.
DECISION 4 — P270 ("a page keeps a stale job list after an engine restart") is DOWNGRADED from a finding
to an unconfirmed hypothesis. The observation was real (a chip reading "1 background job" while three
children ran); the explanation written beside it was a guess, and the client actually DOES reset on a
new baseline (`replaceControlBaseline` clears and repopulates `jobsBySession`,
`dsh-api-session-controller/lib/client.js:2685-2689`). It stays open, marked unconfirmed, rather than
reading as evidence.

WHAT IS HONEST TODAY, AND IT IS ENOUGH TO WORK WITH: the background-JOB surface. With
`enableRunInBackground: true` a mesh child is a real job the moment it starts, and its OUTPUT already
carries `MESH-HOST: <node>`, the `placement = broker → node "…"` line with its lease, the pressure
block, and the `location check` that proves the named node is the node that answered. Expanding the job
shows exactly where the work went.

Full write-up: `docs/mesh/110-subagent-visibility.md`.
