**D3035 · 2026-10-12 · app_voice: resolve the API unit by ExecStart, never by a literal.**

The sentinel moved to the authority (secratary-cloud) on 2026-10-12 and app_voice kept asking systemd for secretary-api, the office unit name, so it reported unknown forever on a host where the API is company-api. Fixed in ck/sentinel.py: check_app_voice now resolves the unit by asking systemd which service ExecStart runs app.main:app (the one host-independent fact about the app), with SECRETARY_API_UNIT / CEO_KERNEL_API_UNIT as an explicit override. No host-name literal and no host-specific path is read; the host name is used only for provenance. Proven by the kernel own reading: before was unknown secretary-api is inactive; after is info the application is audible, 103 of 750 journal lines, newest 03:30:27, unit company-api.service, unit_source systemd ExecStart. Kernel exit 2 to 1.
