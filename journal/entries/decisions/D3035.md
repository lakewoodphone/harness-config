# -NoVideo is now an opt-in profile; on 616468703 the owner kept the gallery, so video stays playable

**Owner decision, 2026-10-08, asked as one question with the cost stated:** presented with "blocking video on a
live E4610 also removes on-phone photo viewing (the gallery shares the package with the video player), camera
still captures" versus keeping the gallery, he chose **keep the gallery, video stays playable**. Nothing was
applied to that unit.

The decision is the same one recorded on 2026-07-16 for E4810. The cost is unchanged and is now written into
the flag's own help text, so nobody has to rediscover it: `jp.kyocera.player.movieview.MovieView` lives inside
`jp.kyocera.datafolder` (gallery + image viewer + file manager), and `com.kyocera.musicplayer` carries the other
video handlers; no root means whole-package disable only.

**What now exists** (commit `86ec4ad0`, pushed): profiles `standard-lite-no-video`, `standard-no-video`,
`filter-only-no-video` (pure YAML additions, every existing profile resolves byte-identically), a `-NoVideo`
flag on `quick-deploy` / `finalize-deploy` / `filter-only` and the E4610/E4810 wrappers with `-Profile`
pass-through, and `forced_disabled_packages` recorded in the deployment receipt so a package-level block is
visible. Verified myself: YAML diffs insert-only, loader resolution for all three profiles plus the unchanged
no-media/no-text profiles, all changed PowerShell parses (working tree and staged blobs), and the three guard
rails fire with messages that name the missing profile.

**Deliberately left undone, and it matters:** `release_gates.py` `MEDIA_PACKAGES` still treats any profile that
disables `com.kyocera.musicplayer` as a *no-media* plan and `_is_base_standard_plan` then refuses it
(`ValueError: Standard plan must not disable stock media package(s)`), and `intent.py` has no `no_video`
concept at all. So the plan/bundle/release-check pipeline cannot select these profiles; only the wrapper and
`lpt ... --profile` path can. The honest fix is a real `no_video` attestation gate (`--no-video-verified`)
plus intent-parser support — not a patch that lets the plan through while demanding a no-media attestation.
Latent today, not live.

**Still open product question:** a customer who wants *both* no video and a working photo gallery needs the
modified DataFolder APK baked into firmware before flashing (`temp/DataFolder-novideo-signed.apk`, built
2026-07-16). That is a flashing-pipeline project, not a deploy flag — the only route that was ever priced.

Evidence: this conversation (owner's answer), commit `86ec4ad0`, the dry-run receipt
`cli/logs/deployments/deployment-receipt-616468703-20261008-211516.yaml` (`profile: standard-lite-no-video`,
forced list = sidsefard/qr/quickjack/musicplayer/datafolder), loader output for all six profile combos.
