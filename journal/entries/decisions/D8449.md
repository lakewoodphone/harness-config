## 2026-10-20T00:18Z · ZABZ-YOGA · a third same-weights pipe, and the difference between a saving and a fallback

Together serves `deepseek-ai/DeepSeek-V4.1-Flash-1017` - the **exact** build DeepSeek serves directly - at
**0.30 / 1.20 flat**. Priced from its own models endpoint at 00:12Z and added to `prices.json` and to the
equivalence group, which now declares three pipes for one set of weights.

### It is a fallback, not an economy, and the number says so

- at DeepSeek **peak** (0.30/1.20) Together is **exactly equal** - a 0 % delta, below any threshold, so the
 yield will keep DeepSeek direct;
- at DeepSeek **off-peak** (0.15/0.60) Together is **twice as expensive** on input.

So it can never win on price, and it should not. Its value is **resilience**: a same-weights lane with a live
key that can serve the identical build when the direct provider's circuit is open. That is a different product
from a saving, and conflating the two would have me reporting a cost win that does not exist.

**The general rule: a pipe can be worth wiring for availability without being worth preferring for price.**
The equivalence group now carries both, and the delta threshold is what keeps them straight - Together is
refused on cost and available on failure, from the same declaration.

### Honest gap in the data

The models endpoint publishes input and output but **no cached-input rate**. `cached_in` is therefore omitted
and defaults to the input rate, which **overstates** cache cost rather than understating it. Given the measured
0.8 % cache hit rate this is immaterial, and it is the right direction to be wrong in.

102 tests green. Deploy deferred until after 04:00Z, with the router change, because a restart 40 minutes
before the first peak observation buys nothing tonight.
