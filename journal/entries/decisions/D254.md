**D254 · 2026-09-17 · Repair the junction from inside ssh; refuse the restart; leave 106 uncommitted.**

Three decisions, each with the measurement that forced it.

**1. The junction was repaired from INSIDE an ssh session, not from a local Interactive-logon task.**
The brief specified a local task and warned that a remote-login token is "the class of token that
fails". Measurement says the reverse: a junction created by a local task gets owner
`zabz-tech\ezabz` and is refused to every remote process (`exit 1`, untrusted mount point), while one
created from the ssh session gets owner `BUILTIN\Administrators` and traverses for both classes
(9/9 correlation across the nine junctions in that directory, plus a two-junction control). So the
repair was done the way the measurement and `mesh-run.mjs:229` both say, and the brief's stated
method is recorded as corrected in `docs/mesh/106` §3. The scope was widened from one junction to
three (adding `dsh-plugin-session-link` and `dsh-mesh-broker`) because session-link is ALSO named in
that profile's `dsh.profile.bundles`, so fixing only the provider link would have left the same wall
one bundle later.

**2. The live engine on `zabz-tech` was NOT restarted, and `docs/mesh/106` §5 records the refusal.**
The gate was closed at both readings: `established_on_3099` 10 at 11:31:36 and 8 at 11:40:14; 4 then
2 `dsh-subprocess-local` runners parented by that engine (pid 24556), i.e. a sibling stream executing
tool calls through it in both windows. The brief's rule governs and the refusal is the correct
outcome. The placement proof was therefore obtained WITHOUT a restart, by booting a second engine on
the same machine on port 3097 (its own process, killed by the session that started it), which leaves
3099 and pid 24556 untouched — the shape `docs/mesh/105` §6.1 had already used on that machine.

**3. `docs/mesh/106-desktop-last-mile.md` is left UNCOMMITTED in the checkout.**
`C:\Users\ezabz\code\harness-config` is at `e0d07cac` while `origin/master` is `a85232c`, and its
working tree carries ~40 paths belonging to other streams. A commit of a new document on top of
`e0d07cac` would diverge rather than fast-forward, and a `fetch`+`merge` in that tree is not this
session's to take. The file is complete on disk; integration is one line for whoever owns that tree.
