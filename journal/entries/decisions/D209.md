**D209 · 2026-09-16 · list_agents replacement: global registration + a platform-gated preset row, not a preset row that names the package.**

DECISION: the replacement `list_agents` is registered GLOBALLY from the host-plane plugin, and the shipped preset row is gated off on Windows — rather than a preset row naming `dsh-plugin-health`.

Why not a preset row: a scoped tool shadows a global one, so a preset row is the natural place; but a preset row that names a package means an uninstalled package breaks the PRESET mount, and therefore session creation, on a machine where the sync's installer has not run. The failure mode of the global row is "the engine cannot boot" — loud, immediate, and already the subject of a keeper script. Prefer the loud failure.

Why the gate rather than a deletion: `scripts/sync.py` runs `install-client-plugins.ps1`, which is Windows-only, so on Linux/macOS the replacement does not exist and the shipped tool must stay. `disabled: !!js process.platform === 'win32'` is the same idiom the MCP rows in that file already use.

Cost accepted, and named: on Windows the tool now exists only where the package is installed and the engine has been restarted. That is one restart per machine, once.

The alternative that was rejected outright: editing DSH's installed `list-agent.js` to add `timeoutMs`. An npm update erases it and no other machine sees it.
