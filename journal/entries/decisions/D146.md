## The person layer: people are built from evidence, and every alias says why

**Decided 2026-09-14.** The comms index gains a `people` tables pair (`people`,
`person_alias`) rebuilt on every refresh, plus four read modes that use it.

**Shape.** An identifier graph union-find over `phone:` / `email:` / `name:` nodes, seeded
from the two address books (`contacts` 623 rows, `dialpad_ui_contact_row` 406 contacts) and
then from what the corpus itself shows. A name merges phones only if it is person-like and
sits on ≤3 numbers (**L1467** has the 37-number counter-example). `comms-search person`
resolves a name/number/email to an identity and returns everything; `thread` is now
identity-aware and says which person and which identifiers it used; `waiting` answers "who
is waiting on us"; `health` reports the index's own completeness.

**Why not fuzzy matching.** A wrong merge is worse than a missing one here: it puts a
stranger's conversation into a customer's record and an agent will believe it. So the rule
is conservative, every alias stores its `reason` and its `source`, and 49% attribution is
the honest result rather than a target to inflate.

**Email is in the index, drafts are out.** 2,846 email records (Gmail triage sender+subject,
plus the 3 messages actually sent). Bodies are not stored locally, so results say
`mail-subject-only` — an agent must not read a subject line as the whole message. Pending
drafts are excluded: a draft is not a communication, and indexing one lets an agent answer
"we told them X" from a message nobody ever sent.

**Registered, not just present.** `comms_search` is entry 518 in `data/tool_registry.json`,
so it appears in the summary that goes into every agent's context and not only to agents
told about it by hand (**L1468**).

**What is deliberately not done yet.** No "waiting" line has been added to the owner's
attention digest — that surface has a documented alert-fatigue history (P40), so a bounded
one-line addition needs its own small change and its own verification rather than riding
along with this one.
