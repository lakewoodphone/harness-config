**D161 · 2026-09-15 · Dictation on the Mac mini is Windows parity: Command+H toggles it, no hold, no Enter, stays local.**

Dictation on LAKEWOOECHSMINI is set to Windows parity, which is the requirement the owner actually stated.

His words (2026-09-15): "i need it to start when i push windows h, and i don't need to hold it down, and it
automatically puts the text in whatever text box" / "basically shes used to windows talk to text, it should
perfect mimic that". That overrides the earlier push-to-talk design, and it is the shape to defend:

 * TOGGLE, not press-and-hold: `push_to_talk: false`. Press Command+H, speak, press it again.
 * The binding is `command+h` -- the key in the WINDOWS-KEY position on her Lenovo PC keyboard. Not Ctrl+H,
 not Option+Space: muscle memory is the feature.
 * `auto_submit: false`. Windows voice typing inserts text and stops; it does not press Enter. It was found
 switched ON during setup and turned back OFF, because an auto-Enter in a customer chat or an SMS box
 sends a half-finished message. This is a safety default, not a preference.
 * Text goes to the focused field (`paste_method: ctrl_v`, `clipboard_handling: dont_modify`).
 * Still entirely local: no cloud post-processing, no account, no subscription.

ACCEPTED TRADE-OFF, recorded so it is not re-litigated: while Handy runs, macOS's own Cmd+H ("Hide") no
longer fires, because Handy consumes the keystroke. That is what buying the Windows habit costs.

EVIDENCE: settings_store.json on LAKEWOOECHSMINI; Handy log "Loaded settings: ... push_to_talk: false ...
current_binding: "command+h" ... auto_submit: false ... paste_method: CtrlV"; the one-page guide on her
Desktop and lpt-hub/docs/setup/TALK_TO_TEXT_MAC_MINI_2026-09-15.md.
