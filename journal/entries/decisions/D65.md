**D65 · 2026-09-14 · The shipped defaults are the legal posture, so they are pinned by a test.**

D37-01's position — the baseline product sends no image of a person off the device, and the cloud tier requires the parent's separate consent — is only as strong as the configuration defaults. A default is exactly the thing a later change can flip unnoticed: an operator setting, a "let's turn it on to test", and the product is disclosing children's images with no consent on file. So `tests/test_compliance_defaults.py` reads the **declared defaults** off the settings model (not the live object, which tests mutate) and fails if accountability, the provider chain, image retention, the egress scrub, the fail-closed gate or the review record's lifetime moves. A deliberate change is still allowed — it has to be made in a diff with the reasoning in front of whoever makes it.
*Also recorded here because it is the same idea in another form:* the two codebase guards that fired on this round's changes (the storage SQL surface digest and the route-security audit) are the reason a new SQL statement and a new mutating route could not slip in silently. Both were answered deliberately, and the digest history comment now records why each move happened.
