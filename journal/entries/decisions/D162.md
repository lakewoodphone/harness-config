**D162 · 2026-09-15 · The evidence archive was world-readable, half of it was 640x480, and clips were never purged.**

**D (2026-09-15) - The security evidence system: the first pass rebuilt the viewer and missed that the archive was world-readable, half of it was 640x480, and clips were never purged.**

Owner: *"you did not work long and hard enough, you didn't think enough or research enough, get to
work."* Correct. The v3 pass (D160) fixed presentation and stopped. Three worse problems were
sitting underneath it.

**1. The archive was readable with no password.** Home Assistant serves `/config/www` at `/local/`
**unauthenticated, by design**, while `/api/states` returns 401. Measured with no token: a 1.82 MB
clip of customers at the door, the whole 927 KB event index, every still. **27 days of footage
browsable by anyone on the shop LAN — which customers use.**

Fixed by moving the archive to `/media/phoenix` (outside the web root) and serving it **only** through
HA `media_source`, which mints a **per-path signature**: a signed URL fetches with no token (200) and
**401s without it**. The page holds no data and no links; it asks HA to sign each path as it renders,
over the same WebSocket the HA frontend uses, with the session already in the browser.
Public files under `/config/www`: **~3,000 → 64** (the shell plus 34 transient notification tiles that
*must* stay fetchable without a session). `/local/snapshots/history/…` → 404.

**2. Half the evidence was 640×480, including every front-door still.** Sampled 1,500 stills by
reading their JPEG headers: **all 1,451 doorbell stills were 640×480**, while every NVR channel gave
2560×1440. Cause found in the entity registry, not the camera: the Reolink integration ships the
**main** stream entity with `disabled_by=integration` and capture was using `…_0_sub`. Enabling it and
pointing capture at it: **640×480/47 KB → 2560×1920/634 KB — 16× the pixels**, verified through the
real capture path, not a test harness.

**3. Video existed for 5.6% of events, and a break-in would produce none.** 164 clips across 2,944
events, from two triggers only. `phoenix_capture_clip_waiting_room` is wired to **NVR channel 4,
which has no camera**, so it burned a 60-second timeout on every doorbell event and produced nothing.
The intrusion response records stills and no video at all.

**Also found and fixed:** `purge_old_snapshots` deleted only `.jpg`/`.jpeg`, so **clips were never
purged** — 188 MB growing without bound. Retention now covers `.mp4`.

**And a trap in my own work, caught by auditing myself:** the backups I made *during* this migration —
including a `.backup` directory holding the old 927 KB index — were sitting **inside the web root and
were therefore public**. A migration that leaks its own backups is not finished. Moved to
`/config/backups-webroot/`; `find /config/www -name '*.bak*'` is now empty.

**Two implementation traps worth keeping:**
- **HA caches `/local/` for 31 days** (`max-age=2678400`). Editing the viewer in place is invisible,
 and the owner's dashboard would have shown the old page — pointing at media that had moved — for a
 month. The shell is now **content-hashed** with `index.html` as a tiny loader, recent shells
 retained because the cached loader may still point at an older hash, and the dashboard iframe
 versioned to escape the entry already cached.
- **`media_source` only serves recognised media types.** A `.json` index cannot be fetched from it
 (browse omits it; the signed URL 404s). Rather than rename it to fake an extension, the viewer now
 builds the timeline from HA's **authenticated directory listing** (`browse_media`, 2,874 + 166
 entries in 1.8 s) — which also removes a whole class of bug, because a listing cannot go stale the
 way a derived index can.

**Verification:** `scripts/timeline-check.py`, **23/23**, driving a private headless Chrome over
DevTools: signed URLs, own-aspect rendering, poster/duration/caption on clips, every filter, the
lightbox, the 4 coverage-gap days, and both the public index and the public history directory
returning **404**.

**Still outstanding, and named rather than implied:** no off-host backup of 624 MB of footage on a
**73%-full SD card**; clip capture for the intrusion response; the dead channel-4 command; and an
alarm for evidence *flow* — the health surface watches entity state and would not notice capture
stopping, which is the P17 failure applied to the evidence pipeline itself.
