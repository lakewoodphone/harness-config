**D59 · 2026-09-14 · The phone layer is delivered twice, and a phone mounts the same client plugin set as a desktop.**

**Decided 2026-09-14 by Zabz** (development decisions are mine; nothing here needed the owner).

**1. The phone layer has two deliveries, and both are load-bearing.** The gate injects
`assets/mobile.css` into every document it serves, **and** serves the same bytes at
`/dsh-phone-mobile.css`, which `dsh-plugin-mobile` links at boot and re-asserts if the app
rewrites `<head>`. The gate additionally sends `Cache-Control: no-store` on documents.

*Why both:* a single delivery by document rewrite is defeated by a client cache — measured
(L188) — and the failure is invisible from the server. Either delivery alone has a failure mode
the other covers: the injection survives a client with no JS, the link survives a cached
document and a head rewrite.

**2. A phone engine mounts the same client plugin set as a desktop**, not a reduced one. The two
exceptions are platform facts, not policy: `plugin-windows` is absent on the phone host and
renders nothing below 768px anyway, and `plugin-mobile` is present everywhere because its
stylesheet link is media-scoped and its drawer rule is a no-op above the breakpoint.

**3. The breakpoint is 768px, everywhere.** `mobile.css`, `plugin-mobile` and `plugin-windows` all
read the same number, and `plugin-windows` reads it per render so a resize does the right thing
without a reload.

**What would reverse this:** a harness that ships a first-class mobile layout would make the
injected layer redundant; a phone that could hold two windows would make the `plugin-windows`
guard wrong. Neither is true today, and both are checked by the probe (13, 14) and by the two
smoke tests rather than by memory.
