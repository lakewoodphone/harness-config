**D7234 · 2026-10-18 · Android install: no wipe for the filter; device owner is an attempt, and a factory reset is the customer's decision.**

Owner, 2026-10-18: "are you sure you have to fully wipe the phone? customers really won't like that" and
"figure out a way to do it without erasing the phone".

MEASURED: no, a wipe is not required for the FILTER. It is required for DEVICE OWNER, because Android
refuses dpm set-device-owner on a phone that has accounts (this repo own script records the refusal:
real_device_provision.ps1 "set-device-owner was rejected because the device already has accounts").
Device owner is what makes the app uninstallable and lets us install a CA and push managed Chrome
policy. Everything else - accessibility, notification listener, usage access, battery exemption,
always-on VPN with lockdown - can be granted over adb with no wipe and no device owner, because adb
shell holds WRITE_SECURE_SETTINGS.

DECISION: the counter flow is INSTALL FIRST and two classes.
 Standard (default): adb install -r (never -w), the four grants via the shared helper,
 always_on_vpn_app + always_on_vpn_lockdown pinned and read back, ws_url + per-phone token, heartbeat
 started, every step checked. Nothing is erased, nothing is uninstalled.
 Sealed (-Mode Sealed): the same, THEN an attempt at device owner. If Android refuses, the phone is
 still filtering and the script says so; a factory reset is the CUSTOMER decision, never a step the
 script takes. Non-destructive workaround named in the refusal: remove every account, retry.
BUILT: scripts/counter_install.ps1 (pushed on agent/kf-counter-install-nonwipe, 65b2d00 + test fix),
documented as the first section of docs/ANDROID_PROVISIONING_GUIDE.md, and guarded by
server/tests/test_counter_install_script.py - 11 tests, all green on zabz-tech, which read the script
to prove there is no pm clear, no pm uninstall, no -w, no remove-active-admin anywhere in it.
TWO DEFECTS FOUND BY RUNNING IT, not by reading it: (1) Windows PowerShell 5.1 turns adb stderr into a
terminating error under ErrorActionPreference=Stop, so the very first "daemon not running" line killed
the install; (2) capturing adb through a pipe HANGS when the call starts the daemon, because the daemon
inherits the pipe write handle - the capture now uses Start-Process with file redirection and a timeout.

OPEN, next on this queue: the MITM CA is not configured on the broker (ChromeMitmConfig defaults to
enabled=false with empty ca_cert_pem, and nothing mitm-shaped is set in the live container), so the
proxy cover - the strongest layer, D35-05 - is still off; and the counter script still takes the token
as a parameter rather than minting it, which is one manual step left.
