# Owner delegated the spend number: 4 releases/day, 1 per project — decided and implemented

2026-09-20, ZABZ-YOGA. The owner was asked one question, in plain language, with a recommendation:
how many autonomous wake-ups per day. He answered *"wahtever you think, and you can change it over
time if neede"*. That is a delegation, not an answer, so the number is mine and it is now implemented
rather than sitting in a queue.

## The policy

**4 autonomous releases per day in total, at most 1 per project per day.** The three projects he named
(kosher-ai-filter, waste-system, lpt-website) get one slot each; the fourth is deliberately left for
the fault-detecting sources — `txt-lost-webhook`, `dormant-handoff`, `decision-answer-unconsumed`. A
cap that starves the detectors that catch customer-harming faults is a bad cap, and the cheapest way
to discover that is to have said it before setting the number.

**Why a count and not a dollar figure.** A release has no measured price. `wake.py` carries
`WAKE_MAX_USD_PER_DAY=3.0` and it is **inert** — `cost_usd` is never written — so a dollar ceiling
tonight would be a number with nothing behind it. The count is the only governor that is honest until
`wake-cost.py` resolves a release to the session it started and prices its tokens. That work is in
flight, and when it lands the count is replaced by a measured dollar ceiling and the number is brought
back to the owner.
