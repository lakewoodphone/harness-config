**D213 · 2026-09-16 · Tunnel only rattlebyte.com through the office server via a localhost PAC (not a Tailscale exit node, not a hosts entry).**

**Decision (mine - dev/ops, not the owner's): fix the unreachable rattlebyte.com by tunnelling only that domain through the office server over SSH SOCKS, exposed to Windows through a localhost PAC file.**

Why not the alternatives:

- **Tailscale exit node on secratary** - routes the *whole machine* through the office for one website, and advertising an exit node needs admin-console approval (an owner step). Rejected as disproportionate.
- **hosts entry + `ssh -L 127.0.0.1:443:185.112.145.212:443`** - cleanest theory (no browser config at all) but the hosts file needs Administrator, this account is **not** admin, and Chrome's Secure DNS can bypass the hosts file. Rejected as unavailable and fragile.
- **Just use the office desktop / phone** - works, kept as the fallback, but the owner works from the laptop at night.

Blast radius is one domain: the PAC returns DIRECT for everything except rattlebyte.com. If the tunnel or PAC server is down, rattlebyte.com fails exactly as it does today and nothing else changes.

Also decided: **do not** report this as an owner problem or park it in the owner queue. It is an external routing fault (T-Mobile <-> 1984 Hosting upstream) that we route around; there is nothing for him to decide.
