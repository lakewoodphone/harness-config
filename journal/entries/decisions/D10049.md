**D10049 · 2026-10-25 · eBay credentials: ~/.secrets/ebay-personal.env per node, env-first resolution, and the authority client is a sha256-identified deployed copy.**

**D — eBay credentials live at `~/.secrets/ebay-personal.env` (0600), resolved env → `$EBAY_SECRETS_FILE` → that path; the authority's `/opt/company/data/tools/ebay_api.py` is a deployed copy of the `lpt-hub` source and is identified by sha256.**

**Decided 2026-10-23**, on the owner's instruction *"if yes update the whole mesh with it clearly"*
after he created an eBay Production keyset.

**1. One canonical store per node, in the estate's existing convention.** `~/.secrets/` at 700 with
the file at 600 is the pattern the estate already uses and already documents
(`docs/mesh/136-ESTATE-INVENTORY.md` §3), so this adds a file rather than inventing a store. On
Windows the equivalent restriction is an `icacls /inheritance:r` grant to the owning account.

**Installed and fingerprint-verified 2026-10-23** — pair fingerprint `a47e8d3196e8` (sha256[:12])
identical on all four: ZABZ-YOGA, ZABZ-TECH, `zabz-tech-linux`, and
`secratary-cloud:/root/.secrets/ebay-personal.env` (root:root 600).

**2. Resolution order is env → `$EBAY_SECRETS_FILE` → `~/.secrets/ebay-personal.env`.** Env first so
a CI job or a one-off run can override without touching a file; the file last so a plain
`python ebay_api.py doctor` works with nothing exported. This mirrors `D2907` — capability is never
reduced for safety, the exposure is what shrinks: one canonical file per node instead of credentials
inline in commands, in scripts, or in a tool's source.

**3. The module never prints a value.** Only lengths, dash-group shapes and a `sha256[:12]` pair
fingerprint — the same standard as `scripts/verify-secret-move.py`. `D2906 D3` says a credential an
agent can read has already reached a model provider, so the code is written to make the readable
form useless for authentication while still being enough to answer "did the right material land on
all four nodes".

**4. The authority copy is a DEPLOYED ARTEFACT, not a second source.** `data/tools/` is gitignored
(`000-SYSTEMS-REGISTER.md` trap 1 — 599 of 607 tool bodies were lost at the cutover), so the
authority cannot carry this file from any branch. Therefore: source of truth is
`lpt-hub/scripts/sourcing/ebay_api.py`; the deployed copy is identified by
**sha256 `a068cc819a591746cdeae0d9f67640c6e84f792047ff0a6db99cb078f1b4c1db`** recorded in the module
docstring, in `ebay_browse_search.py`, and in `docs/mesh/150`. A future session that finds a mismatch
**re-deploys from `lpt-hub`** and never edits the box copy.

**5. The key rotation path is the owner's, and it is one file.** Rotating means writing the new
values to the four `~/.secrets/ebay-personal.env` files; nothing in code changes, because no code
contains a credential and no code contains a model or endpoint literal that would need updating.

**Open at the time of writing:** eBay answers `401 invalid_client` for this pair. That is a defect in
the credential material or its activation, not in this decision; `doctor` names what it can prove and
refuses to guess the rest.
