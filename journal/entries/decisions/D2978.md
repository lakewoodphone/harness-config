**D2978 · 2026-10-08 · One deploy path on a self-hosted runner; 19 workflows deleted; credentials host-local.**

Decided and implemented 2026-10-09, session W17:
1. GitHub stays the git remote and PR surface; the WORK moves to a self-hosted runner on secratary
 (labels self-hosted, Linux, X64, lpt-deploy). Reason: the deploy target is on the office LAN and
 the credentials then never leave the owner's machines. Cost was never the reason.
2. ONE deploy path: deploy-env.yml. Deleted deploy-staging.yml (dead Heroku, self-declared
 non-functional), deploy-production.yml (5/5 GREEN while shipping to a Heroku app that 404s) and
 deploy-prod-blue-green.yml (dead Heroku, and no Stripe mode assertion at all).
3. No GitHub secret is read by any surviving workflow. Credentials live in /etc/lpt-deploy/env (600,
 ghrunner) and ~ghrunner/.ssh. Per-target Stripe secret keys, because the guard compares modes.
4. 19 of 25 workflows deleted on run-history evidence; 2 fixed. Surviving: deploy-env,
 pr-precheck, phantom-dependency-check, validate-main-pr-source, validate-backend-image,
 maintenance. Rationale per file in docs/ci-cd/WORKFLOW-FATE.md.
5. `pnpm bootstrap` (scripts/ci/bootstrap.mjs) is the one command a fresh machine runs: install,
 shared-types, prisma generate, tsc -b, tsc --noEmit, build, then assert the artifacts exist.
 Wrote it because four separate things made a fresh clone unbuildable and none were documented.
 NOTE: another session landed `pnpm worktree:setup` + scripts/build-tools/build-frontend.mjs in the
 same window; the two overlap and should be consolidated into one entry point.
