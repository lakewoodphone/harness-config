**D8322 · 2026-10-19 · Update delivery targets the live install root; DSH models are current but the company gateway silently downgrades; DeepSeek search adopted as a first-class surface.**

THREE DECISIONS FROM THE 2026-10-19 SESSION, each with the evidence that decided it.

1. DSH UPDATES ARE DELIVERED INTO THE LIVE INSTALL ROOT, AND THE VENDOR PREFIX IS STAGING ONLY.
 Evidence: three independent things use ~/.dsh/engine (dshw.ps1:309, plugin-remote-fanout/nodes.js:84,98, both
 running engines); promote was writing dshInstall to dsh-update/vendor/prefix/<ver>. Implemented as
 lib/live-root.mjs + tools/install-engine.mjs; promote and the switch now resolve the same root. Reversible:
 the previous tree is kept beside the new one and `dsh-update rollback` restores the pin.

2. THE DEEPSEEK MODELS WE RUN ARE CURRENT; THE COMPANY GATEWAY IS NOT.
 DSH calls api.deepseek.com directly with model `deepseek-flash`, which is DeepSeek-V4.1-Flash-1017 (released
 2026-10-17) — so the harness is on the newest model and must NOT be "fixed" to a retired id.
 The company gateway is the defect: `POST /v1/chat/completions {model:"deepseek-flash"}` returns HTTP 200 served
 by `deepseek/deepseek-v4-pro` — an older, 4.4x-input-price model — because the id is not in `_CAPABILITY_DB`.
 NOT APPLIED: the remediation (add the id, make an unlisted id return 400 model_not_found, move literals to route
 aliases, stop advertising secretary-genius) is written in docs/model-currency-2026-10-19.md and needs a
 company-api deploy. Deliberately not bundled with an engine upgrade in the same night.

3. DEEPSEEK'S SEARCH API IS ADOPTED AS A FIRST-CLASS SURFACE, NOT AS A REPLACEMENT.
 Verified with our existing key: `POST /v1/tools/search {"query","count"}` -> 200 in 0.63 s with title/url/date/
 authority/rerank_score/summary; `POST /v1/tools/fetch {"url"}` -> 200 in 0.34 s with page markdown. `count`
 controls result volume (2->2, 5->5). Billable only on 200-with-results; free through DSH until 2026-11-01 00:00
 Beijing, then 0.75 USD per 1,000 requests.
 Adopted: scripts/ds-search.mjs (+ docs/ds-search.md) for live web search and single-page reads.
 NOT adopted: replacing jina or firecrawl (their coverage is measured here, DeepSeek's index is not), and not
 our own corpora, which remain esearch/ps_search.
 The reason this matters: dsh-base's `web-search-deepseek` row spends a full auxiliary model turn per search
 because its own README says DeepSeek has no dedicated search endpoint. The vendor's 2026-10-17 changelog says
 otherwise.
