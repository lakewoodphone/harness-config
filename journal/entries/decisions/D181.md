**D181 · 2026-09-15 · chumash-timeline API response contract and Method A out-of-range state.**

chumash-timeline / agent/chumash-search, 2026-09-15, decided by the search/timeline agent.

1. Method A past pasuk 5846 is reported as status:"beyond_range" with the boundary reference (5846) AND an explicit note and eraLabel, rather than as a pasuk. A nullable pasuk was rejected because src/app/page.tsx (owned by the UI agent) dereferences method.pasuk.* and nullable would fail the typecheck for everyone; the explicit status is additive and the UI can render "beyond the range of this method". Same shape on /api/timeline and /api/search?year=.

2. Every search mode reports count (this response), total (all matches) and offset. Year mode fills count/total with the number of methods. This is the documented semantics for defect 2.

3. A store failure is a 5xx with {ok:false,error:{code:"store_unavailable",message:...}}. Plain "0 results" stays 200 {ok:true,count:0,total:0,results:[]}. The error payload is an object carrying code and message because src/app/page.tsx already reads data.error?.message.

4. era_events are attached per method inside each method entry, filtered to that method's own rows, and the top-level eraEvents map is kept only for backwards compatibility. The C panel is empty because the database has 21 era_events rows and all of them are method_id='d' (SELECT method_id, count(*) -> d 21); the key c:Devarim is not wrong, there is simply no C content. Reported to the data-layer owner rather than editing db/**.

5. The route-local duplication of the search predicate was deleted once the data layer landed searchPesukimPage(); the gematria adapter keeps its pre-merge fallbacks (persisted column, then cached scan) but prefers the data layer's searchPesukimByGematria().

6. /api/timeline now 503s when no store is configured, even for includeText=false. That removes the old "view-only with no DATABASE_URL" behaviour on purpose: era events, year events and feedback all need the store, and the brief requires a refusal to be visible rather than dressed as an empty result.
