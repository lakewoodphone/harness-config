**D2918 · 2026-10-05 · Chumash advertiseability: static OG card, first-party analytics, uptime via the deterministic cron.**

## D — four choices made while making the Chumash Timeline advertiseable (2026-10-05)

Every one of these was an engineering decision inside my mandate; none of them was routed to the
owner. Recorded so the next session does not relitigate them.

**1. The social preview card is a committed PNG, not a `next/og` ImageResponse route.**
The card is static copy that changes when someone edits the title, not per request. A committed
1200×630 PNG cannot fail at request time, ships no font into the image, costs the server nothing,
and is regenerable from `scripts/make-og-image.ps1`. A dynamic route would trade all of that for a
small maintenance convenience.

**2. Traffic measurement is first-party, in the app's own Postgres — not a third-party script.**
`page_views` (path, referring host, channel, timestamp) written by `POST /api/pv` from a beacon in
the root layout. Rejected: a hosted analytics script — a new dependency, a new privacy surface, and
a new thing that fails silently, and it is exactly the third party that tells us nothing the
database does not. The row carries **no IP, no user-agent, no cookie and no session id**, so there
is no consent banner to design and nothing to leak. The question this has to answer is the owner's
question — *did the WhatsApp post work* — and a channel roll-up answers it directly.

**3. Uptime for a public site belongs in the deterministic cron, not in the hourly LLM work order.**
`seed_site_uptime_check` (the agent work order that was supposed to do this) is disabled and its last
run failed; the script's own header says why — its trailing "review" goal step was never claimed, so
it failed 63×/week while the services were up. Re-enabling it would buy an hourly LLM cost for a
check `curl` does better. The fix was one line in
`~/personal-secretary-mvp/scripts/site-uptime-check-cron.sh` on `secratary`, which already runs
hourly at :07 and already logs three other endpoints. One monitor, one place.

**4. The two test rows the verification wrote were deleted, not kept.**
A table whose only purpose is counting must not start with rows that are not people. The rows were
mine, seconds old, provably identifiable, and removed with a bounded `DELETE` after the SELECT that
proved them. The evidence of the verification is this record, not a permanent fake view.

**Also decided (dev, recorded for completeness):** the public origin lives in `src/lib/site.ts` with
`NEXT_PUBLIC_SITE_URL` as the override, rather than being repeated across five metadata call sites.
