## 2026-10-19T22:35Z · ZABZ-YOGA · cheap-first is ON; the gate became a function and got tested first

### What changed

1. **The gate was refactored out of `company_tick` into `_filter_by_schedule(active_agents)`.** It had
 been an inline block, which meant it could only be exercised by mocking eight collaborators — i.e. it
 was never actually tested. Ported to production with the same additive proof (**+60/−0** against the
 file production runs) and the identical text applied to the checkout, so the trees cannot drift.
2. **Four tests now cover the properties that matter:** only departments are gated (so the orchestrator
 and verifiers keep ticking through owner-facing work); a deferral is returned as a decision rather
 than dropped, so a waiting department is distinguishable from a stopped one; an exception inside the
 policy ticks everyone rather than halting the heartbeat; and in legacy mode the real policy plus the
 real price book defer nothing. **126 tests green.**
3. **`SCHEDULE_MODE=cheap-first` is now live in production**, verified from the running process's own
 environment (`/proc/<pid>/environ`), which is authoritative in a way the file on disk is not.

### The check that made enabling defensible rather than hopeful

Before flipping the switch I read the two sweeps that could punish a parked department:

- `lifecycle_sweep._close_stale_tasks` auto-closes tasks stale beyond **`STALE_TASK_DAYS` days**, not
 hours — so a four-hour deferral cannot age real work out. The only 4-hour rule in that function
 applies to approval-tagged residue, which is internal workflow litter, not owner decisions.
- `_release_stale_claims` frees a step after `STALE_HEARTBEAT_MINUTES` (10 min) with no heartbeat. That
 **returns the step to the pool; it does not lose it.**

Had the auto-close threshold been 4 hours rather than days, enabling tonight would have been reckless —
the deferral bound and the close threshold would have been the same number, and work would have been
silently closed at exactly the moment it was waiting.

### Still unobserved, and therefore unclaimed

- The **first real deferral**. The company is off-peak; the first peak block starts **01:00Z**.
- Whether claims **churn** while a department is parked — repeated release-and-retry across a block.
- Any effect on the bill. None can appear before 01:00Z.

### A note on the shape of the work

Three times now the same pattern has paid: build the thing, make it **inert by default**, prove it on
the box with the box's own interpreter, and only then flip one environment variable. `PRICING_MODE`,
`ROUTING_KILL_SWITCH`/`ROUTING_MODE`, `ROUTING_HOUR_AWARE_COSTS`, and now `SCHEDULE_MODE`. A behaviour
change that has an off switch is one an operator can survive; one that does not is a bet.
