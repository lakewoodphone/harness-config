**D9371 · 2026-10-27 · Customer data: one home, and the month runs from when the copy was made (owner rule 2026-10-27).**

Owner rule stated 2026-10-27, verbatim: "we only keep full copies of customer data in the downloads/customer data folder that we we can find it and make sure to delete it after a month, so move it there fully".

WHAT IT MEANS, CONCRETELY (implemented the same session, do not re-derive):

1. ONE HOME. `%USERPROFILE%\Downloads\customer data\<customer name> <phone> <device>` is the only place a FULL
 copy of a customer's data may live. A bench pull, a recovery image, a carved set a library can be rebuilt
 from - all of it goes there. Nothing in a scratch tree, nothing in lpt-hub, nothing in case-media beyond
 the small exhibits that ARE the record (intake photos, recovered still frames).
2. THE MONTH RUNS FROM WHEN THE COPY WAS MADE, not from when it was moved. Tidying does not restart the clock:
 the Shande copy was made 2026-10-11, moved into place 2026-10-27, and is due 2026-11-11 - not 11-27.
3. EVERY FOLDER CARRIES `_landed-on.txt` whose FIRST LINE is `Landed: YYYY-MM-DD`. That file is the only
 honest date. A moved folder keeps the phone's own file timestamps, so mtime-based age is a lie: the Shande
 volume's newest file is dated 2026-10-06, which would have called 16-day-old data a month old.
 A folder with NO marker is NOT swept - undated is unread, and unread is never expired.
4. DELETING IS AN ACT, NOT A SCHEDULE. The sweep reports; `-DeleteCustomerData` plus the owner's per-folder yes
 is what deletes, and only after the job is proved finished (completed status + CAPTURED money).
