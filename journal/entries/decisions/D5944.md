**D5944 · 2026-10-13 · A DSH window slot owns its own blank session; no window adopts another window's blank.**

D-DECISION: a DSH window slot now owns ITS OWN blank session, recorded per origin in
`localStorage["dsh.sessions.ownedBlank"]`, and no window may adopt or restore a blank it does not
own. Upstream reused any blank row in the workspace, which made every empty window render the same
conversation. This is a development decision (rule 3), not an owner question.

WHY THIS SHAPE, and what was rejected:
* REJECTED — a host-side blank registry. The session summary carries no ownership field
 (`SessionSummary`: agentAvailable/sessionId/updatedAt/running/blank/parentSessionId/origin/cwd/
 projections), `retain()` counts are client-local, and there is no RPC to ask who holds a blank.
 Building one is host work for a client-side bug.
* REJECTED — a marker inside the session (title, projection). It writes a UI concern into durable
 session data that other surfaces read and the model can see.
* REJECTED — timing ("adopt a blank older than X minutes"). A blank a live window is still sitting
 on is exactly the one that must not be adopted, and age cannot tell them apart: the bug returns.
* CHOSEN — the record is per ORIGIN because the estate's window model already is: `dshw-proxy.mjs`
 gives each window slot its own loopback port precisely so `localStorage` is per window
 (docs/multi-window/MEMORY-AND-SESSION-LIST.md, "the origin is the window").

ACCEPTED COST: orphan blanks are no longer recycled — a blank abandoned by a closed window, or by
switching workspace, is adopted by nobody. Each is one small session directory, the estate's
archival pass already hides blanks, and `startSession()` in a window that still owns its blank
reuses it rather than making another.

NOT ROUTED TO THE OWNER. He gets one line in the report: windows already doubled need one
*New session* click each, and everything opened after this behaves correctly.
