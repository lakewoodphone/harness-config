**D8451 · 2026-10-19 · settlement-crash is retired on 0.2.1 because upstream now catches every lifecycle rejection; the patch registry can express a version-scoped supersession instead of a waiver.**

SETTLED 2026-10-20, with the evidence that makes it a fact rather than a preference.

The `settlement-crash` hand patch existed because a finished child agent could die at settlement and lose its
report: `watchSettlement()` started an async IIFE with no `.catch`, and when the agent's scope had released the
`inbox` projection, the throw became an unhandled rejection and took the process down (P2249b, P2253b; three
recorded incidents).

On 0.2.1 that shape is GONE, measured in the installed tree:
 * dsh-subagent/lib/index.js:171 wraps EVERY lifecycle listener's returned promise in
 `Promise.resolve(returned).catch(...)` and logs the rejection;
 * the settlement path is a defined handler — `settle: ({ stopReason, output })` at :199, with
 `settlementSummary`, `createSettlementMessage` and `kind: "subagent-settled"`;
 * lib/types/activation.js contains no async IIFE at all (the file the patch's second and third targets named);
 * the manager catches every disposal promise (1274, 1306, 1319, 1363, 1381).
So on 0.2.1 the patch has nothing to add: its first target is already hardened in our tree by an earlier partial
apply, and its other two targets no longer exist. On the 0.2.0 line it is still needed — this is a version-scoped
retirement, not a deletion.

ENCODED, so nobody has to be the one who remembers: `patches/registry.json` may carry
`superseded: { fromVersion, evidence }`, and `install-engine` now reports `SUPERSEDED BY UPSTREAM` (with the
evidence line) instead of failing and forcing an operator to type `--allow-patch-failures` for something that is
not a loss. The earlier waiver on the 0.2.1 install reported the patch as "without", which was false — one third
was applied; the receipt now records the patcher's own per-target lines, and the waiver sentence no longer
promises a clean absence.

STILL OPEN on this estate: the window-blank-isolation patch refuses on 0.2.1 (exit 5, upstream bundle changed) and
has no superseded evidence yet — it needs either a re-anchor or an equally measured retirement.
