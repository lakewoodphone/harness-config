**D179 · 2026-09-15 · The production rebuild is BLOCKED on the smsService Dialpad migration - rebuilding today would silently break customer SMS.**

Decision: the owed production rebuild (docs/audit/DEPLOYMENT-GAP-2026-09-15.md) is BLOCKED, not deferred.

Reason: production runs an older tree in which SMS works (Dialpad, 224/240 outbound over 14 days, SIDs
prefixed "di"). The current source removed Twilio and left ~15 call sites on smsService.sendSMS, which now
always returns success:false against a NoOp stub. Rebuilding from source would silently break customer SMS
in four places: repair-status notifications, payment-link texts, MFA codes, AI-workspace customer SMS.

Prerequisite to unblock: finish the Dialpad migration of smsService (repoint it at
getCommunicationProvider(), or route the A2P path through the Dialpad provider), then rebuild with the
named rollback tag. Until then the correct action is NOT to rebuild.

This also means the "deployment gap" is worse than "prod is stale": prod is stale AND source is
un-deployable as-is. Any future rebuild must be gated on this migration.
