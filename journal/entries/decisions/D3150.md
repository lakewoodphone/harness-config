# One relay for the owner's phone: policy in one module, every door submits, asks in one ledger

Decided 2026-10-14 for the owner's text channel (the AI line +17324447361 ↔ +18483897895).

**The finding that forced the shape.** The phone number had **four** independent writers, and that is why
the owner says "your unified brain is not working":

| door | gate it obeyed | owner-bound sends / 30 d |
|---|---|---|
| `/root/bin/textsend.py` | its own owner-turn ledger + 20-min floor | 43 of 502 |
| app `sms_service.send_message` + `owner_message_queue` flush | `app/owner_text.py` only | ~400 |
| `company-heartbeat.sh` → raw Twilio curl, on `waze-mdm-01` + `lpt-apps-01` | **none** | 51 |
| `send-from-ai-line.py` → raw Twilio POST | **none** | 12 |

Wrapping `textsend.py` alone would have mediated **8.6 %** of what reaches his phone.

**The architecture.** `/root/bin/owner_text_relay.py` (+ `owner-text` CLI), store
`/root/.owner-text/relay.db` (WAL). It is **policy only and never transmits** — `textsend.py` stays the
transport. Every door calls `submit(door, subsystem, body, *, reason, urgency, class_hint, ref, topic,
opens_ask, dedupe_extra, dedupe_disabled) -> {verdict, reason, attempt_id, detail}` and gets back one of
`SEND | DEDUPE | FLOOR | COALESCE | SUPPRESS`. **Every submission is written down whatever the verdict**,
so `owner-text status` can answer "what did we decide not to tell him in the last 24 h, and why". One
`ask` table is the single open-question ledger that `textctx.recent_asks` reads, so an ask made by any
subsystem becomes visible to the reply router.

**Load-bearing details, each paid for:**
- The dedupe hash is `sha256(normalised body)` **with no timestamp in it** — a timestamp is exactly how
 identical re-reports bypassed the old `owner_body_seen_recently`.
- The read-decide-write is one `BEGIN IMMEDIATE`: 12 threads and 6 processes submitting the same body
 returned **exactly one SEND**.
- Fail-**soft, never fail-silent**: if the relay is missing, a door sends anyway and logs one line.
 A relay outage may never become silence.
- `DEDUPE_EXEMPT_SUBSYSTEMS = {"security_alert_mms"}`: for a safety-critical class a duplicate is cheap
 and a miss is not, so dedupe is traded away and only the retry cap remains.
- `class_hint="reply"` (`REPLY_CLASS`) exempts a conversational answer from the 20-minute floor. Without
 it, an answer to his own question could be held 20 minutes.

**Rejected alternatives.** Wrapping only `textsend.py` (8.6 % coverage). Putting the policy inside the
FastAPI app (no import path for the `/root/bin` cron scripts, and it would need a service restart to
change a threshold). A second gate per door (that is exactly the four-door defect).
