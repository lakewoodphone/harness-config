**D3151 · 2026-10-14 · Email archive: fill unified-search's registered mail:gmail gap, do not build a second index.**

Decided 2026-10-14 on the authority (secratary-cloud).

QUESTION: how to make the owner's email durably searchable, rather than analysed once.

SURVEY FIRST (estate-systems skill - "before the first design sentence, prove the thing does not
already exist"). Found:
 (1) `unified-search` already exists: adapters emit JSONL against contracts/doc.schema.json, one
 index.db, FTS5, `usearch.py query` - exactly the design I was about to invent;
 (2) config/sources.json ALREADY registers a source named `mail:gmail`, disabled, whose own note
 says "the real reason is upstream of search ... This is a Gmail-connector job";
 (3) docs/search-design.md says "Nothing covers Gmail yet";
 (4) the register's rule: ONE search engine, do not build a second.

DECISION: build the missing half, not a rival system.
 * Connector (the missing half): /root/mail-archive/chevedy/ingest.py pulls the whole mailbox into
 archive.db (SQLite + FTS5) with raw gzipped payloads and attachments alongside. 25,889 messages,
 0 errors, 17.5 min.
 * Adapter (new file in the EXISTING repo): unified-search/adapters/mail/sync.py - one usearch
 document per message, resumable, watermark in ~/.usearch/state/mail-chevedy.json.
 * Index: ~/.usearch/usearch.db on the authority. 25,889 docs / 61,445 chunks / 198 MB. Query in ~5 ms.
 * Registry: added hosts.authority and an ENABLED source mail:chevedy to config/sources.json, plus a
 correction to the neighbouring mail:gmail note (it claimed email_catalog held 0 rows; it held 722
 when measured).
 * Refresh: /root/mail-archive/refresh.sh - connector, corpus rebuild, adapter, index; 12.7 s on a
 no-op run; exit code is the worst of the four steps so cron-wrap records a real failure.

Why not ~/bin/gmail-search.py, which already exists: it queries the Gmail API live, so it cannot
answer a question about 2017 without paying the network and cannot be analysed in bulk. It stays as
the ad-hoc read tool; this is the indexed corpus.

The RAW ARCHIVE is the source of truth. The index is derived and reproducible from it, which is what
makes a rebuild safe.
