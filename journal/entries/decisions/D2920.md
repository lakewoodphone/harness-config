**D2920 · 2026-10-05 · The LPT access kit: eleven decisions, including that live access is the default and temporary is measured not promised.**

Decisions taken while rebuilding the LPT USB access + diagnostics flow (tools/lpt-access-kit/). Recorded because each was contested or would otherwise be relitigated.

D1. LIVE ACCESS IS THE DEFAULT, AND THE USB-BACK PAYLOAD IS THE FALLBACK, NOT THE PRODUCT. The owner asked for access, not for the output of one script. Tier 2 runs whether or not a channel was found, so a dead channel costs only the channel.

D2. ONE KIT, ONE FOLDER, ONE ENTRY POINT, ONE HANDOFF SCHEMA. tools/lpt-access-kit/ is the only source of truth. tools/lpt-diagnostics-kit/ and scripts/copilot-ssh-field-kit/ hold only MOVED.md and must not be run or edited. They measured: the stick was AHEAD of the repo (25,727 B vs 20,354 B; 29,802 vs 15,081), and three handoff formats existed with one reader.

D3. THE TEARDOWN IS ARMED BEFORE THE WINDOW OPENS, AND A WINDOW IS NEVER OPEN WITHOUT IT. If the destructor cannot be armed the entry point refuses to open a window at all. The old kit promised removal on reboot with no mechanism anywhere in the code (P2851) while registering sshd start=auto.

D4. TEMPORARY IS MEASURED, NOT PROMISED. A window has a deadline, a teardown with two independent closures (boot-start destructor, plus each access agent checking its own deadline at start), and a POST-REBOOT ABSENCE CHECK. Until that check reports PASS the window is not closed and Ingest reports it as an open window on a machine that has left the shop.

D5. NOTHING CLAIMS A RESULT IT DID NOT READ. Every capture section writes a STATUS header: OK / EMPTY / COULD_NOT_READ / SKIPPED, with a reason. A non-OK section file says in its own text that it must not be read as a clean result. Elevation is recorded because BitLocker is silently unreadable unelevated.

D6. PER-MACHINE, PER-SESSION CREDENTIALS AND NO SECRET ON THE STICK. The window account password is never disclosed to anyone - key-only T1 means no human authenticates as it. T1 leaves only our PUBLIC half on the target. The shop-wide repairtech password, a private SSH key and the shop WiFi password are all gone from the stick.

D7. REVOCATION IS SERVER-SIDE OR IT IS NOTHING. A credential we leave on someone machine is a credential they hold. T3 therefore creates a PER-MACHINE tunnel and deletes it, because a shared tunnel token cannot be revoked individually. Deleting local files does not make a window closed.

D8. THE DESTRUCTOR REMOVES ONLY WHAT THE STATE FILE NAMES, BY VALUE, NEVER BY PATTERN, and it must be structurally unable to touch a customer own objects: wildcards refused, well-known system paths refused, sshd_config edited only between our own markers, authorized_keys only a line carrying our own comment, sshd stopped-and-disabled rather than deleted when it predated the window.

D9. THE FILTER IS ROUTED AROUND, NEVER DISABLED. This kit is not a filter-bypass tool. Disable-Techloq.ps1 prints success unconditionally while the calls behind it fail and never unloads the driver, so it is not a supported path.

D10. M1 STAYS OPEN UNTIL MEASURED. Whether the filter resets OUTBOUND SSH decides whether a customer machine gets one key (T2) or a whole tunnel, exec agent and browser terminal (T3). It has been asserted since 2026-08-25 on evidence that does not support it - the cited capture shows an ordinary auth failure. Probe: probes/Test-TechloqOutboundSsh.ps1. Control reading on an unfiltered machine is recorded in DESIGN.md section 3.

D11. NO WINDOW OPENS ON ANY MACHINE UNTIL ACCEPTANCE TEST A4 PASSES ON A REAL LAPTOP. A4 is the post-reboot absence check; A5 is the replay failure. This held for the entire build, including when the owner had a live customer machine waiting.
