**D8578 · 2026-10-19 · Condition audit: five statuses, NA vs unmeasured, and an acoustic loopback APK instead of ADB hand-waving.**

Built the fit-to-sell condition audit for E4610/E4810 in `lpt-flip-phone` (branch main, uncommitted at time of writing; files listed in the handoff of the same session).

DECISIONS, each with the reason:

1. Two entry points, one engine. `lpt condition --serial <s> [--bench] [--deep]` is the engine; `scripts/condition/audit-phone.ps1` is what the owner runs (no arguments, iterates every authorised handset, exit 0/1/2).
2. Evidence first: every probe's command, raw output, duration and error is written to `logs/condition/<serial>-<stamp>/raw/<probe>.txt` and into report.json. A parser bug then costs a fix, not the measurement.
3. Status vocabulary is five words, not two: ok / warn / fail / na / unmeasured. `na` means "this firmware cannot answer" (battery `charge_full` is root-only on these Kyoceras); `unmeasured` means "we tried and did not get a reading". Collapsing them is how a dead check looks healthy.
4. Verdict: any `fail` -> NOT_SELLABLE; any `unmeasured` that is a required proof -> INCOMPLETE; any warn or optional gap -> SELLABLE_WITH_NOTES; else SELLABLE.
5. Speaker and microphone cannot be proven over ADB. `dumpsys media.audio_flinger` proves the HAL instantiates playback and capture threads, not that the transducers make sound. So the audit installs a purpose-built APK (`bench-apk/`, package `com.lpt.bench`) that plays 1 kHz at max volume while recording from the mic, then measures that tone with a Goertzel against 500 Hz and 2 kHz, and uninstalls itself afterwards (verified gone). This is the answer to "I wish there was a way to test the mic or speaker" - it is measurable acoustically, in one shot, with no root.
6. The APK is built without Gradle (aapt2 -> javac -> d8 -> zipalign -> apksigner) because the repo already builds APKs that way and a bench tool must build on the machine with the USB cable in it.
7. Expectations live in the device YAML `condition:` block, merged over DEFAULT_EXPECTATIONS - config as data, per the repo's architecture decision.
8. Thresholds are declared guesses and are labelled as such in docs/condition-audit/README.md; they are calibrated from the first real batch, never left as untested numbers pretending to be standards.
