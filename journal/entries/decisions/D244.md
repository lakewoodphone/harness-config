**D244 · 2026-09-17 · O4 node hygiene: two reclaim classes, three gates, and a drift series in the capacity contract's own units.**

Stream O4 (node hygiene) is built and verified. Files: `scripts/mesh-hygiene.ps1`,
`scripts/mesh-hygiene.sh`, `docs/mesh/85-hygiene.md`. Nothing else was touched (phone-gate.py was
read only; the Mac's own reclaim job was left alone).

DECISIONS TAKEN (all mine; none needs the owner)
* Default mode is **report-only on both platforms**; a kill needs `-Reclaim` / `--reclaim`. The Mac
 policy defaults to acting because launchd passes `--reclaim` explicitly; here a human runs it by
 hand, so the safe default is the one that matters.
* Exactly three gates, from 81 §1: console input-idle (`-IdleSeconds`/`--idle-seconds`, default
 1800 s), no `--profile headless` dispatch in flight, no unexpired governor lease. Lease liveness is
 `expiresAt` in epoch **ms**, never a pid guess (governor.js says why).
* Class A = executable PATH under an explicit prefix list, scoped to the console user/session
 (24 prefixes on Windows; .app bundles and install prefixes on POSIX). No readable path → no match.
* Class B = parent gone + command line matches our tool entry points + age ≥ 300 s + holds no
 LISTENING socket. The listener rule exists because the first report tried to reclaim the node's own
 phone-gate (pid 24148, `pythonw … phone-gate.py --listen-port 3086`, recorded parent gone) — a
 service is parentless by design. `dsh/lib/bin.js web`, `--listen-port`, `--engine-port` and
 `tailscaled` are additionally never candidates.
* Class B does NOT duplicate `scripts/dsh-reap.ps1`'s class (npm/npx shims, stale MCP generations):
 one owner per thing, and that reaper is already scheduled on ZABZ-YOGA.
* Drift counters defined once: `avail_mib` = the capacity contract's own number per platform
 (GlobalMemoryStatusEx.ullAvailPhys / meminfo MemAvailable / vm_stat free+inactive+speculative+
 purgeable × hw.pagesize); `reclaimable_rss_kb` = RSS of the two reclaimable classes;
 `placeable_children` = the broker's 71 §2.2 formula **reproduced**, with the gate's own
 `maxChildren` recorded beside it from `127.0.0.1:3086/mesh/capacity`.
* Records: one human line + one JSONL object + one latest JSON per run, in the `~/.dsh-sync-status`
 idiom on Windows and `/var/log` (else `~/.dsh-sync-status`) on POSIX. `at_epoch` is written so no
 platform's `date -d`/`date -j` dialect is needed to compute a rate; the baseline is the oldest
 record inside 24 h; `trend` has a 256 MiB/h dead band.
* **No install anywhere.** Install/off-switch commands live in the script headers and the doc. The
 deployment choice went to the owner as one queue row (#82) with a recommendation: worker/headless
 nodes only, laptops report-only.

EVIDENCE (raw, all 2026-09-17)
* ZABZ-YOGA loaded to `placeable=0` (`avail 3849 MiB`, `swap 23.3%`, gate `maxChildren 2`, drift
 `rate=-33031 MiB/h placeable_d=-12 zero_children_in_h=0 trend=shrinking`) then back to
 `placeable=12` after one run that reclaimed 9412 MiB (`reclaimable_rss_kb 9637912 -> 0`).
* Declines with reasons: `console active: idle 251s < required 1800s`, `a governor lease is held: pid
 1784 overnight-build`, `a dispatch is in flight: pids 2087353`.
* Sparing: a non-listed process and the owner's 29 Edge processes survived the acting runs; the
 self-test kills the hog matching the shipped pattern and spares the one that matches nothing — on
 Windows (PS 7 and 5.1), Linux and macOS (bash 3.2).
