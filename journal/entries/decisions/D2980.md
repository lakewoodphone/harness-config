**D2980 · 2026-10-08 · Required checks must always report: the path filter goes inside the job, and never enforce a gate that cannot pass yet.**

Decided 2026-10-09 while fixing required-check gate jams in `lakewoodphone/phone-and-tech-full` (PR #342).

**1. A path condition on a required check belongs inside the job, never on the trigger.**
A `paths:` filter under `pull_request:` stops the workflow, so no check run is created and the required context can never be satisfied. The job now always runs and always posts a conclusion; a relevance step decides whether the expensive steps execute. Cheap non-Docker steps stay unconditional. Chosen over the alternative — dropping `Build image and assert the sha label` from the required list — because the check guards real production-image provenance (the running image once carried a tag that did not match its own `dist/index.js`, and `/health` reported `commit: unknown`). Removing it would weaken a gate that was just built to catch exactly that.

**2. Relevance must fail safe, and must use a three-dot diff.**
Any unmeasurable state resolves to `relevant=true`; running an unnecessary five-minute image build costs minutes, skipping a necessary one ships a broken artifact. Three-dot (`base...head`) because `strict=true` moves the base branch under the PR and a two-dot diff misattributes base-only changes to the PR.

**3. Job-level `if:` is the same defect as a `paths:` filter.**
`if: github.event.pull_request.draft == false` on `Check for Phantom Dependencies` meant a draft PR produced no check run. The draft flag now gates the work steps, so the job still reports. Same reasoning makes `reopened` a required member of the `types:` list on every required-check workflow: without it a reopened PR can never obtain a check run.

**4. Do not enforce a gate that cannot pass yet.**
Discovered in the same audit: `Lint Backend` cannot fail at all (implicit shell, no `pipefail`), while 41 backend ESLint errors sit in the tree. Repairing the plumbing first would fail the aggregator and therefore the required `CI Validation (PR Pre-Check)`, blocking every PR. Decision: clear the errors first, then enforce, then deliberately break one to prove the gate can go red. Reasoning recorded in `docs/development/required-checks-must-always-report.md`.

**5. Never edit files in a shared checkout; a demo branch can be built without one.**
Created and pushed demo branches straight from a `GIT_INDEX_FILE` pointed at a temporary index (`git read-tree <base>` → `git update-index --add --cacheinfo` → `git write-tree` → `git commit-tree` → `git update-ref`), so a minimal commit could be produced and pushed without a checkout, without touching the working tree, and without a second full worktree.
