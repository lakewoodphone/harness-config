**D3145 · 2026-10-13 · The shop counter devices: managed web clips repointed at the authority and given an Icon payload.**

**Decided and done 2026-10-13, ZABZ-YOGA.** Owner report: on the office iPad and both iPhone 11s the
home-screen shortcuts for **DSH** and for the **Lakewood Phone & Tech** site were grey squares, and he had
had to change his own phone's DSH shortcut by hand after the server moved office -> cloud.

**Two independent defects in one file** — `shop-store.mobileconfig`, profile `com.abletel.lpt.shopstore`,
carried by DRN 2001 / 2002 / 2003 (`store_device`, site `lpt`):

1. it named `secratary.tail93e6e6.ts.net` in **three** places: the DSH web clip's `URL`, the web filter's
 `PermittedURLs[2]`, and its `AllowListBookmarks[2].URL`. That host is the FROZEN office box, which has
 had no phone stack since the 2026-10-11 05:43:36Z cutover. Repointed to
 `secratary-cloud.tail93e6e6.ts.net` (`tailscale serve` on the authority -> 127.0.0.1:3086).
2. **both** `com.apple.webClip.managed` payloads carried no `Icon`. Apple's WebClip reference, verbatim:
 *"Icon data — The PNG icon to show on the Home Screen. If not set, the system displays a white
 square."* That is the grey square. Not a cache, and not about `apple-touch-icon`: a managed clip never
 reads the page's icon — and the intake clip proved it, because `lakewoodphoneandtech.com` has served a
 correct 180x180 `apple-touch-icon.png` with a link tag all along and its clip was grey anyway.

**Derived from PRODUCTION** (`/opt/waze-mdm/profiles/shop-store.mobileconfig`, sha256 `674bd74e…`,
15309 B, mtime 2026-10-08), never from the repo copy (`2d213d96…`, 15311 B). The third recorded drift in
this file and a real one: `allowPasswordAutoFill` and `safariAllowAutoFill` are `true` on the server, so a
rebuild from the repo would have silently reverted them. New file `6da88880…`, 36135 B. Backup on the
MDM host: `/opt/waze-mdm/backups/profiles/shop-store.mobileconfig.20261013T144204Z.pre-repoint`.
**The edit is textual, the verification semantic**: both files parsed with plistlib, every changed path
enumerated, changed set asserted to be exactly `{dsh.URL, webfilter.PermittedURLs[2],
webfilter.AllowListBookmarks[2].URL}` + `Icon` on two clips -> `VERDICT: PASS`, payload list identical,
nothing removed. **Reproducibility proven on the MDM host**: the repo's
`profiles/build-shop-store-icons.py` run against the backup yields a byte-identical `6da88880…`.

**The icons were chosen, not put to him** (his rule: work the number out, do not hand back a menu): the
intake clip wears the shop's own icon — a copy of the 180x180 `apple-touch-icon.png` the site already
serves — and the DSH clip wears the harness's own mark, white on the harness's boot background `#151517`,
rendered from the engine's shipped `favicon.svg`. Sources live in `profiles/icons/`.

**Pushed** to all three DRNs with the documented endpoint
(`POST /fleet/devices/<DRN>/install-profile?profile_type=shop-store`): `ok:true` plus an `InstallProfile`
`command_uuid` and an APNs `push_result` each — which means **enqueued**, never applied. Verification is
`command_results.status = Acknowledged`, then a `ProfileList` (runbook §6). At push time the two iPhone 11s
had last checked in 2026-10-08 and the iPad 2026-10-11 04:22Z, so delivery waits on the device being on.
