**D9360 · 2026-10-22 · Second DoH origin is live on a dedicated Falkenstein box - and the Hetzner account turns out to be one account, not two.**

## 2026-10-22 17:45 UTC · The second DoH origin is live on a dedicated box, and the Hetzner account is finally visible

**What the new API token changed.** With it I could see the account for the first time: **four servers, one Hetzner account, no second account** — `waze-mdm-01` (cpx11, ash), `lpt-apps-01` (cx33, fsn1), `lpt-survivor-01` (cx33, fsn1), `secratary-cloud` (ccx33, ash). One SSH key registered (`mesh-hetzner-2026-08-31`), no firewalls, no floating IPs, no load balancers. So the earlier belief that the survivor sits in a second account is wrong: **account-level independence does not exist today**, and buying a fifth box in this account would not create it.

**Why a new box rather than repurposing one.** The role-conflict review measured what each existing host actually carries. `lpt-apps-01` holds `/root/.restic-env` (the offsite backup repo), `/root/.lpt-r2.env`, and Stripe/Twilio/Gmail/GitHub/JWT secrets in container environments; a public DNS parser there puts the only unrecreatable asset one container escape from the internet. `secratary-cloud` is the sole writer of a 32 GiB authority database on a 90 % disk with no public 443. The survivor is unreachable and is the company standby. So the cheapest honest option was a dedicated box, not a shared one.

**Built and verified.** `dns2-abletel-01`, Hetzner CX23, Falkenstein, 178.104.210.131, created 2026-10-22 (~5-6 a month). Debian 12, python3 + nginx + ufw, no Docker, no credentials, no customer data. The filter runs as a hardened systemd unit on 127.0.0.1:8053; nginx terminates TLS with a copy of the primary's `mdm.abletelsolutions.com` certificate; the PAC is served from there too. Verified from the primary host with the certificate validated against the name: both origins return `http=200 tls=0 rcode=0 answers=1`; the second refuses `updates.cdn-apple.com` with `rcode=3`; the PAC is 8,633 bytes with all eight location markers.

**Kept in step automatically.** `/root/bin/dns2-cert-sync.sh` on the primary runs daily at 04:17: it copies the certificate and key after renewal and the PAC after any change, reloads nginx on the second box, and refuses to fail silently. Installed and exercised today: "certificate copied … nginx reloaded", "PAC unchanged".

**Watched from off-host.** The watcher on `secratary-cloud` now probes both origins every two minutes. The standby probe validates the certificate against `mdm.abletelsolutions.com` over SNI, because a name mismatch would only surface when we needed it. Two healthchecks: `waze doh endpoint` (120 s / 180 s grace) and `waze doh second origin` (300 s / 900 s grace), both bound to the owner's channel.

**The one gap: automatic failover needs a write-capable Cloudflare token.** The token on the primary reads the zone and its records but **cannot write** — a create-record probe returns `Authentication error`. So moving the A record is a two-minute manual step today, documented in `deploy/waze-mdm/second-origin/README.md`. With a token scoped to `Zone:abletelsolutions.com → DNS:Edit` the watcher can move it after three consecutive failures and move it back on recovery.

**Credentials.** The Hetzner token is stored root-only at `/root/.hcloud-token` on the MDM host (64 chars, verified). It has full account control, so it should be rotated once this work is settled, and it must never be committed or echoed into a log.
