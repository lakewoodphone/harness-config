**D184 · 2026-09-15 · personality-system hardening: measured-contract model choice, fail-closed operator surface, CAS on saves, knowable deploys, measured-signal claims.**

## D - personality-system hardening decisions, 2026-09-15 (audit -> fix -> deploy)

Decided and shipped in one session. Each is recorded so it is not relitigated.

1. **Models are chosen by MEASURED CONTRACT COMPLIANCE, not by reputation or by alias.**
 The app's defaults are `deepseek/deepseek-v4-pro -> openai/gpt-4.1-mini -> openai/gpt-5.4-mini`
 (question family) and `deepseek/deepseek-v4-pro -> openai/gpt-4.1-mini` (report family). Chosen
 because I probed the live gateway with the app's REAL 1.3KB question payload and its real
 final-report payload validated against `finalReportSchema`. The gateway's own route aliases
 (`secretary-auto/-fast/-smart`) answer a trivial prompt with 200 and **500 on every real
 payload** at its own 30s timeout, so "prefer the alias" was reverted to "prefer what passes the
 contract", with aliases kept as supported operator options. Evidence lives in code
 (`DEFAULT_MODEL_EVIDENCE`, `describeModelPolicy()`), and `scripts/verify-model-chain.mjs` is the
 deploy-time gate that would have caught the original outage. See L1606, D177.

2. **The operator surface fails CLOSED.** `ASSESSMENT_OPERATOR_KEY` guards `DELETE /api/persistence`,
 the four `?view=` reads and `GET /api/feedback`. Unset or wrong => 503/403, never allowed. The
 participant kiosk flow stays open (no accounts is the product), which is why the client half is
 rate-limited and body-capped instead of authenticated.

3. **A stale write is REFUSED, not merged.** `expectedRevision` is a true compare-and-swap where
 null means "must not exist"; saves serialise under `SELECT ... FOR UPDATE`; a stale writer gets
 409 with the current revision. Rationale: the previous behaviour replaced the whole shared
 library with one device's stale view and reported success. Silent loss with a success message is
 the worst failure shape for a business that has lost customer data twice.

4. **The running commit must be knowable.** Image tag = commit sha, plus OCI labels, a `GIT_COMMIT`
 env var and `/_next/static/deploy-info.json`. A healthcheck exists so `docker ps` can say
 `(healthy)` for the first time. Without this, "is production healthy?" was unanswerable and the
 AI layer stayed dead for over a week.

5. **Test-only files may carry narrowly-scoped lint disables, with the reason stated in the file.**
 Applied to the `pg` test double (19 `no-explicit-any`) and the `.cjs` DDL parity checker. Test
 doubles model dynamic driver shapes; the production code under test is what must stay strict.

6. **Findings are gated on MEASURED signals, and the product must not assert what it did not
 measure.** Five inconsistent "elevated" thresholds collapsed to one; a claim with no data becomes
 "not enough information yet"; cross-version retake comparison is withheld rather than caveated.
 This makes the instrument internally correct. It is explicitly NOT psychometric validation: there
 are still no norms, no reliability estimate and no validation sample, and no prose may imply
 otherwise.

Still open and deliberately not decided here: life-stage and gender NORMING (needs content work plus
an owner decision), and device-scoping the library key so an anonymous caller reads an empty library.
