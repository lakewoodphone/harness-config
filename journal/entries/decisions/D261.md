# D-new — A demo instance of anything customer-facing uses a reserved-fiction number, enforced by the tool

**Decided 2026-09-17.** Any demonstration instance of a customer-facing page or
asset carries a number from **555-0100…555-0199** (reserved for fiction) — never
a real customer's, never the owner's, never an unconfirmed guess at a customer's.
For the WhatsApp sign-up page this is enforced in code: `publish.py --demo`
refuses any number outside that range.

**Why it is a decision and not a preference.** The demo of the Weinberg WhatsApp
page shipped with a real customer's number (18482857640 — Abraham Abramczyk) and
so handed strangers a WhatsApp chat with him. The case file for that very page
had already ruled the reverse way in writing for the real page. A rule that is
only written down in one file did not survive contact with a second file; a rule
the tool enforces does.

**Scope:** demo/test/example instances. The **real** page is unaffected — it
publishes the number the customer confirmed, without `--demo`.

**Related:** L1968 (the repo of a temp-dir publish is not evidence about what is
live). Case: `lpt-hub/docs/customer-operations/cases/whatsapp-status-link-weinberg-2026-09-17.md`.
