# Decision: the findings are computed on the authority, and the badge reads a list of sources

Made 2026-10-12 by Zabz (ZABZ-YOGA session, workstream 168). Developer decisions, taken and recorded,
not routed to the owner.

## 1. `run-sentinel` runs on `secratary-cloud`

- Checkout `/root/ceo-kernel` (HEAD `7be7fde`), state `/root/ceo-kernel-var`, cron every 5 minutes via
 the estate's own `/usr/local/bin/cron-wrap.sh`, under `nice -n 10`.
- **Cadence `*/5` was chosen from a measurement**, not a default: the first run took 15 s (the office
 box took ~13 s), so `*/15` was not needed. `nice` is deliberate: a monitoring job must lose every CPU
 race with the company API on a 2-vCPU box that has OOM-killed it once.
- The job name stays `run-sentinel`, so any monitor or ledger keyed on the name keeps reading true.
- `ck/sources.py` now reads `CEO_KERNEL_DB` / `CEO_KERNEL_AUTHORITY_HOST` from the environment, with
 the old office values as defaults, so the kernel's behaviour on any other host is unchanged.
- **The office box was not touched**: no service state changed, nothing written. It remains the frozen
 rollback anchor.

## 2. Nothing was restarted

`phone-gate.py` defaults `CEO_KERNEL_STATE` to `$HOME/ceo-kernel-var/latest.json`, and the unit runs as
root with `HOME=/root` — exactly where the port put the state. So the gate began serving a live report
the moment the first run finished, with **no restart of any service**. The generalisable rule recorded
with this decision: *the accessor's default is the contract*.

## 3. The badge's data origin is a list, and the freshest reading wins

- `BADGE_AUTHORITIES = ['https://secratary-cloud.tail93e6e6.ts.net',
 'https://secratary.tail93e6e6.ts.net']` — authority first, the frozen box only as a stand-in.
- `assets/phone-badge.js` v4 asks the candidates in order, keeps the freshest **readable** reading,
 falls through on a refusal (`read:false`) or an unreachable source, and keeps a stale reading only if
 nothing fresher answers — still labelled `(stale)`, still naming the host it came from.
- **Why freshest-wins and not first-wins**: a source that answers but is frozen must never shadow a
 live one, and that is exactly the failure this decision exists to kill. **Why a stale reading is
 still rendered** rather than hidden: "I could not get a current number" must not look like "nothing
 to report" — the same rule as `countOf()` refusing null.
- Rejected alternatives: (a) repoint `secratary.tail93e6e6.ts.net` at the cloud — Tailscale names are
 per-node and the office name belongs to the frozen anchor; (b) a public DNS alias — adds a public-DNS
 dependency and a certificate problem for a route that is tailnet-only by design; (c) leave the
 constant and reinstall every machine — the bundle is cached immutably, so the wrong host would have
 been asked for up to a year with no error anywhere.
- Verified: `node scripts/verify-badge.js` 181/181 (was 163) and `python scripts/verify-badge-gate.py`
 55/55.

## 4. The fixed badge asset is deployed to BOTH authority paths

`/usr/local/assets/phone-badge.js` **and** `/root/code/harness-config/assets/phone-badge.js`.
`resolve_asset()` searches `/usr/local/assets/` *before* the checkout, so updating only the checkout
would have changed nothing the gate serves. Both keep a `*.pre-multisource-<stamp>` backup, in the
estate's existing convention. The gate caches the script on `(mtime, size)`, so no restart is needed
for an asset change.

## Open, recorded so it is not re-decided

 the authority's checkout is now ahead of it. Named in `docs/mesh/168-ATTENTION-AUTHORITY.md` §6.3.
