**D251 · 2026-09-17 · the provider row's targetHosts default becomes [] -- no key in the row chooses or validates a node.**

DECIDED and IMPLEMENTED 2026-09-17. Commit 7fdbbc8, +7/-1 on profiles/web/cordis.patch.yml, pushed as a
fast-forward (4d8baa2..7fdbbc8). The commit carries ONLY that line; the 45/14 of placement keys the same
file holds in the working tree are another stream's in-flight work and were deliberately not committed --
their working-tree row was backed up and restored byte-for-byte afterwards (restored_ok=True, 956A1397).

WHAT IT WAS: targetHosts defaulted to ['zabz-tech']. It is the location-check ALLOW-LIST, not the
destination. The destination is `target: process.env.MESH_TARGET_NODE ?? 'desktop-ts'`, and on zabz-tech
`desktop-ts` resolves to zabz-tech.tail93e6e6.ts.net -- itself. So the row named a node twice, and on that
machine blessed a self-dispatch as "matched configured target host".

WHAT IT IS NOW: `: []`. In `broker` mode neither key is consulted -- the placed node's own host list comes
from packages/plugin-remote-fanout/lib/nodes.js. In the hand-set `fixed` fallback an empty list means the
location check is recorded and not made. profiles/mesh/cordis.patch.yml already used the same default.
MESH_TARGET_HOSTS and MESH_TARGET_NODE are set nowhere on any node (re-measured in the process, machine and
user environment).

WHY COMMITTED AND NOT JUST EDITED: the hand-edit is reverted within ~5 minutes by
sync.py:plan_profile_patches (see the reversion lesson). The commit is the only form that survives.

WHAT THIS DOES NOT FIX, AND MUST NOT PRETEND TO: broker placement exists in NO COMMIT
(lib/placement.js, lib/nodes.js, lib/broker-client.js and the row's placement/brokerSsh/brokerUrl/
queueWaitMs). The committed lib/index.js reads no `placement` key -- its own comment says "placement is a
separate decision service". So on zabz-tech the composed row has 0 `placement` hits and a subagent_remote
call still goes to desktop-ts = itself. Setting `placement: broker` on a machine whose code cannot read it
would be inert: a configuration that looks like a capability and is not.

Evidence: docs/mesh/103-route-commit-and-sync.md §3.
