**D3040 · 2026-10-13 · The Amazon and eBay browser scrapers are replaced by the email path, on evidence, not preference.**

Decided 2026-10-13 by the finance-fleet manager. Recorded so it is not relitigated.

THE EVIDENCE.
1. Playwright cannot run on the authority at all. `npx playwright@1.55.1 install --with-deps chromium`
 fails with `ERROR: Playwright does not support chromium on ubuntu26.04-x64`; the host is
 Ubuntu 26.04.1 LTS and no browser landed in ~/.cache/ms-playwright. The amazon/ebay download
 steps are Playwright scripts (`amazon:download`, `ebay:download` in package.json).
2. Even if a browser existed, both scrapers log into Amazon/eBay from a datacenter IP - the exact
 pattern those sites block, and it needs an interactive login the box cannot perform.
3. The data those scrapers uniquely supply is ORDER DETAIL, and the mailbox already carries it:
 3,973 purchase receipts are stored, and a measured backfill from one mailbox alone produced
 448 Amazon orders and 163 eBay orders with item lines, 380 of 611 matched to card charges.
4. The marketplaces' TRANSACTION rows are already visible through Plaid on the cards, so the
 scraper is not even the only source for the money leg.

WHAT IS DONE INSTEAD. The receipt/email ingest is the source of truth for Amazon and eBay orders
(new `app/services/marketplace_order_sync.py` plus a systemd timer, staged by the fleet worker).
The browser steps stay deployed but are expected to fail on this host; that failure is now named in
the freshness report rather than hidden.

WHAT THIS REPLACES: nothing is deleted and no subsystem is disabled by this decision. If the estate
later runs a supported browser on a host that can hold a logged-in session, the scrapers can return
without reversing anything here.
