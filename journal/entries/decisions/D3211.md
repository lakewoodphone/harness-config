## DECISION — company-api's memory bound was below the app's own working set; the bound is now "kill, never throttle"

**Made** 2026-10-14 ~17:2xZ on secratary-cloud by the ZABZ session that answered the owner's
"I keep getting these alerts".

**What changed**
- `/etc/systemd/system/company-api.service.d/30-memory.conf`: `MemoryHigh=4G` **removed**;
 `MemoryMax` 6G → **10G**; `MemorySwapMax` 2G → **1G**. Applied live with `systemctl daemon-reload`
 (verified: cgroup `memory.high` = `max`, `memory.max` = 10737418240, `memory.swap.max` = 1073741824
 — daemon-reload DID apply them to the running unit, so no restart was needed).
- `/usr/local/bin/estate-monitor.py` `api_rss_gib` thresholds 5.0/6.0 → **9.0/10.0**, so `crit` is
 set AT `MemoryMax` and means "a kill is imminent" (new sha 5651aed36c96079d).

**Why, with the arithmetic**
The bound was written at 06:58Z the same day from ONE reading (VmRSS 2.9 GB at 06:56Z, ~40 min after
a restart) and generalised it into "legitimate steady state". estate-monitor's own series settles it:
over the **1,126** `api_rss_gib` readings taken while `MemoryMax=infinity` (the only regime with
enough observations), VmRSS was **p10 4.93 / p50 6.49 / p90 8.86 / max 11.59 GiB**, with `MemoryPeak`
repeatedly 9.099 GiB. A 4 GB soft limit therefore sat below the MEDIAN. Consequences, captured at
17:06Z on the instance started 15:50:40Z: `memory.current` 5,118,967,808 with `file 0`,
`memory.events high=105,611 max=0 oom_kill=0`, one thread in kernel state **D in
`mem_cgroup_handle_over_high`**, last log line 16:05:51Z and 73 minutes of nothing after it.
`max=0` is the whole point: the cgroup never reached `MemoryMax`, so the kernel never killed it, so
`Restart=always` never fired, and the service sat `active (running)` serving nothing from 16:05:51Z
until a human ran `systemctl restart` at 17:10:50Z.

**The rule this establishes:** a soft memory limit below a service's working set does not protect the
box — it converts a crash (which systemd restarts in 10 s) into an invisible freeze (which nothing
restarts). On this estate, prefer `MemoryMax` alone.
