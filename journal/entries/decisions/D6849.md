## DECISION 2026-10-18: the owner queue is ONE table, and its comms channel is Google Voice via email — never Dialpad

**The owner's correction, verbatim (2026-10-18):** *"dial pad calls sms and voicemail do not count. I only want
personal ones ... Google voice numbers and you do have access to my Google voice numbers because they get
forwarded to my email. ... The dial pad is not relevant to my queue And you can access my goal of voice
through my emails."*

So, binding for every session that touches the owner queue:

1. **Dialpad is out.** `dialpad_sms_cache`, `dialpad_call_full`, `dialpad_ui_*` must never feed the owner
 queue. `app/services/owner_attention_sweep.py` is built almost entirely on those tables, which is why it
 was the wrong foundation to extend.
2. **Google Voice is the personal channel, and email is the only access path that works.**
 `+17325691594 -> eliyahuzabrowsky@gmail.com`, `+17329943420 -> ezabz68@gmail.com`
 (`app/services/gv_email_handler.py` `GV_ACCOUNT_MAP`).
3. Three GV item forms arrive as mail: `New text message from X`, `New missed call from X`,
 `New voicemail from X`.

## The architecture decided (mine to decide, not the owner's)

- **One table stays the one queue: `owner_decision_queue`.** No second table, no parallel "attention" store.
 It gains `kind` ('decision'|'attention'), `channel`, `party`, `evidence_at`, `evidence_ref`, `dedupe_key`,
 `meta_json`, `seen_at`. Every pre-existing row migrates as `kind='decision'` so #516/#590 references survive.
- **One ordering function** over everything pending. `brief` already merged three surfaces; that is the shape,
 not a fourth surface.
- **The queue CLI stays stdlib-only** so it runs from any machine and from a live-boot shell; the mailbox read
 needs the app venv, so it lives in a companion script `owner-queue-ingest-gv.py` run by
 `/root/personal-secretary-mvp/.venv/bin/python` and invoked through `owner-queue.py ingest gv`.
- **Noise is the majority and must be dropped by rule, not by volume.** The 200-sample contains OTP codes,
 broadcast lists (Igud Talmidei Fallsburg, zmanim "Alert" numbers), order/shipping notices and mazel-tov
 chains. A queue that shows those is the same as no queue.

## Environment trap worth remembering

PowerShell here-strings carry CRLF, so a piped remote script passes `\r` into paths and args: `sed` reported
`can't read /root/.../email_actions.py` while `ls` showed the file, and `cd` silently did nothing. Also
`ssh host "cmd with | or \\"` is re-parsed by PowerShell and fails. Use **single-quoted** PowerShell strings
for remote one-liners. The app venv is `/root/personal-secretary-mvp/.venv/bin/python`; `app.config` exports
`settings`, **not** `get_settings` — use the fallback ladder in `owner_attention_sweep._load_settings`.
