# 2026-09-23 — SMS replies: fold typography, keep the 2-segment cap, make chops loud

Context: the owner's 20:15Z SMS thread (sms_log 906-909) exposed a hijacked reply and a
chopped joke. Two decisions taken with him in the room, both engineering (not his):

1. Status questions keep the deterministic, model-free path, but only when the whole
 message is the question (anchored + <=9 words). Everything else reaches the model.
2. SMS reply length stays capped at 2 segments (a deliberate owner-facing brevity rule),
 but the encoding cliff is removed by folding typographic glyphs to GSM-7 before
 measuring, and any real truncation now logs a WARNING with before/after sizes.

Not done, deliberately: raising the 2-segment cap, and giving outbound SMS a durable spool
like inbound has. The first is a taste/brevity call; the second is a design change to the
send path and was left for a session that can measure it.
