**D139 · 2026-09-14 · Engine supervision: one recovery path, no reclaim from window-opening verbs, two patient probes before any kill.**

D: Engine supervision in `dshw.ps1` -- one recovery path, and window verbs may not kill.
Decided 2026-09-14 after the owner reported a freeze.

1. `Ensure-Engine` is the ONLY place that may reclaim a bound port. `Invoke-Ensure` now delegates
 to it instead of carrying its own start-only copy (that copy is why the 1-minute watchdog could
 never recover a wedged engine: it just ate "port already in use").
2. `dshw new` and `dshw restore` NEVER reclaim a bound port. If a listener exists, the engine
 exists; they open the window and leave the process alone.
3. Before ANY kill, `Test-EngineWedged` must see TWO failures of a patient probe (10 s connect /
 30 s read), five seconds apart. Default probe budget raised 1500/2500 ms -> 6000/12000 ms.
4. An EADDRINUSE from a start attempt is proof the port is held even when the listen table says
 otherwise: refresh the table with the cache bypassed, and if a node process owns it and is
 silent to the patient test, reclaim and retry.
5. `Get-ListenTable` treats an EMPTY result as a failed read and retries (a live Windows box
 always has listeners).
6. Health transcripts are one appended file per DAY, not one per run (288/day before). Nothing is
 deleted; the ~1000 existing per-run files stay.

Why: the 1-minute watchdog must own wedged-engine recovery, and no command whose job is to open a
window may take a process away. Both invariants exist because the reverse was measured.
