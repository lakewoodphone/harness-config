**D236 · 2026-09-16 · Screen Time (Communication Limits) is the DRN fleet's call-blocking lever; enabled per-DRN on 48/54 as the practice.**

## Decision

For the DRN Waze fleet (site `lakewood`, DRN 1-55, AT&T SIMs), **call blocking is done on-device with Screen Time > Communication Limits**, and the MDM kiosk profile is being changed to allow that: per-DRN profile variants leave `allowEnablingRestrictions=true` and unblock the `com.apple.ScreenTime` Settings-pane entry, for the two practice devices only.

## Why

- The DRN fleet's AT&T lines are supposed to bar voice and do not. The owner's 2026-09-17 sheet marks DRN 9, 30, 47-54 and Chicago 1 as "BAD" (calls still work). The LPT fleet (DRN 2001/2002, site `lpt`) never had the problem because its Telnyx SIMs are data-only.
- Apple publishes no MDM mechanism that blocks native cellular voice: the Restrictions payload (210 keys) has no call/voice kill switch, `blockedAppBundleIDs` cannot carry Phone or Settings, the Settings command has no `ScreenTime` item, no declarative configuration covers Screen Time, and MDM cannot set Communication Limits at all.
- Screen Time > Communication Limits is the only documented thing that blocks incoming AND outgoing calls, and it must be set by hand on the device. `allowEnablingRestrictions=false` — carried by every production kiosk profile — is the documented lever that disables it ("disables the Enable ScreenTime option ... and disables ScreenTime if already enabled").

## Scope of the practice

- DRN 48 (serial `DL6Y9R6VNH`, enrollment `00008150-000C64C80188C01C`): variant installed, **Acknowledged 2026-09-17 03:50:14Z**.
- DRN 54 (serial `GJH2KX93HL`, enrollment `00008150-001160280CC0C01C`): commands queued while the device was offline.
- **No other device's profile changed.** Fleet-wide rollout is not decided.
