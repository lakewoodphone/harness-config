**D236 · 2026-09-15 · Evidence clips now come from the NVR's recording, not the live stream.**

**Decision (2026-09-15): evidence clips are now pulled from what the NVR has already recorded, not recorded live.**

What changed and why:

- **Pre-event footage.** The old path started recording 2-3 s after the trigger, so the approach — the part that identifies a person — was never captured. `phoenix-clip.py` asks the NVR for `[trigger - pre, trigger + post]` (10 s + 10 s by default) and the whole window is recorded before the request is made.
- **Cameras are named, never numbered.** `CAMERAS = {key: (nvr_channel, osd_title)}` in one place, beside the OSD title read off the live stream. The old YAML passed bare RTSP channel numbers, which is how the whole archive ended up mislabelled.
- **Transcode to H.264 at full 2560x1440.** The NVR is HEVC; browsers are not. CPU is spent to buy playability. `-preset ultrafast -crf 26`, ~1 min of Pi CPU per camera per event.
- **Atomic writes** `<name>.part` -> rename, `-f mp4` explicit, and a separate `/media/phoenix/capture.log` line per camera with rc, method, window, duration and reason.
- **Trigger time is read before the lock, not after.** The NVR clock is sampled at process start and the window is anchored to it, so a capture that waited minutes for the lock still records the event's window rather than the moment it finally ran.
- **Rate limited per camera set.** `binary_sensor.video_doorbell_person` fired 774 times in 7 days; that path is capped at one capture per 120 s and takes two cameras. Rings and door contacts are uncapped.
- **Detached.** `nohup ... &`, with no Jinja anywhere in the file (see the shell_command lesson). Home Assistant only notices events now.

Commands are one per event (`phoenix_clip_doorbell_ring`, `phoenix_clip_person_doorbell`, `phoenix_clip_outside_door`, `phoenix_clip_interior_door`) deliberately, so no template is needed.

Verified in production the same day: an `outside_door` event produced 3/3 cameras, all reporting the identical window `14:32:56-14:33:16`, from OSD `Main Entrance`, `IPC` and `Reolink Video Doorbell PoE` respectively; and a frame check confirmed the clip is real-time (OSD 14:15:49 at clip 2 s, 14:16:25 at clip 38 s).

Superseded: `phoenix-capture.sh` (v1) and `phoenix-capture-doorbell.py`. The doorbell script's `except Exception: pass` is why the only camera with a microphone had produced **zero** clips in the entire archive.
