**D2097 · 2026-09-20 · D338 - the org question about shrinking vs repairing departments was the wrong question and I decided it by measurement instead of referring it.**

**This was owner-queue #130, and I should never have put it there.** The owner's standing instruction: *"these are dev questions, their not boss qs you do the dev stuff, i do the boss stuff."* The org shape of my own AI company is dev work. Worse, the row's own recommendation text already said the completion predicate fix *"is not a question for you"* - I wrote that, and then queued the row anyway.

**I have now decided it by measurement, and the measurement dissolves the question.**

## What the data says

**Departments are NOT failing to complete work.** Task completion by assignee:

 dept_business_ops 4793 tasks 4783 done 99.8%
 orchestrator 3381 tasks 3378 done 99.9%
 dept_engineering 2835 tasks 2819 done 99.4%
 dept_home_life 1674 tasks 1672 done 99.9%
 dept_finance 1552 tasks 1549 done 99.8%
 ... 25 largest, every one between 98.5% and 100%

So "repair all 18 departments so they really run" has no problem to solve at that layer, and "shrink it to a small company" would discard the layer that is working. **Both options were wrong**, because both assumed the department layer was the broken part.

**The real defect is where the work sits, and whether anything can ever reach it.** Open `goal_steps`:

 28,757 open steps across 82 assigned agents
 dept_business_ops 6032 open ever_tried=49 has_heartbeat=0
 orchestrator 3437 open ever_tried=0 has_heartbeat=0
 dept_engineering 2849 open ever_tried=69 has_heartbeat=0
 dept_ai_platform 1120 open ever_tried=0 has_heartbeat=0

**`ever_tried=49` out of 6,032 is the whole finding.** The steps are not failing - **nothing ever attempts them.** And 82 agents hold open steps while only 22 `dept_*` names exist in the task layer; **66 of the 82 agents holding open work are not in the executing layer at all**, so no executor will ever reach them. This is accumulated dead queue, not a backlog being worked.

## The decision

1. **Do not shrink and do not repair-sweep.** Neither premise holds.
2. **Treat the orphaned `goal_steps` as dead queue to be measured and retired, per agent, rather than repaired in bulk.** The predicate is now fixed, so "tried and failed" and "never attempted" are finally distinguishable - that is the instrument this decision needed and did not have before.
3. **Keep the `dept_*` task layer**, which completes what it is given.
4. **Decide retirement agent by agent on measurement**, not on the department list. An agent that has attempted its work and failed gets fixed or retired; an agent whose steps are never attempted because it has no executor loses the intray, not the agent.

**Why this is not the "shrink first" option that was recommended.** Shrinking was recommended to get an honest baseline. The predicate fix got the honest baseline without discarding anything - so the premise for shrinking has already been satisfied by other means.

## The process lesson, recorded because the owner had to say it twice

I queued a decision that was mine, with a recommendation attached, and the row's own text proved I knew it. **A queue row is not a safe place for a decision you can make** - it reads as diligence and it is deferral. The test before adding a row: *could I decide this with a measurement?* If yes, measure and decide; the row is only for money, customers, legal, family, irreversible acts, and genuine taste.
