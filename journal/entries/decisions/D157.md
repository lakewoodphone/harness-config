**D157 · 2026-09-15 · The config contract counts accepted env names; templates document declared settings with their code defaults.**

**Decision: the config contract counts the env names the application accepts, and the templates document what exists.**

- **A `validation_alias` replaces the field name; an alias-less field is read under its own name
 uppercased.** That is pydantic's semantics and it is now what `backend_expected_env_keys()` encodes:
 alias names if the field has them, `NAME.upper()` otherwise, plus `ROOT_ENV_ALLOWED_EXTRA_KEYS`.
 Before this, three fields that rename themselves made the contract demand three env names nothing
 reads and call the three real ones unexpected.
- **A template documents every setting the code declares, with the default from `app/config.py`, and
 secrets are left empty.** No invented values, no commented-out keys: the contract's parser skips
 comments, so a `# KEY=` line does not count as documented and would have produced a green test with
 a template that still told a new deployment nothing.
- **Example templates are tracked even where `.env*` is ignored** (`!.env.local.example` in
 `web/.gitignore`), because a contract test asserts the file exists and an ignored file would make
 that assertion true only on the machine that created it.
