**D8450 · 2026-10-19 · DeepSeek's search endpoint is now the first provider in the company's web_search chain, verified with a live call (provider used: deepseek).**

DECIDED AND APPLIED 2026-10-19 on the authority, verified end to end.

DeepSeek's own search endpoint is now the FIRST provider in the company's `web_search` chain. Before: brave,
tavily, serpapi, duckduckgo, jina, firecrawl — each needing its own key, and on the night's own probe tavily
returned 433, serpapi 429, jina timed out, and the answer came from firecrawl. After: `deepseek` is tried first
because it needs only `DEEPSEEK_API_KEY`, which the company already holds.

CHANGES: `app/web_access.py` gained `_search_deepseek()` (POST /v1/tools/search, `count` = max_results, results
mapped to {title,url,snippet} from summary/snippet), the provider list leads with "deepseek", and the if/elif
dispatch has a real branch for it — the first attempt added only the list entry and the chain silently fell through
to firecrawl, because `results` was never assigned for a provider with no branch. `app/config.py::web_search_keys()`
now includes the deepseek key.

EVIDENCE: `search_web("lakewood new jersey phone repair", 3, keys)` -> `provider used: deepseek | results: 3`, with
plausible local results. `company-api` reloaded, `/health` HTTP 200. Measured endpoint behaviour from this host:
200 in 0.63 s, `count` controls result volume, billable only on 200-with-results, free until 2026-11-01 00:00
Beijing then 0.75 USD per 1,000 requests.

WHY IT MATTERS BEYOND COST: the chain's other four providers were all failing or missing keys on the night this was
built. A search that answers at all is worth more than a slightly cheaper one that does not.

NOT DONE: jina and firecrawl remain in the chain as fallbacks and were not retired — their coverage is measured on
this estate and DeepSeek's index is not. `scripts/ds-search.mjs` remains the direct CLI for a session that wants
the endpoint without the chain.
