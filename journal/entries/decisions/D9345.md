## D — the headless child authenticates from the node's own credential store, and that row is now a repo overlay

DECIDED 2026-10-21, after measuring that every mesh child on every Windows node had been dying at startup.

THE STATE. `@deepseek-ai/dsh-headless` sets `credentials`, `authorization` and `deepseek-account` to `disabled: true`, and says why: "One-shot jobs use launch-time credentials instead of the interactive store." This estate keeps its only DeepSeek key in `$DSH_HOME/.credentials.yaml` and never materializes it into the environment. So a one-shot child had no credential source at all. This was not a laptop defect and not a fleet defect: `dsh --profile headless "Reply with exactly MESH-PROBE-OK"` exited 1 with `MISSING_CREDENTIAL ... route "deepseek-official"` ON ZABZ-TECH, the machine whose web GUI works, three minutes before the fix.

THE DECISION, three parts:
1. `profiles/headless/cordis.patch.yml` (NEW in this repo, and this repo now owns it) carries `- id: credentials / name: dsh-credentials-local / disabled: !!js process.platform === 'linux'`. Same row in `profiles/mesh/cordis.patch.yml`, because `mesh-run.mjs` boots `--profile mesh` locally and that profile inherits the same bundle list.
2. THE GATE IS LOAD-BEARING — do not remove it to "make it uniform". `dsh-llm-deepseek-api-key` reads `if (credentials !== void 0) { resolve(ref) } else { ambient env }` and THROWS when a mounted store has no such ref: there is no environment fallback once the service is mounted. `zabz-tech-linux`'s store has no `refs:` section at all; its key is `/etc/dsh-worker.env`, sourced by its `/usr/local/bin/dsh` executor. Mounting the store there would replace a working environment lookup with a throw. Give that node a `refs:` section first, then delete the gate.
3. NOT exporting DEEPSEEK_API_KEY to each node. The Windows roster rows used to say "the parent engine is already running with its key" (lib/nodes.js); it is not, and a key in a process environment would be a second source of truth that must be rotated twice and would put a live secret on an ssh command line (P13b). The store is the one source: rotating through the web Models page now reaches every node with no code and no environment change.

ALSO CORRECTED, because the report was telling operators a credential had been supplied: `nodes.js` `zabz-tech` and `zabz-yoga-1` gain `credentialEnvFiles: ['!self-store']`, and `remote-script.js`'s interpreter fallback no longer claims the child inherits the dispatching environment. It passes no credential file at all.

MEASURED AFTER: `MESH-PROBE-OK` exit 0 on ZABZ-TECH; `MESH-PROBE-OK` exit 0 on ZABZ-YOGA over ssh; `MACMINI_OK` on lakewooechsmini with the store mounted (it had been on the environment path and still answered after the change, so its store resolves too); and a real broker-placed `subagent` child on zabz-yoga-1 -> `MESH-HOST: zabz-yoga`, exit 0 in 20 s, lease mvi6ayul, where six children had died the hour before. The three installed files are byte-identical to the repo (`aab3cd31`).
