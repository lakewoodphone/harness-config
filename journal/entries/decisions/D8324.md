## 2026-10-19T23:30Z · ZABZ-YOGA · a deferral that is only in journalctl is not recorded

The scheduler's deferral existed in two places: a `log.info` line, and the tick's return dict. `activity_log`
- the table briefings and dashboards actually read - knew nothing about it. **A state that lands only in a
log file is not recorded; it is merely printed.**

So the company-tick detail now appends `, N deferred for the cheap window` when a deferral happened, and
is byte-identical when none did. The conditionality is the part that matters: existing readers parse
`agents ticked` and must not be disturbed, and a proof that changes the shape of a shared log string is a
proof that breaks whatever else reads it.

**Verified on the tick immediately after the deploy** (23:29:07Z):
`Company tick: 20 agents ticked in 17.75s` - exactly the old shape, because nothing deferred at that
hour. The first real deferral will show the appended clause, and can be read from the database:

```sql
SELECT created_at, detail FROM activity_log
WHERE detail LIKE '%deferred for the cheap window%' ORDER BY created_at DESC LIMIT 20;
```

### The observer no longer depends on journald

`peakwatch` now counts deferrals from `activity_log` (`deferrals_db`, 600-minute window) as well as from
the journal. Journald rotates; the database is the record. An observation that would vanish on rotation is
not evidence, and tonight's peak block is the only chance to observe it.
