**D8385 · 2026-10-19 · Peak verification is one command with a control window, and it prints its own caveat first.**

## 2026-10-19T23:56Z · ZABZ-YOGA · tonight's answer is one command, and it argues against itself

`peak_verification.py` compares the 01:00-04:00 block with the *same weekday, same hours, one week
earlier*. It checks deferrals against the pre-registered prediction, whether work continued, the cost from
tokens, and whether tick errors rose.

### The control run produced a warning about the tool, before it produced any answer

The two Mondays held **257 and 713 calls** in the same three hours. The raw cost delta reads **-48.5 %**,
which is entirely how much work happened that night. Anyone quoting it as a saving would be quoting volume.

So the tool now prints, *before* any delta:

> a single 3-hour window is NOT a cost measurement ... the money is a week-against-week question and
> belongs to weekly_report.py and bill_report.py

**A tool that only reports the flattering number is not a measurement, it is a press release.** The caveat
had to live inside the tool, not in a document beside it, because the next reader will run the tool and not
read the document.

### And the control is genuinely clean

Both sides: `agents_ticked [20]`, `deferrals 0`, `company ticks 6`. A pre-change Monday behaved exactly as
pre-change Mondays should, which is what makes tonight's number mean something.
