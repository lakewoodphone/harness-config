**D3124 · 2026-10-12 · Wake fleet ceiling set to 5 USD/day (not 25): the same prepaid balance funds company-api.**

WHY: the same prepaid AI balance funds BOTH the autonomous wake fleet AND company-api (618 routes, the
autopilot, every live AI call). A fleet at the old ceiling could therefore starve the company's own
brain. Decision is mine (engineering, not money): bound the fleet so the company cannot be starved.

ARITHMETIC: balance measured 30.55 on 2026-10-13T01:16Z. Authority ceiling in force was
WAKE_MAX_USD_PER_DAY=25.0 (wake.py DEFAULT_MAX_USD_PER_DAY). One unrestricted day at that ceiling
takes the balance to ~5.55, i.e. BELOW the 10.00 guard floor that company API calls depend on. So the
old ceiling was itself unsafe with this balance.

DECIDED: the installed fan-out cron line sets WAKE_MAX_USD_PER_DAY=5 (one fifth of the authority
default) and WAKE_FANOUT_TARGET=3 (office used 5). 5 USD/day at 0.036-0.068 per release is ~74-139
releases/day, which is 4x-30x the historic normal of 4-18/day, and it is sustainable for ~4-6 days on
the current balance without a top-up -- long enough to gather the measured spend that justifies raising
it. RAISE IT AFTER MEASUREMENT, NOT BEFORE.

Note the tooling's own warning, observed in wake-dispatch.log at 01:18:04Z:
"WARNING USD cap drift: wake.py says $5.0/day, WAKE_MAX_USD_PER_DAY overrides to $5/day. The looser
value wins." -- the override works, and "the looser value wins" is the property to remember when
changing either number.

ALSO DECIDED AND VERIFIED: /home/zabz and /root are the SAME directory on the authority (identical
device:inode -- wake.py 2049:2079930, inbox.db 2049:2080009 under both paths). So the office path
/home/zabz in the ported scripts resolves to the same store rather than creating a second one. This
mattered because a second wake store is exactly how the owner's texts went unread for months.
