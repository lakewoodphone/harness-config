**D56 · 2026-09-14 · One writer allocates ids over the index, the shards and every git ref.**

*Decided:* `tools/journal.py` is the only writer, and it allocates ids over the index, every shard and **every
git ref**.

*Why it is not a style preference:* 60 base ids in this journal named more than one entry — `P46` was three
different problems, `D41` five, `W25` five. Two sessions on two machines had each read the file, taken "max+1"
from their own copy, and appended; the git merge then concatenated both. A bare cross-reference in prose
therefore meant nothing, and nothing complained.

*Mechanics:* `next-id`/`append` take the maximum over `index/entries.tsv`, `log/**`, and `git grep` across all
refs, then add one. Existing collisions are repaired with letter suffixes ordered by date (`P46`, `P46b`,
`P46c`) and the repair list is in `archive/MIGRATION.md`. **A bare collided id is never to be written again**;
the suffixed id from the index is the one to cite. `check` reports the collided base ids so nobody re-derives
them by hand.

*Rejected alternative:* a reserved numeric block per machine — it removes collisions but makes ids
unpredictable and leaves the existing 60 unfixed.
