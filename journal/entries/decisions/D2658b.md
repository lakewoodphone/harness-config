**D2658b · 2026-09-28 · checkout-health: a new wake source for the project checkouts, with measured thresholds.**

DECIDED 2026-09-28. New source /home/zabz/bin/sources/checkout-health.py, wired
into /home/zabz/bin/run-wake-sources.sh BEFORE project-keepalive (the store
releases same-priority rows in id order - wake.py `_candidates` - so a checkout
that cannot accept a commit is repaired before the shift that needs to commit is
woken). Subject `checkout-health:<project>:<YYYYMMDD>`, so one row per project
per UTC day, structurally.

THRESHOLDS, each with the measurement behind it:
 * BEHIND_MIN=50. Healthy the same day: 0 (kosher) and 2 (lpt-website). The two
 real incidents were 222 and 426. origin/test gained 340 commits in 14 days
 (~24/day), so 50 is about two days of drift - 4.4x below the smaller incident
 and far above anything one merge cycle produces.
 * DIRTY_HOURS=24. The age is the signal, not the dirty bit: a tree dirty from a
 run happening now is normal. lpt-website measured dirty=1 at 186 h.
 * LOCK_GRACE_SEC=300. An index write is sub-second (measured `git fetch` 0.54 s
 / 0.95 s on these repos); five minutes with no owner is debris.
 * FETCH_TIMEOUT=30 s, because run-wake-sources.sh wraps every source in
 `timeout 90` - one hung fetch must not eat the budget of the projects after
 it. Healthy fetch here is under 1 s.
 * AHEAD of upstream is REPORTED but never a flag: a shift legitimately commits
 locally before pushing, so flagging it would fire on a healthy loop.
 * An UNMEASURABLE signal (fetch failed/timed out, no upstream resolvable) is
 reported and makes the process exit 1, and is NEVER turned into a flag:
 spending a release on a network blip is how an alarm becomes noise.

REGISTRY CHANGE. lpt-website now carries `dirty_ignore: ["reconciliation_plan.json"]`
(/home/zabz/bin/sources/projects.json, backed up .bak-checkouthealth-20260928-172814).
It is a GENERATED data snapshot, not a shift's work: its own header names the tool
(personal-secretary-mvp.open_work_order_reconciliation) and generatedAt
2026-09-20T23:15:20; that tool's default --output is
_scratch/open-work-order-reconciliation/plan-latest.json; and
personal-secretary-mvp/docs/system-inventory/current-repos.json already records
" M reconciliation_plan.json" as a known state of that checkout. Flagging it would
have made the source's own claim ("uncommitted work that never landed") false. The
per-project stderr line still prints it as declared-and-not-counted, so the state
stays visible. Rejected alternative: leave it firing and let a woken session
decide, at the cost of one of four daily releases on a tool's output.
