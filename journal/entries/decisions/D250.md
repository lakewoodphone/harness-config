**D250 · 2026-09-17 · 99: how the POSIX installer, the ZABZ-TECH provider install and the un-synced checkout were decided.**

**D-99-1 — install ZABZ-TECH's provider from `origin/master`, not from the working tree.** `packages/plugin-remote-fanout/**` is being edited by another stream (5 modified + 5 untracked files on the laptop); the committed pair is self-contained (its four `lib/*.js` import only each other and node builtins) and the committed rows carry no `lib/nodes.js` reference — that exists only in the uncommitted rows. So the committed pair composes and nothing had to be guessed about another stream's in-flight code.

**D-99-2 — create the plugin junction with a LOCAL process, never over ssh.** Measured: an ssh-spawned node on that machine read 3 of the profile's 4 junctions and failed the 4th with `UNKNOWN`, so trust is creator-bound, and `90` §3/§6 had already refused that bet on a machine with no console. Implemented as a one-shot scheduled task for that user (new name; no `-Force`, `-Principal`, `-AtLogOn`, `RestartCount`), with a separate-process traversal test before anything was named and a rollback that restores both backups and removes the junction.

**D-99-3 — do not restart ZABZ-TECH's engine.** Not because it would be unsafe — measured at 14:12Z: `established_on_3099=0`, two node processes, last v2 child 13:53:31Z, last activity 14:05:36Z — but because a fresh local `--dump-config` already rehearses what the next start will do, and a restart would additionally load three other streams' in-flight state. The mount is recorded as taking effect at that machine's next start.

**D-99-4 — do not sync that checkout yet, and give the measurement rather than a preference.** Seven files on that machine are newer than `origin/master` and live in no commit; a fast-forward would regress the code its live v2 route serves. The unblocker is one commit by the stream that owns `packages/plugin-mesh-http/**`. Hand-carrying the remaining 26 commits would re-create the drift the fork work removed.

**D-99-5 — do not invent the desktop provider's `targetHosts`.** It is unset there, so the committed row defaults to `['zabz-tech']`, i.e. the machine dispatching to itself. One environment variable overrides it per node; which node a desktop session should dispatch to is a deployment fact, so it is reported and left alone.

**D-99-6 — record the gates' one-place problem; do not fix it.** Two of five nodes run a gate from a hand-placed directory, one of them a third revision out of a non-repository, and both stale copies have no allow-list beside them. The assessment and the three changes that would fix it are in `99` §5.2; the file-beside-the-script convention should be replaced by an explicit configured path whose absence is a refusal.
