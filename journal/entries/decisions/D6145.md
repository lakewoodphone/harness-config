**D6145 · 2026-10-16 · A write guard that refuses on a full disk is right; a backup directory with no retention is the defect.**

Decided 2026-10-16 after the ledger's writer stopped on a full disk. The guard in cfo_backup.vacuum_into requiring 3x the ledger size free with a 2 GiB floor is CORRECT and stays as it is: a write without a backup is not allowed, and refusing is better than filling the last usable space. What changes, and it is mine to change: (1) the pre-write backups get a RETENTION COUNT - keep the newest N and let the rest go - because 537 files accumulating since 2026-10-13 with no bound is what turned a directory with a 2 GB floor into a 33 GB one; (2) a SPACE CHECK ALERT on the same cron cadence, filing a wake row when free space drops below the guard's own floor, so this surfaces as a named problem hours before a write fails instead of as a RuntimeError in a shift log; (3) the directory is for LEDGER backups, and a 29 GB authority VACUUM INTO does not belong in it - whoever owns the authority backup path should be told or the path corrected. The retention number and the alert threshold are mine to set and I will set them with the arithmetic shown; deleting existing backups is NOT mine and is put to the owner as one question with the exact command quoted.
