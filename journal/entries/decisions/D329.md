**D329 · 2026-09-20 · ZABZ-TECH boot/Hello hardening: 4 reversible changes applied and verified (2026-09-20).**

Diagnosed the owner's 2026-09-20 report ("zabz tech takes a long time to turn back on and I have to
reset the pin"). Full record: `harness-config/docs/mesh/117-zabz-tech-hello-and-boot.md`.

Applied on ZABZ-TECH, elevated, each verified afterwards (all reversible):
 1. `HKLM\SYSTEM\CurrentControlSet\Control\ServicesPipeTimeout` 180000 -> 30000 (Windows default).
 Why: any hung auto-start service was costing up to 3 minutes.
 2. `Intel(R) Platform License Manager Service` startup type Automatic -> Manual.
 Why: Auto + Stopped, and event 7009 "timeout was reached (180000 ms) while waiting for the
 Intel(R) Platform License Manager Service service to connect" on nearly every boot.
 3. Removed 8 duplicate `HKCU\...\Run\MicrosoftEdgeAutoLaunch_*` values (backup written to
 `Code\_diag\edge-autolaunch-backup.txt`). Why: logon churn.
 4. Removed stale `...\WindowsUpdate\Auto Update\IsOOBEInProgress` (=1) and
 `AcceleratedInstallRequired` (=1). Why: both absent on the healthy control ZABZ-YOGA.

Verified after: the 3 Lenovo firmware updates are still offered by Windows Update, BitLocker still
Protection On / 100% encrypted, NgcSvc and NgcCtnrSvc running.

Deliberately NOT changed: Fast Startup left ON (a Restart is a full boot anyway, so it is not
implicated and the bootmgr timeout is 0); the stale orphan Hello container {16596639-...} left in
place (touching NGC while the owner is logged in can disturb the live container for no proven
benefit); the shop startup items (Nox, MobileTrans, Smart Switch, Dialpad, Macrium, Tailscale) left
alone because they are business tools.

Owner decision raised, the only one: install the three pending Lenovo firmware updates including the
Infineon TPM firmware 15.23.17664.0 -> 15.24.18954.0. Needs a reboot and carries flash risk. Recovery
path verified first: BitLocker numerical recovery password exists and is backed up to the Microsoft
account, and `DevicePasswordLessBuildVersion = 0` so password sign-in is still allowed - he cannot be
locked out by a Hello failure.
