**D9282 · 2026-10-20 · Journal P1: file-based record stays, derived index untracked, write path forbidden repo-scale work.**

**Decision (2026-10-21, ZABZ-YOGA): the journal stays a file-based record with a derived SQLite index, and the write path is forbidden from doing repo-scale work. Stages B-E are specified in `journal/SPEC-v3-parallel-store.md`.**

Shipped now (commit `e4f015308`, verified):

* `git_max` reads entry ids from **filenames** via one `ls-tree` per ref (0.20 s), memoised on a ref fingerprint — replacing a 332.6 s working-tree `grep`, a 60 s `HEAD` grep and 25 × 15.1 s per-ref greps (~9 minutes per append).
* No fetch inside a write. `spawn_ceiling_refresh()` starts a detached `journal.py refresh` (coordination ref only: **2.8 s, exit 0**, versus `--all` which never completed in 25 s or 300 s), single-flight, rate-limited, delayed 20 s so it does not compete with the write that spawned it.
* `append_index_entry`: one INSERT + one TSV line instead of re-parsing 4,762 files and rewriting a 27 MB database — **23-30 s → 4.3 s**, and verified equal to a full rebuild (4,759 = 4,759 rows, per-kind identical, 0 body mismatches).
* Reads: 3 s patience for the lock, then answer from `index/journal.db` — **status 774 s → 1.15 s**, `newest`/`show`/`list`/`search` 0.33-0.36 s.
* `journal/index/journal.db` + `entries.tsv` untracked (ignore rule existed; the files were tracked so it never applied). History held **3,085 blobs / 15.2 GB** and the ten largest objects in the repo were all journal.db; the record itself is 13.2 MB.

Decided and recorded here so it is not re-litigated: **the record stays one file per entry in git.** A pure-database store or an index daemon were both considered and rejected — one file per entry is why `grep`, `git log -p`, review and a corrupted-index rebuild all work, and the incremental path already removed the 23 s that a daemon was being proposed to hide.

**Open, and it is the owner's:** stage D (history rewrite to drop the ~15 GB of `journal/index` blobs) rewrites every commit hash and invalidates every machine's clone. Not started. Stage C (journal in its own ~15 MB repo) makes D unnecessary if it happens first; recommend C, then decide D.
