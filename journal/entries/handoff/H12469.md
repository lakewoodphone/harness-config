TWO FAILURES IN FLIGHT, both environmental, both worth remembering:
1. `python -m lpt.cli deploy` aborted with `UnicodeEncodeError: 'charmap' codec can't encode character
 '\u2713'` - a redirected shell gives the child cp1252 stdout and rich's progress line writes a
 checkmark. Fix: PYTHONUTF8=1 and PYTHONIOENCODING=utf-8 on the call. The repo already sets both in
 scripts/Invoke-LptCli.ps1 (Set-LptCliOutputDefaults), so only DIRECT `python -m lpt.cli` calls from
 an agent shell hit this.
2. `filter-only.ps1 -AutoRecovery` aborted with `ModuleNotFoundError: No module named 'requests'`.
 Get-LptPythonCommand prefers `py`, and on this laptop `py` resolves to the Windows Store alias
 C:\Users\ezabz\AppData\Local\Microsoft\WindowsApps\PythonSoftwareFoundation.Python.3.13_*\python.exe
 (no requests), while `python` = C:\Python313\python.exe has requests 2.34.2. Worked around by
 calling `python -m lpt.cli enable-tech-window --serial X --test-mode` then
 `python -m lpt.cli finalize --serial X --model E4610 --tier filter-only --recovery-verified`.
 NOT patched in the repo: flipping the interpreter preference based on an agent shell's PATH could
 break the owner's interactive runs, which have been succeeding. The safe fix is for the wrapper to
 verify its chosen interpreter can import adbutils before deploying.
