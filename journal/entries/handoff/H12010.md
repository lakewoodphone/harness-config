## 2026-10-21 · ZABZ-YOGA · Owner dictation on the Android filter, documented and checked: four places the memory and the code disagree

The owner began dictating his vision for the filter (Android first) and asked for it documented and
analysed before discussion. Deliverable: `kosher-filter-ai/docs/design/OWNER-VISION-2026-10-21-android.md`,
16 claims with a verdict each, on branch `agent/kf-owner-vision-20261021`, commit `2a1f36b`, pushed.
Docs gate re-run before the commit: **17 of 17**, exit 0, `--write` regenerated INDEX (308 docs) and the
dead-citation page.

The four findings a future session must not lose:

1. **Enhanced FRP has never been armed.** `PolicyApplier.kt:533-550` arms it only when
 `R.string.frp_google_account` is non-blank and that string ships empty (`res/values/strings.xml:735`);
 only the build property `LPT_FRP_ACCOUNT` fills it (`app/build.gradle.kts:63,207`). Every APK so far
 is unarmed. It is one build property, not a feature.
2. **"The shop cannot override" is a policy with a working door.** `PUT /rules`
 (`server/app/routers/rules_core.py:171,223`) authorises on `super_admin` or the webhook secret.
 Either the route refuses customer-scope writes or the written customer promise changes.
3. **The Android models are hardcoded**, which is the standing "never hardcode a model" rule broken in
 the client: `MlModelProvisioner.kt:50-65` pins three third-party URLs (GantMan release zip, Hugging
 Face NudeNet, MediaPipe pose) and each classifier pins a `MODEL_FILENAME`. A model swap is an app release.
4. **The split tunnel ships behind a cohort flag.** `DnsFilterVpnService.kt:192-208` enables it only when
 `rolloutEnabled && cohort == "split_tunnel_candidate"`, with rollout/control percentages. The
 owner's "only unknown traffic goes through the proxy" is true of an experiment, not of the product.

Also verified and worth keeping: the partner-pressure mechanic is built further than the owner
remembered — `trust.py:1108` caps the score below the stable band when `unpartnered`/`sponsor_only`,
with escalating reminder copy, and `partner_composition.NON_GUARDIAN_DELAY_HOURS = 48`. The parent/child
concept exists server-side as persons with per-person rule overrides (`routers/owner_people.py`), but
nothing in the phone's setup branches on "this is a child's phone" — there is no child flag in `android/`.

Binding constraint restated in the doc: the production broker still has `phones=0, households=0,
tenants=0`; every decision in it is the hourly canary or `zabz-desktop`.
