## 2026-10-18 19:54 UTC · ZABZ-YOGA · Estate search round 15: a per-source timeout that never fired, and the Copilot backfill measured rather than built

Continues **H8361**, **L8830-8832**.

## The defect that mattered: the timeout never fired

\_run_stream\ enforced its deadline only AFTER the adapter's stream ended (\p.wait(timeout=remaining)\). An adapter that stayed alive and produced slowly therefore ran **forever**: measured on ZABZ-TECH, the \chat:vscode\ adapter ran **97 minutes against a 900 s limit** with **5,461 s of CPU**, writing 1,325 documents and never finishing. Because that source never finished, the host never pushed, and ZABZ-TECH's corpus went stale — which /health then reported correctly ('last pushed 104 min ago, expected every 60'), so the alarm was right and the cause was underneath it.

Fixed with a watchdog timer that kills the process at the deadline; the run then reports the timeout through the existing path, with the count of documents already written.

**What this means for chat:vscode on the desktop:** its history takes hours. It is now bounded at 15 minutes per run and makes partial progress each time. If it never catches up, that source needs its own longer window or a chunked read — recorded, not hidden.

## The Copilot backfill: measured, and deliberately not built

- The archive holds **43,497 copilot-chat files, 26.9 GB**; **107 exceed the extractor's 50 MB ceiling** (largest: a 2.39 GB \local-index.1.db\ — Copilot's own index, not a conversation — then a 479 MB chat and two ~400 MB chats).
- The 526 sessions missing from the table are mostly those oversized chats plus older ones (374 of 526 in Nov 2025 - Jan 2026).
- The small ones the estate's reader returns have \.requests: []\ — empty sessions.
- A full sweep stalled on a **220 MB** session; at minutes per large file it is an hours-long job.

**Decision:** not built. Closing it needs a chunked parser for very large chat files, and the value is low — the DSH corpus (which is what he actually uses now) is complete at 8,623 of 8,637 ids, and Copilot use stopped on 18 September.

## The mistake

I wrote my own object-store reader first (sha path, zstd via CLI, JSON parse) and hit 513 'unreadable' files — when \ ranscript-archive-server.py --read\ already existed, was documented in the estate's AGENTS.md, and did it in one call. **Search for the existing reader before writing one.** Recorded as L8832.
