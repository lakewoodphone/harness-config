## 2026-09-15 19:31 UTC · ZABZ-TECH · LPT site->broker session wiring: the site now calls POST /owner/auth/lpt/session (worktree f4bd486)

The site now calls the broker's LPT session route. Gap closed, worktree agent/site-lpt-wiring, commit f4bd486 (not pushed).

CHANGED
- web/server/app/identity.py — LptUser.is_verified: bool = False, read as `identity.get("isVerified") is True`. Only a literal boolean true verifies; absent/null/"true"/1 are unproven, because the broker binds an unlinked subject by email and that is where an unverified address could attach a household to the wrong family (D38-09).
- web/server/app/broker_client.py — BrokerClient.lpt_session(lpt_subject, email, is_verified) POSTs exactly {lpt_subject, email, is_verified} to /owner/auth/lpt/session with header x-lpt-site-secret. Constants BROKER_LPT_SESSION_PATH / BROKER_LPT_SITE_SECRET_HEADER / REASON_SITE_NOT_CONFIGURED / REASON_LPT_NOT_LINKED / REASON_LPT_NOT_HOUSEHOLD_ADMIN. Unverified and unset-secret both refuse BEFORE the call; the broker's own refusal code is passed up unchanged; 401/503 -> not_configured, 5xx -> unavailable, authenticated-but-cookieless -> unavailable.
- web/server/app/config.py — SiteConfig.lpt_site_broker_shared_secret from SITE_LPT_SITE_BROKER_SHARED_SECRET. It is the broker's LPT_SITE_BROKER_SHARED_SECRET, its own value per D38-09a #2, not the LPT SSO secret. No broker setting added.
- web/server/app/main.py — login_form LPT branch: verified assertion -> lpt_session -> on success rotate the site session, adopt the broker cookie (server side only), redirect /onboarding; on refusal render the broker's precise code. Unverified refused before any call. New LOGIN_ERROR_MESSAGES keys lpt_identity_not_linked, lpt_identity_not_household_admin, site_not_configured, refused.
- Docs: web/README.md, deploy/site/.env.example, deploy/site/README.md.
- Tests: web/server/tests/test_site.py +14 rails; test_account_pages.py and test_public_pages.py make_config helpers gained the new required field.

EVIDENCE
- `cd web/server && python -m pytest tests -q --basetemp=./_pt_lpt -p no:cacheprovider` -> 219 passed in 9.51s (was 219 green; the new required dataclass field broke 131 tests in test_public_pages.py before the helper was updated — the full suite caught it, not my new tests).
- End-to-end probe through TestClient with both HTTP fakes: assertion arrives -> POST /owner/auth/lpt/session -> broker 200 + set-cookie -> site session rotated, /api/session/me authenticated true with household_id h1, /api/onboarding/state stage done.
- Broker refusal probe: 403 {refused: lpt_identity_not_linked} renders the message and leaves authenticated false.

BROKEN / UNVERIFIED
- Nothing was tested against live LPT and nothing can be: no isVerified has ever been observed from the real assertion endpoint, and production's customer portal is off (D38-08 probe table). The field name and the request body are read from LPT's route source and server/app/routers/account_owner_lpt.py, not from a live response.
- The site's own env example is the only place the new value is documented; docs/config-reference.md is generated from server/app/config.py and lists no SITE_* values, so it is unaffected by design.

NEXT
