# H509 — round 25: the deploy-verification gap is now mechanised, and tested in both directions

## WHY THIS EXISTS

The gap between **"I wrote it"** and **"it is running"** cost this session more time than any logic bug.
Three failures, all in that gap:

1. **A 33 KB stale copy deployed over the live 89,945-byte sync tool.** It reported success and passed
 `ast.parse` — correctly, because a 28 KB skeleton of a 90 KB program *is* valid Python. Found hours
 later by **running** it, by which time the pre-create guard was gone.
2. **Two rounds spent "fixing" a guard that was never deployed.** The authority's copy had 0 occurrences
 of the marker; mine had 1. Every logical change was applied to a file nobody was running, and
 "exactly zero observable effect" was misread as "wrong logic" — twice.
3. **The owner digest was edited, committed, and never deployed.**

## WHAT LANDED — `harness-config 7229031`, mode `100755`

`scripts/verify-deploy.sh` — a manifest of **11 load-bearing deployed artefacts**, each with a marker
string that exists **only** in the version you meant to deploy. One probe per entry returns size, mtime
and marker count. **A missing marker means the host is running a DIFFERENT version** — which is the
finding. Generic markers ("import json") would prove nothing, so each entry names an identifier
introduced by the specific change.

```
✅ four-surface verifier (collision guard) (67861 B, 2026-09-17T17:24Z, marker x1)
✅ repair tool (F04 sourcePath writer) (36276 B, 2026-09-17T17:26Z, marker x2)
✅ comms surface (17636 B, 2026-09-17T16:27Z, marker x3)
…
✅ all 11 deployed artefact(s) carry their expected marker
```

**Exit 0 all markers present · 1 a marker missing or file absent · 2 could not measure.** An
**UNMEASURED deploy is reported as a failure, not a pass** — an empty result is not health, which is the
rule everything else in this system runs on.
