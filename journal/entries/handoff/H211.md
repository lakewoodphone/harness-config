## 2026-09-14 23:42 UTC · ZABZ-YOGA · config-sync no longer freezes silently: diverged commits are preserved on a side ref (48665e7); secratary still 25/9

**CHANGED.** `scripts/autosync.ps1` + `scripts/autosync.sh` no longer let a
diverged machine freeze silently. Commit **48665e7** (in origin/master, pushed
from ZABZ-YOGA). Measured defect: any local commit the remote lacked made
`git pull --ff-only` refuse, the run ended 'attention'/1, and that machine kept
its OLD config, presets and launcher forever - and could not receive a
model-failover flip, so it could sit on a dead model.

New behaviour: on AHEAD, attempt the ordinary push first (if it is accepted there
is no real divergence and the machine has simply converged). Only if it is
REFUSED, push the local commits to a normal non-forced
`refs/heads/diverged-<host>-<UTC date>` and stop reporting. Still no merge,
rebase, stash, reset or force - the refusal to guess is unchanged, only the
destination changed. Every run also writes
`~/.dsh-sync-status/status.json` ({updated, result, detail, behind, ahead,
branch, local_commits_preserved, ...}). The per-host record at
`~/.harness-config-autosync/status.json` keeps its shape (plugin-attention and
the kernel sentinel read result/detail/at from it; fields were only added).

**IN FLIGHT.** The fix is a bootstrap problem for a machine that is already
frozen: it cannot receive its own fix while it cannot fast-forward. So the fixed
Linux script was copied out-of-band and run once against the real production
checkout - see EVIDENCE.
