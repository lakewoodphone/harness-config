### The design improvement that came from wiring it

The device does not know its own household id (only the E2EE opt-in stores one), which at first looked
like a blocker. The right answer was better than working around it: **`household_id` became optional and
the broker derives it from the phone**, treating any supplied value as a *claim to check, never an
instruction*.

Two properties from that one change:
- the handset needs no household identity at all, so there is nothing for it to get wrong;
- the broker **trusts nothing the client says** about whose decision it is filing.

A mismatch, an unknown phone and a phone with no household all return the same 403 wording, so households
cannot be enumerated by watching which refusals differ — and a refused report writes **no audit row**,
because a 403 that still recorded something would read in the trail as though the decision had been
accepted.

Declines are reported too. Half of what a parent decides would otherwise never leave the phone.
