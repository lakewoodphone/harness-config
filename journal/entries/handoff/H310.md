## 2026-09-15 21:48 UTC · ZABZ-YOGA · fleet-dashboard honesty: dispatch/poll/health truth + the three phantom endpoints

CHANGED
- `deploy/fleet-dashboard` on branch `fix/fleet-dashboard-honesty` (worktree `_worktrees/psm-fleet-honesty`, based on origin/master 4b0170d4).
- Dispatch honesty: every command route returns through `routes/common.py`, so HTTP is 200 only when the enqueue reached NanoMDM, 207 for a partial fleet-wide run, 502 when nothing landed (0 of 3, 3 of 3, no known devices) and 503 when the device list or DB cannot be read. Body always carries `attempted`/`succeeded`/`failed`/`failures`.
- `/poll`: counts real per-device results and returns a REAL `ingested` (via new `services/ingest_service.py`); `devices_polled` removed because it counted attempts.

- New `routes/fleet_health.py` implements the three paths the UI called and got 404 (`/api/v1/fleet/health|stats|alerts`), derived from the dashboard's own registry, every response `derived: true` + `source_note`, unmeasurable metrics `null` + named in `unavailable`.
- Frontend: `client.ts` `ApiError` carries the parsed body; `describeDispatch`/`describePoll` in `shared.tsx` decide the toast; `ConfirmDialog` requires typing `LOCK <count>` / `RESTART <count>` / `ERASE 1`; OverviewPage tracks per-source failure, freezes "Last updated" when everything failed, and renders "not measured" instead of "—".
- `deploy/waze-mdm/docker-compose.yml` (fleet-dashboard service block only): healthcheck now probes `/api/health` (was `/`), plus optional `FLEET_API_URL`/`FLEET_API_TOKEN` passthrough.
