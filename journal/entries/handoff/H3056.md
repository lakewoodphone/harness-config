- **The one-line fix with the biggest effect:** `remote-script.js` captured the target hostname with

 host came back EMPTY and the provider refused the run at the location check **after the child had
 done its work**. That is the whole of `secratary`'s **0 completions in 19 placements**. Fixed to

- **The location policy.** A mesh child that did not open with `MESH-HOST:` had its **entire answer

 transport's host is now authoritative, a missing model line is a note and the run completes with its
 answer preserved, and a *disagreeing* line is still a hard failure.
- **Placement.** Idempotency key on `POST /place` (TTL 300 s, 256 entries) so a retry cannot leak a
 second lease; bounded client retry (3 attempts, jittered 250–4000 ms); distinct error classes so
 "reached but silent" no longer reads as "down". Journal `P2668`, `docs/mesh/126`.
- **Ranking.** A cold-start read miss no longer demotes a node (only a still-slow *second* attempt
 does); a node whose transport is UNMEASURED can no longer outrank one measured working; a node at its
 fleet cap is queued (`min(4, accepts.maxChildren)`, the `P2538b` shape).
- **Two lease leaks closed** (`docs/mesh/121` found them): the broker node-lookup miss threw after the
 lease was issued, and `transportFor()` sat outside the only `release()` path. Both now release and
 say so.
- **The brief ceiling.** A Windows command line caps at 32 767; the script is base64'd at ≈2.67×, so a
 task over **≈11 400 characters** fails with `spawn ENAMETOOLONG` and the child never starts — and the
 fleet's own 8-part brief standard exceeds that. Measured, then reproduced by accident on the dispatch
 of the brief written to fix it. Journal `L3063`. Task now keeps its newlines, large tasks do not
 travel as one argv word, and an over-limit task is refused legibly.
- **Mid-flight capability, at our layer:** `lib/child-registry.js` (durable per-child record) and
 `lib/mesh-tools.js` (`mesh_children`, `mesh_message`, `mesh_interrupt`, `mesh_collect`), plus the
 child-side contract in the task preamble. `mesh_collect` works **after** the transport that ran the
 child has died. **This is a mailbox read at the child's checkpoints, NOT engine-native adjacency.**
- **`mesh-broker.mjs` now threads every key `loadConfig` parses** (`retryTimeoutMs`,
 `requestIdTtlMs`, `fleetConcurrentLeaseCap`) instead of silently ignoring three of them.
