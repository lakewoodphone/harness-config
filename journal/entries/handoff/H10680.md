### The ruler

`scripts/owner_questions.py` asks "does anything come back, fast". It cannot say whether the answer is
the ANSWER. So `scripts/relevance-eval.py` + `config/eval-questions.json` were written: twelve
questions whose answering document is known, scored hit@1 / hit@3, exit non-zero below a floor. Both
are committed, so the next change is judged by the same ruler.

**Baseline: hit@1 1/12 (8%), hit@3 2/12 (17%).** The surface was fast and complete and kept returning
conversations — "the systems register of machines" gave a VS Code chat while `000-SYSTEMS-REGISTER.md`
sat one place away; "the search audit" gave a chat and a test file; "why did the mesh broker move"
gave a kernel header. Sessions and chats are transcripts: they contain nearly every phrase and are
named after none of them.

### Five changes, each measured

1. `merge()` adds a prior proportional to how much of the question a hit's NAME accounts for.
2. A name covering at least half the question **leads** (a band, not a nudge — one rank of lift cannot
 pass ten hits above it).
3. `_path_hits()` asks the title/path trigram index about **every significant word**; it only ever
 asked for one-word queries, which is why the register and the mesh decision were invisible.
4. A session's `title` is a SNIPPET and no longer counts as a name.
5. `_name_rank()` orders the store's own results: basename-without-extension IS the term (6), basename
 contains it (3), title contains it (2), only a directory contains it (1); bm25 stays the tie-break.

**One experiment made it worse and was reverted** (`7646c6a`): ordering the name index "highest
coverage first, newest second" cost a rank-one hit and pushed `owner decision queue tool` from 1 to a
miss. Kept in the record rather than deleted.

### The deploy that lied — L3877

For forty minutes three of those changes measured as exact no-ops. They had never reached the process:
`git merge --ff-only` was refused because files I had `scp`'d onto the box matched files the merge
wanted to create, and `2>&1 | tail -1` showed the `git fetch` line instead of the refusal. `git reflog`
proved it — `HEAD@{0}: merge` was four commits old. Rules now: never scp into a tracked path; never
pipe a command whose exit code matters; prove a deploy with `git log -1` in the checkout the unit runs
from **plus** a grep for a string the new code introduced.
