## THE ANSWER (for the next session, so it is not re-derived)
- Voice input is off **because of a deliberate temporary rollback on 2026-06-14**
 (`audit-logs/2026-06-14_171829.md`, "DRN-50 Microphone Rollback"): *"User chose the safer temporary posture …
 and defer Waze/keyboard voice input until a controlled physical retest can prove it does not reopen broader
 Siri/bypass behavior."* **The retest was never run in four months and no later document records a decision.**
- Four switches, read live off the `commands` table today, not from the repo: `allowDictation=false` (hides the
 keyboard mic), `allowMicrophone=false` (**not an Apple key at all** — absent from the 210-key published
 Restrictions schema at Release-v27.0), `forceOnDeviceOnlyDictation=true` (already correct), and DNS blocking
 `guzzoni.apple.com` (Apple's label: "Siri and dictation requests").
- **The Apple half is answered: turning dictation on costs the filter nothing on the network.** Apple documents
 dictation as on-device with no internet connection in many languages; `guzzoni`/`smoot` stay blocked; no host has
 to be opened. The Waze half needs one physical test — the engine Waze's own mic uses is documented nowhere.

## IN FLIGHT
- **The physical retest is written but NOT run** (`05-test-plan.md`): nine checks on DRN 2003, one profile swap,
 rollback in two commands. It needs a human holding a phone; four of the nine checks are unanswerable from a shell.
- Owner question: whether a sold LPT NAVIGATION device should have a working microphone at all. Recommendation in
 the dossier: test first on the test unit, then decide.

## BROKEN
- **The repo's DNS filter is not the filter that is running.** The live container blocks **no** broad Google roots
 (`googleapis.com`, `gstatic.com`, …) although `doh_filter.py` and `docker-compose.yml` list them, and it *allows*
 `gsp1.apple.com`, `gsp10-ssl.apple.com`, `gsp53-ssl.apple.com` which the repo lists as blocked. Anyone predicting
 device behaviour from the repo predicts a device that does not exist. Filed, not fixed — changing the live filter
 is not a documentation change.
- **`allowMicrophone=false` has been in every shipped profile since 2026-06-14 claiming a protection it does not
 have.** iOS ignores unknown keys. Either remove it or replace it with the documented mechanism (declarative
 `com.apple.configuration.app.settings`, per-app microphone default, iOS 26.4+).
