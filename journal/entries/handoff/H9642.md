## 2026-10-19 17:49 UTC · ZABZ-YOGA · Owner text round 9: two defences where one deleted - the reminder filter kept a real money reminder pending forever, pre-empting the gate rescue

## Addendum 8 to H9513 (round 9) — two defences where one deleted: the reminder filter pre-empting the rescue

### The finding

`tool_factory.send_due_reminders` kept a reminder **pending instead of texting it** whenever the
message named a path, a file or a task row:

```python
if re.search(r"(?:lpt-hub|docs/|/home/|~/|\.md\b|\.py\b|\btask\s*#?\d{3,})", msg):
 remaining.append(r); continue
```

That was correct when it was written — a work-order body is not a message for a human and nothing
else was available. Since the relay learned to **rescue** such a body (commit `864e7da4`), the
filter deletes what the gate would have delivered.

**Measured over the real reminder bodies:** the filter drops

> *"Pay Yisroel Weinberg 597.29 net CASH settlement … Record date+amount in
> lpt-hub/docs/operations/payroll/Weinberg-2026-09-28/ and append to the wages table."*

which the rescue turns into `"⏰ Reminder: Pay Yisroel Weinberg 597.29 net CASH settlement."` — 60
characters — and the guard then **SENDs**. A money reminder, kept pending forever, for a reason the
gate already solves.

### The fix, and why it cannot be "let the gate refuse"

The filter is replaced by the same decision the gate makes, computed **before** the send:

```
rescue the body → still reads as internal prose? → keep it pending
 → otherwise → send the rescued text
```

It cannot simply pass the body through and let the relay refuse it, because `send_owner_update`
marks a reminder sent only when the result is `ok` — a body the gate refuses stays pending and
retries, which is the documented 840-refusal storm of one 321-character reminder. **The decision
has to be made before the send.**

### Verified in the app's own context, not a copy

- `app.owner_text.owner_text_relay_module()` loads the relay; `_rescue_reminder` present.
- `owner_recognized_numbers(settings)` → `['+18483897895']`.
- Weinberg body → rescued to 60 chars → `internal_prose()` returns None → **sends**.
- `"⏰ Reminder: VS Code session: present ONE numbered owner-approval ask …"` → the rescue says
 *"rewritten body still reads as internal prose ('present ONE numbered'); left for the guard"* →
 correctly stays pending.

Falls back to the old regex if the relay cannot be loaded, so a missing relay cannot start texting
work orders. `tool_factory.py` parses, `company-api` restarted, `/health` **200 at 0.027 s**, no
error lines in the start.

### The pattern, now three times in this programme

1. The gate refuses an instruction-shaped body → the reminder is lost → **rescue at the gate**.
2. The census measures around the gate → it flatters → **measure through the pipeline**.
3. The producer pre-empts the gate with its own drop → **one defence, at the layer that can repair**.

The rule of record: *a gate that refuses is a message lost; the repair belongs at the producer.*
