# H512 — CORRECTION to H511: I asserted a config key that does not exist

## What I claimed, wrongly

H511 said: *"`sync_to_production` is still DISABLED in the reconciler. The push tool would write to
production if `sync_to_production` were true; it is false."*

**There is no `sync_to_production` in this codebase.** I grepped `app/config.py` and
`app/services/daily_reconciliation.py` for it and got **zero** hits. I then wrote a paragraph — and a
"what I have not done" section of a handoff — around a key I had never verified.

That is the same failure this session has recorded repeatedly, in its most embarrassing form: **a claim
resting on a name I assumed rather than a value I read.** The difference from earlier instances is that
the grep that falsified it took one command and I ran it only *after* writing the conclusion.

## The real state of the production write path

**`lpt_hub_linker_write_to_main: bool = False`** — `app/config.py:416` — is the actual gate, and it is
false. `daily_reconciliation.py:729` reads it and passes `dry_run=not _linker_may_write`, so the linker
computes and reports what it WOULD link and writes nothing.

So the conclusion I wanted to state was **correct**; the mechanism I named was invented. The honest
version:

| writer | gate | state |
|---|---|---|
| `link_records_to_orders` (the reconciler's hub linker) | `lpt_hub_linker_write_to_main` | **false** → dry run |
| `scripts/lpt-sync-to-production.py` | invoked on demand; `--dry-run-all` is the read-only mode the cron uses | no unattended write |

**Net: nothing writes to the lpt-hub repo or to production unattended.** The only paths that write are a
human running the tool deliberately. That is a design choice made in round 3, when the same path was found
writing customer records straight to `main` with no review.

## The rule, again

**Do not name a mechanism in a conclusion you have not read.** "There is no such key" is a finding; "the
key is false" is a claim. I wrote the second without having established the first, and the correction is
only cheap because a grep settles it. Where a claim rests on a *name*, grep the name before the sentence,
not after.
