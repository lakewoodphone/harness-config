## What I learned that I did not know at the start

1. **`/root/authority.db`'s fleet tables are NOT mirrors.** `waze_mdm_devices` = 2 rows (newest write
 2026-06-26), `mdm_fleet_devices` = 4 (newest 2026-10-05), `mdm_device_locations` = 0. They are a
 separate, near-empty register written only when the company service itself registers a device
 (`app/services/mdm_fleet_registry.py:367` via `fleet_enrollment_lifecycle.py:66`). **The brief called them
 mirrors; that is wrong and it is now recorded.** The only thing they hold that the MDM host does not is
 the owner's two personal phones.
2. **The MDM is authoritative and answers in one query.** `fleet_devices` = 71 rows, one row per device,
 `site` = the fleet. The whole "three fleets" structure is one column.
3. **`device_profiles` is empty (0 rows) while 207 ProfileList replies are on file.** So "which profile is
 installed" IS answerable — from `command_results`, not from the table the schema suggests. Every
 profile claim in my documents comes from the phone's own reply.
4. **`fleet_devices.product` and `.version` are NULL for all 71 rows**, but the DeviceInformation replies
 carry model and iOS for 60. The fleet's iOS spread is real: 8 distinct versions, 17.7.1 → 26.5.2.
5. **The Telnyx cap is 0.8 GB, not the code's 2 GB default**, and DRN 2002 has used 112.93 MB for
 **881 cents** — about **78 cents per GB**, four times the 19.5 c/GB the 2026-08-07 plan assumed. The
 per-device endpoint returns `consumed_data: null` for every SIM while `/fleet/telnyx/billing` returns
 real numbers in the same minute. **Both readings are live and they disagree.**
6. **DRN 2001's line is `disabled` at the carrier while the local DB column still says `disabling`**
 (last written 2026-10-13). The local column is a cache of the last action we took.
7. **DRN 21 and DRN 41 are still one iPhone**, 28 days after `P234`/`H442` recorded it. Also DRN 40 and 101
 have `enrollment_id` NULL although both enrollments exist and check in.
8. **The gemach ledger (WAZE0001–WAZE0045) and the MDM DRN numbers are NOT proved to be the same series.**
 13 numbers are in the ledger and not in the live registry; the registry has 46–55 which the ledger does
 not; the ledger has 12 and 22 which the registry does not. One home-screen photo settles it.
9. **`ssh → docker exec → psql` with INLINE SQL silently corrupts.** An inline
 `to_char(x,'YYYY-MM-DD"T"HH24:MI:SSZ')` came back as `2026-07-05THH24:34:05Z` — the format string lost
 its quotes and produced a wrong number hours before I noticed. Write the SQL to a local file and pipe it.
10. **Python 3.14 t-strings broke my script on the host/container split**: the host is 3.12, the container
 3.13, and a string containing `"T"` after a string literal is a syntax error in one and a string in the
 other. `read`+`edit`+scp is the way to ship a script; never a single-quoted heredoc over ssh.
