### What ships

Every handset pulled a **100,619,093-byte zip to obtain ONE 17,355,548-byte file**. The broker now serves
that file itself:

- `GET /models/artifact/{file_name}` serves a model the broker holds. The name is matched **exactly**
 against a pinned catalogue `file_name`, so there is no path arithmetic to get wrong and `../` cannot
 reach anything. Everything else is a 404, not a 403 — a caller has no business learning which check
 failed, and the only legitimate caller got the URL from our own manifest.
- `hosted_artifact_url(model)` points the catalogue at us **only** when `public_base_url` is published
 *and* the local file's length *and* SHA-256 match the pin — verified once per process and cached,
 because hashing 17 MB on every manifest read would cost more than the download it saves.
- `payload_for()` publishes `served_by` (`broker`/`upstream`) beside the URL, so a reader can see which
 they got rather than inferring it from the host.

### The fail-safe is the design

A broker without the artifact behaves **exactly as today**: upstream URL, route 404. The failure I
refused to create is a manifest advertising a file the broker does not hold — that breaks provisioning
for every phone in the field, which is far worse than a 96 MB download. Seven tests, most of them about
refusal: same-length-different-bytes, length mismatch, missing file, unset base URL, traversal, invented
name, and a real catalogue name with no bytes on disk.

### Placed and proven

On the authority: downloaded the release zip (100,619,093 bytes), extracted the single tflite, placed
`/root/models/nsfw_mobilenet_v2_int8.tflite` at 17,355,548 bytes with sha256
`380f98f7685f9d8a…fab40` — **exactly the digest the catalogue already pinned**. Hosting changes the
transport, not the artifact.

### The last mile, and why it is not automated

The manifest switches to our URL only when the broker has `public_base_url` set, and I could not confirm
it is set on the deployed host. It is **deliberately not derived from `request.base_url`**: a guessed base
behind a proxy would publish an unreachable URL and break provisioning for every phone — the exact failure
this design exists to avoid. One operator step, recorded on the item.

### The merge race cost three cycles

Main moved twice while this PR was green (PR #135 among them), so `mergeable` went CONFLICTING after a
passing run, twice. Each cycle is a merge plus regenerate plus a ~10-minute CI run. The workflow is now:
merge main, `--write`, push, poll until MERGEABLE, watch, merge **immediately** — and even then the loop
can win the race.

### Traps paid for here

- **I committed to the wrong branch for a whole round.** The branch was `feat/quantize-1065` from round 28
 and I never created `feat/model-hosting-1065`; the push failed with `src refspec does not match any` and
 the PR creation saw "No commits between main and …". Renamed and pushed. Check `git rev-parse
 --abbrev-ref HEAD` before pushing, not after.
- **`retry`-style first attempts are cheap; a wrong assumption about a module attribute is not.**
 `model_manifest` imports `settings` lazily, so `catalogue.settings` did not exist and five tests errored
 until the fixture patched `app.config.settings` instead.
