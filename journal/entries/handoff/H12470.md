**Three defects in the shop's own payment flow, all measured this session — they will bite the next job:**
1. **A pay link is reused after the order's total changes.** `getPendingPaymentLinkForOrder` matches on `payment_pages.status=ACTIVE`
 + a `PENDING` payment transaction for the order and **never compares the amount**. The card button takes its price from
 **Stripe's own Payment Link** (`resolveCardPayment` → `plink_…`), and a Stripe price cannot be edited — so once a page is minted
 at 75 the flow hands that same page back for a 79.97 debt, and the body says 79.97 while the button charges 75.
2. **Nothing in the estate can void one pay link.** No `lpt-write` command, no tRPC/API procedure; `deactivateExpiredPayLinks` is the
 only code that expires a page and it answers to its own clock (`ORDER_PAID` / `PICKUP_RELEASED` / `PAST_PAYMENT_WINDOW`).
 The repair was two status flips on rows fifteen minutes old that no customer had seen — `payment_transactions` 3488 → CANCELLED,
 `payment_pages` a0f1b74c → EXPIRED — run from a script with the pre-state asserted inside the transaction and a rollback if it did
 not match, then `lpt-pay-notice draft --apply` minted **64e81d90** at 79.97 (txn 3491, own Stripe link, expires 2026-10-29T17:37Z).
 I asked him before doing it; a production write outside the audited tooling is his call.
3. **`lpt-pay-notice preview` reports the WRONG pay page.** After the new page existed and the old one was expired, preview kept
 printing `pay page EXPIRED uuid=a0f1b74c… amount=75` and never named `64e81d90`. A session trusting it would think the live link
 was dead, or quote the dead uuid to a customer. **Read `payment_pages` for which link is live.**

**Also worth keeping:** the pay-notice draft's own opener is *"Your Qin phone is in for repair"* when the device is **not** in — the
template assumes the device is on the bench. Never send a pay-notice body without reading its first line against reality.
`draft --apply` is idempotent while a draft is PENDING: it hands back the old draft, so a stale one must be dismissed before a fresh
link can be minted. And dismissing a draft does **not** kill the page behind it (verified: page ACTIVE and txn PENDING after the
dismissal).
