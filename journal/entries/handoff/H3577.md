# The pay-before-pickup system was never a product: the message existed, nothing called it, and the test host would have charged a real card

Audited and repaired 2026-10-12 from ZABZ-YOGA against `origin/test` @ `7734e1c88`
and `origin/main` @ `f6abb7ea2`. Branch `pbp2/integration`, PR 372 into `test`.
Full record: `docs/operations/pay-before-pickup-audit-2026-10-12.md`.

## What was actually wrong

`buildPayNotice` rendered a correct, complete message — device, the customer's
ticket number, the tax-inclusive balance, the shop's own `/pay/<uuid>` page, the
6-digit pay-by-phone code and Zelle — and had **zero non-test callers**. The
draft/approve/send pipeline existed only on the unmerged `pbp/w1-notice`, and the
merge that would have landed it was **silently fatal**: `origin/test`'s deferred
`scheduleStatusNotification` called `handleStatusChange(orderId, old, new)` with
no actor, the new 4th parameter was optional, so it compiled clean and
`draftPayNotice(undefined)` returned early. A naive merge would have shipped a
feature that never drafts anything. There was also **no screen**:
`git grep payNotices -- frontend/` returned nothing at either ref.

## Five defects fixed, each reproduced first

1. **The test host would have charged a real card.** `resolveStripePayConnector`
 turned `NODE_ENV=production` + `STRIPE_PAY_CONNECTOR=Stripe_Connector_test`
 into the **live** connector. Both values measured on `lpt-test-backend`.
2. **A Zelle settlement left the Stripe link live**, so a customer could pay
 twice; `getPaymentPage` only stops `ACTIVE` pages, so no later read retried.
3. **"Tell them what they owe" failed at the send.** `payment_pages.paymentTransactionId`
 is UNIQUE and `createPaymentLink` always `create`d; `prepareOweNotice` creates
 the page and the panel's Send created it again.
4. **A replayed phone callback repaired nothing.** Insert, `paymentStatus` write
 and `releaseForPickup` are three statements; a crash between them left a paid
 order reading PENDING and the device unreleased, and the replay returned early.
5. **The actor thread-through and the missing screen** (above).

## Two things the owner asked for on the day

- The closing line now asks the customer to tell us they paid:
 `Please text us once it's paid, and we'll put it out for pickup.` It matters
 most for Zelle, which is invisible to us until somebody opens the bank.
- The Zelle figure already included tax and now cannot stop doing so: pinned by a
 test. `orders.total = discountedSubtotal + taxAmount` (`pricing-summary.service.ts`),
 written by `saved-final-total.service.ts`, and every figure in the message comes
 from `orders.total - settled`. Production: `pricing_config.taxRate = 6.625` and
 `payment_pages.amount = orders.total` on every page checked.
