### Four defects found and fixed after the first handoff

1. **No registry entry ever ran the Copilot parser.** `chat:copilot-cli` has been supported since
 2026-10-18; nothing listed it, so the surface kept a store for a prefix that matched nothing and
 every answer carried `estate:copilot-archive REFUSED`.
2. **The chats adapter's watermark was shared by every corpus.** A `--source all` run marked the
 Copilot files as seen, so `--source copilot-cli` reported `files_skipped_unchanged 1103,
 documents_emitted 0`, exit 0. State is now per source (`chats-<source>.json`).
3. **The adapter's stdout was the Windows code page.** With the watermark fixed it emitted 20
 documents and died on `UnicodeEncodeError: '\u2192'`. Both streams are now UTF-8 with
 `errors=replace` (commit `1f4e2e1`).
4. **THE PUSH POLICY WAS A DOCUMENT ALLOW-LIST APPLIED TO EVERY CORPUS.** Chat, mail and comms
 documents carry the artefact they were parsed from as their path (`.jsonl`, `.json.gz`), so every
 one of them failed the allow-list and was dropped at push time — `1,101 document(s) written`,
 `pushed 0 document(s)`, exit 0. Fixed: the policy applies only to `files:`/`docs:` sources
 (`3b24084`). This is the second reason the centre needed a backfill for corpora the hosts believed
 they were already sending.

### The agent surface

`ps_search(what="files")` and `what="symbol"` ran `fa` on the authority and answered about the

exist on a workstation. `/opt/company/data/tools/search.py` now appends the estate index as a clearly
labelled second answer (`live=false`), with `hits`/`n`/`note` rewritten so the structured fields cannot
contradict the text. Backup kept: `search.py.bak-eskill-20261019T193542Z`. Verified: `read_sessions`
now returns the live negative plus three indexed hits with their hosts.

### The regression, and what caught it

The corpus tripled in an hour and the blind set — 25 of the owner's own questions, mined from
`authority.db` — went from **worst 2,141 ms / 0 problems** to **worst 4,011 ms / 8 problems**. One
store was responsible: `estate:copilot-archive` cost 749–2,982 ms per ordinary answer and was pure
duplication under `scope=all`, where the estate store already searches everything including copilot
sessions. It now runs only for `scope=chats`. Re-measured: **worst 3,303 ms, 0 problems**; the eight
acceptance questions answer in **91–387 ms**. Its first-touch cost also crossed the 4 s store deadline
once the corpus arrived — `warm()` now pays that at boot (`6854549`).

**Lesson worth keeping: the blind set is the only test that noticed.** My own eight questions were
fine at every size; his questions were not.
