### What I got wrong, and fixed

1. **I called a working build a hang and killed it** (L8318 → corrected in **L8319**). The evidence
 that settled it: 30 MB → 1.44 GB in ten minutes with CPU climbing.
2. **`meta.host` is not "where it was indexed".** On a journal entry it is the machine that *wrote*
 it, with 14 spellings in one corpus. `meta.indexed_on` is now stamped at the single point every
 adapter's stream passes.
3. **Dropping a source does not reset the adapter's state.** After `drop --source journal` the next
 run wrote 3 documents, not 5,300; `--full` was required. The same trap would hit anyone rebuilding.
4. **The authority's journal checkout is 674 commits behind** and auto-commits its own writes — a
 second lineage (P3164/H3136/W2799). It was being indexed under the same source id as the live
 copy. `journal:authority` is disabled; the journal now reaches the centre only from the machine
 holding the current checkout, and `/health` says when it last did.
5. **A buffered log reads as a hang.** Python block-buffers stdout when redirected; a healthy
 13-minute `git:local` pass wrote nothing for 13 minutes. The scheduled command is now `python -u`.
6. **The registry validator refused my new field** (`unknown field 'push'`) within minutes. Added to
 the schema rather than bypassed.
