# H502 — round 18: C02 stopped counting credential files as cases, and the customer-credential PII is now visible

## WHAT I FOUND BY READING THE FINDINGS, NOT THE COUNT

C02 reported 48 "cases with no sync record". Reading them, **five were `_credentials-*` files** —
internal artifacts holding customer credentials, headed *"INTERNAL — do not share with customer-facing
docs"*, with no phone, no price and deliberately no sync record. Counting them as cases **buried the 43
files where the statement is actually true**, and the right response to a credentials file is not "add a
sync record".

`_`-prefixed names are now **INFO** ("not a case: internal artifact"); the rest stay **WARN**.

**Measured effect:** C02 `48 WARN` → `43 WARN + 5 INFO`; total WARN `72 → 67`; total ERROR unchanged at
**6**. `lpt-hub 60536213b` pushed, `0 0`.

## THE MORE SERIOUS THING THAT FELL OUT OF IT

The five files hold **customer credentials** and are **TRACKED IN GIT** — verified with `git ls-files`,
not inferred from disk. Introduced by `c5efd646d`, which migrated 177 case files and swept them in.
That is `GAPS-2026-09-16 §D6`.

**Filed as owner-queue #90 (high), and deliberately NOT conflated with #72.** #72 is about
*infrastructure* credentials — an AWS deploy login with AdministratorAccess, an OUTWORQ Twilio token, an
old Stripe key still answering 200, the AI gateway key. These are **customer** credentials: a different
class, and a different risk owner. #72 is our cloud account; this is a customer's account readable by
anyone with repo access.

**Why it needs the owner and not me:** removing a file does not remove it from git history. Genuinely
purging it means rewriting history and force-pushing, which is irreversible and affects every clone —
the authority, ZABZ-TECH, the rescue branches. **I will not force-push this repo on my own judgement**,
and "leave the history" is a real answer if the repo is private and access is controlled. The material
fact I cannot establish is *who can read it*, and my recommendation says so rather than pretending to
know.

## WHAT THIS ROUND ACTUALLY CHANGED

Two things, and the second is the useful one:

1. A check stopped lying. C02's 48 was a true number answering the wrong question, and it hid 43 real
 findings behind 5 irrelevant ones.
2. **A silent PII exposure became visible.** It was already recorded in a GAPS document as §D6 — but
 nothing in the running system surfaced it, and the verifier was actively mislabelling the same files
 as "cases missing a sync record". Now the verifier names them for what they are, and the owner queue
 carries the decision with its options and a recommendation.
