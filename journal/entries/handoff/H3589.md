## THE CAUSE IS NOW FIXED — PR 383, `pbp3/deploy-disk-guard`

A step before the build in `scripts/deploy-backend.sh` that asks the **target** how much room it has,
reclaims the superseded images **for this environment's own image only** when it is short (never the
running image, never `$REMOTE_ROOT/.previous-image`), re-measures, and refuses with both numbers
rather than starting a build it cannot finish. The failure text names containerd and a tarball, so it
reads like a build problem rather than arithmetic — this makes it say the number out loud.

**No test covers it**: the deploy script has no harness. The hand removal is the proof of the
diagnosis; the log line in the next deploy is the proof of the step.
