- **Two defects in my OWN tooling, both found by using it on real work:**
 1. **The gate's `--dry-run` executed DDL and really created those five views.** Python's `sqlite3`
 with the default `isolation_level` opens a transaction only before DML; **DDL runs in autocommit,
 so `rollback()` undid nothing.** Nothing was damaged (views are additive and wanted) but the flag
 LIED, and the next person to point it at a `DROP` would not be lucky. Fixed: DDL is never executed
 in dry mode; it reports `dry-run-validated` with the reason. **L1678.**
 2. The gate refused all five views for having no `affected` count - a row count is meaningless for
 `CREATE VIEW`. It now demands the RULE ("the operation must be able to detect its own silent
 failure") rather than one implementation of it: writes need a count, DDL needs a `verify_sql`,
 and the gate RUNS that query after applying so "created" is a measured value, not an exit status.
