## 2026-10-22 04:42 UTC · ZABZ-TECH · Kosher filter: the MITM CA install reported SUCCESS while installing nothing - HTTPS was never inspected; fixed as a refusal (4cedd33), 764 tests green

## 2026-10-22 06:45 UTC · ZABZ-TECH · Kosher filter: a missing MITM CA reported success — fixed, merged, and HTTPS now says when it is not inspected

`origin/main` = **4cedd33** (merge of PR #125). Ledger **1080 done**. 764 Android tests, 0 failures.

### The defect, and it is the worst shape a failure can take

`installMitmCaFromRepository` returned **`true`** when the certificate was blank:

```kotlin
if (pem.isBlank()) {
 Log.i(TAG, "no MITM CA configured")
 return true // nothing installed, reported healthy
}
```

The caller does `ok = caInstallOk && ok`, so the chrome apply reported a **healthy paste while no anchor
had been installed and HTTPS was never inspected** — the filter's central promise, silently unmet, with
every indicator saying fine.

### The fix was about a decision, not a call

Extracted to a pure function, because the bug *was* the decision:

```
planMitmCaInstall(certificatePem, mitmEnabled)
 -> INSTALL | SKIP_MITM_DISABLED | REFUSE_NO_CERTIFICATE
```

The middle state matters as much as the last: **a deployment that never promised to inspect must not
start reporting a failure.** The refusal is for *"we promised and cannot"*, not for *"we did not
promise"*. Getting that wrong would have traded one dishonest signal for another.

The reason is a constant (`MITM_CA_REFUSAL_DETAIL`), so what it says when it refuses is part of the
contract — a test asserts it names HTTPS inspection, the missing CA certificate, and the broker.

**Five tests, no device-owner mock needed** — which is the point: the branch that was wrong is the branch
nobody could previously reach in a test.

### Honest scope

This does **not** make a CA appear. If the broker never sends one, the device now *says* HTTPS is not being
inspected instead of pretending. That ordering is deliberate: a silent gap is harder to find than a
reported one.

### Traps paid for here, all environmental

- **A killed ssh/gradle job left a `java` process holding the build directory**, and the next build failed
 with `Failed to delete some children. This might happen because a process has files open` — which reads
 like a code error and is not. Fixed with `taskkill /F /IM java.exe` + `gradlew --stop`.
- **Piping gradle through `Select-String` over ssh produces no output until it finishes**, so a 6-minute
 build looks identical to a hung session. Writing to a remote log file and reading it separately is the
 shape that actually reports progress.
- **`$_`, `\"`, and `$LASTEXITCODE` inside a `ssh "…"` PowerShell string each break differently.** The
 base64-script pattern is the only thing that has worked every time; I should reach for it first rather
 than after two failed attempts.
