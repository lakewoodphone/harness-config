## 2026-10-18 · ZABZ-YOGA · Estate search round 33: `scope=all` never searched the estate

Continues **H8686**. Commits `d128a86` (the fix, see the correction below) and `aefd52e` (the record).

## The bug

A search for `existing_field_map` returned four session hits and **no store named `estate` among the
answers** — while the file sat at the top of the estate index. The response's own `stores` list is what
made it visible: five stores answered, and the one holding the document was not among them.

The cause: the fan-out expands `wanted` to **every** scope name when the caller says "all", so

 if "journal" in wanted: # true, because wanted contains everything
 ...journal...

was true and the `elif` chain ran **only the journal slice**. Files, code, docs, mail, comms and git
were never queried by any request that asked to search everything. Everything this system exists for was
absent from the default search, and it had been that way since the fan-out was written.

Fixed by giving "all" its own branch. After: `estate` appears in every answer, and
`existing_field_map` resolves to its own file in **55 ms**.

## Two things found on the way there

- **A name is not prose.** The core consults its title/path trigram index only when nothing else matched,
 so a document whose *name* you asked for stayed behind sentences that used the same words. Single-token
 queries now ask the path index and their matches lead, and path matches win fusion ties (reciprocal
 rank fusion gives every store's first hit equal weight, so the tie was being broken arbitrarily).
- **`meta` is a JSON string in the docs table** and a parsed dict everywhere else. Mixing them raised
 `'str' object has no attribute 'get'` and made the whole feature silently produce nothing — three
 deploys where the code looked right and did nothing.

## And a hazard worth writing down: the repository is shared

My staged `server/esearch.py` was committed **by another process** under *its* message —
`d128a86 "phone watchdog: read the package name, not the directory name"` — which touches exactly one
file and that file is mine. Nothing is lost and the code is verified working, but the repository's log
now describes work it does not contain.

Recorded in `docs/COMMIT-RECORD-CORRECTION-2026-10-18.md` rather than rewriting history under a
concurrent writer. The rule that follows: **commit with an explicit pathspec in one command**
(`git commit -m "..." -- path`), which cannot sweep up another agent's staged work, and read `git log -1`
straight afterwards to confirm the commit is yours.
