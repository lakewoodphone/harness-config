## 2026-09-16 00:24 UTC · ZABZ-YOGA · unified-search: the fleet built it, the core is verified and deployed, the code tree is reindexing

**H-2026-09-15/16 · ZABZ-YOGA · The owner asked for search across everything, fast, and built to stay that way. Fleet of eight built it; the core is verified and deployed.**

## The ask, measured first
`rg -l imei` over `C:\Users\ezabz\code` = **38.8 s cold / 13.3 s warm** across 549,935 files and
73.2 GB. On this laptop the file index **did not exist**, the chat index was **empty**, and
`chatindex.py` crashed on every subcommand. On the authority the 8.10 GB file index had **never been
refreshed once** (`refresh.py --check`: "no successful refresh has ever been recorded"). Of the
company database's 218 tables, **3** had any text index. Of 498 registered tools, **one** searched
anything (comms only). Two inventories (ZABZ-YOGA and secratary) and a web-research pass produced the
evidence.

(git bundle → clone, verified).

## Measured
In-process query latency on a real index: single term **2.6 ms**, two terms 4.8 ms, natural-language
question **13.9 ms**, symbol query **0.6 ms**. Before the strategy ladder that question cost
**1,105 ms** because it fell through to a LIKE scan. Chunk lines are exact to their offsets (575
chunks over 60 real files, 0 mismatches).

## Six defects found by the fleet, all fixed and pinned with tests
1. **Chunk line numbers were wrong at 88% of chunks** (drift up to 249 lines) — the counter did not
 account for the window function moving to a newline boundary. This made "open at line 412" lie.
2. **`stats()` could not return** — `COUNT(*)` on an FTS5 table scanned every row: **157 s** measured
 while a query took 640 ms. The CLI and README were telling every reader to run it.
3. **Prune could delete another source's documents**, and had no guard against an empty stream or a
 partially-read one — absence read as deletion, the failure that has cost this business data twice.
4. **Windows stdout is cp1252 when redirected**, so `--json` died on the first non-ASCII character —
 which is the transport the whole federated path uses.
5. **A 14.3 GB WAL beside a 2.6 GB database** — SQLite's auto-checkpoint can be starved by a reader
 and a starved WAL only grows. Fixed with a size limit plus a `--bulk` rollback-journal load path.
6. **`subprocess.run(text=True)` with no encoding** mangled every remote snippet into mojibake.

## Decisions recorded
**D196** — FTS5 stays, on the evidence that Zoekt has no Windows support in main (restoration PR
still open), ParadeDB/Quickwit ship no Windows artifacts, and Tantivy measured slower. **P203** —
CVE-2026-11822: both hosts run an FTS5 SQLite below the fixed 3.53.2; not exploitable here but must
be fixed before any untrusted data is indexed, and one writer connection per index is mandatory.
**L1676** — SQLite binds a `?` inside `ON CONFLICT ... CASE` to NULL on the INSERT branch, and
`value not in (True, 0, None)` is not a health predicate.
