## The wake-system change, measured and proven
Attempts in the previous 24 h: **475, exit0 268 (56 %), no-proof 125 (26.3 %)**; by `state_after`
**todo 192, done 167, None 49**. The `None` rows were the finding: a shift claimed an item, was killed
before its close step, and `work.py reap` returned the **item** to todo and wrote its own recovery row
— but the **original attempt was never ended**, so the ledger could not answer *"what happened to this
attempt"*, which is the question every proof metric rests on.

`work.py reap` now closes the abandoned attempt in the same transaction, naming the holder and the
expiry, and reports `attempts_closed`. **Proven on a throwaway copy** (the estate has polluted this
ledger before with a test that wrote to a real store):

```
before: ended_at=None state_after=None
reap: reaped {"attempts_closed": 1, "count": 1, "items": [1145], ...}
after : ended_at='2026-10-22T07:22:47Z' state_after='todo' + "CLOSED BY THE REAPER: ..."
RESULT: PASS
```

`work.py selftest` still passes. **Why this half, and not "tell the prompt to close":** a session killed
at its bound cannot run a close step. What can be made true is the ledger's honesty — every attempt now
ends with a state and a reason, whichever process ended it.
