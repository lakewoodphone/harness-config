# 2026-10-14 · ZABZ-YOGA · Round 9: the no-op provider claimed success while sending nothing — and it is the factory default

Goal round 9. State: **`journal/state/work-order-remediation-program-2026-10-14.md`**.

## THE FINDING

Item (3) says fix the notification defect. The Twilio stub was one instance of a **class** — code
calling a removed dependency whose failure is invisible — so the class was swept. It found a worse one.

`NoOpCommunicationProvider.sendMessage` returned:

```ts
{ success: true, externalId: `noop-message-${Date.now()}`, ... }
```

**while sending nothing, and inventing a message id that looks real.** `isConfigured()` returned `true`.
And `getCommunicationProvider()` returns this provider whenever `COMMUNICATION_PROVIDER` is unset —
**which it is in the deployed backend**.

So the documented, idiomatic way to obtain a provider produced **a report of success for a message that
was never sent, with an id a caller could store and later "reconcile"**. That is the mechanism that let
283 finished orders rest at `READY_FOR_PICKUP` with a notification row reading as *"customer told"* and
no message behind it.

**It is the same failure as F4 and worse:** `lib/twilio.ts` at least *threw*. This one was silent and
affirmative.

## WHAT CHANGED — `phone-and-tech-full`, commit `6d29446f7`, on PR #438

* `notSent()` replaces all three fabricated-success returns: `success: false`, with an error naming the
 configuration and both ways out.
* **No `externalId`** — there is no message, so there is no id.
* `isConfigured()` returns **false**. It returned `true`, which is how a caller could ask *"are you ready
 to deliver?"* and be told yes by something that only writes log lines.
* `metadata.recipientType` is **kept**: it is a true statement about what was attempted, and a failure
 that records who it was for is more useful than one that does not.

**Why it is safe:** no production caller uses the factory. The only importer of
`getCommunicationProvider()` is `example-communication-integration.service.ts`; every real sender imports
`DialpadCommunicationProvider` directly. The lie was protecting nothing and endangering the next
developer who followed the documented path.
