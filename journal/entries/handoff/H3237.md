## THE THING THAT COST TIME

I lost 20 minutes and the owner's patience by **confusing ZABZ-YOGA's `C:\Users\ezabz\code` with
ZABZ-TECH's**, which are the same path string on two different machines. Two symptoms:

1. `Copy-Item` reported "cannot overwrite the item with itself" - because the source and destination
 really were the same file, on THIS laptop, while I believed I was copying to a remote host.
2. `scp src "C:/Users/..."` **silently treats the destination as local**, because scp only reads a
 path as remote when it looks like `host:path`. It printed nothing and copied nothing, and I nearly
 recorded success.

Then I compounded it by starting a recursion over all of `C:\` on ZABZ-TECH to find the file. The
owner stopped it, correctly.

**Rules for next time:** use `host:path` for scp, always - a bare `C:/...` is local. And when the two
machines share a directory layout, print `$env:COMPUTERNAME` before claiming which one a path is on.
Verify a copy by hash, never by the absence of an error message.
