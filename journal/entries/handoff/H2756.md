**WHAT THE FOUR WORKSTREAMS DELIVERED:**
1. **Reader card identity (`subagent-1`).** The fix is one expansion: `readSetupIntent` now retrieves with `expand: ['payment_method']` and reads `PaymentMethod.card` (`brand`, `last4`), falling back to `card_present`. **Without the expansion Stripe returns the id alone - which was the whole defect.** `confirmCardCapture` now returns `brand`/`last4`/`cardIdentitySource: 'stripe' | 'unavailable'`/`cardIdentityNote`; an empty or whitespace string normalises to `null` and counts as **no identity**, because `''` is exactly what renders as a blank. **No `•••• 0000` anywhere.** Refusals, idempotency and all money behaviour byte-for-byte unchanged. Service 47, new identity suite 9, adapter 13, arrears 31, billing 50, typecheck 0. It also corrected my brief on a file path.
