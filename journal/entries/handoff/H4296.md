## 2026-10-15 00:10 UTC · SECRATARY-CLOUD · LPT cellular data FIXED — the APN key was the whole fault; fleet pushed, 2007 restored, cold-boot delay open

**CHANGED**
- **The LPT cellular fault is FIXED and deployed.** Root cause: `com.apple.cellular` has no `APN`
 key — the APN string is `Name`, and ours held the label `Telnyx`. Every device wearing that
 profile asked the network for an APN called "Telnyx". **The owner found it by photographing
 Settings → Cellular → Cellular Data Network.** Corrected profile (`Name` = `data00.telnyx`) pushed
 to all seven devices; 2007's filter (siri-dns, webtrap) and kiosk restored and verified against the
 device's own ProfileList — back to its full 14 payloads.
- **Confirmed working on the owner's device**: APN now reads `data00.telnyx`, and Telnyx's log shows
 internet sessions carrying data — **on AT&T (`mnc=410`)** as well as T-Mobile.
- **The AT&T wireless blocklist is REMOVED and the blocklist object deleted** (owner's instruction,
 and he was right). Nothing is blocked on the `lpt` SIM group.
- Journal: L4320 (the APN key defect and the Apple schema), L4321 (the retractions), L4256 superseded.

**IN FLIGHT**
- **Cold-boot acquisition takes ~2 minutes of "No Service"** on 2007. Reported by the owner as a
 customer-facing annoyance. **Not diagnosed — do not state a cause.** The one documented lever is
 the SIM applet's Selection Mode: it is on a manual IMSI pin from tonight's testing, and Telnyx's
 own doc says Manual loses intelligent selection. It should be put back to Automatic.
- DRN 2001 and 2002 have not yet acknowledged the corrected APN profile (pending check-in).
- DRN 2001's SIM is still stuck in `disabling` in Telnyx since 2026-10-13. Do NOT run disable/enable
 on other SIMs — this account demonstrably hangs that action.

**BROKEN / CARRIES RISK**
- **The managed DNS profile sets `AllowFailover: false`** (`waze-siri-filter-dns.mobileconfig`), and
 the web-trap PAC sets `ProxyPACFallbackAllowed: false`. If `mdm.abletelsolutions.com` is ever
 unreachable from a device, that device has **no DNS and no proxy at all** — no data, silently, on a
 customer's phone. Not tonight's fault, but it fails closed on every device we sell. Needs a
 decision: fail-closed filtering vs data that survives.
- `P3929`: still nothing monitors whether bytes actually moved. Tonight's fault was invisible to
 every dashboard for a day and was found by the owner holding a phone.
