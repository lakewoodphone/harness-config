### What landed

`app/routers/owner_level.py` now carries a **separate, optional** modesty ladder level beside the existing
1–3 household level: `LADDER_LEVEL_KEY`, `LADDER_LIVE_RUNG_COUNT = 8`, `LADDER_LEVEL_STRINGS`,
`stored_ladder_level()`, `resolve_ladder_level()`. The read route reports `ladder_level`, `ladder_set`,
`ladder_allowed_levels`; the write route takes an optional `ladder_level` and writes it into `content_profile`
**before** the knob preset applies, so it rides the same path the knobs do.

Three behaviours that are deliberate, not incidental:

- **`stored_ladder_level` is exact and never coerced** — `True` is not rung 1, `2.5` is not rung 2, and a
 stored **9 or 10 is no rung at all** because those were retired.
- **An empty value means "leave the ladder alone"** and returns `(None, None)`, distinct from a refusal.
 Silence must never be read as "choose the strictest rung".
- **Saving a 1–3 level without a rung does not clear the chosen rung** — there is a test for exactly that.

22 new tests in `tests/test_ladder_level.py`; 47 with the owner-level and modesty suites.

### The design decision worth remembering

The obvious implementation — feed the broker's `modesty_level` into the ladder — is a **scale error**:
1–3 knob bundles versus 1–8 attribute rungs. Any mapping (1→3, 2→5, 3→7) is a **policy change that alters
what a child can see**, and it would have passed every test and read as plumbing in the diff. The tests
therefore *assert the two scales differ* rather than merely documenting it, and one asserts every accepted
rung exists in the shipped asset — so the route can never accept a rung the generated policy does not define.

### Traps paid for here

- **The write route and the read route are different paths**: `POST /owner/level` versus
 `GET /owner/api/level`. Posting to the read path returns **405**, which reads like a broken route rather
 than a wrong URL.
- **`pytest tests/x.py::test_name` is refused on this platform** ("Refusing to run the unqualified server
 suite on Windows") — bare filenames only. This cost a cycle for the second time.
- **A household with no level takes the loosening path**, so a first POST lands in the pending-change queue
 and a test asserting the stored value sees nothing. Seed an existing level so the change is a *tightening*
 and applies immediately.
- **`work.py close --proof` is rejected without `--result`**: "a proving command with no quoted output is not
 evidence". Quote the output.
