 still `curl`s Twilio directly, and `P3176` established that is correct: its job is to alert when the
 company API is down, so routing it through the relay would break it exactly when it matters. What
 is open is only whether it *records* its sends, and that needs the owner — it is already in the
 queue (`P3172`).

 holds **0** rows). Wiring it is dead code today; the site is the `INSERT OR IGNORE INTO ask` in
 `main()`.
3. **The digest's ask resolves by inference, not by reference.** Its ref lives in the relay but not in
 its body, and that is deliberate: a `CFO [ask-…]` token in a human text is noise. The documented
 fallback resolves it and tells him which ask it filed against. The CFO's questions do carry the
 token and resolve exactly.

 individually (the relay's dedupe on live traffic, the CFO question-mark A/B, the refusal silencer,
 the settled-answer rungs), but "no repeat has happened since" cannot be observed in the same
