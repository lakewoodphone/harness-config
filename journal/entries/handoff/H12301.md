### The one that mattered: `integrate/level-wire` would have undone a design decision

Item 1120 read *"Integrate origin/integrate/level-wire into origin/main"* — an instruction to merge. I read
the branch first:

- it sets `LEVEL_KEY = "modesty_level"` and clamps that into 1..8 as the ladder's rung;
- `modesty_level` is the **1–3 knob bundle**; the ladder is **1–8 attribute rungs** — so a household on
 knob level 2 would run ladder rung 2, which is exactly the scale confusion 1096's design note refuses and
 which main carries a test against (`theHouseholdFilterLevelIsNotARung`);
- **it touches no Android code** — so it delivers a key the device does not read (the merged
 `HouseholdLadderLevel` reads `content_profile.ladder_level`). Dead on arrival even on its own terms.

It was a **second implementation of 1096**, which PRs #117 and #119 already closed. **Dropped with that
evidence rather than merged**, and filed as **1134**: the loop should check whether an item is already in
flight before building it, and an "integrate origin/X" item should say what X contains and which
implementation wins — it currently carries neither, so the queue asked for a merge that would have silently
reverted a documented decision.
