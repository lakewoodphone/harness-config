### First: I retracted a wrong finding (L12246)

Handoff **H12280** claimed *"22 ledger claims with nothing working them"* on the evidence that
`autonomy-status` reported `in flight: 0 dispatch process(es)` and that no `orchestrator` process, cron
entry or unit existed on the authority.

**They were live.** Minutes later, `work.py show` showed fresh attempts: 1072 attempt 1963 at 22:20:28Z,
1062 attempt 1955 and 1061 attempt 1953 at 22:17:35Z — all `-> None`, i.e. in progress. `in flight` counts
**wake-dispatch** processes only; an orchestrating session claims straight from `work.py` and never appears
in that counter. I also searched for the process **on the authority** when the claimer does not have to run
there at all.

Why the retraction was urgent: the finding said the next step was to check whether `zabz-orchestrator` was
real. A session that skipped that and cleared the claims would have freed 22 leases under a working actor —
manufacturing the duplicate work this system exists to prevent. **Check the attempt table, not the process
table.** `work.py show <id>` is one command and is authoritative.

**The conflict is the reusable part.** Both branches appended tests to the end of
`AntiEvasionPolicyManagerTest.kt`. Resolved by keeping **both** sets — they test different APIs. The two
Kotlin source files merged cleanly.

**Build a merge resolution from the two branch versions, not from the conflicted file.** Git re-labels the
markers (`<<<<<<< ours` after a re-checkout, `<<<<<<< HEAD` before it) and a line shifts, so a resolver with
hardcoded line ranges fails on the second attempt — the first attempt died exactly there. The script that
worked reads `git show <rev>:<path>` for both branches and locates the block **by function name**, then
asserts brace balance and the absence of markers before writing.

### Traps paid for here

- `gh pr checks --watch` exits when the checks it can currently see are done. A workflow that is still
 **queued** is not visible to it, so a green watch with no `android-unit-tests` line did not mean Android CI
 had been skipped — it appeared a minute later. Re-read `gh pr checks` (not the watch) before concluding a
 workflow will not run.
- `[IO.File]::ReadAllBytes("relative")` resolves against the **process** CWD, not PowerShell's location after
 `cd`. Use an absolute path.
- scp to a Windows OpenSSH target failed with "Connection closed" on `host:C:/Users/...`; a base64 payload
 through `ssh` plus `[IO.File]::WriteAllText` worked instead.
