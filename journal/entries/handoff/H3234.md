## 2026-10-05 15:22 UTC · ZABZ-YOGA · The mystery deleter was my own enforcer: New-Item -Force wiped the policy key on every run; fixed and proven with a marker

CORRECTION AND FIX (2026-10-05 11:20) - the missing RDP policy values were wiped BY MY OWN ENFORCER
- For an hour the record said something unexplained was deleting SelectTransport / AVC444ModePreferred / AVCHardwareEncodePreferred / fAllowDesktopCompositionOnServer on ZABZ-TECH, because the enforcement log reported "(missing)" on every run (03:01, 03:02, 10:57, 10:59, 11:02, 11:07, 11:17) while direct reads showed them present and two marker values vanished.
- THERE WAS NO OTHER DELETER. Enforce-RdpPolicies.ps1 began with `New-Item -Path $key -Force`, and New-Item -Force on an ALREADY EXISTING registry key deletes every value in it (measured twice: AVC444ModePreferred=0 and ZabzMarker3=99 both GONE after one call). So the guard wiped the four values at the start of every run, re-added them, and reported "(missing)" - producing confident evidence that something else was at fault. Worse, the key was bare for a window on every run, so a session created in that window got none of the policies.
- FIXED: the key is created only when absent (`if (-not (Test-Path $key)) { New-Item -Path $key | Out-Null }`), the task now runs every 2 minutes (interval PT2M, re-registered after an ssh drop killed the first attempt), and the repair is PROVEN by planting ZabzMarker4=123 and watching it survive two consecutive runs while the log stayed silent.
- Recorded as lesson L-new; docs/remote-access-link-robustness.md section 11(d) rewritten from "unresolved mystery" to the corrected finding, with the measurement and the cost.

STANDING (this round): the launcher is now `mstsc /v:<host>` with settings in Documents\Default.rdp (no .rdp file, so the April-2026 redirection warning never appears); the wrapper has a lock and a 60-second minimum before it calls something a drop; Default.rdp sets dynamic resolution:i:0 so desktopscalefactor:i:150 can take effect; fAllowDesktopCompositionOnServer=0 is a labelled test with a falsification rule.
