### 2. THE THING THAT MAKES THIS CHEAP TO FINISH: IT REPRODUCES LOCALLY

```
pnpm test:frontend:one -- frontend/src/brand/__tests__/brand-assets.test.ts
 -> exit 0, Tests 60 passed (60)
 -> Duration 68.24s (tests 228ms, environment 48.83s, setup 12.58s)
 -> [vitest-pool]: Timeout terminating threads worker for test files .../brand-assets.test.ts
```

**A file of 60 string assertions wedges its worker.** Tests take 228 ms. So the cause is not a heavy or
misbehaving test, not memory, not worker count, not the pool (this line came from `pool: 'threads'`;
with `pool: 'forks'` the same single file also wedges). **The pool experiment was reverted —
`frontend/vitest.config.ts` is unchanged.**

**The real diagnosis: a worker whose event loop never empties after its file finishes.** Vitest waits
`teardownTimeout` (3 s local, 30 s CI), gives up, and then `PoolRunner.stop` -> `ForksPoolWorker.send`
-> `ChildProcess.target.send` throws the UNHANDLED `write EPIPE` that kills the process before any
summary. **The repository knows this** — `test-setup.ts` is nothing but global SDK/socket mocks for
exactly this reason, and it has two force-exit escape hatches that cannot help because they run at the
END of a run that never reaches the end.
