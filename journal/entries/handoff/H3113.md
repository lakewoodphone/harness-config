WHAT THE INSTRUMENT DOES

 ~/.dsh-mcp-health/status.json in the ~/.dsh-sync-status/status.json idiom.
- Exit 0 no give-up / 1 give-up on record for a running engine / 2 cannot-see. A give-up
 older than the freshness window (default 60 min) is reported as history, not state.
- Verified on all four branches: healthy ok; fixture fresh -> mcp-down; fixture aged ->
 ok; missing dir -> cannot-see. Then registered and driven once for real.

THE BOUNDARY I CHOSE, AND WHY
- Detect and make visible; NOT auto-restart. A scheduled task that silently restarts the
 engine would replace a silent tool loss with a silent restart loop, and it cannot even be
 registered here with the privilege S4U needs (L3232). Cost of the residual exposure: the
 tool set can be gone for up to one reboot, or until someone reads the record. The record
 is now queryable in one call instead of requiring this whole investigation.
- If auto-repair is ever wanted, the honest path is: detect -> confirm stable -> restart
 via the launcher's own ensure (not a bare kill), with a rate limit and a written record
 per action. Do not add it inside the detector.
