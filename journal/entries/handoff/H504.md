## WHY THE REPAIR IS A NOTE, NOT A CORRECTION

**The declared phone is not changed.** Not caution for its own sake:

1. **A transposed digit and a second, correct number look identical in the evidence.** Nothing in the
 data separates them.
2. **The declared phone is the join key across every surface.** Silently rewriting it could reattach a
 case to the wrong customer, and **the customer would be the last to know**.
3. A note makes the discrepancy visible **to whoever is about to phone that number** — the moment it
 matters — and keeps the previous value on the record.

The appended note says all three of those things in the case file itself, so the next reader gets the
reasoning and not just the fact.

## THE REFUSAL IS THE INTERESTING HALF

**F03 refuses 23 of the 31**, and the reason is a finding in its own right: **23 records with no comms
behind the phone name a case file that is ABSENT from `cases/`.** It logs the path it looked for, so the
refusal doubles as a measurement.

It will not scaffold a case file: **the case file IS the record**, and creating one from a repair tool
would produce a record with no author and no case facts. That is the same boundary as F02 refusing to
rename a key and call an invalid record valid.
