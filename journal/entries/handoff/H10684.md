### The defect the rollout exposed

Merges had been landing on the authority, but **the workstations had not pulled since `3b24084`**, so
the `chat:vscode --source all` fix existed on one host out of four. Pulling it onto ZABZ-TECH produced
an immediate failure that had been invisible for hours:

 FAIL chat:vscode 0 doc(s) adapter exited 1
 files_seen 1421, files_skipped_unchanged 1414, files_read 7, failures 7

`UnicodeEncodeError: 'utf-8' codec can't encode character '\udd04' … surrogates not allowed`, raised by
`adapters/chats/jwalk.py:225` (`chr(cp).encode("utf-8")` on an unpaired `\ud8xx` escape — VS Code's chat
files really do carry those; a truncated write, an emoji split across a chunk boundary). From seven
files out of 1,421 the consequences were two: those sessions were **never indexable**, and the source
**exited 1 on every hourly run**. Fixed by substituting U+FFFD (`0ac55e7`); the same command now says
`ok chat:vscode 7 doc(s)`.

### Two process facts worth keeping

1. **"Deployed" is a claim about every host.** Prove it with `git log --oneline -1` on each of
 ZABZ-TECH, ZABZ-YOGA, zabz-tech-linux and the authority, and a bundle for the mac mini (its git
 remote is `/root/repos/...`, a path that belongs to another machine — it cannot pull).
2. **A state-file rename is a migration.** The per-source state (`chats-<source>.json`) means the first
 run of each chat source would re-parse its entire corpus — on ZABZ-TECH that is the 4 GB VS Code
 corpus. Copying the legacy shared `chats.json` to `chats-vscode.json` preserved the watermark:
 1,414 of 1,421 files were correctly skipped as unchanged. Do this before the first run, not after.
