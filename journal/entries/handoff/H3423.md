 `Permission denied (publickey)` on five attempts from ZABZ-YOGA and from `secratary-ts`; three keys
 tried from the laptop; the vault `lpt-apps-01` is refused too. The office box holds the **same
 fingerprint** (`SHA256:91iMQc2AFg+sSA1oscDHF9pz7jClBMynfHtRL4rmAKg mesh-hetzner-2026-08-31`) and is
 refused as well, so this is a **box-side access change, not a per-client key problem**. The host key
 is unchanged (`ssh-keyscan` matches `known_hosts`) and the public API stayed up throughout
 (`api.abletelsolutions.com/health` → HTTP 200, `{"ok":true,"autopilot_enabled":true}`). Not
 diagnosed from inside, because the diagnosis is the thing that is blocked.
 **Consequence: the addendum could not be copied to
 `/root/out/migration-review/133-OFFSITE-BACKUP.md`.**
2. **The dead-man switch reports GREEN while the backup is stale if a `running` marker is left
 behind.** `authority-deadman.py`'s `freshness_verdict()` returns `True` unconditionally when
 `/var/lib/authority-backup/running` exists, and v3 removes that file only on success. Reproduced
 with an identical 3-day-stale fixture, varying only that file: with it → `ping … offsite=ok`;
 without it → `fail ping … offsite=STALE`. The same cause returned the success endpoint for a fixture
 reading `status=failed database_sent=no`. Real-world impact: from the 05:43Z cutover until
 06:46:57Z the newest offsite copy was 25 h old and the external switch was green. Fix (not applied):
 treat the marker as live only when its recorded PID exists in `/proc`, and a marker older than ~4 h
 as dead.
3. **The financial ledger's content never reached the authority.** Cloud
 `/root/accounting-data/live/accounting.db` = **16,384 B, integrity ok, one table
 `balance_snapshots`, 0 rows**; the real ledger is **21,995,520 B @ 2026-10-10T10:17Z, on the frozen
 office box only**. The backup faithfully ships an empty ledger (426 B on R2) with a consistent
 sidecar, so a green `accounting.db.gz` does not mean the books are protected.
 `/opt/company/data/accounting.db` is a 0-byte decoy (2026-08-28).
4. **`authority-report-offsite-age.service`'s first invocation failed** — `line 20: HOME: unbound
 variable` (the script keeps the office's `$HOME` references under `set -u`; systemd provides no
 `HOME`). It was made to work by environment overrides in the unit (`HOME`,
 `VENV_PY=/usr/bin/python3`, `VAULT_KEY`). The script still names a venv that does not exist here
 (`$HOME/personal-secretary-mvp/.venv/…`) and `/opt/company/.venv/bin/python -c "import boto3"` →
 `ModuleNotFoundError`, so it works only because of the override. The success is "the service works",
 not "the script works".
