## Addendum 17 to H9513 (round 19) — every door to his phone, and the one that skipped the guards

The three content guards live in `owner_text_relay.submit()`. A door that reaches the phone without
passing `submit()` is a door where quiet hours, credential_request and internal_prose do not apply —
**and every individual guard test still passes.** So round 19 inventoried every door.

### The first pass measured the wrong thing

Searching each transport-calling file for the word "relay" reported **33 "unguarded" files** — most of
which send to *customers* and go through `sms_service.send_message`, the app's declared choke point,
which does call the relay. **A file does not need to name the relay to inherit it.**

### The right predicate: direct transports

**22 files make a direct transport call** (Twilio `messages.create`, `dialpad_send_sms_direct`, a raw
provider POST) which never touches the choke point:

| file | verdict |
|---|---|
| `bin/textsend.py` | names the relay, calls submit — the AI line, covered |
| `app/sms_service.py`, `app/main.py`, `app/autopilot.py` | name the relay — covered |
| `app/family_chat/twilio_client.py` | deliberately separate, with its own owner-leg guard |
| `family_chat_watchdog.py` | reads only, never sends |
| `chaos_tester.py` | **could** text him — scheduled nowhere (0 cron, 0 timers) |
| reconciliation scripts | read status, do not send |

### And one real hole, now closed

```python
app/main.py dialpad_send_sms_direct(to_numbers=[payload.to], text=payload.body, ...)
```

`payload.to` is whatever the caller posts, and that route **never asked the relay**. It logs an
`sms_log` row, so from the ledger side it looked covered. Any caller passing the owner's number would
have bypassed all three guards. Today's callers are customer-facing, so this was a gap and not a live
defect — but it was **the only unguarded door to his phone**, and finding it is what the inventory was
for.

It now does what `sms_service.send_message` does: resolve whether the destination is one of his
numbers, submit to the relay, refuse on a non-SEND verdict — and fail **open**, because a relay that
cannot be loaded must never stop a customer text.
