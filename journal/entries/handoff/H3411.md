**NEW, this round — `usearch.py`: the low-selectivity path is now bounded.**

*`_unranked_scan` did `... WHERE chunks MATCH ? ORDER BY d.ts DESC LIMIT ?`. The sort key is on the
JOINED table, so `LIMIT` cannot bound the work: it reads and sorts EVERY matching chunk. Measured
2026-10-11 on the live index, that statement alone cost **15,071 ms** for the single word `journal`.
The path is now a windowed CTE — take a bounded window of matches on the FTS5 table (a bare `LIMIT`
there IS bounded: measured **2.4 ms**), then order only that window.*

*The guard's cap was `max(200, total_chunks * 0.02)`, which **scales with the corpus it defends**: at
the 2026-09-16 audit's 273,108 chunks, 2% was 5,460 and ranking was cheap; at today's 3,172,071 it is
63,441. It is now clamped by `RANKED_CEILING = 5000`, so `dialpad transcript` (est. 25,095 matches,
previously RANKED at 5,180 ms) takes the bounded path at 304 ms.*
