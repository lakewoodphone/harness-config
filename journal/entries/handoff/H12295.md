### The finding: 1068's last clause is not an Android gap

Its DoD says an approval "applies the change locally **and reports the result to the broker**". The local
half works. The report half **cannot be done today**, and not for a device reason:

```
every /rules/pending route -> _authorize_super_admin_or_secret
 (rules_pending_partner.py:68, applied at 513 and 596)
grep android/app/src/main for 'rules/pending' -> only a doc comment in my own PendingChangeStore
```

So a parent's phone has **no callable route**, `ParentApprovalActivity`'s report callback returns false by
construction, and the screen says so. Filed as **1117** with the security requirement written in: the route
must verify the phone belongs to the **household the change names**, not merely that the token is valid —
otherwise this becomes the feature where a child approves their own change.

### Traps paid for here

 needed a `String` overload. Caught by the host build, not by review.
