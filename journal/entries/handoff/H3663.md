## 2026-10-19 19:44 UTC · ZABZ-TECH · Grading exists: functional computed from evidence, cosmetic supplied by eye, overall = worse of the two; all five are C pending the keypad sweep

Owner asked whether the phones can be graded. Yes - with one computed grade and one supplied grade, kept separate because only one of them can be computed.

Built `lpt/condition/grade.py` + `docs/condition-audit/grading.md` + `docs/condition-audit/cosmetic-grades.txt`, wired into the register so every row now carries Functional / Cosmetic / Overall.

FUNCTIONAL (computed, no judgement): A = every check passed, nothing unmeasured, nothing warned. B = all blocking checks passed but something warned or a non-blocking check is unmeasured. C = every function proven but a REQUIRED proof is missing. D = a blocking check failed. C is not a criticism of the phone; it is the audit refusing to clear it on what was measured.

COSMETIC (supplied): A like new / B light wear / C visible wear / D damaged, one line per serial in cosmetic-grades.txt. Nothing in this system can see a handset, so this is never inferred.

OVERALL = the WORSE of the two. My first version used min(), which returns the better letter and would have graded a cosmetic A on a functionally B phone as an A. The unit test caught it; it is max() now with the reason written beside it.

CURRENT STATE OF THE FIVE, all C, all for one reason: the keypad sweep has never been run (nobody pressed the keys), so the handset is not cleared.
