## `scripts/owner_questions.py`

The test that found the two worst defects in this program — the sentence-shaped query taking 49 seconds,
and the scoped false negatives — lived in `_scratch` on one laptop. It is now in the repository, with:

- questions mined from `authority.db` (`user/message` events, question-shaped), so the set is never
 chosen by whoever is running the test;
- a `--max-ms` ceiling (default 4000, the store deadline) and a non-zero exit for no-hits or overruns,
 so it can go on a clock;
- the normalised query printed under each line, so a poor result can be traced to the question or the
 corpus instead of blamed on the index.

Documented in `OPERATIONS-ESEARCH.md` under the acceptance section, with the reason in one sentence:
**a test set chosen by the author measures the author.**

## The last full scan on the hot path

`/search` computed freshness with `SELECT MAX(indexed_at) FROM docs` — a full scan of 673,000 documents,
cached 60 s, so once a minute the unlucky request paid for it and answers jumped to **4.7 s**. It now
reads the newest row by `rowid`, which is a seek. That is the same fix already applied to `/health` for
identical reasons and not carried across — the third time this program has had to fix one instance of a
pattern and then find the next.
