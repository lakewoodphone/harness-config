### Landed and verified this round — the objective's item (2), as a primitive

`owner_text_relay` is the one file every door already passes through, so the composing brain went
there rather than into any producer:

* **`compose(item, limit=None)`** — an ITEM dict in, ONE message out. Cut to the ceiling **by
 construction** at a sentence, then a clause, then a word boundary, so the reader never sees a
 fragment and never sees the retired `[cut short - ask me to continue]`. The machine shapes are
 refused *after* composing, on the body: `items, `, `full: `, `data/owner-attention`, `cut short`,
 `ask me to continue`. An unclosed parenthesis is dropped rather than printed. An action-only item
 still composes; an empty one returns `""` — a refusal, not a blank text.
* **`submit_item(door, subsystem, item, ref=…, urgency=…, opens_ask=…)`** — compose + gate + file the
 ask, and it **returns the body it judged**, so the judged bytes and the posted bytes are the same
 object. That is the `L3790` property, built in rather than remembered.
* **`standing_rule_mutes(*classes)`** — a durable class-mute read from
 `/root/.owner-text/standing-rules.json` on **every** submit, keyed on the class the producer NAMES.
 `L4770`'s corollary said the key must be a class the producer can name, not a quotation of the
 complaint; this is that, implemented. It **allows on any read failure** and says so on stderr, so a
 missing file can never be why a message he is owed goes unsent.
* **`/root/bin/owner-text item` and `owner-text compose`** — the same two, from a shell line, so a
 non-Python door (or a `curl`-free script on another host) can reach the front desk without an
 import. `owner-text item` reads the item as JSON on stdin or `--json`.

**The retired digest class is now refused at the relay, for every door**:
`submit(subsystem="owner_attention_digest", …)` → `SUPPRESS`, reason `standing-rule`, with his two
quotes carried in the detail. Doors can no longer out-vote a class he closed.

**Verified.** `/root/text-fix-20261015/probe_frontdesk.py`, run with `OWNER_TEXT_RELAY_DB` pointed at
an isolated store: **20 assertions, ALL PASS**. Every pre-existing verdict is unchanged — first body
`SEND`, identical body immediately `DEDUPE`, `class_hint=suppressed-class` → `SUPPRESS/class`, an
over-ceiling body still recorded as `SEND`/`too-long` (the `L3791` trade, deliberately). The two new
behaviours behave exactly as claimed, and the ask round-trips: open → answered → left the open list.
**The live `relay.db` is untouched by the probe** (checked by mtime and by `owner-text status`).
