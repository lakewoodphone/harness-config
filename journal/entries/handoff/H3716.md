## 2026-10-20 19:02 UTC · ZABZ-TECH · round 24: the ledger-driven waker already existed - both run, and the stale blob source still had a vote (ledger 820)

# H (2026-10-20, round 24) - the estate already had the right waker; both run, and the stale one wins

## What the recommendation got wrong
Last round I proposed a monitor. Reading the sources first (rule: one read proving the thing is not already there)
showed the estate already has a ledger-driven waker: **`ledger-keepalive.py`**, whose docstring says exactly the
right thing - "the thing that DECIDES TO WAKE is still reading the blob... The daily loop must be driven by the same
store it writes to, or 'self-renewing' is a coincidence." It files a shift only when the ledger holds a `todo` item.

What was never done is retiring the blob-driven one. `run-wake-sources.sh` loops over **every** `.py` in
`/root/bin/sources/`, so `project-keepalive.py` (state file) and `ledger-keepalive.py` (ledger) both fire on every
tick, sharing the subject `project:<id>:<utc-date>`. They cannot double-file on a day, but **the first to run wins**,
and the state file is a snapshot shifts are meant to rewrite - not a measurement.

So my "add a monitor" would have been a third opinion on a question that already had two. The right fix is either to
stop the blob-driven source being able to file against a stale snapshot, or to guarantee the snapshot is never stale.
That is **ledger 820**, filed with the measurement, and it is a mechanism change rather than a doc one.

## What shipped
**PR #82 -> `2496abe`**: `docs/AUTONOMY.md` now has the table of both sources, what each reads, how their subjects
collide, the measured cost (a paid shift queued for zero startable work), and the two rules a shift must carry:

- **a shift that finds nothing leaves `remaining` empty** - an empty list is how a project goes quiet honestly;
- **`ignore_blocked_ledger: true` makes the ledger verdict annotate rather than suppress**, and that trade (a flagship
 that can never go quiet versus a wasted shift) is the owner's to make, not a session's.

Gate 18 of 18.

## The general lesson
Adding the correct mechanism is not the same as retiring the wrong one. The estate built the ledger-driven waker and
left the blob-driven waker running beside it, so the older authority kept its vote - and the measurable symptom was a
shift queued against a six-day-old snapshot. **A new source of truth is not in force until the old one is switched
off**, and nothing in this estate checks for that.
