## 2026-10-20T13:25Z · ZABZ-YOGA · The cost programme: the money was in one function, and every instrument had been pointed at the wrong path

Read `personal-secretary-mvp/docs/cost/PROGRAMME-2026-10-20.md` first — it is the state file, with
every knob and how to revert each one. This entry is the transferable part.

### What the previous session could not find, and why in one sentence

It instrumented `agent_worker`, which is the **minority** path. A caller-stack marker at the single
`model_usage` writer (`app/database.py::log_model_usage`) named every spending path in 75 seconds:

```
dept_comms_relationships in=45202 -> autopilot.py:5442:_process_work_queue <- assistant_chat.py:5632:run_assistant_chat
email_classifier in=29132 -> email_classifier.py:275 <- run_assistant_chat
email_actions in=28771 -> email_actions.py:1291 <- run_assistant_chat
```

**`app/assistant_chat.py::run_assistant_chat` is the company's real LLM client**, and it carries the
owner-chat prompt into every background job. A generic email classifier was paying 29k tokens.

### Three measurements that reordered the programme

1. **The gateway inflates nothing** — 1.00×, 27,639 chars in, 27,673 forwarded. The caller builds it big.
2. **The scheduling gate fires perfectly and saves nothing** — 250 deferrals, exact prediction, and
 peak-hour input volume *rose* 12.8 % (31.9M → 36.0M) on the day it went live. It defers ticks;
 the spend is in the ungated work queue.
3. **Half the peak bill is untouchable by any scheduler** — 22.14 of 48.50 weekly peak spend belongs
 to the nine agents that must never be deferred. That half needs routing or the prompt.

### What is live now, and the measured effect

- **Work-mode prompt scoped to the step: 44,551 → 16,097 input tokens per call, −64 %**, measured on
 the calls that followed the deploy. This is the money.
- **Spend guard at the choke point**: cap 45.00, spent 16.17, tier `normal`, zero refusals. It fails
 open by design.
- **Priority ladder at dial 1**: nine protected agents run at peak — including `dept_finance`, which
 the previous binary list was **deferring**, so invoice/payment work was waiting three hours.
- **Every tier resolves from `LLM_MODEL_*` to `deepseek-flash`.** DeepSeek's own catalogue contains
 exactly two ids (`deepseek-flash`, `deepseek-v4-pro`); "V4.1-Flash-1017" is a release name, not an
 id. Stop looking for one.

### Four defects found by deploying and reading, not by the tests

1. **The spend guard could never open the database.** `settings.database_url` is
 `sqlite:////root/authority.db` and `_query_spend` interpolated it into `file:<url>?mode=ro`, so
 every read raised and the guard failed open on every call **while reporting itself present**.
 Fixed with `db_path()` and a regression test that builds a real database.
2. **`agent_worker._estimate_cost` did not contain `deepseek-flash` at all**, so every department cost
 estimate fell through to the retired DeepInfra rate — understating roughly 4×.
3. **`agent_worker` and `main.py` defaulted a model parameter to an id DeepSeek stopped listing.**
4. **`LLM_DAILY_BUDGET_USD=45` beside `LLM_MONTHLY_BUDGET_USD=150`** contradicts itself (150/30 = 5).

### What CANNOT ship from this branch, and why that is a measurement not an excuse

The change that would make deferral actually save money lives in `app/autopilot.py`, and
**this branch's copy is 560,412 bytes against production's 571,030** — a different lineage.
Deploying it would revert 10,618 bytes of someone else's work. `app/workforce.py`, by contrast, is
byte-identical, which is why the ladder could be wired safely there.

### Vehicles built that will pay again

- `scripts/cost/positive_control.py` — proves an instrument can emit before its silence means
 anything. Three prior instruments cost hours of interpreting a channel nobody had proved was open.
- `/usr/local/bin/deploy-window-guard.sh` — refuses a deploy inside a peak band or a declared window.
 Lesson L10626 as a mechanism.
- `docs/cost/baseline-pre-programme-20261020.json` — 33–38/day, steps 78–144/day, tasks 73–140/day,
 frozen **before** anything deployed, so the week can be judged against something.
