## THE PHONE, END TO END, AND EVERY LAYER THAT WAS WRONG

The owner's phone app stopped working because FIVE things were wrong at once, each hiding the next.
This is the full list, because any one of them alone would have produced the same white screen:

1. **The engine never migrated.** `phone-engine.service` + `phone-gate.service` + `tailscale serve`
 ran on the OFFICE box; the cloud had only `phone-redirector.service`, whose own liveness guard
 reads a `token=` line from a log - and the cloud contained a 125-byte file whose content is
 `marker only, the link target is the tailnet harness` / `token=cloud-marker-not-a-credential`.
 So `is-active` was green, `curl` returned 302, and there was no engine behind it. THE MONITOR
 ITSELF WAS THE DECOY.
2. **I first pointed the redirector at this laptop.** Wrong, and the owner said so: the office box's
 profile carried the iPhone tuning. Its `cordis.patch.yml` is **147,534 bytes against the laptop's
 117,202**, with `phone`/`mobile` references and the `yocheved`/`zabz`/`cordis-bg` presets. The
 office profile is what now runs on the authority.
3. **Node 20 was the silent killer.** The engine EXITS WITH NO OUTPUT on v20.20.2; it serves on
 **v22.23.2** (what the office box ran). Pinned in the unit with the reason written in it.
4. **70 client plugin packages were missing** from the profile, so the document loaded and every boot
 bundle 404'd - which is exactly what a white page is.
5. **The workspace state and two path aliases were missing.** `storages/workspace.json` on the
 authority was EMPTY (0 workspaces) while the office one holds 2 - `_scratch` (9 sessions) and
 `phone` (88 sessions) - and the paths it names (`/home/zabz/_scratch`, `/home/zabz/phone`) only
 ever existed on the office box. That is "unable to open default workspace", verbatim. State
 restored (755 MB: sessions, attachments, llm-deepseek, mesh, metrics), paths created, the real
 workspace.json installed with the engine stopped so it could not re-init under us.

Verified final state: engine `:3089` 401 (up, asking for auth), gate `:3086` 200, `tailscale serve`
publishing 443, public `/phone` -> 302 -> `secratary-cloud.tail93e6e6.ts.net` -> 200, all 70 referenced
plugin bundles 200, and 2 workspaces present with both paths resolving after a restart.
