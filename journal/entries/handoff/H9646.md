### The three gates, and which one holds which rule

Exercised directly on a throwaway store:

1. **`app/owner_text.gate(db_url, body=...)`** — the TURN, the quota, the machine budget. Fed four
 bodies it **allows all four**, including `"Reminder: EXECUTE: pay him. Record date in
 lpt-hub/docs/pay.md"` and `"Send me the NJ Premier Business Services login"`. It has **no content
 classes**, by design — but it must never be mistaken for coverage.
2. **`textsend.classify_owner_body`** — QUESTION / RESULT / ALERT / NOISE, bound into the app by
 `app/services/owner_text_classification.py`.
3. **`owner_text_relay.submit()`** — quiet hours, credential_request, internal_prose, dedupe, topic
 cooldown, floor. **Everything this programme added lives here.**

### The single line that carries it

```python
app/sms_service.py:1828 _relay_verdict = owner_text_relay.submit(
 door="app", subsystem=_relay_subsystem, ...
```

That call is the **only** reason the three guards apply to app sends. Nothing declared the
dependency; nothing tested it. Delete that call in a refactor and every individual guard test still
passes while every app message loses all three guards — the exact shape of *"a rule that lives in one
surface and is enforced in none"*.

### K2

`text-health.py` now checks it on every run:

```
OK K2 the app send path still calls owner_text_relay.submit
 sms_service.py: 1 submit() call(s), door="app" present=True, relay referenced=True
```

A **source-level** check on purpose: the alternative is sending a probe text, and on this channel
sending is the expensive thing. It verifies the call exists, not that the relay behaved — behaviour
is covered by the relay's 115 checks, the replay and the gate rehearsal.
