Round 1 left 80 sendable and 16 "compose". Chasing those 16 exposed five separate defects,
each found by composing a real row and reading what came out:

1. ASK DETECTION WAS WRONG TWICE. `ASKS_HIM` only accepted a "?" at the very END, so
 "#830 Should the company's agent work move ...? I'd mint one..." (ask first, clause after)
 read as no-ask. Then, after I widened it, "#810 ... should integrator shifts merge ...?"
 and "#805 ... buy Knox seats ..., or skip it?" still failed because an either/or often has
 no question mark at all. Final rule accepts a question in the first sentence, a trailing
 "?", a mid-body "?", an explicit ask phrase, or "should".
2. THE ASK WAS IN THE LAST SENTENCE. Four genuine questions composed to bare statements
 because the composer took the FIRST sentence and dropped the rest: #511's ask is the last
 sentence of a paragraph about kosher-camera connectivity, #714's is "Is the magnet still on
 the door frame?", #885's is "Cut the checks per push, or fund the real cost?". The composer
 now finds the sentence that ASKS and carries it whole, with only a short context clause.
3. ENGINEERING VOCABULARY. ask_quality refuses any body containing fix/patch/deploy/migrate/
 debug/traceback -- and refuses NOUNS ("the two-name fix", "config fix flagged"). Weakening
 that gate would be wrong: it exists because internal instructions once reached him. A
 message to the OWNER should not be written in engineering vocabulary at all, so composition
 now translates it ("fix"->"change", "deploy"->"release", "allowlist"->"approved list").
4. THE EITHER/OR CUT. #805 is 197 characters and was truncated mid-sentence to "so a factory,
 or skip it and rely on making the reset pointless?" -- unreadable. Then a first attempt to
 keep the alternative dropped the PRIMARY option and asked only "Skip it...?" -- the exact
 wrong half. It now cuts on a clause boundary, keeps the primary option, and only falls back
 to the alternative when nothing else fits.
5. DOUBLED WORDS AND A LOST "?". #890 composed to "Approve the the location filtering change
 ..." and lost its question mark to the ceiling cut, turning a question into a statement. The
 tidy step now collapses doubled words and preserves the "?" through truncation.

## A PRODUCER BUG THAT WAS FILLING HIS QUEUE WITH LLM GAPS

Twelve pending rows were "N notices (date): ..." bundles. Reading their context showed why:
"judge returned no verdict for this message". The mail judge skips a message, the fallback
queues it as `attention`, and `fold_routine_notices` bundles the skipped ones by class and
day. So a model hiccup became owner work -- up to 9 unrelated emails per row, including
newsletters and a family name.

Fixed at the source, three ways, because the first two were not enough:
 * the fallback now emits a distinct verdict `unjudged` instead of `attention`;
 * `unjudged` was added to `_VERDICTS`, because `_coerce()` otherwise maps any unknown value
 straight back to `attention` -- i.e. the first fix was silently undone by the next function
 it met. (I caught this by grepping the write path, not by assuming);
 * the queue filter already drops anything that is not attention/decision, so `unjudged` is
 now excluded from the queue by construction.
PROVEN: `_coerce({verdict:"unjudged"})` -> verdict `unjudged`, kept by the queue filter =
False; and an unparsable model verdict ("banana") still coerces to `attention`, so a bad model
output can never silently DELETE mail.
The three existing judge-gap rows (#670 #696 #697) are tagged in their context and classified
JUDGE_GAP by the triage, so they cannot be texted. The nine money/notice bundles are untouched
-- they carry real content ("$1,000 Zelle", "NJ tax payment") and are genuine digest material.
