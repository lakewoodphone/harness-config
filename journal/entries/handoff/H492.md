# H492 — round 11: the verifier now catches a wrong-lineage sync tool (C10)

## WHY THIS CHECK EXISTS — it is aimed at this session's worst mistake

`scripts/lpt-sync-to-production.py` exists in this project as **two incompatible programs**, and git
keeps handing people the smaller one:

| | size | `--dry-run-all` | guard |
|---|---|---|---|
| old lineage | **28,797 B** | 0 | **absent** |
| live lineage | **92,973 B** | 5 | present |

`git merge-base --is-ancestor` between them exits 1 in **both** directions, and `origin/master` still
carries the OLD one. The correct implementation lives on
`origin/rescue/lpt-sync-correct-lineage-20260917` and on the authority's disk.

**What actually happened, hours before this commit:** a 33 KB stale copy was deployed over the live
tool and **the deploy reported success**. `ast.parse` passed — correctly, because a 28 KB skeleton of a
90 KB program is valid Python. The damage surfaced later as
`error: unrecognized arguments: --dry-run-all`: a production sync tool had silently lost its
**duplicate-prevention guard**, i.e. the thing that stops phantom orders. Recorded as **L2108**.

## WHY IT BELONGS IN THE FOUR-SURFACE VERIFIER

**A corpus can be perfectly consistent and still have its sync path be the wrong program.** Drift
between the four surfaces is meaningless if the tool that reconciles them is not the tool anyone
thinks it is. So C10 sits alongside the surface checks rather than in a separate script nobody runs.

```
C10-sync-tool-wrong-lineage
 rule: size >= 50,000 AND "--dry-run-all" AND "_GUARD_REFUSING_KINDS"
```

**A size FLOOR, not an exact size** — the live file legitimately grows (89,081 → 92,973 when root
validation was added), so the test is "far too small to be this program", which is the real failure
mode.

## VERIFIED IN BOTH DIRECTIONS

A check that fires on the correct file is noise, so both cases were run:

| scenario | result |

An **unreadable or absent tool reports WARN (UNMEASURED), never silence** — an empty result is not
health, which is the rule this whole verifier is built on.
