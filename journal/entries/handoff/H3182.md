TWO TOOLING FACTS WORTH KEEPING
1. **A deploy check that could never pass.** `deploy-rentals.ps1` read the revision with
 `{{.Config.Labels.org.opencontainers.image.revision}}`. The label key has DOTS, so Go templates
 walk nested fields and always answer `<no value>` — so every deploy warned "no OCI revision label …
 after the next deploy this answers itself", which was false and never would come true. Fixed to
 `{{index .Config.Labels "…"}}`; now reports the revision and "image revision matches HEAD". If you
 ever see that warning again, it is this class of bug, not a missing label — verify with
 `docker inspect kg-rentals --format '{{json .Config.Labels}}'` (labels only; NEVER grep raw
 inspect output for env names — that leaks values, see P2836).

 `^[A-Za-z_]+=`, which CANNOT match `R2_BUCKET` (the digit). `docker compose config` proves compose
 injects all four `R2_*` from `/opt/lakewood-rentals/.env`, which the deploy never touches; box and
 repo `docker-compose.yml` are byte-identical. There is no drift to fear.
