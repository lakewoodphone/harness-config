### THE IMPORTANT FAILURE, AND IT IS FIXED
The pipeline's FIRST real run reported `BREAKS=2` for this same candidate, at
`AUTHORITATIVE` tier, claiming our override "is applied to nothing" on
`~/.dsh/profiles/web/cordis.patch.yml:248`. **That was false.** The patch applies: the row is
`disabled: true` in both versions and the engine prints **no** `patched by` comment for a
disable-only patch. Asserting on that comment turned "this patch shape prints nothing" into "our
customization was lost".

Fixed two independent ways: `patch-effect.mjs` asserts the patch's EFFECT (composed value against
the engine's own unpatched `--dump-default-config` arm), and `verify`'s G2 prefers a fresh dump and
prints its disagreement with the stored artifact. Proven in BOTH directions before believing it:
silent on the healthy pair (SAFE, 0 findings), and fires on three constructed real breaks (target
row deleted; `disabled` overridden by a later layer; a patch config leaf absent from the row) plus
the P48 class (upstream adds a default key our restated config would swallow → RISKY with the exact
key named).

### BROKEN / LIMITS (honest)
- **A settings key the candidate silently ignores is undetectable by every gate in this pipeline.**
 Measured: unknown top-level key, unknown nested key, wrong type, out-of-range number and invalid
 enum ALL boot exit 0 with no diagnostic. Only an unparsable document is refused.
- `--dump-config` is **not read-only**: a successful run rewrites `profiles/<name>/cordis.yml`
 (mtime moves, content stays the canonical `[]`). Never hash the profile directory as evidence.
- **There are TWO complete DSH installs on this machine** — the npx cache (240 pkgs, the one
 running) and `~/.dsh/profiles/node_modules` (187 pkgs, real dirs). `dshw.ps1` lists both as
 candidate engine paths, with `dshInstall`/`DSH_INSTALL` first. A single silently-chosen path would
 be wrong.
- **`dsh --profile <name> <anything>` boots the app** — unknown tokens are passed through, so engine
 exit codes are not a guard. (Bare `dsh status` DOES error, exit 1.)
- `dsh --version` reports only the launcher package: **230 of 240** `@deepseek-ai/*` packages are at
 `0.1.5-rc.2` under an `0.1.5-rc.1` CLI (`^0.1.5-rc.1` ranges). Version strings are not identity.
- `state/candidates/<ver>/home/.credentials.yaml` is a COPY of the live credential made by
 `verify.mjs`. It is git-ignored twice over and `state/` is ignored wholesale, so it cannot reach
 git — but it exists on disk and should be replaced by the env mechanism.
