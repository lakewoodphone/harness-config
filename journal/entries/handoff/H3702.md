## The two mistakes that made this take three attempts, both worth keeping
1. **I was checking the wrong tree for a while.** `journal.py` defaults its root to the parent of `tools/`, so
 invoking it by absolute path from the primary checkout measured THAT journal. It reported 0 errors while the
 merged tree carried 65. The errors appeared within seconds of passing `--root`. A check against the wrong tree
 is worse than no check, because it is green.
2. **Editing the heading breaks the entry.** The metadata line carries `sha=` over the heading and body. My first
 pass rewrote the heading to the new id as well as the marker, which invalidated the hash on every renamed entry.
 The journal's own recipe is: filename and marker take the new id, **the heading keeps the original**, and the
 metadata declares `legacy_id=<old id>` - which `check` reports as an INFO, not an ERROR.

A third, smaller one: I renumbered numerically where the journal's own convention for a collision is a letter
suffix (`D17b`, which `pairs` still reports for 121 historical cases). The map records what moved and AUTONOMY.md
says so rather than implying the convention was followed.
