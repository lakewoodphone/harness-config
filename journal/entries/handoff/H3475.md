## FOUND AND FIXED THIS ROUND — self-inflicted, found by simulation not reading

The create-then-prune rewrite (round 9) added the block's **OFF** cron to the
`wanted` set unconditionally, while the code deliberately does **not** write that
OFF job unless `shabbat_device_off_schedule` is on (an ungated device OFF is the
2026-09-11 lockout mechanism).

`wanted` is what the prune treats as "ours and current", so it claimed three
timespecs that were never written. Visible symptom: a create-check reporting
`would CREATE: ['15 13 16 10 *', '26 13 9 10 *', '5 13 23 10 *']` — three OFF
jobs it would never create. Latent, worse-in-meaning symptom: had an OFF job
ever been armed by hand, the prune would have been told to KEEP it, on the
strength of a rule that says OFF is software-only.

Fixed by moving `wanted.add(off_cron)` inside the flag branch. `wanted` now
contains exactly the timespecs the code writes.

**How it was found:** by *simulating tomorrow's 10:00 reprogram against the real
device schedule* rather than by reading the code. Reading it twice had not
revealed it; running it against the actual device timespecs did, immediately.
