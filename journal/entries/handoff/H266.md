THE FINDING IS WORSE THAN "STALE" — THE BUILD CONTEXT IS NOT A GIT CHECKOUT
- `/opt/lpt/src` is the compose build context. `git rev-parse HEAD` → *"your current branch 'master' does not
 have any commits yet"*; `.git/refs/heads` is **empty**; `.git/FETCH_HEAD` empty; `git status` reports **every
 path untracked** — `backend/`, `frontend/`, `node_modules/`, `package.json`, `pnpm-lock.yaml`, all of it.
 The remote is configured and unused.
- **So the 3.78 GB production image cannot be rebuilt from what is on the host**, because nothing on the host
 records what it was built from.
- The tree is also **five to six months older than the image**: `print.ts` mtime **2026-03-12** versus
 `dist/index.js` **2026-09-10**. Only **two** `.ts` files are newer than the lockfile — `routes/sso-assert.routes.ts`
 and `routes/google-oauth.routes.ts` — i.e. hand-edited on the host and baked in.
- Production is therefore **a March-2026 tree + later hand edits + hand-patched emitted JS**, and the running
 image is the only artefact reflecting that combination. The deployed dist was already missing the Part 028
 print guard that the repository has had since 2026-08-31.

THE FAILURE MODE TO FEAR, now written down
A `docker restart` **preserves** the hand-patched dist (it is in the container filesystem). A **recreate** —
`docker compose up -d` after any image change — **replaces it from the image and silently reverts all six
routers to unguarded.** Nothing would report it; the endpoints would answer 200 again and only a probe would
notice. That is worse than the original bug because it looks like a working deploy.

WHY I DID NOT FIX IT NOW
A rebuild is not a build. It needs, in order: (1) reconcile the context against `origin/test`, **diffing each
hand-edited file first** because some may exist only on the host; (2) check migrations against `lpt_prod` — a
database a *prior documented deploy would have destroyed* (**H207**); (3) build with a **named tag** so
rollback is `up -d` rather than a rebuild; (4) post-deploy verification of the six guarded groups, the public
paths, the portal, Google sign-in and `/health/live`. Steps 1–2 carry real data and availability risk, and
this session has already made seventeen production changes. **Deferring is the decision; doing it badly is
worse than the gap.** Recorded as a dev decision, **not** an owner question — no money, customer, legal or
taste input changes any of the four steps.
