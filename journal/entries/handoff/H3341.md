**The answer to "why don't I see them in the website".** The 2026-10-07 phone session was a
photo/note *intake*: 460 bash calls, 54 edits, 31 images read, **zero calls to any order-creating
tool**. Its own tool says so — `intake.py` is "the receiving dock … Nothing here interprets
anything — filing a photo against a case is a separate, deliberate step" — and it has no production
write at all. So nothing was ever going to appear. The photos, notes and the prepared counter-entry

`/home/zabz/repos/lpt-hub/docs/customer-operations/case-media/2026-10-07-intake-notes/`.
Its two delegated subagents also hung 205 s on ZABZ-TECH — the broken mesh node fixed earlier in H3329.

**Why the entry was impossible until tonight, in one line.** `lpt-write` could add a note and set a
status but could not create a customer or an order; and **`website_db.ORDER_STATUSES` had gone stale** —
it still listed `CHECKED_IN`, `IN_REPAIR` and `COMPLETED`, none of which the `OrderStatus` enum has
(`COMPLETED` was deliberately deleted 2026-10-07), while omitting `AWAITING_APPROVAL` and
`AWAITING_PAYMENT`, which it does have. `create_order` **defaulted to `CHECKED_IN`**, so the canonical
create path validated its own default and then handed the database a value the enum rejects. **Every
order created through it failed at the database.** Proven, not inferred:
`select 'CHECKED_IN'::"OrderStatus"` is an error; `'AWAITING_DIAGNOSIS'` is accepted. The same stale
list is copied into `shop_ops.py`, `daily_reconciliation.py`, `chat_action_phone_tech.py` and
`assistant_chat.py` — **reported, not touched**: they are user-facing strings and their own call sites.

**Fixed.** (1) `website_db.py` now reads the vocabulary from the enum at call time
(`_live_order_statuses`) and defaults to `AWAITING_DIAGNOSIS`; backup at `/tmp/website_db.py.bak-vocab`.
(2) `lpt-write customer create` and `lpt-write order create` exist, exposing the app's own
`create_customer` / `create_order` — **not a second writer** — with gates: phone is the identity and a
partial number is refused; a name never selects a customer; two matches are refused and listed; the
status is validated against the live enum; `--case-slug` and at least one `--evidence <path>:<sha256>`
are required; `--custody-unverified` when a photo of a bin is all there is; dedup left ON, with
`--new-job --reason` to override a possible comeback; **no `--total` leaves the column NULL, never 0**,
because a blank is not a price.
