**Two defects the tests caught that would have damaged real customer data:**
1. **CRLF.** All 181 case files were CRLF (independently confirmed: 181/181, 0 LF, 0 mixed; and
 **all 377** sync records contain CRLF). Reading in text mode normalised endings in memory, so a
 one-value repair rewrote **every line of the file** — 181 real customer files, unreviewable
 diff, collision with every other writer. Fixed at the read sites with a regression test, and
 the requirement was pushed to the two writers (`store.py`, `record.py`).
2. **Money-refusal bypass.** `repair` now re-reads each file it would touch, so a caller passing a
 filtered findings list cannot buy a `completed→closed` rewrite of a file still booking
 uncollected money. Refusal is a property of the file, not of the input list.

Design decisions recorded: `repair` is dry-run by default; money contradictions are **refused**,
not coerced (`closed`+`uncollected` is an owner question); `unknown` status is **not** silently
mapped to `other` (opt-in flag, default off); the parser is a narrow line-oriented subset, and any
unhandled shape degrades to an extra finding, never a missed one.
