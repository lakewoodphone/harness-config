## THE SUSPICION THAT WAS WRONG, AND WHY THAT IS A RESULT

`createMockPrismaClient` looked like the worst find yet: `findMany` resolves to `[]`, `count` to `0`,
and `create`/`update` to `null` — **silent empty reads and silent no-op writes that report success**. A
missing model would read as *"nothing there"*.

**It is not reachable in production.** The guard requires `NODE_ENV === 'test'` **AND** a `DATABASE_URL`
starting `mock://` **AND** not `INTEGRATION_TESTS`, and production with no `DATABASE_URL` **throws**.
Verified by reading the guard, not by reasoning about it.

That is worth recording as a result rather than buried: **a verified negative is an answer**, and
inflating a suspicion into a finding is the `wrong-data` failure this program keeps cleaning up. The
sweep's value is the table, not a body count.

## ONE REAL CAVEAT WORTH KEEPING

The two SMS reconciliation stubs are benign **only because nothing treats their zeros as a health
signal** — a property that was checked, not assumed, and which would stop being true the day someone
wires one into a monitor. Separately, `src/index.ts:101` logs
`SMS Status Reconciliation Service started { status: 'success' }` for a service that does nothing. Both
are recorded in the inventory rather than changed: the counts are honest zeros and the return type is a
tRPC contract, so a cosmetic change there buys little and risks a caller.

## THE ARTEFACT

`backend/docs/silent-failure-inventory.md`, in the repo that owns the stubs, carrying the table plus five

production delivery**, and its corollary that **when the default value of a setting selects a stub, the
default is the defect** (`noop` as a default makes "unconfigured" look like "working").

## A TRAP HIT TWICE, NOW RECORDED

`git commit … && git push` in one shell printed **`Everything up-to-date`** while the commit was still
being written by a slow pre-commit hook — and the remote was one commit behind, twice. Caught both times
by reading the remote SHA back. Written up as its own lesson: **a push's own message is not evidence;
the remote SHA is.** It is the same shape as the rest of this program — a success message that is not
the thing succeeding.
