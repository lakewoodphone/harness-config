## 2026-09-23 03:51 UTC · ZABZ-YOGA · I created a live Stripe price 1000x too high and caught it by recomputing the effective rate from Stripe - now one active price at \.00/GB

**CHANGED - I created a LIVE Stripe price that overcharged by 1000x, and caught it. Full account below, because the arithmetic is the whole story.**

**What I did and what was wrong.** Creator script `backend/scripts/create-waze-stripe-objects.mjs` made the metered price with `unit_amount: 1800`. The billing engine posts usage in **MEGABYTES** (`value: formatMb(deltaMb)`, waze-billing.service.ts L604), so the meter aggregates MB and a price is PER MB. 1800 cents/MB = **$18,000 per GB**. Nothing was charged - no subscription references it - but it was live, active, and wrong. The counter-sale agent flagged the trap class; I then confirmed it by **reading the object back from Stripe** rather than assuming.

**Then I got it wrong twice more, and my own verification caught both.**
1. `unit_amount: 18` - which is 18 cents/MB = **$180/GB**, still 10x too high. My verification recomputed dollars-per-GB from Stripe's stored value and printed `$180.00/GB` with a `*** REVIEW NEEDED ***` flag. That is the only reason I did not stop there believing it fixed.
2. Correct: **1.8 cents per MB = $18.00/GB** - and because Stripe's `unit_amount` is an INTEGER of cents, 1.8 requires **`unit_amount_decimal: '1.8'`**. `unit_amount: 18` could never express it.

**FINAL VERIFIED STATE (read back from Stripe, recomputed):**
```
price_1UIhCBLnlgYj1gmTGzhuHpPX active=TRUE centsPerMB=1.8 => $18.00/GB lookup_key=kosher_waze_data_per_gb
price_1UIhBNLnlgYj1gmT1WRyGMdK active=false centsPerMB=18 => $180.00/GB
price_1UIgtWLnlgYj1gmTQIVWirok active=false centsPerMB=1800 => $18000.00/GB
```
Exactly one active metered price, and it is $18.00/GB. Both wrong ones retired AND their lookup_keys cleared - which matters, because a future setup run looking up `kosher_waze_data_per_gb` would otherwise have found and "reused" a retired wrong price.

**A Stripe gotcha worth knowing:** you cannot archive a product's DEFAULT price. The order must be: create the correct price -> set it as the product default -> archive the old one -> then move the lookup_key (an archived price still HOLDS its lookup_key until cleared).
