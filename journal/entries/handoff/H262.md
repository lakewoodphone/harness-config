verified by measurement; one decision left for the owner.

MEASURED FIRST: 11 containers up, restart count 0 on every one, none exited, none unhealthy. The stack is stable.
Every problem found is of one kind — something that silently does nothing — which is why none of them ever surfaced.

FIXED AND VERIFIED
1. Activation Lock: six independent faults, had never worked. Both LPT units (DRN 2001/2002) are now locked,
 confirmed by Apple's DEP API (`SUCCESS` on first contact, `FAILED` on every repeat).
2. Nothing refused to start with missing config, and /health answered "ok" while DEP was dead. Startup now refuses
 without NANODEP_API_KEY / NANOMDM_API_KEY / FLEET_API_TOKEN / PG_DSN; /health returns 503 naming what is missing.
 PROVEN by booting a throwaway container without the key and watching it exit with "Application startup failed".
3. Alerts were raised and NEVER resolved — 152 rows, 62 critical, resolved=0 on all. Resolver now clears a stale
 alert when the device reports again. My first attempt silently did nothing (`resolved IN (0,FALSE)` on an INTEGER
 column, exception swallowed); caught only because the counts did not move. Lesson recorded separately.
4. The fleet sweep cron had been 401ing since 2026-09-10 — a hardcoded token that no longer matched .env, writing
 `{"detail":"Invalid token"}` once a minute (rotated logs Sep 10-14 are each exactly 156 bytes = one per day).
 All four fleet cron jobs now read FLEET_API_TOKEN from .env. Verified: one clean 200 per minute, no Invalid token.
 SEVERITY NOTE: /fleet/sweep auto-deploys `registered` devices. There are none right now, so when working it says
 "nothing to do" — indistinguishable from failing. It was dead for five days and nothing noticed.
5. The database password was written to the container log on every boot. Now passes through _redact_dsn(); the real
 password appears 0 times, the masked form once.
