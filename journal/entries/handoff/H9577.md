### Three rules, and the line I did not cross

Added where the **descriptor names the kind of charge** — the rung's only legitimate condition —
and every target name verified present in the ledger first:

- `withdraw` / `withdrawal` / `atm` → **Cash Withdrawals** (14+2 filings)

`bais medrash east fifth`, `chemed`, `conduent state local solutions`, and `adjust membership fee`

### `provisional` meant two different things

`_from_descriptor` set `provisional = weak or not purchase`, conflating **ambiguity** with **is a
reversal**. Measured consequence: `cdd crdt rvsd case` resolved to Fees & Adjustments with
`purchase=False` and came back `solved=False`, so a question he had already answered would be asked
again.

Now `provisional` means ambiguity only, `purchase` travels separately, and `resolved_enough`
refuses on `provisional` rather than on `purchase is False`. A definite reversal is a complete
answer; a bare `adjust` at 0.55 stays provisional and still asks.

### Two bugs of my own, both recorded rather than tidied

1. `resolved_enough` tested `res.get("provisional")`, but `_finish` never put that key in its
 result — the check read `None` and did nothing at all. A flag a caller tests must be a flag the
 caller can see.
2. A patch script's replacement text began `out = {` where the source line was `return {`. That
 turned a return statement into an assignment: `_finish` fell off the end returning `None` and
 the CLI died with *"'NoneType' object is not subscriptable"*. **A function that returns None is
 what a swallowed exception looks like** — the lesson is to call the function after patching it,
 not to trust the parse check.
