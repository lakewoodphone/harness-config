# H519 — round 32: the gateway detector is built, tested in both directions, and wiring into the digest

## THE DURABLE PIECE OF L1942

**Nothing alerted on a configured model's failure rate**, which is why `model_tier1/2/3` sat pointing at a
model failing 74% of calls and nobody knew. `scripts/ai-gateway-health.py` closes that.

**It checks three things:**
1. **failing models** — judged on **recent** traffic (see the calibration below)
2. **configured-but-silent** — a tier whose configured model has **zero calls** in the window, which no
 lookup-based check can see
3. **tier collapse** — tier1/2/3 on one literal, which removes the redundancy that surfaces a bad model

`EXIT 0` healthy · `1` a problem · `2` could not measure. **An UNMEASURED gateway is a failure, not health.**

## THE CALIBRATION CAUGHT ITSELF OUT — and that is the round's real content

The first version judged a model on its **7-day aggregate** and immediately fired:

```
🔴 failing-model 655 of 894 calls failed (73%) in 7 days
```

**And it was wrong.** The model's last four calls were **all successes** (541 ms, 1001 tokens) and its last
failure was **two days earlier**. The 655 failures were *historical*.

**That is the same history-vs-now confusion this project has paid for three times** — C07's pre-corpus
"revoked promises", C13's walk-ins, C14's naming. **A model that was broken and is now fixed must stop
alarming, or the alarm teaches people to ignore it.**

Rewritten so **recent** failures decide a problem, and a bad week with clean recent traffic becomes a
**note** (`recovered`) that keeps the history visible without reading as an active fault:

```
AI gateway: ✅ no model failing now, no configured-but-silent tier
 ⚠️ recovered 655 of 894 failed (73%) over 7d, but the last 6h are CLEAN (4/4).
 Historical, not current — reported so the history is visible without reading as
 an active fault.
```

**I would have shipped the wrong version without the negative control.**
