## THE ANSWER, NOW MUCH SHARPER THAN ROUND 1
- **One key probably explains both symptoms.** Waze's App Store metadata declares
 `NSSpeechRecognitionUsageDescription` — Apple documents that key as required only for apps that "send user data to
 Apple's speech recognition servers" — so on iOS Waze's speech is Apple's `SFSpeechRecognizer`. Apple's own error
 catalogue for it says `kLSRErrorDomain 201` = **"Siri or Dictation is disabled."** So `allowDictation=false` →
 Waze's mic does nothing, silently, *and* the Apple keyboard has no mic key.
 Limit, stated in the dossier: Apple documents the key, the error and `SFSpeechAuthorizationStatus.restricted`
 separately and never the causal link; nobody has published a test of the **MDM key** specifically. Leading
 hypothesis, not fact — hence the test.
- **The precondition that nearly cost the whole test**: Apple's dictation models download from
 `updates.cdn-apple.com`, which our default-deny filter refuses. Measured: NXDOMAIN, and **15 refused requests from
 the fleet in 24 hours**. Fix is provisioning order (download then lock), not a filter change.
- **Corrections made in the open**: (a) `com.apple.configuration.app.settings` per-app microphone default is **iOS
 27**, not 26.4 — and on iOS there is no PPPC fallback, so the on-device prompt is the only way Waze gets the mic;
 (b) my round-1 claim that the shop postures were "safety evidence" was wrong — they differ from the kiosk on
 **43 restriction keys** (L3825).
- **Filter facts measured, not read from the repo**: default-deny; 38 % of this fleet's 56,386 daily DNS requests
 refused; `guzzoni.apple.com` asked for 7 times and refused; `speech.googleapis.com` refused; 4,459 blocked and
 ~14,000 default-blocked requests were CNAME targets of **allowed** hosts.
- **Voice Control is already dead by our own hand**: its one-time asset download is `gateway.icloud.com`, which we
 block. Kosher filter vendors publish no iOS dictation position at all (documented absence).
