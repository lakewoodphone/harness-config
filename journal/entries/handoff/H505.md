## TWO BUGS I INTRODUCED, CAUGHT, AND REVERTED

**1. `ensure_ascii=False` rewrote the corpus.** Serialising the records converted every `\u2014` escape
into a literal em-dash, so **28 intended `sourcePath` corrections became a 226-file diff with 1,532
churn lines** — same values, unrecognisable diff. Fixed to `ensure_ascii=True`, plus **a guard that
refuses unless exactly the `sourcePath` line differs**, so this class cannot recur silently.

**2. The matcher over-fired by 6.5×.** `--apply` proposed **183 corrections where the token analysis
said 28 were near-certain**, because the similarity test compares the record's stem against case stems
and a shared **date prefix** (`2026-08-24`) scores as a matching token — so partly-overlapping
descriptions qualified as total matches.

**Both runs were reverted. Nothing from either was committed.** The tree is clean.

**F04 is now registered `writes: False`**, with a `blocked_reason` naming exactly what to fix (strip
leading date tokens on both sides, then re-measure). That is the honest state: the handler works and
validates its target, but a **diagnosis must not write while its matching rule is wrong**. This is the
same "a proxy for another program's logic must not outrank it" failure this codebase keeps making —
third occurrence, after C07's net-transition ranking and C11's 40-error proxy.
