# H518 — round 31: the model-tier bug is fixed and verified live — and I swept someone else's work into the commit

## THE FIX, AND WHY THE DIAGNOSIS WAS EXACT

`_delegate_model` sent **fast, mid AND ceo** to the literal `deepseek/deepseek-v4-flash` whenever
`ai_gateway_direct_deepseek_enabled` was true — **and it is true in this deployment.** From `model_usage`:

| | calls | failures | error |
|---|---|---|---|
| `deepseek/deepseek-v4-flash` (the route chosen) | 890 | **655** | **`empty_response`** |
| `deepinfra/deepseek-ai/DeepSeek-V4-Flash-0731` (the route that serves) | **14,896** | 0 | — |

**Both routes answer today** — live probe: direct `'ok'` in **1.3 s**, DeepInfra `'ok'` in **0.6 s**. So this
is a **reliability and quality** choice, **not an outage repair**, and it is written up that way rather than
dramatised. The history is 74% empty responses on a route that had silently become the default for three
tiers.

## WHAT CHANGED

1. `_delegate_model` returns the measured-good route by default for fast/mid/ceo.
2. **The direct pipe needs its own opt-in** (`ai_gateway_delegate_use_direct_deepseek`, default `False`).
 `ai_gateway_direct_deepseek_enabled` alone is *not* enough — that is the whole point: it was True, and on
 its own it made the measured-bad route the default. The old flag keeps working for whatever else uses it.
3. **Every delegate model is overridable without a code change**, per the standing instruction that models
 "can never be hardcoded": `AI_GATEWAY_DELEGATE_MODEL` and `AI_GATEWAY_DELEGATE_MODEL_BULK`. A blank
 override falls through to the default rather than reaching a provider as an empty model id.
