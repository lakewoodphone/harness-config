## The five mechanisms that hurt, all now written down as procedures

1. **`git stash pop` with no index pops another session's work** (L4769). Use `stash pop stash@{N}`.
2. **`git checkout HEAD -- file` discards uncommitted work** — and I did it to my own composer (L4897).
3. **A wholesale file overwrite beats a peer's live edit with no conflict** — three times on one file
 (P4313). Look for a claim marker; when a live file differs from every base you hold, that is a
 conversation, not a diff.
4. **`open(path, "w")` truncates BEFORE it validates its arguments** — so a failed write destroyed the
 live composer, and the backup taken on the previous line is the only reason it survived (L4960).
 Write to a temp file and `os.replace`.
5. **Never patch a file another session is editing** — build against a copy and ship a proven patch
 (`/root/_zabz_backups/20261015-norepeat/`, with APPLY-README).

**The pattern was mechanisms, not intentions.** Every one of those is a legitimate-looking command that
turns a small mistake into destroyed work.
