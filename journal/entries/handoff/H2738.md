## CHANGED

- **Every DSH web bundle in the fleet now has `singleDollarTextMath` disabled**, so a message containing two
 dollar amounts renders as text, not as mathematics. One byte flipped per bundle, and the byte count is
 unchanged on every node (740,575 bytes before and after).
- **The durable script**: `harness-config/scripts/patch-dsh-web-currency-math.py`, committed as `d432f45` and
 pushed to the authority's harness-config — every machine's autosync picks it up. `--check` exits 1 when the
 fix is missing; applying twice is a no-op; it writes BYTES because a text-mode write CRLF'd 411 newlines
 the first time this ran.
- **Kernel check 18, `web_currency_math`** (`ceo-kernel` `c1f6082`): reads each bundle under the known
 install roots on the host and goes HIGH if any still enables single-dollar math. Proven both ways — with
 the original bundle restored it reported HIGH, after re-applying the patch INFO. Kernel now: **18 checks,
 18 ok, 0 attention**.

## BROKEN / OPEN

- **The patch is in a build artifact.** A DSH upgrade reinstalls the bundle and silently brings the bug back.
 On the authority, check 18 catches it within five minutes; **on the other four nodes nothing watches it**.
 That is the gap worth closing next: run the patch from the session-start path (a hook or a plugin) rather
 than hoping someone remembers.
- **The mac mini is LAN-only right now**: `ssh mac-mini-ts` → connection timed out, `tailscale ping
 lakewooechsmini` → no reply; it was reached as `mac-mini` (192.168.50.45). Anything that assumes the
 Tailscale name works on that host will fail from the home network.
- The mesh child's copy of the script lives in `/tmp` on two nodes (cleared on reboot). The fix itself is in
 the bundle; a re-run after an upgrade must re-fetch the script from harness-config.
- `harness-config` on this laptop is 71 commits behind origin/master with 118 dirty paths (journal index and
 state files, plus untracked entries from other machines) — pre-existing divergence, not from this work. The
 commit for the script was made on the authority instead (`d432f45`), which is where that repo's remote is.
