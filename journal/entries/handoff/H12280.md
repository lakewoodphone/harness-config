### Shipped: ledger 1060 / roadmap A-P4-01

`AntiEvasionPolicyManager.kt` passed `null` to `setPermittedInputMethods`, which Android reads as "permit
every input method" — a child could install a custom IME and get around the filter. It had been deferred in
the code with the comment `// null = allow all for now`.

**The naive fix is worse than the bug**, and that is the part worth keeping: an allowlist that omits the
handset's own keyboard leaves the phone unable to type at all, which the parent experiences as a broken
device. So `permittedInputMethodAllowlist()` returns exactly one package — the default IME from
`Settings.Secure.DEFAULT_INPUT_METHOD`, taken before the slash — and `null` (never an empty list) when the
default is unreadable, because null and empty both mean "no permitted IME" and the unknown case must leave
the status quo rather than guess. Deliberately *not* Gboard as well: every extra package is one a child can
substitute into.

Verified on `zabz-yoga-ts` (JDK 21, SDK `C:\Android`): `:app:testDebugUnitTest` BUILD SUCCESSFUL; counted
the result XMLs rather than trusting the exit code (116 suites, 0 failures, 0 errors, 0 skipped, 4 new cases
named and passing). CI `android-unit-tests` pass in 3m39s.

**Not what `kf-929` fixes.** That branch adds `applyAccessibilityAllowlist` — the *accessibility service*
allowlist, a different `DevicePolicyManager` API. Two allowlists that read alike.

**Device verification is still owed** and is the only part that waits on hardware: nothing here proves a real
`DevicePolicyManager` accepts the list.
