I "found" that `billingReadiness` still used `getStripeTestSecretKey()` and would report NOT READY on
production forever. That was read from a **stale checkout** — this clone's `origin/main` was still
`bc09ddbe`, one promotion behind. On the real deployed main the block already resolves the actual mode
and reports it correctly. **No such defect exists, I changed nothing, and the branches I made for it
were deleted.** The same trap had already produced the "no such procedure / unmounted" reading earlier
in the day. Standing rule restated: `git fetch` the ref, then `git rev-parse` it, before believing what a
checkout says about production.
