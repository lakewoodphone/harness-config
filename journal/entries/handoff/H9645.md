### A number of mine that was wrong, caught before it was reported

A first pass matched **750 of 792** queue rows claiming `sent` against `sms_log` on a 40-character
body prefix and found nothing behind them. That looked like a catastrophe and was a **matching
artefact**: sampling eight real rows and matching by *time* showed seven of eight correspond
exactly to a delivered `sms_log` row. A prefix match against a templated body is not a measurement.

**Corrected finding: of the 10 queue rows claiming `sent` inside the last 7 days, ZERO lack an
`sms_log` row.** The live path is clean.

### K1 — `sent` must mean sent

`text-health.py` gains **K1**: no queue row in status `sent` inside the window may lack an
`sms_log` row for the owner at about that time — matched by **time as well as body**, so a template
or a re-prefixed send cannot hide a real one. Window-scoped like J1: the backlog is reported every
run, only a fresh regression fails.

```
OK K1 a queue row marked 'sent' has a sms_log row behind it
 10 row(s) claimed sent in the last 7 days; 0 of them have NO sms_log row within ~30
 minutes. 778 older row(s) carry the same claim and are reported, not failed.
```

Read what that does and does not say: the 778 older rows are **not verified** and are **not claimed
to be missing** — they are outside the window. **17 checks, 0 FAIL.**

K1 crashed on its first run with the same bug J1 had — `dict(r)` on a tuple, because `ro()` sets no
`row_factory` — and a crash and a finding print the same FAIL. That is now the second invariant in
this file to hit it, so the pattern is written down rather than rediscovered.
