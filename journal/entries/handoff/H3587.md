## FIXED THIS ROUND — PR 381, `pbp3/receipt-tax`

**Every repair receipt printed the whole bill as tax.** `receipt.service.ts` computed
`tax = total - subtotal` where `subtotal` is the sum of LINE ITEMS — and a repair has none, so
`subtotal` was 0 and `tax` became the entire total. A receipt reading "Tax 2.13" against a 2.13 sale
is a wrong document.

Now: `orders.total` is tax-inclusive, so the tax is taken back OUT of it at the shop's own rate
(`getTaxRatePercent`, never a literal). The line-item path is untouched where line items exist (a
counter sale), because there the old subtraction is right.

Backend typecheck clean; `receipt.service.test.ts` **8 tests pass**. The change produced two failures
first — both the same mock gap (`prisma.pricingConfig` absent from that test's mock), fixed in the
test, not by weakening the code.
