### The defect that was hiding every server test

PR #179's `server-tests` job failed with:

```
ImportError: cannot import name '_speaks_sqlite' from 'app.reset_protection'
```

**This is main, not the branch.** Measured on `origin/main`: `_speaks_sqlite` appears in
`server/tests/test_reset_protection_routes_answer.py` **four times** and in **no production file**. The
module exports `_is_sqlite_connection`, whose docstring carries the same measured reasoning (the guard
tests the API — a real `sqlite3.Connection`, or anything exposing `execute`/`executemany`/`executescript`
— rather than the type, because the SQLite backend hands out a one-connection-per-thread proxy that is
not a `sqlite3.Connection`). The function was **renamed** and the test kept the old name, so collection
failed before a single test ran.

**Consequence: `server-tests` could not collect on main at all, so every PR touching `server/**` was
blocked by a defect that predates it.** It survived because the server workflow is path-filtered — the PR
that renamed the function never ran the job that would have caught it. Fixed on its own branch,
**PR #180**: four occurrences renamed, `6 passed in 2.20s` (was exit 2). Test-side fix only, because the
production code is right and its docstring is the record of the measurement.
