## What exists now (authority: secratary, all as user `zabz`)

- `/home/zabz/bin/shabbat-powerup-probe.py` — reads the state a power-up must leave behind, using the
 app's own helpers (`shelly_plug.get_switch_state`, `_list_schedules`; `home_assistant.check_connection`,
 `get_interior_maglock_state`, `get_entity`): plug on, HA up, interior maglock **locked**, guard-rail
 automation `automation.phoenix_interior_maglock_tamper_restore` **on**, and ≥1 device schedule (the ON
 fallback). Prints `STATE {json}` + `PROBLEMS none|…`. An unreadable value is a problem, never health.
- `/home/zabz/bin/shabbat-powerup-check.sh [--dry-run] [--expect=on|off]` — files a **wake flag**
 (`--subject shabbat-powerup:<date> --kind shabbat --source shabbat-powerup-check --priority high`)
 only when the probe reports a problem; appends every run to `/home/zabz/.shabbat-powerup-check.log`.
 `--dry-run` files nothing.
- Transient timer `shabbat-powerup-check-20260927.timer` → fires **2026-09-28 00:45:00 UTC**
 (Sun 20:45 EDT), 20 min after the Sukkot run's 20:25 EDT power-up, as `--uid=zabz`.

## Limits — say these plainly to the next session

- The timer is **transient**: a reboot of the authority before Sunday drops it. Re-create with the same
 `systemd-run` line if that happens (it is in this entry).
- Only this run is covered. The **durable** version is a repeating source (every 15 min via
 `run-wake-sources.sh`) that first asks `shalom_zmanim.power_down_blocks` whether we are *inside a run*
 — outside a run the plug must be ON, inside it must be OFF — and files on the mismatch. Not built here
 on purpose: 17:12 on erev Yom Tov is not the hour to add a source that can file false flags.
- The wake dispatcher's liveness was checked this session (see the `wake.py stats` read in the handoff
 evidence); if it is ever dead, this guard is silent and "no flag" means nothing.
