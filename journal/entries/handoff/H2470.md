## 2026-09-23 21:21 UTC · secratary · Family Chat direct address, second pass: the adversary broke four of six claims; all four fixed, re-proven, redeployed

## 2026-09-23 21:25 UTC · SECRATARY · direct address, second pass (adversarial)

CHANGED (commit `7294a84e`, on top of `bdd1f50c`)
- An independent adversarial subagent was given six claims and told to break them. It broke four. Every finding was reproduced by me before it was touched.
 1. **15-minute cliff** in the deterministic fallback: "what about me" was answered at minute 14 and silently ignored at minute 15. The fallback now tests the CONVERSATION (Chip's message among the last 4 turns) with a 2-hour backstop, not a stopwatch.
 2. **Alias list too loose**: bare `ai`/`computer`/`robot` were answering "the ai thing works" and "my chavrusa said AI is overrated". Reduced to the names the family actually uses; the classifier handles the rest with context.
 3. **Classifier prompt mislabelled third-person AI talk** (5 of 6 live trials called "my chavrusa said AI is overrated" addressed). Added the observed confusions as few-shot examples. Re-measured on an expanded 16-case labelled set: **16/16**.
 4. **`chip_direct_max = 0` muted every addressed message**; 0 now means no cap, matching the hub's own `cap > 0` convention.
 5. **Quiet-hours refusal was silent** (no admin notice) - the last silent refusal in `decide_reply`.
 6. **Concurrency**: decision and reservation were not atomic; four simultaneous addresses with a 1/day allowance produced 3-4 replies and 3-4x the spend. The slot and the allowance unit are now reserved under `_chip_lock` before generating, and refunded when nothing is sent.
 7. **Marker wedge**: a raise while generating left `chip_in_flight_until` set for 120 s and the next UNSOLICITED message was lost. Now cleared in a `finally`. (Adressed messages waited it out, so the visible symptom was only the lost unsolicited one.)
- New test file `tests/test_family_chat_direct_address_hardening.py` (17 tests), one class per finding.

VERIFIED
- 590 tests pass (was 573 before hardening).
- Labelled classifier set: 16/16 in the live production configuration.
- End-to-end proof through the hub entry point with the carrier stubbed: both real messages replied, all controls silent, in-flight wait works.
- Deployed: restart 21:19:47 UTC, health 200, hub mounted, resilience loop started 21:20:00; process start is after the file mtime, so the live process is this commit.

STILL OPEN
- The classifier spends one reasoning call per inbound message (measured: ~512 prompt + ~51 completion tokens, 1.3-10.2 s), before any gate. `_chat` retries up to 3x on empty content and that happens - 23 retries across a 15-case adversarial run. Cost is small; latency on a burst is the thing to watch.
- A captionless photo (".(sent a photo)") addressed to Chip still classifies as OTHER. Chip cannot see images anyway; noted, not fixed.
- The budget question is queued (#147): at ~$0.18 per group reply the $5/month budget binds after ~27 replies, which is the real limit on this behaviour.
- No production traffic has exercised the new path yet: `chip_model_last_at` was 20:47:37 and the newest family message 20:43:37, both before the first deploy. The first live addressed message is the real test.

LESSON
- An adversarial pass with a permission to break the thing found four real defects in code that was green, tested, deployed and proven on a happy-path harness. The happy-path proof did not catch any of them. Budget for the adversary.
