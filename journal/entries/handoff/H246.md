**What it does.** An append-only `inference_events` table carrying *both* verdicts side by side plus
`verdict_changed` as **tri-state** (1 changed, 0 agreed, NULL never asked), the escalation reason (E1–E6), model id
and prompt version per row, observed image tokens, and cost in **integer micro-dollars**. On top of it:
`inference_spend_for_period`, `inference_budget_check` (the D39-11 money cap), `inference_stats_snapshot` (measures
1–5, 7), `inference_efficiency` (**"did asking for help actually change the answer?"** — the self-improvement
measure) and `prune_inference_telemetry`.

**A bug my own tests caught, worth remembering.** The budget gate was written `spent + projected <= cap`, which
**allows a frame when the budget is exactly exhausted and nothing was projected**. Any unmeasured or
rounded-to-zero cost then walks through a ceiling that reports itself as enforced. Now an exhausted budget refuses
even a zero-cost projection — deny-first, the same rule as D38-05.

**A red main I created, and the fix I chose.** `89f30e7` added six dynamic SQL call sites, which tripped
`sql_surface_audit` (341 → 347) and took **six** tests with it, including three startup-validation tests that only
failed because the SQL audit now raised first. The tempting fix was to refresh the baseline. **I did not.** That
audit exists so every dynamic SQL call site is a conscious decision, and "a stats query with an optional device
scope" is not a good enough reason to grow the audited surface. So the INSERT and the events listing became literal
statements, and the optional scope became a **parameter** —
`(? = 1 OR phone_id IN (SELECT value FROM json_each(?)))` — which also collapsed six counting queries into one
aggregate pass. Result: **341 → 341, digest unchanged, zero new dynamic sites, and the security baseline did not
need editing at all.** `json_each` is available (sqlite 3.49.1; verified before relying on it). 43 tests green across
the seven audit/security suites that were red.

**NOT DONE, and deliberately not glossed: the storage layer has no production caller.** That is the dead-code trap
this repo already has a pain entry for (1,836 lines of screenshot accountability with zero callers). The correct
next step is precise and identified: **`app/routers/screenshots.py:570-593`** is the only live third-party inference
egress that exists today — it already has the shape I need (`provider_chain_configured` → `disclosure_consented` →
`review_image(...)`), so the budget gate belongs as a third gate beside consent, with the cap hit recorded as an
event. Two things make that a real increment rather than a one-line patch: the enforcement must use a **deliberately
conservative upper-bound price per frame** (so the cap cannot be exceeded by an under-projection), and making the
cap configurable adds a setting, which pulls in `config-reference.md` regeneration and `test_settings_usage_audit`.
