## 2026-09-18 04:34 UTC · ZABZ-YOGA · DSH watchdog re-enabled: union liveness, window recovery with five guards, and the open-selector collision

CHANGED
- multi-window/dshw.ps1 (ZABZ-YOGA, working tree; harness autosync commits the tree every few minutes,
 so read `git log -- multi-window/dshw.ps1` rather than trusting a clean status):
 * `Get-OpenOriginPorts` now returns the UNION of three liveness signals instead of only asking the
 proxy in shared mode: (1) the proxy's per-port live-connection count at `/__dshw/open`, (2) a
 process scan keyed on each window's `--app=http://127.0.0.1:<port>` ORIGIN (covers ports 3200-3223
 AND the engine port 3099, in ANY profile mode), (3) two extra 600 ms samples when the first sample
 is empty, to catch a window that is still connecting. New helpers `Get-WindowOriginPorts` and
 `Get-EnginePortWindowCount`.
 * `Get-WindowCount` consumes that union, so "this slot has a live window" is answerable in every shape
 the launcher can produce a window in, and no longer depends on profileMode or on the proxy being up.
 * `Invoke-WindowRecovery` added, called at the end of `Invoke-Health`: restores a window the registry
 says was open and the liveness check says is gone. Five guards (registered open; the RECORDED port
 equals the slot's origin now, which excludes every legacy `port: 3099` row; the origin has a
 listener; the origin is not in the live set; 600 s per-slot cooldown via `window-recovery.json`)
 plus at most 2 opens per run. `dshw health` now always prints
 `windows: live origins [...]; registry-open-and-missing N; reopened M; held for the next run: ...`.
 * `dshw open <slot>` FIXED: the 'open' branch did `$slot = $null`, and PowerShell is case-insensitive
 so that clobbered the `$Slot` parameter (the command then reported "no slot matches ''"). It binds
 to `$slotCfg` now. `Open-SlotWindow` also reads `$slot.port` via `Get-Prop`, because a raw config
 row has no `port` key and `Set-StrictMode` evaluates the name even on the branch not taken.
- Task `DSH Window Fleet Watchdog` RE-ENABLED with `Enable-ScheduledTask` (same registration, action,
 trigger, settings): State=Ready, LastTaskResult=0, interval PT5M, MultipleInstances IgnoreNew. It had
 missed 9 runs while disabled and fired immediately on re-enable (00:12:14).
