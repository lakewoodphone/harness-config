# H506 — round 22: the matcher fixed, the collision guard fixed, and the repairable set is 11 (not 183)

## THREE CORRECTIONS TO MY OWN MEASUREMENT — each found by testing, not reasoning

**1. Date tokens carried no information.** `_norm_tokens` kept every token, so a shared date prefix
(`2026-08-24`) matched on both sides and inflated similarity: **183 records qualified as "all tokens
match" where the analysis said 28.** A token that appears in nearly every filename says nothing about
which file is meant, so it is now dropped exactly like a stopword. **Effect: 183 → 41.**

**2. The collision guard was incomplete.** A case file has exactly **one** record, so a candidate whose
target is already claimed by another record is a **duplicate mirror**, not a repair. My first version
tested membership in `by_case`, which is built during the C02 pass and therefore **missed records that
pair by stem** — it let through `asus-w202na-kaplin-2026-08-12.json` (pairs by stem) *and*
`kaplin-asus-w202na.json` (the orphan) pointing at one case. **Effect: 41 → 11 repairable, 33 collisions
correctly separated, ZERO collisions left in the repairable set.**

**3. The ordering bug behind (2).** Classifying records *while* building the set that decides their class
is the mistake. Both passes are now complete before either is used.
