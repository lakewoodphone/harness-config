## 2026-10-25 · ZABZ-TECH · Apartment deadbolt tenant PIN management live — and the brief's "no automated PIN writer" was false

**Lock measured, not assumed.** `lock.0x002446fffd0a4705` = Kwikset 99140-031 SmartCode deadbolt, firmware v004.010.052, **Zigbee2MQTT 2.6.2** (not ZHA), IEEE `0x002446fffd0a4705`, endpoint 2, input cluster `closuresDoorLock`. The Z2M bridge `definition.exposes` advertises `pin_code` with `user`, `user_type`, `user_enabled`, `pin_code`; the external converter sets `pinCodeCount: 30`. Remote PIN writes therefore work.

**Premise error.** The 2026-10-18 audit said no automated PIN writer existed. On 2026-10-25 `phoenix-pin-rotation.timer` on `secratary-cloud` was **enabled and active**: `/opt/phoenix-pin-rotation/rotate.py` owns deadbolt slots **1 (master), 4 (shared parents), 5 (Yocheved), 6 (master temp when switch on)**, generates new 4-digit codes every 14 days and sends SMS. Last success 2026-10-22T23:08:55Z; next rotation 2026-11-05. A second writer would have created duplicate codes, so the map reuses those slots.

**What is live in HA.** `/config/packages/apartment_deadbolt_codes.yaml` and `/config/apartment_deadbolt_codes.md`.
- Slot map: Eliyahu 1, Mother 4, Father 4 (shared parents code), Yocheved 5, Tenant 11.
- Scripts: `script.apartment_deadbolt_set`, `script.apartment_deadbolt_clear`, `script.apartment_deadbolt_check`; UI fields and password-mode helpers.
- Sensors: `sensor.apartment_deadbolt_user_slots` exposes the lock's `users` map; five per-person status sensors.
- Publish topic is hard-coded to `zigbee2mqtt/Apartment_Door_Smart_Lock/set`; slot 11 exists only in this package. No other lock is referenced.
- YAML only reloaded; HA core and the Z2M add-on were **not** restarted.

**Verification.** Set Tenant slot 11 with a transient 6-digit code → readback `enabled`; clear → readback `available`; helper cleared. Family slots 1/4/5 read back `enabled`, read-only. No remote unlock. The lock reports user status via `getPinCode` responses; the MQTT sensor carries them.

**Open conflict.** The rotation manager can overwrite a family code set through the new UI at the next 14-day rotation; tenant slot 11 is not touched by it. Retiring or redirecting that timer is an owner decision because it also rotates the front keypad and sends the parents/owner texts. Separately, Z2M is at `debug` and logs `getPinCodeRsp` payloads that can contain PINs; reducing `advanced.log_level` and restarting Z2M was not done.

**Measured ghost entities.** 30 `sensor.apartment_door_lock_pin_slot_*` template entities (not 22) and 30 keymaster automations are orphaned; their YAML no longer exists. Keymaster v0.0.99 is installed but has zero config entries. They were left in place, not deleted.
