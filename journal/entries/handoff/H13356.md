### The transferable facts

1. **A department in the blueprint is not a department that exists.** `AUTOPILOT_SKIP_BOOTSTRAP` is set in
 `/opt/company/.env`, and `bootstrap_company()` (`app/autopilot.py:8829`) is the ONLY thing that parents a
 newly-added blueprint department into the agent tree. So on the authority, adding a department to
 `DEPARTMENTS` changed nothing at runtime, silently. `dept_security` was an orphan
 (`hierarchy.parent_agent_id=null`), and `company_tick` dispatches productive ticks from
 `walk_agent_tree()`, which walks `hierarchy.children` — so it was never visited, never called
 `claim_next_step`, and its two standing work orders died as "Lifecycle sweep released stale running
 execution" with all 9 steps `attempts=0, claimed_by=null`. **Any** new department on that host dies
 the same way.
2. **Fixed** with `app/services/org_reconcile.py`, called from `company_tick` before the tree walk. It is
 the narrow half of bootstrap the tick depends on: presence, parent, status, own department block. It
 hires and deletes nothing, and never overwrites an identity that has reflections. Verified live:
 `company_tick: reconciled 1 blueprint department(s) into the agent tree: ['dept_security']`, and
 `walk_agent_tree` now reaches it (91 agents walked).
3. **`mashgiach_dept_scores` was a constant.** All 6,244 rows across 88 departments read
 `findings_count=0, auto_fixes=0, escalations=0` because `mashgiach.py` inserted a literal 0 and never
 wrote the other two. `daily_scan()` had been writing real `mashgiach_audit_log` rows all along — the two
 were never joined. After the fix: **19 of 32 departments have >=1 finding** this week. A scorecard of
 all-zeros is not a measurement; it made the mashgiach look healthy by construction.

 `2026-07-04T09:54:09Z` (~16 weeks) while `evolution_log` applied 103 changes. Nothing grades whether a

 (01:00-04:00, 06:00-10:00 UTC Mon-Fri). Deliberate cost decision, not a bug — but never conclude "this

### Operator notes learned the hard way

- **On ZABZ-YOGA, `bash` resolves to WSL, which has no distro**, so `scripts/mesh/guard-service-state.sh`
 exits 1. That is the environment code, NOT a refusal and NOT permission. Read
 `settings/machines/host-posture.tsv` directly instead.
- **Never inline `$(...)` or `$VAR` in a PowerShell-quoted `ssh` command** — it is expanded locally and
 silently corrupts the remote command. Pipe a script with `Get-Content -Raw x.sh | ssh host "bash -s"`,
 and strip CRLF first or bash reports `$'\r': command not found`.
- The authority's `mashgiach.py` upsert has **no `conn.commit()`** in that block, unlike the local copy, so
 a patch written against the local file will not match. Always diff the authority's actual text first.
- `journal.py search` returns exit 1 and "no match" for a real negative — that is an answer, not a failure.
