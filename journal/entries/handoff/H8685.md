## 2026-10-18 · ZABZ-YOGA · Estate search round 31: `scope=files` was answering nothing at all

Continues **H8684**. Commit for the two scope fixes.

## The audit that found it

"Every important document in every repo" had only ever been tested with questions whose answers I already
knew. This round sampled **one real file from each repo on disk** and asked the search surface for it by
name. Seven samples, every one:

 0 hits · 0 ms

Not a slow corpus and not a missing document — **no query being made**. `files` was missing from the set
that gates the estate fan-out, so `scope=files` fell through every branch and answered nothing. It had
been that way for as long as the scope existed.

**A scope that silently runs nothing is the worst kind of wrong**: it looks exactly like a confident
negative, and an agent that trusts it will conclude the file does not exist.

## Wiring it up, then making it fast

With the branch fixed the query ran and blew the 4 s deadline: `scope=files` spans three sources (the
authority and each workstation), and it searched all three for a term only one of them held. The
existence probe is now run **per source** and only the sources that hold the terms are searched — 9–77 ms
each to remove an entire search.

## And one measurement error of my own

The first audit run reported **1 of 7**, because `os.path.basename()` on Linux does not split a Windows
backslash path — every comparison failed regardless of what the index returned. That is the third
measurement artefact this programme has produced in as many rounds, and each one looked exactly like a
system failure until it was checked.
