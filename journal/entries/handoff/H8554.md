## 2026-10-18 · ZABZ-YOGA · Estate search round 22: the chat corpus could never finish, and the reason was a missing checkpoint

Continues **H8553**. Commits `27ff430`, `fe412ac`.

## Why raising the timeout did not work

Last round gave `chat:vscode` on ZABZ-TECH an hour instead of fifteen minutes. It still failed:

 FAIL chat:vscode 1257 doc(s) 3600.08s timed out after 3600s — the adapter was still producing

(The watchdog firing at exactly 3600.08 s is the previous round's fix working as designed.) The
suspicion was that an hour was simply not enough. **It was not the timeout at all:**

 Get-ChildItem ~/.usearch/state/chats.json -> does not exist

`state.save()` was called **once**, after every source had finished. A run killed at any deadline kept
**nothing** — so every attempt started at file one, and the corpus could never be finished however many
hours it was given. Raising the ceiling was treating the symptom for two rounds.

## The fix, and the experiment that proves it

The adapter now checkpoints every 40 files. Verified by killing it on purpose:

 start the chats adapter -> sleep 75 s -> Stop-Process -Force
 state file exists: True size=210.9 KB

Before the change that file did not exist after two hour-long runs. The next scheduled run resumes from
it instead of restarting.

## Also this round

The journal scope was verified **through the agent surface**, not curl: `ps_search(what="journal",
query="printer")` returns three real entries in **653 ms** — the printer status page, the sign-printing
decision, and the "check the thing, not its status field" lesson. Two rounds ago that query returned
zero.

## The pattern, again

For three rounds I answered "the chat corpus is too big for the timeout" with a bigger timeout, and the
real cause was that the work was never being kept. The question that found it took one command —
*does the state file exist after a failed run* — and I could have asked it before the first timeout
change. **When a job that should make progress never finishes, check whether it keeps any.**
