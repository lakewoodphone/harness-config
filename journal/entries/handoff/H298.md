FIXED, WITH CAUSES — BOTH ARE CONSEQUENCES OF THIS AUDIT
- **`terminal.error-handling`, 3 → 4 passing.** The tests called `router.createCaller({} as never)` with an
 **empty context** and expected the router's Stripe-configuration error. `terminal`'s procedures are now
 `managerProcedure` (bare until commit `489fd3165`), so the guard rejects an empty context with
 *'Authentication required'* **before** the handler's config check. The assertion was right — with Stripe
 unconfigured an authenticated caller should get the helpful message — so the caller now carries
 `user: { id: 1, role: 'ADMIN' }`.
- **`google.router`, 2 → 15 passing.** Both failures were
 *"expected `revokeAllForUser` to have been called with `[1]`"* and got **`[1, null]`** — precisely the shape
 of **round 5's fix**, which added `exceptToken` so an identity change stops revoking the session that made
 it. The test context carries no `lpt_refresh` cookie, so `currentRefreshTokenFromRequest` returns null and
 the call degrades to revoking all of the user's tokens. The assertion now states the `null` **explicitly**,
 which makes the degraded path visible instead of leaving the call incompletely asserted.
