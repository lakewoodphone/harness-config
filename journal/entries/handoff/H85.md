## 2026-09-14 15:35 UTC · ZABZ-YOGA · 2026-09-14 15:35 UTC · ZABZ-YOGA · Self-audit: the largest cause of company work failing was a prompt instructing a disabled syntax, and the host that runs the company could not receive a fix

CHANGED
- **Found and fixed the single largest cause of company work failing.** Measured on the
 authority: 674 work-session failures 2026-09-07..09-14, of which **270 (40%)** carried
 `[STALLED_REPEATING_OUTPUT]`. The cause was a contradiction inside the code, not a dumb
 model: `app/autopilot.py::_build_work_prompt` instructed *"Use [ACTION:...] tags to take
 concrete actions"*, while `assistant_legacy_action_tags_enabled` ships `False`
 (`app/config.py:745`) and was `false` in the authority's `.env` — so `parse_actions()`
 **stripped every tag and executed nothing**. The step still consumed its 5-step budget, the
 agent restated "Let me examine ..." until the repetition guard failed the session, and
 nothing said so. Fixed: the prompt now instructs native tool calling plus the
 structured-JSON fallback (`parse_actions` does accept that), states plainly that tags are
 disabled here, and requires a tool call per step; a new
 `_dropped_action_tag_count()` records `[DROPPED-ACTION-TAGS: n]` and prepends a correction
 to the next step so the session self-corrects instead of narrating until it dies.
 Committed on ZABZ-YOGA as `e600b259` with **16 tests**
 (`tests/test_work_mode_action_syntax.py`), including a negative proof that the hazard is
 real and an assertion that the detector is actually wired into the step loop.
- **Ghost agents: the bleed is closed.** The monitor held 69 `ghost_agent` error rows (15
 distinct messages), all unresolved, re-recorded every 6h, while it rescanned 28,371
 `skipped` goal_steps every 10 minutes. Four ids (`dept_home_and_life`, `dept_personal`,
 `dept_ceo`, `dept_executive_assistant`) were added to `_LEGACY_ASSIGNMENT_AGENT_ALIASES`;
 the startup rewriter healed 4 plans + 4 steps to **0**; `workforce.delegate_task` now
 canonicalizes at the single write boundary so new ghosts cannot be created; `'skipped'` is
 now terminal so cancelled plans stop being rescanned. Verified after restart: 0 orphans,
 0 new findings, monitor has nothing left to find on its scan.
- **The authority's uncommitted code now exists somewhere other than one disk.** Its live
 checkout carried 11 tracked files with bytes present in **no git ref at all** (local or
 remote) plus a commit on no branch — while the 6-hourly backup tars only `.env`, `data/`
 and `.runtime`, i.e. **no code whatsoever**. Pushed a full snapshot of that working state
 to `origin/live-snapshot-20260914T152412Z` (`380e1133`) using a temporary index, so HEAD
 and the working tree were not touched, and added a code tarball to
 `scripts/server/backup-data.sh`.
- Fixed the credential-named junk directory at the repo root
 (`postgres:/<rds-user>:<password>@<host>:5432/<db>`) so git can never capture it: added
 `postgres:*` to `.git/info/exclude`, which is untracked and therefore does not itself
 embed the secret in a tracked file.
