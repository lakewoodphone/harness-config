The company API reaches a degraded/DOWN state **~13 times a day** and recovers on
its own (127 recovery events in 10 days; the watchdog sees it healthy again after
1-8 observations). So it may be degraded **at** 20:04. If it is:

- the plug still turns ON from its own device schedule (no API needed);
- the door relock, guard-rail restore and ceiling-light re-assert are **skipped
 for that tick**, and `recover_incomplete_power_up` completes them as soon as
 the API answers.

this work the same failure left the door released and the owner's tamper
automation disabled for a WEEK, so the retry is what converted a week-long
exposure into a sub-hour delay. Not a clean outcome, but the right shape.
