THE COMPOSE/R2 WORRY IS CLOSED (it was my own bug, twice)
- Round 1 I worried a redeploy could drop `R2_*` because the box's `.env` grep showed no R2 keys. That
 grep used `^[A-Za-z_]+=`, which CANNOT match `R2_BUCKET` (the digit). `docker compose config` proves
 compose injects R2_ACCESS_KEY_ID / R2_BUCKET / R2_ENDPOINT / R2_SECRET_ACCESS_KEY from
 `/opt/lakewood-rentals/.env`, which the deploy script never touches. Also measured: the box's
 `docker-compose.yml` and the repo's are byte-identical. There is no drift to fear.
- LESSON: a key-name filter that excludes digits silently hides exactly the keys people worry about.
