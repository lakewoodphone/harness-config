## THE BLOCKER WAS A GATE THAT WAS WRONG, AND THAT IS NOW UNDERSTOOD

`Deploy frontend + verify (test)` failed on the test deploy with two assertions:

```
FAIL env VITE_API_URL literal present: "https://test-api.lakewoodphoneandtech.com" not found in any scanned file
FAIL Stripe: test carries a real pk_test_... publishable key: NO pk_test_... key in 3 scanned file(s)
```

**Both were false about the host.** Fetching the SAME served entry bundle by hand
(`/assets/index-DKWLMrYd.js`) found `test-api.lakewoodphoneandtech.com` and `pk_test_` present; the
production bundle found `api.lakewoodphoneandtech.com` and `pk_live_`, and no `pk_test_`. The one
worrying substring, `pk_live_` in the test bundle, is a **guard**, not a key:
`function UQ(e){return typeof e=="string"&&e.startsWith("pk_live_")}` — the code that refuses to draw
card fields when a live key is present.

**The cause, at `scripts/verify-deploy.mjs`:** the fetched live files were merged into the scan only
when the local `frontend/dist` had no `index.html`. It had one, so every assertion about THE LIVE
HOST ran against the LOCAL build. A gate reporting "not found" about bytes it never read is this
estate's oldest failure mode. Fixed to always scan the served files (`pbp3/verify-deploy-served`,
branch pushed — **NOT yet merged into `test`, so it is not on main**).

**And it was never a required check:** the PR sat at `mergeStateStatus: UNSTABLE`, not BLOCKED, while
`Validate Runtime Imports` was still running. UNSTABLE means every required check passed and only a
non-required one failed.
