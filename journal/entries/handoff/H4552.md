## 2026-10-15 02:50 UTC · SECRATARY-CLOUD · Profile-key audit: 707 discrepancies, all in one payload type, nothing deleted — plus a mesh child that failed and the audit that was redone locally

**CHANGED**
- **Profile-key audit shipped** (commit `c07048abf`, branch `fix/lpt-waze-onboarding-roaming-and-ack`):
 `deploy/waze-mdm/operator-tools/audit-profile-keys.py`, which enumerates every key in every served
 `.mobileconfig` and resolves each payload type to Apple's machine-readable schema.
 Findings document: `deploy/waze-mdm/docs/audit-2026-10-15-profile-keys.md`.
 - **707 discrepancies, 46 distinct keys, 22 of the 28 served profiles — and every single finding is
 inside a `com.apple.applicationaccess` restrictions payload** (kiosk, callblock, shop,
 family-filtered, quarantine). Everything else is clean, **including `waze-telnyx-apn.mobileconfig`
 after the fix — which is what validates the method, not the tool's own say-so.**
 - Highest-consequence keys: `allowUIAppRemoval`, `allowLocationServices`, `allowScreenTime`,
 `allowSystemSettingsModification`, `allowNotificationCenterModification`,
 `activationLockAllowedWhileSupervised`, and `allowDataRoamingModification` (already confirmed
 invented by a hand check in L3788).
 - **NOTHING WAS DELETED.** A key absent from the schema is *either invented or newer than the
 schema*, and the tool cannot tell which. `allowScreenRecording` is also absent from Apple's file
 — a name that sounds entirely legitimate — which is the warning that burned this. So it is a
 DISCREPANCY report, not a verdict, and the next step is a five-minute behavioural test per key on
 a bench device.
 - The tool **self-validates** and refuses to report if its extraction is broken, because the first
 version produced 23,580 false findings (it walked only one level of Apple's nested `subkeys` and
 flagged `APNs[].Name`) and the second recursed forever on YAML aliases. **Both were confidently
 wrong and one of them nearly shipped.**
