THE DEFECT: AN ADD-ONLY BUTTON OVER A TOGGLE
- POST /api/suggestions/[id]/vote is an upvote TOGGLE. The board was always labelled "Upvote", never
 read the response's `voted`, and the GET projection carried NO per-viewer flag - so the UI could not
 know. Measured: `▲ 0` -> click -> `▲ 1` -> click -> `▲ 0`, with the SAME accessible name throughout.
 A visitor who clicked twice silently removed their own vote and could not tell whether it was ever
 recorded.
- Fix: `lib/voterKey.ts` is the ONE definition of the vote identity (read and write must agree or the
 button lies); `listSuggestions(status, voterKey?)` projects `voted` via EXISTS over
 `suggestion_votes`, normalised to a real boolean; the board renders a distinct class + colour +
 aria-pressed + a label saying what the next click does, and explains the toggle in its copy.

I SHIPPED THE BUG INSIDE THE FIX - the transferable part
- I wrote `aria-pressed={s.voted === true}`, but SQLite's EXISTS answers 1/0, so it rendered "false" on
 a button that WAS voted. The colour and the label were correct, so an eyeball check would have passed
 it. Reading the ACCESSIBLE ATTRIBUTE caught it. Fixed at the source (booleans normalised in the
 repository) and guarded by a test asserting `typeof voted === "boolean"`.
- Same discipline on the styling: contrast taken from the COMPUTED style, not the stylesheet -
 rgb(138,95,8) on rgb(253,247,232) = 5.28:1, passes AA.
