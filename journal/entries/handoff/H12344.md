# What happened on the way (read L12288 before touching this again)

The FIRST real run (22:45Z) texted both parents and then had its owner-message refused by the
owner-text relay, because my body ended with a filesystem path; the script's atomic contract then
rolled every code back, leaving two parents holding a code that was void eight seconds later. Fixed
by removing the path from the owner body, adding `--recovery-note` (a correction line for the parents),
and re-running at 22:47:47Z — all three delivered, codes now match the text. The ordering rule that
comes out of it: **the guarded channel goes first**, and a refusal after delivery is a commit, not a
rollback.
