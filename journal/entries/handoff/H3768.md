## WHAT WAS DONE

Round 4 found that `lpt-record-payment` existed all along and that three orders had a proven Stripe
charge while `collected` read **0.00** — the order claiming money its own ledger denied, because
`collected` is `sum(amount) from payment_transactions where "orderId" = X and status = 'SUCCEEDED'` and
no row existed. Round 5 asked how far that defect extends, and fixed it where the evidence is strong.

**The criterion, applied mechanically and tightened before use** (`unique_attribution.py`): a tax-exact
Stripe charge that is the **only** charge of that amount within **±1 day** — the window was widened from
"the same UTC day" deliberately, because a charge of the same amount on an adjacent day could belong to
the same closing note — on an order whose closing note claims that pre-tax figure and which is the
**only** order in the shop claiming it in that window.

* 254 reconciliation notes held a claim; **126** had a tax-inclusive match; **60** survived uniqueness.
* Applied one order per invocation, with a 3-order trial first, and one trial order verified end to end
 by hand before the rest: `WO2605250003`'s closing note 1323 of 2026-05-25 reads *"paid $75 via card"*,
 the charge `ch_3Tagd6LnlgYj1gmT0XDTMxg6` is 79.97 (75 + 6.625 %), and row 3322 now records it.
* **The duplicate guard proved itself.** Re-running refused the 3 trial orders and the 2 recorded by hand
 with *"already recorded: … has a SUCCEEDED row. Nothing to do."* No double-counting.
* **Database state, verified by aggregate query rather than by my own output: 61 orders, 8002.24.**
 That reconciles exactly: the 60-order list totalled 7693.03, plus the name-matched West order at
 309.21 is 8002.24.

## THE DISTINCTION THAT MADE IT CORRECT

Every `PAYMENT RECONCILIATION CORRECTION` note written earlier today ends with *"DO NOT create a
payment_transactions row **from this note**"*. These rows are created from the **charge** — each carries
`metadata.stripeChargeId` and `metadata.recordedBy` — which is exactly the distinction that note was
drawing. The prohibition is on inventing a payment out of prose; it was never a prohibition on recording
one that the processor proves. **"Do not fabricate" must not become "do not record."**

## WHAT WAS DELIBERATELY NOT DONE, AND SAID SO

The other 66 tax-inclusive matches were **not** given a payment row, because attribution was not unique:
another charge of the same amount fell in the window, or another order claimed the same figure. A row
there would assert money on an order that might not be the one the charge belongs to, and would leave
the real order still reading 0.00. Their correction notes stand as the explanation, and the audit record
states the exclusion rather than leaving silence that would read as "nothing was examined".
