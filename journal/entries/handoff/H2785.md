does not agree with itself. The authority on what the database actually needs is
`prisma migrate diff --from-url <db> --to-schema-datamodel prisma/schema.prisma`, not `migrate status`,
which only reads a bookkeeping table. Confirmed absent either way:
`laptop_preferences.conditionPreference` does not exist (information_schema count = 0).

container IP (`docker inspect` it); `127.0.0.1:5432` on the box is refused.

**PRODUCTION HAS THE SAME DIVERGENCE. It was NOT touched.** Do not run `migrate deploy` against `lpt_prod`
until this is understood on the copy.
