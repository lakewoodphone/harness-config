PART-126 — THE ACCOUNT GATE IS A SUGGESTION, NOT A GATE
ADR-002 requires a Google-only account's "complete your account" step be *"enforced at sign-in and
everywhere"*. The shipped code announces it once and enforces it nowhere.
- **F-1 High:** `needsPhone` exists **only** as a transient `?needphone=1` query parameter on the OAuth
 redirect. It is **not persisted** — no `accountIncomplete`/`pendingPhone`/`phoneVerified` column exists on
 `users` or `customers` (the only `phoneVerified` hits in the tree are test fixtures). Enforcement is one
 client-side redirect, so it reaches exactly the customer whose browser follows the OAuth redirect into
 Settings. Arrive by bookmark or the login page and nothing mentions the missing phone again.
- **F-2 High:** the backend blocks nothing. `createVerifiedCustomerSession` checks role, `customerId`,
 `ACTIVE` and `isVerified` — **never the phone**. The server will mint a full session for an account whose
 only phone is the `oidc-` placeholder.
- **F-4 Medium, and the cheap fix:** `customerPortal.ts:169` already returns
 `hasPlaceholderPhone = phone.startsWith('oidc-')`. The server makes the determination F-2 says it should
 act on and sends it to the client instead.
- **F-3 Medium:** `CompleteAccountCard` renders in exactly one place (`CustomerSettings.tsx:350`) and is
 reactive, not blocking.
- **Recorded as good:** the card's state is derived from **server** state via `google.getStatus`, so the
 prompt is correct whenever it is shown; `hasVerifiedRealPhone` excludes the sentinel; and the card's copy
 is honest about what is missing.
