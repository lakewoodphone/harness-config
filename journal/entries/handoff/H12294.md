### What landed

`PendingChangeStore` — a child's requests held **on the device**, which is what the DoD asks for and also
what the code permits: the broker's `GET /rules/pending` and `POST /rules/pending/{id}/approve` are gated by
`_authorize_super_admin_or_secret`, so a parent's phone cannot call them. The queue is **bounded at 50**
(oldest dropped first), holds payloads rather than rules, and **fails closed on read** — a queue that cannot
be parsed is empty, because approving on unreadable data is the one outcome that must never happen.

`PendingApprovals` — `approve()` requires the credential, applies, reports, **then** dequeues, and a refusal
leaves the request staged so a mistyped PIN is not a lost request. `decline()` is **gated too**: not because
declining is dangerous, but because a queue a child can edit is a queue whose contents mean nothing.

**757 tests, 0 failures** on `zabz-yoga-ts`; `ParentApprovalsTest` 8 tests.

### The defect the tests found, fixed at the source

`approve()` returned `Approved(reported=false)` while the callback returned `true`. Cause: the gate reads
`change_id` **from the payload it applies**, and the queue held the id only *beside* the payload — so the
change applied and the broker report was **silently skipped as "no change id"**.

That is the silent-success shape this project keeps finding. The fix went into `stage()`, not into the test:
the staged payload now carries its own `change_id`, the same field the report names the change by.

### Still owed — the third and final piece

**There is no Activity.** The queue, the gate and both decisions are reachable and tested, but no screen
renders them, so a parent still cannot reach the feature. `AiProfileProposalReviewActivity` and
`AiProfileProposalRepository` are the existing pattern to copy: list the queue, show summary + requester +
age, prompt for the PIN, call approve/decline, and — importantly — surface `Approved(reported = false)` as
*"applied here, broker not told"* rather than as success.

### Traps paid for here

- **A name I got wrong in three places and then once more.** `ParentApprovals` vs `PendingApprovals` — the
 first fix left one occurrence, in a different assertion. Verify with a **case-sensitive count of zero**
 after a replace, not with the replace's own success message.
- **A heredoc is not available in PowerShell.** `git commit -F - 2>&1 <<'EOF'` fails with "Missing file
 specification after redirection operator". Long messages go to a file, every time.
- **The test that failed was the test working.** `Approved(reported=false)` was not a flaky assertion; it was
 the report being skipped for a real reason, and the whole point of asserting on `reported` separately from
 "approved" was to catch exactly that.
