**Seven projects had work sitting in the ledger that nothing could ever pick up**, because
`/home/zabz/.wake-projects/` did not exist on this box and both keepalives raise
`Unreadable('no state file')` without it. The symptom was SILENCE — `autonomy-status` printed
`PROBLEMS: none` the whole time, because the sources that do not need a state file kept the queue
busy. Nothing looked broken.

**Fixed with a tool, not eight manual files: `/root/bin/repair-wake-states.py`.** It is idempotent,
**never overwrites an existing state file** (a project's own file is authoritative over anything
derivable), and derives `work_remaining` / `remaining` **from the live ledger** rather than inventing
them — and says so in each file's own `note`, because the honest weakness of a derived state is that
it is a FLOOR: work living only in a project's own docs is not in it.

```
wrote 8, left alone 1
ledger-keepalive kosher-ai-filter -> filed
ledger-keepalive housekeeping -> filed
```

## THE TEST DEPLOYS THAT FAILED WERE A RACE, NOT A DEFECT

Two test deploy runs failed at **Preflight**, and the log says why:

```
FAIL Build image and assert the sha label: conclusion '(running)' on 4d9f952cb (the deployed commit)
The commit being deployed is 4d9f952cb... A deploy must not run on a commit whose checks are red.
```

The check was not red — it was **still running** when the gate looked.
`scripts/ci/required-checks-gate.mjs:265` treats `run.conclusion !== 'success'` as failure, and a
still-running check has `conclusion === null`. The retry run passed Preflight cleanly. **This is a
real defect and is NOT fixed**: the gate should wait a bounded time for an in-progress check instead
of calling it a failure, and it is the same family as the `verify-deploy.mjs` false red fixed on
2026-10-12.
