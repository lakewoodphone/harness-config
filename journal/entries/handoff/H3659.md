## The defect, now named precisely

`task_lifecycle_governor` (`/opt/company/app/database.py`) ages a **still-open task row** and emits an
honest flag — its own text says *"This is a flag, not a customer message."* Good design. But a
department agent then turns that flag into an **owner-approval task carrying a drafted customer
message**, composed from the stall signal alone, **without reading the case file**. Measured twice on
Felder, twice on Rubin, once on Schuck.

Signatures to recognise it by:
- A task id presented as a case number (`case #3132`, `case #3495`) — **a task id is not an order, a
 ticket or a case.**
- `N days / 0% progress / interaction_count=0` where `N` equals the *task row's* age and the counter
 comes from a CRM stub contact row (Rubin: contact 473, `source=manual`, `created_at==updated_at`).
- A **twin task closed and its sibling left open** (Felder 4486 closed / 4485 open for 111 days).
- The same ask duplicated across two agents (Schuck 28539 dept_engineering + 28550 dept_business_ops,
 the second with an **empty body** — the owner-approval task inherits **no `dedupe_key`** from the
 stall alert that produced it, though the alert itself carries one).
