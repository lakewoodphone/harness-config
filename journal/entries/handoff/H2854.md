### HEADLINE
Moving off the 0.1.5 line needs **three** changes, not one, and the third is the one that matters:
two package renames (both DONE in the repo) and a **preset migration** (in flight). Without the
third, upgrading silently deletes the agent's persona.

### WHY (all measured 2026-09-28, reproduced by hand)
1. RENAMES. `0.1.7-rc.1/rc.2/0.2.0-rc.1` remove `@deepseek-ai/dsh-workflow-worker-thread` (replaced by
 `@deepseek-ai/dsh-workflow-ptc`) and `@deepseek-ai/dsh-agent-presets` (replaced by
 `@deepseek-ai/dsh-agent-preset-registry`). Confirmed from the published manifests' own
 `dependencies` (`npm view @deepseek-ai/dsh@<v> dependencies`) AND by
 `require.resolve` against the fetched install: both old names return MODULE_NOT_FOUND, both new
 names resolve. The configs carry over unchanged and that is not a guess: the new packages' own
 schemas are `{provider: z.string().default("spawn"), ...}` and
 `{default: z.string().required(), ...}`, and upstream's own mounted rows are
 `id=workflow-ptc ... config={"provider":"spawn"}` and
 `id=agent-preset-registry ... config={"default":"standard"}`.
2. **PRESET MIGRATION — the real work.** On 0.1.5, `@deepseek-ai/dsh-agent-presets` discovers
 preset DIRECTORIES: `USER_PRESET_DIR = '.agent-presets'` in three of its files
 (`lib/types/discovery.js:48`, `lib/invariant.js:194`, `lib/index.js:195`). On 0.1.7-rc.2 that
 string appears **nowhere** in the install, and the replacement registry has **no `readdir` and no
 `readFile`** — it takes definitions programmatically (`async register(definition)`). Presets are
 now COMPOSITION ROWS. Upstream's own web composition carries
 `preset-standard|ptc|minimal|cordis`, each `name=@deepseek-ai/dsh-agent-preset`,
 `config={id, order, plugins:[...]}` — and that `plugins` array is EXACTLY the row list our
 `presets/<name>/agent.cordis.yml` files already contain. So `agent-presets.default: zabz` will
 name nothing, sessions fall back to a shipped preset, and the persona is gone with no error.
3. SESSION FORMAT — one-way door CONFIRMED for 0.1.7-rc.2:
 `dsh-session-format-catalog/lib/index.js` line 41 `currentVersion: 4`, line 92 historical
 `currentVersion: 3`. The live home holds 1,095 logs, all `session.v3.jsonl.zstd`.

### VERSION CHOICE — decided, with reasoning
Target **0.1.7-rc.2** (the `latest` tag, published 2026-09-24). NOT `0.2.0-rc.1` (`next`, published
2026-09-28 ~12:34, i.e. ~6 h old). Measured: 0.1.5=240 packages, 0.1.7-rc.2=283, 0.2.0-rc.1=288, and
0.2.0-rc.1 **removes nothing** relative to 0.1.7-rc.2 — it is purely additive (5 packages:
`dsh-otel`, `dsh-client-product-analytics`, session-log settings UI, an experimental schedule bundle,
product telemetry). So a migration done for 0.1.7-rc.2 satisfies 0.2.0-rc.1 with no extra work, and
there is no reason to adopt a 6-hour-old prerelease as the daily driver.
