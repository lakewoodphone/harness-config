## The trap this nearly created, and why it is worth a lesson (L3889)
First attempt: `new=1 filed_this_run=1` and it would have filed **"Reconcile the authority running wake scripts…"**
a second time. Cause: `split_candidates()` dedupes against live items in **the project being supplied**, and ledger
item 643 belongs to `housekeeping`. A mapping row in the `kosher-ai-filter` mapping can never match it, so a correct
mechanism was fed a wrong input and produced the exact duplicate this source exists to prevent - silently, in a
`--dry-run` that otherwise looked clean.

Fix: that row is `not_filed` with the project mismatch named in its reason, and PR #71 (merged `a034ae1`) puts the
mismatch in the register item's own body so the next reader meets it **before** refiling. The rule for the next
shift: a roadmap path's ledger item and the mapping row that points at it must be in the same project, or the row
is `not_filed` with the mismatch named - and read `new=` plus the `filed:` lines of a dry run, not just its exit
code.
