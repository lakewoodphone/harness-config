## THE NEW GUARD — aimed at the exact failure mode of round 9

`check_sync_tool_sanity()` in `app/services/lpt_hub_sync.py`:

```
SYNC_TOOL_MIN_BYTES = 50_000
SYNC_TOOL_REQUIRED_MARKERS = ("--dry-run-all", "_GUARD_REFUSING_KINDS")
```

**A size FLOOR, not an exact size.** The live file legitimately grows — it went 89,081 → 92,973 when
root validation was added — so the test is "far too small to be this program", which is the actual
failure mode. 50,000 sits well below the live file and far above the old one. Fast, offline, no
network, no data access.

**Why a size floor at all:** the expensive mistake is not "the file is missing". It is **"the file is
present, parses, runs, and is the wrong program."** `ast.parse` is a *syntax* gate and it was *right*
to pass a 28 KB skeleton of a 90 KB program. This is the check that can tell the difference.

**Verified in BOTH directions, because a guard that fires on the correct file is noise:**
```
correct file (92,973) -> CLEAN
old lineage (31,617) -> 3 problems: size, missing --dry-run-all, missing guard constant
authority's live tool -> CLEAN
```

**Location note, from getting it wrong first:** the tool lives in **this** repo (`<psm>/scripts/`), not
in lpt-hub. It *reads* the lpt-hub corpus; that is not the same as living in it. The first version of
the function took a hub root, looked in the hub, and reported the file absent. The default now
resolves from the module's own location, and the docstring says why.
