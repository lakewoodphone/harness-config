### The client-side findings, re-read by hand (✅ = I read the line)
1. `PolicyApplier.kt:465` `if (!BuildConfig.DEBUG) {` gates **eight** restrictions — install block,
 unknown sources, safe boot, factory reset, apps control, USB transfer, debugging, overlay windows —
 **and** the accessibility allowlist at `:492`. A debug build enforces none of them.
2. `build_guided_installer_bundle.ps1:5,73,97` and `real_device_provision.ps1:11,849` build and install
 **app-debug.apk**; only `counter_install.ps1:211` uses `app-release.apk`. The operator-facing
 installer therefore ships the unenforced build.
3. `AdminReceiver.kt:48-51` `onEnabled` only logs; `PolicyApplier.apply` runs from
 `onProfileProvisioningComplete` (`:67`) or when the app is opened. `dpm set-device-owner` (the adb
 seal) hits `onEnabled` only, and `guided_phone_installer.ps1:306` passes `NoLaunch = $true`.
4. `AntiEvasionPolicyManager.kt:158-161` overwrites the accessibility allowlist with
 `ourServiceComponent.flattenToString()` — a `pkg/cls` string — where the API takes package names, after
 `PolicyApplier.kt:493` set it correctly. Probable result: no accessibility service permitted, ours
 included (device effect unverified, no phone on this host).
5. Same file `:171` `setScreenCaptureDisabled(adminComponent, false)` and `:210`
 `setPermittedInputMethods(adminComponent, null)` — capture allowed, every IME allowed, each with a
 comment claiming the opposite.
6. `MlModelProvisioner.kt:214-219` validates a downloaded model by size only (`length() >= minBytes`), so
 any blob of the right size counts as a model; and `:50-65` pins three third-party URLs.
7. `modesty_level` has no device reader: two code references, both in `owner_level.py`.
