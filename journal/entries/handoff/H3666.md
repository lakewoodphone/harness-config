## 2026-10-14 12:32 UTC · ZABZ-YOGA · H3666 - dsh unreachable on ZABZ-TECH: origin ports inside the Windows dynamic range, plus a StrictMode Keys bug; both fixed and verified

## 2026-10-14 08:50 EDT · ZABZ-YOGA + ZABZ-TECH · "dsh is 404/unreachable on the tech desktop" - diagnosed, fixed, verified

**The owner's report:** opening DSH on ZABZ-TECH gave an unreachable/404 page. Read first-hand, all times local (UTC-4).

### What had actually happened, from the machine's own logs

- ZABZ-TECH booted ~08:02. From **08:03:56 to 08:11:10**, **11 consecutive starts of the origins proxy failed and 360 binds were refused with EACCES (access denied)** on `127.0.0.1:3200-3223` (`~/.dsh/multi-window/logs/origins.log`; the whole 360-line population is on 2026-10-14, nothing before it).
- Cause: that block is inside the machine's **dynamic port range** (`netsh int ipv4 show dynamicport tcp` -> 1024 + 13977 = 1024..15000) and Windows had it reserved at boot — `vmcompute`, `winnat` and `WslService` are all running on that box, and `netsh int ipv4 show excludedportrange protocol=tcp` carries their signature (9468-9567, 13091-13590, 13637-13836). The reservation lifted ~7 minutes in; the 12th attempt (08:11:10) bound all 24.
- `ensure` behaved correctly and loudly: `watchdog.log` 08:04:13 / 08:05:38 / 08:05:49 `origins proxy is not answering on :3200 and could not be started - REFUSING: every open window uses ports 3200..3223`, and `exit 3` is why `DSH Engine Vitals (5m)` reported `LastTaskResult 3`.
- The engine also failed to boot three times (`EADDRINUSE 127.0.0.1:3099`, `~/.dsh/logs/startup-*` diagnostics: `2 required plugins did not activate / webserver: listen EADDRINUSE`), and `watchdog.log` logged `engine on 3099 not answering the fast probe` at 08:11:18 and 08:11:54.
- With no origins proxy, the launcher opened windows against the ENGINE PORT with a **stale token** (`windows.log` 08:12:50: `?token=zkhRwa6z...`, the 10-12 token, six seconds after the engine minted a new one) and `verify=skipped-direct-to-engine`. That is the auth-required / blank-titled page — the failure the owner saw. Reopened at 08:17:45 with the current token, the same windows loaded (`browser/_shared/Default/History`: title `DeepSeek Harness`).
- A third defect, found while repairing: one line in `Get-OriginLiveLegs`, `@(@(Get-WindowOriginPorts).Keys | ...)`, **throws under StrictMode when the scan map is empty** — the normal state. It had failed the reconcile/recovery pass on 10-11, 10-13 and 10-14 (`health.log`), and on this day it made `up -WindowsMode restore` die *after* opening the windows.

### What was changed (commit `f73d521d`, branch `fix/window-blank-isolation-20261014`)

| file | change |
|---|---|
| `multi-window/windows.json` | `origins.basePort` 3200 -> **19200** (outside the dynamic range and every exclusion; 24/24 binds verified before changing) |
| `multi-window/dshw-proxy.mjs` | EACCES retried like EADDRINUSE; a proxy that bound NOTHING `exit 2` instead of sitting alive holding the lock; `/__dshw/stats` reports `base` and `range` |
| `multi-window/dshw.ps1` | `Get-KeyList` replaces every `.Keys` (D3152/L3808); the reconcile catch now writes `$_.ScriptStackTrace` to `health.log` |

Entries: **L3808** (StrictMode `.Keys`), **L3809** (listener in the dynamic range), **D3152** (the port decision and its consequences), **P3185** (the stale-token fallback and the missing `live-url.txt`, NOT fixed).

### Verified after the change

- ZABZ-TECH: proxy pid 27072 `--base 19200`, `range {bound:24, failed:0}`, `RANGE COMPLETE` in origins.log, 24 listeners owned by that pid. Windows reopened and confirmed live at origins **19200, 19201, 19205, 19206** (proxy leg). `dshw health` and `dshw restore` both run clean, exit 0, no `Keys` error. Registry re-recorded: rows `1 - main`, `2`, `6`, `7` open on those ports.
- ZABZ-YOGA: new base up 24/24 (`range.bound=24`); the old 3200 proxy was deliberately left running so the owner's open window keeps working — it dies at the next reboot.
- DESKTOP-FGV6KMH untouched and unaffected: its machine config has no `origins` block.

### Next, in order

1. **P3185** — make the engine-port fallback use the CURRENT token and write `live-url.txt` on every successful start. This is the difference between the degraded path giving a GUI and giving an auth page.
2. The boot engine race (`EADDRINUSE 3099`, three failures this morning) — the supervisor's "wait instead of race" guard exists but the collisions happened anyway.
3. `netsh int ipv4 add excludedportrange` was considered for 3200 and REJECTED: an excluded range cannot be bound by an application either, which is the whole reason Hyper-V's reservations break other software.
