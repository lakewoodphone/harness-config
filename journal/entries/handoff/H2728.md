**THE UNIT TRAP BIT ME A SECOND TIME, and I caught it the same way.** The generic creation script sets `unit_amount: 1800`, which against an MB-valued meter is **$18,000/GB**. It did the identical thing in test mode. Fixed with a test-mode variant of the repair script (`backend/scripts/fix-waze-metered-price-test.mjs`), verified by reading the price back and recomputing `(centsPerUnit / 100) * 1000 === 18.00`. **The correct figure needs `unit_amount_decimal: '1.8'` because Stripe's `unit_amount` is an integer of cents and cannot express it.** The 1800-cent price is retired with its lookup_key cleared. **Lesson re-earned: the creation script is a trap for anyone who runs it unaware — it should be fixed at source rather than repaired afterwards, and that is NOT yet done.**
