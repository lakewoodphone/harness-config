## 2026-09-20 17:32 UTC · ZABZ-YOGA · H618f - round 7: the autopilot was WEDGED (5 timeouts, 0 completions in 6h) - found and fixed; gate fix still unverified

## THE BIG ONE THIS ROUND

**The autopilot's main loop has not been completing.** Measured before the fix: **5 `run_once` timeouts
in 6 hours, 0 completions.** Every low-traffic reading I had been attributing to "a quiet evening" was
this.

**Cause:** `_run_once_active` (the re-entrancy guard) was cleared only on `run_once`'s success path and
in its `except` - **no `finally`** - so a run that hung inside a blocking call left it `True` for the
life of the process. Every later attempt returned `already_running` and did nothing. The loop's
timeout message claimed it was "killing" the run while calling `shutdown(wait=False)`, which cannot
kill a thread: **the log said killed, the code abandoned, the flag stayed set.** A guard with no
`finally` is a latch.

**Fix (deployed 17:30Z, backup `~/code-backups/20260920T162023Z/autopilot.py.before-wedge`,
sha `39b90d1ad4a865bd`):**
1. `finally:` inside `run_once` - verified as a `try/finally` that is a direct child of `run_once`;
 clear-sites 2 -> 3.
2. The loop clears the guard when it stops waiting.
3. The log now reads "ABANDONING it (the thread keeps running; it cannot be killed)".

**Verification in progress, and it cannot be instant** (a run may take up to 600 s): watcher at
`~/company-reports/autopilot-recovery-*.log` samples `autopilot_state.json`'s `last_run_at`
(17:12:17 at fix time) and the timeout counter every 60 s for 40 min. **Goal stays open until a run
completes.**
