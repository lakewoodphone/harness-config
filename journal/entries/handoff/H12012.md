## 2026-10-21 01:10 UTC · ZABZ-YOGA · Fleet monitor wrote hours into a minutes column: four sold kiosks were reported alive while six days stale, now fixed and verified

Round 3 of the Waze sold-fleet objective - the round that found a monitor that was lying.

## The bug
`fleet_api.py` wrote `int(age_hours)` into `fleet_device_health_history.last_checkin_age`; every reader treats that column as **minutes** (the API labels it `last_checkin_age_minutes`; `data-bearer-check.sql` compares `<= 180` to call a device alive). Live consequence: DRN 2005's newest row held **144** and the operator's data-bearer check reported it as *"alive, SIM has moved under 0.5 MB"*, while `enrollments.last_seen_at` said six days. A device dead for a week was being counted as fine-but-idle on the sold fleet.

Fixed to minutes, API rebuilt and recreated 01:08:07-01:08:32Z (25 s). Verified on the next monitor run: DRN 2004/2007 -> 15, DRN 2005 -> 8690. `data-bearer-check.sh` now returns "no device flagged", exit 0 - correct, because none is alive. Rows older than 01:08Z still hold hours; the write site carries a dated comment. Ported to branch `waze/checkin-age-unit-2026-10-21` commit `62590a96a` so a redeploy cannot revert it (deployed file and master were byte-identical before the patch).

## What that changed about the sold fleet
Four of the six kiosks are stale, not idle: 2002 at 9,159 minutes, 2005/2006/2008 at 8,690. Only 2004 and 2007 are live. Fleet view after the fix: 71 devices, 55 stale.
