## 2026-09-15 21:58 UTC · ZABZ-TECH · 2026-09-15: last audit workstream integrated - the fleet page's auth path, and a finding of mine that was wrong

INTEGRATED AND PUSHED (origin/master 321f167e). This was the fifth and last of the audit workstreams.

WHAT IT CLOSED: the /shadow rewrite in psm's web/next.config.ts added no Authorization header, so
with a valid session the browser's headerless request arrived at the fleet-api and got
401 {"detail":"Invalid token"} - and because fetch does not reject on 401, the fleet page rendered
"No devices registered" with every stat "-" and re-confirmed it every 30s. The agent reproduced the
401 with a stub mirroring verify_token and the stub logged authorization: ABSENT. Fleet reads now
go through session-checked route handlers under web/app/api/fleet/* that inject the bearer token
server-side (web/lib/fleet.ts / fleetRoute.ts); no cookie now gets 401 JSON with a plain-language
message and the upstream is never called; with a session it is 200 with authorization: present and
the browser cookie NOT forwarded.

A CORRECTION TO MY OWN BRIEF, and the reason FINDING 2 needed no fix: I wrote that there is no
web/middleware.ts, and concluded /sms, /voice-notes, /docs were exposed. Next 16 RENAMED
middleware.ts to proxy.ts, and web/proxy.ts has gated all of them since 726d165e. Observed on the
dev server AND the live host: /sms/thread/*, /sms/media/*, /voice-notes, /docs, /openapi.json,
/redoc all 307 to sign-in without a session, while /webhook/twilio-probe is 200 and unaffected.
So the media exposure I flagged as a security finding was already closed months ago - the audit
agent reasoned from the repo's file list instead of the running gate. The durable lesson is in
L1621: a framework rename can make a security control invisible to a file-existence check.

What was decided and changed there: the four API-map rewrites (/docs, /openapi.json, /redoc,
/docs/oauth2-redirect) were REMOVED rather than gated, because they run in beforeFiles ahead of
the filesystem inside the public hostname and hand out the whole backend API map; nothing links to
them and the map stays reachable on the backend port.

STILL OPEN, reported not fixed: scripts/watchdog.ps1:239 generates cloudflared ingress rules that
would send /docs, /openapi.json, /webhook/*, /api/v1/*, /health, /ready straight to the FastAPI
port, bypassing proxy.ts entirely. Today's live host does NOT behave that way (the live /docs 307
proves the dashboard answered), so removing the rewrites was correct - but if that tunnel config is
ever regenerated as written, the API map becomes public via the backend's loopback auth skip
(main.py:353-356). The durable fix belongs in watchdog.ps1 or in the loopback trust, and scripts/
is a live launcher I will not edit without a reason to touch the tunnel.

Also found and reported: three field-mismatch bugs on that page - the fleet-api payload has no
queue_count, push_channel or enrolled_at, so every device rendered a false red "no push channel"
and a false 0 queue depth; /fleet/queue-health returns a nested per-device shape the panel did not
read; and /fleet/alerts has no serial. The page now renders "-" for unknown and understands both
queue shapes. Commit 03e7fb50 (liveness) means those panels show real values with no further
change once deployed.
