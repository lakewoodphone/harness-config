## 2026-09-15 14:27 UTC · ZABZ-YOGA · correction: H229 cites L1505, the trust-grade lesson is L1511 (and why an entry cannot cite its own sibling)

A one-line correction, recorded because the alternative is a cross-reference that silently
points at the wrong entry.

**H229 cites "L1505" for the trust-grade lesson. The lesson is L1511.** L1505 exists and is
a different lesson entirely ("A scheduled task can report Ready while shipping nothing"),
written by another session in the minutes between my computing the number and my entry
being written.

WHY THIS HAPPENED, because it will happen again: `journal.py append` allocates an id at
WRITE time, over the index, the shards and every git ref -- so nothing can be reserved in
advance, and on this machine there are two live writers. Any entry that cites its own
sibling id is therefore citing a number it cannot know yet. The instruction to future me:
**when writing a handoff, cite the lesson's TITLE, not an id you intend to create beside
it** -- or append the lesson first, read its real id back, and then cite that.

The lesson itself is unaffected and reads the same as L1511.
