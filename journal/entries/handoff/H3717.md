## 2026-10-20 19:03 UTC · ZABZ-TECH · round 25: the disagreement monitor was falsified by the live fleet and removed - freshness, not counts, is the discriminator

# H (2026-10-20, round 25) - I built the monitor I recommended, and it was wrong; removed in the same hour

## What I built
A new flag source, `project-state-disagreement.py` (6.6 KB, compiles): for every project, if the state file claims
work and the ledger has no `todo` item, file a flag. Tested against the backup that carried the real defect
(`kosher-ai-filter.json.bak-*`, `work_remaining: true`, 11 stale entries).

## Why I deleted it before it could file anything
Two measurements, both against the design rather than the code:

1. **Against live state files it fires on FOUR projects every day** - lpt-sync, cfo, personality-system, rental-system -
 whose state files say `work_remaining` while their ledger holds only **blocked** items. That is arguably an honest
 state ("there is work, it is waiting"), so the flag is noise, and noise of the kind that trains everyone to ignore
 the channel.
2. **It would not have caught the kosher-ai-filter case at all.** That project's ledger held 9 non-terminal (blocked)
 items, so "claims work, ledger has no todo" is satisfied by every normally-blocked project. The defect there was
 **stale text** naming a document that no longer said what it claimed ("section 7 has 23 unchecked rows") - semantic,
 and no ledger count can see it.

It also had a real bug: the `ONLY_FILE` test seam leaked onto every project, so the "single file" test flagged six.
That is what the backup run showed first, and it is why a test seam needs its own test.

Removed immediately because `run-wake-sources.sh` iterates every `.py` in `sources/`, so shipping it would have filed
four flags a day. `ls /root/bin/sources/*.py | wc -l` is back to **33**, and `project-keepalive --dry-run` shows
kosher-ai-filter quiet.

## The design that would have caught it
Freshness, not counts: flag only when the state file **claims work** and **has not been rewritten in the window being
judged** (mtime older than ~48 h) while the project had no startable ledger work in that window. Tonight's file carried
`remaining` entries dated 2026-10-14..16 and a stale `checked_at`; an honest project's shift rewrites the file every
day it runs. Written into ledger 820 with the measurement it still needs.

## The lesson
**A monitor that fires on honest states is worse than none**, and the test that shows it is running the thing against
the live fleet rather than against the example that inspired it. The example was one project with stale text; the
fleet has four projects in a state I would have called honest.
