## 2026-10-06 05:46 UTC · ZABZ-YOGA · (d) hysteresis implemented and the two-node scenario simulated against the real arbiter; app fence and fail-closed verified

GOAL ROUND 17. (d) WAS THE LEAST-VERIFIED PART OF THE OBJECTIVE AND IS NOW THE MOST CONCRETELY TESTED. WHAT WAS MISSING: the arbiter (company-lease.sh) had no hysteresis at all - the design promised that a node which had just lost leadership must wait before taking it back, and the code did not implement it, so a flapping network could ping-pong the company between two managers (two alternating writers - the exact failure the two-host design exists to prevent). IMPLEMENTED: HOLD_DOWN (default 300s); a holder that LOST the lease (released it, or was replaced while expired) may not re-acquire until the window passes. Deliberately asymmetric: the FIRST takeover after an expiry is not delayed (failover stays immediate) and only the loser is damped (a different node can take over at any time); the returning node rejoins as a FOLLOWER - reads fine, writes not. status now prints the hold-down for an operator. PROVEN BY A REAL TWO-NODE SIMULATION against the actual arbiter in a scratch lease dir (survivor-conformance/two-node-simulation.sh, deployed and run on Box 2): one writer (second acquire refused) -> renewal keeps the epoch -> office dies, wait past TTL -> survivor takes over GRANTED epoch 2 with NO delay -> check-epoch 1 FALSE (stale token) -> office returns while survivor holds, refused -> BOTH lapse so the office finds it FREE and asks back -> 'REFUSED (REJOIN): office lost leadership 6s ago; the hold-down is 15s' -> a DIFFERENT node is not damped (survivor GRANTED epoch 3) -> after the window the office is GRANTED epoch 4. AND THE FIRST RUN OF THAT TEST PROVED NOTHING: every refusal in it was 'someone else holds the lease', so the hysteresis path never executed - a test that passes without reaching the new branch is worth the same as no test. It was rewritten to produce the free-lease state that triggers it. APP SIDE, VERIFIED LOCALLY: fresh lease epoch 4 -> may_send=(True,'lease-held'), current_epoch=4; epoch_is_fresh(2)=False (a stale writer's row is refused), (4)=True, (9)=False; arbiter unreachable -> lease expired -> may_send=(False,'no-lease'); no lease file -> same. The last two are the owner's rule implemented rather than described: NO REACHABLE ARBITER MEANS GLOBAL ACTIONS STOP, fail-closed - a quiet company is recoverable, two companies acting is not.
