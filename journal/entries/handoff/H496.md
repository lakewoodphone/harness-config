### C12 — schema conformance, with a baseline

MEASURED: **315 of 383 records fail the repo's own schema**, and did so long before this tooling
existed. `operational` declares `additionalProperties: false` and **82% of the corpus violates it**, so
the declaration is aspiration rather than constraint — a comment wearing a machine-readable costume,

**This is a BASELINE check, not a pass/fail gate.** Failing on 315 pre-existing violations would make
the verifier useless on the day it ships, and this file's own lesson is that a verifier which cries
wolf gets ignored. What matters is not that the corpus is wrong — that is known and recorded — but that
**it does not get worse unnoticed**, because nothing else would notice.

`SCHEMA_INVALID_BASELINE = 315` is a **literal, deliberately**. Derived from the corpus it would
ratchet silently and never alert. To raise it, someone has to change the number in a commit that says
why.

### C11 — held vs actionable, reported separately

`shouldSyncToWebsite: true` means a case **belongs** on the site; it does not mean the case is **ready**
to be. The reporter conflated the two and produced `would_create = 7` with `rc=1` on every run for
16.5 hours, for records each held for a documented reason. It now reports **held** (waiting, with a
reason) and **not-held** as separate numbers.

## THE MISTAKE I MADE, AND WHY THE FIX IS INFO RATHER THAN ERROR

**The first version of C11 emitted 40 ERRORs and was wrong.** Its "has a production order" test is a
**proxy** — does the record carry an `orderNumber` in one of three fields. The real tool decides
differently and far better: `lpt-sync-to-production.py` also detects duplicates by **title/token
overlap** and by **sibling records**, so it correctly SKIPs records my proxy called unactionable.

**Forty errors on correct behaviour is exactly the "cries wolf" failure this whole tool is built to
avoid** — and it is the **same calibration mistake C07 made** earlier in this file's life (where a
net-transition ranking flagged forward work as backward).

The lesson is not that the check is worthless. It is that **a proxy for another program's logic must
never outrank that program.** So C11 reports a count, labels itself a proxy *in the finding text*, and
tells the reader to run `--dry-run-all` for the authoritative decision.

**Caught before it shipped** — the 40-ERROR run was a local test, and the count went back to 7 before
the commit. That is the difference between running your own instruments and trusting them.
