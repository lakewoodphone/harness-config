## What changed
* **The location policy on every sold kiosk was proven permissive from the payloads they were actually sent**: all six carry `allowLocationServices = True` in their installed kiosk profile (decoded from `commands`/`command_results`, 67 payloads, 30 distinct device+identifier pairs). The device-side policy is not what stops a fix on the sold fleet.
* **DRN 2002's APN is fixed and queued.** `telnyx-apn` is a registered profile type all along (`PROFILE_IDENTIFIERS`/`PROFILE_FILES` in `nanomdm_client.py`), so `POST /fleet/devices/2002/install-profile?profile_type=telnyx-apn` was accepted - command `0748B6DD-3CBF-4F7E-B5A4-A1143EBF056F`. The queued payload was decoded and confirmed: `APNs=[{Name: data00.telnyx, AllowedProtocolMask: 3}]`, no `APN` key - the build the estate verified as correct (`60-lessons/postmortems.md`: `com.apple.cellular` has no `APN` key; the APN string is `Name`).
* **What that explains, and it is not what I first assumed:** 2002 was never mis-configured by omission. The corrected profile was **already queued on 2026-10-15 00:08** and has never been delivered, because the phone has not checked in since 2026-10-14 16:29. It was unreachable, not wrong.
* **One hand edit to a queue, stated:** deleted the superseded payload-version-2 InstallProfile (`F7C85BC5-...`) from 2002's queue by uuid, 7 -> 6 pending, so the phone does not log a pointless error on wake. Every remaining pending command on 2002 was decoded and is a correct build.
