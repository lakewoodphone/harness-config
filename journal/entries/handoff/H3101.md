## 2026-09-30 ~20:30Z · ZABZ-TECH · Two-way conversation delivered, and reroute made real: the objective's four requirements now each have code and tests

CHANGED (two more commits, on top of the five in H3097/H3099)

- `33e5bbd` **the durable child mailbox** — `lib/mailbox.js` plus `test/mailbox.test.mjs`,
 `test/conversation.test.mjs`. An append-only JSONL protocol (inbox, outbox, and a durable
 transcript that `mergeThread` appends to), carried into every dispatch's task. The child is
 told to read the inbox first, write as it goes, and NOT wait for a reply; the parent reads
 the thread back into its report and the thread persists, so a second dispatch on the same
 thread continues the conversation.
- `e08f8a5` **reroute that names the node it must avoid** — `task.excludeNodes` /
 `task.excludeLease` on the broker, `excludeNodes` threaded through the placer and passed by
 the provider on every retry, `test/reroute.test.mjs` (broker) and
 `test/reroute-provider.test.mjs` (provider).

THE OBJECTIVE, REQUIREMENT BY REQUIREMENT, WITH WHAT EACH ONE RESTS ON

1. **Crashes that kill child agents — FIXED** (`97c9c34`). One root cause: a detached async IIFE
 in the settlement watcher with no `.catch`, calling a getter that throws once the agent's own
 scope has released its projection registration (full chain in L3188). Patched at source,
 idempotent and anchor-asserting, applied and CONTROL-VERIFIED on ZABZ-TECH and on the
 `zabz-tech-linux` worker, with provisioning step 8d failing loudly if a version bump moves the
 anchor.
2. **Every failure retried / rerouted / never failing silently — DONE**. Classifier and planner in
 `lib/retry-plan.js` (3 attempts, at most 2 nodes, jittered backoff, 45-minute ceiling), the
 invariant that a child which STARTED is never re-dispatched, a bounded salvage on every
 non-clean outcome, an empty host treated as UNPROVEN rather than fatal, and — this round — a
 reroute that actually asks for a different node instead of hoping the placer picks one.
3. **Continuous two-way conversation — DELIVERED AS FAR AS THE RUNTIME ALLOWS, AND NO FURTHER.**
 Two measurements bound it, and both are in the code: `prepareContinuable` is DATA, never a
 capability (`types.d.ts:360-375`), so a remote child can never be a continuable child and
 implementing it would silently run the child locally; and `dsh --profile headless` takes one
 task positional with no `--resume` (`dsh-headless/lib/startup.js:21`). So the conversation is
 carried by files on the child's node: parent→child before and after a dispatch, child→parent
 at any point during its turn, and parent→child follow-ups across dispatches on one thread.
 **Not delivered, and not claimed: steering a child mid-turn.**
4. **Children spawning their own children — ALREADY TRUE, NOW ASSERTED AGAINST THE INSTALL.** A
 remote child boots `--profile headless` and inherits `dsh-base`, which binds the subagent tool
 to the `spawn` provider, so it can delegate locally on its own node.
 `test/child-can-spawn.test.mjs` reads that binding out of the INSTALLED runtime and asserts
 both that it is there and that no remote provider is claimed — so nobody later reads it as
 mesh nesting. It skips loudly rather than passing vacuously if the runtime is not found.

FOUR DEFECTS FOUND IN MY OWN WORK BY THESE TESTS (all on the record in the commits)
- a child's messages from turn N were LOST when turn N+1 ran, because inbox and outbox are each
 rewritten per turn — a three-message thread came back as two. Fixed by promoting each turn into
 an append-only transcript.
- `collectThread` ignored the transcript, so the canonical history was not counted.
- the thread name was silently sanitised, which could fold two different threads into one
 directory; it is refused instead.
- `mailboxRoot: false` did not switch the mailbox off, because `??` treated the OFF switch as
 absent and re-derived one.
- and from the broker work: `decide()` filtered its first-class pool by `excludedByCaller` only,
 so a node marked excluded by a REROUTE was offered anyway. That is the bug `excludeNodes` exists
 to fix, and without the test it would have shipped dead.
