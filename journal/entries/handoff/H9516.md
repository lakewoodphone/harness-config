## Addendum 3 to H9513 (same session, round 2 cont.) — the self-evolution hook was 91% inert, and it now has an instrument

### The finding that outranks everything else in this session

The alias store `~/.cfo-asks/aliases.db` is the self-evolution hook: what the system writes when he
answers, and reads before asking again. **11 rows; 10 could never be filed.**

| | |
|---|---|
| category `personal` or `unknown` (not in the ledger's 137) | 5 |
| no category at all | 5 |
| filable | **1** |

`category_id_for()` returns "" for a name the table does not hold, so each of those rows resolved a
charge as ANSWERED and filed nothing. The store looked healthy — rows, evidence, timestamps — and
was inert. That is why the same questions return: the channel was learning answers it could not
use.

**"personal" is not a category.** It is which ENTITY a charge belongs to, and the ledger carries
`entity_id` for exactly that. Mapping his word onto a category was a category error in the code.

### What is fixed and verified

- `build_alias` refuses to write a category that cannot be filed, keeps his exact words in
 `evidence`, and says why. (`textdecide.py`, deployed; 21/21 attribution cases pass.)
- The five historical rows corrected from **his own sentences**, each quoting the text and sid:
 `pass`→Parking & Tolls, `american professional`→Insurance, `pocono whitewater`→Travel,
 `aplpay dave busterfreehold nj`→Entertainment, `color me mine tomstoms river nj`→Entertainment.
 All five now resolve `solved=True` at 0.97 **to a real category id**, read back from
 `category_id_for()` — not assumed from the name.
- **New invariant `text-health.py` J1**: no learned alias may name a category the ledger cannot
 file. Reports the full backlog every run; FAILS only on a regression inside the window (default
 1 day). First run caught its own bug (`dict(row)` on a tuple) — fixed, because a check that
 crashes reports the same FAIL as a check that found something.
- **`text-health.py` now: 16 checks, 0 FAIL.** Mirror IN SYNC, 21 files.
- A test that encoded the defect: `test-attribute-reply` case 14 asserted `build_alias` produces
 category `"shop supplies"` — also not a ledger category. Now asserts an empty category with his
 phrase in evidence.

### The category table itself — measured, and partly his to decide

137 rows; **44 names appear more than once with different ids**. 29 are harmless (every alternate
used 0 times). **15 are genuinely split**: Credit Card Payment 59/49, Materials & Equipment 226/54,
AI & API Services 172/4, Gas & Fuel 53/1, Gross Receipts - Non-Card 193/8. A report grouping by
name silently merges them; a report grouping by id splits the books.

`category_id_for()` was `WHERE name = ? LIMIT 1` with **no ORDER BY**, so which twin a charge was
filed under was whatever the query returned. Now deterministic: this entity's id if given,
otherwise the id already used most, tie-break on smallest id, with the ambiguity printed once.

**Merging the 15 split pairs is not done and must not be done quietly.** Nothing is deleted from
his books without his explicit yes.
