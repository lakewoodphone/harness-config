## Two real defects found and fixed on the way

1. **`scripts/merge-settings.mjs` could not resolve `yaml` from a package root.** It probed
 `<base>/yaml/package.json` only, so the `<DSH_HOME>/profiles/web` candidate never matched — and
 because `harness-sync` merges settings FIRST, every later step (presets, links, bundle names) was
 skipped. That is why secratary-cloud and zabz-tech-linux had never received a preset update: their
 sync has been aborting at step one. Fixed by also probing `<base>/node_modules/yaml/package.json`,
 and the apply script now sets `DSH_INSTALL` / runs from the repo as a second route.
2. **`scp -r` nests the package**, so the first rollout created
 `packages/plugin-context-awareness/plugin-context-awareness/` with `package.json` missing at the
 top level — which harness-sync reports only as `link=no bundle=absent`. Both the bash and PowerShell
 installers now resolve the real source and move any nested copy aside (never delete).
