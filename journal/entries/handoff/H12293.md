### What landed

`com.lakewoodphoneandtech.filterai.approval.ParentApprovalGate` — the gate that makes "the parent
approves it" mean something on the device instead of in a chat.

The threat model is **not an abstract attacker**. It is a child holding the unlocked phone, which is the
normal state of a phone being used. Three properties, each with a test:

1. **No credential means no approval.** Defaulting to allow would hand the child the feature.
2. **The credential cannot be replaced without the current one.** Otherwise "forgot the PIN" is the fastest
 way past the gate — re-key it, then approve. (There is no "forgot PIN" recovery here on purpose; recovery
 would be the hole. A shop reset is the honest path.)
3. **Five wrong attempts lock for five minutes, persisted**, because a four-digit PIN is 10,000 guesses.

The PIN is never stored: PBKDF2-HMAC-SHA256, 120k iterations, per-install salt, `MessageDigest.isEqual`.
Approval applies through `RuleRepository.applyFromJson` — the same single writer a rules sync uses — so an
approved change cannot produce a state a normal sync would not. The broker report is a **required
parameter**, and `Applied(reported = false)` means *applied here, broker does not know* rather than success.

**8 tests, 0 failures, 61 seconds.** The duration is the defence, not slowness to fix.

### Still owed, and the ledger and the docs row both say so

Nothing in the UI stages a change for a parent to approve. The broker's `pending_rule_changes` surface
exists and `approveChange()` is ready to consume it, but no screen lists a staged change and asks for the
PIN. Android already carries the pattern to follow — `AiProfileProposalRepository` /
`AiProfileProposalReviewActivity` — so the next round copies an existing review screen rather than
inventing one.

This is deliberately a half. A26 reads `partial` and names what is missing, because a capability row that
says `present` while a parent cannot actually reach the feature is the drift this estate keeps paying for.

### Traps paid for here

- **Quoting, again, and the same fix:** escaped quotes inside a double-quoted PowerShell `-c` string break
 the regex it contains (`SyntaxError: unterminated string literal`). Every non-trivial transform goes in a
 script file; the cost is one `write` call and the saving is a failed round.
- **A new package is a features-gate event.** `check_features` refuses an Android package no row claims, so
 the row is part of the change, not paperwork after it — and writing the row forced the honest answer
 (`partial`) rather than the flattering one.
