**L3413 · LPT production counter: the live DSN, staff roles and bcrypt cost, the tRPC auth shape, one status click = 1 accepted / 3-4 rejected mutations, photo upload endpoint, and where a credential may live**

## 2026-10-09 · ZABZ-YOGA · LPT production counter: how to reach it, where its data is, and what is broken

Measured live on production (`lakewoodphoneandtech.com` + `api.lakewoodphoneandtech.com`) on
2026-10-08/09 with the dedicated read-mostly account `agent-verification@lakewoodphoneandtech.com`
(users.id 300, MANAGER). Every number below came from that session's own request logs.

1. **Which database is production.** `/opt/lpt/.env` `DATABASE_URL` →
 `co8c1665c0p5k.cluster-czrs8kj4isg7.us-east-1.rds.amazonaws.com:5432/d5oq83veii4rlb`, and the
 running `lpt-backend` container resolves the same value (`docker exec lpt-backend printenv
 DATABASE_URL`). Two cheap confirmations, both used here: `select inet_server_addr()` returns
 `10.0.184.73` (a private RDS address; the box's own Postgres answers on the docker network), and
 `select max("createdAt")::date from orders` returns today. The box's `lpt-postgres:5432/lpt_prod`
 container is a **stale mirror** — never write to it and never read it as the shop. psql exists
 **only inside `lpt-postgres`** on the box, so query the live DSN with
 `docker exec -i -e PGHOST -e PGPASSWORD ... lpt-postgres psql "$DSN"`; parse the DSN out of
 `/opt/lpt/.env` on the box and pass it as env, never on argv.

2. **Staff accounts and hashing.** `users.role` enum is only `ADMIN | MANAGER | CUSTOMER | PARTNER`
 (the frontend's `EMPLOYEE` is a type-level fiction — no such enum value exists, so a MANAGER is the
 lowest role that can reach `/work-orders` and open a work order). New passwords are bcrypt
 `$2b$12$`, 60 chars: `hashPassword()` uses `bcrypt.genSalt(BCRYPT_SALT_ROUNDS)` with
 `DEFAULT_BCRYPT_SALT_ROUNDS: 12` (production refuses < 12). Hash with the application's own library
 so the shape cannot drift:
 `printf '%s' "$PW" | docker exec -i lpt-backend node -e '...require("bcrypt").hash(pw,12)...'`.
 Old rows exist at `$2b$10$`; do not copy them.

3. **Storing a harness credential.** `~/.dsh/.credentials.yaml` (read by
 `scripts/model-failover-watch.py`) and `~/code/harness-config/.credentials.yaml` (root of the repo,
 `.gitignore` line 6) are the machine-local stores. **`harness-config` pushes to a public GitHub
 remote** (`offsite = github.com/lakewoodphone/harness-config.git`), so a journal entry is the right
 place for *where* a secret lives and never for the secret itself. I leaked a password into a tool's
 stdout once in this session by printing matching lines of the credential file; rotate on any such
 leak and never print the file.

4. **The counter's API.** `POST /api/trpc/auth.login` takes a **plain** body
 (`{"email":...,"password":...}`) — wrapping it in tRPC's `{"json":{...}}` envelope makes both fields
 read as undefined. Queries are GET with `?batch=1&input={"0":{"json":{...}}}`. The SPA keeps
 `accessToken`/`refreshToken` in localStorage; sign in through `/login`, and any page is reachable
 thereafter. A working account logs in and lands on `/work-orders?…`.

5. **One status click is not one mutation.** On an accepted transition the counter fires exactly
 **1** `workOrders.updateStatus` (200, measured 6.5 s to answer, toast *after* the server answers).
 On a transition the server rejects it fires **3-4** identical POSTs, each `500` — measured twice
 (`Cannot reopen a READY_FOR_PICKUP work order: reopenReason is required`). The status sheet shows
 the same seven statuses on every order, so it offers transitions the server refuses (a
 READY_FOR_PICKUP order is offered "In diagnosis") and never asks for the `reopenReason` the server
 demands. A count of "one click fired N mutations" is therefore only meaningful if you say whether
 the transition was accepted.

6. **Photos.** The upload POST is `POST /api/repair-intake/<caseId>/photos` → **201**, and it fires by
 itself once a case exists; selecting a file on the counter's "Book a device in" view only stages a
 draft. Storage rows are `repair_intake_case_photos` (`storageKey`,
 `repair-intake/<caseUuid>/<position>.<ext>`). On a work-order detail page with no counter case the
 Photos card is a dead end ("no counter case carrying this order number was found").

7. **Smaller facts worth keeping.** `/staff-intake?order=` and `?q=` survive the redirect to
 `/work-orders`; `?ticket=` is dropped. The More hub renders **6 groups and 27 destination cards**
 (+1 footer link) for a MANAGER. Tax is `pricing_config.taxRate` (6.625 %), served through
 `pricingConfigService.getCurrentConfig()` → `workOrders.getPricingSummary.taxRatePercent`, and the
 charge panel shows it as "Sales tax (6.625 %, added)". `CHARGE_PAGE_TOKEN` is not set on the box, so
 `/charge/<token>` uses the token baked into `charge-page.config.js`; correct token → 200, wrong → 404.
