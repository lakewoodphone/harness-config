**L3379 · Every refusal test can pass while the success path is impossible: the promotion was verified four ways to fail and had no way to succeed**

GOAL ROUND 25. I walked the cold-start chain hunting for another 'half built' link and found the worst kind: a step that had been verified to FAIL in four different ways and had never once been shown to SUCCEED. The promotion orchestrator refused correctly on a missing connector, on a primary still serving, on a missing tunnel, and on a promotion already in flight - and I had tested each of those. What had never been tested is the branch where everything is right, because it was IMPOSSIBLE: nothing in the survivor's bootstrap installed a Cloudflare connector, so a perfectly bootstrapped survivor would have served nothing, and the orchestrator would have refused forever, for the right reason, with no path forward. THE FIX: survivor-bootstrap.sh gained a final stage that installs cloudflared, fetches the tunnel token with the Cloudflare API credentials the seed already puts in .env (so no extra secret crosses), stores it 0600, installs the service, and verifies by outcome - Cloudflare must report at least one connector. ORDER IS THE DESIGN: the connector is the LAST stage, after verify, because an empty origin behind a live connector is worse than no connector. THE DEMONSTRATION: cloudflared happened to be installed on this laptop, so I brought up a connector for the STANDBY tunnel from here - DNS still pointed at the office tunnel, so it served nobody - pointed a locally-booted survivor at 8002, and ran the pre-flight: all five checks PASS, exit 0, and the report said what it WOULD do without doing it. Then I proved nothing changed (all four hostnames still on the office tunnel, no state file written) and stopped the connector, waiting out Cloudflare's heartbeat until it reported 0 connectors with no process left. RULES: (a) enumerate the branches of a decision procedure and ask which ones you have actually EXERCISED - a refusal path is easy to test and proves nothing about the path that has to work; (b) if a gate has a condition that nothing can ever satisfy, the gate is not a safety feature, it is a locked door - after testing that it refuses, test that it can open; (c) every stage that makes a host SERVABLE must be part of the thing that builds the host, or the build is decorative.
