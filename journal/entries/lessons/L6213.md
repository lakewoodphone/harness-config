# A safety property of "exactly one" made a shipped fix inert on live data

**Rule.** When you gate a behaviour on an inferred association, measure the distribution of the gate
condition against **real data before shipping it**, not after. I designed the reply router to attach
his text to an ask only when **exactly one** ask was open — the intuitive safe choice. Agent `r4-brain`
built it faithfully and then measured: `asks in window per row : {0: 313, 2: 5}` — **never 1**. The path
fired **zero** times on the live corpus, and his reply stayed classified NOISE.

The fix was not a wider threshold; it was replacing the rule with an ordered preference and making the
guess **visible**: explicit ref → content match → **inferred most-recent**, with the reply telling him
*"Filed against X — correct me if that is not the one."* An optimistic, self-correcting association beats
silence, and it beats a strict gate that never fires. The measured result of the change on the live
corpus: ANSWER count 1 → 2, including his real two-letter **"Yes"**, which had been stored
`state='ignored'`.

**Generalise:** a guard whose condition is rarer than the event it guards is not a guard, it is an
off switch. Print the condition's histogram before you trust it.
