**L5857 · sha256sum of a WAL-mode SQLite file is not a fingerprint of its visible data**

Measured 2026-10-16 on /root/accounting-data/live/accounting.db: the file is in WAL mode, main-file mtime 01:15:58Z, -wal 585,072 B at 01:19:03Z. Two runs of the same read minutes apart returned lpt uncategorised 89, 75, then 74 rows. The sha256 of the main file did not change. So a BASELINE.md that records sha256sum as the ledger fingerprint is recording a file that is not the data: the same hash can describe two different visible ledgers. Any number read out of this ledger must be quoted with a WAL-true fingerprint (checkpoint first, or record PRAGMA data_version and the -wal size/mtime) and never with a bare sha256sum. This is the measurement rule one layer down: a fingerprint is a claim about what WRITES the bytes, and WAL writes somewhere else.
