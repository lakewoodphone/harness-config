**L3821 · An MDM key absent from Apple's published schema is inert, and it manufactures a protection nobody has**

**L · An MDM key that is not in Apple's published schema is inert — and it silently manufactures a protection nobody has**

WHAT HAPPENED, measured 2026-10-14. Every Waze kiosk profile in `deploy/waze-mdm/profiles/` carries
`allowMicrophone=false`, and the 2026-06-14 audit log names it as how "all microphone … access" was blocked on
DRN 50. It is **not a key in Apple's Restrictions payload.**

The check, so it can be repeated rather than believed:
1. Apple publishes the payload schema at
 `https://raw.githubusercontent.com/apple/device-management/release/mdm/profiles/com.apple.applicationaccess.yaml`
 — 124,587 bytes, **210 keys, and no `allowMicrophone`**.
2. Cloned `github.com/apple/device-management` at `Release-v27.0` (2026-09-17) and grepped every file for
 `microphone`: 20 hits, all accounted for — the macOS-only TCC `Microphone` service (deny-only, deprecated in
 macOS 27), the declarative `com.apple.configuration.app.settings` per-app permission default, sample JSON, and
 `CHANGES.md`. None is an iOS restrictions key.
3. The sibling keys in the same profile (`allowCallRecording`, `allowChat`, `allowVideoConferencing`,
 `allowNotesTranscription`, `allowSiriAI`) **are** all present and documented, so the schema is current — this is
 not a stale file.

iOS ignores keys it does not know in a configuration profile. So the key is almost certainly inert, and the real
reason the Waze microphone button is dead is something else entirely — which the dossier has to test for rather
than assume.

RULES:
1. **Apple's schema is the only authority on what an MDM key does.** A key that appears in a generated profile, in
 a test asserting its value, and in an audit log is still not evidence that iOS honours it. The repo's own test
 asserted `restrictions["allowMicrophone"] is False` for four months — it tested the generator, never the device.
2. **A test that asserts our own output is not a test that the output works.** This is the same shape as the silent
 AI fallback and the empty-result-is-not-health rule: a claim about an action is not the action.
3. When a profile key's purpose matters, **grep Apple's published YAML before designing around it**, and treat
 absence as "inert until measured on a device".
4. The documented mechanism for the per-app microphone permission on iOS 26.4+ is the declarative
 `com.apple.configuration.app.settings` (`Microphone: None|Allow`), not a restrictions-payload key.

EVIDENCE: `deploy/waze-mdm/docs/voice-input/02-apple-keyboard-dictation.md` §5 (master `f585413b9`);
`deploy/waze-mdm/docs/voice-input/evidence/live-profile-restrictions-20261014.txt`; Apple schema URLs above.
