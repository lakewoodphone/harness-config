**L3670 · A scheduled task needing elevation fails QUIETLY: it 'restored' a Defender exclusion that was still live, because Get-MpPreference returns empty without admin and an empty security setting reads as an absent one**

**Measured 2026-10-11.** A scheduled task registered to undo a temporary Defender exclusion **ran, reported success, and changed nothing.**

## What happened

To speed a bulk copy I excluded two drives from Defender's real-time protection. I registered a
self-deleting scheduled task to put that back the moment the copy finished — the right instinct,
since the restore must not depend on a session being open. It ran twice and its log read:

```
no copy in flight - restoring
no Defender exclusion of ours was present
Windows Search was already running
verify - exclusions now: [N/A: Must be an administrator to view exclusions]
could not remove its own task: Access is denied.
```

**The exclusions were still live on the machine.** `Get-MpPreference` in a non-elevated context
cannot read `ExclusionPath` at all — it returns empty — so my "was it present?" test answered *no*
and the script concluded there was nothing to undo. It could not remove its own scheduled task
either. Every line of that log was technically true and the machine was left in the wrong state.

## The fix

```powershell
$principal = New-ScheduledTaskPrincipal -UserId "$env:USERDOMAIN\$env:USERNAME" -RunLevel Highest
Register-ScheduledTask -TaskName '...' -Action $action -Trigger $trigger -Settings $set -Principal $principal -Force
```

**`-RunLevel Highest` is not optional for anything that reads or changes security settings.**

## The general rule

**A scheduled task that needs elevation and does not ask for it fails QUIETLY, and an empty security
setting reads as an absent security setting.** Two habits follow:

1. **When a task's job is to undo something, verify the undo from OUTSIDE the task**, with the
 privilege that can actually see the thing. Checking `(Get-MpPreference).ExclusionPath` and
 `(Get-Service WSearch).Status` and `Get-ScheduledTask` after the fact is what caught this.
2. **"I checked and it wasn't there" is not evidence of absence when the check itself is
 privileged.** Same shape as the estate's standing rule that a refusal is not a health signal:
 a permission-denied read came back as `N/A: Must be an administrator`, and the code treated it
 as a negative.
