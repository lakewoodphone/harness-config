**L1092 · A summary that flatters the tree is worse than no summary**

`status` printed "CHECK 0 error(s), 0 warning(s) - clean" while `check` had thirty warnings (dangling refs, an empty-bodied handoff). It was computing a cheaper rule set and labelling it as the whole truth, on the one page every session reads. In the same vein, drift counted by exact hash reported 322 entries "not absorbed" after the migration had absorbed all of them, and pointed at a command that would have added nothing.

Rule: a summary must name the rule set it summarised, and a count that recomputes work must use the same identity rule the work uses. On the always-read page a false alarm is worse than silence, because it trains the reader to skip the line that matters.
