## L — `journal.py append --body-file` silently wrote the path as the body; a missing file is now a hard error

**What happened, 2026-09-25.** I ran
`journal.py append pain --title "..." --body-file C:\...\journal-pain-4.md` for a body file I had
forgotten to create. The command printed `+ P2545 -> entries/pain/P2545.md (2312 entries)`, **exit 0**,
and the entry it wrote had the filename as its entire body:

```
## P2545 — Every 300DDR email is flagged needs_response and filed as personal…
C:\Users\ezabz\code\_scratch\journal-pain-4.md
```

I then probed it deliberately with a path I knew was absent (`--body-file ...\no-such-file.md`). Same
result: `+ P2546`, exit 0, body = the path. **Two junk entries in the journal before anyone noticed.**

**Why it is worse than a typo.** The append path is the one operation this system depends on to exist
across sessions. A write that succeeds, announces success, allocates an id and stores *nothing* is the
exact failure mode the journal was built to prevent, and it leaves no error for `journal.py check` to
catch — the entry is well-formed, just meaningless.

**The cause, one line of Python.** `src = args.body_file or args.body`, then
`if os.path.exists(src): read it; else: body = src`. The `else` branch is correct for `--body TEXT`
and wrong for `--body-file PATH`, and nothing distinguished the two.

**The fix, applied and verified the same session** (`harness-config/journal/tools/journal.py`,
`cmd_append`): `--body-file` is now handled on its own — a path that does not exist prints
*"refusing to write the path as the body"* and exits 2. `--body TEXT` and `--body -` are unchanged.
Verified in all three modes: missing file exits 2; `--body "literal"` still previews correctly;
a real `--body-file` still previews correctly. P2545 and P2546 are retracted; the real content is
**P2547**.

**The general rule.** When one flag accepts either a path or literal text, resolve which one it is
*before* reading, and never let "the file is missing" degrade into "use the argument as data". **Append
paths must fail closed.** A silent no-op write is indistinguishable from a successful one, and this
journal has no other way to notice.
