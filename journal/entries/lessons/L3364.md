**L3364 · An installer that announces success without verifying what it wrote: the pipeline ate my variable and it wrote an empty script to /**

GOAL ROUND 10, and the best catch of the night because the bug was in code I had just written to AUTOMATICALLY repair the very gap this whole night was about. I extended office-return-watch.ps1 so that when the office comes back at 4am with nobody watching, it installs the offsite-copy push script and its cron on the office box. My remote command template was: tr -d '\\r' | REPO=/home/zabz/personal-secretary-mvp; mkdir -p \/scripts/server && cat > \/... && chmod ... && echo INSTALLED. Two defects in one line. (1) In a shell, 'tr | VAR=value' is a PIPELINE whose second element is an assignment, so REPO was never set in the shell that ran the rest - \ expanded to EMPTY, and the path became /scripts/server/ at the FILESYSTEM ROOT. (2) The content was piped into tr, so 'cat >' had no stdin and wrote a ZERO-BYTE file. (3) And the command still printed INSTALLED, because success was an echo rather than a check. Net effect had it run unreviewed: an empty push script at /scripts/server/company-offsite-push.sh, chmod 755, a cron line pointing at it every 15 minutes forever, and a log that said INSTALLED. The offsite gap would have appeared closed while nothing whatsoever was being copied - the exact silent-failure class this night has been dismantling. HOW IT WAS CAUGHT: not by reading it, but by running the template against a LIVE host with a harmless target (/tmp) before trusting the branch. That is the same discipline that found the autopilot gate and the 425-byte... [pardon] the UA 403, and it is the third time tonight that executing beat reasoning. FIXES: redirect form (tr -d '\\r' > \), and - the important one - the installer now VERIFIES what it wrote before touching cron: 'if [ ! -s \ ] then exit 3', 'if ! bash -n \ then exit 4', then prints the byte count. Re-tested: 'VERIFIED bytes=3295', mode 755, valid bash on the far side. CLEANUP, DISCLOSED: the failed template created /scripts/server/company-offsite-push.sh (0 bytes) at the root of a production box; I MOVED it to /tmp/stray-after-failed-test/ rather than deleting it, and verified / is clean - the no-rm rule applies to my own junk too. RULE: an installer must verify the artefact it installed (non-empty, parseable, correct path) and fail loudly, because 'echo INSTALLED' after a broken write is how a system acquires a permanent silent no-op. And pipeline assignments do not set variables in the parent shell - never build a remote install command out of 'producer | VAR=value; consumer \'.
