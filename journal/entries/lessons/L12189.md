**L12189 · A timeout that spans the browser queue looks like a slow gateway; pair client requestedAt with server requestedAt to find the gap**

MEASURED 2026-10-22, fx-ckpt / staging (branch fix/checkpoint-budget, commit aa93763).

A client-side timeout that spans the browser's connection queue looks exactly like a slow gateway,
and the recorded server latency will acquit the gateway every time. The checkpoint summary was
being lost on ~18% of boundaries (6 of 34), all aborting at 12.01 s against a 12 s bound. The
`assessment_ai_events.transport` said the model was fine: executionMs median 3,303.5, p95 5,366.9,
max 6,261, queueWaitMs 0 (n=84, staging, `docker exec -i lpt-postgres psql -U personality -d
personality_test`).

The missing seconds live in an interval NO clock in the system records: client dispatch ->
route handler start. Reconstruct it by pairing two stores that do have times: the client's
`requestedAt` from `assessment_session_records.session_json.participants[].session.aiHistory[]`
(the entry is written even when the fetch aborts, status "failed", error "signal is aborted
without reason") against the server's `transport.requestedAt` in `assessment_ai_events`. Six
aborts, three reached the route: handler started 6.46 / 8.51 / 11.56 s after dispatch and each
completed 0.61-3.65 s AFTER the card had already fallen back. Successful checkpoints: 0.05-0.98 s.

Cause: staging serves HTTP/1.1 (`curl -sI` -> `HTTP/1.1 200 OK`, `Via: 1.1 Caddy`) = six sockets
per origin, and 4-6 question renders were open at every checkpoint dispatch (one fired per answer,
none returned). Fix = cap concurrent question renders at 1 (drop, not queue; the component re-checks
whether the current item has a render on every session change, so it self-heals).

Two things worth remembering:
1. Applying the p95 x 1.5 rule to executionMs gave 8.05 s - LOWER than the existing 12 s. When a
 prescribed formula returns a smaller number than the current constant, the constant was not the
 defect and the loss is somewhere the metric does not reach. Say that instead of raising it.
2. Payload size is not a latency lever. The same checkpoint body at 19,005 B took 4.287 s wall and
 at 6,526 B took 4.203 s - a 65.7% cut for 84 ms. Shrinking it is honesty about bytes and cost,
 never a fix for a timeout.
