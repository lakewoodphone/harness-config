**L3883 · A machine's note is not human work: read what WRITES the field before filtering on it**

2026-10-20, LPT work-order close-out. Owner rule: close anything untouched >50 days. First implementation counted orders.updatedAt and ANY customer_notes row as a touch.

Both are machine-written. Measured on operational: updatedAt clusters 2-4 rows inside one second (2026-08-13 03:00:29-58) and customer_notes authorId 1 (lpt-write/agent) wrote 528 notes in 60 days, authorId 168 (status sync) 255. Consequence: WO2512300001, 294 days old, was skipped because an agent wrote an explanatory note on it 6 days earlier - and 157 of 163 READY_FOR_PICKUP orders were 'protected' the same way. The owner caught it in one line: 'didn't i just freakin tell you that anything with no updates and not touched in 50 days should be closed out'.

Corrected definition: a note by a non-machine author, a payment row, or a message tied to the order. Machine authors configurable (default 1,168).

Second defect caught in the same session before it shipped: the 'no human activity' fallback was epoch, which is always older than 50 days, so EVERY brand-new work order qualified - a dry run's last three rows showed an order opened that day about to be closed. Read the tail of a dry-run list, not the head.

Result: 72 + 47 = 119 orders closed, 0 candidates remaining, ledger verified 407 lines. Tool: lpt-ops/bin/lpt-close-stale, docs/close-stale.md, commits b73bab4 + this one. Supersedes nothing; extends D3991.
