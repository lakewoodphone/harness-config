**L2058 · A URL-specific credential.https://github.com.helper pointing at gh's git-credential silently breaks git when gh's token rots**

SYMPTOM (ZABZ-YOGA, hit 2026-09-18): any non-interactive 'git fetch' failed with 'bash: line 1: /dev/tty: No such device or address' / 'failed to execute prompt script (exit code 1)' / 'fatal: could not read Username for https://github.com'. In an interactive session it would have popped a login prompt instead, so it looks like a missing credential rather than a misconfiguration.

ACTUAL CAUSE: the laptop's user git config did not use GCM for github.com at all. It had:
 credential.https://github.com.helper= (empty - resets that URL's helper list)
 credential.https://github.com.helper=!'C:\Program Files\GitHub CLI\gh.exe' auth git-credential
so github.com delegated to gh's credential helper, and 'gh auth status' reported 'The token in default is invalid.' gh returned no credential -> git fell through to an interactive prompt -> which cannot run headless. The plain 'git config --get credential.helper' returning 'manager' was a RED HERRING: that value comes from the Git-for-Windows SYSTEM config, and the URL-specific override supersedes it for github.com.

THE DIAGNOSIS THAT FOUND IT: 'git config --list --show-origin | grep -i credential' on the machine, not 'git config --get credential.helper'. The per-URL keys are invisible to the latter.

THE FIX APPLIED (ZABZ-YOGA, 2026-09-18):
 1. git config --global --unset-all credential.https://github.com.helper
 2. git config --global --add credential.https://github.com.helper store
 3. install the credential into ~/.git-credentials, ideally by piping it to 'git credential approve' over ssh STDIN so the token never appears in argv, a log, or a transcript
 4. git config --global credential.helper '' ; git config --global --add credential.helper store
 (step 4 matters: without it GCM is still consulted and every fetch prints 'fatal: Unable to persist credentials with the wincredman credential store' - harmless but it looks like a failure and will mislead the next reader)
VERIFIED: two independent fetches, branch resolved, 'git show <ref>:<path>' printed the file.

BACKUP / ROLLBACK on secratary: /tmp/laptop-gitconfig-backup.txt holds the pre-change global config. Original github.com helper value to restore: !'C:\Program Files\GitHub CLI\gh.exe' auth git-credential (with the empty reset line before it).

GENERAL RULE: on these Windows boxes the ssh default shell differs per machine - ZABZ-YOGA's is PowerShell (no grep/head/printf), so remote one-liners must be PowerShell. Also: 'gh auth status' is the fastest way to check whether a machine can reach GitHub at all, and it is worth running BEFORE blaming ssh or the network.
