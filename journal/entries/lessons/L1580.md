**L1580 · A frozen subsystem_health entry for a disabled subsystem is a task generator (W4/D1)**

Measured 2026-09-15 on secratary: boa_sync (114 consecutive_failures, last attempt 2026-07-21), spending_report (38, 2026-09-03) and balance_capture (2) sat in data/autopilot_state.json subsystem_health for 42+ days. None is installed (flags false, spending script absent, zero boa% tables/work orders). ~25 task rows/day about them since 2026-09-06 because every reader treats consecutive_failures>=3 as live work, and a disabled subsystem never runs again so the counter can never clear. Fix shipped on agent/w4-generators (commit 79fe326d): app/services/subsystem_presence.py probes evidence (enabled flag, artifact, module, table, work-order) and retires entries by writing last_status=disabled_superseded + zeroed counters on state load and before every save; autopilot._record_subsystem refuses to record a failure for a not-installed subsystem. Rule for future-me: a failure counter whose owner can never run again is not history, it is a work generator. Presence, not absence, is what makes a subsystem's failures actionable.
