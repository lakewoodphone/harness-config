**L3361 · To relocate a service, find what it READS - not what it is called: the broker needed the tailnet, not ssh to the nodes**

GOAL ROUND 7. The mesh placement broker runs on the office box, and tonight that killed fan-out on EVERY machine - including this laptop, which was fully up - because the client addresses it at secratary-ts:http://localhost:3091 and treats an unreachable authority as a typed error (deliberately: the alternative once produced 11 bogus placements from a 30s ssh blip). I had ASSUMED relocation was gated on ssh trust ('Box 1 was refused, so a pull can never work' was my earlier reasoning about a different script). Reading lib/broker.js's roster header answered it in one paragraph: 'The broker never writes a reading into it and never keeps a heartbeat. baseUrl is the node's gate ... and the broker appends /mesh/capacity.' It reads each node's capacity over HTTP at https://<node>.tail93e6e6.ts.net/mesh/capacity, published by tailscale serve. It does not ssh anywhere. So the real requirement is not ssh trust but TAILNET MEMBERSHIP - and the laptop is a tailnet member today while the Hetzner boxes are not (dead auth key). GENERAL RULE: when asking where a service can live, enumerate what it READS and WRITES, not what it is named or where its config points. That single question turned 'needs the office' into 'needs any tailnet node', and changed the fix from a project into an option. VERIFIED BY OUTCOME: started the broker on the laptop with the office dark, queried /nodes (reads 5, readFailures 4 - the four office nodes timing out after 4000 ms), then POSTed a real placement and got node=zabz-yoga-1, position=0, tier=fits, lease granted, with the four dead nodes named in the rationale as 'unreachable ... reported, never dropped, never faked'. So tonight's fan-out would have worked had the broker been somewhere alive. Also recorded: the durable fix is the broker on the always-on Hetzner box, which needs a FRESH TAILSCALE AUTH KEY (owner's console, 2 minutes) - that requirement is now precise rather than vague.
