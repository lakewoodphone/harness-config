**L1676 · SQLite binds a ? inside ON CONFLICT DO UPDATE to NULL on INSERT; and 'not in (True, 0, None)' is not a health predicate**

**Two SQLite behaviours that produce silently wrong data — both hit in one session, both with a cheap test.**

**1. A `?` inside `ON CONFLICT ... DO UPDATE ... CASE` binds to NULL on the INSERT branch.**
Measured on SQLite 3.49.1 (2026-09-15). This returns NULL:

 INSERT INTO t(source,status,last_ok) VALUES(?,?,?)
 ON CONFLICT(source) DO UPDATE SET
 last_ok = CASE WHEN excluded.status='ok' THEN ? ELSE t.last_ok END
 -- params: ('s','ok',None,'ok','NOW') -> last_ok is NULL, silently

while the same CASE with the value passed as a plain column, or in `ON CONFLICT ... WHERE`, works.
The consequence in this system was that `last_ok` recorded "never succeeded" for every source's
first run — so a freshness check would report a freshly-built index as never having been built,
which is the exact class of lie the whole freshness design exists to prevent.
**Rule: never bind a parameter inside the DO UPDATE clause. Compute the value in Python and pass it
as a VALUES column.**

**2. `value not in (True, 0, None)` is not a health predicate.**
In Python `True == 1` and `False == 0`, so both of these are true:
`0 not in (True, 0, None)` is False (correct), but `1 not in (True, 0, None)` is **False** — a count
of 1 was read as healthy — and `False not in (True, 0, None)` is also **False** — a boolean failure
was read as healthy. An integrity check written this way passes on a broken index.
**Rule: check health by type (`isinstance(v, bool)` then `v is True`), never by membership in a
heterogeneous tuple containing both a bool and an int.**

Both were found by writing the test before trusting the code, and neither would have been caught by
the code appearing to work: the first wrote a plausible wrong value, the second returned "healthy".
The generalisation: **a health check is itself code that must be tested with a deliberately broken
input.** A check that has never been shown to fail on a broken thing is not evidence of anything.
