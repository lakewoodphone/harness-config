**L2089 · Never copy a multi-gigabyte live database for a test on the authority, and never put it in a child's brief**

**L · 2026-09-20 · ZABZ-YOGA — Never copy a multi-gigabyte live database "for the tests" on the authority, and never let a brief ask for it**

**What happened.** A mesh child (the owner-queue guard work) was told, in my own brief, to test against a
copy: *"`cp /home/zabz/personal-secretary-mvp/data/secretary.db /tmp/oq-test.db` … use `--db`"*. The
authority's database is **9.80 GB** (measured 2026-09-20, `database.size_bytes = 9802313728`) and lives on
a **dm-crypt** volume. The child ran the copy for **17+ minutes** (PID alive 918 s, file at 4.44 GB at
15:10Z, 9.80 GB at 15:19Z) and it saturated the disk.

**Measured consequences, all on the live company machine:**
- load average **23.87** (1-min) against a machine that had been at 0.75 an hour earlier, with writeback of
 ~18 GB of dirty pages; `vmstat`-style evidence: no single process above 5.1 % CPU, so the load was I/O.
- **`ssh` to the authority stopped working**: TCP connected (port 22 open) but `kex_exchange_identification:
 write: Connection timed out` — the handshake could not complete, repeatedly, for ~20 minutes.
 `/health` over the tailnet took **18.5 s** (normally 7 ms on loopback).
- An SSH-delivered command was cut off mid-flight twice.
- The copy had to be killed by hand, and killing it took three attempts because the channel that would kill
 it was the channel it was breaking.

**The rule.**
1. **Never copy a live database of more than a few hundred MB on the authority.** For a test, build a
 scratch database containing only the tables and columns the test needs (the guard tests need `tasks`,
 `reminders`, `owner_message_queue` and nothing else — a few KB), or `VACUUM INTO` a filtered subset, or
 copy the schema with `sqlite3 new.db ".schema"`. A test fixture is not a database clone.
2. **Never put a heavyweight operation in a child's brief without bounding it**: a size cap, a time cap, or
 an explicit "if it is bigger than X, do not copy it — build a subset". A brief that says "copy the DB"
 on a 9.8 GB encrypted volume is an instruction to degrade the company for half an hour.
3. **The lesson generalises past this bug.** The authority is a *live* machine: any fan-out that reads or
 writes gigabytes there competes with the shop's inbound calls and texts. Weight the brief by the size of
 the thing it will touch, not by how simple the instruction looks.

**Detection.** `uptime` (1-min load), `ps -eo pcpu` (flat CPU while load is high ⇒ I/O), and
`ps -eo pid,etimes,cmd | grep cp`. Recovery: kill the copy (relieves nothing instantly — the dirty pages
still have to flush), then check `free -m` and `df -h`.
