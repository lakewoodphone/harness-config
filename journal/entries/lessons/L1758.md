**L1758 · Neither repo may be deployed by copying a tree: ha-config's deploy deletes 72 live files, and the secretary repo has diverged from production in both directions**

The ha-config repository is NOT safe to deploy as-is, and the personal-secretary-mvp repository has diverged from production in BOTH directions.

MEASURED 2026-09-16.

1. ha-config: `scripts/deploy.ps1:667` is `rsync -avz --delete`. Running it would REMOVE 72 live files
that are not in the repo, including:
- `timeline_tools/phoenix-clip.py` - six live shell_commands call it
- `timeline_tools/snapshot_probe.sh` - live `configuration.yaml` calls it
- five `packages/.backups-20260911-183834/*.pre-deploy` files - the ONLY surviving record of the
 pre-2026-09-11 state, and not reconstructible from git
It would also OVERWRITE 25 differing files, including `configuration.yaml`. The scp fallback path
(lines 631-637, 701-705, 708-799) deletes nothing, so the risk is transport-dependent and the two
paths are not equivalent.

2. personal-secretary-mvp: the repo `main.py` is a WINDOWS dev copy and the server runs a LINUX
production copy. Whole-file counts: `app/main.py` deployed 22,250 lines vs repo 22,277, but
**27 hunks, 297 added, 268 removed** - they have diverged both ways. Deploying the repo file would
LOSE deployed-only production fixes:
- `"/api/v1/fleet/", "/api/v1/dialpad/"` in a middleware fix whose own comment says the surface was
 "reachable UNAUTHENTICATED on the public internet because the middleware exempted everything under
 /api/v1/"
- the `/health` DB single-flight cache with `HEALTH_DB_CACHE_S`, which is the fix for the lock
 contention that makes `/health` return `ok:false` today
- `from app.logging_setup import configure_logging` (without it, per its own comment, every
 `logger.info` is discarded and warnings reach the journal with no level or timestamp)
- `accounting_db_path()` calls, which the repo replaces with the hardcoded Windows path
 `C:/Users/ezabz/accounting-data/live/accounting.db`
- `assistant_total_prompt_char_cap: int = 200_000` in `config.py`

RULES:
1. Never deploy either repo by copying a tree. Deploy surgically, file by file, and for `main.py`
 patch a REGION, not the file.
2. Before editing a live-serving file, diff the DEPLOYED file against the repo and list what only
 the deployed side has. An agent's "I compared deployed and HEAD" can be true of the region it
 looked at and false of the file: an agent reported "the only divergences were the two you named"
 while the whole-file diff showed 27 hunks. Read the whole-file diff yourself.
3. An agent's report is a claim, not evidence. This is the third time that rule paid for itself today.
4. Drift runs in both directions: the repo had LOST live config (`recorder:`, `media_dirs:`) and the
 live tree had fixes the repo lacks. A one-directional "is the repo behind?" check misses half of it.
