**L12183 · e2e seeds must write the identity-scoped key, and a worktree removes node_modules through a junction**

Two facts learned fixing the personality-test browser gate in _pt_wt/fx-integrate (2026-10-22).

1) THE ASSESSMENT MIRROR IS PARTITIONED BY IDENTITY. Every storage key is '<baseKey>:<scope>' where scope is the server's libraryFingerprint for the signed-in person (GET /api/auth/session -> 'user:<32 hex>'). Specs seeded the bare names, so five specs asserted against an empty library and failed with 'element not found' while the product was correct. Fix pattern: ask the server the same question the app asks, then build the key with the app's own getAssessmentMirrorStorageKey; exported once from tests/e2e/support/assessment-seeds.ts as seedLocalStorage / resolveLibraryScope / scopedStorageKey. Any future spec that seeds localStorage must go through those or it silently seeds nothing.

2) NEVER RUN 'git worktree remove --force' ON A DIRECTORY WHOSE node_modules IS A JUNCTION. Windows recursed through the link and deleted part of the MAIN checkout's node_modules (.bin and @next/env - the alphabetical start). Symptoms: 'Cannot find module @next/env', npx '<bin> is not recognized', dev server exits 1. It looks exactly like a concurrent agent's broken install, so the first instinct was to blame someone else. It was me. Repair: npm install in the junction TARGET (restored 43 packages, 3m) - and it rewrites package-lock.json, which must be reported. Correct cleanup order: cmd /c rmdir <junction> FIRST (removes the link only, target untouched), verify the target's package count, then delete the directory.

Verification discipline for any junction teardown: quote package counts before and after (measured 329 -> 329).
