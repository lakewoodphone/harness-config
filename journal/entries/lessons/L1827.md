**L1827 · macOS load average is not a CPU signal, and Pages free is not available memory**

Two measurement traps on macOS, both measured 2026-09-16.
1. Load average counted WAITING threads, not runnable ones: the Mac Mini read 1.5-2.2 load while
 top's own line said 89.7% idle, 4 running of 765 threads. I had read 'load 3.63 on 10 cores'
 as a busy machine and it was not evidence of busyness. Use top's CPU line or a ps sum of %CPU.
2. 'Pages free' was 148 MB on a 16 GB machine, because macOS keeps essentially all RAM as cache.
 Passing that as free memory would declare a healthy Mac memory-dead and would not mean the
 same thing as Windows' Available MBytes or Linux's MemAvailable. Reclaimable on macOS is
 free + inactive + speculative + purgeable, times the page size. The capacity contract must say
 which definition it means, or the number is not comparable across the mesh.
ALSO: VMware-style per-process windows -- 'top -pid' accepts exactly ONE integer on macOS and
rejects a comma list, exiting without sampling; with stderr redirected it reads as 'no processes'.
