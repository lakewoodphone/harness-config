**L12170 · Process-creation auditing was OFF on zabz-yoga - a 2-minute terminal-flash burst cannot be named after the fact**

2026-10-21, zabz-yoga. Owner reported a terminal window flashing ~3x/second for ~2 minutes at 17:58-18:01 (and once the previous night). Nothing could name the spawner after the fact: 4688 Process Creation auditing was **No Auditing**, and Microsoft-Windows-TaskScheduler/Operational held ZERO events in a 20-minute window — so no process-launch record existed anywhere on the box.

ENABLED 2026-10-21 18:20 on zabz-yoga:
 auditpol /set /subcategory:"Process Creation" /success:enable
 reg add "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System\Audit" /v ProcessCreationIncludeCmdLine_Enabled /t REG_DWORD /d 1 /f
Verified, not assumed: launched a marker cmd.exe and read its 4688 row (18:20:55, C:\Windows\System32\cmd.exe) carrying the full command line.
To undo: auditpol /set /subcategory:"Process Creation" /success:disable

RULE: on Windows, before investigating any transient process or window event, check whether 4688 auditing is on. If it is off, the event is unnameable after the fact — turn it on FIRST, then measure the live rate.

What was measured and eliminated for this incident (all read this session, host zabz-yoga):
- 0 new cmd.exe processes across a 20 s poll (18:02:14-18:02:34).
- 0 visible console windows across 1,523 samples at 20 ms over 50 s spanning a watchdog tick (18:08:22-18:09:12), including ConsoleWindowClass, PseudoConsoleWindow and CASCADIA_HOSTING_WINDOW_CLASS.
- ~\.dsh\multi-window\windows.log: only Edge --app windows; one at 18:01:22-18:01:24 (slot=3, origin=19202) — a browser window, not a terminal.
- link-probe.log: one line per 30 s, five lines per run; each run is exactly ~2 minutes but spawns nothing at 3 Hz.
- watchdog.log: no 10/21 entries at all; the last burst was 2026-10-20 19:00-19:24 ("could not recover an engine on 3099", origins prewarm ECONNREFUSED) while the engine crash-looped — five engine boots 19:21-19:42.
- plugin-health spawns snapshot.ps1 every ~5 s WITH windowsHide:true (lib/index.js:211), so it is not the source.

A 3 Hz burst lasting ~2 minutes is a bounded retry loop (~360 spawns), which is why the forward fix is the 4688 record rather than a guess.
