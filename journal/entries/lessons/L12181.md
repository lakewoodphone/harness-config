**L12181 · A question count and a promised floor are both derived from the wrong field if they count answers or a mutable sequence**

Personality-test engine (fix/engine-runtime, commit ff852dd). Two measured defects shared one root cause: a number was computed from a field that also holds something else. (1) 'Question N' was nswerOrder.length + 1, but answerOrder also holds the 'A Little About You' prelude answers (C15-C18) recorded before the run starts, so the first question displayed as 'Question 5'. (2) The 'at least N' floor summed session.sequence plus each module's live itemIds, both rewritten mid-run (refreshSequence inserts adaptability; reconcileAdaptiveSelections appends adaptive ids), so the floor went 88 -> 93 -> 99 -> 123 during one run and the progress bar walked backwards. Fix pattern that generalises: give the engine an explicit append-only log of what it actually SERVED (written only where the dispatcher hands an item out) and compute a floor from the CONTENT (sum of bank cores), never from the run's mutable state. A floor computed from a mutable sequence is not a floor. Also: a stored final report must never be conditioned on replaying to 'complete' - the replay uses today's content, so any content change silently deleted a finished, paid-for report; keep it and record the definition version instead.
