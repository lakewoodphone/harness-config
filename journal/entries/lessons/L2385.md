**L2385 · The orchestrator must have its OWN worktree - a concurrent shared-types rebuild in the same worktree produced a false 'build is broken' finding**

**Rule:** the orchestrator must work in its OWN worktree. Never verify, build or deploy in a worktree an agent is using. Isolation between worktrees is real; isolation between two processes in the SAME worktree is not.

**Measured 2026-09-22, and it nearly produced a false report.** Running `node scripts/deploy-frontend-cloudflare.mjs --env test --dry-run` failed:
`Error: [vite]: Rolldown failed to resolve import "@phone-and-tech/shared-types" from frontend/src/features/payments/components/POSRegister.tsx`.
I was one step from reporting "the production frontend build is broken, which blocks deploy".

**It was not broken.** `pnpm -F phone-and-tech-frontend run build:production` run directly in the same worktree: **exit 0, 3231 modules, 15.48s**. `shared-types/dist` existed both before and after.

**The cause:** the scheduler agent (job 74) was running in `_fleet/waze-billing` - the same worktree I was verifying in - and its definition of done includes `pnpm --filter @phone-and-tech/shared-types build`. That package's own build script begins `node -e "fs.rmSync('dist',{recursive:true,force:true})"` and only then runs `tsc`. So for the duration of that clean+rebuild, `packages/shared-types/dist/index.js` - which the package's `exports` map points at - does not exist, and any concurrent build that resolves the package fails.

**Two things this proves:**
1. **`clean` + rebuild of a workspace package is not atomic.** Any other process resolving that package during the window fails with a confusing, unrelated-looking resolution error. It is a race, not a defect.
2. **Two agents in one worktree is the failure.** The worktree is the unit of isolation; sharing one between the manager and an agent silently reintroduces every hazard worktrees exist to prevent. The manager must cut its own.

**The generalisation:** a build that fails once and passes on re-run, with a resolution error about a workspace package, should be suspected as a concurrent clean/bake before the code is suspected. And the orchestrator's own worktree is not optional.
