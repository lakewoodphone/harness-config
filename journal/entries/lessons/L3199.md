**L3199 · On this harness the preset rows that matter are the GENERATED copy inside the profile patch, not the preset file**

ZABZ-YOGA 2026-09-30, second failure of the same row: after I renamed the removed workflow-worker-thread row inside ~/.dsh/.agent-presets/*/agent.cordis.yml and verified it on disk, the engine STILL threw 'agent-preset/invalid: workflow-worker-thread ... never started'. Cause: the engine does not mount the preset file directly. It mounts a GENERATED copy of those rows that scripts/make-preset-rows.mjs writes into the managed 'preset-rows: BEGIN/END' block inside ~/.dsh/profiles/web/cordis.patch.yml. That block still carried the old id and package name, so the row mounted, failed to import, and the audit reported its absence as 'never started'. FIX: run 'node scripts/make-preset-rows.mjs --install' (which regenerates both profiles/web/cordis.patch.yml and profiles/web/presets.generated.patch.yml) after ANY preset row change, then restart the engine, and prove it with a session creation. NOTE: that generator REFUSES '--install-target <live path>' (exit 1, writes nothing) -- it will only write its repo default, so the live copy must be updated by the sync or by the same substitution applied by hand. LESSON: when a composition is generated, editing the source is half the change; the generated artefact is what runs.
