**L10623 · A job with zero steps and a 3-second failure is a billing or runner fault, not a code fault: read the check-run annotation**

A GitHub Actions job that never starts is not a red build and not a quiet queue. Measured 2026-10-20 on phone-and-tech-full: three workflow runs failed in 2-3 seconds with steps: [] and the annotation 'The job was not started because recent account payments have failed or your spending limit needs to be increased', reproduced on a re-run 6 minutes later, while the same workflows SUCCEEDED 5 minutes before that. gh run view --log answers 'log not found' for these, which reads like an infrastructure hiccup; the truth is only in the check-run annotation: gh api repos/<owner>/<repo>/check-runs/<job_id>/annotations. What it cost: 10 finished branches that could not merge, and a night loop that would have kept opening PRs it could not land. The rule: when a required check fails in under 5 seconds with zero steps, read the annotation before you debug the code. And when a repo's CI cannot run, the honest move is to verify locally, say so, and put the payment in the owner queue.
