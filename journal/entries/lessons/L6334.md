**L6334 · The reason was already computed and never written next to the row it explained: 1,588 rows moved from 52 to 78 percent**

Measured 2026-10-16 on the CFO ledger. All 293 learned rules carry an evidence[] array with a human sentence and its reference - 'our ledger already categorises this merchant: Materials & Equipment (52 of 62 charges) [records accounting.db/transactions]'. That sentence was computed when the rule was learned and never written next to the rows the rule governs, so 2,853 active rows carried a justification naming the TOOL (auto_rule:card autopay - internal transfer (conf=0.98)) and not the reason. Appending the rule's own evidence to those rows moved P2 from 3,271 (52.3 percent) to 4,859 (77.8 percent) with no research, no new claim, and no category touched. Two things about the method are the lesson. First, the match had to be constrained by CATEGORY as well as merchant: without that, the 'rule pattern appears in the merchant' route claimed 993 rows and a lookalike rule with a different category would have been quoted as the reason - a number that would have looked like progress and been a lie. Tightened, it claims 561. Second, the metric could not see the work: cfo-provenance.py counted P2 by prefix, so appending a reason changed nothing in its own report. The definition of a measured tier is part of the measurement, and a predicate written before the work is often the wrong predicate after it. Verified: category_id changed 0, no justification shortened, original text preserved verbatim as a prefix in all 1,588, ledger totals identical.
