**L1804 · A tool call that never returns kills the whole process tree it started**

Measured twice on ZABZ-YOGA 2026-09-16 while building the phone gate. A pwsh tool call has a
120 s ceiling; when it is hit, the runner kills the whole tree. A nested `pwsh -File
phone-gate-ensure.ps1` whose Start-Process started the gate NEVER RETURNED: the work had
already succeeded (the status record said `repaired`, the gate had been listening) and the
gate was dead a second later anyway. Same shape over ssh: the gate started on ZABZ-TECH during
an ssh session was gone when the session closed, and the one-minute watchdog resurrected it
(pid 22196 -> 9020).

RULE: anything meant to outlive the call must be started by something that does not inherit the
caller's stdout and does not sit in the caller's job object -- a scheduled task, the watchdog,
or a WScript.Shell.Run detached child that writes its own log. Verify survival by re-reading
the process table in a LATER call; the first call returning is not evidence.
