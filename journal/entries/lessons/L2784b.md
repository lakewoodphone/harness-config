**L2784 Â· A liveness test must count overlap, never a wall-clock ratio**

A liveness assertion must count overlap, never a wall-clock ratio.

Evidence: two tests in `kosher-filter-ai` asserted `elapsed < serialised / 2` to
prove a DNS forwarder demultiplexed concurrent queries. The implementation was
correct and every functional assertion passed, but the ratio failed twice under
host load â€” 1585ms and 351ms against a 540ms baseline, on a laptop running 14
agent loops â€” because the ratio measures the property *through a quantity the
machine controls*. A loaded machine inflates elapsed time and the test then
reports "the implementation serialised", which is not the claim the measurement
supports.

The fix (commit 61bc7df, branch kf0928/windows-merge, report section 7 of
`_fleet/kf0928/windows-merge/REPORT.md`): have the test double track
`MaxInFlight` â€” the high-water mark of "unit received, answer not yet sent"
(`Interlocked.Increment` on receipt, `CompareExchange` high-water raise,
decrement after the send, in a `finally`) â€” and assert `MaxInFlight >= 2`. It
counts events that already happened, so a slow machine can make the event later
but cannot make it not have happened. Observed high-water marks with the
threshold forced to an impossible 99: 12 of 12 and 8 of 8, so `>= 2` sits at a
4x-6x margin while still being the honest boundary.

Two rules that came out of it, both measured rather than assumed:

1. Drop the wall-clock assertion entirely rather than widening it. "If in doubt,
 drop it" is correct: any millisecond budget can be exceeded by a busy host,
 so a widened timing test is a fainter version of the same defect. A latency
 guard is a different test with a configuration-tied budget, not the liveness
 test.
2. Prove the new guard can fail. Temporarily serialising the production seam
 (a per-session `SemaphoreSlim(1,1)` around the exchange) turned both tests red
 with `high-water mark 1` while every functional assertion still passed â€” which
 is exactly the distinction the fix was asked to draw. Restore with targeted
 reverse edits and verify with `git diff --quiet -- <production path>` (exit 0),
 never with `git checkout` or a reset.
