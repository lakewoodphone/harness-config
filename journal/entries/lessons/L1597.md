**L1597 · Never relax a guard to make tests green - move the coverage instead**

2026-09-15, phone-and-tech-full backend/src/__tests__/ui.test.ts. A guard change (procedure -> protectedProcedure) turned 16 tests red. The tempting fix is to relax the guard so the tests pass - which would have silently removed an authorisation control that production already enforces. The right fix kept the guard and moved the coverage: export the pure builder the route wraps (buildNavigationContext) and assert role filtering against it directly, then assert the tRPC surface DENIES the now-excluded role explicitly. Net result: fewer reds than the baseline (33 -> 31 failing) and more tests (6131 -> 6172 passing), with the security posture unchanged. Rule: when a security control breaks tests, the tests encode the old contract - re-point them, never re-open the hole. And leave the now-unreachable branch in place, commented as dead behind the guard, so the next reader does not mistake it for the live check.
