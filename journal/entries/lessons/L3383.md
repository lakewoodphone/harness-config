**L3383 · A fix that lives in an uncommitted working tree on a deploy host is a fix with an expiry date**

A fix that lives in a deploy checkout's working tree has an expiry date, and it is the next deploy.

Found 2026-10-06 while preparing a test deploy: `/opt/lpt-test/src` on `lpt-apps` (2.28.33.58) carried
`backend/src/lib/jwt.ts` MODIFIED AND UNCOMMITTED. The change gave every refresh token a `jti` nonce.
Without it, two refresh tokens for the same user minted in the same second are byte-identical, because
a JWT's `iat` has whole-second resolution and Nothing else in the payload varied. Rotation revokes the
old row and then inserts the replacement into a UNIQUE column, so a same-second rotation could not
insert once the revoke had landed: the session died, and the next attempt was read as refresh-token
REUSE and revoked the whole session family. It was live as "Unique constraint failed on the fields:
(`token`)".

The fix was already running in BOTH the test container and the production container, installed by hand.
It was in NO git ref: `git show HEAD:backend/src/lib/jwt.ts | grep -c jti` returned 0, and
`git show origin/test:backend/src/lib/jwt.ts | grep -c jti` returned 0.

Rules this produces:

1. **Before deploying to any host, run `git status --porcelain` in that host's checkout and read every
 modified tracked file.** A dirty deploy checkout is either a fix with an expiry date or a mistake.
 Do not `git checkout` over it and do not `git stash` it until you have read the diff and decided
 which one it is.
2. **A hotfix applied inside a container or a checkout is not a fix.** It is a fix-shaped object. The
 test for whether it is real is: can you name the commit that carries it? If not, it does not exist,
 and the next deploy will prove that at the worst possible moment.
3. **`/opt/lpt/docker-compose.yml` and its neighbours are hand-patched history** — the directory holds
 `*.orig-<timestamp>`, `*.bak-<incident>-<timestamp>` and `patch-*.sh` files from repeated live
 surgery. Treat the remote deploy directories as evidence of what happened, never as the source of
 what should be running.

The repair: the change is now commit `0a39daf61` on `lpt/staff-intake-20261006`, pinned by two tests in
`backend/src/__tests__/lib/jwt.test.ts` (two mints in the same second must differ; the `jti` claim must
be on the wire), and the box's copy was `git stash`-ed with the message
`jti-patch-now-committed-upstream-20261006` rather than discarded.
