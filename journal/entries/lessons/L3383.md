## L-new · An MCP tool added to the server appears in a LIVE session's tool list — a new tool does not need a new session

**Measured 2026-10-08.** `ps_search` was added to `ps_mcp_server.py` (tool 20) on the authority at
02:31Z, while this session was already running. Nothing was restarted. Within the hour the tool appeared
in this session's own tool list — schema, docstring and all — and `ps_search(what="journal", …)` returned
H3326 with `covers_through` and `stale:false`.

**Why it matters.** The handoff written minutes earlier said the opposite ("this session's tool list
predates it and will not show it"). That is the kind of plausible-sounding claim that makes a session
wait for a restart it does not need, or report a capability as unavailable when it is live. The client
picks up a re-synced tool list mid-conversation.

**Corollary for wiring work:** the acceptance test for a new MCP tool is to *call it from the session
that saw it appear*, not to reason about connection lifetime. And the acceptance test for a new skill is
a fresh agent's `<available_skills>` block (skills are watched live too — a skill dropped into
`$DSH_HOME/skills` showed up in seconds).
