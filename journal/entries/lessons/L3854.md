**L3854 · E4810 side button is keycode 10000; any pushed key_map kills the keys app's default key sets**

E4810 side button is keycode 10000, and a pushed key_map silently deletes the app's default keys.

## The measurement (2026-10-18, 558800292460)

With the deploy-written config (voice_toggle: [134] only), pressing the physical side button logged
nothing and Voice Access never opened. After adding 10000 to `voice_toggle` and firing
`am broadcast -a com.lpt.action.RELOAD_CONFIG -p com.android.cts.keysminimal`, the same physical
press logged, in order:

```
I/LptKeys: key code=10000 action=0 mapped=2
I/LptKeys: voice_toggle
I/LptKeys: voice_toggle visible=false requested=false
I/LptKeys: voice_activate_broadcast
...
I/LptKeys: voice_toggle visible=false requested=true
I/LptKeys: voice_stop_listening_broadcast
I/LptKeys: voice_stop_broadcast_only
...
I/LptKeys: voice_activate_broadcast <- third press starts it again
```

So the side button is **10000** (the Kyocera PTT code, `keycodes.ptt` in e4810.yaml), and the toggle
is a true on/off — start, stop, start. The mic key 134 (KEYCODE_F4 on this ROM) is not the side
button and injecting 134 does nothing, which is what sent me looking in the first place.

## The trap, which will bite every device

`MinimalService.loadConfiguration()` (agent/lpt-keys/.../MinimalService.java:964):

```java
boolean hasConfiguredKeyMap = keyMap != null;
if (!e4610KeyOnlyMode && !hasConfiguredKeyMap) {
 registerKeys(ACTION_VOICE_TOGGLE, DEFAULT_VOICE_KEYS); // {285, 10000, 287, 231, 134}
 registerKeys(ACTION_RECENTS, DEFAULT_RECENT_KEYS); // {284, 137}
 registerKeys(ACTION_APP_DRAWER, DEFAULT_DRAWER_KEYS); // {286, 136}
}
```

Any `key_map` at all — even one that only names `app_drawer` — suppresses all three default sets.
The engine's `runtime_config` phase now pushes one from `cli/configs/devices/<model>.yaml`, so the
device config's `lpt_keys` block IS the whole runtime mapping. April-era deployments had no
`runtime_config` phase at all (see the 2026-04-17 receipts for this serial), so defaults were live
and the side button worked. That is the whole answer to "we always run the script and it works".

## Fix, and where it is recorded

- `cli/configs/devices/e4810.yaml`: `voice_toggle_keys` = 134, 285, 10000, 287, 231 (the app's own
 default set) with a comment explaining why the full list matters. Committed `bc116f2f`.
- Handset: pushed the same map to
 `/sdcard/Android/data/com.android.cts.keysminimal/files/lpt_keys_config.json` + reload broadcast.
- Same narrow map exists in `e4811.yaml` (voice [134], side_button 136) — same family of handset,
 same bug, not measured on hardware yet.

## Next time

Map a key by pressing it, never by reading the config: `adb logcat -v time > capture.log` captures
`LptKeys: key code=... mapped=...` for mapped keys only, so an *unmapped* press is silent — add the
candidate code to the map first, then press and read the log.
