**L3827 · Apple device-management docs are client-rendered; read Apple's schema repo instead**

**Apple's developer documentation returns nothing to a fetcher; the schema repo is the primary source.**

`developer.apple.com/documentation/devicemanagement/*` pages are client-rendered. `web_fetch` returns the page TITLE and no content — measured 2026-10-14, `appsettingsallowedobject` returned "AppSettingsAllowedObject | Apple Developer Documentation" and nothing else. An agent that "reads" those pages has read nothing and cannot be audited.

**Use Apple's own machine-readable schema instead**, which is the same information an MDM vendor builds against:
```
https://github.com/apple/device-management branch: release
 mdm/profiles/com.apple.applicationaccess.yaml (124,587 bytes)
 mdm/profiles/com.apple.app.lock.yaml
 declarative/declarations/configurations/app.settings.yaml
curl -sSL https://raw.githubusercontent.com/apple/device-management/release/mdm/profiles/com.apple.applicationaccess.yaml
```
Likewise `support.apple.com` guide pages: a plain curl with a browser UA returns HTML that can be stripped and grepped (measured 200 / 804,668 bytes on the allow-deny-apps guide), while `web_fetch` fails with "unsupported content type unknown".

**What this bought, on the first use:** `allowListedAppBundleIDs` is **deprecated at iOS 27.0** in favour of the declarative `com.apple.configuration.app.settings`; and Apple states verbatim that the device "allows the following apps to run regardless of the configuration: Phone, Settings, Feedback Assistant" — i.e. an app allow-list can never produce a two-icon device. Neither fact is reachable from the rendered pages.

**Corollary — parse a multi-platform schema PER PLATFORM.** Apple's payload schema lists `introduced:` and `deprecated:` separately under iOS, macOS, tvOS, visionOS and watchOS. A grep for "deprecated" inside a key's block returns the macOS line while the iOS line says nothing. Measured 2026-10-14: a crude grep appeared to show `allowAirDrop`, `allowEraseContentAndSettings`, `allowHostPairing` and `allowScreenShot` deprecated on iOS; parsing per-OS showed **they are current on iOS** and the deprecation lines were macOS. The genuine iOS deprecations are the app allow/deny lists at 27.0 and the Siri/keyboard/intelligence keys at 26.4. A research stream was about to publish the wrong, scarier version.
