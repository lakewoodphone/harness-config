**L1545 · Android unit tests cannot run on this machine: no Android SDK, and Gradle says so in 12s**

Evidence: 'cd android && ./gradlew.bat --offline testDebugUnitTest' fails immediately with 'Could not determine the dependencies of task :app:testDebugUnitTest > SDK location not found. Define a valid SDK location with an ANDROID_HOME environment variable or by setting the sdk.dir path in your project's local properties file'. ANDROID_HOME is unset and %LOCALAPPDATA%\Android\Sdk does not exist; only daemon/wrapper distributions are cached under ~/.gradle/wrapper/dists. Consequence: any claim that a Kotlin change compiles or that JVM tests pass on this box is a fabrication. What to do instead, in order of cost: (1) make the module under test depend on nothing Android so plain-JUnit tests can cover it — for the telemetry module that meant putting the vocabulary, the JSON encoder and the Android Log behind a small interface, and writing a self-contained JSON reader in test sources rather than using org.json, which is a throwing stub outside Robolectric; (2) cross-check constants against the authoritative source file with a script (this caught nothing here because the check was run, but it would have caught a rename); (3) sweep every named argument at every call site against the callee's parameter list with a script; (4) reproduce the encoder's exact expected literals against Python's json parser so the hand-written escaping is validated by a strict parser even though Kotlin never compiles.
