**L2580 · Reconciling the owner health record: take the union per file, never one side**

**L2xxx · Reconciling the owner health record: take the union per file, never one side — the live checkout is not uniformly the newest copy.**

RULED 2026-09-25 (ZABZ-YOGA), after nearly forking the record twice in one session.

WHAT HAPPENED. The owner said "i just put the latest results in downloads, save them to my records and update after analysing". The obvious read was: the health record is on `origin/docs/owner-health-2026-09-20`, branch off it, add the labs, push. That would have produced a record that was **seventeen sections out of date and missing an entire condition file's §9**.

MEASURED, in order:
1. `origin/docs/owner-health-2026-09-20` tip = §1–§16, ~30 KB. **The authority's on-disk `docs/personal/health/recurrent-febrile-episodes.md` was §1–§33, 147 KB, uncommitted, on its local master.** The branch was not the head of anything.
2. After switching the base to the authority's live files, a file-by-file comparison against the branches showed the drift runs **both ways**: the authority's `groin-skin-condition.md` was **43 lines OLDER** than the branches (missing §9, the 2026-09-18 Desenex course), while its `README.md` and `recurrent-febrile-episodes.md` were much newer.
3. `git diff --cached origin/docs/owner-health-2026-09-20 -- groin-skin-condition.md` → **0 added, 43 removed**. A strict subset. That is a regression, and it was caught only because the diff was counted rather than eyeballed.

THE RULE. For this directory — and for any file that lives in an unmerged, per-machine-edited state — **do not pick a side. Diff each file against every candidate head and count added vs removed.** A file with 0 added and N removed is a strict regression: take the other copy. A file with additions is newer: take it. Then re-verify that every section number and every cross-reference still resolves (here: sections 1–34, no duplicates, and the 14 section numbers §34 cites all exist).

WHY IT MATTERS. This is P3 (reading the wrong data and believing it) with the polarity reversed — **writing the wrong data and calling it the record**. The damage is worse, because a health record that silently loses a treatment section looks complete.

WHAT WOULD MAKE IT UNNECESSARY. The health record should be on **master**, not on throwaway per-session branches, and the authority's checkout should be the merge target rather than a divergent local master. Filed as pain, not fixed here.
