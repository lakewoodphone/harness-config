**L3207 · An iPhone's Voice Memos are not reachable over AFC - a full backup plus `Manifest.db` is the only route, and the mac mini already has the tools.**

**Measured 2026-10-05 on the mac mini (`LakewooechsMini`, user `lpt`) with the owner's iPhone SE 2 (`iPhone12,8`, UDID `00008030-0002246A2687802E`, iOS 17.7.1) attached over USB.**

**What works, in this order:**
- Identify the device: `/Applications/Apple\ Configurator.app/Contents/MacOS/cfgutil list` prints `Type`, `ECID`, `UDID`, `Location`, `Name` even for a normal (unsupervised) phone, and `cfgutil -e <ECID> get all` prints battery, activation state, build version and more. `cfgutil` has no `--help`; run it bare for the command list.
- **libimobiledevice IS installed on the mac mini at `/opt/homebrew/bin`** (`idevice_id`, `idevicepair`, `idevicebackup2`, `ideviceinfo`, `idevicesyslog`, …) - but that directory is **not on the non-interactive SSH PATH**, so `which idevice_id` returns nothing and looks like "not installed". Always `export PATH=/opt/homebrew/bin:$PATH` first. `brew` itself is not on the PATH either.
- `idevicepair -u <UDID> validate` proves trust; `ideviceinfo -u <UDID> -k ProductVersion` proves the link.
- Pull the data: `idevicebackup2 -u <UDID> backup --full /Users/lpt/<dir>` (unencrypted, 1077 files / ~5 GB for this phone, about 3 minutes including the passcode prompt "*** Waiting for passcode to be entered ***" - the phone must be **unlocked**). It ends with "Backup Successful."
- Find the files: the backup is `<dir>/<UDID>/Manifest.db` (sqlite, 5389 rows for this phone) with `Files(fileID, domain, relativePath, flags, file)`. **Voice Memos live in `AppDomainGroup-group.com.apple.VoiceMemos.shared`, `Recordings/*.m4a`** - and the app container (`AppDomain-com.apple.VoiceMemos`) does **not** hold them. Each file's bytes are at `<dir>/<UDID>/<fileID[0:2]>/<fileID>`.
- Read dates out of the `file` blob with `plutil -p`, not with `plistlib.loads` - in this backup `plistlib` failed on every row and silently produced empty metadata, which made a fresh recording look like an undated file. `sqlite3 "$DB" "SELECT writefile('/tmp/x.plist', file) FROM Files WHERE fileID='…'"` then `plutil -p /tmp/x.plist` works. The memos' own filenames (`20261005 152439.m4a`) are the start time to the second, which is usually enough.

**Two traps that cost time here:**
- **`system_profiler SPUSBDataType` returns nothing at all over SSH** on this mac (0 lines, exit 0), so "is anything plugged in?" has to come from `ioreg -p IOUSB -l -w 0` (look for `USB Product Name = iPhone`) plus `cfgutil list`. `mdls` on a `.MOV` also reported `kMDItemDurationSeconds = (null)` while `afinfo` gave the real 11.215 s.
- **`afinfo` counts audio tracks only**; a video with video+sound reports "Num Tracks: 1" and reads like an audio-only file. `ffprobe` settled it (hevc 1920x1080 + aac). ffmpeg is not on the mac mini; it IS on ZABZ-TECH at `%LOCALAPPDATA%\Microsoft\WinGet\Packages\Gyan.FFmpeg_*\ffmpeg-8.1-full_build\bin\ffmpeg.exe`.

**Why it mattered:** the owner said "i just took a few recordings" and the answer - six memos + one video, all a debrief of what went wrong with the sukkah awning this Sukkos - existed nowhere else. Backup → Manifest.db → extract → Whisper (`app.services.transcription.transcribe_with_whisper` with `app.config.settings`) turned 10 minutes of speech into the defect list, ~0.06 USD of Whisper for the lot.
