**L2851 · Put the MESH-HOST line in the brief yourself - a mesh child is not steerable once dispatched**

**Put the MESH-HOST line in the brief yourself as the first instruction — do not rely on the provider's preamble**

Measured 2026-09-28, a 3-child research fleet dispatched through the `subagent` tool (the mesh provider).

The provider prepends its own `MESH-HOST:` instruction (`plugin-remote-fanout/lib/provider.js`,
`DEFAULT_TASK_PREAMBLE`, line ~108). One of the three children still came back rejected:

 subagent-7 [failed] — diagnostic: the child did not begin its report with "MESH-HOST: <hostname>" —
 its location is unproven, so the run is not reported as complete

`job_output` returned **nothing**. The whole run was discarded after ~10 minutes of real work. The other
child that completed carried the line and was reported normally — so the preamble is not reliably carried
into a long research child's *final message*, which is the only thing the verifier sees (L2070, L2379b,
L2577b all describe the failure; none of them state the caller-side fix).

FIX, applied mid-flight and working: make it the **first line of the prompt I write**, before the task:

 MANDATORY: your final report MUST begin with the exact first line `MESH-HOST: <hostname>`, where
 <hostname> is obtained by actually running the `hostname` command. A report that does not open with
 that line is rejected as unproven and the whole run is discarded. Then continue with the report below.

Also learned: a running one-shot mesh child is **not steerable**. `send_message` to its job id returns
`Error: subagent "subagent-N" is unavailable`, and `list_agents` shows no subagents at all — so a child
already in flight cannot be corrected, only allowed to die and re-run. The brief has to be right before
dispatch.

And the placement note worth keeping: the mesh placed a child on **this same node** (`placement = broker →
node "zabz-tech"`, child's own report `MESH-HOST: ZABZ-TECH`) because the local node was not excluded and
was under no pressure. "Through the mesh" does not mean "on another machine" — read the placement line, do
not assume.
