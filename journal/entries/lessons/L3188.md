**L3188 · A child agent can die AFTER finishing its work: a missing .catch two packages deep (exit -1, report lost)**

## L — A child agent can die AFTER finishing its work, and the cause is a missing `.catch` two packages deep

MEASURED 2026-09-30. A mesh child that has completed its whole turn can still kill its
own process and lose its entire report. Reproduced twice in one session by dispatching a
child into the live mesh: both returned `the remote one-shot exited 4294967295 and produced
no final message`, and one was captured mid-flight with the opening frame written and the
closing frame absent.

THE CHAIN, every link read in the installed runtime (`@deepseek-ai/*` 0.1.5-rc.2):

1. `dsh-subagent/lib/types/continuation-activation.js:556` — `watchSettlement()` starts a
 detached async IIFE, `(async () => { while (true) { ... } })()`, **with no `.catch` on it**.
2. `:564` → `activation.inbox.hasPending`
3. `dsh-subagent/lib/index.js:712` → `this.agent.inbox.nextTurn`
4. `dsh-agent-loop/lib/index.js:82` → `this.current()['next-turn']`
5. `dsh-agent-loop/lib/index.js:178` → `current()` **throws** when the inbox projection
 registration is not active. That registration is owned by the child agent's own scope
 fiber, and teardown disposes that scope *before* the settlement watcher's last read.

So the watcher throws during teardown, the throw becomes an unhandled rejection because
there is no catch, and Node terminates the process. The work is already done; only the
report is lost. That is the entire mechanism behind the recorded `P2249b`/`P2253b`
"children die at settlement with no output", and behind exit `-1`.

FIXED by `scripts/patch-dsh-settlement-crash.py` (three idempotent, sentinel-marked edits):
the inbox getter reads the projection directly and is TOTAL (absent state means
"nothing pending", i.e. `false`); the activation's `hasPending` reads its agent's inbox
defensively; and the watcher gets the `.catch` it never had.

VERIFIED, WITH A CONTROL, by `scripts/verify-dsh-settlement-crash.py`:
the two expressions executed side by side — unpatched throws `TypeError` on the teardown
state, patched returns `false`; and the detached-rejection shape terminates the process
(exit 1) without the catch and stays alive (exit 0) with it, so the check discriminates.

RULE. A crash that happens *after* the work is done is not a small crash: it is silent
data loss with a confident empty result, which is this system's most expensive failure
class. When a process dies with no message, look for the missing `.catch` on a detached
async IIFE before looking anywhere else.

RULE. The runtime is a third-party npx install that a version bump replaces. A patch must
assert its anchor text and FAIL LOUDLY when the anchor moves, and it must ship a `--check`
mode that a provisioning step runs, or it will silently stop applying and nobody will know.
