## Lesson: in the DSH stream pipeline, fix a chunk BEFORE you yield it — mutating after the yield is a no-op

`dsh-llm/lib/index.js:1140 snapshotChunk()` deep-copies every chunk into JSON at the moment
`AssistantStreamAccumulator.push()` receives it, and `blocks()` / `message()` are later assembled from those
copies. So an object mutated after `yield` is never the object the harness records.

This bit the first version of the malformed-tool-input patch. It repaired the tool arguments at `block-end`
and then yielded the block — and because the `yield` expression evaluates the object literal, the harness
snapshotted the malformed text before the repair ran. Measured on the real 86-case corpus: every case
"finished cleanly" while **all 86 still handed the tool unparseable JSON**, i.e. the bug looked fixed and was
not.

Rule: when patching a streaming translator, the change must be complete before the `yield`. Structure it as a
helper that returns the finished chunk (`emitToolInput(block)`), so the settled value is what gets copied.
Verify with a deep copy at the consumer side (`JSON.parse(JSON.stringify(chunk.block))`), exactly as the
harness does — a test that reads the live object will pass either way and prove nothing.

Evidence: `dsh-update/tests/tool-input-repair.test.mjs` check 5 ("34 repaired to real arguments, 52 emptied to
{} for the tool, 0 turns lost") fails against the yield-then-repair version and passes against the fixed one.
