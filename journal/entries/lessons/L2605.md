**L2605 · Inline <a> ignores min-height, so it silently escapes the app's 44px touch-target rule**

`min-height` does not apply to a non-replaced inline box, so an inline `<a>`
silently escapes this app's own 44px touch-target rule.

MEASURED 2026-09-28, CustomerDetailPage of phone-and-tech-full, rendered against
the built Tailwind CSS and probed in a real browser at 393x852 (iPhone 15) and
1024x768.

The app enforces touch targets globally in frontend/src/index.css lines 505-514:

 @media (max-width: 1024px) {
 .touch-target,
 button:not([class*="min-h"]):not([class*="min-w"]),
 a:not([class*="min-h"]):not([class*="min-w"]) { min-height: 44px; min-width: 44px; }
 }

At 393px every `a`/`button`/`summary` on the page measured exactly 44px - except
"Open in Work Orders →", which measured 19px, because it was `class="text-sm"`
with the default `display: inline`. An inline (non-replaced) box ignores
min-height entirely, so the rule never reached it. Adding `inline-block` raised
it to 44px with no other layout change; re-probed: under-44px targets on the
page went to zero.

RULE: a link in this codebase is only touch-safe when its display is
inline-block / flex / grid - `inline` opts it out of the global rule. When
checking touch targets, measure getBoundingClientRect().height at a <=1024px
viewport and do not trust the presence of the index.css rule alone. Other
plain inline `<a class="text-sm">` links across the app are likely still 19px
on touch; the same one-word fix applies.
