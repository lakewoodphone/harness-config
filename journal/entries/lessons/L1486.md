**L1486 · Never gate a safety refusal on a hand-written list of rule names - cite L1485**

I added the sibling rule to lpt-sync-to-production.py AFTER the skip gate was written, and the gate listed the refusing kinds by hand: ('should_sync_false','overlap'). The sibling kind was missing, so a real run would have reported SKIP in --dry-run and then created the order anyway - the exact 'the dry run and the real push disagree' defect the change exists to remove, reintroduced by the fix itself. It was caught only by re-reading the gate against the rule list after the audit, not by the tests or the dry run (both of which passed). Fix: one _GUARD_REFUSING_KINDS constant read by both paths, plus a test that drives EVERY refusing kind through a real (dry_run=False) push against a website_db stub that raises on any write, and a companion test that a CREATE decision still reaches create_order so the guard cannot quietly become a no-op. General rule: when a guard gains a rule, the set of 'refuse' outcomes must be derived from one place, and the test must assert the write path is unreachable for all of them - a passing dry run is not evidence, because the dry run and the write path are different code paths. Second rule: enumerate the guard's return kinds and check each one against the write path by hand once.
