**L3325 · Permission denied is not a filter reset; two different SSH failures were cited as evidence for one conclusion**

**"Permission denied" is not the filter. Two different SSH failures were cited as evidence for one conclusion, and the shop has been designing around the wrong one.**

The shop's guidance has said since at least 2026-08-25 that Techloq's kernel filter driver resets raw
SSH connections pre-authentication "even on loopback, any port", and that therefore SSH is a dead end
on a filtered machine and only an HTTPS path can work (`tools/lpt-diagnostics-kit/REMOTE-ACCESS.md:32-41`).
The *server-side* signature quoted for that is real and specific:

```
sshd: Connection reset by authenticating user <user> <ip> port <p> [preauth]
```

But the capture that is most often cited alongside it —
`scripts/copilot-ssh-field-kit/latest-run/techloq_ssh_self_connect_test.txt:3-16` — records
`Permission denied (publickey,keyboard-interactive)` on `127.0.0.1`, `localhost` and the LAN IP. **That
is not a reset. That is an authentication failure.** The two strings have been treated as the same
symptom.

Measured 2026-10-05 to check which one an ordinary failure produces: ran
`tools/lpt-access-kit/probes/Test-TechloqOutboundSsh.ps1` on `ZABZ-TECH`, a machine where the filter is
**absent** (`filterPresent = False`), and attempted outbound SSH to a host with no key installed:

```
ssh.exe : probe@192.168.50.138: Permission denied (publickey,password,keyboard-interactive).
```

Identical to the string attributed to the filter. So a missing key and a filter reset are
**indistinguishable in those captures**, and the captures cannot support the claim they are used to
support. That matters because the old installer set `PasswordAuthentication no` and an admin-file
`AuthorizedKeysFile` (`Install-CopilotSshAccess.ps1:364-366`) — a well-known way to produce exactly
`Permission denied`.

**Rules that follow:**

1. **Distinguish transport failure from authentication failure by the error string, always.** A reset
 says `Connection reset by peer`; a refusal says `Connection refused`; a missing key says
 `Permission denied`. Never let one stand in for another in a conclusion, and never record "SSH does
 not work" without the verbatim string.
2. **A control reading makes a claim interpretable.** The same probe on an unfiltered machine is what
 turns "it failed here" into "failure looks like this, so what I saw over there means X". Without the
 control, the observation is just an observation. This is `D2087` (validate the instrument with a
 control) applied to network diagnosis rather than media.
3. **A conclusion that a whole architecture was built on deserves the one measurement that
 distinguishes it.** T3 (Cloudflare tunnel + exec agent + browser terminal) is far more machinery to
 leave on a customer's machine than T2 (an outbound SSH key). It was justified by a claim that one
 command could have tested. **M1 remains OPEN** until that command runs on a filtered machine —
 recorded in `tools/lpt-access-kit/DESIGN.md` with the control beside it.
