**L3765 · CORRECTS L3764: journal.py append can fail silently with an inline --body - use --body-file and confirm the + ID line**

**L3764 was filed with a placeholder body by mistake** — it was created while testing whether a short
append would work at all, and the title's rule is real but the body it landed with says only
"SHORT BODY TEST". This entry carries the actual content; L3764 stays as written rather than being
edited, because the record of a messy minute is worth more than a tidy one.

**THE RULE.** `journal.py append <kind> --title "…" --body "…"` can fail **silently**: `append pain`
with a long inline `--body` exited 1, printed nothing at all, and created no entry. The same content
via `--body-file <path>` succeeded immediately (`+ P3158`). Two append attempts in one session
vanished that way, and the only reason it was noticed is that the entry count did not move.

`--body-file` also removes the quoting hazards entirely — the bodies that failed contained
`[data-testid=…]`, `^`, and `"`, and a PowerShell here-string or a shell `--body` is exactly where
those get mangled.

**WHAT TO DO INSTEAD:** write the body to a file and pass `--body-file`. Then confirm the append
actually happened — the tool prints `+ <ID> -> entries/<kind>/<ID>.md (N entries)`, and **if that line
is missing, nothing was written**. Checking `journal.py status` or counting `entries/<kind>/` is the
cheap verification. This is the estate's oldest failure mode wearing a new coat: a command that
fails without saying so, and an operator who assumes silence means success.
