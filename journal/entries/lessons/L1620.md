**L1620 · Never mutate the tree while a read-only fleet is reading it - I contaminated an agent's baseline**

My error, recorded plainly: I edited backend/src/trpc/routers/ui.ts and guard-coverage.test.ts WHILE eight
read-only audit agents were running in the same worktree. PART-058's test baseline then came back
"guard-coverage 1 failed | 3 passed" -- it had run during the window where ui.ts was guarded but the stale
PUBLIC.ui allowlist entry still existed. Its baseline was contaminated by me, and it correctly declined to
re-run and said so instead of reporting a false failure.

The fleet brief I wrote says the manager owns source and agents are read-only. That is necessary but not
sufficient: the manager must also NOT MUTATE THE TREE WHILE THE FLEET READS IT.

RULES:
1. Do the manager's own source edits either BEFORE dispatching a read-only fleet or AFTER it drains -- never
 during. A mid-flight edit changes line numbers and test outcomes under agents that are quoting both.
2. If an agent reports a failure in a file the manager is editing, that result is VOID, not evidence. Say so
 and re-run it yourself.
3. When a fleet is running and the manager has source work to do, put that work in a SEPARATE worktree.
