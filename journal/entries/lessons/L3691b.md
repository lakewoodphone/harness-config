**L3691b · The provenance 'anomaly' is a frozen enum by design, and it validates the census**

2026-10-13. Chased the provenance anomaly from last round. It is not an anomaly, the code says why, and it
confirms the census rather than undermining it.

WHAT I THOUGHT. `personal-checking` 2026-07 carries `source: snapshot` in its month record and a note
reading "anchor 180791 on 2026-07-01 [chase-scraper]". Two fields of the same record naming different
sources looked like a defect in what a human reads.

WHAT THE CODE SAYS, verbatim from `cfo-balances.py`:
 # The frozen enum is snapshot|statement|derived. WHICH snapshot source
 # (plaid-api, chase-scraper, manual) is in the note, not here, so a reader
 # of the frozen field sees the three values the brief defines.
 source, ref = anchor.get("prov", "snapshot"), anchor.get("ref") or ""
So the month's `source` is a FROZEN THREE-VALUE ENUM on purpose - snapshot, statement, derived - and the
finer provenance (plaid-api, chase-scraper, manual) is carried in the note by design, so that a consumer
of the frozen field sees only the three values its brief defines. **Two fields, two resolutions, both
correct, and the choice is documented at the line that makes it.**

AND IT VALIDATES THE CENSUS RATHER THAN BREAKING IT. Last round's table classified all 68 disagreements
using the source from the NOTE - i.e. the finer value - which is the more informative of the two. So
"66 between two authoritative readings, 2 involving one the tool cannot vouch for" still stands, and it
stands on plaid-api/chase-scraper/manual rather than on the coarser snapshot/statement/derived. Had I read
the frozen field instead, `chase-scraper` and `manual` would both have appeared as `snapshot` and the census
would have shown 68 authoritative with 0 doubtful - a materially different and less useful answer, and a
wrong one.

THIRD FALSE ALARM TONIGHT, ALL CAUGHT THE SAME WAY. The other two: the marketplace sync's zero-item delete
(W2779) and the offsite age report's missing boto3 (L3685) - and here the "defect" in the age report was
real while this one is not. **The common shape is that a reading which looks inconsistent is more often
two fields meaning two things than a bug, and the cheapest way to tell is to read the line that writes
them.** The habit worth keeping: when two values disagree, find the code that produced both before
deciding which is wrong.
