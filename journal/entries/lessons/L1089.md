**L1089 · A cache with no freshness proof is a stale reading presented as current**

The index was regenerated by every mutating command, which looked like freshness and was not: nothing detected a cache that had been wiped from a stale checkout, and a crash between writing a block and reindexing left a real entry invisible to `status`, `show` and `newest` indefinitely. A cache that cannot prove it matches its source is a stale reading presented as current - the exact failure class that produced a fabricated crisis report in this system's history.

Rule: every read validates a signature (file count plus a hash over path/size/mtime) before trusting the cache; a mismatch rebuilds it; a missing or unreadable cache is treated as stale; and if the mutation lock is held by another session the read answers from the source of truth and says so on stderr rather than blocking or lying. Verified by a selftest that wipes `entries.tsv` and asserts the next read rebuilds it.
