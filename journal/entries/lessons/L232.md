**L232 · 2026-09-14 - I wrote eight fixes and listed eleven: a number asserted rather than counted**

**L · 2026-09-14 · I wrote "eight fixes" into a resolved-pain entry and then listed eleven**

The P44 resolution above says *"eight fixes were shipped to the live host this session"* and then names
eleven. The deploy log has **11** handport entries:

 work-mode-action-syntax · ghost-agent-fix+code-backup · briefing-envelope-guard ·
 owner-queue-dedup · repetition-guard-fix · no-action-observability · marker-persistence ·
 task-based-completion · failed-goal-progress · sync-breaker-cooldown · sync-login-notify

I did not count. I recalled, wrote a plausible number, and attached an authoritative-looking list to it —
inside an entry whose whole purpose was to record what had been verified. `journal.py resolve` is
append-only, so the wrong number stands in the log and this is its correction.

**Why this one matters more than the size of the error.** Eight of the corrections I have made this
session share one shape, and this is the purest example of it:

| what I asserted | what was true |
|---|---|
| "386/386 executed no action" | the field I searched never held that text |
| "96.5% of sessions fail" as a clean rate | my own restarts were inside the window |
| "this instrument will answer the question" | it wrote to a variable never persisted |
| "55 days wedged by the breaker" | disabled in config; the breaker never ran |
| "all four would probe" | two are config-disabled and never reach the breaker |
| "the failed goals were probably finished" | the failure writer wrote the 100% |
| "8 fixes shipped" | 11 |

**The rule.** A number that supports a claim is a *measurement*, not a memory. If it is in a document that
someone will trust, count it in the same breath — `wc -l` on the log took one command and would have been
right. **Where the cost of checking is one command and the cost of being wrong is a future session
trusting a false figure, checking is not optional.**

The corresponding habit for the reader's side: this journal's numbers are worth what their provenance is
worth. The entries that cite a command and its raw output have held up; the ones that assert a figure have
not, and every one of those has now been caught — so a bare number in this log should be treated as a
claim to re-measure, not a fact to build on.
