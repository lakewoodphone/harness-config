**L1893 · A checkout 26 commits behind is not a mesh node: before any fast-forward, measure whether the machine's uncommitted files are NEWER than the branch**

ZABZ-TECH's `harness-config` checkout was at `8795753`, **26 behind** `bfeb1fa`, with no local commits and no stashes, and its own sync keeper said so — `~/.dsh-sync-status/status.json`, `updated 2026-09-17T14:02:03Z`: `"result":"attention"`, `"detail":"pull --ff-only refused: histories diverged (26 behind / 0 ahead) and step 2b preserved nothing. Needs a human."` So the fixed `install-client-plugins.ps1` (the `dsh.bundle.patch` gate), the snapshot guard ("never link into a transient %TEMP% snapshot") and this morning's gate repairs were all in commits it did not have.

**But the fast-forward was not the safe move, and only comparing content shows why:**

 packages/plugin-mesh-http/lib/node-identity.js laptopWT 02b7e5c6 origin/master 89b5c327 ZABZ-TECH 02b7e5c6

…seven files in all (`lib/index.js`, `lib/runner.js`, `lib/handler.js`, `bin/mesh-http.mjs`, `bin/mesh-dispatch.mjs`, `test/mesh-http.test.mjs`, `lib/node-identity.js`). The machine's **untracked** copies are byte-identical to the **laptop's uncommitted working tree** and differ from `origin/master`: they are the newest revision of the package that machine's live `/mesh/health` route serves — including the `node-identity.js` fix `93` §8 proved live there — and they exist in **no commit**. A fast-forward would overwrite them with older content, so the node would silently regress on its next restart, and putting them back afterwards re-creates the dirty tree that blocks the next pull.

**Rule.** `git rev-list --left-right --count` describes the graph and says nothing about which side is newer **in content**. Before fast-forwarding a stale node, hash its untracked and modified files against both the source-of-truth working tree and the branch. When the machine's copy is newer, the wall is *a commit by whoever owns those files*, not a merge strategy. Second rule, same machine: an untracked path that the branch tracks is a hard blocker — 24 of 30 untracked paths there collide, so the pull refuses before the merge logic is even reached.
