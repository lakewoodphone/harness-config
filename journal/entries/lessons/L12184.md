**L12184 · A ledger item can land on origin/main while you are reading the code: check the ledger number first**

Ledger 1080 was already merged before I started building it, and I only checked after designing the fix. The branch `agent/kf-mirror-mitm` was cut from origin/main `88b925c`, and `88b925c` already contained `c549314 fix(mitm): a missing CA is a refusal, not a success (ledger 1080)` via PR #125.

What I did, in order: read the two roadmap items, read the readiness audit, read `PolicyApplier.installMitmCaFromRepository`, designed a lane-report + broker-channel fix, wrote it, then ran `git log origin/main --since="3 hours ago" --oneline` and found the merge.

What a future session should do first, before reading any code: `git log origin/main --since="6 hours ago" --oneline` and grep it for the **ledger number** as well as the concept — the wake loop names its commits after the item ("(ledger 1080)"), and `git grep -n "<symbol I am about to add>" origin/main`. Ten seconds, and it changes what "the task" is.

Second fact worth carrying: the loop's fix and mine were both honest but at different layers. The loop stopped at the decision ("a missing CA is a refusal, not a success" — `planMitmCaInstall`, `return false`, `Log.w`). What it does not do is make the missing lane **readable by a person or the broker**; `PolicyApplier.mitmCaTrustReportFromRepository` still has no production caller at all, so the only readers of the refusal are logcat and the caller's boolean. The broker-visible path that exists is the tamper/posture channel: the phone's `tamper_alert` over the WS, whose `tamper_type` is a free string the parent dashboard renders verbatim (`server/app/account_owner_dashboard.py`), because `server/app/device_posture_runtime.py` filters the status payload through a closed field allowlist and would drop any new `mitm_lane` field. That is why a new *status field* cannot reach a parent tonight without a server change, and a new *tamper type* can.

Also: `scripts/check_facts.py` in a fresh worktree needs the server venv's interpreter for five facts (`FACT-NOVALUE ... No module named 'fastapi'/'anyio'`); the fact this branch changes, `android-test-files`, needs `VALUE` in `scripts/facts/android-test-files.py` moved by hand — `--write` rewrites the page, not the owner.
