**L3804 · Copilot to DSH: 3 behaviours improved, 2 unchanged, 5 worse - and the always-on rules cover the improved ones, not the worse ones**

The migration from VS Code Copilot to DSH fixed the approval loop and made five other measured behaviours WORSE — and the current instructions spend their words on the behaviours that already improved.

Measured 2026-10-14 by mesh child subagent-8, one classifier (the exact `INTENTS`/`APPROVAL` regexes from `/home/zabz/evolution/finalize_corpus.py`) run over both corpora. Cross-validation: the DSH side reproduces `OWNER-ANALYSIS.md` exactly (keep_going 331, stop_reporting 8, one_at_a_time 77, document 186, analyze 459, dont_edit 69, options_rec 258, explain 117, remember 134, correction 261, frustration 299, restart_agent 93, approval 108 of 4,544; median turn 114 chars). Verdicts over the ten behaviours the predecessor audit (1,642 Copilot sessions / 26,950 owner turns, commit `51e2d32d`) named:

| behaviour | Copilot era | DSH era | verdict |
|---|---:|---:|---|
| approval-shaped turns | 25 % | **2.38 %** | genuinely fixed (and it was not on the list) |
| `one_at_a_time` | 4.2 % | 1.69 % | IMPROVED |
| `dont_edit` | 2.6 % | 1.52 % | IMPROVED |
| `stop_reporting` | 1.0 % | 0.18 % | IMPROVED |
| `keep_going` | 9.9 % | 7.28 % | UNCHANGED |
| `document` | 4.1 % | 4.09 % | UNCHANGED |
| `analyze` | 2.8 % | **10.10 %** | WORSE |
| `options_rec` | 2.2 % | **5.68 %** | WORSE |
| `remember` | 1.1 % | **2.95 %** | WORSE |
| `explain` | 1.6 % | **2.57 %** | WORSE |
| `correction` | 0.3 % | **5.74 %** | WORSE |

**The actionable finding, and it is a budget-allocation finding: `frustration` (6.58 % of his turns), `correction` (5.74 %) and `restart_agent` (2.05 %) appear ZERO times in the preset or in `AGENTS.md`.** The longest paragraphs in the always-on surface go to "do not stop to ask", which fell from 25 % to 2.4 %, and to `asked-unnecessarily`/`asked-badly`, which the round-2 census measures at 2.7 % and 2.6 % — the two *least* frequent frictions in the corpus. Meanwhile `keep_going` (331 turns) persists, which is the direct measure of the failure the approval rules were written for.

**Caveat that limits the comparison, stated by the child and worth keeping:** the parsed Copilot tables hold **4,373 messages, all `role='user'`, over 1,608 sessions — about 16 % of the 26,950 raw owner turns** the predecessor audit read, and **595 of the 1,608 sessions carry zero messages**. So the Copilot-era percentages from the parsed table are thin; the table above uses the predecessor's own published figures where they exist and the parsed table where they do not. **The DSH-side numbers are solid** (they reproduce an independent document exactly); the Copilot-side ones are indicative.

**Two corrections to earlier records, both measured:**
- The archive holds `copilot-chats` = **43,497 files / 26.85 GB**, not the 31.58 GB the predecessor audit reported.
- `AGENTS.md` §1 trap 3 says "14 chat files exceed 50 MB on ZABZ-YOGA". Measured: **5** `.jsonl` over 50 MB on ZABZ-YOGA (683 MB) and **47** on ZABZ-TECH (5.42 GB); 107 files over 50 MB in total. The trap is real — `vscode_chat_extractor.py:199` `_MAX_JSONL_BYTES = 50*1024*1024` still silently skips them — but the count in the rule is wrong, and a wrong count in a rule teaches a reader to distrust the rule.

**The instruction consequence:** the redesign should *cut* the do-not-ask material to a sentence, and *add* what is missing — a rule for being corrected (`correction` + `frustration` = 12.3 % of his turns, and there is no rule about what to do when he corrects you) and a rule for the hang (`restart_agent` 2.05 %, ~93 turns). This is measured, not editorial.
