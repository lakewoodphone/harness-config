**L1982 · The hooks-client vs vanilla-client bug leaves no HTTP trace, and a plausible fallback plus wholesale module mocks hid 62 dead call sites**

**Recorded 2026-09-18. Depends on / supersedes L1890 and L1891.**

The tRPC hooks client (`createTRPCReact`) and the imperative proxy (`vanillaTrpcClient`) are different objects,
and **using `.query()` / `.mutate()` on the hooks client throws inside the proxy before any request is sent**, so
the failure leaves no HTTP evidence at all - no status, no CORS error, no server log. Proven from the installed
package: `@trpc/react-query@11.18.0/dist/shared-JtnEvJvB.mjs`, `createReactDecoration` resolves a procedure name
through the hooks object (`return hooks[lastArg](pathCopy, input, opts)`), and there is no `query` key - so
`hooks['query']` is `undefined` and calling it raises `TypeError: e[i] is not a function`. This settles L1891's
open question: reading **B** is correct - the pattern is genuinely broken, not merely suspicious.

**Measured scope:** 62 imperative call sites across 25 live files (plus 3 archived). 46 were corrected in
`fix/trpc-client-callsites-20260917` across 15 files; the rest are documentation/example strings or were already
using the right client.

**Three things that made this class invisible for months, all worth remembering:**
1. **No network evidence.** Because it dies in JS, you cannot find it by reading status codes, server logs or
 error dashboards. It appears only as a console TypeError - and only on a page someone actually opened.
2. **A plausible fallback.** The one site that was user-visible (the homepage FAQ) had a catch block returning
 mock data, so the page rendered believable content instead of failing. That is how a fabricated street address
 stayed on the live homepage. **A fallback that produces believable content converts a hard failure into a
 silent one.**
3. **Tests that mock the module.** Every affected component had tests, and they passed - because they mock
 `lib/trpc` wholesale, so the wrong client is never exercised. The suite was green while the feature was dead.
 When `vanillaTrpcClient` was added to the mocks, 22 previously-passing tests failed, which is the sound of a
 mock finally telling the truth.

**Corollary for the harness:** when a fix changes WHICH object a call goes through, expect the test mocks - not
the tests - to be what breaks, and treat "many previously-green tests now fail" as evidence about the mocks
rather than as a bad fix. Distinguishing the two requires a baseline on a pristine tree, which is what separated
the one real pre-existing failure here (`OrderTimeline`, reproduced on `origin/test`) from the 22 mock artefacts.
