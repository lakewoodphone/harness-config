**L1548 · Adding lines to storage_sections/screenshot_reviews.py moves the SQL-surface digest, not just the count**

The audit in server/app/sql_surface_audit.py fingerprints dynamic SQL callsites by path+LINE. So inserting any function above an existing execute() call changes KNOWN_DYNAMIC_SQL_CALL_DIGEST even when the call count is identical. Expected: budget for it and write the digest-history entry before running tests, because the failure message is only 'digest changed' and looks like a new unsafe callsite. Also learned: the same SQL digest is embedded in server/security/security_audit_signoff.json as the reviewed sql_surface_audit control digest, so a SQL change also fails tests/test_security_audit_report.py via a stale snapshot. The established fix (commits 063a3d6, 0d13d04) is to REGENERATE the snapshot with app.security_audit_signoff.build_security_audit_signoff_snapshot using the OLD file's reviewed_at/reviewer/review_method/review_notes/assumptions - that touched only the sql_surface digest + generated_at + report/summary digests, nothing else. Two audits to satisfy, one change.
