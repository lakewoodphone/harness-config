**L3320 · L: Dialpad SMS has no send ledger and its sessions API is down; the websocket cache is the only record**

VERIFIED 2026-10-05 while reconciling the shop''s texts before continuing a customer reply session. The owner asked: "make sure we are fully synced with dialpad, my wife may have answered some texts or called some people back."

1. THERE IS NO SEND LEDGER FOR DIALPAD.
 sms_log exists (185 rows in 3 days) but it is TWILIO, the secretary''s own line - the
 recent rows are all a repeating Topgolf reminder to the owner''s personal number
 +18483897895. Nothing writes it from a Dialpad send. So the runbook''s "the script
 path writes no sms_log row" understates it: the action path is the only writer, and
 the direct-Dialpad path has no ledger at all. Consequence: dialpad_sms_cache is the
 ONLY record that a customer text was sent, and it exists only because a webhook
 happened to be running.

2. DIALPAD''S OWN API CANNOT BE ASKED.
 GET digital/sessionsdata returns HTTP 503 {"reason":"backendError"} right now, with
 and without params. GET sms -> 404. GET user -> 404. GET company -> 200, so the token
 is valid and the account is Lakewood Phone & Tech (id 5272393147203584).
 DANGER: a 503 there is not an empty result, but code that reads `items or []` turns it
 into one - which is exactly how a reconciliation reports "nobody replied" during an
 outage. Any sync built on that endpoint must fail loudly.

3. THE WEBSOCKET CACHE IS ALIVE AND IS THE WITNESS.
 dialpad-sms-ws.service, up since 2026-10-02: heartbeat connects=83 received=24
 stored=24 skipped=0 errors=0. lag 0.7-2.0 s. It caught a HUMAN reply made outside this
 session today (15:49:46 to 8456416440, "1001 west Kennedy blvd") - so replies made from
 another Dialpad device DO flow through it. That is the proof the sync is good enough
 for SMS.

4. ACCOUNT STRUCTURE: two lines, and call rows are double-logged.
 calls arrive on +17326552355 (9401 rows) AND +17323052065 / "Eliyahu" (3494 rows). The
 same physical call is written TWICE, 5-9 s apart, with near-identical duration, once
 per line. Do not count calls without collapsing that first.
 SMS rows record NO internal_number, so a cache row cannot be attributed to the line or
 person who sent it. That is a real blind spot.

5. OUTBOUND CALL LOGGING APPEARS DEAD.
 dialpad_call_full holds 9735 inbound and 3612 outbound, but the newest OUTBOUND call is
 2026-09-24 - 11 days ago - and there are ZERO outbound calls in the last 7 days. Six
 callers today had 60-118 s of talk time on inbound legs, so conversations happened;
 whether anyone called back cannot be established from this record. Do not claim a
 callback either way.
