**L2122 · A gateway can answer a JSON prompt with a native tool call, and content is empty -- read message.tool_calls or you will call a working model broken**

**Measured 2026-09-20 on secratary against `secretary-auto`, while rebuilding the AI text line.**

`textwork.do()` asked the model for a JSON object. It got back:

```
finish_reason: tool_calls
message keys: ['role','content','reasoning_content','name','tool_calls']
content: ''
usage: {completion_tokens: 81, reasoning_tokens: 0}
```

**The model answered correctly and the reader saw nothing.** The route had converted the
requested JSON contract into a native tool call; the arguments were inside
`message.tool_calls`, and `content` was an empty string. `Decider.call()` read only
`content`, so every job reported `blocked: the model returned no usable JSON` with
`tools_used=[]` - a working system describing itself as broken, which is exactly the
shape of the `journal L1606` failure (a silent fallback that hid a real outage for a week).

Two further facts about that path, both worth knowing before writing against it:

1. **Batched calls arrive as concatenated JSON**, not a JSON array. Two tool calls came
 back as `{"phone": "+18482102477"}\n{"query": "door code"}` - two separate objects in
 one string. A parser that requires exactly one object discards a good plan.
2. **The tool NAME is not in the arguments.** It lives in `function.name`, where a
 string-content parser cannot see it. The arguments alone still identify a usable
 call: a lone `query` is a search, a lone `sql` is a query, a lone `phone` is a
 contact lookup. Inferring from the shape is lossy but far better than doing nothing.

**The rules.** When a gateway exposes both a text contract and native tool calling,
never read only `content` - read `content`, `reasoning_content`, and every
`tool_calls[].function.arguments`, and always log `finish_reason` when the text comes
back empty. And never let an empty body be reported as "the model failed": name what
actually happened. An empty answer and an absent answer look identical and mean
completely different things.
