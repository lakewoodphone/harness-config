**L213 · Run the target runtime against the real artifact before a hosting cutover: four Netlify semantics do not exist on Cloudflare**

A hosting provider's documented compatibility is not its behaviour. Four of Netlify's
redirect semantics do not exist on Cloudflare Workers Static Assets, and every one was
found by running the REAL Cloudflare runtime locally (`wrangler dev`) against the REAL
`frontend/dist`, not by reading docs:

1. `/* /index.html 200` (our SPA catch-all) is rejected as "Infinite loop detected in
 this rule" and IGNORED. It logged "Parsed 0 valid redirect rules" for the entire file.
 The SPA fallback therefore has to come from `assets.not_found_handling`. Shipping the
 rule would have looked correct in the diff and done nothing at runtime.
2. Only statuses 200/301/302/303/307/308 are valid. A `404` rule was refused: "Valid
 status codes are 200, 301, 302, 303, 307, or 308."
3. `/api/* https://host/api/:splat 200` is refused: "Proxy (200) redirects can only point
 to relative paths." There is no external proxying.
4. A 200 rewrite to `/index.html` is normalised into a **307 redirect to `/`**, throwing
 away the path the client router needs - `/phone-repair` landed on the home page. Only
 requesting the actual path revealed this; the parse log was happy.

Rules:
(a) Before a hosting cutover, run the target runtime against the real artifact. Every one
 of these four is invisible in a diff and silent at runtime. `wrangler dev` needs no
 account, so there was no excuse for guessing.
(b) A silently-ignored rule is worse than a rejected one. The first finding produced
 "0 valid rules" while the file looked fine - so read the RUNTIME'S PARSE OUTPUT, not
 the file, when a config is consumed by a platform.
(c) Test the actual PATH, not just the mechanism. Finding 4 needed a request to
 `/phone-repair`, not an understanding of the redirect system.
(d) When a platform refuses to serve a path the way you need, put the refusal in code
 (here `cloudflare/api-guard.mjs`, scoped by `run_worker_first` so it costs nothing)
 rather than accepting a silent wrong answer.

Cost: four separate test cycles against a live runtime. Cheaper than discovering any of
them after a cutover, when the failure mode is a 404 on a marketing page or a redirect
loop reported by a customer.
