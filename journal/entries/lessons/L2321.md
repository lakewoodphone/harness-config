**L2321 · Harness web_fetch truncates many article sites to their navigation bar; fetch through the shell to verify a quote**

CLAIM: the harness `web_fetch` tool returned nav-only bodies for BBC, Medievalists.net, HarperVoyager, Vulture, Reactor and the Library of Congress this session - literally "Content truncated. Fetch a more specific URL or section for the full text." and nothing else. Any task that requires an exact quotation cannot be completed with it alone.

FIX: fetch through the shell. `/home/zabz/phone/research/got/ft.py` = curl -sL with a browser UA, strip script/style/noscript/svg/head, unwrap block tags to newlines, unescape entities, collapse whitespace, then skip the leading nav by starting at the first line longer than 90 chars. Measured: acoup.blog Part I returned 60,910 bytes of full text through ft.py that web_fetch returned as a title.

USE: batch 4-6 URLs per shell call (one ~700ms pwsh start-up instead of six). Reusable for any source-verification job - this is now the standard way to verify a quote on this fleet.

CAVEAT: JS/Cloudflare/Anubis-protected sites still fail (westeros.org 403, hal.univ-lorraine.fr Anubis PoW, time.com empty body, cbc.ca 403 without UA surgery). A failure there is a gap, not a null result - see L<blocked-source entry>.
