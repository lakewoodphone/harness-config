**L9729 · A test that redirects one store and not the other writes to production - two env vars, two modules, one rehearsal**

A test that redirects ONE store and not the other writes to production. Two env vars, two modules, one rehearsal.

Rehearsing the owner-text gate on "throwaway" stores, I set `OWNER_TEXT_RELAY_DB` to a tempdir and drove the real `submit()` chain. Three of the cases came back SEND and wrote **three real rows into the production topic ledger** at 17:27:43 — because the topic rung loads `owner_topic.py`, which keeps its own store under a **different** variable, `OWNER_TOPIC_DB` (default `/root/.owner-text/relay.db`). Those rows would have suppressed genuine messages for the 20-hour topic cooldown.

The rehearsal reported PASS-ish output the whole time. Nothing said "you are writing production", because a store that is correctly isolated looks exactly like a store that is not.

WHAT CAUGHT IT: the duplicate case failed for the wrong reason (`SUPPRESS` where `SEND` was expected on a fresh store). Chasing *why* — not accepting the first verdict as "the guard working" — meant reading the topic ledger and seeing rows with bodies only my test had.

WHAT TO DO:
1. **A rehearsal must enumerate every store the code path opens**, not just the one the entry point takes. Grep the module for `environ.get(...DB...)` and redirect all of them.
2. **A fresh-store result that appears to know history is the tell.** A first submission refused as `topic_cooldown` against an empty store means something else is holding the history.
3. **When you have written to production by accident, scope the removal precisely** — this session's cleanup deleted only rows whose `first_at` was inside the window AND whose `last_body` was one of the three exact test bodies, printed every row first, and verified `0` afterwards with the three pre-existing rows untouched. "Delete where topic like 'say:%'" would have taken real history with it.
4. **Make the rehearsal assert the store is clean as well as the verdict** — the check that would have failed immediately is `count(owner_topic) == 0` before the first submission.

The instrument is `scripts/text-channel/rehearse-the-gate.py`; it now sets both variables and is the closest thing to an end-to-end test available without sending, because `submit()` reads the wall clock and no test can put the channel at 03:00.
