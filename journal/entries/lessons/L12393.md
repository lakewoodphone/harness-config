**L12393 · Camera clock: read the OSD out of the picture, and fetch twice or you cannot tell a wrong clock from a cached frame**

Measured 2026-10-27 from ZABZ-TECH through `homeassistant.local` (HA 2025.10.3, `GET /api/` 200 in 116 ms,
1,040 entities, 368 unavailable/unknown, 25 camera entities). Three corrections to the 2026-10-26 security audit,
each read off the picture rather than off a config file:

**1. "Two cameras sixteen minutes apart" is one shared Dahua offset plus a separate doorbell offset.** Fetching
`GET /api/camera_proxy/<entity>` and reading the burned-in OSD:
`cam_front_hallway_main` 11:30:01 when the host said 12:21:25 (51 m 24 s behind); `cam_larry_s_exit_main_2`
11:30:03 (51 m 22 s); `reolink_video_doorbell_poe_clear` 27/10/2026 11:13:51 (67 m 34 s). The two Dahua cameras
agree with each other to **two seconds**; 67:34 − 51:25 = **16 m 09 s**, which is where the audit's "sixteen
minutes" came from. The cacheable version of this ("camera clocks drift against each other, five devices to fix") is
wrong: it is **two corrections**, one of which is the doorbell that sees faces.

**2. The stills are live, not cached.** The same camera's OSD advanced 21 s across 23 s of real time, so the offset
is in the camera, not in HA's image cache. Worth writing down because "the API returned a 200 and an image" is
otherwise indistinguishable from a stale frame — and this estate has already been bitten by a snapshot call that
returned another camera's frame with HTTP 200 (audit S62–S66).

**3. "No picture has ever been stored" is true only of the storage path.** A snapshot comes back today with nothing
built: 166 KB / 2,273 ms, 317 KB / 2,766 ms, 1.09 MB / 277 ms. What never ran was the code that saves the frame and
writes its row. That shrinks the build: the capture step is a save-plus-row, not a new imaging system.

**The transferable rule.** A timestamp read out of a config file is not the timestamp the device writes into its
picture, and the difference is invisible until someone looks at the image. Read the artefact, not the setting —
and when a number is an offset, fetch twice and check it advances, or you cannot tell a wrong clock from a cached
frame.
