**L3100 · A double-quote in a mesh subagent prompt kills the remote one-shot: exit 1, no output, no error**

MEASURED 2026-09-29 on ZABZ-YOGA, dispatching to the mesh (children land on ZABZ-TECH).

WHAT HAPPENED. Three long audit briefs were sent with the `subagent` tool. All three came back `failed: the remote one-shot exited 1 and produced no final message`, and the diagnostic `stderr tail` was the TAIL OF MY OWN PROMPT, cut at the same character in every case: the first double-quote.

 brief 39 stopped at: `The standing rule of this system is a` (prompt had: is "a flag is raised only by...")
 brief 40 stopped at: `...is it logging ` (prompt had: is it logging "0 to decide")
 brief 41 stopped at: `#89 p1 blocked owner` (prompt had: blocked "owner asked by text...")

The remote invocation passes the task through a double-quoted shell string, so an embedded `"` terminates it. Exit 1, no final message, and the child never ran.

WHAT I FIRST BELIEVED AND WAS WRONG ABOUT. I guessed the apostrophe, because these briefs were full of them (`owner`s`, `doesn`t`, `isn`t`). Two control probes refuted it:
 - `Reply with exactly the token ALPHA-OK and nothing else.` -> completed, ALPHA-OK
 - `The owner`s name contains an apostrophe. Reply with exactly the token BRAVO-OK...` -> completed, BRAVO-OK
Apostrophes are safe. Only the double-quote kills it.

THE RULE. When writing a `subagent` (mesh) prompt: no `"` characters. Use single quotes for quoted phrases, and prefer unquoted prose. Avoid `$` (it expands) and backticks (command substitution) for the same reason. Also: `repoA/scripts` and similar paths are fine; the failure is specifically the double quote.

WHY THIS MATTERS BEYOND ONE BUG. The failure mode is silent-ish: the job is marked failed but the diagnostic looks like the provider eating the task, which invites the conclusion that the mesh is down. It is not. The mesh was up the whole time - the probe and both control probes ran on ZABZ-TECH at the same minute. A wrong reading of this would have me fall back to `subagent_local` for everything (marking work LOCAL and losing the fan-out that rule 1b requires) while the remote path was fine. Reproduce the transport before blaming the transport.
