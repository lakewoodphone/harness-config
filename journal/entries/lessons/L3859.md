**L3859 · E4610/E4810: IMEI is not a property, board platform is msm8909 vs msm8937, df is kilobytes, batterystats times out**

Four facts measured this session, each with the file they came from:

1. **Neither Kyocera exposes the IMEI as a property.** Grepped `data/device-profiles/E4610/getprop.txt` and `.../E4810/getprop.txt`: no `ro.ril.oem.imei`, no `gsm.baseband.imei`, no `persist.radio.imei`. Any IMEI check must go through `dumpsys iphonesubinfo` (or `service call iphonesubinfo 1`) and, failing that, say "read the label under the battery" rather than blocking the sale. My first version blocked on it, which would have made every handset INCOMPLETE forever.

2. **`ro.board.platform` is the cheapest board-swap detector, and it differs by model.** Captured profiles: E4610 = `msm8909`, E4810 = `msm8937`. Written into the device YAMLs as `expected_platforms`. An E4810 board in an E4610 housing now fails the audit by name.

3. **Android `df` prints 1K-block counts, not bytes and not megabytes.** My parser read a unitless cell as bytes and turned 11.4 GB free on `/data` into "1 MB free". Unitless = kilobytes (toybox header literally says `1K-blocks`).

4. **`dumpsys batterystats` is slower than the tool's patience on these phones.** Measured directly: a captured run in `logs/battery-drain/battery-window-e4610-idle-system-vs-stock-20260512-213834/batterystats-start-192.168.50.15-5555.txt` is 84 bytes - the file contains nothing but `<timeout after 45 second(s)>`. So batterystats lives behind `--deep` with a 150 s timeout and its absence never blocks a verdict.

Also worth knowing: `dumpsys input` prints `Device N: matrix-keypad` / `gpio-keys`, while `getevent -pl` prints `name: "..."`. The input check now reads both, because a firmware without getevent would otherwise look like a phone with no keypad.
