**L3435 · GitHub's implicit default shell has no pipefail - linter | tee swallows the exit code**

GitHub Actions' **implicit default shell on Linux is `bash -e {0}` — `pipefail` is NOT set.** Writing `shell: bash` explicitly gives `bash --noprofile --norc -eo pipefail {0}`. So a step that omits `shell:` and pipes a linter into `tee` gets `tee`'s exit status, which is always 0, and its failure handler never runs.

Live instance, `pr-precheck.yml` step `Run Backend Linting with JSON Reporting`:

```yaml
 run: |
 pnpm -w run lint:backend:json 2>&1 | tee /tmp/backend-lint.log || {
 LINT_EXIT_CODE=$?
 exit $LINT_EXIT_CODE
 }
```

No `shell:` → no `pipefail` → the `||` block is unreachable. Measured 2026-10-09, PR #342, job `Lint Backend` (run 37876302907): the job concluded **success** while its own log recorded `📊 Processing 568 files with 41 errors and 59 warnings` and emitted `##[error]` annotations. `Lint Backend` cannot go red; its failure would fail the `aggregator`, which would fail the required `CI Validation (PR Pre-Check)`, so backend lint errors cannot block a merge at all.

The frontend lint step in the same file does not have the bug — it sets `set -o pipefail` inside the script, which is the tell that the author knew, and missed one of the two.

**Rule:** never rely on the implicit shell for anything whose exit status you branch on. Either set `shell: bash`, or put `set -euo pipefail` at the top of the `run:` block. Check the same pattern anywhere a pipeline feeds a `$?`.
