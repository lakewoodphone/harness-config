**L1748 · When master has diverged, deliver work on a branch built on top of origin/master via git worktree**

## L1748 — when master has diverged, deliver work on a branch built on top of origin/master

**Measured 2026-09-16.** `personal-secretary-mvp`'s local `master` was **106 ahead and 171 behind**
`origin/master` on GitHub. A plain `git push` would have been refused, and the two tempting wrong answers
are both destructive: `git push --force` (forbidden, and would drop 171 commits of other people's work) or
pushing the local master as a branch (which carries 106 local commits that are missing 171 remote ones —
merging it later would look like a revert of everything in between).

**What was done instead, and it is cheap:**
```
git worktree add -b <topic> /tmp/<dir> origin/master # a clean tree, the live one untouched
cd /tmp/<dir> && git cherry-pick <sha>... # only this session's commits
git push -u origin <topic>
git worktree remove /tmp/<dir> # the branch stays
```
The result merges cleanly, touches nothing else, and GitHub prints the PR link. **A dirty working tree
with dozens of another session's modified files is not a reason to skip delivering** — `git worktree`
is exactly the tool for that, and it leaves the in-flight edits alone.

Also worth remembering: a `git status -sb` divergence count read before `git fetch` can be stale. Fetch
first, then decide.
