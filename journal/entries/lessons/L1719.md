**L1719 · Committed and deployed are different facts - the deployment check caught the orchestration skill sitting stale in ~/.dsh for two rounds**

## The gap
`harness-verify.ps1` checked that the repo preset matched its generator — and said nothing about
whether the engine would ever *see* it. `sync.py` copies presets into `~/.dsh/.agent-presets/`, and
**the running harness reads that copy**, so "the repo is correct" and "the harness has it" are two
different facts.

They were different. Checked on 2026-09-16: the deployed preset was byte-identical and correct, but
the **orchestration skill in `~/.dsh` was still the pre-round-5 version** — the measured per-host
fleet budgets and the corrected records line had been regenerated into the repo two rounds earlier
and never deployed, because regeneration updates `presets/zabz/` while only `sync.py` reaches
`~/.dsh`. A document that exists in the repo and not in the deployment is a document no session
will read.

## The fix
The deployment check now covers the whole preset directory — `agent.cordis.yml` **and**
`skills/**` — by hash, and reads the behavioural values back out of the deployed copy (pruner
thresholds, compaction ratio, the presence of both instruction rules). It asserts both, because
either alone is satisfiable while the harness stays stale.

Verified after `python scripts/sync.py`: `preset hash match=True; skills match=True; deployed
thresholdChars=5000 thresholdRatio=0.7; instruction rules=2/2` → **10/10 checks green, exit 0**.

## The transferable rule
**"Committed" and "deployed" are different facts, and only one of them is testable by looking at the
repo.** For any artefact that a running system reads from a second location — a generated file, a
synced config, a copied skill, a junctioned package — the check must compare the *deployed* copy, or
it will pass while the machine runs the old thing. The same class produced two other near-misses in
this program: a plugin package that could silently miss a machine until `sync.py` was wired to the
installer, and the preset itself being generated (so a hand edit silently disappears).
