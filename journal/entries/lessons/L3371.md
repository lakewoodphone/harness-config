**L3371 · A test that passes without exercising the new path is worth the same as no test - my two-node simulation never fired the hysteresis I had just written**

GOAL ROUND 17. The arbiter for two-host leadership had NO hold-down: the design (annex J section 3) promised hysteresis on take-back - a node that just lost leadership must wait before taking it back, so a flapping network cannot ping-pong the company between two managers - and the code simply did not have it. I implemented it (HOLD_DOWN=300s default; a holder that LOST the lease by releasing it or by being replaced while expired may not re-acquire until the window passes; the FIRST takeover after an expiry is deliberately NOT delayed, and only the loser is damped, so failover stays immediate) and then WROTE A SIMULATION to prove it. The simulation passed, printed a beautiful transcript, and proved nothing about hysteresis: every refusal in it was 'someone else holds the lease', which is a different code path. The take-back refusal only fires when the lease is FREE and the previous holder is inside its own hold-down, and my scenario never produced that state - it always had one node holding. I only noticed because I read the transcript for the REFUSAL I expected and could not find it. Rewritten to let BOTH leases lapse, which is the only way the returning node finds the lease free while still damped, and the real refusal now appears: 'REFUSED (REJOIN): office lost leadership 6s ago; the hold-down is 15s'. RULES: (a) when you add a refusal path, the test must produce the STATE that triggers it, not merely a similar-looking failure - check the transcript for the specific message, not for a non-zero exit; (b) 'the scenario ran' is not 'the scenario reached the branch'; (c) a same-machine simulation with a real arbiter, a real epoch file and real timing is worth ten unit tests for leadership logic, because the bugs here live in time and state, not in functions.
