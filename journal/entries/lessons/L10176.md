**L10176 · An equivalence group can name a lane that does not exist; and the peak observer is at /tmp/peakwatch.log on the authority**

## 2026-10-19T22:55Z · ZABZ-YOGA · two traps found by making the gates print themselves

### 1. An equivalence group that names a lane which does not exist

The price book declares this as one set of weights behind three pipes:

 deepseek/deepseek-flash
 deepinfra/deepseek-ai/DeepSeek-V4.1-Flash
 fireworks/deepseek-v4p1-flash

But DeepInfra's actual candidate lanes in `_CAPABILITY_DB` are
`DeepSeek-V4-Flash-0731`, `MiniMax-M3` and `V4-Pro-0813`. **There is no V4.1 lane.**

So with a key and the provider un-disabled, `_yield_to_cheaper_same_model` would find a `deepinfra`
candidate, ask the book to price it against `deepseek-ai/DeepSeek-V4.1-Flash`, and the book would
decline — because the candidate is the *retired* model. The yield could never fire, and nothing would
log why.

**Rule: an equivalence claim is only useful if the lane it names actually exists as a routing
candidate. `provider_status.py` now prints lanes and equivalence side by side so the mismatch is
visible in one screen instead of being discovered by a router that quietly refuses to save money.**

### 2. The book prices one provider, and it is the right one — but say so out loud

Only DeepSeek is in `prices.json`. Google is reported BLOCKED purely for being unpriced, yet Google is
genuinely routing: 11,260 calls and about 48/month over 30 days. `estimate_cost` declines for Google and
falls back to `_GOOGLE_PRICING`, the legacy static table.

That is the designed behaviour — fail soft, count the decline, never invent a rate — and it is why the
fallback must stay. But it means **the hour-aware fix covers the provider that is 99 % of the bill and
not the ones that are not.** None of those providers has time-of-day pricing, so bands would buy them
nothing; what they are missing is a dated, validated rate. That is a smaller job, and it should be done
rather than assumed.

### 3. A detached observer is running for the first peak block

`peakwatch.service` (transient, `systemd-run`) appends one line a minute to **`/tmp/peakwatch.log`** on
`secratary-cloud`, until **04:10Z**, recording: `mode`, cumulative `deferrals_total`, `ticks_30m` from
`activity_log`, `lifecycle_30m`, `claim_rel_journal`, `rows_30m` from `model_usage`.

**A later session must read that file.** It is the only record of whether the first peak block produced
a real deferral, and it is deliberately independent of this conversation — which is the only way the
observation survives the window being thrown away.

First line, for the record: `mode=cheap-first deferrals_total=0 ticks_30m=3 lifecycle_30m=0
claim_rel_journal=0 rows_30m=39`.

**Note it was relaunched once:** `pkill -f peakwatch.py` matched the ssh command line and killed the
session, and a `setsid nohup ... &` inside a piped ssh did not survive. `systemd-run --unit=... --collect`
is the reliable way to detach on this host, and is what is running.
