**L10112 · My checkout was not the estate: 1428 lines of divergence found by hashing before deploying**

## 2026-10-19T22:15Z · ZABZ-YOGA · my checkout was not the estate: a 1,428-line divergence found by hashing before deploying

### What happened

Four rounds of work were committed on `feat/cheap-hours-routing`, cut from `fc65be23d`. Before
deploying to `/opt/company` on `secratary-cloud` I hashed the three files I had touched against the
files production runs. **All three mismatched.**

| | my base | production |
|---|---|---|
| branch | `feat/cheap-hours-routing` | `hk/559-bound-repo-reads` |
| commit | `fc65be23d` | **`5eda34671` — not present in origin at all** |
| `app/pricing.py` | `4edc945a6203a264` | `d24e16e28dd70076` |
| `app/services/smart_router.py` | 2,598 lines | **4,026 lines** |

Deploying the branch would have reverted **1,428 lines of `smart_router.py`** and deleted production's
W6 unknown-model instrumentation (`UNKNOWN_MODEL_FALLBACK_PER_MTOK`, `unknown_model_ids`,
`_note_unknown_model`) — none of which exists in my checkout, so nothing in my checkout could have told
me it was there.

This is `P3164` again, and `AGENTS.md` §6.1 already names it: *"on this estate `harness-config` has had
two `main` lineages at once that were not supersets of each other"*, and *"before editing a script that
runs somewhere, hash the file you are editing against the file on the host that runs it."* I have now
confirmed the same is true of `personal-secretary-mvp`: **the laptop checkouts are not production, and
an unpushed production lineage can be arbitrarily far ahead.**

### The method that worked

1. Copy the production files down (`scp`) and diff them against my base to size the divergence.
2. Never merge or check out. **Re-apply the change onto production's own bytes.**
3. A port script that asserts every anchor occurs **exactly once** and exits if not, so a moved anchor
 fails the port instead of patching the wrong place.
4. Prove the port is **additive before it ships**: `git diff --no-index --numstat` must show
 `0` deletions in every file. It did — pricing `+34/-0`, smart_router `+175/-0`.
5. `cp -p` backups, compile the staged `.new` files with the service's own interpreter, then `mv` for a
 new inode, then an import check, then restart and read a real row back.

### The verification, which is the only part that counts

First row written after the restart, `model_usage` id **353704**, band `offpeak`:

```
stored 0.00436410 by the price book
legacy 0.01278552 by the retired 0.44/1.32 card
factor 2.93x
```

So the overstatement found in round 1 is now fixed **in production**, not just in a test.

### Rule for the next agent

**`git log` in your checkout tells you what you inherited, never what is running.** Before any deploy:
`git show HEAD:<path> | sha256sum` versus `ssh <host> 'sha256sum <path>'`. If they differ, the host is
right and your patch must be ported onto it, not merged into it. And if production's commit is not in
`origin`, no amount of fetching will produce it — copy the files down.
