**L12384 · Fast path into a Windows machine is two double-clicks (W1/WinRM): what it is, where the password lives, and four bugs that looked right**

FAST PATH INTO A WINDOWS MACHINE IS NOW TWO DOUBLE-CLICKS (W1, native WinRM). Built and proven.

WHAT EXISTS NOW (tools/lpt-access-kit, branch zabz/lpt-access-kit-open-fix-20261015, commit 3a65da95)
 * 0-FAST-ACCESS.cmd (target) -> fast\Enable-FastAccess.ps1 opens tier W1
 * 0-FAST-CLOSE.cmd (target) -> the kit destructor -RunNow -> fast\Restore-WinRmAccess.ps1
 * Connect-FastAccess.cmd (ZABZ-TECH, NOT on the stick) -> fast\Connect-FastAccess.ps1
 * state tier "W1": port 5985, rule LPT-WinRM-<runid>, sshdServiceName empty so the destructor CANNOT
 touch sshd, serviceNamesToRemove empty so it cannot touch a customer's cloudflared.
 * The armed teardown is the kit's own (boot-start service + at-startup task), armed BEFORE the window
 opens. One new plan action, RestoreWinRm, driven by a literal state field that is empty for T1-T4.
 * Gates: 12/57/11/50/39/38/8 = 205 green; Deploy ends DEPLOY OK with 28 files.

WHERE THE PASSWORD LIVES: <stick>\LPT-Runs\<run>\fast-access.txt and nowhere else. Not in handoff.json
(Handoff.psm1 refuses to write one), not in the launcher transcript, never printed. 0-FAST-CLOSE
overwrites the line in place. While a window is open the stick IS a credential.

PROVEN ON ZABZ-YOGA 2026-10-26 (readings in REMOTE-ACCESS.md section 9): open 40 s; connect from
ZABZ-TECH with Admin=True; an invented command executed; second launch ADOPTED (one account, one rule);
close restored the machine's own posture both ways (WinRM on->on and, after manufacturing a customer
posture, off->off) with ABSENCE-RESULT: PASS. Test machine restored and proven: sshd_config SHA-256
identical, WinRM Running/Automatic, no accounts/rules/services left.

THE MEASUREMENT THAT CHANGES THE DOC: with LocalAccountTokenFilterPolicy ABSENT, a new local admin over
WinRM does not get a filtered session - it gets NO SESSION. Test-WSMan -Credential returned
<f:WSManFault Code="5">Access is denied.</f:WSManFault>; with =1 it returned Admin=True. The old text
("the session opens but admin commands fail") was wrong.

FOUR BUGS THE RUN FOUND, ALL FIXED, ALL IN THE "LOOKS RIGHT" CLASS
 1. `& Enable-PSRemoting @arr` - ARRAY splatting passes element values POSITIONALLY, so the switch NAME
 '-Force' became a value: "A positional parameter cannot be found that accepts argument '-Force'".
 Use a hashtable. The launcher then correctly refused to claim READY, which is how it was caught.
 2. Set-Item WSMan:\...\TrustedHosts -Value $ip -Concatenate -Force threw "Cannot convert
 'System.Object[]' to the type 'System.String'". Build the comma string and use -Force.
 3. `$x = if ($c) { @() } else { @('a') }` did not give an empty array: the state file got
 "serviceNamesToRemove": {} and the destructor died with "Cannot bind argument to parameter 'Name'
 because it is an empty string". Assign arrays IMPERATIVELY, then override.
 4. A verification regex `(?m)^\s*password\s*=\s*(?!<scrubbed)` reported a SUCCESSFUL scrub as a
 failure, because \s* matches zero characters and the lookahead was evaluated at the space. Parse the
 value; do not look ahead over optional whitespace.

AND ONE ORDERING RULE, LEARNED THE HARD WAY: CLOSE THE WINDOW BEFORE YOU DELETE THE RUN FOLDER. I removed
C:\LPT-Runs (with access-window.json in it) and left a live local administrator and a live 5985 rule on
ZABZ-YOGA with nothing left to name them. The state file is the only thing that names the artefacts.

NOT PROVEN: a customer machine (by instruction); a shop-LAN target (ZABZ-YOGA was at home, so the LAN
address was recorded but the tailnet one answered); a second stick (before-state inheritance reads the
earlier window's state from the SAME stick); a domain pair; -SkipNetworkProfileCheck on a Public target.
The SSH/T1 end-to-end gap (A2-A8) is untouched by this work.
