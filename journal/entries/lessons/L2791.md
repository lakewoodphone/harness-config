**L2791 · Retiring a stale test contract: replace it with a tighter assertion, never a weaker one**

MEASURED 2026-09-28, personal-secretary-mvp.

Three pre-existing tests went red when a real defect was fixed. In every case the test was
asserting the DEFECT, and the honest fix was to write a STRONGER assertion, not to relax one:

1. `test_work_queue_completes_at_planned_step_budget` asserted `len(chats) == 1` (the loop
 charged a work step per TURN, so it closed after one more turn whatever that turn did).
 Replaced with the bound that actually matters, `1 <= len(chats) <= controller._work_turns_cap(5)`,
 AND a new forbidden-claim assertion: `assert "STEP_BUDGET_EXHAUSTED" not in _append`. A session
 that executed nothing must not be recorded as having spent a budget. That assertion did not
 exist before; it is stronger than the one it replaced.
2. `test_artifact_required_work_queue_does_not_auto_complete` used a 4/5 fixture that no longer
 reaches the pre-loop artifact guard (`steps_floor >= total_steps`). The fixture became 5/5 --
 the case the test is NAMED for.
3. `test_ghost_agent_reassigned_to_canonical` asserted `result == 1`, a counter that mixed repairs
 with escalations -- which is why "is the loop closing?" was unanswerable. Replaced with the three
 separate facts: `ghost_repaired == 1`, `ghost_escalated == 0`, `result == 0`.

And one test file whose verdict depended on WHICH HOST ran it: `tests/test_smart_router.py` passed
on Windows and failed `7 failed, 38 passed` on the authority, because the router validates model ids
against the gateway catalogue and that catalogue is ambient configuration. Fixed with an autouse
fixture that disables the catalogue for the module. A test whose result depends on the machine is
not a test, and local green is not production green.

THE RULE: when a fix turns a test red, first ask whether the test asserts the defect. If it does,
the replacement must be strictly stronger -- pin the new honest behaviour AND forbid the old false
claim. "Relax the assertion until it passes" is indistinguishable from hiding the bug.
