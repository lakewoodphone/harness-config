**L · The kiosk's Stripe return URL was `/kiosk` and the page was mounted at `/intake` — fixed, deployed to test, and PROVEN by rendering the live test site. The same proof on production is blocked by a missing live Stripe secret, not by code.**

**The defect and the fix** are recorded in L7294 and the decision in D6273. This entry is the proof, because the whole session's complaint was that the kiosk wrote and nothing read.

That second line is the whole fix: the return URL Stripe is given now lands on the kiosk with its `intake`/`ref`/`payment` parameters intact, which is what the page's resume needs. Before the change, the identical URL rendered `404 / Page not found / /kiosk` (measured on the same host earlier in the session) and, logged out, `/login?expired=true`.

**The 404 was NOT the whole story, and the two were one bug.** The kiosk page never running is what left `KioskIntakePayment.status` at `PENDING`: `submit` is the only writer of `PAID` (`kiosk-intake.service.ts:742`) and only the page calls it. So a paid customer's case read "Not paid yet" for ever. The browser-independent arm added in the same change (`checkout.session.completed` → `kiosk-intake-payment-webhook.service.ts`) removes that dependence.

**Rule this earns, and it is the third time this session paid for it: a merge is not a deploy, and an identical tree is not a running system.** `main` and `test` being byte-identical says nothing about what production serves — production is still on the 2026-10-15T00:25Z deploy. Read the deploy RUN for the environment you care about, not the branch.
