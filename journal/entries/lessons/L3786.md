**L3786 · Customer credentials, extended: Apple IDs are in scope, the photos need a .gitignore whitelist, and the trusted number is the shop's own line**

**Extends L3321** (the `_credentials-*` flow). Three things it did not say, learned on the Mendelowitz
iPhone case, 2026-10-13.

**1. The flow is not Windows-only, and the Apple variant has one extra fact that matters.** A customer's
**Apple ID** uses the same house shape as the Microsoft setups — password `Hello@1234` — but the thing
that must be written down is **whose number receives the verification code**. In this case it is **the
shop's own Dialpad line, `+17326552355`**, because that is what was set as the trusted number during
setup. Consequence worth keeping: *a verification code for a customer's Apple ID arrives on the shop's
business line, and whoever is looking at the shop's messages can complete a verification for that
account.* That is the owner's arrangement; record it, do not re-litigate it. As of 2026-10-13 the single
password `Hello@1234` is on **six** customer accounts, **two of them Apple IDs** — a compromise of any
one has to be treated as a compromise of all six.

**2. The screens of the setup ARE the record, so photograph them.** For an Apple ID there is no
outlook.com address to reconstruct later: the account details exist only in what was typed. The six
photographs of 2026-10-13 (name/birthday, email, phone verification, both intake slips, the printed
label) each carry a sha256 in the case file and match the hash the owner's own upload carried, so the
bytes are provably his.

**3. `*.jpg` is gitignored repo-wide, so a new case-media folder silently drops its photos.**
`.gitignore:44` ignores every jpg; the shop has already lost a photo set this way (April 2026, 82
files). Every photographed case therefore needs its **own `!` whitelist block** in `.gitignore` with a
comment saying what the photos are, why they must survive, the file count and size, and where the
originals also live (`secratary:/home/zabz/phone/<slug>/`). Precedents: `2026-09-24-intake-notes`,
`2026-10-06-kramer-iphone-whatsapp`, `2026-10-06-intake-notes`, now
`2026-10-13-mendelowitz-iphone-apple-id`. A `git add` that shows no photo is the failure, not the proof.

**4. What `lptcase.py check` does with these files.** `_credentials-*` case ids are exempt from the
"case-without-sync-record" rule by design (`lptcase.py` ~line 2560, `doubles.py` `COMPANION_PREFIX`), so
`sync_record: ""` on one of them is correct. Adding the Mendelowitz record did not change any `check`
class count: 4 classes / 287 files before and after.
