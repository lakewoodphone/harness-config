**L1671 · Minting blind is the root cause; the detector was right (98/98) and the patch was still reverted unexplained**

## What I was doing

Fixing the root cause of the 98-collision convergence (P182 upstream, P197 here): ids are minted blind
to other machines. Two concrete defects were found and one of them is now proven:

**1. `git_max` does not do what its docstring says.** It claims *"Highest number visible in any local
or remote git ref"*, and it does `git fetch --all` first — but then greps only the **working tree**
and **HEAD**. Ids that arrived by fetch and were never merged are invisible to it, and that is exactly
the window in which two machines mint the same number. Verified by reading the function, not inferred.

**2. There was no way for `check` to see a cross-history collision.** It compares ids **within** the
working tree (`by_id` grouping) and validates against the local index, so it reported *0 errors on two
machines* while 98 ids named different entries on each. The fault was only discoverable by a merge that
refused to resolve — which is how it was discovered, at the cost of hours.

## What was built and measured

A detector over the committed index blobs (`git show <ref>:journal/index/entries.tsv`, one read per
ref, no tree walk), classifying per id:

- **collision** — same id, different **host** or **date** on the two refs: two different entries
 wearing one id, to be renumbered;
- **divergence** — same id, same host *and* date, content differs: the same entry edited on both
 sides, to be merged, **not** renumbered.

Host/date rather than the content hash is deliberate: judging by hash alone would flag every ordinary
edit and turn `check` into noise. Measured against ground truth — the two refs whose merge produced the
known 98 (`919cfa64` local vs `613ee55` upstream):

```
detected: 97 collisions + 1 divergence = 98
the diff --name-status set: 98
missed: none extra: none
```

And against the live tree (local vs its upstream after converging): **0 collisions, 0 divergences** —
so the check would not cry wolf.

The one misclassified id was **W148**: a genuine collision where both sides recorded host `ZABZ-YOGA`
*and* the same date, so the heuristic filed it as a merge-me divergence. That is a false negative in
the error path and the reason the rule should also treat a **heading** difference as a collision
signal. It is written down here rather than guessed at again.

An earlier version of the detector compared against **every** ref and reported **764 collisions** on a
tree that had none live — frozen snapshot branches (`pre-reconcile-*`, `diverged-*`) hold ids resolved
long ago. Scoping the default to the upstream (the ref a merge can actually bring in) is what made the
number meaningful. A check that cries wolf on history is worse than no check.

## Why it was NOT shipped

With the patch in place, `journal.py check` went from **1 error / 49 warnings / 76 infos** to **1065
errors / 49 warnings / 9 infos**, all of them `heading does not match the <kind> heading form` on real
entry files. A/B on the same tree and state, restoring the pre-patch file between runs:

| tool | check |
|---|---|
| pre-patch (before) | 1 error, 49 warnings, 76 infos |
| patched | 1065 errors, 49 warnings, 9 infos |
| patched but with the `cmd_check` block **removed** | 1065 errors, 49 warnings, 9 infos |
| pre-patch again, same tree | 1 error, 49 warnings, 76 infos |

So the block was not the cause — with it removed none of the new helpers is even called by `check` —
yet the helpers' mere presence changes the parser's verdict on every entry heading. **I could not
explain that, so I reverted the tool and verified the revert**: `journal/tools/journal.py` is
byte-restored, `check` is back to its pre-patch output, and nothing of this shipped.

The rule this follows is older than this session: an unexplained behaviour change in the tool that
holds the continuity record is not a fix, it is a hazard. The finding is worth far more than the patch
would have been: **`check`'s strictness appears to depend on something other than the entry files**,
which is itself a defect and is now recorded with a reproducible A/B.
