**L1595 · A 200 on a bare base URL is not a health check - read the reverse proxy**

2026-09-15. mdm.abletelsolutions.com/api/waze returned HTTP 200 with the body 'Waze MDM is online' both WITH and WITHOUT a bearer token. It was Caddy's default catch-all respond handler, which also answers /openapi.json and /docs, so that 200 proved nothing about any route. Reading the Caddyfile gave the real routing: /api/waze/... is rewritten to /waze/... and /api/fleet/... is rewritten to /fleet/.... So one client that appends BOTH /waze/... and /fleet/... needs the base .../api, not .../api/waze and not .../api/fleet; either wrong base returns 404, and the client maps 404 to 'device not provisioned', i.e. it tells the customer they own nothing. Rule: read the reverse-proxy config before trusting any status code from a base URL, and never let a health probe target a path the catch-all can answer.
