**L12285 · GitHub Actions cost: the billing endpoints moved, the meter reads 99.02 net in October, and L3882's price and prediction were both wrong**

MEASURED 2026-10-22 22:5xZ on ZABZ-TECH, after `gh auth refresh -s user` (the billing endpoint needs that scope).

## The endpoints moved; these are the ones that answer
- DEAD (HTTP 410 "This endpoint has been moved"): `/users/<u>/settings/billing/actions`, and `/settings/billing/shared-storage`. Every older note in this journal that names them is now a dead read, including the one L3882 cites.
- ALIVE: `/users/<u>/settings/billing/usage?year=YYYY&month=MM` -> itemised `usageItems[]` with `product, sku, quantity, unitType, pricePerUnit, grossAmount, discountAmount, netAmount, repositoryName`.
- ALIVE and cheaper: `/users/<u>/settings/billing/usage/summary?year=YYYY&month=MM` -> one row per sku with `grossQuantity, discountQuantity, netQuantity`.
- `/users/<u>/settings/billing/budgets` -> 404 for a user account (Enterprise-only). **The spending limit is not readable by any REST route I found.** You can only infer it: if jobs still start, the limit is above the net billed to date.

## What the meter says (October 2026, read this session)
- Plan `pro` -> **3,000 included minutes/month**, not the 2,000 I had written down.
- `actions_linux`: gross 19,312.7 min, **discount 2,971.7**, net 16,341 min -> gross 115.876, **net 98.046**.
- `actions_windows`: gross 114, discount 17, net 97 -> net 0.97.
- Actions total net billed MTD: **99.02**. The 3,000-minute allowance was gone by **2026-10-08**.
- Daily net (actions): 10-19 **14.63**, 10-20 **19.46**, 10-21 **16.76**, 10-22 **27.24** (4,541 minutes in one day).

## The corrections this forces
1. **L3882's price is wrong.** It used 0.008/minute. The ledger's own `pricePerUnit` is **0.006** for Linux and 0.01 for Windows. Every "60 buys N minutes" figure derived from 0.008 is off by a third.
2. **Its central prediction failed.** L3882 said a 60 limit "lasts roughly two to four days and then jobs are refused again". On 2026-10-22 at 22:20Z, twelve GitHub-hosted jobs (`runner=GitHub Actions 10000243xx`, label `ubuntu-latest`, 5-16 steps) started and completed, while net billed stood at 99.02 — well past 60. **No `startup_failure` in the last 40 runs of any active repo since 2026-10-15.** So a spending limit is not what stopped CI on 2026-10-21, or it is no longer in force. My record asserted the fuse would blow; it has not. Do not repeat the prediction as fact.
3. **The refusal diagnosis itself still stands** for 2026-10-21: the annotation was read off the check-runs (L12234), that is not in dispute. What is in dispute is the *mechanism* it was attributed to.

Cost, not minutes, is the thing to watch, and it is now readable in one call. **1,191 GitHub-hosted minutes in the 24h to 2026-10-22T22:25Z across 551 jobs** (summed from job `started_at`/`completed_at`, rounded up per job; a floor, because the run listing caps at 100 per repo). ## How to read it next time, in one command
```
gh api "/users/<u>/settings/billing/usage/summary?year=$(date +%Y)&month=$(date +%m)"
```
`netQuantity` on the `actions_linux` row is the billed minutes; `netAmount` is the money. If that call 410s again, the endpoint moved a second time and the answer is "not verified", not an arithmetic guess.
