**L1973 · Never put a dollar sign in a PowerShell double-quoted commit message - it eats the number**

**Use a single-quoted here-string for any git commit message containing money. In a PowerShell double-quoted string, `$` followed by a digit is a variable reference, and an undefined variable expands to nothing.**

**Measured, 2026-09-18.** `git commit -m "... understated the spend by $235-311 ..."` was pushed with the subject reading `understated the spend by \-311` - PowerShell read `$235` as an undefined variable and deleted it. The body lost every figure the same way: `$1,065.61` became `,065.61`, `$1,512.26` became `,512.26`, `$446.65` became `.65`. The committed *files* were correct; only the log line was wrong, and it was already pushed, so it could not be fixed by amending - a force-push is not available for cosmetics.

**What was done instead.** `git notes add -f -m <corrected text> <sha>` and `git push origin refs/notes/commits`. The note is on origin (`refs/notes/commits` = a97eaddc) and renders with `git log --notes`. This is the non-destructive way to correct a pushed commit message: never force-push for it.

**The rule.** Single-quote any argument that contains `$`. For multi-line bodies use a single-quoted here-string `@''@`, which expands nothing. Check what landed (`git log -1 --format=%B`) before moving on, because the corruption is silent at commit time.
