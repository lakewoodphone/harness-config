**L1546 · Wiring a SQLite-only storage section into a request path: reach _conn and fail closed, do not grow the Postgres parity surface**

EVIDENCE: `server/app/inference_budget.py` docstring + `tests/test_egress_budget.py::test_anyio_offload_can_read_the_ledger_from_another_thread` (which passes against the real `Storage`).

THE PROBLEM. `app/storage_sections/inference_telemetry.py` takes a `sqlite3.Connection`, and every other section in
the repo is reached through a `Storage` facade method that does `section_method(self._conn, ...)`. `Storage` also
accepts a `PostgresStorageBackend`, which sets `connection = _UnsupportedConnectionProxy()`, and
`tests/test_postgres_storage_parity.py` fails the build if a `Storage` method has no Postgres implementation
(`PostgresStorageParityAuditResult.missing_backend_methods`). So "add a Storage method for the budget check" costs
three PostgreSQL implementations plus dispatch entries plus protocol entries — and for a *fail-closed* gate that is
the wrong shape anyway, because the Postgres path would then need its own copy of the budget SQL and a *second*
definition of what the ceiling means.

WHAT SOLVED IT. Reach `storage._conn` directly (that is what every `*_storage_section` call in `storage.py` does
anyway), then **fail closed when it is not a SQLite connection**. `is_egress_allowed(conn=None)` and the
`except Exception` inside it both return `allowed: False`; `record_inference_budget_event` returns `None` on
failure, which is the honest answer to "did you record it". Result: on the experimental PostgreSQL runtime the gate
refuses egress and says so in a log, rather than metering nothing; no parity surface had to move; the SQL surface
audit count stayed at 341.

THE TRANSFERABLE PART. When a new caller is needed for a section that lives outside the facade, "how do I get a
connection" is cheap, but "what happens on the other backend" is the actual decision. The move that worked was:
take the direct connection, and make *the other backend's absence* a refusal rather than a special case to
implement. A fail-closed feature has no obligation to work everywhere — it has an obligation to be safe where it
does not.
