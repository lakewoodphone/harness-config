**L4578 · \/profiles/<n>/cordis.patch.yml is not a byte-copy of the repo file - the drift instrument is red by construction**

`scripts/preset-drift.py` (changed in round 5) and `sync.py`'s verify step compare `$DSH_HOME/profiles/<n>/cordis.patch.yml` against `profiles/<n>/cordis.patch.yml` byte-for-byte. Measured 2026-10-15 on ZABZ-YOGA, they are different KINDS of artefact:

* repo, 116,970 B - the authored form: a JSON array, ` { id: ui-settings-general, config: { welcomeNoticeVersion: 2026-08-13.1 } }`
* live, 146,715 B - the engine's composed form: `- { id: 'typert-gateway', config: { websocketHeartbeatIntervalMs: 15000 } }`, carrying rows the repo never had (`tool-subagent-remote disabled: true`, a second `agent-preset-registry`) and a NEWER `welcomeNoticeVersion` (2026-09-28.1)

`git diff --ignore-all-space` between them is still 301 hunks. The live file's value being NEWER than the repo's proves it is not a derived copy of the repo file.

CONSEQUENCE: that comparison is red by construction, so a REAL persona drift and the ordinary difference look identical - which is how an instrument becomes noise and then gets ignored. `sync.py`'s verify printed DRIFT on a machine whose composed config was, by `--dump-config`, entirely correct.

NOT PROVEN: what writes the live file every 15-30 minutes with `.bak-<stamp>` backups. `sync.py`'s `plan_profile_patches` does write `.bak-<stamp>`, so it is one writer; `--dump-config` was run twice and does NOT write it (mtime and sha unchanged). Left open rather than guessed.

USE INSTEAD: `dsh --profile <p> --dump-config` with marker assertions. It is stable, it is meaningful, and it is what the engine actually composes.
