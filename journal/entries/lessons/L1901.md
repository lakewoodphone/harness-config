**L1901 · To prove a guard refuses BEFORE billing: pre-seed its counter, then read turn/end**

Measured 2026-09-17 demonstrating the spend guard.

A reject-before-step guard cannot be demonstrated with a low ceiling alone: the first step of a cold day is always admitted (counter 0 < ceiling), so the turn completes normally and the guard looks inert. Seed the guard's own state file (day.json) with a micro-USD total ABOVE the ceiling for the current UTC day first, then run the turn. The first pre-step then rejects.

The three-observation proof, all required, and the second is the one that shows nothing was billed:
 a. ~/.dsh/spend-guard/day.json shows requests: 0 (the counter only moves on a billed event)
 b. read the session log with packages/plugin-cost/src/session-log.mjs and check that turn/end reason.kind == 'blocked' AND there is NO step/start event AND no assistant/message carrying usage
 c. the guard's own log/state shows lastVerdict: reject, lastReason: daily ceiling

Reproduce on an ISOLATED engine, never the owner's: set DSH_HOME to a scratch directory, build a scratch profile with bundles [dsh-base, dsh-headless, dsh-plugin-cost] and junction node_modules/dsh-plugin-cost at the real package, and override the guard row with --patch <json> (a patch entry {id, config} REPLACES the whole config, so restate every key). dsh --profile headless DOES run in that setup - 4-7 s per turn - which contradicts doc 96 section 6.1's report that a headless turn hangs on this machine.
