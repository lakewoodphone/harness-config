**L1951 · disable_texting:false does not mean the SMS app is enabled, and verify cannot see it**

Measured 2026-09-17 on E4610 serial 615765621 while closing out a staged standard-lite deploy.

Fact: at intake (before our deploy ran) `pm list packages -d` listed
`com.verizon.messaging.vzmsgs` = the E4610's SMS app per `cli/configs/devices/e4610.yaml`
(`packages.sms_app`). It had been disabled by the previous filter provider.
Nothing in our deploy re-enables a package it did not disable:
- `bloatware` (`engine._phase_bloatware`) enables only `preserve_packages` (talkback, webview,
 svox.pico on E4610) and then disables the bloatware list + `forced_disabled_packages`;
 `com.verizon.messaging.vzmsgs` is in neither.
- `sms_app_package` / `sms_fallback_app_package` are used by `deployment/verification.py` and
 `release_gates.py` only, never by an install/configure phase.
So `disable_texting: false` means "don't force it off", not "make sure it is on".

Worse, the verify pass cannot see it: `verification._sms_check` compares
`settings get secure sms_default_application` against the expected package, and that setting is
already `com.verizon.messaging.vzmsgs`, so a *disabled* SMS app passes the check while the customer
has no messaging UI at all.

Consequence: on a prefiltered handset, texting can be dead after a "complete" standard/standard-lite
deploy, and no phase or verify check reports it.

Fix (needs a handset to verify before shipping, since it touches every E4610/E4810 deploy path):
1. Add an explicit enable of `config.sms_app_package` when it is non-None (gated exactly as
 `disable_texting` already is, so no-text profiles are unaffected) — `post_install` runs in both
 the stage and finalize paths.
2. Extend `_sms_check` to also assert the package is enabled (`pm info <pkg>` -> `enabled=` state,
 the way `cli/lpt/deployment/cleanup.py` already parses it).
Until then, the intake check in `docs/deployment/PREFILTERED-DEVICE-AND-E4610-MANUAL-STEPS-RUNBOOK.md`
is the guard: `pm list packages -d` at intake, `pm enable <sms_app>` in the finalize pass.
