**L1987 · A connection that has become a raw pipe can never be intercepted again (keep-alive defeats a hybrid proxy)**

MEASURED 2026-09-18. A proxy that splices non-matching requests as raw TCP and intercepts only POST /api/session/list NEVER SAW THE CALL: its own counters read spliced=19, cold=0 while the sidebar sat empty for 27 s.

CAUSE: the page opens ~6 keep-alive connections; each is handed to a raw pipe because it is not session/list, and the browser then reuses one of those pipes for session/list. Once a connection is a pipe it can never be parsed again, so the intercept can never fire. A reachability counter said the proxy was healthy the whole time.

FIX: rewrite the forwarded request'"'"'s Connection header to "close", so the browser cannot reuse anything and every request arrives on its own connection. Measured that the engine honours it: `GET /` with Connection: close -> response header "connection: close" and the response ends; with keep-alive -> "Keep-Alive: timeout=5". NEVER rewrite an Upgrade request - a WebSocket upgrade needs "Connection: Upgrade" intact; splice those byte-for-byte.

ALSO: the header must be inserted BEFORE the terminating CRLFCRLF. A first attempt spliced it at lines.length-1 and produced "...Host: x\r\n\r\nConnection: close", i.e. the header landed in the BODY, and the browser reported ERR_HTTP_RESPONSE_CODE_FAILURE. headOnly ends exactly at the terminator (bodyStart = indexOf("\r\n\r\n")+4), so insert at text.length-4.
