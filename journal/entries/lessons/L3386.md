**L3386 · This laptop's backend suite fails ~55 tests on pristine main - never trust its verdict**

Measured 2026-10-08: on ZABZ-YOGA, pnpm --filter phone-and-tech-backend test reports 55 failures on a feature branch and 56 on a PRISTINE origin/main checkout - identical failing sets, mostly 5000ms timeouts, none importing the changed file. The set is load-sensitive (one file went 30 -> 21 failing across runs); total files are 7876-7879.

The SAME suite on ZABZ-TECH ran clean twice in a row the same day: 7508 passed / 0 failed (509 files) and 7509 passed / 0 failed. So the laptop's verdict is not evidence about the code, in either direction.

Rule: run the authoritative backend suite on ZABZ-TECH. If a LOCAL fallback agent reports failures, compare its branch against pristine main ON THAT MACHINE before believing any of it - and if the deltas match its own new tests, the failures are the environment. The cost of not doing this is either a false alarm that stops a good deploy or a real regression waved through as 'just the machine'.
