# L1938 — harness-config rebases bite: the commit survived, the working tree did not

## What happened

Committing `verify-deploy.sh` to the authority's `harness-config`, the push was rejected because the
branch had diverged — and its conflict is on `journal/state/owner-questions.md`, a **generated** file that
`journal.py questions` rewrites, in a journal store with a documented contested-ids problem across
machines.

I ran the rebase anyway. It conflicted, and **left a rebase in progress with HEAD back at the pre-commit
state** — so `scripts/verify-deploy.sh` disappeared from the working tree, and the commit looked gone. I
had deployed it minutes earlier and verified all 11 markers passed, then could not find the file.

Recovery: `git rebase --abort` restored HEAD to my commit (`7229031`), and `git checkout 7229031 --
scripts/verify-deploy.sh` restored the file. Mode `100755` intact (verified with `git ls-tree`), content
matches HEAD, and the tool runs and passes.

## The rules

1. **Do not rebase harness-config.** This is the THIRD time in this session that a rebase in this repo
 cost time and risked work — round 15 lost a round to it, round 16 avoided it, and this round it
 briefly hid a commit I had just made. Its conflict is always generated journal state owned by another
 machine's commit, so a rebase here is fighting a writer rather than merging content.
2. **A rejected push is not an instruction to rebase.** It is information: the remote moved. Commit
 locally, deploy what you need, and let the repo converge on its own schedule.
3. **`git rebase --abort` is the correct first response to a conflict you did not intend**, and it is
 cheap. Mine restored everything. The expensive mistake would have been to "resolve" the conflict on a
 generated file.
4. **An unpushed commit is not a lost commit.** Verify with `git cat-file -t <sha>` before concluding
 anything — the object existed the whole time; only the working tree had moved.

## Evidence

- Before abort: `HEAD 53cf517`, rebase in progress YES, file on disk NO.
- After abort: `HEAD 7229031`, rebase no, `git cat-file -e 7229031:scripts/verify-deploy.sh` → YES,
 `git ls-tree` mode → `100755`.
- After restore: 6,385 bytes, mode 775, `git status` empty, `bash scripts/verify-deploy.sh` → all 11
 markers present.
