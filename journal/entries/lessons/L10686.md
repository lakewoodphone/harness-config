**L10686 · A consumer reading a local checkout reads yesterday: docs=local hid a detached HEAD, and a --db flag must be forwarded to every child process**

The loop that works the LPT website had been reading yesterday's roadmap and nothing could see it.
Measured on the authority, 2026-10-20: `roadmap-supply.py --dry-run` prints `docs=local`, so it reads
the working tree of /root/repos/phone-and-tech-full rather than a fetched ref; that tree was on a
DETACHED HEAD from the previous day (a6b572bf9, 2026-10-19) with ten uncommitted files whose content
is byte-identical to the already-merged #499. Consequence: a roadmap merged into origin/test would
never have reached the supplier - it would have kept filing work from the previous day's document,
every run reporting `unmapped_boxes=0 stale_mapping_rows=0`, i.e. perfectly healthy.

The three-part rule this generalises to:
1. A consumer that reads a LOCAL checkout is reading whatever that checkout happens to be, which is
 not the same question as "what is on the integration branch". Ask which the tool reads: the
 dry-run's first token (`docs=local` vs `docs=git`) answers it in one word.
2. A detached HEAD is not a branch, and nothing about it looks wrong - `git log -1` shows a real
 commit, the paths exist, the parse succeeds. Compare `git rev-parse HEAD` against the integration
 ref to see the staleness; nothing else will show it.
3. The fix belongs in the thing that already runs on a timer: /root/bin/lpt-reconcile.py --refresh-checkout
 now does `git fetch` + `git checkout --detach origin/test` every 3 h and REFUSES when tracked files
 are modified. Refusing is the important half - the archive step (patch written, verified reversible
 with `git apply --check -R`, plus `git stash push` with a message naming the archive) is what makes
 moving the tree safe rather than destructive.

Second lesson from the same hour: `work.py` writes its DEFAULT database unless given `--db`. A
reconciler that is tested against a copy of work.db will therefore close rows in PRODUCTION. Caught
before it ran because the copy was tried first; the flag is now passed through explicitly. This is the
third instance on this estate of a test that writes to a real store, and the general form is: whenever
a script takes a `--db`/`--root`/`--config`, check that every child process it spawns is given the
same one.
