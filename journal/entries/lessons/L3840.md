**L3840 · pgrep -f matches the shell running the check: it silently disabled a recovery guard for two days (green exit, nothing running); anchor the pattern**

**L · `pgrep -f <pattern>` matches the shell that is running the check. It silently disabled a recovery script for two days, and it is the same self-match trap the delivery docs record for `pkill -f`, one tool over.**

**Measured 2026-10-18 on `zabz-tech-linux`.** `_rearm-if-needed.sh` — the script armed to restart a
delivery verify after an outage — guarded itself with:

```bash
if pgrep -f "copy-to-stick-linux.sh verify" >/dev/null; then
 echo "a verify is already running - leaving it alone"
```

and it printed exactly that, **while nothing at all was running**. The reason: it was invoked as
`ssh … 'bash -c "… sudo bash /tmp/_rearm-if-needed.sh … grep -E \"…|copy-to-stick-linux.sh verify|…\""'`,
so **the caller's own command line contained the pattern**, and `pgrep -f` matched the caller.

**How it was caught, and this is the part to copy:** the script exited **0** and said it had left things
alone. Two independent readings contradicted it — `ps` showed no verify, and `/sys/block/sdc/stat` and
`/sys/block/sda/stat` both moved **0.0 MB/s over 120 s**. A green exit code and a confident sentence are
not evidence; a counter that moved is.

**The fix — anchor every "is it already running" check to the start of the real command line:**

```bash
pgrep -f '^(bash|/bin/bash|sudo|/usr/bin/sudo) /home/zabz/copy-to-stick-linux\.sh verify'
```

A `bash -c "…"` wrapper's command line starts with `bash -c`, so it can never satisfy an anchored pattern.
After the fix the same script correctly printed `verify: no / finisher: no / checksums: no` and armed the
work, and the counters immediately read 12.9 and 17.2 MB/s.

**The generalisation, and every one of these has bitten this estate:**
- `pkill -f <pattern>` can kill the killer (documented, 2026-08-05).
- `ps | grep <pattern>` matches the grep.
- `Get-CimInstance Win32_Process … -CommandLine -like <pattern>` killed its own shell twice on 2026-10-14
 (delivery doc §8.9) — fix there was `$_.ProcessId -ne $PID` and building the pattern at runtime.
- And now `pgrep -f` in a guard, which fails **quietly and green**, the worst kind.

**Two rules to carry:**
1. **Any guard that can suppress work must print what it saw** — the pid and its `cmdline`, not just
 "already running". A self-match is then obvious in one line of log.
2. **A guard's suppression is a claim until the counters agree.** After any "already running, leaving it
 alone", read something that only the real work could move.
