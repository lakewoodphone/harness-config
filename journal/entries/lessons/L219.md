**L219 · 2026-09-14 · Four deployment lessons: prompt/executor mismatch, git apply --check lies, backup coverage, silent deploy preconditions**

**L · 2026-09-14 · A prompt that instructs a syntax the executor discards fails as a mute model, not as a config error**

`app/autopilot.py::_build_work_prompt` told the work-mode agent: *"Use [ACTION:...] tags to
take concrete actions"*. `assistant_legacy_action_tags_enabled` ships `False`
(`app/config.py:745`) and was `false` in the authority's `.env`, so `parse_actions()` stripped
every tag and returned **no actions** — silently. The step consumed its budget anyway.

The reason this cost weeks rather than minutes is the *shape* of the symptom: the agent
appeared to repeat itself for no reason, so the investigation went to the model, the tier, the
prompt length and the task quality. The actual defect was a mismatch between two halves of the
codebase that were each individually correct.

Durable rules:
1. Any prompt string that names a **mechanism** must be paired with a test asserting that the
 mechanism is enabled in the shipped configuration. A default is what an unnoticed change
 moves, so the test must name the default explicitly.
2. When a parser is going to **discard** model output, it must count and report what it threw
 away. Silence is the bug. `_dropped_action_tag_count()` and the
 `[DROPPED-ACTION-TAGS: n]` marker exist for exactly this.
3. Before blaming model quality for a repetition loop, grep the codebase for the instruction
 the model was actually following and confirm the executor honours it.

**L · 2026-09-14 · `git apply --check` exiting 0 does not mean the patch applies cleanly**

Applying a fix to the authority's 87-commit-diverged checkout, `git apply --check --3way`
printed *"Applied patch to 'app/autopilot.py' with conflicts. Falling back to direct
application..."* and **exited 0**. The real apply then wrote conflict markers into a live
production file. The compile gate caught it and the rollback restored the file byte-identically
— but the lesson is that the check was not a check.

Durable rules: after any patch to a diverged tree, grep for `<<<<<<<` **before** trusting it,
and never treat `--check` exit status as proof. On a tree that has diverged this far, prefer
exact-string surgery with a strict "every anchor must match exactly once or refuse" gate
(`harness-config/scripts/port-work-mode-fix.py` is the pattern) over any 3-way merge.

**L · 2026-09-14 · A backup's coverage is what it omits, and nobody had enumerated it**

`scripts/server/backup-data.sh` runs every 6 hours and tars `.env`, `web/.env.local`,
`data/...` and `.runtime` — and **no `app/`, `scripts/`, `tests/` or `docs/` at all**. The live
checkout therefore held 11 tracked files containing bytes present in no git ref (local or
remote), plus one commit on no branch, with **no backup of any kind**. That state survived
because the script's own name ("backup-data") described its contents so well that nobody asked
what "data" excluded.

Durable rules: a backup is not evidence until you have listed what it *does not* contain.
Enumerate the trees the backup omits and compare them against what the system actually needs to
run. The code tarball is now part of that script.

**L · 2026-09-14 · A deploy script whose precondition can silently fail will hide its own death**

`scripts/server/deploy.sh` is `git pull --ff-only` then `systemctl restart`, under
`set -euo pipefail`, with the pull's output piped through `| tail -2`. On a diverged HEAD the
pull cannot succeed, so the script aborts at step 1 of 6 — and the operator sees two lines of
tail, not a failure. Consequence: the documented path had been dead for a week and every
subsequent commit was made *in place* on production instead, which is how the divergence grew
from 71 commits to 87.

Durable rules: every deploy script must assert its own preconditions explicitly
(`git merge-base --is-ancestor HEAD origin/master` is the one that was missing) and fail loudly
with the reason. Verify a deploy path by running its precondition check, not by reading it.
