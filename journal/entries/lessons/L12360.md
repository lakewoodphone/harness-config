Owner-stated 2026-10-25: a **soldered laptop charging-port (DC jack) job is 90 flat** — part and freight
inside it. Not `(part + shipping) × 1.4 + 65` (that gives ~85 with an 8.49 jack, 65 for a pure re-solder),
and not the "65–85 band, 75 precedent" the AV15-51 case file had been carrying. Recorded in
`lpt-hub/docs/customer-operations/PRICING-RULE.md` § "Flat job prices the owner has set", and the superseded
band is pointed at from `cases/acer-aspire-n20c5-charging-jack-greenwald-8482017577-2026-09-17.md`.

Two corrections he made to one SMS draft, both worth keeping:

1. **Do not hedge a quote into the alternative fault.** I wrote "if it turns out to be the plug and not the
 port, we'll tell you" — a real $0 branch from that case file. He cut it: the customer already said it's
 soldered, so the message states the port fix and the number and nothing else — *"if it's only the port
 then to fix it is 90"*. **The $0 branch is a bench rule; it does not belong in the first customer
 message.** A hedge reads as "we might not be able to do it", which is not what a lead needs to hear.
2. **A number he gives replaces mine in every place mine appears**, not only in the sentence he corrected —
 and the draft with the wrong number had to be found in the chat rather than assumed gone.

Mechanics that cost time and should not again:

- **`send-lpt-sms.py` is NOT in lpt-hub.** It is on the authority at
 `/root/personal-secretary-mvp/scripts/send-lpt-sms.py` (found via `ps_search {"what":"files"}`), and it
 must run with **`.venv/bin/python3` from `/root/personal-secretary-mvp`**. System `python3` exits 1 with
 `Cannot load settings from .env: No module named 'pydantic_settings'` — that is an interpreter error, not
 a config error.
- The body goes in a file, `scp`'d over, with the bytes checked (`Get-FileHash` md5 vs remote `md5sum`;
 f0b6ea5e279ba4121eff457dfaaae541 matched) because PowerShell mangles the em dash and `$` on a pipe.
- **Verification is the cache row, not the script's word.** `dialpad_sms_cache`: `created_at` vs `fetched_at`
 3 s apart is a live capture; `status: pending` from the script is not a delivery receipt, and no Dialpad
 API exposes delivery.
- **`ps_db_query` runs SQLite.** `::text` casts fail with `unrecognized token: ":"`. Use
 `pragma_table_info('table')` for columns and plain SQLite SQL.
- **There is no parts inventory in production**: `inventory_items` 0 rows, `stock` 1 row (2026-10-25). "Do we
 have the part" cannot be answered from any record; say unread, not "no".
