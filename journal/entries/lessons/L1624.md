**L1624 · git archive on Windows emits CRLF: a Windows-staged deploy ships different bytes than the git blob**

A Windows-staged deploy can ship bytes that are NOT the git blob, and `git` will not tell you.

WHAT HAPPENED (2026-09-15, deploying `deploy/fleet-dashboard/**` at 1b0c91d6 to waze-mdm-01):
`git archive --format=tar 1b0c91d6 deploy/fleet-dashboard` was extracted on Windows and scp'd to
the Linux box. Every `.py`, `.ts`, `.tsx`, `.json`, `.md`, `.txt` arrived with CRLF line endings —
all 37 files. Root cause: `core.autocrlf`/`.gitattributes` make `git archive` emit platform line
endings, and this repo's `.gitattributes` only pins `eol=lf` for `*.sh`, `*.yml`, `*.ps1`,
`Dockerfile*`, `*.mobileconfig`, `*.pac` — **`*.py` is unpinned**, so the archive carried CRLF.

WHY IT MATTERS: the box tree is the source of truth for what gets built into the image. CRLF there
means the deployed file does not equal the reviewed commit, so "is this deployed?" can never be
answered by comparing hashes, and every future diff of the box against the repo is noise.

THE FIX AND THE PROOF, both cheap:
1. `sed -i 's/\r$//'` on the installed tree (LF).
2. Prove it against the BLOB, not against `git`: `git cat-file blob 1b0c91d6:<path> > f` then
 sha256 `f`. After normalising, all 37 deployed files hashed identically to the blobs. Before
 normalising, 0 of the 21 Python files matched.

RULES THAT FOLLOW:
* Never use `git diff`/`git status` to decide whether a deployed file matches the repo — line-ending
 conversion hides inside the comparison. Compare `git cat-file blob` bytes.
* A `find -name '*.py' -o -name '*.ts' ...` normalisation list silently misses extensions not in the
 list. The first pass missed `frontend/index.html` (no `*.html` in the find) and the byte check is
 what caught it. Always re-hash after, never assume the sweep was complete.
* Better than normalising afterwards: extract with line endings left alone (`git -c
 core.autocrlf=false`, or add `*.py text eol=lf` to `.gitattributes`) so the artefact never carries
 the wrong bytes.
