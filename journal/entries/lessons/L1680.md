**L1680 · An unanchored .gitignore pattern (_archive/) silently dropped a merged adapter; git reported the merge as clean**

**An unanchored `.gitignore` pattern silently deleted a merged adapter, and git reported success.**

`.gitignore` carried these scratch patterns:

 _probe/
 _scratch/

Git matches a pattern containing no slash against **any path component**. When the journal adapter
directory was created at `adapters/journal/`, the `_archive/` pattern in the same block matched it —
`journal` was in the archive-name list — so the whole directory was excluded from the index. The
consequences, in order:

1. `git merge agent/journal` printed **"Automatic merge went well"** and committed a merge whose only
 content was `tests/test_journal_adapter.py`. The 31 KB adapter it tests was never written into the
 tree. Nothing errored.
2. A later `git add -A` then **deleted `adapters/README.md`** for the same reason — its path matched
 nothing, but the staged deletion came from the ignore rule.
3. `tests/test_journal_adapter.py` broke with `ModuleNotFoundError: No module named 'sync'` only at
 the moment a *second* adapter was merged, because each test file put its own adapter directory on
 `sys.path` and imported `sync` by bare name — and every adapter names its entry point `sync.py`.
 The bare import had been latent from the first adapter.

Recovery: anchor every scratch pattern (`/_probe/`, `/_scratch/`, `/_archive/`), give every adapter
directory an `__init__.py`, load each adapter by explicit file location instead of a bare `import`,
and recover the blob with `git checkout <commit> -- <path>`.

**The transferable rules:**
* **Anchor every ignore pattern.** An unanchored directory name is a silent, arbitrary filter over
 the whole tree. `_archive/` should have been `/_archive/`.
* **A clean merge is not evidence that files arrived.** `git merge` reports on the *index*, and an
 ignored path never reaches it. After a merge, run `git show --stat HEAD` and confirm the count and
 the paths — do not read "went well".
* **Audit the ignore file against the tree**, both directions: `git ls-files | git check-ignore
 --stdin` (is anything tracked now ignored?) and a walk of the source directories for files git does
 not track (is anything ignored that should not be?).
* **Never name two importable modules the same thing in one test suite.** `sync.py` in eight
 directories plus a bare `import sync` is a collision waiting for the second file to exist.
* **When a file has two meanings, do not filter on its name.** `journal` is both a corpus and an
 archive-shaped word; the pattern-based filter could not tell them apart and chose wrong silently.
