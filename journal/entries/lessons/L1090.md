**L1090 · Verify a rebuild with a parser you did not write**

The gate that proved this rebuild lost nothing (`_scratch/j-verify.py`) parses the legacy sources with the FROZEN v1 parser and reads `entries/` off the filesystem with no help from the new tool. On its first run it caught three things the new tool's own 240-check selftest could not: the verifier's own regex was wrong (it read "2026" as an id in handoff headings), the frozen v1 copy could not read the index because it sits one directory deeper than v1 did so its `JOURNAL` resolution shifted, and one entry inherited CRLF from a flat source and then a stale sha.

Rule: verify a rewrite with an implementation you did not write, and treat the verifier as suspect until its failures are explained. A tool checking itself agrees with itself; the disagreement is where the information is.
