**L2003 · kia_uvo advertises DTC-count and next-service-distance sensors that are never populated on a US Hyundai**

**L · The `kia_uvo` / `hyundai_kia_connect_api` README advertises sensors that are NEVER POPULATED on a US
Hyundai. Read the API source, not the integration's entity list.**

Measured 2026-09-18 while designing car health for the owner's 2022 Elantra (VIN `5NPLP4AGXNH073821`).
The Home Assistant integration (`kia_uvo`, HACS) is the live one — the rival `dahlb/ha_kia_hyundai` is
**archived** (last push 2025-12-20), so do not use it. Both `kia_uvo` and the underlying package were
pushed the same day, so it is genuinely maintained.

But reading `HyundaiBlueLinkApiUSA.py` (1,449 lines) rather than its documentation:

| Populated for USA | Never filled for USA |
|---|---|
| odometer, `car_battery_percentage` (12 V), fuel level, driving range, location, all four TPMS warnings, lock/door state | **`dtc_count`, `dtc_descriptions`, `next_service_distance`** |

Three fields exist on the Vehicle model and are advertised as entities; the USA parser never sets them.
**An alert built on "DTC count" or "next service distance" would silently never fire** — the same failure
class as the hardcoded-model-name bug in `personality-system` (L1606), where a plausible-looking
integration produced nothing and nobody knew.

Two more limits worth knowing before designing on it: **USA Hyundai does not support force-refresh**
(~30-minute cached state only), and the **Connected Services Agreement drops some services after 96 hours
without an ignition cycle**, so a stolen-parked-car model built only on Bluelink goes quiet after four days.

**Rule:** when integrating a reverse-engineered client for a real-world system, verify each field against
the region-specific source before promising it, and publish which fields are actually usable. A README is
a claim; the parser is the evidence.

**Evidence:** `hyundai_kia_connect_api` 4.31.0, `HyundaiBlueLinkApiUSA.py`; kia_uvo 934 stars / last push
2026-09-18; `docs/personal-vehicle/tracker-and-health-plan-2026-09-18.md` §1. Compare L1606.
