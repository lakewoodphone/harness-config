**L6247 · Build the measurement the harness cannot produce - and let -SelfTest find your own bugs: StrictMode scalar .Count, and fixture epochs**

**L · 2026-10-15 · ZABZ-TECH · When a repo's test harness cannot measure the thing the owner is complaining about, build the measurement — and let `-SelfTest` find your own bugs first**

Context: the E4610/E4810 picture-MMS complaint is a *latency* complaint ("hours", "three days"). The
existing in-repo harness (`scripts/utilities/{New,Invoke,Export}-MmsForensicRun.ps1`) records no send time
at all and has no verdict, so it structurally cannot produce the number. Rather than declare the test
ready anyway, three small scripts were written, each with `-SelfTest` in the style of the repo's own
`ready-e4610.ps1 -SelfTest`:

- `_scratch/mms-ab/Get-MmsPhoneState.ps1` — the arm fingerprint (which app owns `sms_default_application`,
 installed vs disabled for each messaging package, `mobile_data`, APN readability, clock skew, one-word verdict)
- `_scratch/mms-ab/Send-MmsTestPicture.ps1` — Twilio picture out + reply polled back; dry-run unless `-ConfirmSend`
- `_scratch/mms-ab/Measure-MmsLatency.ps1` — T0 from the handset's MMS store / radio log / operator keypress
 (and it records *which* source), T1 from Twilio, latency, verdict, poll-interval uncertainty

**The self-tests paid for themselves immediately — they found two bugs that reading the code had not:**
1. `$things.Count` on a single pipeline result is a **bare string**, and under
 `Set-StrictMode -Version Latest` a scalar has no `.Count` → hard error. Wrap in `@(...)`. This is the same
 class of trap that makes `Export-MmsForensicReport.ps1:76` throw on its first real match.
2. **Synthetic test data carried inconsistent epochs**: a base of `1760000000000` ms is *2025-10-09*, while the
 fixture message was dated Oct 2026 — so "an inbound before the send is excluded" failed for a reason that had
 nothing to do with the code. When a self-test fails, check the fixture's units before "fixing" the logic.
 (2026-10-15T01:00:00Z = `1792026000000` ms.)

**Transferable rules:**
- A harness that cannot produce the contested number is not a test; say so, then build the missing measurement
 as *new* files rather than editing a harness another session may be mid-way through.
- Put `-SelfTest` on anything that will run against hardware you only get one shot at, and make it run
 **without** the hardware.
- Record *which* method produced every timestamp (`outbox` / `logcat` / `manual`) and tag unconfirmed log
 markers. "A timestamp exists" and "a trustworthy timestamp exists" are different sentences.
- `never-arrived` and `no-send-observed` are real results; never let either collapse into a zero.
- When another session's working tree is dirty, stage new tools **outside** the repo and put the *procedure*
 in the repo's docs, rather than adding untracked files that a concurrent `git add -A` could sweep into their
 commit (P13).
