**L3516 · The systems register says the cloud has no tailnet and the broker is on the authority - both false, and one would send the owner to issue a key he does not need**

Two claims in `docs/mesh/000-SYSTEMS-REGISTER.md` that are measurably false as of 2026-10-11 ~20:52Z. The
file was staged/modified and being edited by another agent when this was checked, so these are recorded
here to be applied by whoever owns it rather than edited concurrently.

**1. "No tailnet yet ... the join is blocked on a dead auth key - owner question 445" (the
`secratary-cloud` row). THIS IS STALE. `secratary-cloud` IS ON THE TAILNET.**

Proved from the office box's own `tailscale status`, 2026-10-11 ~20:35Z:

 100.73.176.126 secratary-cloud lakewoodphoneandtech@ linux active; direct 178.156.194.1:41641, tx 1549472 rx 6941232

And a private path now exists and works. On the authority:
`tailscale serve --bg --https=8443 http://127.0.0.1:8002`, giving
`https://secratary-cloud.tail93e6e6.ts.net:8443/health` -> **HTTP 200, `ok=True`, `db_ok=True`**,
verified from ZABZ-TECH. `scripts/mesh/route.sh` now CHOOSES that path first (tail, 0.0687s) and falls
back to `https://api.abletelsolutions.com` (flare, 0.0700s).

**Consequence of leaving this wrong: someone issues a Tailscale auth key nobody needs**, and the
register keeps telling every reader that the estate's private path does not exist when it does.

**2. The "placement broker" row says "`mesh-broker.service` on the authority, loopback `:3091`". It
runs on the OFFICE box.** Measured the same hour: office `secratary` has `127.0.0.1:3091` listening
(`node`, pid 105841); the cloud box's `mesh-broker.service` is `inactive`/`disabled` and **nothing
listens on :3091 there**. The register's own exception note earlier in the file (the block beginning
"One exception is now running there deliberately and is NOT a writer") says the true thing - the row
and the note contradict each other, and the row is the one a reader looking up "placement broker"
will find.

Note this is a live dependency worth naming plainly: **the mesh broker - the thing that makes
`subagent` fan-out work - runs on the box the migration has frozen and told everyone is read-only.**
That is why fan-out still functioned today, and it is also why the freeze is not total.
