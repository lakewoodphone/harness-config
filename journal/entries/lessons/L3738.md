**L3738 · A node whose /mesh/health route is missing is not a dead machine — ask for capacity before discarding it**

MEASURED 2026-10-12. `lib/node-probes.js` read only `GET /mesh/health` and turned anything but 200
into `error`, which `chooseFailoverPlacement` records as unreachable and NEVER scores. Two live,
dispatchable nodes of this mesh answer that route 404 (`zabz-tech-linux`, its gate proxies only
`/mesh/capacity`) and 502 (`secratary`) while answering `/mesh/capacity` 200.

CONSEQUENCE BEFORE THE FIX: the broker-unreachable fallback — the path that exists precisely because
the broker has failed before — could see two of four working machines, and printed the other two as
`unreachable: HTTP 404`. A fallback that sees half the mesh is worse than none, because it looks like
a decision.

THE FIX (lib/node-probes.js + failover-placement.js): when the health read ANSWERED (an HTTP status,
not a timeout), also read capacity; if capacity answers, the node is usable over v1 with slots
UNMEASURED. It scores 0 and ranks below every measured node, and `position` stays 0 because unknown is
NOT short — a node whose slots nobody measured must not make a child wait two minutes. Deliberately NOT
done: deriving slots from the capacity document on the dispatcher. Slot arithmetic lives in
`packages/mesh-broker/lib/scoring.js`; a second implementation is the defect class this programme
exists to kill.

PROOF: `bin/failover-place.mjs` -> `reached: 5, unreachable: (none)`, with both nodes listed as
candidates and the rationale saying why. Test suite 220 pass / 0 fail.
