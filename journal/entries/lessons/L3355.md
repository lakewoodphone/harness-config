**L3355 · Same-shaped code is not the same defect - verify the sibling before recording it as one**

I recorded in H3257 that app/services/autonomy.py:212 carried the IDENTICAL unfixed bug to the one I had just fixed in outbound_buffer.py, on the strength of the grep hitting the same variable name (_table_created) and the same global-flag shape (_table_created = False -> if _table_created: return -> _table_created = True). Reading the function corrected it: autonomy.py:285-294, when its flag is set, RE-CHECKS sqlite_master for autonomy_levels on the current connection and only returns if the table is really there, so a second database still gets its table. It was already safe. The difference is exactly the line that matters - the one that trusts a process-wide flag without asking the database. EVIDENCE: tests/test_table_init_cache.py, written to pin both modules - test_autonomy_creates_its_table_on_a_fresh_database_even_when_the_flag_is_set sets the flag and asserts the table is still created (3 tests, all passing). LESSON: a grep match on the same identifier and the same shape is a LEAD, never a finding. Two functions can look identical and differ entirely in the one line that matters; the way to tell is to read the function and to write the test that would fail if your claim were true. I wrote the claim into a handoff and an annex before doing either, which is how a wrong fact gets a life of its own - and the system's most expensive historical failures were exactly this. Corrected in annex K (edited) and here (appended, citing H3257). The sibling-check rule from here on: before writing 'the same defect exists elsewhere', state the specific line that makes it a defect and run something that proves it.
