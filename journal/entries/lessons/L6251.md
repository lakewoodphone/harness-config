**Correction · 2026-10-15 · ZABZ-TECH · Owner correction: we stopped putting Message+ on E4810s a while ago — he is right, and my report overstated it**

The owner said: *"we stopped putting message plus on the e4810s a while ago i thought."* **He is correct.**

**What I had wrong.** I wrote that "from 2026-08-31 our automated deployer sets Message+ as the default SMS
app on E4810 and disables the stock app", which reads as a live, ongoing state. It is not. It was true for a
**seven-day window** and then stopped in practice.

**Measured across all 261 deployment receipts in `cli/logs/deployments/` and `logs/deployments/`:**

| question | answer |
|---|---|
| receipts that *name* Message+ | 72 |
| receipts that actually **set it as default** | **20** |
| distinct serials ever set as default | **11** (558800023393, 558800024668, 558800112625, 558800182088, 558800238329, 558800294066, 558800298976, 558800335489, 558800639218, 558800773049, VMY62B30791A000) |
| of those, also had the stock app disabled | **4** |
| date range of any Message+ action | 2026-04-10 → **2026-09-07** |
| **last date any receipt touches Message+ at all** | **2026-09-07** |
| E4810 receipts after that | 2026-09-15 ×2, 2026-10-11 ×2 — all **`filter-only`**, which neither lists `message-plus` nor writes `sms_default_application` |

So the stop was real and it was **~5 weeks before this session**: the shop changed which tier it ran for
E4810s, and `filter-only` never touches messaging. The 20-receipt / 11-serial figure is an **upper bound on
units the deploy ever touched**, not a count of affected phones, and the receipts cannot say which reached
customers.

**What did NOT stop — and this is the part worth keeping.** The *code* is still armed:
`cli/configs/tiers/standard.yaml:13` has carried `message-plus` continuously since **2026-04-25** (verified by
`git log -S`), it is still there at HEAD, and the E4810 customer wrapper still requests that tier
(`stage-e4810-standard.ps1:35`, `finalize-e4810-standard.ps1:49`). `engine.py:633-635` still disables the
fallback. So the state returns the moment anyone runs the *named E4810 Standard flow* instead of
`filter-only`. **"We stopped" and "it cannot happen again" are different sentences**, and only the first is
true.

**Consequence for the diagnosis, which the correction improves:** the October complaint cluster (6 new
complainants in the week of 2026-10-05) lands **more than four weeks after** our last Message+ action, and
the complaints are mostly E4610s — which `standard-lite` never touches. The mechanism exists, but it was not
firing during the weeks the complaints arrive in. That weakens the attribution to us further, and it shrinks
the population of anything we might owe a remedy to.

**Transferable:** when a code path exists and a receipt shows it fired, that proves *it can happen* — not that
it *is* happening. Distinguish the armed mechanism from the operating practice, and date both. My own
"live from 2026-08-31" phrasing collapsed that distinction, and the owner caught it from memory in one line.
