## L1744 — with only the option list scrolling, the question is the one thing that cannot be recovered

**The fourth report from the same surface (2026-09-16).** After the sheet was pinned to the visible
band and the fix was committed and proved working against the running app, the owner still wrote:
"I can still only see the options, but I cannot read the question, you did not fix it."

**The structural mistake, not a measurement error.** The shipped card puts the header
(`flex-shrink: 0`) ABOVE the scrollport (`[class*="_body"]`, `overflow-y: auto`). So the question is
outside the only region that can move. If the sheet's top lands above the first visible pixel — which
is exactly what a visual-viewport offset does on iOS, with the keyboard up — the reader sees the
options and the question is unreachable, because there is nothing left to scroll. Every fix that
only moves the sheet can be defeated by the next offset. Making the thing you must READ unreachable
by construction was the bug; the offset was only the trigger.

**The fix.** The card is the single scrollport, the body no longer scrolls in a box of its own, and
the footer is `position: sticky; bottom: 0` so Submit stays on screen while the card scrolls. Now
every part of the card is reachable by the gesture a thumb already knows, whatever the viewport
does and whether or not any script measured the offset correctly.

**Two more lessons from the same report.**
- **An event-driven repair is not a repair.** `visualViewport` resize/scroll is not a reliable
 proxy for the visible band on iOS: the keyboard animates, the band settles after the last event,
 and the repair can be left holding stale geometry. The card is now re-measured every 250 ms while
 it is mounted — two `getBoundingClientRect` reads, only while a card exists.
- **A silent bail-out is a silent failure.** `visibleBand()` returned `null` when `visualViewport.scale > 1.01`,
 which disabled the entire repair on a pinch-zoomed page. `offsetTop` and `height` are already CSS
 pixels and already account for zoom; the guard protected nothing and switched the fix off.

**Verified.** 35 plugin smoke checks (3 new, including "a band that moves with NO event is corrected
at the next tick"); `question-card-live-probe.py` against the running app at 393x852 and 393x640
with band 240-660: question title y=279 and Submit y=608, both inside the band, `repaired: true`;
`check-phone-ui.sh` passes. Committed 8d3b16d.
