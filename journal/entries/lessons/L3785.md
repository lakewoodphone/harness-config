**L3785 · Before writing a conventional filename in a shared repo, read the authority copy - a stale clone nearly overwrote the procurement standing rules**

**The rule:** before creating or overwriting a *conventional* filename (`README.md`, `INDEX.md`,
`AGENTS.md`) in a shared repo, read the **authority's** current copy — not this clone's, which may be
27 commits behind. If one already exists, never clobber it; extend it or choose a different name.

**Measured 2026-10-13, `lpt-hub/docs/procurement/`.** This clone's `main` was 27 commits behind
`secratary-ts`. A session here wrote a folder index and called it `README.md`. Minutes earlier, another
session on the authority had committed `e201971a3` making that same path the **standing procurement
rules** file (written after the April handoff-media directive bought PNY drives on price per unit with
no write-speed requirement, 427 bench hours per 100 handoffs at 10 MB/s). Two different files, one path.

The first `scp` failed with "Connection closed", which is the only reason nothing was overwritten — the
collision was found by luck, not by design.

**The fix that was applied:** adopt the authority's `README.md` byte-for-byte (verified by sha256 on
both sides), and put the dated-record index in `INDEX.md` instead. Identical blobs merge cleanly; a
difference is an add/add conflict for whoever merges next.

**Do it this way next time:** `ssh <authority> "cat <path>"` before writing a conventional name; and
compare hashes after any copy, because a silent mismatch here means two machines holding two meanings
for one path.
