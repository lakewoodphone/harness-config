**L11646 · A staged, GO-preflighted upgrade still went down three times, each time on a fix that already existed somewhere else in the estate**

ON ZABZ-YOGA 2026-10-20, updating 0.2.0-rc.2 -> 0.2.1-rc.2 with the script that was "dry run proven" the night before, three of the four failures were already fixed elsewhere in this estate and none of them was fixed in the place the switch actually looks.

1. THE PATCH AUDIT IS SEPARATOR-BLIND ON WINDOWS. `audit()` in `dsh-update/lib/patches.mjs` tested a registry `covers` glob (written with `/`) against `path.relative()` (which returns `\` on Windows). Every registered patch therefore read as unregistered, and `install-engine` refused with "the install would silently lose 4 hand patch(es)" naming `StateDot.module.css`, `client.js`, `session-persistence-jsonl/lib/index.js`, `index-BPHePDI_.css` — three of which have `covers` entries in that same registry. The refusal reads like four real losses; it is a one-line path bug. Fixed by normalising the relative path to `/` before the substring test; the four then report "registered" (measured: audit rows before/after on the same trees).

2. THE SWITCH NEVER RAN `config-assumptions.mjs`. L10238 (2026-10-19) had already established the class "our config restates an upstream surface" and built the control for it. The switch ran settings regeneration, install, start, compose — everything except the one check that compares OUR config against the CANDIDATE's surface. So the install succeeded, the engine booted, and every turn died with `unknown prompt variable "{{cwd}}" in section deployment:persona-suffix; registered variables: provider, model` — the exact failure L10238 records from ZABZ-TECH, reproduced a day later on the second machine, because the control was a tool nobody had wired in. It is now STEP 2.5, before anything is written, and a finding restores the config and starts the old engine.

3. THE ABORT PATH WAS WORSE THAN THE FAILURE. `install-engine` refused (exit 2) AFTER the script had rewritten the live profile patch into the 0.2.1 shape (`ctx.webStartup`). The script's failure path then restarted the OLD 0.2.0 engine against that patch, which cannot boot ("cannot get property webStartup without inject") — and the machine crash-looped. The `.bak-switch-<stamp>` copy was made ten lines earlier and never used. A failure path that restarts into a config you just invalidated is a self-inflicted outage; restore first, then restart.

4. A REGENERATION SOURCE CAN UNDO A LIVE FIX. The `{{cwd}}` fix existed on ZABZ-TECH's live patch but `scripts/make_zabz_preset.py` still emitted the old suffix, so the switch's preset-row regeneration wrote the breakage back. Whenever a live config is fixed by hand, grep for the generator that produced it the same hour.

ALSO MEASURED, same window: `profiles/web/node_modules/research-offload` was a junction that `fsutil` printed correctly but `fs.realpathSync` could not stat (UNKNOWN, errno -4094), so every engine boot died before listening — no engine had been up since the 22:50 reboot, which is why "it will come online in a few minutes" never happened. `cmd /c rmdir` + `mklink /J` fixed it, target untouched (fingerprint identical before/after). And `dshw ensure` checks the origins proxy before it starts the engine while the proxy's health probe depends on the engine, so a machine with the engine down refuses to start: start the engine directly, then reconcile.
