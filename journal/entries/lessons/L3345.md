**L3345 · mdm_fleet_devices lives in two un-synced secretary.db files - write both**

WHAT: The MDM fleet registry table `mdm_fleet_devices` exists in TWO separate files that are
written only by whoever holds them — `C:\Users\ezabz\Code\personal-secretary-mvp\data\secretary.db`
on ZABZ-TECH (1.79 GB, last written 2026-09-24) and
`secratary:/home/zabz/personal-secretary-mvp/data/secretary.db` (17.96 GB). They are not synced:
the ps_* MCP tools and the desktop API read the desktop file, `sqlite3` over SSH reads the
authority's file.

WHY IT MATTERS: On 2026-10-05 both files still agreed on the four MDM devices (identical June
values), so a write to one alone would have silently produced two different answers to "what is
this device?" — the exact shape of the P3 "reading the wrong data and believing it" failure.

HOW TO APPLY: write both. `deploy/waze-mdm/scripts/register-owner-device.py --db data/secretary.db`
on the desktop, then the same command on secratary (its `.venv/bin/python`), and read the row back
from both before claiming the change is done.

DONE WHEN: `SELECT serial_number, device_class, desired_profile, profile_state FROM mdm_fleet_devices`
returns the same rows on both hosts.

EVIDENCE: this session's SE registration — verified identical rows on both hosts after writing;
file sizes/last-write times above from `Get-Item` (desktop) and `ls -la` (secratary), 2026-10-05.

REF: `app/services/mdm_fleet_registry.py` (`ensure_mdm_fleet_schema` takes a db_url), RUNBOOK
section "Owner devices (personal phones)".
