**L1907 · Junction-mounted packages resolve relative imports against the checkout, and bare node --test in plugin-mesh-http runs the measurement rigs**

Two resolution/collection facts about `packages/plugin-mesh-http`, both measured 2026-09-17, both
costing an hour if you get them wrong.

1. A CROSS-PACKAGE RELATIVE ESM IMPORT SURVIVES THE `~/.dsh` PROFILE JUNCTION. The package is
 mounted at `~/.dsh/profiles/web/node_modules/dsh-plugin-mesh-http` as a junction into the
 checkout, and Node resolves a module's REAL path by default (there is no `--preserve-symlinks` in
 play), so relative imports resolve against the checkout rather than against the junction.
 MEASURED on ZABZ-YOGA with a junction whose two package dirs sat in a temp tree
 (`_scratch/104-junction-test/`): `node <junction>/bin/probe.mjs` printed `import.meta.url` as the
 REAL path and resolved `../../sibling/lib/x.js`. Precedent inside the same package:
 `test/dead-target-fallback.mjs` has imported `../../plugin-remote-fanout/lib/provider.js` since
 2026-09-17. `--preserve-symlinks` would break this — do not add it.

2. BARE `node --test` IN THAT PACKAGE RUNS THE MEASUREMENT RIGS. It collects EVERY `.mjs` under
 `test/`, not only `*.test.mjs`. Measured with same-named probe files in a scratch directory:
 `✔ test\concurrency-sweep.mjs ✔ test\dead-target-fallback.mjs ✔ test\mesh-http.test.mjs
 ✔ test\run-level.mjs — tests 4`. Two of those fire real fleets at real nodes. So the suite command
 is the package's own scoped one — `npm test` (`node --test test/mesh-http.test.mjs`, 40 tests) —
 and the build/verification equivalent is `npm run verify` (node --check on every source + that
 suite). The package has NO build script and generates no artefact: the only `scripts/build.mjs` in
 this repo belongs to `plugin-cost`.
