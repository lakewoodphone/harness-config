**L3768 · CORRECTS L3767: a whole-file comparison and a change-comparison answer different questions**

**L3767 was filed with a placeholder body by mistake** — I passed the wrong `--body-file` and only
noticed because the round's lesson deserved real content. It stays as written; this carries the
substance.

**THE RULE.** When judging what a branch changes, two commands answer two different questions and I
conflated them:

- `git show <branch>:<file>` (or a plain `git diff origin/test -- <file>`) compares **the two FILES**.
 It shows everything that differs, including commits that landed on `origin/test` *after* the branch
 was cut. That difference belongs to test, not to the branch.
- `git diff --numstat <merge-base>...<branch> -- <file>` compares **the CHANGE the branch makes**. This
 is the one that answers "what would merging this do".

**MEASURED 2026-10-13 on PR 367's `AGENTS.md`.** The whole-file comparison said 48 insertions /
48 DEletions and I concluded the docs change was a rewrite that would delete `pnpm worktree:setup`. The
three-dot numstat said **`49 0`** — a pure addition. Both numbers were correct; they answered different
questions. The branch's file *did* lack `worktree:setup`, because it was cut before test gained it.

**WHY IT MATTERED:** on the whole-file reading I nearly shipped a re-cut that removed real
documentation, and I told myself the docs half was "a regression too" when it was not. The insertion I
finally shipped is still the right shape — but I got there by luck of examining further, not by asking
the right question first.

**THE DISCIPLINE:** before characterising a branch, ask *"the branch's change, or the files'
difference?"* and pick the command that matches. For a merge decision it is always the change.
