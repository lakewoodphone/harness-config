**L3849 · LPT Tech Mode unlock code: two screen values (device key + install ID), no ADB needed**

LPT Tech Mode unlock code: two screen values, no ADB needed.

Owner asks for "the tech mode unlock code for device key X and install ID Y".

## Method (lives in lpt-flip-phone)

1. On the handset, open LP&T Tech Mode. Read **Device Key** (15 digits) and **Install ID**
 (integer unix seconds; it may be shown dashed, e.g. `177-662-5245` -> `1776625245`).
2. Compute:

```
C:\Users\ezabz\Code\lpt-flip-phone\.venv\Scripts\python.exe -m lpt.cli get-tech-code `
 --imei <15-digit device key> --timestamp <install id digits>
```

`--serial <adb serial>` reads both values off a connected phone instead (needs ADB, i.e. the
window is already open or the phone is unfiltered). The PowerShell wrapper
`scripts/deployment/get-tech-code.ps1 -DeviceSerial <serial>` is the same CLI call.

## Algorithm, and why the answer is trustworthy

`agent/lpt-techmode/.../TechModeManager.java:140` `generateUnlockCode`:
`high = n / 1e7`, `low = n % 1e7`, `mixed = (high*7919) ^ (low*6997)`,
`withTime = mixed ^ (ts*7)`, `salted = withTime ^ 0x4C5054`,
`scrambled = ((salted*31337) >> 8) ^ (salted & 0xFFFFFF)`, `code = |scrambled| % 1e6`.
Reimplemented independently at `cli/lpt/cli.py:1187` `_calculate_tech_code`; the two agree on the
repo's own cross-validated vectors (e.g. `123456789012345`/`1716150400` = `862773`,
`cli/tests/test_cli_commands.py:3317`).

2026-10-18, owner's job: device key `015588002924600`, install ID `1776625245` -> code **851643**
(confirmed by both implementations and by the shipped CLI itself).

## The caveat that must travel with every code

The Install ID is the install-time wall clock, and the code is bound to it. On a phone with no RTC
(no SIM, no network time) the Install ID is a small number that self-heals on *every* app start,
so a code recorded earlier goes stale. Read both values off the screen and type the code in the
same screen session. Full rule: `docs/deployment/PREFILTERED-DEVICE-AND-E4610-MANUAL-STEPS-RUNBOOK.md`
section 5. A value above the app's 2024 floor (`1704067200`) is a real timestamp and does not move.
