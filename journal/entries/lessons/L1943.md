# L1943 — `git add <path>` commits OTHER PEOPLE'S uncommitted work, and I did not notice

## What I did

Fixing the delegate-model resolution, I applied two literal replacements to `app/services/ai_gateway.py` and
`app/config.py`, verified them, and committed with `git add app/services/ai_gateway.py app/config.py`.

**Both files already had substantial uncommitted changes in the working tree, and `git add <path>` staged
all of them.** The diffstat said 269 insertions where my edit was ~60 lines, and reading it back showed
functional additions I never wrote: `security_api_key`, `ha_ptt_key`, `security_alert_extra_recipients`,
`CONTENT_SANDBOX_ATTR`/`CONTENT_SANDBOX_DEFAULT`, `reconciliation_auto_merge`, and a
`_GOOGLE_MODEL_RENAME` map feeding `billing_model_id`.

So commit `3107ff3b` is **my fix plus someone's in-flight work**, under my commit message. Nothing is lost —
it is all recorded — but my change is no longer separable from theirs, and a reader now cannot tell which
part of that commit was mine or why.

## The rule

1. **`git status` BEFORE staging, not after.** If the file I am about to edit is already modified, that is
 the finding, and it decides the method: patch just my hunk, commit to a separate branch, or stop and
 report that the tree is dirty.
2. **`git add -p` (or an explicit `git diff` review of the staged set) for any file that was already
 dirty.** `git add <path>` is only safe on a file whose working-tree state you just created.
3. **A diffstat far larger than the edit is a signal, not a rounding error.** 269 lines for a ~60-line
 change should have stopped me at commit time; I read the number, noted it, and committed anyway. That is
 the same "the count is the bug report" mistake recorded as L1936.
4. **Check what the working tree holds before a shared-repo edit.** This checkout receives other sessions'
 work. Editing without looking is how two changes end up in one message.

## Why this is the same failure as the deploy gap

Both come from acting on **intent** rather than on **observed state**: I knew what *I* had written and never
asked what the *tree* already contained. Verify the state you are actually operating on — the host's file
contents for a deploy, the working tree's existing modifications for a commit.

## Evidence

- `git show --stat 3107ff3b` → `app/config.py | 133 +++`, `app/services/ai_gateway.py | 167 +++`, where my
 own edit was ~60 lines.
- Functional additions in that commit that I did not write: `security_api_key`, `ha_ptt_key`,
 `security_alert_extra_recipients`, `CONTENT_SANDBOX_ATTR`, `CONTENT_SANDBOX_DEFAULT`,
 `reconciliation_auto_merge`, `_GOOGLE_MODEL_RENAME`, `billing_model_id`.
- Not reverted: `git reset` would un-commit the other change too, and the app compiled, imported and served
 `/health` 200 afterwards, so the combined state is verified-working.
