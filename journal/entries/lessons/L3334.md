**L3334 · Reading Gmail and creating reminders from a shell: gmail_service on secratary, POST /api/v1/reminders**

**L· Any mailbox: read it from the server with gmail_service, and create reminders through the local API.**

Two things that cost time to rediscover:

1. **Gmail, read-only, from anywhere in the fleet.** On `secratary`, from
 `/home/zabz/personal-secretary-mvp` with its `.venv`:
 `from app.config import settings` then
 `app.services.gmail_service.search_messages_across_accounts(settings, query=..., max_results=N,
 per_account_limit=100)` → `{"accounts": [...], "messages": [...]}`, and
 `read_message(settings, message_id=..., account=...)` for the body (`body` key). Four accounts are
 authenticated (`eliyahuzabrowsky@`, `ezabz68@`, `lakewoodphoneandtech@`, `zabzgpt@`); each
 account is paged separately at 100 per call, so a big query needs page tokens to be complete.
 `GMAIL_DEFAULT_ACCOUNT=primary` resolves to the owner's **personal** mailbox — always pass
 `account=`. Use this instead of an MCP tool: the `ps_*` MCP surface has **no Gmail read action**
 (`list_actions` returns 14, none of them mail).
2. **A shell can create a reminder the API owns.** `POST http://localhost:8002/api/v1/reminders`
 on the server with `{message, remind_at, delivery_channel, requires_ack, source, source_ref}`
 returns `{"ok":true,"id":...}`; `remind_at` takes a natural-language string or ISO. That is how
 reminder 567 was made from a shell with no MCP tool for it. `delivery_channel: "both"` is the
 dashboard + owner-text path.

Copying a script to the server: `Get-Content x.py -Raw | ssh secratary-ts 'cat > /tmp/x.py'` — put
the remote command in **single** quotes in PowerShell, and verify with `wc -l` before running.
A `nohup … &` over a non-interactive ssh exits silently with a 0-byte file (measured 2026-10-05,
lost one run); run it in the foreground with a long timeout instead.
