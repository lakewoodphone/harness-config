**L10306 · A green required check is a claim about the check, never about the code - and the LPT site sat 74 commits unpromoted behind exactly that**

**L — A required check that passes on an absence of evidence is worse than no check.**

Measured 2026-10-19 on `phone-and-tech-full`. `pr-precheck.yml` had two independent mechanisms that
both produced a green required check without a test result:

1. `:967` gated test enforcement on `is_copilot == "true"`. Every PR in the repo is human-authored,
 so the frontend/backend suites ran and their verdict was discarded — and the `else` branch
 printed *"the test suites do NOT run anywhere in CI for a human PR"*, which was false.
2. The frontend shard's kill branch did `exit 0` after a timeout, so a shard killed by the 540 s
 inner timeout still passed. A comment there said this was *"deliberately still non-blocking
 until the real runtime is measured"* — i.e. the author knew, and the condition for flipping it
 was never met because nobody measured.

Consequence, measured: the production promotion PR #485 sat `BLOCKED` for three days on four
shards that could not finish, and `origin/main` fell **74 commits / 3 days** behind `origin/test`.
The shop's public site served `[]` dollar amounts on `/screen-repair` while test served
`["$154","$173"]` and a "Screen Repair Prices" table, and `/find-a-computer` answered the 404
page on production.

Root cause of the hang, measured on the same file and commit: `pool: 'forks'` cannot start a worker
in this repo (`Failed to start forks worker … Timeout waiting for worker to respond`, 60.25 s,
`Test Files no tests`, **0 tests run**); `pool: 'threads'` runs it (**53 passed**, exit 0).
Also: `poolOptions` was removed in Vitest 4, so `poolOptions.forks.maxForks` had been silently
ignored — the runtime prints the deprecation on every run and nobody had read it.

**The transferable part:** a CI comment that says "this is a known lie until X is measured" is a
measurement task, not a note. And "the check is green" is a claim about the check, never about the
code.

**L — Two numbers with one label, again, in the wake loop.**

`autonomy-status.sh` prints `liveness: dispatcher heartbeat 297.7 min`. That is *time since the last
release*, not liveness: `~/.sms-inbox/wake-heartbeat` is written only when a release happens, so a
correctly-gated dispatcher and a dead dispatcher print the same number. The same command printed
`PROBLEMS: none` through 2026-10-17, a day on which every release failed with `outcome: prompt
transfer to zabz-tech-ts failed … no session was started` and the website got **zero** shifts
(28 releases against a normal 150).

Fixed this session, in the place a session actually reads: `autonomy-status.sh` now counts trailing
consecutive `failed` releases in the dispatch log and raises a PROBLEM at 3. Tested three ways —
planted 3 failures → reported; 2 failures with a success between them → `none`; unreadable log →
says so rather than staying silent. That last one matters: the failure mode of a silent monitor is
a monitor that looks healthy.

**L — A stale fallback is an unwritten policy.**

`wake-budget.json` carried `count_max: 150` while the same file's `why` explained the money ceiling
was 47.64 USD. `wake-budget-env.sh` says in its own words that 150 is `FALLBACK_MAX_PER_DAY`, *"the
pre-2026-10-14 count"*. Measured spend that day: 150 releases cost **4.178258 USD of 47.64 = 8.8 %**.
So the binding constraint was a leftover default, not the owner's stated limit ("there's no reason to
limit how much you could do per day"). The registry said 500; the enforcement said 150; both printed
as fact.

**L — Check where the work will actually land before you fan out.**

The mesh was unreachable this session with a precise provider diagnostic
(`MISSING_CREDENTIAL: llm-deepseek: no API key for provider route "deepseek-official"` on
`ZABZ-TECH`), and the broker reported local commit at 100.5 % of physical. Five audit children ran
**locally** for that reason and are marked LOCAL in the report. A fallback nobody can see is a lie
about where the work ran.

**L — Read the component you are about to mount, not just its name.**

Filling the empty "What We Work On" section, the repo already had a `ServicesSection` component
with 37 passing tests, exported from the barrel, imported by **no page**. Mounting it would have
published invented prices: its `services.data.ts` carries `'Starting at $79'`, `'$49 - $89'`,
`'$59 - $149'` and invented turnaround times, while its own header claims *"PRICES ARE NOT TYPED
HERE"*. Dead code is not inert — it is a loaded gun pointed at the next agent who wants a section
filled. The empty section was safer than the one that existed.
