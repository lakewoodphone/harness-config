**L1536 · Handy caches settings in memory and rewrites the file: always restart it after editing**

Handy (the dictation app) keeps its settings in MEMORY and rewrites settings_store.json from that memory
whenever anything changes in its UI. Editing the file while Handy is running is therefore a race you lose.

What it actually did on 2026-09-15 (LAKEWOOECHSMINI): paste_method was set to "none" for a closed-loop
audio test, then restored to "ctrl_v" by editing the file. Handy was NOT restarted. Minutes later a human
changed a setting in Handy's own window; Handy serialised its stale in-memory copy over the file and
paste_method went back to "none". The visible symptom was the worst kind: dictation transcribed perfectly
(showing up in history.db as "Does this work?" and "Hello, what's up?") and pasted NOTHING into the text
box, so the app looked broken while every stage before it worked.

RULE: after writing Handy's settings file, ALWAYS restart the app --
`launchctl kickstart -k gui/<uid>/com.zabz.handy.autostart` -- and never edit the file while someone is
using the UI. Then read the log's "Loaded settings: AppSettings { ... }" line: it prints the whole object
Handy actually loaded, which is the only trustworthy statement of what the app is running with.

EVIDENCE: 2026-09-15 18:40:39 UTC log line "Using paste method: None ... skipping paste action" after the
file had been restored to ctrl_v; `settings_store.json` mtime 14:40 local; the backup file
settings_store.json.bak-20260915-143551 shows the pre-edit state.
