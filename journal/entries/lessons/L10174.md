**L10174 · A configured key is not an enabled provider: three silent gates before a provider is routable**

## Measured on production 2026-10-19. Three gates, all silent.

A provider with a perfectly good API key can be completely invisible to the router, and nothing logs a
word. `app/config.py::provider_api_keys()` builds its map through a local `add()` helper that returns
without logging at every one of these:

1. **The key must reach the settings field.** If `PROVIDER_API_KEY=` is absent, empty, or commented out
 of `/opt/company/.env`, the field is `None` and `add()` returns.
2. **The provider must not be disabled.** `LLM_DISABLED_PROVIDERS_JSON` in `.env` **line 454** read
 `["openrouter", "copilot", "deepinfra", "fireworks"]` — so even with a live key, deepinfra and
 fireworks are skipped. This is the gate that is easiest to miss, because it is a *different variable*
 from the key and it is not obvious that disabling is a thing.
3. **A candidate lane must exist** in `smart_router._CAPABILITY_DB`, or the provider can never be chosen.

## What made me look

I was about to add a DeepInfra candidate lane. The obvious question was "would that route live traffic to
a revoked key tonight", and the answer turned out to be more interesting: **deepinfra was never an
available provider at all.**

```
providers with a configured key: ['cohere', 'deepseek', 'exa', 'google', 'groq', 'minimax',
 'openai', 'perplexity', 'together', 'xai']
allowed after health filter : (the same ten)
excluded by circuit : {}
```

No deepinfra. No fireworks. **And no circuit open** — because neither had ever been *attempted*. A
circuit breaker can only tell you about providers you actually call; it says nothing about a provider
that was filtered before any call. That is why "the circuit is closed" was not evidence of health here,
and why I stopped relying on it as the safety argument for adding the lane.

## Two smaller traps in the same half hour

- **`.env` no longer contains `DEEPINFRA` or `FIREWORKS` lines at all.** My earlier reading of a
 32-character value was from *before* the owner removed the keys, and I would have quoted it as current
 if I had not re-measured. A reading has a time; a number without one is a memory.
- **Production's `config.py` is 1,866 lines against 1,658 in the checkout** — the fourth file now found
 to be on a different lineage. Hashing before editing is not a one-off precaution on this estate, it is
 the default.

## Rule

To route to a provider you need **all four**: key in the environment, provider removed from
`LLM_DISABLED_PROVIDERS_JSON`, a lane in `_CAPABILITY_DB`, and priced data in `prices.json` (plus an
`equivalents` entry if it is a same-weights pipe). Verify by *printing the resolved provider list*, never
by checking that the key file contains a name. `tests/test_provider_enablement.py` now pins gates 1 and 2.
