**L1543 · A guard census must parse declaration forms across every router - the guard chain's own file can look perfect while 43 other files pick the unguarded builder**

Evidence, 2026-09-15, PART-120. The tRPC guard chain in backend/src/trpc/context.ts is well built: protectedProcedure rejects CUSTOMER, customerProcedure requires a linked customer, adminProcedure and managerProcedure narrow by role, and createContext adds a path allowlist for customer tokens. Reading that file tells you the system is correctly guarded. It is not - 43 procedures across 8 routers were declared with the bare procedure builder, which is the base builder with only logging middleware and NO authentication, and two of those routers were reachable from the public internet.

THE RULE: the guard a procedure has is a property of the procedure's DECLARATION, and the declarations are spread over ~200 router files. So the audit unit is the census, not the framework. Parse every file:

 for f in backend/src/trpc/routers/*.ts; do
 awk -v r=\ '/^[[:space:]]{2,4}[a-zA-Z][a-zA-Z0-9_]*:[[:space:]]*(procedure|protectedProcedure|customerProcedure|adminProcedure|managerProcedure|publicProcedure)[^A-Za-z]/ { ... }' \
 done

then group by guard and read the bare ones. On this codebase that returned 942 declarations: protectedProcedure 570, managerProcedure 157, publicProcedure 77, adminProcedure 57, bare procedure 43, customerProcedure 23 - and the 43 were the whole finding.

TWO MECHANICAL TRAPS I hit, both worth pre-empting:
1. **Do not run the census as a one-liner whose output streams to the terminal.** My first attempt emitted hundreds of PowerShell errors, and the useful numbers were buried in a wall of noise where they could easily have been missed or misread. Write results to a FILE (a .tsv), then summarise from the file. And use an anchored pattern - the first version matched unrelated lines like object literals and z.
2. **publicProcedure is byte-for-byte procedure on this codebase** (context.ts:616-620, xport const publicProcedure = procedure). So publicProcedure and a bare procedure are the same behaviour with two names, and a census must not treat the alias as evidence of a deliberate decision. Counting them separately is right; assuming the publicProcedure ones were reviewed is not.

Same family as P3 (reading the wrong data and believing it): reading the framework gave a confident, wrong answer. The declaration census gave the right one.
