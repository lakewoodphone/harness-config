**L1806 · 401, 403, 404 and 502 on the same URL mean four different things**

Measured on ZABZ-YOGA/ZABZ-TECH 2026-09-16, and the reason scripts/mesh-health.ps1 exists:
 401 = the fence PASSED, no cookie. This is the correct answer for an anonymous client and
 means the node is healthy. A cold `GET /` through a gate is 200 because the gate signs
 the visitor in itself.
 403 = the fence REFUSED the Host. The node is published without a gate or --trusted-host, and
 every API call from that origin will fail no matter what the client does.
 404 = reached the engine and authenticated. On `/api` with a valid cookie this is CORRECT
 (no route behind the API prefix); on `/healthz` it means plugin-health is not mounted.
 502 = Serve has no backend on the port it proxies to. The node is UNREACHABLE, and
 `tailscale serve status` will still print a correct-looking mapping while it happens
 (observed 21:49-21:53Z: mapping to 3086, nothing listening, 502 for four minutes).
ALSO: this laptop sets a proxy AutoConfigURL (.pac). A proxy can manufacture a 502 that has
nothing to do with the node -- every probe in mesh-health.ps1 sets UseProxy=false. The first
desktop test here timed out on the proxy and looked like a node fault.
RULE: a health check must classify codes, run with the proxy off, and never accept
`serve status` as evidence a node is usable.
