**L3402 · Regenerate-record must work when nothing else changed - and a canary that asserts the world, not the test**

**A derived artifact's writer must be reachable when nothing else changed - otherwise the only way
to heal the artifact is to change something unrelated.** `store.update_case` had two "no write"
branches (`nothing-to-do` when no front-matter key, activity or next_action was supplied, and
`no-op` when the rendered text was byte-identical) and **both returned before the record step**. So
`cli.py edit <case> --regenerate-record` against a mirror that disagreed with an untouched case file
answered `changed: []`, `record: None`, "nothing written" - and left the disagreement in place. The
mirror is *derived from* the case file, so "the case file did not change" is exactly the state in
which a mirror can be stale, which makes it exactly the state a caller asks to heal.

Measured 2026-10-08 on the two cases filed that day. One healed only because an unrelated front-matter
value happened to move in the same call; the other kept a `nextAction` its case file had already
changed, and nothing in the tool said the mirror was the authority's stale copy - `record: stale` had
been printed once, as a warning among seven, and was read past. Fixed by routing both branches through
`_regenerate_mirror_only`, with a test that asserts the mirror is *written* (not merely inspected) and
that the case file is untouched: commit `7962ee702`.

**And the same sitting found a canary that had been lying for a day.** `test_nothing_is_created_
outside_the_fixture_repo` asserted `not (ROOT / ".lpt-locks").exists()` - but `cli.py edit` runs
against the real checkout by design, and the lock directory is gitignored and accumulates one 1-byte
lock file per case ever written. So the assertion was **red from 2026-10-07 16:08**, and a red suite
hides the next real failure. A before/after comparison of that directory catches a leaking fixture and
not an ordinary real edit, which is all the canary is for. Rule: an invariant test must measure what
*this test* did, never a property of a world other tools legitimately change.

Evidence: `tools/customer/store.py` `_regenerate_mirror_only`; `tools/customer/tests/test_store.py`;
`pytest tools/customer/tests tools/intake/tests` -> 172 passed; commits `7962ee702`, `4283ee2b4`.
