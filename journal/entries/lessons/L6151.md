## A client bundle is published from a working tree, so a checkout behind main ships stale UI — and immutable caching makes it look current

**The question, and the answer.** The owner asked, about the pill in his harness: *"why is it saying
it's from 45 hours ago?"* The 45 hours was exact and honest. The badge was told to ask the **frozen
rollback anchor**.

**Measured, with provenance.**

| reading | value | how |
|---|---|---|
| badge's card claimed | `kernel report written 45h ago on secratary (19 checks: 13 ok, 6 needing attention)` | the GUI, 2026-10-13 ~17:25Z |
| the frozen anchor's last write | `2026-10-11T20:20:06Z` (inside the accidental 19:04–20:26Z unfreeze window) | `ssh secratary 'ls -l --time-style=full-iso ~/ceo-kernel-var/latest.json'` → mtime `2026-10-11 20:20:06.262` |
| the live authority, same minute | `at 2026-10-13T17:25:04Z`, host `secratary-cloud`, **15 ok / 3 attention** | `curl https://secratary-cloud.tail93e6e6.ts.net/dsh-attention.json` |
| what this machine's client asked | `const BADGE_AUTHORITY = 'https://secratary.tail93e6e6.ts.net'` (single, hardcoded) | `~/.dsh/profiles/web/node_modules/dsh-plugin-attention-badge/lib/client.js` — a **LINK** into the checkout |

So the pill was not stale, wrong, or broken. It was pointed at a stopped clock: the office box was
frozen at the 2026-10-11T05:43:36Z cutover and its kernel stopped on 2026-10-11T20:20:06Z.

**Why this machine did not have the fix, when the fix was 24 hours old.** The estate already knew:
`8c00270d` ("badge: the findings were being computed on the frozen office box", docs/mesh/168) replaced
the constant with `BADGE_AUTHORITIES` — authority first, frozen box as a stand-in, freshest readable
reading wins — on `origin/main` and on ZABZ-YOGA. ZABZ-TECH's checkout sits on
`mesh/broker-host-cloud-default-20261013` (`367ae00e`), **89 commits behind `origin/main`**, and the
profile links the badge package **straight out of that working tree** (`install-client-plugins.ps1` →
junction, proved by running it with `-Check`: `dsh-plugin-attention-badge LINK bundles=True ok`).
So the machine served the pre-fix bundle; the bundle URL is cached `immutable, max-age=31536000`, so it
kept asking the frozen box on every load with no error anywhere.

**The measurement that keeps the next claim honest.** "89 commits behind" is not "89 commits of client
code missing": `git diff --stat HEAD origin/main -- packages/` names exactly **one** package
(`plugin-remote-fanout`). The rest is journal and docs. Count the commits you are behind only as a
suspicion; diff the artifact you actually serve.

**What was done.** Took the fused files from `origin/main` (`packages/plugin-attention-badge`,
`assets/phone-badge.js` v4, `scripts/verify-badge.js`, `docs/badge/README.md`, `docs/mesh/168`) onto
ZABZ-TECH's branch and committed them (`0975e382`) so a later install cannot regress. Verified:
`node scripts/verify-badge.js` **181/181**; a cold page load of `http://127.0.0.1:3099` fetches
`https://secratary-cloud.tail93e6e6.ts.net/dsh-attention.js`, declares
`https://secratary-cloud… https://secratary…` on the loader, and renders **`3 needing attention`**
(was `6 · stale 45h ago`). The bad news is visible: the same payload the frozen box served said 6.

**Transferable rules.**
1. **Before believing an age on a surface, read the host in the card and find out which origin the
 client is configured against.** "45h" was true about the source it was reading, and false about the
 company.
2. **A client artefact published from a working tree inherits that tree's staleness, silently.** Both
 installers now warn (local `origin/main` ref, no fetch, never a refusal):
 `install-client-plugins.ps1 -Check` on ZABZ-TECH prints it today.
3. **Immutable caching turns a stale install into a permanent one.** Any fix that lives in a client
 bundle is not deployed until the bytes change *and* the page reloads; say which of the two is missing.
