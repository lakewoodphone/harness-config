**L1961 · Opening an LPT case correctly: the sync_record gap, the differ's false positives, and the four-word device slug**

## The trap, measured 2026-09-17 (Rosenberg / Yoga C930 case)

`python tools/customer/cli.py new ... --regenerate-record` DOES write
`docs/customer-operations/sync-records/<case_id>.json`, and it still leaves the
new case file declaring `sync_record: ""`. `cli.py edit` has no `--sync-record`
option, so the front-matter link can never be set afterwards through the tool.
Every case created this way is born an orphan that the tool itself says it was
written to prevent.

The fix at creation time is to pass `--sync-record <repo-relative path>` to
`new` explicitly (the argument exists; it just is not populated for you).

## What "in sync" actually costs you, if you try to satisfy the differ

`record.diff_record(repo, case_id)` is a STRING argument. `store._record_step`
calls it as `fn(repo, case)` with a `Case` object, so the comparison errors out
rather than comparing. And `_diff_verdict` looks for `equal`/`in_sync`/`ok`/
`valid`/`matches` keys, while `diff_record` returns `{"same": bool}` - so even a
correct call reports `differs`. See journal pain entry for the mirror check.

Do NOT contort a case file to satisfy `diff_record`'s report alone. Measured on
2026-09-17, the shop's own best records differ in exactly three classes -
`customer.aliases`, `device.summary`, `operational.nextAction`:

 acer-aspire-n20c5-charging-jack-greenwald-8482017577-2026-09-17 -> those 3
 sd-card-goldstein-8482104005-2026-09-17 -> those 3 + pricing.quoted

So a rich record and a rich case file will always "differ". Make the case file
the truth and let the mirror follow it; do not degrade either one.

## The convention that IS worth matching

One fact, one place. `device:` in the front-matter carries the SAME full summary
string the mirror's `device.summary` carries - see `acer-aspire-n20c5-charging-
jack-greenwald-8482017577-2026-09-17.md`, whose `device:` is a long paragraph.
A short slug there guarantees `device.summary` reports as a difference forever.

## Naming and dates

`store._derive_case_id` slugs the FIRST FOUR WORDS of `device`. So put the model
code inside those four words or it is lost from the filename: "Lenovo Yoga
C930-13IKB (81C4) - ..." -> `lenovo-yoga-c930-13ikb-81c4-...`; "Lenovo Yoga
C930-13IKB (machine type 81C4) ..." -> `...-machine`, which is worthless.

`opened` is the intake date, i.e. the day the device physically arrived, even
when the machine could not be identified until the next day. Say the
identification date in the first activity section.

## The write path

Write through `tools/customer/cli.py` (new / edit / show / find), which routes
through `tools/customer/lock.py` and `store.py`'s hash-keyed lock under
`.lpt-locks/`. If you must edit by hand, lock **`docs/customer-operations`
itself**, not a file - and note that `lock.locked()` puts its sidecar NEXT TO
whatever target you hand it, so a raw path inside the corpus litters the tree.
