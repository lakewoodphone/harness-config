**L2793 · Three ways a scheduled task registers successfully and never runs: wrong principal variables, Interactive logon, and a future -At**

Three ways a scheduled task registers successfully and then never runs. All three hit in one
deployment on 2026-09-28, and none is visible from Register-ScheduledTask's return.

1. THE PRINCIPAL BUILT FROM THE WRONG VARIABLES. "$env:USERDOMAIN\$env:USERNAME" is the obvious
 way to name the current user and it is wrong on a workgroup machine: USERDOMAIN is the literal
 string WORKGROUP, so it builds "WORKGROUP\ezabz", an account that does not exist, and
 Register-ScheduledTask throws "No mapping between account names and security IDs was done".
 Use [System.Security.Principal.WindowsIdentity]::GetCurrent().Name, which is "zabz-tech\ezabz"
 and resolves to a real SID. A guard on EMPTINESS is not enough -- the variables were present and
 wrong, so my first fix ("fall back if they are empty") changed nothing and failed identically.

2. INTERACTIVE LOGON MAKES A TASK INERT WHEN NOBODY IS PRESENT. An Interactive-logon task runs only
 while that user is logged on at the console. ZABZ-TECH is an office machine with nobody logged
 in (qwinsta: "console 1 Conn", no USERNAME), so the installer that worked perfectly on
 ZABZ-YOGA produced tasks that sat at 267011 (SCHED_S_TASK_HAS_NOT_RUN) forever. Same task, same
 installer, measured side by side: Interactive -> 267011, S4U -> 0. Use S4U for headless checks
 (no stored password, runs regardless), and ServiceAccount when the installer itself runs as
 SYSTEM -- deciding from the identity it actually has, because the caller cannot know.

3. A FUTURE-DATED -At LEAVES THE TASK QUEUED AND Start-ScheduledTask IS THEN A NO-OP. So the task
 reports "has not run" and cannot be verified at all. Use a start time in the past. This is
 L174's trap from 2026-09-14, hit again four days of work later.

RULES
* "Registered successfully" is not "runs". A deployment is verified by driving one pass and reading
 the RESULT CODE, never by the registration's silence. Every installer in this repo now takes
 -RunNow for exactly that reason.
* Prefer a mechanism that works when nobody is present. An instrument that only runs while someone
 is watching fails precisely in the window where a silent outage would go unnoticed -- which is
 the case it exists for.
* Choose the scheduler the machine already uses: cron on secratary (active, and Linger=no means a
 user systemd timer would not fire unsupervised), a scheduled task on Windows.
* Non-Windows shells: write the script with LF endings. A CRLF heredoc piped to bash fails with
 "$'\r': command not found" on the last line -- the same family as the exec API's non-ASCII trap.
