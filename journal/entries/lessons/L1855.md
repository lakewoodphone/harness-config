**L1855 · A subagent's remote-command quoting dies three ways; -EncodedCommand is the only shape that survives**

MEASURED 2026-09-17 on ZABZ-YOGA -> ZABZ-TECH. The harness launches ssh through a bash box, and bash
rewrites the remote command line before it is sent, so quoting that works in a terminal fails here:

* `ssh host "powershell -Command 'Write-Output (\$env:COMPUTERNAME)'"` -> the target printed THIS
 machine's name and the remote reported `/ZABZ-YOGA : not recognized`: the backslash survived, the
 dollar was expanded locally.
* `ssh host "powershell -Command <dollar>x = 1; ..."` -> variables arrived EMPTY
 (`= [Console]::In.ReadToEnd()` with no left-hand side).
* `ssh host 'powershell -Command "..."'` -> mangled one layer further along.
* `powershell -Command -` (a program on stdin) EXECUTED NOTHING AND EXITED 0 - twice. The worst
 possible failure for a delivery step, because it looks like success.

WHAT WORKS: build the program locally and pass
`powershell -NoProfile -NonInteractive -EncodedCommand <base64 of UTF-16LE>`. There is no quoting
surface at all, and it keeps the program off the command line. Past ~8k encoded characters Windows
ssh answers `exec request failed on channel 0`, so ship the program as base64 on stdin to a temp file
and run it with `-File` - `packages/plugin-mesh-http/ssh-run.ps1` does both automatically.

ALSO MEASURED, SAME SESSION:
* A payload of 46 KB is ~61 KB of base64, which exceeds the 32,767-character argv limit outright:
 `The filename or extension is too long`.
* `tar -cf -` piped into a PowerShell pipeline does NOT produce a tarball - PowerShell splits the
 output into objects and `[Convert]::ToBase64String` gets strings. Use `tar -czf <file> <dir>`.
* A script piped to a nested `ssh ... -Command -` inside another ssh session does not execute.
* FOR A POSIX TARGET, the one shape that reached the Mac Mini:
 `python3 -c "import sys,base64;sys.stdout.buffer.write(base64.b64decode(sys.stdin.read().strip()))" | sh -s`
 with the script base64 on stdin. The Mac's tailnet path is relayed, and an ssh stdin pipe is the
 only transfer that has been reliable there (81 §2).
* A non-login shell on the Mac has no `~/.local` on PATH: `command -v node` is absent while the
 ENGINE runs that very binary. Check for the absolute path, not for `node`.
