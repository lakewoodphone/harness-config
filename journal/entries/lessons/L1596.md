**L1596 · A source-scanning test must strip comments, or good documentation breaks it**

2026-09-15, phone-and-tech-full backend/src/__tests__/trpc-router-guards.test.ts. The test asserts each router declares N procedures with a given guard by counting substring occurrences in the source file. It passed, then failed the moment the router gained a doc comment explaining that a branch is unreachable because of protectedProcedure - the comment named the guard, so the count went up. Fix: strip block comments and whole-line line comments before counting. General rule: any test that reads source text must strip comments first, or it punishes exactly the documentation that prevents the next person reintroducing the bug. The durable alternative is to assert the invariant (no procedure declared with the unguarded base) plus a floor, rather than an exact occurrence count that every new comment can break.
