**L12294 · A blocker on a partial row does not exist for the register**

A blocker written on a `partial` row does not exist for the register. `scripts/check_roadmap.py` gates
`RM-CLASS` on `state == "blocked"` (`:277-285`) and `RM-BLOCKED` likewise (`:286-290`), so a `partial`
item may carry a `blocked-on:` line that is never validated and never counted. Measured in the rowstates
lane on 2026-10-23T00:21Z against origin/main 7d33610d: A-P5-03 had said `blocked-on: hardware: no
provisioned handset on adb ...` since 2026-10-22 while its state was `partial`, so "how much of this is
waiting on hardware" undercounted it, and the `--write` summary read 26 blocked rather than 27.

The rule to keep: if a row's remainder needs something outside the repository or outside the machine
(a handset, a host, an owner decision, another lane's file), the state is `blocked` with the class-prefixed
`blocked-on`; `partial` is for work still claimable inside the repo. A `partial` row with a blocker is a
row that reads as claimable and cannot be counted.

Second, smaller lesson from the same lane: `scripts/check_runbook_commands.py` proves a runbook clause is
*present* and cannot see a page that states the clause and then denies it elsewhere. `remote-release.md`
passed all six clause patterns while also saying, forty lines later, that the request is refused inside
the thirty days - true of the pre-1187 code, false after it. A green clause checker on a page is not
evidence that the page is consistent; re-read the sections that describe the code.
