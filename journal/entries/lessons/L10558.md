**L10558 · I leaked the DeepSeek API key by interpolating it into an ssh command line - secrets move by stdin into a 0600 file, never through argv; owner queue #850 now covers both keys**

SECOND LEAK OF THE SAME NIGHT, and this one matters more: the DEEPSEEK API KEY was printed into the session
transcript at ~03:05Z on 2026-10-20.

HOW. I needed the key in the environment of a remote preflight, and I built the command as
 ssh host "... DEEPSEEK_API_KEY='<value>' node lib/cli.mjs preflight ..."
Two layers of quoting later the value was no longer quoted, bash tried to run it as a command, and the error line
it printed was the key. The first leak tonight (SerpAPI, L10430) came from a provider's error message; this one came
from MY OWN command construction, which is worse: it needs no code defect at all.

WHAT MUST HAPPEN: the key is live and used by every DSH engine and the company gateway, so it has to be ROTATED.
Owner queue #850 was amended to cover both keys (SerpAPI + DeepSeek) because the queue correctly refused a second
duplicate row.

THE PATTERN THAT REPLACES IT, and it should be the only way a secret moves between hosts from now on:
 # read it on the source host and write it through STDIN on the target, never on a command line:
 ssh source 'grep -m1 "^DEEPSEEK_API_KEY=" /path/.env | cut -d= -f2-' | ssh target 'umask 077; cat > /tmp/.env.key; chmod 600 /tmp/.env.key'
 ssh target 'set -a; . /tmp/.env.key; set +a; <command>; rm -f /tmp/.env.key'
A value that never appears in an argv is a value that cannot appear in a process listing, a shell history, an error
message, or a transcript.

WHAT I KEEP GETTING WRONG, stated plainly so the next session does not have to learn it twice: I have been treating
quoting as a cosmetic problem all night -- it broke node -e, broke here-docs, broke a PowerShell payload, and now it
has cost a live credential. Every one of those was the same mistake: putting a complex string INTO a command line
instead of writing a file and running the file. Files, stdin, and base64 are the tools; inline interpolation is not.
