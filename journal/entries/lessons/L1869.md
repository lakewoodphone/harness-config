**L1869 · Correction to L1868: half the owner restarts are engine terminations no rule can reach - eight fixes tried, none stuck, so the remedy is resume-and-report, not a ninth rule**

Correcting and completing L1868, written an hour earlier. L1868 reported the owner-restarts-a-halted-agent class as 46-51 nudges and noted that the fix D8 predated them and that the rate was worse where it was in force. That is incomplete in a way that changes the remedy. The mining fleet split every nudge against the nearest preceding turn/end REASON: completed 23 - interrupted 12 - aborted 11 - error 3 - none 2 (51 total). So only about 45-54 percent of the restarts are the agent's own decision to stop - the only part an instruction can reach. Roughly half are ENGINE-LEVEL terminations that no prompt rule can touch, which resolves the otherwise impossible observation that EIGHT durable fixes were written against this class inside six days and NONE stuck: rule 1 + D8 landed 09-11T16:32Z and the next nudge came 11 minutes later; rule 2b + L59 at 19:53Z with one 51 minutes later; rule 2c + L61 the same day; the generator repair at 22:42Z (itself re-broken 09-16); the fleet skill + rule 1b at 09-15T19:00-19:13Z, with the owner's do-not-stop-keep-working message arriving 7 minutes after 1b; the session-shape rule 09-16T14:39Z followed by 7 nudges that day; and the overnight contract 09-17T03:34Z, only about five hours old at this reading. Pre-window stragglers failed identically in 2026-05. Fixes that stuck: 0 of 8. THEREFORE THE REMEDY IS NOT A NINTH RULE. It is (a) make a terminated turn RESUME rather than end, and (b) make the engine's termination VISIBLE to the owner as a failure instead of looking like the agent chose to stop. Any future did-the-fix-work verdict on this class must be split on turn/end reason BEFORE it is computed, or it will credit a prompt rule with reaching terminations it cannot reach. Two smaller corrections: the daily nudge series is 0, 5, NOT FOUND, NOT FOUND, 29, 6, 10, 1 for 09-11..09-17 - 09-12 and 09-13 have no rows at all, so no nudge can be counted, which is not the same as zero; and at least one nudge in the class is the owner's own error (09-16T19:51:23Z, 'wait keep going i think i stopped you in middle by mistake'), so the class is not wholly agent-caused. Finally, this study is inside its own evidence - the prompt text of the mining run appears as user blocks in three sessions - the same mirror problem it documented.
