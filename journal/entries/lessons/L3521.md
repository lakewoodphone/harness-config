**L3521 · A guard without its rule is half the protection - I delivered the enforcement but not AGENTS.md, and the guard's own test caught me with 'the rule reaches no agent'**

Coordinator round 22, 2026-10-11 ~21:28Z. The unexplained 31/1 is explained, fixed, and it was my fault.

THE FAILING TEST, verbatim:

 [FAIL] AGENTS.md is absent — the rule reaches no agent

**The suite was right and my delivery was wrong.** In round 21 I delivered the guard, the posture file and
the tests to the bench with a targeted `git checkout origin/main -- <three paths>` - and `AGENTS.md` was
not in that list. **`AGENTS.md` is the file that carries section 5, the rule itself.** So the bench had the
*enforcement* and not the *instruction*: an agent there would be refused by the guard without anything on
that machine telling it why.

FIXED: `git checkout origin/main -- AGENTS.md` on the bench -> `AGENTS.md` present, 13,022 B, carries
section 5. Re-ran the suite: **35 passed, 0 failed**, matching main exactly. And `origin/main` carries
section 5 (1 occurrence), so this was purely my incomplete delivery, not a repository defect.

WHY THIS IS A GOOD TEST AND NOT A NUISANCE. It asserts *"the rule reaches no agent"* rather than *"the file
exists"* - it checks the guard is accompanied by the thing that explains it. That is precisely the failure
mode I created, caught automatically, on a machine I had just declared done. **A guard without its rule is
half the protection**: it makes the right behaviour impossible without making it understood, and an agent
that hits a refusal it cannot read is an agent that will look for another way round. Worth keeping in mind
whenever a guard, a policy or a gate is delivered anywhere - **ship the refusal and the reason together.**

THE TRANSFERABLE RULE, sixth instance of the same shape today: **"I delivered it" is a claim about the
things you listed, not about the thing being complete.** My checkout delivered exactly what I named, the
suite checked something I had not thought to name, and the difference was invisible until the test ran.
The remedy is the one that has worked all day - run the checker, on the target machine, and read what it
actually says.

STATE: the guard, the posture file, its tests and the rule now all reach the bench and ZABZ-TECH. The
office box and the cloud authority still do not, and both need a DECISION (a write on a frozen host; and
where config lives on a box with no harness-config checkout).
