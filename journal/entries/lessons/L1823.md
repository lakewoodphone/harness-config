**L1823 · Windows took the laptop out of the fleet: sshd could not traverse UNTRUSTED REPARSE POINTS, and the relink must run inside an ssh session (corrects L1821)**

CORRECTS L1821 (2026-09-17 earlier): that entry said ZABZ-YOGA's sshd could not traverse the SYMLINKS in ~/.dsh/profiles/node_modules. The link type was wrong - measured the next hour, every one of them is a JUNCTION (Node's lstatSync().isSymbolicLink() returns true for junctions on Windows, which is what misled me). The real mechanism is Windows' reparse-point TRUST check, and cmd says it in words: "The path cannot be traversed because it contains an untrusted reparse point."

EVIDENCE (all 2026-09-17, ZABZ-YOGA unless noted): junctions, targets, ~/.dsh ACLs, token privileges (SeChangeNotifyPrivilege Enabled), integrity level (High) and fsutil SymlinkEvaluation are IDENTICAL on ZABZ-YOGA and ZABZ-TECH; yet the laptop's sshd refused and the desktop's allowed. It is not the caller either - the laptop fails for a connection from ITSELF (ssh ezabz@127.0.0.1) - and not the path: a freshly created junction in a plain directory outside ~/.dsh fails the same way. Only reparse points as a class. Neither the type of link, then, nor the target, ACL, path, privileges or caller decides it. What decides trust beyond "created in the reading session" was NOT established.

THE FIX, AND THE TRAP: recreate the links FROM INSIDE AN SSH SESSION. Recreating them from a local session changes nothing (measured: rmdir + New-Item -ItemType Junction with the same target, still UNKNOWN over ssh). Done in-session: 413 links replaced in 22 s, 0 failed, then `ssh <laptop> node <bin.js> --profile headless "Reply with exactly: LAPTOP OK"` -> LAPTOP OK, exit 0, 10.3 s, engine pid 1784 untouched. Durable: a later LOCAL dsh run (which re-runs healProfilesModuleFallback) left the junction in place and still traversable, because the heal treats a junction with the right target as current.

RULES FOR THE FLEET: (1) this is per-machine and invisible in configuration - PROBE it, never assume; a passing probe is necessary but only a completed one-shot turn is sufficient. (2) The probe must read PRE-EXISTING links: a junction created inside the sshd session is always trusted by it, so probing with a fresh one certifies nodes whose real links are untrusted (my first probe made exactly that mistake). (3) mesh-run now probes before starting a parent and fails the run with phase "traversal". (4) Node names are Tailscale DNS labels (zabz-yoga-1, not zabz-yoga) because the capacity contract fixes node === fqdn.split(".")[0]; a dispatcher that cannot find a broker-named node must fail loudly, or -Exclude strings silently match nothing.
