**L1805 · Publishing a loopback engine yields 403, not a working app: tailscale serve preserves Host**

Measured 2026-09-16 21:47Z on ZABZ-YOGA. `tailscale serve --bg 3099` straight at the harness
engine: `GET /api` through https://zabz-yoga-1.tail93e6e6.ts.net returned **403** while `GET /`
returned 401. Serve forwards the client's Host header unchanged; the engine's fence
(dsh-client-connection isTrustedApiRequest) accepts loopback or a declared trustedHosts entry and
refuses everything else. So a published loopback engine serves a shell that cannot talk -- only
/api is fenced, which is why the index route answers 401 and the API answers 403.
`--trusted-host` is a STARTUP setting (dsh-web-app/lib/index.js:37), so applying it means
restarting the engine and ending every live session, including the one measuring.
THE FIX THAT NEEDS NO RESTART: a gate in front that presents Host AND Origin as
127.0.0.1:<engine port>. Both, because the fence requires origin.host == host.host -- rewriting
Host alone leaves every browser POST 403ed while curl stays green.
