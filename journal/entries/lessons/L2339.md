**L2339 · A flow sequence inside !!js breaks the YAML overlay parser, and --dump-config is the check that catches it**

**L · A flow sequence inside `!!js` breaks the YAML overlay parser, and `--dump-config` is the check that catches it before anything restarts**

MEASURED 2026-09-18 on ZABZ-YOGA, in about four minutes, while raising the dispatch hop's connect timeout.

WHAT I DID: replaced a plain flow sequence in `profiles/web/cordis.patch.yml` with a `!!js` expression so the
timeout could be overridden per host:

```yaml
sshArgs: !!js "['-o', 'BatchMode=yes', '-o', 'StrictHostKeyChecking=accept-new', '-o', `ConnectTimeout=${process.env.MESH_SSH_CONNECT_TIMEOUT ?? 25}`],
```

WHAT HAPPENED: the config stopped loading.

```
Error: dsh: failed to parse overlay C:\Users\ezabz\.dsh\profiles\web\cordis.patch.yml:
 YAMLException: missed comma between flow collection entries (166:26)
```

and the caret pointed at the **next** key, two lines below — the parser had swallowed past my line and was
still waiting for a separator.

THE FILE ALREADY WARNED ME. Forty lines above, its own comment says:

> a block sequence inside a flow mapping is a parse error — "missed comma between flow collection
> entries", measured by `dsh --profile web --dump-config` on ZABZ-YOGA 2026-09-17 while writing this row.

So this exact error had been hit in this exact file before, by a previous session, and written down. I
reproduced it with a different trigger (a flow sequence produced *inside* a `!!js` tag argument rather
than a block sequence written literally), which is one more shape of the same trap: **the `!!js` tag's
argument is not a place to put YAML collection syntax and expect the parser to stay out of it.**

THE FIX, and it is deliberately less clever than the thing it replaces: a plain literal.

```yaml
sshArgs: ['-o', 'BatchMode=yes', '-o', 'StrictHostKeyChecking=accept-new', '-o', 'ConnectTimeout=25'],
```

The per-host `MESH_SSH_CONNECT_TIMEOUT` override is **lost**, and that is an accepted cost — a literal that
parses beats an expression that does not, and the value that matters (25 s rather than 10 s) is carried.
The lesson is not "write the override differently"; it is that **this file's flow style is fragile enough
that cleverness in it is a liability.**

WHY NOTHING BROKE: the engine was never restarted, so the broken overlay was only ever live on disk for the
few minutes it took to find it. **`node <dshbin> --profile web --dump-config` exits 1 with the exact line
and column, and exit 0 when the file is good, and it evaluates the profile without starting anything.** That
is the pre-commit check for every profile edit, and this incident is the argument for running it: the same
edit committed without it would have broken the engine on its next start on every machine that picks up the
repo — a live profile is a thing a running DSH depends on, not a scratch file.

THE RULES:
1. **Run `--dump-config` for the profile you edited, and read its exit code, before committing or syncing.**
 A profile patch that does not parse is a machine that does not start.
2. **The `!!js` tag takes an expression, not YAML.** Collection syntax belongs in the YAML; the tag belongs
 on a scalar.
3. **When a file's comment describes an error you are about to make, that is not background — it is the
 test.** This one named the exact exception string and the tool that prints it.
