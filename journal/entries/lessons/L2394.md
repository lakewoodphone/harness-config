**L2394 · A pushed branch is not a shipped fix: check ancestry of the DEPLOYED lineage, not the handoff that says the gap closed**

Recorded 2026-09-23, from the LPT website redo.

THE FAILURE: H480 (2026-09-17) ends with "the allowlist GAP closed, login proven" - it is true, it was
proven by execution on the integration branch - and H547 (2026-09-18) then repeats, in its NOT DONE list,
that "the customerProcedure path allowlist in context.ts:106-116 still refuses every auth.customer* call".
Both entries are accurate about what they measured. Nobody checked the thing that decides whether a
customer can actually log in: **is the fix an ancestor of the branch that gets deployed?**

Measured today: `origin/test:backend/src/trpc/context.ts:112` still matches `includes('customerPortal.')`;
`rev-list --left-right --count origin/test...origin/integration/lpt-20260916` = 69 ahead / 28 behind;
`merge-base --is-ancestor origin/integration/lpt-20260916 origin/test` exits 1. Six days of a finished,
tested, security-relevant fix that no customer can reach.

THE RULE: a green test on an unmerged branch is not a shipped fix. When you write "fixed" or "gap closed",
name the ref the fix lives on and whether that ref is an ancestor of the deployed lineage:
`git merge-base --is-ancestor <fix-commit> origin/<deployed-branch>`. If it exits non-zero, the fix is
IN FLIGHT, not DONE, and the handoff must say so in those words.

SECOND RULE, same session: production can be AHEAD of the journal as easily as behind it. The holiday
closure surface has been live since ~2026-09-20 (bundle `index-B7Smwo3h.js` carries the generator comment,
the closures through 2026-11-04 and the notice template) while the journal still read "re-dispatch later"
and P335 stayed open. Before acting on a stale open item, spend two minutes checking whether it is actually
already shipped - read the live bundle for its own source comments, which is how this was caught.

METHOD THAT FOUND IT: `Select-String` on the deployed bundle for a distinctive string the feature would
have to contain, plus the source file's comment block. It distinguishes "deployed" from "recorded".
