**L3356 · A test that CAN send is not a test: log the decision, never transmit from a test path**

On 2026-10-06 I ran the heartbeat against a mock to prove the new up-but-not-working alarm, and passed ALERT_ENV=/nonexistent expecting the alert to be suppressed. It was not: company-heartbeat.sh assigned ALERT_ENV=/root/.alert-env unconditionally at the top, overriding the environment, so the script used the REAL credentials and a FALSE alarm went to the owner's phone ('the company ANSWERS but its WORK LOOP IS NOT RUNNING') while the truth was the opposite - the company was DOWN (http 530, 330 minutes). That is the second unintended outbound message of the night; the first was the same class of mistake (TEST=1 passed as an argument instead of an env prefix, which sent a real DOWN alert instead of a test text). WHY IT MATTERS: the outbound hard stop exists because a message cannot be unsent, and BOTH mistakes came from my own test harness rather than from an agent deciding to speak. FIX APPLIED: (1) every channel path is now overridable (ALERT_ENV, HEARTBEAT_STATE_DIR) and (2) a first-class ALERT_DRY_RUN=1 that computes the decision exactly as production would and writes 'ALERT DECISION (dry run, nothing sent)' to the log. Re-proved with it: the same mock produced the same decision, zero sends, and the production state file still reports the real outage untouched. RULE FROM HERE ON: any script that can transmit must have a dry-run switch BEFORE it is tested, and a test must assert on the logged DECISION, never on the absence of an obvious side effect. 'I expected it to be suppressed' is not evidence; a counter of sends is.
