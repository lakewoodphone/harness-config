**L1615 · Cross-file test interference: pair-test, never bisect; and never assign to process.env**

Area: phone-and-tech-full backend suite. Two files, health-slow-logging and health-enhanced, ran green alone
and failed together (1 failure). Both restored env with `process.env = originalEnv` -- an ASSIGNMENT that
replaces the binding on a live process-global proxy -- so whichever restored last clobbered the other's
snapshot inside a shared worker. Fixed by deleting keys added since the snapshot and re-assigning keys
individually. Result: full suite 6199 passed / 0 failed, same at --maxWorkers=1 and at 8 forks.

RULE: a file that fails in the full suite and passes alone is INTERFERENCE, not a stale assertion. The two
need opposite repairs, so isolate before you repair.

RULE: derive the minimum reproducible pair by pairing files WITHIN one area, not by bisecting by halves. Two
files reproduced it in a single run; halving 22 files would have taken six runs to reach the same place.

RULE: never assign to process.env in a test. Snapshot the keys you touch, restore them one at a time.
