**L1815 · A socket timeout is not a wall-clock timeout, and unknown must not be reported as unreachable**

TWO RULES EARNED BY MEASUREMENT, both from building the mesh broker (stream S5, 2026-09-16).

1. A socket timeout is NOT a wall-clock timeout. `request.setTimeout(n)` on a node:http request counts
 from socket assignment, so a name that resolves slowly spends its DNS time before the timer even
 starts. MEASURED on the authority: `GET https://zabz-tech-linux.tail93e6e6.ts.net/mesh/capacity`
 reported `latencyMs 3031` against a `timeoutMs 1500` deadline - exactly two timeouts deep. Any code
 that promises "a short timeout" over Tailscale/MagicDNS needs BOTH timers: the socket one (covers a
 stalled transfer) and a hard `setTimeout` that destroys the request (covers everything else). The
 regression test in `packages/mesh-broker/test/acceptance.test.mjs` measures 310 ms for a 300 ms
 deadline against a server that accepts and never answers.

2. "Unknown" must not be silently folded into "unreachable". Two conflation bugs found by reading the
 live mesh rather than by a test failure: (a) a node answering `mem.freeMiB: null` (legal per §2.1
 "every field is measured or absent", and legal to S1's own checker) was reported as `unreachable` -
 a false claim about reachability, fixed to `reachable: true, slotsKnown: false`; (b) when nothing
 could start, ranking by slots alone put an unreachable laptop ahead of the one node actually
 answering, because a gate-reported restriction (`accepts.fleet:false`) removed that node from the
 pool entirely. Rule that survived both: reachability is a property of the OBSERVATION, never of an
 inference, and when a decision is a queue rather than a start, rank by what was measured - reachable
 first, then slots - and print the blocker verbatim in the rationale.

Related, and worth keeping: a rationale that is generated from a template rather than from the numbers
it claims to explain will lie. The broker's position line printed "21 < 0" (a node with 22 free slots,
queued because the caller had excluded it) until the reason was derived from an explicit `blockedBy`
list. If a field is called `rationale`, its arithmetic must be computed from the same variables that
made the decision.
