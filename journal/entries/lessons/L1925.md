**L1925 · The untrusted-mount-point discriminator is the reparse point's ACL OWNER, not the reader or the creator**

**The discriminator for "The path cannot be traversed because it contains an untrusted mount point"
on Windows is the reparse point's ACL OWNER, not the reader's logon class and not which process
created it.**

MEASURED 2026-09-17 on `zabz-tech`, all nine junctions in
`<DSH_HOME>\profiles\web\node_modules`, read from an ssh-spawned process and from a local
Interactive-logon one-shot task:

 owner=BUILTIN\Administrators -> ssh read exit 0 (7 junctions: attention, attention-badge,
 cost, health, mesh-http, mobile, windows)
 owner=zabz-tech\ezabz -> ssh read exit 1 (remote-fanout, session-link, mesh-broker)

9/9. A LOCAL Interactive process traverses ALL NINE, including the three refused to every remote
process. And `fsutil reparsepoint query` on a failing link and a working one prints byte-identical
reparse data (tag 0xa0000003, same `\??\` substitute name, same 0x94 bytes). `fsutil behavior query
SymlinkEvaluation` on that machine: `Remote-to-local symbolic link evaluation is: DISABLED`.

Reproduced by control: a junction created BY the ssh process -> traversable by ssh (193 lines); a
junction created by the same local task that then read it -> refused to ssh, read fine locally.

**So the fix for a link a remote process cannot traverse is to recreate it FROM a remote process**
— `[IO.Directory]::Delete` (reparse point only, never `-Recurse`) then
`New-Item -ItemType Junction` from inside the ssh session. That is what `mesh-run.mjs:229` already
says in this repo ("fix it by recreating the links INSIDE an ssh session, see 70 §4.4") and it is the
opposite of `docs/mesh/99` §2.2 ("an ssh-created junction is the untrusted kind" — FALSE, measured)
and of `docs/mesh/105` §8 item 7 ("a task-created junction is trusted" — true of every junction for
every local reader, so it proves nothing about the remote one).

RESULT: remote-fanout, session-link, mesh-broker owners -> BUILTIN\Administrators; `cmd /c type`
through each -> exit 0 (193 / 19 / 28 lines); `--dump-config` from the ssh reader went
**exit 1 / 16 lines -> exit 0 / 620 lines**; the loader's own resolution returns the junction path at
version=0.2.0 with patchExists=true. Target content hashes unchanged (re-hashed, not asserted).
Written up in `docs/mesh/106-desktop-last-mile.md` §2-§3.
