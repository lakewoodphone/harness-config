**L8767 · 14,753 files vs 8,637 sessions is not a gap — compare IDs, or you will build an importer for nothing**

Measured 2026-10-18, ten minutes into designing a session-archive importer for the search index.

The evidence looked damning: the raw transcript archive holds **14,753 DSH session FILES** across six machines, and \uthority.db\ holds **8,637 sessions**. That reads as thousands of unsearchable conversations, and the owner's requirement is literally 'every session ever held on every machine'.

**It is not a gap.** The two numbers count different things: one counts files (a session can have several generations, and the archive keeps every one), the other counts distinct sessions. Compared **by ID** — every session id the manifest names, against \dsh_sessions\ — the archive names **8,609 distinct ids and only 14 are absent**. The corpus was already complete.

**The rule, and it is the second time today:** before claiming a gap between two counts, make sure they count the same thing, and compare the *identifiers*, not the totals. The earlier instance was '34.5% of the laptop's documents are missing from the centre', which was also two different sets measured as a ratio.

**What I kept anyway:** the shipper now reads \sessions\ and \sessions-archive\, because a session archived *before* it is shipped lands in neither. That is a race, not a backlog, and the comment next to the code says so — the first version of that comment asserted the non-existent backlog, and was corrected in a follow-up commit rather than left to mislead the next reader.
