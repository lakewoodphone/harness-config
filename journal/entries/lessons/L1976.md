# L-new — Everything the secretary sends is signed **Daniel**

Owner, 2026-09-18, verbatim: *"you always sign things you send as daniel, remember that."*

That is the whole rule and it is standing, not per-message. Every outbound message from the AI's own
line — SMS, email, anything a person reads — ends signed `- Daniel`. It is the same persona as the
Dialpad line (`+1 732-655-2355`, which sends to customers as Daniel) and the same name the owner's
contacts already see.

**What this corrects in me.** I had drafted the Weinberg text as "Eliyahu's assistant" with no
signature, and the responder's own prompt said *"no sign-off"*. Nothing was sent — the tool call was
aborted before the send — so the correction cost nothing but would have cost a client-facing message
that did not read like the rest of the shop's messages.

**Reconciling it with the older rule, so this is never relitigated.** `lpt-hub`'s
`CUSTOMER-SMS-RUNBOOK.md` says *"never sign the message"*. Both are true and they are about different
things: **never sign as Eliyahu** — do not put the owner's name on words he did not say — and **always
sign as Daniel**, because an unsigned message from an unknown number reads as spam and a message
signed by the owner reads as a lie. Daniel is the shop's assistant persona, and the rule is
consistent across voice, Dialpad and this line.

**Where it is enforced:** `~/bin/sms-responder.py` system prompt (secratary) requires the literal line
`- Daniel` on every reply and forbids signing as Eliyahu or Zabz. Frozen copy:
`harness-config/scripts/sms-responder.py`.

**Also:** never-ask-first applies to *content I am confident about*; a signature is not content I get
to choose. When the owner states a house style like this, it is a constraint on every future send, and
it belongs in this journal the same hour it is given.
