**L9986 · A pytest suite that reports setup errors may be the TMP dir, not the code: use --basetemp on this laptop**

Measured 2026-10-19 on ZABZ-YOGA, `lpt-hub/tools/parts-catalog`: `python -m pytest
tests\test_parts_catalog.py -q` gave "11 passed, 8 errors" with every error at SETUP and every one a
`PermissionError: [WinError 5] Access is denied: 'C:\Users\ezabz\.dsh\tmp\pytest-of-ezabz'`. The
cause is the environment: TMP here points inside `.dsh`, and pytest creates its per-run basetemp
under it. Nothing was wrong with the code or the tests.

Fix that worked: `python -m pytest tests\test_parts_catalog.py -q --basetemp
C:\Users\ezabz\code\_scratch\<area>\pytest-tmp` -> 19 passed in 0.44s, rc 0.

Why it is worth writing down: eight setup errors printed next to eleven passes reads exactly like
"this suite is broken", and the first instinct is to distrust the change under test rather than the
temp dir. Also `pytest` was not installed in the default interpreter at all (rc=127-style
"No module named pytest"), so a fresh laptop needs `python -m pip install pytest` before a suite
means anything. Per-file greps of the traceback show only pytest's own pathlib frame, so the error
text has to be read to the end to find the WinError line.
