**L1899 · A generated plugin artifact must not carry require(absolute path) - or the building machine's home**

Measured 2026-09-17 building packages/plugin-cost/lib/guard.js.

The build concatenates src/*.mjs into generated ESM and rewrites each source's import into a require binding. Two failures, both found by reading the generated file rather than the test output:

1. createRequire(import.meta.url) does NOT work as the anchor. A generated lib/*.js sits inside the checkout, harness-config has no node_modules of its own, and the loader mounts dsh-plugin-cost through a junction at ~/.dsh/profiles/web/node_modules. So a package name in a require binding resolves nowhere. The rule that works: node: builtins become require bindings; a PACKAGE dependency stays a static import in the generated file, because the loader resolves that one itself from the profile baseUrl.

2. The first fix baked the building machine's absolute path into the committed artifact - createRequire("C:/Users/ezabz/.dsh/profiles/web/package.json") - which would ship one host's home directory to every other machine. The fix is to emit the anchor as a runtime function of process.env.DSH_HOME and process.env.USERPROFILE/HOME using nothing imported in advance, and to check the generated diff for absolute paths after any build-script change.

ALSO: an import statement cannot be reintroduced by deleting the import line from the template by regex - that edit silently broke both generated files (ReferenceError: createRequire is not defined). Edit the template explicitly and re-run the build.
