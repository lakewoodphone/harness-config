**L3852 · The only device on adb is not the device the owner named - ask for the serial before any write**

Owner's correction, 2026-10-18 ~21:03Z, verbatim: "what the hell that was another phone not hte one i wanted you to touch".

What I did wrong: he said "get ready to run filter only on another e4810". I checked `adb devices`, found exactly one handset (558800292460) plus an offline emulator, and treated the only visible device as the target. I staged filter-only on it. He meant a different handset that was not connected, or not yet connected. Being the only device on ADB is not evidence that it is the device he named, and "another e4810" was never a serial.

Measured impact on 558800292460 (receipt cli/logs/deployments/deployment-receipt-558800292460-20261018-210220.yaml): tier filter-only, profile null, excluded_apps [], forced_disabled_packages [] - so NOTHING was disabled, no USB lock, no wipe, no wallpaper change. What the stage did do: reinstalled the filter-only app bundle (install phase), rewrote com.android.cts.keysminimal:lpt_keys_config.json and com.android.cts.apps4fliplauncher:lpt_app_list_config.json, re-set the stock launcher, re-enabled the app drawer, configured the same three accessibility services, re-enabled DCS and re-disabled the PTT package (already disabled). The handset already carried the same product family (its April 2026-04-17 receipts are tier standard / standard-no-text with every user app excluded, and its live state had the full user app set, 19 packages disabled, com.android.mms disabled).

RULE FOR THE NEXT SESSION: an owner instruction that names a DEVICE must be resolved to a SERIAL before any write, and the serial comes from him or from a device he points at - never from "the only thing plugged in". Read-only inspection of a device he did name is fine; a deploy, a stage, a disable or a lock on a device he did not name is not. If the named device is not visible on adb, the answer is "it is not plugged in", not "here is one that is".
