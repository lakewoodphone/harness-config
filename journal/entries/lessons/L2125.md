**L2125 · L2125 - the company ran on Linux with a Windows blueprint, so every repo tool call pointed at a path that did not exist**

Measured 2026-09-20 on the authority. `app/chat_action_repos.py:75` resolves a repo alias to a
filesystem path with `MANAGED_REPOS.get(repo, {})`, and `app/company_blueprint.py` declared all nine
of its `local_path` values as **Windows** paths:

 phone-and-tech C:/Users/ezabz/Code/phone-and-tech-full
 quickbooks-agent C:/Users/ezabz/Code/quickbooks-agent
 research C:/Users/ezabz/Code/Research
 ha-config C:/Users/ezabz/Code/ha-config
 apps-4-flip C:/Users/ezabz/Code/apps 4 flip
 personal-secretary C:/Users/ezabz/Code/personal-secretary-mvp
 lpt-flip-phone C:/Users/ezabz/Code/lpt-flip-phone
 filter-ai C:/Users/ezabz/Code/kosher-filter-ai
 lpt-hub C:/Users/ezabz/Code/lpt-hub

**`os.path.isdir()` was False for all nine.** The company has run on Linux for months, where the
repositories live under `/home/zabz/repos/`. Two aliases also named the wrong repository: `research`
is really `research-knowledge-base`, and `apps-4-flip` is really `kyocera-escalator` (the blueprint's
own `github_repo` field said so, while `local_path` disagreed with it).

**Visible consequence in the data:** 138 blocked tool calls in 7 days whose reason is a missing file
or repo - `repo_read_file: File not found: DEFINITIVE_PHONE_SETUP.md` 35x, plus a standing order
instructing agents to follow that same file, which exists only in an archived path
(`lpt-flip-phone/docs/archive/2026-07-02/setup/`).

**Fix:** all nine rewritten to paths verified to exist on this host, then proven through
`_resolve_repo_path({"repo_path": alias})` - the code path the agent actually uses - which now returns
a real directory for every alias.

**The lesson is not "a path was stale".** It is that **a configuration document can be valid for a
machine the system no longer runs on, and nothing detects that.** The blueprint was written when the
authority was Windows; it moved to Linux; the file was never updated and no check compares a declared
path against the host. Anything that names a filesystem location must be validated against the host
that reads it - a startup assertion that every `local_path` exists would have caught this on day one,
and would have been one line.

Corollary: when a doc and a machine disagree, the machine wins, and the doc is the bug.
