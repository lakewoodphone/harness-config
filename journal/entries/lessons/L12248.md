**L12248 · lpt-write total set takes a PRE-TAX amount while writes.md calls total tax-inclusive**

`lpt-write total set --order X --amount N` takes N as a PRE-TAX figure and adds NJ tax at 6.625% itself. `lpt-ops/docs/writes.md` says the opposite - that orders."total" "is defined as the TAX-INCLUSIVE figure".

Measured 2026-10-22 on WO2609070001: `--amount 75.00` planned `total=79.97` ("75.00 + 4.97 tax at 6.625% = 79.97 to pay"); `--amount 70.34` planned `total=75.00`. The customer's Stripe charge was exactly 75.00, so 70.34 was the correct input.

The lesson is not the tax rate; it is that a dry run printed the arithmetic and that is the only reason the order did not end up carrying 79.97 against 75.00 of collected money. Every `lpt-write total set` must be dry-run and the printed `tax` line read before --apply, and the doc line in writes.md is wrong and should be corrected in the repo.
