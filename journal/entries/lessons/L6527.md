**L6527 · sqlite3.Connection has no rowcount - my own reflex, twice in one session, so here is the symptom**

Measured 2026-10-16, twice on the CFO ledger within one session (round 7 prune, round 11 text repair). The line is n += con.rowcount after con.execute(...), and sqlite3.Connection has no rowcount: only the CURSOR returned by execute() does. The traceback is AttributeError: 'sqlite3.Connection' object has no attribute 'rowcount'. Both times the failure landed BEFORE commit(), so nothing was written and both times that was PROVEN rather than assumed - round 7 by the untouched stats, round 11 by re-reading the table and finding the same 8 rows still carrying an entity. The correct shape is cur = con.execute(...); n += cur.rowcount. Written down as a symptom to check rather than a thing to remember, because the same reflex appeared twice in one session and the second time it was in a script whose only job was to fix a data defect. A related habit that saved both incidents: put the commit AFTER the loop and assert the expected row count before and after, so a partial write is impossible and a wrong count is visible.
