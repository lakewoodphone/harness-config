**L1088 · Byte identity is the wrong key for a log written by two machines**

A journal written by three machines is not a set of byte strings. Measured here: 789 shard entries were 569 distinct entries (220 copies, 269 KB, ~19%); the six flat files held 446 candidates of which 194 were byte-identical to a shard entry, 184 were the same entry with a different id in the heading, and only 68 were new text. Exact heading+body hashing sees all 378 of those as "different", which is how a log doubles itself.

Rule: identity for storage, dedupe and drift is the logical entry - the normalised body, or the title for a heading-only entry - and any second copy becomes an ALIAS row, not a second file. An alias preserves every reference while keeping one entry per fact. Corollary: any counter that decides whether action is needed must use the same rule as the action, or it reports phantom work forever.
