**L3413b · lpt-hub ignores all media, so a case-file image link is local-only — inbound receipts belong in lpt-books inbox/ with INDEX.tsv**

**L3400 · lpt-hub does not track media: inbound receipts and screenshots belong in lpt-books `inbox/`, and a case-file link to an image in lpt-hub is a local-only file.**

Measured 2026-10-09, recording the Weinberg payment receipt.

- `lpt-hub/.gitignore` excludes `*.webp`, `*.png`, `*.jpg`, `*.jpeg`, `*.gif` (and zip/media/archives) with one curated `external-research/.../photos/` exception. `git add <case-folder>/evidence/receipt.webp` **silently stages nothing** — the file is ignored, no error, and the case doc's link then points at a file that exists on one machine only.
- Caught by `git ls-files` on the folder **after** the commit, not by any warning. Check `git ls-files <dir>` (not `ls`) whenever a document links evidence.
- The version-tracked home for inbound paper is **lpt-books `inbox/<batch>/originals/`** with `INDEX.tsv` (item, slug, ext, bytes, sha256, intaken_utc) and a `RECORD.md` — the documented convention there ("nothing is ever edited, renamed or moved out of `originals/`"). lpt-books has no media ignore rule and already tracks `inbox/desk-2026-09-25/originals/*.jpg`.
- Also: when the artefact arrives as a chat attachment, what the harness stores is a **normalised copy**, and the sha256 quoted with the message is the hash of **that stored copy** — not of the file the human sent. Say which one it is; a hash attributed to the wrong artefact is a provenance lie waiting to be discovered.
