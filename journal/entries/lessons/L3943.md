**L3943 · Blocked fetchers: use the company firecrawl web_search (ps_action) when fccid.io/manualslib/device.report 403 and PDFs fail**

Measured 2026-10-14 while identifying two routers from photos.

What fails:
- Harness web_fetch returns 'unsupported content type application/pdf' on any vendor datasheet (Verizon CHR30A datasheet, FCC manuals).
- fccid.io, fcc.report, device.report, manualslib all return HTTP 403 / Cloudflare 'Just a moment...' to curl and to web_fetch.
- t-mobile.com support pages return JS-only shells to web_fetch (TOC only, no spec text); r.jina.ai returns an empty cache snapshot.
- duckduckgo html/lite endpoints serve a bot CAPTCHA.

What works:
1. curl the PDF, then extract with python3 pypdf (pypdf is installed in this environment; pdftotext is NOT). This got Verizon's own datasheet and 93-page user manual verbatim.
2. The company's firecrawl-backed web search: mcp__secretary__ps_action('web_search', {'query': ..., 'max_results': N}) returns FULL page text in 'snippet', not just links -- it pulled T-Mobile's tech specs, rvmobileinternet's full gateway spec tables, Reddit speed reports and eBay prices, all in one call. This is the tool to reach for when a page is JS-heavy or Cloudflare-protected.
3. Plain curl with a browser UA works on verizon.com support/FAQ pages (162 KB HTML, full FAQ answers).

Cost note: the firecrawl results are verbose; one query returned ~6k tokens of snippet. Ask narrowly, few queries, and don't paste them back into the answer.
