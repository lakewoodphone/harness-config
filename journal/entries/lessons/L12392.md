**L12392 · A bare drive root in -LiteralPath means the current directory**

## L— `Get-ChildItem -LiteralPath 'C:'` measures the CURRENT DIRECTORY, not the drive root

Found 2026-10-27 while building a parallel disk-measure harness on ZABZ-TECH. `[IO.Path]::GetFullPath('C:\')`
then `.TrimEnd('\')` yields `C:`, and in PowerShell **`C:` means "the current directory on drive C:"** —
so a loop meant to enumerate the drive's top-level folders silently enumerated the session's CWD
(C:\Users\ezabz\Code) instead, and produced a "C: (loose files)" row identical to Code's.

Effect: the five biggest trees were missing from the first pass, and the duplicate row looked
perfectly plausible (486 files, 118,664,595 bytes) because it was a real directory.

Fix, in the harness: after trimming, `if ($full -match '^[A-Za-z]:$') { $full += '\' }`. Cheap
detector: if two different roots produce byte-identical rows, one of them is not the directory you
think it is.
