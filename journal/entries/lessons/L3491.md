**L3491 · Printing to the QL-820NWB label printer: lpt-label over ssh, stdin not a path, and compare the tape length before believing a print**

**Two separate errors in one job, and both are about printing to the shop's Brother QL-820NWB.**

**1. The label printer is driven by `lpt-label` on the authority over ssh — never by Windows printing.**
Measured 2026-10-11 on ZABZ-TECH. I printed the obvious Windows way:
`Get-Content label.txt | Out-Printer -Name "Brother QL-820NWB Printer"`. The job went into the spooler
and sat at **`Spooling, Printing, Retained`** on its WSD port, and nothing ever came out. **The printer
was READY the whole time** — `lpt-label find` reported 192.168.50.60, state READY, 29 mm roll, serial
H3G354844. So the fault was the Windows print path, not the printer, and "no label came out" was not
evidence that the printer was off.

The correct path, already documented in L3444: `lpt-label` on the authority —
`cat label.json | ssh secratary-ts "lpt-label print -"`. **Before inventing any print path on this
estate, look for a purpose-built tool: `grep` for the device model in `harness-config` found it in one
call, and the journal already held four lessons about it.** My own journal search for "label printer"
returned nothing (the L3487 gap); searching the *files* for `820NWB` is what worked.

**2. `lpt-label print <path>` prints the PATH as the heading. The documented path is stdin.**
I dry-ran correctly with `print -` (stdin) and got a good render at **25.0 mm of tape**. Then I
printed with `lpt-label print /tmp/label-json.json` and a **7.3 mm** label came off the roll reading
`LAKEWOOD PHONE & TECH / /tmp/label-json.json`. A junk label, one customer's name absent from it.

**The tell was in the tool's own output and I nearly scrolled past it: the dry run said 25.0 mm, the
print said 7.3 mm.** Rule: **compare the tape length the dry run reports with the tape length the
print reports. A mismatch means you did not print what you verified — stop and look at the image the
tool saved**, because `lpt-label` writes the exact PNG it sent to the printer and names it in the same
line.

**3. After any abandoned print attempt, empty the spooler.** I cancelled the stuck Windows job before
doing anything else, because a job that wakes up later prints a stale, wrong, or clipped label onto a
customer's item with nobody watching. `Get-PrintJob -PrinterName ...` then `Remove-PrintJob`.

**4. The only honest proof that tape came out is the printer's own status page**: READY → PRINTING →
BUSY → READY, read with `lpt-label find` at about one sample per second. `brother_ql`'s `did_print` is
false by construction on this model, so it is never evidence of failure — and per L3485 a blank status
read is `unknown`, never a negative, and must never trigger a re-send.
