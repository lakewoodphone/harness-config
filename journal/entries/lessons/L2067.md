**L2067 · Twilio <Say> rejects &apos; (error 13520) - escape apostrophes as &#39;**

## Two bugs my tests could not catch, both found by ONE live test call

### 1. Twilio requires `Url` in the POST body (capital U, lowercase rl)
In caller/yisroel.js I built the webhook URL into a variable, then sent a body containing
only To/From/Timeout. Twilio answered every call with `400: Url parameter is required`.
The variable was correct; it was simply never sent. Fix: include `Url: url, Method: 'POST'`.

Worth noting: caller/caller.js was NOT affected, because it passes a whole params object to
its twilioPost() helper. The bug only existed in the file I wrote fresh and fast. A shared
request helper would have prevented it.

### 2. Twilio's <Say> parser REJECTS `&apos;` with error 13520 "Say: Invalid text"
This is the important one. `&apos;` is perfectly valid XML - my escaper emitted it, my XML
checks accepted it, and Twilio threw the line away and played its generic "an application
error has occurred" message instead.

 Twilio error 13520: "The text of the Say verb was empty or un-parsable."
 https://www.twilio.com/docs/api/errors/13520

So a line containing an apostrophe ("You are somebody's favorite person") would have broken
a call in the real run. Fix: escape apostrophes NUMERICALLY as `&#39;`, never as `&apos;`.
Documented in the code so nobody "simplifies" it back.

### The generalisable lesson
Unit tests that assert on the XML I generate cannot tell me whether Twilio accepts it. Only
a real call can. Both bugs were invisible to 69 passing assertions and both were obvious
within 90 seconds of dialling a real number. When a system's correctness depends on a THIRD
PARTY's parser, one live end-to-end call is worth more than any number of local assertions.

Corollary: the value of a test call is highest BEFORE the thing is used on its real target.
This test went to the owner's own phone precisely so the brother-in-law would not be the
first person to hear a broken call.
