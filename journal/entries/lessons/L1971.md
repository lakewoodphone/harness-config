**L1971 · A documented method whose artifact is missing is NOT a method we have - check that the referenced APK/source still exists before telling the owner we can do it**

2026-09-17. The owner pushed back on the Bachrach Galaxy job: *"i'm talking about without
paying, and we had a method, come on figure it out."* He was right, and the second half was
the real problem.

WHAT I HAD DONE WRONG: I wrote a good document. Three paths, evidence grades, a verification
checklist. But I had recommended the weakest option (pm disable) and presented the strong free
method - Device Owner + DevicePolicyManager.setApplicationHidden - as something to go and do
later. The owner wanted the method, not a survey of methods.

THE TRAP I FELL INTO, and the transferable part: our own 2025 Kyocera work documents this
method thoroughly, CITED a `LockdownController.apk`, and has a Python build script
(build_lockdown_final.py) that names its source directory. It reads exactly like "we have this".
**We did not.** Verified: no `LockdownController/` directory exists anywhere in the repo, and
no `build-tools/apktool.jar` / `uber-apk-signer.jar` either. The docs describe an artifact that
is gone. A method whose artifact is missing cannot be run, however well it is documented.

So I built it: tools/device-owner/ -> com.lpt.searchlock, ~12.5 KB, minSdk 21, three classes,
no Gradle, no third-party deps, built with nothing but the Android SDK already on the bench.
Verified by running it, not by asserting it: apksigner verify clean, `aapt2 dump badging`
shows provides-component: 'device-admin'.

RULES
1. "We have a method" means the artifact exists AND runs. Before claiming a capability, check
 that the binary/source the document cites is actually present. `Get-ChildItem -Recurse
 -Filter <the thing>` costs one call.
2. When the owner says "figure it out", build the thing. A precise write-up of three options is
 not the deliverable when one of them is free and the work to make it runnable is a few hours.
3. Trend: docs outlive their artifacts. Any repo that has survived a cleanup will have
 references to files that no longer exist. Cite-then-check, always.

BUILD GOTCHAS WORTH KEEPING (both cost real time)
- Do NOT pass android.jar as `-bootclasspath` to javac: java.lang.invoke.LambdaMetafactory is
 not in android.jar, so EVERY lambda fails with "Unable to find method metafactory". Use
 `-classpath android.jar` and let d8 desugar.
- Under $ErrorActionPreference='Stop', PowerShell 5.1 turns a native command's STDERR into a
 terminating error. keytool writes its progress banner to stderr, so keystore generation
 aborted the build even though it had succeeded. Relax the preference around the call, judge
 by exit code and by the file existing.
- In Windows PowerShell 5.1, $PSScriptRoot is NOT populated while param() defaults are being
 bound - resolve defaults in the body.
