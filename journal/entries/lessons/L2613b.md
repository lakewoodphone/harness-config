**L2613b · Repairing a generated artifact is not a fix: the guard was in one of THREE writers, and the hand-repair lasted 30 minutes**

MEASURED 2026-09-28, Yocheved's laptop. I repaired her engine's profile by hand, proved it with the
gate (exit 1 / 0 lines -> exit 0 / 581 lines), started the engine, and got a real model completion
out of it. THIRTY MINUTES LATER the same gate on the same machine said CANNOT-BOOT again.

The repair had been undone. Two scheduled tasks rewrote it: PersonalSecretary-HarnessSync at 00:33
and PersonalSecretary-HarnessUpdate at 00:27, and the profile file's mtime was 00:18.

WHY. The defect has a guard, and the guard was added in ONE of the three code paths that write the
same field. install-client-plugins.ps1 was repaired on 2026-09-17 to require a package's own
`dsh.bundle.patch` before naming it in `dsh.profile.bundles`. But:

 harness-sync.mjs:224 `bundles.push(name)` for EVERY package under packages/
 sync.ps1:149 `+ $installed` likewise

`packages/` holds bundles AND plain programs with a `bin` (`mesh-broker`, `deepseek-proxy`), so both
named `dsh-mesh-broker`, and every name in a bundle list is mounted as a patch LAYER - one name
whose package lacks the marker stops the WHOLE engine booting (dsh-app-boot:852). harness-sync runs
on her box on a 15-minute task, so the defect was renewed forever, and my hand-repair bought half
an hour.

RULES
1. WHEN YOU REPAIR A GENERATED ARTIFACT, FIX THE GENERATOR. A hand-edit of a file that something
 else writes is a temporary patch with an unknown expiry, and the expiry will be shorter than you
 think. Grep for every writer of the field before believing a repair.
2. A REPAIR VERIFIED ONCE IS UNVERIFIED. The check that found the defect must be re-run LATER, after
 the writers have had a chance to run. The second run is what found this, and it took one command.
3. "One of three code paths has the guard" is the normal state of a fleet fix, and it is invisible
 unless you count the writers rather than the readers.
4. Guards propagate by SHARED HELPER, not by copy-paste. Three copies of the same list-building
 logic meant two of them were missed. The durable form is one function that builds the bundle
 list correctly and every path calling it.
