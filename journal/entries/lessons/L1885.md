**L1885 · git merge refuses a dirty-but-byte-identical file; do the merge in a throwaway worktree, then fast-forward**

One `git merge` cannot overwrite a file the working tree has modified -- even when it is byte-identical
to the incoming version, and even after `git add`. Do ref surgery in a detachable worktree instead.

Measured 2026-09-17, laptop, merging origin/master after the authority moved:

 $ git hash-object -- scripts/lpt-recon.py -> 67d2d7a4a02e7bfb15af9b45ad59346f349db328
 $ git rev-parse origin/master:scripts/lpt-recon.py -> 67d2d7a4a02e7bfb15af9b45ad59346f349db328
 $ git merge --no-edit origin/master
 error: Your local changes to the following files would be overwritten by merge:
 scripts/lpt-recon.py
 Merge with strategy ort failed. (exit 2)
 $ git add -- scripts/lpt-recon.py # staged, index now == origin/master, diff --cached empty
 $ git merge --no-edit origin/master # SAME failure

ort's `verify_uptodate` refuses when the working-tree entry does not match what the merge would write,
and a dirty index does not clear it. core.filemode is false on this machine, so it is not a mode wedge.
The three ways out are (a) commit the work -- wrong, if it is another stream's in-flight edit;
(b) stash -- also wrong, and it hides the change from the writer; (c) do the merge where no working
tree is at stake:

 $ git worktree add --detach "$env:TEMP\hc-merge" <my-tip>
 $ git -C <wt> merge --no-edit origin/master # exit 0, creates the merge commit
 $ git -C <wt> merge-base --is-ancestor origin/master HEAD ; echo $? # 0 => the push is an ff
 $ git -C <wt> push origin <merge>:master
 $ git worktree remove --force <wt> ; git worktree prune
 $ git merge --ff-only <merge> # fast-forward in the main tree, clean

The fast-forward back into the main tree DID work with the same dirty file present, because ff only
overwrites paths that differ between old and new HEAD, and here the file's content was already the
target content. So the rule is narrow and worth remembering: the blocker is `merge`, not `fast-forward`.

Evidence: docs/mesh/97-fleet-repairs.md SS3.3.
