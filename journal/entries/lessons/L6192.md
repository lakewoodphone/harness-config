**L6192 · Google One backups are per-device and self-erase at 57 days idle; the messages figure is a mirror, not a sync**

Trigger: customer with two BlackBerry KEY2s; "the Google backups aren't synced"; the **messages
component** of the backup reads 1 MB on one phone and 300 KB on the other.

## The mechanics, all confirmed from Google's own docs on 2026-10-13

- **The messages component of a Google One device backup MIRRORS the message database on that
 handset.** Two phones = two independent backups, keyed per device. Nothing merges them. There is
 no sync, no partial top-up, and no "restore just the messages" into a working phone.
- **Restore is a SETUP-WIZARD operation.** Signing an account into a running phone restores
 contacts/Gmail/Calendar/Play — never a device backup, never messages. Post-setup cloud restore
 exists only on **Pixel 9 and later**. So "sign in and let it restore for two hours" cannot work on
 an older Android (a BlackBerry KEY2 is Android 8.1).
- **One backup per restore.** Google, verbatim: *"You can only restore data from one previous
 device."* Changing which backup you want means resetting and starting over.
- **Size tells you nothing about whether the phones agree; the DATE tells you whether the backup
 is current.** Identify each backup at `one.google.com` → Backup → **View** → select device →
 **See details**.

## The 57-day cliff — the fact that is easy to miss and destroys data

Google, verbatim (`support.google.com/googleone/answer/9149304`): **"If you don't use your device for
57 days, the data you backed up (except photos or videos) is also erased."** Turning backup off
deletes it too.

Measured instance the day this was learned: WO2608060002's BlackBerry KEY2 had sat **off the shelf
since 2026-08-21**; on 2026-10-13 that was **53 days** — **four days from its backup being erased**.
**Before assuming a dormant phone's data still exists anywhere, get its last-backup date.** A phone
in a drawer is a data-loss clock, not storage.

## The fix when two phones hold different histories

A one-way copy silently loses whatever exists only on the smaller phone. Do a **TWO-WAY merge on the
handsets**: export from A → restore onto B, then export from B → restore onto A. Both then hold the
union and both Google backups converge on their own. Tool: **SMS Backup & Restore**.

Pitfalls, all of which produce a false "it didn't work":
- Needs **SMS permission** on both handsets.
- **Reboot after restoring** — restored threads frequently do not appear in Messages until then.
- **MMS media is best-effort**: Google's own message backup carries the *text* component only, not
 photo/video, so do not promise picture messages.
- **Never run the same restore twice** — it duplicates messages.
- **Never factory-reset the phone holding the only copy.** Google Messages has no cloud archive
 (L3774).

Sources read 2026-10-13: `support.google.com/pixelphone/answer/15274034` (restore during setup, one
device only), `support.google.com/googleone/answer/9149304` (57-day erasure, per-device list).
