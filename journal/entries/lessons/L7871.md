**L7871 · The dominant failure shape here is a correct mechanism wired to nothing - and wiring one is not free**

MEASURED 2026-10-18 over one night auditing the autonomous wake system on secratary-cloud. Eleven defects were found and eight mechanisms repaired, and almost every one had the SAME shape: the mechanism existed, its logic was CORRECT, and it was WIRED TO NOTHING. Not broken - unplugged, and silently so.

The instances, each measured:
- dormant-handoff.py: 241 runs, 241 failures, 0 findings since 10-13. Two bugs (HOME=/root under cron, and a git ref this estate stopped publishing) and neither produced a distinguishable log line.
- decision-queue-stale.py + decision-answer-unconsumed.py: read a ZERO-ROW copy of the owner queue for their entire life. A blind detector prints exactly what a satisfied one prints: `quiet`.
- work-integrator.py: existed since 09-28, referenced by NOTHING (crontab 0, source runner 0) while 304 settled attempts in 7 days carried a left_over naming an unmerged branch.
- work.py lint-refs and `due`: existed, produce actionable output, run only on the claim-next `nothing-todo` branch - which cannot fire while 112 todo items exist.
- wake-cost/tier: the ceiling measured ~1 USD/day of a 23-39 USD/day real spend; the tier flipped to `conserve` on a one-dollar balance drift and halved the fan-out target from 3 to 1.
- owner_attention: 36 items surfaced from 78 candidates, 258 characters delivered.

THE RULE I NOW APPLY FIRST, before writing any fix: ask "what RUNS this, on what clock, and what does it print when it has nothing to say?" A monitor whose quiet output is byte-identical to a healthy one is not a monitor. Then check the SAME question of any mechanism I am about to wire up - because I wired work-integrator.py into a cron it had never had, and its first act was to manufacture three work items that did not exist (a shallow clone makes `merge-base --is-ancestor` return false for a direct parent). Wiring a dormant mechanism is not free; it needs the same proof as new code.

THREE ANTI-PATTERNS I COMMITTED AND HAD TO CORRECT, all worth remembering:
1. I repeated a child audit's claim that deadline reminders were being deleted. FALSE: 559 sent, 0 past-due pending, delivery punctual to the second. My own confirming check was a false NEGATIVE - I matched on the notification's "Reminder: " prefix and concluded no durable row existed. A negative from a string match is only as good as the string.
2. I nearly retracted three REAL ledger items (536/537/538) because a sibling (533) had been false. Verify each with its own DoD command. A depth reading is a reading with a timestamp, not a property of a repo.
3. I spent three rounds fixing one work.py defect because I reached for a database handle instead of finding the resolver already in the same file 400 lines up (`resolve_oq_db`). Before adding a lookup, grep for the existing one.

AND THE ONE ABOUT HONESTY: on the third attempt at work.py I compiled two patches that did not work. The tempting move was to install the compiled file and report a fix. A change that cannot be shown to change behaviour is not a change - it is a no-op wearing a commit message, and the next session inherits a false belief. I deleted the patched copies instead.

FULL EVIDENCE: harness-config/docs/mesh/178-wake-autonomy-audit-20261018.md (23 sections, every claim carrying its command) and handoff H7146.
