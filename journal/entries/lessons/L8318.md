**L8318 · A detached child dies with its ssh session; a hung sync looks exactly like a running one**

Measured 2026-10-18 on ZABZ-TECH, twice in one hour.

1. Start-Process python scripts/sync.py ... -WindowStyle Hidden from an ssh session wrote a 0-byte log and left no process: the child dies with the session, so it never ran at all.
2. Replaced with a Scheduled Task (the mechanism the laptop already uses). The task started, created \~/.usearch/usearch.db\ (30 MB from an earlier foreground run), and then sat at **6.8 s CPU for seven minutes with the database file unchanged**. That is a hang, and from the outside it is indistinguishable from a long first walk.

What I did about it: stopped the task rather than calling it running, and left the diagnosis to the next round with the adapter run in the FOREGROUND, where its own stderr is visible. A foreground run of one small source on the same machine (--source journal) succeeded in 25 s and wrote 4,014 documents, so the install is good and the fault is in the full run, not the deployment.

Rule worth keeping: **a background job's liveness is CPU delta plus a file's mtime, never the existence of a pid.** Check both twice, a minute apart, before saying a build is progressing.
