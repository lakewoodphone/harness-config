**L3830 · E4610 MMS test fully automated: the send is keycode 23, not a button - and one handset delivers 3/3 at ~10 s as a working control**

**L · 2026-10-15 (late) · ZABZ-TECH · The E4610 outbound-MMS test is now FULLY AUTOMATED - and the one handset tested today delivers 3/3 in about 10 s**

**What was built.** `_scratch/mms-ab/Invoke-MmsAutoTest.ps1` runs the whole loop with no human in it, per round:
enumerate the device → read the state fingerprint → push a JPEG and register it with the media store → launch
Message+ compose pre-addressed and pre-attached → **press send** → capture the MMS network timeline → ask Twilio
whether the picture arrived and when → verdict + JSON record. `-SelfTest` covers the parsers (15 assertions,
green). Runs to `auto-runs/`.

**The one non-obvious thing, and it cost several attempts: the send is a hardware key event, not a button.**
The bottom bar in Message+ compose reads `Abc | Send | Options`. **That bar is a LABEL for the physical soft keys
— tapping it does nothing**, and uiautomator exposes no send node, so any "find the send button and tap it"
approach fails. The send is **`input keyevent 23` (DPAD_CENTER)**, the centre soft key. Verify a send by watching
the MMS network request count rise, not by looking for a button:
`logcat -d | grep 'requestNetwork.*legacyType=2'`.

**Other traps measured today, all of which cost real time:**
- `adb devices -l` carries `product:… model:… transport_id:…` AFTER the state — a regex anchored at end-of-line
 matches nothing, and a one-element result then throws on indexing. Never anchor there; always wrap in `@()`.
- `return ,$array` from a function plus a caller-side `@()` **double-wraps**: a 2-element list becomes 1 element
 holding an array. Use a plain `return` and wrap at the call site only.
- A function parameter declared `[string[]]` with `[AllowEmptyCollection()]` still rejects a single **empty
 string**; add `[AllowEmptyString()]`.
- `screencap` returns **1024 bytes of black** while the display is asleep. Wake it first
 (`input keyevent KEYCODE_WAKEUP`); a 1024-byte pull is a sleeping screen, not a broken capture.
- `content://mms` and `content://carriers` are unreadable from shell on Android 7 (SecurityException).

**Keeping ADB alive for a long session.** `disabled-by-design`-looking 60-minute lockouts are just the tech-mode
window. Extend it with the repo's own tool:
`python -m lpt.cli enable-tech-window --serial <s> --duration-minutes 1440 --test-mode`
**Use `--test-mode`** — that path is capped at 24 h in both the committed and working-tree builds
(`cli.py:116`, `TechModeManager.java:36`), whereas the *normal* cap is 60 min at HEAD. Confirm from the device:
`TechModeManager: Technician mode enabled via broadcast_enable` in logcat.

**Result on the one handset tested (serial 616450266, E4610, Verizon 311480, Message+ default):**
**three out of three delivered**, latency **9.9 s / 9.6 s / 10.9 s**, MMS network hold ~4.4 s, **1–2 orphaned
VZWAPP agents** (healthy; the failing handset earlier today had **10**). So this handset is a working control.
By contrast, the customer's handset (615387849) delivered **0 of 0** across three SIMs today — every send attempt
died, and it accumulated MMS connections instead of releasing them.

**What that does and does not prove.** It does **not** prove the carrier outage is over: the two handsets are on
**different line numbers** (+18482245096 vs +18483267693 / +19086927704), so a working line beside a broken one is
exactly what a per-line fault looks like. It **does** prove the test method is sound and that a plain E4610 with
Message+ as default can send a picture on this network today. The decisive experiment is unchanged: **a handset
that is failing, run against this harness, with this working unit as the control** — which is now one command.

**Transferable rules:**
- **On a device with soft keys, the on-screen bar is a label.** Interactive control is a keycode. Find it by
 probing keycodes and detecting the *effect* (a network request, a state change), never by looking for a widget.
- An automation that "works" once is not automated. Three green rounds plus a `-SelfTest` on the parsers is the
 minimum bar, and every bug above was found by running it, not by reading it.
- Measure the control before blaming the population. One working handset turns "everybody is broken" into a
 comparison.
