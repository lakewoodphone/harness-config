**L1761 · LPT customer comms: a runbook and a generated flows index now exist - read them before rediscovering anything**

Three things were missing on 2026-09-16 and are now built. Use them instead of re-deriving.

1. lpt-hub/docs/customer-operations/CUSTOMER-SMS-RUNBOOK.md - the whole end-to-end for answering a customer by text: the voice rules with real examples, the exact 4-command send path (scripts/send-lpt-sms.py preview then --send, --message-file, --no-signature), the traps, what delivery evidence exists, and how to record the send. Creating it replaced a ~10-tool-call discovery walk.

2. lpt-hub/docs/customer-operations/FLOWS-INDEX.md - GENERATED index of every flow/SOP/knowledge-base doc (59 docs). personal-secretary-mvp/docs/README.md had advertised this file since July and it did not exist, with a wrong relative path ('../lpt-hub/...' from personal-secretary-mvp/docs resolves to personal-secretary-mvp/lpt-hub, not the sibling repo). Both fixed. Regenerate with 'python lpt-hub/scripts/build-flows-index.py'; '--check' exits 1 when stale. Never hand-edit it. First version self-referenced and was permanently stale - the generator now excludes README.md and FLOWS-INDEX.md and does not recurse at the top level.

3. scripts/send-lpt-sms.py now prints a CAUTION block when it auto-appends the agent signature. agent_sms_signature defaults to 'Daniel' (app/config.py L399) and Daniel is a REAL LPT staff member who signs his own customer texts, so the default is intentional - but a non-Daniel message that omits --no-signature goes out signed as him. Verified by dry run in both branches.

DATA SOURCES, checked live 2026-09-16:
- sms_log (authority DB) = the LIVE send ledger, 859 rows, newest 2026-09-15. Best source of real sent-customer text.
- dialpad_ui_message_body_row = richest voice corpus but STALE, last capture 2026-06-19. Tone reference only, never a did-we-send-it record.
- The table list in the ps_db_query MCP tool description names ~25 of 200+ tables. Discover real ones with: SELECT name FROM sqlite_master WHERE type='table' AND name LIKE '%message%'
- ps_db_query is intermittently flaky: three plain SELECT COUNT queries returned an error containing 'locking protocol' in the same minute that identical queries succeeded. Retry once; never report a number from an errored query.

KNOWN GAP (journal pain P217, still open): scripts/send-lpt-sms.py writes nothing to sms_log, so script sends are invisible to cross-process duplicate suppression and to the send audit trail. Deliberately NOT patched on 2026-09-16 - it is a live customer-send path and a fix could not be end-to-end tested without sending a real message. Fix = have the script call the same logging helper the action path uses, then assert it with a monkeypatched test.
