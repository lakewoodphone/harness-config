# L-new — A published artifact is not the repository; a demo page must never carry a real person's number

Two failures in one, both measured on 2026-09-17.

**1. The repo looked clean and the live page was not.** The Weinberg WhatsApp
demo (`lakewoodphone.github.io/whatsapp-signup/`) is published by `publish.py`
from a **temp build dir**, so the repo's own committed `index.html` still holds
the `BUSINESS NAME GOES HERE` / `10000000000` placeholder. `git status` was
clean. Any review of that repository — mine included, if I had stopped at the
repo — passes. The defect existed **only in the served bytes**.

The served page carried `phoneE164: "18482857640"`, which is **Abraham
Abramczyk**, a real customer of the shop (`cases/abramczyk-sd-card-8482857640-2026-08-25.md`:
he brought Savitz's SD card in and paid the $80). So the public demo handed
anyone who tapped it a WhatsApp chat with a real customer, and its
`contact.vcf` saved that customer into the tapper's phone as "Demo Business".

**Rule:** when something was published, read the **live** URL's own config/bytes,
not the source it was built from — and when the build happens in a temp dir, the
repo is not evidence about the artifact **at all**. `curl`/`Invoke-WebRequest`
with a cache-busting query string, then assert on the value you expect. This is
the same shape as the stale-database failure: local view disagrees with the
authoritative one, and the local view is the one that lies.

**2. "Demo" was treated as a label, not a constraint.** The same case file that
refused to put an unconfirmed Weinberg number on a page — *"a wrong number on a
customer-facing page would send strangers to a stranger's WhatsApp"* — had a demo
of that page doing exactly that. The number was almost certainly grabbed from
`tools/case-index/README.md`, where `848-285-7640` is the worked example. A real
number used as test data is still a real number.

**Rule:** a demo/example instance gets a number from the **555-0100…0199** range,
which is reserved for fiction and cannot ring or message anyone. Verified it does
not degrade the demo: `wa.me/18455550100` still serves *"Chat on WhatsApp with
+1 845-555-0100"* with the message pre-typed. Now enforced in code —
`publish.py --demo` refuses any number outside that range, tested three ways
(refuses `18482857640`, accepts `18455550100`, and a real number still publishes
without `--demo`).

**Corollary on force-push:** repointing the demo did **not** use `publish.py`'s
`git push --force`. Cloning the demo repo and committing on top (`9c81800` on
`931bdc0`) produced the identical live page with the history intact. Machine-
generated history that "means nothing" is still not free to destroy, and the
fast-forward took one extra command.

**Evidence:** lpt-hub `c95ade3ca`; demo repo `9c81800`; live check = `phoneE164:
"18455550100"` present, `8482857640` absent, served `contact.vcf` =
`TEL;TYPE=CELL,VOICE:+18455550100`.
