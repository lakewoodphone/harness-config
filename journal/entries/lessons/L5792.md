**L5792 · The Waze fleet has one source of truth at /root/code/waze-fleet on secratary-cloud - resync in three reads, and read its journal citations on the authority**

The Waze device business finally has one source of truth, and re-deriving it is now a defect:

- **`/root/code/waze-fleet` on `secratary-cloud`** (git `master`, `a16253c` on 2026-10-16) covers the DRN
 gemach fleet, the LPT product fleet, the shop counters, the profiles, the CLI and the four research
 tracks. **Resync in three reads** — `00-START-HERE.md` → `INDEX.md` → `AUTHORITY.md` — then only the
 section you are about to touch. `AUTHORITY.md` names the four candidate homes this replaces and why each
 was not it; do not re-litigate that.
- **Where each truth lives:** the fleet is Postgres db `wazemdm` on `waze-mdm-01` (`ssh hetzner`) — **not**
 `authority.db`, which holds 2 Waze rows and is authoritative for nothing fleet-wide. The profiles exist
 in the repo **and** in `/opt/waze-mdm/profiles/`, and **the host copy is the fact** — the served kiosk
 profile differs from git in six restriction keys, so **any rebuild from git silently reverts the fleet.**
- **A journal id cited in the tree may not exist on the machine you are reading from.** `journal.py show
 D3210` → `no entry` on ZABZ-YOGA, and the same id reads fine on `secratary-cloud` (4,264 local entries vs
 4,171 on the authority at the same hour — different content, not lag: open pain `P4185`). Read a citation
 where it lives before calling it wrong.
- **A critical queue row can read `pending` while the owner has already answered.** Row 510 sat
 `pending|critical` from 2026-10-14 until 2026-10-16 because the row's write path was contended when he
 spoke; his answer existed only in journal `D3210`. When a document's own text says "the row and the entry
 disagree", the entry wins — **ask what writes the field you are reading.**
