**L1950 · Prefiltered phones arrive with DCS disabled and unknown sources off; the CLI only fixes DCS**

Evidence: E4610 serial 615765621, 2026-09-17. Filtered by our partner Avi Shapiro's setup before it
reached us. On arrival `pm list packages -d` listed `com.android.defcontainer` (DCS disabled = every
APK install fails with INSTALL_FAILED_INTERNAL_ERROR / "Failed to bind to media container service")
and `settings get secure install_non_market_apps` was 0. No foreign `com.lge.*` / foreign
`com.android.cts.*` packages were present; `pm list packages -3` was empty.

What the tooling already covers: `cli/lpt/deployment/cleanup.py` runs in the CLI `pre_install` phase
and re-enables DCS plus removes the known `com.lge.voiceaccess` / `com.lge.oid.cts.*` conflicts;
`cli/lpt/adb/installer.py` retries past INSTALL_FAILED_SHARED_USER_INCOMPATIBLE by locating and
uninstalling the package that owns the conflicting sharedUserId. Receipt line from this run:
`pre_install: DCS re-enabled | Carrier PTT disabled: com.verizon.pushtotalkplus`.

What it does not cover, so do it by hand at intake:
`settings put secure install_non_market_apps 1`, `input keyevent KEYCODE_WAKEUP` (a sleeping handset
stays asleep through staging), `settings put global stay_on_while_plugged_in 7`.
Optional explicit preflight when foreign packages are present:
`scripts/deployment/prepare-third-party-device.ps1 -DeviceSerial <serial>`.
