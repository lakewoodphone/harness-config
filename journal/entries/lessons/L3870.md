**L3870 · SELECT text FROM chunks WHERE doc_id=? is a corpus scan - and the 482,596 unmapped documents had no chunks at all**

**`SELECT text FROM chunks WHERE doc_id=?` is a scan of the FTS5 table — and the 482,596 documents I blamed it on had no chunks at all.**

Two errors in one afternoon, both caught by counting rather than by reasoning.

**1. The scan.** `chunks` is an FTS5 virtual table and `doc_id` is `UNINDEXED` on it, so that query is
`SCAN chunks VIRTUAL TABLE` over the whole corpus: one document took long enough that the first
backfill run sat at **14 % CPU for ten minutes and sent no chunk**. Through `chunks_meta` (a real
table, indexed on `doc_id`) and a rowid seek into the FTS table it is **0.1 ms/document**, measured
over 40 journal documents. Rebuilding a document's text was never expensive; asking for it wrongly
was.

**2. The wrong cause.** 482,596 of 1,354,955 documents had no `chunks_meta` row, so I concluded the
mapping table was incomplete and wrote a repair tool whose docstring said so — and pushed three
commits saying it. The tool's own first run falsified it: **6,520,381 chunks scanned in 189 s, zero
rows inserted**, documents mapped unchanged. Every chunk already had its mapping; the documents
without one have **no chunks at all** (empty files, `.lnk`, images, binaries), and the stall was the
fallback running *for every one of them*.

What made the difference was running the thing I had built instead of believing the count that
motivated it. What made it costly was that the wrong reasoning was already in two commit messages and
a runbook trap — corrected by `b0d9109`, which keeps the wrong version on the record deliberately.

The rule this leaves: **a count of missing rows is a symptom, and it has at least two causes that look
identical from the outside** — a missing mapping, or a mapping that is correctly absent because there
is nothing to map. One query settles it (`n_chunks`), and it should be asked before the repair is
written.

Refs: `scripts/backfill.py` `doc_text`, `scripts/repair-chunks-meta.py`, `docs/OPERATIONS-ESEARCH.md`
trap 9, `docs/SEARCH-AUDIT-2026-10-19.md` §3.5.
