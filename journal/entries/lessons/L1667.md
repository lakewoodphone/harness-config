**L1569 · Customer price lives in the owner's formula, not in the case file (Gutterman, 2026-09-15)**

Evidence: Gutterman case file (docs/customer-operations/cases/screen-replacement-dell-lp140wfh-gutterman-2026-09-01.md)
and its sync record carry only OUR cost ($65.84 = $49.99 panel + shipping) and "quote_status: ORDERED".
There is no customer-facing price anywhere in them. Asked on 2026-09-15 "how much does Gutterman owe for
the screen replacement", the number had to be derived, not looked up.

The shop's customer price is produced by the owner's formula, documented in two places:
- cases/hp-15-fd0095wm-shimmy-weichbrud-2026-09-03.md:71 -> "Owner formula: cost x 1.4 + $65
 = $51.99 x 1.4 = $72.79 + $65 = $137.79 -> rounded to $135" (round down to the nearest $5)
- cases/shlesinger-thinkpad-x201-screen-flicker-2026-09-15.md:141 -> "the shop's own screen formula
 (cost x 1.4 + $65, as used on the 15ABR8 case)"
Applied to Gutterman: $49.99 x 1.4 = $69.99 + $65 = $134.99 -> $135.

Rule: for "what does <customer> owe", read the case file for the PART cost, then apply cost x 1.4 + $65
rounded down to the nearest $5. Do not expect a price in the record, and do not confuse our $65.84 order
total with the customer price. Where the price matters, write it INTO the case file so the next session
can read it instead of recomputing it.
