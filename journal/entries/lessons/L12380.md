**L12380 · Absence checks on a removable mount: re-read /proc/mounts in the same command**

On 2026-10-26 an ntfs3 mount at /mnt/cust (customer SSD sde3, serial 220343801113) vanished between an rm and the following find. Every 'test -e' and 'ls' after that returned No such file for paths that still existed, because /mnt/cust had reverted to an empty directory on the root filesystem - so the check answered 'gone' regardless of truth. Two rules follow: (1) in the SAME command as any absence verification on a removable mount, re-read /proc/mounts for that mountpoint and fail loudly if the entry is missing; (2) do not narrate the cause of a vanished mount until the block layer is read - here the only kernel line was 'sde3: Can't mount, would change RO state', the volume passed 'ntfsfix -n' clean, and two later mounts were stable through writes and a 16-minute ENOSPC fill, so the drop was never explained. Also: 'grep -c sde /proc/mounts' returned 1 by matching nsdelegate in the cgroup2 line - anchor device greps as grep -E '^/dev/sde' or the answer belongs to a different question.
