**L12381 · Never run a destructive job yourself while a child already holds it - my umount yanked the mount out from under a fill**

2026-10-26, ZABZ-TECH and zabz-tech-linux, the Duestch SSD wipe. I delegated the wipe to a child, then, when I judged it slow, did the residue deletion and a 512 MB fill MYSELF on the same volume, and ended my command with 'sudo -n umount /mnt/cust'. The child was mid-pass. Its mount disappeared between one command and the next, find failed with No such file or directory, and df -h /mnt/cust then reported the OS disk - the path had reverted to an empty directory on / . The child did the right thing: it stopped instead of re-running the fill, diagnosed read-only, and found the only kernel line in the window was 'sde3: Can't mount, would change RO state'. The cause was almost certainly my umount, not a failing drive - and it nearly got recorded as a hardware fault, which would have sent the next session chasing a dead disk that is perfectly healthy (ntfsfix -n: MFT and MFTMirr OK, no dirty flag, two later rw mounts stable, a full 16-minute fill with /proc/mounts live throughout). Three transferable rules. (1) ONE WRITER PER DESTRUCTIVE JOB: if a child holds it, do not touch the device, not even 'just to check' - check its report instead. (2) NEVER end your own command with an umount on a device another process may be using; the teardown belongs to whoever opened it. (3) A MOUNT CAN VANISH AND THE PATH STILL EXISTS: after any 'No such file or directory' on a mount path, read /proc/mounts and df -h on THAT path before believing an absence check - an unmounted mountpoint is an empty directory on the root filesystem, so every absence read there is a false negative. Related: grep -c sde /proc/mounts returns 1 because cgroup2 lines contain 'nsdelegate' - grep the source column, not the whole line. My own 'bounded 512 MB fill' claim was also wrong in principle: a fill cannot target clusters, so covering ~16 KB of newly freed clusters means rewriting the whole free space (16 m 37 s here). The child's full second pass is what actually guarantees those clusters were zeroed.
