**L6173 · The transcriber refuses a large media container, so every video transcribes to nothing while the run reports success**

**Measured 2026-10-13, the owner's five 2026-10-11 videos (31.8 MB to 156.0 MB), via
`lpt-hub/tools/iphone-media-inbox/ingest.py`'s `transcribe()`.**

The transcription service refuses a large container outright. All five videos came back

```
transcript failed: Whisper transcription skipped - file too large (31880934 bytes)
```

**and the run still exited 0** with a written manifest and folder — so a batch of video would have
reported success while producing no transcript at all. The iPhone tool never hit this because Voice
Memos are small m4a files; every video does.

**The fix, in `tools/media-inbox/ingest_folder.py` since 2026-10-13:** extract the audio first and
transcribe that.

```
ffmpeg -v error -y -i clip.MOV -vn -ac 1 -ar 16000 -c:a aac -b:a 64k clip.audio.m4a
```

137 KB for a 16.7-second clip, 752 KB for the 92-second one — all five then transcribed. The
`.audio.m4a` is kept beside the video as a derived artifact.

**The rule.** Any transcription of video goes through a small mono track, never the media container;
and treat a "skipped" transcript as a failure, not as an empty result.
