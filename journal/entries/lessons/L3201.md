**L3201 · A handoff that names a file which was never written is worse than naming nothing**

WHAT HAPPENED: two handoffs — `lpt-hub/research/miscellaneous/SESSION-STATE-2026-10-01.md` §8 and
`play-tonight.md` §6 — cited two `personal-secretary-mvp` docs as written and pushed:
`docs/entertainment/projector-dangbei-atom.md` and `docs/entertainment/couch-gaming-setup.md`.
NEITHER EXISTS. Not in the working tree, not in any ref of the repo (`git log --all --name-only --
'docs/entertainment/*'` returns only `eliya-tv-show-preferences.md` and
`tv-projector-research-2026-08-20.md`), and not on the authority (`ls ~/personal-secretary-mvp/
docs/entertainment/` on secratary shows the same two files). They were named in a handoff and never
written.

WHY IT HURTS: a missing pointer is a dead end the reader can see. A pointer that LOOKS real but
resolves to nothing costs the reader a search, and — worse — it makes the rest of the handoff read
as verified when part of it was never checked. This system's most expensive past failure was
believing a confident claim that had not been checked; an unresolved path is that failure in
miniature.

RULE: before writing a path into a handoff, resolve it. Check the file exists in the tree you are
about to tell the next session to read, on the branch you are about to tell it to read from. A path
is a claim, not a note.

EVIDENCE: 2026-10-01, ZABZ-YOGA. Repo-wide ref scan plus a read of the authority's checkout.
