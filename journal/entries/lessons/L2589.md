**L2589 · Measure real layout with a loopback server: the Playwright MCP cannot read files and blocks file URLs**

Claiming "the card field is usable at 1920x1080, 1440x900, 1024x768 and iPhone 15" needs a real browser, and getting one is less obvious than it looks.

WHAT DOES NOT WORK (all verified 2026-09-25, ZABZ-YOGA, playwright MCP):
- browser_tabs new url=file:///... -> 'Access to "file:" protocol is blocked'.
- browser_run_code_unsafe with require('node:fs') -> 'ReferenceError: require is not defined' (the Playwright server runs as ESM).
- browser_run_code_unsafe with await import('node:fs') -> 'ERR_VM_DYNAMIC_IMPORT_CALLBACK_MISSING'. The sandbox has no dynamic import callback.

So the Playwright process can neither read your files nor load them from disk.

WHAT WORKS: write a ~40-line dependency-free static server (node:http + createReadStream), bind 127.0.0.1, run it as a MANAGED BACKGROUND JOB, and serve BOTH the harness page and the app's real build output (map /assets/* to frontend/dist). Then browser_tabs new to http://127.0.0.1:<port>/harness.html. Link the app's OWN compiled stylesheet (frontend/dist/assets/index-*.css). Do NOT use a Tailwind CDN: then you have proven the CDN's CSS rather than the app's, and you have added network to a run whose whole point was no outbound traffic.

TWO TRAPS INSIDE THAT:
1. Windows path guard. Comparing join()/normalize() output (backslashes) against a forward-slash constant silently 403s every request. normalize() BOTH sides. I lost a cycle to this.
2. PROVE the stylesheet applied before believing any number. My first probe was getComputedStyle(btn).display === 'inline-flex' and it returned FALSE while the sheet was loaded fine (a later rule wins on display). The numbers still looked plausible - 44px heights, no overflow - which is exactly how a plausible wrong reading gets reported. The correct probe was a utility only that sheet defines: min-h-[44px] resolving to 44px. An empty result is not evidence, and a plausible number from an unproven harness is worse.

RESULT once fixed, measured on the app's real CSS: all four viewports, no horizontal overflow, card field inside the viewport, every button at least 44px tall.
