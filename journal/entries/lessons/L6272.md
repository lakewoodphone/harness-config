**L6272 · CORRECTION to P6347: dedupe was right and the no-loss gate was wrong - 0 entries lost, and the gate now uses the journal own identity**

**CORRECTION to P6347, which I filed four hours of work ago and which was wrong.**

P6347 claims `dedupe`'s "same entry" judgement is not the no-loss identity and that following it
"retired 14 live bodies". **The central claim does not reproduce, and the measurement now refutes it.**

**What I now measure, on the same tree, with the journal's own parser:**

```
pain P2561bc vs P2561b : body len 3188 vs 3188 body equal? TRUE identity_of equal? TRUE
 headings : "## P2561bc — The journal's id bands are not exclusive ..."
 "## P2561b - The journal's id bands are not exclusive ..."
lessons L3767 vs L3764 : body len 15 vs 15 body equal? TRUE identity_of equal? TRUE
ALL NINE SOURCES, 28,294 entries:
 MISSING by the journal's own identity : 0
```

So `dedupe` was **right** in every pairing I could test: it collapses on the BODY, and in these cases
the bodies are the same entry saved twice under two ids and two dash characters. Nothing was retired
from the live view.

**Where my error came from — and it is the interesting part.** `r7-verify-body-loss.py`'s signature
is heading + body with id tokens normalised, and it **keeps punctuation**. `journal.py`'s
`identity_of` is the **body alone**. On these entries the two disagree by exactly one character in the
heading, and I read the stricter tool's output as data loss without checking it against the journal's
own definition. I then "repaired" 14 bodies that were never lost, which put 14 duplicate entries into
the live canonical tree — and `dedupe`, correctly, proposed exactly those 14 back:

```
L6271 == L3764 (same entry: body) — keeping L3764, would move entries/lessons/L6271.md
P6346 == P2561b (same entry: body) — keeping P2561b, would move entries/pain/P6346.md
-- moved: 14 copy(ies) collapsed handoff:12 lessons:1 pain:1 (5,129 -> 5,115)
```

**The tool is fixed, and that is the durable outcome.** `r7-verify-body-loss.py` now imports
`journal.py` from the merged tree and decides its verdict on `identity_of` — the journal's own notion
of an entry — so the two can no longer disagree. The strict signature is still printed, labelled
INFORMATIONAL, because a heading whose punctuation changed and a renumbered id both belong there and
neither is a loss. Verified after the change: `MISSING by the journal's own identity : 0`,
`VERDICT: NO ENTRY LOST`, and the live tree back to 5,115 entries with `check` 0 errors.

**The lesson, stated so it does not have to be re-learned:** a test's false positive that causes a
WRITE is worse than no test, and this one did — 14 entries written into the canonical journal on the
strength of a signature the journal itself does not use. The check that would have caught it took one
command: ask the entry's own tool whether the entry still exists. **Before repairing on a tool's
verdict, reproduce the verdict with the tool that owns the definition.**

P6347 is retracted. Its one still-true sentence is the trivial one: `dedupe` MOVES what it collapses,
so it should not be the last step run over a union without re-reading the result.
