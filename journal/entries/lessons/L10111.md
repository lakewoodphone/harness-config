**L10111 · dsh-update describes an install layout the estate no longer uses: pin names a vendored prefix while both machines run ~/.dsh/engine, dshInstall is unset, and the switch's preflight JSON is not kept**

MEASURED 2026-10-19 (ZABZ-YOGA + desktop-ts) while pulling the whole DSH-update history for the owner.

1. THE PIN NO LONGER DESCRIBES WHAT RUNS. On ZABZ-TECH `dsh-update status` prints PIN 0.2.0-rc.2 at
 `dsh-update\vendor\prefix\0.2.0-rc.2\...\bin.js`, then ENGINE (measured now) at
 `C:\Users\ezabz\.dsh\engine\node_modules\@deepseek-ai\dsh\lib\bin.js`, version 0.2.0-rc.2,
 "located via running dsh process command line". Both machines run ~/.dsh/engine (YOGA pid 11640,
 TECH pid 8068, both `... .dsh\engine\node_modules\@deepseek-ai\dsh\lib\bin.js web --port 3099`).
 `pin.json` also reports contract sha256 MISMATCH and tree sha256 MISMATCH.

2. `dshInstall` IS ABSENT FROM `multi-window/windows.json` ON BOTH MACHINES (read via ConvertFrom-Json;
 YOGA's key list has no dshInstall). `dshw.ps1:305-309` says it "names it explicitly on every
 machine" and Resolve-DshBin probes dshInstall BEFORE ~/.dsh/engine. So `promote` - the one verb that
 writes dshInstall - would re-point the launcher from ~/.dsh/engine to a vendored prefix at the next
 boot. That is an install-tree swap, not a version bump, and the vendored tree does not carry the
 hand patches (P3170) that the current engine carries.

3. THE SWITCH DOES NOT KEEP ITS PREFLIGHT JSON. `switch-engine.ps1:1218` writes it to
 `$env:TEMP\switch-engine-preflight-<guid>.json`; on ZABZ-TECH none survives, so a decision cannot be
 re-read after the fact. `state/history/events.tsv` row 2026-10-05T04:06:35Z records
 `preflight ... NO-GO ... settings-effective (the engine's own report)=FAIL`; cli.mjs:1664 prints
 `FAIL` only when the guard is `ok=false AND blocking=true`, and switch-engine.ps1:772-777/1267-1268
 must then refuse. The next row is `promote ... ok` at 04:06:37.997Z and
 `state/switch-20261005T040523Z/PRE-STATE.json` was created 04:06:37.698Z. So either the copy that
 ran differed from HEAD or the switch has a hole; NOT ESTABLISHED, and it cannot be settled from the
 record because the JSON is gone. Fix that makes it settleable: write it under state/logs/.

4. THE UPDATE PIPELINE PREDATES THE INSTALL LAYOUT. Last commit touching `dsh-update/lib|tools` is
 2026-10-04 (`4ac86c85d`); the engine moved to ~/.dsh/engine on 2026-10-08
 (TECH `dsh\package.json` mtime). `~/.dsh/engine/package.json` on YOGA carries the floating range
 `"@deepseek-ai/dsh":"^0.2.0-rc.2"` (mtime 2026-09-30) - the same shape that let `npx` float
 0.1.5-rc.1 to 0.2.0-rc.2 on 2026-09-30 and cost six failed boots.

5. NEWER VERSIONS EXIST AND NOTHING IS ANALYZED: `status` reads `latest=0.2.1-rc.2`, 7 published
 versions newer than the pin, every one `analyzed=false verified=false fetched=false`.

6. THE PATCH REGISTRY IS STILL MISSING ON THE PRIMARY MACHINE: `node
 multi-window/tools/patch-window-blank-isolation.mjs --check` exits 0 on ZABZ-YOGA ("APPLIED") and
 exits 1 with MODULE_NOT_FOUND on ZABZ-TECH, whose checkout is on branch
 `mesh/broker-host-cloud-default-20261013` (c6106a29) while YOGA is on 2a049bbfa.
