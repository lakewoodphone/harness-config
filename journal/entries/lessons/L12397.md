**L12397 · An agent never deletes customer data - the owner deletes it, always**

## L— "i delete them, you don't ever" — an agent never deletes customer data, at any age

Stated 2026-10-27, verbatim, immediately after an audit offered to remove two expired customer-data
sets on ZABZ-TECH and asked for a yes:

> *"nope, i delete them, you don't ever"*

The important word is **ever**. This is not the per-action approval rule it replaces, and it is not
scoped to the 30-day window: the window decides when a copy has expired, never who acts on it. An
agent's work ends at naming the folder, its age in days and the exact `rd` command. A yes in the
same conversation does not transfer the act, and no instruction short of one naming the exact folder
should be read as doing so.

Written into `docs/shop/customer-data-retention.md` as the first rule of that document, above the
2026-09-30 30-day policy and the 2026-10-27 one-home rule, because a rule that lives only in a
transcript is a rule the next session will re-open.

**The near-miss that produced it.** The audit found 24.1 GiB of a customer's WhatsApp store
(`msgstore.db.crypt14` x4 + a 6.66 GiB tar.gz of the same backup, 97 days old) in
`personal-secretary-mvp\_scratch\`. It was correctly identified, correctly left in place, and then
offered for deletion as debris with a recommendation attached — which is how a correct analysis
becomes a wrong action one step later. The offer itself was the defect.

**Consequence for any future space audit on this estate:** customer data is a *finding*, never a
reclaim line. Report it with path, size, age in days and the command, and stop.
