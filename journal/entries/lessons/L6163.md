**L6163 · A classifier's unknown branch and a task's empty result are both silence wearing the costume of a decision**

Two mechanisms, both measured on the live authority database and both in `personal-secretary-mvp`, that together let a vendor's approval deadline pass unmentioned to the owner (full incident: the pain entry written the same session, "A counterparty's approval deadline reached the inbox, was classified twice, and was told to nobody").

**1. In an ordered classifier, whatever the subject fails to match is a decision.** `app/services/email_intake.py::classify_message()` is a chain of regex rules ending in a terminal fallback that returns `{"category": "review", "priority": "p2", "needs_owner": 0, "confidence": 0.4, "reason": "default"}`. `needs_owner=0` there is not a finding — it is the absence of a rule, and it renders identically to "nothing to do". Measured: an email whose subject was `Approval Needed #828330` reached exactly that branch. So did the second one, by a different route — `_ORDER_RE` contains the alternative `order\s+#`, so `Final reminder Review Proof for order #828330` matched rule 8 and became `category="order"`, `needs_owner=0`, `reason="order/shipping"` — **a printing deadline classified as a shipping notice.** When a rule table's coverage is its whole safety story, the tests must assert the *specific* dangerous subjects (approval, proof, deadline, action required), and the fallback must be visibly different from a confident negative.

**2. A task row cannot be trusted because `status='done'`.** `tasks` 27694 was created 2026-10-06T14:32:46.093Z because a proof had to be approved, delegated 14:37:07 to `dept_mashgiach`, and marked `done` at 15:38:26.853Z with `delegations.result_summary=''` — 66 minutes, no artifact, no approval, and zero rows in `activity_log` beyond `task_delegated`. Every downstream reader (briefing, coverage sweep, a future session) sees a completed task and a closed loop. **The check for whether work happened is the result text and the external artifact, never the status column**; and a task whose title states a deadline should be closable only with something that names what was done.

**And the corollary that generalises past this file:** all four failure points were individually "handled" — the email was classified, the task was created and delegated, the notification gate fired. Each component reported success while the outcome was that the owner was never told. When several systems each own a slice of "tell the owner", the slice nobody tests is the handover between them. The test that matters is not "did triage run" but "did the owner receive something".

**Related, same session, worth not re-deriving:** `journal.py append` and the shell — a `| head` outside an `ssh "..."` string fails in PowerShell (no `head`); use `Select-Object -First N`. And `ps_search what=files` on ZABZ-TECH resolves through the authority's path index, so a file that exists only on this laptop reads as "no match (exit 1)" — that is a refusal from a scope that does not cover the host, not evidence of absence.
