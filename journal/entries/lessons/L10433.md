Reason: `applyAll` runs the patcher, the patcher applies target 1 and then fails on targets 2-3 and exits 1. The
patch is a single registry entry, so `check-after` fails, and my `--allow-patch-failures settlement-crash,window-
blank-isolation` waiver let the install continue while printing "this install proceeds WITHOUT this hand patch" --
a claim that was false: one third of it was live in the tree.

IS THE PARTIAL STATE HARMFUL? No, and that is luck rather than design: the applied third is the agent-loop
`hasPending` getter made total (returns false instead of throwing when the inbox projection is released), which is
harmless on its own. The missing third is the settlement watcher's `.catch`, which is the actual crash guard. So the
tree has a defensive improvement without the fix it was paired with.

WHAT I CHANGED so this cannot be reported wrongly again (committed bfb5adadd): the receipt now records each patch
result's own output, and the waived line prints the patcher's per-target lines instead of promising a clean
absence. A future operator reading the receipt sees "one target patched, two failed" rather than "waived".

WHAT COMPLETING IT WOULD TAKE, now measured rather than guessed:
 * `dsh-subagent/lib/index.js` no longer has a `hasPending` accessor at all (grep: zero hits); the closest live
 code is `inbox.nextTurn.length` at :1318 inside the manager. The edit must be re-derived against that.
 * `lib/types/activation.js` carries the settlement language ("notify its settlement watcher when failure changes
 readiness", :52) but not the anchor block the patch expects. Both anchors need re-authoring, not re-pathing.
 * The agent-loop edit is already in place and needs no work.
 * A re-authored patcher must be proven by an actual child dispatch that settles; the mesh children on this
 machine currently fail with MISSING_CREDENTIAL until the sshd session environment carries DEEPSEEK_API_KEY, so
 "it applies" is not "it works" until that is solved too.

VERDICT for the objective: the settlement-crash failure mode is NOT closed on 0.2.1, and the honest label is
"one third applied, two targets re-derivable", not "waived".
