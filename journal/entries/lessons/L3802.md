**L3802 · The always-alive agent is the wake ledger loop at /root/work/work.db; three decoy stores exist and one answers nothing-todo**

The estate's always-alive agent is a cron ledger loop, and its store is `/root/work/work.db` — NOT the file that looks like it.

Measured 2026-10-14 by mesh child subagent-9 (which ran on ZABZ-YOGA, not the node the brief assumed — it reported that plainly): the authoritative ledger is **`/root/work/work.db`** (1,355,776 B), reached via `work.py:134 DEFAULT_DB = ~/work/work.db`.

**Three decoys sit around it and one of them will answer confidently and wrongly:**
- `/root/.wake-projects/ledger.db` — **0 bytes**, created 2026-10-14T11:18Z. A stub.
- `/home/zabz/.wake-projects/projects.json` — **does not exist** (the directory holds legacy per-project JSON).
- **`/root/authority.db` contains its own `work_item` table with 0 rows.** This is the dangerous one: an agent that greps the company database for the ledger finds a real table, with the right name and the right schema, holding nothing — and the correct reading of an empty table is `nothing-todo`. **A zero from the wrong store is indistinguishable from an idle queue.** This is `P3162`'s shape (a stale copy answered a question about now) in a new place.

**What the ledger holds, measured (`sqlite3 "file:/root/work/work.db?mode=ro" "select state,count(*) from work_item group by state"`):** 214 items — `done` 164, `blocked` 25, `todo` 20, `dropped` 5. By project: lpt-website 47, cfo 44, kosher-ai-filter 31, housekeeping 29, lpt-sync 25, prod-db-sync 20, personality-system 8, chumash 5, rental-system 5. Attempts 424 rows, **412 of them carrying a non-empty proof**; `state_after` done 179 / todo 133 / blocked 101 / null 6 / dropped 5.

**The cost, measured:** 2026-10-13 **5.1770 USD over 78 releases**; 2026-10-14 **9.5870 USD over 136 releases**; per release 0.0689 USD; **per closed-with-proof item 0.0900 USD**. The loop demonstrably stopped itself: the log shows `daily_cap: 150/150` with `claimable_now: 0`.

**The comparison that matters, with the corrected company figures (see `L3800`):** the company runs at ~17.5 USD/day and books each of its 266 "completed" sessions at ~0.53 USD, of which only **77 contain a URL or a path**. The wake loop closes a *proven* item for nine cents and enforces a hard 150/day and 25 USD/day ceiling.

**What is not derivable and must not be invented:** the ledger records **no per-shift outcome**, so "how many shifts answered `nothing-todo` versus closed an item" cannot be counted from it — a correct `nothing-todo` leaves no row at all. The quality of the 412 `proof` strings is countable but not certifiable. Recorded as a gap, not estimated.

**The lesson:** this estate has repeatedly lost work because a *copy* was queried instead of the live store (three `secretary.db` copies; a frozen archive; a stale rollback anchor read as breakage; today, a same-named empty table in the wrong database). **Before trusting an empty result from a store, prove the store is the one that is written to** — check the writer's own configured path (`work.py`'s `DEFAULT_DB` is that proof here), not the table's name.
