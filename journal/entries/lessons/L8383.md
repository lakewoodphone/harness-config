**L8383 · Four defects that repeat in every ingest: HTML fallback, unwritten column, non-identity join, recurring notice**

**L — 2026-10-18 · Four defects that repeat in every ingest, and the shape of each**

Building the email half of the owner queue (D6977) cost four bugs, and every one of them was a
*a correct rule reading the wrong thing*. They are worth carrying because each will reappear in the
next ingest anyone writes.

**1. A reader that falls back to the raw part feeds the judge the `<head>`.**
`gmail_service._extract_body` prefers `text/plain` and otherwise returns the raw HTML part. A Chase
notice therefore reached the judge as 17 KB of `<head>`, tracking scripts and inline CSS, truncated at
1 500 characters — so the model never saw the amount, the date or the ask. It said so honestly
("body truncated so amount unknown") *and queued the row anyway*. After stripping tags, entities and
script/style blocks, the same message yielded "account ...9730 overdrawn by $1,956.66" and "card
...4258 statement: $4,530 balance, $196.17 min due Nov 13".
**Rule: for any model-facing read of a message, strip HTML before the truncation, not after.**

**2. A column that is never written is a term that never fires.**
The queue's score had a money term for weeks. Measured across all 42 pending rows: `meta.money` was
set on **zero** of them, so a returned payment of 2 380.06 ranked below a ten-day-old voicemail about
a laptop. The amount was in the sentence the whole time.
**Rule: before trusting any term in a formula, print the predicate's raw value
(`SUM(json_extract(meta_json,'$.money') IS NOT NULL)`) and look at it.** Then derive from the text,
which also repairs every historic row at once.

**3. The identity you join on has to be an identity.**
The dossier's "history with this sender" joined on the mail **domain**, so a card for his wife's
grocery request listed four Telnyx and Chase items — because all of them came from `gmail.com`. A
false provenance claim is worse than no provenance: it is a confident answer about the wrong person.
**Rule: freemail domains identify a mailbox, not a person — join on the full address there, and on the
domain only for a company.**

**4. A recurring notice is one fact, not one row per day.**
Telnyx sent "balance is −$0.01" on four consecutive days → four `critical` rows in a hundred-item
queue. Keying on the message (or the thread) cannot see that. Keying a machine's mail on
`(domain, subject-with-dates-and-amounts-stripped)` collapsed it to one; a person's mail still keys on
the thread, because two people writing about the same subject are not the same thing.
**Rule: decide the dedupe identity per class of sender, not once for the whole channel.**

Two smaller ones from the same session, both about tools lying to you:

* **`pkill -f "<pattern>"` matches the ssh command that carries the pattern** and kills its own shell:
 the command returned exit 1 with no output at all, which reads exactly like the process being
 killed. Use a bracket (`ingest-mail[.]py`) so the pattern cannot match its own command line.
* **`systemctl list-timers` shows `NEXT -` right after `start`** while the unit is still active; the
 next elapse appears once it finishes. Two readings, not one.
