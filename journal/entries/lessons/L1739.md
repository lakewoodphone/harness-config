**L1739 · Chromium ignores a file:// PAC on Windows - serve the PAC over http://127.0.0.1; and never verify a proxy with chrome.exe --dump-dom**

**Measured on ZABZ-YOGA 2026-09-16.**

- With `HKCU\...\Internet Settings\AutoConfigURL = file:///C:/.../rattlebyte.pac`, Playwright Chromium gave `net::ERR_CONNECTION_TIMED_OUT` for rattlebyte.com.
- Changing **only** the PAC delivery to `http://127.0.0.1:1081/proxy.pac` made the same browser render the real page: title "RattleByte Technologies", final URL `https://rattlebyte.com/Shop.php?lang=en`. Control: google.com still loads DIRECT.

So: **Chromium does honour the Windows system PAC**, but a `file://` PAC is effectively ignored - serve it over `http://127.0.0.1` instead. (`HttpListener` needs a urlacl/admin on Windows; a raw `TcpListener` does not - the PAC server uses TcpListener for that reason.)

Two more traps hit while doing this:

- **Windows Chrome/Edge detach from the launcher**, so `chrome.exe --headless=new --dump-dom <url>` returns 0 bytes and exit 21. Do not try to verify a proxy config that way - use Playwright, which speaks CDP and reports properly.
- **Never nest PowerShell inside `powershell.exe -Command "..."` from pwsh.** `\$` is not an escape in PowerShell, so the inner command arrives mangled with literal backslashes and parse errors. Every attempt wasted a call. Write a `.ps1` and run it with `-File`.
