**L3848 · A paid, finished shop job can have no record: lpt-label needs a ticket, lpt order create has three gates, and ssh+bash-s eats CRLF**

A finished, paid, handed-back shop job can exist with **no customer row and no order at all** — and
then "write a label" is really "build the record first, because a label without a ticket is a number
with no case behind it". Wadler, Fig Flip F52, +18482991569, 2026-10-18.

## The identity route when nobody is in the store

Everything the shop's own readers know answered a real negative, in this order:
`lptcase find wadler` / `find 8482991569` -> no match (288 cases); `lpt ticket 8482991569` -> "No work
order matches"; `lpt customer wadler` -> "no customer matched" in **both** stores; a name sweep on
`customers` in both stores (ilike `wad|adler`) -> only *shwadron*.

What found the job was `communications.contactPhone`, last ten digits:
`select ... from communications where right(regexp_replace(coalesce("contactPhone",'') ,'[^0-9]','','g'),10)='8482991569'`
-> **9 rows, 2026-10-15T17:55Z..2026-10-18T16:39Z, every one `customerId`/`orderId` NULL**.
The whole relationship — the price quote and the no-guarantee conversation — lived in Dialpad rows
that had never been attached to anything. Rule: for a customer the owner names from memory, `contactPhone`
in `communications` is the fastest identity there is, and `customerId IS NULL` on those rows is normal,
not a sign you looked in the wrong place. ASR renders the surname as "weather" and the first name as
"Look to para with two Ps and H" — the file records the ASR strings as aliases so a future search lands.

Also: **"fig flip f52" is real shop vocabulary.** Brand `FIG`, model `F52`, brandId 101, modelId 74
(`orders."deviceInfo"`). It is not a mishearing of a brand.

## `lpt-write order create` — three gates, all measured

1. `--evidence <path>:<sha256>` is **mandatory**; without it: `REFUSED - nothing was written`. The house
 convention (ledger seq 479, and mine at 484) is the `lpt-hub` case file's own sha256. So the order is:
 write the case file with `work_order:` empty -> hash it (`Get-FileHash -Algorithm SHA256`) -> create the
 order -> fill the ids in. **The hash then legitimately diverges** from the file; say so in the case file,
 because the ledger plan line calls it "1 photograph(s)" and it is not a photograph.
2. **Create-time status is a different enum from the workflow enum.** `order create --status READY_FOR_PICKUP`
 is refused by `app.services.website_db.create_order`; create at the default `AWAITING_DIAGNOSIS` and then
 `lpt-write status set --apply --order WO... --status READY_FOR_PICKUP`. Second time in one day this bit.
3. **Do not predict `orders.total`.** Same tool, same day: `--total 100` -> stored **106.63** (ledger tax block
 present, `tax_included false`); `--total 75` -> stored **75.00** (no tax block at all). Read the readback
 instead of assuming the writer adds the 6.625%, and put the amount actually charged in a note where a
 human will see it.

Money with no processor id: `lpt-write payment set` and `lpt-record-payment` both **require a `ch_...` charge**,
so a payment taken by hand cannot be recorded through either. 551 of 654 orders sit at `paymentStatus = PENDING`
anyway — PENDING is not evidence that money is owed, and a note that says "PAID IN FULL, DO NOT COLLECT AGAIN"
is the only guard that exists.

## Two shell traps that cost real calls

- **PowerShell here-string piped to `ssh host "bash -s"` carries CRLF.** The last token of every line gets a
 trailing `\r`: `bash: syntax error: unexpected end of file from 'for' command`, and
 `ls: cannot access $'/home/.../docs/\r'`. It reads like a quoting bug and is not. Fix, always:
 `@'...'@ | ssh host "tr -d '\r' | bash -s"`.
- **The `lpt` entry script on `secratary` has no exec bit** (`-rw-rw-r--`), so
 `/home/zabz/code/lpt-ops/bin/lpt` gives `Permission denied`. Run it as
 `python3 /home/zabz/code/lpt-ops/bin/lpt ...` (reads work; `lpt-write` takes `--apply`).

## Label

`#12754` as the ticket heading, then customer / device / the facts the counter needs. The house renderer
wraps at roughly **20 characters on the 29 mm roll**: "TURNS ON, NO GUARANTEE" (22) broke across two lines,
so a line that looks short enough is not. Dry-run to PNG and **look at it** every time. Print proves
transport only — `READY`, model identified, `instructions_sent`; tape is proven by the roll or a person.
