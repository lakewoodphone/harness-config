**L3869 · A rebuilt search index does not reset the adapter watermarks, so every source reports ok while emitting nothing**

**A rebuilt search index does not reset the adapters' watermarks, and every source then reports `ok` while emitting nothing.**

Measured 2026-10-19 on the estate's search system, after the authority was resized. The central index
(`secratary-cloud:/root/.usearch/usearch.db`, `meta.created 2026-10-19T08:23:16Z`) held:

| corpus | on its own host | in the centre |
|---|---|---|
| ZABZ-TECH files | 1,111,314 | 9,927 |
| ZABZ-YOGA files | 195,284 | 8,640 |
| journal | 4,071 | 76 |
| five mailboxes | 118,617 messages in `/root/mail-archive/*/archive.db` | 39 |
| Dialpad comms | 181,182 written by an earlier sync | 0 |
| VS Code chats | 3,638 | 0 |

The mechanism: every adapter keeps a watermark and every push is teed from the adapter's **stdout**, so
a push carries only what that run emitted. The store was rebuilt; the watermarks were not; so each
source re-emitted almost nothing and reported `ok`. `sync.json` still carried the proof —
`comms:authority … docs_written 181182` against **0 rows in the store**, `journal:authority … 5303`
against 76. There was no backfill path at all, and `/health` was green throughout.

Two consequences that generalise:

1. **"The sync ran" and "the corpus is here" are different assertions.** A watermark makes the first
 true forever; only a count makes the second true. `/health` now fails per corpus below
 `config/sources.json → coverage.min_docs` (14 floors), and the first version of that check named
 the gap in one line: `journal holds 76 document(s), floor is 3000 (coverage, not freshness)`.
2. **When a store is thrown away, the state that describes it must go with it.** If the index is
 rebuilt, the adapter state has to be rebuilt too (`--full`) or a backfill must run. The plan
 (`docs/ESTATE-SEARCH-PROGRAM.md` D-C) had already written this down for one source; it was true for
 every source.

Recovery built this session: `unified-search/scripts/backfill.py` — reads `docs`+`chunks` from the
host's own index, rebuilds the adapter contract, applies `push_policy`, POSTs to `/ingest` in bounded
chunks, idempotent on `(source,id)`, resumable by rowid, honours `push:false`. Centre went 18,682 →
334,630 → (see handoff for the final count) documents.

Refs: D2983, H3411, `docs/OPERATIONS-ESEARCH.md` §3b, `docs/SEARCH-AUDIT-2026-10-19.md` §3.1.
