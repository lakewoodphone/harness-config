**L3648 · I installed a timer whose ExecStart pointed at a file I never installed**

2026-10-13. Caught by running the unit rather than by reading it, and it would have failed silently
at 05:13 in the one place nobody looks: a systemd journal on a server.

WHAT WAS WRONG. `deploy/systemd/lpt-marketplace-orders.service` carries
`ExecStart=/usr/local/bin/marketplace-orders-sync.sh`. I installed the unit to
`/etc/systemd/system/`, enabled the timer, and never installed the SCRIPT. Measured:
`ls -la /usr/local/bin/marketplace-orders-sync.sh` -> "No such file or directory". The unit would
have failed with 203/EXEC on its first fire, every day, and the only symptom would have been a red
line in `systemctl status` for a unit nobody had reason to look at.

WHY I MISSED IT, and what the report said. The fleet worker's final message listed this exact
hazard - "the installed clock script was never executed end-to-end, so its `flock`, lock-retry and
status-file paths are unexercised even though the CLI beneath them is" - and I read it as a note
about untested edge paths. It was a statement that the whole unit had never been run. I installed the
timer and moved on; the timer is the thing that runs the unit, and neither of us had pressed start.

FIXED AND PROVEN. Installed the script to the path the unit names, then ran the service exactly as
the timer will:

 systemctl start lpt-marketplace-orders.service
 Process: ExecStart=/usr/local/bin/marketplace-orders-sync.sh (code=exited, status=0/SUCCESS)
 Mem peak 152.1M, CPU 12.827s
 status file: {"ran_at": "2026-10-13T03:41:31", "ok": true, "ingest_rc": 0, "match_rc": 0,
 "evidence": {"written": 44, "skipped_existing": 364},
 "match_status_counts": {"matched": 408, ...}}
 lock file /run/marketplace-orders-sync.lock created

Every path the worker listed as unexercised is now exercised: the oneshot ran, the flock held, the
status file was written, and the evidence write was idempotent (44 new, 364 already present).

RULES.
1. **Installing a timer is not testing it.** `systemctl start <unit>` costs one second and is the
 only thing that answers "will this work when nobody is watching". Do it BEFORE enabling the
 timer, not after.
2. **When a worker says a path is unexercised, that is a task, not a caveat.** The sentence was in
 the report I acted on; I filed it as a limitation instead of doing the one command that removes
 it. The honest reading of "never executed end-to-end" is "nobody knows if this works".
3. **A unit file and the file it execs are two artifacts.** Installing one and not the other
 produces a failure that looks like a broken service rather than a missing install.
