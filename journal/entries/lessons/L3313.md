**L3313 · Never source a .env: a malformed line makes the shell execute the secret, and the secret lands in the transcript**

**L3264 · Never `source` a `.env`: a malformed line makes the shell execute the secret, and the secret lands in the transcript**

WHAT HAPPENED. 2026-10-05 05:0xZ on ZABZ-TECH. To find out which Twilio number is the seat's
own SMS line, I ran `set -a; . ./.env; set +a` inside a shell call so `TWILIO_PHONE_NUMBER`
would be exported. Line 385 of `personal-secretary-mvp/.env` is written as
`AI_GATEWAY_API_KEY=<space><48-character value>`. Bash read the assignment, set the variable to
**empty**, and then executed the value itself as a command — and its "command not found" printed
the entire live gateway key into the tool result, which is this session's stored transcript.

WHY IT WAS EASY TO DO. python-dotenv strips the whitespace, so the application never noticed and
the key worked perfectly. The file is dangerous **only to a shell**, and a shell is exactly what
a session reaches for when it wants one variable. The same run also printed fragments of
`HETZNER_PASSWORD` the same way.

THE RULES.

1. **Never `.` / `source` a `.env`.** Read one value with the application's own loader
 (`from app.config import settings`) or with `python-dotenv`, which parses rather than
 executes. `set -a` is not a safer form of the same thing — it still executes the file.
2. **A `.env` line is untrusted input to bash.** `KEY= value`, `KEY =value`, an unquoted value
 containing spaces, and shell metacharacters all turn one line into an arbitrary command. This
 is not theoretical; it printed a live key.
3. **Never print a credential to check it.** Print a hash and a length.
 `sha256[:12] + len` was enough to prove the key was unchanged across the `.env` repair; the
 value never needed to be visible. Verification does not require disclosure.
4. **A credential that reaches a transcript is burned, not broken.** Rotate it, say so plainly in
 the same session, and put it where a decision is already being made — do not quietly continue.

EVIDENCE. Tool call `myline3.sh` printed `./.env: line 385: <the key>: command not found`; line
385 confirmed as `AI_GATEWAY_API_KEY` followed by a space by a **masked** read (masked form:
`AI_GATEWAY_API_KEY= xxxx…`, 68 chars total) so the check itself leaked nothing; `.env` repaired
with backup `.env.bak-nospace-20261005T050702Z` and the app's parsed value proved identical
(sha256 prefix `e81c265663c3`, len 48). Sibling incidents of the same family: **P2815** (a probe
echoed SerpAPI's own key back), **P2836** (credentials leaked while verifying that credentials
were intact). Queue row 271 now covers this one.
