**L1673 · Look for the vendor's own agent path (CLI/MCP) and read its acceptable-use policy before automating a web app — and know which documents the vendor cannot give you at all**

**L#. Before automating a vendor's web app, look for the vendor's own agent path — and read its acceptable-use
policy. We were one decision away from building the wrong thing.**

The problem looked like a choice between a gated partner API and browser automation. It was neither. Gusto
ships an **official CLI built explicitly for AI agents** (`curl -fsSL https://cli.gusto.com/install.sh | sh`,
OAuth, stable JSON envelope), and its **CLI Beta Terms §1.6** say agent-driven actions are authorized and that
"authentication through valid credentials is conclusive evidence of authorization." Gusto also ships an MCP
server. Meanwhile the same company's **Acceptable Use Policy** bans accessing the platform "through any
mechanism other than the software provided by Gusto" and bans scraping without written consent, enforced by
account suspension — so the browser-automation plan that felt inevitable was the one path that could have cost
us the account mid-cancellation.

Two hours of research replaced what would have been a brittle, ban-risk automation. The transferable rule:

1. **Search for `<vendor> CLI`, `<vendor> MCP`, `<vendor> agents`, and the vendor's `/legal/terms/acceptable-use`
 before writing a single selector.** Agent-native integrations now exist for payroll (Gusto), and the pattern
 is spreading.
2. **Check the App/Integrations API's own fit table first.** Gusto's states outright that it does *not* support
 a customer connecting its own account — so "get an API key" was never available, and knowing that in one
 page saved pursuing a security review built for software vendors.
3. **Distinguish sanctioned-but-weak from unsanctioned-but-powerful.** The CLI cannot submit a payroll (no
 run/submit command) and cannot fetch tax documents; the UI can do both but may not be automated. That split
 — sanctioned read path for data, human click for the irreversible step — is the right design anyway, because
 the thing the CLI refuses to do is exactly the thing that should need a person.
4. **Two documents are unobtainable from the vendor entirely:** NJ-927 and WR-30 are "filed electronically,
 not available for download." The state portal is the only source. A data plan that assumes the vendor has
 everything is wrong for state wage reports.
5. **"Lifetime access" is not a system of record.** Gusto promises unlimited post-cancellation access and also
 reserves the right to withdraw the CLI at its sole discretion with liability capped at $500. Extract early,
 keep our own copy.

**And the one owner action this creates is worth naming precisely:** `gusto auth login` requires a primary or
full admin to approve in a browser. That is not an obstacle to route around — it is the smallest possible ask
that converts this seat from a researcher into the actual bookkeeper.
