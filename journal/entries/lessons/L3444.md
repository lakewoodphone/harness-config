**L3444 · rulesets -> [] does NOT mean nothing is enforced - classic branch protection is a different API, and I published the wrong conclusion in a merged doc**

MEASURED 2026-10-09, ZABZ-YOGA. I wrote in a document that would be merged to the repo, and told the
owner in conversation, that **nothing was a required check and red did not block a merge** on
`test` or `main`. Both branches were protected the whole time, with `enforce_admins: true`. I found
out by trying to merge: `GraphQL: 3 of 3 required status checks are expected. (mergePullRequest)`.

TWO MISTAKES, AND THEY COMPOUND

1. I ran the wrong endpoint. `gh api /repos/.../rulesets` returned `[]` and I treated that as
 settling the question. **Repository rulesets and classic branch protection are different APIs.**
 An empty ruleset list is a true answer to "are there rulesets" and a silent non-answer to "is
 anything required". The endpoint that answers it is
 `gh api /repos/OWNER/REPO/branches/BRANCH/protection`, and it returns
 `required_status_checks.strict: true` with three contexts on `test`, four on `main`.

2. I inherited the claim rather than testing it. The 403 in `docs/ci-cd/ONE-DEPLOY-PATH.md:100` and
 in a subagent's brief were both about the same endpoint, and I let a document's measurement stand
 in for mine on a question that decides whether a bad merge ships. When a reading is the thing
 that gates everything else, measure it yourself.

THE RULE
**An empty result out of the wrong endpoint is a refusal, not a negative.** Before reporting "there
is nothing", name the endpoint and say what question it answers. `[]` from a list endpoint is only
evidence about that list. This is the same shape as the standing line "an empty result is not
evidence of health" - it now has a concrete instance: `rulesets -> []` does NOT mean nothing is
enforced.

HOW TO TEST IT IN ONE COMMAND, AND HOW TO TEST IT FOR REAL
Ask for the object that would have to exist:
 gh api /repos/OWNER/REPO/branches/BRANCH/protection | jq '.required_status_checks'
Better: attempt the action you believe is blocked. A failed `gh pr merge` is unambiguous evidence
and costs nothing. Reading a config is a claim; being refused is a measurement.

WHAT IT CHANGED
Two findings got worse, not better - the `detect-changes` fail-open is now a bypass of a REAL
required check, and the `main` name-gate is a REQUIRED check that only reads a branch name. Two
inverted: `ONE-DEPLOY-PATH.md:100` is the wrong document, not the four files that assert required
checks. And one stood: no test suite runs on these PRs (`Test Backend`/`Test Frontend` are SKIPPED
even on a code PR with all three required contexts green).

CORRECTION IN THE REPO: PR 362, branch fix/state-doc-required-checks.
