**L1515 · A missing system app on a freshly flashed phone is usually DISABLED for user 0 — ask pm before blaming the flash**

A "missing" system app on a Samsung that just came back from a flash is almost never missing. It is installed and DISABLED for user 0.

Evidence (2026-09-15, Eli Green S22 Ultra R5CT43KS46N): the customer reported no Play Store. `pm path com.android.vending` returned an APK under /data/app, Phonesky.apk was present in /product/priv-app, and `pm list packages -d` listed `com.android.vending` — 20 preloads in total were disabled while `dumpsys package` showed `enabled=3` (DISABLED_USER). `pm enable com.android.vending` was enough; the launcher activity resolved and the signed-in storefront rendered. No reinstall, no reflash.

Rule: before diagnosing "the app is gone" or "the flash removed apps", run in this order —
1. `pm list packages -u | grep <pkg>` (is it installed at all),
2. `pm list packages -d` (is it disabled for the user?),
3. `dumpsys package <pkg> | grep -E 'enabled=|installed=|hidden='` (which state, and 3 = DISABLED_USER),
4. only then blame the firmware/CSC.

Corollary: a CSC does not disable apps. The same check on the Visible OMC (FKR) showed its `HiddenStatus` entries govern *APN profile* visibility and its `default_workspace.xml` / `default_application_order.xml` actually place Play Store — the OMC was exonerated by reading it, not by guessing. An "enabled=3" batch of 20 preloads is a *user-space* state created after the wipe, so the actor is a setup flow or a person, not the firmware.
