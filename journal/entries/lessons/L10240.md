**L10240 · all() over zero rows is True: a failure detector that fires on silence, and why deferral reports itself**

## Found 2026-10-19T23:20Z while checking, before the first peak block, whether silence would be punished

I was about to let four hours of departmental silence run in production for the first time, so I read
every surface that could interpret "no tick" as "broken". Two of the three findings are worth keeping.

### `all()` over zero rows is True, and that is a failure detector that fires on nothing

`tick_quality.check_consecutive_failures` ends with:

```python
return all(q in ("failed", "empty") for (q,) in rows)
```

If `rows` is empty — an agent that has not ticked in the window — `all(...)` returns **True**. So an agent
that has done nothing is reported as having *consecutive failures*. A function whose name promises to
detect a run of failures will report one for silence.

It is unreachable from my deferral only because the single caller, `agent_worker._build_perf_context`,
returns early when `stats["total"] == 0`. **The guard is what saves it, not the logic.** Any new caller
that skips the guard inherits the bug.

**Rule: a predicate over an empty set is not evidence of the thing it tests.** Every aggregating failure
detector needs an explicit `if not rows: return False` — because the vacuous truth of `all()` is exactly
backwards from what a fault-finder wants.

### Silence is not an anomaly, and that is a deliberate property

`anomaly_detector` only evaluates an agent *after that agent ticks* ("cost > 0.05 but 0 steps"). A
deferred agent produces no tick and therefore nothing to flag. That is the correct design for this
change — but it also means the anomaly system cannot notice a department that has silently stopped.
**Absence of ticks is invisible to a per-tick detector, by construction.** Anything that genuinely needs
to detect a dead department has to look at *time since last tick*, not at the ticks that happened.

That is also why the deferral reports itself: `scheduled_deferred` in the tick result and a log line,
rather than letting the department simply not appear. If a later session turns on a longer deferral,
the same reasoning applies — a state must be visible or it is indistinguishable from a fault.

### A health flag nobody reads is not a health flag

`main.py` sets `tick_quality_24h.ok = productive_ratio > 0.3`. Deferral will push that ratio down and may
flip it false. But `activation_score` and `tick_quality_24h` appear **nowhere else in the codebase** —
they are built and returned by one endpoint and read by nothing. So the risk is a possible amber badge,
not an alert. Worth knowing, because "it feeds the health score" sounds alarming until you check who
consumes the score.
