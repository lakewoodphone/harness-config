**L3110 · A mesh subagent brief containing an apostrophe or a quote dies before it does any work**

MEASURED 2026-09-30, twice, on ZABZ-TECH. Four `subagent` children were dispatched with their
brief inline and all four failed with `status: failed` and stderr tails that quoted fragments
of the brief as command-line options:

 error: unknown option -u THE OWNER S COMPLAINT, verbatim: make
 error: unknown option -u; ...

The apostrophes and quotes in the brief reach the remote one-shot as shell arguments, so the
child never starts. Two hours of wall clock, two dispatch rounds, zero findings.

THE FIX, PROVEN TWICE AFTERWARDS: write the brief to a FILE, and make the prompt one
argument-safe sentence that contains no apostrophe, no quote, no backtick and no parentheses:

 Read the brief at C:/Users/ezabz/Code/dispatch/brief-x.md and carry it out exactly,
 to completion. Do not ask questions. Write the report to C:/Users/ezabz/Code/dispatch/out-x.md.

The file may contain anything -- quotes, code, punctuation. Only the prompt is restricted.
A probe that made the child read a file, run `hostname`, and write an output file confirmed
the whole path (subagent -> ssh -> file read -> file write) before the real briefs went out.

COROLLARY: verify the child WROTE its artefact. The probe file `probe-out.md` appeared; the
four real reports did not, and that is how the second failure was caught rather than assumed.
