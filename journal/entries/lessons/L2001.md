**L · Four probes, four false conclusions, one cause: a check that cannot look is being read as a check that found nothing**

MEASURED 2026-09-18 on ZABZ-YOGA across one session. This is the single most productive mistake of the
day and it deserves to be the last time it is made.

THE FOUR, in the order they were made:

1. **`node: absent` on mac-mini-ts.** `node -v` printed nothing, so the node was written down as
 having no runtime. Truth: sshd hands a non-interactive macOS session
 `PATH=/usr/bin:/bin:/usr/sbin:/sbin`, and the machine has node at `/usr/local/bin/node` (v24.19.0)
 and at `~/.local/node-v24.12.0-darwin-arm64/bin/node` (v24.12.0). **Two runtimes; the node table was
 right and my probe was wrong.**
2. **`engine:3099: no` on the same machine.** The probe asked `ss -ltn || netstat -ltn`. macOS has no
 `ss`, and BSD `netstat` rejects `-ltn`, so the count was 0 **because the question could not be
 asked**. `lsof -nP -iTCP:3099 -sTCP:LISTEN` showed pid 12458 listening the whole time.
3. **"`secratary` is nearly out of commit, so it cannot host work."** `vm.overcommit_memory = 0`: the
 commit figures are *reported, not enforced*. Real free commit was ~5.5 GB against a `Committed_AS`
 that is 44 % of RAM. The actual constraint is a 4 GiB swap that is **100 % full** — a different
 fact with a different remedy.
4. **"`zabz-tech` is isolated over ssh; no node is reachable at any cost."** A child reported all five
 aliases HANGing *including its own self-hop*. Truth, reproduced from the laptop:
 from `desktop-ts`, `mac-mini-ts` answers in **205 ms**, `linux-pc-ts` in **315 ms**, `secratary-ts`
 in **522 ms**, `laptop-ts` in **1069 ms**. All four work. The defect is that on that node an ssh
 whose **stdout is a pipe** (inline `& ssh`, or `Start-Job { & ssh ... }`) **never returns**, while
 `Start-Process -RedirectStandardOutput <file>` finishes in under 1.1 s. The child read its own
 wrapper's failure as a property of the network.

THE CAUSE IS THE SAME IN ALL FOUR: **the check could not look, and I recorded the blank as a negative
answer.** A missing tool read as "no listener". A PATH that does not contain node read as "no runtime".
A commit limit that is not enforced read as "no room". A piped-stdio hang read as "no route". None of
those blanks was ever a measurement.

THE RULES THAT FOLLOW, and they are cheap to apply:

1. **Every check must be able to say "I could not ask."** If a probe's tool is missing, its exit code is
 non-zero, or its output is empty, that is `UNKNOWN` — never `false`, never `absent`, never `0`.
 Distinguish the three states explicitly in the probe and in the report.
2. **Prefer the question that has a positive control.** `lsof` proved a listener where `ss` proved
 nothing. `Start-Process -RedirectStandardOutput` proved four working routes where `Start-Job` proved
 none. When one instrument says "nothing", reach for a second instrument before writing the sentence.
3. **A sibling's success is evidence. A single failure is not.** Two children ssh'd from
 `desktop-ts` and returned detailed reports in the same hour that a third reported the node was
 unreachable. The contradiction was the finding, and I nearly recorded only the loud one.
4. **An agent's report is a claim; reproduce it.** Rule 4 is the one that caught this: the wrong
 conclusion came with a confident paragraph of reasoning and the right conclusion came from a
 four-line script run by hand.

The general shape, and why it matters here more than anywhere: this system's two worst recorded
incidents — the stale database and the health check that reports green for an absent service — are both
this same mistake. A blank is not a zero, and a tool that cannot see is not a tool that saw nothing.
