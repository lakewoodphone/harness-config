**L1979 · web_search is dead on a DeepSeek 402 — use the Jina/Firecrawl MCP search tools**

The harness `web_search` tool is broken on this machine as of 2026-09-17 (ZABZ-YOGA): every call returns HTTP 402 "Insufficient Balance" from `https://api.deepseek.com/anthropic/v1/messages`. The search plugin routes through DeepSeek's Anthropic-compatible endpoint using the DeepSeek key, and that account has no balance. Chat inference in the same session works, so the chat route is a different key/provider — do not conclude "the model is down".

Workaround that worked immediately, no config change needed: the MCP search tools are independent and live.
- `mcp__jina__search_web` (batch up to 5 queries in one call, returns titles/urls/snippets)
- `mcp__firecrawl__firecrawl_search` (add `categories: ["developer"]` for GitHub/docs)
- `mcp__jina__read_url` with `question` + `topk` to pull only the answering passages out of a page — far cheaper than reading a whole page
- `mcp__firecrawl__firecrawl_scrape` with `maxAge: 0` for a guaranteed live fetch; add `parsers: ["pdf"]` for PDFs

Measured: a full multi-source research task (3 search rounds + 5 page reads + 1 PDF) completed with zero web_search calls.

Rules that matter for the fix: only the owner chooses or changes the search endpoint (Settings > Plugins > Plugin configuration > Web search, or DEEPSEEK_SEARCH_BASE_URL / web-search-deepseek.baseURL). Do not silently repoint it.

Blocked by firecrawl: instagram.com ("we do not support this site") — get Instagram content through search snippets instead.
