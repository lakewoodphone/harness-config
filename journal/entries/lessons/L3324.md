**L3324 · A cleanup promise written in a comment is a lie; the only proof is a post-reboot absence check**

**A "this cleans itself up on reboot" claim is a mechanism or it is a lie — and the only proof is a post-reboot absence check.**

Measured 2026-10-05 across the LPT field kit. Three files promised `Account and SSH are auto-disabled
on next reboot` (`Enable-ShopSsh.ps1:21`, `Enable-ShopSsh.cmd:35`, `Run-CopilotSshAccess.cmd:34`).
A search of the entire kit for `Register-ScheduledTask`, `New-Service`, `schtasks`, `RunOnce`, a `Run`
key or `nssm` found **no cleanup mechanism at all** — while the same kit registered
`sc.exe create sshd ... start=auto` (`Enable-ShopSsh.ps1:83`, `Install-CopilotSshAccess.ps1:281`). So
the access did not disappear on reboot; it was specifically configured to come back, and a temp
administrator account stayed behind on every machine the kit had ever touched. The owner had doubted
the claim for months and was right.

Three rules, each independently sufficient to have caught this:

1. **Do not write the promise until the mechanism exists and has been run.** A cleanup described in a
 header comment, in a `CLEANUP:` line, or in an `echo` is not a cleanup. This is the same failure as
 a check that cannot fail: the artefact asserts a property nobody implemented.
2. **Assert the absence, after the event, from a fresh vantage.** The only acceptable proof of a
 self-removing access window is: reboot, then verify that the account is gone, the service is gone,
 the key file is gone and the port is closed. "I installed a destructor" is exactly the class of
 claim that was false here. This is `L2001` applied to cleanup - a check must be able to fail.
3. **Grep for the negative when auditing a safety claim.** The cheapest audit of any "it cleans up /
 it expires / it disables itself" statement is a single search for the primitive that would
 implement it. Searches return nothing silently, which is why the audit must name the primitives it
 looked for and report that list — an empty result is a refusal, not health.

Corollary for anything that grants access to our infrastructure: **a credential we leave on someone
else's machine is a credential they hold.** If the design cannot revoke it server-side, the design is
not temporary, whatever the header comment says.
