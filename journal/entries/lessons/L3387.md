**L3387 · Waze MDM push path: device truth beats DB truth, baked /srv, and the iOS keys that decide a rollout**

## The five things a future session needs about the Waze MDM push path — measured 2026-10-06

1. **Device truth, not database truth.** `device_profiles` on the Waze MDM Postgres is **EMPTY
 (0 rows)**. Nothing in the database records which profiles a device wears. The only correct
 question is *"what does the device say?"* — enqueue `ProfileList` and read the reply. Any
 automation that consults the database for "is the profile installed" will report success falsely.

2. **`fleet_devices.last_seen` is a trap; `enrollments.last_seen_at` is liveness.** The fleet's own
 code says so at `/srv/fleet_api.py:97-101`. `fleet_devices.last_seen` is not written by any code
 path. A device only advances `last_seen` when something is SENT to it, so a healthy phone that
 nobody called looks months dead. DRN 2002 read as "last seen 2026-09-15"; it answered a
 `DeviceInformation` push in 5.7 s on 2026-10-06.

3. **`/srv` inside `waze-mdm-fleet-api-1` is BAKED INTO THE IMAGE — it is not a bind mount.** The
 host's source of truth is `/opt/waze-mdm/fleet-api/`. Only `profiles/` is a mount
 (`./profiles:/srv/profiles:ro`). To change fleet-api behaviour you must patch the host file AND
 `docker cp` it into `/srv`, then restart; and a rebuild from a stale Dockerfile context silently
 reverts the container. Verify with
 `docker inspect waze-mdm-fleet-api-1 --format '{{json .Mounts}}'` before assuming a mount.

4. **The fleet API binds `127.0.0.1:8003` only.** From off-box it looks dead. Reach it over ssh:
 `ssh waze-mdm-01 "curl -s http://127.0.0.1:8003/health"`. Token: `FLEET_API_TOKEN` in
 `/opt/waze-mdm/.env`, sent as `Authorization: Bearer …`; without it every `/fleet/*` call returns
 `{"detail":"Invalid token"}` — which reads like a routing error and is not.

5. **Pushes are not instant.** `install-profile` returned `ok:true` and the device acknowledged
 ~2 minutes later, when it next checked in. `ok:true` from the API means "enqueued", never
 "installed". Poll `command_results` for the `command_uuid`, and treat an absent row as
 **pending**, not failed and not done. Two of my own reads during this session were wrong because
 I read before the acknowledgement landed.

## iOS profile/wallpaper rules that decide whether a rollout works (all re-verified 2026-10-06)

- **Ordering hazard, permanent damage:** `allowAccountModification=false` applied **before** an Apple
 Account is signed in leaves the device permanently unable to sign in, and therefore permanently
 unable to use Find My. Find My also requires a **consumer** Apple Account — a Managed Apple Account
 cannot use it at all. Ship the non-restricting payloads first; add the allowlist only after Find My
 is on.
- **`allowListedAppBundleIDs` is the COMPLETE visible app set**, not an additive list. Phone and
 Settings are the only apps that cannot be hidden. A Web Clip counts as an app (`com.apple.webapp`)
 — omit it and the clip installs, reports installed, and is invisible.
- **Hiding Safari destroys Web Clip delivery**: Apple's own text — "this setting also prevents users
 from opening Web Clips". `allowSafari` must stay `true` on any device whose main function is a
 managed Web Clip.
- **`allowPasscodeModification=false` prevents a passcode being added at all.** Applied before a
 passcode exists, the device can never set one.
- **Wallpaper IS pushable to a supervised iOS device.** MDM `Settings` command,
 `{"Item":"Wallpaper","Image":<data>,"Where":1|2}` (`1` lock, `2` home, `3` both), iOS 8+,
 supervised only. **Apple requires PNG, and `Image` must be `<data>`, not `<string>`** — a
 `<string>` is rejected with `CommandFormatError`. Proven on DRN 2001/2002 with `Acknowledged` in
 5–8 s and the fleet's own OCR verifier returning PASS.
- **Wallpaper label is a rank, not the fleet id.** `_wallpaper_label` for a non-`lakewood` site
 counts `WHERE site=? AND drn<=?`, so adding another device in the same site silently renumbers
 existing devices' wallpapers. If a label must carry the fleet id, it must be generated, not
 derived.
