2. A work step's message is already self-sufficient. app/autopilot.py
 `_build_work_prompt` injects the step, the job payload, the last 3,000 chars of
 tool output, get_tool_summary() AND `_build_owner_context(target_agent)`.
 So the owner-chat system prompt on that path was pure duplication. Before
 designing any per-call prompt budget, read the caller's message builder: the
 answer to "what does it actually need" is often already in the user message.

3. A fallback that names a provider you hold no key for must be DROPPED, not
 relabelled. First version of `_tier_candidates` read `deepinfra/deepseek-ai/X`
 from LLM_MODEL_FAST_FALLBACKS with no deepinfra key and produced
 ('deepseek', 'deepinfra/deepseek-ai/X') - a nonsense model id sent to DeepSeek.
 Detect "is a provider name" from the Settings class fields that end in
 `_api_key` (pydantic `model_fields`), not from a second hardcoded list.

4. A prompt-cache key must include the behaviour switch. Flipping
 ASSISTANT_WORK_PROMPT_MODE in-process kept serving the cached prompt from the
 other mode until the mode went into `static_key_seed`.

5. The worktree named in a fleet brief may not exist. `_fleet\a5-assistant` and
 `ws/assistant` were never provisioned while a1..a4 were; the brief forbade
 creating worktrees. Created additively (`git worktree add -b ws/assistant <new
 path> feat/cost-programme`) - new branch, new path, nothing existing touched -
 and said so in the report. Check `git worktree list` before writing anything.
