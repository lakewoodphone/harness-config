**L1746 · Plymouth Rock eService can be logged into unattended: use email MFA and read the code out of the owner's own Gmail**


The owner's Plymouth Rock eService login (ci2.plymouthrock.com/eservice/login) needs a 6-digit code. The MFA screen offers 'Text code to ******1594' or 'Use email instead'. Choose email, press Continue ONCE, then poll the owner's Gmail for the message with subject 'Your Plymouth Rock Verification Code' via app.services.gmail_service in ~/personal-secretary-mvp and type the code.

Traps that cost four runs:
- Codes expire fast. Submit within about a minute of the send. Poll every 3 s, do not wait 6 s at a time.
- internal_ts is in MILLISECONDS; divide by 1000 before comparing to time.time() or every stale code looks fresh. Take the newest, and skip the literal 666666 that appears in the boilerplate.
- Press Continue exactly once. Multiple clicks mail several codes, the older ones invalidate the flow and you get 'Oops! Email or password is incorrect.'
- The code field is the input with maxlength=6; the email/password inputs stay in the DOM behind the modal, so 'first visible input' fills the wrong box.
- Playwright 1.54 in ~/personal-secretary-mvp/.venv has no matching browser build in ~/.cache/ms-playwright. Pass executable_path='/usr/bin/google-chrome' to launch_persistent_context and it works.
- The SPA renders slowly and its data calls are POSTs to apims.plymouthrock.com/eservice-ws/api. Real data endpoints that work as plain GETs once logged in: /eservice-ws/policy/cancellation/<policy>, /eservice-ws/payment/checkAnyPendingPayments/<policy>, /eservice-ws/docs/validate/declaration/<policy>, and POST /eservice-ws/common/insurance/document which returns the ID card and declarations as base64 PDF in formServiceResponseList[].data.

Working scripts: ~/phone/insurance-plymouth-rock/evidence/pr_portal*.py (run10 is the first complete one).
