**The run I designed as a negative control turned out to be a real positive, and that is worth
knowing.** `--cross-tree /tmp` returned **128 errors**, not the single "no readable journal tree" I
expected, because `/tmp` on that Mac holds four leftover journal trees from earlier collection work:

```
TREE /tmp/base-pristine/ TREE /tmp/w3base/ TREE /tmp/w4-pristine-a95c3c77.../ TREE /tmp/w4pristine/
ERROR cross-tree id D200 in decisions carries a different body in base-pristine
ERROR cross-tree id H2171 in handoff carries a different body in base-pristine
```

So the tool compared the live tree against four pristine snapshots and reported the differences —
which is exactly the behaviour asked of it. **A "control" that was not actually a control is how a
test gets credited with proving something it did not**, and the reason I caught it is that the number
did not match the designed outcome. The genuine negative control was run earlier and on the canonical
tree: a directory holding no readable journal tree is an ERROR, not silence.

**One limitation, recorded rather than fixed:** the `INFO --cross-tree: compared N tree(s) under …`
summary line goes through the same `infos` list as everything else, so `check`'s info cap can elide
it. The error list is never elided, and comparing ZERO trees is an error rather than an info, so the
exit code still tells the truth — but the count of what was compared can be invisible in a run that
produced many infos. Fixing it means printing that line outside the capped list, which means
re-patching three copies; not worth doing tonight, and it must not be mistaken later for the tool
being silent about what it compared.
