**L2083 · Session-0 SYSTEM task: Start-Process -NoNewWindow silently failed to reboot the machine - verify side effects, not exit codes**

Firmware #1 of 3 installed and staged on ZABZ-TECH at 2026-09-20 16:20:38 UTC. The chain script then
tried to reboot with:

 Start-Process -FilePath 'shutdown.exe' -ArgumentList '/r','/t','60','/c','...' -NoNewWindow

It did nothing. Observed: the task exited `LastTaskResult = 0` (success), no `Start-Process`
exception was thrown, NO event 1074 ("The process ... has initiated the restart") was logged, and
`LastBootUpTime` was unchanged 2 minutes later. A silent no-op that looks exactly like success.

Cause: `Start-Process -NoNewWindow` from a session-0 scheduled task running as SYSTEM has no console
to attach to; the child is not reliably launched and its failure is invisible.

Do this instead - call the tool directly and log the exit code:

 & shutdown.exe /r /t 120 /c "message"
 "shutdown.exe exit code = $LASTEXITCODE" # 0 = restart registered

Verify the restart actually registered rather than trusting the exit code: look for System log
**event 1074**, or check that `(Get-CimInstance Win32_OperatingSystem).LastBootUpTime` moves.

Never add `/f`. Force-closed apps lose unsaved work, and on this machine that is the owner's.

Generalisation: from a non-interactive SYSTEM scheduled task, do not assume a helper process was
launched just because `Start-Process` returned. Anything launched that way must be verified by its
own side effect (an event, a file, a state change), not by the caller's exit status.
