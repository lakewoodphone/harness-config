**L1497 · A provider name that no route defines is not a YAML error, and nothing complains**

MEASURED 2026-09-15 on LakewooechsMini.

Its ~/.dsh/settings.yaml had gent-default-model.provider: deepseek-direct while llm-pi-ai.providers contained ONLY deepinfra. The provider it named did not exist. A hand-merge had also spliced the machine file's comment block into the middle of the document.

Nothing detected any of it: the file parsed, the engine booted, and the failure mode was silent -- the configured model simply was not the one in use, which is why images did nothing there.

THE FIX IS A CHECK, NOT A CAREFUL EYE. scripts/harness-sync.mjs now parses back the merged document before installing it and fails if gent-default-model.provider is not defined by any route, or if defaultPreset / model / agent-presets.default are unset. A merge that would leave the engine unable to mount is a hard failure BEFORE the write, and the previous settings.yaml is left untouched.

LESSON: any config that names a second thing must be validated against that second thing. YAML well-formedness proves nothing about whether the reference resolves.
