**L1686 · Task Manager Speed field on Intel hybrid chips is the base clock - never diagnose throttling from it**

## Rule
Never diagnose CPU throttling from Task Manager's "Speed" field on an Intel
hybrid part (Core Ultra / 12th-gen+ P/E/LP-E). It displays the *nominal base*
clock, not the live clock, so a perfectly healthy chip reads "1.45 GHz" all
day. Eliyahu asked on 2026-09-15: "is it being throttled cuz it's too hot or
something?" — the screenshot said 1.45 GHz, the chip was fine.

## Method that actually answers the question
1. `Get-WinEvent -FilterHashtable @{LogName='System'; ProviderName='Microsoft-Windows-Kernel-Processor-Power'}` —
 Event IDs 37/38 (thermal), 86 (power limit). **Zero events = no OS-visible
 throttle.** Measured 2026-09-15 on ZABZ-YOGA: 0 events in 24 h.
2. Live headroom: `Get-Counter '\Processor Information(*)\% Processor Performance'`.
 This is a percentage **of each core's own nominal clock**. 100 = base,
 <100 = clamped below spec, >100 = boosting. Measured: 113–144 % on all
 22 threads → boosting, not throttled.
3. `powercfg /q SCHEME_CURRENT SUB_PROCESSOR` → PROCTHROTTLEMAX 0x64 (100 %) on
 AC and DC; `Win32_Battery.BatteryStatus = 2` (on AC).
4. Die temperature is **not readable without admin** on this machine —
 `MSAcpi_ThermalZoneTemperature` returns Access denied and the
 `\Thermal Zone Information(*)\Temperature` counter returns −273.15 °C
 sentinels. Say "no sensor exposed" instead of inventing a number.

## What the 1.45 GHz really was
`Win32_Processor.MaxClockSpeed = 1400` on this Core Ultra 7 155H (P-core
nominal 1.4 GHz, E-core 0.9, LP-E 0.7 — the per-core nominal is visible in
`Win32_PerfFormattedData_Counters_ProcessorInformation`). Actual all-core
clocks while measured: ~1.6 GHz P-cores / ~1.3 GHz E-cores — i.e. at the
28 W-class power envelope under a broad 22-thread load, which is by design,
not a fault.
