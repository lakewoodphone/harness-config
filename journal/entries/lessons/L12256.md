**L12256 · A zero keypad count is three different facts - prove the capture path before blaming the keys or the person**

Measured 2026-10-22, ZABZ-TECH, handset 616202539 (E4610).

Three consecutive condition audits read `Keypad sweep | 0 key codes captured` -> INCOMPLETE, exit 2.
That sentence has three different causes and they look identical in the report:
 (1) nobody pressed a key, (2) the phone was asleep / screen off / keyguard up so the keys went
 somewhere else, (3) the bench app genuinely cannot see key events on this model.

How to tell them apart, all read live, no human needed:
 - The bench app logs tag `LPT_BENCH`. The key window announces itself:
 `STEP PRESS EVERY KEY AND SWIPE NOW (150 s)` in `adb logcat -d -s LPT_BENCH:*`.
 - Screen: `dumpsys power | grep mWakefulness=` must read Awake (run 161458 read
 `mWakefulness=Asleep`, `Display Power: state=OFF` - a real fault, and not the cause here).
 - Keyguard: `dumpsys window | grep mShowingLockscreen` - false on this unit.
 - Focus during the window: `dumpsys window windows | grep mCurrentFocus` must be
 `com.lpt.bench/com.lpt.bench.BenchActivity`.
 - Capture path: inject ~15 distinct codes with `adb shell input keyevent <n>` during the window.
 On 2026-10-22 that produced `PASS | Keypad sweep | 15 distinct key codes` and verdict
 SELLABLE_WITH_NOTES. The capture path works, so the three zeros meant nobody pressed.

Rules this produced:
 - A SYNTHETIC run is never keypad evidence. Quarantine it: summarize-condition.py globs
 `cli/logs/condition/*/report.json` one level deep, so move the run to
 `cli/logs/condition/diagnostics/<run>-synthetic-keys` plus a NOTE.md saying what it proves
 (capture works) and what it does not (the switches). Done for 616202539-20261022-162307.
 - `--keep-bench` leaves `com.lpt.bench` installed. Uninstall and prove it:
 `adb shell "pm list packages | grep lpt"` must be empty before the handset leaves the bench.
 - The register file is only written with `--markdown docs/condition-audit/register.md`;
 without the flag the script prints and the file stays stale.
 - For the sweep: `settings put global stay_on_while_plugged_in 7` (read it back) and
 `input keyevent 224` to wake. It MUST be reverted to 0 before finalize.
 - `audit-phone.ps1` resolved `$repo` one level short and wrote artifacts to `<repo>\logs\condition`
 instead of `cli\logs\condition`; fixed in d108aeed by walking up to the dir holding `cli\lpt`.
 - adb watchers must exclude `emulator-*`: a stale `emulator-5566 offline` line fired a
 "handset appeared" alert on 2026-10-22 with no phone on the cable.
