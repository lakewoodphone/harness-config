**L10626 · A restart is a policy change - do not deploy code inside a window you are measuring**

**Measured 2026-10-20 on `secratary-cloud`.** A session spent four hours building a controlled
comparison of DeepSeek's 01:00-04:00Z peak block, then deployed code and restarted `company-api`
**five times inside that block** (03:15:25, 03:17:27, 03:20:58, 03:27:37, 03:37:04). Its own
verifier now prints `CONTAMINATED … Do NOT read the deltas above as a result.` The one comparison
it had built the whole night for is void.

It had refused to switch the *policy* inside the window, on the correct reasoning that two policies
in one result is unmeasurable. It did not apply the same reasoning to *code*, because code feels
inert. It is not: a restart stops ticks, resets cadence and changes what is cached.

**The rule:** a restart is a policy change. A measurement window is frozen against deploys, env
changes and restarts — not just against the one knob you defined as "the setting". If something must
ship mid-window, the window is over; say so and start a new one.
