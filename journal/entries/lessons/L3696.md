**L3696 · The full pass found 44 more purchases and exposed a parser gap: 80 unitemised, none backfillable**

2026-10-13. The monthly full pass changed clause 2's numbers, and checking them found a real parser defect
with a reproducible case.

WHAT THE FULL PASS DID. Measured after it ran:
 purchases 585 -> 629 (+44) the full pass FOUND forty-four more real purchases
 carrying an amount 585 -> 625 of 629
 item rows 725 -> 739
 purchases with items 545 -> 549
 still unitemised 40 -> 80 the denominator grew, not the itemisation
So the unwindowed pass recovered four dozen orders the 90-day window had aged past, and the itemisation
RATE fell because the newly-found orders are older and carry fewer items. **A count that improves while a
percentage worsens is the shape a coverage fix makes, and it is worth reading both.**

AND NONE OF THE 80 IS COVERED BY THE LEGACY TABLE - I checked, and the answer is ZERO. So item 68's backfill
cannot help them; the merge I did earlier covered the then-unitemised set and these arrived afterwards.

THE REPRODUCTION, which is what makes this worth filing rather than describing:
 order 114-7984660-4547428 Amazon 2026-05-20 total 378.92
 note 'amazon-order-block' item_count 0
 subject Your Amazon.com order of "Crucial X9 1TB Portable..." and 3 more items.
 body 3305 characters, message id 19e46ec69937f679
**The subject names the first item and COUNTS the rest, so the mail holds four items, and the parser
returned none.** That is a PARSER gap, not a coverage gap: the message was just read by the full pass, the
order was created, and the items were not. Filed as ledger item 76 with this order as its definition of done
and a warning not to conflate it with the 2026-08 layout change (L3679), which is a SEPARATE cause where the
mail genuinely carries only a category - two different defects with two different fixes, and a session that
merges them will fix neither.

AND A NOTE ON WHAT AMAZON'S SUBJECTS GIVE AWAY. Even without the body, "Your Amazon.com order of X and N
more items" carries the first item's name and the count. A weak extraction would recover something for every
order in this class rather than nothing, and the DoD asks for the full four because the body is there too.
