**L1741 · The only surviving copy of a deleted doc can be under .runtime/deployments/ — and a repo sweep can delete the live one**

The policy record that solved the insurance case (car-insurance-policy-2026-05-09.md, containing the portal password, the VIN and the premium breakdown) no longer exists in the personal-secretary-mvp working tree: commit d7cd4ecf ('workspace sweep 2026-07-07') deleted it along with car-insurance-decision-2026-05-07.md, car-purchase-2026-05-04.md and three research responses.

It survived only at:
 ~/personal-secretary-mvp/.runtime/deployments/stage-20260517-022756-fd50691/docs/...
 (and a byte-identical sibling stage-20260517-022635-fd50691/)
~/.runtime is one 'rm -rf .runtime' away from gone, and it is not obviously part of the doc tree. It can also be recovered from git commit d8ac0fef.

RULE: when a document is reported missing, grep .runtime/deployments/ before concluding it is gone, and when a .runtime copy is load-bearing, cp it to a durable path in the same session. Also: a 'workspace sweep' commit is a destructive operation on documents — check what it deletes.
