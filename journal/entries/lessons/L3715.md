**L3715 · CUSTOMER_CASE_SYNC_RECORD.json: pricing.quoted is type number, so null fails schema validation - omit the key instead**

In `docs/customer-operations/CUSTOMER_CASE_SYNC_RECORD.schema.json`, `pricing` is documented but
NOT closed (`additionalProperties: false` is absent, so ad-hoc keys are accepted) - but the typed
keys it does declare still constrain. `pricing.quoted` is `{"type": "number"}`, so **null fails**:

```
SCHEMA INVALID: None is not of type 'number'
Failed validating 'type' in schema['properties']['pricing']['properties']['quoted']
On instance['pricing']['quoted']: None
```

Measured 2026-10-12 on `lg-gram-16t90p-usbc-bench-2026-07-29.json`, while removing a price that was
never a quote for that case.

**The fix:** omit the key. There is no "no quote" value in that schema; absence is the way to say
it. Same shape applies to any optional typed key in this file - if the honest value is "none", the
key must be absent rather than null.

Worth noting for the next reader: the root schema IS closed (`additionalProperties: false` at the
root) with an explicit `anyOf` matcher requirement, `references` and `pricing` are open, and
`references.productionOrder` is closed again. Validate with `jsonschema.validate` before believing a
record is pushable - the local `lptcase check` does not run the schema.
