# PowerShell: never name a function parameter `$Args` — it binds nothing, silently

Measured 2026-10-08 on ZABZ-YOGA (pwsh 7), reproduced in three lines:

 function A { param([string[]]$Args) "A count=$($Args.Count)" } # A @('shell','getprop x') -> count=0
 function B { param([string[]]$AdbArgs) "B count=$($AdbArgs.Count)" } # B @('shell','getprop x') -> count=2
 function C { "C count=$($args.Count)" } # C 'shell' 'getprop x' -> count=2

`$Args` is the automatic variable holding a function's unbound arguments. A `param()` declaration
for it is accepted but never receives anything, so the variable is always empty. Same family:
`$Input`, `$PSItem`, `$Error`, `$MyInvocation` — declaring any of them as a parameter is a lie.

**Why it mattered here.** `lpt-flip-phone/scripts/deployment/ready-e4610.ps1` (the wrapper written
2026-09-18 specifically so an E4610 cannot leave the bench staged-but-unfinalized) declares

 function Invoke-Adb { param([string[]]$Args, [switch]$Raw) $out = & adb -s $script:AdbSerial @Args 2>&1 ... }

Every call therefore ran `adb -s <serial>` with no command, and adb printed its own help text. The
wrapper read `Android Debug Bridge version 1.0.41 ...` as the device model and aborted with
"this wrapper is E4610-only; detected 'ANDROID DEBUG BRIDGE VERSION ...'". It had never been run on
hardware, so the bug shipped unnoticed — the phone-leak gate was itself dead.

**The fix.** Rename the parameter (`$AdbArgs`), keep a comment saying why it must not be `$Args`,
and be exhaustive about call sites: positional call sites (`Invoke-Adb @('shell','x')`) keep
working after a rename, but named ones (`Invoke-Adb -Args @(...)`) break *silently* — PowerShell
resolves the old name to nothing. PowerShell's parser will not warn you; read every call site.

**Bind proof before believing any wrapper** (used to verify the fix, worth reusing):

 $ast = [System.Management.Automation.Language.Parser]::ParseFile($path, [ref]$null, [ref]$null)
 $fn = $ast.FindAll({ param($n) $n -is [System.Management.Automation.Language.FunctionDefinitionAst] -and $n.Name -eq 'Invoke-Adb' }, $true)
 Invoke-Expression $fn[0].Extent.Text
 (Invoke-Adb @('shell','getprop ro.product.model')).Trim() # must be 'E4610', never 'Android Debug Bridge version'

Source: `lpt-flip-phone` serial 616462586, 2026-10-08; the fixed helper now returns the device's
answer (`E4610`, `package:com.android.cts.techmode`).
