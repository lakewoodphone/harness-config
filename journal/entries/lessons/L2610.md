**L2610 · Ingest age measures new work, not contact: I read a healthy shipper as broken because her DEAD ENGINE produced no new rows**

MEASURED 2026-09-28, on Yocheved's laptop (DESKTOP-FGV6KMH).

I read the authority's per-machine ingest age - `dsh_sessions.updated_at` for desktop-fgv6kmh was
274 hours stale - and concluded the machine's session shipper was broken, so her work was not
reaching the authority. That was a wrong reading of a right number, and it pointed at the wrong
subsystem.

What the number actually measures: the age of the newest ROW. Her engine had been unable to boot for
ten days, so no new sessions existed to ship. Nothing was failing to ship.

What was true the whole time, one line in a log I had not yet found
(`C:\Users\cheve\.dsh\logs\session-sync.log` - I had looked at the owner's path, `~/.dsh-session-ship.log`,
which is a different machine's convention):

 unchanged : 21 session(s) already complete (cursor)
 heartbeat : recorded contact for desktop-fgv6kmh (0 sessions, 0 rows)

So: all sessions shipped, cursor current, heartbeat arriving. The task's non-zero exit
(0xC0000409) is a libuv assertion at Node-on-Windows process TEARDOWN - it fires after the work is
done - so the task's failure status was itself misread as the work failing. That is L174 again
("the task exited 0 is not evidence the work happened") mirrored: **a task that exits non-zero is
not evidence the work failed.**

RULES
1. Age-of-newest-row measures NEW WORK, not CONTACT. When a machine looks quiet, find the heartbeat
 line before diagnosing the producer. "No new rows" and "no contact" are different facts with
 different causes, and only one of them was true here.
2. Do not infer a machine's log path from a convention observed on another machine. Yoga writes
 ~/.dsh-session-ship.log; her box writes ~/.dsh/logs/session-sync.log. The launcher script
 (session-sync.cmd) names the real path in one line - read the launcher.
3. An exit code describes the process, not the work. This one crashes on teardown after a fully
 successful run; checking the artifact (cursor current, heartbeat recorded) is what settles it.
4. Both errors here - the profile defect and this misreading - were invisible until I looked at the
 machine directly instead of at a summary of it.
