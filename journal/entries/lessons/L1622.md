**L1622 · docker compose config inlines env_file and prints secrets; use --no-env-resolution**

`docker compose config` RESOLVES `env_file` AND PRINTS THE VALUES INLINE. Running it to compare a committed compose file against a host's live definition dumps every production secret into the transcript, as plain text under `environment:`.

Measured 2026-09-15 on lpt-apps-01 while diffing /opt/chumash-timeline/docker-compose.yml: the output contained the real DATABASE_URL (with DB password), LPT_SSO_SHARED_SECRET and CHUMASH_SESSION_SECRET. This directly violates the "never print a secret value" rule, and I did not anticipate it.

Correct command when you need to render/diff a compose file that has an env_file:
 docker compose -f <file> config --no-env-resolution
That prints `env_file: - path: <path>` without inlining values. `--no-interpolate` is NOT enough.

Safer still: never render a compose file whose env_file points at production. Query only the fields you need, or render a copy whose env_file is a synthetic file.
Evidence: `docker compose config --help` lists `--no-env-resolution Don't resolve service env files` (Compose v5.5.0). With the flag, the rendered service showed `env_file: - path: /tmp/cv2/.env, required: false` and no secret values.
