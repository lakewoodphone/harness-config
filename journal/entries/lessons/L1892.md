**L1892 · Reparse-point trust on Windows is creator-bound: create a plugin junction from a LOCAL process and traverse it before naming it**

**Measured on ZABZ-TECH, 2026-09-17T14:0xZ.** One ssh-spawned `node.exe` on that machine read four junctions in the same directory and gave two verdicts:

 OK dsh-plugin-cost bytes=708
 OK dsh-plugin-attention bytes=504
 OK dsh-plugin-mesh-http bytes=1504
 ERR dsh-plugin-session-link UNKNOWN: unknown error, open '…\node_modules\dsh-…'

Same reader, same directory, one failure: **the trust attribute is on the JUNCTION, not on the reader**, so `70-remote-fanout-proof.md` §4.4 generalises to — a junction created by sshd is not trusted by the machine's own engine context, and on a machine with no console that bet is an unbootable profile. Corroboration from that machine's own logs: it booted engine pid 23164 at **2026-09-16 23:59:16** with `dsh-plugin-session-link` still named and answered on 3099, so the LOCAL reader traverses that junction; only the ssh-spawned reader refuses it.

**The supported construction, proven end to end on that machine the same hour:**
1. stage the files from the shared branch into the checkout (`git checkout origin/master -- <path>`): HEAD does not move and the index stays consistent for a later fast-forward;
2. create the junction with a process the **Task Scheduler** starts for that user, never over ssh. `Register-ScheduledTask -TaskName <new> -Action … -Trigger … -Settings …` with none of the four shapes measured to fail (`-Force`, `-Principal`, `-AtLogOn`, `RestartCount`) gives `logon=Interactive runLevel=Limited` — the same class as the process that starts that machine's engine;
3. **before naming anything**, have a SEPARATE process traverse the junction and read a file through it (`node -e "readFileSync(<link>/package.json)"` → `TRAVERSAL OK dsh-plugin-remote-fanout v0.1.0 bytes=1152 bundle=./cordis.patch.yml`), then compose the whole profile with a fresh local `--dump-config` (exit 0, 617 lines, both rows present);
4. only then write the name — and roll back (restore the manifest and patch-layer backups, remove the junction) if the composition fails.

An ssh-only `--dump-config` cannot see this class: an audit's ssh-spawned node got **exit 0** on that machine at 13:06Z while one of its junctions was untraversable, because that junction was not *named* at the time. Verify where the engine starts, or do not claim it.
