**L2347 · The phone question card's real fix lives in the phone layer, not in node_modules**

MEASURED 2026-09-22, secratary, the owner's phone path.

The owner reported the ask_user_question card on his iPhone: "the answers are not scrollable
with the question". I patched the module bundle in the npm install first. That was the wrong
lever, twice over:

1. `assets/question-card.css` already fixes this card on phones, and has since 2026-09-14 --
 the frame becomes a fixed 100dvh sheet, the card is the ONE scrollport, the footer is
 sticky. The gate injects it and `dsh-plugin-mobile` links it, so it is live. Before editing
 an installed package, grep the phone layer for the surface you are about to touch.
2. My module patch made the *detail* a capped scrollport (`max-height:...;overflow-y:auto`) and
 the option list a second one. In a plain desktop layout that looked like an improvement. On
 the phone it is the bug: `_body` is `overflow:visible` inside the sheet, so nothing between
 finger and card scrolls, and the 132px detail box swallowed the drag -- the text moved, the
 sheet did not. "I can't scroll" is exactly that.

WHAT WAS ACTUALLY WRONG (v0.1.5-rc.2 module CSS, inherited into the sheet): `.Mbwy4a_detail`
carries `max-height:var(--dsh-question-detail-max,180px);overflow-y:auto` (:132px under 720px).
The sheet does not clear it. A question with a long brief therefore has a nested scrollport on
top of the card's scrollport. The fix is four lines in `assets/question-card.css`: inside the
sheet, `_detail` gets `max-height:none;overflow:visible`.

HOW TO TELL A NESTED SCROLLPORT FROM A LAYOUT PROBLEM: measure `scrollHeight > clientHeight`
on every element between the finger and the intended scrollport, and take the numbers from the
REAL stack -- module CSS first, phone layer second -- not from the module alone. A replica built
from one stylesheet reported "can scroll" for a stack where the gesture was trapped.

PROOF THAT A REVERT IS A REVERT: `curl -sO` the published tarball from registry.npmjs.org,
untar, `md5sum` the file against the installed one. Same hash = the install carries the same
bytes it shipped with, whatever edits came and went.

REUSABLE: the npm install at /home/zabz/dsh-engine is not the source of truth for client UI on
the phone. The phone layer in harness-config is. Patch there, verify there, and leave the
package alone.
