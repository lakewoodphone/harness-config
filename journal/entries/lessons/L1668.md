**L1668 · An unrebuildable journal cache turns a search into a false 'no match'; financial figures must be re-derived from the processor's own notices and the live bank feed**

**L#. The journal tool's cache rebuild is broken right now, and the tool degrades silently to a slower path
that returns emptier answers.** On 2026-09-15 every `journal.py status` / `search` printed
`journal: cache could not be rebuilt (not enough values to unpack (expected 6, got 4))` and answered from
`entries/` instead of the index. `status` still worked; `search "Weinberg"` and `search "arrears"` returned
**"no match"** — which the tool itself labels "a refusal, not health", but which reads like an absent topic.
The topics existed. Cost: I went to the repos and the bank feed instead, which happened to be the right move
anyway, but a session that trusted the "no match" would have concluded the company had never discussed
payroll arrears. *Rule: a journal search that returns nothing while the cache is unrebuildable is a broken
instrument — say so and read the entries directly, do not treat the empty result as fact.*

**L#. Every figure in this session came from one of three places, and naming which one is what made the
number trustworthy.** (a) Gusto's own emails — the processor's statement of intent; (b) the bank feed on the
authority (`plaid_transactions`, account `…69P0`, max txn date 2026-09-14) plus a live
`accounts_balance_get` for the current balance ($1,732.67); (c) the repo's own prior audit, which was right
to the cent. The one number that existed nowhere was the split between the two bad weeks, and it was
recovered by reconciling Gusto's own debit totals. *Rule: when a financial question is asked, do not carry a
figure from a document — re-derive it against the processor's own notices and the bank feed, and state the
age of each read.*

**L#. `app/services/plaid_service.py::get_accounts()` is still broken** (`AttributeError: module 'plaid.api'
has no attribute 'ApiException'`), as the 2026-09-10 audit recorded. The working path is to call
`client.accounts_balance_get(AccountsBalanceGetRequest(access_token=...))` directly with the
`plaid.Configuration(host=plaid.Environment.Production, api_key={"clientId","secret","plaidVersion"})` setup
and the token from `plaid_items.access_token`. That is how the $1,732.67 balance was read tonight.

**L#. Writing to the authority's SQLite from here means working around lock contention.** The
`owner_decision_queue` insert failed twice with `database is locked` because the secretary API holds the DB.
Setting `PRAGMA busy_timeout` and retrying in a loop fixed it on the first retry. Also: multi-line
PowerShell here-strings injected into a Python `-c` or `sys.argv` wrapper break on the embedded newline —
pass payloads as one base64-encoded JSON blob and read them from a file. That is the pattern that worked.
