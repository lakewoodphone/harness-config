**L6237 · AppData/Local is not just caches: it holds Chrome bookmarks and SAVED PASSWORDS, and the house copy tool excludes the whole tree**

**L · "AppData/Local is caches" is false. The house copy tool excludes it wholesale, and inside it sit the customer's browser bookmarks and SAVED PASSWORDS.**

Found 2026-10-14 on the Raitzik job, by auditing what the copy had left behind rather than trusting that "caches" meant caches. `lpt-copy-userdata` runs with `--exclude=AppData/Local --exclude=AppData/LocalLow` and keeps only `AppData/Roaming`. Sitting in the excluded tree on that machine:

| file, at `AppData/Local/Google/Chrome/User Data/Default/` | bytes |
|---|---|
| `Login Data` — **saved passwords** | 61,440 |
| `History` | 344,064 |
| `Cookies` | 1,277,952 |
| `Web Data` — autofill | 94,208 |
| `Bookmarks` — **the bookmarks** | 1,316 |
| also: `AppData/Local/Microsoft/{Windows Live Mail, Windows Mail}` | 44 MB together |

The tool's exclusion list is not wrong about *size* — 3.5 GB of that tree really is cache — but the same directory holds the small, irreplaceable, text-sized files that make a browser feel like the user's browser. **None of them was on the archive and none would have been on the stick**, and no verify of that copy could ever have noticed: the verify compares the destination against the source *minus the same exclusions*, so an excluded file is invisible to it by construction.

**What to do, and it is cheap:**
1. After any copy that excludes `AppData/Local`, audit inside it for user-worthy stores before calling the job done: browser profiles (`Google/Chrome/User Data`, `Microsoft/Edge/User Data`, `Mozilla`), mail stores (`Windows Live Mail`, `Windows Mail`, `Thunderbird`), and anything else whose name is an application rather than a "Cache"/"Code Cache"/"GPUCache"/"WebCache"/"thumbcache".
2. Rescue the profile **minus its cache directories** — 581 MB became 106 MB with only caches dropped — path-preserving (`rsync -aR "$P/./AppData/Local/Google/Chrome/User Data" "$MASTER/"`, note the `-R` and the `/./` or rsync will not create the intermediate `AppData/Local/...` path; the first attempt failed exactly there with "mkdir ... failed: No such file or directory" while my script cheerfully printed "rescued" because I never checked its exit code).
3. **`--exclude=AppData/Local` should be revisited as a default.** The honest default for a recovery job is "exclude the cache directories by name", not "exclude the tree that contains the caches".

**The generalisation worth carrying:** an exclusion rule is a claim about content, and every exclusion in that list was written from a *size* reading. Size is exactly the wrong instrument — the 1,316-byte `Bookmarks` file and the 428 MB Explorer log live in the same tree.
