**L1568 · The chat hub forwarded correctly and stored the opposite, so every test passed while Chip read blank lines**

FOUND 2026-09-15 while investigating why Chip's family-chat texts went out of place.

app/family_chat/db.py insert_inbound_message passed its INSERT arguments in the
wrong order: the SQL column list was (..., body, media_urls, ...) but the tuple
supplied (..., ','.join(media_urls), body, ...). Result: every inbound row was
written with body='' and the message text in media_urls.

Measured on the authority: 116 of 140 stored inbound rows had an empty body with
the text sitting in media_urls, and the SAME signature is in every backup from
2026-08-30 on, so the bug dates from the module's introduction (2026-08-09,
commit 835fbc50). Not a regression.

WHY NOTHING CAUGHT IT: the hub's forwarding path used the correct local variable
(the handler's inbound_text), so all 141 family-chat tests passed. They assert
sender.calls (what went out) and never asserted the row they WROTE. Chip's
context builder reads db.recent_messages(), so Chip was reading a conversation of
blank lines -- 83% of every inbound message invisible -- and filling the gap with
generic lines.

THE RULE: when a function writes a row, assert the row you read back, not the
call you made. Tests that only check the outbound side of a store-and-forward
pipeline cannot see a storage bug in it.

A second trap: two of my four new tests passed against the known-broken code.
One asserted a bare substring after an apostrophe-bearing string (matched the
FORWARDED '[out] Name: text' copy, not the inbound line); another asserted
row['body'].strip() was non-empty, which the '(photo)' placeholder satisfies.
Fixed by filtering out [out] lines and asserting the exact body value. A test
that passes on the broken revision is not a guard -- it is noise that reads as
safety. Always run the new test against the pre-fix code.

SIDE EFFECT WORTH REMEMBERING: because text landed in media_urls, cmd.body LIKE
'http%' fires on real message text, and _requeue_media_fallback would re-send a
failed MMS as a text carrying the ORIGINAL TEXT as if it were a photo link.
