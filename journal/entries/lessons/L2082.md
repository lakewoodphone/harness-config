**L2082 · Scope recursive script searches; an unanchored 'PIN' across ~/code matched node_modules noise and timed out**

A recursive `Get-ChildItem $env:USERPROFILE\code -Recurse | Select-String -Pattern 'Ngc|WinHello|PIN|...'`
cost a 120-second foreground timeout and then returned 14 KB of `pending`/`pin` substring noise from
node_modules bundles. Two costs, no answer.

Do this instead:
- Prefer the in-process `grep` tool with an `include` glob (`*.ps1`) - it is ~700x cheaper than a pwsh
 call and cannot time out the way a recursive filesystem walk does.
- If a shell is genuinely needed, filter BOTH ways in one call:
 Get-ChildItem $d -Recurse -File -Include *.ps1,*.cmd,*.bat |
 Where-Object { $_.FullName -notmatch 'node_modules|\\\.git\\|chocolatey' } |
 Select-String -Pattern '<anchored|word-bounded pattern>'
- Search a short explicit list of directories, never the whole home tree.
- Word-boundary the pattern. `PIN` unanchored matches `pending`, `pinned`, `spinner`.

Corollary for the boot diagnosis that followed: choosing a NARROW, high-signal log
(`Microsoft-Windows-HelloForBusiness/Operational`, which held ~200 events) beat reading the big ones.
