**L12364 · lpt-write order create: the evidence guard, and the CRLF pipe that fakes a failure on Windows**

`lpt-write order create` refuses an order it cannot trace, and on Windows the pipe to it lies about the exit code.

Two things measured 2026-10-25 while opening the first work order for a device that had none (Canon ELPH 330 HS, customer 1396, WO26102512773).

1. **The guard is real, and it is a good guard.** `order create` requires BOTH `--case-slug` and at least one `--evidence <path>:<sha256>`, and the helper refuses with "an order must be traceable to what justified it" without them. The evidence string is not checked for existence and the helper prints it as "photograph(s)" — so passing a non-photo here is possible and would be dishonest. What I actually had was the printed intake label taped to the camera, staged at `/root/lpt-intake-evidence/<slug>/label-intake.png` with its sha256, and the note says in as many words that the token is the label and not a photo of the device. If a bench photo is ever taken, attach it and say so in a note — do not let the create's "1 photograph(s)" stand as a claim about the device. `--custody-unverified` exists for the other direction, and it prints "the photo shows a bin, not a bench".

2. **`Get-Content -Raw file | ssh host 'bash -s'` sends CRLF, and bash reports `$'\r': command not found` on the LAST line only.** The script body runs, the write applies, `rc=0` prints — and the ssh session still exits **1**, because the trailing `echo "rc=$?"` line carries a stray CR. That is a harness artefact, not a failed write, and the way to tell the difference is the read-back, not the exit code: `lpt-write` printed `WROTE` + ledger seq, and `lpt ticket` then showed the row. `-replace "`r",""` in PowerShell did not remove it, so the CR is added when PowerShell serialises to the native stdin. **Never conclude a Windows→bash write failed because of a trailing exit 1; re-read the record.** And never conclude it succeeded from `rc=0` alone either — the same line is what produced it.

The read-back that settled it: `lpt ticket WO26102512773` -> `[AWAITING_PARTS]`, `total USD 95.00`, ticket 2840, one GENERAL note, status history `None -> AWAITING_PARTS`. Ledger `/home/zabz/lpt-ops/audit/writes.jsonl` seq 497 (create) and 498 (note).

Related: a device physically in the shop with no row anywhere is the failure this whole session started from (L12361). The label was printed first and got a work-order number on it only after the order existed — two labels, 61.3 mm of tape, and the second one is the one the secretary can actually act on.
