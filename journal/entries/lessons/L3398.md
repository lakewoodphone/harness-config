**L3398 · Read the tool's --help before its README, and fix the README in the same session**

**A tool's README rots faster than the tool, and the owner says "the flow from your session" about
the code, not the prose.** 2026-10-08: the owner wrote *"pull up the flow to create work orders in
case files from your session"*, meaning the intake-to-production path built earlier the same day.
`tools/intake/README.md` (written 2026-10-07) documents `take`, `file`, `question`, `close-out` and
nothing about production - but `tools/intake/intake.py --help` lists **`promote`**, the subcommand
that turns one judged ledger row into a real work order, and `file`'s `--order` flag, which the
README predates. Reading only the prose would have produced a session that filed a case and then
told the owner production could not be reached from here - which was true on 2026-10-07 and false by
2026-10-08.

Rule: when asked to use a flow, run the tool's own `--help` before the doc, and treat a subcommand
the README does not mention as a **documentation defect to fix in the same session**, not a curiosity
to note (fixed here in `2367c159e`). The same hour, the same page: the 2026-10-07 README's own
"Still outstanding" list said rows 7-16 were not entered, and by the time I read it every one of them
had a work order.

Evidence: `tools/intake/intake.py promote --help`; H3380; commits `1ed611566`, `2367c159e`.
