**L12190 · Observe a read's revision before the write it licenses is enqueued**

A write that a READ licenses must be enqueued AFTER the read's revision is observed. The write queue reads the revision at ISSUE time (`drain` -> `options.readRevision()`), and `enqueue` issues synchronously when the wire is free — so an `enqueue` placed above `applySharedStateToUi` sends the write with the mirror's stale revision and the route refuses it 409 against this device's own lost write.

Measured shape: the first write after a page reload was refused "expected revision 16 but the stored revision is 17" — the write that consumed 16 went out just before the reload and the navigation destroyed its response (net::ERR_ABORTED), so the browser never learned 17. The boot read reported 17 and the boot write carried 16.

Where: repo `_pt_wt/fx-bootwrite`, commit f9ab6ec on fix/boot-write-revision. Fixed by `issueBootWrite` in src/lib/assessment/persistence-write-queue.ts: observe the read's revision, then enqueue. Cost is zero — the read has already returned — and `observe` only raises the watermark, so no rule is weakened.

Transferable technique, because this cost me a decision: this suite runs `environment: "node"` with no jsdom or testing-library, so a defect living inside a React component (assessment.tsx) cannot be driven by a failing test. Extract the defective ordering into a production function in the module that owns the rule, wire the component to call it, and the test can then drive the real queue, the real watermark and the real handoff. Extract behaviour-preserving FIRST (bug included), watch the new test fail with the measured shape, quote that line, then move the line.

Checked and already correct, same shape: any read applied through `applySharedStateToUi` before it returns (refreshStoredRegistry's non-boot branch) leaves the watermark holding the read's revision before the caller's commit, so syncVisibleSessionWithSharedLibrary, the storage handler and the boot effect were never exposed. `retryPendingRemoteSync` and `commitRegistry` enqueue with no read in scope. `loadSharedAssessmentLibraryStateForBoot` writes with the read's own revision explicitly and is unused by the component.
