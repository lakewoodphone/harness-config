**L3351 · Two records disagreeing about a physical safety mechanism means unknown - read the device**

When two records in one repo disagree about a physical safety mechanism, neither is evidence — read
the device.

**Rule.** If a document asserts a property of the physical world that a human's safety depends on
("the door holds released", "nothing is cut when the server is down"), that assertion is a claim no
file can settle. Two docs in the same repo asserting opposite things means the truth is *unknown*,
not that the newer doc wins. Resolve it by reading the device's own state, and until then report the
risk as unknown and act conservatively — because the expensive error is a confident "it's safe".

**Evidence, 2026-10-06 (P2858).** Two current docs describe the same Shabbat power-down:
`shabbat-power-automation-hardening.md` states *"if the secretary is down, nothing is cut (no
device-side off-schedule)"*; `shabbat-power-automation.md` (marked LIVE) states the on-device
schedule *"fires even if the secretary or HA is down"* and records a real cut firing on 2026-09-25.
Both are in the repo, both marked current, and they disagree about whether the house's interior door
can be opened during the automated window. Detection of the disagreement took reading both, which
only happened because the outage forced a re-read. A design that had trusted either one alone would
have shipped a confident claim about a door.

**Corollaries.**
- Prefer device state to documentation for anything physical: the plug's `Schedule.List`, the
 relay's event stream, a photograph. The docs describe intent at a moment; the device holds fact.
- Mark safety-critical claims in docs with the check that would falsify them, so the next reader
 knows which sentence is load-bearing.
- Write the *ask* as the deliverable when you cannot resolve it. "Read the plug's schedule list" is
 a better output than a paragraph that picks a side.
