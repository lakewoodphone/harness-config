**L2363 · SQLite: datetime('now') does not compare against an ISO stamp with a T and an offset -- the filter silently matches nothing**

## The rule

**`datetime('now')` and a stored ISO stamp with a `T` and an offset do not
compare in SQLite; the comparison silently returns zero rows.** Parse the stamp
in Python, or wrap BOTH sides in `datetime()`. A filter that returns nothing is a
refusal, not health.

## Measured evidence

2026-09-23, on `secretary.db` (`owner_message_queue`, 1,863 rows): this returned
**0**

 SELECT COUNT(*) FROM owner_message_queue
 WHERE status='held' AND created_at < datetime('now','-24 hours');

while the oldest `held` row was 44 hours old. Cause: string comparison.
`created_at` is `2026-09-22T03:20:10.900253+00:00`; `datetime('now')` produces
`2026-09-23 23:16:00`. `'T'` (0x54) sorts above `' '` (0x20), so every stored
stamp compares greater than every generated one and the predicate is never true.
`app/services/lifecycle_sweep.py` gets this right by wrapping both sides in
`datetime()`.

I have now made this mistake once and read a healthy table as empty. Write the
age comparison in Python, or wrap both sides, and never report a count whose
query you have not sanity-checked against an extreme row.
