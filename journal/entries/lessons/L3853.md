**L3853 · E4810 558800292460 full re-install: 10 apps were never installed; two verify gates are profile-blind**

E4810 558800292460 full standard re-install 2026-10-18: what it fixed, and the two gates that still lie.

## Why she "didn't have all the apps"

Not a hidden-app problem. Ten packages were **not installed at all** — `dumpsys package` ABSENT for
`com.android.cts.palms` (tehillim), `.haderech`, `.brochos`, `.smartzmanimk`, `.adndaven`, `.crc`,
`.qr`, `.weather`, `.lionscribe.elist` (smart-list), `.quickjack` (quickoffice). They are exactly the
10 user slugs the 2026-04-17 receipt for this serial lists under `excluded_apps`. `lpt-keys` was
also behind: device 4.0.0, repo APK 4.2.0.

## What was run

```
.venv\Scripts\python.exe -m lpt.cli deploy --model E4810 --tier standard \
 --profile standard-no-text --serial 558800292460 # dry-run first, then real (2m10s)
```

Result: install, permissions, post_install, runtime_config, accessibility, keys_whitelist,
bloatware, launcher all `success`; **verify failed** on `accessibility_runtime` (rc=1).
All 17 apps then measured at the exact repo APK versions (`to install/update: 0`, aapt-verified):
keys 4.2.0, techmode 2.0.0, matvt 1.0.3, voiceaccess 4.0.304676510, waze 4.99.1.1, and the 10.

## Gate 1 lie: accessibility_runtime, and the real fix

The check searches `dumpsys accessibility` for the service's package/class markers. On this ROM the
dump prints services **by label, truncated to 20 chars**: `Service[label=com.google.android.app…`.
After a reinstall the label is a resource-failure fallback (logcat: "Failure retrieving resources for
com.android.cts.apps.accessibility.voiceaccess"), so no marker can ever match → permanent false FAIL.

Fix that worked: force a rebind by rewriting the secure setting with the service removed and then
restored:

```
FULL=$(adb shell settings get secure enabled_accessibility_services)
adb shell settings put secure enabled_accessibility_services '<FULL minus voiceaccess>'
sleep 2
adb shell settings put secure enabled_accessibility_services '<FULL>'
```

The label then reads `Service[label=Voice Access` and `accessibility_runtime` PASSES. The engine's
accessibility phase should do this rebind itself after installing the APK.

## Gate 2 lie: lpt_keys_runtime_config

Verify demands `key_map.home_message`, `home_message_package/activity/home_only`. The loader
**deliberately** omits them when texting is off (`config/loader.py:648`
`home_message_enabled=(not disable_texting and "message-plus" in app_slugs)`). On a `-no-text`
phone that FAIL is by design. `apps_installed` fails the same way: it wants
`com.verizon.messaging.vzmsgs`, which `standard-no-text` excludes. `lpt verify` has **no --profile
flag**, so it cannot know either. Both FAILs are the verifier being profile-blind, not phone faults.

## The one thing that was actually broken on the phone, and is now fixed

The app drawer opened with **one entry** — `LP&T Tech Mode` — because
`/sdcard/Android/data/com.android.cts.apps4fliplauncher/files/lpt_app_list_config.json` contained
`allowed_packages: ["com.android.cts.techmode"]` only, written 17:02 during the deploy.

The loader is NOT the cause: called directly with the same arguments it yields 13 packages
(techmode + the 12 user apps). Something rewrote/never wrote the pushed payload; cause unproven,
recorded as pain. Re-pushing the 13-package file stuck (unchanged after 12 s and after a
force-stop + relaunch) and the drawer now reads 13 entries, confirmed by `uiautomator dump`:
LP&T Tech Mode, Tehillim, Teffilas Haderech, Brochos, Smart Zmanim, AndDaaven visible, with
cRc Kosher Guide, LP&T Waze and LP&T Waze Launcher rendered below the fold.
`lpt verify` now reports `app_list_runtime_config PASS`.

## Method note

`aapt dump badging <apk> | grep versionName` (SDK build-tools 36.1.0; aapt is not on PATH) is what
turns "latest version" into a measurement. Compare it against
`dumpsys package <pkg> | grep -oE 'versionName=[^ ]+'` per installed package; `_scratch/e4810-app-gap.py`
in the lpt-flip-phone checkout does the whole tier in one pass.
