**L3643 · A freshness check that asks 'is a job scheduled' is not asking 'is the money arriving'**

Found 2026-10-13 in `/opt/company/app/services/finance_freshness.py` by disbelieving its own green.

THE FALSE PASS. The tool reported `lpt_openai -> OK, age 0.003h`. The OpenAI spend feed was in fact
dead: its Costs API returns HTTP 403 "Missing scopes: api.usage.read" on every window, and no data
had arrived since 2026-06-12. Two independent mechanisms produced that green:

1. **A manual run masks a dead pull.** I ran the SaaS ingest by hand at 02:56; it wrote 121 rows to
 `lpt-openai-spend` (107 -> 228) with historical transaction dates, bumping `created_at` to now.
 The tool's ledger signal is `created_at`, so the source read "captured 0.003 hours ago". A source
 is only as fresh as the last time somebody ran it by hand, and nothing distinguishes that from a
 working clock.

2. **The probe tested presence, not success.** For sources in `PULL_SCHEDULE_PROBE`, the code did
 `if token in schedule_text: PULL_OK`. That answers "is a job scheduled". A job that runs every
 night and fails every night read OK forever. The estate already has the data to answer the real
 question - `cron-wrap.sh` appends `timestamp \t job \t exit \t seconds \t stderr` to
 `~/.cron-status/runs.tsv` for every run - and nothing consulted it.

FIXED. The probe branch now reads `~/.cron-status/runs.tsv` and takes the last run per job:
non-zero exit -> `PULL_FAILED` with the exit code and the captured stderr; no run recorded ->
`PULL_OK` but saying so ("no run recorded yet"), so a newly-installed clock is not mistaken for a
proven one. `lpt_openai` and `lpt_twilio` were also absent from the probe map entirely and are now
mapped to their `finance-saas-sync` clock.

RULES.
1. Two different questions, two different probes: "is it scheduled", "did the last run work", and
 "is the data recent". A check that collapses them will be green for the wrong reason.
2. When a system has an outcome log, measuring presence instead of consulting the log is choosing
 the weaker signal deliberately. `~/.cron-status/runs.tsv` is that log on this estate.
3. Before reporting a green, ask WHAT MADE IT GREEN. Here the answer was "I ran it myself an hour
 ago" - which is a fact about me, not about the feed.
