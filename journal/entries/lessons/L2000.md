**L2000 · 'The probe could not see it' is not 'it is not there': two of my own conclusions falsified by the fleet I sent to check them**

**L · "The probe could not see it" is not "it is not there": two of my own conclusions falsified in one hour by the fleet I sent to check them**

CORRECTS AND SUPERSEDES part of **L1998** ("A node's name is not a capability"). L1998's headline lesson
was right and its evidence was half wrong. Both wrong halves were produced by the same habit, and the
habit is the actual lesson.

WHAT L1998 CLAIMED, AND WHAT IS TRUE:

1. *"`mac-mini-ts` has NO node on PATH today, so its row [in `lib/nodes.js`] is stale."* **FALSE.**
 Workstream M3 measured it: sshd gives a non-interactive macOS session the PATH
 `/usr/bin:/bin:/usr/sbin:/sbin`. Node exists at `/usr/local/bin/node` →
 `node-v24.19.0-darwin-arm64/bin/node` (**v24.19.0**, Mach-O arm64, `-v` rc=0) and at
 `~/.local/node-v24.12.0-darwin-arm64/bin/node` (**v24.12.0**, added only by `.zshrc`/`.zprofile`,
 which a non-interactive ssh never sources). **Two working runtimes. The node table was RIGHT and my
 probe was wrong.**
 A second defect in the same probe: `engine:3099 = no` for that machine. The probe asked
 `ss -ltn || netstat -ltn`, and macOS has no `ss` while BSD `netstat` rejects `-ltn` — so the count
 came back 0 **by error**. `lsof -nP -iTCP:3099 -sTCP:LISTEN` shows **pid 12458 LISTEN**; a DSH
 engine has been running on that mac mini all along.

2. *"`secratary` cannot absorb agent work — it is nearly out of commit."* **OVERSTATED.** Workstream M2:
 `vm.overcommit_memory = 0` — heuristic mode, in which `CommitLimit` and `Committed_AS` are *reported*
 but **not enforced**. "3.4 GB commit free" therefore never meant 3.4 GB usable. Measured:
 `Committed_AS` ≈ 10.3–10.4 GB (**44 % of RAM**), real free commit ≈ 5.5 GB, `MemAvailable` 17.7 GB.
 The genuinely scarce thing is different: **swap is 4 GiB and 100 % full (216 kB free)** with
 `vm.swappiness = 10`, so there is no reclaim buffer for anonymous memory at all. The one tenant with
 a runaway history is `secretary-api` (uvicorn), bounded by a cgroup drop-in at 5/8 GB because it
 previously reached ~20 GB and triggered 8 OOM kills on 2026-09-15 and 23 more on 2026-09-16 — and it
 was restarting *during* M2's probes, which is why M2 could not reproduce my sample. **Verdict:
 secratary CAN host a long-lived child, if it is small.** The rule is "place small and watch the
 swap", not "never place here".

THE ROOT CAUSE OF BOTH, which is why this entry exists: **I read a probe's inability to see something as
evidence that the thing was absent.** `node -v` printing nothing is a statement about the *environment
the probe ran in*; I wrote it down as a statement about the machine. `ss -ltn` returning 0 rows is a
statement about `ss`; I wrote it down as "no listener". This is the same failure class as the stale
database this repo has been bitten by twice: a confident reading of something that was never measured.
And the fix is the same one the recovery paths already use — **when a check can fail by not being able
to look, it must distinguish "no" from "could not ask".**

WHAT WAS ACTUALLY A FIX, VERIFIED BY OBSERVATION RATHER THAN BY CONFIG: the child-turn ceiling raised in
L1997/D267 is live. Two children on `desktop-ts` ran **449,151 ms** and **503,943 ms**, both `exit = 0` —
both well past the old 300,000 ms guillotine that killed five fleets on 2026-09-17.

ALSO MEASURED, AND IT MATTERS FOR SCHEDULING: **reachability is directed.** A child running on
`desktop-ts` hung at ssh connect to another node and exited 255 with no final message, while the laptop
reached all five nodes in under 3.4 s each; M2 hit the same thing from the same node and had to route
every command through `Start-Process -RedirectStandardOutput` because "the pwsh wrapper never saw it
exit". So no scheduler may assume any node can reach any other, and any brief that asks a child to ssh
between nodes must bound every hop with a hard timeout — otherwise the child dies holding the parent's
work, which is exactly what happened to M1.

ACTION TAKEN: `_scratch/mesh-inventory/probe.sh` now falls back to absolute node paths (reporting *which*
path answered) and tries `ss`, then `lsof`, then `netstat -an -p tcp`. `docs/mesh/109-node-inventory.md`
carries both corrections inline with the strikethroughs left visible, because the record of having been
wrong is the point.
