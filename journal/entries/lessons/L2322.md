**L2322 · A blocked source is a gap, never a negative finding (westeros.org and Martin's Dothraki claim)**

RULE: when a canonical source is unreachable, the finding is UNKNOWN - never "it did not happen".

CASE (2026-09-22, GoT research): westeros.org, which hosts "So Spake Martin" - the canonical archive of George R.R. Martin's own statements - returned Cloudflare 403 on every attempt. A subagent then concluded that the claim "the Dothraki are based on Mongols and steppe peoples" was NOT Martin's own claim, only fans'/journalists'. That conclusion is FALSE. Martin's words: "The Dothraki were actually fashioned as an amalgam of a number of steppe and plains cultures... Mongols and Huns, certainly, but also Alans, Sioux, Cheyenne, and various other Amerindian tribes... seasoned with a dash of pure fantasy." Found quoted verbatim in Bret Devereaux, acoup.blog "That Dothraki Horde, Part IV", 2021-01-08.

WHY IT MATTERS: this is P3's failure class ("reading the wrong data and believing it") in a new shape. A blocked source becomes a confident negative that reads exactly like evidence of absence, and it survives into the deliverable unless someone re-checks it. The verification pass caught it only because the second source happened to quote the original.

DO: label it UNVERIFIED - SOURCE BLOCKED, name the blocked URL in the report, then actively hunt a secondary source that quotes the original before settling for a negative.
