**L2061 · Twilio browser SDK: use the npm package dist bundle; the CDNs 403 from this host**

## What happened
Building the live voice-changer dialer I needed the Twilio Voice browser SDK served locally.
Three "obvious" URLs all failed from secratary:

 https://sdk.twilio.com/js/voice/releases/2.15.1/twilio.min.js -> 403 AccessDenied
 https://media.twiliocdn.com/sdk/js/voice/releases/... -> 404
 https://unpkg.com/@twilio/voice-sdk@2.15.1/dist/twilio.min.js -> 404

## The working path
`npm install @twilio/voice-sdk` ships a ready browser bundle at `dist/twilio.min.js`
(303 KB, browserify IIFE). No bundler needed:

 npm i @twilio/voice-sdk@2.18.5
 cp node_modules/@twilio/voice-sdk/dist/twilio.min.js public/vendor/

Verify it exposes globals before believing it:
 node -e "global.window=global; require('./public/vendor/twilio.min.js');
 console.log(typeof window.Twilio.Device)" # -> function

## Why it matters
I nearly hand-rolled an esbuild bundle from `es5/twilio.js` (CommonJS, requires
`errors/index.js` etc.) when a complete prebuilt bundle was already inside the package.
(1) `dist/` in an npm package is usually the browser build - look there before bundling.
(2) A CDN 403/404 tells you nothing about the library, only about that URL.

Evidence: /home/zabz/phone/live-voice-dialer/public/vendor/twilio.min.js (303272 B) loads
and exposes Twilio.Device / Call / PreflightTest under a fake window global.
