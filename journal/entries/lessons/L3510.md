**L3510 · A production work order can only be created through app.services.website_db.create_order - lpt-write order create does not exist and intake.py's promote path calls it anyway**

**Measured 2026-10-11 (ZABZ-TECH, Fisher SD-card intake).** There is exactly ONE way to create a
Lakewood production work order, and it is **not** a CLI.

**What does not exist.** `lpt-write` (lpt-ops) ships `doctor, deploy, vocab, note, status, total,
payment, audit, probe` — no `order`, no `customer`. Verified it never existed:
`git log --all -S 'add_parser("order"'` in lpt-ops returns nothing. Yet two files reference it:
`lpt-hub/tools/intake/intake.py:450` ("It creates nothing itself: `lpt-write order create` owns every
gate") and its `cmd_promote`, which builds that exact argv at line 472, plus `lpt-ops/lpt_ops/photos.py:10`.
**So the intake promote path is dead** — it shells out to a subcommand that has never existed, and no test
covers it.

**What does exist.** `app/services/website_db.py::create_order()` — its own docstring calls it "the
single canonical WO-create path". It finds-or-creates the customer by phone, dedups against recent
orders, bumps `ticket_counters`, inserts a `tickets` row and an `orders` row with
`orderNumber = WO{YYMMDD}{ticket#}`, writes `order_status_history` and `website_write_log`. Callers:
`app/chat_action_phone_tech.py:1311` (the CEO action **`create_work_order`**, params name/phone/email/
notes/device/issue/status/quote/skip_dedup) and `app/services/daily_reconciliation.py:1518`.

**The route that worked** (from any machine, no production credential held locally):
scp a small python file to the authority, then
`cd /home/zabz/personal-secretary-mvp && .venv/bin/python3 /tmp/x.py`, with
`pg_url = settings.phone_tech_full_database_url` (present — it is in the repo `.env` as
`PHONE_TECH_FULL_DATABASE_URL`) and `secretary_db_url = settings.database_url`. Refuse-on-existence
guard first. Result: order 3037 / **WO26101112743**, customer 2840, ticket 12743, verified with
`lpt ticket` (`operational=FOUND`, `app=absent`).

**Two consequences nobody had recorded:**
1. **`create_order` writes no `workOrderId` on its notes.** The intake note landed on the customer's
 file and NOT on the work-order timeline — `lpt ticket` printed "NOTES (0 on this work order, 1
 including the customer's file)". The fix is one `lpt-write note add --apply` afterwards (note 3119,
 ledger seq 321). Always do that second write, or staff reading the work order see nothing.
2. **`create_order` writes no link back into the lpt-hub sync record** — the same defect the skill
 records for `lpt-write order create`-created orders. The record is born unlinked; backfill all the
 link homes by hand (`workflow.orderNumber`+`orderId`, `references.orderNumber`+`workOrderId`+
 `ticketNumber`+`productionOrder`+`websiteOrder`, the `production` block). Confirmed it works:
 `sync-health-audit.py --days 21` reverse gap stayed at 15 and does **not** list WO26101112743.
