**L242 · Interactive login on a headless authority: Xvfb + x11vnc + noVNC over the SSH tunnel**

Interactive login on the headless authority (Amazon / eBay / any MFA-gated site)

PROBLEM: `secratary` has no display. Amazon's activity downloader refuses a
headless login: scripts/amazon/download-activity.ts:176 "CAPTCHA detected —
cannot solve headlessly. Run with --visible on the desktop". The 05:00
daily-finance-sync-cron.sh therefore fails every day with needs_mfa
(amazon_sync) / Authentication failed (ebay_sync).

ROOT CAUSE, measured 2026-09-14: the state files were not stale — they were
ABSENT. `ls ~/accounting-data/browser-auth/amazon/` and `.../ebay/` were both
empty (only the dirs, mtime 2026-09-04). With no storageState, every run does a
fresh headless login, which Amazon answers with an MFA challenge. The sibling
dirs amex/boa/chase had content, which is why only these two were broken.

MECHANISM (built and verified 2026-09-14):
 ~/bin/login-desktop.sh amazon|ebay # up: Xvfb :99 + openbox + x11vnc + websockify + visible run
 ~/bin/login-desktop-stop.sh # down
 Tunnel from his machine: ssh -L 6080:127.0.0.1:6080 secretary-cf
 Then open http://localhost:6080/vnc.html in the existing browser.

KEY FACTS
- x11vnc/websockify bind 127.0.0.1 ONLY (verified `ss -ltnp`), so the desktop is
 reachable only through the SSH tunnel. Never rebind to 0.0.0.0.
- A window manager is required, not optional: with no WM the X input focus is
 PointerRoot and typing into the browser is unreliable. openbox + fonts
 (fonts-liberation/dejavu, 133 fc-list entries) are prerequisites — without
 fonts Chromium renders the login page as tofu boxes.
- ssh -L WORKS through the cloudflared ProxyCommand in ~/.ssh/config
 (CloudflaredAccessSshProxy.ps1); the forward rides inside the SSH channel.
 Verified: vnc.html HTTP 200, 17810 bytes, from the laptop.
- The downloader needs cwd=/home/zabz/repos/quickbooks-agent because it calls
 loadDotenv({path:'.env'}) relative to cwd.
- useBiz = (--account === "biz") => state-biz.json; otherwise state.json.
 NO caller passes --account (verified main.py:9147/9223 and
 autopilot.py:6301/6385, signature account: str | None = None), so the cron
 path needs state.json for each site. One login per site, not two.
- The script's own --visible flag sets headless:false, slowMo:100 and waits
 10 minutes for a manual sign-in, then writes storageState to stateFile.

GENERAL RULE: for any MFA-gated scraper on a headless host, do not look for a
headless workaround. Give the host a display, expose it to the owner's own
browser over an SSH tunnel, and let him do the one-time challenge.
