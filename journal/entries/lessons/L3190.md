**L3190 · Ship shell code as a file, run long remote jobs detached, and never fetch heroku remotes on the owner's machine**

**Ship shell code as a FILE (scp/base64), never interpolate it through PowerShell or an ssh command string - and run long remote jobs detached.**

Every one of these was hit for real on 2026-09-30 while freezing git state across the mesh.

- **PowerShell eats `<` and `$( )` inside command strings.** `ssh host "bash x.sh $(cat list)"` dies with `The '<' operator is reserved for future use`; escaping `\$` did not save it. **Fix:** put the list in a file and give the *script* a `--from <file>` flag, so the command string contains no shell syntax at all.
- **PowerShell's `-replace` corrupts shell code.** Replacing a guard with `'[ -e "$r/.git" ]'` inserted the file's own shebang into the middle of the script (`$_LIST` was read as a substitution), producing `set -- $(cat "#!/usr/bin/env bash`. **Fix:** write scripts with the file writer, never rewrite them with regex.
- **Piping a string into `ssh ... "bash -s"` converts LF to CRLF.** Bash then fails on `$'\r'` at the last line - a *partial* run that looks like a success. **Fix:** `scp` the script; bytes survive. (On yoga, scp itself is broken - `scp: Connection closed` - so ship with base64: `[IO.File]::WriteAllBytes(...FromBase64String(...))` over `ssh powershell -Command`.)
- **`/tmp` is not durable.** A path list written to `/tmp` was gone minutes later, so the second run silently processed **zero** paths and still printed its success banner. **Fix:** keep tools and inputs under the backup root, and make the script print `paths: N` so a zero-path run is visible.
- **A dropped connection kills a long remote job.** `ssh host "bash long.sh"` died twice mid-run on the mesh link (`Connection timed out`, `Connection reset`). **Fix:** `setsid nohup bash long.sh > log 2>&1 < /dev/null &`, then poll `tail` with short calls. Re-run the same script afterwards - the additive design makes it idempotent.
- **Parallel ssh is self-defeating.** Firing many ssh/scp calls at once got `scp: Connection closed` from the server. **Fix:** one connection at a time, with retries and backoff.
- **Never run `git fetch --all` on the owner's machine without checking the remotes first.** Two repos carry heroku HTTPS remotes (`https://git.heroku.com/...`) and there is no stored credential for that host, so Git Credential Manager opened a dialog on his desktop, repeatedly, from a background job - while he was not using git at all. Fixed with `credential.https://git.heroku.com.helper ''` and `credential.interactive false`, verified by a fetch that now fails fast with no dialog. **Also: recon must skip non-essential remotes by default and run with `GIT_TERMINAL_PROMPT=0` and `GCM_INTERACTIVE=never`.**
