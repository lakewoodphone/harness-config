**L4640 · The T-Mobile 5G gateway publishes its own radio status unauthenticated at http://192.168.12.1/TMI/v1/gateway?get=signal - and the bundle-regex trick that finds such paths on any appliance**

The T-Mobile 5G gateway (Arcadyan TMO-G4AR, and its Sercomm twin) publishes its own radio status over HTTP with NO authentication. Found 2026-10-15 on the owner's home network; nothing in the estate had ever read it.

 curl http://192.168.12.1/TMI/v1/gateway?get=signal # radio only
 curl http://192.168.12.1/TMI/v1/gateway?get=all # radio + device + uptime
 curl http://192.168.12.1/TMI/v1/version

No token, no cookie, HTTP 200. The gateway's LAN address is 192.168.12.1 and it is reachable from behind whatever router sits downstream of it.

WHAT IT ANSWERED, 2026-10-15 14:18 UTC:
 5g.bands ["n41"], bars 4.0, rsrp -89, rsrq -10, rssi -78, sinr 28, antennaUsed Internal_omni
 generic: apn FBB.HOME, registration "registered", roaming false, hasIPv6 true
 device: model TMO-G4AR, manufacturer Arcadyan, softwareVersion 1.00.18, serial JT74032C0
 time.upTime 389506 s (4.5 days)

HOW TO FIND THE PATHS ON ANY SUCH BOX: the web UI is a React bundle. Fetch the bundle and regex the quoted paths rather than guessing:

 curl -s -o tmo-main.js http://192.168.12.1/static/js/main.<hash>.js
 [regex]::Matches($js, '"/[A-Za-z0-9_\-/\?=&\.]{3,90}"') | Sort-Object -Unique

That returned exactly: /TMI/v1/auth/login, /TMI/v1/auth/refresh, /TMI/v1/gateway?get=all, ?get=signal, /TMI/v1/gateway/upgrade, /TMI/v1/network/configuration?get=ap, ?set=ap, /TMI/v1/network/configuration/v2?{get,set,delete}=ap, /TMI/v1/version.

READS ARE OPEN, WRITES ARE NOT. /TMI/v1/network/configuration?get=ap returns 401 {"error":"AuthorizationError","message":"Not Authorized, Access token is missing or invalid"}. So turning the gateway's own Wi-Fi off needs the admin password; reading its radio does not.

WHY IT MATTERS: this is the only instrument that separates "the cellular link is bad" from "something behind it is bad", and it costs one curl. A 4-bar n41 signal at SINR 28 dB is a healthy radio and rules the uplink out as a cause of slowness; a 1-bar or negative-SINR reading would have ended the investigation in ten seconds. Reach for it before blaming anything downstream.
