**L1839 · Four operations lessons from the HA evidence overhaul**

Four operations lessons from the 2026-09-15 Home Assistant evidence overhaul. Each cost real time.

**1. A backup that copies files while they are being written stores corrupt ones.**
The off-host rsync ran during a clip capture and stored a file that `ffprobe` rejected with `moov atom not found`. Fix in two places: every writer writes `<name>.part` and renames only on success (so the origin never exposes a partial file), and rsync carries `--exclude='*.part' --exclude='*.err'` (so the backup never looks for one). Atomic-on-both-sides, or the archive silently contains unplayable evidence — the worst possible failure for a security archive, because it looks present.

**2. Shipping a file *into* a container through Windows PowerShell needs base64 plus a checksum, and `ssh -n` silently truncates a redirect.**
PowerShell converts the LF line endings of a here-string on the way to a native command's stdin, which drops literal `\r` bytes into the file being created. And `ssh -n ... "cat > /dest" < local` writes a **0-byte** file, because `-n` makes ssh read from /dev/null instead of the redirected stdin. Reliable pattern used all session:

 [Convert]::ToBase64String([IO.File]::ReadAllBytes($local)) | ssh host "tr -d '\r' | base64 -d > /dest"
 # then compare SHA256 on both sides before trusting it

Also: `scp` fails against a Home Assistant SSH add-on with `subsystem request failed on channel 0` — there is no sftp subsystem. Base64-over-ssh works; so does hopping through another host with plain `cat`.

**3. A nested `ssh` inside a piped script eats the rest of the script.**
`$script | ssh host "bash -s"` with an inner `ssh` call: the inner ssh inherits the pipe as stdin and consumes the remaining lines, so the outer script silently stops partway and looks like truncated output. Always `ssh -n` (or `</dev/null`) for inner calls.

**4. Home Assistant's `shell_command` is not reloadable and its foreground timeout is 60 s.**
`POST /api/services/shell_command/reload` -> HTTP 400; a core restart is required, while `automation.reload` succeeds immediately. So a config change that renames shell commands produces a window where the new automations are live and their services do not exist. Sequence it: deploy, `ha core check`, restart, then verify `/api/services`.
And anything a capture needs must be **detached** (`nohup ... &` in a template-free command). A snapshot that shared the clip lock sat behind a three-minute transcode and was killed at exactly 60.1 s (HTTP 500). Long work is background work — the same rule as the harness's own shell discipline.
