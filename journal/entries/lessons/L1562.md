**L1562 · An empty-scope refusal must not report itself as fleet-wide**

In the D39-11 measures reader I added (kf2/measures-reader, app/inference_measures_report.py), the empty-report path hard-coded all_devices=True. That is right for one caller (no ledger configured: the fleet-wide question simply could not be answered) and exactly wrong for the other (a non-super-admin scope that can see no devices: the request was REFUSED). Both ended up rendering 'scope: every device' over an unmeasured report - the inversion of the truth, in the one feature whose entire point is not to look healthy when nothing was measured. Fixed by making the caller state it: _empty_report(..., all_devices: bool) with no default. The transferable rule: when one branch serves two callers with opposite meanings, pass the meaning in and give the parameter no default - a default is how the wrong one gets chosen silently. This is the same shape as the budget gate's deny-first rule (a missing value must close a door, never open one).
