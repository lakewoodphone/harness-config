# In this estate a message store's `state` column is a decision, and `ignored` is where his instructions go to die

**Rule.** `/root/.sms-inbox/inbox.db:messages.state` has eight live values — `new, seen, answered, queued,
working, blocked, woken, ignored` — written from `sms-responder.py`. `ignored` is the value that means
"seen and deliberately not acted on", and it is where both of the owner's standing instructions sit. Any
audit of "is his channel working" must start with
`SELECT state, COUNT(*) FROM messages WHERE direction='inbound' AND from_number LIKE '%8483897895%'`,
because a rising `ignored` count is the system quietly deciding not to listen to him.

Measured 2026-10-14: 30 days, 79 inbound from him, **only 18 answered (22.8 %)**; longest gap from his
text to any reply **248 hours**. There is no `CHECK` constraint on the column, so a new writer can invent
a ninth value silently.
