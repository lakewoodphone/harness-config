**L1757 · A registry naming adapters/<name>/adapter.py scheduled thirteen sources that never ran; the list command looked healthy**

**A registry that named a file which has never existed, and a scheduled job that did nothing while looking healthy.**

`config/sources.json` listed thirteen search sources. Every one named its adapter as
`adapters/<name>/adapter.py`. No adapter in this repo has that filename -- they are all `sync.py` --
so every source failed with "adapter not found", the refresh ingested nothing, and `sync.py --list`
printed a correctly scheduled pipeline with per-source staleness limits.

The failure was invisible for three reasons, and each is worth remembering:
1. **The list command only reports what it can parse.** It showed names and limits from the registry,
 which were all fine; the path was never resolved until run time.
2. **A missing adapter was recorded as a failure, not a crash** -- which is correct behaviour, and it
 is exactly what made it quiet. Thirteen identical "adapter not found" lines across several runs
 read as noise rather than as "nothing is being refreshed".
3. **The registry was written from the brief, not from the adapters.** The paths came from what the
 plan said the adapters would be called, and no one ran one.

**The rules this produced:**
* **A registry entry is a claim that the thing exists. Verify it against the artifact, not the plan.**
 Reading each adapter's `--help` and copying its real flag names is what fixed it, and it also
 caught two entries that were not merely misspelled but wrong: `db:secretary` pointed at the
 local-database adapter, which cannot read the server database, and `mail:gmail` was blocked by
 something entirely upstream (an empty table), not by a wiring mistake.
* **Prefer `enabled: false` with a written reason to an entry that silently cannot run.** A disabled
 source with a note shows up in `--list` as a known gap; a broken-but-enabled one looks like
 coverage.
* **Run the pipeline once, by hand, after wiring it.** Not the unit tests -- the actual command, with
 its actual arguments, against the actual corpus. Every one of these thirteen would have been
 caught by one manual run.
* **"It is scheduled" is not "it ran".** The measured rule from this fleet already: read the schedule
 back AND observe a run. Do both, and make the observed run produce documents.
