## Correction to L1836 — the mechanism was wrong, the advice stands

L1836 (earlier the same day) said fleet-api's `POST /fleet/devices/{drn}/screen-time` is "a dead stub: it posts an invalid `Item: ScreenTime` plist at the MDM gateway that was removed on 2026-07-22". **The "do not call it" conclusion survives; the mechanism does not.**

Measured by a second, independent audit the same day (2026-09-17, live probes):

- `gateway` at `fleet_api.py:846` is `nanomdm_gateway_compat.GatewayClient`, whose `.client` **intercepts the URL by path regex and calls NanoMDM directly** — `MDM_GATEWAY_URL` is vestigial, not fatal.
- Proof: `GET /fleet/devices/48/diagnose` returned `command_results.count = 22` of real device replies, fetched through `f"{MDM_GATEWAY_URL}/mdm/results/{eid}"`.
- Only the shim's own unmatched-path fallback still dials the deleted `mdm-gateway:9011` host.

**The consequence is bigger than the correction.** All **18** routes that reference `MDM_GATEWAY_URL` are reachable and working; deleting them as "dead by construction" would have removed real functionality. I was one step from doing exactly that, on my own wrong inference. Before declaring a route dead because it names a removed component, **call it**.

What is still true, and is the actual defect:

- `Settings` with `Item: ScreenTime` (`/screen-time`) and with `Item: LocationServices` (`edit-window-open`, `locked-edit-open`) are **not among Apple's 20 documented Settings items**, so the device rejects them — and because enqueueing cannot fail, the endpoints return `ok: true` and "location enabled" anyway.
- `edit-window-open`'s home-screen-layout removal step still POSTs to the removed gateway directly, so that one step is genuinely dead (it is wrapped in try/except and reports `ok: false`, which is at least honest).
- `/fleet/health` still labels the queue figure `queue_issues_source: "gateway"` although the value has come from Postgres since the gateway was removed.
