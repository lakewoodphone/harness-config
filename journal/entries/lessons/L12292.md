**L12292 · PowerShell appends CRLF to a piped string, so the last line of an ssh 'sh -s' script arrives with a trailing CR - and one 'docker compose build' never gives two services the same image id**

## The mechanism

PowerShell writes each piped string to a native command followed by the PLATFORM line terminator
(CRLF on Windows), regardless of the newlines already inside the string. So

 $text | & ssh host sh -s

delivers `<text>` + `\r\n` - and since the text ends without a newline, the FINAL line on the box
carries a trailing CR.

## What it looks like

 $lines = @('set -u','cd /opt/filter-broker || exit 1','docker compose -f ... config --services')
 $s = $lines -join "`n"
 $s | ssh lpt-apps od -c
 # 0000160 r v i c e s \r \n

 $s | ssh lpt-apps sh -s # -> unknown flag: --services exit 1
 # the same three lines typed by hand on the box -> broker, broker_b, socks_failover

## Why it hides

A probe whose last line is `echo KEY=value` survives: `echo` prints the value with the CR and every
reader does `.Trim()`. Only a probe whose last line passes an ARGUMENT to a program fails, and it
fails with the program's own vocabulary ("unknown flag: --services"), which points at docker, not at
PowerShell. Steps 1-5 of the same deploy passed for exactly this reason; step 6 was the first probe
ending in an argument.

A trailing-newline "fix" does not work: it moves the CR onto a line of its own, which dash reports as
`sh: 4: : not found`, exit 127. The only dependable fix is to stop piping: write the normalised text
to a temp file as UTF-8 WITHOUT a BOM and let the shell redirect it -

 ssh ... sh -s < "C:\...\file.sh" (cmd /c on Windows, sh -c elsewhere)

## Second, independent trap found in the same deploy

Two services built by ONE `docker compose build` NEVER share an image id. Compose stamps
`com.docker.compose.service` per service, so the image config differs and so does its digest.
Measured: broker 108343740 B, broker_b 108343742 B (the 2-byte gap is "broker" vs "broker_b"),
all thirteen RootFS.Layers digests identical, one Created timestamp. Asserting `.Id` equality between
the two tags refuses a correct deploy; assert the rootfs layer list instead.

Evidence: deploy/broker/deploy-broker.ps1 commit a31c8cd8 on branch agent/kf-deploy-finish;
deploy proved on lpt-apps 2026-10-22 (37 migrations, 359 openapi paths, both containers healthy,
https://filter.lakewoodphoneandtech.com/health 200, manifest serving the pinned int8 sha 490afad0...).
