**L10880 · Phone 0.2.1: engine+profile+config PROVEN serving in a foreground run with the unit's own environment; the live home is what still fails, and my rollback left a rewritten patch behind that turned 401 into 404**

STATE AT THE END OF THE WINDOW, 2026-10-20 ~12:50Z box time. The owner's phone engine is on **0.2.0-rc.2 and fully
healthy**: unit active, restarts 0, HTTP **401** on 3089, and the phone gate on 3086 answers **200**. He can use it.

WHAT IS NOW PROVEN, by a foreground run rather than by inference: a clean 0.2.1 tree boots and SERVES when given
(a) a profile installed at 0.2.1, (b) a profile patch with `ctx.webRuntime` -> `ctx.webStartup` and `{{cwd}}`
removed, and (c) the unit's own environment (`NODE_ENV=production`, `TMPDIR`, `HOME`, `DSH_HOME`). Measured twice:
`dsh web: http://127.0.0.1:3092/?token=...` and again on 3093 with the full environment, each staying up past a
45-50 s timeout. So the ENGINE, the PROFILE and the CONFIG are all correct.

WHAT STILL DIFFERS is the live home itself (`/root/.dsh`): sessions, archive state, settings, the real credential
store. The same tree, started by systemd against that home, stays `activating`. The next step is a bisect of that
home — copy it to a scratch, install the 0.2.1 profile there, run the same foreground command, and if it fails,
remove one element at a time (sessions first, then settings, then .credentials). That is now a bounded experiment
with a working control, not a guess.

A MISTAKE I MADE AND ITS EXACT COST, because it is the most transferable thing here: my last switch script rewrote
`profiles/web/cordis.patch.yml` (webRuntime -> webStartup) and its rollback restored the tree and package.json but
NOT the patch. A 0.2.0 engine cannot inject `webStartup`, so the web rows failed and the phone served **404 where it
had served 401** — up, but wrong. I caught it only because the health check distinguishes those two codes; a check
that had merely asked "is it up?" would have called it healthy. Restored from `.bak-phone021v2-*` and verified 401.
RULE: a switch script must back up EVERY file it modifies and restore ALL of them, not the ones it remembers.

ALSO: three of my own attempts produced `missing webStartup` from an engine tree whose `@deepseek-ai` had **zero**
packages — earlier move/repair cycles had emptied it. A tree that does not carry ~300 packages is not a candidate;
check that before swapping, every time.
