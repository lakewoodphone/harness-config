**L3732 · Two installed copies of one package in one Node process silently break every module-level Symbol**

## One package, two trees, two symbols

@deepseek-ai/dsh-scope identifies a scoped context with a module-level symbol:

 const kScope = Symbol('dsh.scope');
 createScope(ctx, key) -> ctx.extend({ [kScope]: key })
 scopeOf(ctx) -> ctx[kScope]

Symbols are compared BY IDENTITY. If two copies of that module are loaded, one copy stamps the
context and the other reads it and sees undefined - with no error about modules at all.

Measured on secratary-cloud 2026-10-12: the service ran the engine from the flat npm tree
(/opt/dsh-phone) so dsh-agent-loop came from there, while ~/.dsh/profiles/web keeps its own pnpm
tree so dsh-client-file-upload came from there. Result: assertAgentScope failed, and every prompt
from every phone was rejected as session/agent-busy.

HOW TO FIND IT in one step: log each candidate module's import.meta.url from inside the failing
function, then from inside the constructor that writes the value. Two different URLs for the same
package name = two instances. Do not reason about it; print it. Two rounds of guessing produced
wrong answers; the constructor log produced the answer immediately.

HOW TO FIX: make the trees resolve the SAME FILE (a symlink from the duplicate to the canonical
copy), never by editing code. Verify by behaviour, not by the absence of an error.
