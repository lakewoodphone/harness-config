**L3706 · A sync record cannot carry root 'filename' or contactPreference: null - both make it fail its own schema, and record.py writes one of them**

A sync record cannot carry a root `filename` key and cannot carry `contactPreference: null`, and both were in the file this session touched.

`docs/customer-operations/CUSTOMER_CASE_SYNC_RECORD.schema.json` is `additionalProperties: false` at the root and does not list `filename`; `workflow.contactPreference` is typed `string`, not nullable. Validated with jsonschema 2026-10-12: the rabbi-shereshevsky record as it stood (and every other record written the same way) failed on exactly those two keys — `SCHEMA OK` only after both were removed.

Why the `filename` key exists: `lpt-hub/tools/customer/record.py:471` writes it into every record it creates, so any record that tool has touched is born schema-invalid. That is a tool/schema disagreement, not a bad record — fix it at one end or the other (drop the key from the writer, or add it to the schema), never by leaving records invalid.

How to check a record in one line (jsonschema is installed in the Windows Python 3.13 that runs scripts here):
 python -c "import json,jsonschema;s=json.load(open('docs/customer-operations/CUSTOMER_CASE_SYNC_RECORD.schema.json'));r=json.load(open('<record>'));jsonschema.validate(r,s);print('SCHEMA OK')"
