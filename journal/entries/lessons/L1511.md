**L1511 · A 300DDR ticket number is per-device and does not exist until the final form is submitted**

A 300DDR ticket number is per-DEVICE and does not exist until the final form is submitted.
Do not assume a familiar-looking number is "our case".

WHAT HAPPENED, 2026-09-15. Eliyahu asked "what's the 300drd case number for this" about the
Weissman WD PC SN740 512GB SSD. The case file had no number, so I read the mailbox
(lakewoodphoneandtech@gmail.com, read-only gmail_service). Two numbers were visible and
NEITHER belongs to this drive:
 - Ticket #73459 — a live ticket, updated 2026-09-14. Body names the device:
 "SanDisk Z4480104744 NAND 256G controller 20-82-00388-B0". Mail-in form submitted
 2026-08-12. Still in the lab: PC-3000 Flash gave documents-only, everything larger
 corrupt; being retried with a second tool.
 - Tickets 73890 / 73896 — the two Sep 8 mail-in forms: "SanDisk Ultra PLUS 32 GB" and a
 second SanDisk whose form left the device name blank and therefore shows as "?".
Writing 73459 on the Weissman package would have attached the wrong device to a live
recovery and corrupted two cases at once.

WHAT THIS DRIVE ACTUALLY HAS. Only a Chances Form submission ID:
 sub_e98984276bd57b116df40300 (2026-09-03 15:40 UTC confirmation)
plus Nathan's estimate reply (2026-09-03 16:21 UTC) which references the drive as
SDDQNQD-512G-1014 and quotes 65% / $500 flat. 300DDR issues a ticket number only when the
Drop-Off or Mail-In form is submitted; that never happened for this drive, so the number
does not exist yet. It is a missing step, not a lost document. Nathan's reply contains
pre-filled Drop-Off and Mail-In links that already carry model + problem description, so
booking is a click, not a re-interview.

THE RULE. Before quoting or reusing a 300DDR identifier: read the email body and match the
device string. A ticket is bound to one device. Match by device model/serial, never by
"the newest 300DDR email". The Chances Form submission ID is the only tracker that exists
before a ticket, and it belongs in `labEscalation.submissionId`.
