**L12173 · A directory-size tree can sum to more than the disk; reconcile against fsutil before quoting any total**

ZABZ-YOGA 2026-10-21, owner asked whether ~200 GB is wasted. Two independent methods (robocopy /L /XJ /BYTES and a python os.scandir walk skipping reparse points) agreed exactly on every directory measured by both - C:\Program Files (x86) 10.50 GiB / 61,639 files, chumash-timeline 493,161,921 B / 22,516 files, ProgramData 46.78 vs 47.10 - yet the per-directory sizes summed to ~535 GiB on a 476 GiB disk with 449.14 GiB used. Ruled out as the cause: CompactOS/compression (off), sparse files, hardlinks (fsutil hardlink list = 1 link on 16 sampled files across 4 repos), symlink following (/XJ vs /XJ /XJD /XJF identical on PF(x86) and _fleet). Conclusion: at least one path is counted at more than one location and the whole excess lands on C:\Users\ezabz\code - measured 256.19 GiB, bounded by arithmetic at ~172 GiB. RULE: never present a directory tree's sum as disk usage; bound each big item against fsutil volume diskfree minus everything else measured, and say which figure is a ceiling.
