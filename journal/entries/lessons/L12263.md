**L12263 · Playwright sessions are forced local-only on personality-test — verify with navigator.webdriver false**

Measured 2026-10-22 on production `https://personality.lakewoodphoneandtech.com` (container `personality-test`, image tag `personality-test:4c44fc5f…`, i.e. commit 4c44fc5 — f010883 is an ancestor, not what is deployed).

THE TRAP: `src/lib/assessment/remote-persistence.ts:154` — `shouldUseLocalOnlyPersistence()` returns `navigator.webdriver`, so **any Playwright/Selenium session is forced local-only**: the client never calls `/api/persistence`, the badge reads "Not saved to your account yet", and `/api/owner/records` shows no record. A verification run in a stock automation browser therefore measures the *local-only* path and looks like the account-save feature is broken when it is not. Launch with `ignoreDefaultArgs:['--enable-automation'], args:['--disable-blink-features=AutomationControlled']`, assert `navigator.webdriver === false`, and only then trust a persistence result.

WHAT THE REAL PATH DOES (webdriver false, synthetic identity resume-a-20261022):
- 12 answers -> badge "Saving your progress" -> "Saved to your account: Resume A" in <=10 s; `PUT /api/persistence` 200; owner record `session-1792691947209`, `answeredCount: 12`, `status draft`.
- Same browser, page closed, new page: "Pick up where you left off" / "Continue my assessment — 12 answered" -> returns to `Personality · Question 13 of 21`, exact same item text.
- Fresh profile (localStorage verified 0 keys by loading `/api/health` on the origin first), only the `dyp_session` cookie: the identical screen, byte-identical screenshot, same Question 13. The second-device promise holds.
- Loss window: answering and closing the tab 300 ms later left `answeredCount` at 12 (the autosave is debounced); with the tab left open it went 12 -> 13 in ~1 s. So "stop at any question" is true except for a sub-second window right after the last answer.
- API surface actually used: `GET /api/auth/session`, `GET|PUT /api/persistence`, `POST /api/assess`. Zero console errors.
- Owner route auth is header `x-lpt-operator-key` (NOT `x-operator-key` — that returns 403 "Operator access denied."); key read on the host with `sed -n 's/^ASSESSMENT_OPERATOR_KEY=//p' /opt/personality-test/.env`.
- Namespace for an identity is `user:<first 32 hex of sha256(sub)`; filter the owner route with `?libraryKey=` rather than paging 500 rows.
- Copy defect seen both ways: the "WHERE THIS ATTEMPT STANDS" box renders with only its description ("Counter and save state for this attempt.") and no content, while the not-saved copy says "the box beside this says why, and what to do about it"; and the drafts list says "Every unfinished attempt on this device" even when the draft it lists was just pulled from the account on a device that never saw it.
