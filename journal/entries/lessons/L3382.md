**L3382 · I killed the primary alert while making the alerts independent, and only an unrelated test found it**

GOAL ROUND 27, second half - the most serious defect I introduced all night, and I introduced it while trying to make things safer.

In round 16 I gave every alert condition its own rate-limit mark so that one condition could not silence another. While doing so I removed the company-down block's mark assignment, on the stated belief that "down/up fire unconditionally and do not read a mark". THAT WAS WRONG: the down block does read a mark, for its six-hourly re-alert. So MARK was never initialised anywhere, `set -u` is on, and the down block's file test on $MARK therefore ABORTED THE WHOLE SCRIPT at exactly the moment the alert should have fired.

MEASURED: with consecutive_failures 1 and 2 the script exits 0 and logs normally; the run that reaches 3 exits 1 having written NOTHING - no alert, no liveness tick, nothing at all. The primary alert of the entire system was dead from roughly 05:40 to 11:31 tonight. The only reason I know is that a test I was writing for an unrelated reason (a standby monitor) happened to drive three failing runs, and I noticed the third produced no output.

THE EXPOSURE, stated precisely rather than dramatised: the company stayed down through that window, so the initial down alert at 04:16 - before the edit - had already been sent. What was lost were the six-hourly re-alerts and any NEW up-to-down transition during those hours. The recovery path never read MARK, so a return would still have been announced. I am not going to inflate it, and I am not going to hide it.

FIX: the down block now assigns its own mark before reading it, and MARK is initialised to a default near the top as a seatbelt - a future condition that forgets to assign one now reads an empty string and degrades instead of killing the script mid-run.

THE REAL FIX, because a one-line patch does not address a class: heartbeat-selftest.sh walks EVERY condition - down with its threshold, up, loop-dead, api-guard, mute, the survivor exemption, peer, standby, offsite, backup - and asserts each one fires exactly when it should, and that every run exits 0. It reports 18 passed, 0 failed. It would have caught this the day I introduced it, in about twenty seconds, and it needs no live company: a mock and a temporary state directory per case.

RULES: (a) when you refactor an alerting path, the test is "walk every branch and assert it fires", not "the syntax is valid"; (b) `set -u` turns a forgotten variable into a dead monitor rather than a visible error, and on a script whose whole job is to alert that trade has to be paid for with a test that runs every path; (c) "exits 0" proves nothing about the branch that only executes at the threshold, because the failure mode I shipped looked perfectly healthy at one or two failures; (d) when passing prose to a command in PowerShell, backticks and dollar-paren are expanded before the command sees them - write the body to a file, which is how this entry got written at all after the first attempt silently mangled itself.
