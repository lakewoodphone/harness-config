# The wake loop's roadmap supply, measured 2026-10-20 - why the kosher roadmap is not robust

## The mechanism that already exists (do not rebuild it)
`/root/bin/sources/roadmap-supply.py` + `/root/bin/sources/roadmap-<project>.json` is the source that turns a
project's own roadmap into ledger work. It runs from `run-wake-sources.sh` (cron `7,37 * * * *`) and files ONE ledger
item per unchecked checkbox in the docs its mapping names, deduped by exact title against live ledger states. Flags:
`--project <id>`, `--dry-run`, `--limit` (default 3), `--check-projects`, `--selfcheck`, `--audit-dods`.
For kosher: `roadmap-kosher-ai-filter.json`, 85,985 B, 47 items, every one carrying a `dod`; `source_docs` =
`docs/IMPLEMENTATION_BACKLOG.md` and `docs/cross-platform-filter-master.md`; `source_git` = the GitHub URL read with
`git show` out of a shallow bare cache at `/var/cache/roadmap-supply` (NOT raw.githubusercontent - the repo is private).

## Measured state, one command, 2026-10-20
`python3 /root/bin/sources/roadmap-supply.py --project kosher-ai-filter --dry-run` ->
`unchecked_boxes=26 mapped=26 new=0 filed_this_run=0 already=1 done_not_landed=12 unmapped_boxes=0
stale_mapping_rows=6 uncovered=0 bad_hosts=0 authoring_item=not-needed
ledger=blocked:8,done:150,dropped:3,running:5,todo:3`

Five findings, each a reason the roadmap is not robust FOR THE WAKE SYSTEM:

1. **12 `done_not_landed`.** Twelve roadmap boxes are unchecked in the doc while their ledger item is `done`. A shift
 reading the doc sees work that is already finished; the supply refuses to refile (correctly). The doc and the ledger
 each hold half the truth and nothing reconciles them.
2. **6 `stale_mapping_rows`** - mapping rows whose checkbox text no longer exists in the doc (`w-back-058 password
 reset...`, `watchdog service...`, `overlay / block page ui`, ...). Keying on checkbox TEXT means a reworded box
 silently orphans its mapping row. This is the fragility a stable ID removes.
3. **One of the two `source_docs` is `superseded`.** `docs/IMPLEMENTATION_BACKLOG.md` is `status: superseded` per
 D-20261019-02, and the supply still reads it as a live source. Most of the 12 `done_not_landed` are its boxes.
4. **The loop's code has no faithful lineage.** `/root/bin` IS a git repo, but the live `sources/` tree has diverged
 from `~/code/harness-config/scripts/wake/sources/`: of 33 live files, **1 matches, 32 differ, 23 have no copy in
 the repo at all**, and there are **310 `.bak-*` files** in `/root/bin`. The repo copy of project-keepalive.py is
 33,682 B against a live 54,407 B. So "harness-config is the source of truth that reaches every machine" is FALSE
 for the wake sources, and the de-facto backup is in-place `.bak` files.
5. **The live shift prompt was stale.** `project-keepalive.py` told every woken shift that `python scripts/docs_check.py`
 is "(all six checks, one exit code)"; the repository runs 17. Patched 2026-10-20T15:50:05Z with backup
 `/root/bin/sources/project-keepalive.py.bak-gatecount-20261020T155005Z`, verified `py_compile` rc=0, `--dry-run`
 rc=0, new text `(every check, one exit code)`. The count is now not stated at all, which is the durable form.

## The path forward this implies (the roadmap rework)
Roadmap items become files with stable IDs and a `ledger:` field (`docs/roadmap/items/<ID>.md`, ledger item 784);
`roadmap-supply.py` reads the ITEM FILES' front-matter instead of checkbox text, so a reworded doc cannot orphan a
row and a ticked box cannot go blind; the superseded doc leaves `source_docs`; and a repo-side checker
(`check_roadmap.py --ledger`) plus the supply assert the same agreement from both ends. Then the 12 `done_not_landed`
become a finite, checkable list instead of a weekly report nobody acts on.
