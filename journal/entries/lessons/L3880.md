**L3880 · CI: the self-hosted runner died with the secratary freeze and nothing noticed for nine days**

CI for phone-and-tech-full is broken in two independent ways, and only one of them is money.

**1. The self-hosted runner no longer exists.** Measured 2026-10-20:
`gh api /repos/lakewoodphone/phone-and-tech-full/actions/runners` -> `{"total_count":0,"runners":[]}`.
`secratary-lpt` (runner id 21, installed 2026-10-08/09 per L3425) lived on `secratary`, which was
frozen 2026-10-11 as the rollback anchor. The runner went with it and **nothing checked**. So
`deploy-env.yml` — the ONE deploy path that D2978 declared and that replaced 19 deleted workflows —
has had its 3 jobs pointed at `[self-hosted, linux, x64, lpt-deploy]` with no runner to take them
for nine days. A green decision quietly became an unrunnable one.

**2. The verification workflows still burn metered GitHub minutes.** Surviving jobs on
`ubuntu-latest`: `pr-precheck.yml` 12 jobs, `maintenance.yml` 7, `phantom-dependency-check.yml` 1,
`validate-backend-image.yml` 1, `validate-main-pr-source.yml` 1.

**Measured burn, not estimated:** 231 successful runs between 2026-10-19T00:00Z and
2026-10-20T03:25Z, 68,375 run-seconds = **1,140 run-minutes**, average 4.9 min/run, max 32.8 min.
Runs per day: 10-19 = 207, 10-20 = 490. That is a trigger storm, not work volume — roughly 2,000
free-tier minutes consumed in under two days, every day.

**L3425 is STALE on plan tier — do not quote it.** L3425 (2026-10-08) records branch protection 403
with "Upgrade to GitHub Pro" and concludes private + free plan. On 2026-10-20
`gh api .../branches/test/protection` returns full JSON: `enforce_admins.enabled = true`, strict
checks, three required contexts (`CI Validation (PR Pre-Check)`, `Check for Phantom Dependencies`,
`Build image and assert the sha label`). So the account is on a paid tier, a spending limit DOES
exist, and **no merge can bypass a refused job, not even for the owner.** Measure plan tier; never
inherit it.

**The refusal is undiagnosable from inside the account.** When Actions refuses to start a job the
annotation is `The job was not started because recent account payments have failed or your spending
limit needs to be increased` — identical text for a declined card and for a maxed limit. The billing
endpoint `/users/<login>/settings/billing/actions` needs the `user` scope; the `gho_` token on
ZABZ-TECH has `gist, read:org, repo, workflow` and gets HTTP 404 + "needs the user scope". An agent
**cannot** settle this alone: the owner must read Settings > Billing & plans. Do not spend an hour
inferring which cause it is; ask for 60 seconds on that page.

**The transferable rule:** anything a written decision depends on being *alive* needs a check that
fails loudly. Freezing a host silently reverted D2978 and nothing surfaced it for nine days. When a
workflow's `runs-on` names a label, assert the label has a runner before you trust the workflow —
`gh api .../actions/runners` is one call.
