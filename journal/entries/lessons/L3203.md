**L3203 · The journal allocated an id that already meant another entry - the 25-ref window in git_max**

WHAT HAPPENED: `journal.py append` allocated **L3196** for an entry written on 2026-10-01 — a number
that already meant something else. `journal/entries/lessons/L3196.md` exists on
`origin/hk/20260928-journal-utf8-complete` and holds "building a Hyper-V lab that actually isolates".
Two different entries, one id. That is the one thing the journal may never do.

ROOT CAUSE, in `git_max()`: the ceiling scan read only the **first 25** remote-tracking refs
(`refs/remotes/origin` sorted by refname, truncated to `[:25]`) and ran a separate `git grep` per ref.
`refs/remotes/origin/hk/20260928-journal-utf8-complete` sorts outside that window, so the branch
carrying the newest journal contributed nothing, and the allocator happily chose a number that branch
had already used. The comment said "bounded on purpose: a writer path must not hang on a hub with
hundreds of refs" — but refname order is arbitrary with respect to what is inside a ref, so the bound
silently discarded the most important one.

TWO TRANSFERABLE RULES:
1. **A bound that does not report what it skipped is not a bound, it is a hole.** If a scan truncates,
 it must say so, and a truncated scan of a set whose order carries no meaning must not be used to
 prove absence.
2. **The same defect made the writer hang.** 25 refs x a 60 s timeout each is a 25-minute worst case.
 An `append` had to be killed by hand during this session because of it. One `git grep` over ONE
 argument list of all refs fixed the hole and the hang together: complete coverage, one process,
 one timeout.

AND ONE REFUTED ASSUMPTION, because it is the kind that gets repeated: the first fix attempt used
`git grep --all`, on the belief that `--all` covers every ref under `refs/`. **Measured on git
2.52.0.windows.1, it does not.** `git grep -h -E --all <pattern>` returned a maximum of L3101, while
`git grep -h -E <pattern> refs/remotes/origin/hk/20260928-journal-utf8-complete` returned L3200 from
3397 matching lines. `--all` would have preserved the exact hole it was meant to close, and it would
have looked like a fix. Passing the refs explicitly is the version that works.

EVIDENCE: 2026-10-01, ZABZ-YOGA. `git cat-file -e origin/hk/...:journal/entries/lessons/L3196.md`
exits 0. `journal.py next-id lessons` returned L3198 before the fix and L3201 after, with the ceiling
line reading `git @ 0820479 L3200`.
