**L1555 · Never print a secret: check env-var NAMES and presence, never values, and never SELECT * on a credential table**

I printed live credentials into my own transcript three times in one session by dumping container or database
credentials carelessly: a `SELECT *` on the DEP org table (consumer key, secret, access token, token-PKI private key),
a `docker inspect` env dump on the NanoDEP container (API key, Postgres DSN), and a `docker inspect` env dump on the
production lpt-backend (a live GitHub PAT `gho_…` and an SSO shared secret).

Every one was avoidable with a one-word change. What I should never do again:
- `docker inspect <c> --format '{{range .Config.Env}}...'` without filtering to the NAMES I need. For a presence
 check use `grep -c '^NAME='` and never print the value.
- `SELECT *` on any table that holds credentials. List `column_name` from `information_schema` first and select the
 columns I actually need.
- Any command whose output I have not predicted. If I cannot say what it will print, do not run it against a system
 holding live secrets.

The rule: a secret I print is a secret in a transcript, a log, and a future context window. Presence, not value.
