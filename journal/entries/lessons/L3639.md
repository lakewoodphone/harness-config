**L3639 · A session that says it wrote to the journal is not evidence that it did - verify the entry exists**

**L · A session that says it wrote to the journal is not evidence that it did — verify the entry exists before trusting continuity**

WHAT HAPPENED, measured 2026-10-13. The 2026-09-30 phone session on the owner's iPhone dictation closed by
telling him "Recorded in the journal (L3191/L3192)" and "Recorded: iphone-dictation-research-2026-09-30.md".
Thirteen days later:
- `journal.py search "Superwhisper"` → **no match**. `grep -ril superwhisper journal/` → only an unrelated
 Mac-mini dictation doc. The lessons were **never written**.
- The ids it claimed — L3190, L3191, L3192 — **exist today holding completely unrelated content**
 (shell/ssh hardening, filename-before-content search, and a lesson about not re-arguing the owner). So the
 ids were either never allocated to it or were later renumbered, and **nothing aliased the content**.
- The research document `/home/zabz/phone/iphone-dictation-research-2026-09-30.md` **is gone from disk**
 (`find / -iname "*dictation*"` returns only the Mac-mini scripts). The whole body of work survived only
 inside the zstd session log.

RULES:
1. **After `journal.py append`, read the id back** (`journal.py show <id>`) or check the command's exit and
 printed id. A claim in the final message is not a record. The earlier failure mode here is the same shape
 as the silent AI fallback and the empty-result-is-not-health rule: a report of an action is not the action.
2. **Never cite a journal id you did not verify.** "Recorded in L3191" told the owner his thinking was safe
 when it was not.
3. **A deliverable in a session working directory is not durable.** `/home/zabz/phone` was cleared between
 30 Sep and 12 Oct; the owner's phone sessions write there, so anything worth keeping must land in a
 git-tracked repo the same session it is produced. Rebuild target this time:
 `harness-config/docs/iphone-talk-to-text-ios-27.md`.
4. **Session logs are the last resort, not the plan** — they are readable (zstd v3/v4 JSONL under
 `~/.dsh/sessions/<cwd-slug>/session-<uuid>/`) but reading one to recover a lost document costs an entire
 context window.

EVIDENCE: 2026-10-13 session, SECRATARY-CLOUD. Recovered findings and the rebuilt document are in
harness-config/docs/iphone-talk-to-text-ios-27.md.
