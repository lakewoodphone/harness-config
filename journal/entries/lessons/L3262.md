**L3262 · Correction to H3161: the 0.2.0-rc.2 startup log I called clean records a FAILED start (EADDRINUSE on 127.0.0.1:3099, 2 plugins not activated) — a restart race, not a mount failure**

CORRECTION TO H3161, which said "the newest 0.2.0-rc.2 startup log is clean". IT IS NOT, and I read it
after writing that line. The log at
`~/.dsh/logs/startup-2026-10-05T04-25-40.198Z-7cb97e31-f1e8-4b94-afb1-e5e97e367c23.log` records a FAILED
start:

 error: StartupError: dsh: startup failed: 2 required plugins did not activate
 Failed plugins (1):
 Error: listen EADDRINUSE: address already in use 127.0.0.1:3099
 [cause]: AggregateError: Plugin activation failures

WHAT THAT IS, and what it is not. It is a RESTART RACE, not a configuration or mount failure: an engine
started at 00:24:16 local (pid 22224) already held 127.0.0.1:3099, and the next attempt could not bind.
A later engine started at 00:30:19. The claim in H3161 that stands is the narrower one — there are no
MOUNT failures in the logs (no "failed to mount", no "cannot be resolved", no `agent-preset/invalid`) —
but "clean boot log" was wrong and is withdrawn.

WHY IT STILL MATTERS. It means the machine went through at least one failed engine start during the
switch/restart window, which is consistent with the crash he reported without proving it caused it. Two
engines from the same 0.2.0-rc.2 install are running at once; one is the :3099 GUI engine, and the other
is consistent with a headless wake session. Nobody should read "the upgrade is done" as "every boot in
the window succeeded" — exactly one bound the port and at least one did not.
