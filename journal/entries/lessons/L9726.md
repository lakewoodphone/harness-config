**L9726 · A guard that has only passed its own test suite has not been tested: replay it and read WOULD-LOSE first**

A guard that has only passed its own test suite has not been tested. Replay it against the corpus, and score the LOSSES first.

Finished and deployed a set of three SMS guards whose own suite passed 115 checks. Replaying every one of the 482 texts that had ever reached the owner showed **14 that he had engaged with would now be refused — and ten of those were false positives.** `addressed` treated "Done —", "No —" and "Understood —" as somebody's name. `instruction` silenced two SECURITY questions he had answered ("Legitimate", "Yes, it was authorized by me"), because `Task #\d+` cannot tell an agent instruction from a question carrying a task id.

The suite never saw them, because the suite asserts the shapes the author thought of. The corpus contains the shapes he actually received.

WHAT TO DO. `scripts/text-channel/replay-owner-text.py`. Run it with `--base` pointing at the deployed directory. Read `WOULD-LOSE` before `WOULD-SAVE`: a suppression statistic that reports only what it saved is how a channel goes quiet and nobody notices. An `of-answered` count does NOT mean he engaged — a bare ack is "answered" by his next unrelated sentence, so the harness also computes `responsive` (his reply shares a distinctive token with the text) and reports that separately. 14 lost / 61 saved became 5 / 28 after narrowing, and four of the five remaining are texts that should never have been sent in that form.

Two specific narrowings worth keeping:
- **An id is not an instruction.** `Task #123` / `WO12345678` fire only beside an imperative about the work AND only when the body is not a question to him. "Task #12 is still open in the hub" is a message.
- **A capitalised word and a dash is not a name.** "Done —", "No —", "Understood —", "Ha —", "Ok —" are openers, not addressees. Keep a stoplist or the rule eats half the replies.
