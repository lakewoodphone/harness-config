**L2095 · L2088 - a monitor whose verdict depends on which window you asked for is not a monitor**

Three real bugs found by the test suite while building `company_outcome_monitor`, each worth keeping:

1. **`Cursor.set_progress_handler` does not exist.** It lives on the Connection. Because every
 section caught its own exceptions, the AttributeError was swallowed and every section silently
 reported UNMEASURED - the monitor looked like it was running and reported nothing. Found only by
 asserting on the *values*, not on "it did not crash".

2. **A verdict that changes with `--windows`.** `build_verdict` read `outcomes_7d`, so calling the
 monitor with `--windows 1` produced the verdict **OK** on an empty database. Fix: always compute
 the reference windows (1, 7, 30) regardless of what was asked for, and make an unreadable or
 empty section force UNMEASURED globally before any arithmetic runs.

3. **A `held` message that ages out of view.** Reporting "held" messages scoped to a time window
 makes the OLDEST held messages invisible - exactly the ones that matter most. The window is
 right for throughput and wrong for backlog. Fix: backlog sections are not windowed.

The generalisable version: **a monitor is only as good as the assertions on its numbers.** "It ran
and printed something" is not evidence. Assert on values, vary the parameters, and check that a
missing source produces UNMEASURED rather than OK - because "OK" and "no data" are the two states a
monitor must never confuse, and the empty-database case is how you tell whether it does.
