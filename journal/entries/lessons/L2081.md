# `--dry-run` on scripts/deploy-frontend-cloudflare.mjs DEPLOYED - the flag only skipped the credential check

Measured 2026-09-20 08:24Z on ZABZ-YOGA, while shipping the website holiday-closure fix.

The script's own docstring says `--dry-run` needs no credentials and "is the way to check this without
touching Cloudflare". It was not: `dryRun` was read at line 86 only to relax the token guard at line 97,
and the `npx wrangler pages deploy` call at line 107 ran unconditionally. So

 node scripts/deploy-frontend-cloudflare.mjs --dry-run

**built and uploaded a real deployment** - `76dd13de` to project `lakewood-phone-test`, i.e. the staging
host `test.lakewoodphoneandtech.com`. It only missed production because `arg('env') ?? 'test'` defaults
the target to test. **`--env production --dry-run` would have shipped to the live customer site while the
operator believed nothing was touched.** That is the real defect: a safety flag that performs the
dangerous action.

FIXED on branch `fix/holiday-closure-notice` (commit after e3fb20567): when `dryRun`, the build and the
redirects generation still run - that is the useful half of a dry run - and the function returns before
`run('npx', deployArgs, env)`, printing the exact command it would have run. The fix is in the repo only;
it is not uploaded anywhere, so it takes effect for the next person who runs the script from that branch.

NEVER trust a `--dry-run` flag on this repo's deploy scripts without reading the code that consumes it.
Two of this project's deploy paths have now been caught doing real work under a safety-sounding flag.
