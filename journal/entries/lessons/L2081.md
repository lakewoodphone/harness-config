**Lesson (2026-09-17, Goldstein microSD intake): the bench's `/usr/local/bin` engine can silently
lag the repo, and nothing checks it — verify the tools a playbook step depends on are actually
deployed before starting a case.**

`scripts/linux-pc/README-RECOVERY-ENGINE.md` states the rule plainly: the engine lives in two
places (repo = source of truth, `/usr/local/bin` = what agents actually run) and they must stay in
sync. Arming this case showed the rule is not enforced. `recovery-sigscan.py` — the **mandatory
Step 5a** of `playbooks/sd-card-recovery-playbook.md` — and `dedupe-recovery.py` (**Step 5e**) were
**absent from the bench entirely**, so two steps the playbook calls mandatory could not run there at
all. Both were deployed today by the documented procedure (CRLF stripped, syntax-checked, backup
kept, mode 755).

How it was found: an explicit `for t in …; do command -v $t` loop over every tool the playbook
names, rather than assuming. That loop should be the standard pre-case check.

Two related traps hit while doing it:
- `python3 -m py_compile` **cannot** be used as the syntax gate when the file is in `/tmp`: it tried
 to write `/tmp/__pycache__/…` and failed with EACCES because a **root-owned** `__pycache__` from an
 earlier `sudo` run was already there, so the check reported FAIL on a perfectly valid file. Use
 `python3 -c 'import ast,sys; ast.parse(open(sys.argv[1]).read())' <file>` — it checks syntax and
 writes nothing.
- The missing tools were invisible because the repo and the bench both "look right" in isolation.
 The fix is a one-line hash comparison, not discipline.
