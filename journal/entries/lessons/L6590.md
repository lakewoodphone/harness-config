**L6590 · publication restored: the journal publishes again after 2.5 days, to a dedicated ref rather than by force**

**The canonical journal had not been published off-machine since 2026-10-13T15:00:05Z. It is again, and
the fix is a ref, not a force.**

**The failure.** `journal-commit.sh` runs every 15 minutes, commits `journal/` and pushes `HEAD:$BRANCH`
with `BRANCH` defaulting to `main`. `vault/main` is `12147204` — a work commit, merge-base `83bc260b`
with the local checkout — so every push was rejected non-fast-forward. 158 non-zero rows in
`~/.cron-status/runs.tsv`; `cron-failures.py` reported it and the wake loop had **suppressed** it. The
checkout's branch is `i359-contentless-waiting`, so the publisher was pushing whatever branch happened to
be checked out to a ref named `main`, and once a different branch had been published there the mismatch
was permanent.

**The fix, and why it is a new ref rather than a reconciliation.** The script already reads an override
(`BRANCH="${JOURNAL_BRANCH:-main}"`), so the change is the cron payload, not the code:

```
# decode: JOURNAL_BRANCH=journal /usr/local/bin/journal-commit.sh
*/15 * * * * /usr/local/bin/cron-wrap.sh journal-commit Sk9VUk5BTF9CUkFOQ0g9am91cm5hbCAvdXNyL2xvY2FsL2Jpbi9qb3VybmFsLWNvbW1pdC5zaA==
```

Proven before installing, then installed, then run exactly as cron runs it:

```
[commit] 1 path(s) on journal at 76c45f2d
[pushed] 76c45f2d published to .../harness-config.git journal (remote HEAD read back and matches)
run row 2026-10-16T02:58:36Z journal-commit 0 2 <- rc=0
vault refs/heads/journal = 76c45f2d = local HEAD
```

**`vault/main` is deliberately NOT touched.** Reconciling it decides what the remote's canonical branch
means, and the two ways to do it are a merge into a live repository that other sessions are committing to,
or a force-push — forbidden without a per-action yes, and the reason this estate has a rule about it. A
dedicated rolling ref cannot conflict, publishes everything immediately, and leaves the old lineage intact
for whoever decides. Filed as its own pain; `P4697` is resolved because its stated condition — "the
journal has not been published off-machine" — is now measurably false.

**One consequence to keep in mind:** every preservation made earlier tonight went to
`refs/heads/authority-preserve-<date>` because this was broken. Those still exist and still hold the
intermediate states; they are now a dated history rather than the only copy.
