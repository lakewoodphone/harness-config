**L1977 · A dead entry point is caught by asserting the wire, not the behaviour**

Measured 2026-09-18 on kf-android (kosher-filter-ai): ScreenshotService.kt is 1,836 lines with no test file; the repo had 414 green unit tests and a shipped-looking MediaProjection feature whose only entry point (startWithConsent) had ZERO callers and createScreenCaptureIntent() appeared nowhere. No behavioural test can see a call that was never written, and there is no androidTest source set, so the defect was structurally invisible. Pattern that catches it, now in ScreenshotServiceConsentWiringTest.kt: (1) a pure/internal seam the JVM can exercise (handleResult -> recorded state + ShadowApplication.nextStartedService with the consent extras), and (2) a SOURCE-SCAN test that asserts production code outside the big class references the entry point. Resolve the source root as ['src/main/java','app/src/main/java'] (Gradle unit tests run with the module dir as cwd) and assert the scan is non-vacuous (file count > 50, the class under test is present) — otherwise the guard passes by scanning nothing. Use it whenever the audit finding is 'nothing calls this'.
