**L2790 · ast.parse is not a structural check: an inserted module-level def closed a class body and cost AutopilotController 62 methods**

`ast.parse()` proves a file is still Python. It proves nothing about structure, and on 2026-09-28
that gap cost a live `AutopilotController` 62 of its methods.

WHAT HAPPENED. A patch script inserted two module-level helper functions into `app/autopilot.py`
by REPLACING the text of an INDENTED method header:

 anchor: " def _maybe_flush_owner_message_queue(self, now_monotonic: float) -> None:"
 replacement: "def helper(...): ...\n\ndef helper2(...): ...\n\n def _maybe_flush..."

A `def` at column 0 ENDS the enclosing class body. So `class AutopilotController` terminated at the
insertion point, and every method after it -- 62 of them -- was re-parented as nested functions
inside the helper. The file still parsed. It still compiled. `py_compile` said OK. Only a test that
reached for one of the missing methods noticed, with
`AttributeError: type object 'AutopilotController' has no attribute '_maybe_flush_owner_message_queue'`.

THE FIX, and it is the reusable part: a patch script that touches a file containing classes must
compare the AST shape before and after, and refuse to write if it changed.

 def _class_shape(src):
 tree = ast.parse(src)
 return {n.name: len([c for c in n.body
 if isinstance(c, (ast.FunctionDef, ast.AsyncFunctionDef))])
 for n in tree.body if isinstance(n, ast.ClassDef)}

 before = _class_shape(original); after = _class_shape(source)
 for name, n in before.items():
 if after.get(name) != n:
 raise SystemExit(f"class {name}: {n} methods -> {after.get(name)}; the edit closed a class body")

That guard now lives in `scripts/owner-text-gate-2026-09-28-{c,d,e}.py` and prints
`class shapes preserved: {'AutopilotStatus': 0, 'AutopilotController': 109}` on success.

GENERALISED: any anchored text patch to a large file needs a STRUCTURAL assertion, not a syntactic
one. Syntax checking is what let this through; the class-shape count is what caught it. Insert
module-level code at module level, and let the guard say so if you did not.

Also worth remembering: the anchor made it look safe. Replacing ` def foo(...)` with text
starting at column 0 looks like "inserting above a method". It is not.
