# The PR gate ran no tests at all for human-authored PRs, and the file said so for five days

**Fixed 2026-10-14.** PR 426. Every earlier PR merged that day went in on lint and typecheck alone.

## WHAT WAS TRUE

`.github/workflows/pr-precheck.yml` gated both test jobs on
`needs.detect-changes.outputs.is_copilot_author == 'true'`. Every PR this session was authored through the
`lakewoodphone` account, which is not Copilot, so both shards **skipped** on every one of them.

**The merge queue said it out loud, and I read the line repeatedly without understanding it:**

```
CI Validation (Merge Queue) pass "PR pre-check passed (lint, typecheck and imports; no test suite ran)"
Test Backend (… Shard …) skipping
Test Frontend (… Shard …) skipping
```

## AND THE FILE ALREADY KNEW

`pr-precheck.yml:16-25`, corrected 2026-10-09, in its own words:

> *"They run ONLY for Copilot-authored pull requests … For a human-authored PR nothing in this repository
> runs `vitest` at all: the workflow that was supposed to (`merge-queue.yml`) no longer exists, and it
> could never have run anyway, because a merge queue requires branch protection that GitHub refused on
> this plan."*

**It was diagnosed, written down, and left in place. That is the finding.** A known gap that is documented
is more dangerous than an unknown one, because reading the file makes you believe the question is settled.

## THE RULE THIS PRODUCES

**A check that skips is indistinguishable from a check that passes to anyone reading the checks page.**
That is the worst property a check can have, and it is why the word `skipping` must be treated as a red
flag and never as a passing state.

Corollary, for every workflow in this estate: **a conditional test job must state, in the file, the
measured budget that justifies gating it.** If a job is skipped for a reason nobody wrote down, nobody can
tell a deliberate saving from a silent failure.

## THE COST, MEASURED

Six pre-existing test failures were later found in files nobody had touched:

- `CounterPage.test.tsx` — a row prints the short ticket number, not `WO-2026-0009`; an intake row prints
 `Ticket 41`, not `Case #41`
- `query.service.test.ts` and `query.service.search.test.ts` — both `TypeError: prisma.$queryRaw is not a
 function`

And the owner was shown live defects a running suite could have caught: a counter reporting
`Out for pickup 0` over a shelf holding hundreds, an inert-looking `Sales tax included` checkbox, and a
Card-reader panel printing `VITE_STRIPE_TERMINAL_READER_ID` at him.

## THE PROOF IT IS FIXED

PR 426 — which changes only a workflow file, so the old gate would have skipped it too — reports:

```
Test Backend (Shard 1/3) pending
Test Backend (Shard 2/3) pending
Test Backend (Shard 3/3) pending
Test Frontend (Shard 1/4) pending
Test Frontend (Shard 3/4) pending
```

`pending`, not `skipping`. **The fix is its own test.** The job ids keep the historical `-copilot` suffix
because saved check names refer to them; only the display names and the condition changed.
