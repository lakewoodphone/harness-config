**L2056 · Owner health facts live in docs/personal/health/, not in the memories table**

RULED (2026-09-18, SECRATARY): the source of truth for what is known about Eliyahu's health is docs/personal/health/ in the personal-secretary-mvp repo. owner_profile_v2 (category=health) and memories (category=health) are INDEXES that point at it, never replacements.

HOW TO WRITE A HEALTH FACT: (1) add/extend a per-condition file under docs/personal/health/, appended with a date, with an evidence level per claim (CONFIRMED / REPORTED / UNKNOWN); (2) index it with app.services.owner_model.set_preference(db_url, category='health', key=..., value=..., source=...); (3) one pointer memory row via app.services.unified_memory.save_memory. Never let a health fact exist only as a memory row.

EVIDENCE - why this had to be ruled rather than assumed: the owner asked me to 'document this as a health thing about me'. The obvious-looking home, memories category='health' (44 rows), turned out to be 100% duplicate CHEMED 'test results are available on the patient portal' notifications and ZERO actual health facts. owner_profile_v2 had no health category at all. So the system looked like it had a health record and had none - reading a row count from that category is not evidence of anything. This is P3 (reading the wrong data and believing it) applied to the owner's health.
