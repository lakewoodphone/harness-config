**L12258 · A declared runtime permission is not a granted one, and notify() reports success either way**

Lane kf-notify on ZABZ-TECH (branch agent/kf-android-notify, commit 745a9dbf): POST_NOTIFICATIONS was declared in android/app/src/main/AndroidManifest.xml and never requested anywhere in the app, so on Android 13+ every NotificationManager.notify() call succeeded and showed nothing. Two transferable facts. (1) On API 33+ a denied notification permission is invisible at the call site: notify() returns normally, logcat is quiet, the only honest detector is NotificationManagerCompat.areNotificationsEnabled() asked BEFORE posting, and the only durable evidence is a count of suppressed posts (push/NotificationDeliveryLedger in that tree). Any 'we send notifications' claim that was not read back through that gate is unverified. (2) The version gate and the grant state are separable and both belong in one pure function - decide(sdkInt, granted, deniedBefore) - because minSdk 29 vs the documented API 30 floor means the below-33 branch is real and a stale 'granted' reading must never produce a request on a platform that has no such permission. Precedence, not just each branch, is what needs a test. Also measured: the broker's POST /self/push/register takes a fixed pydantic model with no notification field and phone_push_tokens has no column for it, so a client that 'reports notification state to the broker' there is sending into a discard - pydantic ignores unknown fields silently, so the lie is invisible too.
