**L3118 · work.py add has no --json: passing one made 13 filings die silently on stderr**

Measured 2026-09-30 on the authority. A filer script passed --json to 'work.py add' because every other subcommand of wake.py accepts it. The add subcommand does not, so argparse printed its error to STDERR and stdout stayed empty. The filer captured only stdout and reported 'failed 13' with a blank reason for each - a silent failure that looked like thirteen different problems. FIX: capture stderr as well, and read the interface from the source (work.py:168-170 prints a bare status word plus optional JSON, so no flag is needed at all). RULE: when a batch of identical calls fails identically, the reason is almost always in the part of the output you are not reading. Capture both streams in every automated caller.
