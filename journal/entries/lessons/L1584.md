**L1584 · A red test suite breaks the whole instrument: while it is red no new test can act as a control, so proving a test RUNS is not proving its result means anything**

**Evidence, 2026-09-15, round 14.** I proved a test was wired into CI correctly, and in doing so found that the CI is already red — which makes the wiring worthless. Both halves are worth keeping.

## The measurement

`npx vitest run --root backend src/trpc` on a **clean** tree:

```
 Test Files 6 failed | 99 passed | 2 skipped (107)
 Tests 25 failed | 1398 passed | 86 skipped (1509)
```

Every failure is **pre-existing** (`terminal.ts` and `laptop-preference.ts` here are byte-identical to `origin/test`), and the two groups I read are **stale tests, not product defects**: `customers.backups` calls four procedures that no longer exist, and `terminal.error-handling` expects a *configuration* error while now receiving an *authentication* error — an assertion that could only ever have passed **while the router was unguarded**.

## The rule

**A red test suite is the instrument broken at the level of the whole repository.**

Every other measurement failure found this session was local — a warning that described a fixture, a count that
described mentions, a census read from the wrong tree. This one is structural: **while the suite is red, no new
test added to it can function as a control.** CI was failing before my guard test existed, so its failure changes
nothing anyone acts on, and a reader sees "6 files red" and files it as known noise. The test is correct and
invisible at the same time.

**So: before adding a control, check that the instrument it reports through is working.** I verified the wiring
properly — injected a bare procedure, watched a run that did *not* name the guard test fail it by name — and that
verification is exactly what exposed the red suite. **Proving a test runs is not the same as proving its result
means anything.**

## The inference I got wrong, and how

From the failure *shape* alone I wrote: *"`customers.backups` failing all four tests is the shape of a real
regression, not a stale assertion."* Reading them showed the opposite — the tests call procedures that **do not
exist**. A four-for-four failure *looked* like breakage and was drift.

**Failure shape is not evidence of cause.** The same mistake in the other direction would be worse: a stale test
that looks like drift while a real defect hides behind it. The only reliable move is to read the assertion, and
the cheap version is to read **one** from each group before assigning severity to all 25.

I left the correction visible in the note rather than quietly fixing the sentence — the note is *about* instruments
that report confidently, and it would be a poor example of one if it hid its own bad inference.
