**L1714 · DSH session logs are multi-frame zstd; .decompress() silently returns only the first frame**

Measured 2026-09-16: zstandard.ZstdDecompressor().decompress(bytes) on C:\Users\ezabz\.dsh\sessions\--C-Users-ezabz-code--\<id>\session.v3.jsonl.zstd returned 198 bytes for a 48,568,009-byte session (1,848 billled requests, 12.8 MB compressed). DSH appends frames, so the log is a concatenation of zstd frames and the non-stream API stops at the first. Anyone auditing these logs the obvious way concludes 'DSH records no usage' and is wrong.
