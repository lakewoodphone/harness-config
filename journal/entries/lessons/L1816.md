**L1816 · A vendor's self-serve order tracker is a hint, not ground truth - the carrier number is truth**

**Rule.** A vendor's self-serve order-status page is a *hint*, never ground truth. The only status that
counts is the carrier's tracking number, which has to be asked for and then watched. Poll the tracker for
corroboration, never to *conclude*.

**Measured evidence (2026-09-16).** ALCO Covers' public tracking Google Sheet (gviz endpoint, tab `August
2026`, row `216040-00`) read **"In Production"**, tracking empty, courier empty — on 2026-09-14 02:07 UTC
*and again on 2026-09-16 ~23:35 UTC*, the second read **two days after the tarp had already been delivered**
(2026-09-15 11:18 AM, UPS `1ZA257X90398834085`, per AKON's own service email msg `1a0aabc4c9cc3886`). The
same tab carried live UPS numbers on 721 other rows, which is exactly why the row looked authoritative and
was believed: a live sheet is not the same as a maintained row. On the strength of that row, three durable
records concluded "not shipped", the owner spent attention on a chase for an order that was already in
transit, and P52b was written up around a 16-day silence that was really a 16-day *lookup failure*.

**Second-order trap.** AKON's service team writes this order as `216040-00A`; the tracker row is `-00`. A
status lookup keyed on the wrong suffix can never match an update written against the other.

**What to do instead.** For any open order: get the **carrier tracking number** (ask for it explicitly in
the first confirmation email), record it next to the order, and poll *that*. If a tracker is used at all,
treat "In Production" as "unknown", not as "not shipped".
