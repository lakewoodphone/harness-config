**L1728 · tools.register() takes RAW JSON Schema: required is an array, not the author DSL's required: true**

`tools.register(definition)` validates `definition.output.schema` with `assertSupportedJsonSchema`, and that validator is RAW JSON Schema: `required` must be an ARRAY of property names. The author DSL used by `defineTool` (and therefore by every shipped plugin that calls `defineTool`) writes `required: true` INSIDE a property. Copying such a schema into a raw `tools.register` call throws

 JsonSchemaError: ... required must be an array of strings

and because the registration is (correctly) wrapped so a name collision cannot take the plugin down, the tool silently does not exist while the plugin reports itself mounted.

Evidence: dsh-plugin-health's `list_agents` replacement, 2026-09-16 — schemas copied verbatim from `dsh-tool-subagent-control/lib/types/list-agents.js`, registration threw, `ctx.logger?.warn` was a no-op in that context, and the only visible symptom was `/healthz` reporting `registry: not registered`.

Two durable habits from this: (1) validate any hand-built schema against the framework's own checker before believing it —
`assertSupportedJsonSchema(definition.parameters)` / `(definition.output.schema)`, both currently VALID for this plugin;
(2) never let a registration failure be a log line only — record it and publish it on the surface the plugin owns (here: `listAgents.readoutToolRegistrationError` and `governor.registrationError` in `/healthz`).
