**L1871 · The waze-mdm fleet-api container runs the IMAGE, not the host directory - a restart after editing the host file changes nothing**

## Lesson — the waze-mdm fleet-api container runs the IMAGE, not the host directory

Measured 2026-09-17. `docker inspect waze-mdm-fleet-api-1` shows exactly these mounts: `/opt/waze-mdm/profiles → /srv/profiles` (ro), `/opt/waze-mdm/wallpapers/source → /srv/wallpapers/source` (ro), the VPP token, and two named volumes (`waze-mdm_fleet_data → /data`, `waze-mdm_wallpaper_data → /data/wallpapers`). **`/srv/*.py` comes from the image build (`Dockerfile` COPY), not from a bind mount.**

Consequence: editing `/opt/waze-mdm/fleet-api/fleet_api.py` on the host and then `docker restart waze-mdm-fleet-api-1` changes **nothing**. I did exactly that with a fix and watched the behaviour stay identical — the giveaway is `docker exec waze-mdm-fleet-api-1 md5sum /srv/nanomdm_client.py` still showing the old hash while the host file shows the new one.

Three ways to deploy, in order of preference:
1. `cd /opt/waze-mdm && docker compose build fleet-api && docker compose up -d fleet-api` — the host directory is the build context, so this is the real path. Slower, and a failed build leaves the old container running (that is a feature).
2. `docker cp /opt/waze-mdm/fleet-api/<file> waze-mdm-fleet-api-1:/srv/<file> && docker restart waze-mdm-fleet-api-1` — fast, works, and leaves the container's copy ahead of the image; the host build context has the same file, so the next rebuild converges.
3. Editing the repo copy and expecting it to be live — never works. The repo's `fleet_api.py` is 318,014 B / md5 `3741035e8d34548d0b3eceacf611474d`; the running one is 348,219 B / md5 `aba5f091269311e6ef68eeb2ca989b21`.

This is the mechanism behind the repo↔host fork: people fixed production by editing the host copy and rebuilding the image, and the repo never heard about it. Proof it is one lineage and not two: `/opt/waze-mdm/fleet-api/fleet_api.py.bak-20260915` (mtime 2026-09-15 19:00:17Z) is byte-identical to the repo's HEAD blob; the divergence is exactly four host edits made between 2026-09-15 20:22 and 21:38 UTC.

Verification rule: after any deploy, `docker exec … md5sum /srv/<file>` must equal the file you built from, and at least one behavioural number must move.
