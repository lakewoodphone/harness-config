**L1593 · A coerced 0 is a confident lie: never default an unknown reading to zero**

Seen 2026-09-15 in phone-and-tech-full backend/src/services/waze/waze-device.service.ts. toNumber(value, fallback=0) mapped the fleet-api's null usage figures to 0, so a FAILED Telnyx read rendered to customers as '0 MB of 0.8 GB - Plenty left'. The API changed to send null + usage_known:false; Number(null) is 0, so nothing errored and nothing looked wrong. Fix: a separate toNullableNumber for any value that can legitimately be unknown, keep toNumber only for genuinely required fields, carry an explicit known/unknown flag, and make the UI render an 'unavailable' state. Also: an unrecognised enum member must not fall through to the optimistic one ('unknown' band must not become 'ok'). Rule: when a field can be unknown, null is the only honest default.
