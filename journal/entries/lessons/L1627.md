**L1627 · chumash-timeline API work: index first, validate at the edge, verify the brief's numbers**

A "search is slow" bug in this codebase is usually a missing index, not slow code — but you can only prove it with EXPLAIN (ANALYZE) on the real data before and after.
Evidence: /api/search?q=... ran 371.808 ms as a seq scan because it called regexp_replace(hebrew, niqqud, '', 'g') on the column side, so no index could serve it. Creating pg_trgm plus one GIN index on that exact expression, and one each on transliteration and translation, turned it into a BitmapOr at 0.407 ms. The single Hebrew index alone was NOT enough: an OR across three columns only becomes a BitmapOr when all three branches are indexable, and ILIKE '%x%' cannot use a btree.

Zod's z.coerce.boolean() is wrong for query strings. Boolean("false") === true, so ?includeText=false silently meant true and no payload ever shrank. Parse flags explicitly ("true"/"false"/"1"/"0") and 400 on anything else.

A missing index is not the only way to hide a bug in an endpoint: the same request path can be 500-with-an-empty-body. GET /api/search?q=%00 returned HTTP 500 and ZERO bytes because a NUL byte reached Postgres (22021 "invalid byte sequence for encoding UTF8: 0x00"). Validate control characters and unencodable input at the edge, and make every route answer JSON on every path — a client library cannot tell an empty 500 from a crash.

"0 results" and "the store is down" are different answers. This codebase's data-layer functions returned [] when DATABASE_URL was unset, so the route said {ok:true,count:0,hebrew:""}. Gate every DB-backed branch on isStoreConfigured() and map thrown pg errors to 5xx; a valid query with no matches stays 200 with count 0.

The Hebrew calendar's four dehiyyot are not optional. A shortcut like "if ((3*(monthsElapsed+1))%7 < 3) day += 1" put 1 Tishrei on a Sunday/Wednesday/Friday for most years tested. Compute the molad (29d 12h 793p past the molad of year 1 at 5h 204p into Monday, day boundary 18:00), apply molad zaken / GaTRaD / BeTUTaKPaT, then lo ADU rosh — and decide 12 vs 13 months from the Metonic cycle, never from the year length. Cross-checking 1001 years against @hebcal/core is cheap and found two wrong "correct" values in my own task brief.

When a task brief hands you numbers to assert against, verify them against an independent implementation before asserting. Two of the four claimed Rosh Hashanah values in my brief were wrong (5785's weekday, and 5788's date by two days); the independent implementation and the Hebcal REST API agreed with the computed values, not the brief.

A git worktree whose node_modules is a junction into the main clone breaks Turbopack: "Symlink [project]/node_modules is invalid, it points out of the filesystem root". next.config.ts must set turbopack.root to the nearest ancestor that actually contains the real node_modules (main commit 7eae4e5), otherwise every worktree fails npx next build.

`npx next start` does not work when next.config.ts sets output: "standalone" — it prints a warning and can serve a stale bundle (I got 401 "unauthorized" from a leftover standalone tree). Serve the production artifact with `node .next/standalone/<trace-root>/server.js` instead.
