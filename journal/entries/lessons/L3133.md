**L3133 · PowerShell over ssh returns CRLF: strip CR at the ssh helper, not per call site**

Windows PowerShell over ssh emits CRLF, and a trailing CR silently defeats every numeric
comparison on the Linux side. Measured 2026-09-30 while building the C3 check suite: three
checks (P2550 log count, P14 runner memory, P10 bridge count) returned UNKNOWN inside the
script although the identical command worked standalone, because `cnt=$(ssh ... powershell ...)`
yielded "921\r" and `case "$1" in ''|*[!0-9]*)` therefore rejected it. A parse that uses sed
tolerates the CR and hides the defect; a parse that uses an exact numeric test does not.

Fix, now in checks/C3.sh: strip CR at the transport boundary in every ssh helper
(`... 2>/dev/null | tr -d '\r'`), not at each call site. Applies to C1/C2/C4/C5 too, since all
five builders ssh to zabz-tech-ts for live facts.
