**L2609 · One machine was missing from a fleet repair, and the defect was invisible for ten days because a profile only fails at engine START**

Her laptop's assistant was dead for TEN DAYS (2026-09-18 -> 2026-09-28) and nothing said so.

CAUSE: `~/.dsh/profiles/web/package.json` declared `dsh-mesh-broker` as a profile bundle. That
package is the broker SERVICE - it resolves, but declares no `dsh.bundle.patch`, and
dsh-app-boot/lib/index.js:852 throws for any declared bundle lacking one. A bundle list is a LAYER
list, so one bad name stops the whole engine. That exact defect was repaired on ZABZ-YOGA,
ZABZ-TECH (H441) and lakewooechsmini (H451) on 2026-09-17. Her laptop was never on that list.

L1865 had already stated the shape of the trap: "the machine looked healthy and was one reboot from
an engine that could not come back." It rebooted 2026-09-18 18:05 and never came back. The engine
reads its profile at START, so a running engine proves nothing about the next one, and the failure
is invisible until a reboot.

WHY NOBODY NOTICED, WHICH IS THE REUSABLE PART:
* the shipper task ran hourly and reported success while doing nothing (L174: "the task exited 0"
 is not evidence the work happened);
* the logon-trigger task fired 4 minutes after boot and returned 0 while the engine died in < 1 s;
* the authority's `dsh_sessions` was the only surface that knew, as a growing age: newest ingest for
 desktop-fgv6kmh was 2026-09-16T17:41Z, 274 hours stale.

RULES
1. A per-machine repair list IS NOT A FLEET REPAIR. The three machines that got fixed were the three
 in front of the repairing session; the fourth was invisible BECAUSE it was not. Verify a fleet fix
 by asserting the ABSENCE OF THE DEFECT on every machine, not by listing the machines you touched.
2. A defect that only manifests at process start is silent on a running machine. Any machine you have
 not restarted since a profile change is UNVERIFIED, not healthy.
3. The cheapest real gate for a profile is `dsh --profile <name> --dump-config` - it composes the
 layers, starts nothing, evaluates no `!!js`, and is safe on a machine in use. Run it as the
 explicit post-repair gate; on her box it moved from exit 1 / 0 lines to exit 0 / 581 lines.
4. When a machine goes quiet, age-of-last-ingest is the signal, not task exit codes. That is how this
 was found: a 274-hour gap in one column.
