**L12168 · A synthetic input that produces no effect on a CONTROL page has told you about your instrument, not the site**

2026-10-21, the LPT website on the owner's phone: 'it keeps refreshing and going to the top, so it's stuck on top and I can't scroll down, cuz every time I scroll it looks like it's flashing.'

MY FIRST MEASUREMENT WAS A CONFIDENT FALSE POSITIVE. I drove Production in Chromium at an iPhone 13 viewport with Playwright's Input.synthesizeScrollGesture and read '0 -> 0 -> 0': the document never moved. I inspected the CSS, found 'html, body { overflow-x: clip }', and concluded that clipping the root scroller makes Chrome refuse touch pans. I wrote that down as the cause and started a fix.

WHAT SAVED IT: a control. Before shipping, I served a plain 6000px page from the same server and ran the same gesture - and it also reported 0 -> 0. A gesture that cannot scroll a bare div has told you nothing about the site. The instrument was broken (that CDP method produces no scroll in this Chromium build), and every conclusion built on it was worthless.

THE REPLACEMENT, and it is the general shape: dispatch the actual event stream a device sends - Input.dispatchTouchEvent with touchStart, touchMove xN, touchEnd - and validate it on the control in the same run. Then: control moves, production Chromium 0 -> 2400, production WebKit 0 -> 2500, zero navigations, zero page errors. The 'html overflow-x: clip' theory was retracted and the CSS was left alone.

WHAT DID turn out to be real, from a different instrument (computed styles): pull-to-refresh was enabled - htmlOverscroll 'auto', bodyOverscroll 'auto' - so a downward drag at the top lets Android Chrome re-fetch the whole document, which looks exactly like his description. overscroll-behavior-y: contain closes it; measured after: 'auto contain' on both, page still scrolls under a real touch gesture.

THE RULE: before believing a NEGATIVE from any synthetic input - no scroll, no click, no key, no network event - run the same input against a control that must respond. A page that fails to move is the site's fault only if a bare page moves. This is the same class as reading a refusal as a negative, and it cost the same hour.
