# L1937 — I fixed the same bug twice while the fix was never on the host

## What happened

For two rounds the orphan-vs-orphan collision guard in `audit.py` "did not take effect". I read the code,
reasoned about the logic, rewrote the logic, re-measured, and it still did not take effect — so I rewrote
the logic again.

**The deployed file never contained either version.** The authority's copy had **0** occurrences of the
identifier I was grepping my local file for; my local had 1. The guard was written in my editor and never
reached the host, so every logical change I made was applied to a file nobody was running.

It surfaced only when I finally grepped the DEPLOYED copy instead of re-reading my own:

 ssh host "grep -c orphan_shared_targets /path/to/audit.py" -> 0

One command, two rounds earlier, would have ended it.

## Why this is a distinct failure from round 9

Round 9 I overwrote a live tool and discovered it by RUNNING it — the damage was active and loud.
This was the inverse: I edited a file that was not being run, so the damage was *silent*. Nothing was
broken; my work simply had no effect, and I interpreted "no effect" as "wrong logic" for two rounds.

Both come from the same root: **I verified my intent, not the host's state.**

## The rules

1. **After deploying, prove the host changed.** Grep for an identifier you just introduced. A deploy
 command that prints nothing, or the absence of an error, is not evidence.
2. **When a change "has no effect", suspect the deployment before the logic.** Logic errors usually change
 behaviour in *some* way. A change with EXACTLY zero observable effect is more often not running.
3. **Never diff your editor against your memory. Diff your editor against the host.**
 `ssh host "diff <(git show HEAD:path) path"`, or simply grep for the new symbol.
4. **This is the third deploy-verification failure in this session** (round 9's overwrite, round 16's
 digest, this one), and all three sat in the same gap: the step between "I wrote it" and "it is running".
 That step has now cost more time than any logic bug in the session.

## Evidence

- Before: `ssh secratary-ts "grep -c orphan_shared_targets /home/zabz/repos/lpt-hub/tools/customer/audit.py"`
 → **0**; local file → **1**.
- After deploying and re-checking: → **1**, and `meta["orphan_shared_targets"]` immediately printed the 5
 shared targets, `near_certain_collisions` went 33 → 43, `records_with_near_certain_case` 11 → 5.
- The logic bug that WAS real took one edit once the file was actually deployed: the guard sat inside
 `len(rt) >= 3`, so 2-token collisions never reached it.
