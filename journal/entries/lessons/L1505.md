**L1505 · A scheduled task can report Ready while shipping nothing — read its log, do not trust its state**

FOUND AND FIXED 2026-09-15, in the last verification pass.

HER LAPTOP WAS SHIPPING ZERO SESSIONS while its scheduled task reported "Ready". The task exited 1
with "error: no token: set DSH_ARCHIVE_TOKEN", every hour, since I had moved the credential.

CAUSE, and it was mine: `push-dsh-sessions.mjs` searches `personal-secretary-mvp/.env` only. I had
moved her token into `harness-config/.env` because it cannot live in `~/.dsh/.env` -- the harness
refuses to BOOT when a bootstrap name appears there, which is what took her engine down earlier in the
same session. So the token had a correct home and the script did not look in it.

FIX: harness-config's own .env was added to the search list, with the reason recorded at that spot
(including why ~/.dsh/.env is forbidden), plus BOM tolerance because PowerShell's Set-Content writes
one and it silently defeats a key-name match.

VERIFIED BY RE-RUNNING THE TASK, not by reading the code: result 0, "shipped: 3 session(s), 102 new
row(s), 241 KB / unchanged: 9 session(s) already complete (cursor)".

THE GENERAL LESSON: a task showing "Ready" says nothing about whether it is DOING anything. Read the
task's own log. This one was Ready and useless for hours, and it was caught only by re-running it and
reading what it wrote.
