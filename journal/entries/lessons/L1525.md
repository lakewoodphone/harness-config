**L1525 · A notification IMAGE is fetched by the app with no session - a login-gated URL breaks it, including on the LAN**

**A URL used as a notification *image* is fetched by the phone app in the background, with no session. Pointing it at a login-gated host breaks the picture everywhere -- including on the LAN where it used to work.**

Measured 2026-09-15 on the live estate, minutes after the owner approved and I applied the change.

`phoenix_external_base_url` was `http://192.168.50.34:8123` (LAN only). The owner's snapshot links
in notifications therefore only rendered at the shop. He approved repointing it at
`https://ha.abletelsolutions.com`, the existing cloudflared tunnel, so they would work anywhere.

I changed the secret, reloaded, and **proved the new value was live** by reading a fresh script trace:

 base url check 3 -- https://ha.abletelsolutions.com/local/snapshots/latest_..._control_room_interior.jpg

Then I checked *how* the URL is actually consumed, which I should have done first:

 image: '{{ snapshot_url }}' <- the picture shown INSIDE the notification
 clickAction: '{{ snapshot_url }}' <- the tap-through link

`image:` is downloaded **by the app, in the background, with no interactive login**.
`https://ha.abletelsolutions.com` is behind Cloudflare Access, which answers a sessionless request
with **302 to `https://dawn-cell-26a7.cloudflareaccess.com/cdn-cgi/access/login/...`** (measured).
So the app would receive a login page instead of a JPEG.

And because the URL is now the *external* one, it would fail **even on the office WiFi** -- where it
works today. A change meant to add "works from anywhere" would have removed "works at the shop".
Net: worse, on the thing he looks at every day.

**Reverted**, reloaded, re-proved with a fresh trace that the LAN URL is back, and the change is
recorded with its backup (`secrets.yaml.bak-baseurl-*`, `.before-revert-*`).

**The rules.**
- **Check how a value is consumed before changing it.** `image:` and `clickAction:` are different
 transports with different authentication; one secret fed both.
- **"Verified live" is not "verified correct".** I proved the new URL was in use and that was true;
 it was the wrong URL to have in use.
- **A gated public URL is not a public URL.** Behind Cloudflare Access, requests that cannot log in
 -- background image fetches, webhooks, other services -- get a login page. Convenience for a human
 tapping a link is not availability for a machine.
- The version that actually delivers "snapshots from anywhere" needs a Cloudflare Access policy
 change (bypass for `/local/snapshots/`), which is the owner's dashboard, not a secret edit.
