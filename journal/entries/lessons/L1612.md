**L1612 · personality-system scoring backbone: what you cannot widen, and the real baselines**

Repo: C:\Users\ezabz\Code\_worktrees\personality-system\scoring-truth (branch agent/scoring-truth), 2026-09-15 session.

FACTS A FUTURE AGENT NEEDS BEFORE TOUCHING src/lib/assessment:
1. 'NumericProfile<TKey> = Record<TKey, number>' CANNOT be widened to 'number | null' or 'Partial'. Five files outside the scoring scope index profile.scores[key] directly and do arithmetic on it: adaptive-selection.ts (lines 91,138-163,247-267,284), routing.ts (59,63), runtime.ts (1429 .sort((l,r)=>r[1]-l[1])), plus ai-payloads.ts (771-777 serialises the profile objects) and assessment-scores.tsx (84-112). Widening produces production type errors in files you may not edit -> the change fails definition-of-done.
 The honest low-blast-radius pattern that works: keep 'scores' with its historical 0 sentinel and add an optional additive 'readings?: DimensionReadings<TKey>' ({value:number|null; contributions:number}) plus 'answeredFields?: readonly string[]' on ContextProfile, with accessors dimensionReading/dimensionValue/measuredDimensionCount/isFullyMeasured in types.ts. Legacy profiles without 'readings' -> the literal 0 still means unanswered, any other finite number is taken at face value (this is what keeps test-fixtures.ts and runtime.test.ts passing).
2. RecommendationCandidate's lens fields CAN be widened (interestCorrelation/capabilityAlignment/feasibilityAlignment to number|null) because ai-payloads.ts declares 'shortlist: unknown'. test-fixtures.ts and assessment-features.test.ts only assign numeric literals, which widen fine.
3. 'runtime.ts' constructs an AdaptabilityProfile literal (UNASSESSED_ADAPTABILITY_PROFILE, line ~202) with scores all 3 and no readings, and it supplies that placeholder when a session skips the adaptability module. So any module-completion gate MUST NOT require the adaptability module; runtime.test.ts:949 and :966-975 assert a shortlist exists for exactly that case.

Real baselines in this repo (measured, not assumed): 'npx vitest run' = 103 tests / 15 files passing; 'npx tsc --noEmit' = 28 errors, ALL in test files (ai-model-policy.test 10, runtime.test 7, ai-payloads.test 5, ai-orchestration.test 2, tests/e2e/generated-content-refresh.spec 2, app/api/assess/route.test 1, session-insights.test 1). The task brief said ~34; it is 28. Verify before claiming a regression.
5. 'npx eslint . --max-warnings=0' fails on react/no-unescaped-entities in assessment-launchpad.tsx and assessment-scores.tsx (the latter's lines are owned by a separate lint agent; the four flagged lines there shift by +2 if you add comment lines above line 44).
6. Running a scratch harness: vitest refuses globs that escape the config root. Use an ABSOLUTE include pattern ('C:/.../_scratch/harness/**/*.test.ts') and set root to the repo so node_modules resolves, with the '@' alias pointed at either the repo src (after-values) or a mirror of HEAD (before-values).
