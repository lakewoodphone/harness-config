**L3675 · 'Pull up X' means SHOW X - not my summary of X. And a one-word 'which customer is this?' means the record's identity fields are broken, not that I need a better summary**

**Owner, 2026-10-12, opening of this job:** *"which customer is this pull up their case file fully, come on."*

## What he was correcting

I had answered "pull up the 73459 data recovery case" with **my own summary** — a table of numbers and a status narrative. He wanted **the case file**, and he wanted to know **whose case it was**.

Two failures in one line of mine:

1. **A summary is not the thing.** I rebuilt my own version of the record instead of showing the record. My version dropped the customer's identity, the device, the timeline, the lab terms, the policy decision, the stop rules — everything that makes the file the authoritative artefact. **When he says pull up a case, the case is the deliverable.**
2. **The record could not answer "which customer".** The file's slug was `usb-files-disappeared-tbd-2026-08-06`, its `customer` field had been empty for the first seven weeks, and the two production identifiers read `TBD`. The name **Kogel** had been in the file since 2026-08-30 and in a Dialpad transcript since 2026-08-25, and the customer's **full name was on a Stripe page**. **A one-word question — "which customer is this?" — is a signal that the record's identity fields are broken, not that the reader needs a better summary.**

## The rules

- **"Pull up X" means show X.** Not a précis, not a table I composed, not "here's what matters about it". The record goes on screen, in its own words, and then anything I want to add goes after it.
- **The first three things any case file must answer: who, what device, what state.** If a file cannot, fixing that comes before anything else in the case.
- **A `TBD` in a current-state field is a defect with an owner.** Chasing it found a name that had been sitting in the record for eleven weeks and a `case_id` that still reads `tbd` today because the case standard forbids renaming.

## Why this one mattered more than a formatting nit

The same session later needed **Abraham Kogel's** first name, and it was on a Stripe checkout page nobody had looked at while the case file said *"first name not established"* and *"gender not established"* for weeks. **The identity fields were the least maintained part of the record and the most asked-for part of it** — he asked "which customer is this" as the very first thing, and had to ask again before I answered it properly.
