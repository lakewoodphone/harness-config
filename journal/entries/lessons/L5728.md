**L5728 · ZABZ-TECH: the display blanks itself after 300s on AC; the real risk is 8 hard stops in 30 days**

Owner asked (2026-10-15, ~19:50 local / 23:50 UTC): ZABZ-TECH must stay ON for
Saturday in a room where people sleep, and the screens must stay dark. He then
observed the display already dark and asked whether that was me or automatic.

ANSWER: automatic. Every call I made to that box was a read (powercfg /query,
powercfg /requests, powercfg /a, query user, Get-CimInstance, Get-HotFix,
Get-WinEvent). Nothing I ran writes. `powercfg /requests` returned
`DISPLAY: None.` — nothing was holding the display on. VIDEOIDLE on AC was
`0x0000012c` = 300 s before the read and the same `0x0000012c` after, i.e.
unchanged by me.

VERIFIED CONFIG (ssh ezabz@zabz-tech, 2026-10-15 23:52-23:58 UTC)
- Windows 11 Pro build 26200, LENOVO 30H10010US, 68,339,048,448 B RAM,
 chassis type 35, 4 monitors (DELL S2725QC, Acer KB242Y E, 2x U27B3A),
 Intel UHD Graphics 770 + NVIDIA T1000 8GB.
- Active scheme "Lenovo Default" 6a6afb64-10b2-42f6-9aa8-54d67f56a03b.
- VIDEOIDLE (turn off display after) AC = 0x12c = 300 s. Sleep after AC = 0x0 =
 Never. Hibernate after AC = 0. Hibernation NOT enabled; only Standby (S3)
 available — no Modern Standby (S0), so `powercfg /sleepstudy` is meaningless
 on this box even though it still writes a 911 KB HTML file.
- Screen saver: ScreenSaveActive=1 but no SCRNSAVE.EXE and no timeout.
- So: display blanks itself ~5 min after the last input, machine stays fully on.
 Owner confirmed the dark screen visually. Nothing needs changing for Saturday.

WHAT WILL LIGHT ALL FOUR SCREENS: a restart. POST + the logon screen, then dark
again ~5 min later.
- BIOS (Lenovo_BiosSetting WMI): AfterPowerLoss = `Last State`, SmartPowerOn
 Enabled, EnhancedPowerSavingMode Disabled. There is NO battery and NO UPS
 (no Win32_Battery device). Because it is Last State, an AC loss brings the
 box back on by itself — good for "keep it on", bad for "keep it dark" for
 the ~5 minutes it takes to blank again.

THE REAL FINDING — 8 HARD STOPS IN 30 DAYS (Kernel-Power 41)
9/27 10:50, 9/30 16:59, 10/6 09:01, 10/6 18:24, 10/7 16:39, 10/9 11:37,
10/11 14:26, 10/15 19:49. Seven of the eight: BugcheckCode 0 AND
PowerButtonTimestamp 0 — no crash record and no power-button press, i.e.
sudden power loss or a hard lockup that wrote nothing. One real bugcheck:
307 = 0x133 DPC_WATCHDOG_VIOLATION on 10/11 14:26 (power button pressed to
recover). WHEA-Logger: 0 events in 30 days, so no recorded CPU/PCIe/memory
hardware error. The last one was 19:39:54 on 10/15 — 22 minutes before he
asked me. Times of day cluster around shop hours (11:35, 14:23, 16:37, 16:59,
18:23, 18:56, 19:39) plus one morning — consistent with a load-dependent power
problem, unproven. NOT YET DIAGNOSED.

METHOD LESSON — Kernel-Power 41 is written at the NEXT BOOT, not at the crash.
Its TimeCreated is boot time; the crash time is in the text of event 6008
("The previous system shutdown at H:MM:SS was unexpected"). A "5 minutes before
event 41" window therefore reads BOOT events (BitLocker-Driver 24641, etc.),
not pre-crash events. I did that first and it was worthless. Use 6008 for the
crash time.

WINDOWS UPDATE on this box: KB5127647, KB5127648, KB5127690 installed
2026-10-14. TrustedInstaller/MoUsoCoreWorker restarted it 3x between 03:43 and
03:49 on 10/14, and StartMenuExperienceHost restarted it again 08:06. So the
monthly restart is already spent for this cycle. NoAutoRebootWithLoggedOnUsers=1;
active hours 10:00-02:00; no pending-reboot flag at the time of reading.
