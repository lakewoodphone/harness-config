**L12366 · onboard.py and every python-spawned ssh hang on ZABZ-TECH; drive the fleet API from pwsh instead**

MEASURED 2026-10-25 rebuilding LPT 2002 after its reset.

onboard.py 2002 on ZABZ-TECH: clear-passcode and push-apns worked (both are HTTP), then the check-in wait died 4 times with subprocess.TimeoutExpired on 'ssh -i ... hetzner docker exec -i waze-mdm-postgres-1 psql ... -f -' and the script aborted before any write step. That error message says 'devices not checked in' and blames the device; it was the CLI's own transport.

The same command typed in pwsh returns in under a second, with the hetzner key, with the zabz-tech key, and with no -i at all. So it is not the key and not the host: python subprocess with piped stdio cannot reach ssh.exe in this session (the harness sandbox blocks the pipe; the same fault showed earlier as a Cygwin NtCreateDirectoryObject 0xC0000022 from git-bash ssh). WAZE_MDM_SSH_KEY fixes the key, not this.

What works from here: read the WAZE_MDM_SSH_KEY env for anything that only needs the key, and for anything that shells out, do the HTTP calls in pwsh. The full onboarding, in onboard.py's own order:
POST /push-wallpapers, /lockdown, /install-profile?profile_type=telnyx-apn&drn=<drn>, /install-waze, /lockdown again (the app install strips webtrap + siri-dns), /set-device-name?device_name=..., /activation-lock. Then push-apns and read commands JOIN command_results USING (command_uuid) — commands has no enrollment_id, command_results has no request_type.
