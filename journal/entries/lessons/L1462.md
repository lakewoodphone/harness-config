**L1462 · A production checkout can be hundreds of commits behind origin; push your one commit from a detached worktree, never by pulling**

**Evidence:** 2026-09-14, `secratary`'s `/home/zabz/personal-secretary-mvp` was **20 ahead / 108
behind** `origin/master` (`git rev-list --left-right --count HEAD...origin/master`) and had 20
modified tracked files plus 53 untracked ones belonging to a running system. `git push` was rejected
(`fetch first`). Reaching for `git pull --rebase` there would have rewritten the branch under a live
autopilot, and `git stash -u` would have churned a 4 GB tree.

**What worked, in ~5 s and with the working tree untouched:**
```
git worktree add --detach /tmp/wt origin/master
cd /tmp/wt && git cherry-pick <my-commit> && git push origin HEAD:master
git worktree remove --force /tmp/wt
```
This is the general rule for any shared/authority checkout: **commit locally, then move the commit to
the remote from a worktree based on `origin/master`**, and verify with `git ls-tree`/`git log
origin/master`. Do not chase a diverged production branch, and do not "fix" it — 19 of those 20 local
commits were real unpublished work by other sessions, which is a separate finding, not a cleanup
invitation.
