**L1570 · Family chat has five send paths that never write the message row, so 'why did Chip say that' cannot be answered from our own DB**

CONFIRMED 2026-09-15, same file (app/family_chat/hub.py). twilio_client.send_message
is called with no db.log_message() in these places:

 hub.py:171 _notify_admins -> admin notices go out unrecorded
 hub.py:335 admin-command reply -> an admin's ! list / ! status reply is unrecorded
 hub.py:722 mute notice -> the "you're muted" text is unrecorded
 hub.py:838 flush_outbox send -> a retried outbox message updates the outbox row but writes no message row
 hub.py:852 (same flush path, MMS fallback branch)

_send_to_member (hub.py:399 and :413) DOES call db.log_message, and that is the
only path that does -- so Chip's normal group replies are recorded while
everything in the list above is invisible.

This explains the observed count: on 2026-09-15 Twilio shows 19 sends on the hub
number between 15:48 and 15:53 and the messages table holds exactly one row,
the 15:50:45 group send that went through _send_to_member. The 15:48:33 send to
+18482455577 carried canned text with no [Family Chat] prefix, so identify the
exact path from the row, not from the label.

Consequence: Twilio is the only complete record of the family chat. Any
investigation ("why did Chip say that", "did the reminder go out", "how many
messages this month") is unanswerable from family_chat.db, and the monthly spend
figure read from chip_monthly_spend only counts the logged subset.

Fix shape: one send-and-record function in the hub that every path must use, so a
new path cannot forget; plus a reconciliation against Twilio's list that reports
drift instead of accepting it.
