**L3329 · In PowerShell 5.1 @() on a List[object] throws; it silently killed the collector's SUMMARY.md for two rounds**

**In Windows PowerShell 5.1, `@($someList)` THROWS `ArgumentException: Argument types do not match` when `$someList` is a `System.Collections.Generic.List[object]`.**

Measured 2026-10-05 on ZABZ-TECH, reproduced in a bare session, outside any module, with no
`Set-StrictMode` in play:

```
$L = New-Object System.Collections.Generic.List[object]
$L.Add(1)
@($L) -> THROWS: Argument types do not match
@($L.ToArray()) -> OK, count=1
$A = @(1)
@($A) -> OK, count=1
```

So the array-subexpression operator is safe on an `object[]` and **fatal on a `List[object]`**. It does
not warn, and the failure lands wherever the expression sits.

**What it cost here.** `collect/Collect-LptState.ps1` accumulates its guarded outcomes in
`$script:Results = New-Object System.Collections.Generic.List[object]` (line 93) and its verdicts in
`$script:Verdicts` likewise (line 94). Three separate `@()` coercions on those lists threw:

- `Get-GuardedSummary -Results @($script:Results)` — died **before entering the helper**, so the helper's
 own robustness was irrelevant and the run logged `outcome counts UNAVAILABLE`;
- and inside the SUMMARY.md writer, `if (@($script:Verdicts).Count -eq 0)` threw, caught by a broad
 `catch` that logged `ERROR writing SUMMARY.md: Argument types do not match`.

The combined effect: **`SUMMARY.md` was never written** — the one document whose whole purpose is to say
at the top "this run is 40% unreadable". The failure was caught, logged, and then the run continued
looking normal. Two rounds of diagnosis went into the wrong layer (the parameter binding, then property
access under StrictMode) because the error message names no line and the catch was broad.

**Rules:**

1. **Never `@()` a collection you did not create.** If it might be a `List[T]`, materialise it with
 `.ToArray()`, or iterate it with `foreach`. `@($x)` is a coercion, not a safety net.
2. **Accumulate in a `List[object]` OR in an `@()` array, not both.** Mixing the two containers and then
 passing them through `@()` is the exact combination that breaks. This kit's collector declares a
 `List[object]` and then treats it like an array in three places.
3. **A broad `catch` around a report-writer turns a fatal bug into a cosmetic one.** `catch { $summary =
 $null }` and `catch { Write-RunLog 'ERROR writing SUMMARY.md' }` both converted a hard failure into a
 degraded report that still exited and still looked finished. When the thing being caught is the
 *report itself*, the catch must escalate, not continue.
4. **An error message with no line number is not a diagnosis.** The stack named a line only because the
 exception was rethrown through a helper; the first two hypotheses (parameter binding, then StrictMode
 property access) were both wrong and both looked plausible. Reproducing the primitive in isolation -
 `@($L)` on a bare list, in a bare session - settled it in one command.

**Counted outcomes now go through a plain `foreach` with integer counters** in
`lib/Guard.psm1:Get-GuardedSummary`, which takes the list directly and reports anything it cannot
classify as `Unclassifiable` rather than aborting.
