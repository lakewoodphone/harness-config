**L3329 · A Windows path in any .properties file is silently mangled: backslash is an escape in java.util.Properties**

`android/local.properties` is read by Gradle through `java.util.Properties.load`, which treats a
backslash as an ESCAPE character. A Windows path written naturally is silently mangled:

 written: LPT_RELEASE_STORE_FILE=C:\Users\ezabz\.lpt-keys\lpt-release.jks
 read as: C:Usersezabz.lpt-keyslpt-release.jks

No error is raised by `load` - the value just arrives wrong. Write every path in any .properties
file with FORWARD slashes (`C:/Users/...`), or double every backslash. `android/local.properties.example`
already doubles them (`..\\keystore.jks`); that is why, not a typo.

Measured 2026-10-05 on ZABZ-YOGA, kf1005/android-signed: the first `assembleRelease` of the branch
refused with the mangled path in the message, because the new signing guard resolves the path and
checks it exists. Before that guard existed the same mistake produced an unsigned APK and a
successful build - the failure was invisible, which is the general shape of this trap.
