# L1936 — every defect was found by attempting the action, not by reasoning about it

## The record

Three rounds spent on ONE repair (F04, correcting a record's `sourcePath`). Each attempt to enable it
found a different defect, and none of them was in the part I kept fixing:

| round | defect | effect |
|---|---|---|
| 21 | `json.dumps(ensure_ascii=False)` rewrote `\u2014` escapes as literal characters | 28 intended corrections became a **226-file diff, 1,532 churn lines** |
| 21 | date prefix counted as a name token in the similarity test | **183** records qualified where the analysis said **28** |
| 22 | collision guard tested `by_case`, built later, so it missed stem-paired records | 4 duplicates survived into the "repairable" list |
| 23 | F04 read **C02's** rows while declaring `check: C14` | **208 proposals**, each targeting the record's own path |
| 23 | partial match ("1/4 tokens") treated as a pair | fired on a shared token like "asus" |
| 23 | backup created **before** the dry-run exit | a **dry run wrote 226 files**; untracked, so it survived two rounds |
| 23 | orphan-vs-orphan collision guard | **still not working**; 4 duplicate targets remain |

The part I kept fixing was the matcher. The matcher was never the only problem.

## The rules

1. **Enabling a write is its own step with its own evidence.** I held F04 for three rounds and was right
 to: each "just enable it now" was followed by a fresh defect. A fix that has been wrong three times in
 three different places has not earned a write.
2. **Verify a fix is reading the rows it declares.** The check name in a registry is a claim, not a
 guarantee. 208 proposals carrying the wrong payload came from trusting that field.
3. **A ratio stated in your own finding is a filter.** C14 printed "1/4 name tokens match" and the repair
 acted on it anyway. When a rule emits its own confidence, the consumer must read it.
4. **A dry run that writes anything is not a dry run.** Side effects must come after the apply check, and
 UNTRACKED files are invisible to `git status` — so litter from a dry run can survive for rounds while
 the tree looks clean. `find`/`ls` the directory, do not only read git.
5. **Count what you propose against what you measured.** 208 vs 11, and 183 vs 28, were both obvious from
 the numbers before any write. A proposal count far above the measured set IS the bug report — I read
 that number and applied anyway, twice.

## Why holding costs nothing

The diagnosis ships either way: C14 reports every case whose `sourcePath` is broken, with the breakdown
(208 unpaired, 33 collisions, 165 partial guesses) and the individual near-certain pairs. The corpus is
not harmed by the repair waiting one more round. **Partial delivery with an honest boundary beats either
withholding the finding or shipping the wrong write.**
