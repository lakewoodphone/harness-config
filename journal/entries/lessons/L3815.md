**L3815 · The OU product API silently ignores an unknown parameter and returns unfiltered rows**

The OU's product API **silently ignores an unknown query parameter and returns unfiltered results**.
Measured 2026-10-14, independently, twice in one session: `?searchTerm=Skippy`, `?searchTerm=RXBAR`,
`?searchTerm=ZZZZQQQ` and `?searchTerm=x` all returned **byte-identical** result sets — the same first page
starting at "1000 PESCADORES" and "100 Grand". The filter simply does not exist; nothing errors, nothing
warns, and `total` looks plausible.

Why this is a top-tier trap rather than a curiosity: a kashrut check is a **binary gate**. An agent that
queries `searchTerm=Chomps`, sees 25 rows come back, and glances at them will read a Pareve symbol and
report "Chomps is pareve". The real answer is that Chomps is **not kosher certified at all**. The failure
mode is not a missing answer, it is a **confident wrong confirmation on demand** — and it would have
happened in two separate subagent runs if neither had noticed.

The working calls (verified 2026-10-14):
- search: `https://productsearch-v2.oukosher.org/api/v1/product?query=<term>` and/or `?brandName=<term>`
- one record: `https://productsearch-v2.oukosher.org/api/v1/product/<agencyUniqueId>` returning
 `{"results":[{...}]}` — an object with a `results` array, not a bare array.

**The general rule, which is the real lesson:** when a filter is a string parameter, prove it filters
before you trust a result. Send a deliberately absurd value (`ZZZZQQQ`). If the response is identical to a
real query, you have no filter, and an empty result is not a negative — it is a refusal. Two independent
subagents caught this within hours of each other, which is the only reason it did not produce a wrong
kashrut claim about a product the owner would then buy.

Corroboration: journal L3776 (the OU search page's stale result table nearly caused the same class of
error) — the same API is unsafe to trust at two different layers, the UI table and the query filter. A
third layer is fine: the by-id endpoint returns exactly one record and can be trusted.

Also worth carrying: **a brand is not a kashrut status.** Within one brand the answer flips by SKU —
Justin's nut-butter *jars* are pareve and its *cups* are OU-D; Kinder — KIND nut bars are OU-D and KIND
Breakfast Protein is pareve; Orgain's plant shakes are pareve and its "Organic Nutrition Shake" is OU-D;
OWYN's cartons are plain OU and its bottles are OU-DE. Always resolve to the flavour and the package
format, and re-read the symbol on the carton actually bought.

Evidence: the runs above; personal-secretary-mvp/docs/personal/desk-food-2026-10-14.md §5 and its sources.
