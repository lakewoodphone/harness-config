**L3368 · A parameter added to the source is not a parameter the running system has - and the repair that matters is the monitor's truthfulness**

GOAL ROUND 15, and I made the mistake this lesson is about. To rehearse the offsite round trip WITHOUT polluting the production signal I added a REPO_SUFFIX override to company-offsite-backup.sh so a drill writes to its own restic repository. I edited the file in the repo. I did NOT redeploy it to Box 2, where the running ingest still had the hardcoded path. So the drill snapshot went into the PRODUCTION repo (company-offsite), exactly the pollution the override existed to prevent: company-offsite-status.sh would have reported a fresh offsite copy while the authoritative database had never been copied - a monitor telling the truth about a FILE and lying about the COMPANY. Caught by checking which repo actually held the snapshot instead of trusting the log line (which said 'company-offsite' because that string is hardcoded in the log call). REPAIR, in order: redeploy the fixed script; identify the stray snapshot BY ID and confirm it was mine (only snapshot, my stamp, created 2 minutes earlier); remove it with a guard that REFUSES unless the repo holds exactly that one snapshot; restic check -> no errors; then confirm the freshness monitor returned to 'CRITICAL: the company has NO offsite copy'. Then redo the drill into the drill repo and verify the split (drill 1, production 0). RULES: (a) editing a script is not deploying it - after any change, verify the RUNNING artifact (grep the deployed file for the new parameter); (b) when a monitor's truthfulness is at stake, repair the signal first and then re-verify the signal, because a false green is worse than the red it replaced; (c) remove a stray artifact by identity with a refusal guard, never by pattern.
