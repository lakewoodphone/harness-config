**L3678 · The customer-case sync SCHEMA is not a gate (306 of 413 records fail it) - the push tool's dry-run is; and write all six link homes in one pass**

**MEASURED 2026-10-12 on the lpt-hub clone (ZABZ-YOGA), while reviewing the Wilner SD card case.**

`docs/customer-operations/CUSTOMER_CASE_SYNC_RECORD.schema.json` **is not a working gate**: **306 of 413 sync records fail it**, mostly on ad-hoc keys that the schema already chose to keep closed (`workflow` is `additionalProperties: false` while 6 records carry `workflow.resolution`; `references` was deliberately relaxed for exactly this reason and still 90+ records carry extras). The Wilner record was invalid **before** I touched it and is invalid after, on `workflow.resolution`, whose text is the record's own resolution narrative - so **do not delete narration to satisfy the validator.** I left it standing and corrected the one sentence in it that had become false.

**What actually decides, per the skill and per measurement:**
- `python scripts/lpt-sync-to-production.py --push-only <basename>.json` (read-only) is the authoritative per-record verdict. For Wilner it answers **SKIP**: *"record already references live production order WO2608280002 ... creating another order for this case is the duplicate defect"*. `--dry-run-all` is the whole-directory form.
- **`--push-only` takes the record's BASENAME, not a path.** Passing a path resolved it a second time against the lpt-hub root and produced *"Sync record not found: ...\sync-records\..\lpt-hub\docs\..."* - a confusing error for a correct-looking argument.

**And the six-homes defect is not rare.** The Wilner record had `workflow.orderNumber` and `references.productionOrder` set, but `references.orderNumber`, `references.workOrderId` and `references.websiteOrder` were **all null** although the order had existed since 2026-08-28. Cause: the order was created with `lpt-write order create`, which writes nothing back, so the record is born unlinked in the homes the verifiers read. **When you touch a case, write all six homes in one pass and put an honest `linkedBy` on it so the next reader knows it was a hand backfill and not the push tool.**

**Also, while working a case on Windows: `lpt sql` cannot take a file and PowerShell eats the embedded double quotes,** so `"createdAt"` arrives as `createdat`. Use `to_jsonb(<table>)->>'createdAt'` instead of a quoted identifier - that is the whole fix, and it works for camelCase columns in both stores.
