**L12284 · A health check that simulates from the NEXT run's window reports not-yet-due work as missing**

**A health check that simulates from the NEXT run's window reports work that is not yet due as missing.**

`verify-shabbat.sh` compared the plug's on-device schedule against one `wanted` set, computed from
`now + 1 day` at 10:00, and used it for BOTH directions — "nothing missing" and "nothing stale".
The programmer only creates jobs for blocks inside ITS window: today's 10:00 run had window end
2026-11-05, tomorrow's has 2026-11-06. So the check demanded the 7 Nov power-on job a day before
the run that writes it, and printed `FAIL no schedule drift (nothing missing) 27 18 7 11 *` on a
plug that was exactly right.

Measured 2026-10-22, same live state, only the check changed: before `1 CHECK(S) FAILED`, after
`ALL CHECKS PASSED`. The raw values that settle it, printed from the same functions:

 NOW 2026-10-22 18:18 EDT window_end 2026-11-05
 block 2026-10-24 | OFF 2026-10-23 13:05 | ON 2026-10-24 19:44
 block 2026-10-31 | OFF 2026-10-30 12:56 | ON 2026-10-31 19:35
 TOMORROW 10:00 2026-10-23 10:00 EDT window_end 2026-11-06
 ... plus block 2026-11-07 | OFF 2026-11-06 11:48 | ON 2026-11-07 18:27

**The rule.** Two questions have two windows. "Is anything missing?" must be judged against the
window of the run that should already have written it (the last 10:00 local, not tomorrow's);
"is anything stale?" against the window of the run that will prune it next (a superset). One set
cannot answer both, and the day the two windows disagree the check cries wolf.

**Why it matters more than a cosmetic FAIL.** The whole value of this automation's health check is
that a FAIL is believed. This estate has already paid for the opposite: an alarm nobody reads
because it fires on a schedule, and a `SILENCE`-shaped check read as health. A check that fails
once a week by construction teaches every future session to explain the FAIL away — including the
one time it is real.

Written the same night the drift appeared, so the next session does not "fix" the plug to satisfy
a broken check.
