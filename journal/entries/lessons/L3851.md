**L3851 · Phase 1 on a Kyocera E4810 = the stage script; plus three measured traps (execution policy, broken plan-install, the correct uncommitted e4810.yaml)**

What the owner means by "phase 1" on a Kyocera, settled from lpt-flip-phone/AGENTS.md and the repo itself (2026-10-18):

- phase 1 = STAGED DEPLOY = scripts/deployment/quick-deploy.ps1. For an E4810 it is `scripts/deployment/stage-e4810-standard.ps1 -DeviceSerial <serial>`, which calls `python -m lpt.cli deploy --model E4810 --tier standard --serial <s> --stage-only --fast-stage`.
- phase 2 = FINALIZE = scripts/deployment/finalize-deploy.ps1; for E4810 `finalize-e4810-standard.ps1 -DeviceSerial <s> -VoiceAccessVerified -RecoveryVerified`.
- Between them are four manual checks the stage script prints: Voice Access activation button/notification off, `open-matvt.ps1` then MatVT Override Activation Key = 17, LP&T Tech Mode recovery visible, right-soft from stock home opens the messaging app.
- There is NO one-command E4810 wrapper. `ready-e4610.ps1` exists for E4610 only; do not pretend it covers E4810.

Three measured facts that will bite at the bench:
1. Windows on ZABZ-TECH blocks these .ps1 files ("not digitally signed"). Run them with `pwsh -NoProfile -ExecutionPolicy Bypass -File <script>` or the run dies before touching a phone.
2. `lpt plan-install` and `lpt generate-install` are BROKEN in main: both crash with AttributeError 'ResolvedConfig' object has no attribute 'visible_user_app_slugs' (cli/lpt/config/intent.py:382, install_bundle.py:47; the field is absent from the dataclass at loader.py:69). All 5 tests in cli/tests/test_install_intent.py fail, including the E4810 one. The `deploy` path does NOT touch this code, so phase 1 is unaffected - but the offline preview is dead, and a device-free dry run is impossible because `deploy --dry-run` still resolves the model over adb.
3. Working tree of lpt-flip-phone carries an UNCOMMITTED 5-line change in cli/configs/devices/e4810.yaml (and e4811.yaml) that flips sms_app + home_message from Message+ (com.verizon.messaging.vzmsgs) to stock com.android.mms. That change is CORRECT: docs/E4810_MESSAGING_SYSTEM_RUNBOOK.md and docs/deployment/E4810_E4610_STANDARD_OPTIONS_REFERENCE.md both make stock com.android.mms the production default since the owner's 2026-09-09 decision. The stale lines are the docs that still say Message+ is preferred (DEPLOYMENT_SCRIPTS_GUIDE.md:68, devices/README.md:118, and the banner printed by stage-e4810-standard.ps1 itself). Deploy with the tree as it stands; do not "fix" it back. Also open: tiers/standard.yaml still lists message-plus under infrastructure, so whether Message+ is actually installed as hidden infra on this E4810 has to be READ BACK from the phone after staging, not assumed from either doc.
