**L2607 · lpt/cf-hub: no-deletion checks vs a moving origin/test, a probe that emulated a shell, and CRLF test files**

Title: a no-deletion check, a probe that emulated a shell, and CRLF test files

1. **`git diff --diff-filter=D --name-only origin/test HEAD` is not a valid no-deletion
 check when other worktrees share the repo.** Measured 2026-09-25: `origin/test` moved
 from 6377943ac to 73ffc148 mid-session because another worktree ran `git fetch` in the
 SHARED `.git`; the same diff then reported 14 "deletions" that were additions on `test`.
 Diff against the branch point (`git merge-base <base> HEAD`) and say which base you used.
 Symptom to recognise: deletions in directories you never opened.

2. **A measurement harness that emulates an application shell must be re-verified against
 the real shell, or it lies quietly.** The hub layout probe reproduced the staff sidebar
 (`100vw - 256px`) but omitted the `p-6` that `MVPLayout.tsx` puts on `<main>`, so every
 number it produced was 48px too wide per viewport — and it is what `__probe__/reports/`
 had recorded as "BEFORE". After adding the padding it reproduced the persona walk
 exactly (1280 / 800 / 720 at 1920 / 1440 / 1024). A probe whose output differs from the
 walk it exists to reproduce is a bug in the probe, not a finding about the app.

3. **"The page does not use the width" can be 100% shell chrome and 0% page.** Arithmetic
 that reconciles every measurement is the proof: 1920 - 1280 = 640 = 256 sidebar
 + 48 padding + 336 panel(gap included), and 1024 - 720 = 304 = sidebar + padding with
 `xl` inactive. Before writing a width fix, subtract the shell and check the page is not
 already filling what it is given.

4. **Test files in phone-and-tech-full are CRLF.** A scripted multi-line edit with `\n`
 anchors matches 0 times; single-line anchors appear to work and leave MIXED line
 endings. Detect the EOL, edit in LF space, write back with the original EOL, and have
 every anchor assert its occurrence count so a silent no-op is impossible.

5. **jsdom has no layout and no visibility.** Unmounting is the only way to reduce a
 jsdom-visible control count; CSS-hiding leaves the elements queryable, and `user-event`
 then refuses to type into them because it does check visibility. When a suite reaches
 for a field that moved behind an affordance, the fix is a guarded
 `if (aria-expanded === 'false') click` in the render helper — one line per file, no
 assertion weakened. `@/test-utils` re-exports all of `@testing-library/react`, so
 `fireEvent` is importable from it.
