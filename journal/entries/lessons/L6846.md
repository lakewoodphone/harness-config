**L6846 · To prove a cron job you must run the crontab LINE, not the payload - cron strips five fields and changes the shell**

Measured 2026-10-16 on secratary-cloud. Three jobs installed today each had exactly one run recorded, mine, and I had run them as 'cron-wrap.sh <name> <base64 payload>' - which proves the payload and NOT the schedule. Cron strips the five schedule fields and runs the rest through /bin/sh with a minimal environment; none of that path had been exercised, and this is the same estate where four 'scheduled' finance jobs had never completed a single run. The procedure that proves it without waiting for the clock: take the literal crontab line, cut its first five fields, and run the remainder under 'env -i HOME=/root PATH=... SHELL=/bin/sh /bin/sh -c'. Done that way: cfo-balance-capture rc=0 and balances-live.json restamped, finance-reconcile rc=0, cfo-statements rc=0 with statements-latest.md restamped AND pnl-categories.json restamped - that last one proves the chained generator added earlier in the day actually executes inside the scheduled payload, which a payload-level test cannot show. My first attempt passed the whole line including the schedule fields and returned rc=127 '12: not found': a non-zero exit that meant my TEST was wrong, not the job. General rules: the schedule and the command are two different things to verify, and a minimal environment is part of the command's contract - HOME, PATH and SHELL are inputs, not ambient facts.
