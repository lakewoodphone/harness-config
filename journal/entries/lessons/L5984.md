**L5984 · A check that cannot see the other tree will always answer 0 errors: measured 0 vs 524**

**A check that cannot see the other tree will always answer 0 errors**

`journal.py check` already had a duplicate-id rule: group the entries by `(kind, id_full)` and raise
an ERROR when one id carries two different bodies. It is **intra-tree**, and that is the whole
reason a forked journal looks healthy — a tree cannot collide with itself.

**Measured 2026-10-16, against nine real source trees** (a COPY of the canonical journal, so the
live tree was not touched):

```
shipped tool, no option -- 0 error(s) exit 0
with --cross-tree /root/work/r8/trees -- 524 error(s) exit 1
 ERROR cross-tree id D200 in decisions carries a different body in hcd
 ERROR cross-tree id H3576 in handoff carries a different body in hcd
 ...
```

That is the shape of the defect in one pair of numbers. `D3034` means *"the shop's money & customer
tracking survives long-term"* on ZABZ-YOGA and on the authority, and *"Weitman SD copy route"* on
ZABZ-TECH; a `resolve D3034` run on either side closes the wrong decision and raises nothing. Rounds
4-6 measured 363 ids carrying two or three different bodies across five trees, and every one of them
sat inside a tree whose own `check` said 0 errors.

**The option is added to `check` as `--cross-tree DIR`**: DIR holds one subdirectory per journal
tree, each with `entries/` or `journal/entries`. Three design choices, each because the alternative
is a check that lies:

* **OFF by default.** An offline machine must still be checkable, and a session that never passes the
 flag must not be told anything changed.
* **A DIR holding no readable journal tree is an ERROR, not silence.** "I compared nothing" and "I
 compared and they agree" are different sentences; a check that cannot see the other trees must say
 so. (`exit 4` semantics, applied here: nothing was searched is not a negative.)
* **It compares BODIES** (`e["hash"]`, the entry's own identity), not file bytes or file names, so a
 renumbering does not read as a collision — the same definition the union's acceptance gate uses.

**One implementation trap, paid for immediately:** the first version assigned `JOURNAL` inside
`cmd_check` to re-point it at each tree, which makes Python treat `JOURNAL` as a **local** for the
whole function — the first read, the lock path, raised `UnboundLocalError`. A `global JOURNAL`
declaration at the top of the function is the fix. It was caught by running `check` with no flag at
all, which is why "the default path is unchanged" is tested first and not assumed.

**NOT DEPLOYED TO THE OTHER TREES, and that is deliberate.** The estate ships **four different
`journal.py` versions** — ZABZ-YOGA `47fbf32b`, cloud `f6a7a014`, tech=linux `87737e66`, mac
`9b0e020b` — so writing this into all four by hand would be a fifth variant of a tool whose whole
problem is that there are four. Deploying it IS the pin-one-journal.py decision, and it belongs with
the cutover. Until then the rule is available to any tree that runs this file.
