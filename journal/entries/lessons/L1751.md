**L1751 · phone-and-tech-full: 16-error lint baseline, dangling node_modules junction, transposed branch names**

Durable facts earned on `phone-and-tech-full` (ZABZ-YOGA, 2026-09-16), T1 hours-audit.

## 1. The frontend lint baseline is 16 errors / 5 warnings — do not chase it

`cd frontend && pnpm exec eslint src --ext ts,tsx` on a cold cache reports
`✖ 21 problems (16 errors, 5 warnings)` and exits 1. This is **pre-existing on
`origin/test`** and is why the CI job "Lint Frontend" fails on every PR, which in
turn makes "PR Pre-Check Summary" and "CI Validation (PR Pre-Check)" fail and the
**test shards get SKIPPED** (the summary job is a fail-fast gate). CI therefore
never runs the test suite on a normal PR.

The 9 offending files, each xN errors:
CompleteAccountCard.tsx(1), CreateWorkOrderOrderSummary.tsx(1),
CustomerAuthContext.tsx(2), CustomerPortalAccess.tsx(3), CustomerSettings.tsx(2),
GoogleSignInCard.tsx(1), MVPLayout.tsx(2), SearchBar.tsx(1), trpc.ts(3).

Cheapest proof that a failure is pre-existing, without a second full run: if the
failing files are untouched by the branch, their output cannot have changed.
`git diff --name-only origin/test...HEAD -- <those paths>` empty == pre-existing.

`Assess PR Risk Level` also fails on every PR for an unrelated reason:
`scripts/merge-queue/risk-calculator.mjs` dies with
`Not Found - https://docs.github.com/rest/pulls/pulls#get-a-pull-request`.
Do not read that failure as "your PR is risky".

## 2. A dangling `node_modules` junction silently breaks the whole frontend suite

Symptom: every frontend test file fails at *setup* with
`Error: Cannot find module '/@id/C:/.../frontend/vitest-canvas-mock'`,
`Test Files N failed (N)` and `Tests no tests` — ~16 s, no transform, no setup.
The `/@id/` prefix is Vite reporting an unresolvable dep.

Cause: `frontend/node_modules/vitest-canvas-mock` was a **junction** whose target
under root `node_modules/.pnpm` had vanished. `Test-Path` still returns True for a
dangling junction while `Get-ChildItem` says "Could not find a part of the path",
so `Test-Path` alone is not a health check.

Detect and fix:
```powershell
foreach ($d in @('node_modules','frontend/node_modules','backend/node_modules')) {
 $links = Get-ChildItem $d -Force | Where-Object { $_.LinkType -in @('Junction','SymbolicLink') }
 $broken = ($links | Where-Object { -not (Test-Path -LiteralPath $_.Target) }).Count
 "$d links=$($links.Count) DANGLING=$broken"
}
pnpm install --frozen-lockfile --prefer-offline # repaired it; DANGLING -> 0
```
On this box the repo is a **shared** working tree with other agents running
concurrently (I saw `package.json` gain `wrangler`, `pnpm-lock.yaml` +564 lines
and `reconciliation_plan.json` regenerate underneath me mid-session). A partial
install by another agent is the likely cause. `--frozen-lockfile` never adds
dependencies, so if `package.json` gains a dep it was not your install.

## 3. Distinguish an environment flake from a content change with a control run

Before trusting a "these tests fail because of my change" conclusion, re-run the
**identical command at unmodified HEAD**. Here the 3-file vitest subset failed
with the canvas-mock error both with the change swapped out *and* at unmodified
HEAD — proving the collection failure was environmental and the comparison
method, not the code, was at fault. I then widened the selection to
`src/components/landing src/pages/__tests__/HomePage.test.tsx src/features/communications/utils`,
which collects fine, and got a valid back-to-back comparison.

## 4. `phone-and-tech-full` branch names are transposed and will bite you

Local branch `fix/hours-walkin-20260916` tracks remote
`fix/walkin-hours-20260916` (**hours**-walkin vs **walkin**-hours) — and the
remote one is the PR head. `git push origin fix/hours-walkin-20260916` therefore
creates a **duplicate** remote branch instead of updating the PR. Always push with
the explicit refspec (`git push origin HEAD:refs/heads/<pr-head>`) or bare
`git push` (which follows `@{u}`), and check
`git ls-remote --heads origin | Select-String <name>` first.

## 5. Two files in this repo advertise hours that never existed

`frontend/index.html` hand-maintains a schema.org `openingHoursSpecification`
block (the copy crawlers read) separate from all visible copy; it had drifted to a
third, never-true schedule while the HTML around it was corrected. And
`backend/src/lib/business-hours.ts` is **dead code** (only its own test imports it)
whose `timezone: 'America/New_York'` is declared but never read — it uses
`now.getHours()`, i.e. container-local time, so reviving it in a UTC container
shifts the window by the UTC offset. Correcting visible copy is not enough; grep
the structured data and the seeders too.

## 6. The repo shifts its own file set under you

`docs/` and `.github/issues/` hold dated audits and decision records that still
quote the old hours. They are **records of what was observed/decided**, not
surfaces. Editing them to match today's truth falsifies the audit; the correct
move is a new entry that supersedes them. Same for already-applied Prisma
migrations — edit them and you break checksums; write a new forward migration.
