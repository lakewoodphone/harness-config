**L1577 · A bind-mounted single file in Docker is pinned to an inode - replacing it on the host changes nothing in the container**

Evidence (2026-09-15, waze-mdm-01): I added `handle_path /api/waze/*` to
/opt/waze-mdm/Caddyfile, validated it, reloaded Caddy, and the route still fell through
to the catch-all. Host file: 3652 B, md5 83e4a764, inode 259905. Container's
/etc/caddy/Caddyfile: 3185 B, md5 72364865, inode 259987. `install` (and `mv`, and
`sed -i`) create a NEW file, so the container kept serving the old inode. Writing in
place with `cat file > /opt/.../Caddyfile` also failed, because by then the host path
pointed at an inode the mount did not reference.

Rule: after editing a single file that is bind-mounted into a container, re-create the
container (`docker compose up -d --force-recreate <svc>` - a plain `up -d` prints
"Running" and does nothing) and then verify INSIDE the container:
 docker exec <c> md5sum /path/in/container vs md5sum /path/on/host
Corollary: `caddy validate` and a successful `caddy reload` prove nothing about which
file was read. This system has had Caddyfile edits that never took effect.
