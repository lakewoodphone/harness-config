**L2853 · PowerShell -match is case-insensitive, so a convergence check greping WOULD matched "would run <installer>" and could never go green**

-powerShell -match IS CASE-INSENSITIVE: a monitor greping for WOULD matched "would run <installer>" and could never go green.This is the same failure as a monitor that always alerts, and it is worse than silence, because it hides the one real signal.

Measured: autosync.ps1 verified convergence by running sync.py --dry-run a second time and failing the run
if the output matched 'WOULD'. sync.py prints "client plugins: would run install-client-plugins.ps1" and
"metrics sampler: would run Install-MetricsSampler.ps1 -Quiet" on EVERY run in both modes, because a dry run
cannot know whether an installer is already satisfied. -match ignores case, so 'would run' matched 'WOULD'
and the run reported "apply did NOT converge - a second run still reports pending changes" forever.

Numbers from this machine's own log before the fix: 290 occurrences of "apply did NOT converge" since
2026-09-16; 1112 attention against 403 clean verdicts. So ZABZ-TECH had TWO independent reasons to report
attention (this, and the blocker refusal in the same file), and the ONE true signal -- 56 commits of
configuration not arriving -- was indistinguishable from the noise. After -cmatch: the same machine at
85acb9a reports {"result":"clean","converged":true}.

RULES:
1. When matching a sentinel string, use -cmatch (case-sensitive) unless the producer documents case
 insensitivity. Check what the producer actually prints, in both modes.
2. A monitor must be able to report BOTH states on a healthy machine. If it cannot go green, it is not
 measuring what it claims. Ask of every assertion: which measured condition makes this FALSE?
3. When a run has two independent reasons to say "attention", fix the false one - otherwise the true one
 is invisible, which is precisely what a monitor exists to prevent.
