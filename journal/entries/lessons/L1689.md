**L1689 · A queue row whose premise was never tested is worse than no row: row 28 cost the owner two asks and hid 3 dead cameras**

MEASURED 2026-09-16, owner queue row 28, and its cost.
A row asked the owner to log into the Dahua NVR and report whether admin/Hello@1234 was accepted, on the theory that 40 minutes of 401s meant the password was wrong. It was never true. One command from the authority settles it: `curl -sk --digest -u admin:Hello@1234 'https://192.168.50.170/cgi-bin/magicBox.cgi?action=getDeviceType'` returns `type=N41C2P2` HTTP 200, and a wrong password returns `Invalid Authority!`. Home Assistant's custom `dahua` integration sends BASIC auth and gets 401. The row sat for two days, cost the owner attention twice, and the real consequence - 3 of 6 shop cameras `not_loaded` - was buried inside it as context.

RULES. (1) Before an owner row is filed, the premise must be tested by me, not asserted: if the row says "X is broken", I need a command and its output that shows X broken, and I should try the obvious falsification first. (2) A 401 is not a wrong password until the auth SCHEME has been matched to the device - digest vs basic is the first thing to check on any embedded device. (3) When a row contains a consequence that is worse than its question (here: dead cameras), the consequence is the work, and the question is usually void.
