**L7742 · The PIN rotation exists, rotates every three days, is announced to nobody — and the weekly one was deleted in the September dead-generation purge**

MEASURED 2026-10-18. The owner said the room codes were supposed to rotate every two weeks and be texted out. He was right that something was supposed to be doing it. Here is what is actually there.

**The only rotation in the estate** — `ha-config/config/automations/access_control.yaml` (`id: house_access_pin_auto_reset`, line ~1331):
```
trigger: platform: time, at: 03:15:00
condition: value_template: '{{ now().timetuple().tm_yday % 3 == 0 }}'
action: input_text.set_value -> input_text.phoenix_house_access_pin = '{{ range(1000, 10000) | random }}'
```
**Every third day of the year, at 3:15am, silently.** Confirmed live in the HA logbook: fired Sep 18, 24, 30, Oct 6, 9, 12, 15; the value moved 5780 -> 8614 between 8 and 18 October. No notification action. So anyone given that code finds it dead within 72 hours, and the owner is never told the new one.

**The weekly drop-off rotation does not exist.** `docs/AUTOMATIONS.md:45` still claims `drop_off_pin_auto_reset — Weekly drop-off PIN rotation`. `git grep drop_off_pin_auto_reset` finds it in exactly one place: `docs/DISPOSAL-PLAN-2026-09-11-dead-generations.md:110`, marked **"customer-access path, not running"**. No YAML defines it. It was removed in the Sept 11 dead-generation purge and never rebuilt.

**Nothing sends a code to anybody.** No automation, script or custom component in ha-config sends a PIN outbound. `phoenix_access_manager` is six files with no user database and no SMS path. The only notify target is `notify.mobile_app_zabz_waze` (the owner's own phone) and it reports PIN *use*, not PIN distribution. Twilio `sms_log` and Dialpad `dialpad_sms_cache` hold **no** message that ever carried a house or door code — searched 'code is', 'pin is', 'new code', 'new pin' and the two known values.

**Written decision that contradicts the plan**: `docs/DECISIONS.md:16` — "2025-12-15: Customers use one shared long-term PIN for the outside door; rotate manually as needed."

THE LESSON. A rotation with no announcement is worse than no rotation: it silently invalidates a credential that people are still using, and it produces exactly the owner's symptom — "it didn't rotate" — because from his side nothing ever arrived. Rotation and distribution are one mechanism; building half of it converts a working static code into a broken moving one.

SECOND LESSON, same session. `scripts/check.ps1` treats a yamllint ERROR as fatal and `deploy.ps1` calls it, so **five trailing blank lines at the end of access_control.yaml shut the deploy gate for the whole repo** — pre-existing, proven at HEAD~1. A lint gate with no allowlist and no owner is how a config repo stops being deployable and nobody notices, because the failure looks like a stuck script rather than a red gate.
