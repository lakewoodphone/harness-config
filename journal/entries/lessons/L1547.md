**L1547 · An environment's source tree is not the repository, and a false positive in analysis can be a true positive in production - measure what is DEPLOYED, not just what is committed**

**Evidence, 2026-09-15, PART-120.** Auditing auth guards, I ran a census of which tRPC procedures have no guard by parsing declarations in `backend/src/trpc/routers/*.ts`. I ran it against **`/opt/lpt/src` on the production host**. That checkout is **stale** — it does not contain commit `19f9481dc` (2026-08-31, "Part 028: protect print router"), which had already converted all ten `print` procedures to `protectedProcedure`.

Result: I reported **43** bare procedures across **8** routers. The authoritative answer is **28 across 6**. The extra 15 were the difference between a checkout and the repository.

**Two rules, and the second is the one that cost something.**

1. **An environment's source tree is not the repository.** A census, a coverage count, a "what exists" claim — none of it may be derived from whatever tree happens to sit next to the running service. Pin the revision and say which one: `git -C <worktree> rev-parse --short HEAD`, and read there. The production host's tree is edited by deploy scripts and hand-patches, so it drifts from the repo in both directions.

2. **A false positive in an analysis can be a true positive in production.** Here the census said "print is unguarded" and the repository said "print was guarded five weeks ago" — and **both were wrong about the thing that mattered**, because *production had never been rebuilt after the fix*. The deployed `dist` still served bare `procedure`: `print.checkStatus` and `print.getPrinters` returned HTTP 200 to an anonymous caller. So the correct question is not "is it guarded in the repo?" but **"what is deployed, and does it match the repo?"** Those are two different measurements and this incident needed both.

Corroborating lesson: **a subagent contradicted my record and was right.** It said the premise was stale, checked HEAD instead of the census, and cited the fixing commit. The correction came from the cheapest possible source — someone re-deriving a number I had asserted — so a census count is worth re-deriving the moment anyone disagrees with it, and "I measured this" is not a reason to skip the check.

Reproducible version committed at `docs/audits/account-audit/tools-census-repo.ps1`, which prints the revision it read.
