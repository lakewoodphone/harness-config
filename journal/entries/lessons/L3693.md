**L3693 · lpt-write can set an order's total (total set / payment set) - docs/writes.md documents only note and status**

`lpt-write --help` lists far more than `docs/writes.md` documents. The doc says "this is the write path: change a work order's status and append a note" and names two commands; the tool itself also has **total set**, **payment set**, **audit**, **vocab**, **probe**, **doctor**, **deploy**.

Measured 2026-10-12 on WO26081312596: the order carried total 75.00 while the governing charge and what the customer had been told in writing was 50. The doc gave no way to fix that, and the sync push tool cannot update a linked record (see the companion lesson), so the number would have been left wrong. `python bin/lpt-write total set --order K --amount N --reason "..."` fixed it, audited, with a read-back.

Rule: before concluding "the tool cannot do X", read the tool's own `--help`. A doc that under-describes a command set costs a wrong number left in production, and this is the second time in this repo that a doc and its tool disagreed (CUSTOMER-SMS-RUNBOOK.md told sessions to pass `--no-signature` until 2026-09-17).

Bonus from the same session: `total set` and the sync push tool write the same store through the same single writer (`app.services.website_db.update_order` with the ORDER_WRITABLE_FIELDS whitelist), so "one writer" is preserved — but `lpt-write` is the only one that leaves a ledger line.
