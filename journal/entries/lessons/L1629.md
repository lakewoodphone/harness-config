**L1629 · publicProcedure IS procedure: an alias counted as guarded hid 59 unauthenticated declarations, so the count was 79 not 20**

Evidence: backend/src/trpc/context.ts:620 is `export const publicProcedure = procedure`. The tree-level guard
test's BARE regex matched only the literal token `procedure`, while its GUARDED regex matched
`publicProcedure` - so a declaration written `x: publicProcedure.query(...)` was counted as GUARDED and
applied NO authentication. PART-066's census had reported "publicProcedure declared 0 times in router files".

Flipping the regex to treat publicProcedure as bare surfaced 59 previously-invisible declarations across 20
router files at once (catalog.router 15, status-workflow-config.router 5, services.router 5,
repair-job.router 4, motherboardSwap 3, laborTier 3, +14 more files). The true unauthenticated count is 79,
not 20. Every earlier part that said "20 unauthenticated declarations" understated by 59.

Two things made this findable, and both are the lesson:
1. An ALIAS is not a different thing. When you write a scanner over declarations, enumerate every name that
 resolves to the same builder, or the alias becomes a blind spot that reads as compliance.
2. The reassuring half only came from looking: all 52 distinct publicProcedure names are `.query(` - not one
 is a mutation. So the hidden surface is read-only. Three of them still expose pricing/settings/operational
 config without auth and are marked NOT REVIEWED.

RULE: a census is a claim about a PATTERN, not about the tree. Before quoting a count, prove the pattern
matches every spelling of the thing you are counting.

RULE (from the same change): my first attempt at the mutation check scanned router bodies for
prisma.<model>.update( and found NOTHING, because router procedures delegate to services and the write happens
elsewhere. What saved it was the test's own fail-closed assertion ("the scan found NO public writes at all,
which cannot be right for a set containing auth.register"). A detector whose empty result is indistinguishable
from health is worse than no detector. Always assert that the scan found SOMETHING it must find.
