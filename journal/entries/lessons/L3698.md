**L3698 · A check whose failure does not stop the next step is not a check - I pushed a sync record that did not parse, from the same command that validated it**

A check whose failure does not stop the next step is not a check. I pushed a sync record that did not parse, in the same command that validated it.

Measured 2026-10-12, `lpt-hub` commit a534bfe2e on `lg-old-phone-shwartz-2026-08-12.json`: I pasted an owner sentence into a JSON string with its double quotes intact — `("include owes 50 but we may not charge ...")`. The file stopped parsing entirely (`json.decoder.JSONDecodeError: Expecting ',' delimiter: line 71 column 1527`).

**The two defects, and only the second one cost anything:**

1. **Hand-edited JSON carries a quoting hazard from prose.** Every other quote in that record is single, and the two places where the same sentence appears used single quotes. One paragraph pasted a sentence in double quotes. Rule: an owner quote inside a JSON string uses single quotes or is escaped; keep every long prose field in this corpus on single quotes so a paste cannot break it.
2. **The validator was in the same command as the commit, and its failure changed nothing.** I ran the validator, printed its last three lines with `Select-Object -Last 3` — which is exactly where the traceback landed, so I saw it — and then ran `git add`/`git commit`/`git push` unconditionally. The check reported the truth and the pipeline ignored it.

**What to do instead.** Either gate it (`python validate.py || exit 1`) or run the check as its own step and read the exit status before touching git. The general form: never place a verification and the irreversible action it protects in one shell chain without an explicit guard. That applies to the production writers too — `lpt-write` is safe there because it refuses without `--apply`, which is a guard in the tool rather than in my command line.

**Cost when it does go wrong:** a record that no reader can open — the case index, `audit.py` and the push tool all fail closed on it, so the case looks missing, which is the failure mode this whole record system exists to prevent.
