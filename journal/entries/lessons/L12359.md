**L12359 · A config value in the wrong case is a silent no-op; read the tool's own status, not the registry**

A Windows config value written in the wrong letter-case silently does nothing, and the only honest read-back is the tool's own report.

Measured 2026-10-25 while recovering files from the customer laptop WO26102312771 (Dell Latitude 7430, service tag BVHV1T3). The 2026-10-22 session had reached the machine over WinRM and recorded the access step as done: `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\WSMAN\Client\TrustedHosts` = the laptop's IP. Every attempt in this session failed with the same 0x8009030e "destination machine must be added to TrustedHosts" message, and `winrm get winrm/config/client` printed `TrustedHosts` EMPTY - because the WinRM client reads `trusted_hosts` (lower case), which was blank. The registry even held both values, one populated and one empty.

Fix: `winrm set winrm/config/client '@{TrustedHosts="192.168.50.114"}'`. The proof that it took is that get command's output, never the registry value.

What transfers:
- A registry write that succeeds is not a setting that took. Read the component's own status command.
- When an error message names a cause the last session already "fixed", suspect the fix, not the message.
- Applies to every casing-sensitive config in this estate, and to any note that records a config change without recording the read-back.
