**L · A merged, green branch can still be a file that does not compile - run the whole pipeline, not just the suite.**

Measured 2026-09-20, ZABZ-YOGA, integrating eight fleet branches into the CFO books repo.

**The sequence, exactly.** Five branches were merged, each one verified by running its own suite first
(267 tests across them), then the merged suite was run (**270 passed**). Three more branches landed the
same way. Final merged suite, run three times: **485 passed, 17 skipped, 0 failed.** Green.

Then the pipeline was run end to end on the authority, and stage 9 of 9 failed:

```
File "books/report/cfo_report.py", line 515
 if k not in ("details",)], indent=2, default=str))
 ^
SyntaxError: closing parenthesis ']' does not match opening parenthesis '{' on line 514
```

A one-character typo, in a module that **no test imported**, in a package that **had no `__init__.py`**.
Two independent reasons the suite could not see it:

1. **A green suite only covers what it imports.** WS8's report module had no tests of its own (its child
 was killed at the 30-minute remote turn cap before it wrote any), so "the suite is green" said nothing
 whatsoever about `books/report/`. The manager merged on the strength of a suite that never loaded the
 code being merged.
2. **`pkgutil.walk_packages` cannot descend into a directory that is not a package.** With no
 `books/report/__init__.py`, Python still imports `books.report.cfo_report` as an *implicit namespace
 package* - which is why `python -m` got far enough to hit the SyntaxError - but every enumeration-based
 tool, including any test that walks the package, skips the whole directory. **A directory that imports
 by accident is a directory whose tests do not run.**

**The two fixes, and the one that generalises:**

- Fixed the typo; added `books/report/__init__.py`.
- Added `tests/test_modules_import.py`: it walks the package and **imports every module**, asserts the
 walker actually found the package (an empty result is a refusal, not health), asserts no `.py` file on
 disk is missing from the walk, and asserts every directory with a `__main__.py` is importable as a
 module. That is the generalisation: **for the cost of one import, the suite's claim now covers every
 file, including files written by a workstream that never wrote a test.**

**And a second instance of the same lesson, same session, one hour later.** Running the pipeline for real
then found three more defects that no test could have caught, because each needed the whole system:
a stale-balance fallback that led the owner-facing page with **-$59.06** and an instruction to fund an
account that held **$1,269.01**; a `TypeError` on the funding path (`age()` given a string `now`); and a
`db_path` passed both by name and through `**kwargs`. All three were on paths that only execute against a
real store with real data.

**The rule, stated so it transfers:**

> The suite is a *lower bound* on correctness, not a certificate. Before you call an integration done,
> run the **whole pipeline against real data**, end to end, and read every stage's output. Merging is not
> verifying, and green is not the same as working. If a module has no test of its own, the suite tells you
> nothing about it - so either it gets a test, or the *runner* gets a test that imports it.
