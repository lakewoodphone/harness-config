**L2375 · workflow() results are spilled and TRUNCATED at ~50 KB — children that must return a lot of text will be silently lost; make them write files**

Measured 2026-09-24 on ZABZ-YOGA. A 6-agent workflow() fan-out (norethindrone duration review) returned 252 KB; the tool result was cut and the spill file /tmp/dsh-spill-<session>/<id>-workflow.txt held only 50,222 bytes, so axes A3-A6 were gone — the runtime printed '… [truncated: 202202 more characters]' and no complete copy existed anywhere. Cost: 4 agents re-run to recover.

Fix, now the standing pattern for research fleets: give each child a FILE PATH and tell it to write its findings there as markdown, then return ONLY a summary under ~1200 characters in its final message. The file survives; the summary is what crosses the boundary. Also have the parent list the directory afterwards to prove the files exist (ls, not trust).

This applies to subagent_local too. It is why the four axis reports for the Aygestin question live in docs/wedding/aygestin-duration-research/ instead of only in a transcript.
