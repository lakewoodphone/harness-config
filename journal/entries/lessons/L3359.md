## L-new · Every mode of a search tool must be run before its help text is believed — `fa` had five defects, four silent

**Measured 2026-10-08 on `secratary`, first end-to-end exercise of the fast-search surface** (the
`fast-search` skill had been carried onto `main` in commit `4dd70dbb` but no mode had ever been run).

Five defects, all found by running the tool rather than reading it:

1. **`fa data <q>` was a STUB.** Advertised in the help, matched no branch, printed nothing, exited **0**.
 To a reading agent that is indistinguishable from "no such record" — the P66 failure class.
2. **`fa symbols` never matched anything.** ctags writes `name<TAB>file<TAB>pattern`, and the pattern
 (`\t$Q|\t$Q$`) required a tab *before* the name, so it returned zero hits for `create_task` while the
 live `fa symbol create_task` found it twice. A mode that always answers "nothing" is worse than absent.
3. **`ask` / `look` / `find` were advertised as "the three words to memorise" and were not modes.** Each
 fell through to a bare query, so `fa look database.py` ran a live **code** search for the literal
 string and returned nothing, exit 0.
4. **`index_age_s` was the index FILE mtime, not content freshness.** The authority's journal index read
 "29 minutes old" while its corpus stopped in September; `fa journal vahab` answered "no match" for a
 customer whose case was written that night. The tool now publishes `index_entries` and
 `covers_through` (newest entry date in the index) and no longer swallows `journal.py`'s own refusal
 through `2>/dev/null`.
5. **`--max-age` defaulted to 300 s against indexes rebuilt every 15 min** (path + ctags) and every
 30 min (comms), so every indexed answer was "stale" and every `fa files` silently fell back to a live
 scan (measured 973 ms; **40-51 ms** from the path index now). Same defect, second instance, in the
 MCP wrapper `data/tools/search.py`, which passed `--max-age 300` to `fa` on every call: **a freshness
 threshold shorter than the refresh interval is a false-alarm machine, and a banner that always fires
 teaches readers to ignore it.**

**Rule.** A zero-result answer and a not-searched answer must be different exit codes. `fa` now uses
0 = hits, 1 = no match (real negative), 3 = answered but possibly stale, 4 = nothing was searched,
5 = the index failed. Prove every new mode with a query that MUST hit, a query that MUST miss, and a
query run with the index deliberately absent.

Fixed in `/home/zabz/bin/find-anything` (bin.git `1b276b4`, `2274c28`), deployed to all four nodes
(`secratary`, `linux-pc`, `hetzner`, `lpt-apps-01`, md5 `8198912469d660cbfd0bad471014dfab`), re-verified
mode by mode. <!-- j2 tags=search,tools,fa,testing,provenance refs=P66,L3352 -->
