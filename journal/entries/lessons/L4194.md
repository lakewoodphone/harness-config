**L4194 · A status chosen for legibility is invisible to every filter that reads it: paused retries start empty**

**The company's biggest measured failure is invisible to its own retry, and the reason is a one-word enum.**

Measured and reproduced 2026-10-14 on the authority against `/root/work/r5-company` (which is byte-identical to the live `/opt/company` for the files in scope):

- A session that reads forever and never acts is closed by the reconnaissance budget at `app/autopilot.py:3489` with `status="paused"` — deliberately; the comment at `:3471` says `paused` "is this codebase's status for 'stopped by design'".
- The retry seed reads the previous attempt through one query filtered by `PRIOR_ATTEMPT_STATUSES = ("failed", "expired")` (`app/services/attempt_context.py:79`).
- **`paused` is not in that tuple.** So a read-storm attempt is invisible to its own retry: `build_attempt_context` finds nothing, emits the "no prior attempt" marker, and the new attempt starts empty and re-pays for every read the previous one already did.
- The give-up counter has the same hole: `app/database.py:9630` counts `status = 'failed'` only, so a task that keeps read-storming is not even counted toward the block.

That is the mechanism behind the round-4 measurement (238 tasks retried with 2+ attempts, 78 ever completed). **Every fixed retry path inherits; the one failure mode that dominates does not.**

**The general rule: when a status is chosen for a human-legible reason ("stopped by design"), check every consumer that filters on status.** A new enum value is not additive — it silently leaves every existing filter, and the filter is usually a tuple of strings far from the writer. Grep the *value*, not the concept.

**Not fixed.** This is analysis only; the fix is one tuple entry and a decision about whether a budget-paused attempt's context should be inherited with or without its "I was stopped" marker. It belongs to the next round's company work, and it should be measured before and after rather than assumed.
