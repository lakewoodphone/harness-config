**L3624 · A fleet's output is only as collectable as the contract you gave it: one file, one path, six lines back, hash checked**

**L (2026-10-12, secratary-cloud)** - I ran a 12-cluster research fleet (24 mesh agents) whose output was ~90% unreachable, and the cause was the brief, not the mesh. Then I re-ran it with a contract and got 12/12.

**What failed.** The first briefs said "write your document to a file" without naming a machine-safe path. Children were placed on Windows nodes (`zabz-tech`, `zabz-yoga-1`) where `/home/zabz/...` does not exist; several therefore wrote to `C:\home\zabz\phone\...` (a literal directory named `home` at the drive root) or nowhere, and their final message was a status line - "DONE. Brief written to C:\home\zabz\phone\clusterB\R2-zeno-and-supertasks.md" - pointing at a file that was never created. The verify stage then had no document to verify. Net: 24 agents, one verification report, and about eleven usable briefs recovered only by mining the mesh mailboxes' `outbox.jsonl` with a tolerant JSON parser (Windows paths inside JSON strings break `json.loads` - escape the stray backslashes, then parse).

**What worked.** The contract, verbatim in every brief:
1. Write the COMPLETE document to exactly one path, chosen per OS by the child: Windows `C:\Users\ezabz\fleet-drop\<ID>.md`, Linux/macOS `$HOME/fleet-drop/<ID>.md`. Create the directory. Write no other file.
2. Do NOT spawn subagents. Do NOT do any other task.
3. Reply with EXACTLY six lines and nothing else: `ID / HOSTNAME / OS / PATH / BYTES / SHA256`. No document text, no summary.
The parent then pulls from the named node with `scp -O` and checks bytes+sha256 against the child's own report. 9/9 research documents and 12/12 verifier reports landed this way; A, B, E and L hashes matched exactly.

**Two mechanisms worth reusing.** (a) Publish the inputs of a second pass to every node's drop directory (`scp -O -r final host:drop/`) and let children read locally, with a `ssh secratary-cloud "cat <path>"` fallback - no child ever needs a shared filesystem and no document passes through the parent's context. (b) Ask for the reply as six lines; the six lines are cheap, the documents are not. Routing 12 x 10 KB documents through a session's context twice (in, then out to disk) is the single most expensive way to move them.

**Pacing.** The mesh places roughly one child per 4-8 minutes with 1-2 concurrent across `zabz-tech`, `zabz-yoga-1` and `zabz-tech-linux`; a 12-agent fleet is a 45-90 minute wall-clock commitment. Size fleets accordingly, and put them in background jobs so the turn is not idled.

**Windows transport, needed every time:** plain `scp` and `sftp` to the laptops die with `Connection closed` (no working sftp subsystem under the default PowerShell shell). `scp -O` (legacy protocol) works in both directions, as does `ssh` for exec and `powershell -NoProfile -EncodedCommand <base64-utf16le>` for reliable remote PowerShell.
