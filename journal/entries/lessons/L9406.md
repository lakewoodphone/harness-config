**L9406 · Five checks of 'it works' that were all false in one repository: documented commands, interpreter shims, corrupted-state exceptions, TLS rej**

## Five checks of "it works" that were all false in the same repository

All measured 2026-10-19 in `kosher-filter-ai`. Each is a general trap, not a local bug.

1. **A documented command is a claim, not evidence — run it before you quote it.**
 `make docs-check` was named in `START-HERE.md`, `CONTRIBUTING.md`, two runbooks and `STATUS.md`,
 with a transcript of five `OK` lines beneath it. `make` is not installed on the host those documents
 were written on (`make --version` → "The term 'make' is not recognized", exit 1), and even where it
 exists `PYTHON ?= python` resolved to an interpreter without `pydantic` or `anyio`, so two of the
 five checkers aborted with `ModuleNotFoundError` before running a single assertion. **The set of
 commands a repository documents should be the set of commands someone has run today.** If you cannot
 paste the invocation and its output line, the command belongs in a draft, not in a start-here.

2. **`command -v python` succeeding is not `python` running.** Windows installs an *execution alias*
 for the Microsoft Store: `command -v python` resolves the shim, `exec python …` then fails with
 "Python was not found; run without arguments to install from the Microsoft Store". A pre-commit hook
 whose header promised "if Python cannot be found it allows the commit" therefore blocked **every**
 commit while claiming it would allow them. Prove an interpreter with `"$x" -c 'pass'` before trusting
 it: found ≠ runs, on every platform, and the failure is invisible in the exit code alone.

3. **A corrupted-state exception is not catchable by `catch (Exception)`.** A `FactAttribute`
 constructor in `windows/FilterService.Tests/DesktopDuplicationLiveTests.cs` P/Invoked DXGI, so it ran
 at xunit **discovery**, and an `AccessViolationException` terminated the test host before one test
 executed: the log said `Test Run Aborted … Test host process crashed`, and the suite was not red, it
 did not run. Native probes belong in a test body, never in an attribute constructor, and a
 `try/catch (Exception)` around P/Invoke is not a guard.

4. **A rejected TLS client certificate may surface as EOF, not as an exception.** Under TLS 1.3 the
 client's handshake can complete before the server's `certificate_unknown` alert arrives, so
 `wrap_socket` returns and the first `recv` yields `b""`. The test asserting `pytest.raises(...)` said
 DID NOT RAISE while the server *had* rejected the certificate — and on a slower day it passed for the
 opposite reason, because `ConnectionRefusedError` (a dead listener) was inside the accepted tuple.
 Assert rejection on the side that decides it: the server records the alert, and the application
 exchange must not complete. Then prove the assertion by making the server accept everything
 (`verify_mode = CERT_NONE`) and watching the test fail.

5. **A generated document must emit its own front-matter, or every regeneration breaks the checker.**
 `docs/config-reference.md` had been hand-patched to satisfy `check_docs_index.py` because its
 generator wrote a bare body. The moment anyone regenerated it — the correct action — the estate went
 red with `FM-MISSING`, leaving a choice between hand-editing a generated file (a fact with two owners)
 and never regenerating (drift). Generators own their metadata; a generated artefact that a checker
 validates must produce the keys the checker requires.

**The shape they share:** each was a surface asserting its own correctness — a document quoting a
command, a hook quoting a promise, an attribute quoting a probe, a test quoting a rejection, a generator
quoting a schema. None was verified against the thing it described, and in every case one execution of
the real thing would have shown it. When a claim and its evidence are written by the same hand in the
same pass, they agree for free and mean nothing.
