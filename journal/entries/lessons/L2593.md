**L2593 · Three measurement traps that each produced a confident wrong answer (timing coincidence, grep self-match, log-on-schedule)**

Three measurement traps, all hit in one night (2026-09-25/28) while chasing
"ZABZ-YOGA is slow". Each produced a confident wrong answer before it produced
a right one.

1. A NUMBER THAT AGREES WITH YOUR THEORY IS NOT EVIDENCE.
A probe that read all 837 session files in full finished in 6,437 ms; the
engine's own scan counter said 6,623 ms. That 3% agreement "confirmed" that the
engine reads whole files, and it went into a handoff as measured fact. It was
coincidence: the engine reads session HEADERS only (readFirstZstdLine,
dsh-session-persistence-jsonl/lib/index.js:3125) and the real cost is 263 ms for
the whole corpus. Two unrelated mechanisms happened to land in the same range.
RULE: agreement between two numbers is evidence only once the MECHANISM is
shown. Read the code path or reproduce it; do not infer it from a timing match.

2. GREPPING YOUR PROCESS TABLE FOR A PATTERN THAT IS IN YOUR OWN COMMAND LINE
 FINDS YOU.
`CommandLine -like '*bin.js web*'` reported a "second engine process" three
times. Every match was a child of the engine (ppid=21440) running MY OWN tool
call, whose script text contained the literal string being searched for. It
looked like the unsupported-two-engines-on-one-home scenario and was recorded as
an unexplained anomaly. RULE: when matching process command lines, exclude your
own process tree, or match something the target cannot share with you - e.g.
check which pid holds the listening port.

3. A LOG THAT IS RIGHT IS STILL A PILE IF IT IS WRITTEN ON A SCHEDULE.
The first version of engine-vitals appended an entry per pass whenever a
threshold was crossed. Loop lag above threshold is CHRONIC on a busy host (p95
2,879 ms with 14 agent loops), so that would append 288 entries a day - the exact
unbounded pile this repo already has 900 `health-*.log` files from. RULE: log on
CHANGE (restart, or a new warning signature) plus a slow restate, never per pass.
Verified after the fix: three identical passes wrote one entry; a changed
signature wrote the second.

Also fixed in the same folder: an installer that unregistered a scheduled task
BEFORE registering it. When the register then threw (a PowerShell -At parsing
bug), the machine was left with no task at all - a silent window in which the
instrument did not exist. Register with -Force: one step, no gap.
