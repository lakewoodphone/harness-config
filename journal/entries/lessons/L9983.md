**L9983 · The shop-bin photo catalog: where it actually runs on ZABZ-YOGA, and that photo bytes are not in git**

The shop-bin photo catalog lives in lpt-hub at `tools/parts-catalog`. On ZABZ-YOGA the main checkout
`C:\Users\ezabz\code\lpt-hub` sits on branch `docs/attention-sweep-20261014` (9e1dc9ae0) and does NOT
contain that directory, so a plain `Test-Path lpt-hub\tools\parts-catalog` returns False and the tool
looks absent. It is not absent: `git ls-tree -r --name-only origin/main -- tools/parts-catalog` lists
56 paths. Run it from a worktree of main instead --
`C:\Users\ezabz\code\_worktrees\parts-catalog`, created 2026-10-19 from origin/main be59f39c3.

Measured 2026-10-19, in that worktree: `python tools\lptparts.py status` gives 2026-10-10 = 22 items /
21 photos, 2026-10-11 = 0/0, 2026-10-18 = 0/0, TOTAL 22, exit 0. The photo DROP folder
`C:\Users\ezabz\Downloads\bin-photos` did not exist and was created; `weekly.py` reads it, or
`$LPT_BIN_PHOTO_DROP`, or `--from <zip|folder>`.

Photo BYTES are not in git. The worktree's 2026-10-10 has ledger.json, catalog.jsonl, prompts/ and
results/ but no `photos/` directory, and the authority's clone at `/home/zabz/phone/lpt-hub` is the
same. Consequence: an old batch can be re-reported but never re-read, because the evidence is gone.
A new batch must keep its own `photos/` beside its catalog and be committed with them, or the same
loss repeats next week.

The reading contract is fixed and lives in the generated `prompts/per-photo/*.prompt.txt`: one JSON
object per photo, vocabulary `category|subcategory|condition|confidence` closed, one file per photo
into `results/<stem>.json`. `apply` then validates; a result naming a photo absent from the ledger is
a refusal, not an empty catalog.

Fetching: `git -C lpt-hub fetch origin` works from ZABZ-YOGA (rc=0, origin/main be59f39c3
2026-10-19 14:41Z). There is no remote named `github` in the laptop clone -- that name exists only in
the authority's clone, and asking for it returns rc=128 with an access-rights message that reads like
a credential failure but is only a wrong remote name.
