**L1964 · Publishing a static page from ZABZ-TECH: Netlify is dead, GitHub Pages works, and the gh credential cannot delete repos**

Measured 2026-09-17 while publishing the Weinberg-whatsapp-status-link page. All of this was found by running things, not by reading docs.

1. NETLIFY IS UNUSABLE FROM THIS MACHINE. deploys fail 403 with 'Account credit usage exceeded - new deploys are blocked until credits are added'. This is account-level, so it affects EVERY Netlify deployment from this machine, not one project. There is a linked site papaya-palmier-5c4ba0 on the ableTelSolutions team. Adding credits is a money decision and therefore the owner's.

2. GITHUB PAGES IS THE FREE PATH AND IT WORKS. One command sequence: create repo (POST /user/repos), git push, POST /repos/{o}/{r}/pages with {'source':{'branch':'main','path':'/'}}, then POLL the URL. Verified end to end; second run is idempotent ('using existing repo', 'Pages was already enabled'). Add a .nojekyll file.

3. THE STORED GITHUB CREDENTIAL CANNOT DELETE REPOS. git credential fill for github.com returns username x-access-token and a token with scopes gist, read:org, repo, workflow. It authenticates to the API as lakewoodphone and CAN create/modify repos, but DELETE returns 403 'Must have admin rights to Repository' because x-accepted-oauth-scopes says delete_repo and the token lacks it. CONSEQUENCE: do not create throwaway repos to test a pipeline - you cannot clean them up. Publish to the real target name, or get a token with delete_repo. (I learned this the hard way: a test repo had to be privatized with Pages disabled instead of deleted.)

4. NETLIFY CLI GOTCHAS, each of which cost a wrong guess:
 - On Windows the npm shim is netlify.ps1, which subprocess/CreateProcess CANNOT start (no PATHEXT, no PowerShell). Use shutil.which('netlify'), which honours PATHEXT and returns netlify.CMD.
 -
etlify status exits NON-ZERO outside a linked folder EVEN WHEN LOGGED IN, so it is a useless auth probe and a false negative. Use
etlify sites:list.
 -
etlify sites:create prompts INTERACTIVELY for a Team; it cannot be scripted as-is. Its -a/--account-slug needs the team SLUG, not the display name - display 'ableTelSolutions' has slug 'zabz68', and guessing the display name returns 404.

5. LIVENESS CHECKS MUST ASSERT ON CONFIGURED CONTENT. My first check looked for the string 'wa.me/' in the served page. That string is present in the BLANK template's own JavaScript, so it would have reported a live unfilled page. Assert on the real phone digits instead. A check that can pass on the broken case is not a check.
