**L1729 · A new bundle in dsh.profile.bundles does NOT hot-mount; patchReload:live does not cover the bundle list**

Measured 2026-09-16 on an isolated engine (own DSH_HOME, port 3097), so nothing about the live engine was disturbed:

1. bundle absent -> `GET /healthz` 404;
2. add the package name to the RUNNING profile's `dsh.profile.bundles` and junction the package into its `node_modules`;
3. wait 8 s -> `GET /healthz` STILL 404, no side-effect directory, nothing in the log.

`patchReload: live` reloads the profile's own `cordis.patch.yml` (the user patch layer). It does NOT re-read the bundle list. So a new bundle — i.e. any new plugin package — costs one engine restart, and on this deployment that restart ends every live session.

Consequences worth acting on: (a) "install the plugin" and "activate the plugin" are two different steps and the second one is the expensive one; (b) a plugin addition should be batched with whatever other restart-requiring change is pending, not applied when it is finished; (c) editing a row inside an ALREADY-MOUNTED bundle is the cheap path and is worth preferring when the choice exists.
