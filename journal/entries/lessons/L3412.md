**L3412 · Three views of one fact: an optimistic value released into a stale read**

lpt-staff-kiosk /staff-intake, 2026-10-08. StaffWorkOrderDetailPanel rendered the status as pendingStatus ?? workOrders.getById.status. On a successful status change it did setPendingStatus(null) and nothing else, so the pill fell back to the CACHED pre-change row while onChanged() invalidated workOrders.getAll and the queue row moved to the new one. Symptom: success banner says the new status, pill and grid say the old one, in both directions. Fix: take the mutation's own return value (workOrders.updateStatus returns OrderWithRelations, the updated row) and utils.workOrders.getById.setData({id}, prev => ({...prev, ...confirmed})) BEFORE releasing the optimistic value. Do NOT hold the optimistic value open until a re-read - that is the same two-sources bug with a longer window. Evidence: new test in frontend/src/features/staff-intake/__tests__/StaffIntakePage.test.tsx (leaves the pill, the queue row and the banner saying the same status) fails on the pre-fix code at the pill assertion (Expected Out for pickup, Received In diagnosis) and on the queue-row assertion (Expected Out for pickup, Received In diagnosis); 129 passed with the fix.
