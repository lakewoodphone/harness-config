**L7294 · The kiosk's Stripe return URL is /kiosk and the page is mounted at /intake, so every card customer lands on the sign-in page holding no confirmation and the payment stays PENDING**

**L · The kiosk's Stripe `success_url` is `${publicUrl}` where `publicUrl` defaults to `FRONTEND_URL + '/kiosk'` — and the self-serve page is mounted at `/intake` and never was at `/kiosk`. Every card customer who pays is returned to a page that does not exist.**

Measured 2026-10-16, reported by the owner from his own live test ("after i paid it redirected to a 404").

**The writers of the return URL**, in order:

```
backend/src/services/kiosk-intake/kiosk-intake.service.ts:1255
 success_url: `${publicUrl}?${query}&payment=success`
backend/src/services/kiosk-intake/kiosk-intake.service.ts:363-369
 const explicit = (process.env.KIOSK_PUBLIC_URL || '').trim()
 if (explicit) return explicit.replace(/\/+$/, '')
 const frontend = (process.env.FRONTEND_URL || '').trim()
 if (frontend) return `${frontend.replace(/\/+$/, '')}/kiosk`
frontend/src/App.tsx (both origin/main and origin/test)
 <Route path="/intake" element={<KioskIntakePage />} />
 <Route path="*" element={<MVPRouter />} /> <- /kiosk falls through
frontend/src/routes/MVPRouter.tsx:658
 <Route path="*" element={<NotFoundPage />} />
```

`git log -S'path="/intake"' -- frontend/src/App.tsx` returns exactly one commit,
`da93b3172 feat(kiosk): self-serve intake page at /intake`. `git log -S'"/kiosk"' -- frontend/src`
returns **nothing**: the page was never mounted at `/kiosk`. So the backend's default has always
pointed at a path the frontend never served.

**Read live, logged out, this session** (Playwright, 2026-10-16):

```
GET https://lakewoodphoneandtech.com/intake
 -> 200, title "Start a repair | Lakewood Phone & Tech" <- the kiosk
GET https://lakewoodphoneandtech.com/kiosk?intake=<uuid>&ref=<ref>&payment=success
 -> lands on https://lakewoodphoneandtech.com/login?expired=true
 title "Staff Sign In | Lakewood Phone & Tech" <- not the kiosk, not even a 404
```

So the paying customer is dropped on a **staff sign-in page** (or, signed in as the owner was, on
`NotFoundPage`). Either way the kiosk page's whole post-payment block never runs: it cannot poll
`GET /api/kiosk/intake/:uuid/status`, cannot see `paid`, and cannot call
`POST /api/kiosk/intake/:uuid/submit` — which is the ONLY place `KioskIntakePayment.status` is
written to `PAID` (`kiosk-intake.service.ts:742`). The customer's card is charged and the work order
says "Not paid yet" **permanently**, exactly as the owner reported.

**Second finding, same read: nothing in the Stripe webhook reconciles a kiosk session.**
`grep -n 'kiosk|Kiosk|kioskIntake' backend/src/services/payments/webhook.service.ts` returns no
matches. The pay-before-pickup branch handles `checkout.session.completed` for its own flow only.
So a kiosk card payment depends entirely on the browser surviving the round trip — and the round
trip is broken. A webhook arm keyed on `session.metadata.kioskIntakeId` (which the create call
already sets, `:1252`) would make the payment independent of the browser.

**The cheap fix, and it needs no deploy of the API:** set `KIOSK_PUBLIC_URL` to
`https://lakewoodphoneandtech.com/intake` on the backend host. It is read before `FRONTEND_URL`
and used verbatim. **Better, because env is not durable:** add
`<Route path="/kiosk" element={<Navigate to="/intake" replace />} />` (or simply mount
`KioskIntakePage` at both paths) so the default resolves to a real page, and correct the
`FRONTEND_URL + '/kiosk'` fallback in the same commit. Fix both; the env alone leaves the landmine
for the next environment.
