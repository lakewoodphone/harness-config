## The 0.1.7 line REMOVED local preset directories: upgrading silently drops the agent's whole persona

MEASURED 2026-09-28 (ZABZ-TECH), by searching two real installs.

BASELINE `@deepseek-ai/dsh-agent-presets` (0.1.5) -- the mechanism this deployment depends on:
```
$ grep -rn '\.agent-presets' <npx install>/node_modules/@deepseek-ai --include=*.js
dsh-agent-presets/lib/types/discovery.js:48: export const USER_PRESET_DIR = '.agent-presets';
dsh-agent-presets/lib/invariant.js:194: const USER_PRESET_DIR = ".agent-presets";
dsh-agent-presets/lib/index.js:195: const USER_PRESET_DIR = ".agent-presets";
```
It discovers `$DSH_HOME/.agent-presets/**` with `readdir` and loads each `agent.cordis.yml`.

CANDIDATE `0.1.7-rc.2`:
```
$ grep -rn '\.agent-presets' <vendor>/0.1.7-rc.2/node_modules/@deepseek-ai --include=*.js
No matches found
$ grep -rn 'USER_PRESET|agent-presets|presetRoot|presetDir|customPreset|userPreset' ...
 only a UI section id "agent-presets" and an invariant name; no discovery at all
```
And the replacement package `@deepseek-ai/dsh-agent-preset-registry` contains **no `readdir` and no
`readFile`**; it exposes `async register(definition)` and takes preset definitions
**programmatically**. Presets on 0.1.7 are **composition rows**, not directories -- measured rows in
its own web composition:
```
id=preset-standard name=@deepseek-ai/dsh-agent-preset config={"id":"standard","order":1,"plugins":[...]}
id=preset-ptc ... order 2 ... id=preset-minimal ... order 3 ... id=preset-cordis ... order 4 ...
id=agent-preset-registry name=@deepseek-ai/dsh-agent-preset-registry config={"default":"standard"}
```

CONSEQUENCE, and why this is the headline rather than the two package renames: this deployment's
`settings.yaml` sets `agent-presets.default: zabz`, and `zabz` lives ONLY as a directory under
`~/.dsh/.agent-presets/`. On 0.1.7 that directory is never read, so `zabz` does not exist, sessions
fall back to a shipped preset, and the persona -- every owner rule, all the hardened behaviour --
is gone **with no error at all**. `yocheved` and `cordis-bg` likewise.

THE MIGRATION IS MECHANICAL, which is why this is tractable: the `plugins:` array of a
`preset-<id>` row is *exactly* the row list our `agent.cordis.yml` files already contain --
`{id, name, config, disabled, group, isolate}` maps including `cordis:group` groups with a nested
`config:` list. Our preset list becomes `config.plugins`. Row ids must be `preset-<name>` and
`order` must sort after the shipped 1-4.

HOW TO CHECK A VERSION FOR THIS BEFORE TRUSTING IT: grep the install for `.agent-presets`,
`USER_PRESET_DIR` and `readdir` inside the preset package. If the directory discovery is absent,
the config must be migrated, not merely renamed.

GENERALIZATION: a package RENAME is loud and cheap to fix; a change of MECHANISM is quiet and
expensive. `dsh-agent-presets` -> `dsh-agent-preset-registry` looked like a rename and was actually
a different way of declaring a preset.
