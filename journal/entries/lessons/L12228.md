**L12228 · Pay-notice audit: five transferable facts (trigger measurement, DEBUG=false, Zelle destination, container ESM, host quirks)**

Five transferable facts from the pay-notice audit (2026-10-21).

1. **Measure a trigger by the rows it wrote, not by the code that should write them.** The
 pay-notice loop was documented, tested and deployed, and had produced **zero** drafts from
 staff in nine days. The proof was one query - `select "createdByUserId", count(*) from
 pay_notice_drafts group by 1` -> `168 | 8`, machine account only - plus
 `order_status_history.changedBy` showing every recent transition to READY_FOR_PICKUP written as
 user **1** by `lpt-write` / the secretary reconciliation. That path never enters
 `workOrderService.updateStatus`, so the actor is absent and `draftPayNotice` returns early.
 Reading the fixed code would have said "works". The rows said otherwise.

2. **A production host with `DEBUG=false` makes every `debug.log`-only feature invisible.** Same
 container: 1650 `ERROR` lines in 240h, zero pay-notice lines of any severity. If a feature's
 whole diagnostic surface is `debug.log`, a dead feature leaves no trace and nobody can see it
 die. Check `printenv DEBUG` before concluding "it never ran".

3. **The Zelle destination is `payments@lakewoodphoneandtech.com`, never the business line.** Three
 values lived in code: `BRAND_CONTACT.PHONE` (printed by the owe-notice composer),
 `BRAND_CONTACT.EMAIL` (`info@`, used by `ZellePaymentFlow`), and the real one. Settled by three
 independent readings: 503 outbound texts carry the address and **zero** carry a number;
 `payment_pages.zelleEmail` on the live page the message links to is the address with
 `zellePhone null`; `.env.production.template` records it as the enrolled destination ("Set
 2026-10-07 (owner)"). **The page's own column is the tie-breaker** when constants disagree.

4. **`docker exec -i <container> node --input-type=module -` runs ESM inside a container from
 stdin.** Verified on `lpt-backend`: absolute `import('/app/backend/dist/...')` works, no
 `docker cp`, no temp file, no rebuild. This is the clean way to call a deployed service function
 once from a shell - and it is what `lpt-pay-notice` now does.

5. **Two host quirks that cost this session three failed calls.** BusyBox `grep` inside
 `lpt-backend` has **no `--include`** (it errors, and with stderr swallowed the search looks
 empty); and PowerShell has **no `<` input redirect** (`The '<' operator is reserved`). Both are
 solved the same way: write the script to a file and `scp` it.
