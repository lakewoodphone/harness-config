**L6172 · The psmvp venv Python can only write inside media-inbox - other paths need C:\Python313\python.exe**

**Measured 2026-10-13, ZABZ-TECH, by writing a probe file to five directories from each interpreter.**

`C:\Users\ezabz\Code\personal-secretary-mvp\.venv\Scripts\python.exe` can **only write inside
`C:\Users\ezabz\Code\media-inbox`**. Every other path tested was denied with
`PermissionError: [Errno 13]`:

| path | psmvp venv python | C:\Python313 python |
|---|---|---|
| `Code\media-inbox` | OK | OK |
| `Code\_tmp\shlock-t2\src` | **denied** | OK |
| `Code\_scratch` | **denied** | OK |
| `Code\_worktrees\shlock-register\_scratch` | **denied** | OK |
| `Downloads` | **denied** | OK |

Both run as the same user; both are ordinary `python.exe` files (255,320 B and 105,816 B, no reparse
point). The only asymmetry found is the interpreter path, and `icacls media-inbox` carries a
`(CI)(DENY)(DC)` ACE for `Everyone` that the other paths do not — consistent with a sandbox marker, not
with a normal ACL. **The mechanism is not explained; the behaviour is reproducible.**

**The rule.** A Python job that must write outside `media-inbox` runs on `C:\Python313\python.exe`.
This cost real time twice in one session — once as a confusing `PermissionError` from Pillow inside a
tool that had just passed its own selftest, and once on a scratch write probe. Diagnostic one-liner
before blaming the code: try creating a file in the target directory from both interpreters.
