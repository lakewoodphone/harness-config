**L2356 · PowerShell eats dollar amounts before the program sees them - use a file, never an inline argument**

PowerShell expands `$name` inside DOUBLE QUOTES before the program ever sees it. An
unset variable expands to nothing, so the text arrives silently incomplete - no error,
no warning, exit 0. Anything that carries a dollar amount is at risk.

MEASURED THIS SESSION (2026-09-22, ZABZ-TECH), two separate hits in one afternoon:
1. `git commit -m "... Option 2 ($500 Latitude 7430) ..."` produced a subject reading
 "Option 2 ( Latitude 7430)". `$500` vanished. Fixed by amending with `-F <file>`.
2. `journal.py append handoff --title "Weitman laptop: she chose the \$500 option ..."`
 filed H2409 with the title "she chose the \ option". The backslash is NOT an escape in
 PowerShell - the escape is a backtick - so `\$500` passed a literal backslash and then
 expanded the empty `$500`.
The same trap is already visible in the repo: lpt-hub/_scratch contains
`fix-rosenberg-dollar-escape.py`, a session that had to repair a case file afterwards.

THE RULE:
- `$`-bearing text NEVER goes inline on a PowerShell command line. Not in `-m`, not in
 `--title`, not in `--body`, not in `--message`. Write it to a file and pass the file:
 `git commit -F msg.txt`, `journal.py append ... --body-file body.txt`.
- Where a tool has no file option (journal `--title`), prefer a `$`-free title and let the
 body carry the number, or escape with a BACKTICK (`` `$500 ``), never a backslash.
- Verify the artifact, not the command: read back `git log -1 --format=%s` and the entry
 heading. Both failures were invisible in the command's own output.
- This is the same family as the runbook's `--message` warning for customer SMS, which
 exists because a stripped `$155` once went out to a customer as a blank amount.

NOT CORRECTED IN PLACE: H2409's title stays as filed. The journal is append-only and an id
must never mean two different things, so the fix is this entry citing it, not an edit.
ANYTHING THAT NEEDS H2409 LATER SHOULD SEARCH "Weitman" OR "H2409", NOT "$500".
