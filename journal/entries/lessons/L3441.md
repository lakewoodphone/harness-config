**L3441 · Frontend bundle is not byte-reproducible across CRLF/LF checkouts; sha256 deploy checks must build from LF**

A Windows checkout cannot produce a byte-identical frontend bundle to the Linux deploy runner: Vite preserves CRLF inside source template literals, which changes the content hash of a lazy chunk (jspdf.es.min-*.js) and therefore the entry asset name.

Measured 2026-10-09 (this worktree): the same commit f6abb7ea2 and the same plan env gave index-C5Q8z10Q.js / 3843233 bytes / sha256 d65f84ae... on a CRLF checkout (core.autocrlf=true), and index-92AbkZkm.js / 3842999 bytes / sha256 7172d5cf... with core.autocrlf=false. The LF build is byte-identical (Buffer.equals=true) to what https://lakewoodphoneandtech.com/ actually serves.

So: any sha256 equality check between a deployed bundle and a local build must run from an LF checkout (the runner, or git config core.autocrlf false + re-checkout). Diffing the two showed exactly two differences: that chunk's name, and \r\n vs \n at one offset. scripts/deploy-frontend-cloudflare.mjs --build-only now warns when the checkout is CRLF.
