**L3370 · A monitor that can be silenced by an unrelated monitor is not a monitor: one shared rate-limit mark suppressed every other condition**

GOAL ROUND 16. The alerting layer had a defect that made the whole layer unreliable, and it was invisible in every test I had run because I always tested ONE condition at a time. company-heartbeat.sh kept a single mark file (.last-alert) written inside alert(), so ANY condition firing reset the rate limit for ALL of them: a company-down alert at 03:00 could suppress a 'the API key guard is not enforcing' alert for the next six hours. Five different conditions (down, up, loop-dead, api-guard, mute) shared one timer. FIX: alert() now takes a condition KEY (alert <key> <body>) and keeps a mark per key (.last-alert-<key>); every call site names its condition. VERIFIED BY BEHAVIOUR, not by reading the code: in one state dir, [offsite] fired at 05:39:57 and 18 seconds later [mute] ALSO fired (under the old code it would have been silent for six hours), while [offsite] correctly did not repeat - both halves matter, because independence without rate limiting would just be a louder alarm. AND THE GAP THIS ROUND ACTUALLY CLOSED: backup-status-check.sh has carried 'wire into alerting so staleness is never silent' in its own header since it was written, and nobody ever did - cron ran it hourly into a log file. company-offsite-status.sh was the same: it recorded, perfectly, that the company has NO offsite copy anywhere, and told no one. Both are now conditions that send a text. RULES: (a) test alerting with MORE THAN ONE condition true, because the failure mode is interaction, not individual logic; (b) a monitor must be able to fire while another monitor is firing - per-condition state, never a shared timer; (c) when a script's own header says it must be wired somewhere, check that it actually is, because a script that documents its own integration gap is a gap with a receipt; (d) the residual is now written down rather than implied: nobody watches the watcher, and the alert channel itself is one Twilio number whose failures go only to a log.
