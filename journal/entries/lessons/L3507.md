**L3507 · On the 0.1.7 line, presets/*/agent.cordis.yml is INERT - the preset-rows block in profiles/web/cordis.patch.yml is what mounts**

**WHAT.** On the DSH 0.1.7 composition line, `presets/<name>/agent.cordis.yml` is NOT read. Local
preset-directory discovery was removed -- a preset is a ROW now, and the rows that actually mount come
from the `preset-rows` managed block inside `profiles/web/cordis.patch.yml`, generated from the preset
file by `node scripts/make-preset-rows.mjs --install`. `~/.dsh/.agent-presets/<name>/agent.cordis.yml`
still sits on disk and still looks authoritative; it is inert.

**EVIDENCE, 2026-10-11.** I retargeted `presets/zabz/agent.cordis.yml` from `secratary-ts` to
`secratary-cloud`, copied it into `/root/.dsh/.agent-presets/zabz/` on the authority (sha256 verified
identical), restarted the owner's phone engine at 20:19Z -- and the engine spawned
`ssh -T ... secratary-ts /home/zabz/personal-secretary-mvp/.venv/bin/python .../ps_mcp_server.py`, the
OLD row, with the OLD `/home/zabz` paths. Two independent signals in one process list: the target host
and the interpreter path both came from the patch, not from the file I had just written.

**WHAT TO DO.** Edit the preset, then run `make-preset-rows.mjs --install`, then get the resulting block
into the LIVE `$DSH_HOME/profiles/web/cordis.patch.yml`, then verify the LIVE FILE (`grep` it for the
value you changed) -- never the preset. The comment block above the managed block says all of this; I
read the file and did not read the comment.

**SECOND TRAP, SAME FILE.** The live web patch's managed block is a BLOCK sequence (`- {\n insert:\n ... }`)
while the generator writes a FLOW sequence (`[ { ... } ]`), so
`--install --install-target <live>` REFUSES: "the lines between the markers do not parse as a flow
sequence of patch entries". Correcting the live file then means either the dsh-update staging run or a
targeted line substitution inside the block. Say which one you did.

**THIRD TRAP.** `--check` compares the REPO's patch to the presets. It does not look at the live file.
A green `--check` says nothing about what the engine will mount.
