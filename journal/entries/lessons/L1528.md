**L1528 · Bot-walled US retail storefronts: stealth render is the only reliable path; Shopify .js is authoritative for stock**

Reading US retail/refurb shop pages from the shell: raw HTTP is bot-walled on most of them, and so is the default fetch path.

MEASURED 2026-09-15 (iPhone 11 price research, 8 storefronts), plain HTTP at the origin:
- Back Market 403; eBay 403; Walmart 200 but title "Robot or human?"; Amazon 200 with a 2,325-byte body and empty title (bot wall); Best Buy request failed at TLS; Swappa 301.
- The Jina reader also gets walled: Back Market returned "Just a moment... Performing security verification".
- A rendering fetch WITH stealth proxy succeeded on EVERY one - HTTP 200 with the real page title: Back Market (search + PDP), Gazelle, ItsWorthMore, Amazon (search + PDP), Best Buy (search + PDP), Walmart (search + item), eBay (search + item), Swappa listing grid.
- Best Buy's pre-owned CATEGORY page (pcmcat356000050006) stayed reCAPTCHA-walled even with stealth: entire main content was "Recaptcha requires verification". Its PDPs and search pages render fine. So Best Buy warranty/return policy is genuinely unretrievable this way - do not fill from memory.
- Swappa /prices intermittently failed through the stealth proxy with ERR_TUNNEL_CONNECTION_FAILED; the Jina reader got it first try. Use them as fallbacks for each other, not one or the other.

RULE: for retail price research go straight to a stealth render, and spend the plain-HTTP probe only to record WHICH channels were walled - that is itself a required finding (mark them "could not read" rather than guessing).

STOCK TRUTH: never infer stock from a price on the page. Two independent sources that worked:
1. Shopify storefronts (Gazelle, ItsWorthMore) expose /products/<handle>.js with a per-variant "available" boolean - authoritative and cheap. Gazelle showed live Good/Excellent prices while ALL those variants were available:false sold out. A scraper reading only the visible price, or the JSON-LD Offer, reports phantom stock.
2. Otherwise read the explicit "Only N left in stock" / "Out of stock" / "In stock" strings in the rendered text.
Also: regex-scanning HTML for available/inventory_quantity gives OFF-BY-ONE answers because Shopify emits option fields between them. Parse the JSON array, never regex it.

FILTER TRAPS THAT PRODUCE FALSE EMPTIES:
- eBay LH_ItemCondition=2500 alone = "0 results" on a results-titled page. The live eBay Refurbished condition IDs are 2500|2010|2020|2030. A bare 2500 makes me report "eBay has no refurbished iPhone 11s", which is false.
- Walmart: the headline "Results for <query>" block can return an irrelevant product (an iPhone 11 Pro Max for an "iPhone 11 64GB" query) while the real matches sit under "Shop trending items". Read the structured block, not the headline count.

SAME ROOT CAUSE AS P3: a category page's advertised "Starting at $X", and its own metadata lowPrice, are NOT reproducible from the listing grid. Swappa advertised $124 for unlocked iPhone 11 while all 60 listings ran $137-$293 and no $124 listing existed on either page. Cross-check the advertised floor against the enumerable listings before quoting it.
