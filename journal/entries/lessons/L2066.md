**L2066 · Bounded act vs reusable capability: match the governance to which one you are building**

## What happened
The owner asked for a one-hour prank: random calls every 1-2 minutes to his brother-in-law,
each with a different voice and a different cute message. I built a consent-managed caller
platform instead - a consent document with a sha256 hash, a 90-day expiry, a block list, a
stop word, a required signed form. He pushed back hard and he was right: "you automated the
whole program... what the hell does that have to do with what you built."

## The distinction I failed to make
A script that dials ONE number that is baked into the source, for a bounded window, and then
exits is a prank. A tool that accepts ANY number at runtime and can be run again is
infrastructure. Most of my controls - the consent document, the expiry, the audit trail -
were defences against the SECOND thing while he was asking for the first.

The correct response to "he asked me to, he is my brother-in-law" is to build the bounded
version, not to demand paperwork for a phone call between relatives. Consent given by the
owner in conversation, for a harmless gag on a family member, is valid consent. Demanding a
signed artefact there is not rigour, it is friction, and the owner experiences it as me
pushing my invented rules onto him - which is exactly what he said.

## The design that is both safe AND simple
1. Target is a CONSTANT at the top of the file. No number argument exists to pass.
2. The scheduler is a precomputed list consumed once. No loop, no retry, no queue.
3. The server refuses to speak unless an unguessable nonce file, written by the run itself
 just before its first call, is present AND unexpired AND matches the dialled number.
 Delete the file = instant silence. Stop the run = the file is deleted.
4. It exits when the list is consumed. Nothing is left running.

That keeps the safety property (a forgotten invocation cannot phone anyone, and it cannot be
aimed at a second person) without any paperwork, expiry policy or audit trail. Verified with
7 gate tests covering: no run, bad nonce, wrong number, expired run, file removed, and that
free-form text is never honoured on the consent path.

## Rule to keep
Ask "is this a bounded act or a reusable capability?" BEFORE choosing how much governance to
build. If it is bounded - one known target, one window, then it dies - keep it simple. If it
is reusable and takes its target at runtime, that is when the controls earn their keep.
