**A brand-new eBay Production keyset that answers `401 invalid_client` is usually DISABLED, not mistyped — "Non Compliant" in the portal is the tell.**

**Correction, 2026-10-25.** In `H13033` and on the owner queue row `#967` I reported that eBay was
rejecting the credential *pair* and asked him to re-copy the App ID and Cert ID. That was the wrong
first remedy. His own screenshot of the developer portal shows the application labelled
**"Non Compliant"**, and that is the cause.

**The mechanism, from eBay's own guide**
([marketplace user account deletion](https://developer.ebay.com/develop/guides/marketplace-user-account-deletion.md)):
every developer must **subscribe to or opt out of** Marketplace Account Deletion *before making the
first production API call*, and *"failure to comply … will result in termination of your access to
the Developer Tools, and/or reduced access to all or some APIs."* A Production keyset whose
application has not satisfied that requirement **stays disabled**, and a disabled keyset answers
`invalid_client` — the same body, the same 401, as a wrong secret. There is no signal in the
response that separates them.

**What localised it, and what did not.** The App ID was compared character by character against the
string the portal itself renders beside "App ID / Client ID": **identical, 40 characters, no
differing position.** So the App ID half was never the problem. My shape validator, my selftest
(17/17) and the `invalid_request`-vs-`invalid_client` distinction all correctly said the *request*
was well formed — and all three were silent about the keyset being switched off, because none of
them can see the portal.

**The rule.** `invalid_client` is not evidence of a bad paste. Before asking a human to re-enter a
secret, check whether the vendor has disabled the credential: a compliance gate, an unpaid account,
an unaccepted agreement, an application in a review state. Three questions in order — *is it
disabled, is it the right pair, is it correct* — and a disabled credential produces exactly the
symptom of a wrong one. Also: **ask for the portal screenshot before asking for the secret again.**
One image answered in a minute what two sessions of shape-checking could not.
