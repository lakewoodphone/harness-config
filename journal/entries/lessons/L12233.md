**L12233 · Cash has no table in LPT production; a card figure read back from Stripe settles a prepay dispute, and the Stripe CLI key is dead**

Measured 2026-10-21 on WO2610200008 (Hiller, Kyocera E4610). The owner said "prepaid 150 plus tax"; the order
showed `collected 59.94`; orders."total" was NULL. Two findings, both reusable.

1. THE CARD FIGURE IS SETTLED BY STRIPE, NOT BY THE DATABASE. `payment_transactions` row 3423 carried
 `stripePaymentIntentId pi_3USkR7LnlgYj1gmT1lXPHOI0` and metadata `transactionType terminal`,
 `readerId tmr_GavzfgCDIyZ9pN`, description "Charged on the counter page for work order 3182".
 `stripe payment_intents retrieve` FROM THIS WINDOWS BOX FAILS: the CLI's restricted key expired
 2025-11-15 ("The API key provided has expired"). The live key is on the app host, so read it where it lives:
 pipe a small node script into the backend container and use the container's own env —
 Get-Content pi_probe.js -Raw | ssh secratary-ts "ssh lpt-apps 'cat > /tmp/pi_probe.js'"
 ssh secratary-ts "ssh lpt-apps 'docker cp /tmp/pi_probe.js lpt-backend:/tmp/pi_probe.js && \
 docker exec lpt-backend node /tmp/pi_probe.js'"
 Result: `pi_amount_cents 5994 ... succeeded`, `charge_amount_cents 5994 paid true captured true`.
 NOTES: `python3` is NOT in that container (rc=127, exec failed); `node` is. Never print the key.
 The PaymentIntent amount is the money that actually moved — treat it as the authority over any recollection,
 and over `orders.total` (which was never written on this order at all).

2. CASH HAS NOWHERE TO BE RECORDED. `payment_transactions` carries exactly one `type`, `PAYMENT` (all 464 rows
 ever), and there is no cash/tender table in the schema (checked information_schema for %cash%/%payment%/
 %tender%). So a figure the owner reports as paid and the database cannot show is NOT proof of an error — it is
 "unrecorded", and the question ("was 100 taken in cash?") has to go back to him. Corollary, already written up
 in lpt-ops/docs/writes.md for Terminal rows: `collected 0.00` is a refusal, not health — same defect family.

3. SIDE EFFECT WORTH KNOWING: 150 grossed up at the shop's 6.625% is 159.94, and the shop has charged exactly
 159.94 before (WO26101812752). A card charge of 59.94 against a 159.94 expectation is a classic dropped
 leading digit, but the Stripe read-back proves which one the customer was actually charged — so the conclusion
 is "the gap is real and 100.00 wide", not "the record is wrong".
