LESSONS THAT WILL BITE THE NEXT SESSION
1. THE BOX'S COMPOSE IS AHEAD OF MAIN, NOT BEHIND IT. /opt/filter-broker/docker-compose.ha.yml (7498 B) has a `socks_failover` service publishing 1080 and the base file moves the primary's host port 1080 -> 1082; main's copy (5559 B) has neither. Copying main's compose as the ops README instructs would delete the failover service and collide on port 1080. Read the box copy before syncing compose, always.
2. `build.context` in both compose files is the absolute path /opt/filter-broker/server, which is now STALE (31 migrations). Any future `docker compose build` on the box rebuilds OLD code and would silently roll the broker back — the exact failure ops/README.md documents from 2026-10-05. The build for this deploy bypassed it with `docker build` + explicit tags. Next deploy must either sync server/ from main or keep using an explicit docker build.
3. TWO IMAGE TAGS, NOT ONE. broker -> filter-broker-broker, broker_b -> filter-broker-broker_b (compose names by service). Building only the first leaves the twin on old code behind the same Caddy round-robin, so half the requests 404 a new route. Build with both -t flags.
4. A 403 `error code: 1010` from curl against https://filter.lakewoodphoneandtech.com is Cloudflare blocking urllib's default User-Agent, not a broker fault; with a browser UA the same URL returns 200. Do not read it as an outage.
5. verify-broker.sh reports a container in its 20s start_period as `(health: starting)`; run it twice (the README says so) before calling anything unhealthy.
6. The live DB has 0 rows in phones/households/phone_tokens/tenant_billing_state (phone_api_keys has 1). So a device-token call for the canary phone authenticates and answers UNKNOWN — UNKNOWN here is "no billing row", not a lapse. /self/status 404s {"detail":"Unknown phone_id"} for the same reason.
7. The brief I was given said the running image was created 2026-10-21T13:50:42Z; both broker images were actually 2026-10-19T22:26:01Z. 13:50:42Z is the mtime of /opt/filter-broker/.env. Read image creation from `docker images`/`docker inspect`, never from a note.
