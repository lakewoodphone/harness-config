**L3866 · Tech Mode Install ID moves on reboot (+611 s measured) and silently kills the old code - read it off the screen each time**

The E4810 558800238329 was restarted and its Tech Mode Install ID moved from 1791303670 to 1791304281 - +611 seconds - so the support code issued at 13:20 (720337) was dead and a new one (694902) had to be generated. Owner handed over the new number; code issued from `lpt get-tech-code --imei 673359501439973 --timestamp 1791304281`.

Why it moves, read from the source (`agent/lpt-techmode/.../TechModeManager.java:86-121`): the displayed Install ID is NOT a constant. `getInstallTimestamp` returns `storedWall + (elapsedRealtime_now - elapsedRealtime_at_install)` whenever the wall clock has drifted more than 300 s from that projection. `elapsedRealtime` resets to zero on every reboot, and this handset had no network time for hours in a dead-coverage room, so both halves of that calculation changed on restart. The device key is stable (derived from the IMEI and stored), the install ID is not.

OPERATIONAL RULE: read the Install ID off the phone screen immediately before generating the code, and regenerate after any reboot, battery pull, or clock change. An old number produces a code that looks valid and is silently wrong. Measured cost: one wasted unlock attempt this evening.

DESIGN NOTE worth acting on later: the correction logic exists to survive a factory reset with a wrong clock, but it makes the code fragile for a shop that pulls batteries to fit SIMs. Options are to display the stored value uncorrected, or to accept either value when validating. Not changed tonight - it means rebuilding and redeploying the Tech Mode APK to five handsets, and the phones are mid-audit.
