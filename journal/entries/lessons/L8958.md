**L8958 · L: /config on a Home Assistant host is a 21 GB tree; grep -r it and you wait**

**L · `/config` looks like a config directory and is a 21 GB filesystem**

Measured 2026-10-18 on the Phoenix host while chasing where `phoenix_drop_off_pin_enabled` was read: `grep -rn "drop_off_pin_enabled" /config/` did not return in 60 seconds and had to be killed. `/config` contains `home-assistant_v2.db` (519.7 MB, SQLite), `www/snapshots`, `esphome`, `custom_components`, and 116 MB of leaked Windows deploy-staging directories; `/media/phoenix` beside it is 2.9 GB.

The answer was in two globs the whole time: `/config/automations/*.yaml` and `/config/packages/*.yaml`, which returned in under a second.

Rule: on an HA host, never search `/config` unscoped. Name the directory the automation lives in. And when the question is "who reads this entity", the durable answer is not a grep at all — it is `ha_truth.py`'s entity surface plus the packages; a grep tells you where the string is, not whether HA loaded it.
