## L1747 — the journal allocates ids locally, so a machine that is behind can mint an id that already exists on the remote

**Measured 2026-09-16.** This checkout was four commits behind `origin/master` in harness-config. Another
machine had meanwhile filed `L1736`–`L1740`. This session's `journal.py append` allocated `L1736` and
`L1737` — numbers that were already taken — because id allocation reads the local tree, and the local
tree did not have the other machine's entries yet.

**Consequence if it is not caught.** Two different lessons both called `L1736`. The merge conflicts on the
filename itself, and whichever resolution loses, an entry silently disappears or ends up mis-cited. The
failure mode the journal was built to prevent — "one id meaning two things" — arrives anyway, through the
one door the design left open: allocation is local, publication is shared.

**What to do when it happens** (done here, works):
1. Move the local colliding files aside rather than resolving the merge by hand.
2. Commit and merge everything else; take the remote's generated `journal/index/entries.tsv` and rebuild
 with `journal.py index`.
3. Re-`append` the set-aside entries with `--body-file`. They get fresh ids.
4. **Strip the stale heading the re-append leaves behind.** `append` prefixes its own heading, so the
 body's original first line (`**L1736 · ...**`) survives as a second, wrong one. Delete it and
 re-stamp `sha=` with the module's own `entry_hash(heading, body)` — import `journal/tools/journal.py`
 with `importlib` and use its parser, do not hand-roll the hash.
5. Verify with `journal.py check` (0 errors) and `journal.py next-id <kind>`.

**What would fix it properly.** `append` should fetch (or at least consult a cached `origin/master`) and
allocate above the highest id in `entries/` **plus** `git ls-tree origin/master journal/entries/`, and
refuse to write an id that exists remotely. Until then: **fetch harness-config before a session that will
write journal entries**, and if `git status -sb` says "behind", pull first.
