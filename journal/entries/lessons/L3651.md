**L3651 · Four dead ends on the ST-50 basis, and one false alarm that was right to check**

2026-10-13. Four sources probed for the ST-50 taxable-sales basis. None holds it. Recorded so the
next session does not re-run these four dead ends, plus one false alarm that was worth checking.

WHAT I RULED OUT, each by measurement:
 1. Deduplication. The raw query is inflated, so the obvious theory was duplicate transactions.
 Excluding `duplicate_of_transaction_id IS NOT NULL`:
 quarter known raw dedup ratio(dedup/known)
 2025-Q3 3051 16,754.84 16,094.10 5.28
 2025-Q4 3429 6,532.61 6,518.80 1.90
 2026-Q1 4928 10,312.98 9,665.11 1.96
 2026-Q2 16880 34,567.27 20,029.42 1.19
 The ratios are not constant, so it is not a fixed double-count and not a dedup artefact.
 Whatever "taxable sales" means in those filings, it is a NARROWER population than any
 account_name-based credit query - most plausibly goods only, with repair labour outside it.
 2. The current P&L. 2025-Q3 revenue is 4,022.29 against a filed 3,051. Not the basis.
 3. The v9 FINAL P&L that `calculate-sales-tax.py` cites as its source. Not on the box: the estate
 file index returns NO MATCH for it.
 4. The mail. `from:getgov2go.com "Sales and Use Tax"` returns the DORES reminder programme's
 notices. They name a tax type and a due date and carry NO amount. Nothing from a preparer or
 accountant exists in 179,771 indexed communications.

A FALSE ALARM I DID NOT RAISE. Those Gov2Go notices include "NJ Sales & Use Tax Monthly Payment",
due 2026-08-20 and 2026-09-20 - two more deadlines the tax clock does not model, both in the past.
Before treating that as a missed obligation: NJ requires MONTHLY sales tax remittance only when the
liability exceeds 500 a month, and LPT's filed quarters imply 67 to 373 a month. So LPT is correctly
a quarterly filer and the monthly notices do not apply. The notices are template-driven and the
email itself says "If you are not required to file this return ... please disregard." Had I reported
them, it would have been a crisis that did not exist - the exact failure this estate has already
made once.

MADE THE DIGEST SELF-CONTAINED INSTEAD. `tax-deadlines.py` now also reads
`scripts/tax/nj-portal-state.json` and prints what the STATE says was filed, so one daily file
carries both halves of the question:
 last period filed: 2026-06-30 <- nothing filed since June, so Q3 is outstanding
 current balance: 2.76

 2025-Q3 268.23 | 2025-Q4 295.23 | 2026-Q1 384.2 | 2026-Q2 1118.04
A deadline with no filing status beside it makes the reader go and look; this one does not.
