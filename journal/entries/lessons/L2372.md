**L2372 · A document's claim that an owner-queue row is open is a pointer, not a fact - read the row**

**A project document's claim that a queue row is open is not evidence - read the row.**

**Measured, 2026-09-24.** `2026-09-23-shlock-decisions.md` §5 listed "Owner decision queue #79 (no permit on
the frame) is still open and still his". Read back from `owner_decision_queue` on the authority, row 79 is
`status='answered'`, answered 2026-09-20 with "leave it - accept the exposure" - four days before the
document called it open. A session that trusted the document would have re-asked the owner a question he had
already answered, which is the exact failure the queue exists to prevent (P1: his attention spent on
questions that are not his).

**Rule.** An open/closed claim about the owner queue inside any document, plan or handoff is a *pointer*, not
a fact. Read `owner-queue.py next` / the `owner_decision_queue` row before acting on it or repeating it, and
correct the document in place with a dated line when it is stale. The row is the authority; the prose is not.

**Refs.** `lpt-hub/research/miscellaneous/2026-09-23-shlock-decisions.md` §5, corrected in `2dc36fc86`;
`owner_decision_queue` rows 79 and 80.
