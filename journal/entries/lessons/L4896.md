**L4896 · GMAIL_DEFAULT_ACCOUNT=primary silently sends from the wrong mailbox**

Hit this 2026-10-15 sending the Lakewood referral list.

SYMPTOM: send_message(settings, to='lakewoodphoneandtech@gmail.com', ..., account='primary' - or account unset) returned ok:true with a message id and labels ['SENT']. It looked like a shop email. It was not: reading the mailboxes back, the message was in chevedy@gmail.com SENT and lakewoodphoneandtech@gmail.com INBOX, From: Yocheved Yanofsky <chevedy@gmail.com>. An outbound email went out under a FAMILY MEMBER'S personal account because the config alias resolved to it.

MECHANISM, from app/services/gmail_service.py:
- _resolve_account() treats any account string without '@' as an alias. GMAIL_DEFAULT_ACCOUNT=primary in personal-secretary-mvp/.env.
- It prefers env GMAIL_PRIMARY_ACCOUNT (unset here), then falls back to list_authenticated_accounts()[0] when the alias is 'primary'.
- list_authenticated_accounts() enumerates data/gmail_tokens, whose filenames sort as: chevedy_at_gmail_com, eliyahuzabrowsky_at_gmail_com, ezabz68_at_gmail_com, lakewoodphoneandtech_at_gmail_com, zabzgpt_at_gmail_com. So [0] is chevedy.
- THE FIRST ENTRY IS THE WINNER. Adding one token file beginning with an earlier letter silently changes which mailbox every outbound email leaves from. ok:true is returned either way, so nothing surfaces the change.

FIX AT CALL TIME: pass the REAL address, e.g. account='lakewoodphoneandtech@gmail.com'. Passing the token stem 'lakewoodphoneandtech_at_gmail_com' does NOT work - _resolve_account rejects it because it has no '@'.
NOTE ON SIGNING: with from_addr unset the shop send still went out as From: info <info@lakewoodphoneandtech.com>, not the gmail address. That is the configured send-as alias and is the desired shop identity.

FIX AT SOURCE (needs the owner - ~/.dsh and app .env are not mine to edit blind): set GMAIL_DEFAULT_ACCOUNT=lakewoodphoneandtech@gmail.com in personal-secretary-mvp/.env, and/or set GMAIL_PRIMARY_ACCOUNT, so 'primary' stops being resolvable to an arbitrary mailbox.

VERIFY RULE, and this is the general one: after ANY outbound send, read the recipient AND the sender back from the message headers, not from the tool result. 'SENT' describes what we did with the message, not who it came from or who received it. This is the same class as pain P2477, which caught the recipient side of it; this caught the sender side.
