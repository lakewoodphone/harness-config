## "The last message was inbound" is not "the customer is waiting" — three filters, measured

First attempt at the most valuable view in the archive ("who is waiting on an answer")
returned **137 rows**, led by Stripe payouts, GitHub notifications and Lowe's marketing.
True by the letter, useless as a signal — and the journal already records what happens to
a surface like that: it stops being read.

Each filter was added because the list showed the failure, and each removal is now
*counted and reported* rather than silent:

| filter | why |
|---|---|
| email must not look automated **and** must not be an `email_auto_discovered` / `email_thread_state` contact | 137 → 40; those contact rows are created mechanically from senders, so "on file" proves nothing |
| a **call that was answered** is never "waiting" | in a phone business nearly every completed call has no text afterwards, so all of them were flagged; a held call was answered by definition |
| a message that is only an acknowledgement is a conversation *closing* | "Perfect thank you so much", "ok", "have a good yom tov" — their word was last and nobody needed to reply |
| calls where nobody spoke (no transcript) move to a separate **missed calls** list | someone tried to reach us, but there is nothing to answer |

Final: **20 customers waiting** inside 7 days, every row actionable — "would you be able to
fix a laptop that had water damage?", "Do you have cheaper?", two unanswered voicemails.
Plus 18 missed calls in their own bucket.

The acknowledgement test is token-based, not a phrase list: split the message, and if every
token is in a closed vocabulary of ~75 acknowledgement words and there is no question mark,
it is a closing. `"Perfect thank you so much"` fails a regex over whole strings and passes
this. **A question mark disqualifies** — a question is waiting on an answer by definition.
Where the filter is a heuristic it is labelled as one in the code; where it is evidence
(the contact provenance) it is not.
