**L1824 · PowerShell is case-insensitive: a local \ destroyed the -Body parameter and four acceptance sub-cases passed while testing the wrong task**

A PowerShell local named `$body` IS the `-Body` parameter. Variable names are case-insensitive.

MEASURED 2026-09-16, scripts/mesh-e2e.ps1: an HTTP helper had `[string]$Body` as a parameter and
`$body = ''` as a per-attempt local. The local wiped the parameter, so every POST went out with
content-length 0. The broker's frozen never-refuse rule then silently rewrote each dropped
"6-child fleet" into a 1-child one-shot, and FOUR acceptance sub-cases PASSED while testing a task
nobody had asked for. A green run that was wrong - the most expensive kind.

THE GUARD, and it generalises: assert on what the SERVER echoes back, not on what the client meant
to send. The broker's placement response carries `kind` and `children` (§2.2), so
`Test-TaskEcho $placement 'fleet' 6` converts a dropped body from a silent change of subject into a
loud FAIL. Any time you POST to a service that echoes its parsed input, check the echo.

Same file, same session, same class: `$args` is an automatic variable (Start-Process argument lists
must not be called that), and `ConvertFrom-Json` returns Int64 so `-is [int]` rejects a good 15423.
Write `-is [int] -or -is [long]` when testing "is a number", not `-is [int]`.
