**L3744 · A refresh job cannot report that it stopped running - three dead search clocks, and two jobs on one minute cost 21.9 s**

**Measured on `secratary-cloud` and `zabz-tech`, 2026-10-12 (journal H3571).**

A refresh job cannot report that it has stopped running. This estate has now shipped a **silently dead
search clock three times**, and each time every surface still described the index as "scheduled":

| instance | what was actually true |
|---|---|
| `P2899` D2 (2026-10-09) | the trigger was `Duration=P1D, Interval=PT30M` — it fired every 30 min **for one day**, then the repetition pattern expired. `NextRunTime` empty, `LastTaskResult=1`, index 21 days dead. |
| `H3376` (2026-10-09) | the same clock re-registered; the index read 21 days stale with `NextRunTime` empty. |
| `zabz-tech` (2026-10-12) | task `DSH search index refresh` `LastTaskResult=1`; `~/.fsearch/index.db` 4,885,487,616 B @ `2026-09-14T17:42:12Z` — 27 days stale. |

In all three, the *only* thing that knew the index was dead was the index's own timestamp, and nothing
read it. A job that rebuilds an artefact is silent when it fails; only a job that **measures the
artefact** speaks.

**The rule.** Any scheduled refresh must be paired with a separate scheduled check that measures the
artefact's freshness, **runs on a different job name, and exits non-zero** so the estate's run ledger
(`~/.cron-status/runs.tsv`, written by `cron-wrap.sh`) records the failure. A guard that only prints is
worth nothing — it is a log line nobody opens, which is how all three of the above survived for weeks.

Implemented as `scripts/find-anything/check-faindex-freshness` (exit 0 fresh / 1 missing-or-stale /
2 could not check) beside the `fa-index-refresh` job it watches.

**A second, less obvious half of the rule.** Two correct jobs can still break the budget by landing on
the same minute. The first cut of the refresh job used `*/15`, colliding with a pre-existing
`journal-commit */15`, and the index builder calls `journal.py status`, which rebuilds the journal
cache — measured consequence, `ps_search what=journal` at **21,902 ms** against a 5 s budget. Pick
minutes that are congruent to a value no other job uses (here `8,23,38,53`), and check it with a
computed collision test rather than by eye.
