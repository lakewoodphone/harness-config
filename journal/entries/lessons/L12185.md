**L12185 · Adding a broker route moves 5 things, and the shared MITM root is the real defect (ledger 1064)**

Adding an HTTP route to personal-secretary-mvp costs more than the route.

Read on `agent/kf-device-cert` (ledger 1064, A-P4-02), cut from `f811b67`, 2026-10-22.

WHAT MOVES WHEN A ROUTE IS ADDED. Five things, and only the first is obvious:

1. `server/app/route_security.py` -> `KNOWN_HTTP_ROUTES`. Missing from it, the app raises a hard
 `RuntimeError` **at boot**, not at request time. `('METHOD', '/path')` tuples, flat frozenset.
2. `server/app/route_hardening.py`. You usually do NOT need to edit it: `/pairing(?:/|$)` already
 requires RATE_LIMIT and `/pairing/bootstrap/redeem` is already classified, so a route named
 under an existing pattern inherits its classification. Check `HTTP_HARDENING_RULES` for a
 pattern match BEFORE adding a rule. The required control is detected by AST marker names, so
 calling `deps.require_sync_callback("rate_limit_admin")` satisfies it.
3. `server/security/security_audit_signoff.json` -> digests move, and
 `tests/test_security_audit_signoff.py` fails with `assert 'fail' == 'pass'`. The remedy is one
 command and it insists on a reason:
 `python scripts/refresh_security_snapshots.py --reason "..." --skip-audit`
 `--skip-audit` reuses the pip-audit snapshot, which is right when no dependency changed.
4. `docs/FEATURES.md` -> `check_features.py` reports FEAT-UNCLAIMED for any new router module the
 live app serves. Add its path to the row for the capability it belongs to (B02 Phone lifecycle
 for pairing-adjacent routes).
5. `scripts/facts/*.py` -> seven counters move on a route addition (server-route-count,
 openapi-paths, openapi-operations, server-module-count, server-router-modules, test-file count,
 kotlin-file count) and `docs/IMPLEMENTED-VS-DESIGNED.md` contradicts them. **`docs_check.py
 --write` does NOT fix these**: it rewrites the page, not the owner. Each needs `VALUE` set and
 `MEASURED` bumped in its own file. That is `scripts/`, so a scoped branch cannot do it — the
 estate convention is that the integrating merge updates them; see the merge commits whose
 subjects end "(generated documents and fact counters)".

So `python scripts/docs_check.py` CANNOT reach exit 0 on a feature branch that adds routes, if
`scripts/` is out of scope. Say that up front instead of discovering it after the work is done.

THE KOSHER FILTER'S SHARED ROOT, WHICH IS THE REAL DEFECT BEHIND ITEM 1064. The broker ships ONE
MITM CA — certificate **and private key** — to every phone through the rules payload:
`server/app/models.py:1748-1749` (`ca_cert_pem`, `ca_key_pem`) -> `broker/RuleRepository.kt:434-451`
-> `vpn/split/SplitTunnelLocalSocksProxy.kt:391-397` -> `MitmCertificateAuthority.fromPem`. That is
precisely what `docs/corpus/FILTER-MODES.md:60-67` says must never ship, and it is live today.
`agent/kf-device-cert` built the per-device replacement (device generates its own root, broker
records only the public half) but did NOT retire that path — retiring it is `broker/` + `vpn/` work
and it is the next real step, not a nice-to-have. A per-device certificate beside a shared one
fixes nothing.

THE EDGE AUTHENTICATES WITH A TOKEN, NOT A CERTIFICATE. `LPT_WS_AUTH_MODE=per_phone` since
2026-10-21T13:51Z: `phone_id` + its own token from `POST /pairing/phone_tokens/rotate`. mTLS is
wired only as verification of a proxy-forwarded header (`server/app/mtls.py:53`) and
`mtls_required` defaults False (`config.py:271`), so a client certificate is a SECOND layer beside
the token, never a replacement. Do not describe it as replacing the token.

Kotlin/Kotlin detail worth keeping: BouncyCastle's `BasicConstraints` has `(Boolean)` and `(Int)`
constructors and NO `(Boolean, Int)` overload — CA with pathLen 0 is `BasicConstraints(0)`. And an
`internal` Kotlin member is name-mangled in bytecode, so `getDeclaredMethod("signerKey")` throws
NoSuchMethodException; match by `name.startsWith(...)` and assert the return type instead.
