**L3200 · A restart mints a new single-use launch token, so every engine restart breaks every already-open window**

ZABZ-YOGA 2026-09-30: the engine was restarted by the mesh restart-when-idle window and by my own repair work, and after each restart the owner's open window showed 'dsh web authentication required; reopen the URL printed by dsh web'. Cause: the launch token is SINGLE-USE and per-process -- each boot prints a new one and exchanges it once for a cookie -- so an already-open window that reloads without the current token cannot authenticate. This is why the machine looked broken while the engine was healthy (it answered /healthz and served the full app HTML throughout). FIX in the launcher: Set-LiveEngineUrl now writes the current tokenized URL to ~/.dsh/multi-window/live-url.txt on every boot (stdout parse) and on every launch URL that answers 303, so 'open this URL' is answerable by any agent over SSH instead of only from the engine's stdout that a detached boot throws away. STILL OPEN: a window already open across a restart is never re-pointed at the new token -- dshw needs a refresh pass after restart that walks live windows and re-navigates them.
