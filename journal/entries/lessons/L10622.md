**L10622 · A browser walk cannot see a document-level SEO defect: read the head with JavaScript off**

The LPT website had one indexable URL and we could not see it from a browser. Measured 2026-10-20: every public route on production serves the same 8,422-byte client-rendered document with the same title and the same rel=canonical pointing at '/'. The reason no browser walk found it is that the app writes per-route title/description/canonical at runtime (frontend/src/utils/publicPageSeo.ts:39-45) for 9 pages, so the tab looks right and the document is wrong. The class: 'the browser shows X' and 'the document contains X' are different measurements, and every crawler, link unfurler and social preview sees only the second. Where to apply it: any SEO, share-preview, or 'is it live' claim - curl the document with no JavaScript and read the head, do not screenshot the tab. The four pages that never set a canonical at all were /kosher-waze (the only page with real prices), /find-a-computer, /intake and /login, so the money page advertised itself as the homepage.
