**L3549 · A repeating Trust This Computer dialog is a host-side pairing failure - unpair/pair/validate before blaming the device**

An hour of failed iPhone backups on 2026-10-08 — attempts hanging at 0%, "Connection was
terminated abruptly", loops restarted, the device rebooted — was caused by the Mac having NO
PAIRING RECORD for the phone. iOS kept showing "Trust This Computer"; the operator kept tapping
Trust; the host side was never paired; so `com.apple.mobilebackup2` never started.

THE RULE: a trust dialog that keeps coming back is a HOST-side pairing failure, not a device
fault, not a cable, not the app and not the OS version. Check
`idevicepair -u <UDID> validate` FIRST; if it is not SUCCESS then `unpair` -> `pair` (accept the
dialog on the phone) -> `validate`. Measured: after that fix the next backup ran on the first
attempt.

Related, same session: `pymobiledevice3 backup2 backup` has NO timeout of its own, so a wedged run
sits at 0% forever and a retry loop that waits on it never retries. Always cap it
(`~/bin/backup-once-timeout.sh`).
