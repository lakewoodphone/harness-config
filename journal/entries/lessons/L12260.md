**L12260 · Get-Content -Raw -replace truncates the file to zero bytes, and an empty script parses clean**

A PowerShell one-liner of the shape

 (Get-Content $f -Raw) -replace 'a','b' | Set-Content $f

is not a find-and-replace. `Get-Content -Path x -Raw -replace ...` binds `-replace` as a
PARAMETER NAME, which fails ("A parameter cannot be found that matches parameter name
'replace'"), the pipeline hands Set-Content a null value, and the target file is
truncated to 0 bytes. Measured 2026-10-22: scripts/condition/audit-phone.ps1 went from
246 lines to 0 bytes, and the parse check I ran afterwards PASSED, because an empty
script is valid PowerShell.

What caught it was reading the size on the very next command (0 bytes, 0 lines) and
restoring from the last commit (git checkout -- <file>).

Rules that follow:
- Use the edit tool for text changes; it fails loudly when the anchor is missing.
- If a shell replace is unavoidable: build the new text in a variable, assert the anchor
 was found, write to a temp path, compare size, then move.
- A parse check proves nothing about content. Check size, line count and git diff after
 every scripted write.
