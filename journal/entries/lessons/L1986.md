**L1986 · The DSH session list: real RPC shape, 25-31 s cause, and the empty sidebar**

MEASURED 2026-09-18, ZABZ-YOGA, engine pid 4416.

THE RPC IS NOT A GET. GET /api/session/list -> 404 is a VERB error, not a symptom:
dsh-client-connection/lib/index.js:640 404s anything that is not POST to an endpoint path; :641 415s a non-JSON content type. The real call (client.js:6194-6216 createWebConnectionRpc.call):
 POST http://127.0.0.1:<origin>/api/session/list, content-type: application/json
 {"type":"client-request","rpcId":"<uuid>","method":"session/list","payload":{"args":{"_request":{}}}}
 -> {"type":"server-response","rpcId":"<same>","result":{"ok":true,"value":{"items":[...]}}}
The payload is {args:{...}}. {"_request":{}} alone passes the connection layer and is then refused by dsh-api-gateway/lib/index.js remoteRequest with "Remote payload must contain exactly one plain-object args field". The client THROWS on rpcId mismatch, so a cached reply must be re-labelled per caller, never replayed verbatim.

TIMING: 25370 / 25069 / 31357 ms, 679 rows, 1.46 MB. Every other RPC on the same page load answered promptly, so it is this code path, not a saturated event loop.

CAUSE, reproduced without the engine (tools/replicate-list-scan.mjs): dsh-session-persistence-jsonl listArtifacts() walks EVERY session dir every call - 6 project dirs, 681 session dirs, one stat and one first-zstd-line read each = 5900 ms raw (2723 ms reads + 3127 ms of stat()). 681 dirs, no cache, and the RPC has no paging parameter ("reserved empty list request"). Cost is LINEAR in stored sessions.

THE VISIBLE BUG: the sidebar renders the workspace tree from the workspace list (fast) and the session ROWS from this call, with NO loading state. Measured live in Playwright on a fresh origin: treeitem "code" with nothing under it and placeholder.workspace = "Choose a workspace to start" (dsh-client-ui-conversation/lib/client.js:13805) for ~27 s, then 6 rows + "Show 51 more sessions". Nothing was empty; it was not there yet and it said nothing.

FIX (no engine restart, no client patch): cache it in the proxy that already fronts every window. 25371 ms -> 29/29/92 ms, rpcId re-labelled correctly, 685 rows. dshw ensure already runs every minute as a scheduled task, so it prewarms.
