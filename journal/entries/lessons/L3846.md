**L3846 · A PowerShell here-string piped to ssh 'bash -s' loses its tail - base64 the whole command into one argument instead**

**Measured 2026-10-18, ZABZ-TECH (pwsh) to secratary-ts (bash).**

A PowerShell here-string piped to `ssh host 'bash -s'` **loses its tail**. Two symptoms, and both look like something else:

- a `for` loop died with `syntax error: unexpected end of file from` `` `for' `` `command on line 7`
- the last command received a corrupted argument: `sed: can't read /home/zabz/code/lpt-ops/lpt_ops/writes.py: No such file or directory` for a file `ls -l` had printed one line earlier, and `ls: cannot access $'/home/zabz/code/lpt-ops\r'` when a CR survived the trip.

Roughly 5 short lines survived; 8-10 did not. Two of those failures I first blamed on the remote filesystem and re-tested the file five times before spotting it - the file was fine the whole time.

## The route that works: base64 the whole command into one argument

```powershell
$b64 = [Convert]::ToBase64String([Text.Encoding]::UTF8.GetBytes($cmd))
ssh secratary-ts "echo $b64 | base64 -d | bash"
```

Nothing crosses as stdin, and no quoting can break because the payload is base64. `$`, backticks, double and single quotes and apostrophes all arrive intact.

**Two things it does not fix:**

1. The payload is still *run by bash*, so whatever bash interpolates still needs escaping there - a literal dollar sign in the text is `\$`, or PowerShell expands it before it ever leaves.
2. Build the payload from a **literal** here-string (`@'...'@`). An interpolating one (`@"..."@`) turns `$50` into `0` and `$75` into `5` before ssh sees it. That happened, and the error surfaced as `lpt-write: error: unrecognized arguments: ... they did not want to pay 0 for a full diagnostic`.

**Corollary for SQL:** a statement with string literals cannot be passed through a PowerShell single-quoted arg (bash collapses the doubled `''`), and double quotes are stripped on the way to a native command. base64 is the quoting-free route; I used it for every read-only query on the shop database this session.
