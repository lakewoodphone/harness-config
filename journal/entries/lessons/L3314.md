**L3314 · A CSS fix cannot reach an inline style, and a component that handles a missing field hides a missing endpoint**

## 2026-10-05 · ZABZ-TECH · A CSS fix cannot reach a value that is set inline - and re-measure after every fix

WHAT HAPPENED. The rating stars measured 1.53:1 and failed contrast. I changed `.star-btn` in
globals.css from #cbd2d9 to a measured #7d8794, rebuilt, restarted, and re-ran the audit. The page
STILL reported 1.53:1 and the computed colour was still rgb(203,210,217). The temptation is to assume
a stale cache; the served CSS actually contained the new value (verified by fetching the stylesheet
with cache:no-store and grepping it), which ruled the cache out and pointed at the DOM instead. The
answer was one line in the component: `Stars.tsx` set `style={{ color: n <= value ? "#f5b301" :
"#cbd2d9" }}` — an INLINE style, which wins over any stylesheet rule. No amount of CSS could ever have
fixed it.

THE RULES.
1. Before "fixing" a colour, size, margin or display in CSS, check whether the element carries an
 inline `style` for that property: `el.getAttribute('style')`. If it does, the fix belongs in the
 component and the CSS change is dead code that will silently do nothing.
2. When a fix appears not to work, do not guess at caching. Fetch what is actually served
 (`fetch(href, {cache:'no-store'})` and grep the text) and read what is actually rendered
 (`getComputedStyle`). Those two readings localise the fault immediately: served-but-not-applied
 means inline/!important/specificity, not cache.
3. On this app a CSS or component change is invisible until a REBUILD plus a RESTART. Any audit run
 against the previous build reports the previous state, and the numbers look identical to "my fix
 did nothing".

THE SAME LESSON TWICE. Round 3 also found the ratings panel rendering `mine` and `counts` that the
endpoint never returned, and round 2 found the reveal-status GET that the component called and the
route never exported. Three times now: **a component that handles a missing field defensively hides a
missing endpoint.** When a component reads a field, check that something actually sends it.
