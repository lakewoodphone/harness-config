**L1603 · Do not junction node_modules into a git worktree - Vite /@fs refuses paths outside the root; run pnpm install**

Vite/Vitest resolves module ids to **real** paths and serves them through `/@fs/`, and it only
allows paths inside its project root. So a `mklink /J` junction from `worktree/node_modules` to
`main-checkout/node_modules` makes the worktree fail with:

 Cannot find module '/@fs/C:/.../phone-and-tech-full/node_modules/.pnpm/vitest-canvas-mock@.../dist/index.js'

even though the file exists at exactly that path. The dependency leaks into the resolution as a
path outside the configured root, and the fs allow-list refuses it. The backend suite happened to
pass through the junction (plain relative imports, no `/@fs/` indirection), the frontend did not --
so this is the kind of breakage that looks like a flaky test rather than a setup mistake.

**Do this instead:** run `pnpm install --frozen-lockfile` inside the new worktree. The pnpm store is
shared, so it is mostly hardlinks and it finished in a few minutes on this machine.

**Cleanup trap:** remove a junction with `cmd /c rmdir "<path>"`, never `Remove-Item -Recurse`.
Recursive delete follows the junction and destroys the target's real contents -- i.e. the main
checkout's entire `node_modules`.

Evidence: `_worktrees/lpt-walkin-hours`, 2026-09-15. Junctioned: `frontend` suite 2 files / 0 tests
run (2 failed suites). After `pnpm install`: 45 tests collected, 42 passed, the same 3 failures that
exist on pristine `origin/test`.
