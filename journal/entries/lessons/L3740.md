**L3740 · Cloud vs office: 'faster' is meaningless without the operation and the load - and the cloud box is 3x smaller on RAM, which is the one metric that got worse**

Two numbers settle any "is the new machine better" argument, and I measured both on 2026-10-12 03:18-03:35Z:
RAWS (same script both boxes, O_DIRECT): office secratary writes 3,851 MB/s and reads 4 KiB at 578k IOPS; cloud
secratary-cloud writes 1,323 MB/s and reads 4 KiB at 401k IOPS. At the APPLICATION level (the 23.6 GB consistent
`.backup` + verify) the cloud does 139 MB/s where the office's own recorded figure is 2-7 MB/s under load, and the
cloud has not taken its sshd down in 19 h while the office did it 3 documented times. So "which is faster" has no
answer until you say WHICH operation and UNDER WHAT LOAD. An idle 4-core 2013 desktop beats a busy 2 vCPU VM on
microbenchmarks by 1.4-2.9x; the same VM is 20-70x faster than the desktop on the class of work that was killing
the desktop. Office: 23,421 MB RAM, 0 kernel OOM kills ever. Cloud: 7,742 MB, 2,558 MB swap in use, 3 OOM kills of
`company-api` on 2026-10-11 (05:47:24Z, 07:10:45Z, 15:17:30Z, all global OOM, `MemoryMax=infinity`). Memory went
the wrong way and nobody has explained why the same application peaks at 7.4 GB - systemd recorded that same
7.4 GB peak on the office box when it stopped `secretary-api` at 20:23:21Z, so it is not obviously a new leak.
