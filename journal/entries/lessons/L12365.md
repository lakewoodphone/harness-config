**L12365 · Rendering images for the fleet: ZABZ-TECH can neither run chromium nor let the venv python write; use zabz-tech-linux**

Measured 2026-10-25 while making the LPT 2002 demo wallpaper.

1. Headless chromium WILL NOT START on ZABZ-TECH from a DSH pwsh call: 'Failed to create a message-only window: Access is denied (0x5)' then FATAL in message_pump_win. playwright's chromium, and chrome in general, cannot create its window in this session. Do not retry with flags.
2. The repo venv python on ZABZ-TECH also cannot WRITE anywhere: tempfile.gettempdir() raises 'No usable temporary directory found' for .dsh/tmp, AppData/Local/Temp, C:/WINDOWS/Temp and the repo dir; PermissionError on open(). Reading is fine. So a PIL script that saves a PNG fails. Workaround that works: have python print base64 to stdout and let pwsh write the file (the pipe is pwsh-side, so it costs no context).
3. What DOES render: google-chrome --headless=new --no-sandbox --disable-gpu --hide-scrollbars --force-device-scale-factor=1 --window-size=720,1280 --screenshot=out.png file:///tmp/x.html on zabz-tech-linux (Chrome 148, fonts Nimbus Sans / Liberation Sans / Lato present). Copy the HTML over ssh, render, scp the PNG back.
4. The fleet API wants 'Authorization: Bearer <FLEET_API_TOKEN>' (from personal-secretary-mvp/.env). 'X-API-Key' returns 401.
5. _common.pg_query() from ZABZ-TECH dies: it forces -i zabz-tech-ed25519 and the docker psql call times out. Query the MDM postgres directly with the Hetzner key and SQL on stdin: Get-Content probe.sql | ssh -i id_ed25519_hetzner root@87.99.141.172 'docker exec -i waze-mdm-postgres-1 psql -U wazemdm -d wazemdm -At -f -'. Nested quotes through pwsh-plus-bash-plus-psql do not survive; a stdin file does.
6. 'ok:true' from push-wallpapers means enqueued. Proof of delivery is command_results joining commands on command_uuid (commands has no enrollment_id; command_results has no request_type).
