**L6718 · My patches to big files fail at the seam, not in the helper - three times today, so test the CALLER**

Measured 2026-10-16 on cfo-resolve.py and cfo-shift.py. (1) A guard installed into cfo-resolve.py refused on spending_shaped(category_name) with no evidence counts; spending_shaped is False for personal/Home Improvement even WITH the counts (51 debits, 13 credits, so it is not money-out-only), so the guard allowed every write it existed to refuse - an inert guard, which is worse than none because it looks like protection. (2) The corrected guard's call site passed ent=ent while the signature did not accept it: shift 20261016T031002Z recorded 5 errors and 0 resolved, every traceback at the call site with TypeError. My unit test had called the helper WITHOUT ent=, so it exercised the helper and not the path the shift uses. (3) Earlier the same day, sqlite3.Connection has no rowcount - twice. The pattern is not carelessness in any one spot: it is that a patch to a large existing file has a seam between the new helper and its caller, and my verification habit was exercising the helper. So the discipline: after patching, run the CALLER - the engine's own test if it has one, and a real bounded run always; and read the call sites out of the source and assert every keyword they pass is in the signature, which is now a script I ran and which passes. A real shift with errors_count 0 is the only evidence that a guard is installed rather than merely written.
