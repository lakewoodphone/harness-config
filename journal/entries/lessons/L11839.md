**L11839 · A local staging copy silently reverted a host edit; the file you upload wins, not the newer one**

Measured 2026-10-21 while working the Waze filter docs. I edited `ROADMAP-2026-10-21.md` twice: once on the host (`secratary-cloud`, direct python edit, committed) and once in a local staging copy under `C:\Users\ezabz\code\_waze-today`. Later I `scp`'d the local copy over the host file as part of an unrelated change, and it **silently reverted the host-only edit** - the roadmap went back to saying the two fix branches were "not merged" after they had been merged.

Nothing failed. No command errored. The commit succeeded and pushed the older text.

The rule: **a file with two editable copies has no source of truth, and the copy you upload wins regardless of which is newer.** Either edit in place on the host and never keep a local copy, or keep the local copy and always pull before editing. Staging a doc locally is only safe while it is the only writer.

Same class as the estate's older `git add -A` lesson: the damage is not the wrong text, it is that a later reader believes it.
