**L3741 · A -shm mtime on a frozen database is not a write: prove a frozen DB by the data file's mtime+size over time**

`secretary.db-shm` on the frozen office box had mtime 2026-10-12 03:18Z - tonight, four hours ago - and I nearly
reported "the anchor is being written to". The DB file itself had not moved since 2026-10-11 22:33:19Z and was
identical bit-for-bit in size and mtime five hours later. A `-shm` mtime also moves when a process merely OPENS or
READS a shared-memory database, and my own db-metrics probe had just connected through the WAL. The real write
event was elsewhere: the database FILE mtime at 22:33Z, the grew-by-393 MB size, `family_chat.db-wal` at 00:00Z,
and a `mesh-broker.mjs` PROCESS started at 23:34:48Z on a host the register calls frozen. Lesson: to prove a frozen
database is being written, compare the DATA FILE's mtime+size over time, never the `-shm`/`-wal` timestamps, and
look for a process whose start time is after the freeze.
