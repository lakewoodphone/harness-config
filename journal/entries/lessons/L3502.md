**L3502 · Get-Volume can hang for over a minute on an SD reader; use System.IO.DriveInfo**

`Get-Volume -DriveLetter E` **hung for over a minute** against the SD card reader on
ZABZ-TECH (2026-10-11, ~15:38), twice, while `[System.IO.DriveInfo] DriveInfo('E')`
answered instantly. The first time it looked like the install script had stalled; the
second was a deliberate timing test that never returned within 60 s. The same cmdlet had
answered fine fifteen minutes earlier, so this is a provider that degrades — probably
because of the phantom `X:` removable volume with size 0 that appears alongside a card
reader.

Rule: never put `Get-Volume` (or any Storage-WMI path) on a route that runs with a card in
a reader or in front of a customer. Use `New-Object System.IO.DriveInfo <letter>` and
`$di.IsReady / DriveFormat / TotalSize / TotalFreeSpace`. It is instant and it needs no
provider.

Also recorded there: `install-to-card.ps1` now re-reads every file off the card and compares
sha256 before it claims success, because a copy that was not read back is not verified.
