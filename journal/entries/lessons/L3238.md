# Text line round 18 — the cache, and a fifth silent failure

## What was built

The Gmail order fallback cost **2.5–7 s per call** and sat on the send path (`compose()` is
called from a `*/30` cron). Measured in the production shape before the change:

 cold _email_order_match : 3.53 s
 second call : 6.96 s
 compose('amazon') : 2.55 s

Added a bounded JSON cache at `~/.cache/charge-msg/`, keyed by the charge date, written
atomically (`.tmp` then `replace`), with a **short TTL for dates within 3 days** (an order
can still arrive) and a **long one for older dates** (a three-week-old window cannot change).
It is **fail-open by design**: any cache problem means "no cache", never "no answer".

**Verified after the fix:**

 call 1: 5.71s -> '3 Amazon orders in this window - cannot tell which from mail'
 call 2: 0.00s -> same answer <-- cache hit
 files: ['amazon-orders-2026-09-28.json']

`compose()` for an Amazon charge now pays the Gmail cost once per date per TTL, instead of
on every question.

## The fifth silent failure, and it took four rounds to see

The cache wrote nothing at all, and the only symptom was that every lookup stayed slow. The
`_email_cache_put` helper ends in `except Exception: pass` — so a real write failure looked
exactly like "no cache yet".

Making that exception visible (`f"cannot write the cache at {p} ({exc})"`) gave, immediately:

 charge_msg: cannot write the cache at /home/zabz/.cache/charge-msg/amazon-orders-2026-09-28.json
 (name 'timezone' is not defined)

**`charge_msg` imports `date, datetime, timedelta` and not `timezone`.** The same class of
defect as the missing `import sys` two rounds earlier, in a module written and reviewed by me
on the same day, and caught the same way: by refusing to let a fallback be silent.

The tally of silent fallbacks in this one engagement, all found by making the exception
visible and none by reading the code:

| # | silent fallback | symptom that hid it |
|---|---|---|
| 1 | undefined `BIN` in the composer wrapper | printed the OLD bare body — looked like success |
| 2 | `app_db_query` on a DB with no `transactions` | `FAILED` with no reason |
| 3 | `import sys` missing in `charge_msg` | empty result = "no mail" |
| 4 | relative `gmail_tokens_dir` + `$HOME` cwd | unauthorised = "no mail" |
| 5 | `timezone` not imported; `except: pass` | no cache = "slow", never an error |

**The rule, for the fifth time and now with five examples behind it: a catch-all except must
say something.** Every one of these five was a plausible empty result standing in for a real
failure, and every one was fixed within minutes of being made audible.

Also fixed on the way, and worth naming because it was mine: two patch scripts failed against
anchors that were present, because a **later** replacement had already rewritten the text the
**earlier** one searched for (`add-email-cache.py`), and because my own edit removed a cache
write it had just added. A patch that modifies a file in several steps has to be written in
the order the text is consumed, and re-verified after every step.
