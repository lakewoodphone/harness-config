**L5449 · The old working USB access kit never moved sshd off port 22. A random port in sshd_config is the whole reason the rebuild kept failing.**

Found by archaeology, 2026-10-15, in the owner's words: *"we originally built the USB months ago ... we had the
same failures again that you were going through now ... instead of keep on reinventing the wheel."* He was right.

**The proven-working predecessor is `personal-secretary-mvp/scripts/copilot-ssh-field-kit/`** (Gen B, added
`e1538fdb` 2026-07-05 / `d7cd4ecf` 2026-07-07), with `scripts/windows/` before it (Gen A, `7775e17e` 2026-05-21)
and both retired by `MOVED.md` (`f3d52ad8`, 2026-10-05). **`CopilotSshAccess` is the USB FOLDER name
(`D:\CopilotSshAccess\`), not a repo directory** - which is why months of looking for it in a repo found nothing.

**A real working run is preserved, uncommitted, at `scripts/copilot-ssh-field-kit/latest-run/`** - MIRIAM,
2026-07-04 23:33. `CopilotAccess.txt`: `status=REVERSE_TUNNEL_ACTIVE`, `port22_listening=True`,
`direct_ssh=ssh Miriam@192.168.50.239`, `problems=0`. The log shows `[OK] TCP/22 LISTENING` and
`[OK] REVERSE TUNNEL ACTIVE to 192.168.50.138:2222`.

**WHAT IT ACTUALLY DID, and the one difference that explains everything:**

1. **IT NEVER USED A NON-DEFAULT sshd PORT.** It left sshd on **22** and wrote **no `Port` directive at all**.
 `latest-run/sshd_config.after` proves it: the managed block is only
 `PubkeyAuthentication / AuthorizedKeysFile / PasswordAuthentication / PermitEmptyPasswords`.
 The only non-default port anywhere was the **reverse-tunnel** port on the DESKTOP
 (`$ReverseTunnelPort = 2200 + (Get-Random -Min 1 -Max 100)`, `Install-CopilotSshAccess.ps1:139`), where
 the desktop listens and the target dials out: `-R 127.0.0.1:2222:127.0.0.1:22`.
 **The rebuild writes a random `Port` into sshd_config - and then has to make that config change take
 effect on an already-running service. That is a problem the old kit never had, because it never changed
 the port.** Every "not listening" blocker of 2026-10-15 descends from that one design difference.
2. **It RESTARTED sshd and PROVED the listener**: `Restart-Service sshd -Force; Start-Sleep 3` then
 `netstat | Select-String "0\.0\.0\.0:22\s+.*LISTEN"` (`Install-CopilotSshAccess.ps1:472-474`). The rebuild
 had `if ($svc.Status -ne 'Running') { Start-Service }`, so a running sshd never re-read the config.
3. Key written to **BOTH** `<profile>\.ssh\authorized_keys` AND `%ProgramData%\ssh\administrators_authorized_keys`,
 with `AuthorizedKeysFile` forced to the absolute admin path after deleting the `Match Group administrators`
 block, and `icacls /inheritance:r /grant:r` for user+SYSTEM and Administrators+SYSTEM.
4. Firewall: Gen 1 opened TCP/22 restricted to RFC1918; **Gen 2 opened TCP/22 `-Profile Any -RemoteAddress Any`**
 plus an sshd.exe program rule, ICMPv4, a netsh fallback, and force-enabled every existing OpenSSH rule.
 The rebuild is narrower again (`-RemoteAddress 192.168.50.0/24`) - **keep the rebuild's tightening, do not
 copy this part.**
5. **IT HAD NO TEARDOWN AT ALL.** Exactly one removal verb existed in the whole kit, and it removed the kit's
 own previous firewall rules for idempotency. The "auto-cleaned on next reboot" claim in `Enable-ShopSsh.ps1:16`
 and both `.cmd` files is implemented nowhere (**P2851**): the account, the key line, the firewall rule and
 the config edit all stayed. **A real teardown is the rebuild's one genuine addition and the reason it must
 not be thrown away.**
6. `Disable-Techloq.ps1` is a false claim - it prints `[STOPPED]`/`[DISABLED]` behind `-ErrorAction SilentlyContinue`
 and never touches `tpd.sys`. **And the rebuild's selector DECLINES T1 whenever the filter is detected
 (`Select-Transport.ps1:388-394`) - yet T1 worked on MIRIAM with the filter running.** That gate may be too strict.

**THE RULE.** When a working predecessor exists, the rebuild must be a *port of its mechanics plus the new
requirement*, not a fresh design. Two days of failures came from one gratuitous design change - moving the
sshd port - that the original had specifically not made. Before changing any mechanism in a rebuilt system,
read the original and write down why the change is being made; if the answer is "it seemed tidier", do not.

the repo - **a generation that was never committed.** They are in no commit and on none of ZABZ-TECH, D:\,
`_scratch`, `_worktrees`, secratary-ts, secratary-cloud or zabz-tech-linux. If they still exist anywhere, it is
on a physical stick. The session archive search (`A-archive.md`) was still running when this was written.
