**L1609 · An HTML tag-strip that keeps element CONTENTS silently poisons every derived number**

## An HTML tag-strip that keeps element *contents* silently poisons derived numbers

**The failure.** `scripts/fetch-pesukim-hebrew.py` cleaned Sefaria's Hebrew by stripping HTML *tags*
(`re.sub(r'<[^>]+>', ...)`) and unescaping entities. Sefaria embeds editorial annotations as
`<sup class="footnote-marker">*</sup><i class="footnote">(בספרי תימן ...)</i>` and parsha breaks as
`<span class="mam-spi-samekh">{ס}</span>`. Removing the tags left the **text contents** inside the
verse, so 1,082 of 5,846 rows carry `*(...)`, `{ס}`, `{פ}`, `[ketiv]`, NBSP, thin space and CGJ.

**The consequence nobody noticed for months.** The gematria engine derives its numbers from whatever
Hebrew letters it finds, so it faithfully counted the letters inside those annotations. Gematria was
wrong on **716 rows (12.2%)** — 364 off by exactly +60 (the `{ס}` setumah marker's letters), 284 by
+80 (`{פ}`), worst case **+2417**. The visible symptom: a user searching for a verse's true value got
zero results, and searching the wrong value got the verse — a miss and a false positive, both
silent. A second, quieter symptom: 660 rows no longer ended in sof pasuq, because the annotation was
appended after it.

**The rule.** When you strip markup, strip the *element contents* too, not just the tags — and then
**assert the invariant on the output**, not on the input. The decisive test is not "did the strip
run" but "does any row still match `[{}()\[\]*]`, and does every row still end in sof pasuq". Derived
numbers are the canary: a corpus-level numeric invariant (here: the first pasuk must be 2701, and
`Devarim 11:21` must be 4099) fails loudly the moment the text rots, while a text-integrity test that
only counts rows passes happily.

**Why it survived review.** The corpus *was* verified correct — a full re-fetch of all 174 chapters
matched 5,846/5,846 verses byte-for-byte. The letters were right. Only the annotations were wrong,
and no test looked at characters outside the Hebrew block. **A corpus can be textually faithful and
still be contaminated.**

**Also worth keeping:** the markers `{ס}`/`{פ}` are real Masoretic data (open/closed parsha
divisions), not garbage. Strip them from the display text, but capture them into their own
columns/fields rather than deleting them — deleting them destroys information a study product wants.
