**L3436 · A backend-served page can still be shadowed by the SPA host, and the counter is what answers**

Measured 2026-10-09 on the LPT production estate, defect on the money path.

THE FINDING THAT MATTERS: the charge page is served correctly by the backend host
`api.lakewoodphoneandtech.com/charge/<token>` — 60/60 charge page over HTTP, 10/10 in a
browser with Stripe Elements drawn, and 100/100 unknown paths on that host are an Express
404. That host cannot serve the SPA at all; it has no catch-all route. But the SAME path on
the SPA hosts is owned by nobody, so Cloudflare Pages' "Single-page application" fallback
answers it with index.html AT THE REQUESTED PATH, and the app's own catch-all
(`MVPRouter.tsx`: `<Route path="*" element={<Navigate to="/" replace />} />`) forwards to `/`,
which `HomeRedirect` resolves to the signed-in user's home.

Measured on `lakewoodphoneandtech.com` and `test.lakewoodphoneandtech.com`: title
"Counter | Lakewood Phone & Tech" at `/work-orders`, 10 loads of 10, signed in; the public
home page when signed out; and a refresh STAYED there, because `Navigate` uses `replace` —
so the address bar no longer holds the charge path and the page can never recover.

LESSONS
1. When a URL is described as "served by the backend", measure it on EVERY host that
 resolves the same path before believing which host served the defect. The bytes from one
 host say nothing about the other.
2. Wherever an SPA fallback is on, every unmatched path is a live app route. "Unknown path
 -> the app home" turns a mistyped or wrongly-hosted link into a staff surface. A typo
 must render not-found, not the counter.
3. A Cloudflare Pages Function takes precedence over the SPA fallback — `functions/api.js`
 already relied on this and it is measured live (`/api/*` returns the refusal, every other
 unmatched path returns index.html). That is the in-repo instrument for owning one path
 without touching the app's routing.
4. To check whether a redirect target is a payment surface, do not proxy it: the page posts
 to `<its own origin>/charge/<token>/api/...` derived from `window.location.pathname`, so a
 proxy would move the intent/record calls to the new host and duplicate the CSP. Redirect.

TOOLING TRAPS
* PowerShell treats `[token]` in a path as a wildcard character class: `Remove-Item` silently
 matched nothing. Use `-LiteralPath` for bracket paths.
* Git pathspecs treat `[token]` as a glob too: stage the directory, not the file.
* A cached 308 from an earlier probe made a browser replay a stale route; cache-bust with a
 query string when re-measuring the same URL after changing routing.
* On Windows, a cold vitest run of `backend/src/routes/__tests__/charge.routes.test.ts` can
 blow the 5 s default test timeout on a machine under load (61 sequential supertest round
 trips in the rate-limit test). It passes with `--testTimeout=60000`; do not read the
 timeout as a failure of the code under it.
