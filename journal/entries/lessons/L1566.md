**L1566 · Rotating a shared auth token: enumerate consumers, restart them, THEN promote - and never read a slow startup as a failure**

MEASURED 2026-09-15 during the Lakewood Twilio rotation (D165).

WHAT MADE IT SAFE
- Twilio's own rotation facility is create-secondary -> update consumers -> promote. The secondary token authenticates immediately, so nothing breaks while you work; only the promote invalidates the old primary. Promote is authenticated with the SECONDARY credential (HTTP 200 here), not the old one.
- The consumer list is discoverable in minutes and no single source shows it: git grep for the secret across repos, grep TWILIO_AUTH_TOKEN in every .env*, docker inspect <c> --format '{{range .Config.Env}}' per container, sudo grep -l TWILIO_AUTH_TOKEN /proc/*/environ for live processes, and plain ind for env files under home//opt//etc on each host. The five hosts that mattered were found that way; the authority alone would have missed four of them.
- Session processes cache the value at import time. Patching .env does nothing until the process restarts, so EVERY consumer must be restarted or it keeps using a credential that the promote has just killed. Expect to restart more than you think: systemd service, docker compose recreate, two Windows dev stacks, plus MCP children spawned by a running session (those only refresh in a new session).

WHAT WENT WRONG AND WAS FIXED
- The local API on ZABZ-TECH is slow: uvicorn started 15:42:22 and logged 'Application startup complete' only around 15:48 - roughly six minutes, with the last visible line a Chroma telemetry warning. restart-api.ps1 waits 45 seconds for /ready, so it reports failure, and my foreground pwsh call was killed at the 120s cap mid-restart, which left the API down until I re-ran it as a background job.
- RULE: restart that API with run_in_background and wait for the port, not for a fixed timeout, and do not conclude it failed before ~7 minutes. A killed restart script is a real outage on that machine.
- Two probes worth repeating after any credential swap: the new value authenticates, AND the old value is now rejected, AND a deliberately bogus value is rejected (the control proves the probe can fail). All three were run at secratary and at Twilio.
