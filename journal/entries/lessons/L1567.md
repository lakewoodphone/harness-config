**L1567 · lpt-hub is not one record - check which clone before trusting a case file**

**Lesson · 2026-09-15 · lakewooechsmini · The lpt-hub repo is NOT one record — check the clone before trusting a case file.**

What happened: asked to document a payment on the Weissman SSD case, the shared repo
(origin/main, and this machine's ~/lpt-hub) turned out to have no mention of ticket 74048,
while the customer's live, current case file existed only in the office desktop's clone
(zabz-tech, `C:\Users\ezabz\Code\lpt-hub`), which reports
`## main...origin/main [ahead 46, behind 2472]`. The two clones also disagree on format: the
desktop has YAML front-matter case files plus an lptcase CLI (commit c5efd646d), origin still
has the markdown-header style that ps-case.mjs writes.

Rule: before writing or answering from a customer case file on this fleet, check both
- `git -C ~/lpt-hub status -sb` (ahead/behind), and
- whether the case content you are about to extend is the newest one — `node ps-mesh.mjs run
 desktop-ts` and read that clone's copy of the file if the case is active and recent.

Consequence if ignored: a stale read makes a "correct" update that contradicts or duplicates
the real record, and an agent will report a case as having no lab ticket when the ticket
exists. Do not try to reconcile the clones by guesswork — report the divergence and let the
owner decide.

Evidence: 2026-09-15 session on lakewooechsmini; `git log` on the desktop showed local commits
(d70209a78, 16a1749a1) that our fetch could not resolve at all (`git cat-file -t 16a1749a1` ->
"Not a valid object name"), while `git show origin/main:...weissman...md | grep 74048` -> 0.
