**L3550 · WhatsApp iOS often refuses a grafted store - merge the rows into the store the app created instead**

WhatsApp Business on iOS will not always accept a whole-file graft of ChatStorage.sqlite. Measured
2026-10-08 on the Kramer case:
 * iPhone 11, iOS 26.5, app build 1082919065 -> accepted the graft, chats and media displayed.
 * iPhone 16, iOS 27, app build 1086504165 -> refused it: "couldn't update - check for updates in
 the App Store", with Core Data's `lost_and_found` table in the app's copy.
The refused store was byte-identical in Core Data metadata (model 2.12.14, same hashes) and schema
(74/74 tables, zero column differences) to one the app writes, integrity ok. So the refusal is the
app's CONVERSION step on that build, for a store it did not create - and no App Store update existed.

THE RULE, now the default: do not hand the app a database. Let it create its own store (clean
install + register), then write the recovered rows INTO it - primary keys remapped, every foreign
key rewritten, chats reconciled onto the app's own chat rows by JID rather than appended. Tool:
lpt-hub/scripts/ios-whatsapp/merge-whatsapp-stores.py. It landed 19,167 messages and the media on
the phone that refused the graft. Full procedure: lpt-hub/docs/customer-operations/sops/
IPHONE-WHATSAPP-BUSINESS-LANDING-PLAYBOOK.md.
