**L12275 · A real report at fec31a6: the floor holds, but the gate scores a different object than the one that ships**

Measured on one real production report at fec31a6 (2026-10-22, Pass Eight Measure, 113 answers). The floor is computed as designed and stated exactly once, both named roles have cards. Two of the build's three fixes have blind spots only a real run exposes.

1. THE RENDER PATH WRITES AFTER THE GATE. applyShortlistFloor adds the 30-word floor sentence to one card's caution at render, so card 0 goes 78 -> 108 words against the promised 105 cap and no gate can see it. The gate's own length violation names recommendations[3] "108 words" while index 3 ships at 104 and the 108-word card ships at index 0: stabilizeFinalReport (participant-column.tsx:2181) reorders open roles first and rewrites every caution after scoring. A gate index is meaningless on the shipped object whenever the browser re-stabilises; read the count, not the index.

2. A WITHHELD PART THE VERDICT CANNOT SEE. keepCheckedSentences (assessment-final-report.tsx:451) replaced a whole Part-1 paragraph at render with the plain "This paragraph was withheld..." sentence, while transport.reportVerdict.withheld was [] and truthfulness []. The banner therefore took the "failed, nothing withheld" branch and said "The report is saved and it is complete" over a report with a missing paragraph. The stored payload still contains the paragraph, so operator view and participant page show different reports.

3. THE DANGLING-LIST GATE NEEDS A COMMA. finalSentenceEndsOnDanglingList judges the final CLAUSE only when the sentence has a clause mark, so a truncated list that lost its commas passes: "A role combining leadership." (4 words, no verb) shipped with the gate refusing nothing of 16 fields. Whether the writer or a trimmer produced it is not provable from the payload: raw model text is not persisted, reportParts carries only status/model/elapsedMs.

METHOD THAT WORKED. Reimplement the shipped predicates from source (countWords, reportCardWordCount, cardFieldEndsACompleteSentence) and apply them to participant_json->session->finalReport, then diff stored vs owner API view vs rendered body text before claiming any two of them disagree. Both were identical here; the page differed only where the render path rewrote it.
