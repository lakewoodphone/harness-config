**L3692 · The label printer already existed: lpt-label, and a tool nothing points at is indistinguishable from a missing one**

**L · The label printer already existed. Nothing pointed at it, which is the same thing as it not existing.**

Measured 2026-10-12 on ZABZ-YOGA, during a request that was four words long: *"print out a label"*.

**What I did.** Hand-rolled a PowerShell `System.Drawing.Printing.PrintDocument` path to the Brother
QL-820NWB over its **Windows WSD queue**, set the page size myself, sent the job on the driver's
default **die-cut 28 x 90 mm** while the loaded roll is **29 mm endless**, and **froze the printer
hard enough that the owner had to power-cycle it.** Eleven tool calls. His line: *"every other agent
has been printing labels for a few days, why are you the only one with issues?"*

**What already existed the whole time.** **`lpt-label`** on the authority — `lpt-ops/bin/lpt-label`,
`lpt_ops/label_printer.py`, `docs/label-printer.md` — sending raw Brother raster over **TCP 9100**
from the authority, proven on this exact device since 2026-10-08, with three journal lessons already
written about how to drive and verify it (**L3534**, **L3484**, **L3486**). One command:
`ssh secratary-ts 'lpt-label ...'`.

**Why I never found it: I did not run the survey.** `AGENTS.md 0` says read
`docs/mesh/000-SYSTEMS-REGISTER.md` before the first design sentence — and **the register had no row
for the label printer at all**; `grep -i 'label|printer|QL-820'` over it returned nothing. The
knowledge lived in `lpt-ops` and in the journal; the document an agent actually reads first did not
mention it. **A proven tool that nothing points at is indistinguishable from a missing one.**

Three traps, worth their lines:

1. **A media mismatch on this printer reaches Windows as `DetectedErrorState=4` — "No Paper".** So
 "the printer is empty" is usually the wrong conclusion; the roll was loaded and reporting
 `Not Empty 29mm` on its own status page throughout. Windows never asked the device.
2. **`PrintDocument.Print()` returns success while the printer sits in that error**, and a
 pre-flight WMI check does not save you: the state does not clear until the media matches, so the
 *correct* job is refused on the strength of the previous wrong one.
3. **PowerShell variable names are case-insensitive.** A local `$paper` and a `[string]`-typed
 parameter `$Paper` are the SAME variable, so every `PaperSize` assigned to it was silently
 converted to its `ToString()` — three failures that read like a framework bug and were my own
 scope collision.

**Fixed in the harness so it cannot recur:** `docs/mesh/000-SYSTEMS-REGISTER.md` gained **2.5
Labels** (device, command, roll, dry-run rule, "the device's own status page is the only proof", the
dead website button) and trap **4.9**; a new skill **`lpt-label-printing`** was added at
`presets/zabz/skills/lpt-label-printing/SKILL.md` and installed. harness-config commit `b5e87b0f`.

**The general rule, which is the one worth keeping:** when a task names a physical thing the shop
owns — a printer, a card reader, a label roll — search for the tool **before** designing anything,
and if the tool exists but the register does not name it, **the missing register row is the bug, not
a nice-to-have.**
