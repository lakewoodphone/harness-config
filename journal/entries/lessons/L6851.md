**L6851 · Five rules in the store match no row in the ledger, and every one is counted as COVERAGE - a dead rule does no work and blocks the research that would**

Measured 2026-10-16 on the CFO engine. A rule whose match.pattern no row's cluster key ever equals is dead: it can never write anything. Five exist - autopay payment, bkofamerica mobile, zelle payment from eliyahu, atm check deposi, and one I had just written - and the shift's rule_index() reports ALL FIVE as coverage, so a cluster can be skipped for ever as 'covered by a rule' when no rule can write it. This is the round-18 false-cover mechanism measured at five instances instead of three, and the reason is a two-derivation defect: rule_index() accepts any field that looks like a key (merchant_key, key, pattern, merchant, learned_from, match) while the writer's rule_for() matches on match.pattern, so an entry can be real to one and invisible to the other. MINE was the newest: I wrote a rule keyed on the row's DESCRIPTION ('desc:online payment - thank you') when the row's actual key is 'online', because cfo_rules.cluster_key keys on merchant_name first and that row's merchant_name is 'ONLINE'. The writer reported no error, because a rule that matches no row is not a failure to it. Fixed by COMPUTING the key from the row's own columns instead of inferring it from the description, and the row is now categorised 27.42 -> Credit Card Payment. Two of my own checks were also wrong and only running them showed it: the guard I wrote to keep the rule safe refused a correct rule because its second check re-counted cluster members with an empty merchant_name, and a PowerShell printf inside a double-quoted string made a whole command fail to parse so a script I believed had run had never been deployed. The general rules: compute the key, never infer it; a rule store needs a detector for rules that match no row, because the coverage test will happily treat them as work done; and when a system reports 'covered' ask WHICH function decided that, not whether a rule exists.
