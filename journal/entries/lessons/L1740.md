**L1740 · When a SaaS endpoint cannot be guessed, read the product's own JavaScript out of the browser cache**

## L-new4 — When you cannot find a SaaS endpoint by guessing, read the product's own JavaScript. The browser cache holds the authenticated bundle the CDN will not give you.

Measured 2026-09-16, Dialpad.

**The failure:** 26 guessed endpoint paths across two rounds returned 404 (`/api/workflow*`, `/api/scripted_ivr*`,
`/api/ivr_workflow*`, `/api/callflow*`, `/api/callrouter*` and more). The correct path is
**`/api/scriptedivr`** — no underscore, and the underscore was the whole difference.

**What worked, in order:**

1. **The public page tells you which bundle to look for.** `https://dialpad.com/app` is a client shell whose
 only useful content is one script tag: `/static/cdn/uber-voice/guestbasic.<hash>.js`. That names the
 product's internal codename. The *guest* bundle contains almost no API surface, so this alone is not
 enough — but it proves the app is a separately-bundled SPA, not the Next.js site.
2. **The Chrome profile's HTTP cache already holds the authenticated bundle.** The CMS/crawler profile at
 `data/dialpad/chrome_profile/Default/Cache/Cache_Data` contained the chunks the logged-in app had loaded.
 It is readable **while Chrome is running** (unlike the Cookies SQLite file, which is exclusively locked).
3. **The cached bodies are gzip, even though the URL ends in `.js`.** The first pass returned "0 occurrences
 of `/api/`" in a 214 KB JavaScript file, which is impossible — the file began `1f 8b 08`. Gzip, then
 zlib raw/deflate/auto, then search the plaintext. 117 real API paths fell out.
4. **Mine the *stale* helper names, not just the current ones.** The decisive find was a one-line URL builder
 in a settings chunk: `let h = new URL(\`${o().REQUEST_URL}scriptedivr\`)`. That is the endpoint, spelled
 the way the app spells it.
5. **Read the store, not the view.** The pinia stores name their own calls (`ivrWorkflowsFetch`,
 `ivrMediaFetch`) and carry the query parameters the server expects (`office_id`, `state: "deployed"`,
 `limit`, `extended`, `lightweight`, `include_shared`). Copying the app's own parameters is why the first
 correct call returned data.

**Two traps inside this technique.**
- **A 200 you cannot parse is compressed, not broken.** The internal API returns `content-encoding: zstd`.
 `response.json()` raises `Expecting value: line 1 column 1`; the repo's `_safe_json()` handles it. Chasing
 that as a permissions problem wastes a round.
- **A field named for the thing is not the thing.** `connections` on the workflow object is an **integer
 count**, not the node list — so the prompt bodies are not reachable from that endpoint at all, and the
 content lives in the audio library instead. Confirm a field's *type* before building on its name.

**Why this generalises:** any vendor with a web app has an authenticated bundle that enumerates its own API.
It is static, public, and unauthenticated to fetch; only the data behind it needs a session. Reading it turns
"guess the endpoint" into "read the endpoint", and it is strictly cheaper than another sweep.
