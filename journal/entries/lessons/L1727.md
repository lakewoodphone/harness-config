**L1727 · child_process.spawn('pwsh', {detached:true}) on Windows exits 0 without running the script**

Measured on ZABZ-YOGA 2026-09-16 with PowerShell 7, spawning the same argv four ways from Node:

 detached:true, stdio:'ignore' -> exit 0 after ~160 ms, NO file written
 detached:true, stdio:'ignore', windowsHide -> exit 0 after ~164 ms, NO file written
 detached:true, stdio:['ignore','ignore','ignore'] -> exit 0 after ~211 ms, NO file written
 detached:false, stdio:'ignore' -> exit 0 after 1173 ms, 58107 bytes written

A detached `pwsh.exe` has no console to host itself in and quits immediately — with a CLEAN exit code, no stderr and no output, which reads exactly like success. The same script run from PowerShell (`& pwsh -File ...`) always worked, so the defect only exists on the child_process path.

Rule: never use `detached: true` to spawn pwsh from Node. Use `detached:false` + `stdio:'ignore'` + `child.unref()`. That keeps everything detachment was for (no pipe for the parent to service, no reference holding the event loop open) without the silent no-op.
