**L1866 · Two cheap facts that cost agents real data today: the mesh ssh users, and that the callblock profile would break CarPlay**

Both found 2026-09-17 while sweeping machines that had never been content-read. (1) SSH TARGETS: an explicit user@ in an ssh command overrides ~/.ssh/config, so 'ezabz@mac-mini-ts' and 'ezabz@linux-pc-ts' both return Permission denied (publickey). The correct users are lpt (mac-mini) and zabz (linux-pc and secratary) - use the BARE aliases mac-mini-ts / linux-pc-ts / secratary-ts with ~/.ssh/zabz-tech-ed25519, and note the authority database is /home/zabz/personal-secretary-mvp/data/secretary.db owned by zabz. Any agent that used a literal user@ in a brief got zero data and could easily have reported it as absence. (2) THE CALLBLOCK PROFILE WOULD BREAK CARPLAY: waze-callblock-bundle.mobileconfig sets allowAssistant=false (L60->61) and allowHostPairing=false (L166->167) and omits allowCarPlay entirely, while waze-layered-kiosk.mobileconfig sets allowAssistant=true, allowHostPairing=true and allowCarPlay=true. The fleet's own archived runbook says current CarPlay setup requires Siri/assistant enabled enough to pass the car's gate (L945) and documents --carplay-siri as the compatibility fallback (L947). CarPlay is the product premise, so the profile our README calls the call-blocking VPN profile is unusable on these devices as written - which is consistent with it never having been installed on one.
