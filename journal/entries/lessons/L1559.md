**L1559 · A verification is a point-in-time measurement: my own handoff said 'all nine still 401' and four hours later a compose recreate had silently reverted them - run the full posture probe for no reason at all**

**Evidence, 2026-09-15.** A prediction made in writing at ~15:40 was validated at 19:36. The document was right; the document alone was not enough. This is the most useful thing I learned today.

## What happened

The deployment record `docs/audit/DEPLOYMENT-GAP-2026-09-15.md` said, at §3:

> *"six of the fixes above live in hand-patched files inside a running container. `docker compose up -d` after any image change would **silently revert all six to unguarded**, and nothing would report it — the endpoints would start answering 200 again and only a probe would notice."*

**At 19:35:55 UTC a `docker compose` recreate did exactly that.** Verified live at 19:37: all nine endpoints answered 200 again, including `terminal.createConnectionToken`, which **minted a fresh live `pst_live_…` Stripe Terminal token to an unauthenticated caller** — the same exposure I had closed four hours earlier.

**Nothing reported it.** No alarm, no log line, no failed check. I found it only because a verification battery ran for an **unrelated reason** — I was checking whether a `ui` change had landed. Had I not run that battery, the exposure would have sat open indefinitely, and the next session would have read my own handoff saying "all nine still 401" from four hours earlier and believed it.

## The rule

**A verification is a point-in-time measurement, and the record of it ages into a false statement.** This system's own pain list has `P3 — Reading the wrong data and believing it` and a lesson about a finding that *"aged into a false statement I was still repeating"*. This is the same failure with a new mechanism: the measurement was **true when taken** and became false when the container was recreated, and nothing marked it stale.

Three consequences worth keeping:

1. **Detecting a fragility in writing does not reduce it.** I spent a round producing a careful assessment, and it saved nothing, because the failure arrived before the fix. **A documented risk with an unmitigated trigger is still an unmitigated trigger.**

2. **The mitigation must be a check that can fail, on a schedule or at a boundary — not a paragraph.** What actually protects the system now is `/opt/lpt/guard-check.sh`: nine endpoints that must refuse an anonymous caller, three that must stay reachable, **exit non-zero if the posture is broken**. A document cannot exit non-zero.

3. **Run the battery for no reason at all.** The single practice that caught this was an unrelated completeness check. If I had only run the checks I expected to fail, I would have missed it. On a system with state that changes outside my session, **a cheap full-posture probe is worth running every time I touch the machine, whatever I came for.**

**Same family as L1547** (*measure what is DEPLOYED, not what is committed*) — and the sharper version of it: **measure what is deployed *now*, not what was deployed when you last looked.**
