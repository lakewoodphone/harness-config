## The sign-in flow, verified end to end 2026-10-13

Sign-in page offers Google / Microsoft / other OAuth / email link / password / SSO. The email route
is passwordless: submit the address, Telnyx mails "Your Single Use Telnyx Portal sign-in link" from
`portal@telnyx.com`, and the magic URL is
`https://portal.telnyx.com/#/freemium-redirect?token=<uuid>&email=lakewoodphoneandtech%40gmail.com`.

Following that link lands on a **two-factor challenge**, not the portal. The page reads exactly:

 Enter your verification code
 In case you do not have access to your device, please enter a backup code.
 [Verification Code] [Verify]
 [ ] Remember this browser for 30 days
 Resend Code (nn) SMS | Call | WhatsApp

The API behind it (`GET /v2/ai_dev_event_sessions`) says
`"two_factor_auth_type":"two_factor_phone_number","preferred_method":"sms"` — i.e. **the code is
texted to whatever mobile number is saved in the account's security settings.** It is *not* emailed
and it is *not* sent to any fleet/Waze device. `POST /v2/send_two_factor_auth_code` returns only
"Success! You should receive a verification code soon." — the destination is never echoed, masked or
not, so the portal cannot tell you which number it used; only the owner can.

**Not the shop line.** A code was requested on 2026-10-13 ~20:29Z and no Telnyx SMS appeared in
`dialpad_sms_cache` (newest row 19:54Z). So the 2FA number is an external mobile, not a business line
we ingest.

## Cloudflare Turnstile: Camoufox passes, headless Chrome does not

The sign-in form carries a `cf-turnstile-response` field. From `secratary-cloud`:
* Playwright + `/usr/bin/google-chrome` (155) headless, with or without a UA override or a faked
 `navigator.webdriver`, **never** receives a Turnstile token in 60 s; submitting anyway returns
 "Security verification failed. Please refresh and try again."
* **Camoufox** (Firefox, `pip install camoufox && python -m camoufox fetch`) gets a token in seconds
 and completes the whole flow. Use it for any Turnstile-protected portal.

Working recipe: `/root/_scratch/telnyx/probe8.py` — Camoufox (headless, humanize) → fill email →
"Send me sign-in link" → read the newest `portal@telnyx.com` mail through
`app.services.gmail_service` with **cwd `/opt/company`** (Settings resolves `data/gmail_tokens`
relative to cwd; from anywhere else the search silently returns zero accounts) → take the URL that
contains `token=` (the mail's first `portal.telnyx.com` link is a marketing URL) → navigate it.

Also measured: `app/services/gmail_service.search_messages_across_accounts` with the query
`subject:sign-in link` returns nothing although the mail exists — filter client-side on the subject
instead.
