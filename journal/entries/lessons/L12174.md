**L12174 · An ancestor-accumulating walk must not cap its depth: the cap silently truncates the shallow totals**

Built a one-pass scanner for ZABZ-YOGA that added each file's size to its ancestors but stopped after 5 dirname() steps. Every directory shallower than a file's depth-5 ancestor was under-counted, so C:\Program Files (x86) read 5.89 GiB / 3,531 files against a true 10.50 GiB / 61,639 files, and a child could exceed its own parent. Caught only by cross-checking one directory against Get-ChildItem -Recurse. Fix: depth cap 20, and always verify a new measuring tool against one directory whose size is already known a third way before trusting any number it prints.
