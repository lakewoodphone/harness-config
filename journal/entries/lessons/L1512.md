**L1512 · eBay refuses this machine — harvest eBay from desktop-ts, not from the Mac mini**

On 2026-09-15 the Mac mini (LAKEWOOECHSMINI) could not read eBay at all, two different ways:
1. web_fetch on https://www.ebay.com/sch/177/i.html?... -> HTTP 403, body 'Error Page | eBay ... Something went wrong on our end'.
2. Headless Chromium (Playwright 1.54, Chromium 139, real desktop UA) on the same search URL -> page title 'Error Page | eBay', body 'SORRY ... Something went wrong on our end'. Not a captcha, not a login wall: an outright block.

The shop's own harvester (~/personal-secretary-mvp/scripts/ebay_laptop_search.py) ran to completion and reported result_count 0 / candidate_count 0 with NO error, because it parses whatever HTML it gets. A blocked eBay therefore looks exactly like 'no laptops matched'. That is the dangerous part: the tool cannot distinguish 'eBay banned us' from 'nothing for sale', so a zero-result eBay harvest is not evidence of an empty market. Always eyeball the saved markdown or re-run the URL through a plain fetch to see the block page.

WORKAROUND THAT DID WORK, same session: Newegg. Both web_fetch and Playwright returned real Newegg search and product pages (HTTP 200) with prices, sellers and shipping. Newegg is a viable channel from this machine; eBay is not.

NEXT MOVE IF EBAY IS REQUIRED: run the harvester on desktop-ts (ZABZ-TECH, Windows) via ps-mesh — the owner already runs this pipeline there — or check whether eBay unblocks a non-headless/headed browser from this host.

EVIDENCE: eBay HTTP 403 via web_fetch 2026-09-15; Playwright title 'Error Page | eBay'; Newegg 200 on /p/pl and /p/<item> same session.
