**L3357 · A killed deploy leaves no image and no report - check for the image by sha**

An aborted backend deploy produced NOTHING: no lpt-lpt-backend:<sha> image on the box, an empty /opt/lpt/.deploy.json, and production still running the previous commit. The only tell was that 'docker images | grep <sha>' found no such tag.

Because docker images / .previous-image / .deploy.json are the only provenance, verify after ANY deploy that did not print its own report: (1) docker images | grep <short sha> exists, (2) /health .commit equals the sha, (3) grep the shipped bundle for a string you know is in the change. Measured 2026-10-07: production was silently one commit behind the fix and the deploy had 'succeeded' in the shell's eyes.
