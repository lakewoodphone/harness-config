**L1898 · The gateway's 'force the fast/cheap tier' alias is a tier FLOOR, not an equality**

Measured 2026-09-17 while writing docs/mesh/101-spend-guard-installed.md section 7.

personal-secretary-mvp/app/services/smart_router.py:796 defines secretary-fast as RoutePolicy(min_quality='low', min_tier='fast', max_output_cost_per_mtok=5.0). _capability_rejection (smart_router.py:1399-1416) rejects a candidate only when its tier rank is BELOW the required rank, with _TIER_RANK = {fast:0, mid:1, ceo:2} (line 693). So min_tier='fast' admits fast, mid AND ceo. The only money constraint on the whole policy is the 5.0 USD/M output cap, and deepseek-v4-pro is 0.87 so it passes. Ranking is capability x 0.7 + cost x 0.3 (line 2010), so the mid-tier/high-quality model beats the fast-tier/medium-quality one.

That is why the alias whose own description says 'Force the fast/cheap tier (tool-capable)' (ai_gateway.py:987) served deepseek/deepseek-v4-pro in doc 96's live probe - 3.3x the output rate of flash.

RULE FOR ANY FUTURE ROUTING WORK: in this router, min_* means AT LEAST. A policy that intends 'use the cheap tier' must get a max_tier ceiling or the model row's tier must change. Lowering max_output_cost_per_mtok to 1.0 does NOT work: 0.87 < 1.0.

The DSH fleet is unaffected today: re-verified 2026-09-17 that ~/.dsh/settings.yaml, settings/base.yaml, settings/machines/*.yaml and presets/** contain NO SECRETARY_API_BASE and no secretary-* route (one grep hit, the standing instruction's own prose), and agent-default-model is deepseek-official/deepseek-flash against api.deepseek.com direct.
