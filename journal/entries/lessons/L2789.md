**L2789 · A message must go to the phone the human actually reads: delivery target is not the identity field**

The owner, 2026-09-28: *"btw, i almost never monitor my google voice number, so if you want me to
see soemthing you have to send it to my personal number not my google voice"*

THE CONFIGURATION, which had been wrong the whole time:
 OWNER_PHONE_NUMBER = +17325691594 <- his GOOGLE VOICE line. He does not read it.
 OWNER_NOTIFY_NUMBER = +18483897895 <- his PERSONAL phone. The one that works.
 OWNER_ALT_PHONE_NUMBERS = +18483897895,+18482245096 (recognition only)

`app/services/owner_notifications.py::owner_notify_target()` already resolved this correctly and
prefers the notify number. `tool_factory.send_owner_update` already used it. But FIVE other
delivery paths went straight to `owner_phone_number` and therefore to the line nobody reads:

 1. `app/autopilot.py::_maybe_flush_owner_message_queue` -- the message-queue flush. This is
 where every `queued` and `held` row is drained, i.e. the main delivery channel.
 2. `app/sms_service.py::send_sms_to_owner`
 3. `app/sms_service.py` -- the security-alert roster (an intrusion page went to the wrong phone)
 4. `app/main.py` -- the urgent-operational-SMS escalation
 5. `app/main.py` -- the voicemail notification

MEASURED CONSEQUENCE, `sms_log` 2026-09-28: id 1019 (the held Chase-claim reminder), 1016 and 1012
all went to `+17325691594`. He never saw them. So every "one at a time" rule built on top of that
channel was decoration: the messages were correct and addressed to a phone nobody looks at.

Ranked lesson: **A delivery target and an identity field are different questions, and a config name
that says "owner" answers neither.** `owner_phone_number` was doing double duty -- "which number
means the owner when a text arrives" and "which number do I send to". Only the first is identity.
The moment the two diverge, an entire channel silently stops working and every metric stays green.

WHAT TO DO: delivery must resolve through `owner_notify_target()`. Recognition must keep using
`owner_recognized_numbers()` / `is_owner_number()`. Never fix one by repointing the other -- that
moves the failure into who counts as the owner.

PATTERN FOR NEXT TIME: when a message is "sent" but the human says he never saw it, check the
DESTINATION before the content.
