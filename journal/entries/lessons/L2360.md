**L2360 · Google Maps JSON extraction fabricates a full weekly hours table - trust the visible markdown; IG/FB are login-walled**

## Trigger

Owner asked whether two Lakewood clothing stores ("Finale Boutique", "Miri") were open tonight
and what their pre-Yomtov hours were. Research task, 2026-09-23.

## Lesson 1 — Google Maps JSON extraction FABRICATES the weekly hours table. Trust the markdown.

Asked `firecrawl_scrape` on a Google Maps **search** URL and on a resolved `/maps/place/...` URL,
both with `formats:["json","markdown"]` and an explicit hours schema.

Both JSON extractions returned a complete, confident, seven-row weekly table for Finale Boutique:

```
Monday: Closed / Tuesday: Closed / Wednesday-Saturday: 10:30 AM-6 PM / Sunday: Closed
```

**Every row of it is wrong.** The markdown returned in the *same response body* contained only
Wednesday's hours and the line `Closed · Opens 10:30 AM Thu` — Google's logged-out Maps view
renders one day, not seven. The model filled the other six rows from nothing.

What the truth actually was, per four independent sources (MapQuest, Loc8NearMe, Yahoo Local,
Waze, plus Facebook's own page): Mon-Thu 10:30-6, Fri 10:00-12:45, Sat closed, Sun 11-5 — i.e.
open Monday and Tuesday, closed Saturday.

Also note the tell I ignored at first: the search-URL scrape's `og:image` static map was centred
on **38.44,-122.67 (California)** — the page had not resolved to the Lakewood place at all, and the
extraction still produced a plausible table.

**Rule:** when scraping Google Maps for business hours, read the returned `markdown`, not a
schema-filled `json` blob, and treat any *structurally complete* answer as suspect when the page
was only partly rendered. Verify the resolved map centre resembles the real address, and
cross-check against at least one non-Google aggregator before reporting a number to the owner.

## Lesson 2 — Instagram and Facebook are login-walled to every tool I have.

- `firecrawl_scrape` → refuses Instagram and Facebook outright ("we do not support this site").
- `jina read_url` → returns the Instagram *login* page, and a Facebook page body only when the
 page is old enough to have been publicly cached (a 2016-post page rendered; the active page
 returned a login screen).
- Google **search-result snippets** for `instagram.com/<handle>` did leak the profile bio — which
 is how the store's WhatsApp number was found — but not post captions or stories.

**Consequence:** for small local businesses, holiday/extension hours usually live only in
Instagram stories or WhatsApp status. That evidence is unreachable from this harness. Say so
plainly and hand the owner the phone/WhatsApp number rather than guessing at extended hours.

## Lesson 3 — Lakewood store hours: which sources are worth the call.

One scrape each, cheapest first:

| Source | Verdict |
| --- | --- |
| MapQuest place page | **Best.** Renders a live `Closed until Thu 10:30 am` line plus full week. |
| Google Maps `/maps/place/...` **markdown** | Good for the live open/closed line and today only. |
| Loc8NearMe | Matches MapQuest; carries real phone numbers and addresses. |
| Yahoo Local / Waze | Independent confirmations of the same numbers. |
| The store's own website | Only if it actually loads — check TLS before trusting absence of hours. |

Finale Boutique's own domain `finaleboutique.com` (a Shopify store) is **down**: DNS resolves to
Shopify, HTTPS fails TLS, and `finaleboutique.myshopify.com` serves "This store will be right
back". A broken own-site is not evidence about the physical store — the physical store is fine.
