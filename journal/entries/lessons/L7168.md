**L7168 · Win+H shadowed by Handy; single-chord global hotkeys conflict silently**

SYMPTOM (ZABZ-YOGA, 2026-10-16): pressing Win+H stopped opening Windows voice typing ('Talk to Text').

CAUSE, proven from Handy's own log: Handy (pais, v0.9.8, C:\Users\ezabz\AppData\Local\Handy\handy.exe, autostarts via HKCU Run) had its 'transcribe' binding set to 'super+h' = Win+H, and registers it as a GLOBAL hotkey. Log line: [2026-10-16][09:46:54][handy_app_lib::shortcut::handy_keys][DEBUG] Registered handy-keys shortcut: transcribe -> Hotkey { modifiers: Modifiers(CMD_LEFT | CMD_RIGHT), key: Some(H) }. Every Win+H press after that went to Handy's recorder. Windows voice typing was never broken: TextInputHost runs, MicrosoftWindows.Client.CBS 1000.26100.360.0 is Ok, ctfmon running, no crash in the event log.

WHEN IT CHANGED: Handy was installed 2026-10-15, its exe/resources/uninstall.exe were rewritten 10-16 04:45, it restarted 05:46:53, and settings_store.json has current_binding super+h from then. Backup timeline: .bak2 (04:58) = ctrl+space + onboarding false; .bak (05:09) and current = super+h + onboarding true. So the user chose Win+H while completing onboarding.

FIX APPLIED: rebound Handy's transcribe to 'ctrl+space' (Handy's own default_binding for that action) and restarted Handy. Verified: new registration line at 14:53:20 = Hotkey { modifiers: Modifiers(CTRL_LEFT | CTRL_RIGHT), key: Some(Space) }; the CMD+H line no longer appears after the restart.

RULES FOR NEXT TIME:
1. A chord that stops opening a Windows feature is almost always a second app having taken the chord as a global hotkey. Go to the app that arrived last. Do not start by debugging the Windows feature.
2. Handy's evidence trail is: C:\Users\ezabz\AppData\Roaming\com.pais.handy\settings_store.json (bindings.<id>.current_binding) for intent, and C:\Users\ezabz\AppData\Local\com.pais.handy\logs\handy.log for \Registered handy-keys shortcut\ + \handy-keys event ... state=Pressed\ lines, which show exactly which app received the keystroke and when. .bak/.bak2 siblings give the setting's history.
3. Stop the app before editing settings_store.json (it holds settings in memory and would overwrite a live edit), then restart it, then re-read the log for the new registration.
4. PowerShell process scans that filter on guessed names MISS things: a scan for 'whisper|wispr|handy' as a NAME pattern did not surface the \handy\ process; match on Name with an explicit list, and always check HKCU Run keys for what autostarts.
5. Unrelated open item on this host: KB5121794/KB5127648/KB5127647 installed 10/15 with RebootPending=True and WU RebootRequired=True; last boot was 10/14 22:28. The machine is due a reboot.
