**L2787 · A per-branch test gate is a false green - gate on the pre-existing tests that touch the same modules too**

## LESSON — a per-branch test gate is a false green; gate on the pre-existing tests that touch the same modules too

**Measured 2026-09-28, company-evolution fleet on `personal-secretary-mvp`.**

I merged 13 branches and gated each merge on the tests **that branch added or changed**. That gate
caught nothing wrong, and let a real regression through into a production deploy.

**What happened.** W6 (model routing) changed `app/pricing.py`, `app/services/smart_router.py`,
`app/config.py` and `app/services/model_registry.py`. Its own new file
`tests/test_co_w6_acceptance.py` passed (75 tests), so the merge was accepted and **deployed**. The
deploy script then ran the changed-test set on the authority, where
`tests/test_smart_router.py` — a **pre-existing file the branch never touched** — went
**`7 failed, 38 passed`**. The deploy gate correctly refused to restart, and the live tree had to be
rolled back from the backup the deploy had just taken.

**Root cause of the regression.** W6 added runtime validation of model ids against the gateway
catalogue. The pre-existing tests are built on synthetic ids (`deepinfra/test/cheap-high`,
`google/test-expensive-high`), which the new validation rejects as `not_in_gateway_catalogue:<id>`.
On the Windows worktree no gateway catalogue exists, so the tests passed there; on the authority one
does. The failures are NOT test-order pollution — the same 7 fail with
`pytest tests/test_smart_router.py` run on its own. Check that before blaming isolation.

**Rule 1 — gate on the union, not the delta.** A branch's gate must run (a) the tests the branch
touched, **and** (b) the pre-existing tests that already import the modules the branch touched.
Mapping module → test by basename is too broad (it drags in unrelated reds and caused three spurious
rejections earlier the same session); mapping nothing is too narrow and caused this one.

**Rule 2 — local green is not production green.** The same commit passed on Windows and failed on the
Linux authority, because the authority has a real `.env`, a real gateway catalogue, and real data.
Any change that reads ambient configuration must be gated **on the target host**, not in the
worktree. A deploy script that runs its tests on the target before restarting is what turned this
from an outage into a rollback.

**This is the same class as the estate's original sin**: a number that looked like proof and was not.
`75 passed` was true and it was not evidence.
