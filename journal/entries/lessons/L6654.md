**L6654 · A failing push can report rc=0: journal-commit exits 0 after a rejected push when nothing is staged, so the log is the evidence**

**A failing push can report `rc=0`. The log is the evidence; the exit code is not.**

Correction and sharpening of `L6590`, found by reading the log instead of trusting the run rows.

```
2026-10-16T02:45:04Z [ahead] the remote is behind (remote 1214720, local 59a04b7) - pushing
2026-10-16T02:45:06Z [failed] push to vault main -- ! [rejected] HEAD -> main (non-fast-forward)
2026-10-16T02:58:04Z [commit] 1 path(s) on journal at 76c45f2d
2026-10-16T02:58:07Z [pushed] 76c45f2d published to .../harness-config.git journal (remote HEAD read back and matches)
2026-10-16T03:00:10Z [commit] 5 path(s) on journal at 16461ba7
2026-10-16T03:00:19Z [pushed] 16461ba7 published to ... journal (remote HEAD read back and matches)
```

`~/.cron-status/runs.tsv` records `2026-10-16T02:45:01Z journal-commit rc=0` — **and the push at that
tick failed.** The exit contract of `journal-commit.sh` is: it tries the push, prints `[failed]` when the
push is rejected, and then falls through to `if [ -z "$(git status --porcelain -- journal)" ]; then exit 0`.
So a tick with a rejected push and nothing left to commit exits **0**, and the cron layer records success.

**Why this matters more than the incident.** `P4697` was filed from the log; `cron-failures.py` counts
*n consecutive non-zero rows* — and this job can interleave `rc=0` rows into a failing streak, which is
how 158 non-zero rows sat alongside rc=0 ticks for two and a half days. **A job whose failure is louder in
its log than in its exit code is invisible to everything that watches exit codes**, and this estate watches
exit codes: `cron-wrap.sh` → `runs.tsv` → `cron-failures.py` → the wake loop. The `[pushed] … remote HEAD
read back and matches` line is the only thing here that is a measurement, because it re-reads the remote.

**Rule for anything publishing from this estate:** a push is verified by reading the remote ref back and
comparing, never by an exit code and never by the word "pushed" in a log line the same script wrote. That
is the shape `journal-commit.sh` already uses in its success path — the defect is only that its *failure*
path does not set the code.

**NOT fixed here.** Changing `journal-commit.sh`'s exit contract means deciding what a push-with-nothing-
to-commit should report, and it is deployed-only (there is no repo copy — `ls
/root/code/harness-config/scripts/journal-commit.sh` is not found). Filed as a way of reading it, not as a
repair.
