**L2136 · L2150 - a test written against a fix can pin the fix's SHAPE and block the next correction**

Concrete instance, measured 2026-09-20.

To fix mashgiach's silently-lost findings I took `BEGIN IMMEDIATE` before the first read, and wrote a
test to pin it:

 assert lock_at < read_at, (
 "the write lock must be taken BEFORE the first read; taking it after reproduces "
 "SQLITE_BUSY_SNAPSHOT, which busy_timeout does not cover"
 )

One round later, measurement showed that shape was wrong: holding the lock across `daily_scan`'s four
SELECTs blocked every other writer and produced **31 `database is locked` errors in a single minute**.
So the lock moved to immediately before the write - and my own test then FAILED against the corrected
code, because it was pinning the shape of the first fix rather than the property being protected.

The distinguishing question is: **what is this test defending?** Here the property was "the insert does
not have to upgrade a read snapshot". Both shapes satisfy it; only one is cheap. The assertion had
grabbed the shape.

**How to tell them apart.** A property test survives a re-implementation; a shape test breaks when the
code is improved. If a test fails after a change that measurement endorses, check whether the test is
asserting a *property* or an *incident* before "fixing" the code. Revising the test is correct here -
and the revision must carry the reason, so the next person does not re-derive it. The revised
assertion now pins both ends:

 lock_at < write_at # the lock is held when the write happens
 lock_at > first_read # ...and it does not span the reads (which cost 31 lock errors)

That is a property plus the measurement that shaped it. It would survive a different implementation
and it will not silently permit a regression to either failure.

**Corollary for this session generally:** I wrote a lot of tests today in a hurry. They have already
caught one stale assumption in a sibling file, which is the mechanism working - but the failure mode to
watch is a test that encodes WHAT I DID rather than WHAT MUST BE TRUE.
