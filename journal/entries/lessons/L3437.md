**L3437 · A script ending in top-level await main() is entry-only - never import it in a test**

A script that ends in a top-level `await main()` is ENTRY-ONLY. Importing it runs it.

Measured on ZABZ-YOGA 2026-10-09 while writing `scripts/__tests__/verify-deployed-commit.test.mjs`:
one `import { FRONTEND_COMMIT_STAMP_PREFIX } from '../verify-deployed-commit.mjs'` silently ran
the whole verifier against `https://test.lakewoodphoneandtech.com` - a live network call from a
unit test - and left `process.exitCode = 1`, so `pnpm test:deploy-verify` reported 16/16 pass and
still exited non-zero. It was visible only as a stray verification block above the first checkmark.

The fix used here, and the rule: read the constant out of the source text instead of importing it,
and drive the script as a CHILD PROCESS - which is what that suite already did for every real case.

Do NOT "fix" it by making the module import-safe with an entry-point guard
(`import.meta.url === pathToFileURL(process.argv[1]).href`). A symlinked invocation makes that
comparison false, and the script would then do nothing and exit 0 - a deploy verifier that reports
success without verifying, which is the exact defect it exists to catch. Fail-open guards on
load-bearing verifiers are worse than the footgun they remove.

Applies to every file under `scripts/` that prints a result and sets an exit code.
