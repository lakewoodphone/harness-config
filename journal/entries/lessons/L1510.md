**L1510 · Answer a live case question from the newest communication, not the case file**

Answer a live case question from the newest communication, not from the case file.

WHAT HAPPENED. Eliyahu asked "weissman 8482993187 — pull up that case file". The case
file was complete, well written, and (per its own front-matter) correct as of 2026-09-03:
300DDR chances form submitted, estimate received, a price discrepancy flagged, NEXT =
"confirm which quoted price applies, then submit the Mail-In form". Reading it, the case
looked parked and awaiting a decision. It was not. On 2026-09-14 19:22 UTC Eliyahu had
called the customer, quoted $800 recovered / $160 not at ~65%, and the customer said
"mm-hmm I'll do it". The real next action is booking + shipping, and the case had been
stale for 12 days.

WHERE THE TRUTH WAS. Not in any file: in `dialpad_call_full` in the secretary DB on
secratary (transcript, 348 s, external_number +1848293187). 25 calls and 25 SMS rows for
that number; the newest call was the decisive one.

THE RULE. The case file is the authoritative record of what has been WRITTEN DOWN. It is
not the authoritative record of what has HAPPENED — the shop's last mile is voice, and
voice lands in the call log, not in a repo. So for any live case question: pull the case
file for structure/state/money, then check the newest calls and SMS for that number
before answering, and write the delta into the case file in the same turn.

HOW, concretely, on ZABZ-TECH (no grepping needed, ~seconds):
 dialpad_call_full WHERE external_number LIKE '%<last7>%' ORDER BY date_started_ms DESC
 dialpad_sms_cache WHERE phone_normalized LIKE '%<last10>%' ORDER BY created_at DESC
Rows appear duplicated (2 harvest passes ~1 min apart) — GROUP BY date_started_ms.
Convert date_started_ms/1000 to UTC before believing it is recent.

A near-miss worth naming: I did not report the stale state, but I nearly did. The only
reason I did not is that the case file's own NEXT line said "confirm which quoted price
applies" — an open question that a 12-day-old file had no business still containing.
