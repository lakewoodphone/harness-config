**L5921 · Two honest numbers from two stores under one word: todo=17 vs 1 item(s) remaining**

Two surfaces reported the SAME lpt-website backlog as two numbers that a reader cannot tell apart,
and both were right. Measured 2026-10-16 on secratary-cloud.

 `autonomy-status.sh` -> lpt-website todo=17 running=0 done=44
 `project-keepalive.py --dry-run` -> lpt-website flagged (1 item(s) remaining)

The predicates are different and neither label says which store it measured:
 * 17 = `work_item` rows in state `todo` in the LEDGER (/root/work/work.db).
 Ledger breakdown, same moment: done 44, todo 17, dropped 3, blocked 2.
 * 1 = `len(remaining)` from the project's STATE FILE (/home/zabz/.wake-projects/lpt-website.json),
 read by `work_remaining()` at project-keepalive.py:290-297.
 Verified the type rather than trusting a shell: python says `type=list, len=1`.

WHY IT MATTERS: a 17-item backlog is reported as "1 item(s) remaining" by the line that decides
whether to spend money on a shift, in a system whose own contract says the ledger is the only place
work lives. The number deciding the branch is honest; the sentence around it is not.

THE RULE THIS BELONGS TO: print the raw value next to the predicate AND name the store. "todo=17"
and "1 remaining" become a reading the moment they say "17 ledger todo rows" and "1 entry in the
state file's remaining list". Until then they are two facts wearing one word.

TRAP IN MEASURING IT: PowerShell's ConvertFrom-Json UNWRAPS a single-element JSON array, so
`$j.remaining.GetType().Name` said `String` while the file really holds a one-element list. It
reported `(1 item(s) remaining)`, which is `len()` of a list — that inconsistency is what made me
re-check in python. Read JSON with python when the TYPE decides anything.

SAME SHAPE, MEASURED THE SAME DAY, IN THE SIBLING STORE: `.wake-projects` had split across three
directories on two machines, and /home/zabz/.wake-projects/housekeeping.json (8429 B) vs
/root/.wake-projects/housekeeping.json (22780 B) were not stale versions of each other but two
different documents — `work_remaining` a BOOLEAN in one and a STRING in the other, with disjoint
key sets (remaining/shift_lesson_* vs facts/finding_*/updated_by). Two producers, one filename, no
arbiter. A state file written to the directory no consumer reads is work that never landed, and it
looks exactly like a state file that was never written.
