**L1833 · A sandbox rule that blocks egress silently blinds the service it protects (mesh-broker, secratary)**

A sandbox option that blocks EGRESS silently disables the service it was added to protect.

MEASURED 2026-09-17 03:42Z on secratary. I installed the mesh broker as a systemd service and added
`IPAddressDeny=any` + `IPAddressAllow=localhost` so the owner's loopback-only rule would be enforced
in the kernel rather than by a `--host` argument. IPAddressDeny/Allow apply to egress as well as
ingress, so the broker could no longer reach any node:

 zabz-tech / zabz-yoga-1 / zabz-tech-linux / secratary: unreachable,
 "timed out after 4000 ms (hard wall-clock deadline)", readFailures 8/8

and the install script reported **19 passed, 1 failed** — the one failure being a bug in my own
grep. Everything else was green: the port, the loopback rule, all four verbs, a supervised restart,
a SIGKILL restart. **The broker could not see a single node and the install said 19/20.**

Controlled experiment, which is what turned a guess into a fact:

 systemd-run -q -p IPAddressDeny=any -p IPAddressAllow=localhost curl ... zabz-tech gate -> 000
 curl ... the same URL outside the sandbox -> 200
 systemd-run -q -p IPAddressDeny=any -p IPAddressAllow=localhost curl 127.0.0.1:3086 -> 200

`SocketBindDeny=any` + `SocketBindAllow=127.0.0.1:3091` is the tool that WOULD have restricted the
bind without touching traffic, and every documented spelling (`:3091`, `127.0.0.1:3091`,
`ipv4:127.0.0.1`, `ipv4:127.0.0.1:3091`, `tcp:127.0.0.1:3091`) is rejected by this systemd with
`Failed to parse SocketBindAllow= value ...: Invalid argument`.

RULES.
1. For any service that makes outbound connections, an address filter is an outage waiting to
 happen. Loopback-only for a LISTENER is a property of the bind, and that is where it belongs.
2. The assertion that matters is the service DOING ITS JOB, not the service being up. "Port
 answers" passed while the broker was blind. `install-authority.sh` now asserts "the service can
 read the mesh" by name and fails the install if no node answers.
3. Never add a sandbox knob you have not tested against the service's purpose. Ask: what does this
 service do that this rule could stop?

Applies to every future unit in this fleet: the gate, the phone engine, the dashboard.
