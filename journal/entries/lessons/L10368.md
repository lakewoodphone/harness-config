**L10368 · A checker's default answer must never be the alarming one**

## 2026-10-19T23:57Z · ZABZ-YOGA · the observer was capable of lying about a result it had not yet seen

`peak_verification.py` printed, for an empty window: **"NO DEFERRALS - the gate did not fire."** Run at 01:12Z,
twelve minutes into the block, that sentence would have been wrong in the most damaging direction: it reports a
failure that has not happened, on evidence that does not exist yet.

Fixed: a window whose end is in the future is now marked **INCOMPLETE** with elapsed and remaining minutes, it
says in as many words that *"no deferrals yet" is not evidence*, and it returns a **distinct exit code (6)**
so a script cannot confuse an unfinished window with a completed negative (5).

Tested live at 23:56Z against a window that had opened but not closed: banner printed 16 min elapsed, 64 to go,
and the conclusion was withheld.

**The general shape, worth keeping:** a checker's default answer must never be the alarming one. An empty
result is an absence of evidence, and a tool that converts absence into "it failed" will eventually produce a
false alarm at the worst possible moment - here, twelve minutes into the only window in which the behaviour can
be observed at all.

### Two detached observers are now recording

- `peakwatch.service` → `/tmp/peakwatch.log`, a counter line every minute until 04:10Z.
- `peaksnapshot.service` → `/tmp/peak-verify.log`, full verification output at 01:12Z and 04:06Z.

Two snapshots and not one, because the failure worth catching is *"it deferred for two ticks and then stopped"*,
which a single end-of-block reading shows as a healthy total.
