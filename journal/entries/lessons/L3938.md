**L3938 · Allow the domain was the wrong question: one CDN carried both the asset we wanted and the update we did not**

**L · "Allow the domain" was the wrong question: the same CDN carries both the asset we wanted and the OS update we did not**

WHAT HAPPENED, 2026-10-14. The requirement looked like a domain decision — allow Apple's software-update CDN so the
on-device dictation model can download. But the same three hosts (`updates.cdn-apple.com`,
`updates-http.cdn-apple.com`, `appldnld.apple.com`) deliver iOS updates and restore images, and opening them makes a
fleet self-updating that had no update policy at all. Both answers were wrong.

The right answer needed one measurement, not an argument. Fetched from Apple's own public catalogues:

- `com_apple_MobileAsset_EmbeddedSpeech` — the dictation models — **80 entries**
- `com_apple_MobileAsset_SoftwareUpdate` — the over-the-air OS payloads — **2,532 entries**
- **Assets using a `/mobileassets/` path: 35 of 80 for dictation, and 0 of 2,532 for OS updates.**

So the split exists, it is made by **path**, and it is made at the **PAC** — because a DNS allowlist sees a name and
structurally cannot see a path. That single count turned an unresolvable policy trade-off into a four-line rule.

RULES:
1. **"Open the domain" is almost never the unit of decision.** Ask what else that host carries before deciding, and
 look for a layer that can see the *path*. A name-level allowlist is the wrong instrument whenever one host serves
 two things with different risk.
2. **Fetch the provider's own index rather than reasoning about its naming.** Apple publishes signed catalogues of
 every asset with `__BaseURL` and `__RelativePath` in them. The answer was a count from primary data, and no amount
 of reading documentation or forum posts would have produced it.
3. **The trap in the obvious rule:** an over-the-air OS update *is* a MobileAsset
 (`com_apple_MobileAsset_SoftwareUpdate`), so any rule that matches on the string `MobileAsset` opens exactly the
 door it means to close. The separator is the segment: `/mobileassets/` versus `/patches/`.
4. **State the convention's status.** Apple publishes no path contract for this CDN. The rule is safe today because
 it is measured today, so it needs two alerts — no asset fetch in N days, and a version change the fleet did not
 choose — or it becomes a silent failure later.

EVIDENCE: `deploy/waze-mdm/docs/voice-input/10-block-updates-allow-assets.md` (master `eb0cef81b`); the two
catalogues fetched live 2026-10-14 from `https://mesu.apple.com/assets/<AssetType>/<AssetType>.xml`.
