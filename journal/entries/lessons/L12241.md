**L12241 · Paying a customer is the pay rail, never a text I write: check lpt-web doctor first, and a MANAGER login is a human's job**

Owner, 2026-10-21, after I drafted a pay text by hand: "no, i'm talking about the payment flow, why do you always not do that".

THE RULE. When the owner asks for a customer to be told what they owe, the deliverable is the PAYMENT RAIL, not a message I write. The rail is three commands in lpt-ops, and it is the only sanctioned way:

 lpt-web owe-notice --order <WO> balance read from the order, reuse-or-mint exactly ONE live link
 lpt-web pay-notice draft --order <WO> write the draft for an order that never got one
 lpt-web pay-notice approve --draft <id> --apply THE SEND - the only command that messages

A hand-written body around it is the failure this rail exists to prevent (the 2026-10-14 session that wrapped a static Stripe link copied out of an old case file was rejected the same way).

FIRST ACTION, ALWAYS: `lpt-web doctor`. It costs one call and separates three states that look identical in a chat: PRESENT and working, present but dead, and absent.

 every rail command exits 1/3 at the credential, dry run included. NO CREDENTIAL, nothing attempted.

Prior state, from lpt-ops/docs/web-parity.md (measured 2026-10-14): the token WAS there and was a well-formed unexpired phone-and-tech-refresh JWT for agent-verification@ (users.id 300, MANAGER), but its refresh_tokens row (id 3270) was isRevoked=true. Re-sending a revoked refresh token makes the API call revokeUserSessionsOnReuse, so it must never be replayed. Today the line is gone entirely.

HOW IT IS FIXED, and why an agent cannot: `lpt-web login --email agent-verification@lakewoodphoneandtech.com` reads the password from a TTY only - never an argument, never a file, never echoed - and refuses with exit 4 when stdin is not a terminal. `payNotices.approve` is a managerProcedure, so a MANAGER credential is required. That makes provisioning a ONE-HUMAN action: the owner runs the login in his own terminal, or a manager does. An agent that cannot do it must say so in the first sentence, not produce a message and mention the gap in passing.

SO: if doctor says ABSENT, the answer to "send them the payment text" is "the payment rail needs a staff login on the authority; run this one command, then I do the rest". It is never a drafted body with the link missing.
