ONE DEPLOY PATH: .github/workflows/deploy-env.yml, self-hosted, 3 jobs preflight -> backend ->
frontend+verify. It already implemented every required guarantee: ancestor check, served-asset
changed, live bundle SHA256 == build bytes (sha256OfBytes in scripts/verify-deployed-commit.mjs),
22P02==0 with an EMPTY LOG = FAILURE, and a Stripe publishable-vs-target mode guard. I added
--require-commit (asserts the LIVE host reports github.sha) and moved all credentials host-local:
/etc/lpt-deploy/env (600, ghrunner) holding CLOUDFLARE_API_TOKEN, CLOUDFLARE_ACCOUNT_ID,
LPT_APPS_HOST, STRIPE_SECRET_KEY_TEST, STRIPE_SECRET_KEY_PRODUCTION. The Stripe key must be
PER TARGET because the guard compares the publishable key's mode with the secret key's mode - a
live secret handed to a `test` deploy is refused by design. The publishable key stays in BASE_ENV
in scripts/lib/frontend-deploy-config.mjs (its own comment demands that).

host, so it is the owner's call, not mine.
