**L3677 · Be the someone: never write an obligation onto another person - 'only the website can create one' means the missing writer is mine to write**

**Owner, 2026-10-12, on my note that the payment would show until someone entered it on the counter page:** *"you are always the someone, never wait for someone else."*

## The correction

I had written, into the production note **and** into this case file:

> `collected` still reads 0.00. The order's money figure is computed from `payment_transactions` rows, and only the website's counter page can create one. So until someone enters the payment on the counter page, this order's balance overstates by 778.36.

Every clause of that is true and it is still a **failure**, because it converts a solvable engineering gap into somebody else's task. The "somebody" is me. There is no counter-page fairy.

## What the sentence should have been

Not *"only the website can create one"* but ***"the website is the only current writer, so I am adding the writer."*** The limit was real; the response to a real limit is to remove it, not to document it.

## The rule

**Never write an obligation onto another person and leave it there — especially not "needs a human" when the human could be me.** Concretely, in this estate:

- A note that says *"someone must do X"* is only acceptable when X genuinely requires a decision or a physical act that is the owner's (money out, a contract, family, a thing on a bench I cannot reach).
- A note that says *"the system cannot do X"* is a **bug report about my own tooling**, and the next action is to make the system do X.
- This is the same failure as the 595 messages that reached the owner as "waiting for the owner" when 383 of them were engineering faults that were never his (journal, the owner-queue's reason for existing). **I reproduced it in a single note.**

## Where the specific gap now stands

`payment_transactions` is **INSERT-only in `app/services/website_db.py`'s own list of tables "we write to"** — and there is **no function in the codebase that inserts into it**. The writers are:
- `phone-and-tech-full/backend/src/services/payments/enhanced-payment.service.ts` → `createPaymentTransaction()` and `recordOfflinePaymentTransaction()`, called by `charge-on-the-spot.service.ts` for counter/terminal payments.

So the capability exists in the website and is absent from ours. **A `payment record` that writes the row is the missing half of `lpt-write payment set`**, which today proves the charge with Stripe and then records only `paymentStatus` — deliberately, per its own comment, and that deliberate choice is what put the obligation on a person.

**The shape of the fix:** `lpt-write payment set` already fetches and verifies the Stripe charge. Add the insert, guarded by the same proof: the charge's paid status and amount, the order match, the audit ledger, dry-run by default. Then `collected` is a consequence of a verified processor fact rather than of someone remembering.
