**L1857 · Mesh acceptance: a dispatched child is a PROCESS, and three naive counters each produced a false verdict in one night**

MEASURED 2026-09-17, all on ZABZ-YOGA. (1) mesh-run's verifier required the literal token 'MESH-HOST:' in the PARENT's summary while the provider teaches children a form the parent reports as 'MESH_HOST=<host>' - so a run whose six children all ran on the named node scored 0 of 6 and exited 1. (2) Its exit gate then read the pre-fix variable while verify read the new one: verify said meshHostLines:6 ok:true and the next line exited 1 with 'only 0 MESH-HOST lines'. (3) A harness counting 'MESH-HOST:' occurrences counted the transport wrapper's own echo lines: 3 lines for 1 child. (4) Counting dsh-subprocess-local workers as client load produced a false 'the client ran the fleet' - 11 of them sit on this laptop with NOTHING dispatched, and they moved 8->12 during a run whose six children were demonstrably on zabz-tech. (5) The runner detector originally excluded the engine by '--profile web', but the engine is 'bin.js web --port 3099 --no-open' with NO --profile, so it counted the owner's live engine (pid 1784) as a dispatched child. RULE: before believing ANY red result - including from your own tool - print the raw string it matched and the process table it read.
