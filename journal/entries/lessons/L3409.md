**L3409 · A second source derived from the first is not a second source — the comms index is built from secretary.db**

## A "second source" that is derived from the first is not a second source

MEASURED 2026-10-08, on secratary, while cross-checking the shop's money/customer report.

I had verified the money three ways but had taken the customer/outreach numbers on trust from one
query. When challenged, I set out to triangulate and reached first for `~/.fsearch/comms.db` — the
222 MB full-text index of every text, call and voicemail. It agreed closely with the local Dialpad
tables (45 inbound callers vs 46; 21 vs 20 SMS senders). That looked like corroboration.

It was not. **The index's own `meta` table says `source=/home/zabz/personal-secretary-mvp/data/secretary.db`.**
It is built FROM the same tables it appeared to confirm — a second *view*, not a second *measurement*.
Agreement between them can only ever prove the index is not corrupt. It cannot detect a defect in the
source, which is the only thing worth detecting.

THE RULE: before calling something a cross-check, read its provenance and ask *"what would have to be
wrong for these two to agree?"* If the answer is "nothing, they are the same data", it is not a check.
`fa data` / the comms index / `ps_comms_*` are all one lineage derived from `data/secretary.db`.
Genuinely independent lineages for shop money are: **Stripe's own API**, **the bank (Plaid →
accounting.db)**, and **the app's Postgres**. Independent lineages for customer contact are:
**the local Dialpad harvest** vs **the website's communications push into production**.

WHAT THE REAL CROSS-CHECK FOUND (all read-only):

- Calls today: local Dialpad harvest 46 people; production `communications` 45 people. SMS senders:
 20 vs 20. Two independent pipelines agreeing to within one call.
- The report's own outreach figure for today was **52 when it ran at 22:40 and 54 when I re-ran it at
 23:15** — and my hand-recomputation from the local tables gave exactly 54. The "disagreement" was
 thirty-five minutes of live phone traffic, not a bug. **A moving source must be compared to the same
 instant, or the difference you "find" is just time passing.**
- Money: the ledger's `stripe-charges` source matched **Stripe's own API to the cent on every day from
 2026-09-29 to 2026-10-07.** September's ledger Stripe gross was 61 charges / 7,347.69 — identical to
 the API's 61 / 7,347.69.

CHEAPEST DETECTOR for the next instance: `sqlite3 ~/.fsearch/comms.db "select key,value from meta"`
before quoting the comms index as evidence for anything.
