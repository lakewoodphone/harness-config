**L2392 · pwsh eats dollar signs inside double quotes - it silently corrupted a customer case record**

Measured 2026-09-22, lpt-hub, ZABZ-YOGA.

I recorded a customer quote by running: python tools/customer/cli.py edit "<case>" --activity "Owner quote: **$35** ... $23.88 ..." from a pwsh tool call. PowerShell expanded every $token inside the double-quoted string as a VARIABLE, and because $35 / $23 / $88 are undefined it substituted EMPTY. What landed in the append-only customer case file was:

 - Owner quote recorded 2026-09-22: **\**, ... off the \.88 invoice ... about \.64 ...

Every dollar figure was destroyed. The command exited 0 and the tool printed a clean "changed:" diff, so nothing in the output indicated corruption - I only caught it by reading the file back.

Rules from this:
1. Never pass money, code, or any text containing a dollar sign as a double-quoted argument in a pwsh tool call. Use SINGLE quotes (PowerShell does not expand those), or a single-quoted here-string, or do not use the shell at all.
2. The in-process edit tool does NOT expand anything - it is the safe way to write literal text containing a dollar sign.
3. This applies to journal.py append --body too, and to every other CLI that takes prose.
4. Always read back what a CLI appended to a record. A zero exit code and a tidy diff are not evidence the bytes are right.

Fix applied: rewrote that one activity section with the edit tool. Everything else in the case file and the sync record was written with the edit tool and is intact.
