**L12288 · A rollback that fires after delivery makes the delivery wrong - send through the most-guarded channel first**

**A rollback that fires after delivery makes the delivery wrong. Send through the most-guarded channel first.**

2026-10-22 22:45Z, the first real door-code rotation. Every gate passed in order — deadbolt slot 1
confirmed by the lock, slot 4 confirmed, the four Home Assistant helpers written and read back — and
then the two parents were texted their new code:

 SMS to +17326745878 status=delivered sid=SM305f7525…
 SMS to +17326747491 status=delivered sid=SM67a9d7d5…

The third message, to the owner, was refused by the company's own owner-text relay:

 FAILURE: owner SMS not accepted: [suppressed] owner_text_relay refused (SUPPRESS):
 internal prose, not a message to a human -- class path, matched "/root/.phoenix-pin-rotation/."

The body had ended with "Copies in /root/.phoenix-pin-rotation/." — a path, which the relay is right to
treat as machine text rather than a message to a person. The script's contract is atomic, so it did
what it was built to do: restored the four helpers and republished the OLD codes to slots 1 and 4.

**The rollback was correct and the outcome was still wrong.** Two people had been told "your code is
X, the old one stopped working just now" and held a code that was void eight seconds later. The design
had reasoned about delivery failure and never about *ordering*: it sent to the least-guarded channel
first (plain Twilio to two phones) and the most-guarded channel last (a relay with a content filter),
so the only failure that could arrive after the point of no return was the one that arrives late.

**What fixed it, and what to do instead.** A second run at 22:47:47Z with the path removed from the
owner's message, a correction line prefixed to the parents' message ("ignore the code I sent a few
minutes ago, that one is void"), and all three messages delivered. Verified afterwards by comparing
the delivered body against the live helper: the code in the text is the code on the door.

**The rules, both of which would have prevented the incident.**
1. **Order multi-recipient sends by how guarded the channel is, not by who matters most.** The relay,
 the approval gate, the quota — anything that can refuse — goes first, because a refusal there is
 cheap and everything after it has not happened yet.
2. **A refusal that arrives after a human has been told is a COMMIT, not a rollback.** The secret has
 already left. Rolling the code back turns a delivered message into a lie about a door. In that
 state the only correct move is forward: keep the codes, send the correction, and record it.

**And one layer up, the same session, the same shape.** The unit's first run died instantly on
`RuntimeError: no owner phone number configured` because the systemd unit had no `WorkingDirectory`,
so pydantic found no `.env` — and every `--dry-run` I had run from a shell in `/opt/company` passed.
**A dry-run of the script is not a test of the unit.** The thing that runs at 4am is the unit: run
`systemctl start`, read `journalctl -u`, and fix what only appears there. A daily tick that refuses
because it is not due must also exit 0, or it sits in `systemctl --failed` thirteen days out of
fourteen and teaches everyone to ignore the list.
