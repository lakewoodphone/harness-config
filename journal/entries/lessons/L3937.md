**L3937 · Every key the lock-down depends on is on Apple's deprecation path, and the MDM cannot send the replacements**

**L · Every key this fleet's lock-down depends on is on Apple's deprecation path, and the MDM cannot send the replacements**

WHAT HAPPENED, measured and verified 2026-10-14 while answering "can a software update break the Waze kiosk".

Two independent facts, both checked rather than assumed:

1. **Apple's `release` branch IS iOS 27.0**, and its `CHANGES.md` marks **`allowListedAppBundleIDs`**,
 **`blockedAppBundleIDs`** and **`com.apple.dnsSettings.managed`** as deprecated at 27.0. Those three are the app
 lock-down, the app deny list, and the DNS filter itself. And Apple's own precedent sits in the same release: the
 software-update restriction keys were deprecated in 26.0 and **removed in 27.0**, with Apple's own words "Legacy
 software update management no longer functions in all 27.0 operating systems." The cadence is deprecate in N,
 remove in N+1.
2. **Our MDM cannot send the replacements.** These are declarative configurations (iOS 18+). NanoMDM's own README
 feature list contains no declarative device management, and our Caddy routes only
 `/mdm /checkin /version /v1/* /migration /authproxy/*` to it — no declaration path is served. So the fleet can
 only use deprecated legacy keys, and the modern replacements for update control, per-app privacy defaults, app
 gating and DoH are all unavailable.

The consequence is a countdown nobody owns: every control that holds this product's lock-down will be *removed* on
a cadence Apple has already demonstrated, and the stack has no way to move to the replacement.

RULES:
1. **A deprecation notice on a key you depend on is a dated deadline, not a style note.** Read
 `apple/device-management`'s `CHANGES.md` against every key in your profiles, and treat "deprecated in the version
 we run" as a project with a deadline equal to the next major release.
2. **Check that your management tooling can actually deliver the replacement before choosing it as the plan.** A
 self-hosted MDM with no declarations endpoint cannot manage any modern iOS setting, however good the profile is.
3. **Nobody documents what happens to a profile carrying a REMOVED key** — ignored, or payload rejected. The blast
 radius is one dead setting versus a dead lock-down, and the same payload carries both. Test it in a lab before
 any fleet-wide upgrade.
4. The reassuring half is real and worth holding onto: a software update does not remove a configuration profile,
 and the app allow-list **hides** rather than merely blocks ("only shows or can launch"), so a new app from a new
 iOS does not appear — the only exemption Apple names is Settings and Phone, which is why the kiosk folders them
 instead of relying on the list.
