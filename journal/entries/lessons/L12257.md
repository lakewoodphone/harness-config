**L12257 · Our kernel probe read 10 of 1717 dmesg lines - and the blindness was written up as a firmware limit**

Measured 2026-10-22, ZABZ-TECH, E4610 616202539.

The condition audit's kernel probe ran `dmesg 2>/dev/null | tail -1500`. This toybox tail accepts
only `-n NUMBER`, so `-1500` was read as garbage and it fell back to its default of 10 lines:

 adb shell "dmesg | tail -1500 | wc -l" -> 10
 adb shell "dmesg | tail -n 1500 | wc -l" -> 1500
 adb shell "dmesg | wc -l" -> 1717 (118,533 bytes)
 adb shell "tail --help" -> usage: tail [-n|c NUMBER] [-f] [FILE...]

So every handset ever graded here was graded on ten lines of routine noise, and the register said
"no kernel red flags" for all seven. The string grading.md itself had named (`core_set_license:
Invalid cal block to send`) was in the buffer 22 times the whole time.

The worse failure is what happened next: the 10-line capture was written up in grading.md and
STATE.md as a FIRMWARE LIMIT ("dmesg on the E4610 keeps only the last ~13 lines - the ring buffer
is consumed by logd"). It does not. We were reading ten. A limit of our instrument was recorded as
a property of the hardware, which then justified not looking harder. Rule: before writing "this
device cannot tell us X", prove it with a second instrument - here `wc -l` and `tail --help` were
the whole proof and cost one command each.

Second correction, same session: that cal-block line is NOT radio calibration. All 22 occurrences
are paired on the same line with `msm_ds2_dap_set_security_control: failed to set dolby license` -
the Dolby/DS2 audio licence handshake to the ADSP. The unit was registered home on LTE 311480,
data connected, SIM READY, and its acoustic loopback measured -13.9 dBFS. So it is disclosed as
info and never scored (KERNEL_LICENCE_NOTES); a `cal block` from anything other than
`core_set_license` still scores C. Also excluded as config/log noise, each measured:
`msm_thermal:store_cc_enabled`, `thermaladj` init lines, `migrate_irqs: N callbacks suppressed`,
`wlan ... WDI_ProcessInitScanRspi:0 BMPS0`.

The test suite had the wrong doctrine encoded: `test_kernel_cal_block_is_a_serious_flag` asserted
grade C using the exact Dolby line as its fixture. Replaced with two tests - the Dolby line is
info on an otherwise clean phone, a bare `cal block` fault still scores C. Suite: 33 passed /
2 failed before, 36 passed after.

Commits 5eb72c4b (probe + grader + tests + docs) and d108aeed (audit-phone.ps1 repo-root path).
A register row now carries the licence note instead of "none" - which is the point: "none" should
mean examined and clean, not "we looked at 0.6% of the evidence".
