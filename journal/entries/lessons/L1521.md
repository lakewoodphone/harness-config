**L1521 · A unit test that reads the deployment's .env is not a unit test -- and the same file was disabling cheap-first routing in production**

**A unit test that reads the deployment's `.env` is not a unit test -- and the same file was silently
disabling a feature in production.**

Measured 2026-09-15. `test_assistant_chat_prompt_profiles.py` built its `Settings` with plain
`Settings(database_url=...)`. pydantic-settings loads `.env` by default, so the test inherited
`USE_DYNAMIC_REGISTRY=false` **from the authority's real environment**, the semantic-routing gate
closed, and two assertions failed for a reason that had nothing to do with the prompt telemetry the
test is named for. `_env_file=None` fixes the test; the same value also turns out to be why production
never routes cheaply (queue #39).

Rules:
- **Every test that builds settings passes `_env_file=None`.** Otherwise it is an integration test
 against whichever deployment happens to sit next to it, and it will pass on one machine and fail on
 another for reasons nobody can see in the test.
- **When a test fails, ask what the test *is* before adjusting the code.** Here the honest answer was
 "three defects in the test and one real production finding", and none of it involved changing the
 behaviour under test.
- **Instrument rather than infer.** I spent several probes on the gate (`router called: 0`) before
 printing the four gate values, which named the culprit in one line: `dyn=False`. The values are
 cheap; the reasoning about them is not.
