**L1537 · Never write an act in the past tense before you read it back**

## Rule

**Never write an act in the past tense until you have read it back.** A queue row, a
commit, a file — the record must describe something you have observed, not something
you instructed or intended.

## What happened

While draining the owner queue I resolved row #39 with text that said *"the
settings_overrides row that nothing honoured is gone"*. The delete had been in the
same batch, one step earlier, and it had failed on `database is locked` — the live app
writes that table constantly. The batch used `set -uo pipefail` without `-e`, so the
failure was swallowed and the script walked on to the next step, which is the step
whose error I actually saw. The row was still there.

I caught it only because the verification printed `before` and `after` and both showed
a row. The false claim lived in the authoritative queue for about ten minutes.

## Why it matters here specifically

This is the same failure the whole system was built against: a confident statement
about state that nobody had checked. A stale database read once produced a reported
crisis that did not exist. Here it was smaller — one clause in one resolution note —
but the shape is identical, and it was written by me, in the same round where I was
grading other people's claims for provenance.

## The fixes, both applied

1. When a claim is *about* an effect, order the work so the effect is verified **before**
 the text that asserts it is written. Verify-then-record, never record-then-verify.
2. A batch script that must not continue past a failure needs `set -e` **and** the real
 error surfaced per step — not `set -uo pipefail` plus a `tail` that shows only the
 last thing to fail.

## Evidence

- `settings_overrides` row for `use_dynamic_registry` still present after the failed
 batch; aligned to `.env` (`false`) in the follow-up run, printed as
 `STORES AGREE`.
- Row #39's resolution text now carries an explicit `CORRECTION:` clause saying the
 earlier version was false and why, rather than being quietly rewritten. The record of
 having been wrong is worth more than a clean-looking one.
