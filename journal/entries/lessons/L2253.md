**L2253 · L2249 - ever_tried is the column that separates a backlog from dead queue**

Measured 2026-09-20 on the authority, and it reframes the largest number in the AI-company audit.

The audit''s headline was "23,046 open goal steps assigned to non-executing departments". Counting them is
easy; the number does not say whether they are a **backlog** (work being worked through slowly) or **dead
queue** (work nothing will ever touch). Those need opposite responses: a backlog needs capacity, dead
queue needs retirement.

 select assigned_agent, count(*) n,
 sum(case when attempts > 0 then 1 else 0 end) tried,
 sum(case when last_heartbeat_at is not null then 1 else 0 end) heartbeat
 from goal_steps where status not in ('done','completed','closed','cancelled')
 group by assigned_agent

 dept_business_ops 6032 open ever_tried=49 has_heartbeat=0
 orchestrator 3437 open ever_tried=0 has_heartbeat=0
 dept_engineering 2849 open ever_tried=69 has_heartbeat=0
 dept_ai_platform 1120 open ever_tried=0 has_heartbeat=0

**49 of 6,032 is 0.8%. It is dead queue.** And the second column matters independently:
`has_heartbeat=0` for every agent - nothing has ever claimed or started any of it. Two cheap columns turn
an ambiguous 28,757 into a definite answer.

**The generalisable rule.** When a backlog is large, count **attempts**, not just rows. A count of
outstanding work conflates three different states that need three different fixes:

 - **attempted and failing** -> fix the executor (this is where defects are)
 - **never attempted, has an executor** -> the scheduler is not reaching it
 - **never attempted, no executor** -> the rows are dead and should be retired

**And the structural half of the finding:** 82 agents hold open steps while only 22 `dept_*` names exist
in the task layer, **66 of the 82 are not in the executing layer at all**. Rows assigned to an agent with
no executor cannot be a backlog by construction - there is nothing that could ever pull them. That check
(`assigned_agent` not in the set of agents that have executed anything) is one query and should run
wherever these rows are created, so dead queue is never accumulated again.
