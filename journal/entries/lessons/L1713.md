**L1713 · Regenerating a generated preset deletes hand edits - --check warned me and I regenerated anyway, deleting two owner rules from the live system prompt**

## What happened
`presets/zabz/agent.cordis.yml` is **generated**: `scripts/make_zabz_preset.py` rewrites it
wholesale from its own `PERSONA` string plus the MCP rows inside that script, taking the rest
from `presets/cordis-bg/agent.cordis.yml`. Two rules had been hand-added to the *live* preset
and never put back into the generator:

- "**1b. On any larger job, orchestrate — do not grind serially.**"
- "**AI models are never hardcoded — resolve them at runtime.**"

I ran the generator anyway. Its own `--check` had printed the warning verbatim: *"Re-run
without --check to regenerate -- but move any hand edit into this file first, or regeneration
deletes it."* The regeneration deleted both rules from the file that ten live sessions read as
their system prompt.

## Why it was dangerous, not cosmetic
Those are standing owner instructions, and they were sitting in the only place the running
sessions could see them. A regeneration would have silently removed the orchestration rule
(the one that says fan out rather than grind serially) from every session started afterwards,
with no error and no visible symptom — the classic shape of this system's worst failures: a
change that looks like it worked.

## The fix, and how it is proven
`_dsh-scale/tools/restore_persona_rules.py` copies the two paragraphs **byte-for-byte** out of
a pre-regeneration backup and inserts them into the generator's `PERSONA` at the same relative
positions (after rule 1, and after "One source of truth per thing"). Then:
- regeneration ran again, and a line-by-line diff of the persona block against the backup
 reported **0 lines missing** (116 backup lines -> 118);
- `make_zabz_preset.py --check` now prints **"zabz: in sync with the generator"**, so the
 generator is the single source of truth and the next regeneration is a no-op;
- the MCP direct-node rows were moved into the generator in the same pass, so the earlier
 direct-YAML edit is no longer at risk of being reverted.

## The rule that follows
**A `--check` that reports drift is a STOP, not a formality.** Before regenerating any
generated artifact: diff the artifact against the generator's output, port every hand edit
into the generator first, regenerate, then diff again and prove nothing was lost. And when
verifying the result, read the file with a real search tool — two of my PowerShell "checks"
in this same round were wrong because the regex was wrong, and a wrong check is
indistinguishable from a passing one.
