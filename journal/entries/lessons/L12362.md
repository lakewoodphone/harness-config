**L12362 · A folder that was MOVED looks exactly like a folder that was DELETED, and a file-only listing cannot tell you either way**

Case Werner (WO26102012764), 2026-10-25. The customer said, twice, that she was missing FOLDERS. Two sessions answered a FILE question and concluded nothing was lost; both were wrong about which object she named, and the shop told her twice that her data was fine while she could not see the folders.

The measurement that settles it: on exFAT, moving a directory inside one volume CREATES an entry in the new parent and CLEARS BIT 7 of the entry in the old parent. Both entries carry the SAME FirstCluster and the same creation stamp. So a deleted directory entry whose cluster is ALSO claimed by a live directory is a MOVE, not a deletion - the folder is not missing, it is somewhere else. A real deletion frees the cluster chain, so the husk points at a cluster nothing live claims.

On this card: DCIM at the root ran 886, 887, 897-906 then jumped to 913-920. The six absent folders (907_2903, 908CANON, 909CANON, 910CANON, 911___05, 912___06 - 1,713 files) were all live inside DCIM/902___11, each with the same first cluster as its root husk (270119, 299836, 322282, 341802, 377463, 427123).

Two rules to carry:
1. Before saying a folder is missing, list the DIRECTORIES of the image - not the extracted file tree, and not a tool's list mode. An extracted tree shows only what the extractor walked.
2. Two paths claiming one cluster is evidence, not noise. Print it.

The tool defect this exposed, now fixed in lpt-hub/scripts/data-recovery/exfat-named.py: walk() descended only into directories whose in-use bit was set (old line 236, 'and d[inuse]'), so a deleted folder was counted and never entered; and --list printed NO directory at all (old lines 291-296), so searching that output for a folder name could only ever return nothing - a silent refusal read as a negative. Patch: two-pass walk (live tree first so a moved folder's cluster is claimed by its live path, then the deferred deleted dirs), a via_deleted flag, output under deleted-folders/, directories printed with DIR/DELDIR, and a 'reused' marker on a husk whose cluster a live entry already claims. Control: the live-file census is unchanged by the patch on the same image - 10,882 files / 93,291,521,717 B.
