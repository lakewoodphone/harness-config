The marriage corpus — one index, and the two things that are gone

Built 2026-10-19: personal-secretary-mvp/docs/wedding/00-MARRIAGE-INDEX-AND-STORY.md
(mirror /opt/company/docs/wedding/, 11,857 B / 179 lines). It indexes the 12 wedding docs,
the 4 Copilot chats, the mail that seeded them, and the besulim/nidah chronology.

What a future session must not re-derive:
- The 12 docs under docs/wedding/ ARE the record. The chats that produced them are gone:
 only owner turns survive in vscode_chat_messages (truncated), and the .jsonl for
 03ece8b8 (Nidah and dam besulim notes) and 81a89dec (Chosson and nida halachos) is on
 neither zabz-yoga AppData nor reachable zabz-tech. Do not hunt again.
- vscode_chat_sessions.indexed_text is a flattened token soup, NOT a transcript. Reading it
 costs context and yields UI chrome. Do not use it as a chat reader.
- Gmail attachments are metadata-only in /root/mail-archive/<box>/archive.db: table
 attachments has 1,277 rows and an EMPTY path column. Chosson class.docx (73,477 B, from
 Shabsi 2026-06-24) and chosson-class-revised-2026-06-13.docx (64,627 B) cannot be
 recovered from the archive; they would need the Gmail API by attachmentId.

Facts worth keeping: wedding 16 Aug 2026, Ateres Esther. Aygestin 5mg BID from 30 Jul 2026
to stay tahor. Rav ruled 2026-08-27 on yichud. 03ece8b8 spans 08-03..08-16 — the only window
in which those notes were live.

Shell lesson, paid for twice tonight: `ssh host "sqlite3 db \"SELECT ...'\''...\""` from
PowerShell mangles the SQL into cmdlet names (exit 1, "indexed_text is not recognized").
Pipe the script over stdin (`$lines -join newline | ssh host bash -s`) and strip CR — a stray
CR at the end of the last line makes bash report $'\r': command not found and exit 1 while the
earlier lines still succeed, which reads like a failure and is not one.
