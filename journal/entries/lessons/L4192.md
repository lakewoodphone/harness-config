**L4192 · A detector that checks a surface nothing loads reports 15/15 while the instructions are stale**

**Measured 2026-10-14 23:22Z on ZABZ-YOGA, before this was found.** `scripts/preset-drift.py` — the tool whose own docstring says it answers *"is the instruction surface this machine LOADS the one in the repo?"* — compared 15 files: the six `$DSH_HOME/.agent-presets/<p>/` files and the nine skills. It printed `compared 15 match=15 drift=0 missing=0`, and `sync.py` printed `verify: loaded surface matches the repo (compared 15 match=15 drift=0)`, while

 sha256 ~/.dsh/profiles/web/cordis.patch.yml != sha256 profiles/web/cordis.patch.yml

**On the 0.1.7 line, `.agent-presets/` is not read at all.** Local preset-directory discovery was removed; the persona a session receives is the `preset-rows` managed block inside `$DSH_HOME/profiles/<n>/cordis.patch.yml`. So the detector verified the surface nothing loads and was blind to the one that decides every session's instructions — and it was written on 2026-10-13 *specifically* to catch a stale persona. It found the previous form of the defect and missed the new one.

**The rule, generally: name the surface the caller READS, then prove the check touches that file.** A comparison set is a claim about coverage. Write the set down beside the code that walks it, and when the platform's loading path changes, the SET is what must change — not only the code.

Fixed the same night: the profile patch layer is now compared (15 → 17 rows). Proven by putting one stale line into the live file and reading `drift=1, exit 1`, then restoring it and reading 17/17.

**Corollary, and it is the one that costs money: `--check` exit 0 is not "the surface is right", it is "the surface this check knows about is right".** Two of the three defects found that night sat behind a green check. The end-to-end instrument is `node <engine>/lib/bin.js --profile web --dump-config`, which composes the same tree boot does; grep it for the rule you just wrote.
