**L3191 · L: a timed-out search is a failed search, not a negative result - and search filenames before content**

EVIDENCE: 2026-09-30, the projector incident (pain P2823, decision D2908).

WHAT HAPPENED: asked whether the owner had documented a projector, I ran content searches (grep for 'projector' across C:\\Users\\ezabz and across Code\\**\\*.md). Both timed out at the 30-second tool limit. I treated each timeout as a dead end, moved on, and then told the owner twice that no record existed. A filename search run afterwards - Get-ChildItem -Recurse filtered on Name -match 'projector|dangbei' - returned the file on its first page: personal-secretary-mvp\\docs\\entertainment\\tv-projector-research-2026-08-20.md, 625 lines, present since August.

RULES:
1. A TIMED-OUT SEARCH IS A FAILED SEARCH. It is not 'nothing found'. It must never be reported as absence. Retry with a narrower path, an --include filter, or a filename filter before drawing any conclusion, and if it still fails, say 'I could not complete the search' and not 'there is no record'.
2. SEARCH BY FILENAME FIRST, CONTENT SECOND. A recursive content grep across C:\\Users\\ezabz\\Code (40+ repos, 322k+ files) is guaranteed to time out - the lpt-hub AGENTS.md already says so. Get-ChildItem with a Name filter is fast, has no content-parsing cost, and would have found this immediately.
3. DO NOT SEARCH THE WHOLE HOME DIRECTORY. C:\\Users\\ezabz contains Downloads, .vscode extensions, node_modules trees and browser profiles. Scope to specific roots: the owning repo, then that repo's docs/, then the journal.
4. WHEN THE OWNER SAYS SOMETHING EXISTS AND I CANNOT FIND IT, THE PRIOR IS THAT HE IS RIGHT. Say which searches were run and what they returned, then ask for a location - do not assert that it does not exist. He remembered correctly and I contradicted him twice.
5. THE JOURNAL'S DEAD ZONE IS REAL. The journal only reaches 2026-09-14. Anything older is findable only via repo docs and VS Code chat logs (workspaceStorage/*/chatSessions/*.jsonl, searchable with Select-String). Check those explicitly when a question concerns pre-September work.
