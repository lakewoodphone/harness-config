**L1765 · Panasonic "This USB device is incompatible" is the same message for a wrong-model FRM and a bad stick - check the file, not the media, first**

*(Re-appended 2026-09-16 after an id collision. This record was first written under id `L1743` on a checkout that was nine commits behind `origin/master`, so that id already meant a different entry written on another machine. `journal.py` allocated a fresh id rather than let one id mean two things; the content below is unchanged apart from this note.)*

**Measured on ZABZ-YOGA 2026-09-16**, on the Panasonic DMP-BD84 / RattleByte case (ticket #188880).

The player had been refusing the mod's Initial flash with **"Firmware update. This USB device is incompatible."** and the open
question was whether the *stick* was at fault. The stick turned out to hold a `PANA_DVD.FRM` of **130,250,740 bytes dated
2026-04-22** - the **BD83** archive file, while the unit is a BD84 with no network interface, which the vendor says is
firmware-wise a **BD90**. The correct BD90 file is **77,730,260 bytes**. Both files carry an **identical 32-byte header**, so the
old one was a genuine FRM of the same family, not a corrupt download - the difference is the model payload.

**Rule.** On these players, "This USB device is incompatible" is the *same message* for a wrong-model file and for an
unusable device, so the message cannot rank the causes for you. Read the model code, size and hash off the file **before**
touching the media: a 130 MB FRM where the correct one is 78 MB was the whole defect, and it was invisible on the stick.

**Corollary for vendor-supplied firmware:** the archive name does not tell you the target model. RattleByte ships the
"BD83" archive as the default answer for a BD84 and then corrected it to a **BD90** archive for the no-network variant. Take
the model from the unit's own label (or the vendor's explicit reply), never from the archive filename.
