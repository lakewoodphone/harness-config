**L2120 · L2103 - a documented off-switch is not in force until the code path that acts checks it**

`OWNER_BRIEFINGS_ENABLED=false` was recorded as an owner decision (`04-D5`) and set in `.env`. The
gate helper exists and is correct - `autopilot_auxiliary_contract._enabled_owner_briefings` - and
`app/agent_bus.py` honours it at lines 306 and 323. But `app/autopilot.py::_send_owner_briefing`,
which is the path the autopilot's own scheduler calls, checked **nothing**. Result: 26
`owner_briefing_morning` / `owner_briefing_evening` rows enqueued in 30 days with the flag false.

**Rule: a flag is only in force at the points of EFFECT, not at the points of definition.** When a
setting exists, enumerate every place that acts on the behaviour it names and confirm each one reads
it. One grep for the flag name across the repo is normally enough - `owner_briefings_enabled` already
appeared in four files, which is exactly how the missing fifth was findable.

The generalisable version, because this is the third instance this session: a decision does not
persist because it was written down, and it does not take effect because a helper exists to honour
it. It takes effect when every acting code path calls that helper. Guard the *effect*, and put the
guard at the top of the method that has the side effect so no future caller can route around it.
