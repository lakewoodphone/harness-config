**L3695 · A sync record's sourcePath must name the case .md - a .json sourcePath can never resolve**

A sync record's `sourcePath` must point at the **case file** (`.md`), repo-root-relative. A record that names itself — or any `.json` — can never resolve.

Why it matters, measured 2026-10-12: `lptcase._sp_candidates` only yields candidates when the value ends in `.md`, so `docs/customer-operations/sync-records/<case>.json` produced no candidate at all. `lg-old-phone-shwartz-2026-08-12.json` carried exactly that (inherited), so the case index could only attach it by its last-resort `caseId-fallback` rule, and `tools/customer/audit.py` counted it among **C14-record-cannot-find-its-case INFO=208** — i.e. 208 of 412 records cannot find the case they belong to.

Fixed to `docs/customer-operations/cases/lg-old-phone-shwartz-2026-08-12.md`; the link rule became `sourcePath-basename` (the resolved-path rule needs the hub root as cwd, so basename is what a run from elsewhere gets).

Corpus convention, counted in the same directory: 278 records use a bare `docs/...` path, 43 still carry a `lpt-hub/` prefix (which `_sp_candidates` strips, so those work if the rest is a `.md`). AGENTS.md §3 already says sourcePath is relative to the lpt-hub repo root.

Rule: when touching any sync record, point `sourcePath` at the case `.md` and re-run `lptcase show "<customer>"` — if it says `linked by: caseId-fallback`, the record has not really been linked.
