**L1879 · Preset routing mechanics: disable-by-id works; one tool name per scope; a tool row can inject prompt text; a preset change needs NO restart**

Four mechanism facts, each read or measured this session, that a future session would otherwise rediscover.

1. **A preset row CAN be disabled by id from the preset itself, `!!js` included — and for delegation tools it is the ONLY place.** A `cordis:group`'s `config:` list is an ordinary loader entry tree (`cordis-plugin-group` → `EntryGroup.update()` → `Entry.create()`), and the loader honours `disabled` per entry, evaluating a `!!js` expression against the loader context (`cordis-plugin-loader/src/config/entry.ts:19, 88-108`, "a `!!js` expression evaluates against the loader context"; `Entry.refresh()` returns early when disabled, `:126`). Already exercised in the `zabz` preset by `tool-subagent-codex`/`-claude-code` (`disabled: true`) and `tool-subagent-list-agents` (`disabled: !!js process.platform === 'win32'`). Sharper: the `web` profile's own patch layer disables the HOST copy of `tool-subagent` (`--dump-config` line 279-285 prints the row with `disabled: true`), so a session's `subagent` tool comes from the preset alone — disabling it there is total, and the host plane is not a backstop.

2. **Two tool rows in one scope cannot share a `toolName` — it throws, it does not shadow.** `tool "subagent" is already registered in this scope` (`dsh-tools/lib/index.js:2538`). So "keep the local `subagent` and add a remote `subagent` next to it" is not a routing option; giving a name to a provider is a one-to-one act. (Scoped registrations shadow GLOBAL ones, `:2564` — that is a different axis and is what makes the preset-over-host pattern work.)

3. **`@deepseek-ai/dsh-tool-subagent` emits a system-prompt section of its own, and it is a trap for a fallback tool.** Whenever a row is both background-enabled and continuable the shipped row registers a section whose text is `Use <toolName> in the background by default. Start independent delegations together in one assistant message …` (`lib/index.js:576-580`). A local fallback left `continuable` therefore puts a prompt in front of every agent telling it to prefer the LOCAL tool — so the fallback was configured `backgroundMode: one-shot`, which silences that section. Corollary worth keeping: a tool row is not just a listing, it can inject model-visible instructions, and which row does that is a design decision.

4. **A preset change does NOT need an engine restart — `71-mesh-program.md` §5 and P210 say it does, and that is wrong for a preset.** Discovery is unmemoized: "`list()` and `resolve()` re-read the roots on every call so a preset authored while the process runs is visible immediately" (`dsh-agent-presets/lib/index.js:1152-1158`); a session resolves its preset at creation (`dsh-api-session-controller/lib/types/agent.js:382-391` → `presets.mount`); and the standing mount is keyed by the composition file's `mtimeMs`+`size` stamp and RE-COMPOSED when it changes (`ensureStanding` `:1767-1776`, `compositionStamp`/`sameStamp` `:1806-1820`). Only HOST-plane rows (the profile's patch layer, a bundle's own patch) need a restart. Limit: an already-running session keeps the composition it mounted under, and a child created by an old session binds to its parent's standing composition rather than re-resolving (`:1507-1521`).

5. **A preset edit has a free gate that costs no engine and no tokens.** `js-yaml`'s `load(text, { schema: entryListSchema })` with `entryListSchema` from `@deepseek-ai/cordis-plugin-include` is the exact parse `fileComposition` performs (`dsh-agent-presets/lib/index.js:1019-1032`); walking the result catches a duplicate entry id, a missing row and a wrong tool name. Then `Config(...)` from the plugin itself (`dsh-tool-subagent` exports `Config`, `lib/index.js:659`) validates each row's config against the shipped schema and reports the defaults. Run from the npx install root so bare specifiers resolve. This would have caught a typo'd key that would otherwise have failed at the next session's mount.
