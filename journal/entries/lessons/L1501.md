**L1501 · Her web search was silently dead: the endpoint is Techloq-blocked and the chat path hid it**

MEASURED 2026-09-15, on Yocheved's laptop (DESKTOP-FGV6KMH), from her own session archive.

The harness web-search provider is a DeepSeek Anthropic-format Messages call hardcoded to
https://api.deepseek.com/anthropic/v1. Techloq blocks that host by URL category on her laptop, so web
search failed on EVERY call. Chat was unaffected -- chat uses the deepseek-proxy route -- which is
exactly why nobody noticed: the only symptom was that searches degraded into a dozen r.jina.ai page
fetches, one URL at a time. Session 901efff6 shows `DeepSeek search request failed: TypeError: fetch
failed` before each such sequence.

The fix is one environment variable, and HOW to set it was the hard part:

* `DEEPSEEK_SEARCH_BASE_URL` is in dsh-app-boot's BOOTSTRAP_NAMES ("it decides how this process
 reaches the network"). A .env file may NOT set it. The harness-home .env is the only layer ever
 exempted, and only for HTTP(S)_PROXY/NO_PROXY. Putting it in ~/.dsh/.env made the engine REFUSE TO
 BOOT -- and the symptom read as a launcher fault, so I chased the launcher first.
* It must be in the environment of the process that starts the engine. On her laptop that is dshw.ps1,
 which is reached by THREE different entry points (the machine launcher, the desktop shortcut's VBS
 wrapper, and a hand-run `dshw ensure`). Only one of them was setting it, so the engine never saw it.
 Setting it inside dshw.ps1, hostname-gated, covers all three.
* Our own Worker passes the request path straight through, so ds.abletelsolutions.com carries
 /anthropic/v1/messages unchanged. Verified: HTTP 200 application/json through the proxy, versus the
 filter's HTML block page (HTTP 200, text/html, 2498 bytes) on the direct host -- a success status and
 the wrong content type, which is this filter's signature.

LESSON: on a filtered network, a feature with its OWN endpoint config can break while the chat path
works fine. Search was broken for a full day of real work and never once reported an error the user
could act on.
