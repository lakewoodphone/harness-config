**L3684 · Print labels from ZABZ-TECH with the repo build: the printer is on this LAN, and the copy on the shop box is older than the repo**

Measured 2026-10-11 on ZABZ-TECH while printing a customer label. Two findings that together save the
next session an hour and a write to a frozen machine.

**1. The label printer is reachable directly from ZABZ-TECH, and the repo build runs there.**
`Test-NetConnection 192.168.50.60 -Port 9100` → **True**. ZABZ-TECH is on the office LAN, and the printer
is on it. Its Python already has `Pillow 11.3.0` and `brother_ql`, so the current checkout prints without
any deployment:

```
cd ~/code/lpt-ops
Get-Content label.txt | python bin/lpt-label print - --heading "BALANCE DUE 500" `
 --printer tcp://192.168.50.60:9100 --dry-run --out big.png
```

`--printer tcp://host:9100` skips discovery, which matters on Windows (no mDNS). This is the same raw
raster over port 9100 the box uses — it is NOT the Windows print spooler, which L3491 proved never prints.

**2. The build installed on the shop box is OLDER than the repo, and it is not a git checkout.**
`/usr/local/bin/lpt-label` execs `/home/zabz/lpt-ops/bin/lpt-label` with a private venv, and
`/home/zabz/lpt-ops` is a plain copy — `git log` there says *not a git repository*. Its
`lpt_ops/label_printer.py` (mtime 2026-10-11 18:09) contains **no `HEADLINE_MARK` and no `_body_px`**, and
its `--help` has no `--roll-mm`, both of which the repo has. Consequence measured on tape: the box's
renderer sizes all body text at one small size and **ignores line length**, so *shortening the lines does
not enlarge the letters* — it only pads the tape. The first attempt produced 28.3 mm, then 48.8 mm, with
identical glyph sizes. Only the repo build, run locally, produced the big bold text.

**The `!` headline marker, which is the lever for bigger words.** In the repo's renderer a line beginning
`!` is drawn **bold, sized to the tape, never wrapped** (`_fit(..., start=34)`), while unmarked lines are
body text at one size capped at 22 px for the whole label. On the old build the `!` is not a marker at all
and prints literally — that is the tell that you are talking to the stale copy.

**Two rules that follow.**
* To print at the newest build without touching the office box (a frozen rollback anchor), **print from
 ZABZ-TECH** — it is on the printer's LAN and the repo is there.
* When a rendered artefact's text will not get bigger, check **which build is answering** before changing
 the content. I changed the wording three times for a size problem that was a stale binary, which is
 P3009's lesson wearing different clothes: ask whether the constraint is the content, the container, or
 the code that draws it.

Every print was verified the documented way: the dry run's tape length matched the print's (28.3 / 48.8 /
42.7 mm exactly), the two PNGs were **byte-identical** each time, and the printer's own status went
`READY → PRINTING → BUSY → READY`.
