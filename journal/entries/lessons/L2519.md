**L2519 · Two dollar signs in one paragraph render as maths in his GUI: serif, spaces eaten, word-joined - rule 8 now lives in the agent persona so no session relearns it**

**Two dollar signs in one paragraph make the Web GUI render the span as inline maths: serif font, spaces eaten, words joined. The owner reads every reply in that GUI, so a session that writes money in prose is writing unreadable text — and he had to ask for it repeatedly.**

**MEASURED 2026-09-24 (ZABZ-TECH), from the owner's own screenshot.** A reply of mine that said, in one line, `$410 in ($160 + $250), $350 out ($250 deposit + $100 decline fee)` rendered as:

> 410in(160 + 250),350out(250deposit+100 decline fee)

and the next paragraph came out ending `*.*If*thelabcredits...` — italics, no spaces, word-joined. Four dollar signs in a paragraph, two maths spans, and the text is destroyed. The owner's words: *"why do you keep writing like this in funny font and no spaces, it happens all the time and makes it very hard to read."*

**THE CAUSE.** The renderer treats a **pair** of dollar signs as inline maths (KaTeX-style). A single, unmatched dollar sign renders literally — which is why tables mostly survive (one amount per row) and prose never does. It is not a formatting preference, it is markdown that means something else.

**THE RULE (now rule 8 of the agent persona, so every session on every machine inherits it).** In prose, write amounts as plain numbers with the unit once — `800`, `USD 800`, `800 dollars` — or at most one dollar sign per paragraph, never two. Tables are safe per row; prose is not.

**WHY THIS CLASS KEEPS RECURRING.** The failure is invisible from the writing side: the message looks correct in the raw markdown and only breaks in the owner's viewport, on his machine, at his font. Nothing in the toolchain complains — no lint, no error, exit 0 — so the same mistake repeats for weeks until a human sends a screenshot. When the owner reports a presentation defect, treat it as a measurement about his screen, not as taste, and change the harness so no future session has to learn it again.

**NOT FIXED, AND WHY.** The DSH implementation path I was given (`...\_npx\1e7f6d9597241db0\`) holds no source — only `node_modules` and an `out/` directory of unrelated research files (apple_esim.html and similar), and no match for `katex`, `remark-math` or `rehype-katex` anywhere in it. So the renderer cannot be disabled from here, and the honest fix available is the writing rule above. If a real checkout appears, the better fix is to enable inline maths only for a doubled delimiter (`$$`) and leave single dollar signs literal.
