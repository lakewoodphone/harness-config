**L3755 · ffmpeg cannot open every iPhone HEIC and fails on only part of a real batch - use pillow-heif**

**Measured 2026-10-13, 17 HEIC files from an iPhone 15 Pro (IMG_1142–IMG_1158), ffmpeg 8.1, on
ZABZ-TECH.**

ffmpeg refuses `IMG_1142.HEIC` with *"Derived Image item of type tmap is not implemented"* — and
**succeeds on `IMG_1154.HEIC` from the same phone, the same minute, the same folder.** So an
ffmpeg-only HEIC path fails on *part* of a real batch and quietly works on the rest: the run finishes,
the manifest looks complete, and the images that matter are the ones missing.

`pillow_heif` read **all 17**, preserving the EXIF block (so `DateTimeOriginal`, and therefore the
capture time, survives the conversion). It is installed in both interpreters on this machine
(`C:\Python313` and the psmvp venv).

```
pillow_heif.register_heif_opener() # required, or Pillow cannot even identify a HEIC:
with Image.open(path) as im: # UnidentifiedImageError
 exif = im.info.get("exif") or b""
 im.convert("RGB").save(path.with_suffix(".jpg"), "JPEG", quality=95, exif=exif)
```

**The rule.** For HEIC/HEIF, never route through ffmpeg; use `pillow-heif`, and make the failure
visible in the manifest rather than silent. `lpt-hub/tools/media-inbox/ingest_folder.py` does this as
of 2026-10-13, and its README records the measurement.
