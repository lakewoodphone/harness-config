**L1830 · Shell traps that fail SILENTLY and make a checker report the opposite of the truth**

Four found on macOS 2026-09-16, each of which made a check pass while the thing it checked was broken.
1. `uid` IS A READONLY BASH BUILTIN. `while ... read -r kind p | awk -v uid=` -- the assignment
 fails silently, the loop body never runs, the parser returns nothing, and every caller reads
 "nothing found" as "no blockers". Use a different name (`_want_uid`). Any script in this repo
 that parses a username is exposed.
2. `ps -o comm=` ON macOS RETURNS THE FULL PATH INCLUDING ITS SPACES, so `` yields `Chrome`
 or `Helper` or `(Renderer)`. A matcher built that way found 1 of 5 Chrome processes and
 reported "targets live: 1" while 486 MB was resident. Rebuild comm from fields 5..NF and pass
 `-ww` (without it, output truncates to terminal width). Helper processes do NOT match
 `pgrep -x "Google Chrome"`; match by bundle containment.
3. `pmset -g assertionslog` HANGS FOR EVER on macOS 26 (killed at 120 s), and assertion lines do
 not carry a "created" time -- it is a separate tab-indented line. Find the kind by the
 HH:MM:SS token, never by field position.
4. `timeout(1)` does not exist on macOS, and `vm_stat` prints its field names on a header line,
 so a per-line label match finds nothing -- parse columns by name from the header.
RULE: a checker that reports "clean" is not evidence. Before trusting any of these, run the
counter against a case known to be dirty.
