**L10369 · settings-effective was never blind: the verb overwrote the module's own ran=false record with a stub whose reason was a JSON preview, destroying the diagnostic it was reporting**

MEASURED 2026-10-19 on ZABZ-YOGA and ZABZ-TECH, and fixed the same night.

THE SYMPTOM. `dsh-update preflight` reported, on BOTH machines:
 settings-effective (the engine's own report) did not run — the module produced no usable artifact
 (exit 0): { | "schemaVersion": 1, | "generatedAt": "2026-10-19T22:25:04.492Z",
A truncated JSON preview where a reason should be, and a gate that could not be trusted either way. It is the
gate that found 15 real silent settings losses on 2026-10-05, so losing it quietly is expensive.

THE CAUSE, in the reporter and not in the detector. `lib/cli.mjs::verbSettingsEffective` runs
`lib/settings-effective.mjs --out <artifact>` and then reads the artifact. When the module's own record carries
`ran: false` (a legitimate outcome -- no credential, a boot that failed), the verb called its local `refuse()`,
and `refuse()` WRITES A STUB over the module's artifact:
 { schemaVersion: 1, version, ran: false, verdict: null, reason, generatedAt }
with `reason` set to a preview of the module's STDOUT. So the module's real diagnostic was destroyed by the code
that was supposed to report it, and the preview showed the first three lines of the module's JSON instead of the
sentence explaining why it stopped.

THE FIX (cli.mjs, ~12 lines): if the module wrote a record, KEEP IT. Report `ran=false` with the module's own
reason, exit 7, and do not touch the file. The stub is now used only when there is no record at all.

WHAT IT REVEALED once the file was preserved: on YOGA the module had been running fine -- verdict RISKY,
present=17 absent=0 different=0 BREAKS=0 over 98 consumed entries / 34 distinct keys, 17 unverified. The gate was
never broken; only its reporting was. And the earlier BREAKS (the retired DeepInfra 0731 entry, S001) disappeared
once that entry was removed from the settings layers, which is a separate fix recorded in H10220.

THE TRANSFERABLE RULE: a reporter must never overwrite the reading it is reporting on. If the downstream artefact
exists and says something, that sentence is the answer; a wrapper's complaint about it is not. Watch for this
whenever a verb shells out to a module and then judges the module's output -- the wrapper tends to write its own
"it didn't work" file at the same path.
