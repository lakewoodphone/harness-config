**L3403 · Check the running container before believing a capability is missing - and drive the service, not the table**

**The code that gives a feature its data may already be in the running image while both disk checkouts
are behind it - so read the CONTAINER before concluding a capability is missing.** 2026-10-07's
measurement ("`repair_intake_case_photos` exists with 0 rows and no app code writes it") was true that
day and false the next: the deployed backend at revision `1e6a6ee8c` carries
`backend/src/routes/repair-intake.routes.ts` and
`backend/src/services/repair-intake-cases/repair-intake-case-photo.service.ts`, and neither file exists
in `C:\Users\ezabz\Code\phone-and-tech-full` (HEAD `1ba47a6c`) nor in the authority's checkout. A
session that trusted the checkout would have concluded the feature did not exist and started building
a second one.

Rule: before designing around a missing capability, ask the running thing.
`docker inspect <c> --format '{{.Config.Cmd}}'`, `cat /app/REVISION`, then
`docker exec <c> sh -lc "grep -rl <symbol> /app | head"`. And `git show <revision>:<path>` against the
local clone works whenever the commit is present locally — no checkout, no branch switch, no disturbing
another session's working tree.

**Second half of the same lesson: the deployed service can be driven directly, and that is not a second
write path.** The photo service's own file-header comment says the REST route is the staff surface; but
`attachPhotos` is the thing that validates the mime type, the 10 MB cap, the sha256 and the per-case
position lock, and it is the only thing holding the R2 client. Calling THAT, inside the app's own
container, through the app's own `PrismaClient`, is one writer with one set of rules. Hand-written SQL
against `repair_intake_case_photos` plus a `PUT` with the backup credentials would have been two. The
distinction is not "route vs script": it is whether the app's own validation and its own client are the
thing doing the work.

Evidence: H3384; `lpt-ops/docs/photos.md`; commit `2865c9e`.
