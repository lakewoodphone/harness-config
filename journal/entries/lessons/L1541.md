**L1541 · A code default is not the behaviour: read the running container against the declared default, and report the measured effect not the setting**

**Evidence, 2026-09-15 (PART-119).** Three separate findings in one part came from reading running configuration rather than source, and none of them were visible in code or tests:

| What | Code default | Production | Test |
|---|---|---|---|
| `JWT_EXPIRES_IN` | **`15m`** (`backend/src/config/security-env.config.ts:37-40`) | **`7d`** | **`7d`** |
| `GOOGLE_OAUTH_ENABLED` | gate returns 503 when unset/absent | **absent → 503** (PART-118) | present → enabled |
| `CUSTOMER_ACCOUNT_CREATION_MODE` | **`disabled`** when the env var is absent (`customer-account.service.ts:110-127`) | `hybrid` | `hybrid` |

The `JWT_EXPIRES_IN` one is the sharpest: **672×** the intended access-token lifetime, invisible to 115 green auth tests, and its effect is measurable in data — **all 287 sessions in `lpt_prod` have a TTL of exactly 168.00 h**, which is what turned "the env file looks wrong" into "every session ever created is wrong".

**The rule.** A code default is a promise about behaviour that holds only until someone sets an environment variable. When auditing an auth or security surface, read the **running container**, not the schema and not the `.env` you found first:

 docker exec <container> printenv | grep -E '^(JWT_|SESSION_|CUSTOMER_|GOOGLE_)' # names only

and then map each value to the code's declared default. A value that differs from its default is a **decision someone made**, and it belongs in the audit whether or not it is wrong.

**And the second half of the rule, which is the part that is easy to skip:** report the *effect*, not the setting. `JWT_EXPIRES_IN=7d` is a line in a file; "all 287 sessions have a 168-hour TTL" is a fact about the system. When the two are both available, the measured effect is the finding and the config line is only its explanation.

**Cross-check for the same class in this fleet:** the same inspection found production and test **agreeing** on `CUSTOMER_ACCOUNT_CREATION_MODE=hybrid` — which mattered, because the code default is `disabled` and a claim that self-service was switched off would have been wrong. The check cuts both ways: it kills false alarms as well as finding real ones.
