**L3637 · A missing module degrades silently to the most conservative verdict, which looks exactly like the system working**

Measured 2026-10-13, on the owner text line.

`safe_decide4` in `sms-responder.py` is written with the right instinct: a missing or broken
decision layer "must never invent an action", so it returns NOISE - no message, no work. That
instinct is correct and it is also why nobody noticed for days.

 if decide_mod is None or not hasattr(decide_mod, "decide4"):
 return blank # {"decision": "NOISE", "why": "textdecide unavailable", ...}

Three consequences, each measured:
 * The system kept running, kept logging, kept exiting 0. Nothing failed.
 * Every inbound text - including a direct instruction and an answer about a business loan - was
 classified NOISE and dropped. The owner experienced silence, and reported it as a defect
 ("Your unified brain is not working"), which was the only signal that anything was wrong.
 * The reason string was the SAME for "module absent" and "module present but lacks the function",
 so deploying the wrong `textdecide.py` produced an identical reading. Two different faults,
 one message, no way to tell them apart from the log.

RULES.
1. When a fallback exists, it must NAME what is missing precisely enough to be actioned:
 `why="textdecide module absent"` vs `why="textdecide present but has no decide4 (has: choose,
 classify_text, ...)"`. Print the available attributes on the failure path.
2. A degraded fallback deserves its own alarm. A NOISE rate of ~100% on a personal line is not a
 quiet day, it is a broken component; `finance-freshness` is the pattern to copy - it reads the
 subsystem's own health and exits non-zero rather than trusting that a process that runs is a
 process that works.
3. Capability, not presence. A check that asserts "the file exists" passes on the file that cannot
 do the job. Assert `hasattr(mod, "decide4")`.
