**L3746 · Never write a machine's absolute layout into a shared script - resolve by env, then probe, then legacy path**

**Measured on `secratary-cloud`, 2026-10-12 (journal H3571).**

Three separate hardcodings broke the search system at the cloud cutover, and each one failed
*plausibly* rather than loudly:

| hardcoded | where | what it did on the authority |
|---|---|---|
| `~/.dsh/bin/find-anything` (as `/home/zabz/bin/find-anything`) | `data/tools/search.py:43` | `search backend missing at /home/zabz/bin/find-anything` — a path no cloud node has. Bound once at module import, so a long-lived API process could never pick up a corrected PATH either. |
| `$HOME/personal-secretary-mvp/...` as the code root set | `bin/find-anything` ROOTS | resolved **no roots at all**; every `code`, `files` and `symbol` call on the authority scanned an empty list. The checkout there is `/opt/company`. |
| `$H/harness-config/...` as the journal/scripts root | `bin/build-indexes.sh` | silently skipped that root on **every host it ever ran on** — harness-config lives at `$H/code/harness-config`. |

**The rule.** *Never write a machine's absolute layout into a shared script.* Resolve it, in this order,
and let an operator override it:

1. an explicit environment variable (`FA_CHECKOUT`, `FA_HARNESS_CONFIG`, `FIND_ANYTHING_BIN`);
2. a probe of the known candidate paths, first hit wins;
3. the legacy absolute path last, so nothing that already worked stops working.

And **resolve it per call, not at import** — a module-level constant is bound once, so a long-lived
service process cannot see a corrected path, and the operator's fix appears not to work.

**Why this class is dangerous.** Every one of these resolved to *something*, so the tool ran, exited
with a real code, and printed a confident answer — "not found", "no match" — where the truth was
"nothing was searched". A crash would have been caught in minutes. The estate's own convention already
covers it: exit **4** means NOTHING WAS SEARCHED and must never be rendered as a negative.

**The generalisation.** For any tool that must work on more than one machine, the test is not "does it
work here" but "does it report honestly on a machine that is not laid out the way I expect". Resolve,
then verify on the *other* host — the office box's copy of this engine worked perfectly the whole time
the authority's was blind.
