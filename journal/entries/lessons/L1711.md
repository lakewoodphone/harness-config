**L1711 · Count browser memory by private bytes, never WorkingSet - the 8.18 GB window figure was 2.2x inflated, and tabs cannot replace windows**

## Rule
**Measure private bytes, never `WorkingSet`, when counting a browser fleet.** A number that
double-counts shared pages will be believed and then acted on.

## Evidence (2026-09-16, ZABZ-YOGA)
The figure "12 Edge windows cost 8.18 GB" -- which I carried into this program from a prior
session's document -- is the **sum of `WorkingSet` across 113 msedge processes**. The same
fleet measured by `WorkingSetPrivate` is **3,622.9 -> 3,898.1 MB** (drifting up ~23 MB/min as
windows warm). `PERFORMANCE-MEASURED.md:142` already mandated private bytes; the 8.18 GB was
taken with the other counter. The error was ~2.2x, and it was used to argue about whether
windows were the binding constraint.

Correct per-window cost: **324.8 MB private mean, 9-10 processes each** (1 browser + 1 GPU +
2 renderers + 4-5 utility + 1 crashpad). GPU processes are one per profile (12 for 12 windows,
1,159 MB) -- each window has its own `--user-data-dir`, so nothing is shared.

## Consequence
Windows are **not** the binding constraint: at ~271-325 MB private each, this machine has ~46
windows of headroom before paging. Running agent turns are: measured 10 running = 28.7 GB commit
= 2.9 GB headroom, slope ~0.81 GB/turn, so ~13-14 turns pages. `maxParallelToolCalls: 20` costs
at most 1.12 GB and fits with 1.78 GB spare.

## Corollary that matters for design
**Tabs cannot replace windows.** All tabs of one origin share one
`localStorage["dsh.sessions.current"]`, and no URL carries session identity, so N tabs give one
session slot written by N pages -- not N parallel sessions. Independent parallel sessions
require separate origins, i.e. separate browser profiles. The right shape is 8 windows (the
configured count), for **correctness**, not for memory.
