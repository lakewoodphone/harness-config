**L3743 · A gitignored directory holding runtime state does not survive a migration - 599 of 607 tool bodies were lost at the cutover**

**Measured on `secratary-cloud`, 2026-10-12, in the hours after the cloud cutover (journal H3571).**

`data/tools/` is in `.gitignore` (line 58). It holds the *bodies* of the company's dynamic tools —
the files `run_tool()` actually executes. It is not configuration and not cache: it is the
implementation of 600 capabilities, and it lived only on the office box that the cutover was freezing.

Counted on the authority:

 registry entries total : 608
 status=active : 607
 active WITH body file : 8
 active WITHOUT body file : 599 <-- unreachable via /tools/run
 .py files actually in data/tools: 8

`run_tool()` answers `Tool <name> not found` from a single `if not tool_path.exists()`
(`app/tool_factory.py:705`). So **"it is registered" and "it does not exist" produced the same string**,
and every caller — including `ps_search`, the tool the `fast-search` skill instructs every agent to
use — received a message that reads like "no such tool" for a capability the system advertised.

**The transferable rule.** *A gitignored directory that holds runtime state will not survive a
migration, and nothing will tell you.* Registering a tool does not create it; a deploy from a branch
cannot carry what is not in the branch; and a missing file is indistinguishable from a typo unless
something asserts the invariant. Two things are required, and they are different:

1. **A guard**: `scripts/guards/tool-body-guard.py` asserts that every `status="active"` registry
 entry has `data/tools/<name>.py`. Exit 1 when not, and **exit 2 when it could not check** — a
 refusal must never be reported as a pass.
2. **A tracked copy, or an explicit decision that there is none.** Restoring the files fixed the
 outage; it did not fix the fact that 600 files still live outside version control.

**The generalisation.** Ask of any stateful directory: *is this in git, and if not, where is the second
copy and what checks that it exists?* If the answer is a shrug, the next migration loses it silently.
