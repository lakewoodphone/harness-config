**L1949 · E4610: Voice Access swallows injected keyevents, and Star opens the dialer**

Measured 2026-09-17 on E4610 serial 615765621 with Voice Access enabled and listening.

- Injected D-pad keys never moved focus: `input keyevent 20` produced Voice Access's "Sorry, didn't
 understand that" and left the same view focused. The accessibility service consumes injected key
 events before the focused window sees them.
- `input keyevent 17` (Star) — and `input keyevent --longpress 17` — on the home screen opens
 `com.android.dialer/.DialtactsActivityKc` with a `*` in the dial string (normal flip-phone
 dial-from-home behaviour); it does not toggle the MatVT mouse.

Consequences:
1. Before scripted UI work, narrow the service list so Voice Access is out of the way:
 `settings put secure enabled_accessibility_services <matvt>:<keysminimal>`, do the work, then
 restore the full three-service string. Save the full string first.
2. The MatVT boss key / mouse cursor can NOT be verified by injecting Star — that check needs the
 physical key. Do not claim "mouse verified" from an injected keyevent.
3. Prefer `input tap` (see the sibling lesson) over keyevents whenever both would work.
