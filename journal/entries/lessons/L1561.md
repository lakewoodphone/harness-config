**L1561 · A generated doc that CI diff-checks is part of the route change, not a separate task**

In kf2/measures-reader (parental content filter), adding two operator GET routes broke nothing in the pytest suite I was told to run, but CI's 'Verify generated documentation' step diffs docs/API_REFERENCE.md and docs/ARCHITECTURE_DIAGRAMS.md against freshly generated output. Two more findings from the same step: (1) the checked-in docs had already drifted from the prior merges (311 documented HTTP paths vs 317 real; 28 routers listed vs 30) - regenerating my own change forced the whole stale doc up to date, so the diff is larger than my change; (2) server/security/security_audit_signoff.json is a checked-in snapshot whose digests cover the route surface, so test_security_audit_report.py and test_security_audit_signoff.py fail on ANY route addition. Regenerate it with scripts/security_audit_signoff_report.py --write-snapshot, and pass --reviewer/--review-method/--review-notes explicitly: the script defaults OVERWRITE the file's own honest metadata ('automated' / 'NO MANUAL SECURITY REVIEW WAS PERFORMED') with 'code_backed_manual_signoff', which would make a generated file claim a human review. Rule: before calling a backend change done in this repo, run the three CI generators plus find_unused_settings.py --fail-on-unused, and read the snapshot diff for metadata you did not mean to change.
