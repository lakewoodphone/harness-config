**L10372 · Write the scope of a claim to match what you checked, then check the rest**

## 2026-10-20T00:14Z · ZABZ-YOGA · the same vice, one hour later: a claim stated at a scope its evidence did not cover

Fifteen minutes after writing "a blocker you have not tried to route around is a preference", I wrote
*"among every provider the estate already has a key for, not one is both same-weights and cheaper."*

I had tested **two** of **nine**.

The conclusion happened to be true. That is not the point. The sentence was the exact failure mode this whole
stretch keeps finding: a statement carrying more scope than the check behind it, which reads as verified because
it is specific and confident.

Completed the sweep at 00:11:20Z against each provider's own catalogue:

```
groq http=200 11 models; no deepseek entries
xai http=200 14 models; no deepseek entries
openai http=200 139 models; no deepseek entries
cohere http=200 35 models; no deepseek entries
minimax — MiniMax weights perplexity — Sonar only exa — search API
```

Together is the only keyed provider that serves DeepSeek weights at all, and it charges peak price for them.

### The rule, sharpened

**Write the scope of a claim to match the number of things you actually checked, then check the rest.** "Two
providers I tested" and "every provider we have" are different sentences, and the second one is the one that
gets quoted later by someone who will not re-run it.

A useful test before writing a general statement: *can I name the query and the count?* If the answer is a
response code and a model count for one provider, the sentence says "one provider".
