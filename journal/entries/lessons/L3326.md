**L3326 · In this repo a .test.tsx is compiled by NOTHING: vitest includes only src/**/*.test.ts, so render components with react/jsx-runtime inside a .test.ts**

MEASURED IN _ov_card (branch overhaul/question-card), 2026-10-05.

`s\src/components/question/question-card-pieces.test.tsx` did not run: `vitest.config.ts` has
`include: ["src/**/*.test.ts"]`, so a `.tsx` test file is discovered by nothing. A suite that never
runs is indistinguishable from a suite that passes, which is the exact failure the brief warns about.
Writing JSX in a `.test.ts` file is a parse error in tsc and in vite:oxc.

WHAT WORKS, NO CONFIG CHANGE NEEDED
Call the jsx-runtime factories directly, in a `.ts` file, under the node environment:

 import { jsx } from "react/jsx-runtime";
 import { renderToStaticMarkup } from "react-dom/server";
 const html = renderToStaticMarkup(jsx(AnswerField, { item, value: null, ... }));

`renderToStaticMarkup` needs no DOM, so the whole question card can be rendered for real and asserted
on with `html.indexOf(...)` - including its ORDER, which is the only way to test "the options come
before the Continue button" without a browser. Use `jsxs` when a component takes an array of children.

If a `.test.tsx` is genuinely wanted, `vitest.config.ts` must gain it to `include` - which is a change
to a shared file, not something a component phase may do on its own.

Caveat to state in any report: server-rendered markup has no effects, no layout and no interaction, so
it proves order and content, never position. Position came from Playwright (see H3232).
