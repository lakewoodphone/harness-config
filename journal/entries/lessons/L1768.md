**L1768 · A schedule column nobody reads is a decorative field**

The `reminders` table has a `recurrence` column (app/database.py ~1210) and `create_reminder()` accepts `recurrence=` (~8930). Grep across app/ found ZERO code that reads it: `mark_reminder_delivered()` (~9044) just flips status to sent/expired, and `process_due_reminders()` (app/services/personal_ops.py:690) never mentions recurrence. So a reminder created with recurrence="monthly" fires ONCE and then is a dead row forever.

Same failure class as the hardcoded-model incident: a field set, looked configured, and silently did nothing.

RULE: before creating anything with a schedule/recurrence/cron field, find the code that READS it. If no reader exists, the field is a lie, and the deliverable is not the row - it is the reader. "It is configured" is not evidence; the only evidence is an observed second firing.
