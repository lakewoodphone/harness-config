**L3873 · Grading corrected: usage + kernel red flags + keypad; cosmetics never change the grade; my own probes were the 'red flags'**

CORRECTION, 2026-10-19 evening. The owner stated the grading method and it is not what I built:

 "We do gradings based on how much the phone is used, if there's any red flags in the kernel and things like that, keyboard switches, an external check ... It doesn't change the grading."

What I had was backwards: a functional grade from check statuses, a cosmetic grade from eyes, and overall = the worse of the two. Cosmetics DO NOT change the grade. Rebuilt:

- USAGE: charge counter, battery health flag, capacity where a learned figure exists, user-installed apps -> band light / normal / heavy.
- KERNEL RED FLAGS: dmesg patterns (cal block, thermal, storage, panic, watchdog), SELinux state, build type, bootloader, root, and dropbox crash/ANR records -> severities B/C/D.
- KEYPAD SWITCHES: the bench sweep, all / partial / untested.
- Bands: A light+clean+all keys; B normal use or a non-blocking flag or keypad untested; C heavy use or a C flag or partial keypad; D panic/root/unlocked bootloader/non-production build.
- The external check is a separate recorded column and never moves the letter.

TWO FALSE POSITIVES the first run produced, both caused by my own audit:
1. `avc: denied ... scontext=u:r:shell:s0` is our own `ls`/`df`/`cat` hitting restricted paths, not a fault. It flagged every handset.
2. `system_server_wtf` is a logged warning, not a crash - 59 of them on one handset, all timestamped the minute the SIMs went in. Counting them made every phone look unstable.
Both excluded, both pinned by tests.

THE HARD LIMIT worth knowing: on the E4610 the kernel ring buffer read by shell holds only ~13 lines because logd consumes it. The one real flag seen today ("core_set_license: Invalid cal block to send") had rotated out by the next audit. So "no kernel flags" means "nothing visible in the last few lines", not a clean bill. E4810 dmesg is empty for non-root, /proc/last_kmsg does not exist and /sys/fs/pstore is denied. The dropbox is the only crash history that survives reboots. If kernel red flags become a primary grading input, the upgrade is reading /data/system/dropbox in full (root) or collecting dmesg continuously instead of once per audit.

CURRENT: all five grade B - light usage, no visible red flags (E4810s carry "kernel log not readable on this firmware" as information), keypad untested. Pressing the keys on all five would take them to A if nothing else appears.

Code: cli/lpt/condition/grade.py, docs/condition-audit/grading.md (rewritten), cosmetic-grades.txt (external only), commit 9fae40cc. 34 tests pass.
