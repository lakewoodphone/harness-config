**L1826 · macOS: never invoke bare tailscale over ssh -- and a subprocess timeout that kills only the shim leaks a spinning orphan**

Measured 2026-09-16 on the Mac Mini. /usr/local/bin/tailscale is a three-line shim that execs the
Tailscale GUI app binary, which never answers a non-interactive ssh invocation.
subprocess.run(['tailscale','status','--json'], timeout=10) kills the SHIM; the shim's forked
grandchild keeps the stdout pipe open, so the caller waits for EOF FOR EVER, the lookup thread
blocks for ever, and an orphan spins at ~1.4% CPU for ever. Thirteen of them had accumulated --
one per session that touched the CLI -- and between them they pinned Apple's network-extension
host nesessionmanager at 33.5% of a core continuously for 32 hours.
RULE: on macOS use /opt/homebrew/bin/tailscale (talks to the running tailscaled; 0.01-0.02 s
measured), pass start_new_session=True, and kill the PROCESS GROUP on timeout, not the child.
The callers were phone-gate.py and phone-redirector.py -- our own code.
