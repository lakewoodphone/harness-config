**L6266 · Landing the attention fixes: bare stash pop, a control that proved nothing, and a dry run that found the design error**

# Lessons — 2026-10-15, evening: landing the attention fixes

**L-8. `git stash pop` with no stash named pops ANOTHER session's work.** In a worktree sharing a
repo, `git stash push -- <paths>` says "No local changes to save" when the paths are already committed —
and the following bare `git stash pop` then pops **stash@{0}, which was someone else's `wip-bd84`**.
Measured 2026-10-15: it applied with conflicts to two finance docs and silently staged a third file.
Nothing was lost (a failed pop keeps the entry), but it could have been. **So: always
`git stash pop stash@{N}` by index, or better, `git stash push -m "<what and why>"` so the entry is
identifiable, and never pop bare in a repo another session can reach.**

**L-9. The control run must isolate the CODE, not the code and the test together.** My first control for
the bulk-ordering change stashed both the script and its test file, so the new tests vanished and the old
suite passed — proving nothing while looking like a passing run. The correct control reverts only the
implementation and keeps the new tests, so they run against the old behaviour. **So: before quoting a
control, ask "did the new test actually execute against the old code?"** In this session the honest
control was `git show HEAD~1:<file> > <file>`, run, then `git checkout HEAD -- <file>`.

**L-10. A hand-rolled tripwire on an import has to allow `__path__`.** A `ModuleType` subclass whose
`__getattr__` raises on everything dies on `__path__` the moment Python imports a submodule, so the test
fails for a reason that has nothing to do with the behaviour under test. Give the fake module
`__path__ = []` and spy on the *named* functions instead. **So: spy on the API, not on attribute access.**

**L-11. `install -o "$(stat -c %U ...)"` fails on a numeric-only user, and fails AFTER saying nothing.**
`install` returned `invalid user: 'UNKNOWN'` on the authority, so the file was never replaced — and the
script carried on to restart the service anyway, reporting a healthy 200 for a deploy that had not
happened. **So: (a) install by writing in place — `cat NEW > LIVE` keeps inode, owner and mode and cannot
invent a user; (b) every deploy script must compare the sha of what landed against the sha of the source
and abort loudly when they differ, BEFORE it touches a service.**

**L-12. A `find /` count is not the count of the thing you care about.** I reported "201 profile copies
accumulated" from `find / -maxdepth 7 -name 'account_[0-9]*.broken-*'`, which swept up pytest worktrees
under `/root/work/*/_pt*/gv_profiles`. The live directory holds **11**. The headline was 18x the real
damage, in the direction that makes the story better. **So: scope the measurement to the directory that
matters before quoting it as a cost.**

**L-13. A dry run is not a formality — it is where the design error shows up.** The personal-mail
reservation passed 20 unit tests and then, on its **first live run**, filled both reserved slots with
American Express notices while a relative's request sat below them. No unit test could have caught that,
because the fixtures were mine. **So: run the thing against real data before calling it done, and treat
what the first run selects as evidence about the selection rule.**
