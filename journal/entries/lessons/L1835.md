**L1835 · A hardware-derived constant is not a constant: the broker's 3885 MiB reserve was one machine's number**

The mesh broker's `3885 MiB` reserve was ONE machine's number applied to four, and on the biggest
node it was wrong in the dangerous direction.

`packages/plugin-health/lib/governor.js:126` is
`reserveBytes = max(2 GiB, round(totalBytes * 0.12))` — a PER-HOST quantity, because it is the
memory held back on that host for everything that is not a tool process. docs/mesh/71 §2.1 said so
correctly for the gate. docs/mesh/71 §2.2 froze the number it produces on the 31.6 GB laptop and the
broker used it as a literal for every node.

MEASURED 2026-09-17 03:36-03:45Z from each node's own §2.1 document (`mem.totalMiB` was already
being reported):

 zabz-tech-linux 11,673 MiB -> 2,048 (2 GiB floor binds) frozen 3885 over-reserved by 1,837
 secratary 23,422 MiB -> 2,811 frozen 3885 over-reserved by 1,074
 zabz-yoga-1 32,373 MiB -> 3,885 frozen literal is EXACT here
 zabz-tech 65,173 MiB -> 7,821 frozen 3885 UNDER-reserved by 3,936 MiB

Right on one of four, and under-reserved by ~24 slots on the node work actually lands on.

RULES.
1. A constant derived from one machine's hardware is not a constant. If a value comes from
 `totalmem()`-style arithmetic, it is per host — pass the host's own measurement in, and name the
 basis (`derived` / `floor` / `fallback`) in the output so a silent substitution is impossible.
2. When two frozen documents disagree, prefer the one that is a DERIVATION over the one that is a
 NUMBER, and correct the other. §2.1's `max(2 GiB, 12% of physical)` is a rule; 3885 is a result.
3. A cap hides this class of bug: `maxSlots=24` made the §2.2 worked example produce `score 9` under
 either reserve, so the pinned test could not see the error. Assert on the INTERMEDIATE numbers
 too, not only the published one — the updated test now asserts `reserveMiB == 7819` and
 `beforeCap == 269` explicitly.
4. The gate's own `governor.budgetSlots` is ADVISORY and must not be consumed as capacity: it is
 floored at 4 and capped at 24, so it reports "4 slots" for a node with no headroom and hides the
 difference between a 64 GB desktop and a 24-core box behind the cap.

Implementation is `lib/scoring.js reserveMiB(reading)`; `3885` survives only as the documented
fallback for a node reporting no `mem.totalMiB`. Full record: docs/mesh/86-authority.md §3.
