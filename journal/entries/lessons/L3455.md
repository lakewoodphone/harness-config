## A same-shaped path on another machine is NOT the same file — check hostname before believing a brief

Measured 2026-10-11, building the Yanofsky profile.

I probed the mesh before fanning out. The probe child landed on `ZABZ-TECH` and reported honestly:
hostname `ZABZ-TECH`, Windows 11, cwd `C:\Users\ezabz`, and `C:\Users\ezabz\code` **exists and I can
list it**. It is a *different filesystem* from this laptop's `C:\Users\ezabz\code` — the listing it
returned shared almost no entries with mine. Later children ran on a third host, `zabz-tech-linux`,
where the path is `/home/zabz/code`.

The trap this sets: a brief that says "read `C:\Users\ezabz\code\<dir>\<file>`" will be answered —
successfully, with a real file — on a machine where that directory exists but contains somebody
else's content. No error, no denial, just the wrong bytes. And on this estate the shape is
deliberately identical across nodes, because the repos are the same repos.

What to do, and what worked here:

1. Every worker brief states **"run `hostname` first"** and gives the input path **per platform**
 (`C:\Users\ezabz\...` and `/home/zabz/...`), with the instruction to stop and say so if neither
 exists — never to fall back to a near path.
2. Before a fleet, decide **where the inputs live** and therefore where the workers must run. Files
 that exist only on the laptop cannot be read by a child on another node, full stop.
3. When the work is file-local, run the children locally and say so in the report. Here the book
 half ran on this laptop for exactly that reason (the second reason being the broker outage), and
 that split is written into `SOURCES.md` §2 rather than blurred.

Corollary worth as much as the rule: the same trap applies to *outputs*. A worker that writes a
report "into the profile directory" on another node writes it to that node's disk. Collection is a
separate, explicit step (`tools/collect.ps1` in this job: scp from four aliases, dedupe by name,
keep the larger file, report the conflict).
