**L3147 · CORRECTION of L3146: mesh children CAN push - I over-generalised one uncommitted tree into a rule, which is the error I have spent the day correcting**

2026-09-30 round 36. L3146, written two rounds ago, states that a mesh child cannot push because git push runs over ssh and ssh hangs from inside a child, and it tells future briefs to make the child commit locally and let the manager push. THAT IS TOO STRONG AND IS CORRECTED HERE. subagent-141, running on the same laptop, committed and pushed successfully in this round: commit fcc4217 onto agent/deployed-truth, reported as 6f01ddf..fcc4217 HEAD -> agent/deployed-truth with exit 0. So pushes from a mesh child work. What I actually observed in round 34 was an uncommitted tree on that laptop, which is equally consistent with a child that had not yet finished, and I turned that single observation into a rule - the precise failure this session has corrected four times already in items 54, 12 and 13, 161, and my own Qwen candidate. The CORRECTED statement: an ssh call from inside a mesh child can hang and never exit, which is proven by a controlled probe and by nine audit children lost this morning; a git push MAY therefore stall, but it demonstrably often succeeds, so the brief should say commit and push AND report the commit hash, with the manager verifying the remote afterwards rather than assuming either outcome. The rule is: verify the push landed, never predict it. AND THE GENERAL RULE THIS COST: one observation is not a pattern, and a lesson written from one observation becomes policy that is wrong for everyone who follows it. L3146 was written minutes after the observation, before any child had reported, which is exactly how L3106 went wrong this morning too.
