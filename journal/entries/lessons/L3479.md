**L3479 · Parallel image reads: one subagent per photo, JSON back, keeps the parent's context flat**

WHAT I DID. 21 shop photos needed reading. Instead of reading them in the session (21 images x ~1.5k tokens of pixels, permanent), I launched one child per photo, each told to read exactly one file with read_image and return ONE JSON object against a fixed schema. 21 children, ~4 minutes wall clock, and the parent's context grew by the parsed JSON only.

WHY IT MATTERS. The same shape works for any corpus of images or files that must be read uniformly: fan out one child per artefact, give every child the IDENTICAL contract, collect structured JSON. It also gives free disagreement detection - two children reading the same photo independently disagreed on IMG_1125 (battery vs charge-port flex) and on IMG_1129, which is real evidence a single read would have thrown away.

THE CONTRACT IS THE ARTEFACT. Put the prompt in a file (tools/parts-catalog/tools/lptparts/prompt.py) and write it into the batch (prompts/per-photo/*.prompt.txt). Then any agent - this harness, a mesh child, a future local model, a human - can do the reading, and no model id is baked into the tool.

CONSTRAINTS FOUND. From here, subagent_local runs the child on THIS machine (ZABZ-TECH) - and `subagent`/`subagent_remote` (the mesh) was unreachable all session: "broker-unreachable: the placement broker could not be reached at secratary-ts:http://localhost:3091/place - ssh exited 7". So every result was LOCAL and must be reported as LOCAL.

EVIDENCE 2026-10-10/11: subagent-3..subagent-23 (21 jobs), each returned one JSON object; verified a child can genuinely perceive pixels (asked one to transcribe a battery label verbatim and it returned EB-BA217ABY, 3.85V, 4900mAh/18.87Wh, 5000mAh/19.25Wh - all correct vs the image).
