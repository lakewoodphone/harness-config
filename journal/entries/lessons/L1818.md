**L1818 · Provisioning from Windows: scp dies on a C:/ path, and errexit kills a run over a cosmetic du**

Two transfer/errexit traps that each cost a provisioning run, both hit while building a Linux mesh
node from a Windows laptop on 2026-09-16.

1. `scp` is NOT portable when the script runs under MSYS/git-bash. `bash -c 'scp -q local user@host:/path'`
 works, but `scp -q "$self" host:dest` where `$self` is `C:/Users/...` (a path with a drive letter,
 i.e. what BASH_SOURCE gives when bash is invoked with a Windows-style path) dies with
 `scp: Connection closed` and exit 255. Nothing about the host is wrong. The portable replacement,
 used for every transfer in scripts/provision-mesh-node.sh, needs no sftp subsystem and cannot mangle
 a path:
 push_file() { ssh "$t" "cat > '$d'" < "$src"; }
 pull_file() { ssh "$t" "cat '$p'" > "$dst"; }
 push_tree() { tar -c -C "$src" . | ssh "$t" "mkdir -p '$d' && tar -x -C '$d'"; }
 Note /usr/bin/scp (MSYS) worked while a first PATH entry of C:\Program Files\OpenSSH\scp.exe is a
 different program with different rules; `command -v scp` differs by login vs non-login shell.

2. `set -euo pipefail` turns a COSMETIC measurement into a fatal abort. `aptsize="$(du -sh /var/cache/apt
 | cut -f1)"` exits 1 on this host because du cannot read a root-only subdirectory while still printing
 the size it could read; pipefail propagates it and errexit kills the run 30 lines later with no message.
 Same class: any `cmd && var=1` used as a statement, and any `[ test ] && x=y`. The habits that fix it:
 `|| true` on every pipeline whose only job is to print a number, and `if cmd; then var=1; fi` never
 `cmd && var=1`.
 The abort was CORRECT — it caught a real unchecked failure — so the fix is to guard the command, not
 to drop errexit. Also: run each half of a script in `( set -e; half )` and read `$?`, never
 `set +e; half; rc=$?`, which silently disables errexit for the whole half.

Evidence: scripts/provision-mesh-node.sh before/after; the failing transcripts are in
~/.dsh-mesh/provision-20260916T231440Z.log (the exit-1 abort) on zabz-tech-linux.
