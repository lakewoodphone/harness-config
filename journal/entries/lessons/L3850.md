**L3850 · E4810 music + pictures: what the no-media profile really disables, and the exact restore**

E4810 serial 558800292460 (IMEI 015588002924600): music + pictures restored for a customer who wanted them back.

## What was actually disabled (device read, not config read)

`adb shell pm list packages -d` on 2026-10-18 listed 22 disabled packages. The three that
constituted "music and pictures" — all `enabled=3` (COMPONENT_ENABLED_STATE_DISABLED_USER, i.e.
`pm disable-user --user 0`):

- `com.kyocera.musicplayer` — stock music player (music)
- `jp.kyocera.camera` — camera (pictures)
- `jp.kyocera.gallery.launcher` — the gallery *entry* shim (pictures)

**The photo viewer was never disabled.** `jp.kyocera.datafolder` (which holds
`jp.kyocera.gallery.GalleryActivity`, plus the CyanogenMod file manager and the movie viewer) read
`enabled=0` = default/enabled the whole time. So "pictures" was only ever the camera + the gallery
icon, and the tier config's `gallery: jp.kyocera.datafolder` line is about the viewer, not about
what the no-media profile switches off.

`jp.kyocera.gallery.launcher/.activity.MainActivity` is a 1.0.0 shim: `am start -W` on it returns
`Status: ok` and hands off to `jp.kyocera.datafolder/jp.kyocera.gallery.GalleryActivity`, which is
what ends up resumed. Launching the datafolder activity directly is the more direct check.

## What was done

```
adb -s 558800292460 shell 'pm enable com.kyocera.musicplayer; pm enable jp.kyocera.camera; pm enable jp.kyocera.gallery.launcher'
```

Each returned `new state: enabled`; each reads `enabled=1` afterwards. Proof they open, not just
flag-flipped — resumed activity read back after each launch:

- `com.kyocera.musicplayer/.TopMenuActivity`
- `jp.kyocera.camera/.MainActivity` (resolve it with `cmd package resolve-activity --brief`; there is
 no `.CameraLauncher` activity, that guess fails with "Error type 3")
- `jp.kyocera.datafolder/jp.kyocera.gallery.GalleryActivity`

No `FATAL EXCEPTION` / `ANR in` in logcat after the three launches.

## Left alone on purpose

Still disabled: `com.android.mms` (stock SMS — texting is off on this handset), `com.android.email`,
`com.android.exchange`, `com.android.browser`, `com.mobisystems.office.kyocera`, `com.vcast.mediamanager`,
`jp.kyocera.kc_fmradio`, `jp.kyocera.kc_soundrecorder`, `com.ffm.kyocera`, the Verizon stack
(`bootstrapclient`, `mdm.xvlte`, `mips.services`, `obdm`, `obdm_permissions`, `pushtotalkplus`) and
`jp.kyocera.oemsetupwizard`, `jp.kyocera.WebViewer`, `jp.kyocera.vzwextension.service`.

## Consequences to say out loud

- On E4810 the stock music player registers video handlers, so restoring music (and the gallery)
 puts **video playback back within reach**. Documented, and unavoidable without modified
 DataFolder firmware: docs/devices/E4810_GALLERY_VIDEO_ARCHITECTURE.md.
- A later re-run of a `no-media`/`no-video` profile (or `finalize-e4610-standard.ps1`) will
 re-disable these three. This change lives on the handset only.

## Record trail that did not exist

- Only deployment receipts on disk for this serial are two from 2026-04-17, profile
 `standard-no-text` (forced-disabled `vzmsgs` + `com.android.mms`; no media entries) — so the
 media removal was not recorded in a receipt here.
- `deployments` table does not exist in the production store DB (`d5oq83veii4rlb` on
 co8c1665c0p5k…) even though receipts cite `deployments.id`.
- No `orders` row carries this serial or IMEI in `deviceInfo` (0 rows), so there was no case to
 append a note to. Case identity is still unknown; ask for the WO number if a note is wanted.

## Trap hit on the way in

`adb devices` showed `558800292460 unauthorized` and `adb shell` failed with
"This adb server's $ADB_VENDOR_KEYS is not set". Cause: this PC's adb key was replaced
2026-07-05 (`~/.android/adbkey_pre_shapiro_swap`, `adbkey_backup_20260608_162216`) and the phone
still trusted the older key. Owner re-authorised the new key on the handset; nothing else was wrong.
