**L3862 · First live batch: a sleeping phone fakes a dead mic and camera; no sensor stack; wlan0 needs the radio on; input threads are on demand**

Five facts from the first live batch (2026-10-19, five handsets, artifacts under `lpt-flip-phone/cli/logs/condition/` and the write-up in `docs/condition-audit/batches/2026-10-19-first-five.md`).

1. **A sleeping handset manufactures hardware failures.** Two E4810s (Android 9) asleep on the cable reported microphone ambient -120 dBFS, loopback -120 dBFS on both capture sources, and camera "Fail to connect to camera service" - all sale-blocking, so both phones came out NOT_SELLABLE. `dumpsys media.camera` showed 1 device and 0 active clients, `dumpsys power` showed `mWakefulness=Asleep`, and the same app on three E4610s (Android 7.1) captured audio and a 2592x1944 JPEG on the same cable. Android 9 blocks camera and silences the mic for an app that is not visible; 7.1 does not. Fix: the bench now wakes the handset, dismisses the keyguard, and refuses to run if it cannot. Re-run: both passed at -13.9 and -13.6 dBFS.

2. **Neither Kyocera model has an Android sensor stack.** `pm list features` declares no `android.hardware.sensor.*`; `dumpsys sensorservice` answers "No Sensors on the device" on both E4610 and E4810. There is no accelerometer - which also means the vibrator cannot be proven by motion. It is proven by the vibrator service logging the request (`timeout: 700 ... opPkg: com.lpt.bench`) plus a hand on the phone.

3. **`wlan0` only exists while Wi-Fi is on.** `wifi_on=0` means no interface, so `cat /sys/class/net/wlan0/address` returns cat's error text - which is not a MAC and must be scored `n/a`, not "pass". Three E4610s with Wi-Fi on read real addresses (`24:29:fe:...`); two E4810s with it off could not be read at all.

4. **Audio input threads are created on demand.** A healthy E4610 passed the acoustic loopback at -13.9 dBFS while `dumpsys media.audio_flinger` showed zero input threads on that boot. Requiring an input thread failed a working microphone; only a missing playback path is a fault.

5. **Measured loopback spread across five healthy units: -13.6 to -13.9 dBFS, 33.1 to 56.2 dB over noise.** The original bars (-40 dBFS, 9 dB) were 16-26 dB looser than any healthy phone and would have passed a badly blocked speaker. They are now -30 dBFS and 20 dB - 16 dB below the worst healthy unit - and the calibration is recorded next to the constant.
