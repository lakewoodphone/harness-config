**L10434 · The phone profile anchor has one viable state and it is version-coupled: 0.2.0 anchor = engine exits 2, no anchor = nine estate plugins silently skipped, 0.2.1 anchor = the only runnable state**

MEASURED 2026-10-20 on secratary-cloud, while preparing the phone engine's window.

THE PHONE PROFILE ANCHOR HAS EXACTLY ONE VIABLE STATE, and it is version-coupled. Three states were tested on the
same box with the 0.2.1 candidate:
 1. anchor at 0.2.0 (the current state, 487 pnpm packages under /root/.dsh/profiles/web/node_modules):
 the engine EXITS with status=2 -- "scope: TWO COPIES ... every prompt will be rejected as session/agent-busy".
 Measured last night in the real switch (L10431), with the tree rolled back afterwards.
 2. anchor ABSENT (a probe home with settings, .credentials.yaml, .agent-presets and the profile patch but no
 node_modules): the engine boots but SILENTLY SKIPS nine of this estate's own plugin bundles, exit 0:
 dsh-plugin-attention, -attention-badge, -cost, -health, -mesh-http, -mobile, -remote-fanout,
 -session-link, -windows
 Each skipped with "cannot resolve profile bundle ... run 'dsh plugin --profile web install'". That is the
 same silent-skip class as the stage-home anchors on 2026-10-19, and it means deleting the anchor trades a
 crash for a quiet loss of the phone's plugins.
 3. anchor rebuilt at 0.2.1: the only state that runs the new engine WITH the estate's plugins. Not yet built.

SO THE PHONE WINDOW'S WORK IS FIXED, not exploratory: with the engine stopped, `pnpm install` in
/root/.dsh/profiles/web against the 0.2.1 engine root (the profile carries pnpm-workspace.yaml, 61 B), then the
same ladder as scripts/switch-phone-engine.sh: prove by composing with the candidate binary, swap the tree by
rename, start, verify version + HTTP + a real turn, roll everything back on any failure.

WHY THIS CANNOT BE DONE AHEAD OF THE WINDOW: the anchor is the tree the RUNNING 0.2.0 engine loads its modules
from. Rewriting it while the service is up breaks the live phone; that is the same "the engine owns it" rule as
L10302, applied to a module tree instead of a settings document.

CLEANUP: the probe home (/root/.dsh-021-probe) was removed after the reading; it held copies, not originals.
