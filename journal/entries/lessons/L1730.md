**L1730 · sync.py copies presets from the working tree on a timer: land the adder before the remover, because the preset lands first**

`scripts/sync.py` copies `presets/` into `~/.dsh/.agent-presets/` from the REPO WORKING TREE, not from HEAD, and it runs on a timer (PersonalSecretary-HarnessSync) — while `autosync.ps1` exports HEAD to a temp snapshot and runs sync.py from THAT snapshot. So a preset edit lands in a live engine's preset directory without any restart and without any commit.

Consequence, measured while landing the list_agents replacement (2026-09-16): a preset edit that only makes sense AFTER a plugin is mounted leaks FIRST, because the plugin needs an engine restart and the preset does not. Deleting the shipped `tool-subagent-list-agents` row before the restart would have left ZABZ-YOGA sessions with no `list_agents` at all in the interval.

The ordering rule that follows: when a change removes a contribution and another change adds the replacement, land the ADDER first (even though it is inert until a restart), then the REMOVER. And when the adder needs a restart, prefer gating the removal on something that is true only after the mount — here `disabled: !!js process.platform === 'win32'`, because the installer that provides the replacement is Windows-only.

Second-order rule: never assume a preset edit is "just a file change". It takes effect at the next preset mount (a new session), which is usually much sooner than the next engine restart.
