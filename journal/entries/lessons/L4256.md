**L4256 · The APN realm encodes the active IMSI — 311588 vs 311210 is the whole LPT cellular fault, and it was never the carrier or the filter**

**L — The APN realm string encodes the SIM's active IMSI: `.mnc588.mcc311` IS IMSI 311588**

**Read the realm, and you can see the identity.** Every Telnyx data session carries an APN realm of
the form `<x>-telnyx-internet-01.mnc<MNC>.mcc<MCC>.gprs`. I spent an hour treating that suffix as
opaque platform naming. It is not: `mnc588.mcc311` is MCC 311 / MNC 588 = **the IMSI 311588**, and
`mnc210.mcc311` is **the IMSI 311210**. The realm names the SIM profile the session ran on.

**Confirmed on screen, 2026-10-14.** On LPT2007, SIM Applications → Telnyx → Select Account lists
five profiles with an asterisk on the active one:

| slot | IMSI | what it is |
|---|---|---|
| IMSI1 | 22201 | MCC 222 / MNC 01 — Italy (TIM) |
| IMSI2 | 20601 | MCC 206 / MNC 01 — Belgium (BICS/Proximus) |
| **IMSI3** | **311210** | **US — Telnyx's own. Every working device runs this.** |
| IMSI4 | 313260 | US 313/260 — T-Mobile US |
| **IMSI5** | **311588\*** | **US 311/588 — selected on the four dead SIMs** |

Selection Mode was `Automatic*`, Fallback Status `Enabled`, and **no OTA update has ever been pushed
to the account** (`GET /ota_updates` → 0 rows). So the applet selected 311588 on its own, on the
four SIMs bought 2026-10-13 (2005, 2006, 2007, 2008) while 2004 — same purchase, same minute — got
311210 and carries data.

**The split, and it is total:**

| realm / IMSI | DRNs | consumed |
|---|---|---|
| 311210 | 2001, 2002, 2004 | 0.93 / **112.93** / 1.22 MB |
| 311588 | 2005, 2006, 2007, 2008 | 0.015 / 0.081 / 0.057 / 0.062 MB |

**And it is not the carrier** — 2006 sits on T-Mobile on the 311588 profile with the same ~zero.
That is why "switch to T-Mobile" looked like no fix at all, and why banning AT&T was wrong: the
variable was never the network, it was which of the five identities the SIM was using.

**Two eliminations worth keeping**, both done the hard way on 2026-10-14:
1. **Carrier** — eliminated by 2006 above.
2. **Our filter** — eliminated by test. The DNS (managed DoH, `AllowFailover: false`) and web-trap
 (global proxy, `ProxyPACFallbackAllowed: false`) profiles were removed from DRN 2007 and verified
 gone from the device's own ProfileList (only the APN profile and MDM enrolment remained). Still
 no data. The device wears **the identical 14 profiles** as the working DRN 2002, so the filter
 was never the differentiator on paper either.

**There is no API to set a SIM's IMSI.** Searched the whole Telnyx OpenAPI spec: the only IMSI
surface is `GET /ota_updates` (read-only), and there is no `network_preferences` path. A wrong
profile is fixed on the device (SIM Applications → Telnyx → Selection Mode) or by Telnyx support
pushing an OTA. **Anything that needs a menu tap on a customer's phone is not a fix — it is a
support call**, so the durable answer has to come from Telnyx.
