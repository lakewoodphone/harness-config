**L4128 · A Telnyx eSIM pinned to AT&T attaches, creates data sessions, and moves no payload**

**L — A Telnyx eSIM pinned to AT&T attaches, creates data sessions, and moves no payload**

Measured 2026-10-14 on the LPT Waze fleet (7 Telnyx IoT eSIMs, DRN 2001-2008). Two faults
stacked, and fixing the first hid the second.

**Fault 1 — Data Roaming OFF.** Already known (L3788). Not re-litigated.

**Fault 2 — Network Selection pinned to AT&T**, which L3788 did not cover. On DRN 2007
(`LPT2007`, serial `C7CD7NG7N72K`) roaming was ON and the device still had no bearer. Its own
screenshot showed `Network Selection → AT&T`; the Telnyx API agreed: `current_mcc/mnc = 310/410`
(AT&T), `live_data_session: connected`, `radio_access_technology: EUTRA` (LTE), and internet-APN
sessions created on **every attach** — `ch1-telnyx-internet-01.mnc588.mcc311.gprs`,
`dc2-telnyx-internet-01.mnc588.mcc311.gprs`. And
`current_billing_period_consumed_data = 0.049814 MB`. **50 KB lifetime.** Attached, session up,
no payload.

**The fleet split is the evidence, and it is clean:**

| attached to | DRNs | consumed |
|---|---|---|
| T-Mobile 310-260 | 2001, 2002, 2004, 2006 | 0.93 / **94.96** / 1.22 / 0.076 MB |
| AT&T 310-410 | 2005, 2007, 2008 | 0.010 / 0.050 / 0.058 MB |

Every SIM that has ever moved real payload is camped on T-Mobile. The three AT&T-pinned SIMs have
moved **118 KB between them, ever**. AT&T is not one of the five IMSIs on the Telnyx profile —
Telnyx, Sparkle, BICs, T-Mobile, US Cellular
(<https://developers.telnyx.com/docs/iot-sim/imsi-selection>) — so a pin to AT&T takes the SIM off
the networks it is built for.

**How the pin gets set: by following the vendor's own advice.** Telnyx's connectivity
troubleshooting page says, under "No connectivity logs at all": *"Scan networks and manually
select one."* On a device whose intelligent IMSI applet is supposed to choose, that is a trap —
it pins the SIM and the applet stops being consulted. **Do not put "manually select a network"
in a runbook for these devices**, and if a device already reads a carrier name in Network
Selection, set it back to Automatic.

**Three corollaries:**
1. **"Registration succeeds but no data" has a second cause beyond roaming** — check *which
 network* the SIM is attached to before concluding the SIM or the APN is at fault.
2. **`current_mcc`/`current_mnc` on the Telnyx SIM object is the cheapest network check we have**;
 the connectivity log's APN realm suffix (`.mnc210` = Telnyx/T-Mobile path, `.mnc588` = the
 AT&T path) is a second, independent tell.
3. **A data session existing is not data flowing.** The one number that cannot lie is
 `current_billing_period_consumed_data`. Read it before saying anything is fine.
