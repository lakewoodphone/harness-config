**L1889 · Measuring and raising mesh transport concurrency: 9 rules, each with its evidence**

# Lessons: measuring and raising mesh transport concurrency (2026-09-17)

Context: `docs/mesh/93-transport-concurrency.md`, `packages/plugin-mesh-http/**`. Every rule below
cost time in that session and each one has its evidence attached.

## 1. A memoised read that cannot tell "good" from "degraded" caches the failure for the process life

`readTailnet()` read `tailscale status --json` once and memoised it. A read that *succeeds* and returns
an empty `Self.DNSName` is indistinguishable from a good read, so the value was never retried.

MEASURED, ZABZ-YOGA: engine pid 4880 started **08:51:07**; `tailscale-ipn` started **08:51:59** — 52 s
later. The engine therefore cached `fqdn: ""`, reported `node: "zabz-yoga"` (its `os.hostname()`) for
the rest of its life, and simultaneously reported `nodeSource: "tailscale status --json
Self.DNSName"` — a source that had NOT produced the value. A **fresh process** on the same machine
reading the same file returned `zabz-yoga-1.tail93e6e6.ts.net` at 13:06Z.

RULE: cache a *good* read for the process; retry a *degraded* one on a rate limit (15 s here). And a
field that names its provenance must be one of a closed set of literals, or it will eventually name a
source that failed.

## 2. Never guess a name you failed to read

`tailscale status --json` carries both `MagicDNSSuffix` (`tail93e6e6.ts.net`) and `Self.HostName`
(`zabz-yoga`), so `"<HostName>.<MagicDNSSuffix>"` looks like a free repair for an empty DNSName. It is
wrong: that machine's real label is **`zabz-yoga-1`**. A plausible, well-formed and incorrect node
identity is worse than an absent one, because the broker's arithmetic then looks authoritative. Report
it absent, set `identityDegraded`, and let placement refuse.

## 3. A `Start-Process`-detached process on a Windows node dies with the ssh session that launched it

The sampler wrote a CSV containing the header and **nothing else**; the identical script run inside a
live session produced a row every 4 s. Two levels' worth of capture were lost to this. The fix is not
to detach harder — it is to run the sampler in the **foreground of a session held open for the whole
measurement**, so nothing detached exists and there is nothing to clean up afterwards.

## 4. `Get-Counter`'s `CounterSamples.Path` is MACHINE-QUALIFIED

It returns `\\zabz-tech\memory\committed bytes`, not `\memory\committed bytes`. A hashtable keyed on
the bare path returns `$null` for every counter, and the row written is a **machine that looks idle**:
commit 0, avail 0, CPU 0 — while the fields read a different way (loop lag, child count) are correct.
A half-zero row is more dangerous than a missing row. The key must strip the machine prefix.

## 5. An admission decision must reserve the slot in the same synchronous step it tests it

If anything is awaited between "there is a free slot" and "I have taken it", N simultaneous dispatchers
all observe the same free slot and the node runs N children with a limit of 1. `OneShotRunner.run()`
therefore decides and reserves with no `await` in between, `release()` hands the slot to the queue head
inside the step that frees it, and there is a test that fires six callers at two slots. The same
reasoning applies to a promise-based queue in any server: **test-and-set, or you have no limit.**

## 6. A reported position must be the one the caller held, not the one it holds now

Renumbering the queue as it drains is right for a live view and wrong for an answer: the third arrival
was told it had been first. Store `enqueuedPosition` and report that; renumber only for
`/mesh/health`. A test caught this.

## 7. On this harness, `$payload | ssh ...` hangs and `Start-Process -RedirectStandard*` returns

`70-remote-fanout-proof.md` §4.1 measured the CLIENT-side defect (a Win32-OpenSSH client whose stdout
is a pipe does not exit). The pwsh-side fix is the same idea: `Start-Process -RedirectStandardInput/
Output/Error` hands the child real OS file handles rather than pipes. Both a `ship-to-node.ps1`
invocation and a 100 KB stdin ship hung until this replaced them; `scp` for the payload plus
`Start-Process ... -EncodedCommand` for the program works.

## 8. Measuring a fleet: the budget must be sized per LEVEL, not per question

The brief allowed 30 child turns for **N = 1, 2, 4, 8, 12 on two transports** — which is 27 turns for
ONE transport's sweep alone. What was actually measured (29 turns) was one transport at its derived
limit plus a second at a single small level, and the **matched pair at equal N — the comparison the
question was really about — could not be afforded**. When a brief asks for a sweep of M levels on K
transports, the turn budget must be at least K × Σ(N) plus repeats; otherwise the answer is "one
curve and one point", and that should be agreed before the first turn is spent.

## 9. sshd's real ceiling is a compiled default that nothing in the transport knows about

On `zabz-tech`, `sshd_config` has `#MaxStartups 10:30:100`, `#MaxSessions 10` and `#MaxAuthTries 6`
**all commented out** — so the defaults are in force. `MaxStartups 10:30:100` starts dropping
unauthenticated connections at random from the 11th. Twelve simultaneous sessions survived (key auth is
fast), but the margin is one connection and the failure mode is a 255 exit with no diagnostic. A
transport that spawns one process per child and holds no slot has an invisible, probabilistic ceiling
on somebody else's node.
