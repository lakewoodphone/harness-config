**L3461 · On the cloud authority, /home/zabz/bin -> /root/bin is what makes the office payloads run unedited**

WHAT: On secratary-cloud, root's HOME is /root, so every office payload that says `$HOME/bin/x` resolves to /root/bin/x while every payload that says /home/zabz/bin/x resolves to a directory that does not exist. Fix that satisfies both without editing a single payload: mkdir /root/bin, `ln -s /root/bin /home/zabz/bin`, plus symlinks /home/zabz/<state> -> /root/<state> and /home/zabz/personal-secretary-mvp -> /opt/company.

EVIDENCE (2026-10-11, workstream 139): sms-inbox.py exited `no /root/personal-secretary-mvp/.env`; cfo-scoreboard.py exited `cannot read ledger /home/zabz/accounting-data/live/accounting.db` while /root/accounting-data/live/accounting.db was present and correct (sha256 55a9801a..., 21,995,520 B). After the symlinks, both ran: `scoreboard: 579 unexplained / 6030 non-duplicate (90.4% clear)`.

WHY IT MATTERS: `136-ESTATE-INVENTORY.md` recommends recreating /home/zabz wholesale "to require ZERO edits to 87 cron payloads". The symlink set gets the same zero-edit result for the families that are actually ported, is reversible, and does not commit the box to a 15 GB copy. If /home/zabz is later recreated for real, `bin -> /root/bin` is the one entry that must be reconciled rather than overwritten.
