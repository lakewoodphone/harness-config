**L3056 · The Chip eval harness has a 10-66 point per-case noise floor: do not gate a small prompt change on one run**

**L — The Chip eval harness cannot resolve a change of a few points: the SAME config moved 21 of 33 cases on a repeat run.**

Measured 2026-09-29, and it changed a decision. The standing rule is "gate every quality
change on the harness; do not ship prompt changes on taste" - so the register change for
Chip was run through it. First run came back WORSE: 87.87% -> 85.2%, hard gates 9 -> 13,
B4_no_invention 0.81 -> 0.70. On that evidence I nearly reverted a change the owner had
explicitly asked for.

Before reverting, I quantified the harness's own noise by comparing two runs of the SAME
config that already existed on disk from 2026-09-25 (results/after-sensitive-gate.json vs
results/repeat-noise-1.json):

 21 of 33 cases moved at all
 9 of 33 cases moved by MORE THAN 10 POINTS
 largest single-case move: 66 points
 moves: -61.7, -47.3, -38.0, +66.0, +17.3, +12.0 ...

Generation runs at temperature 0.9 and a second LLM judges the output, so this is expected
- but it means a total-score difference of 2-3 points, and a churn of 5 hard gates, is
NOISE. The harness can only resolve changes big enough to move whole classes of cases.
It is a regression-detector for structural damage, not a scale for prompt tuning.

Consequences, recorded so a future session does not repeat my mistake in either direction:
1. Never conclude "my change regressed/was better" from one run and a few points. Measure
 the noise floor for the configuration you are comparing, or run N>=3 and compare means.
2. Prefer evidence the harness cannot fuzz: deterministic unit tests, single-case behaviour
 reproduced by hand, and the live ledger. For this change the decisive evidence was that
 the exact message Chip answered at 03:52 ("At 4:16 pm") now returns (False, 'turn share'
 ) while "Chip, are you awake?" still returns (True, 'answered').
3. Judge hard-gate churn by the KIND of failure, not the count: in both runs the new gates
 were the same class the baseline already fails (invented physical detail), which is
 evidence of noise, not of a new behaviour.

Also worth recording: my first instinct on seeing 85.2% was to blame one thing (silence).
The dimension table refuted it - silent cases that spoke were 5 in BOTH runs; what actually
moved was B4_no_invention. The aggregate was the wrong place to look.
