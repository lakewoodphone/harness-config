**L3691 · A push that fails silently forks the journal - the BOM in .ssh/config, six stranded commits, and 19 ids that mean two different entries**

Measured on ZABZ-TECH, 2026-10-12.

`C:\Users\ezabz\.ssh\config` began with a UTF-8 BOM (`ef bb bf`). Windows OpenSSH
(`C:\Program Files\OpenSSH\ssh.exe`) tolerates it, so `ssh secratary`, `lpt`, and every mesh tool
worked. Git's bundled ssh (`C:\Program Files\Git\usr\bin\ssh.exe`) does not: every `git push` to
`origin` (secretary-ts) died with

```
/c/Users/ezabz/.ssh/config: line 1: Bad configuration option: \357\273\277#
fatal: Could not read from remote repository.
```

The pushes looked like "the remote has work I do not" or were never attempted again, so **six commits
sat local and the journal forked**. When the BOM was stripped and `origin/main` was finally fetched,
the damage was measurable:

- `origin` was **24 commits ahead**, the local branch **6 commits ahead**, and
- **19 journal entry paths held a DIFFERENT entry on each side** — P3002, P3006-P3009, P3130-P3137,
 W2735-W2740. `P3137` was a rollback-anchor pain entry on ZABZ-YOGA (2026-10-11) and a
 tooling-gap pain entry here (2026-10-12). One id, two meanings, which is the one outcome the
 journal's own design calls unacceptable.
- The allocator made it worse in a way worth knowing: after removing the colliding file it offered
 `P3137` again, then `P3138`, then `P3139`-`P3141` — every one of them already taken on
 `origin/main`. **It allocates from the local tree's maximum and does not consult `origin`.** The
 entry had to be placed by hand above the authority's maximum (P3142).

The rules that follow:

1. **Strip the BOM** (`[System.IO.File]::WriteAllBytes` on the bytes minus the first three, backup
 first). Any tool that reads a text config with a parser that is not PowerShell's should be
 assumed to reject it.
2. **`git fetch` first, then append.** Appending before the fetch is what made the collision —
 the id was free in the tree this machine could see.
3. **Verify the push landed, not that `git push` ran.** `git log --oneline origin/main..HEAD` empty
 is the check. A machine that cannot push is not a machine with local work; it is a fork.
4. When the allocator's next id is already on `origin/main`, place the entry above the authority's
 maximum by hand and say so in the entry, rather than writing a second meaning onto a taken id.

Until the lineages are reconciled, **treat any ZABZ-TECH entry written between the last successful
push and 2026-10-12 as forked** and check it against `origin/main` by path before trusting the id.
