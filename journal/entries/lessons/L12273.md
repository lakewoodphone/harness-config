**L12273 · KF androidTest: the seal's apply window is 10 s and the app applies on three broadcasts only**

Kosher AI Filter androidTest lane (worktree _kf-lanes/devfix, branch agent/kf-devfix, commit 61229a56): the seal's apply window on the API 30 AVD is 10 s, measured not assumed, and the app has exactly three triggers.

WHAT IS TRANSFERABLE
1. `dpm set-device-owner` returning is NOT the seal being applied. Measured on Medium_Phone_API_30 (AVD, wiped, provisioned), 2026-10-22: dpm returned 15:43:59.579, `LPTSealPolicy: Seal policy at admin_enabled applied=true` landed 15:44:09.596 — 10.0 s later. Any instrumented test that reads DPM state once, immediately after dpm, reports a sealed phone as unsealed. Await it (waitForSeal pattern now in SealDevice.kt, 15 s / 250 ms).
2. The app applies policy on EXACTLY three signals (android/app/src/main/.../deviceowner/AdminReceiver.kt:30-83): ACTION_DEVICE_OWNER_CHANGED, onEnabled (admin_enabled), BOOT_COMPLETED. There is no apply-on-Application.onCreate and no apply from MainActivity, so nothing self-heals.
3. On that AVD the ownership broadcast sometimes never starts the app at all: three separate wiped-boot runs showed "Device owner set" with no `Start proc <pkg>` and no LPTSealPolicy line afterwards, and the restrictions stayed absent until the next reboot. One run DID deliver it (log line present). The delivery is nondeterministic here, so an instrumented suite on a freshly sealed AVD can legitimately fail with "never applied"; a reboot seals the phone and the same suite goes green (14 tests, 4 skipped, 0 failures). If the counter flow ever reports "device owner but not sealed" on a real Android 11 phone with no counter log line, reboot before believing the app is broken.
4. `gradle :app:connectedDebugAndroidTest` re-installs the app when the installed APK is not the one it built, and that install FORCE-STOPS it. Measured 15:28:22: "Force stopping com.lakewoodphoneandtech.filterai ... installPackageLI", 2 s after the seal began — it kills an in-flight apply. To test a freshly sealed device, let gradle own the install first (installDebug/installDebugAndroidTest, then connectedDebugAndroidTest with everything UP-TO-DATE), or seal after gradle has installed.
5. `adb shell dpm list-owners` does not exist on Android 30 [API 30], exits 0 anyway, and prints the error on stderr — an exit-code check cannot see it, only the text can. On API 34 it answers `1 owner: ... DeviceOwner,Affiliated`. seal_policy_checks.ps1 now treats dumpsys device_policy as primary and list-owners as an API-31+ cross-check (Test-LptDpmListOwnersAvailable).
6. `:app:testDebugUnitTest` prints UP-TO-DATE and exits 0 having executed nothing; `--rerun` forces the real run. Counts only exist in the XML: 173 files, 1008 tests on this branch (the "942 baseline" in circulation is stale for 1a02b151).
