**L1509 · A swallowed exception in my own journal tool hid a real defect: the alias table stores rows, not ids**

**A swallowed exception in my own tool hid a real defect for an unknown length of time -- and the
journal is the one tool whose defects I cannot afford.**

`journal.py append` printed this, three times in six appends, and carried on:

 journal: legacy absorption skipped (sequence item 2: expected str instance, dict found)

That is a `%s`-formatted `TypeError` inside a bare `except Exception` in `cmd_append`, so the note
named the symptom and dropped the location. Reproduced on 2026-09-15 by calling `absorb_all`
directly: `--kind lessons` and `--kind wins` raised, `apply=True`, every time.

The defect: `alias_map()` returns `{alias_id: ROW}`, where the row is a dict
(`amap[cur]["canonical_id"]` is how the rest of the file uses it). In `absorb_all`, when a legacy
candidate matched only through the alias table, the row dict was assigned straight to `owner` and
handed to `record_alias(..., canonical_id=owner, ...)`, which builds a TSV line by joining --
hence "sequence item 2 ... dict found". Two consequences, both silent: absorption **aborted
mid-pass**, so every candidate after the first alias match was never absorbed; and the
`c["id_full"] != owner` guard was always true against a dict, so an alias could be recorded even
when the candidate was already its own canonical id. In `append` the whole pass was swallowed into
one note and the append itself succeeded, so nothing anywhere said the record was incomplete.

Fixes, all three together because each alone leaves a hole:
- resolve the row to its `canonical_id` at the source, so `owner` is an id string like every other
 value compared against it;
- `record_alias` now raises `TypeError` for a non-str id instead of writing `str(dict)` into
 `index/aliases.tsv` -- a corrupt alias row is a *permanent claim about the record*, which is worse
 than a crash;
- `cmd_append`'s except now names the exception type and the raising line, because a silent skip is
 a refusal, not health.

Verified after: all five kinds absorb with `apply=True` (lessons: 407 aliases where it previously
aborted), `added=0` everywhere, nothing re-written, `check` 0 errors / exit 0.

The durable rule: **`PATCH OK` and "the tool printed a warning and continued" are claims about
control flow, not about the record.** Three of this session's defects -- this one, the patch script
that kept only the last edit per file, and `_run_reminder_poll` never existing -- were all invisible
because something swallowed an exception and reported success. When you write the swallowing code,
you are the only one who will ever see the failure; make it speak.
