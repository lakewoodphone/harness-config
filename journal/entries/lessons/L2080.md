**L2080 · Before basing a fix on a default branch, hash the LIVE asset against the candidate build output - the deployed commit may be on an unpushed branch**

Never branch a customer-facing fix off a repo's default branch before checking which commit
PRODUCED the live page.

On 2026-09-20 the brief said "HEAD is commit 6b94038c4". That was the main worktree's HEAD. The
page actually served at lakewoodphoneandtech.com was built from 59f1763d5, five commits further
on, on a branch pushed nowhere. The default branch origin/test still held hours copy the owner
had already had removed from the live site - so a literal "branch off the default branch" would
have shipped a regression while fixing a bug.

The cheap decisive test, no build required: hash the LIVE asset against the candidate worktree's
frontend/dist asset. `Get-FileHash` on the live bundle vs the local build artifact - identical
SHA256 means that worktree produced that deploy. Do this BEFORE choosing a base. A stale local
build that does not match is itself a signal the tree you are looking at is not the tree that
shipped.
