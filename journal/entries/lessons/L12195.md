**L12195 · A green test is not a guard until a mutation makes it red**

A green test is not a guard until a mutation makes it red. Three times in one session I wrote a test or a selftest that passed while proving nothing:

1. **A mutation that does not compile is not a mutation.** I broke Kotlin syntax while mutating a rule; the build failed, and "FAILED" reads identically whether a test failed or the compiler did. Nothing was tested.
2. **A key that does not match means the code path never ran.** A selftest built its cached-baseline dict with `str(Path("docs")/"d.md")` (backslash on Windows) while the lookup used the document's own `rel` (forward slash). The baseline came back None, the function took a fresh path, and the case passed for the wrong reason.
3. **A fixture that skips the guard is not exercising it.** The same selftest's fixture writer never read the clock, and the function under test only inspects writers detected as clock readers - so the document was filtered out before any assertion could run.

The disciplined sequence, every time: write the assertion, then break the production code in a way that still compiles, then watch the named assertion go red, then restore and watch it go green. Two of these three were caught only because I ran the mutation *after* the green run; had I trusted the green, I would have shipped a guard that cannot fire.

Corollary for reviews: when an agent reports "tests pass", the useful question is not how many passed but which mutation makes them fail.
