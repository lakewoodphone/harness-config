**L1888 · A supervised engine with a broken profile is a crash loop, not a quiet node -- read launchd before describing blast radius**

A machine whose engine is supervised by launchd gets a CRASH LOOP from a broken profile, not a quiet
outage -- measure the supervisor before describing the blast radius.

docs/mesh/95-audit-live-mesh.md SS3.2 concluded the Mac Mini was the most likely thing to break "because
there is no second engine to fall back to and no supervision that would report it -- the node would
simply stop answering /mesh/capacity and the broker would file it unreachable." Measured 2026-09-17
13:39Z, on the same machine:

 $ launchctl list | grep lakewood
 12458 0 com.lakewoodphone.mesh-engine
 26384 -15 com.lakewoodphone.mesh-gate
 $ sudo launchctl print system/com.lakewoodphone.mesh-engine | grep -E "state|runs|pid"
 state = running
 runs = 2
 pid = 12458
 /Library/LaunchDaemons/com.lakewoodphone.mesh-engine.plist:
 "RunAtLoad" => true
 "KeepAlive" => { "SuccessfulExit" => false }
 "ProgramArguments" => [ … "@deepseek-ai/dsh/lib/bin.js", "web", "--port", "3099", "--no-open" ]

So the pre-repair state was a crash loop armed by the node's own supervisor: the engine exits non-zero
on the bundle error, launchd starts it again, forever. Both facts are worse than "the node goes quiet"
(the failure is loud but unattended, and it burns a restart every few seconds) and better than "a human
must notice" (it is self-healing the moment the profile is fixed -- which is why the repair needed no
restart and the running pid was never at risk).

The generalisable rule: before describing what happens when a service dies, read what starts it.
`launchctl list`, `launchctl print system/<label>`, and the plist's RunAtLoad/KeepAlive say what a
process list and an uptime cannot. Also note the finding's shape -- the audit was right that the bug was
the highest-value thing to fix and wrong about the consequence, and the correction came from a file
nobody had read, not from an argument.

Evidence: docs/mesh/97-fleet-repairs.md SS1.5.
