**L12289 · A guard that runs before the write destroys the evidence the decision asked for (ledger 1187)**

Ledger 1187, branch agent/kf-release-clock, commit aa74e058 (unpushed). The defect had a shape worth recognising elsewhere: D-20261021-05 said thirty days 'from the request', the code computed it from sealed_at, and the guard ran on the REQUEST path before any write. So two promises were unreachable ('a request is taken at any time'; 'a request inside the first thirty days is flagged, never refused') and the failure was INVISIBLE — both routes answered 409 with a plausible reason and wrote no row, so an empty trail looked exactly like 'nobody asked'. Lesson: when a guard runs before a write, ask what evidence the refusal destroys. Second lesson: one stored date was serving two meanings (when a release may happen, and the seal boundary). Splitting it into eligible_at_for(requested_at) and seal_floor_at_for(sealed_at) is what allowed the clock to be corrected while the flag boundary survived. Third: a request made in the same second as the seal makes request+30 == sealed+30 exactly, so any test meant to see the two clocks disagree must move one of them — my first assertion failed on that and it was the test that was wrong, not the code.
