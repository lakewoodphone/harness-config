**L1825 · Read a Start-Process redirect file with Get-Content -Raw, never [System.IO.File]::ReadAllText**

Against a file held open by a `Start-Process -RedirectStandardOutput` child:
 [System.IO.File]::ReadAllText($path) THROWS MethodInvocationException -- 0 of 6 succeeded
 Get-Content -Path $path -Raw returns the text -- 6 of 6 succeeded

MEASURED 2026-09-16, 3 rounds x 2 node stub gates, Windows/pwsh 7.6. The .NET static call is the
obvious one and it is the wrong one: the child's handle share mode will not admit it.

Why this matters beyond the one bug: I hit a single stub-gate flake, "fixed" it by swapping in
ReadAllText, and thereby turned an intermittent failure into a DETERMINISTIC one - then found it
only because I re-ran the script after editing it. Two rules fall out:
 1. Read another process's redirected stdout with Get-Content -Raw, retried, never with ReadAllText.
 2. Re-run the thing you just edited before you believe it. Every "fix" is a new unverified claim.
Corollary already learned: a FAIL must carry the SERVER's own words. A broker 500 whose body said
{"error":"effective is not defined"} moved to my evidence line as an empty string until the non-200
path started excerpting the response body.
