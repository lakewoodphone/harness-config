**L10814 · run_assistant_chat is the company's real LLM client and carries the owner-chat prompt into every background job**

**Measured 2026-10-20 in production, with a caller-stack marker at the single `model_usage` writer
(`app/database.py::log_model_usage`), which is the one place every LLM call is recorded.**

```
USAGE-CALLER agent=dept_comms_relationships model=deepseek-flash provider=deepseek in=45202
 path=autopilot.py:5442:_process_work_queue <- assistant_chat.py:5632:run_assistant_chat
USAGE-CALLER in=29132 path=email_classifier.py:275:_classify_with_llm <- run_assistant_chat
USAGE-CALLER in=28771 path=email_actions.py:1291:_extract_followup_task <- run_assistant_chat
```

**`app/assistant_chat.py::run_assistant_chat` is the company's real LLM client.** The autopilot work
queue, the email classifier and email follow-up extraction all call it. It carries the full
owner-assistant prompt — world context, personality, memories — so a background email classifier
pays **29k tokens** and every department work step pays **45k**. In a 3-hour window: 1,175 calls
averaging 44,551 input tokens, about 95 % of all model spend.

**Why every earlier instrument was silent, in one sentence:** they were attached to
`agent_worker`, which is the *minority* path. Measured the same day: the agent-gateway path carries
18–24k *characters* (~5k tokens) and emitted 100 `GATEWAY-SHAPE` lines; the `run_assistant_chat` path
carries 180k characters and emitted none, because it never calls `ai_gateway.prepare_request`. Zero
of the 100 instrumented calls exceeded 23,701 characters.

**And the gateway does not inflate anything** — measured 1.00x inflation, input 27,639 chars →
`upstream_body` 27,673 chars. The body is built big by the caller.

**What to do with it:** a `call_type` that a machine uses (work_mode, email classification) must not
be served by the function written for the owner's conversation. Either give work-mode its own lean
prompt inside `run_assistant_chat`, or route machine work to the department path. Whichever is
chosen, measure the prompt size per call_type and assert it in a test — a call_type that is not
budgeted will grow back.
