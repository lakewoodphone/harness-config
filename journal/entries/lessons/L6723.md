**Three distinct Cloudflare tokens exist in this estate. All active. None can reach Pages.** None can
manage tokens. No Global API Key pair. That is the complete answer, and it is now measured against the
capability the task needs rather than a proxy for it.

The one place that plausibly holds a Pages-capable token is `secratary:/etc/lpt-deploy/env` — the
credential the old self-hosted runner used. That box is powered off, and it is frozen, so it is not the
answer even if it returns.

**THE THING THAT TOOK SIX ROUNDS, NAMED PLAINLY, BECAUSE IT IS THE TRANSFERABLE PART.** Rounds 1-3 were
spent reporting that no credential existed when what had been searched was one NAME. Round 4 found the
credential and then tested the wrong CAPABILITY. Rounds 5-6 were the work that should have been round 1:
enumerate every candidate, and ask each the single question the task depends on. **Search breadth and
capability specificity are the two dimensions of a negative, and a negative is worth nothing unless
both are stated with it.** A colleague reading "no Cloudflare token exists" cannot tell whether to
search harder or stop. A colleague reading "three tokens found across six hosts and every backup, all
active, none can reach Pages" knows exactly where they stand — and that is the sentence that should
have been the first one.
