**L3871 · A colon-space in a skill's YAML frontmatter removes the skill from the catalog silently**

**A colon-space in a skill's YAML frontmatter removes the skill from the catalog silently — no error, no warning, one fewer skill.**

Editing `harness-config/presets/zabz/skills/fast-search/SKILL.md` on 2026-10-19, I rewrote the
`description:` line and put `ps_action("search", {"what": …})` into it. The sequence `": "` inside an
unquoted YAML plain scalar turns the value into a mapping, the document stops parsing, and the effect
is not an error anywhere an agent can see: the next system-reminder's skill catalog simply **did not
contain `fast-search`**. I noticed only because the catalog changed under me mid-session.

The fix is one quoted scalar, plus a check:

 python -c "import yaml; d=yaml.safe_load(open('SKILL.md',encoding='utf-8').read().split('---')[1]); print(d['name'], len(d['description']))"
 # fast-search 711

and the installed copy at `~/.dsh/skills/<name>/SKILL.md` must be byte-identical to the preset
(`Get-FileHash` both).

Rules:
1. **Quote the whole `description:` scalar.** It is prose written by a human, and prose contains
 colons.
2. **After any frontmatter edit, re-read the catalog, not the file.** A skill that fails to parse is
 indistinguishable from a skill that was never written — and the failure mode is silent in the one
 direction that matters (an agent that needed the skill never loads it).
3. The same shape applies to any watched `.md` with frontmatter on this estate (presets, agent
 definitions): valid YAML or invisible.

Refs: harness-config commit `01f16dd4`; `harness-config/docs/skill-wiring.md`.
