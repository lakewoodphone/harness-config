**L3137 · The 300DDR >=99% letter has no decline branch - read which letter arrived before pricing an exit, and file the lab's answer the day it is read**

**The 300DDR >=99% letter carries NO decline branch - so a policy written for "<99%" has no cheap exit, and the lab's letter is the only place that tells you which one you got.**

What happened, measured. The 73459 case (SanDisk 256GB, chip-off) had a settled owner policy
written 2026-09-18 for a **<99%** result: show the customer the listing, and if she does not want
it, decline and pay the lab a 100 per-chip labor fee. On 2026-09-29/30 the lab returned pass 2:
*"We got more than 99% of all the sectors"*, with partition corruption and bit errors, plus a
downloadable file listing and *"PLEASE WRITE BACK TO APPROVE OUR RECOVERY"*. That letter contains
**no 100-decline line at all**, and the terms recorded on 2026-08-11 and in the referral workflow
say at >=99% the flat fee is payable with no option to decline. So the decline branch the policy
relied on does not exist for this result: approving and refusing cost the lab fee either way, and
the only live decision is what the customer is charged (the 700 advanced tier she approved when
she authorised the chip-off on 2026-08-25).

The transferable rule. **300DDR's >=99% and <99% letters are different documents with different
rights, and only the >=99% one removes the choice.** Read which letter arrived before pricing any
exit path; a "we can always decline for 100" plan is valid only inside the <99% branch. Same shape
applies to the chip-off policy (>=50% is auto-success with no decline) on 73890.

**Second half of the same lesson, and the one that cost the most time: the lab's answer is filed
the day it is read, or the row lies.** Five 300DDR messages sat UNREAD in the shop mailbox from
2026-09-25 to 2026-09-30 - one lab invoice, one file listing, one pass-2 result, one return-shipping
request - and not one had reached the case file that owns the ticket. Every board row on
2026-09-30 was therefore asserting a state from 09-25 that the lab had already moved past. Before
answering any question about a partner's or a customer's current state, read the live source first
(mailbox, portal), and file what it says in the same session. See P2547 - the message is triaged,
categorised `personal`, given a task, and never filed.
