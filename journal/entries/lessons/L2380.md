**L2380 · Prose children must write their report to a FILE on their own node - a settlement crash loses the final message**

**Rule:** any mesh child whose value is PROSE (research, audit, analysis, a report) must write its output to a file on its own node AND name that file's path as the first line of its final message. Do not rely on the final message surviving.

**Why - measured 2026-09-22:** two long web-research children failed at settlement with `the remote one-shot exited 1`, stack `dsh-agent-loop/lib/index.js:82:15 at get hasPending` <- `ContinuableActivationRegistry.settlementState` (`dsh-subagent/lib/index.js:1196`). The crash is at settlement, i.e. AFTER the work completed. `job_output` returned `(no new output)`: the whole run was unrecoverable and the parent could not tell how far it had got.

**Distinguish the two mesh failure modes, they need different fixes:** (1) report did not open with `MESH-HOST: <hostname>` -> protocol refusal, output discarded (H7 / L2379); (2) settlement crash -> output discarded, no partial artifact. Both lose the work; only (2) is fixed by writing to a file.

**Build children are less exposed** because commits survive in git even when the report does not. Prose children leave nothing. So: for prose, file-first; for builds, commit-early.
