**L2380 · The website push wrote the same customer note TWICE and a paragraph as the order title — read the production row back after every push**

## L2406 · 2026-09-24 · Two silent quality defects in lpt-sync-to-production.py, found only by reading the rows back

FOUND BY READING PRODUCTION BACK, not by the tool's own success message. Both defects had been
shipping on every push and neither ever raised an error.

1. **Every pushed customer got the same note TWICE.** `website_db.create_customer(notes=…)` writes
 any notes it is given as the customer's first `customer_notes` row ("Add initial note if
 provided"), and `push_to_production` Step 4 then writes the identical text again behind a
 `[Secretary Sync] ` prefix. Measured on customers 2741/2742/2743 — each carries both copies, one
 prefixed and one not. Fixed: the push path passes `notes=""` to create_customer and lets Step 4
 write it once, where the quote is appended too. Nothing is lost — the raw notes still reach
 production as the order `description`.

2. **Order titles were 170-210 character paragraphs.** The create path passed the whole
 `device.summary` as `title`. Across 595 pre-existing production orders the MEDIAN title length is
 **20** characters ("Acer Aspire N20C5 — charging jack repair"). Fixed with
 `_compact_order_title()`, which picks the longest of three candidates that fits a board line
 (device + issue, device + the issue's first clause, device alone), drops parenthetical detail,
 and appends the surname; short house-style titles pass through unchanged.

WHAT MADE THE FIX SAFE. The title is load-bearing for duplicate prevention, so shortening it is not
cosmetic: the pre-create guard token-matches title **+ description** (`_blocking_order`), and the
full text still travels as the order description and the customer note. `title` is also
deliberately NOT in `ORDER_WRITABLE_FIELDS` on orders — duplicate detection reads it — which is why
the three already-created orders cannot be retitled through the sanctioned writer and were left
long. Do NOT write raw SQL to production to fix a cosmetic title.

RULE. A push tool's exit status is not evidence. After every push, SELECT the created customer and
order back — name, phone, status, total, note count — and read them. Both of these were invisible in
every log line the tool printed.

RULE. When you change what a tool writes, check what else READS that field. The title is also the
dedup key; the note is also the record of the case.
