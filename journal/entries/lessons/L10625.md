**L10625 · An instrument that has never emitted a line is not evidence of absence - run a positive control first**

**Measured 2026-10-20 on `secratary-cloud`.** A session instrumented the wrong code path twice,
diagnosed it correctly, then moved the diagnostic to `ai_gateway.prepare_request` — the callee every
caller shares. That instrument emitted **zero lines in all time across 53 LLM calls**, with the flag
proven present in `/proc/<pid>/environ` and `StandardOutput=journal` confirmed.

Three instruments, three silences, hours spent interpreting a channel nobody had proved was open.

**The rule:** before you read an instrument's silence as a finding, make it emit one line on
purpose. One known call, one expected line, and the exact command in the same breath. "Deployed and
verified in the running process" proves the *config*, not the *channel* — and the two fail
independently.
