**L11007 · A no-hardcoded-models rule needs the data/selection boundary stated, or it either deletes the price book or declares victory early**

**The distinction that made the sweep tractable, and the one that made it stop.**

The owner's instruction is "no hardcoded models — all of them as env variables". Applied literally to a
100k-line codebase that is impossible, because a price book, a capability table and a roster are all
*keyed by model id* and deleting those keys deletes the prices. The rule that actually works:

- **SELECTION** — the value decides which model gets called, or is a fallback used when the configured
 model cannot be parsed. **Must** become configuration.
- **DATA** — a price row, capability row or display name keyed by a model id. **Must stay.** It is the
 lookup that prices the thing the selection chose.

Applied to 39 flagged literals across 20 files: 35 were selection and became named lanes
(`LLM_MODEL_VISION_JSON`, `LLM_MODEL_TRANSCRIBE`, `LLM_MODEL_UTILITY_JSON`, `LLM_MODEL_SELF_EDIT_JSON`,
`LLM_AGENT_MODEL_CATALOG_JSON`, …). 2 are data. 2 of the original 39 were already stale — the fixes had
landed and the allow-list had not noticed, which is why the baseline now has
`test_the_baseline_has_no_stale_entries`.

**The one that stayed, and why stopping was correct.** `mem0_service.py` names
`deepseek-ai/DeepSeek-V4-Flash-0731` — a provider-scoped DeepInfra id whose every spelling is retired
upstream. Converting it either sends a DeepSeek id to DeepInfra (a guaranteed 404) or moves memory
extraction onto a pipe nobody has exercised, and mem0 failing is *silent* memory loss for the whole
company. It stays, with the exact operator step written into its baseline row.

**Lesson:** a hardcoding rule needs the data/selection boundary stated explicitly, or an agent either
deletes the price book to satisfy a linter, or declares victory with 39 literals left. And when the last
literal cannot be converted safely, the deliverable is the reason plus the one-step fix — not a
conversion that trades a lint result for a silent data-loss path.
