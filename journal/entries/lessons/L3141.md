**L3141 · A case file with no customer name is not proof the name is unknown - read the Dialpad call transcript first**

**When a case file has no customer name, read `dialpad_call_full.transcription_text` before saying the name is unknown.**

Measured 2026-09-30, case `usb-files-disappeared-tbd-2026-08-06` (300DDR ticket 73459). The case file
said `customer: ""`, its Customer row read "TBD - no name yet", and the case index raised
`customer-name-missing` every time it was read - for seven weeks. I told the owner "still no name in
the record" twice. He pushed back with "are you sure you don't have the customers name?" and he was
right: the **2026-08-06 inbound call transcript** (`dialpad_call_full`, call `4655344811834880`...
exact id `4655341811834880`) contains, verbatim:

- *"(848) 525-8603: Hi, my name is rom cog. I see I missed a call from you earlier."* - first name garbled by ASR
- *"Eliyahu: Yeah, do you want to share the last name with me again?"* -> *"(848) 525-8603: K-O-G-E-L."*

**Letters spelled out loud survive ASR; ordinary name pronunciation does not.** So the surname is
reliable and the first name is not - record exactly that distinction rather than guessing a first name
to fill the field.

Cheap rule, and it generalises past this case: before telling the owner a fact is absent, search the
place the fact would be if a human had ever spoken it. For a customer, that is the call transcript,
the SMS bodies, and the shop's intake slip - not the case file. A file that says "TBD" is evidence
that nobody FILED it, never evidence that nobody KNOWS it.

Fixed the same session: front-matter `customer: Kogel`, the header, the Customer table row (with the
ASR caveat and the call id), the sync record's `customer.name` plus a new `nameSource` field, commit
`80ad2e62b`; the index now reads `cust Kogel` and the warning is gone.
