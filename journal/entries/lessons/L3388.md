**L3388 · Three of eight search modes exited 0 on a genuine no-match**

**Tested the fast-search surface end to end on 2026-10-08, all modes, both surfaces
(`fa` on the Linux nodes and `ps_action("search")` from any agent).** Seven defects came out;
this is the one that mattered most.

`fa code`, `fa symbol` and `fa files` exited **0 on a genuine no-match**. Only `journal`, `data` and
`symbols` returned the documented `1`. `rc` was initialised to 0 and the live branches only ever
*raised* it back to 0, and the `files` branches called `exit 0` unconditionally.

So an empty result read as success in **three of eight modes** - including `symbol`, which the skill
calls the one mode that must never lie because you are about to edit against it. The documented table
("0 = hits, 1 = no match") was simply not implemented for the modes agents use most.

**Rule: a search tool's exit code is part of its contract, not decoration.** An empty result that
cannot be distinguished from success is the same class of failure as the stale-database incident:
a confident wrong answer. When you add a mode, add its miss path in the same commit.

Fixed in `/home/zabz/bin/find-anything` (md5 `6424111d1b173cbb3af8488cd9056ee8`), deployed to all
four nodes, battery-verified before and after. Evidence: before `code NO MATCH rc=0`; after `rc=1`.
