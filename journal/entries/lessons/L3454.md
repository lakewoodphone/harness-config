**L3454 · A CRLF in a credential file made a Cloudflare token invisible, and the error named the wrong thing**

## L3601 — A CRLF in a credential file made a Cloudflare token invisible, and the failure named the wrong thing

MEASURED 2026-10-11 ~00:15Z on lpt-survivor-01. The handoff (H3403) recorded an "open defect": the
CF_API_TOKEN in /opt/company/.env reported the standby tunnel b69e2492 as "not found in this
account" (0 connectors), while the token in secratary's .env listed the same tunnel as healthy with
4 connectors. It concluded "the two tokens differ" and left it to be resolved.

THE ACTUAL CAUSE: the survivor's file was CRLF (254 CR bytes, 254 lines). `grep -m1 '^CF_API_TOKEN='
/opt/company/.env | cut -d= -f2-` therefore yielded a 41-character token whose last byte was \r. The
office file was LF, giving 40 characters. The tokens were THE SAME TOKEN: both ended `vdq`, and the
longer one was the shorter one plus a carriage return. Cloudflare rejected the 41-char string as
"not found in this account", which reads like a permissions or account problem and is not one.

FIX: `sed -i 's/\r$//' /opt/company/.env` (backup taken first). The token immediately listed all six
tunnels in the account, and the same token then passed the promotion pre-flight's tunnel-exists and
connector checks that had failed an hour earlier.

WHY THIS MATTERS BEYOND ONE FILE
 1. A 1-character difference in a secret is not "the tokens differ" - it is a measurement that was
 not taken. `cut -d= -f2-` on a CRLF file is now on the list of things that lie quietly.
 2. The same CRLF applies to EVERY line of that file. Any other value read from it by the same
 pattern was equally wrong, and would have failed the same way with the same misleading message.
 3. THE GENERAL RULE: when a credential is rejected as unknown rather than as forbidden, compare its
 LENGTH with a copy of the same credential that works. An unknown-credential error from a
 truncated or over-long string is indistinguishable from a wrong-account error until you count
 the characters.
