**L1865 · a bundle list is a layer list: one bad name stops the engine booting, plugin logs are not durable, and node stdout is buffered on a pipe**

Three facts measured 2026-09-17 on ZABZ-YOGA and ZABZ-TECH, each one a fault that had already happened by the time it was found.

1. **A profile's bundle list is a layer list, not a dependency list — and one bad name stops the engine booting.** `dsh-app-boot/lib/index.js:852` throws `profile bundle "X" declares no dsh.bundle in its package.json` for any declared name whose package has no `dsh.bundle.patch`, and `:831` throws for one that does not resolve. MEASURED: `dsh --profile web --dump-config` exited 1 on ZABZ-YOGA naming `dsh-mesh-broker` (a service with a `bin`, no `dsh` key) and on ZABZ-TECH naming `dsh-plugin-session-link` (a junction that exists but cannot be walked). Both engines were UP at the time, because an engine reads its profile at start — so the machine looked healthy and was one reboot from an engine that could not come back. The origin was `install-client-plugins.ps1` enrolling every package it could link; it now requires `dsh.bundle.patch`, and `harness-verify.ps1` check 11 was widened from `-like 'dsh-plugin-*'` to every declared name (its failure mode was demonstrated on the pre-repair profile before the repair was applied). **`dsh --profile <name> --dump-config` is the cheapest real gate in this harness: it composes the layers, starts nothing, evaluates no `!!js`, and is safe on a machine in use.** A running engine proves nothing about the next one.

2. **In the `web` profile, a host-plane plugin's `ctx.logger` output is written NOWHERE durable.** MEASURED: a scratch engine's entire stdout+stderr over a 15-minute life was ~204 bytes (the launch line and two HTTP access lines) and contained no plugin line; the owner engine's 32 KB `.err.log` holds only MCP child output. So "assert the row mounted by grepping the engine log" is not available — it is an assertion that can never fail. Assert by EFFECT instead: for the remote subagent provider the only reader of a session's tool catalog is a session, so the check creates one session on the preset under test and asks it (no tools called) to name the tools it has containing `subagent`. In the isolated-home rehearsal the answer was `subagent subagent_fork subagent_remote`. Check that an assertion surface exists before writing it into a script.

3. **Node's stdout is block-buffered when it is a PIPE, so `& node … *> file` leaves the engine's launch line invisible until the process exits.** MEASURED: the scratch engine's log was 0 bytes while the engine was up and answering, and held `dsh web: …?token=…` only after it was killed; `Start-Process -RedirectStandardOutput` (which hands node a FILE handle) shows it immediately. This is why the multi-window launcher's `<port>-<stamp>.log` works and why `scripts/phone-gate.py`'s `live_token` reads it. The token line also appears a few seconds AFTER the port binds, so any reader must POLL for it rather than read once at readiness.

Two smaller ones from the same night: a patch entry can disable a row by id from a later layer (`{ id: X, disabled: true }`) and the composed tree proves it (`--dump-config` prints `disabled: true`) — no guessing needed; and a scratch `DSH_HOME` starts with only the shipped presets, so a session on `zabz` there answers `agent-preset/not-found` until the preset is copied into that home's `.agent-presets/`.
