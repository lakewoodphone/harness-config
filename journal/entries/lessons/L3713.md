**L3713 · A case file is unfindable when customer: holds a title, and lptcase show returns a different case instead of failing**

A case file is unfindable when `customer:` holds a title instead of a name, and `lptcase show`
returns a different case rather than failing. Both were true of the Vahab LG Gram case on
2026-10-12.

**Measured, before the fix.** `docs/customer-operations/cases/lg-gram-16t90p-usbc-bench-2026-07-29.md`
carried `customer: "Mrs"` and `aliases: []`. `lptcase find "vahab"` searched 284 cases and returned
**NO CONFIDENT MATCH** - the case scored **0.80 (body-text)**, against a confidence floor of 3.00.
The shop's own search for the customer's surname did not find her case.

**The dangerous part.** `lptcase show "vahab"` did not say "no match". It printed
`qin-towin-2026-08-12` - a different customer, different device, different money - formatted
exactly like an answer. `show` is a best-match view, not a lookup. Never use `show` to establish
identity; use `find` and read the `match reason` it prints.

**The fix.** `customer: "Vahab"` plus every spelling anyone has used:
`["Mrs Vahab", "Mrs. Vahab", "Sori Vahab", "vahab", "gram laptop (website intake 2026-07-28)"]`.
Result: `name-exact(vahab) -> 4.00`, found in 80 ms.

**The same file's other numbers were also wrong, and nothing could see it.** It read
`status: "waiting"`, `price: 829.99`, `payment_state: "paid"`. The 829.99 was a *replacement-laptop*
option from an 08-06 market-research sweep and was never a quote for this case; nothing had ever
been paid; and the repair had been declined by the customer three days earlier. `lptcase check`
reported nothing for this case - a wrong customer name and a wrong price are both valid strings.

**Rules.** (1) Whenever a case is touched, read the front-matter numbers against production before
trusting them - the front matter is what every script and every search reads, and it drifts
silently. (2) `customer` is the canonical name; every other spelling is an alias. `customer: "Mrs"`
is not a name. (3) A search that returns a case with a weak match reason is a miss, not a hit.
