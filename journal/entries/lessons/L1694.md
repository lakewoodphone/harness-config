**L1694 · A disabled HA config entry yields NO state object, so a Lovelace tile is silently blank**

A DISABLED Home Assistant config entry produces NO state object at all. A Lovelace card pointing at it renders silently blank and nothing is logged.

MEASURED 2026-09-16. The owner reported "2 cameras aren't showing on the dashboard". Root cause:
three Dahua config entries on the NVR are disabled at the config-entry level —
"Cam Deserted Exit" (channel 0), "Cam Larry's Exit" (channel 2), "Cam Waiting Room" (channel 4).
Their devices carry `disabled_by: config_entry` and all 16 entities each are disabled.

The diagnostic that actually finds this, and is NOT `/api/states`:
 GET /api/config/config_entries/entry
 -> dahua not_loaded Cam Deserted Exit
 dahua loaded Cam Larry's Interior
 dahua not_loaded Cam Larry's Exit
 dahua loaded Cam Front Hallway
 dahua loaded Cam Deserted Interior
 dahua not_loaded Cam Waiting Room

`/api/states` simply does not contain the entity, so a check written only against the state list
reports "entity missing" and sends you looking for a renamed entity that does not exist. The entity
IS in `/config/.storage/core.entity_registry`; it just has no state.

Rules:
1. To verify a dashboard reference, compare against BOTH `/api/states` and the config-entry load
 states. A `not_loaded` entry is the difference between "wrong entity name" and "integration off".
2. Do not delete the dashboard reference for a not_loaded camera. Keep the tile and make it degrade to
 an explicit "CAMERA DISABLED" panel naming the entity and the entry, so re-enabling the entry
 restores the feed with no dashboard edit. Removing the reference is the one change that would make
 the re-enable invisible.
3. Also seen the same night: 437 entities `unavailable`, 885 registry entities disabled. A "show
 everything" card is actively harmful here.
4. Related trap found in `configuration.yaml`: the `Hallway Humans Recent` template sensor read
 `binary_sensor.cam_front_hallway_smart_motion_human` (dead) while `..._human_2` worked, because two
 duplicate device sets exist per camera — one keyed `['dahua','43d946db242577fe15fd239f3e5db8e5_ch']`,
 one keyed `['dahua','8C03EA3PAZC4C2D_ch']`. Duplicate device identities silently split an entity's
 live/dead halves. Check for a `_2` twin before concluding a sensor is broken.
