**L2391 · Case lookup in lpt-hub: build the index first, and the 196-vs-193 warning is real**

Measured 2026-09-22 on ZABZ-YOGA (~/code/lpt-hub).

1. 'no index found - run: python tools/case-index/lptcase.py index' — the case index is NOT committed, so a fresh or un-synced checkout has no index/cases.json and every find/show exits 1 until it is built. Build is cheap: 196 cases / 1.9 MB / 29,290 lines in 1.15 s. Any session asked 'pull up the case for X' must run index first.

2. The warning CASE COUNT MISMATCH: 196 case file(s) on disk, 193 tracked by git is accurate and is not an index bug — 'git status --porcelain' shows exactly 3 untracked case files (quin-factory-reset-hirschfeld-2026-09-16.md, quin-screen-1326-2026-08-30.md, surface-laptop-7-2036-drop-no-charge-9082165652-2026-08-24.md, plus two untracked sync records). Those are real case files that exist on ONE machine only, so a case can be invisible on every other node. Do not dismiss the warning; the drift is the finding.

3. 'lptcase.py open' is unusable as a worklist: it returns 136 open of 196 and 48 with no dated entry, oldest 95 days. Staleness alone does not rank it.

4. AGENTS.md section 0 is right and fast (~150 ms warm). Repo-wide grep for a case is still the wrong tool.
