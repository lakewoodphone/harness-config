**L2396 · Raising a ceiling in one layer leaves every other layer enforcing the old number**

LESSON 2026-09-23. When you raise a ceiling in one layer, find every other layer
that enforces the same concept. The lowest number wins, and it is usually the one
nobody remembered — including the layer that can only ever fire falsely.

Measured: on 2026-09-20 `agent_worker._PER_TICK_ACTION_LIMIT = 6` was split into 6
for mutating tools and 18 for read-only lookups (`_PER_TICK_LOOKUP_ACTION_LIMIT`),
because 146 of 836 blocked calls in a 7-day window were `repo_search` refused
mid-research. `cost_circuit_breaker.DUPLICATE_TOOL_LIMIT` stayed at 6 and counts tool
NAMES. From that day a legitimate research tick of 7-18 searches tripped the breaker:
trips/day went 0 (before 09-20) -> 1, 5, 5, 3 (09-20 -> 09-23). All 14 were lookup
tools (repo_search 11, list_tasks 1, memory_search 1, repo_read_file 1). No mutating
tool ever tripped, and none could: the worker blocks a mutating tool at its 7th call,
so the breaker could only fire inside the band the worker deliberately allows. The
check was not "too sensitive" — it was unreachable except by false positives.

Cost: 14 owner texts (spend $0.0000 each), ~7 agent-hours of 30-minute cooldowns in
the engineering department, and the day's owner-SMS allowance spent so that real
questions sat `held` in `owner_message_queue`.

Second-order corollary, same session: the call was made without `db_url`, so
`_log_event`/`_persist_state` no-op'd and none of the 14 trips appears in
`circuit_breaker_events` or `circuit_breaker_state`. A side effect gated on an
optional argument is invisible exactly when the caller forgets it; the journal held
the only record.
