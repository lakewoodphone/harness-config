**L1810 · Tailscale serve forwards device identity, and Serve status is still not evidence**

Two measurements worth keeping, both 2026-09-16 on ZABZ-YOGA.
1. A loopback listener placed behind Serve receives, on every request: `Host: <node>.tail93e6e6.ts.net`,
 `Tailscale-Headers-Info`, `Tailscale-User-Login`, `Tailscale-User-Name`,
 `Tailscale-User-Profile-Pic`, `X-Forwarded-For` (the CALLER's tailnet IP),
 `X-Forwarded-Proto: https`. So a backend CAN tell callers apart, and an allow-list is possible
 without the admin console. But the LOGIN header is useless for that here: every device on this
 tailnet is under one Google identity. Use X-Forwarded-For.
2. The probe cost nothing to run and settled a design question in one call: bind a 20-line listener,
 point `tailscale serve --bg <probe port>` at it, make two requests, read the dump, point Serve
 back. Prefer this to arguing from documentation.
