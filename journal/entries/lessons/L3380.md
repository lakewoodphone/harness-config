## L-new · A generator that can delete a hand edit needs a guard, not a warning

**`scripts/make_zabz_preset.py` did two real destructive things on 2026-10-08, both while I was trying to
add one paragraph.**

1. It carried the source preset's skills across with `rmtree(dst_skills)` then `copytree(src_skills)`.
 That **deleted `presets/zabz/skills/fast-search/SKILL.md` and `secretary-wake/SKILL.md`** — the two
 skills only the target preset had. Recoverable only because git still held them and the deletion
 showed up in `git status`. It now merges per skill and reports what it kept.
2. Running it without `--check` overwrote the committed preset and **dropped eight persona rules added
 by hand since the last generation** — money rendering, "do not make him think for you", five
 outbound-comms hardening bullets, and "ask him before a counterparty". These were *live*
 (they are in the shipped persona). `--check` had detected the drift, but reported it as one line
 naming only the file, and the message only *advised* moving the hand edit first.

**The lesson is about the shape of the safeguard, not the incident.** A warning that cannot stop the
damage is not a guard; a drift check whose output does not say *what* drifted forces the operator to
guess. The generator now refuses to write when the destination holds a rule paragraph it does not
produce, names every one of them, and requires `--force` to discard them deliberately.

Generalising: any tool that rewrites a file humans also edit must be able to state, in one run, exactly
what it is about to destroy — and must default to not destroying it.
