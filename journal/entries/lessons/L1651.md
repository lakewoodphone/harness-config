**L1651 · A test helper encodes a timezone, and that assumption travels with the machine it was written on**

**A test helper encodes a timezone, and that assumption travels with the machine it was written on.**

Measured 2026-09-15, the fourth instance of this shape in two rounds (Windows paths in the gateway
guard, a Windows URI decoder, `.env` inheritance in a Settings fixture, now server-local timestamps
against family-local logic). The tell is the same every time: **the test passes on the author's
machine and fails on the server, and the failure looks like a logic bug.**

Here the arithmetic was invisible in the assertion: `in_quiet_hours(_local_ts(2))` reads as "02:00",
and it is 02:00 -- in a zone nobody wrote down. `time.mktime` silently uses the host's local time;
`_family_dt` silently converts to the family's. Two silent conversions cancel on one machine and
contradict on another.

Rules:
- **When a test builds a timestamp for a function that evaluates in a named zone, build it in that
 named zone** -- import the same zone constant the code uses, do not rely on the host agreeing.
- **A blanket substitution is not a fix.** Replacing the helper across the whole class broke 8 passing
 tests and thereby *measured the boundary*: only nine call sites meant the family zone. Change the
 sites whose expectation is the thing being tested.
- **Flakiness has a signature; go looking for it.** The failing count moved between full runs (7, then
 4, then 4 with a different membership), which is information: it rules out "a broken test" and
 points at time, races and shared state.
