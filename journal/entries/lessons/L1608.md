**L1608 · Turbopack build fails when a worktree's node_modules is a junction (points outside project root)**

EVIDENCE: in C:\Users\ezabz\Code\_worktrees\personality-system\delivery-ci, `npx next build` (Next 16.2.2, Turbopack default) died with `TurbopackInternalError: Symlink [project]/node_modules is invalid, it points out of the filesystem root`. The worktree's node_modules was a Windows Junction -> C:\Users\ezabz\Code\personality-system\node_modules, and next.config.ts sets `turbopack: { root: process.cwd() }`, so the symlink target is outside the Turbopack root. `npx next build --webpack` compiled fine (proof the code was sound). Replacing the junction with a real directory (robocopy /E) made the default `npx next build` pass with exit 0.

RULE: if a worktree has a junctioned node_modules and the Next build must actually run, `--webpack` proves the code but is NOT the gate command; `npx next build` needs real node_modules. Docker/CI are unaffected (they copy a real dir). `--webpack` is also a useful one-command discriminator between "my code is broken" and "the build harness is broken".
