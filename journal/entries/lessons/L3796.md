**L3796 · My 675 [WORK_DONE] count was a false positive: the predicate matched the denial, not the signal**

My own first measurement of `[WORK_DONE]` was wrong, and the way it was wrong is the failure this estate measures most.

WHAT I MEASURED, 2026-10-14 ~11:50Z on ZABZ-YOGA, via `sqlite3 -readonly /root/authority.db` over ssh to secratary-cloud:

 SELECT COUNT(*) FROM work_sessions
 WHERE started_at > datetime('now','-7 days') AND output_log LIKE '%[WORK_DONE]%';
 -> 675

Round 2 (`55-company-design.md` D4, and `H3632`) says completion is keyed on `[WORK_DONE]` and that **zero** sessions ever emitted it. 675 against zero looked like a contradiction, and I said in my report to the owner that "`[WORK_DONE]` appears in 675 output logs, not zero" — while correctly refusing to assert that the model emitted it.

WHAT IS ACTUALLY TRUE, measured by mesh child subagent-2 on zabz-tech-linux and returned 2026-10-14 ~12:20Z: the 675 is a **pure false positive**. Every one of the 675 rows contains the token inside a sentence that says the session did NOT emit it. Decomposed:

- **411** rows contain the string `without [WORK_DONE]`
- **266** rows contain `no [WORK_DONE] token was required`
- 2 rows contain both; 411 + 266 − 2 = **675**, exactly.

And the checks that settle it: the prompt text itself is **not** logged into `output_log` (count of the prompt phrase there = 0), `[WORK-DONE-INSUFFICIENT]` = 0, `COMPLETED by LLM signal` = 0. **Round 2 was right: the model emitted the token zero times.** The writers of those sentences are `_close_unfinished_work_session` (`autopilot.py:3543`) and `_complete_if_task_closed` (`autopilot.py:3935`) — the loop explaining, in the log, that it is closing the session without the token.

WHAT I SHOULD HAVE DONE DIFFERENTLY: I had the right instinct (I refused to claim emission) but I still put a number in front of the owner that a later reader could quote as a contradiction of the record. The cheap version of that check was one more `SELECT` — `... AND output_log NOT LIKE '%without [WORK_DONE]%'` — which returns **0**. **A count whose predicate you have not read is not a measurement.** The predicate here matched a denial, which is the general shape: a search for a failure marker will find the sentences that report the absence of the failure.

This is the `wrong-data` failure (#1 measured, 12.0% of owner sessions) committed by the session auditing it, in the same program where round 2 committed two of its own (`L3774`). Recorded rather than quietly dropped.
