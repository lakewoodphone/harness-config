**L1884 · dsh.bundle.patch is a path to a patch layer, not an identity marker -- drop the name, do not invent a bundle**

`dsh.bundle` is a PATH to a Cordis patch layer, not an identity marker — so the repair for a
bundle-less name is always to DROP the name, never to invent a bundle for the package.

Measured 2026-09-17 on both sides of the loader:

 dsh-app-boot/lib/index.js:849-855
 const declared = JSON.parse(readFileSync(join(packageDir,"package.json"),"utf8")).dsh?.bundle?.patch
 if (declared === void 0) throw new Error(`... profile bundle "..." declares no dsh.bundle ...`)
 const patchPath = join(packageDir, declared)
 ... patches: loadOverlayPatches(binName, patchPath)

`dsh.bundle.patch` must name a cordis.patch.yml the loader will MOUNT into every booting engine. So a
package with a `bin` and no host rows (`packages/mesh-broker`, `packages/deepseek-proxy`) cannot carry
one honestly: the only way to satisfy the loader would be to invent a patch layer for a service, which
changes what that package means for every node. The correct repair is the one
install-client-plugins.ps1 already performs automatically ("declares no dsh.bundle -- REMOVING from the
bundle list"), and it is what mac-mini needed on 2026-09-17: exit 1 -> 0, 585 lines, engine untouched.

WHY IT MATTERS BEYOND THIS CASE. The same shape recurs: a config key that looks like a flag is
actually a pointer to behaviour. Reading the consumer's source before choosing a repair is what
separated "drop the row" (correct, one machine, zero fleet blast radius) from "give the package a
bundle" (wrong, and it edits a shared package to fix one machine's symptom).

Evidence: docs/mesh/97-fleet-repairs.md SS1.2; docs/mesh/90-provider-mount.md SS3.
