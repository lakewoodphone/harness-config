**L1990 · One scheduled source can start your singleton twice: register the task, do not unregister it**

MEASURED 2026-09-18. `dshw ensure` runs every minute as a Task Scheduler task, so a manual `dshw ensure` and the watchdog's run can call Start-OriginsProxy in the same instant. Both registered the transient task, both started a process, and the two proxies SPLIT the 24-port range between them.

WHY THE ENGINE'"'"'S PATTERN DID NOT TRANSFER: Start-EngineDetached registers a transient task and unregisters it once the port answers. That works for the engine because the port itself arbitrates a single process. A proxy that owns MANY ports cannot be arbitrated that way, and -MultipleInstances IgnoreNew is useless if the task has already been unregistered - there is nothing left to ignore.

FIX, three layers: (1) leave the task registered so IgnoreNew has an instance to ignore; (2) the proxy exits 0 if /__dshw/stats already answers on its base port; (3) an atomic fs.writeFileSync(lock, {flag:"wx"}) whose recorded pid is liveness-checked, so a crash leftover is taken over rather than wedging the proxy forever.
