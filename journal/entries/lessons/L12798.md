**L12798 · The authority owner_timezone is UTC - human wall-clock times must not read it**

## The authority's `owner_timezone` is UTC, so any path that reads it for a human wall-clock time writes hours early

WHAT I MEASURED (2026-10-22, secratary-cloud, live API on :8002):

- `app/config.py` defaults `owner_timezone = "America/New_York"`, but `/opt/company/.env` line 136
 sets `OWNER_TIMEZONE=UTC`, and the runtime value is UTC —
 `python -c "from app.config import settings; print(settings.owner_timezone)"` -> `'UTC'`.
- `POST /calendar/events` (`calendar_quick_add`, main.py ~18646 before the fix) built the event as
 `datetime.fromisoformat(f"{date}T{time}").replace(tzinfo=ZoneInfo(settings.owner_timezone))`.
- Probe: quick-add `{"date":"2026-11-01","time":"15:00"}` returned
 `"start": "2026-11-01T10:00:00-05:00"` — Google stored **10:00 EST** for a 3 p.m. request, 5 hours early.
 After the fix, the same call returned `"start": "2026-11-01T15:00:00-05:00"`.

FIX (edited in place 2026-10-22, NOT yet loaded — company-api started 06:22 UTC, before the edit):
- `app/config.py`: new setting `calendar_timezone: str = "America/New_York"`, documented as separate
 from `owner_timezone` on purpose.
- `app/main.py` `calendar_quick_add`: resolve the zone from `CALENDAR_TIMEZONE` -> `settings.calendar_timezone`
 -> `America/New_York`; never from `owner_timezone`.
- Verified by importing the edited module in a fresh process and calling the route function directly
 (probe event deleted afterwards; calendar read-back shows only the intended events).

WHY IT MATTERS: this is the route a chat/tool add uses. Any owner appointment entered that way landed
4-5 hours early and nothing errored — the same silent-fallback shape as L1606.

STILL OPEN: company-api must be restarted in the 02:00-04:00Z window for the fix to take effect;
the .env value itself was left alone because machine schedulers legitimately read `owner_timezone`.
The two touched files carry another session's in-flight edits, so this was left uncommitted rather
than sweeping them into a commit (P13).
