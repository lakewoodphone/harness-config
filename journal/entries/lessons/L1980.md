**L1980 · A new broker route stops the app booting, not just the route-security audit test**

EVIDENCE (kf-level worktree, branch fleet/level, 2026-09-16): adding `POST /owner/level` to `server/app/router_registry.py` makes `with TestClient(app)` raise at startup:

 RuntimeError: HTTP route security audit failed: unexpected routes requiring review (1): POST /owner/level

`include_default_routers` sets `app.state.route_security_audit_enabled = True`, and `validate_startup` (server/app/startup_validation.py:419) runs `audit_http_route_security(app).raise_for_failures()` inside lifespan when that flag is on. So an unregistered route is not a failed test - it is an app that cannot boot, which fails EVERY test in the repo that opens a TestClient, including the new route own tests.

WHY IT MATTERS: a brief that says "the global security-audit tests will fail, that is expected, report the tuple" is describing something with a much bigger blast radius than it sounds. A fleet worker given that brief and no fix would report "I could not run my own tests".

WHAT TO DO: two parts, both needed.
1. In the worker own test module, add a module-scoped autouse fixture that sets `app.state.route_security_audit_enabled = False` and restores it - the same shape as tests/conftest.py::legacy_main_app_auth_token_audit_opt_out, which does this for `auth_token_config_audit_enabled`. Comment it with the exact tuple so the opt-out cannot be mistaken for weakening the audit.
2. Report the tuple for integration: ('POST', '/owner/level') into server/app/route_security.py KNOWN_HTTP_ROUTES.

BONUS FAILURE: tests/test_route_security_audit.py::test_startup_validation_fails_on_unreviewed_websocket_route also fails on collateral - it asserts the message matches "WebSocket route security audit failed" but startup now dies earlier with the HTTP audit message. Registering the tuple fixes both.

ALSO MEASURED: each TestClient(app) boot in this repo costs ~18-25 s (startup validation scans the SQL surface over the whole server tree). One test per value of a parametrized table therefore costs minutes: 11 parametrized values took 5m23s as 11 tests and 2m29s as one test looping inside a single TestClient. Loop inside one client, and give each iteration its own household + owner so one iteration rate-limit budget cannot fail the next.
