**L3817 · lpt ticket prints comms times that are not the row times - quote created_at / date_started_ms, never the display clock**

**Measured 2026-10-15 on WO26100812736 (Senzer), ZABZ-TECH.**

`lpt ticket` prints a timestamp beside every communication. On these rows that printed clock is NOT the row's
time, and the error is not a constant offset:

| what | printed by `lpt ticket` | stored in the row |
|---|---|---|
| call 4728846742757376 | 2026-10-13 17:09:03 | `date_started_ms` 2026-10-13 16:49:46 UTC — **+19m17s out** |
| SMS 4897128391155712 inbound | 2026-10-15 00:09:06 | `created_at` 2026-10-14 23:39:25.473 UTC — **+29m41s out** |
| SMS 6744484690567168 outbound | 2026-10-15 00:09:05 | `created_at` 2026-10-14 23:39:26.228 UTC — **+29m39s out** |

Three rows, two different offsets, one case — so the printer is neither UTC nor a timezone shift of the row (ET
would be −4h from UTC, not +29m). The row and the epoch agree with each other AND with the comms index's `ts`;
the printer is the only outlier.

**How it cost me.** I quoted the printer instead of the row and wrote two wrong times into the case file *and*
into a production note: 4098 on order 3015 said the call ran 17:09-17:10 UTC and the text arrived 20:09 UTC. The
owner's very next question was about those calls, so the wrong numbers were one sentence from being handed back to
him as fact. Corrected in the same session: production note 4100 citing 4098, both times fixed in the case file
(and a bullet saying where they came from), the sync record's `operational.internalSummary` fixed, branch
`case/senzer-diagnostic-fee-20261015` pushed. It is also the second correction on this one order in twenty
minutes, which is itself the lesson: **do not write a number into two records and a production note before reading
the column it came from.**

**The rule.** For any comms time quote the stored column — `dialpad_call_full.date_started_ms` /
`date_ended_ms`, `dialpad_sms_cache.created_at`, or the comms index's `ts` — never the ticket printer's clock.
When two readers of the same row disagree, read the column, not the renderer: same shape as L3796/L3798, *print
the raw value next to the predicate*.

**Also measured on the same rows.** The 2026-10-14 inbound text and its auto-reply each sit in
`dialpad_sms_cache` **twice**, 2.8 s apart, with the same `message_id` (4897128391155712 at 23:39:25.473 and again
at 23:39:28.260; 6744484690567168 at 23:39:26.228 and again at 23:39:29.149; the second pair carries `fetched_at`
23:45:02 against 23:39:26 for the first). The earliest copy is the true arrival time, and a count that does not
fold duplicates by `message_id` overstates the traffic.
