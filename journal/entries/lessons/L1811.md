**L1811 · Personal-life lookups (contact lenses) live in personal-secretary-mvp/docs/personal/, and ps_action gmail_search beats email_catalog**

**Asking "pull up my X info" for the owner's PERSONAL life is not a database query — it is a repo query.**

2026-09-16, "pull up my contact lenses info". Every database path came back empty:
`ps_memory_search "contact lenses"` → 0; `memories`/`knowledge`/`captures_inbox` LIKE '%lens%' →
only camera-repair rows; `email_catalog` LIKE '%lens%|toric|contact|optical' → **0 rows**; `journal.py search
"contact lens"` → no match. The complete answer — prescription history, both vial labels with lot numbers,
prism on the left eye only, care routine, order prices — was sitting in
`personal-secretary-mvp/docs/personal/eye-care/` (9 files + vial photos + OCR JSONs), committed to git.

Two rules worth keeping:

1. **Personal-life facts live in `personal-secretary-mvp/docs/personal/<topic>/`, one folder per domain**
 (eye-care is the template: README with a Current Status block, prescription-history, measurements,
 options-and-decisions, plus memory-hint and care docs). Search the repo before concluding "we have nothing".
 This is the same failure the phone agent was already diagnosed with — `docs/dsh-mobile/00-RESEARCH.md:227`
 quotes the owner's own symptom table: *"Contact lens → found nothing."* It was never a search bug; the agent
 was looking in the wrong store.

2. **`ps_action gmail_search` works and is the live personal-mail path.** Query
 `{"query": "...", "max_results": 25}` returned real messages from his personal Gmail
 (`eliyahuzabrowsky@gmail.com`) — including a Google Voice voicemail transcription from Clearview about the
 lens order — while the `email_catalog` table held **zero** matching rows for the same terms. When
 `email_catalog` says nothing, that is a refusal, not health: go to the API.

Corollary used the same day: the newest physical evidence (a Sept replacement-lens shipment) was in **neither**
the docs nor mail nor SMS (`dialpad_sms_cache` had nothing but camera repairs), so the honest answer was the
recorded pair + the decisive rule (prism = left eye), with the unresolved mapping written into the record as
UNVERIFIED rather than guessed into it.
