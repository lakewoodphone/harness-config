**L11391 · L11391 · I named a cause from a refusal and wrote it in five documents; one probe undid it — a refusal is not a failure**

**2026-10-20, measured both ways inside one session.** I committed a confident cause for the location
failure — "the allowlist refuses the iOS 26 geo-selector names, so allowing them fixes it" — wrote it
into five documents, pushed it, and built a canary around it. Then two independent read-only workers
measured the same filter and one line undid it: **`gs-loc.apple.com` answers through our filter with an
A record (17.242.184.19)**. A refused CNAME target does not stop a client that already holds the
parent's address, so the names I had made the villain were noise. What is actually refused at the entry
name is a different set: `cl2.apple.com`, `cl3.apple.com`, `iphone-ld.apple.com` — locationd's tile and
GNSS hosts.

The error was not the reasoning about CNAMEs, which is real and is 102-of-113 real. The error was
**treating "the resolver refuses name X" as "the feature that uses X is broken"** without a single
device-side observation, and then writing it in the past tense.

RULES:
1. **A refusal is not a failure.** Before naming a cause, find the observation that connects the
 mechanism to the symptom — a device, a user, a second source — or label the mechanism "consistent
 with, not established". My own measurement was available and would have stopped me: one probe
 printing the answer set instead of the row count.
2. **Commit the uncertainty in the same commit as the finding.** The first commit's commit message and
 five documents asserted a cause; the proof that killed it took one command. A document that cannot
 survive one probe is not documentation, it is a confident guess with a file path.
3. **A fan-out is worth it for the disproof, not the confirmation.** Seven workers, five returned; the
 value was two of them contradicting the manager. Delegation that only confirms is expensive; the
 briefing must ask for the specific measurement that could falsify the parent's claim, by name.
4. **Correct in place and keep the wrong version visible.** The docs now open with a CORRECTION block
 that states the withdrawn claim and why. Deleting it would have destroyed the most useful thing in
 the file: the exact shape of the mistake, which is what the next session has to avoid.
