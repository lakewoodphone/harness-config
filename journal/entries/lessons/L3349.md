**L3349 · An iOS app allow-list hides everything except Phone and Settings - including Safari and the Web Clip itself - and the kiosk template ships allowMicrophone=false**

**An iOS app allow-list hides everything except Phone and Settings — including Safari, and including
the Web Clip itself.**

Measured 2026-10-06 while building the family profile for DRN 39. Three consequences, each of which
would have shipped a broken phone:

1. `allowListedAppBundleIDs` does not "add" apps, it is the complete visible set. Messages, Camera,
 Photos, Calendar and Find My vanish unless they are named explicitly. Phone and Settings cannot be
 hidden.
2. **A managed Web Clip is an app** (`com.apple.webapp`). Allow-list the eleven apps you want and
 forget that one and the web clip is installed, is reported as installed, and is invisible on the
 home screen. Apple's own text: "To allow all Web Clips, you need to add the value `com.apple.webapp`."
3. **Hiding Safari removes the Web Clip's delivery path**: Apple — "this setting also prevents users
 from opening Web Clips."

So "give her one web app and block the browser" is self-contradicting on iOS: pick the browser plus a
URL whitelist, or no browser at all and no clip.

**And the kiosk template is not a template for a phone.** The shop's `waze-layered-kiosk-drn26`
restrictions carry `allowMicrophone = false` — correct for a Waze kiosk, fatal for a phone whose only
voice path is Dialpad VoIP. Copying that file and changing the app list would have produced a phone
that cannot make a call on the app it exists for. The other keys flipped for phone use, each for the
same class of reason: `allowChat`, `allowCamera`, `allowScreenShot`, `allowSafari`,
`allowPasscodeModification` (Apple: false "prevents adding … the passcode", so applying it before a
passcode exists leaves her permanently unable to set one), `allowAccountModification` (she still has
to sign in), `allowFingerprint*`, `allowLockScreenNotificationsView`, `allowLockScreenControlCenter`,
`allowCloud{AddressBook,Calendar,Notes,Reminders}` (her own data must survive a lost phone), and
`allowVPNCreation` / `allowSpotlightInternetResults` turned **off** as back doors around a web
whitelist. The generator that applies exactly these and prints the still-false list is
`_scratch/build-family-profile.py`; the reasoning is in
`deploy/waze-mdm/docs/family-phone-drn39-plan.md`.
