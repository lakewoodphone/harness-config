**L241 · Scheduled-task console windows: -WindowStyle Hidden still pops; wrap in wscript for SW_HIDE at creation**

PROBLEM. Owner: automated powershell windows "keep popping up every minute" and "keep coming to the
forefront", clobbering dictation/typing. The 1-minute DSH Engine Watchdog was the main offender on
ZABZ-YOGA and ZABZ-TECH.

WHY `-WindowStyle Hidden` IS NOT ENOUGH. The watchdog task ALREADY had `-WindowStyle Hidden` and still
popped. PowerShell applies WindowStyle after conhost has created and shown the console, so the window
still appears (flash + focus steal) before it is hidden.

THE FIX THAT WORKS. Point the task action at `C:\Windows\System32\wscript.exe //B //NoLogo "<vbs>"`,
where the generated .vbs is:
 Set sh = CreateObject("WScript.Shell")
 sh.CurrentDirectory = "<workdir>" ' only if the original action had one
 WScript.Quit sh.Run("<full command line>", 0, True)
`0` is SW_HIDE in STARTUPINFO, so the console is created hidden - no window, no flash, no focus steal.
`True` waits, and `WScript.Quit <rc>` returns the command's exit code, so Task Scheduler Last Run
Result, MultipleInstances and ExecutionTimeLimit keep their old meaning. VBS escaping is only: double
every `"` in the command, then wrap the whole command in quotes.

VERIFY A WRAPPER WITH: Start-Process wscript.exe -ArgumentList ... -Wait -PassThru -> .ExitCode.
A bare `& wscript.exe ...` does NOT set $LASTEXITCODE (wscript is GUI-subsystem, the call does not wait).

TOOLS. harness-config/scripts/Set-TaskHidden.ps1 (convert existing tasks; -WhatIf / -Restore /
idempotent), harness-config/scripts/HiddenTaskAction.ps1 and
personal-secretary-mvp/scripts/HiddenTaskAction.ps1 (registration helpers), dshw.ps1's
New-HiddenTaskAction + Invoke-HiddenTaskBootstrap.
