**The pull half exists, and the canonical tree is a superset again — measured 2026-10-16 02:41Z.**

The union landed at 02:02 and was a superset for 38 minutes; by 02:40 it was missing 6 yoga entries
(L6464). That is what a repair is without a convergence step: a snapshot. `converge-pull.py` is the
missing half.

**ADDITIVE BY CONSTRUCTION.** Only the INCOMING entry's id can change — `L5984` came in as `L6465`


Nothing on the canonical side is read-modified, moved or removed, so no existing citation can break,
and everything this does is reversible by deleting files that did not exist before.

**AND THE PROOF OF THAT IS git, NOT mtime.** `find -newermt` listed ~150 entry files with mtimes one
second after the pull, which looks like a mass rewrite. `git status --porcelain` reports exactly
**6 paths, all `??` — new files, nothing modified**. The 150 were `journal.py check --fix` re-emitting
entries through its writer: new mtime, byte-identical content. **A file's mtime is a claim about when
something wrote it, never about whether it changed** — the same family as "a window's end is when the
process loaded the code, not when the file was written". For "did this change anything", `git status`
answers and `find -newermt` does not.

**WHAT IT IS NOT.** One iteration, run by hand, against one capture. It is a loop body without a
scheduler, and it does not stop the machines colliding — that is the ledger's job (L6463). What it does
is make the canonical tree catch up on demand, which is the half of convergence that does not require
any machine to change how it writes.
