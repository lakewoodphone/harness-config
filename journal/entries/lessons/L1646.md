**L1646 · CORRECTION to P188: the contract ignores validation_alias; I looked up uppercase env names in a dict of snake_case fields**

**CORRECTION to P188, and the real root cause of the other half.**

P188 said "`.env.example` is missing 24 declared settings" and listed them as "<not a Settings
field>". The first half is correct; **the second half was wrong, and I was wrong twice in the same
reading**:

1. I looked up the uppercase env names (`SHABBAT_TIMEZONE`) in `Settings.model_fields`, which holds
 **snake_case field names** (`shabbat_timezone`). Every lookup returned "not a field" and I
 believed it. There are **zero** uppercase keys in `model_fields`; that alone should have stopped
 me. All 24 are real fields with real defaults -- `shabbat_timezone: str = "America/New_York"`,
 `shabbat_candle_offset_min: int = 60`, `shabbat_keep_ha_running: bool = True`,
 `shelly_plug_host: str = ""`, `computer_form_webhook_secret: str | None = None`. So the template
 genuinely should document them, and P188's substance stands.
2. I then concluded the contract's three names were "stale" because nothing reads them. They are not
 stale -- they are **field names**, and the fields deliberately accept only the `HA_*` spelling:

 security_api_key: str | None = Field(default=None,
 validation_alias=AliasChoices("HA_SECURITY_API_KEY"))
 ha_ptt_key: str | None = Field(default=None, validation_alias=AliasChoices("HA_PTT_API_KEY"))
 security_alert_extra_recipients: str | None = Field(default=None,
 validation_alias=AliasChoices("HA_SECURITY_EXTRA_RECIPIENTS"))

**The actual root cause, for both halves:** `backend_expected_env_keys()` is
`{name.upper() for name in Settings.model_fields}` -- it uppercases **field names** and ignores
`validation_alias` entirely. So the contract demands `SECURITY_API_KEY`/`HA_PTT_KEY`/
`SECURITY_ALERT_EXTRA_RECIPIENTS`, which the code does *not* accept, while calling the three names
the code does accept "unexpected keys". The contract is the thing that has drifted, not the template.

**The fix, precisely (round 42):**
- `backend_expected_env_keys()`: add each field's alias names (`validation_alias`, including every
 member of an `AliasChoices`) to the expected set. That removes the three `extra_keys` warnings and
 three of the 24 `missing_keys` at once, with no template change and no lie.
- Then document the remaining ~21 genuinely-missing settings in `.env.example` with their declared
 defaults (secrets empty), which is what P188 asked for and what a fresh deployment needs.
- Verify with `pytest tests/test_config_contract.py -q` -- three tests, 11 seconds.

This is L1642 a fourth time in one session (a representation is not the value): I read a
representation of the field set (uppercased keys) and of the constant (`ROOT_ENV_ALLOWED_EXTRA_KEYS`
membership) and drew two confident conclusions from them. Both were checkable in one call each, and
the second one contradicted a fact I had already measured -- 5 files reading `HA_PTT_API_KEY`.
