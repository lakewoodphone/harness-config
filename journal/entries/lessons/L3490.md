**L3490 · Coosea SL006 (IRIS Easy Flip / Summit FL!P): enabling adb needs the left soft key, and the obvious web procedure wipes userdata**

Coosea SL006 platform (IRIS Easy Flip SL006-CC, DISH/Boost Summit FL!P SL006D; Android 12 on
MT6739WW, 8 GB eMMC, F2FS userdata, file-based encryption).

**Unlocking developer options is NOT "tap Build number 7 times".** On this firmware:
Settings -> About Phone -> Software Information -> Software Version, then **press the left line key
(the soft key above CALL) repeatedly**, then Settings -> Phone Settings -> Developer Options. USB
debugging is the setting that matters. Documented on the identical platform in the XDA thread
`boost-summit-flip-adventures.4723603` (2025-03); not yet verified on the IRIS-branded handset,
which is unpowered on the bench.

**The trap, and why this is worth a journal entry at all:** the same thread's headline procedure is
a bootloader unlock, and `fastboot flashing unlock` **wipes userdata**. On a deleted-media recovery
job that wipe IS the evidence - the customer's file, permanently gone, on a device a search for
"SL006 adb" recommends. TWRP exists for the platform but flashing it needs the same unlock, and
stock firmware bootloops on a Magisk-patched boot image, so root is not a route.

**What ADB is worth on this class of handset, without root:** evidence and extraction, not undelete.
`/sdcard` is on the same F2FS userdata partition and Android 12 uses FBE, so a raw partition dump is
ciphertext and a logical copy of `/sdcard` holds only live files. It does give: the internal
`Bluetooth` folder (where a Bluetooth-received file lands on Android) listed without opening an app;
`find /sdcard -iname '*.mp4'` with timestamps; the MediaStore row for a deleted file, which can
linger and carries the original filename, path and date; and `.thumbnails`, which can still hold a
frame. Enabling it writes a few KB into userdata and costs one boot, so it belongs in ONE planned
session with the PIN and a PC, never in repeated fiddling.
