**Removing texting from an E4810: the no-text profile named only stock MMS, so Message+ survived**

Owner: *"remove texting from the connected e4810"*. Serial 558800069737, model E4810, ADB-visible on
ZABZ-TECH.

## The defect, measured

`cli/configs/devices/e4810.yaml` sets `sms_app: com.android.mms` and
`sms_fallback_app: com.android.mms`. `loader.py:601-609` builds the `disable_texting` set from
exactly those two fields, so for E4810 it resolves to `['com.android.mms']` after dedupe.
Message+ (`com.verizon.messaging.vzmsgs`) is installed on the handset and was never named.

Printed before any change, E4810, tier standard / profile standard-no-text:
`forced_disabled = ['com.android.mms']`, and `pm list packages -d` did not list vzmsgs — so a
"no-text" build still had a working texting app.

Same resolution on tier standard-lite (`standard-lite-no-text`) additionally carried the base
profile's kosher-app disables: `['com.android.mms', 'com.android.cts.sidsefard',
'com.android.cts.qr', 'com.android.cts.quickjack']`. `com.android.cts.qr` and
`com.android.cts.quickjack` WERE installed on this handset, so running the supported
`scripts/deployment/disable-texting.ps1` as shipped would have removed the QR reader and
QuickJack along with texting. That is why the wrapper was not simply run.

## The fix (working tree, lpt-flip-phone, not committed — repo already had an uncommitted
## E4810 messaging work stream)

1. `cli/configs/tiers/{standard,standard-lite,filter-only}.yaml`: `com.verizon.messaging.vzmsgs`
 added to each `*-no-text` profile's `forced_disabled_packages`. Dedupes to a no-op on E4610
 and S2720, where Message+ is already the device's `sms_app`.
2. `cli/lpt/cli.py` `disable_features`: subtract the tier's **base** profile disables from the
 requested set before applying, and print `Profile: ... Packages: ...`. Feature toggles now
 apply only the delta, so `--no-text` no longer drags `standard-lite`'s kosher-app set onto a
 handset deployed on another tier.

Verified resolution after the change (E4810, all three tiers): delta =
`['com.android.mms', 'com.verizon.messaging.vzmsgs']`.

## The second half: LP&T Keys, or the right soft key opens a dead app

`home_message` maps right-soft key 2 to `com.android.mms.ui.ConversationList`. Disabling the app
while leaving the map is incident `CRITICAL_E4810_DEPLOYMENT_FAILURE_2026-01-22` (right button
opens nothing). The runtime config lives at

```
/sdcard/Android/data/com.android.cts.keysminimal/files/lpt_keys_config.json
```

reload with `am broadcast -a com.lpt.action.RELOAD_CONFIG -p com.android.cts.keysminimal`
(constants `LPT_KEYS_CONFIG_FILE` / `LPT_KEYS_RELOAD_ACTION`, `engine.py:33-35`). A no-text
resolve writes the map WITHOUT `home_message` (`loader.py` passes `home_message_enabled=False`),
and that is what was pushed here: key_map keeps app_drawer 136, recent_apps 137 and voice_toggle
{134,285,10000,287,231}; `home_message*` removed.

## Proof pattern for "texting is gone" (use these three reads)

```
adb -s <serial> shell pm list packages -d | grep -E 'mms|vzmsgs' # both present
adb -s <serial> shell am start -n com.android.mms/com.android.mms.ui.ConversationList
 -> Error type 3 / Activity class does not exist
adb -s <serial> shell monkey -p com.verizon.messaging.vzmsgs 1

```

## Traps that cost time here

- The receipt path the CLI prints (`logs\deployments\...`) is relative to `cli/`, not the repo
 root; the file actually lands in `cli/logs/deployments/`. `DEPLOYMENT_RECEIPT_DEFAULT_DIR` is
 `Path("logs/deployments")` and the CLI runs with `cli/` as cwd.
- `sms_default_application` still reads `com.android.mms` after the disable. That is the same
 end state a full no-text deploy produces (the resolver sets `sms_app_package = None`, it never
 clears the setting), but it is a disabled-but-default parcel and should be read, not assumed.
- `tempfile` is broken on ZABZ-TECH inside this harness (`No usable temporary directory found`:
 TMP points at `C:\Users\ezabz\.dsh\tmp`, which does not exist). Write scratch files to an
 explicit path; do not use `tempfile.mktemp`.
- E4810 radios: `dumpsys telephony.registry` on this unit showed `OUT_OF_SERVICE` /
 `NOT_REG_SEARCHING`, no SIM registered. Calls cannot be verified on this handset off-network —
 do not claim them.
