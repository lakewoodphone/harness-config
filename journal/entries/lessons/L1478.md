**L1478 · A stale ref and git add -A caused a cross-machine journal id collision, and my commit claimed another session work**

**A stale local ref plus `git add -A` produced a cross-machine id collision, and my commit swept up another session's half-finished entries as its own.**

Measured 2026-09-14 on `harness-config`, the journal.

`journal.py append` is designed to allocate ids "over the index, the shards **and every git ref**, which
is what stops two machines choosing the same number twice". It did not, because my local ref was
stale: `origin/master` was **3 commits ahead** of where I last looked. While I was appending, a
session on `ZABZ-YOGA` had already published **L1474** -- a different entry, about freshness having
two halves. My append also chose **L1474**.

Compounding it: my commit used `git add -A`, which swept in **`L1473`, `P136` and a recovered archive
file that another session had written into this working tree but not yet committed**. So my commit
claimed its content, and `git push` was rejected.

**The collision is only half the damage.** The second half is that for a while the tree contained
*two different entries under L1474*, and the only reason it surfaced is that git refused the push. Had
the remote been behind instead of ahead, both entries would have merged as one file and the journal
would have silently lost one.

**Rules.**
- **`git fetch` before any append.** The id allocator can only see the refs this clone has. On a
 multi-machine journal, an unfetched clone is a machine that will collide.
- **Never `git add -A` in a shared working tree.** It cannot tell your files from another agent's
 in-flight work. Stage the paths you actually wrote.
- When a push is rejected, do not force and do not bulk-resolve. Read both sides per file. Here the
 right answer was upstream's version for the three files I had merely swept up, and a fresh id for
 my own entry (**L1477**) after the rebase.

**What made recovery clean:** `journal.py index` rebuilds the index from the log, so the one genuinely
derived file (`index/entries.tsv`) does not need hand-merging, and `journal.py check` ends by proving
0 errors. The tooling was right; the operator skipped a step it depends on.
