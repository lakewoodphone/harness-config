**L1931 · dialpad_transcript_cache.duration_seconds is milliseconds, and has_transcript=0 means the call content is gone**

Measured 2026-09-17 on +19177572354, secretary DB: dialpad_call_full reports a 74.7-second call while
dialpad_transcript_cache reports duration_seconds = 62967 for a call at the same timestamp. The cache field is
milliseconds, not seconds. NEVER report a call duration from dialpad_transcript_cache - use dialpad_call_full.
Second half of the same trap: has_transcript = 0 on all 9 calls for this number and transcript_text was empty
on every row, so the CONTENT of those calls is unrecoverable. Say so. Do not reconstruct what was discussed
from call metadata, contact names or durations - that is how a confident wrong history gets written into a case.
Same family as comms_identity_link's "first contact" (DELETE+INSERT on every rebuild, so first_seen_at is just
the rebuild instant), already recorded in docs/customer-operations/FIND-AND-RECORD-ANYTHING.md section 2.
