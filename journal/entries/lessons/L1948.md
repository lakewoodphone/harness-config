**L1948 · E4610 UI is scriptable over ADB: injected taps land even with no touchscreen**

Measured 2026-09-17 on E4610 serial 615765621. `dumpsys input` shows no touchscreen on this handset
(matrix-keypad, gpio-keys, button jack only), yet injected touch events DO reach the view tree:
`input tap <x> <y>` checked MatVT's `cb_override` checkbox and focused its EditText.

So the "manual, on-the-phone" half of the stage flow is scriptable:
1. `adb shell am start -n <component>` to put the target screen in front.
2. `adb shell uiautomator dump /sdcard/ui.xml` + `adb pull` — gives text, resource-id, bounds,
 focused and checked state for every node; take the centre of the bounds as the tap point.
3. `input tap <x> <y>` (then `input text 17` for a field), and **dump again to verify** — never
 assume the tap landed.
4. `screencap -p` + pull + read the PNG for visual proof.

Verified end to end: MatVT `cb_override` unchecked -> tap -> `et_override` appears -> tap + type 17
-> tap `bt_override` (SAVE) -> dump shows `cb_override checked="true"`, `et_override text="17"`.
This turns a step the guides call hand-only (docs/guides/Kyocera E4610 Mouse Activation Protocol.txt)
into a repeatable, verifiable script.
