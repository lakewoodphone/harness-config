**L12180 · measure-space.ps1 read the wrong robocopy column: an indented summary line shifts -split indexes by one**

Found 2026-10-21 while breaking down C:\Users\ezabz\code. Measure-One did [int64]((\.ToString() -split '\\\\s+')[3]) on a line reading ' Bytes : 8085154005 4134303446 3950850559 0 0 0'. The leading spaces produce an empty element at index 0, so [3] is the FIRST number (Total), not the third. It hid because on ordinary trees Total == Copied. On C:\\Users\\ezabz\\.cache robocopy counts every file twice through a self-referencing junction - Total 8,085,154,005 = Copied 4,134,303,446 + Skipped 3,950,850,559 - and an independent Get-ChildItem -Recurse gives 4,134,303,446. So .cache was reported as 7.53 GiB against a true 3.85 GiB. Fixed by parsing with named regexes and using the Copied column; verified by re-running the script on C:\\Users\\ezabz\\code\\_scratch (71 folders, 8.51 GiB). RULE: never index into a whitespace-split of a human-formatted table; name the field. And when a total disagrees with the filesystem, suspect the parser before the filesystem.
