**L3447 · A remote child can never be continuable or messaged - engine invariant, choose the delegation path per job**

## L — No out-of-process child can be a live two-way participant: that is an engine invariant, not a package gap

ANSWERED BY AN ADVERSARIAL AUDIT OF THE INSTALLED ENGINE, 2026-10-09,
@deepseek-ai/dsh 0.2.0-rc.2, read-only, file:line evidence in docs/mesh/119 section 6.

SubagentProvider is FIVE members: name, capabilities, inheritsParentContext, start
(required), plus agentRouteDefaults and prepareContinuable (optional)
(dsh-subagent/lib/types/types.d.ts:327-376). There is NO send, interrupt, list,
dispose or resume on a provider. Messaging is a SERVICE method bound to a live
in-process Agent:
 - sendMessage requires this.ctx.agents.get(sender.id) === sender (index.js:1763)
 - child -> parent additionally requires a RESIDENT CONTINUABLE child (index.js:1766-1770)
 - interrupt consults this.resident only (index.js:849-850)
And a continuable child is ALWAYS in-process, because the continuation manager
composes the child itself: activations.materialize -> ownerCtx.agents.create(...)
(index.js:1082-1091), with prepareContinuable documented as "DATA, never a
capability" (types.d.ts:360-374). A remote node can therefore never host one.

CONSEQUENCES, measured and worth memorising:
 - a remote child is invisible to list_agents (no catalog row without
 run.localAgent, index.js:3130-3132; the mesh provider returns localAgent undefined)
 - interrupt_agent on a mesh child is a SILENT NO-OP THAT RENDERS AS SUCCESS
 (dsh-tool-subagent-control/lib/index.js:86-90). To stop a mesh child, kill its job.
 - send_message cannot reach a mesh child (remote ids are NOT_RESUMABLE)
 - dsh --profile headless has no --resume, and --session-id refuses any session with
 origin === 'subagent' entirely (dsh-headless/lib/index.js:224)
 - subagent_fork (same process, this machine, parent history) is the ONLY delegation
 path with live two-way conversation

SO: for a REMOTE child the conversation is the durable file mailbox on the child's
node (lib/mailbox.js): the child writes as it works, the parent reads it back, and a
SECOND dispatch on the same thread reads everything said so far. Never promise live
steering of a remote child - the engine's own README names the missing mechanism
("remote providers need an Activation ownership contract"; "no durable parent
mailbox") and it is an engine change, not a package change.
