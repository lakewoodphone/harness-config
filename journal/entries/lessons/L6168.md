**L6168 · An ownership test must be able to fail: a name search cannot clear a card that holds only recordings**

MEASURED 2026-10-13, the Fisher SD card case (WO26101112743). This one cost a real customer conclusion,
so it is written down as a rule.

An ownership test must be able to FAIL on its own terms. A whole-surface search of a card for the
customer's name and phone number ("fisher", "9145702075") was run twice and returned 0 hits both
times, and the second time it was reported as clearing the card. It does not. The customer then said
the card held RECORDINGS ONLY, some with Hebrew names - and a card holding only recordings has no
documents, no contacts and no vCard in which a name could ever appear. Zero hits was the EXPECTED
result for his own card. The test could not have distinguished his card from anyone else's, so its
"negative" carried no information at all.

The rule: before running a search as an ownership test, ask what the media could possibly contain
that would carry the identifier. A name search is strong on a family camera card, a document drive or
a phone with contacts. It is worthless on a card that holds only recordings, only music, or only a
single application's data. Ask the customer what was on it FIRST - one line of description decides
whether the test is worth running at all - and if nothing on the media could carry the name, say the
test is inapplicable rather than reporting it as a pass.

Corollary that bit in the same session: an absence of results from a tool that was KILLED (grep OOM
on a raw image, lesson L3703) is also not a negative. Both failures look identical in a report and
both mean "no information", not "cleared".
