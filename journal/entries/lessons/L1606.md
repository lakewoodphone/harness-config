**L1606 · AI models must never be hardcoded: resolve from the gateway catalog, prefer route aliases, env chain + validation + provenance**

## L - AI models must be resolved at runtime from the gateway's own registry, never hardcoded

**The rule (owner, 2026-09-15, verbatim):** "in general in all our apps and systems ai models
change very often, can never be hardcoded and get changed and updated all the time so we need
robust easy flows for that. currently the model we are using for almost everything is
deepseek 4.1 flash."

**Why it is not advice but a measured defect.** `personality-system` hardcoded
`deepseek-v4-flash` / `deepseek-v4-pro` in `secretary-provider.ts`. Result: the AI layer failed
on 100% of real recorded production requests (assessment_ai_events, 4 rows, all failed) and
nobody noticed for over a week because the deterministic fallback silently produced text that
looked fine. Fixing the name is not the fix - the next rename reproduces it.

**What to do instead, in this order:**
1. Call the gateway's own catalog: `GET {SECRETARY_API_BASE}/v1/models` with the bearer key. It
 returns `{secretary_catalog_version, default_model, data:[{id, kind: route_alias|concrete_model, ...}]}`.
2. **Prefer `route_alias` ids.** They are slots the gateway fills with whatever model is currently
 best, so provider churn never reaches the app. Measured 2026-09-15: `secretary-auto` 200,
 `secretary-fast` 200, `secretary-smart` 200, `secretary-genius` **502 - do not use**.
 `deepseek/deepseek-v4-flash` (a *concrete* id) returned 500 while `secretary-auto` served
 `deepinfra/deepseek-ai/DeepSeek-V4-Flash-0731` on the same call.
3. Let the operator override per tier with an **env var holding a comma-separated chain**, so a
 model swap is an env edit + container restart, never a code change or redeploy.
4. **Validate every configured id against the catalog and DROP what is not listed** - record the
 drop. If the catalog is unreachable, accept the configured value but mark it `unvalidated`,
 never `known good`.
5. Cache the catalog (minutes), single-flight the fetch, and **fail soft**: a catalog outage must
 never break the user flow. But it must never fail SILENTLY - a total AI outage must be visible
 to the operator, because that is the failure that actually happened here.
6. Publish provenance: per tier, the effective chain and where each entry came from
 (`env:VAR` / `alias-default` / `catalog-validated` / `dropped-not-in-catalog`). An operator
 should never have to read code to learn which model served a request.

**Applies to:** personality-system, any app on `ai.abletelsolutions.com`, and the secretary's own
router. When you touch a model name in any of them, this rule governs.

**Evidence:** journal H301; `_scratch/gateway-models.sh` and `_scratch/gateway-alias-test.sh`.
