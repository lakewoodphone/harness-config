**L3417b · Owner-to-machine media: the proven route off an iPhone is email, and the far end now works**

**L (2026-10-10, SECRATARY)** — Asked "how do I download these audio files from my iPhone", the honest answer is the one path whose far end I have actually run, not a menu of iPhone tap routes.

VERIFIED, not assumed:
- The shared Google token (`app/services/google_oauth_scopes.py`, GOOGLE_SHARED_SCOPES) carries `gmail.readonly` + `gmail.modify` + `drive.readonly`, and `data/gmail_tokens/eliyahuzabrowsky_at_gmail_com_token.json` authenticates. Run of 2026-10-10: `users().messages().list(q="has:attachment newer_than:60d")` then `messages().attachments().get(...)` returned real bytes (e.g. IMG_6408.jpeg, 4,666,010 bytes) — so **the owner mailing a file to himself is sufficient; no new infrastructure is needed to receive it.**
- Transcription of whatever lands is already solved: `app/services/transcription.py :: transcribe_with_whisper(audio_path, settings=...)` takes mp3/wav/m4a (~0.006/min), and is the same call the voicemail path uses.
- Inbound MMS media is persisted for *any* content type (`app/services/sms_media.py :: persist_inbound_mms`, `_safe_ext`), so audio texted to the Twilio line *would* be kept — but carrier acceptance of .m4a over MMS is unverified. Do not recommend it as the first route.
- There is **no** libimobiledevice/ifuse/adb on secratary and no cron/timer that syncs an iPhone, so "plug it into the server" is not a route here.

TOOL: `/home/zabz/bin/owner-media-pull.py` (list mode tested 2026-10-10 against a 30-day window) — lists media attachments across the connected owner mailboxes, downloads them to `/home/zabz/evidence/owner-media-<utc-stamp>/` keeping the original filename and recording bytes + sha256, then transcribes the audio to a sidecar `.txt`. `--list` writes nothing. Provenance is the point: a transcript is never detached from the file it came from.

THE OWNER'S SIDE, which is the only part I cannot do for him: in Messages, long-press the audio attachment → Save to Files (or preview → share icon), then either attach the files in the DSH chat (he is on the phone: workspace `/home/zabz/phone` is the phone desk) or mail them to himself from Files (multi-select → Share → Mail). The 2026-10-05 `~/evidence/shlock-sukkos-debrief-2026-10-05/` folder shows the same shape of job previously completed — six voice memos plus one .MOV, transcribed to `transcripts.md`.
