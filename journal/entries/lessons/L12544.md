### Why the tool answered UNRECORDED — two defects, both now fixed

1. **`lookup()` required an exact form string.** The register names the obligation `NJ-927 + WR-30`; a query for `NJ-927` matched nothing and returned UNRECORDED *even against a correct file*. The tool was unanswerable for the one form an operator names by its first half.
2. **It read the WORKING-TREE copy, and the authority checkout is not on master.** `/opt/company` sits on `keepalive/323-pickup-live-restore-20261021` with **287 dirty files**, and its `scripts/tax/filing-register.json` is a *different version* that **also declares `updated: 2026-10-21`** and contains **no NJ-927 entry at all**. origin/master carries the record (`filed_on 2026-08-13`, amount 370.02, added in commit `0d5719881`).

Fixed in `/opt/company` commit **43a94ab02**: `_same_form()` matches token-wise so a combined return answers to either half (the period is still exact); every `--status` prints provenance (path, mtime, branch@HEAD, differs-from-origin/master); and when the checkout has no record but origin/master does, the answer comes **from master** with an explicit note that the checkout needs reconciling, because a branch-local absence is not evidence of a missing filing.

Verified after the fix: `--status "NJ-927" 2026-06-30` → FILED 2026-08-13 answered from origin/master; `--status "NJ 941" 2026-09-30` → UNRECORDED with provenance; `--status "NJ ST-50" 2026-09-30` → FILED FR1101374370 unchanged; `--check` 10 entries, 0 problems.

### The transferable lessons

- **A file that says `updated: <today>` is not evidence that it is current.** Ask which FILE and which COMMIT answered, every time. I wrote this same lesson earlier today (L12478) about document existence and then walked straight into the identical trap on the register, because I used the tool instead of reading origin/master.
- **Two checkouts of one repo both claiming today's date is the "one source of truth per thing" rule failing in silence.** The authority's 287-file divergence is an open estate problem, not just a tax problem.
- **When a tool returns a negative, ask what it READ.** UNRECORDED, "no filing record", "not found" are all claims about a specific artifact; if the artifact is not named, the claim is unfalsifiable and will be repeated to the owner as fact.
