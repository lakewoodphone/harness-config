**L3419b · Moving a file onto a Windows node: pull with scp from the node, do not push a PowerShell here-string over ssh stdin**

**L (2026-10-11)** — Measured while filing the uncle correspondence onto ZABZ-YOGA.

DOES NOT WORK: `{ echo "\$b64=@'"; base64 -w76 file; echo "'@"; echo "[IO.File]::WriteAllBytes('C:\\path',...)" } | ssh user@win powershell -NoProfile -Command -`. The command returns 0, prints nothing, and writes nothing - including its own `"wrote"` marker line, so there is no error to see. Repeating it with `2>&1` still prints nothing. Three separate attempts "succeeded" this way before a listing proved the directory was still empty. **A zero exit status from ssh is not evidence that PowerShell ran.**

WORKS, both directions, and should be the default:
- READ: `ssh user@win powershell -NoProfile -Command -` with the script on stdin, printing `[Convert]::ToBase64String([IO.File]::ReadAllBytes($p))`, then `base64 -d` locally. Byte-exact; used for a 188 KB zstd session log and an 8.6 KB UTF-8 README.
- WRITE: from the Windows node, `scp user@<linux-host>:<remote path> "<C:\local path>"` - the Windows node already holds a key for the Linux host (verified: `ssh zabz@secratary-ts hostname` -> `secratary`). Wildcards in the remote path are expanded remotely.

Also measured: `ssh ... powershell -NoProfile -Command "Get-ChildItem \"quoted path\""` mangles quoting; feed the script on stdin in single quotes and put every Windows path in PowerShell single quotes inside it. Verify with `Get-FileHash -Algorithm SHA256` on the far side and compare to `sha256sum` locally - do not assume a quiet scp copied what you meant.
