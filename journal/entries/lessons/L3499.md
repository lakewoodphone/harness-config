**L3499 · Raw python -m lpt.cli on Windows aborts the deploy on the first phase checkmark (cp1252) unless PYTHONUTF8 is set**

Trap found 2026-10-11 while staging filter-only-no-text on E4810 serial 558800800678.

Running the CLI raw - python -m lpt.cli deploy ... from cli\ - crashes inside the rich Progress callback on the first phase line:
 UnicodeEncodeError: 'charmap' codec can't encode character '\u2713' (the checkmark)
because the console falls back to cp1252 when stdout is redirected. The exception is raised inside on_phase_complete, so it aborts deploy_with_callback after the FIRST phase and the run dies with exit 1.

Observed cost: the first attempt installed nothing and wrote NO receipt (checked: pm list packages | grep com.android.cts empty, adb_enabled still 1, no new yaml in cli\logs\deployments). It is not obvious from the traceback that nothing happened, so the phone looked possibly half-staged.

Fix, either one:
 - set $env:PYTHONUTF8='1'; ='utf-8' before the raw CLI call (this is exactly what scripts\Invoke-LptCli.ps1 does in Set-LptCliOutputDefaults, so the PowerShell wrappers are immune), or
 - always drive the CLI through scripts\deployment\*.ps1 wrappers.

Second run with the env vars staged all 10 phases, 13 verify checks, and wrote deployment-receipt-558800800678-20261011-193742.yaml.
