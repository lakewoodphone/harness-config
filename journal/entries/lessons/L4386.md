## Two readings that looked fine and were wrong — both because the INSTRUMENT was wrong, not the data

Both measured 2026-10-14/15 while integrating other agents' branches. Same shape, cheap to
avoid, and each one nearly produced a false claim in a report.

### 1. `git cat-file -p <ref>:path | Out-String` cannot tell you a file's line endings

I measured `CRLF=323, LF=323` on two versions of a markdown file and concluded they matched.
They did not: one was CRLF and the other was LF-only. **PowerShell's pipeline normalizes line
endings as it decodes**, so the count of CRs it reports is a property of PowerShell, not of the
blob. The wrong reading would have had me write "the diff is just a display artifact" about a
323-line whole-file rewrite that hid a real change.

**The instrument that works** — write the blob to a file with `cmd`-style redirection (no
pipeline decoding), then count the bytes:

```powershell
git cat-file blob <sha> > "$env:TEMP\x"
$b = [System.IO.File]::ReadAllBytes("$env:TEMP\x")
($b | Where-Object { $_ -eq 13 }).Count # CRs, truthfully
```
Result: `37125 bytes / CR=323` vs `37025 bytes / CR=0`. The file with no CRs had been rewritten
by a script, and its 323-line diff contained exactly one real change.

**Also worth carrying:** several of this estate's files are CRLF. A tool that writes text
(PowerShell `Set-Content`, a naive `writeFileSync`) silently converts. **If you edit a file with
a script, check its line endings before and after** — the change you made will be invisible in
review otherwise, and a reviewer who cannot see the change cannot reject it.

### 2. A loop's boolean disagreed with a direct check — and the loop was wrong

A polling loop reported `carries-my-string=no` for thirteen consecutive iterations while reading
a served JavaScript bundle; a direct, repeated check on the same URL found the string three
times (`IndexOf` = 3391655, `-like` = True, with the byte length and `Content-Type` printed
alongside). The loop's verdict was never explained, which is exactly why it cannot be reported.

**What to do:** state the reading, the URL, the byte length and the type of the object you took
the reading from. A boolean with no instrument behind it is not evidence — and when two of your
own instruments disagree, **say so and rerun**, rather than picking the one that suits the
conclusion. A number you cannot attribute is worth less than "not measured".
