**L1588 · A health check that writes is not a health check - and a probe that can fail must not be able to kill the process**

MEASURED 2026-09-15 (secratary). W1 added a database WRITE probe to /health. Under production config the app then entered a restart loop: 16 API starts in 30 minutes, systemd 'restart counter is at 6', and the journal showed Health DB write probe failed (transient): OperationalError: database is locked immediately before each restart. The watchdog was innocent -- 0 watchdog restarts, and its own log showed the guards I added correctly deciding NOT to act ('service is still starting; not restarting').

Reverted from a backup taken before the merge. Verified by observation, not assumption: 90 seconds after the revert, **0 starts, 0 process exits, 0 probe warnings, 0 lock errors**.

RULES.
1. A health endpoint must be READ-ONLY and cheap. Its job is to answer 'are you there', not to prove the write path works by writing. On a 4.48 GB SQLite store under contention, a write probe is a load generator attached to the thing that is supposed to detect load.
2. If a health probe can fail, the failure must not be able to terminate the process or trip a restart policy. A check that can kill the service is a single point of self-inflicted failure -- and this system already lost a day to a watchdog that restarted a service it found mid-startup.
3. When a change causes a production regression you cannot fully diagnose, REVERT to the known-good state and re-land deliberately. 'A branch that breaks main is reverted, not repaired forward.'

SECOND FINDING, and it invalidates a class of evidence: **every fleet worktree lacked .env** (gitignored, never copied in). So all green test output from this fleet was measured under DEFAULTS, not production configuration. W1 is the proof it matters: 30 passed in 25.86s in a worktree, and the process DYING after 4 of 30 cases on live (exit=15, not a timeout). Per-test bisect: the 3 unit-level probe tests pass; every test that calls the real /health endpoint times out at 60 s. Verify tests in an environment that matches production, or say plainly that you did not.
