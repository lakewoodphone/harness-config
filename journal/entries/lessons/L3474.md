**L3474 · Correction: H3467 supersedes H3464 (not 'H3465') - and three failures in one evening of the form 'what I wrote is not what is true'**

**Correction, same evening.** Two references I wrote are wrong, and a future
session following them would land on the wrong thing. Recorded rather than
edited, per the append-only rule.

## 1. H3467's body cites the wrong supersession

H3467 opens with *"Handoff, supersedes H3464."* That part is right. But it also
says the redeploy replaces the state described in **H3464**, and the state I
actually superseded was that of **H3464** *and* the resolution note I then wrote
on it, which pointed forward to **"H3465"** — an id that does not exist for this
purpose. The entry that supersedes H3464 is **H3467**.

Correct chain:

```
H3463 (superseded) - the timed deploy it described had already completed
H3464 (superseded) - claimed a deploy queued 20:05; ships a stale file
H3467 (current) - 20:05 shipped a STALE home_assistant.py; redeploy Sat 20:10
```

## 2. A note about this incident's own shape

I made this mistake *while writing the record of* two other mistakes of the same
family (a stale stashed deploy script, and a same-day target that should have
been tomorrow). Three separate failures in one evening, all of the form **"the
thing I wrote down was not the thing that was true"**:

- the deploy script on the server was not the version I had edited;
- the staged `home_assistant.py` was not the version I had fixed;
- the entry id I cited was not the entry I meant.

The common remedy is the same and it is cheap: **after writing or copying
anything, read back what landed.** For a file, compare a hash. For a journal
reference, confirm the id exists and says what you think. For a scheduled unit,
read its own log line, which states its target. Each of the three was caught in
under a minute that way, and none of them by reasoning.

Note also which mechanism actually caught the most dangerous one: the
mis-scheduled redeploy was caught because **its wait loop logged its target
every minute** — the loop was written to make its reasoning visible, not to be
pretty, and that is the only reason a shutdown 9 minutes into Shabbos did not
happen.
