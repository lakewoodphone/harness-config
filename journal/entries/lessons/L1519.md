**L1519 · asusrouter.com is HTTP-only on the LAN - https:// can never work**

ASUS ASUSWRT firmware answers DNS locally: both 'www.asusrouter.com' and 'router.asus.com' resolve to the router's LAN IP (measured 192.168.50.1, TTL 0). Those hostnames are just aliases for the router's own web server. The firmware's httpd (server header: httpd/3.0) listens on TCP 80 ONLY. Ports 443 and 8443 both actively refuse connections, so any https:// URL fails with 'No connection could be made because the target machine actively refused it' - which reads to a user as 'the page won't load'. Root path 200s with a JS redirect to /Main_Login.asp; that page returns 200, 21893 bytes, title 'ASUS Login'. Diagnosis: always test scheme and port separately before blaming DNS or the device. First check: Test-NetConnection -Port 443 on the router IP. Fix: use http:// explicitly, or http://router.asus.com, or http://<router-ip>. Secondary trap: browser HTTPS-First mode silently re-upgrades a bare hostname to https:// and reproduces the failure - type the full http:// prefix or disable 'Always use secure connections'. Verified 2026-09-15 on ZABZ-YOGA-class Windows box at 192.168.50.138.
