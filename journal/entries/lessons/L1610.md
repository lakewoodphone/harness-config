**L1610 · An adversarial verifier agent refuted six of my own claims, two of which would have caused wasted work**

## An adversarial verifier agent is what caught *my* wrong claims, including two I would have acted on

**What was run.** Six read-only audits partitioned by file scope, plus a seventh subagent whose brief
was solely to **disprove** the other six's claims — for each claim, design the strongest falsifying
test, run it, report the raw output, and mark CONFIRMED / REFUTED / UNVERIFIABLE. It was told
explicitly not to be agreeable.

**What it caught, which mattered.** It refuted six claims that would each have sent work in the wrong
direction:
- "There are no backups for this database" → **20 restic snapshots to R2, nightly, `restic check`
 clean.** Acting on this would have meant building a backup system that already existed.
- "The container runs as root" → **`USER nextjs`, uid 1001.**
- "`/api/search?gematria=26` wrongly returns 0" → **0 is correct**; the minimum gematria of any pasuk
 in the Torah is 229. The endpoint was right and I was wrong.
- "`eraLabel` is empty for every method" → withdrawn; C and D return a non-empty label for all 6,000
 years. The real defect was narrower and different (two sources of truth, no `c:`-keyed rows).
- "There is no index on `pesukim`" → there is; `EXPLAIN` shows `Index Scan using pesukim_pkey`. The
 accurate claim is "no index can filter by gematria", which changes the fix.
- "Three of eleven gematria systems are duplicates" → it is **four, in two pairs**, and two of them
 were swapped relative to their published definitions rather than merely duplicated.

It also disproved **its own** two hypotheses and recorded them, so nobody re-tests them: `era_events`
is not duplicated (21 distinct tuples), and its first pasuk-search timing of 0.29 s was cold-start
noise (clean p50 = 0.078 s).

**The rule.** An audit's findings are claims, not evidence. **Run one agent whose only job is to
falsify the others, and make it publish a corrigenda list.** The measured failure mode in this system
is confident wrongness, not laziness — and the cheapest cure found so far is a dedicated
disprover that is rewarded for refuting rather than confirming. It cost one subagent and removed six
wrong premises, two of which would have caused wasted or harmful work.

**Mechanic that made it work:** every claim was written down as a numbered, falsifiable statement
(C1..C9) with a named test, so the verifier had something concrete to attack. Claims phrased as
impressions ("the UX is bad") cannot be refuted and therefore cannot be trusted.
