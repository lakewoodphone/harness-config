**L3690 · lpt sql from PowerShell splits on escaped quotes - express camelCase columns through to_jsonb() instead**

Measured 2026-10-12 on ZABZ-TECH, three failed queries before the shape was found.

`lpt sql --store operational "select id, \"orderNumber\" from orders ..."` fails with
`lpt: error: unrecognized arguments: orderNumber\, ...`. PowerShell does not honour the backslash
escape: it splits the statement at the spaces around the escaped quotes and hands the native command
several arguments, so the SQL arrives truncated.

Two ways out, the second better:

1. `lpt --% sql --store operational "..."` — the stop-parsing token passes the rest of the line
 through literally.
2. **Avoid the double quotes entirely.** `to_jsonb(orders)->>'orderNumber'` reads the same camelCase
 column and needs none. This also dodges the recorded trap where `"createdAt"` becomes `createdat`
 (`column "createdat" does not exist`). Single-quoted literals are safe, so
 `where to_jsonb(orders)->>'customerId' = '925'` works.

Same rule for any native command given a long argument with embedded quotes from PowerShell: prefer a
shape with no quotes to escape, or write it to a file first.
