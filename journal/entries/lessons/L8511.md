**L8511 · The query defines the universe: in:inbox hid 385 messages a week and no health line could report it**

**L · The query defines the universe: `in:inbox` hid 385 messages a week and nothing reported it as missing.**

The owner-queue email judge read `in:inbox newer_than:Nd`. Measured 2026-10-18 over one week, same
four accounts: **223 messages in the inbox, 385 outside it** -- 99 on his personal account, 178 on the
shop account. Gmail filters auto-archive receipts, invoices and notifications before he ever sees
them. On the first run with `newer_than:Nd -in:spam -in:trash`, a supplier's return-instructions
request appeared that the queue had never held.

Nothing was broken. Every health line was green, every verdict was cached and correct, the timer ran
every 20 minutes. The queue was answering a question about a systematically smaller world than the
one the owner lives in, and a reader cannot notice a population it never asked for.

**The rule:** for any reader that claims to watch a channel, write down the query and measure the
population it EXCLUDES -- in the same units -- before trusting its coverage. `-in:inbox` is not a
relevance filter, it is a folder boundary, and relevance is the reader's job. The same day, the
`health` command gained a `read everything` line per source carrying `fetched / dropped / written /
folded / errors`, so "18 arrived" can no longer be compatible with "62 never read".
