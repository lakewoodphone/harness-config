**L1604 · A DSH window opened at the clean origin 401s on any profile whose cookie was never seeded; open the tokenized URL**

WHAT: `dsh web` browser auth (`dsh-client-connection/lib/browser-auth.js`) accepts only
`GET /?token=<launchToken>` and mints an authority-bound cookie (`host:port`, 30 days, HttpOnly,
SameSite=Strict). Any other request without that cookie gets a bare 401 whose body is
"dsh web authentication required; reopen the URL printed by dsh web."

THE TRAP: the cookie is the ONLY thing that makes a clean-origin window work, and nothing in
`dshw.ps1` ever seeded it. `Open-SlotWindow` opened `--app=http://127.0.0.1:<port>/` and worked only
because profiles created before 2026-09-14 had a cookie as a side effect of the older launcher, which
still used the tokenized URL. A profile created after that (`w9`, then `w10`) 401s forever.

WHAT IS NOT TRUE -- checked on 2026-09-15, because the code comment said otherwise:
- The token is NOT a one-time exchange. `processLaunchToken` caches one random 32-byte value in a
 WeakMap on the process owner; it can be exchanged repeatedly.
- The 303 to `/` does NOT lose the window's session. The client boot path reads `location.search` only
 for `?fixture=` test hooks; session identity is `localStorage["dsh.sessions.current"]`, keyed by
 origin. A throwaway profile launched twice at the tokenized URL kept ONE window root and the SAME
 session id (`session-ea10e311-...`) both times.

FIX: prefer the tokenized URL (`Test-LaunchUrl` / `Resolve-WindowUrl` in
`harness-config/multi-window/dshw.ps1`), and recover a fresh token from the engine's own
`dsh web: <url>` log line when `state.json` is stale, because the token changes on every restart. A
stale token still degrades safely: the server 303s an already-cookied browser to `/`.

SEE IT WITHOUT BREAKING ANYTHING: `dshw doctor` prints the URL a new window would use and proves the
token with a live 303 probe; and a window showing the 401 page is literally titled
"dsh web authentication required - DeepSeek Harness", so a window-title enumeration identifies the
broken window without opening anything.
