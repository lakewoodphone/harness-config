**L3619 · On this estate the DEPLOYED script can be newer than the committed one, so a fix applied only to /opt is a fix scheduled to be reverted**

Measured 2026-10-12 on secratary-cloud. /opt/company/archive/tools/transcript-archive-run.sh (176 lines) is a SUPERSET of the repo copy at /root/code/harness-config/scripts/transcript-archive-run.sh (146 lines): the deployed file has the 'PULL FAILED is also an ALARM' branch and the 'CHECK FAILED' branch, and the JOURNAL variable, none of which exist in git. Those branches were evolved on the host and never committed. .source in that directory records only 'harness-config commit ee3a7e2f01b7b9e2c259a052d2cc93992f62830a', which does not describe the file actually running. Consequence: an agent that 'syncs the repo copy down' silently DOWNGRADES the authority - which is exactly what happened to the previous agent on this workstream before it restored its backup. Rule for next time: diff the deployed file against the repo BEFORE copying, and when they differ, decide which is the newer INTENT rather than which is newer by timestamp. Protection applied: the repo copy was overwritten FROM the deployed, working artifact and committed, so the direction is now repo := proven-deployed.
