**L3721 · Sanity-test a certifier endpoint before it goes into a fleet brief - a 200 with no rows is a silent false negative**

COST: five mesh research children were briefed with a certifier endpoint I never ran: OK Kosher's product search as `https://www.ok.org/product-search/?s=TERM`. That URL returns **HTTP 200 with a page containing no results** - a silent false negative. Result: two children independently concluded "OK Kosher cannot be queried from this host" and filed real OK-certified products as UNVERIFIED.

EVIDENCE (2026-10-12): `?term=philadelphia cream cheese` returns 9 Kraft Heinz rows (status Dairy); `?s=philadelphia` returns 200 with nothing. `?term=tropicana` returns 169 Pareve rows. `?term=mazor` returns 13 - the house's own pizza dough, all Pareve|Yoshon.

THE RULE: before an endpoint goes into a brief that other agents will obey, run it yourself with a term you KNOW exists, and read the response body, not just the status code. A 200 is not an answer. Corollary discovered the same day: a raw match COUNT is not a row - the OK reported "2 matches" for `pringles`, and both rows were a Kellanova "Incogmeato Chik'n Fries Pringles Original" product, not the crisps. Print the rows, not the count.

WHY IT MATTERS TWICE OVER: background mesh children are **jobs, not continuable agents** - `send_message` to a `subagent` job id returns "unavailable", so a wrong brief cannot be corrected mid-flight and must be caught at integration. Every negative in the fleet's output had to be re-run by hand. Budget for that.

SECONDARY LESSON (same session): the OK's real search page is `ok.org/product-search/` (a form). `ok.org/kosher-products/` is a WordPress 404 that answers HTTP 200. Star-K's `/search?q=` is a Google Custom Search of site CONTENT, not a certification lookup; its product listings are `star-k.org/listings/product` and `/listings/star-k`. The OU has a keyless JSON API (`productsearch-v2.oukosher.org/api/v1/product?...`) found by sniffing its own search page, and a SEPARATE yoshon database (`e9rhv1gurf.execute-api.us-east-1.amazonaws.com/prod/products?tag=all&filter=TERM`).
