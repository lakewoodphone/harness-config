**L3825 · A device is a control only when it differs in one variable**

**L · A device is a control only when it differs in one variable — my "existing proof" differed in forty-three**

WHAT HAPPENED, 2026-10-14, the same session, twice in ninety minutes. Asked to work out why voice input is off on
the Waze kiosk, I found that three other postures in the same estate (shop-store, shop-counter, family-filtered)
have `allowDictation=true` while the kiosk has it false, and wrote in the dossier that this was "the strongest
safety evidence available" and that the shop phones were an existing proof on our own hardware.

Then I diffed the profiles key by key instead of assuming:

- kiosk vs `shop-store`: **43 differing restriction keys**
- kiosk vs `family-filtered`: **35**
- kiosk vs `shop-counter`: **35**

Every one of them also sets `allowSafari=true`, `allowCamera=true`, `allowAirDrop=true`, `allowChat=true`,
`allowAccountModification=true`, `allowPasscodeModification=true`, `allowScreenShot=true`, allows 10-20 apps and
blocks **no** bundles — where the kiosk allows one app (`com.waze.iphone`) and blocks 133. They are ordinary phone
postures, not filtered ones. "Dictation is on where Safari is also on" says nothing about dictation on a device with
no browser.

The claim was corrected in the same commit that made it questionable, in four places, with the numbers, rather than
quietly dropped — `04` §6b, `06` §2 D, `05` step zero and the README.

RULES:
1. **Before calling something a control, diff it.** "Same fleet, same generator, different switch" is a hypothesis
 about a control until the diff shows it. Here the obvious control was useless and would have been quoted to the
 owner as evidence.
2. **Resemblance is not equivalence.** Two profiles generated by the same function with the same identifier shape
 can still differ in forty-three ways.
3. **A cheap and genuine use survives even a broken control**: the shop phone still answers "does
 `allowDictation=true` put a microphone key on this iOS version and this hardware", because that key depends on
 `allowDictation` and the Settings toggle, not on the app allowlist. State the narrow claim the control supports
 instead of discarding it and instead of overclaiming it.
4. The safety argument has to rest on the mechanism (on-device dictation, a filter that fails closed, a single
 permitted text destination), not on "we already do it elsewhere".

EVIDENCE: `deploy/waze-mdm/docs/voice-input/04-filter-safety-and-options.md` §6b and `06` §2 D (master
`d0d8da984`); the diff was run against `/opt/waze-mdm/profiles/{waze-layered-kiosk,shop-store,shop-counter,family-filtered}.mobileconfig`
on `waze-mdm-01`, 2026-10-14.
