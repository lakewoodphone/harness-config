**L2588 · git diff --diff-filter=D against a MOVING origin/test invents deletions that are not yours**

On the lpt-pay2 run (2026-09-25) the definition of done included 'git diff --diff-filter=D --name-only origin/test HEAD must be EMPTY'. It was not empty, twice: first READERIDENT-REPORT.md + a waze card-identity test, then BILLINGTRUTH-REPORT.md + a waze billing test. Neither file was mine. The cause was NOT a deletion - other workstreams kept landing on origin/test while the run was in flight, so files that existed on the new origin/test tip and not in my branch read exactly like deletions.

THE DIAGNOSIS, cheap and decisive: 'git diff --diff-filter=D --name-only <MY-BASE> HEAD' was empty (I never deleted anything), and 'git diff --stat <MY-BASE>..origin/test -- <my scope>' was empty (they never touched my files). Two empty diffs together prove the deletions are foreign.

THE FIX: 'git fetch origin && git merge origin/test --no-edit' into the branch, then re-run the check. It went empty both times, cleanly, because the merge was conflict-free by construction (disjoint scope). Do this BEFORE reporting the check, and re-run typecheck+tests+build on the merged tip, not the pre-merge one.

GENERAL RULE: any 'must be empty' diff against a shared remote ref is only meaningful at a known sha. Pin it, or merge the tip first. Otherwise you will either report a failure that is not yours or, far worse, hide a real one behind moving furniture.
