**L1503 · An agent's first call is the only one you get: a tool that errors on a guessed parameter is dead**

MEASURED 2026-09-15, ZABZ-YOGA + secratary. `comms_search` was registered (registry entry
518, `hit_count` 25) and the fleet had been told, in its own description text, to use it
before answering anything about a customer -- and every one of the 34 POSTs to
`/tools/run/comms_search` in the API log was mine, from verification, with zero
independent agent calls in the 11 hours after the goal closed. The tool was not
unpopular. It was unreachable by an agent that had not read its source.

Three ways the first call dies, all of them mine to have prevented:

1. The arg name. An agent calls it `query=`, because that is what every other search
 tool calls it. `run()` took `q`, the unknown key was dropped by inspect.signature
 filtering, the search ran on the empty string, and FTS5 returned
 `syntax error near ""` -- which reads as "this tool is broken". An unknown *mode*
 silently fell through to a default search instead of naming the valid modes.
2. Punctuation. `screen replacement?` -> `syntax error near "?"`.
3. A whole sentence, which is what a model actually writes.

THE RULE, and it is general to every dynamic tool in this company: the caller is an LLM
that knows what the tool does and not what its parameters are called. So --
accept the aliases; take `**kwargs` so a stray key is never a TypeError; name the valid
options when an enum is wrong; tokenise and quote anything that will reach a query
parser; and when nothing can be found, return guidance rather than a parser error.

TWO MEASUREMENT RULES THAT COST ME TIME TODAY:
* HTTP 200 is not success. `{"ok": false, ...}` rides inside a 200 response, so
 `journalctl | grep comms_search` showing 34x "200 OK" is not evidence that the tool
 ever worked. A dynamic tool's outcome has to be read from its body (`error_count` in
 the registry, or the `ok` field), never from the status line.
* `app/main.py:17084` kept only string-valued params (`if isinstance(v, str)`), so an
 agent sending `{"limit": 3}` had it discarded before the tool ran, and received 20
 results with no way to tell whether the tool ignored the parameter or never received
 it. Silently dropping an argument is indistinguishable from not honouring it. Fixed
 both lineages: 8d4968d21 (origin/master) and d8603d17 (the authority's checkout).

EVIDENCE: scripts/comms-verify.py (13 assertions through the live HTTP dispatcher and
the CLI) -- all 13 pass; the same file existed as a battery of FAILs before the fix.
