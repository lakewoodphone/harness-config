**L1716 · A trivial pwsh tool call costs 540-700 ms and 78% of it is PowerShell's own startup - the fix is using read/grep instead, not tuning the runner**

## What a tool call actually costs (ZABZ-YOGA, 2026-09-16, n=30 interleaved, ms)
| Component | min | p50 |
|---|---|---|
| kernel process creation floor (`cmd.exe`) | 32.8 | 35.9 |
| `runner.js` spawn — the Job owner, pure overhead | 120.3 | 136.3 |
| `node -e` (warm compile cache) | 69.8 | 76.6 |
| `pwsh -NoLogo -NoProfile -NonInteractive -Command "<ENC>; exit 0"` | 405.0 | 548.0 |
| **trivial `pwsh` tool call, total** | **~540** | **~700** |

Split: **pwsh start-up 78 %, the Job-owner runner 19 %, everything else <3 %.** The kernel spawn
is 6-7 ms and there is no sandbox cost at `danger-full-access`. My own n=20 pass on the bench
harness reproduced the shape independently (pwsh enc exit p50 292 ms, runner idle 110 ms,
`node -e` 70 ms, `cmd` 32 ms) — run-to-run spread on this host is large, so min and p10 matter
more than p50.

Two consequences that reframe the problem:
1. **The overhead is the shell, not the machinery around it.** No amount of tuning the runner or
 the spawn recovers the 78 %.
2. **`POWERSHELL_TELEMETRY_OPTOUT` / `POWERSHELL_UPDATECHECK` cannot be set.** `ENV_OVERRIDES`
 in `dsh-pwsh-local\lib\index.js:145-149` is a hardcoded constant (`NO_COLOR`, `PAGER`,
 `GIT_PAGER`) and the Config schema exposes only `cwd`, `timeoutMs`, `maxTimeoutMs`,
 `maxOutputBytes`, `maxSpillBytes`, `graceMs`, `pwshPath` (`:199-207`) — none of which touches
 start-up. Setting it would mean editing the installed package, which the next npm update
 erases and which does not sync to the other machine. Not done.

## The real lever, and it is not code
`read` p50 **0.76 ms** and `stat` **0.11 ms** — in-process — against **~700 ms** for the same
bytes through `pwsh`. That is a ~700x difference, available today, with no capability change:
same information, different tool. And because **every shipped tool is declared exclusive** (no
tool declares `isConcurrencySafe`, `dsh-tools\lib\index.js:2951-2959`), parallel calls in one
step run *in series* — N shell calls cost N x ~700 ms, while N `read`s cost about a millisecond.

Adopted as a standing rule in the preset's Technical discipline block (source of truth:
`scripts/make_zabz_preset.py`, so it survives regeneration): `pwsh` is for what only a shell can
do — running a program, git, a package manager, inspecting processes; `read`/`grep`/`glob`/`edit`
are for bytes; batch shell work into one call; `run_in_background` for anything slow. Verified
after regeneration: `--check` reports in-sync and a line diff against the previous preset shows
**0 lines removed**.
