**L3733 · A relative asset path is a deployment bug waiting for the second machine**

## Path(__file__).parent.parent / 'assets' works only from a checkout

phone-gate.py resolved its phone-layer CSS as <script dir>/../assets. Run from the repo that is
<repo>/assets. Deployed as /usr/local/bin/phone-gate.py it is /usr/local/assets - a directory the
install step must create. The office box had it; the cloud box did not, so the gate concatenated
zero files and served /dsh-phone-mobile.css as 0 bytes.

The cost was invisible in every server reading: the gate answered 200 with
'phone layer stylesheet: 64 bytes', the engine was healthy, the API worked. A phone got an
unstyled shell. Only a browser at 393x852 showed it.

RULE: for anything that ships to more than one layout, SEARCH for the file (beside the checkout,
beside the deployed script, under /usr/local) and fail loudly when none exists - do not compute one
path. Log the SIZE of what you serve, not the fact that you served it: '64 bytes' was the tell.

Corollary: the deployed tree and the repo are two different files. Editing the repo copy on a
running box changes nothing. install-from-repo.sh is the deploy step.
