**L1808 · dshw.ps1 redefines Add-Content, and a called script inherits that**

`multi-window/dshw.ps1` defines its own function named `Add-Content` (a wrapper around its
per-slot log writer). PowerShell resolves functions through the CALLER's scope chain, so
phone-gate-ensure.ps1 -- which is invoked from `dshw ensure` every minute -- had its bare
`Add-Content -Path` bind to that function and die with "A parameter cannot be found that
matches parameter name 'Path'". The gate self-healed and the status JSON was still written, so
the only symptom was a red line and a LOST log entry.
RULE: any script that may be called from dshw.ps1 must qualify cmdlets it shares a name with --
`Microsoft.PowerShell.Management\Add-Content`.
