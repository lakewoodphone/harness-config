**L1829 · $pid is read-only; and do not call a process 'leaked' until you have checked whether the run that owns it has finished**

MEASURED 2026-09-16, end of a long working session on scripts/mesh-e2e.ps1.

1. `$pid` IS READ-ONLY. `foreach($pid in @(1,2,3))` fails with "Cannot overwrite variable PID
 because it is read-only or constant" - the loop body never runs, so a cleanup that "killed six
 processes" killed zero and printed nothing alarming if the error is non-terminating. Same family
 as `$args`, `$input`, `$host`, `$error`, `$matches`, `$true/$false/$null`. Use `$procId`.
 I wrote this bug in the same session in which I recorded a lesson about `$body`/`-Body`: the
 lesson was known and did not prevent it. Knowing a trap is not the same as avoiding it; only a
 habit is (grep your own edits for `$` + an automatic name before running them).

2. "THE HARNESS PRINTED A CLEANUP LINE" IS NOT EVIDENCE THAT NOTHING LEAKED. Enumerate the
 machine's own listeners and children after the run:
 Get-CimInstance Win32_Process -Filter "Name='node.exe' OR Name='ssh.exe'" | Where CommandLine -match 'mesh-'
 That is how five stub gates and an ssh tunnel of mine were found, still LISTENING minutes later.

3. BUT ATTRIBUTE BEFORE YOU KILL. My first cleanup killed six processes I had correctly identified
 as mine - and several belonged to a BACKGROUND RUN OF MY OWN SCRIPT THAT WAS STILL IN FLIGHT,
 whose gates were legitimately alive. I read "processes I started are still running" as "leaked"
 and did not check whether the run that owned them had finished. Half my diagnosis was wrong and
 I stated it as fact in the deliverable before checking. The fix that actually holds is structural,
 not a better story: register every mesh, and in a `finally` stop (a) the registry, (b) the tracked
 PID list, (c) the backstop - every process whose ParentProcessId is this script, which is by
 definition a process this script started and nothing else.

The general rule: for a cleanup that must not fail, do not rely on remembering to call it at the
right point in the control flow, and do not rely on a list you maintained by hand. Use parentage,
which is a fact about the system rather than a fact about your attention.
