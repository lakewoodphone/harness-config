**L1742 · A fix that exists only in the live install is not a fix: the phone question-card repair was never committed**

The owner, 2026-09-16: 'you were supposed to fix this... you fix the sum up but clearly not all the way.' He was right, and the defect was not the CSS.

WHAT WAS ACTUALLY WRONG. Two harness-config trees exist on secratary and they had drifted apart in both directions:
 /home/zabz/harness-config the LIVE install the services read (phone-gate reads assets/*.css per request; the client-plugin roster symlinks packages/*)
 /home/zabz/code/harness-config the git checkout that is supposed to be the source of truth
The 2026-09-14/15 question-card repair was made in the LIVE tree and never committed. The checkout's HEAD held the broken version:
 assets/question-card.css 5015 B (sheet anchored to the LAYOUT viewport) vs live 7382 B
 packages/plugin-mobile/lib/client.js 10141 B (no visualViewport repair) vs live 20173 B
 scripts/question-card-live-probe.py absent from the checkout entirely
So any sync from another machine would have pushed the older copy back onto the phone and re-broken a fixed bug. I copied live -> repo for the whole phone surface and committed (eb34bc8).

THE SECOND DEFECT, which is why he could still hit it after the fix shipped. The phone layer reaches a browser by REWRITING the document the gate serves. A tab that has ALREADY loaded is unreachable by that mechanism and never learns a fix exists. A phone tab lives for days. Measured 2026-09-16: scripts/question-card-live-probe.py against the running app shows the sheet pinned to the visible band with the question inside it (band 240-660 on 393x852, title y=279, Submit y=608, repaired=true) — the fix works on a cold load, and his phone still could not read a question. Fixed by giving the layer a token (assets/mobile.css) that plugin-mobile compares against the served copy every minute and on visibilitychange; it re-applies the newer bytes in place, and reloads only when no question card is mounted and nothing is focused or typed. Bump the token when the layer changes or the change reaches only new tabs.

GENERAL RULES.
- After changing anything under /home/zabz/harness-config, copy it into ~/code/harness-config and commit in the same session. Verify with on the surface you touched; a clean in the checkout does NOT mean the live tree matches it.
- Any client-side fix delivered by rewriting documents needs a self-delivery path for already-open tabs, or it is only a fix for people who reload.
- Verify against the RUNNING app (scripts/question-card-live-probe.py), not a replica; the replica cannot see the real ancestor chain.
