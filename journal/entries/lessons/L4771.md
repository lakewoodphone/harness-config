# L — A live artefact is not a branch: a concurrent session replaced a deployed fix with no merge conflict anywhere

**Rule.** `/opt/company` (aka `/root/personal-secretary-mvp`) and `/root/bin` are **live artefacts**,
not working copies. A session that edits them in place is racing every other session, and the loser
of the race is silently deleted — there is no conflict, no warning, and no diff, because the later
`write()` just wins.

**Measured 2026-10-15, on `/opt/company/scripts/owner_attention.py`.** This session deployed a
verified change to `sms_body()`/`send()` (one item instead of a count + list, no truncation marker,
a daily cap, a standing-rules gate), proved it with `send --dry-run` on the live queue, and moved on.
At **14:46:16Z** — about a minute later — another session wrote the whole file, restoring the
`'N items, M urgent` head and adding its own `_PERSONAL_MARK` / `PERSONAL_SMS_SLOTS` logic. The new
file is a **different size** from both the original and mine (30,237 B vs 25,253 B), so nothing was
merged: the whole file was replaced. `git status` on that tree showed 30+ modified files that were
not mine either.

**Why nothing caught it.** `/root/bin` is **not a git repository at all** (`git rev-parse` fails), so
half this estate's deployed code is invisible to every review, blame and merge tool the estate has.
`/opt/company` *is* a repo, but the writer wrote the working tree, not a branch, so the dirty-file
list simply grew.

**What preserved the work.** A pre-change backup (`/root/text-fix-20261015/backup/*.pre`) and a copy
of the concurrent session's version (`owner_attention.CONCURRENT-SESSION-14-46.py`). Both exist only
because the session took a backup *before* writing — the one habit that turns this from data loss
into a merge.

**Apply this.**
1. **Back up before you write**, to a directory named for the change, and say the revert command in
 the same breath. `cp -p <f> <f>.pre` costs nothing.
2. **Check the mtime before you write.** `ls -la --time-style=full-iso <f>` — a modification seconds
 old means someone else owns it right now.
3. **Put the change in the repo and let the deploy carry it** whenever the path is versioned; write
 `/root/bin` changes down somewhere durable because nothing else will.
4. **If two sessions want the same behaviour, merge the intent, not the file.** Here, both fixes were
 right: one wanted a single item, the other wanted his own mail to keep a slot. Overwriting threw
 away a real measurement (the 320-char digest carried four decisions and zero email items).
5. When you lose a file to another session, **record the collision** — journal `P13` is this defect
 in the repo, and it recurred here on a live script rather than a branch.
