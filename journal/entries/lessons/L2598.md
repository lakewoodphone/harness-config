**L2598 · A root-level splat hands a descendant Routes the FULL pathname - you cannot wrap an app router to intercept one path**

On 2026-09-25 the /contact public-route job had MVPRouter.tsx (the app's whole route table, ending in a catch-all Route path="*" -> Navigate to="/") forbidden, but still had to make /contact a real page. Two things were measured from the react-router 7.18.1 source (chunk-KS7C4IRE.mjs), not guessed:
1. matchPath sets pathnameBase = matchedPathname.slice(0, len - splatValue.length) for a splat, so a root-level splat route always has pathnameBase "/".
2. useRoutes then does: if (parentPathnameBase === "/") remainingPathname = pathname. A descendant Routes therefore receives the FULL pathname, not the remainder.
CONSEQUENCE: rendering an outer Routes whose "*" branch renders MVPRouter does NOT isolate anything - MVPRouter's own catch-all still matches /contact and still redirects to /. The working shape is sibling routes in ONE Routes: the /contact route beside a "*" route that renders MVPRouter. computeScore ranks a static segment far above a splat (12 vs -1), so /contact wins and MVPRouter never mounts; every other pathname matches only "*" and routing is unchanged. Verified live against the dev server: /contact renders the page, /definitely-not-a-real-page-xyz still lands on /.
