**L1853 · ProfileList cannot show a profile's content - put a version marker in PayloadDisplayName**

## Lesson — ProfileList cannot show a profile's content, so put a version marker in the display name

When a profile's *values* change but its identifiers and payload UUIDs stay the same — the normal way to update an existing profile in place — every remote read gives the same answer as before. `ProfileList` returns identifiers, payload types and UUIDs, never the restriction values, and an API `ok: true` only means "enqueued". On 2026-09-17 the Screen Time variant of the DRN kiosk profile deliberately kept identifier `com.abletel.waze.layeredkiosk.drn` and every payload UUID, so the only way to prove device 48 held the new bytes was to name it differently: top-level `PayloadDisplayName = "DRN Waze Layered Kiosk (Screen Time open)"`. That then showed up in the device's ProfileList (Acknowledged 2026-09-17 03:50:14Z).

Rule: every in-place profile change gets a visible marker (display-name suffix or a bumped PayloadUUID), and the deployment is not "done" until ProfileList shows that marker on the device.
