**L3788 · L — A Telnyx eSIM on iOS needs Data Roaming ON; bars without LTE/5G is the tell**

**The tell is the status bar, and the owner found it, not me.** An iPhone shows the data type
(`LTE` / `5G`) immediately right of the signal bars **only while a cellular data bearer is up**.
**Bars with no data type = registered for voice/SMS only, no PDP context.** That is the whole
diagnosis, and it is visible from a photograph of the screen.

**Cause class: a Telnyx IoT eSIM is a roaming attach in the US.** The SIM's home PLMN is Telnyx
itself (IMSI MCC/MNC `311210`), and it camps on T-Mobile (`310260`). iOS compares the two and
classifies the network as **not home** — so with **Data Roaming = Off** iOS never opens a data
bearer at all: full bars, no internet, and WiFi is the only thing that works. Telnyx says it in one
sentence, twice: *"Finally, enable data roaming on your device and you are good to go"* and
*"Registration succeeds but no data sessions → Fix: enable data roaming"*
(<https://support.telnyx.com/en/articles/3269600-how-to-set-up-a-telnyx-sim-card>,
<https://developers.telnyx.com/docs/iot-sim/connectivity-troubleshooting>).

**Measured, 2026-10-13, DRN 2002 / iPhone 11 / serial `FFXGT23HN72J`:** Telnyx reports the SIM
`enabled` ("Ready to connect to networks and consume data"), the account funded (balance 115.36), a
live data session on `310260` — and **0.812 MB consumed in this billing period, ~0.9 MB in the
SIM's whole 44-day life**. Cellular data has never actually carried payload on that line.

**Two corollaries worth keeping:**
1. **A healthy SIM is not a working data path.** Enabled + funded + registered + a session on the
 network side all coexisted with a phone that had no data. Never report "the SIM is fine" as
 "the device has data".
2. **`allowDataRoamingModification` is NOT an Apple key.** Our kiosk profiles set it `false`, which
 iOS ignores — verified against Apple's own machine-readable schema
 (`raw.githubusercontent.com/apple/device-management/release/mdm/profiles/com.apple.applicationaccess.yaml`,
 grepped case-insensitively for `roaming`: only `allowGlobalBackgroundFetchWhenRoaming` exists).
 It is the same class of invented key as L1873's `LocationServices` Settings item: a profile that
 *looks* like it locks a setting and locks nothing. **Check a key against Apple's schema before
 believing a profile enforces it.**
