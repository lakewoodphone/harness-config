**L3321 · The customer setup/login flow is a tracked _credentials-* file in lpt-hub - plus the closed status vocabulary and the .local-secrets trap**

**The customer setup/login flow, in full — there is only one, and it is not `.local-secrets/`.**

When the owner sets up a machine for a customer and wants the login information kept, the flow that
exists and is used is: **a `_credentials-<customer>-<date>.md` file under
`lpt-hub/docs/customer-operations/cases/`**, front-matter per `CASE-FILE-STANDARD.md`, headed
*"INTERNAL — do not share with customer-facing docs"*, **git-tracked in the private lpt-hub repo** and
pushed to `origin/main`. Five precedents: `_credentials-pinter-2026-09-01`,
`-debban-2026-09-10`, `-speigel-2026-08-25`, `-tzipporah-tchiprout-2026-08-11`,
`-perel-kuritsky-2026-06-24`. Referenced from the case file, never copied into a sync record, an
order description, a production note or a customer SMS — the sync record carries the **path** only
(`"credentialsFile"`, precedent `windows-laptop-tchiprout-8482261949-2026-08-05.json`). Governing
decision: journal `D2517` (2026-09-24). Owner-queue rows 66 and 90 (move them out of git / rewrite
history) were put to him and **dismissed** — do not relitigate.

**The house account shape** — four of five precedents match it exactly, so it is a convention, not a
coincidence: email `<first letter of last name><customer's 10-digit phone>@outlook.com`, password
`Hello@1234`, Windows PIN `1001`, alternate address `lakewoodphoneandtech@gmail.com`
(`p8484808424`, `d7329663107`, `s7329981024`, `t8482261949`). **Write it into a record only as a
labelled convention, never as a reading** — a plausible-looking wrong password is worse than a blank
field, and it is the exact failure mode this system has already suffered.

**Record the recovery facts, not just the password.** A password can be reset; a Microsoft account
recovery form cannot be guessed. Full name, date of birth, alternate email, recovery phone, and
whether 2FA is on are the items that actually recover the account years later. `Tchiprout`'s file is
the only precedent that carried the birthdate and alternate address — copy that, not the thinner
`Pinter` shape.

**Never claim a credential flow whose storage dies with the machine.** `.local-secrets/` is
git-ignored (`.gitignore:148`) and one `bitlocker/` key lives there on a single laptop. Any owner
requirement phrased as *"she may need it in a few years"* is failed by an untracked file on one
laptop, however tidy the folder looks. Tracked record, or the authoritative store on `secratary` —
not a local folder.

---

**`status:` in a case file is a closed vocabulary, and an out-of-vocabulary value vanishes silently.**
`CASE-FILE-STANDARD.md` §3 allows exactly `new` / `quoted` / `parts` / `in_progress` / `waiting` /
`ready` / `closed` / `unfixable` / `other`. The Whiteman case carried `status: arrived` from
2026-10-05, which is not in the list; `lptcase.py` reported `state other` and the case **disappeared
from every status view** while it sat on the bench. Correcting it to `in_progress` was a one-word fix
that had been hiding a live, high-priority job for a customer who had already been dropped four
times. Whenever a case's state genuinely changes, use one of the nine words — a nicer word is not a
status.
