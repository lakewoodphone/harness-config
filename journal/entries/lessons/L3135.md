**L3135 · A dead-weight agent is usually a broken model chain, not worthless work - read its working memory before retiring it**

**A dead-weight agent is usually a broken dependency, not worthless work. Read its working memory before retiring it.**

Measured 2026-09-30, chasing the kernel's `agent_dead_weight` finding: two live agents at **0
completions in 14 days**, `cross_domain_synthesizer` (41 ticks) and `frontier_risk_board` (38 ticks).
The kernel had already retired five agents of the same profile, so retiring these two looked like the
established remedy. **It would have been the wrong fix.** Their own working memory says why they fail:

- `cross_domain_synthesizer` — *"Step failed (error): LLM error (round 1): [identical failure 1/3 for
 this model chain inside 300s]"* — and it names the exit condition explicitly: *"a successful LLM call
 for this agent, **a change to the department model candidate list (an operator model swap)**, or
 t[ime]"*.
- `frontier_risk_board` — *"Step failed (escalate): ... previously attempted and failed with three
 consecutive LLM call failures"*.

Both are **model-chain failures**. The agents are not idle and not useless; they are attempting work
and failing to make a single successful model call. Thousands of rows support that reading: 4,310
`model_usage`, 4,293 `gateway_trace_span`, 1,345 `tick_telemetry`, 1,347 `cognitive_decisions` and
1,347 `task_outcome_signals` between the two of them. **They are spending budget every tick and
completing nothing, which is exactly the shape of the costliest failure in this system's history** -
the `personality-system` live AI path that failed for over a week behind a silent deterministic
fallback because a hardcoded model name stopped existing.

**The rule.** `agent_dead_weight` measures an outcome. Before acting on it, read the agent's own
`agent_working_memory.context_summary` and its `model_usage` rows. Three outcomes, three different
remedies:

| What the memory says | The remedy |
|---|---|
| LLM error / identical failure / model chain | **repair the model chain** - never retire. Retiring hides a live outage and destroys the agent that would have reported it. |
| finished work, nothing to do | retire it |
| no work routed to it | fix the routing, not the agent |

**And the standing model rule applies directly:** read the gateway's own catalog
(`GET $SECRETARY_API_BASE/v1/models`), prefer its route aliases (`secretary-auto`, `secretary-fast`,
`secretary-smart`), let an operator override per tier by environment, **validate every configured id
against the catalog and drop what is not listed**, cache with single-flight, fail soft, and publish
which model actually served a request. The department model candidate list for these two is the thing
to repair.

**Not yet done:** the repair itself. Recorded rather than rushed, because the wrong move here - retiring
two agents whose only fault is a model name nobody validated - would have looked like progress.

**Evidence:** `agent_working_memory` rows for both agents (read 2026-09-30, second row updated
2026-09-30T15:54Z so it is still ticking); kernel `latest.json` `agent_dead_weight` metrics
(`agents_assessed` 22, `threshold_rate` 0.02, `window_days` 14); row counts above from
`secretary.db`. The AI gateway itself is healthy - `/v1/models` 200 and chat completions 200 - so this
is not the gateway, it is the per-department model candidate list.
