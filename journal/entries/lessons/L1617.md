**L1617 · A duplicate key in a JS object-literal allowlist is silent dead code - and a test title can lie about its own coverage**

Evidence: backend/src/trpc/__tests__/guard-coverage.test.ts, the PUBLIC allowlist, held the key `ui` TWICE.
In a plain object literal the second silently wins, so the first entry was dead code and no test could notice.
Found while unlanding the ui DEBT block, not by any check.

RULE: never hand-maintain an allowlist as an object literal where a duplicate key is invisible. Either assert
the object has no duplicate keys, or build it from an array of [key, reason] tuples so a duplicate is loud.

RULE: the same file's regression-pin test was titled "the six routers that were open on 2026-09-15" while its
`watched` array held FIVE names. A test whose name overstates its coverage is worse than no name, because it
is believed.
