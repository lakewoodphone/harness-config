## W-new — Four parallel read-only audits mapped a business fact across 100+ surfaces in one pass, and found the two things single-threaded reading had missed

2026-09-15. The owner asked what had to change after one walk-in-hours change. Serial reading of the two
documents that "cover" the hours (the Dialpad runbook and the after-hours plan) would have produced a
confident, wrong plan, because **both documents state the shop's hours as Dialpad's hours** — and Dialpad's
live hours are a 24/7 ring window instead.

Four subagents, each with one partitioned surface, one output file, and an explicit "if you could not read
it, say UNREAD — an empty result is a refusal, not health" instruction, produced:

- `W1-website-portal.md` — 61 rows: five mutually contradictory hours models in the website/portal stack,
 PR #142 open with failing CI, JSON-LD wrong a third way, a seeder that would silently restore Wednesday-open.
- `W2-external-listings.md` — 16 rows: GBP/Bing/MapQuest all still say Wednesday open, the documented GBP
 access path is dead (token gone, API disabled) while a doc says it "WORKS reliably".
- `W3-internal-systems.md` — 37 rows: three customer-sending code paths assert the shop is open, zero
 closed-day logic anywhere, and a 119-day-old memory that returns FIRST for "business hours".
- `W4-consequences.md` — 29 rows: the hours change derives from a staffing change, the money arithmetic
 (every method ≤ 0), and 0 Wednesday appointments in Google Calendar.

What made it work, and is worth repeating: (1) the brief carried the NEW fact as authoritative **and** the
OLD string to search for, so no agent had to interpret; (2) each agent was told to write its own file and
to label every reading with source and timestamp; (3) the brief asked for "what you could not verify" as a
first-class column, and every agent used it — the four refusal lists (live Dialpad PWH, the two live MP3s,
Yelp, the prod work-order DB) are where the remaining risk actually lives; (4) partition by surface meant
zero file overlap and no integration conflicts.

Two findings came only from the fan-out and neither was reachable from the documents: the 24/7 ring window
(W2 confirmed it independently through a second API path) and the fired-employee fact that reframed why
Wednesday closed (W4, from a finance doc and D106).

Cost of not doing this: the plan would have said "set Wednesday closed in Dialpad", which would have routed
every Wednesday call straight to a "we're closed" message and rung nobody — the exact opposite of the
promise the new sign makes.
