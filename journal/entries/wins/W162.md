The four were not wall-clock dependent, which was the hypothesis: `_local_ts(hour, minute)` builds an
epoch from the **server's** local time (`time.mktime`), while the code evaluates quiet hours in the
**family's** zone (`personality._family_dt` -> America/New_York). On a UTC host `_local_ts(2)` is
02:00 UTC = **22:00 family-local**, which is outside a 23:00-07:00 window -- so "02:00 is quiet" was
really asserting "22:00 is quiet" and correctly returned False. On the developer's New York machine
the two agreed and the tests passed.

Added `_family_ts(hour, minute)` and used it in exactly the nine places whose expectation is
family-local. `_local_ts` was left alone because other tests in the file depend on its server-local
sense -- proved by doing the blanket substitution first and watching it break 8 tests (6947d9d8).
