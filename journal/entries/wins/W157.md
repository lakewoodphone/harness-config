Two independent causes, both measured rather than guessed:

1. **`backend_expected_env_keys()` ignored `validation_alias`.** It uppercased *field* names, so the
 contract demanded `HA_PTT_KEY`, `SECURITY_API_KEY` and `SECURITY_ALERT_EXTRA_RECIPIENTS` -- names
 the code never reads, because those three fields declare
 `AliasChoices("HA_PTT_API_KEY" | "HA_SECURITY_API_KEY" | "HA_SECURITY_EXTRA_RECIPIENTS")` -- while
 reporting the three names the code *does* read as "unexpected keys" in the template. An alias
 replaces the field name; alias-less fields keep using theirs. `extra_keys` 3 -> 0 with no
 template change.
2. **Both templates were incomplete, for real settings.** 21 declared settings were undocumented,
 nineteen of them `SHABBAT_*` (the Shabbos power and lock automation), plus `shelly_plug_host` and
 `computer_form_webhook_secret` -- and the dashboard's 11 variables had no template at all.
 Documented with the default from `app/config.py`; secrets left empty.

`web/.gitignore` ignores `.env*`, which would have left the new dashboard template untracked and the
test red on any fresh clone; it now carries an explicit `!.env.local.example` with the reason. This
is the first cluster of P139 (the suite cannot be a gate) closed since the triage began.
