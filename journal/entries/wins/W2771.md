Fixed on the clock.

THE BLIND SPOT, measured. The SMS clock runs `sms-inbox.py sync --pages 3` every five minutes. Measured
just now, that pull returns **3,000 outbound** of the **11,908** Twilio holds - the most recent quarter.
The tool's own comment says why that matters and what to do about it:
 "STORE GAP is the one that loses a text: Twilio holds a message the store does not. It can only see
 as far back as the pull actually reaches, which is exactly why `sync --all` is required for the
 number to mean anything (measured 2026-10-13: the `--pages 3` window reaches back about a day ...)"
So a message missed more than a day ago was invisible to the only check meant to find it, and the
five-minute cadence made that look like diligence.

FIXED: `23 4 * * * cron-wrap.sh sms-inbox-fullsync` added to the crontab (cron-wrap jobs 52 -> 53),
running `sync --all` daily. Crontab backed up to `/root/crontab.bak-fullsync-<ts>` first. Verified by
running it exactly as cron will: exit 0, 66 seconds, recorded in `~/.cron-status/runs.tsv` as
`sms-inbox-fullsync 0 66`, and its log shows the full comparison rather than a window of it -
"inbound: 412 from Twilio, 0 new / outbound: 11908 from Twilio, 0 new / new this run: 0".
