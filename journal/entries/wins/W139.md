**W139 · 2026-09-15 · Three live credentials that sat in git history are rotated and probe-verified.**

The private repo lakewoodphone/personal-secretary-mvp had the CURRENT values of the
NanoMDM API key (8 commits), the NanoDEP API key (6 commits, including one I wrote the
same day), the wazemdm Postgres password (2 commits) and a base64 `admin:<pw>` pair
(1 commit) in its history. Rotation is what makes that exposure moot; rewriting history
on a shared repo is a force operation nobody needs once the secret is dead.

Each rotation was verified by an auth matrix, not by a restart:
- NanoMDM: docker run --rm --network waze-mdm_default curlimages/curl -u nanomdm:$K
 -X POST http://nanomdm:9000/v1/push/<all-zeros> -> new key 500 (auth passed, nothing
 to push), old key 401, junk 401.
- NanoDEP: POST /v1/bypasscode -> new key 200, old key 401.
- Postgres: ALTER USER + .env + recreate the four clients -> old password rejected, new
 accepted, zero client errors, fleet API healthy in 3 seconds.
