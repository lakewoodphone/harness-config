## 2026-09-28 20:15 UTC - ZABZ-TECH - Round 27: the bridge is BUILT and SCHEDULED - the text channel now has nothing missing but a real text

WHAT I BUILT. `mirror-owner-sms.py`: the owner's live texts are written by the Twilio webhook into the
app's `sms_log` (982 rows, 228 from his iPhone, newest TODAY), while the responder reads
`~/.sms-inbox/inbox.db`, whose newest inbound row was 2026-04-29. The mirror copies inbound rows from the
former into the latter, which is all the responder needed to start seeing him.

WHY A MIRROR RATHER THAN EDITING THE RESPONDER - and this is the judgement I want on the record: the
responder runs LIVE every five minutes with `--send`. Editing its worklist would put new code directly in
the path that sends text to a human being. A separate mirror process means the responder keeps its own
proven path and its own store; if the mirror is wrong the worst case is that no new rows appear and the
responder behaves exactly as it does today. Containment first - the responder is untouched.

SAFETY PROPERTIES: reads the app database READ-ONLY (`mode=ro`, the same discipline used elsewhere in this
codebase); takes only inbound rows; maps the schema explicitly with the mapping written out in the file so
it can be checked rather than trusted (twilio_sid->sid, created_at->date_sent, and the rest); DEDUPES on
sid; INSERT-ONLY into the inbox, never an update, never a write to the app database.

A SECOND JUDGEMENT THE DRY RUN FORCED. My first version had no time bound. The dry run showed it would have
mirrored 27 rows from as far back as 2026-03-23 - including several "Public ingress probe" test messages -
and EVERY ONE would have become a ledger item. The responder decides about NEW texts; mirroring history
would have manufactured stale work. `--days` now defaults to 7, and with it the same run reports 0 to
insert, 263 already present, 27 correctly left as history. The dry run is what caught that, not reasoning.

SCHEDULED: `*/5 mirror-owner-sms.py --apply`, with the measurement written into the cron comment so the
