**W · A wrong scheme kept a 10-core node off the mesh for two days, and the broker now reports five nodes**

MEASURED AND DEPLOYED 2026-09-18.

THE DEFECT. The broker's roster excluded `lakewooechsmini` (Yisroel's macOS mini, 10 cores, 16 GB,
45.7 GiB free) with this recorded reason, `packages/mesh-broker/nodes.json`:

> MEASURED 2026-09-16 23:30Z from the authority - `curl http://lakewooechsmini.tail93e6e6.ts.net/mesh/capacity`
> exits 7 (connection refused/failed) …

**Port 80 has no listener on that machine, and every other row in that roster uses `https://`.** The
exclusion was a probe of the wrong URL. The gate had been answering correctly the entire time.

WHAT WAS MEASURED TODAY, both halves, rather than argued:
- `curl.exe -sS -m 8 https://lakewooechsmini.tail93e6e6.ts.net/mesh/capacity` → **HTTP 200**, curl exit 0,
 a schema-1 body: `cpu.logical 10`, `mem.totalMiB 16384`, `mem.freeMiB 6566`, `disk.freeGiB 45.7`,
 `governor {budgetSlots 24, inUse 0}`, `accepts {oneShot true, fleet true, maxChildren 12}`. Pinned to the
 tailnet IP 100.126.146.121 → also 200. The same URL over `http://` → exit 7, which is exactly the
 number the exclusion recorded.
- `ssh mac-mini-ts "/usr/local/bin/node /Users/lpt/.dsh-install/node_modules/@deepseek-ai/dsh/lib/bin.js --profile headless 'Reply with exactly: MACMINI_OK'"`
 → **exit 0 in 2948 ms**, stdout exactly `MACMINI_OK`.

WHAT WAS CHANGED AND HOW IT WAS DEPLOYED:
1. A new `nodes[]` row (`node`/`fqdn` `lakewooechsmini`, `baseUrl https://…`), `dispatch.v1: true` with
 both measurements in its evidence, and the whole wrong-scheme story in the row so the next reader does
 not re-derive it. **`location` deliberately omitted** — never measured, and `lib/config.js:92` maps an
 unrecognised value to `null`, so a guessed `home`/`office` would silently mis-apply the preference bonus.
2. `_excluded_on_purpose` emptied. Its single entry was the defect.
3. The **deployed** broker reads `/home/zabz/mesh-broker/nodes.json`, NOT the repo — a distinction worth
 remembering, because editing the repo alone changes nothing about the running mesh.
4. **The file was taken from the fetched ref, not by updating secratary's clone.** That clone is diverged
 (it has its own unpushed commits), `git merge --ff-only origin/master` refused, and the design's first
 refusal rule is not reconciling a shared clone you do not own. So: `git fetch` then
 `git show origin/master:packages/mesh-broker/nodes.json`, parsed and asserted **before** deploying
 (`PARSES nodes=5 lake=true`), copied into place, `PROVENANCE.md`'s hash updated from `6bc7134c…` to
 `806cbc87…`, and `systemctl restart mesh-broker.service` (passwordless sudo verified first).

PROOF, from the running service rather than from the file:
`curl http://127.0.0.1:3091/nodes` → **five nodes**, `lakewooechsmini` among them.

THE RULES:
1. **When a node is excluded because it "does not answer", ask which URL was asked.** `http://` and
 `https://` are different machines as far as a probe is concerned, and this roster's own convention said
 which one was meant. A blank at the wrong address is not a blank at the right one.
2. **A node excluded for two days by one wrong scheme is a capacity loss that looks like a capacity fact.**
 The roster carried the exclusion as a settled measurement, and it was read as one by everyone since.
3. **Extract a file from a fetched ref; do not reconcile a clone you do not own.** `git show ref:path` is
 the whole mechanism, it touches no working tree, and it cannot conflict.
