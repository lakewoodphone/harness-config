**`Stripe key pair : VERIFIED` IS THE LINE THAT MATTERS MOST.** The mode guard degrades to
`NOT VERIFIED - STRIPE_SECRET_KEY is not visible to this deploy` when the variable is empty - it does
not fail - so a wrong variable name here would have shipped a silent hole rather than a red build.
That is the failure shape this estate keeps paying for, and it is now measured as VERIFIED.

**AND A MISMATCH I WENT LOOKING FOR THAT WAS NOT THERE - recorded so nobody re-derives it.** The
guard reads `STRIPE_SECRET_KEY` (`STRIPE_SECRET_ENV_KEY` in `scripts/lib/frontend-deploy-config.mjs:231`)
while the workflow's preflight demands `STRIPE_SECRET_KEY_TEST` / `STRIPE_SECRET_KEY_PRODUCTION`. Two
names for one credential in one deploy path looked like a live bug. It is not:
`deploy-env.yml:431-433`, inside the `frontend` job and immediately before the deploy, bridges them -
`export STRIPE_SECRET_KEY="${STRIPE_SECRET_KEY_TEST:-}"`. My staging file writes exactly the names the
preflight checks, and the bridge feeds the guard. **Checked, coherent, no change needed.** The lesson is
the checking, not a fix: a name that appears in two places is a hypothesis until you read the line that
joins them.
