# Built: premise freshness — the queue now re-measures a decision before it reaches the owner

**2026-10-16 · `secratary-cloud` · the system is LIVE, tested, and scheduled.** Source in
`harness-config/scripts/premise-check.py` (commit `467ab76c`), tests alongside it, deployed at
`/root/bin/premise-check.py`.

## What was built

`amend` already carried the rule in its own docstring — *"an item is a statement about the world at
FILING time"* — and nothing ever ran it. This runs it.

- **`premise-check.py`** — a probe registry with seven probes, a `sweep` (defaults to dry-run), a
 single-row `check`, a `gate` whose exit code is 10 when a premise has moved, and an
 `owner_premise_check` table recording `row_id, probe, checked_at, verdict, detail, expect_max_h`.
- **Delivery hook in `owner-queue.py`** — `next` prints, before the row it shows, every pending row
 whose premise has MOVED. Guarded so a broken checker cannot break the queue tool.
- **Cron**, every 30 minutes, through `cron-wrap.sh`, logging to `~/.sms-inbox/premise-check.log`.
- **18 tests**, 0 failures, runnable bare without pytest.

## The two design decisions that matter, both forced by a real miss inside the first hour

**1. Only text-local probes may fire automatically.** `elapsed` and `deadline` re-measure what the row
itself asserts. Everything else needs an explicit `[probe:NAME]`. Heuristic detection produced
*adjacent-question* matches: the word "balance" made a family-tuition row (#169) and a Chase-card row
(#482) report the AI credit balance; "stripe" made the sales-tax row (#465) report Stripe's last ledger
charge instead of its own deadline. **A true answer to a neighbouring question looks like evidence and
is not.**

**2. Not-found is `unknown`, never `changed`.** The repo-citation probe hard-coded three repo paths and
declared row 465's cited file missing — it lives in a repository that was not on the list. **Absence
from a search is not evidence about the thing searched for** — the same error I made by hand a day
earlier with a camera citation.

## Proven end to end

- Sweep applied over the live queue: **33 checks recorded, 1 row amended.** #492's context now carries
 `[premise-check 2026-10-16] PREMISE MOVED: stated 75 days late, measured 78 days as of today (due
 2026-07-30)`.
- **Idempotent**: an immediate second sweep reports `due for re-measurement: 0`.
- **Gate**: rc=10 for the moved row, rc=0 for a fresh one.
- **The queue tool is unaffected**: `stats`, `list`, `next`, `next --peek 3` all behave, and with the
 checker hidden `next` still returns rc=0 with no traceback.
- The banner fires for a **deferred** row, which is the case that mattered: #492 is deferred, so `next`
 never chooses it, and the first version of the hook was silent about exactly the row that was wrong.

## Honest limits, recorded in the doc

**24 of 32 pending rows are `unprobed`** — nobody has described how to re-measure them, and the system
says so rather than guessing. Seven rows are now tagged with the probe that speaks to their premise.
It decides nothing: a moved premise becomes a `changed` verdict and an amended row, never a resolved
one.

## The generalisable lesson, which is the point of the whole build

**The most valuable work in that queue was checking what the queue said, and nothing in this system
was doing it.** Eight rounds of one session found five moved premises by hand. The instrument that
replaces the hand is now running every 30 minutes — and its hardest part was not the probes, it was
refusing to answer when it was not sure it had been asked the right question.
