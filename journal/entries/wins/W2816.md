**W2816 · 2026-10-14 · The company's autonomy gate now fails closed, live - an unclassified action resolves to L1 where it was L4, verified by reading the gate.**

The company's autonomy gate fails closed, live, and the change is proved by reading the gate rather than by reading the diff.

**Before.** `app/services/autonomy.py:376` returned **L4 (execute immediately, no human)** for any action the framework had not classified — *"Unknown actions default to L4 (autonomous) — bias towards action"* — and the matrix it replaced had **56 rows of which 37 were L4**, with exactly one action at L0/L1 (`propose_human_job`). So `hire_department`, `fire_agent`, `delete_tool`, `run_command` and the whole `shop_*`/`website_*` family ran unattended, and so did any name nobody had thought about.

**What shipped.** A regenerated matrix (150 rows) that enumerates the dispatcher chain from the real source by AST, so a name it does not know is a **hard generation error** rather than a silent L4; a fail-closed default; and hard ceilings so a DB row, an in-memory override or an auto-promotion cannot lift a restricted action. Patch `188,387 B` across 6 files, `git apply --check` exit 0, applied cleanly, backup of every replaced file taken (`.bak-gatefix-20261014T124411Z`), and `import app.main` OK before the restart. 51 tests passed on the build (`23` matrix + `2` regression + `26` existing), and **the regression test fails on the base** (`2 failed`) — it is a real test, not a snapshot.

**Three honest caveats, none of which the change fixes.**
1. **The gate is still advisory on the chat-action path.** `chat_action_runtime.py:381` computes `should_execute(...)`, stores it in `_autonomy_action` — a variable that appears in exactly two lines of that file, both assignments — and dispatches regardless, with `except Exception` setting the verdict to `"execute"`. So this change hardens the **agent-worker** path and the **default**; the chat path still needs the verdict to reach a branch. P6 has two parts and this shipped one.
2. **`_check_autonomy` returns `execute=True` on exception** (`agent_worker.py:2348`) — fail-open on error — and `lifecycle_sweep.py:2245` still writes L4 overrides, now inert only because the new rows carry hard ceilings.
3. **A deploy needs a restart, and a restart is how a change becomes invisible-or-live.** This one was applied at 12:44 and did not take effect until 12:47. Between those three minutes the tree said one thing and the process did another — the exact defect this round spent its morning on, deliberately staged but still worth naming.

**And a deploy risk I caught before acting, which changed nothing but was worth the check.** 31 newly-restricted actions include customer-facing sends, and the estate records **1,170 approval requests that expired unanswered** plus 300 repair-ready notices that failed silently. Gating the shop's messaging would be a business change it is not my place to make unilaterally — until I established that the dispatcher is the **company agent's** action path, not the staff portal and not the owner's own typing: the owner's and staff's messages do not go through it. So this gates the autonomous agent's outbound, which is precisely what the estate's standing outbound rule is about, and leaves the shop's messaging untouched.
