## WIN — the `--basetemp` trap is now refused, not diagnosed

`L3336` recorded the lesson twice over. This is the mechanization of it (PR #29, `kf1005/basetemp-guard`):
`server/tests/conftest.py` now refuses an explicit `--basetemp` that resolves inside the repository,
before a single test runs, with a message that names the cause, the reason and the fix - including the
second half of the trap, that the parent directory must already exist or pytest fails as a confusing
collection error.

The counting argument for spending code on a test-harness message: the trap produced a **24-failure
report against innocent code** for one agent, cost me a full cycle on a different day, and was one
keystroke from reaching the owner. A red suite nobody trusts is the expensive failure mode, not the
slow test.

Verified both ways: inside the repo, refused with the message; outside, the same file runs 11 passed.
pytest's default basetemp is under the system temp directory, so ordinary runs and CI are untouched.

**Transferable rule, now enforced rather than remembered:** when a mistake has a mechanical
signature, make it impossible rather than documenting it. Five wrong-instrument readings happened this
session; this is the one whose signature was cheap to detect, so it is the one that got code.
