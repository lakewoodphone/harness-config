**W126 · 2026-09-14 · Her laptop's web search works again: real search snippets instead of a dozen page fetches.**

MEASURED 2026-09-15 on her laptop, end to end, through her own agent.

BEFORE: every web search failed ("DeepSeek search request failed ... api.deepseek.com/anthropic/v1")
because Techloq blocks that host. The only way her agent could reach the web was fetching one URL at a
time through r.jina.ai -- a dozen fetches per answer, and no search snippets at all.

AFTER the fix (DEEPSEEK_SEARCH_BASE_URL -> our Worker, set in dshw.ps1, hostname-gated):
 task : "Use web search to find the current price of an NV156FHM-T07 laptop screen panel..."
 result : NV156FHM-T07 (15.6" FHD touch) - GBP 61.14 at Laptop-LCD-Screen.co.uk, with the URL and
 the caveat that the page itself is Cloudflare-blocked so the figure came from the snippet.
 evidence: the agent's own reasoning in the run log -- "The search returned sources but no summarized
 price" then "The fetch is blocked, but the search snippet showed..." That is a SEARCH
 returning sources, which is exactly the capability that was dead.

This is the value of the learning loop: the defect was invisible from the outside (no error she could
act on, chat worked fine, answers still arrived) and was found by reading her archived sessions
rather than by waiting for a complaint.
