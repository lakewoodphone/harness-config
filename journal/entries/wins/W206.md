**W206 · 2026-09-17 · 2026-09-17 - A cross-tree landing is provable before it is pushed: one hash guard catches the whole class.**

**What worked.** The 108 allocator existed locally as `7403b76` with parent `622876e` -- 13 commits
behind `origin/master` and holding **1706** journal entries against the converged tip's **1728**.
Pushing it would have deleted 22 entries and the whole 107 convergence, exactly as `79efb088` had
done hours earlier. Landing its PATCH instead took a throwaway worktree off the immutable
`53cf517` and a cherry-pick, and it produced `95fcd61`: parent = the ref that was read seconds
earlier, tree `2a353c3f`, 11 paths, +1846/-8, **1732 entries**.

**The guard that generalises, and it is one comparison.** A commit whose tree is not its parent's
tree IS a mass deletion, so resolve the parent commit and the parent tree from the SAME immutable
reading -- and then assert, before pushing, that the new tree is not the stale base's tree:

```
intended base (fetched tip) : 53cf517c61ce83f1426e096458e9e5d338cf8770 tree 5684ffdb
stale base (the trap) : 622876e965f8b03c35dc012aec83a0184e9ed748 tree 36ec672c
new commit : 95fcd6117e04261f37c659ee98b9013394ce42c2 tree 2a353c3f
 guard 1: parent == fetched tip -> True
 guard 2: new tree != stale base's tree -> True (2a353c3f != 36ec672c)
 guard 3: 1706 + 4 new = 1732 entries, counted from the TREE, not from a name
```

**Why the base was proved current by content, not by a name.** `journal/entries/**/*.md` counted
**1728** in the landing worktree and `check` reported **0 error(s), 85 warning(s), 80 info** --
the same three figures the 107 convergence recorded for `53cf517`. A hash I typed proves only
that I typed it; a byte-count and a passing gate prove what tree I am actually standing on.

**The gates that made the push safe, in this order:** `check` 0 errors, `verify-alloc.py` 21
checks 0 failures, `selftest` all 240 passed, entry count accounted for (1728 + 4), and then
`ls-remote` re-read immediately before the push and compared to the value fetched minutes
earlier, with `rev-list --count 53cf517..95fcd61` = 1 and `95fcd61..53cf517` = 0.

**Two readings is the whole method, and it is cheap.** Fetch a hash, re-read the remote just
before acting, and refuse to act if they disagree. Every failure in this family -- the reverted
`origin/master`, the five contested ids git called clean, the 23 entries that existed in no
commit -- happened because one of the two readings was taken from a mutable name.
