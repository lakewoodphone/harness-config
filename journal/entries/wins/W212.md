**W · Every node now has a measured unit cost except one, and the authority turns out to be able to host a child after all**

MEASURED 2026-09-18 by workstreams L (zabz-tech-linux) and S (secratary). Consolidated table,
with method and date per cell: `docs/mesh/114-node-capacity.md`.

THE NUMBERS:
- **`zabz-tech-linux`: 113 MiB per concurrent agent turn** (CI 110-117, R² 0.9971), K in {0,2,4,6} x 5 runs,
 with a control that gave a delta of **exactly 0 kB in all five K=0 runs**. Same method as `zabz-tech`'s
 295, so the two are comparable.
- **BUT the plateau is a ramp, and the safer number is bigger.** Children were still allocating at the last
 alive sample of every run (alive windows 3.2-4.4 s). Sized by PEAK instead: **140 MiB/turn
 (CI 138-142, R² 0.9994)**. The child said it plainly: headline 113 for cross-node comparison because that
 is the method-identical figure, **140 for capacity planning** because that is what must be reserved. Both
 are in the table. A measurement that reports only the flattering of its two defensible numbers is how a
 machine gets overcommitted.
- **`secratary` CAN host one agent child.** One child cost ~181 MiB peak RSS — 1.2 % of free RAM — **drew
 ZERO swap** (SwapFree moved UP by 4 kB), and left `mesh-broker.service` and `secretary-api` `active` in
 all 44 loaded samples. The child did not escalate, as instructed, and said so.
- The binding limit on the authority is **not RAM** (14.6-14.8 GiB free) — it is **swap: 712-716 kB free of
 4 GiB, 0.017 %, already below any sane abort floor at rest**. An already-running process that starts
 growing cannot be paged out. That is the "one runaway from a global OOM" condition of `112`, now measured.

THREE THINGS THE CHILDREN FOUND THAT NOBODY WAS ASKING FOR:
1. **A prior record was stale and had been read as fact.** The record said `secratary`'s `DSH_HOME` holds
 "only `node_modules` and `web`", so no headless child could run there. `ls` shows **`headless` exists**,
 dated Sep 17 03:57, and a real child ran on the authority and reported `HOSTNAME=secratary`. The stale
 row was the reason that node's `dispatch.v1` read `null`.
2. **On BOTH Linux nodes `vm.overcommit_memory = 0`, so the commit figures are ADVISORY, not enforced.**
 On the authority `Committed_AS` sat at 84.5 % of `CommitLimit` for 149 samples with nothing rejected.
 Both children flagged this independently and unprompted; it is the same trap that produced a wrong
 conclusion in `112`.
3. **The metric is not identical across platforms.** Windows `GlobalMemoryStatusEx` commit and Linux
 `Committed_AS` are method-identical, not metric-identical, and nobody has shown they count the same
 thing. Cross-platform comparison is directional until someone does.

AND A HAZARD IN OUR OWN VERIFICATION, FOUND BY ACCIDENT: workstream S opened its first message with
`MESH-HOST: ZABZER` — **a value it had not measured**, which it then corrected. **`MESH-HOST:` is a token
the CHILD writes**, and the mesh's placement verification compares that token against the node the broker
named and treats agreement as proof. A child that guesses, or reads the expected hostname out of its own
brief, produces a confirmation without having run anywhere. Today's guess did not match, so the check
passed — but the weakness is specific and worth naming: **any check whose only evidence is a sentence the
checked party writes can be satisfied by writing.** The existing transport-block comparison (`transport
host`, recorded by the target shell BEFORE the agent starts) is the part that carries real weight; the
right hardening is a nonce the target shell echoes and the child never sees, which is a transport design
change rather than a patch and is recorded here rather than attempted blind.
