**W2755 · 2026-10-13 · Five tools imported a module that was never copied to the authority.**

2026-10-13. A 498-line module that five tools import had never been copied to the authority, and
every one of them had been quietly running without it.

THE MODULE. `charge_msg.py` composes the owner money-question and carries the evidence with it: the
card from `accounts.last_four` (never `account_name`, because - its own words - "two different cards
both read Blue Cash Everyday(R)"), the exact charge ROW rather than a MAX() from a different row,
the bank's own words from `raw_payload_json.raw_name`, the merchant's sibling charges so a grouped
total is never mistaken for one charge, an Amazon order match by exact amount plus or minus five
days, and the single ask. It lives at `/home/zabz/bin/charge_msg.py` on the frozen office box.
It did not exist on the authority at all - `find` on both boxes for `charge_msg*` returned nothing
here and five files there (the module plus four dated backups).

WHO WAS RUNNING DEGRADED. `grep` over the authority: `cfo-ask.py` (line 579, where the import is
wrapped in a try that prints "charge_msg unavailable" and falls back to a bare body), `textwork.py`,
`cfo-resolve.py`, `merchant_resolve.py`, and `cfo-balances.py` - which names it in a docstring as
"the reader `app.services.gmail_service`, the one `charge_msg.py` already calls". Five tools
documenting or importing a module that was not on the machine. Each one had a fallback, and every
fallback is silent by design, which is why nobody noticed.

COPIED AND VERIFIED. `cat` over ssh into `/root/bin/charge_msg.py`, 498 lines, compiles, and imports
with `card_last4`, `compose`, `connect`, `email_match`, `bank_words` present. The asker's own check
line changed from
 receipts: charge_msg unavailable (No module named 'charge_msg')
to
 receipts: no vendor mail for this merchant within a few days of the charge
which is a real answer rather than a broken method reported as unchecked. And the composed body
changed from
 "what was 299.00 at polka dot on 27 Sep (ending 4258)? My guess: shop supplies. Reply 'yes'"
to
 "299.00 at Polka Dot on 27 Sep, card ending 4258. No guess from me - say what it was and I'll
 file it for good."
The second is SHORTER and it drops the guess, which is the composer behaving correctly: it guesses
when the records support a guess and says so plainly when they do not. "My guess: shop supplies" was
the old fallback inventing confidence.

LESSON, and it is the fourth variant this session of the same failure. **A fallback that prints a
warning nobody reads is indistinguishable from a working system.** The import has been failing on
every run, and the only trace was one stderr line inside a log that also carries the successful
output. When a module is imported in a try/except, that except clause is a place a deployment can
rot undetected - worth checking the fallback path's own words for "unavailable", "falling back" and
"not importable" across the tools, which is how this one was found.
