WHY THIS ATTEMPT SUCCEEDED WHERE THE LAST ONE CRASH-LOOPED PRODUCTION
1. The patch is done by a Node helper (docs/audit/priceguard-patch.cjs) that DEDUPES the import
 specifier list. The previous failure was a token replace creating
 'import { protectedProcedure, protectedProcedure, router }' -> SyntaxError -> crash loop.
2. 'node --check' on EVERY patched file BEFORE the image is built, in the container, with restore-and-abort
 on failure. Nothing was built until all three parsed. On the failed attempt the gate that existed was a
 count of 'publicProcedure' == 0 - TRUE, and the file did not parse. A token count is not a parse check.
3. Absolute rule enforced: derive FROM the CURRENTLY RUNNING image, never ':latest', so previously baked
 guards are preserved - and then VERIFY that in the image rather than assuming it.
4. Automatic rollback on unhealthy, so a bad patch cannot sit as a crash loop.
