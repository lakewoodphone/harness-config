**W117 · 2026-09-14 · The duplicate-task guard could not see blocked tasks or other agents' tasks.**

The duplicate-task guard could not see the duplicates it exists to stop

MEASURED 2026-09-15: task #25106, a $167.96 PayPal dispute, collected five tasks about the
same order in three hours -- 1777, 25106, 25117, 25158, 25174, 25179 -- three of them
near-identical titles. `create_task` ALREADY dedupes: an exact dedupe_key path and a fuzzy
find_similar_open_tasks at 80% word overlap. So the defect was not a missing guard; it was a
guard that could not see its own subject. Two narrow causes, both found by testing the
function against the live rows rather than by reading it:

 1. THE LIVE SET WAS TOO SMALL. The query matched status IN ('open','in_progress'). At 00:45
 when duplicate #25158 was created, #25106 was `blocked` -- put there an hour earlier by
 the retry ceiling. So blocking a task licensed the creation of copies of it. The table
 also holds 'waiting on customer' (3), 'in-progress' (3), 'awaiting_part' (1), 'paused'
 (1) and 'todo' (1): pending work, invisible to the guard. This is L1477's shape, and
 this time I caused it.
 2. THE SCAN WAS AGENT-SCOPED. create_task passed agent_id=agent_id, so #25174, filed by
 dept_finance, could never match orchestrator's #25106. chat_action_tasks.py already
 scanned globally for exactly this reason, so the DB writer was the inconsistent one.

And a third, already fixed the same night: #25174 was created while #25106 was FALSELY `done`
from a rollup (commit e88dccff). Two of the three duplicates trace to guards of mine that
could not see what was in front of them.

FIX: TASK_PENDING_WORK_STATUSES (the pending-work question, deliberately distinct from
TASK_ACTIVE_STATUSES, which answers the ceiling-capacity question) and a global scan in
create_task. Committed 27d7d51c, six tests including a wiring assertion. The live duplicate
#25179 was cancelled with a note pointing at #25106. Verified afterwards: health 200, tasks
still being created at the normal rate with distinct titles, and zero live duplicate clusters.
