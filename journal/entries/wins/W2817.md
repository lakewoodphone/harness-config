**The defect, measured.** `app/chat_action_runtime.py` called `should_execute(action_name, settings)`, stored `decision.get("action", "execute")` in `_autonomy_action`, and then fell straight through to `_dispatch_action_inner`. The variable appeared in **exactly two lines of the file, both assignments** — the verdict was computed, recorded and discarded — and the `except` clause set it to `"execute"`, so an error in the gate granted execution. **A gate is not a gate because it is called: the verdict has to reach a branch.**

**The fix, and it mirrors the file's own house pattern rather than inventing one.** `_dispatch_action` (line 325) already returns a soft `ActionResult(success=False, detail=...)` for two pre-dispatch blocks — `_validate_params` and `_enforce_action_policy` — so the autonomy verdict became a third, placed in the same position and shaped identically. It reads `decision["execute"]` (which `should_execute` already returned, `False` for L0/L1/L2), and when the verdict is "do not execute" it queues an approval task through the existing `_create_approval_task` helper and **returns without dispatching**. The `except` path now **fails closed** (`execute=False`, level L1) instead of granting execution.
