| | before | after |
|---|---|---|
| `MANAGED_REPOS` paths that exist on this host | **0 of 9** | **9 of 9** |

`app/chat_action_repos.py:75` is what turns a repo alias into a path, and every alias pointed at
`C:/Users/ezabz/Code/...` on a Linux box. The repos are under `/home/zabz/repos/`. Two aliases also
named the wrong repository: `research` -> `research-knowledge-base`, and
`apps-4-flip` -> `kyocera-escalator` (the blueprint's own `github_repo` field named the right repo all
along while `local_path` contradicted it).

The fix refuses to write a path that does not exist on this host - the whole defect was paths that
did not exist, so a blind rewrite could have reproduced it. Verified by calling the program's own
resolver, not by reading the file back.

**Why this one matters more than its size suggests:** it was not one broken reference. It was the
entire repo-facing capability of the company, silently pointing at a machine that no longer exists,
while agents dutifully reported "File not found" and the failure count blamed the agents. The 138
missing-path blocks were the *symptom the system was reporting about itself* and nobody had read them.
