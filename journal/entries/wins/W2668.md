## W-new · Fast search verified end to end on 2026-10-08: the scope claim reproduces, 100 s vs 20 ms

**The premise of the fast-search skill is now measured, not asserted.** Same host (`secratary`), same
query, cold caches:

| | |
|---|---|
| `fa journal "journal lock"` | 317–544 ms (index path) |
| `fa files database.py` (path index) | 40–51 ms |
| `fa data battery` (comms FTS, 178,125 comms) | 205–312 ms |
| `fa symbol create_task` (always live) | 1,370 ms |
| `fa code _owner_sms_allowed` | 909 ms |
| `rg` scoped to `app/` | 20 ms |
| `rg -uuu "journal lock" /home/zabz` | **100,075 ms** (100 s, 49 files) |

**SCOPE is the lever, exactly as claimed: 100 s unscoped against 20 ms scoped.** The index is a second,
smaller lever. The published "6 ms journal / 8 ms path index" figures were warm micro-benchmarks; the
honest end-to-end numbers above are 40–540 ms and are published in the skill now.

What the surface does that nothing did before: one grammar across four nodes, uniform provenance on
every indexed answer (`source`, `ms`, `index_age_s`, `index_entries`, `covers_through`), a telemetry log
(`fa stats`: median 394 ms, p90 2,351 ms, 5 over the 2 s tripwire) and an explicit refusal instead of
silence when an index is missing.
