### Method - and five defects in my own tooling that each cost a round

1. **Pass 1 named the office bare hubs as URLs; they are local PATHS on the box** - three
 `FAILED-CLONE`. Fixed by running `git bundle create` **on** the source host, which also means no
 network is needed between hosts.
2. **Pass 2 used a bash heredoc over ssh, but the Windows hosts run `pwsh` as their default shell** -
 every desktop and laptop rescue failed with *"WSL has no installed distributions"*. Fixed with a
 PowerShell variant.
3. **My bash wrapper's quoting produced an empty result**, so six repos reported `FAILED` while the
 script worked perfectly when run by hand. **A wrapper that swallows a subprocess's output cannot
 tell success from failure** - the same class as the estate's own "green light measuring the wrong
 thing".
4. **`Get-Date -AsUTC` does not exist in Windows PowerShell 5.1** (it is PowerShell 7+), so `$stamp`
 was empty and the archive step silently did not run. Harmless here only because the bundles were
 already written to a real directory.
5. **`scp` DOES NOT WORK TO THE LAPTOP** - its ssh advertises **no sftp subsystem**, so every scp fails
 with exit 255 and creates no file. Delivering the helper script needed **base64 through ssh stdin**,
 and the 781 MB collection had to be pushed **from** the laptop to the authority rather than pulled
 by it. **Two independent fallbacks found**: base64-stdin for small files, and the laptop has its own
 Hetzner key and a direct route to the authority for large ones.

**The transfer that nearly lost data.** The first attempt to move the desktop's 716 MB archive *through
this laptop* produced a **159 MB truncated file** - `tar: Unexpected EOF in archive`. Caught by
unpacking rather than by believing the copy. The fix was to cut out the middleman: the desktop has the
Hetzner key and reaches the authority directly, so **host-to-host transfer, never via a third machine**.
*A `scp` that exits 0 has not necessarily transferred the file.*
