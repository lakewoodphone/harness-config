**W2737 · 2026-10-11 · Hostile-fixture test suite for the card copier: 51/51, and it caught 4 real defects including one showstopper.**

The shop's SD-card customer-data copier was rebuilt as a single compiled `GO.EXE` and
proved before it was put on a card: **51 checks, 51 pass**
(`hardware-diagnostics/sd-data-copy/test/run-tests.ps1`), driven through two `subst` drives
so the tool sees a real non-C: card, against a hostile synthetic tree — a 288-character
path, a junction loop back into the source, 1,500 small files, an 800MB file, a file locked
open by another process, browser caches, `NTUSER.DAT`, a unicode filename, a hidden file and
reserved profiles.

The harness earned its keep: it caught **four real defects, one of them a showstopper**,
none of which a happy-path run would have shown.

1. `TrimEnd('\\')` turned `E:\` into `E:`, so every path began `\\?\E:...` — not a legal
 path — and the tool aborted with *"this card cannot be written to"* on a **good card**.
 Caught by the first test.
2. Ledger keys were relative to the scanned folder rather than the job folder, so an AppData
 entry read `Local\Google\...` and `--check-card` could not find a single file.
3. The ledger was never flushed on a normal exit: managed buffers died with the process.
4. An unreadable folder still produced a clean `VERIFIED` — a false-verified claim, the one
 thing this business cannot afford.

Also worth keeping: the independent side of the suite hashes **every** file on the card and
compares it with the source (1,509 files, 0 different) — the tool's own verification is not
evidence that the tool is right.
