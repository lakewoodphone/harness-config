## dsh-update found real breakage on 0.1.7-rc.1 that a version-number comparison would never have shown

MEASURED 2026-09-23/24 (ZABZ-TECH). The new `dsh-update` pipeline, run against `0.1.7-rc.1` (the
`next` tag), returned `analyze` = **BREAKS=2 RISKY=4 CAPABILITY=59 INFO=53**, while `patch-effect`
returned **SAFE**.

WHAT MAKES THIS A WIN AND NOT A COINCIDENCE: the two BREAKS were **reproduced by hand against the
fetched install** before being believed. `@deepseek-ai/dsh-agent-presets` and
`@deepseek-ai/dsh-workflow-worker-thread` are genuinely absent from
`vendor/prefix/0.1.7-rc.1/node_modules/@deepseek-ai/` — verified by direct directory check, and the
contract map agrees. They were renamed:

 removed appeared instead
 dsh-agent-presets -> dsh-agent-preset + dsh-agent-preset-registry
 dsh-workflow-worker-thread -> dsh-workflow-ptc, dsh-ptc-runtime(-node)
 cordis-plugin-hmr -> dsh-hmr
 dsh-settings-file -> dsh-config-editor

WHY IT MATTERS: a version-number comparison (or a changelog read) says "0.1.5 -> 0.1.7, probably
fine". What actually happens is that a composition row in `profiles/mesh/cordis.patch.yml:69` names
an uninstalled package and fails to resolve at mount (in the mesh host composition that can take the
boot down), and all three of our presets name the removed workflow worker, which breaks **session
creation** on `zabz`, `yocheved` and `cordis-bg`. Nothing raises an error until a session is created.

THE SAME RUN ALSO SEPARATED TWO THINGS THE EARLIER DESIGN CONFLATED: the patch layer
(`patch-effect` = SAFE, all four targets intact) versus the packages our *rows* name (BREAKS). They
are different planes with different failure modes, and one can be clean while the other is broken.

CROSS-CHECK ON THE DETECTOR ITSELF: on the same day, the same pipeline returned a FALSE `BREAKS=2`
for `0.1.5-rc.3`, which breaks nothing (LESSONS L2373). So this is not "the detector always says
BREAKS": `0.1.5-rc.3` = SAFE `BREAKS=0`, `0.1.7-rc.1` = BREAKS=2 with both verified by hand. That
pair of readings is what makes either one worth anything.

EVIDENCE: `harness-config/dsh-update/FINDINGS.md`; `state/candidates/0.1.7-rc.1/{diff.json,report.md}`;
`state/candidates/0.1.5-rc.3/{diff.json,verify.json,patch-effect.json}`.
