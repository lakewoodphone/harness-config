**W2798 · 2026-10-13 · The owner queue's deferral mechanism already works; verified before patching it.**

A NEGATIVE RESULT WORTH RECORDING, SO THE NEXT SESSION DOES NOT "FIX" A WORKING SYSTEM.

The open-work triage reported six pending rows past their `deferred_until` date. I read that as a
mechanism defect -- nothing re-surfaces a deferred row -- and went to patch `owner-queue.py`.

**I was wrong, and the code already said so.** `_is_deferred()` returns True only while the stated
date is still ahead (`dt > now`), and `_is_overdue_deferral()` exists for the other half. So a
deferral is a *hold that expires by itself*, which is the right design, and the six rows are not
stuck at all -- they are active again and `next` will present them.

VERIFIED TWICE, not once:
 * by reading the two functions rather than assuming from the field name;
 * by running the command the owner's path actually uses -- `owner-queue.py next` returns **#475**,
 the 2025 tax extension, critical, two days out. The prioritisation is working.

THE HONEST STATE OF THE QUEUE, MEASURED: 162 pending -- 4 critical, 41 high, 106 medium, 11 low --
and **all four critical rows are the same cluster**: #475 (2025 return, 2 days), #477 (NJ-927/WR-30
payroll, 75 days past), #478 (NJ employer number into Gusto, 59 days), #480 (ST-50 sales tax, 85
days past, next due in 7). They are one question, and **it has already been asked**, once, with a
recommendation. Nothing further should go to him about it.

So the queue's MECHANISM is sound and the problem is its DISCIPLINE: ~137 of the 162 are engineering
that the queue's own doctrine says should have been fixed rather than asked ("a queue row is an
admission that I could not"). That belongs at the `add` end, as a check -- not as a mass-close, which
would be false completion at scale.

THE GENERAL LESSON, because this is the third time this program has nearly built something that
already existed: **read the implementation before believing a field name.** `deferred_until` sounds
like a latch. It is a timer, and it works.
