**W54 · 2026-09-14 · 2026-09-14 - Three feature flags were read but never declared: one feature dead, two un-switchable.**

**Three feature flags were read but never declared, so one feature was dead and two could not be switched off**

Audited every `getattr(<settings>, "name", <default>)` in `app/` against the fields declared in
`config.py` and the keys in `.env`: **24 settings are read with a default but never defined**, and
**exactly one of them was broken by it**.

- **`spending_report_enabled`** — default `False`, not in `.env` either. Permanently off, and **not
 settable by configuration at all**; turning it on required editing code. 38 failures recorded, never
 run on purpose. Fixed: declared in `config.py`, behaviour unchanged, now a decision rather than an
 accident.
- **`plaid_sync_enabled`** and **`receipt_sync_enabled`** — found by the *guard test I wrote for the
 class*, not by the original audit. Both default `True`, so they ran — but they could not be turned
 **off** by configuration either. Declared at 2026-09-14, behaviour unchanged.

The other 21 are times, limits and paths whose defaults work, plus `lpt_hub_local_repo_path` (default
`None`, guarded at its use site). They are left alone and named here so a future session does not
re-audit them.

**The pattern is the one this session keeps finding.** A default hides an absent definition exactly the
way a breaker hid a switched-off sync, an unfetched ref hid a stale ID space, and a log field hid an
unmeasured action. **Where a mechanism is silent, absence and health look identical.** Three of the five
corrections I have had to make in this session were of that shape.

**Verified.** `tests/test_settings_flags_are_declared.py` — 3 cases, including one that scans the
autopilot source for every `*_enabled` flag it reads and fails if any is undeclared. That guard found
`plaid_sync_enabled` and `receipt_sync_enabled` the moment it was written, which is the point: the test
pins the class, not the instance I happened to trip over.

**Not deployed to the authority, deliberately.** The change is behaviour-neutral — every default preserves
what the `getattr` defaults already did — and deploying requires a service restart, which also spawns a
work session (L229). Restarting production to change nothing is worse than carrying the commit until the
next functional deploy, so it goes to `master` now and rides the next hand-port.
