**W2825 · 2026-10-14 · The journal's cross-host id ceiling is now shared and proven: yoga's ceiling 3188 -> 3198, next-id P3189 -> P3199 - and the reservation layer is still private.**

The journal's cross-host id visibility is fixed and proven, and the fix exposes the next layer down, which is a code change and not a configuration one.

**The mechanism, now read from the source rather than its docstring** (`L3818` corrected my first account; this is the measured one). `git_max()` enumerates exactly one ref family:

 git for-each-ref --format=%(refname) refs/remotes/origin # journal.py:3356, bounded to 25 refs

and greps the pattern in each. Every one of my earlier test fetches landed in `refs/remotes/cloud/…` and `refs/remotes/offsite/…`, **which is why they changed nothing** — not because the ref was immutable, which was my second wrong answer. `allocation_ceiling()` then reads `max(local tree, stamp.json:git_ceiling)`, so a fetch alone is not enough either: the ceiling is a **cache**, refreshed only when a writer path calls `git_max`.

**The fix, proven on ZABZ-YOGA.**

 git remote add cloud secratary-cloud:/home/zabz/code/harness-config
 git config remote.cloud.fetch '+refs/heads/*:refs/remotes/origin/cloud/*'
 git fetch --all -> exit 0

 before git_max(pain) = 3188 allocation_ceiling(pain) = 3188 cache {"pain":3188}
 after git_max(pain) = 3198 allocation_ceiling(pain) = 3198 cache {"pain":3198}
 next-id pain -> P3199

The refspec is the whole trick: it lands the **other host's** branches under **my** `refs/remotes/origin/`, which is the one family the allocator reads — no network hop beyond the ssh it already has, and no change to `origin`'s fetch or push behaviour (which matters: adding GitHub as a second `origin` URL would have made `git push origin` write to the FROZEN box, since a multi-URL remote pushes to every URL). The authority's symmetric half is in place too (`git config remote.journalpub.fetch '+refs/heads/journal/*:refs/remotes/origin/journal/*'`), and its `refs/remotes/origin/journal/zabz-yoga` is visible after a fetch, exit 0.

**What this actually fixes, stated exactly.** ZABZ-YOGA was returning **P3189** — an id the authority already owned, because its ceiling was its own local maximum. It now returns **P3199**. So the **guaranteed-collision class is gone**: this host no longer mints a number the other host already holds. At roughly 7 collisions an hour, that is the bleeding stopped for every id minted from here on.

**And what it does not fix, which I am recording rather than papering over — including a risk the fix exposes.** Both hosts now return **P3199**:

 ZABZ-YOGA highest seen: P3198 reserved through P3194 for ZABZ-YOGA next P3199
 secratary-cloud highest seen: P3198 reserved through P3229 for SECRATARY-CLOUD next P3199

They now **agree on the next number**, and two hosts agreeing is exactly the state that races. The reservation layer exists (`RESERVATION_WINDOW = 64`, `journal/alloc/bands.tsv`, and the "reserved through … for <HOST>" line) and would prevent this — the authority has reserved through **P3229** for itself, so P3199 is inside *its* band and outside yoga's. **Yoga ignores that reservation because `claim_map()` reads `bands.tsv` locally; it does not read it from the fetched refs the way `git_max` now does.** So the ceiling is shared and the reservation is not, and a shared ceiling with a private reservation produces agreement-then-race rather than partition.

**Both defects have the same shape as everything else today: the reading is taken from a source the other host cannot reach.** The remaining work is small and specific — make `claim_map()` read `bands.tsv` from `refs/remotes/origin/*` as `git_max` already does, so a host sees the windows its peers have claimed and takes one outside them. **Not done tonight, deliberately:** it is a code change to the allocator of the one record this system promises not to lose, and the ceiling half is a measured improvement that stands on its own. **The measurement that will say whether it worked is the collision rate: 7 per hour, so a re-count one hour after this change is decisive.**
