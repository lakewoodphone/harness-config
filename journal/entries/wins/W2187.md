**W2187 · 2026-09-22 · Closing a 102-commit journal divergence with zero loss: back up off-host, merge on a scratch branch, let repair-ids renumber, prove no deletions before you commit.**

**What measurably worked, and should not be "optimised" away later.**

The journal divergence (P2185, open since 2026-09-20, "the fix is the operation that once deleted the
whole log") was closed on 2026-09-22 with **no data loss and no force push**, in four steps worth
repeating verbatim:

1. **Backup off-host first.** `tar czf journal-20260922.tar.gz journal/` and
 `git bundle create harness-config-20260922.bundle --all`, then `scp` both to a second machine.
 Two minutes, and it is what turns an irreversible mistake into a recoverable one.
2. **Merge on a scratch branch, never on `master`.** `git checkout -B reconcile/... master` then
 `git merge origin/master`. `master` stayed untouched until the result was verified.
3. **Let the tool resolve id collisions, not your judgement.** 21 add/add conflicts were 21 real
 collisions (two different entries claiming one id). `journal.py repair-ids --apply` renumbered the
 later claimant, wrote the alias, and archived the superseded file. Hand-editing them would have
 rewritten entries, which the record forbids.
4. **Prove no loss before committing.** `git diff --name-status --diff-filter=D origin/master --
 journal/entries` was **empty**; entry count went 2175 → 2213; `journal.py check` returned
 **0 errors** and legacy drift **0**. Only then `git merge --ff-only` and a plain push.

Measured result: `6a48b11..8004ea5`, fast-forward, `master...origin/master` level, verified by reading
the merged entries back from a *different machine* after a fetch.

**One ordering rule learned the hard way inside that run:** resolving the generated cache files
*last* fails. A conflicted `journal/state/status.tsv` makes `repair-ids` die in `rebuild_cache` with
`ValueError: not enough values to unpack` — and, worse, it uses `<<<<<<<` marker lines as data.
Resolve `state/*.tsv` and `alloc/*.tsv` **before** running any journal tool. Those two files are
append-only records of independent machines, so the right resolution is a **union**, theirs first with
exact duplicate lines dropped once — not "ours" or "theirs".
