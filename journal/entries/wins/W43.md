**41 owner briefings were raw tool-call JSON, and the guard now catches every one of them and nothing else**

**What was wrong.** `owner_message_queue` held 102 owner briefings. **41 of them** — 20 of 50
evening and 21 of 52 morning, from **2026-07-06 through 2026-09-14 07:30, still firing today** —
had a body that was not a briefing at all but the model's raw action envelope:

 {"reply": "", "actions": [{"name": "list_tasks", "params": {"status": "open"}}]}

`owner_briefing_llm_synthesis` defaults to `True` (`app/config.py:835`) and is not overridden in
the authority's `.env`, so `build_llm_briefing` is the live path, and it used the model's reply
verbatim whenever it exceeded 50 characters. `call_fast_model_simple` does not parse the structured
action block, so when the model chose to *call a tool* instead of writing prose, the envelope **was**
the reply — and an envelope clears 50 characters easily. The length guard could tell short from long
but not prose from a machine instruction.

Had the delivery channel been open, the owner's morning briefing would have read as that JSON. This
is the third instance today of the same class: **a consumer treating a structured action envelope as
human-facing text** (the work-mode prompt `e600b259`, this, and the reason the envelope format
exists in the first place).

**The fix.** `is_model_action_envelope()` rejects text that is entirely a JSON object, or that
carries an `actions` array in envelope shape; `build_llm_briefing` falls back to the deterministic
briefing and logs a warning when synthesis returns one. Deliberately conservative, so a briefing
that merely *mentions* a brace is untouched.

**Proven against the real rows, not fixtures.** On the live database after the deploy:

| check | result |
|---|---|
| stored envelope bodies in `owner_message_queue` | 41 |
| flagged by the new guard | **41** |
| every one caught | **True** |
| genuine briefings checked for false positives | 61 |
| falsely flagged | **0** |

Perfect separation on production data, not on a synthetic case. 9 unit tests pass on the authority's
own tree (`tests/test_briefing_is_prose_not_action_envelope.py`), including the two exact production
bodies and a prose paragraph that quotes an envelope.

**Deployed** by the gated hand-port (`.runtime/deploy-backups/handport-briefing.py.pre`), because
`deploy.sh` still cannot run: compile gate, then tests, then restart, then `/health` 200. Recorded in
`.runtime/deployed-commits.log` at 15:59:21Z.

**Named, not fixed.** The same envelope can reach **any** other `call_fast_model_simple` consumer
that treats `reply` as prose. The durable fix is to parse the structured block at the source, or to
give pure text tasks no tools bound at all — a briefing is a text task and should not have tools. This
change makes the briefing path safe in the meantime, which is the one that reaches the owner.

**The next honest verification point**: the 21:00 evening briefing. It will be the first briefing
generated with the guard in place. If it arrives as prose, the fix works in production and not only
in my checks; if it arrives as an envelope, the guard is in the wrong place. Nothing before 21:00 can
settle it.
