THE MATH, closed the same night by arithmetic and then by the database:
`75 / 1.06625 = 70.34` exactly. The quoted price was read as tax-INCLUSIVE and stored as its pre-tax
base; `65.97 + 4.37 = 70.34` is that number / 1.06625. Order 3139 (`WO26101812753`) has `total 70.34`
with **every price field NULL** (`adjustmentAmount`, `chargeAmount`, `laborOverrideAmount`,
`discountAmount`), so the panel printed the stored total as if it were the quote. One cause, three
symptoms. The owner then answered the rule in two words - **"the customer pays 79.97"** - so tax is
added, the box defaults unchecked, and the sale test now pins 191.93 for a typed 180.

THE SIGN-OUT DEFECT, root cause: `auth.logout` was a `protectedProcedure`. An expired access token
returned **401**, the client swallowed it and cleared only the tokens, leaving the **HttpOnly refresh
cookie valid**; the login screen was *pushed* rather than *replaced*, so the account URL stayed one
Back away. Fixed by revoking server-side through the refresh token, clearing client caches, `replace`,
and re-verifying on mount and on bfcache restore. There is a reproduction script whose BEFORE shows
the account page with the phone number and whose AFTER ends at `login?expired=true`.

THE PHONE CODE: the login-code lookup ignored `purpose`, so it could compare a login code against the
phone-change row and return "invalid verification code" for a code that had just arrived.

THE PHOTOS: never lost. In R2, linked to the case, kiosk and counter rows pointing at it - and the
work-order card searched the case list for the order number and **never looked at
`promotedOrder.orderNumber`**, so it printed "No photos are stored against this order" for every real
order. One clause.
