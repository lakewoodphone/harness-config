**W134 · 2026-09-15 · Real human speech on the Mac mini transcribed exactly -- and the log, not the file, revealed the stale setting.**

The dictation install on the office Mac mini was verified with real human speech, by accident, and that
turned out to be the best evidence of the whole job.

While it was being set up someone sat down at the machine, recorded Command+H in Handy's own settings UI
(which is how that key was chosen -- the setup kept the human's choice rather than overriding it), and
dictated twice. history.db holds: id 2 "Does this work?" 14:39:52 and id 3 "Hello, what's up?" 14:40:39 --
both exact, from real speech at the desk, against the whisper-large-v3-turbo Q8_0 model.

The lesson generalises: a synthesised-voice loopback test through speakers (my own test, which misheard
"Yocheved" as "Yachi" and lost the price in the sentence) UNDERSTATES the system badly, and a real human
sentence through the real microphone is worth more than any number of configuration checks. Design the
verification so a human can do the decisive step in ten seconds, and watch the log while they do.

SECOND FINDING, and it is why the first human test looked like a failure: those transcripts never reached a
text box. `paste_method` had been left at "none" by my own test and Handy had written its stale in-memory
copy back over the file (see the sibling lesson on Handy's settings cache). The discovery method that worked:
read the app's own log line "Loaded settings: AppSettings { ... }" and compare it with the file on disk --
that is what exposed the stale value, not the file.
