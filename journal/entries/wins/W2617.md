**W2617 · 2026-09-30 · Round two: the control plane is versioned and backed up, every cron job's exit code is recorded, and the open pain list is now a measurement.**

Round two of the 2026-09-30 corpus work: five mechanisms that make the defects visible instead of hopeful.

WHY ROUND TWO EXISTS. Round one audited 305 open pain entries, verified 297 against the live systems,
and fixed eight specific things. But most of what it found was the same shape over and over: a thing
that was supposed to happen did not, and nothing could tell. Round two builds the readers.

**1. `~/bin` IS NOW A GIT REPOSITORY (P2258).** 176 operator scripts, 271 tracked files, first commit
`d52a2dc`, bare remote at `/home/zabz/bin.git`. This is the directory that holds the wake sources,
every cron target, the only writer of the owner decision queue, the journal commit path, and the three
guards added today -- and until this commit it had NO history at all. A single accidental edit or a
copy-style deployment could destroy any of it with nothing to restore from, which is the same class of
accident that deleted five cron targets and a backup-retention script in the four days before.
Off-box replication is NOT done and is recorded as open.

**2. THE BACKUP DID NOT CONTAIN THE CONTROL PLANE.** Measured: `tar tzf
personal-secretary-code.tgz | grep -cE '(^|/)bin/'` -> 0. The hourly backup collected
`personal-secretary-mvp` and `quickbooks-agent` and nothing else, so 271 operator scripts and the whole
journal tree existed on exactly one disk -- the same disk that reached 100% on 2026-09-27 and 99% on
2026-09-30. A `control-plane.tgz` is now written alongside (322 MB: 172 operator scripts, 2,762 journal
entry files), and the script VERIFIES its own archive afterwards and exits 3 if the journal is missing.
The first version of that block named `/home/zabz/harness-config`, which is a SYMLINK, so tar stored
the link and the archive contained zero journal entries -- a backup that looked complete and was not.
Caught by the archive's own verification, which is why the verification is in the script and not in a
session's memory.

**3. `cron-wrap.sh` -- EVERY JOB'S OUTCOME IS NOW RECORDED.** cron's only output is a line in a
per-job log nobody opens, and this host has no `mail` binary, so a job that fails every single run is
indistinguishable from one with nothing to do. All 59 crontab jobs now run through a wrapper that
appends `<time> <name> <rc> <seconds> <stderr tail>` to `~/.cron-status/runs.tsv`. The command is
passed BASE64-ENCODED -- not for security, for quoting: these lines contain single quotes, backticks,
`$` and nested quotes, and every naive re-quoting is a chance to silently change what runs. The
installer verifies every payload decodes to the original line byte-for-byte before it touches anything,
and the old crontab is saved at `~/.cron-status/crontab.bak-wrap-20260930T161404Z`.
IT PAID FOR ITSELF IN THE FIRST TEN MINUTES: `journal-commit`, `converge-authority`,
`dialpad-recording-gap`, `mesh-placement-monitor` and the `sync` chain are all returning non-zero, and
none of that was visible an hour before.

**4. `pain-check.py` -- THE OPEN PAIN LIST IS NOW A MEASUREMENT.** 166 of the audit's verified entries
were rewritten by a fleet as executable checks (five files, `~/bin/pain-checks/C*.sh`), each printing
`<ID> TAB FIXED|LIVE|UNKNOWN TAB reason`. The runner runs them, compares against the journal's open
set, and writes `~/.pain-check/status.json`. First full run, 2026-09-30T16:30Z:
**FIXED 30 | LIVE 133 | UNKNOWN 3**, with 30 entries proven fixed and still filed open -- the debt that
grew to 52 in one afternoon in round one, now visible as a number. **27 of those 30 were closed from
the checks' own evidence.** The suite runs daily at 06:20 through the wrapper, and
`sources/pain-checks.py` files ledger work when the debt is non-zero or a check file breaks.

**5. THE AUTHORITY'S JOURNAL LINEAGE CONVERGED -- ON A BRANCH, VERIFIED, NOT YET LIVE.**
`converge-authority.sh` had been exiting 1 every 15 minutes with `[diverged] behind=38 ahead=26`,
which the wrapper made visible. Merge-tree named exactly seven conflicting paths: three generated
(`index/{entries.tsv,journal.db,stamp.json}`), `alloc/bands.tsv`, and three real wake-source mirrors.
Resolution rules, each with a check: the generated paths take origin/master (they rebuild); bands.tsv
is UNIONED (it records which host claimed which id range, and losing a side re-opens the id-collision
defect); the mirrors take the authority's copy and are then DIFFED AGAINST THE LIVE FILES THEY MIRROR
-- which caught that the mirror in git was a 2026-09-29 snapshot, fifteen thousand bytes behind
`checkout-health.py` alone. Refreshed and verified byte-identical. Result: **2,760 entries (more than
either side), `journal.py check` 0 errors, `idguard` 0 collisions**, pushed as
`integrate/authority-master-20260930T161751Z` (`afbe6eb`, then `3cd9f81`). THE LIVE CHECKOUT WAS NOT
MOVED: advancing the trunk is a separate decision.
