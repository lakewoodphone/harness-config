## A SMALL THING THAT MATTERED, AND A LESSON ABOUT SWALLOWED OUTPUT

My FIRST call to the tool reported `bash: line 1: Select-Object: command not found` and I read that as
the tool failing. **It had not failed — it had already written item 37 and raised wake 764.** The error
was in the PowerShell pipe I had added to shorten the output, *after* the remote command had done its
work. The second call then correctly deduped and told me item 37 was already open, which is how I
found out.

**Rule worth keeping:** a non-zero exit from a pipe is not evidence that the command at the far end
failed. Check the effect, not the exit code — the same discipline as the `journal.py append` that fails
silently (L3765), in the opposite direction.
