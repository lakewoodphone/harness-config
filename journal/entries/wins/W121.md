**W121 · 2026-09-14 · A health check returned 1,780 run records: ps_health cost ~100k tokens, now 27 KB.**

A health check was returning 1,780 run records: ps_health cost ~100k tokens per call

MEASURED on secratary 2026-09-15 -- this is pain P7's specific trap ("the MCP bridge returning
huge payloads"), and it was far worse than my own note about it.

 GET /autopilot/health 245,897 bytes on the wire (345,072 as indented JSON)
 health.subsystems 326,259 bytes as JSON
 recent_runs 295,615 bytes across 1,780 stored entries
 (the same subsystems WITHOUT recent_runs: 12,143 bytes)
 worst: boa_sync 32,166 bytes (50 runs), ebay_sync 27,275 (46), amazon_sync 27,109 (45)

ps_health aggregates that endpoint, so ONE health call handed a model 385,651 bytes -- roughly
100k tokens, an entire context window, spent on history nobody had asked for. A note of mine
from an earlier session said ps_health returns 90 KB; it was four times that by now, because
every subsystem keeps a rolling 50 runs and _record_subsystem appends one per record.

FIX, both paths. READ: health() returns each subsystem's summary plus the newest run, and
`recent_runs_total` so the history is visibly there-but-not-included rather than silently
missing; health(recent_runs=N) still returns it for a caller that wants it. WRITE: the stored
rolling log is capped at 10 instead of 50 -- the same 295 KB also sat inside
data/autopilot_state.json (386 KB), which _save_state() rewrites IN FULL on every record, so the
cap is a write-amplification fix too.

VERIFIED: /autopilot/health 245,897 -> 17,643 bytes, 13.9x smaller; ps_health 385,651 -> 27,350
bytes, ~100k tokens -> ~7k. Committed 33bc517e, seven tests.

NOTHING WAS LOST THAT ONLY LIVED HERE: scripts/sync-health-audit.py reads its own recent_runs
from a `reconciliation_runs` table, and the other callers (autopilot_contract, main.py) read the
summary fields. I checked each caller before changing the shape.

THE GENERAL POINT: an endpoint named for a QUESTION ("is this healthy?") should answer that
question. Returning the underlying state blob makes every caller pay for the largest consumer's
worst case, and the caller cannot tell -- it just gets a slow, expensive answer. When an
aggregate endpoint feels heavy, measure the payload by KEY, because the offender is usually one
field and the fix is usually one default.
