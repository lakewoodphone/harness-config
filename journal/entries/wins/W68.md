**W37 · 2026-09-14 · The filter's website went from "planned" to running, answering, and testing green in one round — by cutting the plan down.**

The owner said *"keep working"*, and the honest way to make that count was to force the first slice to be
**verifiable today** rather than architecturally perfect. Two flips did it:
- **Server-rendered pages instead of a Vite/React SPA** (D38-06). The SPA was a plausible house-style
 match; it would also have made the customer-facing surface the only part of this product with no cheap
 way to prove it works, on a repo whose entire test suite is Python. Reversing that assumption turned an
 unbounded front-end build into **33 tests passing in ~5 s**, with no browser and no npm step in CI. The
 JSON endpoints were written first, so the SPA is a later layer rather than a rewrite.
- **Start the app's state at construction, not in the lifespan.** My first cut wired everything inside
 `lifespan`; a bare `TestClient` never runs it, so 21 of 33 tests failed with `'State' object has no
 attribute 'sessions'`. The fix was to the *app*, not the tests: state exists the moment the app is
 built, so a test harness and a server start from the same place — and a missing piece of wiring can no
 longer masquerade as a request-time bug.
*It was then run and probed rather than assumed* — `/` 200, `/login` 200 with a real CSRF token,
`/onboarding` 303 signed out, and an unreachable broker producing `err=unavailable` instead of a false
"wrong password". Provenance for every number above is two commits and one command
(`cd web/server && python -m pytest tests -q --basetemp=./_pt` → 33 passed).
