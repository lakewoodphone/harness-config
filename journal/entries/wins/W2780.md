**W2780 · 2026-10-13 · cron-liveness.py: the check that finds a job which never ran.**

2026-10-13. Built the check that found all four of tonight's silent failures, and it immediately caught me
in a false positive.

THE FOUR, for the record, because the shape is the point: the tax calendar ran daily into a file nobody
read (P3010); the forward view was well built and had never been run (W2778); the CFO's ears matched owner
replies and nothing on a clock fed them (L3681); the marketplace sync documented its own schedule in its
header and had no crontab entry at all (W2779). **In every case the code was good and the connection to a
clock or a reader was missing, and in every case it looked healthy, because a job that never runs and a
job that runs correctly print nothing different.** `~/.cron-status/runs.tsv` has held the answer all along
- timestamp, job, exit, seconds, reason - and nothing ever asked it.

THE TOOL. `/root/bin/cron-liveness.py`. It reads the crontab for cron-wrap.sh jobs, reads the run log, and
reports NEVER RAN (scheduled, no run recorded - the most dangerous, because it looks installed), STALE
(last run older than its OWN cadence allows, read from the cron expression rather than assumed), and
non-zero exits. Read-only, exit 0 always. First run: 53 jobs, 51 with history, 5 never run, 0 stale, 4
non-zero. Three of the five never-run jobs were installed tonight by me and legitimately have not reached
their slot - which the tool now says out loud, beside the crontab's age, so a new job is not reported as a
broken one.

AND IT CAUGHT MY OWN FALSE POSITIVE IN THE SAME MINUTE. It listed `cfo-ask rc=3` as FAILING. It is not:
the log says "owner conversation open: he has not answered the message sent 3.49h ago; one at a time ...
refused before any network call. This is the owner's own rule." **The gate is working.** So the section is
now NON-ZERO EXIT, not FAILING, and each code is printed with cron-wrap's own reason tail beside it -
which is what `cron-wrap.sh` already insists on in its own header: "EXIT CODE: the command's own exit code,
always. A wrapper that swallowed it would be a new instance of the silent failure." A monitor that reads a
number and invents a meaning is that same failure wearing a dashboard.

STILL OPEN FROM ITS FIRST RUN, and NOT chased because they are outside the CFO: `ai-gateway-health rc=1`,
`pain-check rc=1`, `prune-backups rc=4`. Recorded here so the next session starts from the reading rather
than from the question.

**The two questions this estate never asks, and should ask nightly: for every capability, WHEN DID IT LAST
RUN - and for every artifact, WHO READS IT.** Every defect found tonight is one of those two.
