**W · 2026-09-14 · The largest single cause of company work failing was found by counting failure reasons instead of reading failure stories**

Reading the newest failed work sessions one at a time produced a plausible but wrong diagnosis
("the model is weak / the task is unactionable"). Grouping the failures by what their
`output_log` actually contained produced the answer in one query:

| reason | sessions |
|---|---|
| `[STALLED_REPEATING_OUTPUT]` | **270** |
| `repetition_guard_without_artifact` | 24 |
| artifact-other | 19 |
| other (mostly `STEP_BUDGET_EXHAUSTED`) | 361 |

674 failures in 7 days, 40% one marker. Following that marker to
`app/autopilot.py::_build_work_prompt` exposed a prompt instructing a syntax that
`parse_actions()` was configured to discard.

Keep this: **when many things fail, classify the failures before reading any of them.** The
aggregate is cheap, and it points at the mechanism; the individual stories point at the symptom.

**W · 2026-09-14 · A per-anchor refusal gate made a live-code port safe enough to do under production**

The port scripts refuse to write anything unless every anchor matches exactly once, and the
deploy runs an automatic rollback. That combination has now been exercised against reality
once: the first attempt conflicted, the compile gate fired, and the rollback restored

by hash before/after, `/health` 200x3). A deploy method that has survived its own failure is
worth more than a deploy method that has only ever succeeded.

**W · 2026-09-14 · Preserving a divergent working tree without moving HEAD**

`git checkout -b` plus a commit would have left HEAD off `master` and risked the switch back.
Instead the snapshot was built with a **temporary index**: `GIT_INDEX_FILE=/tmp/... git
read-tree HEAD`, `git add` the explicit paths, `git write-tree`, `git commit-tree -p HEAD`,
`git push origin <sha>:refs/heads/live-snapshot-<ts>`. Result: 28 paths and 2666 files
preserved on origin, HEAD still `master`, working tree unchanged (`dirty=52` before and after),
and a credential-named path deliberately excluded by an anchored filter. Reuse this whenever a
live host's uncommitted state must be saved without disturbing it.
