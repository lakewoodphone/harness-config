**W2760 · 2026-10-13 · Never lose an owner decision: the answer path writes the journal copy, and 14 lost answers were recovered.**

MEMORY GAP (a) CLOSED, both halves, 2026-10-13. "Never lose an owner decision."

THE GAP: `owner_decision_queue` is the single source of truth for what waits on the owner, and it is
a MUTABLE table -- `amend` can overwrite `answer`. The journal is append-only. **Nothing connected
them.** So a decision he had given lived in one cell, was lost exactly when the agent that recorded
it forgot to write the entry, and was lost SILENTLY, because the row still reads `answered` and
every check says the record is fine.

MEASURED BACKLOG: 488 rows, 67 carrying an answer, **14 with no journal copy anywhere.**

 * D3129-D3142 -- the backfill, via `journal/tools/reconcile-owner-answers.py`, which is dry-run by
 default, never writes to the queue, and is idempotent (the re-run reports 0 missing). Among the
 14: a 28,142.70 payment reconciliation, a customer quote (*"the total will be 6550 goes towards
 it"*), three customers whose texts were to be left unanswered, two bank-charge attributions, and
 two Kosher Waze approvals -- one of which is a single word, *"APPROVED"*.
 * `/root/bin/owner-queue.py answer` now writes the entry itself, so the durable copy exists BEFORE
 the row can be edited. Best-effort by design: if the journal is unreachable the answer is still
 recorded and the command says so. Applied as a patch that refuses on a missing anchor and backs
 up first (`scripts/patch-owner-queue-journal-copy.py`).

VERIFIED IN ISOLATION. A temp database and a temp journal tree, with `OWNER_QUEUE_JOURNAL` pointing
at the throwaway copy: the row became `answered` with his words and `D1` landed in the TEMP tree,
and the real journal's decision count was unchanged at 378. A test that writes to a real store is the
defect `secretary-wake` names; this one does not.

ALSO FOUND, AND IT IS THE SAME DEFECT AS P3164: the repo's `scripts/owner-queue.py` was **37,712
bytes against the deployed tool's 46,383** -- 8.7 KB behind the thing that runs. The repo copy is now
the deployed file. Third instance in two days of "the file I can edit is not the file that runs".
