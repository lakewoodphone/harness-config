**W137 · 2026-09-15 · The family hub number now has a carrier-level fallback webhook, so a tunnel outage no longer loses the family's texts silently.**

WHAT CHANGED 2026-09-15
Twilio hub number +17328009174 (AbleTel Solutions) had an EMPTY sms_fallback_url.
Twilio calls that URL only when the primary sms_url fails (5xx or connection
failure). With it empty, a Cloudflare tunnel or dashboard outage meant an inbound
family text was answered by Twilio with a failure and then dropped at the
carrier: nothing retried, nothing arrived, and nothing on our side could see it,
because the request never reached us.

Set sms_fallback_url to https://api.abletelsolutions.com/webhook/family-chat/sms
- a different public host from the primary (ai.abletelsolutions.com), confirmed to
serve that exact path (GET returns 405, i.e. the route exists and is POST-only).

Verified by reading the number back from Twilio afterwards:
 sms_url https://ai.abletelsolutions.com/webhook/family-chat/sms (unchanged)
 sms_fallback_url https://api.abletelsolutions.com/webhook/family-chat/sms (was '')
 status_callback https://ai.abletelsolutions.com/webhook/family-chat/status (unchanged)
 voice_url https://chaya.lakewoodphoneandtech.com/voice/incoming (unchanged)

Only sms_fallback_url was written. Reversal is setting that field back to "".

WHY IT IS A WIN RATHER THAN A CONFIG TWEAK
Nine of the ten family-related defects found today looked like a healthy system.
This one is different in kind: it is a failure that produces NO evidence anywhere
in our system, because the evidence is discarded by the carrier before it reaches
us. A fallback path is what makes that class of failure survivable.

STILL FRAGILE (not fixed, needs the owner or an infra change): if BOTH public
hosts go down, the fallback fails too. The remaining hedge would be a
Twilio-side voicemail/forward, or a second tunnel host.
