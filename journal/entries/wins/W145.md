## W — Six read-only audits + one adversary located a live production app I had never seen, in one pass

**What measurably worked.** An app running in production on `lpt-apps-01` was invisible to every repo
listing on this machine, and a previous session had recorded its source as "not found at the path the
master index cites". A single `journal.py search chumash` found it — which is the whole argument for
the journal existing.

Then: six read-only subagents partitioned by **file scope** (search/API, data/DB, gematria engine,
live UX, auth/security, build-deploy-docs), running concurrently in scratch with no writes, produced
~90 findings and 9 criticals in a single pass. A **seventh** subagent, whose only instruction was to
disprove the other six, refuted or narrowed nine claims — six of them mine.

**Why the partitioning worked.** Each auditor owned an explicit, exclusive file list, and the brief
named every cross-file boundary ("do not touch `db/**`; another agent owns it"). Because no two agents
wrote to the same path, there were zero conflicts to resolve in the audit phase, and the audits needed
no worktrees at all — scratch output only. Isolation was created by the manager, in the brief, before
anyone started.

**Why it was worth more than one thorough agent.** The findings that mattered most came from the two
auditors whose scopes looked least promising. The live-UX auditor found that **every year carries a
Gregorian label wrong by 7,520 years** and that **all 21 era-event rows (all method D's) are printed
under all four method cards** — a factual error at the heart of the product — neither of which any
code-reading agent flagged. The auth auditor found that **sign-in is dead for every user**. Both are
user-visible failures invisible in the source.

**The cost, stated honestly.** One auditor hit Next 16's per-directory build lock because a sibling
built the same checkout concurrently — a real, measured collision, fixed by giving every *builder* its
own worktree. Audits are cheap to parallelise; builds are not.

**Reusable shape.** Read-only audits need no isolation beyond an exclusive findings file. Builders
need a worktree each. Never mix the two phases in one directory, and never assume "no writes" means
"no conflicts" when a build is involved.
