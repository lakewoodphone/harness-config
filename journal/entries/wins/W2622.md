**W2622 · 2026-09-30 · The right instrument for what we pay for: grep the DECLARED config field, not the env var name - and it names one retirement candidate.**

2026-09-30 round 27. Round 26 established that a by-name grep for an uppercase env var produces false negatives, because pydantic-settings maps a field named tavily_api_key to TAVILY_API_KEY by convention and the literal uppercase string appears nowhere. The replacement instrument is the DECLARED CONFIG FIELD, and it is now proven both ways on the authority. app/config.py declares fields at lines 165 to 182 for openai, anthropic, google, groq, xai, mistral, cohere, together, deepseek, deepinfra, fireworks, minimax, perplexity, exa, moonshot and azure, and at lines 237 to 239 for tavily_api_key, brave_search_api_key and serpapi_api_key. So the literal NAME does exist in the source - in lowercase, as the field - which is exactly why the uppercase search missed it. Measured for six providers: tavily declared=1, exa=1, brave=1, serpapi=1, qwen=0, spider=0. TAVILY IS CONFIRMED USED, closing the question from round 26. QWEN_API_KEY HAS NO DECLARED FIELD and its only mention in the whole application is research_openrouter_qwen3_model, an OpenRouter model id rather than a Qwen credential, so it is the first defensible RETIREMENT CANDIDATE found - stated as a candidate and not a certainty, because whether it is paid is a question for the provider dashboard and a credential can be live on the provider side with nothing here to use it. SPIDER declared=0 is expected: added today, nothing wires it yet, and wiring it is the next step. CARRIED FORWARD: this instrument has been sent to the agent building the capability registry, with the instruction to derive a DECLARED flag from the field name and to state which test produced each verdict - a registry that concludes unused from a text search would repeat the exact error that nearly produced a wrong cancellation list.
