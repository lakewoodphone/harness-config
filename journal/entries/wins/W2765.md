THE BACKFILL, and it writes through the ingest's OWN writer rather than any SQL of its own.
`/opt/company/scripts/marketplace-backfill-totals.py`:
 1. reads stored orders where `total_amount is null` and `parse_note` is not a notification and
 `gmail_message_ids` is non-empty - every input it needs was already on the row;
 2. re-reads those message ids with `marketplace_order_sync.read_bodies` (the same reader the clock
 uses), builds `MailMessage` objects, and re-parses with `receipt_parser.parse_receipt_email`;
 3. folds with `marketplace_order_sync.fold_records` and writes with
 `marketplace_order_sync.upsert_orders`.
Nothing bypasses the ingest's own rules, and `upsert_orders` is the reason this is safe: it refuses to
let a weaker record move the money (`rank_ok = new rank >= stored rank`), which is exactly the
protection a backfill needs. It is dry-run by default and applied with `--apply`.

WHAT MADE THIS POSSIBLE, and it generalises. The bug was ONE character class - `^Order Total` versus
`^[^\S\n]*Order Total` - and no amount of reasoning over rows would have found it. It was found by
reading the actual email text, which took four wrong calls to `read_message` before it would answer:
positional `settings`, keyword-only `message_id`, a real `account`, and then the WORKING DIRECTORY,
because `/root/personal-secretary-mvp` is a symlink to `/opt/company` and the token path resolves
relative to it. Three separate rounds now have ended with the same shape: the code was right, my call
was wrong, and the false result was convincing. **When a whole capability looks broken, the first
suspicion belongs on the invocation, and the check is a print of what the parameter actually
resolved to.**

A NOTE ON THE FIX ITSELF. `^[^\S\n]*` still requires the label to be the first non-whitespace on its
line, so it cannot start matching mid-sentence - which is why this is a correction and not a loosening.
Five patterns were corrected together (the four label patterns plus the legacy `AMAZON_TOTAL_RE`)
because leaving one anchored at column zero would reintroduce the same silent gap the first time a
caller used it.
