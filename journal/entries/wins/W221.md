**W · 2026-09-20 · Five stranded fleet branches were recovered, verified and merged into one green tree - and the merge caught a defect no single branch could see.**

The state on arrival: the CFO books repo had **eight fleet branches from a 2026-09-17 fleet that was cut
off before integration**. Five of them held real work (WS1 chart of accounts, WS2 ingest, WS5 audit, WS6
personal, WS7 tax), **two of them with uncommitted working-tree changes** from agents that were killed
mid-write - i.e. work that existed in exactly one place on one laptop and nothing else.

What the manager did, and what it bought:

| Step | Result |
|---|---|
| Committed the uncommitted working-tree state on `fleet/ws2-ingest` and `fleet/ws6-personal` first | 27 files, ~1,000 lines that would otherwise have been lost |
| Ran **every branch's own suite from its own worktree**, itself | 48 + 33 + 81 + 27 + 78 = **267 passed**, 7 skipped, 0 failed - so all five were real |
| Checked the real conflict surface before merging: files touched by more than one branch, and any touch of a frozen file | **NONE, and no frozen file touched** - the partition held |
| Merged in risk order (foundation, then new isolated directories, then the shared test infra) | five clean merges, no conflicts |
| **Re-ran the merged suite** | **1 failed, 266 passed** - and the failure was invisible from either branch |

The failure, which is the whole point of the exercise: `test_accounts_opening_warns_on_an_unopened_account`
went red. WS5's test asserted `lpt-amex-business-gold-1005` had "no documented opening" and used it as the
fixture for the WARN. WS1 then **derived a real opening for that account**, so the check correctly stopped
warning. WS5 passed 81/81 alone; WS1 passed 48/48 alone; together they were wrong. Fixed by moving the
fixture to `lpt-stripe`, a clearing account whose NULL opening is documented in `coa.OPENINGS_LEFT_NULL`.
**This is the concrete measured case for the rule "never merge a branch whose combined suite you have not
run yourself" - branch-greenness is not transitivity.**

Two more things came out of running the merged tree against **real data** rather than fixtures:

- The first real ingest **died on one CP1252 byte** and cost the whole legacy seed
 (see the CP1252 lesson). No unit test in any of the five branches could have caught it.
- A second real defect surfaced in the WS2→(authority) path: 5,039 of 5,600 legacy categorisations name a
 category the books chart does not have. That is not a crash, it is the next workstream's queue - and it
 is now a number instead of a suspicion.
