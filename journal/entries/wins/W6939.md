**W — 2026-10-18 · The queue closes its own loops and there is one ranking again**

Two gaps from H7722, both closed and both proven by running the thing rather than reading it.

**1. A resolution now retires the alarm it refers to.** `reconcile()` in the mail ingest: a later
message from the *same sender identity* (full address for freemail, domain for a company), newer than
the row, whose text says the problem is fixed, resolves a pending `attention` row that reads like an
alarm. It never touches a decision — those stay his, with `POSSIBLY MOOT` on the card instead. Every
close records its cause, e.g. `auto-closed: portal@telnyx.com said "Telnyx account re-enabled after
payment" (2026-10-13)`.

The case that forced it: Telnyx's "balance is -$0.01, services will be suspended" sat at **critical,
rank 1**, for two days *after* Telnyx wrote "account re-enabled after payment". Both facts were in
the mailbox; nothing connected them. On the 14-day corpus the rule proposed **exactly one** close and
no false ones, so it is not guessing.

**2. The daily phone digest reads the one queue.** `owner_attention.py` read `owner-queue.py list
--json`, which is decisions-only by design — so every text, call, voicemail and email item was
invisible on his phone, and the digest ranked its own narrower set. It now reads `queue --json`.

Three parser defects surfaced, **all of them only by executing it**:

* `int(id)` on the sort key — the one queue also carries held app rows (`m2631`) and agent questions,
 so the first real run died with `ValueError: invalid literal for int() with base 10: 'm2631'`.
* every item had `" Yes?"` appended, because the relay only opens a reply turn when the body ends in
 a question mark. Correct for a decision; nonsense for news, and the dry run printed it:
 *"Chase: overdraft or declined transaction on account ...9730 Yes?"*. News now asks
 `" Want details?"`.
* `kind` never reached the composer at all, so the tail question could not tell them apart.

Verified with `send --dry-run` (prints the exact body, sends nothing) plus a unit check of the tail
question. The patch lives in `harness-config/scripts/owner-queue/patch-attention-digest.py`, written
as literal replacements **plus an asserted end state** — its first version refused to run once an
earlier replacement had altered the text a later one looked for, which is the general shape of a
migration script that works once and never again.

What is left on this queue: one knock-through session with him. Nothing has been answered or dismissed
yet, so the learning loop is built, proven on a scratch copy, and **still has no data**.
