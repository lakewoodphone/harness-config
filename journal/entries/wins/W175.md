**W175 · 2026-09-16 · harness-verify.ps1: the program's invariants as an executable check - 9/9 green, and commit went 36-39 GB to 21.8 GB with hard faults 600-2400/s to 18/s.**

## Why a verification script is a deliverable, not housekeeping
Between 2026-09-15 and 2026-09-16 this harness changed in ways that are **silent when undone**:

- the journal lock became an OS lock — a re-added `unlink` reintroduces a race that once produced
 161 collided ids with no error;
- the preset's MCP rows moved from `npx.cmd` to a direct `node` path — one regeneration without
 the generator being updated reverts them, and the symptom is only "the machine got slow again";
- the preset became GENERATED, which is exactly how two owner rules were deleted from the live
 system prompt today by a regeneration I ran after ignoring `--check`;
- the reaper must exist as a scheduled task, or discarded process generations accumulate to the
 ~2-3 GB that was measured;
- `sync.py` must install client plugins, or a plugin package silently misses a machine;
- memory commit must stay under physical RAM, because 36-39 GB of 31.6 GB is the condition whose
 symptom is "everything froze" while CPU reads a harmless ~65 %.

A change that looks applied is not applied. `harness-config\scripts\harness-verify.ps1` checks the
FACTS and exits non-zero when one is false. Read-only; it starts nothing, stops nothing, writes
nothing; `-Quiet` prints nothing on success so it can be run from a timer.

Two of those numbers are the whole program in one line: commit was **36-39 GB** and hard faults
**600-2,400/s**; they are now **21.8 GB** and **18/s**.

## A deliberate design choice in the engine check
It does **not** say "there must be exactly one engine". An isolated second engine with its own
`DSH_HOME` is a legitimate way to test a composition change — it is how the plugin work is being
verified right now — and a check that fails during legitimate development is a check people stop
believing. What must never happen is **two engines on one `DSH_HOME`** (the documented
duplicate-sequence corruption), so the check asserts the observable invariant — the primary port
has exactly one listener — and *reports* every other engine with its port and the reminder that it
needs its own home.

## First thing it caught
Running it found `engines=2`, which my earlier one-line assumption ("there is one engine") had
made invisible. That is the point of writing invariants down as executable checks: the discovery
took one command instead of a "why is this slow again" investigation three weeks later.
