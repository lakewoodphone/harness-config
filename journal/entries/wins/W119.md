**W119 · 2026-09-14 · The thrash generator: two invisible closure gates, with the rule documented in the wrong surface.**

The thrash generator: two invisible closure gates, and the rule written in the wrong surface

MEASURED on secratary 2026-09-15. Task #25163 ran twice, same task, same budget:

 75426 FAILED 11/11 steps 5-11 = [update_task] x7, each refused, until the budget died
 75427 COMPLETED 11/11 and it says how it escaped: "The prior update_task calls failed
 because the task is only ~1h old and needs force='true'."

`_exec_update_task` refuses a closure in two cases, neither discoverable from the work prompt:
age < 48h, and status in_progress with age < 7 days. Practically EVERY task these sessions work
is younger than 48 hours, and a task being worked is in_progress -- so both gates apply to the
ordinary case, and the ordinary closing call is refused. A refused update_task still looks like a
mutating action, which is how these sessions collected budget extensions while retrying it.

THE RULE ALREADY EXISTED, IN THE WRONG PLACE. The individual `close_task` TOOL description
states it exactly: "tasks < 48h old OR in_progress tasks < 7 days old cannot be closed unless
force='true' is passed. Always pass force='true' when closing stale, duplicate, or superseded
tasks regardless of age." The work prompt -- the surface that tells these sessions to call
update_task(status="done") -- never mentioned it. The sessions were steered into the gated path
by instructions that omit the gate.

FIX: the work prompt now states the rule, including the sentence that actually stops the loop --
that calling again without force will keep failing. No gate is relaxed, and
_task_close_would_be_a_lie still refuses a completion whose only evidence is failure. Committed
da83fc60, 26 tests across the prompt suites.

THIS EXPLAINS THE SPINNERS GENERALLY, not just #25163: it is why 75415 could repeat
[list_tasks, update_task] nine times, why 75419 and 75426 ran [update_task] seven times, and why
these tasks were re-claimed over and over -- the session finished its work, could not close, and
died. The earlier work in this session treated the SYMPTOMS (extensions gamed by repeated
actions, retry thrash); this is the cause underneath them.

FOLLOW-UP, NOT DONE: the 48h gate is now partly redundant. It refuses purely on age, while
_task_close_would_be_a_lie refuses on evidence (no active session, recent failures, no
successes) -- a better rule. Relaxing the age gate would remove a surprise from the model's path
entirely, but it is a safety guard with its own history and should be measured after this prompt
fix, not before.
