THE THIRD QUESTION, now with evidence. Ten silent failures tonight were found by asking when a capability
last RAN and who READS its output. Two more - the marketplace sync and these nineteen modules - were found

AND A DISTINCTION WORTH KEEPING, because the obvious version of this is wrong. "Commit everything
uncommitted" would have swept 39 files carrying someone else's unrecorded judgement into a new baseline,
which loses information rather than saving it. The principle is not tidiness, it is **whether a record
already exists**: an untracked file needs one created, a modified file needs its author to decide. The same
reasoning that says "do not commit what you cannot account for" says "do commit what has no account at
all", and tonight both applied in the same directory.
