**His bar, verbatim, 2026-10-14:** *"every single amazon and ebay, and almost every other online merchant should be found in my emails — almost everyone online emails you when you buy something from them ... so if you arent getting 90 percent coverage on your online stuff then something is wrong."* And: *"lakewoodphoneandtech@gmail.com has a bunch of other emails forwarded to it like info@lakewoodphoneandtech.com and a bunch of others."*

**53 of the 56 merchant domains have no `purchases` rows at all, and for 51 of them no source row is even possible** — the table holds only `amazon`, `ebay`, `deviceparts`, `globaldirectparts`. Fully uncovered, by name: Home Depot, MobileSentrix, US Mobile, Newegg, B&H, DigiKey, Mouser, AliExpress, Alibaba, LaptopScreen, InjuredGadgets, Simplified Building, Pirate Ship, Hetzner, Dialpad, Kyocera, VisionTek, x.ai, Stripe-billed SaaS. **So this is not a parser that fails on some merchants; it is a pipeline that was pointed at two of them and reports healthy.**

**The forwarding question is answered, and the answer is the opposite of the obvious worry.** Forwarding **preserves the original `From:`**, so `from:<merchant>` search works — verified on real mail: `from:toasttab.com newer_than:90d` returns exactly one message, `To: info@lakewoodphoneandtech.com`, `From: no-reply@toasttab.com`. What matters instead is that **the mailbox answers to six addresses**, and a `to:info@…` search alone catches **4 of 585** receipts. **A query keyed on the wrong field would have looked like a coverage problem while the `From:` field was fine**, which is exactly the class of error this session has made four times.

**AND A CORRECTION OF MY OWN REPORTED FIGURE.** I told the owner eBay was the healthy side at *"97.7 % of rows carrying items"*. Measured: **eBay's 3,934 rows resolve to only 290 distinct emails** — one email produced **58 rows**, and **3,644 rows are duplicates** produced by an old salted-hash `order_id`. So the row count is ~13x the real order volume, and the 97.7 % described duplicates. **A row count is not a measure of coverage, and I reported one as if it were.** The child also found that 0 of 146 in-window eBay emails carry an eBay order number, so eBay is excluded from both sides of the fraction — stated rather than invented.
