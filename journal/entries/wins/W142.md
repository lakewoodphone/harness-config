## W-AW - The rentals backup has been restored once, on purpose (2026-09-15)

**What was true before.** Nothing backed up the rentals database at all. The nightly job
(`/root/lpt-apps-backup.sh`, cron 35 3 * * *) dumped every Postgres container and copied `/opt` config
files into restic on Cloudflare R2, but the app keeps its data in a Docker volume as SQLite, and that
volume was in no backup anywhere. The audit's OPS-1/OPS-2: no backup, and no restore ever performed -
a backup that has never been restored is a hope, not a backup.

**What is true now, with evidence.**
1. The job snapshots the volume with `VACUUM INTO` through the app's own `node:sqlite`, checks the
 snapshot has tables, and fails the whole run if it does not. A plain file copy would have been
 worse than nothing: in WAL mode the schema can live entirely in the `-wal` sidecar, so copying the
 `.db` alone yields an *empty database that looks like a successful backup*. The live file was
 literally 4 KB with a 498 KB WAL when I found it.
2. The job also now asserts the set is not empty (>= 6 files, plus the rentals snapshot when
 `/opt/lakewood-rentals` exists) before it may report success; previously an empty sweep still
 logged "Backup complete" and exited 0.
3. I ran the job: `sqlite: lakewood-rentals -> sqlite-lakewood-rentals.db (13 tables)`, restic
 `20 snapshots`, `no errors were found`.
4. **I restored it.** `restic restore latest` to `/tmp/restore-drill-*`, then verified the restored
 file with the app's own engine: `tables=13 rows=0 integrity={"integrity_check":"ok"}`; then ran the
 real production image against the restored copy on a throwaway port - `/api/health` 200 and the
 board page 200 - while `https://rentals.lakewoodphoneandtech.com/api/health` stayed 200 throughout,
 i.e. the live service was never touched.

**Still open, and honestly so:** the drill restored the *current* snapshot, which contains an empty
database, so it proves the mechanism and not the recovery of real rows; and the restore script on the
box (`lpt-apps-restore.sh`) still has no rentals branch - the drill was driven by an ad-hoc script.
Both are in the ops workstream's brief.
