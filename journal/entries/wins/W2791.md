2026-10-13. Tonight's lesson is now in the repository, on main, for every future session - and getting it
there found one more instance of the thing it is about.

WHAT I WROTE. `harness-config/docs/silent-failure-checks.md`, committed to main as c6d329d. It states the
three questions that found twelve defects in one session, each with the command that answers it:
 1 When did this capability last RUN? -> cron-liveness.py. A job that never ran and a job that runs
 correctly print nothing different.
 2 Who READS this artifact? -> grep the tool surface for the filename.
 3 Is it IN THE REPOSITORY? -> git status --porcelain | grep '^??'
plus the two about evidence - is the measurement INDEPENDENT of the thing it tests, and is the value
IMPOSSIBLE (a deposit account cannot be negative; that one invariant reconciled a savings account with 22
impossible months).

AND THE DISTINCTION THE THIRD QUESTION NEEDS, because the obvious version of it is wrong. Commit what has NO
record: untracked modules, because committing one CREATES a record. Never blind-commit what has a baseline:
39 modified files, left alone, because committing those blends changes nobody described into a new one.
"Commit everything" loses information; "commit what has no account at all" saves it. The doc says so, and
the reason is recorded with it.

AND IT ENDS WITH THE THING MOST EASILY FORGOTTEN. Six of the twelve apparent defects were FALSE ALARMS -
four were two fields meaning two things, or a lagging tail. So the last section is not a fifth question but
a warning: **read the artifact's own docstring or the code that produced the reading before proposing a
change.** `AGENTS.md` section 0 already says it - "prove it does not already exist" - and the freshness
source proves the point by being a better answer than mine would have been.

AND GETTING IT ONTO MAIN FOUND THE PATTERN ONE MORE TIME. My first commit landed on
`hk/28-refresh-deployed-sources-20261013`, because that is the branch the checkout is sitting on - so the
file was committed, tracked, and invisible to `main`, to `remotes/origin/main`, and to every other machine.
**Committed and unreachable is the same failure as written and unread, one level up.** Landed it on main
through a temporary `git worktree`, which touched nothing in the branch's own tree - deliberately, because
that tree carries someone else's uncommitted `AGENTS.md`, and the whole point of the untracked-versus-
modified rule is not to blend changes I cannot account for.
