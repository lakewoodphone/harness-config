**L1642 · A representation is not the value: a missing log line, an aggregate age, and a capped list all lied in one session**

**A representation is not the value -- three times in one session, and each time it was the
representation that lied.**

Measured 2026-09-15, same day, same agent, three separate conclusions drawn from something that
merely *stood for* the number:

1. **A missing log line is not a missing subsystem.** `INFO Lifecycle sweep complete` stopped
 appearing; I concluded the sweep was dead and built two diagnostics for it. The sweep was
 running every 120 s. The representation (the journal) had stopped carrying the value because
 the application's logging was never configured. (L1639.)
2. **An aggregate age printed beside a subset count is a wrong number.** My own new line said
 "2 critical message(s) held, newest 0.1d old" -- the age came from the newest held row of any
 urgency (the evening briefing) beside a count of criticals that were 5.9 days old. (L1641.)
3. **A capped list is not a count.** `journal.py list --kind pain --status open` printed 50 rows,
 and I took 50 for the number of open entries; it was the display cap against 91 real ones. That
 one almost made me "fix" a correct number -- I was two minutes from changing the page from 95 to
 50 when the tool's own resolver said 91. (The 95 really was wrong, but for a different reason:
 three callers counted marker status instead of effective status, so the four `superseded` entries
 were open work forever.)

The rule, stated so it can be applied: **before acting on a reading, ask what produced it and what
it can hide.** A log line is produced by a logger (check its config), an aggregate is produced by a
set (check which set), a list is produced by a cap (check the header line, which said `# 91 entries`
while showing fifty). Two of these three cost real time; the third would have introduced a wrong
number into the one page every session reads. The common failure is not carelessness about the
data -- it is trust in a faithful-looking proxy for it.
