**L1736 · Ask the artifact, never the document: three deploy paths, three truths**

EVIDENCE: 2026-09-16, ZABZ-YOGA. Auditing where the LPT build was holding produced a finding nobody would have guessed from the git graph: production was already running unpromoted code, from three different sources, and the deploy history said otherwise.

- The prod API container is a hand-patched image. /opt/lpt/src has ZERO git refs; `git rev-parse HEAD` prints nothing. An image tagged priceguard-20260915-222840 contains a dist dated Sep 10. There is no commit to report for production because there is none.
- The prod frontend was uploaded by scripts/deploy-frontend-cloudflare.mjs, which passes --branch from a HARDCODED map ({test:'test', production:'main'}) plus --commit-dirty=true. Cloudflare therefore records `branch=main commit=44c99ea07` for a deployment built from 44c99ea07, a commit that is NOT an ancestor of main (`git merge-base --is-ancestor` false; it is on test).
- main was 102 commits BEHIND test, so promoting main could not have shipped anything; and no PR had ever targeted main in the repository's history. The gate existed, permitted test as a head branch, and had run exactly once, and that attempt was abandoned 104 seconds later into a PR that merged to test instead.

THREE RULES EARNED:
1. Ask the artifact, not the document. `git rev-parse HEAD` on the deploy tree, the image's labels, and the live bundle's contents are the truth. Three published docs disagreed with the running system in this one audit, in both directions.
2. A deploy tool that hardcodes its own provenance is worse than no audit trail, because it makes the trail authoritative-looking and false. If the branch/commit label cannot be derived from the tree being built, omit it; never forge it.
3. A dirty-tree deploy flag (--commit-dirty=true) turns every other agent's working tree into a release candidate. On this machine the main checkout is also the build source for production, and a sibling agent had 10 uncommitted files in it. Isolation is not tidiness here; it is the difference between a test and a customer's site.
