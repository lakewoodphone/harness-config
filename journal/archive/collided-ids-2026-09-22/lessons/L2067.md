**L · A session that finishes work and raises no flag has not finished — it has abandoned. The reactivation half existed and I never used it.**

MEASURED 2026-09-20, after the owner came back and said plainly: *"I don't want to ever see this level of
stalling again … the whole point of you being truly autonomous is you being able to reactivate yourself. I
don't want to have to keep monitoring you enforcing you back to work."* He is right, and the mechanism is
specific and entirely mine.

WHAT WENT WRONG, IN ONE LINE: the work was done **in-session**, the session ended, and **no flag was
raised**, so the always-on half never knew there was anything left. Everything else follows from that.

AND THE MACHINERY WAS ALREADY THERE AND WORKING. Verified rather than assumed:
- `wake-dispatch.sh` runs from cron **every 5 minutes** and its log shows a release at 2026-09-19T04:16:57Z;
- `wake.py stats` reports `new=1 claimed=0 done=6 failed=0`, `released today: 0/8`, caps in force: none;
- the cross-machine selftests (`selftest-wake-chain`, `selftest-crossmachine`) are `done`;
- `run-wake-sources.sh` runs five sources every 15 minutes and writes a sources heartbeat.

**So nothing was broken. I simply never raised a flag.** A system that can revive a session is worth
exactly nothing if the session that has work does not tell it.

WHAT WAS BUILT, so this is structural rather than a promise:
`scripts/wake/dormant-handoff.py` (deployed to `/home/zabz/bin/sources/` and registered in
`run-wake-sources.sh`) — a flag source with **two independent signals**, because "unfinished" has two
shapes:

1. **The newest handoff is old.** It reads the highest-numbered entry **from `origin/master` via git, never
 from the working tree** — and that correction was forced by measurement: its first dry run read `H479`
 from 2026-09-17 out of the authority's stale clone while `H603` existed upstream, and would have raised
 a flag about the wrong work, forever, while looking exactly right on the machine it ran on. **The same
 "your checkout is not the base" fault that cost two patches on 2026-09-18 (L2066).** It also refuses to
 guess a date: the headers carry `2026-09-17 16:15 UTC`, not ISO, and the first version printed
 `SIGNAL UNREADABLE` rather than treating an unparsed date as fresh.
2. **The session archive has stopped advancing.** `~/dsh-archive/dsh-archive.db` exists so that *"no
 conversation is ever only on one laptop"* — and its newest `dsh_sessions.updated_at` is
 **2026-09-11**, nine days stale, with every session since single-homed. **Nothing reported it, because
 an archive that stops looks exactly like an archive with nothing to do.**

Both are honest about firing: on the first real run it flagged the archive stall and stayed **quiet** on
the handoff, because the newest handoff was only 1.7 days old against a 3-day threshold.

AND THE WORK ITSELF IS NOW REGISTERED: `mesh-offload-program:2026-09-18` was filed with a full, standalone
prompt — what is done, what is unfinished in priority order (the placement-nonce patch waiting to be
applied, R2's result to record, `P331(a)` still open), and the instruction to raise new flags rather than
leave anything in a chat session.

THE RULES:
1. **Finishing the work in a session is not finishing it.** If the outcome has to survive the session, it
 must be written where the always-on half can see it — a flag, a standing work order, a journal entry.
 Anything else is a draft.
2. **When you stop, write a handoff — and if there is work left, raise a flag for it in the same breath.**
 The handoff is for the record; the flag is what actually revives you.
3. **A quiet system is not a healthy one.** The archive was nine days dead and reported nothing; the flag
 store was empty because nobody filed. Liveness is a heartbeat being *recent*, never a queue being short.
4. **The same "which tree is the truth" rule keeps recurring** — `git apply --check` (L2066), `repair-ids`
 (L2064), `node -v` (L2000), and now a flag source reading a stale clone. Read from the authority, or
 from `origin/master`, or it is a guess about a copy.
