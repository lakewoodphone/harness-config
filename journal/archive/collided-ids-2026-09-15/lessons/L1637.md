**L1637 · MCP Playwright: context reuse inflates CLS, and pre-hydration clicks fake 'nothing changed'**

Two MCP-Playwright traps that fabricate numbers, both hit today on the chumash-ui workstream:

1. The MCP browser context PERSISTS between browser_run_code_unsafe calls. An addInitScript that counts layout shifts installs again on every run, so a second run double/triple-counts CLS. Measured "CLS 0.35" and "0.65" that were nothing but duplicate observer pushes. FIX: open a fresh context inside the script - page.context().browser().newContext() - and close it at the end. Every number in the chumash report was re-taken that way (real CLS 0.0724 -> 0).

2. Clicking before hydration silently does nothing, and the resulting "nothing changed" reads like the bug you are hunting. A 250ms wait after domcontentloaded returned the PRE-hydration default for all 7 hero years (identical readings were the giveaway). FIX: wait for a state that only exists after hydration (text that comes from fetched data), or wait ~4-5s in Next dev, and assert a post-condition after each interaction.

Corollary for the fleet: an interaction harness must prove it interacted. Identical before/after readings are evidence only if the click demonstrably ran.
