## 2026-09-16 00:53 UTC · ZABZ-TECH · Chumash Timeline audited, fixed, deployed and verified live - main 72a7eaa on lpt-apps-01

## H — Chumash Timeline: audited, rebuilt, deployed, verified live (2026-09-15/16)

**Scope.** `github.com/lakewoodphone/chumash-timeline` — audited, fixed across seven parallel
workstreams, integrated, and deployed to `lpt-apps-01` behind
`https://chumash.lakewoodphoneandtech.com`. The app maps the Torah's 5,846 pesukim onto ~6,000 Hebrew
years under four traditions, with a gematria calculator and four search modes.

**CHANGED**

- **`main` is at `72a7eaa`, deployed and healthy.** Host `/opt/chumash-timeline` pulled, migrated,
 container rebuilt. `main` went from 36 to **301 tests**; typecheck 0, eslint `--max-warnings=0` 0,
 `next build` 0.
- **Data (the biggest visible change).** A JPS 1917 public-domain translation, a parsha map, and
 persisted gematria columns now ship for all **5,846** pesukim, from committed data files — the app
 previously had **zero** translations and **zero** parsha.
- **The Hebrew corpus was contaminated and is now clean.** An HTML tag-strip had left Sefaria's inline
 annotations *inside* the verses on 1,082 rows, which made gematria wrong on **716** of them. Fixed;
 `global_index=5224` is now 4099 (was 5461). The Masoretic `{ס}`/`{פ}` markers and 64 editorial notes
 are preserved as data rather than deleted.
- **Method D was showing the wrong parsha for today's year** — it returned `Devarim 32:19` (Ha'azinu)
 under the label "Nitzavim-Vayelech". Now `Devarim 31:21`, inside Nitzavim-Vayeilech, and every year's
 verse falls inside its own labelled century (14-year sweep, 0 violations).
- **Sign-in works for the first time.** It had never worked: the SSO base URL pointed at the Vite
 frontend (which 404s every `/api/*`), and the app held the *test* backend's shared secret while
 production expected a different one. Fixed on the host per the owner's instruction (point at the
 correct existing secret, rotate later). `/api/health/sso` now reports all five checks `ok`.
- **The gematria engine is honest.** 3 of the 11 advertised systems were mislabelled and 4 formed 2
 identical pairs; `boneh` used the wrong formula (`אחד` gave 84, published bone'eh gives 23);
 `numberToHebrew(1.5)` returned the string `"undefined"`. All fixed, with a hand-computed reference
 vector for every one of the 11 systems and an 11×11 duplicate matrix asserting **zero** identical
 pairs over 551,880 synthetic and 75,559 live inputs.
- **The interface tells the truth.** The hero Gregorian label was wrong by 7,520 years; era events
 were printed under all four methods; Hebrew rendered left-to-right so `שלום` displayed reversed;
 zero search results rendered nothing at all; translation and parsha had no element and no
 placeholder; every route overflowed horizontally on mobile. All fixed and measured in a browser.
- **Deployment is reproducible and carries no secrets.** The committed compose previously described a
 database and no app; the running definition existed only as an uncommitted host edit. Now committed
 and field-for-field equal. The shipped image contained `/app/.env` (412 bytes: `DATABASE_URL`,
 `LPT_SSO_SHARED_SECRET`, `CHUMASH_SESSION_SECRET`); it is gone, verified by `ls: /app/.env: No such
 file or directory`. Also: healthcheck, log rotation, `.dockerignore` (build context 681 MB → 680 KB).

**IN FLIGHT / KNOWN GAPS**

- **Free-text search costs 130–413 ms** (measured on production). A GIN trigram index was proposed
 with a claimed ~900x improvement; I tested it and it does not work — see
 `text-search-index-finding.md`. Reverted, not shipped. A real fix needs a stored stripped column or
 a `tsvector`.
- **Method D reaches 860 of Devarim's 956 pesukim**, and cannot reach more: a century is 100 years and
 six units are longer, so ≥96 are unreachable by arithmetic. Fixing it means moving the 1840/1940
 anchors — the owner's call.
- **A real end-to-end Google login is unverified** — it needs a human. Everything up to and including
 the assertion endpoint is verified.
- `npx next dev --webpack` no longer builds this tree (`src/lib/sso-config.ts` imports `node:crypto`,
 which webpack rejects). Turbopack works and is the documented build path.

**BROKEN** — nothing. The site was healthy before and after; no user data was touched
(`feedback`/`submissions` are both 0 and survived every seed run).
