**D3044 · 2026-10-11 · Card copier design decisions, 2026-10-11: exe over script, size+mtime default, repair before reporting.**

Decided 2026-10-11 while rebuilding the customer-data card copier, all of it dev-level and
therefore recorded rather than asked about.

1. **The card carries a compiled exe, not a script.** A TAG-filtered customer machine can
 block PowerShell or script execution from removable media; `GO.EXE` (C# 5, .NET
 Framework 4.0, built by the csc that ships inside Windows) needs nothing installed. Note
 `subagent`-free: this is one artefact, built and tested serially.
2. **`GO.BAT` + `lpt-copy.ps1` stay on the card as the fallback**, and were themselves
 fixed for the same two defects (stable job folder, size-based verification). Third route
 if both are blocked: a hand-typed `robocopy` line, in `READ-ME-FIRST.txt`.
3. **Default verification is size + timestamp, not sha256.** Hashing 35GB twice turns a
 hand-over into an overnight job. `--deep` exists for when the data matters more than half
 an hour, and the limit is written down rather than hidden: a same-length corruption with
 the timestamp already fixed is invisible to the default check.
4. **A verification that finds a problem repairs it before reporting failure.** Reporting is
 not fixing; the exit code still reports honestly if the repair does not work.
5. **No prompt, no cancel window.** "One click and done" was an explicit requirement: `Esc`
 at any time is the only interaction, and it leaves the ledger intact.
6. **The tool adds to a card and deletes nothing, anywhere, ever** — no `Remove-Item`, no
 temp file, no purge. It also never writes to the source machine.
