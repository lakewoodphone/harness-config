**L3441 · a launcher in ~/.local/bin is not runnable by name over ssh - Ubuntu's ~/.bashrc returns early for non-interactive shells**

A launcher installed into `~/.local/bin` is NOT runnable by name over ssh on this estate.
`ssh host 'lpt-label ...'` runs a NON-interactive shell, and Ubuntu's stock `~/.bashrc` returns
early for those (`case $- in *i*) ;; *) return ;; esac`), so any PATH line appended there is never
read.

Measured 2026-10-08 on the authority: the `lpt` installer's marker block is present at
`~/.bashrc:119`, and `ssh secratary 'lpt doctor'` still answers `command not found` - while
`lpt_ops/transport.py` works only because it invokes an absolute path.

The fix that works: symlink the launcher into a directory that is already on the non-interactive
PATH (`/usr/local/bin`), which `install-label.sh` now does and PROVES by running the bare command.
Any future install script on this estate should be assumed to need this; "installed" is not true
until a shell that read no profile can run it by name.
