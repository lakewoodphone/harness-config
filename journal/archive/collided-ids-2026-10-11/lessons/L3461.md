**L3461 · A database copied out of a running app can be torn - never judge corruption or count from it**

A file lifted out of a backup of a RUNNING iOS app is not a faithful snapshot. On 2026-10-08 the
device's ChatStorage.sqlite came back unreadable - "malformed database schema ... no such table:
main.ZWAMESSAGE" - and `.recover` pulled 698 chat sessions and ZERO messages out of it, because a
live SQLite's biggest table lives in pages a copy can miss (WAL/journal state).

THE RULE: never conclude "the app's data is damaged" from such a copy, and never report a count
taken from one. Ask the app on the device, and count from the healthy source. The same trap has a
sibling already recorded: counting manifest ENTRIES instead of typed files produced the false
"78% of media" claim on this same case.
