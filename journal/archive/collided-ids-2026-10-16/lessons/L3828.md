**L3828 · The intake passcode column exists and is empty on all 374 cases - a case filed from photographs can never carry a machine login**

**Where a machine's login is supposed to be recorded:** `repair_intake_cases.passcode`, in the operational
store (the column exists — read 2026-10-15 from `information_schema.columns`).

**Measured 2026-10-15, operational store:**

| reading | value |
|---|---|
| `repair_intake_cases` rows | **374** |
| rows with a non-empty `passcode` | **0** |
| intake case 1282 (Senzer, WO26100812736) `passcode` | NULL |
| order 3015 `"deviceInfo"` | NULL |
| that customer's comms, searched for password / passcode / PIN / login | **0 hits** |
| customer notes for that customer or order matching pass/pin/code/password | 1 hit — and it was the words *warranty code*, not a passcode |

So "we do not have the passcode" was not a fact about that one case: **the field has never been used on any case
in that store.** A session that asks "do we have the passcode" must not stop at the one row it was asked about,
because the answer is a property of the intake path, not of the case.

**Why it can never be filled by that path.** This case was filed from two photographs of the machine and its
handwritten note, promoted to a work order by `tools/intake/intake.py promote`. There is no conversation in that
flow and therefore nobody to ask, so `passcode` is born NULL and stays NULL. The same is true of every case built
the same way.

**The trap this creates at the bench.** The machine is in Safe Mode, and the two calls about it were about the
symptom (2026-10-08) and the fee (2026-10-13) — access was never discussed. So the first time anybody needs the
login is the first time anybody discovers nobody has it, which is exactly the re-derivation the case file exists to
prevent. Write the absence into the case file's header next-action the moment it is measured: **"no login is on
file" is an operational fact, and an unrecorded absence reads the same as nobody having looked.**

**Not done:** the intake path was not changed to capture a passcode (nobody to ask in a photo-based intake), and
no case was backfilled. Recording the gap, not repairing it — repairing it needs a decision about whether the shop
wants to store customer machine passwords at all.
