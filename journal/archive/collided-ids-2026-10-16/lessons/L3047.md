### 2. THE SESSION RATE IS THE WRONG DENOMINATOR
Measured on the authority, tasks touched today:

```
done 96 | open 10 | blocked 6 | in_progress 4
TASKS touched today = 116, finished = 96 -> 83 %
SESSIONS since the W1 deploy = 14, completed = 10 -> 71 %
```

and how many sessions each task took:

```
1 session -> 9 tasks
2 sessions -> 1 task
3 sessions -> 1 task
```

**So a task that legitimately takes two or three sessions is counted as one or two session
failures.** The company's own unit of work — the task — is at **83 %**, twelve points above the
session figure, and the gap is *exactly* the multi-session tasks. The objective's "≥85 % of work
sessions finish with evidence" measures sessions; the outcome the owner cares about is whether the
**work** finishes, and by that measure the company is much closer than the session number suggests.

**Caveat, stated because it matters:** `done` is set by the agent itself, so 83 % is the company's
self-report of its tasks, not an independent verification. It is a better denominator than sessions
but it is not ground truth. A follow-up worth doing: sample the 96 `done` tasks and confirm a few
really are done.
