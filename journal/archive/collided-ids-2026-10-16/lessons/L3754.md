**L3754 · git add silently skips .gitignore'd files - verify a commit by listing the tree, not by reading the diff stat**

**Measured 2026-10-13, lpt-hub.**

Committed ten evidence images into `artifacts/shlock-tranche-2-20261011/`. `git add <dir>`,
`git diff --cached --stat` and `git commit` all reported success: *"9 files changed, 357
insertions(+)"*. The commit contained **six** files. `.gitignore` line 44 is `*.jpg` — and
`git add <directory>` skips ignored files **silently**, no warning, no error, exit 0.

The manifest that shipped in that commit listed ten images with their sha256 that no reader could open.
I found it only because I checked the tree instead of the diff:

```
git ls-tree -r --name-only HEAD -- artifacts/shlock-tranche-2-20261011 # 6, not 16
git check-ignore -v artifacts/shlock-tranche-2-20261011/01-...jpg
 -> .gitignore:44:*.jpg
```

**The rule.** After any commit that adds files — and always when it adds media — verify with
`git ls-tree -r --name-only HEAD -- <path> | Measure-Object`, and compare the count against what you
put in. `git diff --cached --stat` counts *staged* files, and a silently-ignored file is not staged.
A `git status` "nothing to commit" after `git add` is the loudest version of this and looks like
success.

**The repo's own fix, which is what was used:** a scoped negation beside the existing curated-photo
exceptions — `!artifacts/shlock-tranche-2-20261011/` and `!.../*.jpg`. The convention for putting
media in this repo is a named exception, never `git add -f`, and never a blanket `.gitignore` change.
