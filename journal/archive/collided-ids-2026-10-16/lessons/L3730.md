**L3730 · CORRECTION to L3727: the stick does 17-21 MB/s, not 3 - the many-file path is the open problem, and I slandered the medium**

**Correction to L3727, which concluded "the true sustained rate is ~3 MB/s" and laid that at the medium's door. The stick is not slow.**

WHAT IS NOW MEASURED, with the device provably idle (`pgrep -ax` clean, `fuser -m` clean) and the rate read from `/sys/block/sda/stat` field 7:

| regime | measured |
|---|---|
| negotiated link | 5000 Mbps, USB 3.20 |
| single-file sequential write, 1 GB, four arms (bs=1M/8M x O_DIRECT on/off) | 17-21 MB/s |
| single 4 GB file, `oflag=direct` | 19.9 MB/s (kernel counter 18) |
| one 4.4 GB file through `cp` | ~4 MB/s wall including the flush |
| the SOURCE drive, one big file | 400 MB/s |
| another device on the same USB controller | 104 MB/s |
| host CPU during the folder copy | 99% idle, iowait ~0 |
| **a whole folder of 1,812 files (rsync)** | **1-3 MB/s at the device, while rsync's own line spiked to 26-29 MB/s** |

So the medium does ~20 MB/s and the many-file path does 1-3 MB/s, at the same time, on the same stick. **L3727 said the second number was the stick. It was not: it is the many-file path, and that is a different question** - candidates and the test for each are in the runbook now (`docs/customer-operations/recovered-data-delivery-to-customer-media.md` section 7): 1-deep queueing (`nr_requests` reads 1, `queue_depth` 1, ~250-600 ms per 1 MB command), allocation scatter on cacheless flash, or per-file metadata.

The error was not one bad measurement - it was a chain of four, and each link is now a rule:
- 1.3 MB/s: taken while my own `dd` and three `rsync` children were still on the device.
- 17 MB/s: a 300 MiB write, which is the SLC cache, and L3512 says so in its own words.
- 3 MB/s: a folder copy - real, but about the workload, not the medium.
- and because `pkill -f` matched its own command line, every "I killed everything first" claim in that chain was false.

TOOLING FIXED SO IT CANNOT RECUR: `lpt-hub/scripts/customer-operations/copy-to-stick-linux.sh` (refuses while anything else is on the device, kills/checks by exact process name, captures `rc=$?` before any command substitution, resumes by size, no delete path, measures the kernel counter); runbook section 7; and the `lpt-production-case-work` skill section 8. Commits: lpt-hub `56ac4c07f`, harness-config `60d8ff43`.

The general form, worth more than the numbers: **a throughput figure is a statement about a regime, not about a device.** Size, block size, cache state, queue depth, what else was running - without all five it is a rumour, and in this job it was a rumour that would have cost a night.
