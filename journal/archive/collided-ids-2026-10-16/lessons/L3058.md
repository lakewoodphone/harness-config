**L3058 · A version-coupled plugin rename applied ahead of the engine promotion broke every new session, and it arrived as HTTP 200**

**Measured 2026-09-29 on ZABZ-YOGA.** New DSH windows became unusable: choosing a workspace flipped
straight back to "Choose a workspace" and the composer never became a textbox.

**The cause.** The presets and profile patches were moved to the 0.1.7-era plugin names on 2026-09-28
15:32, but the engine on this machine was still **0.1.5-rc.1** and was never promoted —
`dsh-update/FINDINGS.md:314` says so in as many words: *"Nothing has been promoted"*. Ten rows across
five files named three packages the installed engine does not contain:

```
dsh-workflow-ptc -> dsh-workflow-worker-thread
dsh-agent-preset -> dsh-agent-presets
dsh-agent-preset-registry -> dsh-agent-presets
```

`presets/cordis-bg/agent.cordis.yml:284` had **predicted this exact failure**: *"applying it while an
0.1.5 engine is running breaks preset mounting"*. The warning was written and then not enforced.

**Why it was invisible — the part worth keeping.** The failure is not an error to the user:

```
POST /api/session/create -> HTTP 200
{"ok":false,"error":{"code":"agent-preset/invalid",
 "message":"agent-presets: preset \"zabz\" failed to mount: row \"workflow-ptc\" names a plugin
 that cannot be resolved: @deepseek-ai/dsh-workflow-ptc"}}
```

The client's picker does `selectWorkspace(id).catch(() => setPendingWorkspaceId(undefined))` —
**the rejection is swallowed and the UI deliberately resets itself** — so a hard configuration error
presents as "the picker bounces back". `scripts/sync.ps1` reported success throughout, the engine booted
fine, and nothing in the GUI said why. The cause was only found by reading the **response body** of a
request the browser showed as `200 OK`.

**Rules this proves, both already in the journal and both worth repeating.**
1. *A config change and the runtime it targets are one unit.* A version-coupled rename applied alone is
 strictly worse than not applying it, because it turns a working system into a broken one with no
 error anywhere. `dsh-update` exists to move both together.
2. *"The request succeeded" and "the operation succeeded" are different claims.* An HTTP 200 carrying
 `ok:false` is the failure mode; always read the body of a 200 before concluding a call worked.

**Fixed.** Reverted the config to the engine that is installed (`d5393a8`), delivered to the live
`~/.dsh/.agent-presets/` and `~/.dsh/profiles/{web,mesh}/`, and verified in the browser: the picker
now selects `code` and the composer is a real textbox.

**Guarded.** `scripts/preset-package-gate.ps1` (`6bdbc88`) checks every `@deepseek-ai` package named in
`presets/` and `profiles/` against the packages actually installed, and `sync.ps1` now **refuses to
deliver** when one cannot resolve. Proven: 202 references in 8 files on the repo; a fabricated
`dsh-workflow-ptc` row fails with `file:line` while a comment naming it is ignored; an empty scan is a
refusal, not a pass; and sync exits 1 applying nothing when a bad row is appended.

**And the meta-lesson, because it recurred three times in one day.** The first two drafts of that gate
reported *"OK — 0 package reference(s) in 0 file(s)"*: `-Include` with `-LiteralPath` matched nothing,
and `Join-Path $Root 'a', Join-Path $Root 'b'` yields one malformed path rather than two. Both were
green and both were decoration — the same shape as the screenshot wiring guard that stayed green on a
dead feature (`L2786`), the six Windows live-driver tests that SKIP and read as "87 passed"
(`docs/audits/kf0928/windows-merge.md`), the alembic duplicate check that walked a de-duplicated map
(`L2799`), and my own first negative proof of the MDM validator. **A guard must be run against the
defect it claims to catch, twice: once to fail, once to pass. Anything less is a claim, not a check.**
