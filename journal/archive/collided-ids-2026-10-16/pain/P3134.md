## P3134 — The agent SMS path is policy-blocked, and the approved script path leaves no audit row

## P-new — every agent-issued customer SMS has to go around the policy gate and past the audit log

MEASURED 2026-10-12, ZABZ-TECH, sending the first reply to customer 8456712943:
`ps_action send_sms` returned `ok:false` —
`Policy denied: requires owner approval - task #28371` (`policy_tier: critical`), and this session
has approval prompts disabled, so that path is closed outright. The refusal is a correct guardrail,
not a bug; the problem is what the only workable alternative costs.

WHAT IT COSTS
The approved path is `scripts/send-lpt-sms.py`, and `lpt-hub/docs/customer-operations/
CUSTOMER-SMS-RUNBOOK.md` §4 already documents the gap (journal pain P217): that script calls
`dialpad_service.send_sms` directly, so **it writes no `sms_log` row**. Consequences, all live:
- cross-process duplicate suppression cannot see script sends, so the same reply can be sent twice
 by a later session that checks the log for evidence of an earlier one;
- there is no send audit trail for the messages that actually reach customers;
- the only witness afterwards is `dialpad_sms_cache` on the authority (message id + `fetched_at`),
 which the runbook correctly calls the real witness, but which is **not replicated to any other
 machine** — so a session on ZABZ-YOGA or ZABZ-TECH cannot verify its own send without an ssh.

WHAT WOULD FIX IT
Make `send-lpt-sms.py` write the same `sms_log` row the action path writes, at minimum
(message id, to, from, body, status, session id). One row per send, written by whichever path sent
it, is enough to make duplicate suppression and the audit trail path-independent. Until then the
runbook's §6 "record it in the case file by hand, not optional" is the only mitigation and it is a
manual step that will be skipped.

ALSO WORTH FIXING
The script's money-validator exits 1 on any body mentioning cost with no numeric amount ("This is
almost certainly a shell-escaping bug"). It is right to exist — a stripped `$155` once went out
blank — but it fires on the deliberate case of a first-contact text that asks for the device model
before quoting. It should distinguish "a currency token with no amount" from "the word price with
no amount", so honest drafts do not need `--force`.
