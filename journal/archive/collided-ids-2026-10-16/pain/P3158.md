## P3158 — lpt ticket <WO number> says 'no store returned a case' while the phone and order-id routes both open the case

**Measured 2026-10-13 on WO26100812737 (order id 3016), from the laptop, through the shop's own reader `lpt`.**

```
lpt ticket WO26100812737 -> lpt: order 3016 matched but no store returned a case [exit 1]
lpt ticket 3016 -> full case, WORK ORDER WO26100812737 section printed [ok]
lpt ticket 7325972935 -> full case, same order, store: operational=FOUND [ok]
```

So the **work-order-number path is the broken one**, and it is the path staff use: the shop refers to jobs by `WO...`, the sync verifiers match on `orderNumber`, and labels and notes all carry it. The order matched, so the identifier resolution works - the failure is in whatever assembles the case afterwards for that route, and it reports the misleading sentence "no store returned a case" while both stores are healthy (`lpt doctor`: operational OK 838 ms, app OK 1598 ms, and a direct `lpt sql` read of id 3016 returned the row with its 6 notes).

**Why it matters beyond annoyance:** the same sentence - *no store returned a case* - is what the shop's own reader says when a case genuinely does not exist. A reader that uses one sentence for "we could not assemble it" and for "it is not there" is the exact defect class P3002 already records for `app=FOUND` on an empty store: the tool's summary hides the divergence it exists to expose.

**Traps for whoever fixes it:** it is NOT missing data (the row and all six notes were read directly: ids 2868, 3085, 3108, 3162, 3163, 3164), and it is NOT a store outage (doctor clean, both stores answering at the same minute). Reproduce by comparing the WO-string route against the order-id route for order 3016, then make the WO route reuse the exact assembly path the id route uses - and give the two failure modes two different sentences.

**Evidence:** the three invocations and their exact output lines above; `lpt doctor` at 2026-10-13 15:49:27Z; `lpt sql` returning `{"id": 3016, "total": "50.00", "status": "AWAITING_DIAGNOSIS"}` and the six note rows.
