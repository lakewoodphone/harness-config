## P3174 — The live autopilot.py already carries 446 lines of another session's uncommitted work - copying the loop build in would have destroyed it silently

CAUGHT BEFORE ANY DAMAGE, 2026-10-14 01:55Z. I was one command away from deploying the evolve2/loop build by copying app/autopilot.py into the live tree /opt/company. The check that stopped it: 'git status --porcelain' in /opt/company names app/autopilot.py as modified, 'git diff --stat db07e8e0' shows 446 insertions and 7 deletions, and md5 differs - live 7db8748fe642de33a42368dfdd91a80e against my built worktree copy 25862605be0ac9e882997cf528a59073. The live file was modified at 2026-10-14T01:11:43Z, 44 minutes before I looked. WHAT IT CONTAINS: a fix labelled WS-STORM, the three brakes that end an owner-message retry loop, measured read-only on the authority - since 2026-09-01 the owner's line holds 3,063 outbound sms_log rows and only 95 ever reached him, 2,010 logged refusals and 939 failed attempts, four bodies re-driven at a median 60.6 s apart, including 863 copies of one message. That is substantive, valuable, live production work by another session. WHY A COPY IS WORSE THAN A MERGE: a copy has no conflict, no marker and no record. My build would have replaced those 446 lines, the suite would still have passed, and the loss would have surfaced only when the SMS storm resumed and someone asked why the brakes were gone. This is exactly the class in AGENTS.md 6.1 and the orchestration skill: before editing a file that runs somewhere, hash the file you are editing against the file on the host that runs it. I did, and it is the single most valuable thing this session did. THE RULE I AM ADDING TO MY OWN PRACTICE: a deploy is not 'copy my files in'. It is 'diff the destination first, and if the destination has moves the base does not, the base is stale and the deploy is a merge, not a copy'. WHAT MUST HAPPEN BEFORE evolve2/loop CAN LAND: the live WS-STORM change must be committed to a branch of its own by whoever made it, evolve2/loop (currently at 8554b4e1, based on db07e8e0) must be REBASED onto it or merged with it, the full suite must be re-run on the merged result against the base's 46 failed / 3536 passed, and only then deployed. DO NOT copy the three app files into /opt/company until that is done. NOTHING WAS DEPLOYED and company-api was not restarted.
