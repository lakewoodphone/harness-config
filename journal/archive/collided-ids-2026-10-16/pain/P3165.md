## P3165 — lpt-hub AGENTS.md names a flows-index builder that does not exist; lptcase new silently doubles your slug

## Two tooling defects hit while doing the Mendelowitz Apple ID case (2026-10-13)

**1. `lpt-hub/AGENTS.md` §11 orders a script that does not exist.**
It says: *"If the flow you need is missing, add the doc and run `python scripts/build-flows-index.py`."*
`Get-ChildItem -Recurse -Filter 'build-flows-index*'` over `lpt-hub` returns **nothing** (exit 1).
`FLOWS-INDEX.md` is nevertheless marked "(generated)". Consequence: a session following §11 either stalls
or silently skips the index update, and the new SOP stays invisible. I edited `FLOWS-INDEX.md` by hand
(priority table + SOP table + maintenance log) — which is what the file wants anyway, since the tables carry
prose the generator could not write.

**2. `lptcase.py new` appends `-<phone>-<date>` to the slug you pass.**
`fname = f"{device_slug}-{slugify(args.slug)}-{phone}-{today}.md"` (`tools/case-index/lptcase.py:2829`).
Passing a full slug (`iphone-mendelowitz-2015667853-2026-10-13`) produced a **156-character** filename and a
matching `case_id`. The correct call passes the *device* as `--device` and the bare customer slug:
`new mendelowitz --name "Mendelowitz" --phone 2015667853 --device iPhone` → `iphone-mendelowitz-2015667853-2026-10-13.md`.
Neither the CLI help nor `CASE-FILE-STANDARD.md` says this. Fixed by `Move-Item` + rewriting the front-matter
(this file was 60 seconds old and referenced nowhere, so the "never rename an existing case file" rule did
not apply — I did not delete it).

**3. `glob` at `C:\Users\ezabz\Code` times out.** `AGENTS.md` §11 already says never to point glob/grep at
that root; I did it anyway and burned 30 s. Scope to one repo.
