**D3139 · 2026-10-15 · Voice input goes live on the six LPT units by a Settings consent tap - no filter, PAC or profile change; Waze's own mic is inside Waze's code.**

**Decision (owner, 2026-10-15 ~22:1xZ): voice input goes live on the six LPT NAVIGATION units (DRN 2002, 2004-2008) through the Apple keyboard microphone, and the DNS filter posture does not change.**

**How it is applied:** one human tap per device, ~2 minutes — force-quit Waze → Settings → General → Keyboard → tap the Settings search field → tap the mic key → the "Enable Dictation?" prompt **sticks** (it is torn down inside Waze by Waze's own audio code) → accept → the Dictation Languages row appears → dictate into Waze's search box. Confirmed on DRN 2005 by the owner: text typed into Waze's search field, **and again with airplane mode on and Wi-Fi off**.

**Why no MDM or filter change is needed:** all six already carry `allowDictation=true` and `forceOnDeviceOnlyDictation=true` in the newest kiosk `InstallProfile` payload each was sent (2002/2004/2005/2006/2008 at 2026-10-14 16:26, 2007 at 2026-10-15 00:09 — decoded live this session from NanoMDM Postgres). No Apple MDM key enables dictation; every key in that family only disables it.

**Filter verdict: no breach.** The flow completes with the radios off; `forceOnDeviceOnlyDictation=true` forbids the server path and fails closed for a language with no on-device model; the filter was not touched (PAC md5 `18e81bc82dc64ccbf53c81c2a435b764` unchanged, DNS container up 28 h, no allowlist edit); the transcript can only land in the focused field of the one allowed app (`com.waze.iphone`, 133 bundle ids blocked); `guzzoni.apple.com`, `*.smoot.apple.com`, `gateway.icloud.com` and Shortcuts stay blocked. Residuals stated: Apple's own footnote says "in some cases", and Siri's on-device intents were already reachable through the CarPlay gate — unchanged by this.

**What it does NOT fix:** Waze's own mic button. It fails with the network on and in airplane mode, the filter logged **zero** speech/assistant lookups across the tap window, Waze **is** listed under Microphone (on), and the Speech Recognition pane is **empty** with nothing appearing after a tap — the failure is inside Waze's code and it does not block the feature.

**Open sub-decisions, recorded rather than taken:** (1) `LOCKDOWN_PROFILES` still lists `layered-kiosk-phase1` (`nanomdm_client.py:70`, `fleet_api_remote.py:1285`), which sets `allowDictation=false` — a future `/lockdown` re-disables voice; fix = drop it or align its keys, and it touches the new-device provisioning path. (2) The generator defaults are still the false posture (`nanomdm_service.py:1000,1034`) and the fleet's `true` lives only in the file on the host; changing the module default flips the **63-device gemach fleet** too — the owner's call.

**Robustness:** a restore or re-image loses the consent (per-device state; no MDM key grants it on iOS 26), so the tap belongs in onboarding and the QC checklist. Runbook + evidence: `waze-fleet/50-research/voice-to-text/RUNBOOK-voice-input-2026-10-15.md`.
