**D — 2026-10-13 · The Waze kiosk allows Bluetooth modification, for both kiosk fleets.**

**The owner's direction, verbatim:** *"turn bluetooth on for both, but only push the new profiles to
the 6 waze devices … make sure to document all this clearly very well organize commit and push and
only implement after thinking and analyzing fully and properly"*.

**What it was and why.** `allowBluetoothModification` was `false` in the kiosk restrictions, so a
customer could not pair their own car. That was **deliberate, not an oversight**: the pilot doc lists
"Bluetooth modification" under *"strongly consider also blocking or controlling"*
(`APPLE_WAZE_SOFT_KIOSK_PILOT.md:132`), and the bench paired the car during handoff through a
temporary `--carplay-bootstrap` window that sets the key true, then `service-close` restored the
locked profile (archived runbook `:1022`, `:1030`; `test_nanomdm_service.py:948-977`). The same pilot
doc listed *"Bluetooth behavior for the exact customer use case"* as an **open question** (`:170`).
This decision closes it: the customer pairs their own car, headset or speaker, at any time.

**What changed.**

| File | Key | Was → now |
|---|---|---|
| `deploy/waze-mdm/profiles/waze-layered-kiosk.mobileconfig` | `allowBluetoothModification` | false → **true** |
| `deploy/waze-mdm/profiles/waze-layered-kiosk-phase1.mobileconfig` | same | false → **true** |
| `deploy/waze-mdm/profiles/waze-layered-kiosk-drn13.mobileconfig` | same | false → **true** |
| `app/services/nanomdm_service.py` — `make_waze_layered_kiosk_profile()` default | `allow_bluetooth_modification` | False → **True** |
| `tests/test_nanomdm_service.py` | the assertion pinning the old default | updated to True with the reason |

**The reason that is three profile files and not one:** `/lockdown` installs
`LOCKDOWN_PROFILES = ["layered-kiosk", "layered-kiosk-phase1", "webtrap", "siri-dns"]` and iOS applies
the **most restrictive** value across installed profiles — so changing `layered-kiosk` alone would
have left `layered-kiosk-phase1` silently holding Bluetooth off.

**What did not change:** the app allow-list stays `["com.waze.iphone"]`; `allowAirDrop` false;
`allowUSBRestrictedMode` true; app install/removal, erase, passcode, device-name, wallpaper, hotspot,
eSIM and cellular-plan modification all still false. Bluetooth cannot install anything.

**Deliberately not changed, with reasons:** `waze-layered-kiosk-drn26` (already true);
`waze-layered-kiosk-shop` (the *shop* variant — the shop's own devices allow Bluetooth via
`shop-store`, which is what they wear); `waze-callblock-bundle`, `-v2` and `waze-phone-data-block`
(not in `LOCKDOWN_PROFILES` — superseded modes no current install path reaches); `mdm-quarantine`
(a containment state, not customer stock); `shop-store`/`shop-counter`/`family-filtered` (already true).

**Pushed to the six only** — DRN 2002, 2004, 2005, 2006, 2007, 2008. No gemach device was touched;
that fleet picks the new value up whenever a device is next re-locked, which is what "both fleets"
means here.

**Record:** `personal-secretary-mvp/deploy/waze-mdm/docs/bluetooth-policy.md` (decision, mechanics,
what was left alone, the three verification readings and the results). Pointers added from
`profiles/README.md`, `docs/deployment-process.md` and the LPT fleet registry.
