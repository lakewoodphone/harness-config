Decisions taken 2026-09-17 (docs/mesh/104-node-enabled.md; all measured, none escalated — these are
development decisions, not owner decisions).

D1. `packages/mesh-broker/nodes.json`, `zabz-tech-linux.dispatch.v1`: **false -> true**, evidence
replaced by the dated restoring measurement, `measuredAt` 2026-09-17. WHY: the `false` answered "can a
child the dispatcher actually places here run", and both conditions `98` §4.2 named are now met — the
invocation is corrected (`plugin-remote-fanout/lib/nodes.js` invokes the node's `dsh` executor BY NAME)
AND the credential reaches the process (the executor sources `/etc/dsh-worker.env` itself, rather than
a key being exported into an ssh session). The old row's `false` was a dispatcher defect wearing a node
defect's clothes. `test/config.test.mjs`'s assertion moved with the flag in the same change, and the
new evidence names what would REVOKE it, not only what restored it.

D2. `plugin-mesh-http/bin/mesh-dispatch.mjs`: **read the shared table (option A)**, not "correct the
path identically + add an agreement test" (option B). WHY, in the order it decided: (i) reading across
packages IS possible in that package's resolution — `test/dead-target-fallback.mjs` already imports
`../../plugin-remote-fanout/lib/provider.js`, and nothing bundles `bin/**`; (ii) the junction is safe,
MEASURED — Node resolves the real path by default, so a junction-mounted CLI's relative imports resolve
against the checkout; (iii) a path-only correction still leaves the interpreter form, which dies
`MISSING_CREDENTIAL` on this node even with the path right, so option B would have shipped a second,
differently-broken invocation; (iv) one table, one place to be right.

D3. The v1 program became a pure exported function (`buildV1Program`) and the credential-sourcing rules
are the ones `remote-script.js` already implements (`set -a` before the source, only for the interpreter
form, only when readable; a half-pair refuses to spawn). WHY: the defect was a STRING, so the string had
to become something a test can read.

D4. Deploy by the package's own `deploy/install-authority.sh` from a staged tree, checked with
`verify-deploy.sh`; 22/22 sha256 between local and staged, 20/20 installer assertions, `NO DRIFT`.
WHY: the broker on the authority is a COPY, and its only failure mode is silent drift (`86` §1).

D5. Only the broker service was restarted (three times: installer, supervised restart, SIGKILL test).
No engine anywhere was touched. WHY: the brief says so, and the roster change is read by the broker
only — the provider reads the roster through the broker's HTTP answer.

D6. `mesh-dispatch.mjs` deliberately does NOT re-produce `nodeExe`/`dshBin` aliases for its callers.
`test/concurrency-sweep.mjs` (the v1 concurrency rig) was updated instead to take the invocation from
the shared table, and it now REFUSES a POSIX node by name, because it drives a PowerShell
`-EncodedCommand` and a node it cannot run a program on must not be "measured" by it. `nodes.js`'s own
rule is that those two spellings are READ, never produced.
