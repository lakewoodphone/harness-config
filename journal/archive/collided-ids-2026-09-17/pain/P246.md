## P246 — zabz-tech cannot ssh to itself, so a child placed on the broker's favourite node dies at 255 in 108ms

Ranked with what would fix it.

**1 — `zabz-tech` cannot ssh to itself, so a child the broker places THERE dies at 255 in 108 ms.**
MEASURED: `ssh -n -o BatchMode=yes -o ConnectTimeout=8 desktop-ts hostname` from an Interactive
one-shot task on that machine -> exit 255 in 112 ms, `Permission denied
(publickey,password,keyboard-interactive)`; it offers `~/.ssh/zabz-tech-ed25519 ED25519
SHA256:tuQvTkv6fNSyfSjzylJpBkDkJo87YIeN9PEElUhotdE`. `lib/nodes.js` maps broker node `zabz-tech` to
ssh alias `desktop-ts`, and the broker ranks that node FIRST (score 18 of 24, four eligible), so the
most-likely placement is also the one that cannot be dispatched to. The ledger already records the
whole failure (`exitCode 255, ms 108, reportedHost null`) — only the transport is missing.
FIX: put that public key in that machine's own `authorized_keys` for `desktop-ts`, or point the alias
at an identity its sshd accepts. Then the placement proof completes with no code change at all.

**2 — A verification whose verdict depends on which process runs it, and whose output never says
which.** `--dump-config --profile web` on that machine: exit 0 / 620 lines from a local
Interactive-logon reader, exit 1 / 16 lines from an ssh-spawned one, same bytes, same minute. The
remote class is the one that runs a dispatched child, and it is the one nobody runs the check as.
FIX: a `--reader-class` line in the output, or run the composition from both classes in the keeper.
`mesh-run.mjs:229` already refuses on the right condition; `--dump-config` should not be quotable
without it.

**3 — The junction trust rule was recorded wrong twice, and the wrong version is the one that
propagated.** `99` §2.2 says an ssh-created junction is the untrusted kind; `105` §8 item 7 says a
task-created one is trusted. Both are FALSE as stated (measured 9/9: the discriminator is the reparse
point's ACL owner, `BUILTIN\Administrators` vs the user, and a local reader traverses everything).
A stream that follows either sentence repairs the link into the state that is still broken for remote
processes — which is exactly what `99` §2.2 did at 10:10, and why this session had to redo it.
FIX: the rule is now in `journal/entries/lessons/L1913.md` and `docs/mesh/106` §3; the two docs carry
the correction inline. Nothing further.
