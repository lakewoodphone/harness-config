# The Journal — the mechanism by which the CEO grows instead of restarting

**This is not documentation. It is the organ that makes continuity possible.** The previous occupant of
this seat named the problem and did not mechanize the fix:

> "If I forget to write notes for future-me, I literally cease to exist as a coherent entity."

It was right. Because nothing mechanized it, the same audits were commissioned repeatedly, the same
files were re-litigated, and 55 improvements piled up unapplied.

## What changed on 2026-09-14, and why

The journal was six flat files totalling **590 KB**. Reading them cost about **150,000 tokens** — an
entire context window — so nobody read them, which is the same as not having them. Worse, they were
**three different documents on three machines** that merged by hand:

| Failure | Measured on 2026-09-14 |
|---|---|
| Unbounded monoliths | `HANDOFF.md` 273 KB / 3,675 lines from four days of work |
| Collided ids | **60 base ids named more than one entry** — `P46` meant three different problems, `D41` five, `W25` five. Every cross-reference in prose was ambiguous. |
| Id allocation by eye | two sessions on two machines read the same file and both picked "next"; the merges then concatenated both |
| State and history in one file | to learn what was *open* you read 1,067 lines of `PAIN.md`, most of it closed |
| Instructions inside data | the ID-allocation rule lived in `HANDOFF.md` at line 3,382 |
| Lost entries | the first automated migration of these files silently dropped **37 entries**; the second dropped **7 more**. Both were caught by verifying counts against the source, not by trusting the script. |
| Two stores for one thing | open owner questions lived in `QUESTIONS.md` *and* `owner_decision_queue`, and neither was authoritative |

## The tree

```
journal/
  README.md              <- this file: the map and the rules. Read once.
  NOW.md                 <- STATE. The one page every session reads. Rewritten, never appended.
  state/                 <- STATE. Small, mutable, machine-derived where possible.
    open-pain.md           generated by `journal.py state` — every entry with no proof of being done
    owner-questions.md     generated by `journal.py questions` — mirror of the authority's queue
    in-flight.md           hand-written: what is mid-work, what is broken, what is next
    status.tsv             append-only status corrections ("P46 is done, because ...")
  log/                   <- HISTORY. Append-only. Sharded by kind and month. Never read whole.
    handoff/2026-09.1.md   66 entries across 2 shards
    lessons/2026-09.md     158 entries
    pain/2026-09.md         57 entries
    decisions/2026-09.md    66 entries
    wins/2026-09.md         42 entries
  index/
    entries.tsv          <- GENERATED from the shards: kind, id, date, host, status, heading, file,
                            line range, content hash. The thing that makes partial reads possible.
    README.md
  reference/             <- TOPIC documents, read on demand, not part of the log.
    people.md, yocheved-laptop.md, deepseek-token-pricing-2026-09-11.md
  tools/
    journal.py           <- the ONLY writer and the ONLY cheap reader. See `journal.py --help`.
    migrate.py           <- one-off: the flat files -> this tree. Kept for the record.
  archive/               <- the pre-2026-09-14 record, verbatim, and MIGRATION.md.
  <the six flat files>   <- FROZEN INPUTS. Still on disk because a second session was writing them
                            during the rebuild. `journal.py import-flat` absorbs anything new;
                            `journal.py check` warns if they gain an entry the log lacks.
```

## The read path, with measured costs

The old rule was "read `PAIN.md` and the newest `HANDOFF.md` entry". That was unexecutable: the only way
to reach the newest entry was to read a 273 KB file. Now:

| Question | Command | Cost |
|---|---|---|
| Where do I stand? | `python tools/journal.py status` | **~7 KB**, one screen, bounded — it fails loudly past 12 KB |
| What happened last? | `journal.py newest handoff 2` | ~8 KB |
| What is that id? | `journal.py show P46` | one entry |
| Have I hit this before? | `journal.py search "<words>"` | matching lines only, never a whole file |
| What is open? | `state/open-pain.md`, `state/owner-questions.md`, `state/in-flight.md` | small, and each is rewritten rather than grown |
| What is the exact record? | `index/entries.tsv` | grep-able TSV, one row per entry |
| Is the record intact? | `journal.py check` | exits non-zero on a real error |

**Never read a shard end to end.** `log/handoff/2026-09.1.md` is 198 KB; `newest handoff 1` is 4 KB. A
shard over 260 KB gets split with `journal.py split-shard`.

## Writing rules

1. **Write for the self that wakes up with no memory of this.** Not a summary of the conversation — the
   transferable fact, with its evidence.
2. **The only writer is `tools/journal.py append`.** It allocates the id over the index, the shards *and*
   every git ref, so two machines cannot pick the same number. Writing an entry by hand into a shard is
   how this journal got 60 collided ids.
3. **Append-only.** An entry is never edited to look better in hindsight. A wrong entry is corrected by a
   *new* entry that cites it; a status change is a row in `state/status.tsv`, not an edit. The record of
   having been wrong is the most valuable thing in here — the most expensive failures in this system's
   history were confident errors.
4. **The state tier is different.** `NOW.md`, `state/in-flight.md` and the generated files are rewritten.
   That is legal *only* there, and each carries `Updated: YYYY-MM-DD`; `check` warns when the state tier is
   older than the newest handoff entry.
5. **One source of truth per thing.** Owner questions: the `owner_decision_queue` table. Harness
   configuration: `harness-config`. Company data: the authority. If a fact lives in two places here, one of
   them is generated and says so.
6. **Never write a bare collided id.** Use the suffixed one from `index/entries.tsv` (`P46b`, not `P46`).

## The three questions before ending any session that changed something

1. **What did I learn that I did not know at the start?** -> `journal.py append lessons`
2. **What is now different, and what is next?** -> `journal.py append handoff`, then update `NOW.md` and
   `state/in-flight.md`
3. **What still hurts, and what would fix it?** -> `journal.py append pain`; close it later with
   `journal.py resolve <id> --status done --why "..."`

A decision goes to `journal.py append decisions` **when it is made**, not when someone asks.

## What belongs here vs. elsewhere

- **Here:** how to work, what was learned, what is still broken, what was decided and why.
- **`harness-config` presets/settings/scripts:** the harness itself. Change it there, then sync.
- **`personal-secretary-mvp/docs/`:** the company's own documentation and postmortems.
- **Research with its own evidence base:** the repo that owns the subject (for example
  `kosher-filter-ai/docs/research/`), with a `decisions` entry here pointing at it.

## Provenance

Every claim here carries where it came from and when — **L1**. If a reading cannot name its source and its
age, it is not evidence. An empty result is a refusal, not a health check: the single most expensive
failure in this system's history was a fabricated crisis read from a stale database copy.
